## 逐项核查

### 1. 必须改：派生式的编译范围用了全局维度表，不是主体本表的维度（`server-plugin/kernel/dimensions.mjs:184`）

`compiledDerived` 取 `engine.env.rxScope`；该对象由 `server-plugin/kernel/validate/dimensions-validate.mjs:99–:107` 用**全部表**的维度建成，
同名不同定义还标 `ambiguous`。但卷二是按主体本表读变量：:372「主体的基值维度」、:378「派生变量一律读基值」，
求值处也确实用 `readBase(engine, state, kind, id, k)`（`dimensions.mjs:219`）。

后果有两类：
- 公式引用只在别的表登记的维度名时，读时编译通过，`readBase` 才在 `dimKeyOf` 处报 `E-DIM-REF-MISSING`（`kernel/handles/keys.mjs:61–:63`），
  而不是加载期 `E-DIM-DERIVED-VAR`；
- 两张表有同名不同定义的维度时，全局表把该名标成 `{ambiguous:true}`，本表定义明确的派生式反而编译失败 `E-MOD-RX`。

修法：派生式编译的 `scope.dims` 取 `t.doc.dimensions`（本表），`vocabIndex`/`ns`/`maxDepth` 仍从加载结果取。
现有测试用 `engine.env = report.env`，但夹具只有一张 gadget 表，这条测不到。

### 2. 必须改：map 派生维度的结果类型是错的（`server-plugin/kernel/dimensions.mjs:192–:206`）

`derivedValue` 对 `def.type === map` 取 `def.value.type` 当标量类型，然后要求 `typeof v === 'number'`。于是：
- 整维读（`key === undefined`）返回一个**数**当作 map 值，违反维度声明的类型；
- 带下标读时 `pick(v, key)` 对数是 `undefined`，返回未知（`dimensions.mjs:230–:231`）。

卷二 §1.12 的 `derived` 确实包含 map 维度（§5 :1873 `traitValence`、:1874 `hostility`、:1904 `acceptance`），
也有 set/struct 派生（:1626 `substitutePool`、:1676 `categories`、`producedBy`）。RX 变体表（§2.9 :1163–:1182）没有产出 map/set 的变体，
所以这些在聚合/集合原语建成前不能是 RX。当前实现应把 map/set/list/struct 的派生维度按登记码拒收（加载期，或至少读时 `E-MOD-RX`），
不要保留一个会把 map 维当标量返回的分支。

### 4. 等李白裁定：加载期编译/环检测与卷文冲突，且真实世界数据现在过不了加载期

`dimensions.mjs:174–:189` 明确写「P-2 头注说加载期不编派生式，这里按表对象读时编一次并缓存」。
卷文不是这样：§2.9 :1182–:1183 规定 `kernel/load` 在加载期编译、加载期失败即 `E-MOD-RX`；
§4.1 :1500 的 L1 明列「derived 可编译、变量存在（E-DIM-DERIVED-VAR）、自引用带 recursive」，
:1532 把 `E-DIM-DERIVED-VAR/-CYCLE/-RECURSIVE` 定为 L1/L2。P-2 头注只是**未做清单**，不是豁免。

现状效果：世界数据里一条编译不了的派生式会**零 error 加载成功**，等人读到该维度才报；维度级环同理。
但真实世界 `world/ontology/dimensions/material.json` 的六处 `derived` 还是出处文字（:1673、:1689、:1926、:1969、:2148、:2400），
不是 RX；若现在把编译放进加载期，`loadWorld` 会直接失败。两条路都要李白定：
（a）开加载器补卡，连同卷三乙把六处写成 RX，再在读时只消费已编译树；
（b）书面豁免为读时编译，把冲突与真实数据缺口记进 `docs/问题.md`。
本卡不能以「P-2 头注说」自行取舍。

顺带：`dimensions.mjs:213` 的环检测不读 `def.recursive`。RA-N3 :380 只规定「自引用不带 recursive 才报 `E-DIM-DERIVED-CYCLE`」；
带 `recursive` 的合法自引用应走聚合展开（`rx.mjs` 的 `agg` 求值未建，现会报 `E-MOD-RX`），不能直接判环。
现在没有测试盖住 recursive；若保留读时检测，至少要区分这两种情况。

### 6. 可保留：模块级 `deriving` / `derivedTrees`

卷二没有「内核不持隐藏状态」的通用条款。§1.10 :330 本身就用 `WeakMap` 记忆采样值：
`采样值不写回，每次重算（WeakMap 记忆）`。`deriving` 是单趟求值的重入栈，`try/finally` 必清（`dimensions.mjs:231–:233`）；
`derivedTrees` 是按表对象缓存的冻结编译树。就现有卷文看，不构成违规。
但它是第二条编译路径，第 4 条一旦按卷文改成加载期编译，这里应改成只消费加载器交下的树，不再自己编。

### 7. 期望值手算：10/100/1.66/11/121/1.83 全部正确

夹具（`tests/kernel/fixture.mjs`）：
- `gad_box` 实体行 `mass = 5` → `reach = 5×2 = 10`；`reachArea = 10×10 = 100`；`halfMass = 5÷3 = 1.6666…` 向零截断到 2 位 = `1.66`。
- `gad_hammer` 走类别链 `cls_base mass=1` ×2（`cls_tool`）= 2，＋3.5（`cls_heavy_tool`）= `5.5` →
  `reach = 11`；`reachArea = 121`；`halfMass = 1.8333…` = `1.83`。
- `gradeIsA`：`gad_box` 不属 `byClass:cls_tool` → `grade` 不适用 → 整条未知；`gad_hammer` 经 broader 属 `cls_tool`、`grade=grd_a` → `true`。
- 只读基值：`workSpeed` 基值 1、修正后 2，`doubleSpeed = 1×2 = 2`（若读修正后会得 4），正确。
测试与报告没有抄仓库当前读数；采样的期望是「等于 `sample()` 且两次同值」，是接线与确定性，不是手算常数，可接受。
