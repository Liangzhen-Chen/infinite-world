## 二、`visibilityAllowed` 一律取全集（核查项 2）

判定为不违规。C24-12 在待批清单里属于“字段（设计填值）”一类，已经批准；表 B 规定这一列非空、缺写按 error 处理，所以必须由登记动词的卷十八给出值。“发出卷没说的不填”针对的是发出卷没有提出请求的项，这一列不属于这种情况。

但要注意两点：
- 全集是改稿者自己定的值，依据只有一句“随场合而定”。卷二十三的先例是按每个动词分别收窄（如 {private, witnessed}）。
- 同一批里，`visibilityAllowed` 定了值，`perceivable`、`senses` 却留作未决，标准前后不一。

## 三、逐格查未决项（核查项 3）

### 真问题（能定而没定，或依据有误）

1. **优先①的目标没有达成。** 两行仍写着“不并入数据块”；动词表里立嗣整行、谎言揭穿与群体行为的 `payloadShape`、三行的 `worthSlots` 仍是未决。按表 B（`payloadShape`、`worthSlots` 缺写都按 error 处理）和卷十三 :338，加载照样失败。
2. **§2.3 的依据写错了。** 原文“按表 B 的 onUnknown 分别取 0、空表、假、空集（都不致加载失败）”与表 B 不符：表 B 这四列的 onUnknown 都是 `error`（11-14 缺失处置对齐之后），“无则写 0 / 写 `[]` / 写假”是要求在行上显式写出的值，不是缺省值。另外，如果真按“假”去写，斗殴开始、成婚这类事件就没有亲历者（卷二十二 R22-2.2），这种暂代值本身也不对。
3. **以下各格能定而没有定：**
   - `sigBase` 写 0、`tallies` 写 `[]`：表 B 原文就规定“无则写 0”“没有写 []”，卷二十三的先例也是这样写；本卷没有任何规则给出基值或累计口径。
   - 离异、分家、遗产分配的 `worthSlots` 写空表：同一张表里，成婚（聘礼、嫁妆由合同事件计）、授予荣誉、传承解锁（费用经账本）都以“经账本或合同另计”为由写了空表；这三行的理由完全相同，却标了未决。
   - 在编 `hyper` 取 `hk_member_of`：数据块里凡是 `membership` 为真的行，不是 `hk_member_of` 本身就是它的下位词，没有例外。
   - 在编 `pins` 取 `pside_none`：§5.3（:1318）明文规定“成员类边……都不钉住”。
   - 在编 `concluded` 取假：卷十三 R13-10.2 规定征召兵“按数开在编边”，不经同意动作；如果取真，按 R18-1.5 征召就开不了边。同类的受雇行 `hk_employed_by` 这一格也是假。
   - 在编 `vacated`、`defected` 取 `ho_close`：上位词 `hk_member_of` 与成员类各行（商号成员、信奉、公民）都是这样取。R13-10.2“合同了结，在编边随之关闭”说的是离任一路。
   - 在编三个传导系数：§4.1.5 自己说明主列的传导系数“为占位”，可以取上位词 `hk_member_of` 的值（0.4 / 0.1 / 0.5）。
   - 手持 `defected` 取 null：持有者指向物、不存在脱离含义的行（`hk_possesses`、`hk_cursed_by`、`hk_enshrined_in`）都取 null。
4. **R18-1.12“写一条新边前求值”会放过超限。** “手数之和不超过可用肢端数”这一条件，按写入前的状态求值不包含新边，因此一只手已占用时再拿双手兵器也能写进去。应改为对写入后（含新边）的状态求值。此外，每条边各自重算一个合计条件时，会把同一人的全部手持边一起关闭；而 R13-5.2 举的例子是只放下那件占两只手的兵器，先关哪一条要有规则。
5. **小项：** 在编 `gone` 的依据引了 R13-10.2，而这一条讲的是合同了结（属于离任一路），不是持有者终止。值本身（`ho_close`）没有错，依据引错了。

### 确需新设计，须报李白

- 手持 `holdWhile`：要卷十三（或卷四）先登记两个可读的派生维度，一个是“可用肢端数”，一个是“现役手持边所占 `hands` 之和”，并一并定下超限时先放下哪一件。还要留意有效完好度如果随时间连续变化，按 §3.6 不能用事务推动求值。
- 手持、在编的 `functional`：两种取法都有先例（受雇为真，成员为假），卷十三没有给出依据。
- 各动词的 `perceivable`、`senses`：要逐个动词设计（卷二十三是逐行定的）。
- 立嗣整行：本卷除名单外没有立嗣的规则，是保留这一行还是删掉，要先定。
- 谎言揭穿的 `lieId`、群体行为的 `subjectRef`：类型要由卷二 §1.5 定。§1.5 写明“扩展须改本卷并报李白”；`subjectRef` 是实体与事件的联合，按 §1.5 的规定，两种字串形态不能放进同一个 `anyOf`。
