# ③ 停报理由

**前提**：`kindFrom` 只能指动词。卷二十四:163 写“`payloadShape` 里类型为 `ref vocab verb` 的字段”；:181 表 C 三栏类型是 `ref vocab verb`，onUnknown 为 `error`。

**1) 为什么分不清（例子）**：如果不新登动词，又要给 `kind` 填一个演出专属的值，就只能借现有动词，比如 `showBegun`。事件流如下：
1. `instanceStep` 建好演出实例，发出 `instanceStart`，载荷 `kind=showBegun`。
2. 按 R24-2.10（:413），“`isA(event, A)` 当且仅当动词本身或所指动词 `isA` A”，这条起始事件也算作 `showBegun`。
3. R24-2.2（:405）说“订阅一个动词即订阅它的全部下位词（含 R24-2.10 合看的那些事件）”，所以起始事件会被当成 `showBegun` 送到订阅方。
4. 宣布阶段的催化是 `{verb: showBegun, whenRX: 恒真, points: 1}`，`advanceAt` 1（卷二十三:202）。按 R24-4.3（:491），实例刚起始就被自己的起始事件加到 1 点，主办还没开演就转入演出阶段，宣布阶段被跳过。
5. 同理，R24-3.5（:450）的累计会把 `showBegun` 的 `tallies` 多记一次。

另一种做法是 `kind` 填通用动词本身。这时订阅方按 `kind` 分不出演出和宴饮（只核报告:32）。

**2) 三个“从不发出”的子类型动词行做什么用**：它们只作 `kindFrom` 所指的动词，并参与合看：
- 上位词判定：经 `parent`（:162）参与 `isA`；
- 分量基值：R24-2.5（:408）取两行 `sigBase` 的较大者；
- 累计：两行 `tallies` 之并（:413）；
- 订阅方可以按它们只订演出。

这三行从不被发出，所以它们在 R24-2.1（:404）“每个动词恰有一个登记的发出系统”下算什么身份，现在没写。这就是只核报告的记账 k5。

**3) 不登会断在哪里**：
- `startVerb` 等三栏找不到动词，加载报错（:181 onUnknown 为 `error`）；
- R24-2.1（:404）加载核对 `kindFrom` 所指字段，填不进合法值；
- 起始、换阶段、收场三步（R24-4.1 :489、R24-4.3 :491、R24-4.5 :493）的载荷 `kind` 没有值可取。

**替代办法：不登新动词**

可以让 `kindFrom` 改指非动词的子类代号，例如直接用 `event_type` 行的句柄 `roles.types.show`。代价是：
- 要改卷二十四:163、:181 的类型；
- R24-2.10 要从表 C 行取 `isA`、`sigBase`、`tallies`，而表 C 行没有这三项，得给表 C 加字段；
- 终止、复生的 `kindFrom = cause` 仍然指动词（:163），合看就有了两类所指、两套口径；
- 这属于新设计，要改卷二十四，还牵连卷二十的灾异行（C24-6 :806）。
