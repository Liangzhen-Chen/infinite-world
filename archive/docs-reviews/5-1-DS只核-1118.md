### 必须改

**1. 规则层 import 了 kernelApi 表外的 `T`（E-VIEW-INPUT-IMPORT）**

- 文件:行：`server-plugin/primitives-runtime.mjs:16` `import { T } from './kernel/handles/markers.mjs'`；`:103–:111` 的 `TYPE_CHECK` 与 `:59–:67` 的 `CATALOG` 用它取类型名。

- 查证：`world/ontology/state-owners.json` 的 kernelApi（56 条）与卷二 §2.7 :577 起的清单都没有 `kernel/handles/markers.mjs#T`；`T` 没有 `callers: ["rules"]` 登记。

- 改法二选一（要主会话/李白定）：① 卷二 §2.7 kernelApi 增 `kernel/handles/markers.mjs#T`、callers `["rules"]`，并同步 `world/ontology/state-owners.json`；② 不 import `T`，改用已登记入口，或按卷二 §2.9 S13(d) 允许的文法记号写法。

**2. kernelApi 新登 `runTransaction` 没有卷二 §2.7 的对应条目**

- 卡文重点一原问：是否有卷文依据，或应经别的已登入口开事务。查现清单，规则层可用的入口里没有能开事务的；`submitProposal` 只对 inputEdge。即执行器要自开事务，就必须给卷二 §2.7 补一条（照 B5-0 勘误 1118k25 的做法，world 数据与卷二同改），否则是表外新增。

**4. 契约的代号文法校验比卷二 §1.9 宽，48 字符上限缺失**
