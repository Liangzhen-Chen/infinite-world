## 真问题

**P1 C22-2：缺口理由不实，按纯登记应当全做。** 新增的 §2.2 条（:402）和附录 D（:2522）说"本卷现无对外的逐项解释入口（附录 B 的 `explain` 只是算例的一列）"，`explain(target, subject)` 是新入口、属机制。这与卷二原文不符：`kernel/dimensions.mjs#explain` 已经登记在 §2.7 kernelApi（:505，callers rules），§3.3（:1150）也已定义它返回 `[{stage, id, source, value, penalty, before, after}]`。C22-2 请求的后一半是"修正项的来源取现有 `explain` 的逐项 `source`"，只是约定现有入口怎么用，不改 Fact 形状，没有超出收尾待办:304"只许约定现有字段"的范围。改法：§2.2 那一条补上"修正项的逐项来源取 §3.3 `explain` 返回的逐项 `source`（实体与代号）"，删掉不实的那句；附录 D 的 C22-2 行改为全做；落地数相应改为全做 8、部分 8。

**P2 §5.6 `hiddenness` 行写了常量缺省。** onUnknown 栏写"skip（按 0）"，这与 §1.6"无任何常量缺省"相抵：skip 的语义是整个实体被排除，不是按 0 参与。全卷只有这一处。这也和本批处理卷二十四表 C 缺省的口径不一致。改法：删去"（按 0）"，或者改成 `always | error`、行上显式写 0（与表 C 同一口径，推荐这一种）。卷十七 §2.3 :175 的同一写法须一并对齐，与卷二十四同列为待办。

**P3 §5.22 `venueRX` 行与表后一段自相矛盾。** 行上登的是 `never | skip`。表后一段却说表 C 的缺省（含"`venueRX` 不设限"）"按 §1.6 改为行上显式写，上表据此登记"。二选一：行改为 `always | error`、写 null 即不设限（推荐，与段落一致）；或者从段落里去掉 `venueRX`。

**P4 §2.6"行改挂"一条只收窄了一半。** C17-5 ④ 把首句收窄成只管地点表，但同段末句"凡实体还是同一个、只是换了地方的，一律用本原语，不得用终止加新建代替"仍然覆盖一切实体，与人物经 `placeSubject` 换地点相抵。改法：末句改为"凡地点行还是同一行、只是换了挂靠位置的……"。这是同段的同类残留，须同批改完。
