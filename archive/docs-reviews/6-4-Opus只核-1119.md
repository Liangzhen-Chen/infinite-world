**M1 新增两种未建登记 families、fields 没有卷二勘误（重点 3）**
- 卷二 §1.12 :390（entries，勘误 1118k23）、:391（columns，勘误 1119k3）、:399 第 6 点（names，勘误 1118k31）：`_unbuilt-derived.json` 的每一种登记都是先在卷二写成"唯一定义"，再落代码。本卡新增的两种只写在 JSON 的 note 和 server-plugin/kernel/validate/dimensions-validate.mjs 新增的 readUnbuiltFamilies、readUnbuiltFields、refsFamily 里（diff 中 :218–:273），卷二没有对应条文。families 有主会话裁定，但裁定代替不了已封卷的勘误；fields 是写者自己加的（回报"偏离"第 4 条）。
- 两种都不是多余的：fields 管的是词表族条目字段，columns 管的是表的维度列，不重复。体例与 names、columns 一致：四字段，缺字段、重复、族已建成仍登记都会报错。空串、null、通配都绕不过去：族名要过 CODE_RE，空前缀会和已有前缀冲突；字段要过 KEY_RE，缺值只有在 `undefined` 时才放行，写成 null 照样报 E-DIM-STRUCT-FIELD。
- 下面两处行为比 1119k3 宽，勘误必须写清楚：
  ① dimensions-validate.mjs 中 `for (const [k, d] of Object.entries(t.doc.dimensions)) if (… refsFamily(d, unbuiltFamilies)) t.unbuiltColumns.add(k)`：只要维度类型里任何一层引用了未建族，整个维度就自动免掉必填核对。1119k3 定的是按（表，维度）逐条登记在 columns 里。
  ② types.mjs :192/:200：行上的值如果引用未建族，查 `vocab.index` 查不到，会被拒。这和 1119k3 的"旧数据有的值照转保留、照常校验"冲突（6-23 转换时会碰到）。
- 改法：交卷二 §1.12 封卷后勘误（改前快照，不升版本），定义 families 与 fields 的字段、错误码和放行范围；fields 要有裁定依据（报李白，或主会话裁定后照写）。建议 families 只负责放行表头类型引用，行上必填的放行仍走逐条 columns，不另开自动放行这条路。勘误合入前本卡不封。
