# 验证分层方案（FASTV）

目标：一次合并检查不再默认跑全量 533 个测试文件（m2-3 实测 06:24–11:37Z，6 路并行，5 小时 13 分）。不降低任何检查强度、不放宽断言、不加机器；全量仍在阶段收尾、合入正式主线前、夜间完整跑。

数据来源：`F:/dnd-tmp/m23/full.full`（533 文件，总 112681 秒，6 路并行 = 18781 秒 = 5h13m，与实际墙钟一致）与 `F:/dnd-tmp/b1m1/full.full`（527 文件，总 96863 秒）。本文所有"改造后"数字都是静态推算，没有运行任何测试。

## 1 分层规则

| 层 | 何时跑 | 内容 | 入口 |
|---|---|---|---|
| T0 冒烟 | 每次合并必跑 | `tools/smoke-tests.json` 的 `tests`（160 个，单个 ≤60 秒，覆盖 130 个子系统家族） | `--smoke` |
| T1 影响集 | 每次合并必跑 | 受改动影响的测试（`tools/affected-tests.mjs` 静态算出）去掉夜间专属（`nightlyOnly`，32 个耗时 ≥1000 秒或超时的） | `--tier merge` |
| T2 全量 | 阶段收尾、合入正式主线前、每夜 | 全部测试，含夜间专属 | `gate.sh run <dir> 6 --all`（现状不变） |

T1 的意义：夜间专属不是被放弃，而是推迟到夜间；脚本把被推迟的测试以 `# deferred` 行与 stderr 计数列出，合并记录里必须写明"推迟 N 个，最近一次全量对应提交 X"。

## 2 影响范围算法（`tools/affected-tests.mjs`）

输入：`git diff --name-only <base> <head>`（或 `--files a b c`）。输出：测试文件列表（stdout，一行一个）；`--why` 加每个测试的理由链（`测试 -> 中间文件 -> ... -> 改动文件`）；`--json` 机器可读；`--per-file` 看每个改动文件选中几个测试。

1. **依赖图**。对 `.mjs/.js/.cjs` 文件解析：静态 `import/export from`、字面量 `import('...')`、所有字符串字面量（含 `path.join/resolve` 多段拼接、模板字面量静态前缀）按"本文件目录/仓库根/`world/`"三个基准解析到的已跟踪文件或目录。命中文件 = 依赖该文件；命中目录或文件名前缀 = 该目录下任何改动文件都算相关（readdir、整目录读取、通配类测试因此被任何子文件改动选中），但**不把目录里的脚本拉进依赖闭包**（读取不是执行）。
2. **选中**：测试的传递依赖闭包（自身、import 的、读取的，递归）含任一改动文件即选中。
3. **世界数据**：`tools/load-world.mjs` 以动态根读取 `world/`，所以凡闭包含 load-world 的测试依赖整个 `world/`，**唯独 `world/drafts/**` 除外**（创作草稿，loadWorld 不读，只有字面量显式提到才算）。`world/` 下任何其它数据改动 → 选中全部依赖 loadWorld 的测试（实测约 516/527）。不做字段级映射：加载器本身会校验全部文件，任何数据文件出错都会让所有用到它的测试失败，字段级映射只能靠猜。
4. **全局文件**：仓库根的 `package.json`、`package-lock.json`、`.gitattributes`、`.npmrc`、node 版本文件 → 全部测试；根目录出现未知文件、或顶层目录不在已知集合（server-plugin tools tests world docs schemas prompt extension assets 跑团资料）→ 全部测试。
5. **没有任何测试依赖的改动文件**（例如 `tools/cloud/**`）不选任何测试，但会在 `--why/--json` 中列为 `unmapped`，不会静默丢弃。
6. **删除的文件**：闭包里仍读取其所在目录的测试被选中。
7. **非字面量动态导入**（`import(表达式)`，排除 `engine.import(bundle)` 方法调用与 npm 包）视为不透明：该文件被当作导入了自己所在目录及其字面量所指目录下所有脚本。
8. 保守原则：判断不了的一律选中。本工具与 `tools/build-smoke-set.mjs` 自身不入图（它们对整目录的读取会回环到所有测试）。

### 诚实的局限（重要）

- `server-plugin/index.mjs` 与 `storage.mjs` 是中枢：299 个插件模块里每一个的改动都选中 516/527 个测试。**影响分析对引擎/世界数据类改动几乎不省时间**，对 `tests/`、`tools/` 中不在引擎链上的文件、`docs/`、`world/drafts/` 才有效（实测：改一个测试文件选 ~64 个，改 docs 选 ~53 个，改 `world/drafts/**` 选 ~65 个）。
- 因此 T1 的主要节省来自"夜间专属推迟"，不是影响分析。
- 更细的第二阶段（尚未做）：在云上对全量做一次 `NODE_V8_COVERAGE` 插桩，得到"测试 → 实际执行过的函数区间"，再按改动行区间选测。需要一次约 5 小时的插桩全量；模块顶层语句（常量表）的改动仍会选中所有 importer。收益未知，需插桩后才能估算。

## 3 冒烟集（`tools/smoke-tests.json`，由 `tools/build-smoke-set.mjs` 生成）

- 依据：两份全量日志里都通过（exit=0）且每次 ≤60 秒的测试；按文件名第一个 `-` 前的词分成 130 个家族（a3、s5、magic、npc、w2、farm、engine、storage……每个子系统一族），每族取"通过子测试数 / 耗时"最高的 2 个，并列按文件名。可复现：`node tools/build-smoke-set.mjs <full.full>... > tools/smoke-tests.json`。
- 数量：160 个。耗时（取两次日志的较大值求和）：1497 秒，按 m2-3 日志秒数 6 路最长优先推算墙钟约 244 秒（约 4 分钟）。
- 夜间专属判据同一脚本给出：任一日志里超时（exit=124）或 ≥1000 秒，共 32 个；合计秒数口径不同：smoke-tests.json 的 basis 为 77179 秒（取每个测试在两份日志中的较大值求和），m2-3 日志口径为 75504 秒（仅 m2-3 日志）。本文推算用 m2-3 口径。阈值是脚本顶部常量，可调（见 §5 的取舍）。

## 6 m2-3 实例演示（静态推算，`t-int..t-m3`，59 个改动文件）

- 影响集：527/527 全选（口径：按 t-int 的 527 个测试文件算；m2-3 日志 533 个，含新增 6 个，耗时数字以日志为准）（`--why` 理由链保存在运行输出；world 数据与插件模块均经 loadWorld/storage 链命中）；`--tier merge` 后 498 个，推迟 29 个。
- m2-3 的 39 个新失败（`diff-vs-b1m1.txt`）：**39/39 全在影响集内，无漏选**。其中 38 个在 T1 内；`s5-law-public-maintenance`（753 秒变超时）属夜间专属，会推迟到夜间才发现——这是推迟的明确代价，不是影响分析的缺口。
- 规则缺口检查：两个实现期缺陷已修正并写入脚本——① 目录读取曾被当作执行（导致一个 docs 改动选中全部测试）；② `engine.import(bundle)` 方法调用和 npm 包动态导入曾被当作不透明导入。
- 建议配套（未实现）：夜间报告里对比相邻两次全量的逐文件秒数，涨幅 >3 倍标红（本次 s2c-estate 43→1494、s5-law-public-maintenance 753→超时、s5-law-tenancy-sharing 1097→2400）。

## 7 落地步骤

1. 合并检查：`ssh ... run <dir> 6 $(node tools/affected-tests.mjs <base> <head> --smoke --tier merge)`。stdout 每行一个测试路径，门禁已有"最长先跑"排序，**无需改 gate.sh / 门禁**。门禁 `run` 的 hash 绑定、两轮审查不变。
2. 阶段收尾、合入正式主线、夜间：`run <dir> 6 --all`（不变）。
3. 每次完整全量后重新生成冒烟集与夜间专属名单：`node tools/build-smoke-set.mjs <最新 full.full> <上一份> > tools/smoke-tests.json`（改了会改变 hash，需再审）。
4. 需要李白决定：HEAVY_SECS 阈值；是否给门禁加 `--test-name-pattern` 以拆并行；是否做 §2 的覆盖率第二阶段。

## 8 门禁清单与耗时回归哨兵

- 合并层 = 影响集 + 冒烟（`--smoke --tier merge`），被推迟的重测试以 `# deferred` 行列出并写入合并记录。
- 合入正式主线（t-int / master）之前必须跑一次全量（`--all`），并通过哨兵。
- 每晚全量；全量结束后自动跑 `node tools/perf-sentinel.mjs <上一次全量.full> <本次全量.full>`，结果写入夜间报告。
- 哨兵（`tools/perf-sentinel.mjs`）逐文件对比秒数：标出 NEW-TIMEOUT（新超时）、SLOWER（涨 >3 倍且现 ≥60 秒）、RECOVERED（基线超时现完成）；有新超时或大幅变慢时退出码为 1。以 b1m1 对 m2-3 试算：22 项告警（含 s5-law-public-maintenance 新超时、s2c-estate 43→1494 秒）。
- `affected-tests.mjs` 的 `git diff` 已加 `--no-renames`，重命名的旧路径也计入改动。
- 补正（fv-2）：`--tier merge` 时被改动的重测试本身不推迟；`--json` 含 `deferred`；`--tier` 非 merge/full 报错退出；哨兵在当前日志为空、无 FINISHED 行或缺少基线文件时失败退出，基线快速失败（exit≠0 且 <60 秒）单列 BASE-FAILED 不判变慢。
