### 第 3 条 执行器：卷九 `execute` 在 `primitives-runtime.mjs`，卷二 kernelApi 登 `kernel/primitives.mjs#applyPrimitive` 【部分有据】
- **有据：入口名用 `execute`。** 卷九 :652 定唯一写入口 `execute`，只由 `resolve()` 提交段与推进钩子的调度方调用；卷九 :496、:503 同。建议 kernelApi 删 `applyPrimitive` 一行，入口名改为 `execute`，走卷二勘误。
- **无据：执行器归哪个组。** 卷九 :652、:496 只写文件名 `primitives-runtime.mjs`，不写组；把它归 kernel 的唯一出处是 M2-38（卷二 :2284），这一行已随方案 §2.2 R3 退役。可供判断的事实有两条：推进钩子的输出清单由"钩子的调度方"交 `execute` 执行（卷九 :661 R9-2.6），调度方是 `kernel/scheduler.mjs`（推断：卷九 :661 原文只写"钩子的调度方"）；而 kernel 不得 import 规则层（卷二 :796）。选项：
  - A（建议）：`execute` 放 kernel 组（`kernel/primitives-runtime.mjs`），在 kernelApi 登记给 `resolve()` 所在文件。代价：要卷二勘误；执行器所调的各适配器、各卷入口也要经 kernelApi 或登记交入，不能直接 import 规则层。
  - B：`execute` 放规则层。调度器要调它时，像 `registerAdvanceHook` 那样由规则层登记交入，需新增一个登记函数。代价：kernelApi 多一个登记入口；执行器与内核事务的边界要另写清楚。
- **排期**：不变（块 5 内容）。
