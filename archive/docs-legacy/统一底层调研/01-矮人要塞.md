## 0. 摘要

《矮人要塞》(DF) 的"统一底层"不是一个引擎抽象，而是**三层数据 + 两类运行时对象**：

1. **材料（material）是万物的公分母。** 一种材料用同一张属性表描述：密度、熔点/沸点/燃点/比热、六种应力（冲击、压缩、拉伸、扭转、剪切、弯曲）各自的屈服/断裂/屈服应变、最大锋利度、价值倍率、各物态下的名字与颜色、用途标记（可做武器/盔甲/家具/可食……）、反应类别与反应产物、附带综合征、所属领域。石头、金属、木材、皮肤、骨头、血液、酒、毒液、天气云，全部是这张表的实例，差别只在填的数字和标记。模板（material_template）负责把共性抽出来，具体材料只写差异。（第 2.1 节）
2. **身体是材料的分层组合。** 生物 = 身体部件图（BODY 模板拼接）+ 细节计划（把组织层按顺序贴到部件上，并可带参数）+ 组织模板（每种组织指向一种材料，并声明自己是否出血、是否承重、是否有痛觉等）+ 材料模板。因此"用什么材料做身体"是一个参数：遗忘兽可以是石头、金属、宝石、气体做的，用的是同一套结构。（第 2.3 节）
3. **物品 = 类型 + 子类型定义 + 材料引用 + 质量/磨损/装饰。** 运行时所有物品共享一个基类（位置、重量、磨损、堆叠、温度、引用表），再按"是否制造物"分层，具体类型只追加极少字段（武器多一个锋利度）。有 raw 子类型定义（itemdef）的只有 14 类（武器、盔甲、工具、乐器、玩具、弹药、陷阱部件、食物等）；床、门、桌、条块、石头等无 raw 定义，是硬编码类型。（第 2.2 节，第 6 节）
4. **行为由公式从维度推出，而不是逐物写死。** 战斗：攻击动量由攻击者体型、力量、武器密度×体积算出，再与目标每一层组织/盔甲材料的剪切或冲击屈服/断裂值比较，决定切开、钝化还是弹开；价值：基础值 × 材料倍率 × 质量倍率 + 装饰；温度：按比热向环境靠拢，过熔点/燃点就熔/燃；reaction：原料按 `REACTION_CLASS`、`MATERIAL_REACTION_PRODUCT`、物品类型、材料标记匹配，产物可"继承原料的材料"。（第 3 节）
5. **社会层也是统一结构。** 文明、城邦政府、宗教、公会、商会、剧团、军队、流民团都是 `historical_entity` 的一个 `type`；国王、神、吸血鬼、史诗诗人都是 `historical_figure`，神只是多了 `deity` 标记和一个领域列表；人物↔人物、人物↔实体的关系是两张链接表（父母/配偶/主仆/崇拜神……；成员/职位/囚犯/敌人……）。（第 2.4、2.5 节）
6. **领域（sphere）是一个约 130 词的受控词表**，带父子/友好/不相容关系，神祇、巨兽、生物、神金、地区邪恶、庙名、文明宗教倾向都挂在它上面。（第 2.6、3.5 节）
7. **世界生成复用同一套 raw：** 遗忘兽、泰坦、恶魔、天使、夜生物、神金在生成时写成带 `[GENERATED]` 标记的普通 raw，存进存档，之后走与手写生物完全相同的代码路径。新增一种生物/物品/文明只需填 raw 并在文明里登记许可。2025-07 的 52.01 版把这些生成器本身也开放为 Lua 脚本，官方承认之前约 15 年它们是硬编码的。（第 5 节）
8. **局限同样清楚：** 行为本身大多硬编码，token 只是开关；无 raw 的物品类型、工坊与建筑类型、劳动/技能/职业枚举、库存分类、贵族职责枚举、伦理枚举都是代码里的固定表；多种族文明不工作；领域词表不可扩展；经济系统停用。（第 6 节）

对 infinite-world 的启示集中在第 8 节：借鉴"材料为公分母、身体为分层、效果层统一、社会对象统一、生成物写回同一数据格式"这五个架构点；不照搬"token 只是开关、硬编码枚举、无单元测试、单线程"等历史包袱。

## 1. raw 文件体系总览：一切对象的共同载体

**什么是 raw。** DF 的游戏内容放在 `data/vanilla/`（旧版 `raw/objects/`）下的纯文本 `.txt` 文件里。每个文件第一行是不带扩展名的文件名，第二个有效行是 `[OBJECT:类型]` 声明本文件只放哪一类对象，之后每行以 `[TOKEN:参数:参数...]` 书写，方括号外的所有文字都是注释。文件名决定读取顺序（影响 `COPY_TAGS_FROM` 这类前向引用），重复的 raw 会报错甚至崩溃。
来源：https://dfwk.ru/Raw ；https://dwarffortresswiki.org/index.php/Raw （英文原页，本次限流未读到正文，由搜索摘要确认位置）

**对象类型（OBJECT）一览**，每类一个或多个文件：

| OBJECT 类型 | 内容 | 典型文件 |
|---|---|---|
| `MATERIAL_TEMPLATE` | 一组材料的共同属性 | material_template_default.txt |
| `INORGANIC` | 石、矿、宝石、金属、土 | inorganic_stone_*.txt, inorganic_metal.txt |
| `PLANT` | 植物及其派生物（酒、种子、线、木） | plant_*.txt |
| `TISSUE_TEMPLATE` | 组织模板（皮、脂、肌、骨……） | tissue_template_default.txt |
| `BODY` | 身体部件模板 | body_default.txt, body_rcp.txt |
| `BODY_DETAIL_PLAN` | 把材料、组织层、位置贴到身体部件上 | b_detail_plan_default.txt |
| `CREATURE` | 生物 | creature_*.txt |
| `CREATURE_VARIATION` | 对生物的模板化改写（巨型、兽人化） | c_variation_default.txt |
| `ITEM` | 14 类有子类型的物品定义 | item_weapon.txt, item_armor.txt … |
| `REACTION` | 工坊配方 | reaction_*.txt |
| `BUILDING` | 自定义工坊/熔炉 | building_custom.txt |
| `ENTITY` | 文明与其他社群 | entity_default.txt |
| `LANGUAGE` | 词、符号组、翻译 | language_words.txt, language_SYM.txt, language_DWARF.txt … |
| `INTERACTION` | 交互（诅咒、复活、呼吸攻击、天气） | interaction_*.txt |
| `DESCRIPTOR_COLOR / PATTERN / SHAPE` | 颜色、花纹、形状描述词 | descriptor_*.txt |
| `GRAPHICS` | 图块（不在 objects 下） | — |

来源：https://dfwk.ru/Raw

**运行时对应。** df-structures 的 `world` 结构里有一个 `raws` 复合体，为上述每类各放一个"处理器"：无机物、植物、生物、生物变体、身体细节计划、身体模板、组织模板、物品定义、反应、交互、实体、语言、描述词、材料模板、建筑定义，另有文本集、音乐、随机对象与材料表。全局对象表（实体、单位、物品、历史）与之并列。
来源：https://raw.githubusercontent.com/DFHack/df-structures/master/df.world.xml

**要点：** DF 没有"系统各自的配置格式"。所有内容类型共用一种语法、一种加载器、一个 `world.raws` 容器；不同对象类型之间靠 token 的字符串 ID 相互引用（`USE_MATERIAL_TEMPLATE:STONE_TEMPLATE`、`BODY:HUMANOID`、`CREATURE:DWARF`、`PERMITTED_REACTION:MAKE_STEEL`）。

## 2. 统一维度

### 2.1 材料（material）：所有实物共享的一张属性表

**raw 层：材料 token 全表。** 下表来自材料定义 token 页（镜像）。每个无机物、植物材料、生物材料都可以写这些 token；写在模板里再被 `USE_MATERIAL_TEMPLATE` 继承，后写的 token 覆盖模板值。
来源：https://dfwk.ru/Material_definition_token （英文原页 https://dwarffortresswiki.org/index.php/Material_definition_token 限流未读）

| 维度 | token | 含义 / 默认值 |
|---|---|---|
| 密度 | `SOLID_DENSITY`, `LIQUID_DENSITY`, `MOLAR_MASS` | 固/液密度 kg/m³；摩尔质量本意用于气体，页面注明大概未用 |
| 热 | `MELTING_POINT`, `BOILING_POINT`, `IGNITE_POINT`, `SPEC_HEAT`, `HEATDAM_POINT`, `COLDDAM_POINT` | 熔点、沸点、燃点、比热（NONE 则温度钉死）、热/冷损伤阈值 |
| 冲击强度 | `IMPACT_YIELD`, `IMPACT_FRACTURE`, `IMPACT_STRAIN_AT_YIELD` | 屈服/断裂（kPa，默认 10000）、屈服应变（十万分之一，默认 0） |
| 压缩 | `COMPRESSIVE_YIELD/FRACTURE/STRAIN_AT_YIELD` | 同上 |
| 拉伸 | `TENSILE_YIELD/FRACTURE/STRAIN_AT_YIELD` | 同上 |
| 扭转 | `TORSION_YIELD/FRACTURE/STRAIN_AT_YIELD` | 同上 |
| 剪切 | `SHEAR_YIELD/FRACTURE/STRAIN_AT_YIELD` | 同上，**切割伤害用它** |
| 弯曲 | `BENDING_YIELD/FRACTURE/STRAIN_AT_YIELD` | 同上 |
| 锋利 | `MAX_EDGE` | 可达的最大锋利度，默认 10000；石头≥10000 才能做武器 |
| 吸水 | `ABSORPTION` | 容器需上釉才能装液体 |
| 物态命名 | `STATE_NAME`, `STATE_ADJ`, `STATE_NAME_ADJ`, `STATE_COLOR`, `DISPLAY_COLOR` | 按 SOLID/LIQUID/GAS/POWDER/PASTE/PRESSED 六种物态分别给名词、形容词、颜色；有 ALL / ALL_SOLID 简写 |
| 用途标记 | `IS_METAL`, `IS_STONE`, `IS_GEM`, `ITEMS_WEAPON`, `ITEMS_ARMOR`, `ITEMS_HARD`, `ITEMS_SOFT`, `ITEMS_METAL`, `EDIBLE_RAW`, `EDIBLE_COOKED`, `EDIBLE_VERMIN` … | 决定材料能被哪些工坊、哪些成品、哪些库存分类使用 |
| 价值 | `MATERIAL_VALUE`（默认 1）, `MULTIPLY_VALUE` | 价值倍率；负值表示买方倒贴 |
| 反应接口 | `REACTION_CLASS`, `MATERIAL_REACTION_PRODUCT`, `ITEM_REACTION_PRODUCT`, `HARDENS_WITH_WATER` | 分类名（FLUX、FAT、SOAP、CAN_GLAZE…）；"本材料经某反应变成哪种材料/哪种物品" |
| 效果 | `SYNDROME` … | 接触/吸入/注入/食入后触发的综合征（见 2.8） |
| 领域 | `SPHERE`, `DIVINE` | 无机物页记载：神造实体可用的材料并挂到一个领域 |

无机物专属 token（决定地质分布与冶炼）：`SEDIMENTARY / METAMORPHIC / IGNEOUS_INTRUSIVE / IGNEOUS_EXTRUSIVE / SOIL / SOIL_SAND / SOIL_OCEAN / AQUIFER / LAVA`（成层方式）；`ENVIRONMENT:层类:CLUSTER|CLUSTER_SMALL|CLUSTER_ONE|VEIN:频率` 与 `ENVIRONMENT_SPEC:具体石:…`（矿脉/矿簇分布）；`METAL_ORE:金属:概率`（每块矿石掷四次 d100，成功一次出一条金属）；`THREAD_METAL:金属:概率`（可抽丝，精金用）；`WAFERS`（出薄片不出条块）；`DEEP_SPECIAL / DEEP_SURFACE / SPECIAL`（通向地底的特殊石；SPECIAL 使 AI 文明不用它做东西、不交易、生成生物不用它做身体）；`DIVINE / SPHERE`（神金）；`MYTHICAL*`（v51 beta 新增）；`GENERATED`（引擎自标，raw 不可写）。
来源：https://dwarffortresswiki.org/index.php/Inorganic_material_definition_token （英文原页，本次成功读到）

**运行时层（df-structures `material`）。** 运行时的 `material` 结构字段与 raw token 一一对应：ID 与宝石/石头名；热属性组（比热、热/冷损伤点、燃点、熔点、沸点、固定温度，均为 16 位无符号）；固/液密度与摩尔质量；按物态索引的颜色/名词/形容词数组；吸收值、按应力类型索引的屈服/断裂/屈服应变数组、最大锋利度；基础价值与按 `material_flags` 索引的标志数组；屠宰/食物相关（提取物容器类型、特殊屠宰品、肉名、块名）；反应产物组（类别 ID、物品类型/子类型、材料引用、字符串）、遇水硬化组、反应类别列表；显示（tile、颜色、RGB、染料、饮食信息）；综合征容器；肥皂等级、领域类型、前缀、食物材料索引、材质贴图位置。`material_template` 是同一结构的精简版（去掉 RGB、前缀、贴图等）。

**材料引用方式 = (mat_type, mat_index) 二元组。** 运行时任何地方指一个材料都用一对数：16 位 `mat_type` + 32 位 `mat_index`；类型区分内建材料 / 无机物 / 生物材料 / 植物材料，索引选具体一个。物品、组织、尸体材料、骨材料、肉材料、提取物、分泌物、反应产物、"遇水硬化"都用这一对字段，许多地方用 `aux-value` 机制把两者绑定。
来源：https://raw.githubusercontent.com/DFHack/df-structures/master/df.material.xml ；https://raw.githubusercontent.com/DFHack/df-structures/master/df.creature.xml

**结论：** 材料是 DF 唯一真正"跨所有系统"的维度。地质（无机物成层）、冶炼（METAL_ORE）、战斗（六种应力）、温度（熔点/比热）、经济（MATERIAL_VALUE）、库存与工坊许可（ITEMS_*、IS_*）、医疗（HARDENS_WITH_WATER）、毒理（SYNDROME）、宗教（SPHERE/DIVINE）全部读同一张表。

### 2.2 物品（item）：运行时类层级与 itemdef 子类型

**运行时类层级（df-structures `df.item.xml`）。**
- 基类 `item`：位置、两组标志位、id、年龄、通用引用表 `general_refs` / `specific_refs`、重量（仅在"已计算"标志置位时有效）、库存倒计时、世界数据引用、缓存温度。
- `item_actual`（继承 item）：堆叠数、磨损与磨损计时、生产区、温度、污染物、魔法、历史信息。
- `item_crafted`（继承 item_actual）：`mat_type`/`mat_index`、制作者种族、质量、制作时技能、制作者、杰作事件。
- `item_constructed`（继承 item_crafted）：装饰列表 `improvements`。
- 具体类型只追加极少字段：`item_weaponst` = 子类型指针 + 锋利度；`item_armorst/helmst/shoesst/shieldst/pantsst` = 子类型指针；`item_barst` = 材料 + dimension(默认 150)；`item_boulderst/blocksst/roughst` = 仅材料；`item_liquid_miscst` = 材料 + 液体标志（dimension 继承自 `item_liquipowder`）；`item_powder_miscst` = 材料 + 染料；`item_body_component`（尸体/残肢）= 种族、性别、生死数据、伤口、部件状态、各尸体材料的量；`item_threadst` = 材料 + 染料 + dimension(15000)；`item_clothst` = dimension(10000)；弩炮/投石机零件、管段、陷阱零件为不加字段的 `item_constructed`；`item_coinst` 多一个币批号。
- 虚方法：`getMaterial/getMaterialIndex`、`getActualMaterial`（永不返回种族/等级）、`getRace/getCaste/getPlantID`（仅生物/植物材料）、`getWeaponAttacks`、`getQuality/getOverallQuality/getWear/getStackSize/getTemperature`、`addImprovementFromJob`、`getStockpile`、`getCorpseInfo`。
来源：https://raw.githubusercontent.com/DFHack/df-structures/master/df.item.xml

**子类型定义（`df.itemdef.xml`）。** 基类 `itemdef`：id 字符串、子类型序号、标志（目前只有 generated）、来源历史人物/实体、原始 raw 行、雕像贴图；虚方法负责解析 raw 行、归入子类型列表、算基础价值、建立材料信息、暴露给 Lua。`itemdef_type` 枚举只有 14 个：Weapon, Toy, Tool, Instrument, Trapcomp, Armor, Ammo, Siegeammo, Gloves, Shoes, Shield, Helm, Pants, Food。
- `itemdef_weaponst`：名称、体积、最小体型、双手体型、材料用量、价值、近战/远程技能、弹药类、射力、最大射速、装填方式、瞄准难度、装填/射击时序、按属性/技能的力量修正、标志（可用石做、有刃、训练用）、攻击列表。每个 `weapon_attack`：有刃标志、接触面积、穿透尺寸、速度倍率、动词、名词、准备/恢复时间、多连击标志。

- `itemdef_toolst`：用途列表、形状、容器容量、默认装饰、很多贴图槽；`itemdef_instrumentst`：乐器部件、音域、音量、发声/定音/调音方法、音色；`itemdef_trapcompst`：命中数、螺旋/尖刺/木/金属标志、攻击；`itemdef_ammost`：弹药类、攻击；`itemdef_shieldst`：格挡率；手套/鞋/头盔/裤：护甲属性；`itemdef_toyst`：硬材料标志；`itemdef_foodst`：配料数等级。
来源：https://raw.githubusercontent.com/DFHack/df-structures/master/df.itemdef.xml

**raw 层：物品 token（武器/盔甲示例）。**
- 武器：`NAME`、`SIZE`（cm³，默认 100）、`TWO_HANDED`（默认 50000 cm³）、`MINIMUM_SIZE`（默认 40000）、`SKILL`（默认 MACE；AXE 兼伐木、MINER 为镐）、`RANGED:技能:弹药类`、`SHOOT_FORCE`、`SHOOT_MAXVEL`、`SHOT_FORCE_REQUIRES`、`AIM_DIFFICULTY`、`LOADED/NOCKED`、`INITIATE_SHOT_TIME`、`SHOT_RECOVERY_TIME`、`ATTACK:EDGE|BLUNT:接触面积:穿透:动词2:动词3:名词:速度倍率`（EDGE 被选中的概率约为 BLUNT 的 100 倍）、`ATTACK_PREPARE_AND_RECOVER`、`ATTACK_FLAG_BAD_MULTIATTACK / INDEPENDENT_MULTIATTACK`、`MATERIAL_SIZE`（必需；精金片数，条块按三分之一）、`CAN_STONE`、`TRAINING`。

### 2.3 生物与身体的分层：BODY → 身体部件 → 细节计划 → 组织模板 → 材料模板

这是 DF 最有代表性的"分层复用"。五层由上到下：

**(a) 生物（CREATURE）** 用少数几行把下面几层拼起来：
- `BODY:模板1:模板2:...` —— 从 body 文件取身体部件模板拼接，如 `[BODY:QUADRUPED_NECK:SPIKE_LAYOUT_8:SPIKE_BASE_THICK:SPIKE_2]` 得到八个粗基座、每座两根刺。空 BODY 会在生成时崩溃。
- `BODY_DETAIL_PLAN:计划名:参数...` —— 载入细节计划，把从皮到骨的组织层贴到部件上，并定义材料。
- `USE_MATERIAL_TEMPLATE:本地材料名:模板名`、`USE_TISSUE_TEMPLATE:本地组织名:模板名` —— 声明本生物的材料与组织（继承模板全部属性，再可覆盖）。
- `TISSUE_LAYER / TISSUE_LAYER_OVER / TISSUE_LAYER_UNDER` —— 单独给某些部件加层（如铁人的内部气体层，受伤后泄漏）。
- `SELECT_MATERIAL / PLUS_MATERIAL / REMOVE_MATERIAL / SELECT_TISSUE / REMOVE_TISSUE / SET_LAYER_TISSUE / TL_*` —— 局部改写。
- `SET_BP_GROUP / PLUS_BP_GROUP / BP_ADD_TYPE / BP_REMOVE_TYPE / RELSIZE / BODYGLOSS` —— 选部件改属性或改描述词。
- `ATTACK:名:BODYPART:BY_CATEGORY|BY_TYPE|BY_TOKEN:部件`，附 `ATTACK_SKILL`、`ATTACK_VERB`、`ATTACK_CONTACT_PERC`（接触面积占部件体积百分比，可超 100）、`ATTACK_PENETRATION_PERC`（需 EDGE，上限 15000）、`ATTACK_FLAG_EDGE`、`ATTACK_FLAG_WITH`、`ATTACK_VELOCITY_MODIFIER`（千分制）、`ATTACK_PRIORITY`（MAIN 被选中概率约为 SECOND 的 100 倍）、`SPECIALATTACK_INJECT_EXTRACT`（把某材料以某物态注入血液，钝击/无血管则喷在部件上，附带综合征转移）、`SPECIALATTACK_INTERACTION`、`SPECIALATTACK_SUCK_BLOOD`。
- `BLOOD / PUS / EXTRACT / EGG_MATERIAL（壳、蛋白、蛋黄三次）/ SECRETION（触发条件：持续、用力、极端情绪）` —— 体液与分泌物也是材料。
- `CASTE / SELECT_CASTE / SELECT_ADDITIONAL_CASTE`、`BODY_SIZE:年:日:克`、`PHYS_ATT_RANGE / MENT_ATT_RANGE`、`PERSONALITY`、`BIOME`、`FREQUENCY`、`SPHERE`、`MEGABEAST / SEMIMEGABEAST / FEATURE_BEAST / LAIR`、`CDI`（可做交互）、`COPY_TAGS_FROM`、`APPLY_CREATURE_VARIATION`、`GO_TO_START/END/TAG`。
来源：https://dfwk.ru/Creature_token （两段读取）；https://dfwk.ru/Body_token

**(b) 身体部件（BODY / BP）。** `BP:ID:单数名:复数名` 定义部件；`CON:父部件` 或 `CONTYPE:UPPERBODY|LOWERBODY|HEAD|GRASP|STANCE` 挂接；`CATEGORY` 自定义类别、`CON_CAT:类别` 挂到所有同类部件（用于批量生成重复结构）；`DEFAULT_RELSIZE` 相对大小（无单位）；`NUMBER`（最多 32 个同名部件，只能整体受伤）、`INDIVIDUAL_NAME`。功能标志：`UPPERBODY/LOWERBODY/HEAD`（全失即死）、`GRASP`（持物、抓斗；无则不能徒手开战）、`STANCE`（站立）、`LIMB`、`JOINT`、`CONNECTOR`、`DIGIT`、`SKELETON`、`EMBEDDED`（表面嵌入如眼，可被挖出）、`INTERNAL`（内脏，不可直接瞄准）、`SOCKET`（易脱落如牙）、`APERTURE`、`PREVENTS_PARENT_COLLAPSE`（颅骨/脊柱）、`SMALL`（遗留）、`LEFT/RIGHT`、`TOTEMABLE`、`VERMIN_BUTCHER_ITEM`；生命功能：`BREATHE`、`CIRCULATION`、`THOUGHT`、`NERVOUS`、`GUTS`、`UNDER_PRESSURE`、`GELDABLE`、`THROAT`；感官：`SIGHT`、`HEAR`、`SMELL`。
来源：https://dfwk.ru/Body_token

**(c) 细节计划（BODY_DETAIL_PLAN）。** `ADD_MATERIAL:本地名:材料模板`、`ADD_TISSUE:本地名:组织模板`、`BP_LAYERS:BY_CATEGORY|BY_TYPE|BY_TOKEN:部件:组织:厚度:组织:厚度...`（也有 `BP_LAYERS_OVER / UNDER`）、`BP_POSITION:...:FRONT|BACK|SIDES|TOP|BOTTOM`、`BP_RELATION:部件:AROUND|SURROUNDED_BY|ABOVE|BELOW|IN_FRONT|BEHIND|CLEANS|CLEANED_BY:父部件:覆盖率`（眼睑 AROUND 眼 50）、`BP_RELSIZE`。**计划可带最多五个参数 `ARG1..ARG5`**，由生物在调用时填入组织名；这就是原版 `VERTEBRATE_TISSUE_LAYERS` 配 `SKIN:FAT:MUSCLE:BONE:CARTILAGE` 的做法——同一份"脊椎动物分层"计划，鱼、鸟、矮人各填自己的组织。镜像页未给出原版调用示例原文，仅说明参数机制。
来源：https://dfwk.ru/Body_detail_plan_token

**(d) 组织模板（TISSUE_TEMPLATE）。** `TISSUE_NAME`、`TISSUE_MATERIAL:材料`（**组织指向一种材料**，物理与价值全部来自材料）、`TISSUE_MAT_STATE`（固/粉/液/气）、`TISSUE_SHAPE:LAYER|STRANDS|FEATHERS|SCALES|CUSTOM`（STRANDS 可纺线，锐器直接穿过；FEATHERS 切割直接穿过）、`RELATIVE_THICKNESS`（相对厚度，抬高一层等于相对压薄其他层）、`HEALING_RATE`（无则永不愈合）、`VASCULAR`（出血量，心脏很高）、`PAIN_RECEPTORS`（骨高）、`INSULATION`、`THICKENS_ON_STRENGTH`、`THICKENS_ON_ENERGY_STORAGE`、`SCARS`、`STRUCTURAL`（承重，断则部件失效）、`CONNECTS`（全断才脱离）、`CONNECTIVE_TISSUE_ANCHOR`（韧带肌腱，切断致残）、`MUSCULAR`、`FUNCTIONAL`（器官功能组织）、`ARTERIES`、`SPLINTABLE`、`SUBORDINATE_TO_TISSUE`（毛发附着于皮，皮毁即落）、`COSMETIC`、`STYLEABLE`。
来源：https://dfwk.ru/Tissue_definition_token

**(e) 材料模板**：见 2.1。

**运行时对应（`creature_raw` / `caste_raw`）。** `creature_raw`：token、单复数与幼体名、tile 与颜色、温度范围、频率、种群/群落范围、成体体型、地下深度、`sphere` 列表、`caste` 向量、`flags`、**`material` 与 `tissue` 两个向量（本生物自有的材料与组织）**、图形、蜂巢产物（物品类型+子类型+材料引用）、来源历史人物/实体 ID。`caste_raw`：名称与描述文本、`misc`（产仔数、寿命、宠物价值、视野、蛋大小、放牧量、材料力倍率）、`attributes`（物理/精神属性区间、成长率、上限）、`personality`（每个人格维度的最小/中位/最大）、**`body_info`**（`body_parts`：每个 `body_part_raw` 有标志、位置、厚度分数、关系与覆盖、`layers` 向量；每个 `body_part_layer_raw` 以 ID 指向组织、带厚度/愈合/感觉/位置/关系/嵌套深度，部分为从属层或非固体层；`attacks` 向量：动词、标志、特效（提取、注入、吸血）、目标部件与层、技能、时序、接触/穿透百分比；交互；提取物与屠宰物；步态按类型索引）、外观修饰、基因计数、天赋技能、职业名、分泌物与综合征、口癖、衣物尺码、世界生成用材料。
来源：https://raw.githubusercontent.com/DFHack/df-structures/master/df.creature.xml

**生物变体（CREATURE_VARIATION）作为模板运算。** `CV_NEW_TAG/CV_ADD_TAG`、`CV_REMOVE_TAG`、`CV_CONVERT_TAG` + `CVCT_MASTER / CVCT_TARGET / CVCT_REPLACEMENT`、条件版 `CTAG`；参数 `!ARG1...`；处理顺序先删后换再加、文件内自下而上。巨型动物、兽人等都由此派生。
来源：https://dfwk.ru/Creature_variation_token

**结论：** 身体不是一张血量表，而是"部件图 × 组织层 × 材料"的三维结构；战斗、医疗、屠宰、温度、外观、步态都读这同一结构（见第 3 节）。更换材料就得到石人、铁人、气体兽，这正是遗忘兽生成器所做的事（第 5 节）。

## 3. 行为怎样由维度算出

### 3.1 战斗伤害：动量 × 接触面积 × 材料强度 × 组织层

以下公式来自玩家逆向与实验（页面自己注明是简化），是目前最完整的公开描述。
来源：https://dfwk.ru/Material_science （英文原页 https://dwarffortresswiki.org/index.php/Material_science 限流未读；镜像页为同一文本的译本，公式与数字相同）

**(1) 攻击类型。** 有 `EDGE` 标记的武器/生物攻击用 `SHEAR_*`；接触面积 ≤ 50 视为穿刺，否则为切割。其余为钝击，用 `IMPACT_*`。无攻击定义的生物/物品用默认推击，接触面积 = (体型)^(2/3)。锋击可退化为钝击，反之不行。

**(2) 有效接触面积** = min(武器接触面积, 被击层的面积)。身体部件面积 = 生物体型 × 部件相对大小百分比。盔甲面积 = 被覆盖部件面积 × 覆盖率/100 × 层尺寸/100 × (1 + (UPSTEP+UBSTEP+LBSTEP)/4)。

**(3) 动量 I。**
`I = Strength × Speed / (10^6 / c_Size + 10 × k_Size / (c_Size × o_Weight))`
等价形式 `I = c_Size × Strength × Speed / (10^6 × (1 + k_Size / (o_Density × o_Size)))`
其中 Strength 力量属性（普通矮人约 1250）、Speed 攻击速度倍率、c_Size 种族平均体型（矮人 60000）、k_Size 攻击者体型、o_Weight 武器质量 kg、o_Density 武器材料密度、o_Size 武器体积。矮人简化为 `I = 0.06 × Strength × Speed / (1 + k_Size/(o_Density × o_Size))`。修正：武器技能最高 ×2（大宗师）、快攻 ×0.5、重击/狂击 ×1.5、打倒地目标 ×2。远程：`SHOOT_FORCE/20` 给动量，速度上限 `SHOOT_MAXVEL/10`；陷阱武器固定速度 200，动量 = 200 × 重量。
**推论：武器重量只在很小程度上影响动量（轻则快），密度与体积通过 o_Density × o_Size 进入分母。**

**(4) 锋击穿透门槛。**
`I ≥ (A_shearY / W_shearY + (A+1) × A_shearF / W_shearF) × (10 + 2 × q_armor) / (sharpness × q_weapon)`
A 为接触面积；sharpness 为武器材料锋利倍率（金属 1、神金 1.2、玻璃 1.5、黑曜石 2、精金 10、其他多为 0.1）；q 为质量倍率。达标则切开该层、动量减约 5%，进入下一层；否则本层转为钝击继续。

**(5) 钝击门槛。** 若 `2 × o_Size × W_impactY(MPa) > A × 盔甲密度` 不成立则被完全挡住；否则需 `I ≥ (2 × A_impactF − A_impactY)(MPa) × (2 + 0.4 × q_armor) × A`。达标穿层、动量减约 5%。

**(6) 弹性与钝化。** 两门槛都失败则永久转为钝击，动量乘 `STRAIN_AT_YIELD / 50000`（锋击用 SHEAR 的，钝击用 IMPACT 的）。多数金属屈服应变远低于 50000，故挡下的攻击削减 98–99%；链甲（`STRUCTURAL_ELASTICITY_CHAIN_*`）把屈服应变抬到 50000，不削动量但把锋击变钝击；织物把剪切值降到约 20–30 kPa（精金布例外）。

**(7) 组织层与肢解。** 伤害逐层施加；一个部件在所有层都达到 100% 挫伤/烧伤/冻伤/坏死等、或 250% 凹陷、或 100% 切割时被摧毁；带 `PREVENTS_PARENT_COLLAPSE` 的颅骨/脊柱在被毁前保护父部件；只有外部部件会被压碎，无骨部件（眼、耳）极易被毁。穿透深度决定武器在转为钝击前能走多深，超过部件尺寸可整体切断（页面标注待验证）。

**(8) 页面给出的经验结论。** 接触面积影响最大；重量超过阈值后影响很小，密度与体积更重要；剪切屈服对锋击穿透几乎无实际影响；冲击屈服关乎钝器攻击、冲击断裂关乎抗钝击；盔甲质量在低与大师之间差约 15%；武器质量对钝击伤害似乎无效；"刚性甲下穿致密金属链甲"最强。

**命中与防御（公式外的部分）。** 攻击按部件可达性与直接性选目标；命中率看双方技能；防御有盔甲偏转、闪避、盾挡、武器格挡（手动防御成功率高但不能攻击）；摔跤有抓、锁喉、关节锁、摔；冲锋可撞倒，体型越大打得越重；伤口导致疼痛、恶心、昏迷；每次攻击有准备/恢复刻（典型 3:3），重/精准/快/狂四种风格修正。
来源：https://dfwk.ru/Combat

**草算核对（本机脚本，见附录 A）。** 用上面的公式与 2.1 节的材料数值算"普通矮人（力量 1250、体型 60000）持短剑（300 cm³）刺/砍骨头层（接触面积 50 / 20000）"：

| 金属 | 短剑质量 kg | 动量 I（速度 1.25） | 刺击门槛（对骨） | 砍击门槛（对骨） |
|---|---|---|---|---|
| 铜 | 2.68 | 91.7 | 381 | 141845 |
| 铁 | 2.35 | 91.4 | 266 | 100659 |
| 钢 | 2.35 | 91.4 | 114 | 43339 |
| 银 | 3.15 | 92.0 | 482 | 183552 |
| 精金 | 0.06 | 46.9 | 1.6 | 624 |

核对结论：(a) 动量几乎不随金属变化（铜/铁/钢/银都在 91–92），精金因密度极低动量减半——与页面"重量影响很小"一致；(b) 穿透门槛随武器剪切强度与锋利倍率剧烈变化，精金低两个量级——与"精金切一切"一致；(c) 大面积砍击对骨头门槛远高于动量，说明实际切断骨头靠的是技能倍率、先切开皮/肌后的部件面积缩小、以及钝化后冲击断裂判定，不是单次砍击数字——这与页面"接触面积影响最大"一致。此表只验证公式与数值的量级自洽，不代表游戏内精确结果。

### 3.2 物品价值：基础值 × 材料倍率 × 质量倍率 + 装饰

`价值 = 基础值 × 材料倍率 × 质量倍率 + 装饰价值`。
- 基础值按物品种类，不看材料：尸体/骨/部件 0；野生害虫、油脂 1；鱼、肉、农作物 2；原石、原木、石块 3；条块、砖、切割宝石、皮革 5；线 6；布 7；有质量等级的物品从 1（弩矢）到 126（部分陷阱部件），衣甲家具居中。
- 材料倍率即 `MATERIAL_VALUE`：石 ×1 到 ×250（生精金）、宝石 ×2–×60、金属 ×2（铜铅）到 ×300（精金）、动物材料 ×2–×15、植物 ×1–×5。同一材料的木块、原木、箱子共用同一倍率；木炭不再算木。
- 质量倍率：普通 ×1、精良 ×2、优秀 ×3、上等 ×4、卓越 ×5、大师 ×12、**神器 ×120**。
- 页面标注过时，若干条目为 "?"，饭菜与维度（dimension）影响未给出。
来源：https://dfwk.ru/Item_value

**房间/区域价值。** 每格：原始 1×材料值，打磨后地板 4× / 墙 5×，建造的地板 7× / 墙 9×，雕刻另加；家具价值求和并乘质量倍率；重叠区域计 0。卧室等级阈值：Meager 0、Modest 100、Quarters 250、Decent 500、Fine 1000、Great 1500、Grand 2500、Royal 10000。雕刻价值加成 = 10 × 材料值 × 质量（1×–12×）；偏爱该石头的矮人双倍评估。
来源：https://dfwk.ru/Zone ；https://dfwk.ru/Engraving

**饭菜。** 2/3/4 种配料对应简餐/佳肴/盛宴；价值取质量倍率并在配料间分摊；成品比生食腐烂慢。
来源：https://dfwk.ru/Cooking

**草算核对（附录 A）。** 以武器 `VALUE` 默认 10 为基础值：大师级钢短剑 = 10 × 30 × 12 = 3600；普通铜短剑 = 10 × 2 × 1 = 20。量级与玩家经验一致（钢器大师级值数千）。

### 3.3 reaction：按材料类别与"反应产物"匹配原料

**语法。** `[REACTION:ID]`、`[NAME:显示名]`、`[BUILDING:工坊:热键]`、`[REAGENT:名:数量:物品类型:子类型:材料类型:材料索引]` + 修饰、`[PRODUCT:概率:数量:物品类型:子类型:材料类型:材料索引]` + 修饰、`[PRODUCT_DIMENSION:n]`（条块/粉/液 150，线 15000，布 10000）、`[PRODUCT_TO_CONTAINER:容器原料名]`、`[IMPROVEMENT:概率:原料名:COVERED|GLAZED|RINGS_HANGING|BANDS|SPIKES:材料]`、`[SKILL:技能]`、`[FUEL]`（岩浆版免燃料）、`[AUTOMATIC]`、`[ADVENTURE_MODE_ENABLED]`。
**原料匹配不靠枚举具体物品，而靠属性：**
- `NONE:NONE` 接受任何材料；`INORGANIC:IRON` 指定；通配 `ANY_RAW_MATERIAL`、`ANY_CRAFT`。
- `REACTION_CLASS:FLUX` —— 任何材料只要自己声明了 `REACTION_CLASS:FLUX`（方解石、白云石、大理石……）就能当助熔剂；加一种新石头只需在无机物里写一行。
- `HAS_MATERIAL_REACTION_PRODUCT:TAN_MAT` —— 任何材料只要声明"我经制革变成 X 皮革"就能进制革反应；产物侧用 `GET_MATERIAL_FROM_REAGENT:原料名:TAN_MAT` 取出 X。酿酒同理用 `DRINK_MAT`，榨油、磨粉、提取物同理。
- 其他过滤：`CONTAINS / EMPTY / BAG / FOOD_STORAGE_CONTAINER / PRESERVE_REAGENT / DOES_NOT_DETERMINE_PRODUCT_AMOUNT / UNROTTEN / NOT_WEB / WEB_ONLY / NOT_PRESSED / NOT_IMPROVED / NO_EDGE_ALLOWED / ANY_SILK_MATERIAL / ANY_YARN_MATERIAL / ANY_LEATHER_MATERIAL / ANY_BONE_MATERIAL / ANY_HORN… / GLASS_MATERIAL / HARD_ITEM_MATERIAL / DOES_NOT_ABSORB / BUILDMAT / FIRE_BUILD_SAFE / MAGMA_BUILD_SAFE / WORTHLESS_STONE_ONLY / USE_BODY_COMPONENT / CAN_USE_ARTIFACT / HAS_TOOL_USE / MIN_DIMENSION`。
- 产物修饰：`FORCE_EDGE`、`PRODUCT_PASTE`、`PRODUCT_PRESSED`；`CRAFTS:NONE` 随机工艺品。
- 文明访问：实体写 `PERMITTED_REACTION:ID`；向已有世界加许可可以让已存在的反应生效，全新反应需新世界。
来源：https://dfwk.ru/Reaction

**炼钢链（真实配方）。** 生铁：1 铁条 + 1 助熔剂 + 1 精炭 → 1 生铁条；钢：1 铁条 + 1 生铁条 + 1 助熔剂 + 1 精炭 → 2 钢条；普通熔炉里炭兼燃料，岩浆熔炉里只是原料。助熔剂即 `REACTION_CLASS:FLUX`。
来源：https://dfwk.ru/Steel

**植物衍生品同理。** 植物最多 200 个本地材料；`BASIC_MAT:LOCAL_PLANT_MAT:名` 指向本地材料；`DRINK` 现在要求反应产出 `MATERIAL_REACTION_PRODUCT:DRINK_MAT`；`MILL` 需 `POWDER_MISC_PLANT`；`THREAD`、`SEED`、`EXTRACT_*` 各需对应库存标记；`GROWTH` 定义叶/花/果等生长物，`GROWTH_ITEM:PLANT_GROWTH:NONE:材料`，`GROWTH_TIMING`、`GROWTH_PRINT`；`TREE:木材材料`。
来源：https://dfwk.ru/Plant_token

**自定义建筑。** `BUILDING_WORKSHOP / BUILDING_FURNACE`、`NAME`、`DIM`（默认 3:3，最大 31×31）、`WORK_LOCATION`、`BUILD_LABOR`、`BUILD_KEY`、`BUILD_ITEM:数量:物品:材料` + 与 reaction 相同的修饰（BUILDMAT、WORTHLESS_STONE_ONLY、CAN_USE_ARTIFACT、FIRE/MAGMA_BUILD_SAFE）、`NEEDS_MAGMA`、`BLOCK`、`TILE`、`COLOR`（可用 MAT 取主材料颜色）。
来源：https://dfwk.ru/Building_token

**结论：** 配方对原料的描述是谓词（"任何标为 FLUX 的材料"），对产物的描述是函数（"取原料的 TAN_MAT 产物材料"）。这使"加一种石头/一种动物/一种植物"不必改任何配方。

### 3.4 温度：材料热属性驱动燃烧、熔化、冻结

单位 Urist（°U），10000 = 0 °C，°U ≈ °C × 9/5 + 10000；矮人体温约 10067；水 10180 沸；有机物约 10508 燃；岩浆 12000（高于有机物燃点，故附近物品会着火）。每刻物品/生物按材料 `SPEC_HEAT` 向环境温度靠拢；越过 `MELTING_POINT / BOILING_POINT / IGNITE_POINT` 则熔/沸/燃；`HEATDAM / COLDDAM` 决定伤害；固定温度材料（如 nether-cap）免疫。局部温度由气候与生物群系决定。
来源：https://dfwk.ru/Temperature

天气：雨冲洗血迹、填池、使室外矮人不悦；冷则降雪、水结冰（站在上面即死）；邪恶群系有致综合征的云与雨；降水形态由温度与季节决定；风随纬度推动云。
来源：https://dfwk.ru/Weather

液体：水 1–7 级深度，向下落、侧向扩散、同层对角流动；压力经格边传递；1/7 深会蒸发（热干气候更快）；墙、闸、门、舱口阻水，栅、栏、射击孔透水。
来源：https://dfwk.ru/Flow

### 3.5 宗教领域：领域如何影响神祇、信仰、诅咒与世界生成

- **神的生成**：世界生成时随机生成，每位神挂若干领域和一种神金；山地与平原文明多神，常以本族形象呈现，偶为动物；森林文明不奉神而信"森林之力"；宗教可跨文明传播。神不在普通游戏中出现（有 DFHack 脚本可据其历史人物记录造出单位）。
来源：https://dfwk.ru/Deity
- **文明一侧**：`RELIGION:PANTHEON|REGIONAL_FORCE`、`RELIGION_SPHERE` 限制领域、`SPHERE_ALIGNMENT` 偏向领域。运行时 `historical_entity.deities` 持有神的历史人物 ID，`worship` 存接受度，`belief_systems` 存先知所创信仰。
来源：https://dfwk.ru/Entity_token ；https://raw.githubusercontent.com/DFHack/df-structures/master/df.entity.xml
- **个人一侧**：`histfig_hf_link` 的 `deity` 链接与 `vague_relationship_type` 的 `worshipped deity`；要塞模式崇拜深度四级（ardent / faithful / casual / dubious），祈祷是一种需求，不能祈祷会分心、不悦；需为不同神（含巨兽）分别设庙。
来源：https://raw.githubusercontent.com/DFHack/df-structures/master/df.history_figure.xml ；https://dfwk.ru/Religion
- **神做的事**：诅咒亵渎庙宇者为吸血鬼或狼人（DEITY 源交互）；给予刻有秘密的石碑（死灵术，`IS_SECRET`，由 DEATH 相关神授予）；造天使守护恶魔金库，天使的外观、材料、特质取自其创造神的领域，名字来自世界的神圣语言，raw 标为 generated；神金 10/26 种每世界，各挂一领域。
来源：https://dfwk.ru/Deity ；https://dfwk.ru/Vampire ；https://dfwk.ru/Night_creature ；https://dfwk.ru/Necromancer ；https://dfwk.ru/Angel ；https://dfwk.ru/Divine_metal
- **宗教作为实体**：`historical_entity.type = Religion`；先知在世界生成中创立并扩散宗教；庙宇可献给某神或某宗教，10 名信徒可请愿建庙，价值 2000 批准、10000 成庙宇群落（高阶祭司需要）；乐器与 25 格舞池增强崇拜；圣物置于庙底座。
来源：https://raw.githubusercontent.com/DFHack/df-structures/master/df.entity.xml ；https://dfwk.ru/Prophet ；https://dfwk.ru/Temple
- **庙名**：城镇庙名来自所奉神的领域。来源：https://dfwk.ru/Religion
- **地区**：邪恶地区由常驻实体的领域塑造；噩梦/黑暗领域地区有 bogeymen。来源：https://dfwk.ru/Surroundings ；https://dfwk.ru/Night_creature

**诚实说明：** 镜像 Religion 页明言"个体如何选择崇拜哪位神，机制不清"，且领域在要塞模式中只在庙名上体现。领域→性格/价值的直接映射，公开资料中没有证据。
来源：https://dfwk.ru/Religion

### 3.6 屠宰、农牧、生长：由体积与组织厚度算产量

- **屠宰**：每层产量 = 修正体积 / 25000 向下取整（大体积至少 1）；产物由组织层决定（肉=肌、脂=脂、骨=骨、皮=皮、器官各自）；`BUTCHER_SPECIAL` 指定特殊产物；智慧生物因 `EAT_SAPIENT_OTHER` 伦理为 UNTHINKABLE 不能屠宰。
来源：https://dfwk.ru/Butcher
- **驯养与繁殖**：`PET / PET_EXOTIC`、`TRAINABLE(_HUNTING/_WAR)`；文明对物种的知识降低训练难度；成年不续训会野化；胎生在牧场产仔，卵生需巢箱；`CHILD` 幼体首次训练即全驯；放牧动物需草场。
来源：https://dfwk.ru/Animal_training
- **农业**：每格一粒种子，按季选作物，部分作物限季；地下作物生长 30000–50000 刻；钾肥 floor(面积/4)+1 单位/季、每堆最多 +4；土层地块减产 75%。
来源：https://dfwk.ru/Farming
- **树木**：多格树（主干、粗/细枝、细梢、根），每年随机检查生长，幼苗约 3.5 月成形；每主干格一根原木；幼苗自然再生。
来源：https://dfwk.ru/Tree
- **害虫**：<2 kg 的 `VERMIN_*` 生物按栖息地刷出而不繁殖，偷吃未入桶的食物；可诱捕、作宠物，猫与猎鹰捕食。
来源：https://dfwk.ru/Vermin

## 5. 世界随机生成怎样复用同一套 raw

**生成流程。** 选极点 → 在网格上播种高程、降雨、温度、排水、火山、野性六个场并分形填充 → 不满足参数则整图重做 → 由高程/降雨/温度推出植被与生物群系（而非直接摆放群系）→ 侵蚀、河流、湖泊 → 重算气候与盐度 → 命名区域、加地质与地下层 → 播种野生动物、初始化天气 → 放置文明与洞穴，逐年模拟战争、围攻、饥荒、人物、巨兽、神器直到设定年 → 可立即开玩或保存；种子记录在 gamelog。高级参数控制尺寸、历史长度、文明数、站点上限、巨兽数、野性、灭绝、矿物稀缺。
来源：https://dfwk.ru/World_generation ；Adams 2008 访谈谈"先找基本元素与规则再让它们互动"的方法：https://www.gamedeveloper.com/design/interview-the-making-of-dwarf-fortress

**生成物写成 raw。**
- 遗忘兽：随机身体（动物形或 blob/虫/四足/人形/昆虫/蜘蛛）、材料（肉、液、气、粉、石、宝石、金属——材料决定耐久）、组织、攻击、随机综合征、CAVERNS + 一两个领域；页面展示了从 world.dat 取出的生成 raw，带 `[GENERATED]` 与 `FEATURE_BEAST`，用与普通生物相同的 token 定义身体、组织、攻击、综合征、步态、描述。
来源：https://dfwk.ru/Forgotten_beast
- 泰坦、恶魔、天使、夜生物：同样 `GENERATED`；恶魔自地狱生成；天使按创造神领域决定外观材料；夜生物部分全随机、部分由交互把普通生物转化、部分两者结合。
来源：https://dfwk.ru/Megabeast ；https://dfwk.ru/Demon ；https://dfwk.ru/Angel ；https://dfwk.ru/Night_creature
- 神金：每世界 10/26 种、各挂一领域、密度 1000、极锋利、极高屈服/断裂，也是普通无机物 raw（`DIVINE`、`SPHERE`）。
来源：https://dfwk.ru/Divine_metal ；https://dwarffortresswiki.org/index.php/Inorganic_material_definition_token
- 乐器：原版无 item_instrument.txt，因为乐器随机生成，但仍是 `itemdef_instrumentst`（部件、音域、发声/定音方法、音色）。
来源：https://dfwk.ru/Item_token ；https://raw.githubusercontent.com/DFHack/df-structures/master/df.itemdef.xml
- 诗歌/音乐/舞蹈形式按文明生成。来源：https://dfwk.ru/Poetic_form
- 运行时标记：`itemdef.base_flags` 只有 generated；`inorganic` 的 `GENERATED` 不可手写；`entity` 的 `GENERATED` 标神造种族；`creature` 的 `GENERATED` 由引擎设置。
来源：df.itemdef.xml；Inorganic token 页；Entity_token；Creature_token

**新增内容只填 raw。** 加一种生物：写 CREATURE（拼 BODY、调用细节计划、选模板）；加一种材料：写 INORGANIC 并挂 `ENVIRONMENT` 与 `REACTION_CLASS`；加一种物品：写 ITEM_* 并在 ENTITY 里登记；加一个文明：写 ENTITY（生物、语言、许可、职位、伦理、价值、站点、宗教）；加一种配方：写 REACTION 并 `PERMITTED_REACTION`。每个世界保存自己的一份 raw 副本，改 raw 不影响已有世界。
来源：https://dfwk.ru/Modding ；https://dfwk.ru/Reaction

**2025-07-21 的 52.01：生成器本身开放为 Lua。** 官方发行说明列出开放的生成器：遗忘兽、神罚诅咒（吸血鬼与狼人）、神造物品、死灵法师及其副手与实验体、邪恶天气等；并承认这些系统 "hard-coded in Dwarf Fortress" 约十五年；原版脚本在 `data/vanilla/vanilla_procedural`，与其他 mod 同结构（需 `init.lua`，含 `generators` 文件夹）。Kitfox 补丁说明称这是为"程序化魔法"等高级系统铺路，Putnam 持续改进该 Lua 更新。

## 6. 诚实的局限：哪些仍是硬编码

1. **行为本身大多硬编码，token 只是开关。** Modding 页直言多数行为写在代码里，token 打开预设行为而不能定义新行为——可以让生物食肉，不能给每种生物自定义食谱。来源：https://dfwk.ru/Modding
2. **无 raw 的物品类型。** 床、门、桌、椅、条块、石、砖等子类型为 NONE，无定义文件；`itemdef_type` 只有 14 种；`item_type` 是代码枚举。来源：https://dfwk.ru/Item_token ；https://raw.githubusercontent.com/DFHack/df-structures/master/df.itemdef.xml
3. **工坊与工作。** 部分工坊工作硬编码（造床、制玻璃等），自定义建筑只能是 `BUILDING_WORKSHOP / BUILDING_FURNACE` 两类并只承载 reaction。来源：https://dfwk.ru/Reaction ；https://dfwk.ru/Building_token
4. **枚举表全在代码里**：`profession`（MINER, WOODWORKER, CARPENTER…）、`value_type`（33 项价值）、`ethic_type`（22 项伦理）、`sphere_type`（领域）、劳动、技能、职责（RESPONSIBILITY 的可选值）、`historical_entity_type`（11 种实体类型）、`item_type`。raw 只能从中选，不能增删。来源：https://raw.githubusercontent.com/DFHack/df-structures/master/df.d_basics.xml ；df.entity.xml ；df.history_figure.xml ；https://dfwk.ru/Position_token
5. **多种族文明不工作**，用等级（caste）凑合则会互相繁殖；无性生殖不支持。来源：https://dfwk.ru/Modding
6. **职位系统有多项 token 失效或未用**：GENDER 坏、TAME_EXOTICS 未用、COLLECT_TAXES 等五项遗留未用、ACCOUNT_EXEMPT / PUNISHMENT_EXEMPTION / MILITARY_SCREEN_ONLY 不工作。来源：https://dfwk.ru/Position_token
7. **经济停用**：矮人经济自 0.31.01 起关闭。来源：https://dfwk.ru/Economy
8. **部分 raw token 本身有硬性限制**：`MEGABEAST` 必须有 BIOME 且不能地下；`FEATURE_BEAST` 0.47.01 前不可手写；`GENERATED` 不可手写；`SMALL` 为遗留；`CREATURE_CLASS` 任意命名但只有少数类被代码使用；`SPECIAL` 材料的 AI 行为固定。来源：https://dfwk.ru/Creature_token ；https://dwarffortresswiki.org/index.php/Inorganic_material_definition_token
9. **战斗公式不可配置**：3.1 节的全部公式与常数（5% 动量衰减、50000 应变基准、材料锋利倍率表、技能 ×2 上限）写在代码里，raw 只提供输入数值。来源：https://dfwk.ru/Material_science
10. **原版乐器文件不存在**，乐器只能生成，不能像武器那样手写（0.42 起 INSTRUMENT 实体 token 弃用）。来源：https://dfwk.ru/Item_token ；https://dfwk.ru/Entity_token
11. **工程层面**：约 71 万行 C/C++，作者自称 "sort of a mess that's accreted over time"；无多线程（除图形）；早期按类型的多态物品类层级被作者视为错误；寻路用 A* + 连通分量索引，作者早年称之 "creaky and slow"。来源：https://stackoverflow.blog/2021/12/31/700000-lines-of-code-20-years-and-one-developer-how-dwarf-fortress-is-built/ ；https://www.gamedeveloper.com/design/interview-the-making-of-dwarf-fortress
12. **生成器直到 2025-07 才开放**，此前 15 年硬编码（官方承认）。来源：https://dwarffortresswiki.org/index.php/Release_information/52.01
13. **文档层面的局限**：Material science 页的公式是逆向与实验的简化版；Item value 等页面标注过时；Modding 页说物品 token 文档不全需试错。来源：https://dfwk.ru/Material_science ；https://dfwk.ru/Item_value ；https://dfwk.ru/Modding

## 8. 对 infinite-world 的启示

只借鉴架构，不照搬内容与实现。

### 8.1 可借鉴的架构要点

1. **把"材料"做成全系统唯一的物理公分母。** 一张属性表（密度、热四点、六种应力的屈服/断裂/应变、锋利度、价值倍率、物态命名、用途标记、反应接口、效果、领域）覆盖石、金、木、肉、骨、血、酒、毒、云。任何新实物 = 新的一行。infinite-world 若要让战斗、温度、价值、配方、医疗互相贯通，先统一这张表，再让各系统只读表、不各自存"硬度/价格"。出处：2.1 节。
2. **身体 = 部件图 × 组织层 × 材料，而不是血量。** 组织模板声明功能语义（出血、承重、痛觉、功能器官、从属层），材料给物理；细节计划带参数（ARG1..5）让同一份"脊椎动物分层"服务所有脊椎动物。这使"换材料就换生物种类"成为可能，也让医疗、屠宰、外观、步态读同一结构。出处：2.3 节、3.6 节。
3. **效果层统一为"源→目标→效果"的交互 + 挂在材料上的综合征。** 毒、酒、诅咒、变身、呼吸攻击、天气、复活是同一数据格式，没有各自代码分支。infinite-world 的"规律层/原语层"若要一类一起覆盖（亮圳红线），这正是范本。出处：2.8 节。
4. **配方用谓词匹配原料、用函数派生产物。** `REACTION_CLASS:FLUX` 与 `HAS_MATERIAL_REACTION_PRODUCT:TAN_MAT → GET_MATERIAL_FROM_REAGENT` 让新增一种石头/动物/植物无需改任何配方。出处：3.3 节。
5. **社会对象统一：一个实体结构 + 一个人物结构 + 两张链接表。** 国家、宗教、公会、商会、剧团、军队共用 `historical_entity`；神与凡人共用 `historical_figure`，神只多一个标记和领域表；人↔人、人↔实体、实体↔实体、实体↔站点都是显式链接对象。传奇模式、阴谋、迫害、崇拜都查同一张图。出处：2.4、2.5 节。
6. **受控词表（领域）做跨系统的"主题标签"。** 一张约 130 词、带父子/友好/不相容关系的表，同时给神、生物、材料、地区、庙名、秘密、文明倾向打标签，是让"世界有主题一致性"的廉价手段。出处：2.6 节。
7. **生成物写回同一数据格式。** 遗忘兽、天使、神金在生成时写成带 `GENERATED` 的普通 raw 并随存档保存，之后走与手写内容完全相同的代码路径；生成器只是"会写 raw 的程序"。这保证了生成内容与手写内容享有同样的系统覆盖。出处：5 节。
8. **文明能做什么全是引用表，不是代码分支。** 许可的工作/建筑/配方、装备清单、动植物、材料偏好、伦理、价值、职位、站点偏好、进度触发器都在 `entity` 里；加一个文明不改代码。出处：2.4 节。
9. **公式吃维度、不吃种类名。** 战斗、价值、温度、屠宰公式只读材料/部件/属性数值；"钢比铜好"是数据结果而不是 if 分支。出处：3 节与附录 A 草算。
10. **每个世界保存自己的数据副本**，保证同版确定性与复演（与本项目"保留同版确定性"原则一致）。出处：https://dfwk.ru/Modding

### 8.2 不宜照搬之处

1. **"token 只是开关"的模式。** DF 的多数行为仍在代码里，raw 只能打开预设行为（可食肉、不可自定义食谱）。infinite-world 以规律层通用修复为红线，应让规律本身可由数据表达（例如把 3.1 节那类公式的常数与结构也放进规则层），而不是只把输入参数化。出处：6 节第 1、9 条。
2. **代码枚举（职业、劳动、技能、价值、伦理、领域、实体类型、物品类型）。** 这是 DF 多种族文明失效、乐器不能手写、领域不能扩展的根源。我们应把这些做成可增删的数据表。出处：6 节第 2–5 条。
3. **按类型的多态物品类层级。** 作者本人认为是错误，妨碍生成；他现在偏向"工具 + 可开关组件"。我们直接从组件式开始。出处：https://stackoverflow.blog/2021/12/31/700000-lines-of-code-20-years-and-one-developer-how-dwarf-fortress-is-built/
4. **公式常数硬编码且无文档，依赖玩家逆向。** 5% 衰减、50000 应变基准、锋利倍率表都只能从玩家实验得知。我们应把公式与常数放在可读的规则文件里，并有确定性测试。出处：https://dfwk.ru/Material_science
5. **"每个世界存一份 raw 副本、改 raw 不影响旧世界"虽然保证确定性，但 DF 没有版本迁移**——本项目已有"不做旧存档兼容、规则只一版"的原则，与之相容，但需保留"同版确定性"的测试，而非照搬 DF 的无测试状态。出处：https://dfwk.ru/Modding ；工程状况见 6 节第 11 条。
6. **过度物理化。** 六种应力三参数、Urist 温度、每刻热交换是 DF 的乐趣来源，但对以叙事/派生为主的产品，应按"规律是分布、允许随机与个别不合常理"的原则取其结构（维度→公式→行为），不取其精度。出处：3.1、3.4 节。
7. **单线程与 71 万行单体。** 不是架构选择，是历史包袱。出处：6 节第 11 条。
8. **生成器 15 年硬编码才开放。** 我们应从第一天就让生成器与手写内容共用同一数据格式与同一加载器（8.1 第 7 条），不要等到后期再补。出处：https://dwarffortresswiki.org/index.php/Release_information/52.01
