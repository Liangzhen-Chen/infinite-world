## 〇、一页结论

亮圳在 2026-10-14 至 11-13 一个月里，围绕"统一底层 / 不准写死 / 行为从属性推出"提过 **9 轮**要求（§一表 1），每一轮都有对应的调研或设计文档（架构设计 28 份、世界设计 15 份、AI 作用 7 份、审查与方案十余份，按 wc -l 合计逾 1.5 万行），其中三轮是完整的顶层设计（10-15 目标架构 15 章、11-09 世界设计 15 册、11-10 AI 作用 7 册）。但到 11-13 的写死自查（06a），规则代码里仍有 198 处实例 id 字面量、38 行对中文描述做正则分类、83 行睡眠正则分布在 62 个文件、coins 被 22 个模块直写。

未落实不是因为没设计、也不是因为没人提：**每一轮都在"设计完成 → 开始实现 → 阶段收口"之间被同一组机制截断**：

1. **迁移半途改为"渐进演化"**（10-27 G0 定稿 "默认不做迁移"，v3 指南 A.3 第 8 条"不再做一次迁移"，亮圳的原话是"上一次改架构的迁移花了好几天"）。于是账户、持有、义务、原语这些统一底层概念和旧字段**长期双写并存**，旧写者从未退役，双写退出被推到 S6 → S7 → "不承诺 S8 物理删光"。
2. **阶段收口按"选项"放宽并把统一主路推到末尾**。A3 以"选项 2"收口（10-25），开放路径只能派生 9 类效果、工具面 ≤16 归 S8（设计 10 §10.4 本来就排在 S8），其余 337/341 条动作是旧处理器外壳；"黑名单零命中"也排在 S8 退出标准。统一主路缺席，每个新动词只能写处理器，这就是"一张卡补一件"的机制来源。
3. **维度层只做了设计，数据与读取方没补**。目标架构 01 §1.2 规定"身份、称呼、法域…禁止落盘"；13 §13.2 规定文化记录字段；物种统一 schema 定了——但到 11-09，地点 culture 字段 0/458、职业文化字段 0/65、怪物 sources 0/168、新 schema 物种 5/168。没有维度，规则只能从中文描述里正则"猜"（06a 第 3、4 节）。
4. **主线被收口与流程占满**。S5 从 10-25 拖到 11-11；11-03 至 11-09 master 229 个提交里 218 个只改 docs，代码 tip 停在 10-28；一轮全量 4.5 小时、每张卡两轮审查、一天换约 30 个云上副本。通用门、K1–K3 经济规律、RG-B、供给网、WD 批次统统排在"S5 合入之后"。
5. **红线没有机器门禁**。11-04 把"不准硬编码"写进 AGENTS.md 作为永久红线，11-10 实施日程给每张卡加"grep 无字面量分支"验收，但一直没有一条进 CORE 的扫描；审 diff 问"一类还是一件"时，卡本身的范围就已经是一件（盐、冬荒乘数、徐玲烙饼、口渴找水）。
6. **多线并行、各自"整类"，没有跨系统的共同底层**。11-04 之后 K1–K8、通用门、Jev、WD-01…38、AI-01…23、NM-0…5、EC-1、MKTW 并行推进，每条线都按"一类一起"写，但物品、地点、人物没有共同的维度表；供给网 v11 仍"围着柴、炭、盐写"（11-13 02:0x 李白纠偏）。

这次要避免重蹈覆辙，核心只有一条：**把"维度表 + 校验器 + 禁 id / 禁自然语言扫描"做成 CORE 门禁，先于任何实现卡上线，并把扫描数（而不是测试通过数）写成每个阶段的退出标准。** 其余建议见 §四。

### R1（10-14）系统底座 K1–K10：做成了读层，没有收掉旧写路径

## 四、这次怎样避免重蹈覆辙

对应 §三的 C1–C9，建议写进卷一总纲与卷十二验收：

1. **门禁先行，不排在 S8。**（对 C4、C2）卷二维度表规范一定稿，先做三件进 CORE 的扫描：实例 id 字面量（item_/loc_/npc_/bld_/culture_/monster_/office_/skill_/profession_/deity_）、对描述性字段的自然语言匹配（正则/includes/startsWith 作用于 name/purpose/occupation/personality/terrain/polity/folklore）、跨模块直写（npcs.coins、settlements.treasury、npcs.memoryStream）。基线数登记后只允许下降；任何提交让数字上升即拒绝。这是 06a §四验收标准 1–4 的机器化。
2. **退役写进每个阶段的退出标准，不接受"双写待收口"。**（对 C1）每张卡的验收含"旧写路径删除数"；阶段退出标准用扫描数而不是测试通过数；"不迁移"改写为"不做一次性全量迁移，但每个领域在其卡内完成退役"。
3. **维度表 + 数据补齐 + 读取方改造是同一张卡的三段，缺一段不算完。**（对 C3）00 册里 culture 0/458、职业 0/65 这类数据缺口与代码改造同级登记；内容审批管线按维度表校验，缺字段直接报错不回退到解析文本（06a §四"每张表配一份校验器"）。
4. **卷零覆盖表是唯一验收账本。**（对 C7、C8）每张卡必须写明覆盖卷零的哪几行子系统、改前改后该行的"维度/入口/写死"三列如何变化；没有行号的卡不派。多线并行只允许在不同卷之间，同卷串行。
5. **"归后续阶段"必须带接收卡号与日期，否则不准收口。**（对 C5）A3 的教训是登记表有、接收阶段永远没到。卷十一迁移路线里每项遗留都要有接收卡；阶段收口时登记表为空或全部有卡号。
6. **扩展性测试作为阶段门：只在表里加一个物品类别、一种设施、一种职业、一种地形，不改代码，日耗、贸易、库存、受理、产出自动获得。**（对 C2、C3、C9）这是 06a 验收标准 6；它直接否决"一卡补一件"，因为补一件永远过不了这道门。
7. **remote-generation、supply network 这类"内容在代码里"的模块，先数据化再改规则，不排队改。**（对 C7、R7）实施日程里 8 张卡排队改 remote-generation.mjs 的做法要撤掉，改为卷十世界生成里一次性把文化→物种→职业→货单→命名库搬进数据表。
8. **冻结期内不开"整类小修"。**（对 C6、C9）11-13 的冻结是对的；在卷一到卷二十写完并过李白核之前，不再接受任何以"整类"为名但对象是盐、柴、水、烙饼的卡——它们都是维度层缺位的症状。
9. **统一底层的验收由主会话亲自跑扫描，不由执行者自报。**（对 C4、C9）产品原则三.5 已有"主会话是设计者不是转发器"，这里具体化为：合并前主会话运行三项扫描并把数字写进提交信息。
