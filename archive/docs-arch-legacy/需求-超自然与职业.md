# 需求：超自然生灵与职业呼应（SX-1，2026-10-15）

**定位**：系统需求，不是内容。用户原话：用中国妖怪故事和希腊、北欧、印度、南美、埃及等神话的事件与怪物补充世界，"并且和我们的游戏职业可以呼应，所以现在先扩充好你的设计，然后再加这些，系统本身才是最重要的"。本文给下一轮架构修订（Fable）提供输入：现状接点、类型学、互动方式与所需机制、各文化职业与本项目职业的对应、待决策的设计问题、验收条目。YG（妖怪志）和 WM（万灵志）的内容都要等本文对应的设计定稿后再写。

**依据**：目标架构 0 章与 01/03/05/06/12 章；PLAN「派生优先」「超自然生灵与职业呼应」「妖怪志」「万灵志」；world/meta/professions.json、skills.json、spells.json、monsters.json、bosses.json；world/lore/deities.json、faith.json、cultures.json、festivals.json、factions.json；world/ontology/*。YG-1 的 motifs.json 还没产出（F:/dnd-wt/YG1 下没有 drafts/yaoguai），所以母题统计这里只用学科分类，不用 YG 的数字。外部只取分类事实：Aarne–Thompson–Uther 故事类型索引（ATU，2004）、Thompson《民间文学母题索引》的大类、van Gennep 的过渡礼仪三段论、Hertz 的二次葬与"亡者过渡期"、Frazer 对交感巫术（相似律、接触律）的分类、Mauss 的礼物互惠、Eliade 对萨满出神的描述，还有各文化有文献记载的职业名与仪式名。没有抄任何现代文本。

**本文不做的事**：不定词条、不定数值、不写具体生灵。凡是"应该怎样实现"的地方，都写成可选方案交给架构师。

### 1.2 现有接点（可以直接承接的机制）

1. **生灵已经是实体**：creature 属于 agent 模板，可挂账户、可作持有人与义务的一方；种群是 population 实体。精怪聚居地已经是 org 与 culture。
2. **契约已经是义务**：召唤的 upkeep 义务、promise、service 都在；召唤师的技能描述已经按"契约条款、供魔、期限、可拒绝"写。
3. **符与阵是物和标记**："实际持有的符""标物可被搬走"说明符箓是 item，阵界依附于 mark/boundary 实体。这已经符合"持有 + 物"的形状。
4. **知情层承载传说与真相的落差**：怪物的 folklore 字段与观察记录不一致，正好对应 05 §5.4 的主观视图、推断规则和"传闻不改变事实"。
5. **同意与合法性**：精神类状态必须取得同意（12 §12.2.3）；巫师和祭司的技能反复强调"不改写记忆、不强迫、可退出"。驱邪误认会伤及无辜，葭界的禁忌也写进了数据。
6. **神迹有预算**："有限神迹 + 资源损失 + 职责后果"可以直接对应账户与转移（香火 incense 账户）和修正项预算。
7. **规范栈**：门规、戒律和非人政体法典（林地议会把"惊扰精怪"列为罪名）可以承载禁忌和生灵的规矩。
8. **转移协议**：死亡统一走 transition(gone)；遗产实体承接死者的财物与债务，亡魂的"未了之事"可以挂在上面。
9. **兜底标记**：mark:offering、mark:sacred_symbol、mark:omen、mark:boundary、mark:memorial 已经存在，玩家即兴的供奉、画符、立界能留下痕迹，反应规则可以订阅。
10. **隐藏职业由事迹触发**：只要增加相应的计数（安抚、超度、解咒、跨文化仪式），就能派生出新的隐藏职业。

## 2. 跨文化超自然生灵类型学

### 2.1 原则

1. **分类是标签层级，不是实体种类。** 存储层只有 creature（个体）和 population（种群）两种；"亡魂""精怪"等都是带上位词的标签（12 §12.3.3 的 broader 链）。规则按"本词 → 上位词 → 更上位"回退匹配，所以"葭界道院的辟秽符对 `super:dead` 有效"会自动覆盖北欧的守冢尸、希腊的亡影和中国的游魂。新文化只需加下位词。
2. **多轴，而不是单棵树。** 民俗学的经验是：同一个对象常常同时属于几类（如日本的怨灵既是亡魂，被封神后又成了神；狐既是兽、是精怪，又是变形者）。所以分成几条正交的轴，每条轴各自有层级：
   - **本源轴（是什么来的）**：决定通用的克制与仪式。
   - **形态轴（以什么存在）**：决定能否被物理伤害、能否进入某地、能否附身。
   - **依附轴（拴在什么上）**：决定在哪里出现、怎样封印或释放。
   - **驱力轴（想要什么）**：决定行为与谈判的筹码。
   - **处境轴（现在怎样）**：被封印、被供奉、被驱使、在游荡、已安息……**这条轴必须派生**，由持有与状态算出，不能写成标签（派生优先）。
3. **"契约生灵""变形者"不是本源。** 契约生灵是处境（存在一份契约义务）；变形是能力。它们在类型学里列出，但在数据里分别落在处境轴（派生）和能力上。

### 2.2 本源轴（建议层级）

|---|---|---|
| 形态 `form:` | corporeal 有形 / incorporeal 无形 / possessing 附体 / vessel 寄于器 / shifting 可变形（下分兽形、人形、物形） / mist 雾形 | 决定 vital 能否命中、move 能否穿墙或过门、感知派生（能否被看见）、附身前提 |
| 依附 `anchor:` | place（某地点或分区）、object（某物品）、body（尸骨、坟）、person（某人、血脉）、name（名字被呼唤）、time（时辰或节日） | 决定出现的位置；封印或驱离的对象；"移走尸骨即可平息"这类条件 |
| 驱力 `drive:` | hunger 饥渴、grievance 冤屈、duty 职守、attachment 眷恋、desire 欲求（情欲、财物）、mischief 戏弄、territory 领地、cultivation 修行、reciprocity 礼尚往来 | NPC 决策（05 §5.7）的需求输入；谈判筹码；满足条件 |
| 能力 `power:` | possess、curse、glamour（迷惑）、shift（变形）、invisible、dreamsend（托梦）、bless、plague、bind（缚人）、foresee | 动作注册表里生灵可发起的动作的前置 |
| 规矩 `bound:`（生灵自身受的约束） | threshold（需邀请才能入门）、running_water（不能渡流水）、counting（必须数完撒下的谷粒）、truthful_name（被叫出真名就要应答）、sunlight、iron、reciprocal（受礼必还） | 规范条目（生灵自身的"法典"），引擎在生灵的动作前置中读取 |
| 处境（**派生，禁止存**） | wandering 游荡 / enshrined 受供 / sealed 被封 / bound 被驱使 / contracted 有约 / rested 已安息 / reborn 已转生 / married 已婚配 | 由持有、义务与状态计算；界面中"它现在是什么"的投影 |

### 2.4 共同属性（所有超自然个体都应能回答）

1. 本源、形态、依附、驱力、能力、规矩（存的是物种或个体的事实，规矩可以由文化补充）。
2. 灵智与可谈判性（现有 intelligence，派生出能否同意、能否订约）。
3. 维系它存在的存量（"灵力/香火/怨气/饥渴"之类，是账户，只能由转移改变，例如供奉流入、超度流出到汇）。
4. 克制与媒介反应（见 §5 Q3 的数据形状）。
5. 与生前实体或与地点的链接（亡者的 `soulOf`，地灵的 `anchor`）。
6. 文化来源（`culture` 或文化圈上位词），供跨文化效力计算使用。
7. 公开传说与真实性状的分离：传说属于知情层（书本、传闻、推断），真相属于事实层。现有 folklore 字段的写法应当保留并制度化：**每个生灵条目要能分别写出"人们相信什么"和"实际上是什么"**。

## 3. 生灵与人互动的通用方式

下表的"所需机制"只用架构已有的八个概念和三种声明式形状，外加本需求提出的少数新种类（标 ★ 的是缺口）。"义务"指 obligation 种类，"持有"指 holding 种类，"规范"指规范条目，"知情"指主观视图、推断与 tell，"仪式"指 §4 的仪式动作形状，"时钟"指到期项或时钟规则。

| # | 互动方式（母题大类参考 Thompson 索引） | 所需机制 |
|---|---|---|
| 1 | **附身**（E、F、V 类） | ★持有 `possesses`（生灵 → 人，exclusive，handover：宿主死则关闭，生灵进入游荡）；★非自愿精神状态族（`super:possessed`，不要求同意，但必须有生灵为来源，并带合法性标签）；知情：症状被他人看见 → 推断规则在"病 / 祟 / 装"之间给候选，并按文化先验加权（误诊是玩法）；仪式：驱离；自愿附身（降神、灵媒）是另一种持有条款 `consensual: true`，读同意规则 |
| 2 | **诅咒**（M 类"预定未来"、D 类魔法） | ★状态带"解除条件谓词"（`liftWhen`：达成某事、某人死、某物归还）；★媒介链接（受诅物 item 或人的毛发、名字，见 #13）；可继承的诅咒 = 持有 `cursed_by`，handover 为 `succeed_to_heirs`；时钟（定期发作）；规范（施咒在多数法典中有罪名标签 `offense:maleficium`，上位 `offense:harm`）；仪式：解咒、反咒、转嫁 |
| 3 | **迷惑与幻形**（K 类欺骗、D 类） | 物或人的 `purports`（自称的样子）与真实分离，这是 01 已有机制的扩展：感知派生在某些条件下（镜、狗、符、晨光）给出真实；状态 `glamoured`（被迷路、被蒙蔽）；动作：识破（检定读形态与反制物） |

| 5 | **婚配**（ATU 400–459 超自然配偶，T 类） | 持有 marriage（已有亲属与婚姻种类，放宽两端模板允许 creature）+ ★附带禁忌的条款（`taboo`：不许窥看原形、不许提起出身、不许在某日进屋）；违反禁忌 → 反应规则：holding.close + 生灵离开 + 子女留下；后代 `super:hybrid` 事实；冥婚 = 一端是亡者的婚配持有（需要 §5 Q7 决定死者能否作为持有人） |
| 6 | **报恩**（Q 类"奖赏"、B 类"动物报恩"） | ★义务 `gratitude`：由事件（救命、放生、葬骨）经反应规则自动创建，债务人是生灵，债权人是恩人；清偿方式由生灵的驱力与能力派生（送宝、护佑、化人相报）；不设到期日，或设一个"必须报"的期限；债权人死亡 → 转到其子孙（`onCreditorGone: heirs`） |
| 7 | **复仇与冤屈、索命**（Q 类"惩罚"、E 类亡者回归） | ★义务 `grievance`：由冤死、不葬、毁巢、背约事件创建，债权人是亡魂或生灵，债务人是加害者（可继承到子孙，或按文化规范"冤有头债有主"不继承）；可以由"伸冤"（案件定罪 = 清偿）、赔礼、供奉、迁葬来清偿；违约（长期不清偿）→ 索命，即 vital 或 status 原语；知情：加害者往往不知道自己被记了债，托梦是 tell |
| 8 | **作祟与安抚**（E、V 类） | 时钟规则：依附于地点的生灵按驱力与存量周期性产出原语（怪声 → impress，病 → status，器物损坏 → fact.set）；安抚 = 供奉 transfer 进生灵的账户，或立祠 create(building) + ★持有 `enshrined_in`；香火的存量决定作祟强度（修正槽 `super:hauntPressure`）；被供奉的怨灵可以转为地方神（日本菅原道真成为天神就是这类先例）：处境的派生从 wandering 变为 enshrined，进而可以持有 local_god 职位 |
| 9 | **驯服与驱使**（D 类魔法控制、ATU 500–559 超自然助手） | 已有持有 tamed_by（动物）；★持有 `bound_by`（役鬼、式神、精怪仆从：条款有供养义务、命令范围、期限、解约方式）；规范：役使亡魂在多数文化与法典中是罪或破戒（标签 `offense:necromancy` 或类似词）；召唤师现有的"合法役灵"概念要扩展到全部 `super:*`，"合法"由规范栈派生 |
| 10 | **镇压与封印**（D 类） | ★持有 `sealed_by`（被封者 → 封印物或封印地，handover：封印物被毁 → 关闭持有，产生 release 事件）；封印有强度存量 + 时钟（衰减）+ 维护义务（定期补符，即葭界的"撤旧符日"）；知情：谁知道封印在哪；规范：擅自揭封是罪 |
| 11 | **超度、安息与转生**（E 类、V 类） | ★transition 新起因 `rested`（安息）、`reborn`（转生），沿用 04 的 gone 流程（亡魂实体消失，交接其义务）；条件来自仪式与驱力满足（冤已伸、骨已葬、愿已了）；转生可以生成新个体，并带一个 `rebirthOf` 不可变事实（可选，见 §5 Q7）；不同文化的安息条件不同：亡魂的文化或宗教归属派生出它"认"哪种仪式 |
| 12 | **献祭与供奉**（V 类，Mauss 的互惠） | transfer 到 ★源汇 `sink:offering`（凡间可见的消耗），同事务的另一笔：生灵、神祇或阴间账户 `src:offering_realm` 增加（守恒：两本账要能对平，或者把阴间账户定义为同一转移的另一端）；"焚化纸钱"是一种转移路径（凡间物质销毁 → 阴间账户增加）；以活物献祭：动物可以；**以人献祭只能出现在反派、历史与传闻中，不提供给玩家作为可执行的动作**（规范 + 内容纪律） |

| 18 | **召请与降临** | create（召唤物）或 move（从异界地点来）+ upkeep 义务；"请神"必须取得神的同意（神作为实体时走 NPC 决策；作为不在场实体时走有限神迹预算） |
| 19 | **变形** | 个体事实 `form`（当前形）可以由 fact.set 改变；身份知情：认得人形不等于认得兽形（主观视图里两条认知链，被揭穿后合并）；狼人式的非自愿变形 = 时钟 + 状态 |

| 21 | **异界之旅**（ATU 中的冥府之旅、希腊的冥府之行 nekyia、萨满的出神） | 异界是地点（§5 Q7）；路线有特殊的进入条件（死亡、出神状态、仪式门户）；出神 = 身体留在原地（失能，impaired），魂以另一种位置移动；归途有禁忌（回头、吃异界食物） |
| 22 | **考验与试炼**（H 类） | 生灵发起的动作：request(试炼)，结果决定奖赏或惩罚；与 #6、#7 同一形状 |
| 23 | **赐福与护佑** | 修正项（`when` 谓词 = 持有某护身符 / 受某灵庇佑 / 某日），有期限（时钟）与维持义务 |
| 24 | **疫病与灾异归因** | 05 §5.5 的疫病与灾害可以有"超自然来源"作为修正项来源（某作祟提高感染率）；更重要的是**知情层的归因**：民众把疫病推断为"闹鬼"或"被巫害"→ 舆论、猎巫、误伤无辜（呼应葭界的禁忌） |

**横向要求**：每种互动都有"人对它的认识"和"它的真相"两层；每种互动都能成为传闻和书本知识（妖怪志条目）；每种互动都有至少一种不靠战斗的解法（交涉、仪式、满足需求、查明真相）。

### 4.2 仪式（不是职业）

仪式应当是一种**动作形状**，由谁来主持取决于主祭资格谓词（职位、职业阶、受戒、受神认可），而不是写死在某个职业里。按 van Gennep 的三段论，大多数过渡类仪式（葬、婚、成年、入教）都能拆成"分离—阈限—聚合"三段；驱邪、净化、献祭、占卜则是"准备—施行—封结"。

| 仪式族 `rite:` | 各文化的例子 | 机制要点 |
|---|---|---|
| funeral 葬仪 | 土葬、火葬、船葬、风葬、二次葬（Hertz）、木乃伊制作 | 让亡者"得到安葬"，是阻止滞留的主闸门；要求依死者的文化与宗教归属而定（数据） |
| ancestor 祭祖 | 中国祭祖与寒食清明；罗马的祭亡节 Parentalia；印度的祭祖 śrāddha；美索不达米亚的亡灵供食 kispum | 周期性转移（时钟），满足 `dead:ancestor` 的需求；断祀 → 祖灵转为饥渴亡魂 |
| feed_hungry 施食 | 盂兰盆与放焰口；罗马的驱亡节 Lemuria（抛豆送亡灵）；希腊在十字路口供给赫卡忒的晚餐 | 面向无主亡魂种群（§5 Q5）的群体安抚，降低作祟压力 |
| exorcism 驱离 | 道教驱邪、傩、āšipu 净化、各地的驱魔 | 关闭 possesses 或 haunting 持有；**误诊（其实是病或装）时的后果必须有数据** |
| sealing 封镇 | 符镇、镇物、压胜、以石或山压住 | 打开 sealed_by 持有，带维护义务 |
| pacify 安抚与立祠 | 日本的御灵信仰；中国的立庙祀厉鬼 | wandering → enshrined |
| offering 献祭供奉 | 奠酒、燔祭、北欧献祭宴、烧纸钱 | 转移；`do ut des`（罗马"我给是为了你给"）= 供奉换来生灵的义务或修正项 |
| divination 占卜 | 龟卜、蓍草、鸟卜、脏卜、卢恩、抽签 | 只产生知情，不改事实 |
| summoning 召请 | 请神、召魂（《楚辞·招魂》一类的招魂仪式）、降灵会 | 创建或移动生灵，开启契约 |
| purification 净化 | 洗浴、烟熏、盐、圣水（宗教中的现实用法只取功能） | 移除 `pollution`（洁净或污秽的状态），这是许多生灵规矩的前置 |
| binding 盟约 | 歃血、誓言、写在铅板上的诅咒或约束（希腊的诅咒板 katadesmoi）、约束书 | 产生义务与规范 |
| curse_counter 反咒 | 巫瓶、焚烧巫偶、namburbi（美索不达米亚的禳解凶兆仪式） | 关闭 cursed_by，可以选择"反弹"给施咒者（反咒是另一条带法律后果的原语） |
| passage 过渡 | 入教、成年、婚礼 | 产生或改变持有；与超自然的关系是"在阈限期最容易受侵扰" |

## 5. 关键设计问题（交给架构师）

### Q1 跨文化效力：道士的符对北欧亡灵是否有效？

| 方案 | 内容 | 利 | 弊 |
|---|---|---|---|
| A 普遍论 | 效力只看机制标签：符 `ward:dead` 对一切 `super:dead` 一样有效 | 最简单；跨文化内容即插即用 | 文化差异被抹平；"按其文化安葬"失去意义 |
| B 文化绑定 | 只对同文化的生灵有效 | 文化味最浓 | 组合爆炸；跨文化的村子里道士无用武之地；第三方文化"落地无声" |
| C 标签匹配 + 文化亲和修正项 | 基础效力 = 仪式或物件的目标标签与生灵本源链的最近公共上位词的距离（越近越强）；再乘文化亲和修正项（同文化 ×1，近缘文化圈 ×0.8，异文化 ×0.5，由数据给出）；材质类克制（铁、火、盐）不受文化影响 | 可解释（界面能说出"为什么只有一半效果"）；新文化只需挂上位词与亲和表 | 亲和表本身是 N×N 的数据；需要平衡 |
| D 信念论 | 效力取决于生灵（或亡者生前）认不认这种仪式：亡魂读自己的文化与宗教归属，"它信什么就怕什么"；自然灵和异兽不受信念影响，只认材质与规矩 | 最贴近民俗逻辑；让"按他的规矩送他走"变成玩法；与"派生优先"一致（认什么由归属派生） | 要求亡魂保留生前的信仰归属；无归属的种群要有缺省 |

**建议**：C 与 D 组合，按机制分两类：**物理与规矩类**（铁、火、盐、门槛、日光）走标签与材质，不分文化；**意义类**（经文、神名、符、葬仪）走 D（读生灵的归属），D 缺省时退回 C。

### Q2 文化圈作为概念还是标签？

| 方案 | 内容 | 利 | 弊 |
|---|---|---|---|
| A 新存储概念 | 文化圈成为第九个概念 | 表达力强 | 违反"存储层只认八样"，不可接受 |
| B 实体 | 文化是一种实体（collective 模板的子类，不可作持有人） | 可以挂事实（规矩、亲和、葬俗）、可以版本化 | 文化不"行动"，硬当成实体会诱导出不该有的持有 |
| C 词汇标签 + 数据表 | `culture:*` 是有上位链的词（`culture_ms_taideng` → `sphere:beastfolk` → `sphere:*`），文化的规矩、亲和、葬俗、职业变体都是一方包或 lore 里的数据表，派生规则查表 | 不增加概念；上位链直接给出跨文化回退 | 数据散在几个表中，需要作者工具汇总视图 |
| D 混合 | 文化圈（大类）是标签层级；具体文化是 lore 数据记录，其 id 同时是一个词 | 兼有 B 与 C 的优点 | 两套 id 需要保持同步（由加载校验保证） |

**建议 C 或 D**。还要同时决定：生灵的文化是**不可变事实**（来自物种或原典），还是**派生**（从栖地、所属聚居地和供奉者派生）。建议物种带"原型文化"作为不可变事实，个体的"当前归属"派生（被北境人供奉的游魂会逐渐"认"北境的仪式，可以作为修正项）。**职业的文化变体**同样应该派生：一个人的职业是一条持有，变体由"职业 × 师承所属文化"派生出称呼、材料、仪式名，不新增职业 id。

### Q3 克制关系的数据形状

| 方案 | 内容 | 利 | 弊 |
|---|---|---|---|
| A 矩阵 | 仪式或物件 × 生灵种类的效力表 | 直观 | N×M 增长；第三方包无法扩展 |
| B 双边标签 + 派生 | 物件、仪式带 `ward:*`、`bane:*` 标签；生灵的物种事实带 `vulnerable: [{to: tag, effect: primitive, magnitude, when}]` 与 `immune: [tag]`；派生规则做标签上位链匹配 | 线性增长；可以按上位词回退；第三方新物件只需打标签 | 需要一个"效力"派生的修正槽 |
| C 纯修正项 | 每条克制都是一条修正项，挂在 `super:efficacy`、`combat:damage` 等槽上 | 复用 05 §5.9 | 修正项过多会撞上预算；不利于作者阅读 |

**建议 B**，再开放修正槽 `super:efficacy`（文化亲和、时辰、主祭资格、供品品质都挂在这里）。首领现有的 `weaknesses: [{tactic, requiresStatus}]` 应迁移到同一形状。另外要决定**传说中的弱点是否为真**：建议物种在事实层写真实弱点，传说层另写"民间以为的弱点"，两者可以不一致（现有 folklore 字段的风格）。

### Q4 仪式的成败与代价

| 方案 | 内容 | 利 | 弊 |
|---|---|---|---|
| A 确定性 | 条件全部满足即成功（无检定） | 可预期；适合葬仪、祭祖这类"做对了就成"的仪式 | 缺少张力 |
| B 单次检定 | d20 + 技能 + 修正 vs 难度 | 与现有动作一致 | 多日的法会不该一掷定输赢 |
| C 阶段工程 | 仪式是 project 实体（已有临时法人种类），分阶段 schedule，每阶段有前置、材料、在场角色；中断留下"未处理区"（道士的清秽分段）；最后一阶段可以检定 | 能表达斋醮、葬仪、出神；中断可以被敌人利用 | 实现复杂度高 |
| D 诊断先行 | 成败首先取决于"诊断是否正确"（目标真的是祟吗？真的是这个亡魂吗？），诊断来自知情层；诊断错误时仪式必然无效，甚至伤及无辜 | 把知情层与仪式绑在一起；呼应现有的误认与禁忌数据 | 需要好的界面来展示"你以为的"与"实际的" |

**建议 C + D**：仪式 = 一种动作形状（`kind: rite`），短仪式退化为单阶段。**代价**应当是多种的、并且都可审计：材料（transfer 到汇）、时间、魔力、香火（组织账户）、**灵债**（向生灵或神欠下义务，例如请神之后必须还愿）、**戒律后果**（役鬼破戒）、**反噬**（06 §6.6 的反噬表增加超自然条目：被附身、受诅、折寿、灵智受损）、**法律后果**（罪名标签）。

### Q5 生灵的个体与种群如何区分

| 方案 | 内容 | 利 | 弊 |
|---|---|---|---|
| A 全是个体 | 每个亡魂都是 agent | 精确 | 离屏与存档成本爆炸（每死一个人就多一个实体） |
| B 种群 + 物化 | 无名亡魂是地点上的 population 账户（子账户：未安息 / 已安息，类似疫病的 S/I/R）；被注意到、被命名、有冤的才物化为个体（沿用 07 的物化与聚合，总数守恒） | 与生态、疫病是同一形状；统计层便宜 | 物化时要给出一致的身份（谁的鬼？），需要按种子从当地死亡记录中抽取 |
| C 只要个体与派生压力 | 不建亡魂种群；地点的"阴气 / 作祟压力"是从当地未得葬仪的死亡事件派生出来的值 | 最省；不增加账户 | 施食、群体超度没有对象可减；派生压力不能"被转移走" |

**建议 B**：人死后**若未在 N 天内（数据，按文化）得到葬仪**，就向当地 `pop:unrested_dead` 账户转入 1（来源是该次死亡事件；身份链接保存在事件中，物化时可以追溯）；有 grievance 义务的死者直接物化为个体。精怪物种（狐、树精）按现有规则：普通的是种群，开灵或修成的个体是 agent。

### Q6 神祇级存在与"有限神迹"的边界

现状：神祇是 lore 条目，"真实存在、直接显现须留下可追查的资源损失和职责后果，平常通过有限神迹回应"。

| 方案 | 内容 | 利 | 弊 |
|---|---|---|---|
| A 神只是派生 | 神没有实体；神迹 = 仪式效力的修正项 | 简单；不会出现"打神" | 神无法"拒绝"、不能有立场、不能回应祈求 |
| B 不在场的 agent 实体 | 神是 agent，没有位置（或位于异界地点）；有香火与神力账户（只由供奉流入）；只能通过注册的"神迹动作"行动，每次从账户扣除，幅度上限由账户与职责派生，必须留下可见痕迹（事件 + 资源损失） | 与"有限神迹 + 可追查"完全一致；神可以有立场、可以拒绝；守恒 | 需要 NPC 决策对"神"的特化；要防止神被玩家利用为无限资源 |
| C 神 = 组织 | 神等同于其教会组织 | 复用组织 | 混淆神与人的机构；教会可以腐败而神不可以 |

**建议 B**，并划出边界：
- **神祇**（`divine:deity`）：不在场，不可被击杀、伤害或驱使（硬规则，加载期校验）；只能经神迹动作行事；神迹的幅度有全局上限。
- **神使、地方神、半神**：在场的 agent，可以交涉，按自己的规矩行事；**地方神是职位**（城隍、土地 = office，持有人可以是亡者或精灵，任命者是神或阴间组织）。这一条把"城隍"这类民间信仰直接对应到 05 §5.3 的职位模型，继任、罢免、俸禄（香火）都可以复用。
- **现有 12 位神祇**是本世界真实的神；外来神话中的神祇原型只以本世界原创的神出现，或作为现实古神（`realWorldFigure`，互动上限对话与赐物，13 §13.1A），或以"他乡的传说"出现在书本知识中（见 Q8）。

### Q7 阴间与亡魂社会的结构

| 方案 | 内容 | 利 | 弊 |
|---|---|---|---|
| A 无阴间 | 亡魂只滞留在人间；安息就是消失 | 最省 | 冥府之旅、阴司审判、冥婚、烧纸钱无从实现；PLAN 已经把"阴间社会"列为缺口 |
| B 统一的异界地点树 | 一棵"幽冥"地点子树，下分各文化的冥土（地府、北欧的冥界与英灵殿式去处、埃及式的冥世、希腊式的冥府、阿兹特克式的冥界……全部以**原创名称**出现，原型只作设计依据），各有法典（阴律）、职位（判官、接引者）、法域与路线；进入要满足条件 | 完全复用地点、法域、规范栈、职位、案件；"阴司审判"就是案件 | 内容量大；需要决定异界之间、异界与人间之间的路线；统计层离屏 |
| C 抽象命运 | 不模拟阴间；亡者的去向是一次派生（按生前事迹与葬仪，算出"去了哪"），只在知情层可见 | 便宜；仍然支持"烧纸钱到了没有"这类问题（派生） | 无法游历；阴间没有社会 |
| D 分级 | 默认 C；当玩家或剧情触及时，按需物化出 B 的局部（只建一个冥土郡和路线），沿用 07 的三层模拟 | 成本可控，可扩展 | 物化前后要保持一致 |

**同时要决定**：
1. **亡魂与生前实体的关系**：(a) 同一实体，transition 到"亡"态继续存在（但 04 规定消失者名下不得有任何存活持有，所以亡态必须是一个不持有凡间财产的新模板状态）；(b) 新建亡魂实体，带 `soulOf` 不可变事实指向原实体（建议此项：不碰转移协议；亡魂对旧宅的"主张"是 claim 契据，不是 owns 持有）。
2. **记忆是否延续**：亡魂是否继承生前的主观视图（建议：继承截至死亡时刻的知情，供"冤魂指认凶手"使用，其证据效力由法典决定）。
3. **烧纸钱的账**：凡间 `sink:offering` 与阴间 `src:offering` 是否必须一一对应（建议对应，由同一事务的两笔转移实现，以满足守恒审计）。
4. **转生**：是否生成新个体并带前世链接（建议可选，由文化数据决定是否存在转生；不存在转生的文化，亡者只能安息）。

### Q8 在世宗教的尊重边界如何写成规则

PLAN 的纪律：不把在世信仰的神祇当怪物或反派，取其民间生灵或改编原型；不收录社群明确反对外用的对象（如纳瓦霍的"换皮者"、澳洲原住民的"梦创"神圣存在）；避开威世智的专有怪物。

| 方案 | 内容 | 利 | 弊 |
|---|---|---|---|
| A 只靠人工审核 | 在 L2/L4 审核时检查 | 灵活 | 第三方包、后续批次都会漏 |
| B 词汇敏感度字段 + 加载校验 | 原型元数据 `sensitivity: {livingTradition: bool, closedPractice: bool, community, note}`；加载器硬规则：`livingTradition` 的神祇原型不能带 `hostile`、可掉落、可击杀、可驱使、可封印标签，不能作为"罪名对象"之外的负面角色；`closedPractice` 的条目一律拒绝加载；blocklist.json 扩展为"原型名 + 社群反对外用"的清单 | 自动化；第三方也受约束；可测试 | 需要维护原型清单；边界案例（佛教的饿鬼是民间生灵还是教义概念？）需要逐条标注 |
| C 全部原创化 | 世界内一律使用原创的名字与神，现实原型只出现在作者元数据里 | 最安全；与现有世界（18 种原创文化、12 位原创神）风格一致 | 用户想要的"希腊、北欧、埃及"辨识度会变弱 |
| D 分层命名 | 已无人信仰的古代宗教的**生灵与事件**可以在世界内用接近原型的名字（如九头蛇、守冢尸）；**神祇**一律原创化；在世宗教只取民间生灵，且按 B 方案标注 | 兼顾辨识度与尊重 | "已无人信仰"本身有争议（希腊与北欧多神信仰都有现代复兴群体），需要用户定口径 |

**建议 B + D**，口径交给用户确认（这是内容与玩法层面的问题，不是技术问题）。另外两条规则建议写进不变量：(1) **真实存在的在世宗教仪式不能作为可施放的"法术"注册**（如真实的经名、咒语原文）；只能用功能名，配合原创文本；(2) **"以人献祭""猎巫"只能作为反派行为、历史与传闻出现**：可以被玩家阻止、调查和审判，不能作为玩家获得增益的路径。

### Q9（追加）超自然的"真"有多少？

现有生灵数据的写法有明显倾向：传说往往被观察否定（"传说吸雾能治百病，凑近只闻到腥气"）。而神祇被设定为真实存在。需要定一条全局口径：

| 方案 | 内容 |
|---|---|
| A 祛魅为主 | 绝大多数超自然传说在事实层不为真，真正的超自然稀少而有代价；玩法重点在"查明真相" |
| B 民俗为真 | 传说大多为真，玩法重点在"按规矩应对" |
| C 逐条标注 | 每个母题或物种在事实层与知情层各写一份，真伪比例作为世界参数（按地区、文化可以不同） |

**建议 C**，缺省值贴近现有风格（真实的超自然有，但比传说少、比传说有限）。这直接决定 YG 和 WM 内容怎么写，需要在写内容之前确定。

### Q10（追加）非自愿超自然状态与同意规则的冲突

现行规则：精神类状态必须取得同意。附身、迷惑、诅咒在本质上是非自愿的。方案：(a) 生灵来源的精神状态豁免同意，但必须带合法性标签并可被检定抵抗；(b) 不豁免，改为"抵抗检定失败视为被动接受"；(c) 分两类：生灵对人（豁免，世界规则）与人对人（仍需同意，或构成罪名）。**建议 (c)**：保持现有"玩家与 NPC 之间不得强控心智"的设计，生灵作为世界的危险源例外，但玩家借助生灵（役鬼附身他人）仍然算人对人。

## 6. 验收用的需求条目（系统必须能做到）

每条都能写成无 LLM 的确定性测试或推演题。"数据决定"指改数据不改代码。

**类型与词汇**
1. 任何超自然生灵都能用本源、形态、依附、驱力、能力、规矩六条轴描述，且每个词都有上位词；加载一个只认 `super:dead` 的规则时，它对新包定义的 `dead:xyz` 生效，不需要改规则。
2. 一个生灵"现在是什么"（游荡、受供、被封、被驱使、有约、已安息）由它当前的持有、义务与状态派生；数据文件中出现这类字段即校验失败。
3. 同一个物种的"人们相信的弱点"和"真实的弱点"可以不同；玩家依传说使用错误的克制物时，效果按真实弱点结算，并留下"传说不灵"的知情。
4. 带 `sensitivity.closedPractice` 的原型条目加载失败，带 `livingTradition` 的神祇原型不能被标为可击杀、可掉落、可驱使或可封印，违者在加载期报错。

**亡者与阴间**
5. 一个人死后若在其文化数据规定的期限内没有得到葬仪，当地未安息亡者的存量加 1，并且能追溯到这次死亡事件。
6. 同一个亡魂在道观超度与在北境火葬礼中都能被安息，但所需条件（材料、主祭资格、时辰、在场者）不同，且由数据决定。
7. 亡魂对其生前文化或宗教的仪式反应更强；对异文化的意义类仪式只有部分效力，界面能列出效力的来源（文化亲和、时辰、主祭资格、供品）。
8. 亡魂安息后（transition 起因 rested），其名下的 grievance 等义务按声明的 onCreditorGone 处理，不留悬空的义务端。
9. 冤死者产生一个 grievance 义务，债务人是加害者；加害者在法院被定罪时这个义务视为清偿，亡魂的驱力随之消失。
10. 加害者不知道自己被记了冤债；只有经过托梦、占卜或调查，这条义务才进入他的主观视图。
11. 烧化纸钱（或任何焚化供品）时，凡间汇的减少与阴间账户的增加在同一事务内完成，全局账目能对平。
12. 城隍或土地这类地方神是职位实体；持有人（一个亡者或精灵）可以被任命、罢免、继任，其香火收入从职位与供奉派生，而不是写在人物上。
13. 断了祭祀的祖灵在若干周期后（时钟，数据决定）转为饥渴亡魂，作祟压力上升；恢复祭祀后可以回落。

**互动方式**
14. 附身是一条持有：宿主死亡时持有自动关闭，附身者转为游荡；驱离成功也关闭该持有，并产生可见事件。
15. 旁人看到附身的症状时，推断规则给出"病 / 祟 / 装"三种候选，权重按观察者的文化与知识而定；对实为疾病者执行驱邪，不能治愈疾病，并按数据造成伤害或耽误病程。
16. 驱邪时如果主祭没有合法授权（受箓、受戒或职位），法律或戒律包能识别出罪名或破戒标签，但不阻止动作本身（法律不拦截）。
17. 诅咒能带有解除条件谓词；条件达成时（如归还被盗之物）诅咒自动解除，不需要任何人施法。
18. 可继承的诅咒在受诅者死亡时按持有的交接规则转给继承人；继承人放弃继承（限定继承）是否能摆脱诅咒由数据决定。
19. 拿到某人的毛发或生辰帖后，可以对他发起寻踪或诅咒类动作；物品被烧毁后链接断开，这类动作失去前置。
20. 知道某个生灵的真名，可以让针对它的若干动作（命令、驱离、订约）的难度下降，下降幅度由数据决定；真名只能通过知情获得（书、拷问、交易、偷听），可以被 tell 传播。
21. 生灵带 `bound:threshold` 规矩时，未经邀请不能 move 进入带门槛事实的分区；被邀请后由事件留下许可，许可可以撤回。
22. 与超自然配偶的婚配是一条持有，附带禁忌条款；违反禁忌时，反应规则关闭婚配，生灵离开，子女仍是双方的亲属。
23. 放生、救助、葬骨等事件可以自动产生报恩义务（债务人是生灵）；生灵按自身的驱力与能力派生出清偿方式，恩人死亡后债权转给子孙。
24. 与生灵的交易可以约定延期的代价；到期时如果债务人已死，按 onDebtorGone 追到其亡魂或继承人，具体由契约数据决定。
25. 人间法典可以把一份与生灵订立的契约判为无效，但生灵一方的规范仍认为有效；两者的冲突由规范栈的冲突法给出结果，并对玩家可解释。
26. 封印是一条持有，带强度存量与衰减时钟；封印物被毁时产生释放事件；维护（补符）是周期性的义务，可以欠下并违约。
27. 被长期供奉的怨灵，其处境可以从游荡变为受供，并进一步获得地方神职位；整个过程只通过事件、持有和职位任命完成。
28. 依附于某棵树的精灵与那棵树的资源点账户相连：砍伐转移会同时伤害精灵，并按林地议会的法典命中"惊扰精怪"罪名。
29. 生灵在阈限时间（夜半、节日、特定月相，数据定义的日历窗口）的活跃度与仪式效力能经修正槽变化，界面能说明原因。
30. 占卜只产生带置信度的知情或信念，永远不改变事实；伪占卜（装神弄鬼）和真占卜对外表现一样，区别只在事实层，可以被揭穿。

**职业与仪式**
31. 仪式是一种动作形状：有主祭资格谓词、在场角色、分阶段、各阶段的材料和时辰条件；中断时留下"未完成"的状态与后果（如未处理的区域）。
32. 一个仪式的主祭资格由持有派生（职业阶、受戒、职位、神的认可），同一仪式可以由不同职业主持（葬仪可由祭司、僧侣、道士或殓葬师主持），效果按资格与文化修正。
33. 同一职业在不同文化中呈现不同的变体（称呼、材料、仪式名），变体由"职业持有 × 师承文化"派生，不新增职业 id；更换师承后变体随之改变。
34. 道士的辟邪符是物品，有作者、授权与真伪；伪符的 purports 与真符相同，实际无效，用后会产生"伪符流通"的推断与传闻。
35. 元素召唤师可以与任何灵智足够、愿意回应的 `super:*` 生灵订约；役使亡魂会在适用的规范栈中命中罪名或破戒标签；订约对象拒绝时走 NPC 决策规则。
36. 出神（或同类能力）让施术者的身体进入失能状态并留在原地，同时其魂在异界或远处以另一个位置移动；身体在此期间受伤会影响魂，魂未归时义务照常到期。
37. 自愿附身（降神）需要宿主同意，任何时候撤回同意都会终止附身（与现有"暮境见证"的代价写法一致）；非自愿附身属于世界危险源，人借生灵对人施加则构成人对人的罪名。
38. 至少有一个隐藏职业的触发事迹是"在三种不同文化中各完成一次让亡魂安息的仪式"，计数从事件派生。
39. 每一种互动方式都至少有一条非战斗的解法（交涉、满足需求、仪式、查明真相），推演测试能在不使用 vital 原语的条件下解决附身、作祟、诅咒、冤魂各一例。
40. 克制关系由双边标签加上位链匹配算出；新增一个文化圈的物件（例如某种新植物，带 `ward:dead`）时，所有既有亡魂自动受其影响，不需要修改任何生灵数据。

**神祇与边界**
41. 神祇实体不在场，不能成为 vital、bound_by、sealed_by 的标的（加载期与事务期双重校验）；神迹动作每次从神力账户扣减，幅度不超过派生上限，并留下可追查的事件与资源损失。
42. 以人献祭不能注册为玩家可执行并获益的动作；NPC 或反派的献祭事件可以被调查、阻止和审判。
43. 无 LLM 模式下，上述每一种互动在动作目录中都有对应的注册动作或构造器路径，以及事件流模板。
44. 生灵与仪式的全部新增内容都以包的形状接入（词汇、持有、义务、规范、修正项、推断规则、动作），卸载包后存档仍能载入，已有的封印、契约、冤债按卸载处置规则处理。

## 7. 防重复与可区分度（用户追加，2026-10-15）

用户原话："神和怪物一多就很容易重复，比如很多怪物都和火有关，这地方你要设计好。"补充修正："也不能硬拆成同一元素的不同怪……这样会导致神太多。"

### 7.1 原则：宁合不拆

1. **目标是让每个存在有分量，不是增加数量。** 防重复用来判断两条内容"是不是真的不同"，不用来制造新条目。区分手段（元素×关系、特征向量）都只是判据，**禁止为了填满某个格子而新建生灵**（例如"火 × 畏惧""火 × 吞食""火 × 由其所生"各造一只怪）。
2. **机制无实质差异就合并。** 两个候选在系统里触发的机制相同（同样的互动方式、持有与义务、克制、生命周期转换），就是同一个存在；各文化的说法成为它的**别名与地方传说**（知情层的书本条目与传闻），可以互相矛盾。
3. **称呼按观察者派生。** 合并后的物种只有一个 id；玩家或 NPC 看到的名字由观察者的文化与所在地派生（派生优先），人们叫"水猴"还是叫"水鬼"，取决于是谁在说话。
4. **分立的门槛是机制差异，不是描述差异。** 外形、颜色、出处不同都不构成分立的理由；只有跨文化变体真的带来不同机制（例如一种要求邀请才能入门，另一种怕流水），才分成两个条目，并且仍然归在同一个原型族之下。
5. **神祇采用"一神多面"。** 同一个神在不同地域与文化中有不同的名号、形象、祭仪与禁忌，但共享一个实体（一个神力账户、一套职责与规矩）。多个文化都有"雷神""冥王""太阳神"时，它们是已有神祇的不同面，而不是新增的神。
6. **神祇与大型存在设总量上限**（§7.5）。

### 7.2 判据：机制签名与特征向量

**机制签名**（判断"是否不同"的主要依据，从数据自动计算，不由作者手填）：一个生灵条目在系统里会用到的 {互动方式（§3 的 24 类）、持有种类、义务种类、克制与免疫（§5 Q3 的形状）、生命周期转换（出生 / 开灵 / 化形 / 死亡后转化 / 安息条件）、规矩 `bound:*`、能力 `power:*`} 的集合。

**特征向量**（辅助判据，用于发现"签名不同但实际上很像"的情况）：
| 维度 | 内容 |
|---|---|
| 元素 × 关系 | 元素（火、水、土、风、光、暗、木、金、冰……）与关系的组合：产生、吞食、畏惧、操控、由其所生、被其所缚、化为、依附于。**同一元素的不同关系是不同机制**（"由火所生"与"畏火"是两回事），所以它可以证明两个火系生灵确实不同；但它不是造怪的模板 |
| 生态位 | 食性、栖地、活动时段（昼、夜、晨昏、阈限时间）、体量与群居性 |
| 与人的互动 | §3 的互动方式及其主次 |
| 弱点与克制 | ward/bane 标签 |
| 生命周期 | 来源与转化链 |
| 社会性 | 独居、群居、有社会（怪物社会、聚居地）、有主人 |
| 母题 | ATU 与 Thompson 大类，以及 YG/WM 的母题索引 |
| 驱力 | §2.3 的 drive |

**独有钩子**：每个保留下来的条目，都必须至少有一条机制或行为在**同原型族、同地区**内是独有的（例如"只在有人哭丧时出现""收到供品必须回礼"）。找不到独有钩子的候选不收录，或者并入已有条目成为别名。

### 7.3 原型族

跨文化的同类生灵归入一个**原型族**（例：变形诱惑者、拖人入水者、守冢尸、家宅灵、饥渴亡魂、火中生灵）。原型族是词汇层级里的一个上位词（与 §2 的本源轴相容），它的作用有三个：
1. **合并的单位**：L1 审查先在原型族内比对。
2. **跨文化规则匹配**：对原型族生效的克制与仪式，自动作用于族内的所有条目。
3. **配额的单位**：每个地区每个原型族只容少数几个条目（§7.5）。

族内分立的条目，必须在机制签名上与族内其他条目有差异，并写明差异（`distinctFrom` 字段，沿用 12 §12.3.3 的词汇闸门写法）。

### 7.4 生态位竞争排斥

1. **创作期**：同一地区同一生态位（栖地 × 食性 × 活动时段的重合度超过阈值）只容一个稳定物种。新候选与现有物种生态位过近时，L1 退回，并建议"合并"或"换地区"。
2. **运行期**：机制不同、但生态位部分重叠的物种，通过 05 §5.5 的种群竞争表互相挤压（竞争系数由生态位重合度派生），结果成为世界事件（某种精怪退出某地、迁徙、传闻"某林的狐少了"）。这是重叠的自然结果，不是新增内容的理由。
3. 人格化的个体（首领、具名精怪）的"生态位"还包括它的领地与职能；两个首领不能同时 controls 同一领地而不发生冲突。

### 7.5 神祇层：一神多面与总量上限

**一神多面**：
- 神祇是一个实体（§5 Q6 方案 B），面（aspect）是这个实体的作者事实：`{id, culture/region, 名号, 形象, 职能侧重, 祭仪, 禁忌, 圣物}`。寺观与信众持有的是"奉某神的某面"（devotion 持有的条款里记面 id）。
- 外来神话里的雷神、冥王、太阳神，**首先映射为现有 12 位神祇或新神的一个面**；只有当职能确实不能被任何已有的神覆盖、而且配额允许时，才新建神祇。
- **职能拆分与地域化**：一个神话里的"大神"如果职能太宽，可以按职能拆到不同的已有神祇身上（雷 → 某神的雨水面，审判 → 某神的契约面），也可以只保留与本地域相关的那一面。
- **诠释冲突**：不同的面属于同一个实体，这是事实层的真相；信众未必知道或接受这一点。两个教派"我们拜的是同一位吗"的争论属于知情层（信念、立场、舆论、寺观竞争），可以引发改宗压力、合祀或冲突，但神本身只有一个账户、一套规矩，神迹预算不会因为面多而翻倍。
- **尊重在世信仰**：面是本世界原创神祇的面；现实中在世宗教的神不作为任何神的"面"，也不作为生灵（§5 Q8）；现实古神同样不作"面"、不作生灵，只在宗教与朝拜系统内按 13 §13.1A 存在。除现实古神外，现实神话只作为原型元数据，在世界里出现的名号、形象与祭仪都是原创的。世界里不出现"某个现实宗教的神其实是我们的某神"这类断言。

**总量上限**（数字交给架构师与用户定，这里给决定方式）：
1. **神祇实体**：全世界一个硬上限（现有 12 位，加上少量新增，总数建议为个位数到十几位）；新面不受实体上限约束，但每个文化圈的面数有上限。
2. **大型存在**（传说级生灵、半神、地方神职位以外的神使、首领级精怪）：**按地区与文化圈配额**。配额 = 文化圈份额（WM 规模比例：中国约四成，其他圈按 WM-1 的八圈分配）× 世界总量，再按九省及各政体的面积与人口分摊；每个省有密度上限（例如每省传说级存在不超过若干个），保证"一个省里遇到一个大妖是件大事"。
3. **原型族配额**：每个地区每个原型族的条目数有上限（建议很小，例如 1–2 个）。
4. 配额是数据（一方包的参数表），由加载校验执行；超额时报错并列出可以合并的候选。

### 7.6 自动检查与指标

1. **L1 内容审查**：对每个新候选计算 (a) 与同原型族、同地区条目的机制签名 Jaccard 相似度；(b) 特征向量的加权距离；(c) 描述文本的相似度（只作辅助）。超过阈值 → 退回，附"建议并入 X，作为 Y 文化的别名"。没有独有钩子 → 退回。
2. **标杆标准新增"可区分度"指标**：盲测给出同一地区两个条目的描述（去掉名字），判断是否为不同的生物（人工抽查或 L2 模型盲判），区分率需达到阈值；同时报告**合并率**（被合并为别名的候选比例）和**独有钩子覆盖率**（应为 100%）。
3. **神祇层检查**：新神祇必须说明为什么不能作为已有神的面；超出配额或职能与已有神重合度过高 → 退回。
4. 这些检查都以作者工具命令提供（12 §12.7），对第三方包同样生效。

### 7.8 验收条目（续第 6 章）

45. 任一新生灵候选在加载期（或 L1 审查时）自动计算出机制签名；与同原型族、同地区的已有条目签名相同则拒收，并给出"并入 X 作别名"的建议。
46. 每个已收录的生灵都至少有一条在同原型族、同地区内独有的机制或行为；作者工具能列出这条独有钩子，覆盖率为 100%。
47. 两个火相关的生灵只有在元素×关系或其他机制上不同时才能并存（例如一个"由火所生"、一个"畏火而食灰"）；仅外形或出处不同的两个候选会被合并。
48. 合并后的物种只有一个 id；北境观察者与镜沼观察者看到的名字不同，由观察者文化派生；两地的传说可以互相矛盾，并分别成为可读的书本条目。
49. 同一地区同一生态位的两个物种，在创作期被检查拦下；部分重叠的物种在运行期通过种群竞争表互相挤压，结果作为世界事件和传闻出现。
50. 一个神祇有多个面；在两个文化里分别奉祀它的两座寺观，向同一个神力账户供奉，神迹预算不因面的数量增加。
51. 两个教派对"是否同一神"的分歧只存在于知情层（信念、立场），可以引起改宗压力或寺观竞争事件；事实层始终只有一个神祇实体。
52. 新增神祇必须声明为什么不能作为已有神的面；超出全局神祇上限或文化圈面数上限时加载失败。
53. 传说级大型存在按地区与文化圈配额校验；某省超出密度上限时加载失败，并列出可以合并或移往他省的候选。
54. 标杆标准报告可区分度（盲测区分率）、合并率、独有钩子覆盖率三个指标，并有通过阈值。
55. 对现有怪物与首领数据运行同一套检查，产出合并候选清单（不自动合并，交由用户确认）。
56. 第三方内容包同样受机制签名、独有钩子、原型族配额与神祇上限的检查，违者在加载期报错，错误信息指出与之冲突的已有条目。
