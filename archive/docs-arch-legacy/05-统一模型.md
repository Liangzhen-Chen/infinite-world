## 5.1 经济

**账户**：人（钱袋、随身物）、建筑/商号（库存、经营账、柜台现金）、聚落（公库、粮仓、公产、聚合市集账户）、组织（公库）、钱庄网点（现金）、遗产与案件（托管）、资源点（储量）、残骸（可回收物）、源汇。账户所属实体的位置就是价值的位置（15 §15.1.1）。铸币按政体与金属分资源种类（15 §15.3）。资源种类带商品类标签 `goods:*`（第12章 §12.4.5），替代品按商品类聚合。

**转移是唯一动作**：
- 买卖 = 同一事件里钱与物两笔互逆转移；市场渠道的成交价由市场投影按数量与**方向**出清（`settlePrice(…, side: sell | buy, business)`：商号卖出按加成、收购按折让，同一 `value`，15 §15.2；**小额按 `quote × q` 成交、总额取整一次，大宗才沿稀缺曲线积分**，边界 `retailShare`）。有有效双方同意的私约按本次冻结的约定价成交，不受市场渠道深度限制；实物、付款、权属、排他承诺、地点或交付载体约束仍成立（15 §15.1.1、§15.2.3）。【来源：LAW-astra-001，DS5 / MKT01】
- **拍卖**= 注册动作 `auction{lot（物品个体、持有或批次）, reserve, closesAt, paymentDays, fallback: next_bidder | reauction}` 创建 interim 实体 `project{kind: auction}`（执行人 = 拍卖方，附录 A §A.15.13）与落槌到期项，并对标的开立 `frozen`（持有人 = 该 project，01 §1.3）；出价 = 事件 `bid{amount}`（公开，进入在场者知情；出价人账户或信用由动作前置检查 `value` 上限）；落槌到期项取最高有效出价 → 创建义务 `auction_sale`（01 §1.4：付款义务 + 交付义务）；付款逾期 → 按 `fallback` 递补次高出价者（重新创建义务，起因指向违约事件）或重拍（新到期项），`frozen` 随结果关闭、project 关闭；流拍 = 无出价 ≥ reserve。官产拍卖的拍卖方是治理组织（职位 actedAs），所得入公库。
- **官员考绩**：章程 `appraisal: {period, rx: RX（读 `taxGap`、公库 `treasuryCover`、`cases(受理职位, 状态)`、舆论投影）, grades: [{id, when, effect: promote | demote | remove | none}]}`；时钟规则每期对各职位持有人产出公开事件 `appraisal{grade}`，`removalTriggers` 与任免候选（§5.7.3）读它；考绩只是事件，任免仍走议案 `appoint`。
- 税 = 反应规则在交易或按期事件后按税表条目向其 `recipient`（法域公库、节点控制者、职位所属组织、持许可者，附录 A §A.7）的转移，税表是规范栈中的条目（按商品类标签 × 聚落等级，主权法典与次级规范都可设，第三方的减免经补丁 §5.2.8）；关税与通行费 = 经过关卡或 `controls` 节点时按该节点规范栈税表与控制者条款的转移。**征管层**：税表条目的 `collection`（附录 A §A.7）决定税怎样到公库——`automatic`（缺省，上述反应规则）、`assessed`（经过关卡或按期 → 纳税人 `declare` 子事件 → `tax` 义务按申报额 → 税吏查验检定（读 `effective`、`dutyOfCare`、货物 `purports`、槽 `tax:inspection`）查获差额则补征并命中 `offense:tax_evasion`；未查验即放行是税吏以职位 actedAs 的 `release` 事件，受贿与过失谓词读它）、`farmed`（包税人收款并对公库负定额 `tax` 义务）；automatic 在纳税人账户不足时的差额转为 `tax` 义务（附录 A §A.7 税表条目），所以"税 = 反应规则转移"与 15 §15.1.1"税 = autoSettle 义务"是同一机制的先后两段。于是私盐过关、税吏受贿、漏征都有税额后果：`taxGap(法域, 期间)` = Σ `taxDue` − 实收，稽查与审计动作读它。
- 利息、租金、工资、分红、俸禄 = 义务按 `accruedTo` 闭式累计，到期清偿即转移。土地租约与建筑租约分两种条款：建筑租约的租金读 condition 派生系数；土地租约不读 condition，遇灾减租只能来自合同条款、规范条目（例如通过的"霜灾减租"村规）或出租人的动作。
- 存款 = 钱庄对储户的义务；汇票 = 不记名债权 + 代表它的票据物品，清偿前提是兑付地有该钱庄的 branch 持有。
- **票据结算**：以票据缴税或付款 = 票据物品 holding.transfer 给收款人 + 被清偿义务标记 `settledBy: 票据`（附条件清偿）。收款方"可用余额"派生时把未兑付票据列为应收而非现金。票据兑付时最终确定；若被拒付或识破为伪造（`represents` 为空），反应规则重开被清偿的义务（obligation 状态回到未清，起因指向拒付事件），收款方账面自然"冲回"——因为钱从未进入其账户，不需要逆向转移。伪造与行使伪造票据是否构成罪名由规范栈谓词判定（§5.2）。
- 质押 = pledged 持有；绝当 = 到期项把 owns 转给当铺；与冻结的优先见 14 §14.4。
- 股份 = share 持有（份额）；分红 = 组织 → 持有人的义务；价值 = 组织净资产 × 份额。组织章程 `acceptsShares: false` 时，"入股"提议被路由为捐赠（转移 + 功德/立场事件，不开 share、不生分红义务）。**增发与稀释**= `holding.rescale`（06 §6.3）：章程 `authority.issuance` 写明谁能增发、需全体持有人同意还是按 `votingWeight` 表决；法典民事⑦可再限制。未授权的"擅自增资"在事务内被拒（副手只是 employed_by / operates，没有增发权能），世界里只留下他的提议事件与传闻；授权的增发写 `holding_rescaled` 事件（前后份额表），不在场持有人经文书 / 传闻得知（I25）。
- **商号经营**（R5 专项⑦第 2 条）：商号 = business 实体 + `operates` 持有人；自治候选包括进货（库存 < 周转保留 → 向最近供给地或在场行商交易，或下托运义务；进货量经槽 `economy:restock`）、定价（读主观报价与库存压力改变店主加成）、用工（销量与人均处理量派生工时缺口，决定招工或解雇），以及维护、更新、缩减、暂闭、续营、转让或退出（§5.1.2）。周转保留由近期销量与现金流窗口派生（15 §15.2、§15.2.2）。统计层声明对应聚合变体（07 §7.3）。【补充来源：LAW-astra-001，DS2 / AS01、AS02】
- 雇佣 = employed_by 持有 + wage 义务；停工 = 反应规则 `当 wage 欠额 ≥ 阈 → status(employee, striking)`；辞工/挖人 = 持有关闭/新开。**工价来自劳务市场投影**：雇佣动作的缺省条款、商号用工候选的出价、雇员辞工 / 跳槽候选的比较基准都读统一估值 `value(劳务(技能族, 阶), 地点)`（别名 `wageQuote`；15 §15.2 估值表的劳务行：典型日收入表 × 用工需求 ÷ 可雇劳力 × 修正项，槽 `economy:value`）；已签条款冻结，所以"工钱整体上升"表现为新签与续签的工价上升、在职者被更高出价挖走——与商品报价同一结构，不另设劳务订单簿。
- **制造**：计量产出（面包、盐、铁条、布、酒、铸币）只能经**配方**从 `src:craft` 流入（制造守恒对：同一事务消耗配方投入；01 §1.6 的配方形状 `rules/tables/recipes.json`）；物品个体（杰作、符、车船）仍经 `create`。工坊的日产量是时钟规则（闭式）：配方 × `laborHours(business)` × 设施 × 槽 `economy:yield`；玩家与 NPC 的制作是注册动作（路由到配方，06 §6.8），即兴制作只能产出 `crude` 品级的物品个体（06 §6.7）。副产品与损耗由配方给出；产物批次带 `origin`（配方、制造者）与可选 `purports`（掺假、私铸）。私铸 = 产物为 `goods:coin` 的配方，合法性由规范栈判（`offense:counterfeiting`，§5.2.4）。矿、林、渔、田的产出不是制造：它们是从资源点储量账户的转移，储量由 `src:regrowth` 再生（§5.5）。
- 托运 = delivery 义务 + 车船物品实体（容量事实）+ 在途位置（move 原语按路线逐段，天气与封闭使其滞留）；护卫 = escort 义务，工资按实际天数累计。**出发时刻**：承运人（驿站、车行、船行、镖局）的实际出发按承运表 `rules/tables/carriers.json` 的 `departures`（附录 A §A.18）取下一班，到达 = 出发 + 路程 ÷ `transport:speed`（夜不行车顺延）；delivery 条款的到期日只是违约线，不是到达时刻。**运力**由派生得出：`min(车船容量, 所 owns 役畜种群数量 × 每头载量)`，役畜是商队或驿站 owns 的种群账户，马瘟使其数量下降 → 运力降 → 托运价与在途时间上升；**驱赶活畜**另有上限 `牧人数（在场 companion / employed_by 中有 `skill:herding` 者）× 每人可驱头数（技能阶表）`，超出的畜群不能随行（分趟），两者都经槽 `transport:capacity`。载体毁灭 → 货损条款立即触发（04 §4.2）。
- 远期交付 = forward 义务（青苗契等）：对价先付，实物到期交付；进入市场预期的条件见 15 §15.6。
- 价格、汇率、利率、银根、购买力、以及物品个体 / 生灵 / 土地 / 劳务 / 债权的估值：全部是市场投影（统一估值 `value(x, frame)` + 估值表），定义在 15 章；本节不写公式。

**生产投入**：产量派生（作物、矿、工坊）的**基础公式输入 = 资源点 / 田地事实 × 在岗工时**（在岗工时 = 该经营持有下全部 employed_by 与经营者本人的日程片段在期间内未被状态打断的时数，`laborHours(business, period)`；**非 person 劳力**：该商号 owns / commands / tamed_by 的标的若其物种或模板声明 `labor: {factor, hoursPerDay}`（役畜、傀儡），按 `factor × hoursPerDay` 折算计入，不需要 employed_by，用工候选的工时缺口随之减少；伤休、罢工、拘留、缺勤按比例折减）；农具、耕牛、肥料的存量以修正项进入槽 `economy:yield`（§5.9）；农户的投入决策是自治候选读价格（主观报价）与自身账户的成本收益判断，所以农具涨价 → 少买农具 → 下季产量修正降。

**统计层的经济**：15 §15.8。

### 5.1.1 土地收益、租约与风险分担

【来源：LAW-astra-001，DS1 / LAND01、LAND02、AS03；既有部分实现按本节收口】土地以面积、田质、作物及合法使用窗口派生产能，建筑以服务用途、完好度与区位派生服务价值；两者不能共享房租锚，土地不乘建筑 condition。土地改良、灌溉或灾害改变的是相应土地/生产事实，不是给田地套建筑耐久。

缺省定额田租以“年预期产量 × 签约当地可知报价 × 地方惯例份额”形成议价锚，按当地历法换算期间；当前世界的 **3/10** 是从 NUM-W10 反推的待标定惯例，不是全国历史租率，也不是每个承租者必须接受的价格。双方还须按各自所知的投入、家庭劳动机会成本、生计缺口、风险与外部选择决定是否签约（15 §15.2.1）。按亩约定时，租入面积不能超过有效地权与可分配面积；不能因此重复出租同一排他使用权。

定额租在签约时冻结面积、作物、报价时点和来源、产量基准、惯例份额、议定金额、租期、付款日与先付额的依据；后续行情变化不重算已签租金。允许双方同意秋后交、分期和部分先付：余款是有明确到期日的 rent 义务，未到期不算逾期；当前无钱不等于永远付不起。不能让延期拒绝自动代替当事人接受另一个现付方案。报价不足时可以找人、查价、补资料，不回退到房租。

分成租与定额租分开：冻结的是产出基数（毛产/净产）、分成比例、投入和损失分担、核验方式与到期规则，应付额由约定期间的真实产出事件派生。不能以固定惯例份额锚冒充已经实现的分成租。灾年减免须来自合同条款、有效规范或有权出租人的行动，不能为了收支达标自动免租。租期末作物、改良和收获窗口按已同意条款及现行规范处理，单纯到期不凭空销毁或复制作物。

### 5.1.2 资产生命周期与维护责任

【来源：LAW-astra-001，DS2 / AS01、AS02、ORG01】有损耗的生产、经营和公共资产都应有可识别的管理责任主体；所有人与经营者不同，由租约、经营持有、职权或规范派生谁能提案、谁负担成本。L1提供主观可知的状态、维修材料与工时、报价、停工损失及继续使用风险；L2比较维护、暂缓、更换、缩减、暂闭、续营、转让或退出，而非每逢损坏必修或一次亏损必关。

维修沿已有服务义务或工程执行：先有授权、实际材料、支付安排及可用劳力，按真实完工改变状态；不能日历到点自动回血。物品维修、农业维护、一般建筑与公共工程共享这项因果要求，具体工序由数据给出。公共设施的维修由有相应职责/预算权限者提出并支付；预算不足或决策失误允许持续失修，世界继续承受损失。

投资与退出比较未来增量收益、可回收资产、现金周转、替代用途、风险及转换成本；已经发生且不可收回的沉没成本不重复计作下一次经营的现金支出。暂闭、退出和出售不抹去工资、租金、贷款与其他未清义务；资产与经营权的转移仍走既有持有协议。个人固执、祖业依恋或赌气可以改变选择，整体失修和普遍亏损仍须按数值方案 §1.10诊断。

### 5.1.3 家户预算、劳动分配与缓冲

【来源：LAW-astra-001，DS3 / HH01、HH02、HH03、LAB01、AS03】家户预算是现有成员关系、账户、持有与义务的派生，不另存一份家户余额。按成员当量、照料需求、季节作业和下一次可靠收入日，分开食用、种用、已承诺交付、可出售量和可支付现金；未来收成及未收工资是有风险的未来来源，不能当作现款。户成员可共享资源的范围、支配权和分担规则由地方规范与成员真实关系决定，不默认人人全额交公。

同一成员在务农、受雇、照料、赶集与运输之间共用可用时间。L1从有效状态、日程、在途与既有义务派生空档及机会成本；L2在可行分工中选择，实际出勤和生产仍分别结算。可消费/可播种由资源用途、营养与作物事实判断，不能靠物品名字推断。农具、役畜、种子、设施和播种窗口是互补约束，不能重复记投入或让已错过农时的劳动得到全年平均收益。

缓冲目标随收入波动、收款时点、信贷可得性、亲友风险相关性和人格差异派生。消费、存钱、储粮、借贷和求助都可成为候选；互济只有实际同意与转移后才提供资源，共同灾害不能由村内互助凭空消除。主观决策仅见本人及合法获知的家计信息，内核只在校验和结算时使用真相。

### 5.1.4 集期、出行与交易渠道

【来源：LAW-astra-001，DS5 / MKT01、MKT02、MKT03、MIG02】日历中的集期只协调机会，实际营业取决于卖家/服务者到场、真实货物、可用时间和运力；常设店铺、临时集市与现场私约分别使用自己的服务容量。L2根据可知价差、路程、误工、运储费用和风险决定赶集、补货或不出行；没有信息时不能全知追逐异地最优价。货物远距离转移须经真实交付，报价中的到岸成本不代替实际运输。渠道的定价与深度保证见15 §15.2.3。

## 5.2 规范层：法域、法典、次级规范、成员规范、补丁与案件

### 5.2.1 规范条目

法律、村规、郡法、门规、戒律、条约里的约束、生灵的规矩、第三方的特权与豁免都用同一形状——**规范条目**（01 §1.8）：

```
规范条目 = {
  source:   来源组织（政体 / 治理组织 / 门派 / 寺院 / 行会 / 家族 / 冥府 / 生灵物种或文化）或包（补丁）,
  scope:    适用谓词（下列一种或组合）
            place_subtree(地点)            —— 属地：事件发生在该子树
            member_of(组织) / certified / holds_office(该组织职位)  —— 成员：行为者具有该身份
            citizen_of(政体) / holds_office(政体爵位)            —— 属人（域外管辖用；citizen_of 的标的就是政体组织，01 §1.3）
            property_in(地点)              —— 物之所在（租约、地产）
            being(标签)                    —— 生灵自身的规矩（13 §13.3）
  layer:    contract | subordinate | sovereign | membership | personal     （补丁另有 patch 标记，§5.2.8）
  priority: 同层内的次序（数据给出；第三方绑定的冲突裁决见第12章 §12.4.4）
  content:  附录 A §A.7 的十种内容类型之一
  version, enactedBy（事件）, effectiveFrom
}
```

规范条目存为来源组织实体的"法典/章程"事实（01 §1.2），不是新存储概念；一方包与第三方包的法典文件（第12章 `law/codes.json`）与补丁文件（`law/patches.json`）在纪元边界转换为这些事实；议案通过是对其的 fact.set 事件。

### 5.2.2 规范栈

`normStack(行为者, 地点, 时刻)` 是 L1 派生——视角 `frame` 的 jurisdiction × time 两轴在规范上的特例（附录 A §A.15）——返回有序列表：

1. **合同层**（只对民事条款）：当事人的条款快照。
2. **次级属地层**：从地点向上，沿包含树收集 `administers` 该节点的治理组织（村民大会、镇、郡府）的次级规范，以及第12章 `place.lawCode` 槽位的地方法典绑定——**槽位绑定就是"地点子树"类条目的单一赢家约束**（同一节点同一层只能有一个绑定，冲突按第12章 §12.4.4 报错）；越具体（越靠近事件地点）越靠前。
3. **主权层**：最近 `governs` 政体的法典。
4. **成员层**：行为者所属组织（member_of、certified、holds_office、devotee_of）的门规戒律，与地点无关；生灵的物种规矩也在此层。
5. **属人层**：任何政体法典里 scope 为 citizen_of/爵位、且声明 `extraterritorial` 的条款（例：王国法"本国贵族在境外杀害本国贵族者，归国可诉"）。只扫行为者 citizen_of / 爵位所属的政体（07 §7.5）。

**生效规则**：
- **下级只在授权内生效**：主权法典（或上级次级规范）的**授权表**写明下级可以设哪些条款族、可约束谁（本地居民 / 一切在场者 / 本地财产）、可设的刑罚上限、哪些主权条款 `reserved`（不可被下级覆盖或豁免，例如叛逆、铸币）、哪些执行类议案需上级批复（§5.2.5）、接受哪些补丁族与幅度（`patchable`，§5.2.8）。越权部分无效，议案动作的预览给出世界内原因（"村规管不到外村地主的租约"）。第12章的地方法典绑定视为主权方以安装配置授予的完整地方立法权，只受 `reserved` 限制；core 政体法典缺省只保留叛逆、主权与铸币类条款。
- **民事、程序、税、认可条款**：按栈序取第一条覆盖该事项的条款（合同 > 次级 > 主权 > 包缺省），未写的事项用 `inherit` 回落上一层；选中后应用补丁（§5.2.8）。**成员层的民事条款**（门规对契约、生灵规矩对 pact）不进这一缺省选序：只经冲突法条目 `conflict` 或合同效力条目 `contract_validity.refersTo: membership` 被显式引用时参与（13 §13.4 的 pact 冲突法即此）；否则成员层只管内部制裁。
- **罪名**：属地层（次级 + 主权合成一部"行为地法"）独立判定一次；属人层各自独立判定，产生的案件只能在该政体能执行处执行（境内或经引渡）；跨法域重复立案的缺省是程序条目 `neBisInIdem: credit`——已在一法域执行的刑罚额计入另一法域的量刑，法典可改为 `bar`（不再受理）或 `none`（附录 A §A.7）；成员层判定交给来源组织的内部程序。
- **无行为者事件**（灾害、设施失效、天象、践踏等由时钟或反应规则产生、`actor` 为空的事件）：只在**属地层**按事件地点求值；谓词的角色从起因链 `causes` 取（例 negligent 读起因链上以某职位 `actedAs` 的批款事件，vicarious 读起因链上的驯兽），成员层与属人层对无行为者事件跳过（它们按行为者身份选栈，没有行为者就没有栈）。
- **罪刑以行为时法为准、程序从新**：案件记录立案时所用规范条目及版本；之后法典修订或第12章卸载时，罪名与刑罚按行为时版本（刑罚取轻），程序按现行；合同效力随条款快照冻结。
- **可解释**：解析返回各层命中的条目与补丁清单（标杆 B03.6）。

### 5.2.3 罪名判定：对原语与持有状态的谓词

罪名不再由"动作本身的规则打上"。罪名表的每一项是谓词，由法律包的反应对**每个事件**按规范栈求值：

```json
{"offense": "offense:smuggling",
 "on": "event",
 "when": "anyPrim(op in ['move','transfer'], commodity == 'goods:salt', crossesNode(scope)) && warrantCover(actor,'goods:salt',now) < qty",
 "roles": {...}, "penalty": {...}, "evidence": "witness || evidenceChain"}
```

- 谓词能读：事件动词与原语（op、资源与商品类、批次的 origin 与 taint、来源去向、经过的节点）、事件的描述标签、参与者的持有与状态、知情集合（`knows(x, 事件)`，用于共犯与故意）、地点与时刻。表达式用 RX（第12章 §12.8.1）。
- **`on: event | state`**：事件类谓词在事件发生时求值一次（幂等键 = 条目 × 起因事件）；**状态类**谓词（囤积、非法持有、长期不履行）由规范层的周期时钟（条目声明每日或每月）对持有、账户与义务状态求值，幂等键 = 条目 × 实体 × 期间。
- **三种"合法性"的分工**（B 专项④ 第 1 条）：①**描述标签**由动作附加，只陈述事实（`unconsented`、`deceive`、`forced`、`cause:negligence`、`duel:consented`、`lie`）；②**合法性标注**（包的 `rules/tagging.json`，第12章）是包随内容提供的、与罪名谓词同形的**预判**：在裁决第 3 步对提案求值给出预览（"在此地会构成什么罪、谁会看见"），并在事件上打 `offense:*` 候选标签；③**罪名认定只以规范栈的法典谓词为准**：嫌疑记录（§5.2.7）只在法典谓词命中时产生；合法性标注与法典冲突时法典优先，标注只作证据材料。**标签怎样进入法典谓词**：罪名条目可写 `matches: offense:<族>`（附录 A §A.7）——事件带该标签或其**下位词** ∧ 标注的 `scope` 成立即谓词为真，与 `when` 取并集；core 缺省法典数据每条 offense 缺省 `matches: 本族`，法典数据可改 `none`。于是包打 `offense:salt_smuggling`（上位 smuggling）能在有 smuggling 条目的政体立案，是因为**该政体的条目声明了 `matches`**，不是因为立案规则自行回退；要在没有该族的政体立案，用补丁 `append(clause)` 追加条目（§5.2.8）。这样"罪名标签由动作或任一包的合法性标注规则打上，并由规范栈的罪名表认定"。
- 结果：新禁令只加数据。盐引制度= 一条合法性标注或罪名谓词，运输包零改动；禁活契= 合同效力条款；戒律禁杀生= 寺院的成员层条目，谓词 `vital(target: creature, lethal) || transfer(from: population, purpose: hunt)`；神畜皮扣押= 诸帐法典谓词读批次 `origin.species`。

**角色**（词汇族 `role:*`：每个角色是一条谓词模板数据，core 预置五个，包可加——附录 A §A.7）：罪名条目的 `roles` 声明谁以何种身份担责：

| 角色 | 条件（谓词模板） |
|---|---|
| principal 主犯 | 事件的发起者 |
| accomplice 共犯 | 在同一起因链上有参与原语（护送、提供工具、望风、companion）∧ `knows(x, 意图或计划事件)` 在行为时为真 |
| instigator 教唆 | 其 tell/request 事件是行为的起因之一 ∧ 内容指向该行为 |
| negligent 过失 | **行为时**持有带注意义务的职位（数据：职位的 `dutyOfCare` 列表，如税吏核验票据），或起因链上存在其以该职位 `actedAs` 作出的事件（批款、主办、签发）∧ 相关检定失败或未执行；卸任不免责，事发时未任职且起因链上无其 actedAs 事件者不命中 |
| vicarious 代负 | 行为者是其 tamed_by 驯兽、commands 役灵或 employed_by 雇员 ∧ 条件（主人在场且未制止 / 受其指使 / 在职务范围内） |

不满足任何角色条件的参与者不担责（不知情的护送者、合法授课的教师）。知情集合是见证与转述派生的，证据也要能证明"知道"（收据、证言、文书）。同一套 roles 也用于民事侵权（民事⑧）。

- 程序：阶段与期限（附录 A §A.7：嫌疑 → 指控 → 立案 → 缉捕/通缉 → 审理 → 判决 → 执行 → 上诉；破产：受理 → 申报 → 裁定 → 清算；宣告失踪/死亡与撤销的期限，04 §4.5.1），法院层级（村镇初审、郡府复审、王都终审；非人政体按议事制度），**`appealStaysExecution`**（按案件种类），**证据规则**（证据类型的基础权重、证人可信度派生式、定罪阈值 `convictionThreshold(offense)`，§5.2.7），**裁量**（哪些阶段由职位持有人决定是否推进、必须推进的罪名族），**拘禁制度**（法域缺省的 `regime`（附录 A §A.15）、探监许可种类、劳役对应的 `keepsEffective`、脱逃后余刑的重算规则 `escapeRecapture: resume | restart | add(days)`）。
- 民事条款族 `civil:*`（附录 A §A.7：core 十类；完整性校验只对 core 十类要求齐全或显式 inherit，包加的类自带缺省）；程序条目加 `conquest`（主权易手后治理组织、职位、公库、封地的处置，04 §4.2.1）、`limitation`（民事时效）、`neBisInIdem`（跨法域重复立案缺省）。
- 程序成本（附录 A §A.7：讼费、冻结担保、败诉承担、滥诉计数，R5 专项②第 7 条）：起诉与申请冻结是带代价的动作——讼费 transfer 到法域公库，冻结须先出担保（pledged 或现金托管）；败诉或撤案时担保赔付被冻结方的损失（compensation），讼费按 `loserPays` 比例由败诉方补偿；同一指控人在期间内败诉 / 撤案达 N 次 → 受理裁量加严并可命中 `offense:vexatious_litigation`。冻结竞争者资产因此不再免费。
- **豁免条目**（core 预置四条谓词，法典数据可改或收窄）：`exemption:incapacity`（`capacity(actor, 'criminal') = none` → 免责；limited → 刑罚 RX 减等）、`exemption:involuntary_act`（`has(event, 'forced') ∨ (actor ≠ owner(actorAs) ∧ ¬possesses.terms.consensual)` → 身份键所属实体免责，施加者按 instigator / principal，附录 A §A.15 行为归属）、`exemption:self_defense`（vital 事件起因链上有对方先行 harm ∧ 幅度 ≤ 比例 RX）、`exemption:necessity`（起因链上有灾害 / 威胁事件 ∧ 造成的损害 `value` < 避免的损害）。未遂与中止不另设条目：罪名谓词可读事件 `outcome` 档（failure / fumble 即未遂）与 `plan_abandoned` 事件，刑罚 RX 按档减等。
- **行为能力与效力**：民事④ 的 `majority` 年龄表与 `limitedActs`（附录 A §A.7）；`validity(event, j)` 对一切法律行为按本法典求值（附录 A §A.15）；越权职位行为标 `ultra_vires` → `offense:abuse_of_office`。
- **查表条目 `schedule`**：俸禄表、额度表、职位表、聚落等级线（`settlementRank: {thresholds: [{rank, rx, graceDays, hysteresis}]}`，`rx` 读人口、设施、税基，自动升降与升格申请读同一条——附录 A §A.7）都是本法典的规范条目，治理包在纪元边界注入初值，议案 `norm` 可改；俸禄、额度、应有职位由派生读规范栈得出。
- **程序条目**：受理管辖 `forum`、回避 `recusal`、职位决定的复核 `review`、代收解缴 `remittanceDays`、托管保管人 `escrowCustodian`（附录 A §A.7）；回避命中时该职位持有人对该事项 `effective` 为假（04 §4.6 代理承接），认证、受理、批复一类职位决定可按 `review` 上诉。
- 兼任规则 `plurality`：哪些职位可兼、俸禄是否只取最高。
- 冲突法：财产所在地、婚姻缔结地、侵权地、户籍地、合同缔结地的选法顺序；人间法典与生灵规范对同一契约的冲突由此给出结果（13 §13.4）。
- 引渡与协查：由 allied_with 条款与政体关系投影派生（U12/L1 已有方向）；阴阳协查同形（13 §13.7）。
- 授权表（§5.2.2）、域外条款、`patchable` 表（§5.2.8）。
- 认可条款（附录 A §A.7，`recognized(x, j)` 读它——视角的 jurisdiction 轴）：法定货币与计价单位（可为任一资源，15 §15.3）、承认的凭证（盐引、汇票、他家纸币）、发行者（谁能引用 `src:mint` / `src:issue`、准备金率下限）、承认哪些外地认证（`certifications`：执业资格须经本地承认即此）与婚姻形式（`marriages`：部盟婚在王国是否有效）、身份链接的鉴定、所用历法与单位表、神职与仪式资格；无条目缺省承认。
- 税表条目：每条带 `recipient`（法域公库 / 节点控制者 / 职位所属组织公库 / 持许可者）与可选 `split`、按人按期的 `exemption`（读 `countEvents`，附录 A §A.13）；包税 = 关卡 `controls` 持有或 `permit` 持有 + 税表把该条的 recipient 指向持有人；通行费与关税由此派生，`controls` 本身不收钱（01 §1.5）。
- 合同效力条款加 `authoritativeText`：多份语言文本并存时以原件、译本、各方母语文本还是条款快照为准（缺省条款快照）；文书只是证据，条款快照是真相（§5.4）。
- 非人政体各自成表（林地议会：滥伐、采灵芝、惊扰精怪；部盟：习惯法均分；城邦：商事；冥府：阴律）。
- 完整性校验：每个政体十类民事规则与程序成本齐全或显式 inherit（11 §11.2 第 1 条、第12章）。

### 5.2.5 次级规范与议案

- 村民大会、镇议事、郡府是治理组织（`administers` 聚落或行政区）；**议案**是 interim 实体 `motion`（提案动作创建；状态枚举见附录 A §A.7；表决由章程议事方式与投票权重决定，NPC 按立场表态；同一人多次表态按章程 `decision.voteRule: last_valid | first | locked`（缺省 last_valid）取舍，表态时 `capacity` 为 none 者的表态无效、limited 者按章程 `limitedVotes` 计或不计）。通过时按 `resolution.kind`：
  - `norm`：对本组织规范条目 fact.set（新增、修改或废止一条），写明范围与生效日；
  - `execute`：以本组织的权能执行一个注册动作（拨款、修渠、拆除某建筑、征发、赈灾），actor = 组织，权能由 administers / owns / 公库动用权派生；destroy、transfer 等原语的校验接受"有权组织的执行类决议"作为授权来源（06 §6.3）；**通过即对决议标的开立 `frozen{asOf: 表决时刻}`**（持有人 = 议案）：待执行期间标的不得转让，执行与补偿对象按 asOf 时刻的持有人确定（征用李某的田——表决后过户给张某无效或待执行后撤销，补偿付李某，民事⑩ `expropriation`）；议案 executed / lapsed / rejected 时 frozen 关闭；**执行者**是章程 `offices` 中持有相应权能的职位持有人或其代理人（事件 `actedAs` 记决议与职位），职位空缺且无代理 → 议案停在 `approved`（待执行）直到有人可执行（04 §4.6）；
  - `appoint`：任免。
- **上级批复**：授权表可声明某类 execute 或 norm 需上级批复 `{approvalBy: 上级治理组织的职位, days, onLapse: void | deemed_approved}` → 通过时创建 `approval` 义务（债务人 = 批复职位经持有人，债权人 = 提案组织，标的 = 批复动作，期限到期项）；公文是文书物品，由驿卒 move 携带，批复职位持有人只有在阅读后才知道（I25）；期限到期 → 议案 `lapsed`，预留款（公库的用途账户）按 onLapse 释放或继续冻结；补批或退回是批复动作。
- 能立什么由上级授权表决定：例如王国授权村规"本村公产使用、本村居民之间的租佃减免、本地禁令（罚金上限）"，于是"霜灾减租"对本村地主有效、对外村地主无效；"限制教授此术"可作为本地禁令通过，罪名谓词只在本村子树生效；"限制囤积青苗契"可限制本地缔结的 forward 义务数量。
- 议案越权：通过事件照常产生（世界里确实表决了），但越权条款被解析器标为无效，并在公告与预览中给出原因；这本身可以成为后续政治事件的材料。
- **主权立法**：政体组织用同一议案形状（actor = 政体组织，按其章程议事方式：君主独断 / 议会 / 长老）修订自己的法典，没有上级授权表，只受条约（allied_with 条款）约束；NPC 政体的立法由组织自治候选发起（§5.7.3）。

### 5.2.6 成员规范：门规、戒律与生灵规矩

- 寺院、门派、行会、家族的章程可含成员层条目：谓词 + 内部制裁（罚香火/贡献度 transfer、立场 impress、禁足 status、开除 = holding.close(member_of)）+ 内部程序（住持裁断、长老会）。
- 与政体法律独立：狩猎在王国合法，在寺院戒律下是破戒；两者可以同时命中同一事件。
- 驯兽与役灵代负同样适用：猎犬自行捕猎是否算破戒，看戒律条目的 vicarious 条件（主人在场、指使）。
- 生灵自身的规矩（`bound:*`）与随誓约、婚配、恩惠而来的禁忌是同形条目，来源是物种、文化或生灵个体（13 §13.4）。

### 5.2.7 案件

**两步立案**：
1. **嫌疑记录**（反应规则，优先级类 legal）：`当 事件 E 使 normStack(行为者, E.地点, E.时刻) 中某罪名谓词为真 → suspicion{条目与版本, offense, 真实角色, 见证集合, 证据链}`。嫌疑记录是**私密的内核记录**，不是案件，不进任何人的知情；它只在被指控时作为真相对照。同一 legal 反应在嫌疑成立且事件携带取得批次的 transfer 时，对该批次写 `taint`（01 §1.6 批次：唯一写入者）。NPC 之间的犯罪与玩家犯罪走同一规则。
2. **指控与立案**（动作）：报案、巡检发现、官府自诉、告发（含诬告）都是动作；指控人只能依**自己的主观视图**指控（被告 = 指控所指，可错；可以是一个**身份键**而非实体——法域只对其承认链接的实体执行通缉与冻结，附录 A §A.15）；立案 = create(case{offense, 被告, 证据清单}) 由受理职位持有人决定（裁量：读证据初评、立场、贿赂、政治——这是"借罪名报复"与腐败的落点）；法典可规定某些罪名族（命案）必须受理。指控与嫌疑记录不符（无嫌疑记录或被告不符）→ 案件照常审理，证据评分低；故意为之且被证明 → `offense:false_accusation`；`case_dismissed` 事件撤案。

**案件是实体**：阶段是时钟到期项；执行是原语（罚款 transfer 到公库、**监禁 = move 到牢房 + `holding.open(guest_of{mode: detained, host: 官府组织（典狱职位 actedAs）, until: 刑满, regime: 法典的拘禁制度})`**——受限而非失能（囚犯仍能对话、受教、授艺、签约、结社、买通、申诉、脱逃，附录 A §A.3 / §A.15）、劳役 = employed_by 公家且 `regime.keepsEffective` 含它、赔偿 = compensation 义务、剥夺持有、流放 = banished 持有、**依判决清算 = transition(gone, insolvency)**（组织）或对个人的破产判决事件触发 core 预置钩子（04 §4.1：人仍存活，财产类持有转入清算实体，免责与否按民事①））；上诉 = 阶段，执行是否暂停读 `appealStaysExecution`；通缉 = 法域对人的 `wanted` 持有，范围由引渡派生，逃到无引渡政体即不可执行；**执行阶段的原语失败**（被告不在场可及：逃亡）或**脱逃 / 劫狱**（`guest_of{detained}` 被非东道关闭 → 事件 `escaped`；劫狱 = 对看守的 vital / status 原语 + 带人 move，同一起因链）→ 案件阶段回到 pursuit，`wanted` 持有续期并记入起因，**执行到期项在缉获后重登记：余刑 = 原到期 − 已执行天数（脱逃期间不计），法典程序条款 `escapeRecapture` 可改为重算或加算**，脱逃本身另按罪名表立案、自首按刑罚 RX 减等；原官职 / 职业是否恢复由章程 `removalTriggers` 决定（04 §4.6）；**法律类受限与状态的施加 / 解除有权能标注，不拦截**（与 01 §1.3、06 §6.3、附录 A §A.15 同一口径）：`guest_of{detained}`、`banished`、`wanted`、`frozen`、案件施加的状态由案件执行、有权职位的 actedAs（典狱、执法、法官）或到期项开立与关闭时为**合法**；无权者的开立**照常成立**（绑架、俘虏、私押），事件标 `authority:none`，反应规则按规范栈判 `offense:unlawful_detention` 与否——这与"同意只是裁决输入""法律只打标签"一致；无权者对任一法律类持有的 `holding.close` 提案被拒并给世界内原因（"你无权放人"，06 §6.3）——放人在世界里只能靠物理手段：劫狱 = 对看守的 vital / status 原语 + 带人 move，持有被非东道关闭即 `escaped` 事件链（上文）；有权职位无依据的关闭照常成立但命中 `offense:unlawful_release`（替身、放人）；处决等 vital 原语绝不对不在场者生效（I26）；讼师 = service 义务，影响证据评分；新证据（收据等文书）在上诉审进入证据评分。

**证据评分**（法典程序数据）：`evidenceScore(case) = Σ 证据项权重`，证据项 = {witness: 证人可信度派生（与当事人立场、灵智、视线质量、见证版本完整度）, document: 文书经鉴定的真伪与完整度, mark: 现场遗留经感知/鉴定, confession, 亡魂指认（阴律承认与否，13 §13.7）}；讼师与辩护经修正槽 `law:evidenceWeight`；判决 = 评分 ≥ `convictionThreshold(offense)`；民事事实认定（例如"签约时无行为能力"）同样由证据评分对命题求值。

**民事争议**同一种类：分产、欠薪、欠租、货损索赔、监护侵吞、撤销买卖、返还、侵权。判决内容由民事⑧⑨条款给出：侵权责任按 roles 与 standard（过错 / 无过错）产出 compensation（可由反应规则在和解或起诉时自动创建）；救济按顺序：撤销 → 返还原物（标的仍在被告处）→ 返还不能或已被善意有偿第三人取得 → 折价赔偿；强制履行；质押优先。冻结 = case 对持有/账户的 `frozen` 持有；分红入案件托管；判决改分股份保持总和 1.0；判决可约束案件追加的第三人（质权人、买受人）。

**行为能力案件**（`capacity`）：申请人 = 亲属、医者、债权人或职位；阶段：申请 → 鉴定（医者的检定动作，读症状状态与技能）→ 判决：对本人 `status(capacity:limited{scope})` 或 `capacity:none`，并 `holding.open(guardian_of)`（持有人按法典监护顺位，可为职位或组织）；效力只及判决之后的行为，此前行为按民事④"行为时无能力"的事实认定逐件撤销（证据评分）；恢复 = 撤销判决 → 状态解除、guardian_of close（04 §4.3 钩子）。

**破产案件**（`insolvency`）：触发 = 债权人申请（前置：对该债务人有已到期未清偿义务且逾期 ≥ N）、债务人自申请，或组织的月度检查（资产 < 负债 ∧ 到期不能清偿）触发债权人 NPC 的申请候选；阶段：受理 → 申报期 → 裁定（清算 / 和解展期）→ 清算执行（上述原语）→ 承接实体程序（04 §4.2 第 6–10 步）；偏颇清偿与诈害行为的撤销在申报期提出（04 §4.4）。

**证据链**：物品个体带来源事件 → 赃物身份派生（买赃可追）；批次的 taint 对可替代物同样生效（01 §1.6）；见证由感知派生（01 §1.5）；现场遗留 = 事件携带的 mark（K2 的 mark 机制）；文书物品的 records 可作书证。

### 5.2.8 补丁：对任何已注册定义的受控修正（原"规范补丁"是它的一种目标）

第三方与世界内的条约都会遇到"新身份在既有规则中获得特权、负担或前置"（驿商关税减半、僧侣免役、行会专营、条约国货物减税、拜师三年方可认证）。合并语义不允许改他人数据，整部覆盖又不可行，所以引入**补丁**：对选中定义**结果**的受控修正，与修正项同一思路（修正项改派生值、补丁改定义；附录 A §A.9 第 4 条）。

```
补丁 = {source: 包或组织（条约、章程）,
        target: {定义 id 或 selector, field}   —— 三类目标：
                  ① 规范条款：{family: tax | exemption | penalty | procedure_deadline | tariff | recognition | …, selector: 条款谓词}
                  ② 动作与种类：core 或他包动作的 preconditions / consent.scope、持有种类的 incompatibleWith、义务种类的 terms 范围
                  ③ 派生值 —— 即修正项（§5.9）
        op:     append(前置或不相容) | append(clause)（向目标法典追加一条规范条目，受其 patchable.clauses 与 reserved 约束）| exempt(when) | mul(value) | add(value) | reduce(value) | narrow(range),
        when:   RX（读行为者持有、事件、地点）,
        reason: 世界内原因（append 必填："行会规矩：须拜师三年"）}
```

- **应用点**：规范栈选中条款之后、求值之前；动作在裁决第 3 步把追加的前置当作自己的前置（06 §6.5）。只作用于目标定义 `patchable` 允许的 op 与幅度：**追加型**（append、exempt 非 reserved、narrow）对一切定义缺省允许；**改写型**（mul / add / reduce）只对声明的字段与区间允许（core 法典缺省：tax 与 tariff mul ∈ [0.5, 2]、penalty 只能减、procedure_deadline mul ∈ [0.5, 2]）；`reserved` 拒绝一切；超出在加载期报错（E-PATCH）。
- **合成**：同目标的多个补丁按 (包 id, 补丁 id) 字典序，append 与 exempt 取并集、mul 连乘后钳制，与加载顺序无关（I24）；结果附补丁清单（可解释）。
- **世界内来源**：政体之间的 allied_with 条款、行会与政体的协议、章程的成员特权都生成补丁（来源 = 组织），用同一机制；玩家受封的免税权是法典自己的条款，不是补丁。
- 不是层：补丁不参与"第一条覆盖该事项的条款"的选择，所以不会把主权条款挤掉；不能删改既有前置或 outcomes。

## 5.3 组织与职位

**组织实体**：章程、公库账户、职位实体集合（按章程或聚落等级派生应有职位，缺的创建为空缺）、成员持有、对外立场投影、计划（势力时钟阶段，K6 效果）。**章程字段**（B 专项④ 第 4 条；全部可选，缺省见治理包数据）：

| 字段 | 含义 |
|---|---|
| `decision` | 议事方式：首领独断 / 投票 / 长老会；`votingWeight: per_head | by_share` |
| `succession` | 首领与各职位的继任规则（04 §4.6）与候选谓词 |
| `removalTriggers` | 解任触发谓词（04 §4.6） |
| `admission` / `expel` / `expelOn` | 入会条件、开除条件、与其他持有的不相容 |
| `liability` | 股东责任类别：有限 / 无限 |
| `dues` | 会费（upkeep 义务模板） |
| `acceptsShares` | 是否接受入股 |
| `rules` | 成员层规范条目（门规、戒律） |
| `offices` | 可设职位表（种类、职级、职权、俸禄来源、注意义务、可代理权能） |
| `authority` | 各职位的处分权范围与需追认 / 需上级批复的行为类（下文）；含 `issuance`（谁能发起 `holding.rescale` 增发、需全体同意还是表决）与 `contracts`（哪些义务种类可由哪些职位以组织名义缔结） |
| `military` | 军事组织或政体的军事章程：兵员来源（常备 member_of / 征召义务 `levy` / 雇佣）、补给账户、指挥职位、战役规则参数（§5.10） |
| `faith` | 教团：信奉是否排他（`exclusive`）、奉哪位神的哪一面、仪式集（13 §13.8） |
| `patches` | 本组织对成员或盟友给出的补丁（§5.2.8：条款、前置、不相容） |
| `goals` | 组织需求与目标（§5.7.3） |

**治理是组织的特例**：聚落或行政区的治理组织 `administers` 它；政体 `governs` 若干地点；职位的职权、俸禄、额度由 `职级 × 所辖聚落等级` 查表派生（V3 的 rankedOffice 方向正确，扩到所有职位）；任命由职位发出（appointed 的授予者是职位）。

**首领** = 首领职位的持有人；更替只动这一个持有。公库属于组织实体；个人只有经职位派生的动用权限，免职即失。

**代理与追认**（四种代理统一）：凡以组织或他人名义行事，事件与所创建义务的条款快照记 `actedAs: {来源, 权能, 版本}`；来源就是 `authority()` 的六项（附录 A §A.15）——**法定代理**（guardian_of 的 `derives.authority`）、**职务代理**（holds_office / operates / appointed / commands）、**委托代理**（`mandate` 义务的 scope，01 §1.4）、章程授权、决议、认可条目。
- 范围内的行为成立即生效，持有或委托关闭后已成立的义务照常有效（04 §4.5）。
- 章程或法典声明 `requiresRatification`（庙产处分、超额拨款、长期合同）的行为类：成立即 `validity = pending_ratification`，由章程指定的职位或上级在期限内追认（动作）或撤销；期限到期 → void，已履行部分按民事⑨返还或折价，善意第三人不追。职位更替时新持有人对待追认事项有同样期限。
- **无权代理与越权**：有来源但 op 超出其范围 → 行为成立、标 `ultra_vires`，`validity` 按章程 `voidable` / 民事④ 判（缺省 pending_ratification）；完全无来源 → 拒绝并给世界内原因。**表见代理**（民事④ `apparentAuthority`）：第三人的知情集合含曾经的授权（tell、文书、公开的 actedAs 事件）且不含撤销 → 对该第三人 valid，本人向无权代理人追偿。
- 执行人（遗产管理人、清算人、工程管事、公库出纳）是同一机制的派生 `executor(x)`（附录 A §A.15）：无位置实体凡要出面，都经执行人以 actedAs 行事。

**爵位**是职位种类 `peerage`（所属政体）；封地是爵位授予的 `fief` 持有，其派生权能见 01 §1.3（不含封地内聚落的公库）；额度取官职与爵位中的最大值（只在同一法域内比较；跨政体的职位各按其法域的 `schedule` 分别计，不合并）（T123 决定保留）；兵役、贡赋是义务。

**身份冲突的裁决顺序**：新开持有时，①新持有种类自身的 `incompatibleWith`；②相关组织章程的 `expelOn` / 职位的兼任条款；③规范栈的 `plurality` 条款。三处任一给出 forbid 则拒绝；给出 auto_vacate 则同一事务关闭旧持有；给出 flag 则派生"身份冲突"标记——额度、派任务、俸禄视图读这个标记（例如行会章程声明"会员出家 → 会籍保留但停派狩猎配额"）。改宗（devotee_of）按同一顺序：教团章程 `faith.exclusive` 决定旧信奉是否自动让出；观主职位的 `removalTriggers` 含"失去本组织 devotee_of" → 职位 vacated → 权限即刻消失。

**建国** = create(org{kind: polity}) + governs 持有 + 法典数据（可从模板复制再修订）；承认是各政体关系状态（外交包），不自动；法典只覆盖 governs 的地点。

**同盟与条约** = allied_with 持有（条款：互助、通商、引渡、关税优惠 → 补丁、阴阳协查）；立场沿其传导（§5.6）。

**政治过程**（B 专项⑦ 第 2 条）不另设系统，由已有形状组合：派系 = 组织内的子组织（member_of，带目标）；投票交易 = request / promise 义务 + 表态动作（NPC 决策读立场、欠情、贿赂）；政变与分裂 = defected + 组织计划 + claim；阴谋 = NPC 计划（§5.7.2）。

**怪物社会、门派、商会、教派、家户、学堂、剧团、走私网、镖局、互助会、冥府**都是组织，差别只在章程数据与成员模板（creature 也可作成员，V4 已允许；亡魂可任冥府职位）。

**组织的反应规则**：成员受害 → 组织立场（K4 传导）；成员退出/叛离 → 补缺/分裂；公库不足 → 计划暂停；首领空缺 → 继任规则；成员数 → 香火/会费流量派生（槽 `organizations:offeringFlow`，名士作品、神迹、竞争者等以修正项进入）。

## 5.4 知识与传播

**知情集合**（L1 派生，L3 缓存）：`知道(x) = {见证的事件} ∪ {作为听者的 tell 事件} ∪ {读过的文书 records} ∪ {开局/pack.install 的作者知情种子} ∪ {物化时的聚合传闻}`（五种来源，附录 A §A.8）。NPC 记忆流 = 知情集合按**记忆可得 `recall(x, event)`**（附录 A §A.15，槽 `social:recall`：显著度 × 时间衰减 × 年龄修正）排序，`recall` 低于阈的事件对知情域检索与证言**不可得**（遗忘只影响投影，事件日志完整；老人的遗忘 = 包对该槽按 `age` 的修正项）。知情索引是缓存（I17），可按显著度截断，截断部分从日志重建。

**公共知情集合**（统计层聚落的聚合变体，07 §7.3）：每个未完全物化的聚落维护一个公共知情集合 = {(事件编号, 到达时刻, 失真版本)}，由传闻规则的路线延迟闭式算出，按显著度截断；骨架物化或完全物化时，个体的知情集合从公共知情按角色（掌柜知道商事、里正知道官事）与显著度**确定性抽样**，来源记为"聚合传闻"事件（可回溯到原事件）。于是星湾分号的掌柜在玩家到达时已经"听说"总号倒闭。

**主观视图**（I25）：`subjectiveView(x)` 是实体 x 眼中的世界，由四域合成（附录 A §A.8）：
- **自知域取真相，但只含此刻能直接感知的**：自己的身体与状态、随身账户与物品、在场（同地点）的持有与义务对手方、自己发起的事件、自己签过的条款快照（条款快照的可得同受 `recall`——口头债可以忘，账簿文书的 records 不受，翻账本即重新读到）。**不在场的持有与义务的状态**（已清偿 / 违约 / 作废 / 对方消失 / 船沉）不在自知域——货主不会在船沉的那一刻"知道"。
- **可观测域取真相**：当前所在地点此刻的公开状态——本地报价（`market_report` 的当日快照）、天气、在场者与可见活动、公告（公开宣告事件 `announce`：当场、口头、在场者入知情；**告示是文书物品**，须阅读，见下文"文书"）、本地路况。异地报价只经知情域（别处的 `market_report` 被转述、商队带来的价讯）或先验，所以 NPC 对异地价差的认识是主观的、滞后的。
- **知情域**取"知道的最新版本"：对某实体某事实，取知情集合中 `recall` 可得、且权重最高的说法，权重 = 来源等级（见证 > 可靠转述 > 传闻 > belief）× **采信 `credence(听者, 讲者, 命题)`**（附录 A §A.15，槽 `social:credence`：信任立场 × 命题的文化先验 × 讲者利害——自称转世、自述清白一类对己有利的自述折减）；低于阈值的说法只作 belief 候选，不覆盖已有说法；`belief` 事件覆盖较弱的说法，被更高显著度的见证或 reveal 推翻。
- **先验域**取模板缺省（"船按期会回来""钱庄照常兑付""小芸在家""远方的粮价和这里差不多"）。
- 视图只按决策需要的字段惰性计算（决策规则声明读哪些字段），结果按版本键缓存（07 §7.5）。
- 玩家的面板（任务与约定、账目、人物）读玩家的主观视图：远方悬赏被他人完成，玩家得知前面板不变；到期提醒读条款快照。

NPC 决策（§5.7）、自治、对话答复、推断规则、智能层 LLM 输入、玩家面板都只读主观视图；真相视图只供内核校验与结算。所以"东家溺亡"的传闻会让储户挤兑、让外地商户拒收汇票，而钱庄的真实偿付能力只决定兑付动作能否成功（I2）；小芸失踪期间村民按自己的版本行动，没人"知道"她在精怪处。

**推断规则**：没有源事件的说法来自推断。形状：

```json
{"id": "ship-overdue",
 "premise": "exists(o: obligation.delivery|escort, knows(self,o) && overdue(o, 7d) && carrierRouteHasStorm(o))",
 "candidates": [{"belief": "carrier_lost_at_sea", "weight": "0.5 + trait(self,'pessimistic')*0.3"},
                {"belief": "delayed_by_storm", "weight": "0.5"}],
 "confidence": "0.4 + 0.1*daysOverdue/7",
 "tellable": true}
```

- 前提读主观视图（期望事件未发生、观测到异常：逾期未归、库房见底、陌生人出没、作物枯黄、孩童性情大变）；候选命题的权重按性格与文化先验；输出只能是 `belief` 事件（I26：不能产生 transition 或改真实状态）。
- `tellable` 的信念可作 tell 的源，按失真表扩散——"逾期 → 溺亡"、"人没回来 → 被拐/被吃"、"公库空 + 灾 → 要民变"、"症状 → 病 / 祟 / 装"（13 §13.4）这类谣言就是这样产生的；源头可追溯到推断规则与前提事件（I12）。
- 推断规则由包以数据提供（manifest 的 `inferences`）；离屏反思产出的 belief 也走这一形状。
- 更正：本人出现（见证）或 reveal 事件推翻 belief；立场按衰减回升。

**转述事件** `tell(讲者, 听者, 版本, 源, 通道)`：版本由讲者的性格与立场从**失真表**生成（夸大数量、省略主体、偏向己方、细节误传："被打死"→"被毒死"是失真表的一条规则：死因细节在二手转述时按概率替换为同类死因）。**失真表是 extend 扩展点**（包文件 `rules/distortion.json`，12 §12.2.3）：每条 `{id, when: RX（讲者性格与立场、通道、源的类型、`canCommunicate(讲者, 听者)` 的沟通度、讲者对该语言的熟练度）, op: replace_detail(同类, fields: [{field, p}]) | omit_subject | scale_quantity(k) | drop_clause | bias_toward(讲者立场), p: RX}`（core 行的 `fields` 表把 `date` 的替换概率定为 0——日期只会被省略不会被换掉，附录 A §A.18），触发概率经槽 `social:distortion`（§A.16）；core 预置跨语言衰减：沟通度 1 → 细节丢失与数量误传概率上升，通译代读文书走同表。传闻 = 沿路线以旅行时间为延迟的 tell 链，对有见证且分量够的事件、以及 tellable 的 belief 自动生成（K5）；私密与未成年保护标签阻断；**通道表**（当面、带信、公告、商队、吟游诗人、托梦、神谕、异象）各有延迟与失真参数，是 extend 扩展点（第12章），速度与范围开放修正槽 `social:rumorSpeed`、`social:rumorReach`（驿商、驿传、鼓楼都以修正项进入）。市况（`market_report`）是公开事件（含当日报价与工价 `wageQuote` 快照），同样经通道传播。

**谎言**：带 `lie` 标签的 tell，保留真相链接；揭穿 = reveal 事件（U8 已有）。

**伪造物**（物品的谎言）：物品带 `purports`，真实属性另存。持有者与接收者在主观视图里看到的是 purports，除非他知道真相（制作者、见过鉴定事件者）。鉴定 = 检定动作（技能 + 工具 + 对照真品），成功产生"识破"事件进入知情集合。行使伪造物是否犯罪由规范栈谓词判定（`tender(item) && item.purports≠真 && knows(actor, forged)`）。会幻形的生灵、化名与易容的人同理：**身份键**（附录 A §A.15）——事件按行为者当时的键记录，观察者按认出的键记忆与评价（`identify()`），嫌疑与指控可指向一个键，法域只对其承认链接的实体执行通缉与冻结；真相层只有一个实体，守恒与义务两端不受影响。

**文书**：账簿、契据、收据、书信、告示、公文是物品个体（**告示 ≠ 公告**：张贴告示只创建物品与"有一份告示"的知情，内容须阅读；当众宣读才产生公告事件 `announce`），事实 `records: [事件编号 + 版本文本]` 与 **`language: lang:*`**。记账是反应规则：组织或商号作为当事方的事件，按章程追加到其账簿的 records（私密子事件只记入其自己的账簿；账簿语言 = 组织文化的语言）。阅读动作 = tell(源 = 该物品, 版本 = records 内容, 听者 = 读者)，**前置 `canRead(读者, 文书)` = 识字 ∧ 该语言熟练度 ≥ 读写阈**（附录 A §A.15）：不识该语言者只得到"有一份某文的文书"的知情，不得内容；可请在场懂该语言者**代读**（tell(源 = 物品, actedAs: interpreter)，经失真表，可私吞可改译）；**译本** = create(item 文书, records 由译者动作写入, language 改, translatedFrom 指向原件, 译者署名)，译本文本可与原件不同（`deceive` 改译是译者的 tell 版本）；学会该语言后再读原件才得到原文——"复读契约发现问题"的触发点。合同的条款快照是真相，文书只是证据：多份语言文本以哪份为准由法典 `contract_validity.authoritativeText` 决定（§5.2.4）。于是新掌柜翻账簿就知道"剑卖给了赵三"。文书可偷、可毁、可伪造（purports）；毁掉文书不删除事件，只删除这条知情来源。公文在驿卒手里时，收件职位只有阅读后才知道。**收信的阅读时机**：交付本身不产生阅读；core 预置反应规则 `read_on_receipt`（优先级类 autonomy）——`当 文书物品（purports 的 `addressee` = 本人、本人职位或本人所属户）经 delivery 清偿或当面交付进入 NPC 的随身账户 ∧ 收件人在场 ∧ 未失能 → 若 canRead(收件人, 信) 则同刻执行阅读动作（tell 源 = 信，知情与记忆随之更新，面板与答话读它）；否则产生自治候选"找人代读"（附录 A §A.17：在场 canRead 为真者中按 trust 立场择一，tell(actedAs: interpreter) 经失真表，无人则信保持未读，候选在下次在场时重试）`；公文到职位同此。**玩家**收信只产生"未读信件"推荐（06 §6.9.1），不自动读。规则层按日批处理同一规则；统计层不物化，视为当日已读。

**技艺与书本**：书是物品个体，事实 `teaches`（技能/法术/配方 + 前置 + 品级 + 版本 + 作者）与 `language`；读书 = learn 原语，前置派生（`canRead`：识字与该语言熟练度、资质、前置技能）；师徒授艺 = learn 的来源为人：读来源方的同意或由来源方发起的 service 义务（06 §6.3；受限者仍可授艺，失能者不能）；抄写 = create(item, 复制 teaches, 品级不超原本)；**师徒 = 持有 `mentor_of`**（01 §1.3：结构持久、可传导、可回读），授艺本身是 service 义务或 learn 的同意；游学/迁居把持有的书与技能带到新地（RW-05 方向）。识字率 = 聚落居民识字技能的派生比例。作品传播 = 沿路线与驿传边、按各地识字率加权的 tell/copy 链。

**法术登记** = spell 实体与法域管理职位之间的 `registered` 持有；"未登记授课"是规范栈的罪名谓词（`learn` 事件的来源是未登记法术的授课或书）。

**玩家的知情**与 NPC 完全一样地派生；场景卡、返场摘要与回程见闻、人物面板、地图迷雾都只读玩家知情集合（I12）。

## 5.5 生态

**资源点与种群**都是带账户的实体；容量是地点派生（地形、季节、被 controls 的领地、污染、设施）。

**再生** = 时钟规则从 `src:regrowth` 流入，逻辑斯蒂闭式（可一次算 N 天，I14 精确类）；采伐、狩猎、盗采、捕鱼、采药都是从同一账户的转移；归零即无产出；古树是慢再生子存量（年计）。**田地同形**：田地是资源点 node（被 owns / leases），作物是它的储量账户（`lots`，批次带品质与入库期）；**播种**是注册动作：消耗种子（`area × 用种量`）、写田地事实 `sown: {crop, area, at}`（01 §1.10）；生长 = 时钟规则按积温、`sown.area`、作物行的典型产量（附录 A §A.18）与田地 condition 从 `src:regrowth` 流入当季可收量，**`sown` 为空的田不生长**（闭式；槽 `economy:yield` 的修正项在此进入），收获 = 从田地账户到农户的转移（受在岗工时与工具限制），未收割的到期转 `sink:decay`。农产出因此不走制造源，与林矿渔同一账目。

**河段有向边**：污染与水量按日沿边传递（迭代规则，声明容差）；一个河段有多条出边时按其事实 `outflow: [{edge, share}]` 分水（和为 1，缺省均分；闸门、运河、堤坝设施以修正项改 share，槽 `hydrology:split`，01 §1.5）；下游产量、渔获、疫病派生各只读该段账户一次，不重复扣减。**种群与个体的转换**走个体化守恒对（01 §1.6）：钓起的金鲤化形、捕获野鹤驯化都是 population −1 与 `create(creature)` 同事务；放归则反向。

**首领领地** = `controls` 持有 → 相邻地点容量下降 → 迁徙流量规则逐日把种群移到容量更高的邻地（含农田 → 害兽压力）；首领死亡只关闭持有，回迁按流量速率发生；空巢由"若干天后另一生物占据"的时钟规则处理。迁徙中的群不是实体，是逐地点 population 账户之间的 transfer；"帐神畜"只能写成规范条目与批次 origin，不是对一个群的 owns。

**家畜**是被 owns 的种群账户；饲草是账户约束；繁殖经 `src:birth`；**蛋、奶、毛等活体产物经 `src:husbandry`**（01 §1.6：物种 `yields.alive` × 头数的时钟闭式流入 owns 持有人指定账户，挤奶、剪毛是引用该源的动作）；役畜决定运力（§5.1）并可计入工时（§5.1 非 person 劳力）。**首领领地与采集**：资源点被 `controls` 覆盖或 `transport:risk` 高时，采集 / 采伐 / 捕猎动作的 `check` 难度与产出读它（槽 `economy:yield` 的 core 修正项 `when: controls 存活 ∨ risk ≥ 阈`），采集者的候选 risk 项同读，所以野兽回山即压低他人收获。

**种群相互作用**：不再是 core 一张表，而是每条**物种数据**自带的 `interactions: [{with: 物种或标签, kind: predation | competition | mutualism, k, season}]`（13 §13.3；普通动物在 `ecology/species.json`，超自然在 `beings.json`，同一 schema）；core 生态时钟读全部已装物种的行，按 kind 把猎物账户转入 `sink:death`、捕食者增长读猎物密度（迭代规则，声明 tolerance）。鸡鸭鸟类压蝗、狼群压鹿都是各自物种的行；新物种包只写自己的物种数据，不碰他人；生态位重合度过高的物种的竞争系数由重合度派生（13 §13.9）。**繁殖**：种群经 `src:birth`；被命名的个体（种马、猎犬）经时钟或配种动作 `create(creature)`，facts 按物种 `heritable` 规则由双亲视图与骰值算出，孕期按 `lifecycle.gestation`（可按季节修正）登记到期项，幼崽归属缺省为母畜 owns 持有人、租用条款可改。**人口动态**：人的婚配是自治候选（`need:家人`，读 `population:marriageRate` 槽与立场）、生育是出生反应规则（读 `population:birthRate` 槽）；两槽的基础曲线在 `rules/tables/balance/population.json`（数值平衡调研 §3.2 形状，按年龄与文化），core 修正项读**住房容量占用率**（01 §1.5 容量）与 **`granaryDays`**（粮仓可供天数）压低出生率、抬高迁出候选的 utility，死亡走 `npcLife`；统计层按同一闭式对聚合人口账户执行（`aggregate: auto`）。这不是自动求平衡（11 §11.1），只是密度与口粮进入速率。

**疫病**（统一个体与群体两种形状）：
- 感染率派生 = 病种基率 × 水质暴露 × 密度（居民或畜群/面积）× 隔离/净水/医疗措施（修正槽 `health:infectionRate`）。
- **智能层与规则层的人**：病例是人的慢变事实（病种、病程、严重度），传播沿路线与家户。
- **种群（畜群、野马、蚕群）与统计层人口**：拆为子账户 S/I/R（01 §1.6），时钟规则按感染率与康复率在子账户间转移（迭代规则，声明 tolerance）；死亡转入 `sink:death`。马瘟、蚕病、远方疫情都是这一形状。
- **医疗的两种形状**：个体诊疗 = service 义务 + heal（同意读附录 A §A.15）；群体 = 药材 transfer 到 `sink:consume` + 医者服务能力派生 → 以修正项提高 I→R 康复率（槽 `health:recoveryRate`）；兽医与人医是不同动作与技能。
- **服务容量与分诊**（对医师、讼师、教师、匠人同形）：每个提供服务的 `operates` / `holds_office` / `certified` 持有派生 `serviceCapacity`（每日可接次数 = 技能阶表 × 助手数 × 设施，槽 `service:capacity`）；请求事件带 `urgency`（诊疗按伤情 / 病情严重度派生，附录 A §A.15）；超出容量的请求由 NPC 决策答复为"拖延"并登记排队到期项，按紧迫度降序、同紧迫按全序处理；伤者在排队期间按未治疗病程推进。统计层聚合变体：聚落医者容量总和 vs 病例数 → 康复率修正项（已有）。
- 物化与聚合时两种形状互相转换（按种子把 S/I/R 分配给个体，或把个体病例计入子账户），总数守恒（I28）。
- 超自然来源（作祟）以修正项进入感染率；民众的归因在知情层（13 §13.4）。

**天气与灾害**：天气是时钟规则的种子派生（现有马尔可夫链保留）；天气对人的作用只有两条路——速率槽（`transport:speed`、`body:drain` 的 core 修正项读天气槽）与暴露状态（core 反应规则 `weather_exposure` → `wet` / `cold` / `heatstroke`，附录 A §A.18）；灾害是时钟阶段 → 原语（河段水量、田地事实、设施 condition、路线封闭持有）；灾害概率与损害开放修正槽（风水、堤防、防火设施）；灾害类时钟规则多为 paceable 与 major（14 §14.8）。

**年久成精**：器物与建筑的年岁派生 + 时钟规则（13 §13.3）。

**寿命与衰老**（core `npcLife` 时钟）：每个个体的寿命上限是派生 `lifespan(x)`（物种 `lifecycle` 给基础值，槽 `life:lifespan`，阶段含 max——修仙、神恩一类延寿以 max 进入，不叠加）；衰老是年速率 fact.set（属性递减，槽 `life:aging`）；老死是风险函数而非阈值瞬判：年死亡概率 = f(age ÷ lifespan)（闭式，paceable: false），超过 lifespan 后概率趋近 1 但仍逐刻掷骰。寿命派生因修正项卸下或境界回落而骤降时，npcLife 不在下一刻判死，而是按物种数据 `agingCatchUp`（年数）加速衰老到对应年龄段。首领与精怪的 `lifecycle` 可声明 `lifespan: null`（不老死）。

## 5.6 立场（态度性关系）与舆论

**立场是投影**：
```
standing(holder, target) = 基线(基线表 rules/tables/standing-baseline.json：每行 {holder: 选择器, target: 选择器, value}，选择器可按文化、组织、持有种类、职业标签、物种，
                                 所以"部盟对人类商人"是一行；组织间基线同表；可扩)
                         + 饱和( Σ 印象(holder 知情集合内与 target 相关的事件 × 事件权重 × 价值乘子 × 归因系数 × 衰减), 按事件类；target 按 holder 认出的身份键归档；
                                 **不经 `recall`**：印象是知情集合的全量投影，只按事件权重表衰减——细节忘了，怨恨还在 )
                         + 传导(沿 holder **知情集合中可见的**、且其持有种类声明了 `derives.conduction` 的持有，系数由该声明给出；
                                core 声明：member_of / kin / household / allied_with / citizen_of / resident_of / holds_office(政体职位) / devotee_of / 种群成员 / employed_by / operates)
```
维度：信任、亲近、敬重、畏惧、欠情（义务账派生）、恋慕（成年且长期）、竞争、依恋 `attachment`（生灵对主人，别名 `loyalty`）。**对类别的立场**：impress 事件的 target 可以是**类别键** `category:<certified:医师 | culture:* | species:*>`（反应规则在 harm / breach 事件后按行为者的公开持有或物种另发一条对类别的 impress，系数为数据），`standing(holder, category:*)` 同一投影；个体立场 = 对该个体的立场 + 其所属类别立场 × 权重（数据）——"一个医师骗了我"于是落到"对所有医师"，求医候选读它（附录 A §A.17）。

- **传导的知情门控**（附录 A §A.15）：传导项读的不是真相持有，而是 `knownHoldings(holder, target)`——`visibility: 公开` 的持有（亲属、公民籍、公开职位、公开会籍）视为人人可知；`仅成员` / `仅当事人` 的持有只在 holder 的知情集合含其开立事件、转述或文书，或 holder 有相应 `belief` 时才传导。秘密结社的会籍因此不会把不知情者对结社的恶感传到成员身上，而误信某人入会会传；告发后身份按传闻扩散，传导随知情扩散（I25 双世界：真相不同、四域相同则立场相同）。组织作为持有者时，其知情集合 = 章程指定的决策职位持有人（缺省首领）的知情集合 ∪ 组织文书。

- **价值乘子**：事件权重表的每行可声明相关价值（门第、平等、虔诚、护生、勤俭……）；乘子 = 持有者价值排序中该项的权重。于是同一件事在不同性格的人那里分化；林地议会价值"圣兽"高，所以射杀角鹿的 harm 权重大。
- **饱和函数**（B 专项② 第 5 条）：同一 (持有者, 对象, 事件类) 的累计印象经递减函数（数据），第十次送礼远不如第一次；兜底 mark 引起的印象另按 06 §6.9.5 的作者 × 标签 × 地点衰减。
- **状态评价**：对持续状态（"贵族兼任村正""寺院收了猎户""长期压迫活契劳工"）的态度不是一次性事件。时钟规则（月）对选定状态谓词产出 `impress` 事件，幅度同样按价值乘子，见到状态的人才评价（读主观视图）。谓词可读任何状态，含"受益或受损于某组织的决议、设施、许可"——core 预置两条：①"因治理组织的决议获益 / 受损"（渡船生意因议会未禁而兴 → 船家对议会的正向印象）；②**竞争失客**：`knownHoldings` / 知情集合中可见的"本人主顾的同类 service 义务对手方变为他人"（经知情门控，§A.15.26）→ 对该人按事件权重表 `lost_custom` 行产负向 impress，沿 kin 传导；更远的因果（断供 → 减产）只能经推断规则的 belief。**belief 进权重表**：`belief` 事件按权重表的 `belief` 行计入印象，权重 = 命题所指事件类的权重 × `credence`（附录 A §A.18 事件权重表），被 reveal 推翻时冲回。
- **归因系数**：印象沿事件的 `causes` 各因按权重分配给链上的贡献者，系数按角色数据给出（行为者 1.0、教唆者、授艺者、雇主、招揽者……各有较小系数），所以学生用所学法术行窃，授课者的声誉也小幅下降，但不构成犯罪；先生被门派挖走，家长对门派的不满按招揽事件的因权重分配。
- **同盟传导**：组织间 allied_with 持有带传导系数，林地议会的不满沿同盟传播。
- **属人传导**：个人的行为经 citizen_of / 政体职位持有传导到其政体，系数为数据；外交立场读这一项。
- **种群立场**：population 实体可作立场持有者——对其成员的 harm（狩猎 transfer、杀幼崽）计入种群对行为者的立场；物化出的个体以种群立场为基线（动物复仇、护子，YG 母题）。

**存储**：印象以 `impress` 事件存在（由反应规则对 harm/gift/breach/help/judgment 等产生，或由状态评价时钟规则产生）；现状的七份态度账合并为一个可重建缓存（I17）。

**舆论** = 聚落内各人立场的聚合投影（公众对某实体），供场景卡与界面；统计层聚落的舆论从公共知情集合派生。

**双键分离**：standing(部盟, 玩家) 与 standing(部盟, 王国) 是不同键。

## 5.7 NPC 决策（动作层与离屏自治共用）

NPC 面对请求（玩家或其他 NPC 的 request 事件、自治候选的内在需求）时的裁决规则，按指南 5.7 顺序，是 L1 的规则骨架，各包提供数据。**全部输入读该 NPC 的主观视图**（I25）：

1. 禁区与价值：red_lines（作者数据）命中 → 拒绝，理由模板引用该禁区；价值排序决定后续权重。
2. 关系：standing 各维度；欠情（义务账：对方为我履约而我未回报）。
3. 代价与收益：请求的代价（钱、时间、风险、名声、家人）与收益（报酬、立场增益、需求满足）**按 NPC 相信的世界**估算——他以为钱庄要倒，就不收它的汇票；他不知道票是假的，就会收；他对异地价差的认识来自听说的市况（§5.4）。
4. 处境：忙（日程占用、服务容量已满）、心情（状态）、更急的事（已接请求与目标进度按 `urgency` 比较，附录 A §A.15）、当前计划（§5.7.2）。
5. 冲突：现有义务是否冲突；身份冲突标记（§5.3）；所属组织的成员规范与生灵规矩。

输出四种之一：同意 / 有条件同意（开价或前提） / 拒绝（理由 + 替代方案："该找谁"由本地职位与服务派生） / 拖延（创建待办到期项）。决策返回各项依据（标杆 B03.6，`explain()`）。决策是确定性的（输入 + 战役种子噪声），所以无 LLM 时可直接用，有 LLM 时作为必须遵守的约束给模型渲染。NPC 的自主行动也包括空间上的选择：走近、避开、跟随，都是 move 到相邻分区，读主观视图里的站位与立场；偷窃、潜行、偷听的机会评估读站位、遮挡与声音（01 §1.5）。

### 5.7.1 自治候选：需求 → 目标 → 候选 → 动作

自治包的决策时钟（频率按层级与节奏，07 §7.2.1）对每个 NPC 执行：评估需求（温饱、钱、安全、家人、地位、好奇、信仰、恩义、仇、领地……词汇族 `need:*`）→ 取最紧迫的需求 → 收集**全部已注册的自治候选**中 `need` 匹配且 `applicability` 为真的 → 在候选预算内评估主观收益、资源和时间机会成本、风险、切换成本以及关系/规范/习惯价值 → 按下述有限理性选择规则选出候选 → 若所选候选 `horizon > 1` 则写入计划（§5.7.2）→ 否则作为提案经同一裁决管线（06 §6.5）。同分排序只保证稳定输入，不得以固定实体ID长期代替有种子的选择差异。【修订来源：LAW-astra-001，DS4 / DEC01、DEC02、DEC03】

**差异、噪声与少数行为**【来源：LAW-astra-001，DS4 / DEC01–03；适用于§5.1各经济候选】：

- **个体差异持久**：风险、耐心、诚信、冲动、节俭、固执、迷信、互惠和个人好恶分开，由世界数据声明适当条件下的联合分布；有经验样本优先用经验分布，无样本的有界/正值/零膨胀混合先验标P，不能当成已证实历史分布。初次生成后的偏好作为慢变事实保存；习惯、参照点和经历变化有真实事件依据，不因查询、读档或再物化重抽。
- **一次选择可有噪声**：可用满意即止，或在可行候选中用logit/mixed logit选择；后者概率为 `exp(U/τ) / Σexp(U/τ)`，τ按重复选择的一致率和近似等价方案的选择份额标定。评分尺度、分布、温度和搜索预算来自世界数据，同一处境的独立新决定可以不同，同一事件重放必须相同（14 §14.5.1）。效用不要求一律折铜；各项量纲和权重必须一致。超越函数遵守14章定点协议，缺少确定性数值能力时优先用满意即止，不引入平台浮点随机路径。
- **离谱少数允许**：祖产执念、赌气关店、盲信偏方、冲动借贷、人情价都可以由持久偏好或有限持续状态产生。状态概率及持续期由数据控制，后果沿普通价格、债务、健康、法律和社会反应发生；不设“必须赚钱”或“亏损自动救济”。规则约束中的物理可行性、真实同意、权限、守恒、私密和未成年保护不因高效用或噪声失效；违法意图须走真实对抗与法律后果，不能直接绕过L0。
- **冲击另外建模**：灾年、疫病、事故和战争来自相应世界过程，按地区、时间和接触共享相关性；不能用每个NPC独立噪声冒充共同灾害。正常环境同类主体普遍长期亏损或停业应查共同公式，不能都归为个人不理性。主体尾部0–5%、5–10%敏感性是批准的P初试口径（数值方案§1.10），不覆盖既有门禁。

**自治候选**（声明式规则形状，01 §1.8）：

```json
{"id": "indenture-when-insolvent", "need": "need:money", "goal": "cover_debt",
 "action": "sign_indenture", "role": "actor",
 "applicability": "subjective(self).overdueDebt > subjective(self).account('coin') && exists(c: creditor(self), present(self, c))",
 "utility": "subjective(self).overdueDebt", "risk": "0.6 - trait(self,'desperate')*0.3", "horizon": 1}
```

- 候选由包声明（`autonomy/candidates.json`，或内联在动作文件的 `satisfies` 字段）；自治包不需要知道任何新动作，只读注册表。
- `schedule` 原语的 `via: npc-autonomy`（第12章 §12.7.3 的构造正式化）表示"把这个动作作为候选交给该 NPC 的决策"，而不是直接执行。
- 机会评估的输入全是主观视图：主观报价与价差、听说的路况、相信的法律风险（规范栈预览读自己知道的法典）。私盐、走私因此随（他相信的）税差增减（第12章 §12.10.2）。

### 5.7.2 计划：多步图谋

`horizon > 1` 的候选产生一个**计划**——NPC 的慢变事实 `plan: {goal, steps: [{action, slots, done}], secrecy, deadline, basis}`（01 §1.2，不是实体）。每一步仍是普通动作，经同一裁决；`secrecy` 让各步尽量选隐秘方式（manner stealthy、避开见证）；每步前重算效用，不划算就放弃（事件 `plan_abandoned`）。他人只能经见证、推断（推断规则"有人在打什么主意"）或告密得知计划；试探 = 低代价的 request；结盟 = promise / allied_with；背叛 = defect 或 cancel。计划存依据，可解释。不建模"他以为我以为"（11 §11.1）。这给出 CK3 式阴谋与 DF 式图谋的最小形状，而不引入新概念。

### 5.7.3 组织的自治与群体行为

组织也有需求（公库、安全、威望、信众、领地）与候选（议案、征发、赈灾、立法、照会、宣战、招收）；actor = 组织，经首领或相关职位的持有人执行（决策读该持有人的主观视图），所以林地议会立法、王国加征关税、郡府征发都是候选的产物。群体行为（暴动、集体迁徙、挤兑）= 多个 NPC 对同一需求的候选在短时间内同向触发；统计层以聚合变体表达（暴动率、迁出率、挤兑率，I28）。

### 5.7.4 core 候选与遭遇规则的输入契约

core 自带的候选与遭遇规则只读附录 A §A.17 列出的派生值，而这些派生值都在 §A.16 开放修正槽或读扩展事实。于是第三方包"让山贼看见镖旗就绕道"不需要知道山贼候选怎么写：注册一条 `combat:deterrence` 的修正项（`when: has(party, 'mark:escort_banner')`，`stage: add`），劫掠候选的 risk 项就读到它；"让修士当镖师时保费不同"= 保险包的保费派生开放槽，修仙包对该槽注册修正项并读扩展事实 `xiuxian:realm`——两包仍不相知，只共享槽 id 与词汇。候选的 `utility` / `risk` 读表外真相量在 P8 被拒（E-INV-I25）。

## 5.8 日程（派生）

日程 = 基准作息（作者数据或按职务模板生成）⊕ **任一持有种类在 `derives.schedule` 中声明的片段**（holds_office、employed_by、operates、member_of 的门派作息、disciple_of 的功课、indentured 的债主安排、enshrined 生灵的显灵时段……）⊕ 季节修正 ⊕ 义务占用（等候、会面、带路）⊕ 做客/留置（guest_of：并入东道日程；受限者的日程 = 东道的拘禁制度给出的作息（放风、劳役、探监时段），自己的职务片段因 `effective()` 为假而不生效）⊕ 状态打断（患病、照护、节日、`exhausted` / `starving` 等身体阈值状态）⊕ 位置约束（在途时只有路上的作息）⊕ 阈限时间窗（生灵）⊕ **规范约束**（所在地规范栈中声明 `scheduleConstraint: {window: RX 时段（可读 `daylight`）, zone: 选择器}` 的条目（宵禁、禁入、斋期）把该时段落在该分区的外出片段改为留在住所或东道分区；`trait(x, 'lawless') ≥ 阈` 或持有相应 `permit` 的不受约束——于是宵禁改作息是数据，而违反者的 move 仍进规范求值，07 §7.5）。读取时合成，不复制存储（V3 已朝此方向）。两条持有的片段冲突时按持有种类声明的优先级，先生被门派挖走后不会同时出现在两处。死者没有持有 → 没有日程。日程同时是画面客户端站位投影的输入（08 §8.8）。

## 5.9 派生的开放：修正槽与修正项

run-002 的 N3（风水影响火灾与洪水、与寺观争香火）、E8（关税进到岸成本）、N1（预售影响现货价）说明：派生公式如果是封闭的，新包只能改别人的代码。规则如下：

- **每个派生缺省就是槽**（附录 A §A.9 第 3 条）：派生规则登记即开槽，可声明 `{stages, bounds, inputs, paceable?, closed?}`，缺省 `stages: ["mul","clamp"], bounds: [0.5, 2]`；只有声明 `closed` 的派生（守恒相关的量、规则的合法性判定、随机、`effective`）不能被修正；每个槽自动有读函数 `derived(id, x)`。core 派生值的 bounds 清单是附录 A §A.16（契约附表 B，数据），core 自治候选与遭遇规则只读 §A.17 列出的派生值；"新增槽"不再需要契约版本，`pack doc` 的"接口缺口"只报告被 `closed` 的派生。
- **包注册修正项**（数据，manifest `modifiers`；第12章扩展点表的"修正项"一行，合并语义 extend）：
  ```json
  {"id": "fengshui:siting", "target": "facilities:fireRisk", "stage": "mul",
   "when": "fact(subject, 'fengshui:rating') != null", "value": "1 - 0.1*fact(subject,'fengshui:rating')"}
  ```
  `when` 与 `value` 是只读视图上的 RX 表达式；修正项不能写状态、不能读真相以外的随机。`when` / `value` 可读本包在 core 种类上声明的**扩展事实**（`fact(subject, 'xiuxian:realm')`，12 §12.2.3），这是包把"自己的状态"带进 core 派生的标准路径。
- **五个阶段与合成顺序**（附录 A §A.9）：基础值 → 全部 add（按包 id、修正项 id 字典序求和）→ 全部 mul（连乘）→ 全部 max（取各修正项值与当前值的最大，用于"寿命取最大而非叠加"一类）→ 全部 min（取最小，用于"抑制降水不低于下限"一类）→ 节奏系数（仅 paceable 槽，14 §14.8）→ 派生方的 clamp/bounds。派生方声明它接受哪些阶段；与加载顺序无关（I27）。
- **可解释**：派生结果附修正项清单与各自贡献（界面"为什么这么贵"、调试与推演断言用）。
- **跨层**：统计层聚合变体读同一组修正项（按聚落聚合的事实计算）。
- **预算**：每个槽声明最多可挂的修正项数与总幅度上限，超出在加载期报错（第12章 §12.8.3 的平衡预算）。

core 预置的修正槽、各槽的阶段与 bounds、读它们的 core 消费者，唯一定义处是附录 A §A.16；本节不再重复列举。`world:pace` 是特殊槽：向全部 paceable 槽提供节奏系数，由 `pace_set` 事件改变。

## 5.10 军事与战争（形状；R5 专项⑦第 1 条、M8）

战争在 10 §10.2 只有"关系状态 + 阶段"，没有军力与战斗结算的输入输出。本节给出**最小形状**，全部落在已有概念里；战术级战棋与逐兵单位是故意不做的（11 §11.1）。

- **军队 = 组织**（`org/army`，章程 `military` 字段，05 §5.3）：兵员是 `member_of`（常备）或 `levy` 征召义务的债务人（领主 / 政体 → 封臣与公民，期限、人数、自带装备写在条款；封地的 `fief.derives` 含征召权能）或雇佣（employed_by + wage）；装备、粮草、役畜是军队组织的账户与 owns 的种群；指挥是职位。
- **军力是派生** `strength(org)`（槽 `military:strength`）= Σ 兵员（按技能阶与装备加权）× 役畜 / 车船（机动与骑兵系数，读 owns 的马匹种群数量）× 士气（成员立场与欠俸状态的饱和函数）× 补给系数（`supply(org)` = 粮草账户 ÷ 日耗，槽 `military:supply`）× 修正项（地形、城防设施 condition、法术、士气类 mark）。可解释。
- **战争 = 关系状态 + 阶段**（10 §10.2 不变），**战役 = `project` 实体**（临时法人：目标地点、参战组织、阶段到期项：集结 → 行军（move 按路线）→ 接战 / 围城 → 结果 → 解散或驻防）。
- **战斗结算是专用求解器**（11 §11.1 已保留"战斗交锋"，这里扩到军团级）：输入两方 strength、地形与设施、补给、骰值键；输出只有原语：兵员 transfer → `sink:death`（种群式）或对具名个体的 vital、装备 → `sink:destroy` / 战利品转移、`controls` 的开关（封闭关卡、占领）、`governs` 的 `holding.transfer`（征服，须随后经条约或占领期转正，法典 `conquest` 条款）、俘虏 = guest_of{detained}、harm 事件（立场、传闻、罪名谓词照常反应）。守恒与起因链照旧。
- **外交筹码** `leverage(A, B)`（槽 `diplomacy:leverage`）= f(strength 差、同盟传导、对方的经济依赖（贸易流量占比）、在押人质 / 欠债）；政体候选（照会、条约、宣战、求和）的 utility 读它，所以马匹存量下降 → strength 降 → leverage 降 → 更少宣战、更多让步。
- **统计层聚合变体**：军队是钉住实体（有职位持有人），战役按阶段到期项精确结算；远方的小冲突以聚合率（劫掠率、边境冲突计数）进公共知情。
- **不做**：阵型、逐兵移动、战术 AI；战役求解器的参数（地形系数、士气表）对包开放为数据，算法不开放。
