# 14 确定性与时序：同刻全序、事务、骰值、并行、世界节奏

（目标：**给定存档与输入，任意两次推进的事件序列逐字节相同**（I31），"逐日推进"与"一次推进 N 天"的事件序列也相同，不只是总量相等。修订历史见 修订记录.md：非争夺型稀缺标的与阶段 4 产生的争夺。）

## 14.1 刻

世界时间的最小单位是分钟；同一分钟内的全部处理构成一个**刻**。一刻之内发生的事可能很多（同日到期的十笔义务、一次死亡引发的二十个子事件、三条反应规则级联），它们的顺序由本章规定，不由代码执行顺序或哈希表遍历顺序决定。

## 14.2 同刻全序

每个事件获得全局单调递增的序号 `seq`；事件头 = `{seq, time, epoch, ...}`。同一刻内按**五个阶段**依次处理，每个阶段内部有固定排序键（阶段与到期项类的枚举见附录 A §A.5）：

| 阶段 | 内容 | 阶段内顺序 |
|---|---|---|
| 1 外部提案 | 本刻提交的玩家 / 界面 / LLM 提案 | 提交顺序（单玩家即自然序） |
| 2 到期项 | 日程堆上时刻 ≤ 本刻的项 | (到期项类, **锚实体 id** 字典序, 登记序号)。锚实体按到期项类固定：协议续步与承接实体阶段 → 承接实体；义务 → **债务人**（同一债务人的多笔义务按法典清偿顺序而非登记序，§14.3）；案件阶段 → 案件；组织计划阶段 → 组织；效果与状态到期 → 目标实体；许可 / 托养 / 封印维护 → 持有人 |
| 3 时钟规则 | 本刻应唤醒的时钟规则（含自治包的决策时钟） | (层级 智能→规则→统计, 包 id, 规则 id, **对象的骰值键序** `roll(规则 id, 对象 id, 刻)`)——对象顺序确定但不按 id 字典序，消除"id 靠前者永远先选"的偏向 |
| 3′ 争夺裁决 | 阶段 1–3 中指向同一**声明了 `contest` 的**互斥标的的提案（exclusive 持有、声明 `contest` 的限量账户——商号每日成交量、限量货，普通账户不进池、按阶段序即时结算——、开放债权人、驻地、服务名额）不在提交时结算，而是登记到本刻的**争夺池**；**粒度是整个提案**（R4 专项①）：提案含任一争夺型原语即整体登记，其全部原语在本阶段裁决后一起执行（事务原子不破），败者的整个提案得到世界内原因（"刚被人买走了"）；裁决按标的声明的 `contest` 规则（附录 A §A.15：lottery 骰值键抽签 / price 出价 / arrival 到达时刻 / rank）；本阶段产生的事件 `seq` 晚于阶段 1–3 的全部事件，阶段 4 按 seq 广度优先，所以不会出现"先反应后发生"；提案者在提交时得到 `pending` 回执，本刻末得到结果（06 §6.5 第 8 步） | (标的 id, contest 结果) |
| 4 反应队列 | 阶段 1–3′ 与本阶段产生的事件触发的反应规则 | 广度优先：按起因事件 `seq`；同一事件触发的多条规则按 (优先级类, 包 id, 规则 id) |
| 5 刻末断言 | I1–I32 的增量断言 | — |

规定：
- **到期项的缺省时刻**是到期日的最后一刻（24:00 前），所以"今天到期的债"在玩家当天的还款动作之后才判逾期。义务条款可以写明别的时刻。
- **反应队列**有深度上限（缺省 8）与每刻提案上限（12 §12.8.3）；超限的链被截断并写事件 `reaction_cut{cause}`，可审计、可重放；被截断的因果不在下一刻自动续算——需要续算的规则（火灾蔓延）应写成时钟规则而非深链反应。**深度上限只作用于 `social` 与 `autonomy` 优先级类**（R4 专项①）：**core** 的 `settlement`（协议子步、货损、冲回、记账）与 `legal`（合法性标注、嫌疑记录）类反应不受截断——它们保证账本、义务状态、文书与事件一致，被截断会留下守恒以外的不一致；每刻提案上限对它们同样豁免，它们的数量由事件数线性限定。**包声明的反应规则无论优先级类一律计深度**（包的 settlement / legal 类上限另设，缺省 16，12 §12.8.3），两包不能借声明 settlement 类互相触发成环。同一起因对同一规则只触发一次（I4）。
- **刻回滚后的重跑**：回滚整刻后用剩余规则重跑，序号重新分配，同一提案的骰值键因序号不同可能得到不同骰值；玩家可见口径：被回滚的那一刻从未呈现过结果（回执在刻末才返回），玩家只看到重跑后的唯一结果，`tick_rolled_back` 事件可审计；重放时同样回滚同样重跑，I31 不受影响。
- **调度配置是输入事件**（R5 专项① (b)）：深度上限、每刻提案上限、每事件谓词预算、D3 滞回天数等"配置"都写在存档的调度配置里（07 §7.6），改变只能经输入事件 `config_set{key, value}`；因此配置不同的两次推进是不同的输入序列，I31 仍成立。
- **NPC 自治提案**不在阶段 1：它们由自治包的决策时钟在阶段 3 产生，经同一裁决管线（06 §6.5），其后果在阶段 4 级联。玩家提案在阶段 1 只是"先登记"，与 NPC 争夺同一标的时一样进争夺池，没有先到先得的阶段优势。
- **非争夺型稀缺标的**：阶段 2 内同一刻多笔到期项指向同一账户而余额不足以全部清偿、或指向同一容量（仓容、服务名额）而不足时，这一组到期项视为争夺进 3′（清偿顺序优先，同序 lottery），不按锚实体 id 字典序先到先得；阶段 2 的 id 序只决定互不争夺项的事件编号。标杆 B13.8 的测量范围据此扩到非 `contest` 标的。
- **阶段 4 产生的争夺型提案**：本刻末再开一次 3′（最多一次），仍未裁决者登记到下一刻的争夺池。
- **`contest` 缺省表——全篇唯一定义**（X3；01 §1.3、附录 A §A.15 只引用）：未声明 `contest` 的标的一律 `lottery`（骰值键抽签，§14.5）。core 数据为下列标的显式声明：商号的限量货与每日成交量 → `price`（出价高者，同价 lottery）；职位 → `rank`（继任规则给出的顺位，无顺位者 lottery）；开放债权人 `firstToSatisfy`（悬赏、委托的承接）→ `lottery`；`guest_of{detained}`（脱逃 vs 巡查）→ `rank`（看守的警觉检定先于脱逃）；驻地与服务名额、`lodges` 的房间 / 铺位 → `lottery`；阶段 2 的非争夺型稀缺标的 → 清偿顺序优先、同序 lottery（上一条）。包声明新标的时不写 `contest` 即取 lottery；本表之外任何章节不得另给缺省。
- **阶段 5 失败**：账本类不变量（I1 守恒、I2 非负、I15 账户唯一）违例 → **回滚整刻**（刻开始时有检查点；刻内全部事务作废，写 `tick_rolled_back{rule, cause}`），熔断导致违例的规则（12 §12.8.4）后用剩余规则重跑本刻；其余不变量违例记录 `invariant_violation{rule}` 并熔断相关规则，不回滚。在测试里两者都是失败。

## 14.3 事务与嵌套

- **一个提案 = 一个事务**：解析引用 → 校验 → 执行原语 → 写事件；任一步失败整体回滚，返回可改正的错误（01 §1.8）。
- **转移协议是一个事务**：§4.2 的全部子步在同一事务内完成并通过 I6/I7/I8 断言；它的子事件触发的反应规则在阶段 4 运行（协议完成之后，不在协议内部）。
- **反应规则的提案是独立事务**：子提案失败不回滚父事件，记 `proposal_rejected{cause, rule}`。需要"要么都发生要么都不发生"的后果，必须写进同一个动作的 outcomes 或同一条反应规则的原语列表（它们在一个事务里）。
- **跨层交互**：到期项与义务精确、不分层（07 §7.3 第 1 条）。智能层的玩家向统计层郡的商号下单，订单成为义务时就登记了到期项；到期时在阶段 2 结算，对手方按 07 §7.3 骨架物化。层级只决定时钟规则的步长与自治频率，不决定"何时结算"。
- **跨区陈旧读**：任何派生读到另一地区的状态（到岸成本沿路线读他郡存量、义务到期读对手方账户）时，调度器先把被读地区按其层级**补算到读取时刻**（07 §7.3 第 4 条的补算推广到一切跨区读），补算不足一个步长的部分按该规则声明的 `tolerance` 处理并记入 I14 等价测试；投影结果附"数据时刻"。**补算事件的编号**（R5 专项① (a)）：补算是被读地区把它自己的阶段 2–4 从"已结算到"推进到读取时刻，产生的事件以当前 `seq` 连续编号，插在触发读取的那个事务**之前**（读取事务的 seq 在补算之后分配）；"逐日推进"与"一次推进"下读取发生在同一刻、同一事务，而**刻的集合由日程堆唯一确定、与步长无关**（01 §1.9：没有到期项与时钟规则的刻在两种步长下都不存在），所以补算事件的位置与编号相同。**补算不递归**（R4 专项①）：补算的上界是读取时刻，深度 ≤ 1——补算 B 区时 B 的规则若读 A 区，取 A 当前的"已结算到"值而不再触发 A 的补算（A 若落后于读取时刻，差额按被读规则的 `tolerance` 计入 I14）；两区互读形成环时，环内各区按地区 id 顺序各补算一次到读取时刻，第二次读取用已补算值。于是补算总量 ≤ 被读地区数 × 一次，终止有保证。I31 的夹具含"跨区读触发补算"与"两区互读"各一例。
- **同一债务人同刻多债**：阶段 2 的义务到期项按债务人分组；同一债务人同刻到期的多笔义务在其账户不足时按法典清偿顺序（04 §4.4 民事①）结算，不按登记序先到先得。
- **transitioning 期间的提案**：实体一旦被标记 transitioning 或已 gone，提案中对它的引用解析到其承接实体（遗产 / 清算 / 残骸）：向死者还钱 = 向其遗产还钱；没有承接实体的引用（对话、请求）被拒绝并给世界内原因（"他已不在了"）。
- **阈值到期项**（附录 A §A.15）：单调随时间的派生（年龄、刑期）的阈值跨越时刻由闭式预测后登记为到期项（类别"效果与状态到期"），其余阈值在该派生的输入事件之后的阶段 4 重算；`threshold_crossed` 事件的 seq 因此确定，成年当日的监护关闭与当日的其他到期项按 §14.2 全序。
- **回合**：玩家的一个"回合"是一个或多个刻；玩家与界面的提案都在各刻的阶段 1 提交；NPC 自治在每刻的阶段 3 由各自的决策时钟触发；没有"玩家回合 / NPC 回合"之分，只有刻与阶段。

## 14.4 典型同刻冲突的裁决（协议与法典数据）

| 冲突 | 裁决 |
|---|---|
| 两人同刻死亡且互为继承人 | 两个 transition 的处理顺序由产生它们的阶段与排序键决定（到期项按锚实体序、npcLife 时钟按骰值键序、战斗反应按起因序；04 §4.10），协议不另排；继承结果**与处理顺序无关**：继承表派生继承人时跳过"本刻已 gone 或 transitioning"的实体，再按法典民事②条款 `simultaneousDeath` 修正——`presume_none`（core 缺省：互不继承，各自遗产按下一顺位）或 `presume_elder_first`（年长者视为先死：年幼者的遗产可含年长者份额，反向不可，由派生读出生日期判定而不是看谁先被处理） |
| 冻结 `frozen` 与绝当同日 | 绝当是到期项（阶段 2），起诉引发的冻结是反应（阶段 4）：同日起诉时绝当已完成，法院只能判折价（民事⑨）。冻结先于到期日存在时，到期项读到 `frozen` → 绝当延后到结案，质押物由案件托管，担保债权人结案后优先受偿（民事⑥） |
| 钱庄解散判决与汇票提示同刻 | 提示是外部提案（阶段 1），解散是案件阶段到期项（阶段 2）：先兑付或拒付，再清算 |
| 分期到期与入狱判决同日 | 都是到期项：义务类先于案件阶段类（附录 A §A.5）；分期先尝试清偿（条款 `autoSettle` 时从账户自动付，否则逾期），再执行判决 |
| 征发与工资结算同日 | 工资义务到期（阶段 2）先于郡府的征发（自治提案，阶段 3） |
| 协议子步产生的反应 | 在协议事务完成并断言之后（阶段 4） |
| 同一事件同时命中多个政体的属人条款 | 各自独立立案（05 §5.2.2），案件按 (政体 id) 顺序创建，互不影响 |
| 玩家与 NPC 同刻争购最后一件货 / 争同一空缺职位 / 同刻完成同一悬赏 | 都进争夺池（阶段 3′）：按 §14.2 缺省表（限量货 price → 出价高者，同价 lottery；职位 rank，无顺位 lottery；悬赏 firstToSatisfy 同刻 → lottery）；骰值键含序号，重放一致；玩家没有阶段优势 |
| 判决执行到期而被告已逃 | 执行原语失败（目标不在场可及）或 `escaped` 事件 → 案件回 pursuit、wanted 续期、执行到期项在缉获后按余刑重登记（05 §5.2.7） |
| 脱逃检定与看守的巡查同刻 | 脱逃是提案（阶段 1 或 3），巡查是时钟规则（阶段 3）：都指向同一 `guest_of{detained}` 持有，按 §14.2 缺省表对 `guest_of{detained}` 的声明 `rank`（看守的警觉检定先于脱逃，失败则脱逃照常裁决）进争夺池 |
| 跨区读触发补算与本刻其他事务 | 补算事件先于读取事务编号（§14.3），同刻其余阶段不变 |

这些裁决都是确定的；玩家可见的解释由事件序号与阶段给出（"你起诉那天当期已过，剑已归当铺，所以判赔价"）。

## 14.5 骰值键

`roll(key)` 的键 = hash(战役种子, 规则或动作 id, 对象 id, 时刻, 本刻内序号)。同一对象同一天两次检定得到不同骰值；重放时序号相同，骰值相同。LLM 提案的骰值与裁剪记录写入事件（06 §6.10.5），重放不调用模型。

### 14.5.1 人格、决策噪声与共同冲击

【来源：LAW-astra-001，DS4 / DEC02、DEC03；适用于DS1–DS5各候选】随机性走同一骰值键协议，不新增全局随机流。键的规则/动作命名区分人格初值、单次选择、状态进入/持续、自然冲击等用途；一个用途的新增查询不得消耗另一个用途的样本。刻内序号由§14.2的稳定事件顺序确定，不能取注册遍历顺序、线程完成顺序或随机调用次数。

- **持久参数**：实体创建或按需物化的正式事件按稳定主体键抽取一次人格/偏好，结果进入慢变事实或可恢复的物化分配记录；并回、重新到访、存读档与投影查询不刷新。已有主体的经历变化必须有世界事件依据。
- **一次决定**：先按主体可知输入与稳定候选集合计算概率，再对该真实决定抽样；同刻确有第二次新决定时使用其独立事件序号。显示报价、预览候选、解释和失败后重新读取同一决定不重抽；没有真实新输入或重试事件，不能靠重复询问刷同意。已经记录的同意、拒绝、报价和合同条款按记录复演，不重新决策。
- **少数状态**：冲动、执念等若有持续时间，其开始/结束由已记录状态与到期项定义，不能每次查询独立变性格。logit/满意即止等选择模型的分布和强度是世界数据；0–5%尾部及5–10%敏感性按数值方案§1.10统计，不能变成“每20人必有1人亏损”的配额。
- **共同冲击**：灾年、疫病接触、暴风封路等先确定地域/时间/接触过程，再计算个体暴露；共享因果使用共享事件，个体残差才按主体键抽样。决策噪声不制造自然灾害、实物和资金。

数值运算、离散累计概率和抽样边界全部遵守§14.6的定点/舍入口径。I31既覆盖相同输入与种子的重放一致，也覆盖逐日/长步进、串行/并行、分片次序和查询插入不改变真实决定。跨种子比较选择分布，不要求不同种子每次都选不同动作。统计层与物化分配见07 §7.3.1；层级切换不能给同一主体再掷一遍人格。

## 14.6 并行与确定性

- 允许并行的只有阶段 3 中声明 `local: true`（只读写本郡分片）的时钟规则，按郡分片并行计算，各分片的提案先收集、再按阶段 3 的**全局顺序键**（层级, 包 id, 规则 id, 对象骰值键序）归并后依序执行与编号——不是按郡 id 合并；归并后的事件序号与串行执行逐字节相同（I31 的夹具含跨郡交错规则）。
- 其余阶段串行。任何并行化在合入前必须通过 I31 的"串行 vs 并行逐字节一致"测试与跨平台矩阵（标杆 B13.2）。
- **数值确定性**：RX 与全部派生公式的数值类型是**定点数**（整数 + 固定 4 位小数，整数运算），不是浮点；`log/exp` 等超越函数由引擎提供确定性的定点近似实现，禁止调用平台数学库；账户与事件写入的数值是整数（最小单位）；舍入规则（向零取整）是 L0 的一条函数，所有派生共用。跨平台矩阵（标杆 B13.2）对派生值与骰值逐字节比对。

## 14.7 不变量与测试

- **I31 同刻全序**：给定存档与输入序列，任意两次推进（含逐日 vs 一次、串行 vs 并行、不同平台）产生的事件序列逐字节相同。测试：`tests/invariants/i31-total-order.test.mjs` 构造同刻多到期项、多死亡、级联反应的夹具，比较事件序列哈希；性质测试随机打乱规则注册顺序与分片顺序，序列不变。
- 重放（I16）只覆盖"快照 + 事件 → 状态"；I31 覆盖"输入 → 事件"。两者合起来才是标杆标准 B13 的确定性。

## 14.8 世界节奏（用户决定）

用户：玩家离屏时世界推进的快慢由玩家自选，本人偏好"极其极其慢"；节奏是全局速率修正项，时间照常流逝，守恒与因果不变；与玩家相关的重大事件在慢节奏下有预兆并延后；回来时按知情范围给"回程见闻"；默认"适中"。

**节奏是修正项，不是时间缩放**。档位与系数见附录 A §A.10；档位改变是一条输入事件 `pace_set{level}`，进入事件日志，重放一致。

节奏只缩放"事情多快展开"（延迟与反应速度），不改变"每年平均发生多少"。受影响的只有**延迟类**；决定长期存量与年统计的率属**均衡类**，一律 `paceable: false`（数值方案 §1.7、§2.21 逐槽登记）。

| 受节奏影响（延迟类，声明 `paceable: true` 的槽） | 不受影响 |
|---|---|
| 组织计划与图谋的阶段推进、个人多步计划的步间隔 | **均衡类**：火灾、旱涝等灾害、蝗灾、疫病暴发、首领出巢、年久成精、宣战候选的年基率、战役阶段、婚配与生育、迁居（迁徙触发）、商队与进货起意、犯罪的每次机会起意概率、价格与工价的回复（价格是存量与需求流量的瞬时投影，没有"回归过程"） |
| 传闻扩散的每跳延迟（不低于行程下界） | 时间流逝、义务到期与罚息、日程、通行耗时、作物积温、利息闭式、腐坏（这些是守恒或契约，I32） |
| 预兆到主事件的间隔（见下） | 对请求的答复（当下的决策不延后） |
| 社交起意（拜访、闲谈、结交）的频率 | 结算价、守恒转移的数量、已到期的计划阶段 |

实现：派生合成器对声明 `paceable` 的槽在 add / mul / max / min 之后、clamp 之前再乘节奏系数（由 `world:pace` 槽提供，05 §5.9）。包不需要知道节奏存在。

**预兆与延后**（只对"与玩家相关的重大事件"，由框架处理，规则作者不写）：
- 判定：时钟规则产生的事件显著度 ≥ 阈值，且其参与者或起因链上的实体与玩家有持有、义务或强立场（智能层"相关实体"集合，07 §7.2）。
- 节奏系数 < 1 时：框架不立即应用该事件，而是先发一条可感知的 **预兆事件** `omen{about, channel}`（异象、传言、征候；可 tellable，进入传闻），再把主事件登记为到期项，延后 `(1/系数 − 1) × 基准延迟`（基准延迟按事件类数据，有上限）；期间状态若已改变使事件不再成立（首领已被别人杀了），到期时自然落空并记 `lapsed`。
- 节奏系数 ≥ 1 时不预兆、不延后。
- 延后只挪动主事件的发生时刻，不改变其年发生数，所以对均衡类事件（灾害、疫病暴发等）同样适用：它们的触发率不随档，被延后的只是与玩家相关的那一次。
- 预兆不是脚本：它只是把"将要触发"的事实用世界内渠道提前泄露一次，内容由事件模板生成。

**离开时选择节奏**（用户决定）：玩家离屏所经历的世界变化取决于所选节奏。玩家在离开时（离开动作、睡眠 / 长途赶路的快进确认、退出存档）可二选一：**按最慢进度**（本次离开期间世界按最慢档推进），或**为本次离开单独选一档**（只覆盖本次离开，回来时恢复原全局档）。该选择是一条输入事件 `pace_set{level, scope: global | away}`，`scope: away` 的覆盖在玩家返场时由 `pace_set` 还原，两者都进事件日志，重放一致。

**回程见闻**：返场摘要（08 §8.2）在慢档下额外包含回程沿途可感知的景象与公告（按路线与知情范围），不给数字。

**I32 节奏不改因果**：任一档位下 I1–I31 成立；义务到期、日程、通行耗时、守恒数量与档位无关；节奏只改延迟与起意时机，且只作用于声明 `paceable` 的延迟类槽，均衡类的年率不随档；预兆与延后不改变事件的因果链（主事件的 cause 仍指向原起因）。测试：同种子三档各推进一年，守恒与义务到期序列相同，均衡类事件的年统计相同，事件集合差异只在 paceable 延迟类规则的触发时刻与集合。

**标杆**：故事密度等指标在默认档测；另测极慢 / 很快两档的合理率（标杆 B01.6）。
