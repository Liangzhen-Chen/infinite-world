## 10.1 现状结构（代码事实）

- 规模（S0 基线，度量基线.md）：218 个模块（L0 24、L1 25、L2 118、L3 20、L4 31；server-plugin 约 2.92 万行，extension 2,034 行）；2,711 个顶层函数/处理器；tests 272 个测试文件；world/meta/rules.json 51 个顶层规则块（389KB）；world 数据 455 地点、459 路线、12 聚落档、251 家户、548 名册、275 完整档、49 势力；动作清单 242 个（25 个公开工具）。
- 内核：storage.mjs（CampaignStorage、PatchCursor、事件日志 + 快照 + 原子写）；engine.mjs（WorldEngine.reduce：工具分派 → 处理器 → 前后差分 → deriveWorldEvents → 订阅者；737 行）；advance-registry.mjs（57 个推进项）+ advance-layers.mjs（三层 + 补算）；effect-registry/effects.mjs（K6）；magic-effects.mjs + magic-primitives.mjs；interactions.mjs + world/design/interaction-rules.mjs（K2）；traits.mjs（K1）；world-events.mjs（K3：SOCIAL_VERBS 24 个动词、见证派生、订阅者注册、传闻生成）；standing.mjs（K4：归一与传导）；entity-view.mjs（V1：person/group/place/population/item 视图，459 行）；entity-transitions.mjs（V6：转移事件发布，25 行）；group-account.mjs（V4：统一公库）；checks.mjs（d20 五档、对抗、协助、工具加值、隐藏被动）。
- 状态：state.records 是事实上的平行账本集合（扫描到 70 余种 category：debt、contract、legal_case、organization、governance_office、title、territory、diplomacy、pledge、guardianship、physical_feature、authorization、transport、war…），另有 state.npcs/player/effects/creatures/itemInstances/settlements/skills/projects/family/inventory/buildings/professions/obligations/quests/created/remote/pets 等分区。
- 工具：25 个，operation 枚举 221 项（world_settlement 84、world_field 45、world_trade 40、world_law 18、world_companion 17）+ task/choice/action 二级枚举；resolveToolCall 把分组工具映射回内部工具；/execute 路由执行工具调用；界面面板只读（/read）。
- 写入方向：处理器直接 d.set 状态 → 事后差分推导世界事件。与目标相反。
- 循环依赖：PR-01 分支在 entity-transitions 里登记义务交接导致 import 环；RW-07 合并时效果注册表也曾因环移入无依赖模块。

## 10.5 每阶段的测试策略

- 双写期：旧路径与新路径同时写，一条对账测试断言两者一致（账户：余额；持有：集合；义务：到期金额）；对账失败即阻塞，不允许"以新为准"跳过。
- 快照对照：现有 advance-registry 金快照（UPDATE_ADVANCE_GOLDEN）在每阶段重生成一次并在 PLAN 登记原因；结算数值改变必须逐条列旧→新与理由（现有规定）。
- 推演复跑：每阶段合入后 run-001r 全量 + 新题一轮；合理率登记在 docs/事件推演测试.md。
- 意图语料：A3 起每阶段跑桩翻译器；T2 时跑真实模型。
- 无 LLM 场景：A1 起把指南 11.3 的 L/T/S/F 场景逐步脚本化为确定性测试（这是目标架构带来的新能力：绝大部分验收不再需要模型）。
- 基线：tests/baseline 不动；run-baseline 必须继续报告 23 项全部预期失败。
