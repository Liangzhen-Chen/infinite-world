# J1 出题（甲 1：菜单路由没有生产调用者）

出题人：Claude Sonnet 5.5 中档，出题方（只出验收测试，未写修复；未交 DeepSeek）。

## 偏离成立
成立。server-plugin/kernel/transport/menu-entry.mjs:19、:27-31、:43-48 的 installMenuDispatch 在 server-plugin 生产代码里零调用（grep 只命中 tests/kernel/assembly.test.mjs），
server-plugin/index.mjs init 之后 dispatch 恒为 null，一切菜单请求回 rejected 加 E-ACT-WRITER-NOT-READY。
卷二 :965（menu 路由三种载荷由 menu-entry.mjs 分流）、:999（错误上报载荷回 received，各返回路径恰回一次）、:1001 第 1 条（存档读档是 menu 路由上的动作，由 menu-entry 分流）。

## 测试
tests/acceptance/ds-j1-menu/menu-dispatch-wired.test.mjs
- 「生产装配 init(router) 之后，菜单请求不再因处理函数未交入被拒」：不手工调 installMenuDispatch，用生产 init 装配，向 /menu 发动作、错误上报、界面命令、空对象四种形状的请求体，每个恰一个响应、都不得回 E-ACT-WRITER-NOT-READY。
  wire-up-menu-v1 字段表未建（menu-entry.mjs:6），所以不规定字段名，别的拒收码（E-DIM-STRUCT-FIELD、E-ACT-UNKNOWN）都算通过。
  修前红：`生产装配 init(router) 之后，菜单请求不再因"处理函数未交入"被拒（E-ACT-WRITER-NOT-READY）`，断言信息「动作载荷……回了 E-ACT-WRITER-NOT-READY」。
- 「生产装配后，菜单请求体不是对象仍回 E-DIM-STRUCT-FIELD」：对照，修前后都过。

## 提醒修复方
修复后 tests/kernel/assembly.test.mjs 里那条"没有处理函数回 E-ACT-WRITER-NOT-READY"和 installMenuDispatch 的几条测试会与生产装配里的处理函数相撞（重复交入拒 E-WRITER-DUPLICATE），那是已有测试对旧行为的断言，需另行处理，不在本出题范围。
装配文件只许调 assembly.calls 清单内的函数（assembly.test.mjs 有静态核对），所以交入处理函数的位置要在清单内的挂接函数里（如 mountMenuEntry）。
