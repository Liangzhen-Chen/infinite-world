## 五、两件待裁定（方案 :130 写明“块 5 开工前定”）

### 五.1 执行器归哪个组

卷文原句：
- 卷九 §4.2.2 :652：“写：`execute(engine, state, primitives, cause)`，只在 `primitives-runtime.mjs`，只由 `resolve()` 的提交段与推进钩子的调度方调用。”
- 卷二 kernelApi :585：“`kernel/primitives.mjs#applyPrimitive`”。
- 方案 §3.5 第 3 条 :341：“有据一半已裁：入口名 `execute`、删 `applyPrimitive`；组归属待裁定（块 5 开工前定）……块 5 执行器的文件名、导出名与所在组（规则层还是 kernel）定不下”。

可选方案（不超过 3 个）与各自影响：
- **A. 归 kernel 组**：文件 `server-plugin/kernel/primitives-runtime.mjs`；kernelApi 增 `kernel/primitives-runtime.mjs#execute`（callers `rules`），删 `applyPrimitive`；`files.json` 加文件。影响：执行器随内核事务与 `storage` 走，内核不 import 规则层；适配器要调领域写者时只能经 kernelApi 登记入口（与卷二 :578 的 `registerAdvanceHook` 同一做法）。需改 `files.json`、`state-owners.json` 两处共用文件；`sys.ai_interface` 系统行按内核组登记。
- **B. 归规则层组**：文件 `server-plugin/primitives-runtime.mjs`（rules 组）；kernelApi 删 `applyPrimitive` 后不登执行器；执行器经 kernelApi 调 `transaction`／`storage`／`ledger` 等。影响：执行器可直接 import 规则层的领域写者；kernel 写者（持有、终止、事件）仍经 kernelApi，不能直接 import；规则层 import 矩阵要核不越组；`resolve()` 与钩子调度方都在规则层，调用面自然。
- **C. 拆两半**：内核执行核心（契约校验、固定序、事务）在 kernel；适配器表由规则层在模块加载时经登记交入（同 `registerAdvanceHook`、`registerTerminationCleanup`）。影响：多一套登记设施与一张登记表，卡数 +1；内核与规则层都不 import 对方；与现有 kernelApi 登记方向一致，但实现最重。

影响面：决定 5-1 的文件路径、`files.json`、kernelApi 行、门禁闭集，以及 5-3／5-4／5-6 适配器的调用方式。**等李白裁定，不自行取舍。**
