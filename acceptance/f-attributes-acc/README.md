# 卡 F 物品属性由规律派生（K4）：独立验收包

验收方不读 `server-plugin/` 的实现，只经引擎公开入口驱动：`WorldEngine.createCharacter` 开新档，`reduce` 跑 `world_act`（登记动作）和公开工具（`world_field` 钓鱼），`applyPatches` 落盘。
观察只读存档文档里的 `state`、`ledger`。守恒用 `ledger.auditLedger` 和 `tests/helpers/ledger-audit.mjs` 的 `conservation`。
不直接改状态，不调用真实模型，不改仓库。

## 运行

```
# 本机冒烟（浸泡 3 天；实测 2–10 分钟，取决于要等 NPC 开门营业、导师上课几回）
TEMP=F:/dnd-tmp TMP=F:/dnd-tmp node F:/dnd-tmp/f-attributes-acc/acceptance.mjs --days 3
# 只跑营养、生熟、用途，不浸泡
TEMP=F:/dnd-tmp TMP=F:/dnd-tmp node F:/dnd-tmp/f-attributes-acc/acceptance.mjs --skip-soak
# 30 天正式跑（交李白在 Linux 上执行；浸泡约 2 秒/天，连同前两段预计 3–12 分钟）
ACC_REPO=/path/to/被验收的树 node acceptance.mjs --days 30
```

- 仓库由环境变量 `ACC_REPO` 指定，缺省是基线 `F:/dnd-wt/S5FIX`（t-s5fix@58e8d709）。
- 产物目录缺省是脚本所在目录下的 `out/`，环境变量 `ACC_OUT` 可以覆盖。Linux 上不用改代码。
- 产物包括 `out/acceptance.json`、`out/acceptance-days<N>.json`、`out/mutation.json`、`out/mut/`。全过时退出码为 0。
- 每次运行都会从 `ACC_REPO` 重建变异副本 `out/mut/`。副本只拷贝 package.json、schemas、server-plugin、tools、world（不含 drafts）、extension、prompt、tests/helpers、tests/fixtures；node_modules 用 junction 连回。

| 文件 | 作用 |
|---|---|
| lib.mjs | 驱动层：开树、开新档、调用工具、真实取得（买、学艺、按配方做）、吃的探针、守恒 |
| mutate.mjs | 建变异副本，写 `mutation.json` |
| acceptance.mjs | 现象验收，生成 acceptance.json |
| expected.json | 本卡交付后应当 pass 的断言（含 `minDays`） |

## 量具

- **一份东西的营养**：同一存档分两支。一支 `core:eat.meal` 吃下去，另一支原地休息同样时长，比两支的饱腹、水分。这个差就是"吃下去的实际作用"（`dSat`、`dHyd`）。
  引擎回执里报的 `nutrition` 也记下。两者要一致；饱腹到 100 封顶时，按剩余量程比。
  吃之前先休息到饱腹 ≤55（变异段 ≤45），给量程留出空间。
- **来源**：投入材料都向世界里实际持有它们的 NPC 买，或者用开局行囊（干粮）。产物都来自 `core:craft.manufacture` 的真实配方事件。
  检定失败会耗掉材料，所以每次动手前按次补料。
- **刨屑用完**：刨屑每次只补 1 份，动手就耗掉。所以做完之后行囊里不再有刨屑，燃料顶替的断言才成立。断言里同时核对"刨屑 = 0"。

## 断言（28 条）

### 一、营养守恒派生
| id | 现象 |
|---|---|
| N0 | 对照：物品表写了营养的干粮照样能吃（量具本身是好的） |
| N1 | 按真实配方（林穗教的燕麦脆）做出的产物，物品表没写营养，也吃得下，吃完饱腹上升 |
| N2 | 燕麦脆的营养不超过投入：水分 ≤ 投入的一份清水；体征变化与回执报的营养一致 |
| MN1 | 变异：新配方"煮稀干粮汤"，产物是新物品、没写营养字段，吃得下，饱腹上升 |
| MN2 | 变异：稀汤的营养 = 投入之和 − 损耗。饱腹 ≤ 一份干粮（实测），水分 ≤ 一份清水，损耗 ≥ 0 |
| MN3 | 变异：营养跟着投入走。稠汤（两份干粮）比稀汤多，且不超过两份干粮 |

### 二、生熟由加工派生
| id | 现象 |
|---|---|
| R1 | 燕麦炒熟（烤燕麦配方）后可以当一餐吃 |
| R2 | 同一种燕麦，生的与炒熟的，可食性或营养不同 |
| R3 | 差异来自加热：只磨成粉、不加热的燕麦粉，与生燕麦同属生食；炒熟的才不同 |
| MR1 | 变异：新原料灰皮块茎煮熟后可以吃，与生块茎的可食性或营养不同 |

### 三、用途按类别派生
| id | 现象 |
|---|---|
| U1 | 粮：公仓捐粮时，行囊里只有小麦、没有燕麦，小麦照样当粮收下 |
| U2 | 燃料：配方写的是刨屑，行囊里只有木炭时，照样生火做成燕麦脆，并烧掉木炭 |
| U3 | 粮（家户侧，浸泡）：NPC 吃掉的食物不只燕麦和野食，至少还有 2 种别的食物 |
| U4 | 药：资助义诊时拿制黄精片（herb 类，不是"药草"那一件），医馆收下 |
| U6 | 对照：拿盐资助义诊，不被当药收下，拒绝理由里讲到"药" |
| U7 | 饵：谷粒钓饵（用燕麦按真实配方做的）能当饵钓鱼。基线 blocked：世界里没有竹鱼竿 |
| U9 | 对照：没有任何燃料、只有盐时，做不成燕麦脆，盐不会被烧掉 |
| MU3 | 变异：新燃料泥炭砖能生火，顶替刨屑煮成块茎泥，并被烧掉 |
| MU5 | 变异：新药性物品苦根片能入药，资助义诊时医馆收下 |
| MU7 | 变异：副本里有竹鱼竿时，谷粒钓饵能当饵，抛竿时被消耗 |
| MU8 | 变异：新饵蟋蟀饵（bait 类）能当饵，抛竿时被消耗 |

### 四、损耗产生需求（浸泡 `--days N`）
"日用品"由验收方按物品数据界定：配方里当工具用（不消耗）的物品，以及 tool、weapon、clothing、container、liquid_container、w3_household、light 类。

| id | 现象 |
|---|---|
| W1 | NPC 手里的日用品按使用磨损，耐用度下降（库存条目或物品个体上的 durability） |
| W2 | 磨坏的日用品离开 NPC 手里，流进汇（不算作配方投入的那部分） |
| W3 | 替换需求：某 NPC 失去一件日用品，当天该物品有非配方的汇流入；之后他又取得同种物品，而且那天的增量不是 `src:import` 凭空补的 |
| W5 | 玩家随身穿的衣物按耐用参数磨损 |
| W4 | 守恒：浸泡期间账本审计为空，各资源 Δ总量 = 源净流入 − 汇流出 |

### 守恒
NB、MB：基线这一局、变异这一局，账本审计都为空。

## 变异（mutate.mjs，只改数据、不改代码）

新增 7 件从没出现过的物品：稀干粮汤、稠干粮汤、灰皮块茎、灰皮块茎泥、泥炭砖（fuel）、苦根片（herb、medicine）、蟋蟀饵（bait）。食物都不写 `nutrition`。
新增 3 条配方，都在青灯酒馆的灶上做，导师是林穗：煮稀干粮汤、煮稠干粮汤、煮灰皮块茎。

另有一项**取得路径补位**，不是本卡要证的东西：林穗的库存里加了上面 4 种新原料，以及竹鱼竿 1 根。
基线世界里竹鱼竿没有卖家，也没有配方，所以钓鱼的前提造不出来，U7 记 blocked（K1/K2 取得路径）。副本补上一根竿，是为了让"饵按类别匹配"能被测到。

## 基线结果（S5FIX@58e8d709，--days 3）

共 28 条：pass 7（N0、U6、U9、NB、MB、W1、W4），fail 20，blocked 1（U7）。所有 fail 的原因都是被测的规律本身，没有卡在取得或检定上：
- 吃：燕麦脆、烤燕麦、稀稠干粮汤、块茎泥都回"这件物品没有登记为可食用的一餐"；
- 燃料：回"缺少干木刨屑"；
- 药：回"冒险者缺少药草"；
- 饵：回"钓饵不足"；
- 粮：行囊里有小麦，回"行囊谷物不足"；
- 家户只吃燕麦和野食；
- 没有磨坏的汇，没有替换，玩家衣物耐用度不变。

制作检定失败（动作提交了，但没做成）时，用真实动作重试：基线段最多 8 次，变异段最多 5 次。全部失败才记 blocked，写明"检定失败"，不判 fail。涉及的断言：基线段 N1、N2、R1–R3，变异段 MN1–MN3、MR1、MU3、MU7。被引擎拒绝的（比如"缺少干木刨屑"）照常判 fail。

## 期望（expected.json）

- 除 U7 以外的断言，本卡交付后都应 pass。
- W2、W3、W5 带 `minDays: 30`，只在 30 天正式跑时才要求。理由是 `durability.lifeYears=5`，3 天内工具几乎不会磨坏。
- U3 带 `minDays: 3`。
- 基线上已经 pass 的对照：N0、U6、U9、NB、MB、W4。
- 基线上也已经 pass 的 W1：阿砚的削刀在做工时从 79 磨到 77，这是现有的配方 `toolWear`。它说明 NPC 有使用磨损，但不说明磨损来自耐用参数。

## 已知假定（主会话 11-04 认可）

1. **R3**：磨粉不加热，所以燕麦粉仍是生食。判法是燕麦粉与生燕麦的可食性相同。
2. **U1**：只测公仓捐粮这一个入口。周贸易、商店补货里的"粮"只能在 NPC 一侧观察，由 U3 粗测。
3. **U3**：门槛是"除燕麦、野食、清水外，至少还吃掉 2 种别的食物"，属于经验门槛。
4. **W2、W3**：按账户日差推断磨坏和替换，不读专门的"替换"事件。磨坏的汇只排除了用途里带 craft 的那部分。
5. **W5**：浸泡期间玩家全程休息，只测这种情况下衣物的磨损。
6. **N2**：燕麦粉自身的营养从外部量不到（生粉吃不下），真实数据只核对水分上界。严格的"等于投入之和减损耗"放在变异段 MN2、MN3，用能直接吃的干粮作投入。
