# 卡 Q 手艺档位与品质链：独立验收包

验收方不读 `server-plugin/` 的实现。驱动只经引擎公开入口：
- `WorldEngine.createCharacter` 开新档；
- `reduce` 跑工具面的 `world_act`（登记动作）和 `world_trade`（带 `instances` 的出售）；
- `applyPatches` 落盘。

运行时世界用 `tools/load-world.mjs` 的 `loadRuntimeWorld`。观察只读存档里的 `state`（`inventory`、`itemInstances`、`skills`、`player.coins`）和 `ledger`。守恒用 `ledger.auditLedger` 和 `tests/helpers/ledger-audit.mjs` 的 `conservation`。
不直接改状态，不调用真实模型，不改仓库。基线是 `F:/dnd-wt/INT`（t-int@7d5d06b4），可以用 `ACC_REPO` 换成别的树。

## 运行

```
# 本机冒烟（基线）：练 3 天，每档 16 次，约 8 分钟（基线上 B、C 谱系第一步就被拒，不练）
TEMP=F:/dnd-tmp TMP=F:/dnd-tmp node F:/dnd-tmp/q-quality-acc/acceptance.mjs --days 3
# 交付后本机冒烟：B、C 谱系也要学和练，耗时约为基线的 3 倍。为守 15 分钟上限，本机只跑 1 天、每档 8 次：
ACC_REPO=<交付工作树> TEMP=F:/dnd-tmp TMP=F:/dnd-tmp node F:/dnd-tmp/q-quality-acc/acceptance.mjs --days 1 --trials 8 --rebuild
# 交付后分族跑（还超时就这样拆开跑）：
ACC_REPO=<交付工作树> TEMP=F:/dnd-tmp TMP=F:/dnd-tmp node F:/dnd-tmp/q-quality-acc/acceptance.mjs --days 1 --trials 8 --families 木,金属 --no-mut
```

**30 天正式跑（交李白，Linux）**：把整个目录拷过去，不带 `mut/`。

```
ACC_REPO=/path/to/infinite-world node q-quality-acc/acceptance.mjs --days 30 --trials 24 --rebuild
```

- 预计耗时：每个游戏日约 12 秒。基线上每条 A 谱系练 3 天约 1–2.5 分钟；去外镇买料的族（皮）更慢。
- 谱系数量：4 个材料族加 1 个变异族，每族 3 条谱系，最多 15 条，每条练 30 天。
- 合计约 15 × 30 × 12 秒 ≈ 90 分钟，加上做工和出售，留 2 小时。
- 输出 `acceptance.json`（`ACC_TAG=x` 时为 `acceptance-x.json`）。全过时退出码为 0。

可选参数：
- `--trials K`：每档从同一快照分叉做几次，默认 16；
- `--families 木,布`：只跑指定的族；
- `--no-mut`：跳过变异。

| 文件 | 作用 |
|---|---|
| lib.mjs | 驱动层：开树、调用、买或采（`obtain`）、学技能和配方、逐日练习、对账 |
| spec.mjs | 从数据推出材料族、每族要测的配方、可降级的工具和原料 |
| run.mjs | 谱系、三档快照、分叉试做、失败分类、留样与出售 |
| mutate.mjs | 建变异副本 `mut/`，只改数据 |
| acceptance.mjs | 断言与汇总 |
| expected.json | 卡 Q 交付后应为 pass 的断言 |

## 从数据推出测什么（spec.mjs，不按名单）

**材料族**：按配方投入物品的性状归到卡点名的五族。
- 木：timber、wood
- 金属：metal、iron、ore、steel
- 皮：leather、hide
- 布：cloth、fiber、wool、flax、silk、yarn
- 石：stone、clay、ceramic、slate

归族时取用量最大的投入，只当燃料的投入（带 fuel 且不带 timber）不算。

**每族的配方 X** 要满足五条：
1. 有技能；
2. 出生聚落里有人会这门技能（`teachers` 或 `proficiencies`）；
3. 材料、工具在出生聚落买得到或采得到；
4. 工位存在；
5. 产物有耐久，并且是"耐用品"或"配方工具"（`item-use-tags.json` 的 durable 类或 recipeTool）。

候选打分，按以下顺序优先：
1. 产物有用途；
2. 投入里有一种可由配方做出的加工原料 M；
3. 工具里有一种可由配方做出的工具 T；
4. 熟练度门槛为 0。

各族依次挑选（木、金属、皮、布、石），已被别族用过的技能和工具扣分，好让各族换手艺、换工具。

**基线上推出的 4 族**：

| 族 | 配方 | 技能 | 工具 | 降级工具 | 降级原料 |
|---|---|---|---|---|---|
| 木 | 手拨陶轮 | 木匠 | 削木小刀 | 削木小刀 | 铁边料 |
| 金属 | 錾花冲 | 铁匠 | 锤、钳 | 锤 | 铁边料 |
| 皮 | 皮囊小风箱 | 木匠 | 削木小刀 | 削木小刀 | 鞣熟软革 |
| 布 | 宽口滤布 | 织缝 | 针、小刀 | 缝针 | 窄幅麻布 |

具体以 `acceptance.json` 的 `specs` 为准。

**用途集**：由以下三部分合成：
- 物品性状里的用途标签（`item-use-tags.json` 的 `tags`）；
- 命中的用途类别（`classes`）；
- 被任何配方当工具用（recipeTool）。

**手艺档的顺序**：取 `rules.equipment.workmanship` 的顺序，并上 `balance/crafting.json` 里 `workmanship:*` 行。"仿制""粗陋"如果数据里没有，就排在最低两档之下。
**品级**：取 `rules.equipment.qualities`（木 < 石 < 铜 < …）。

## 谱系与三档（run.mjs）

每族开三条谱系，每条都是一局新档，从开局 09:00 出发：

| 谱系 | 工具 | 原料 | 用来测 |
|---|---|---|---|
| A | 向持有人买的真工具 | 真原料 | Q1、Q2、Q3、Q4c、Q5，并作 Q4a、Q4b 的对照 |
| B | 劣工具 T′ | 真原料 | Q4b 工具变量 |
| C | 真工具 | 劣原料 M′ | Q4a 原料变量 |

- T′ 是开局时还什么都不会的玩家，按 T 的配方用真实动作自己做出来的。
- M′ 是同一个外行玩家按 M 的配方做出来的。
- 做不出来就重新备料再做，最多 5 次。

每条谱系取三档存档快照：
1. **缺技能**：备齐料、到工位，什么都没学；
2. **刚入门**：向会的人学会技能，配方要学就也学会，熟练度约为 0；
3. **熟练**：逐日 `core:practice.session` 练 `--days` 天。本机 3 天约 18 点，30 天约 120–180 点。

每档从同一快照分叉 K 次，每次做一次 `core:craft.manufacture`。分叉之间工具、原料、时刻、地点全部相同，只有检定的随机数不同。每次记录：
- 状态和理由；
- 检定档；
- 新实例的手艺档（`workmanship`）；
- 耐久（`maxDurability`）；
- 品质（实例的 `grade`，数值，标准件 1；目录 `quality` 只是物品种类的档次，另记作 `catalogQuality`）；
- 剩余用途；
- 失败时各材料的数量与品质（退回前后的最低 grade）；
- 检定档与技能状况（回执 `degree`、`standing`，缺省为 skilled）；
- 材料消耗比例；
- 这一次的账本对账。

**物品用途集**（spec.mjs `usesOf`，与引擎读的用途同一口径，全从数据推）：`item-use-tags.json` 命中的用途类别（含 recipeTool、nutrition 规则）＋物品性状里的用途标签＋物品带的机制字段 `combat`、`checkBonus`。
**可丢用途**：用途集与 `balance/crafting.json` 各手艺档 `loses` 的交集。没有可丢用途的物品（例如亚麻滤布）不当 Q1d 的样本。

**实例缺掉的用途**以引擎的 `unitLostUses`（`server-plugin/item-class.mjs`，只读调用：实例记的 `lostUses`，旧实例按手艺档推）为准；`physicalItem` 也按它去掉用途标签、检定加成、战斗属性。树里没有这个导出时退回读实例的 `lostUses`。

**A 谱系另外在主线上真做留样**：每档最多试 3 次，留下一件产物。练完以后，在同一时刻、对同一买家，从分叉各卖一件：
- **报价**：回执里的单价，没有单价就取钱数差；
- **成交价**：真成交后玩家的钱数差。

买家依次试：会这门技能的人，再试同聚落有钱的人。

**物理不可行的三种探针**：在 A 谱系的缺技能档，从开局分叉，分别做：
- 只买工具，到工位做（缺材料）；
- 只买材料，到工位做（缺工具）；
- 买齐了在聚落中心做（不在工位）。

## 断言（每族一套，前缀是族名；变异族前缀 V）

| 编号 | 现象 | 判定 |
|---|---|---|
| Q1a | 外行不被拒 | 缺技能档没有一次被拒，且做出了同一种物品 |
| Q1b | 降级档 | 缺技能档所有产物的手艺档都是"仿制"或"粗陋" |
| Q1c | 耐久明显低 | 缺技能档产物平均耐久 ≤ 物品表耐久 × 0.8 |
| Q1d | 部分用途缺失 | 样本配方：X 的产物有可丢用途就用 X；否则在同族、取得得到的配方里另选（同技能优先），在 A 谱系缺技能、刚入门两档同一快照上另做 K 次。样本是落在低档（该档 `loses` 与物品用途有交集）的产物；每件的 `unitLostUses` 都必须包含该档应缺的全部用途。族内没有这样的配方判 blocked |
| Q1e | 只有物理理由才拒绝 | 三种探针都被拒；理由分别命中材料、工具、工位，且不含"学会、技能、熟练、掌握、手艺、资格、尚未、不会" |
| Q2 | 档位分层 | 三档的平均手艺档、平均耐久、平均剩余用途数逐档不减（容差：手艺档 0.15 档，其余 10%）；熟练档的平均手艺档严格高于缺技能档 |
| Q3a | 失败有结构 | A 谱系三档的全部失败按现象分四类，四类都出现过。分类方式见表下 |
| Q3b | 频率相符 | 在 `balance/crafting.json` 的 params 里找 id 含 fail、失败、mishap、outcome、值为"检定档 → 技能状况 → 各类概率"的条目。期望按本次实际出现的（检定档, 技能状况）逐次加权：每类期望次数 E = Σp，方差 Σp(1−p)（二项标准差的逐次推广）；观测次数与 E 之差 ≤ 2.5σ。表里没有那一行的失败（烧制裂损等）不进比较、单列。找不到参数判 fail；表内失败少于 8 次判 blocked |
| Q3c | 失败守恒 | 每次失败的分叉，账本审计和逐资源守恒都为空 |
| Q4a | 原料定上限 | C 谱系熟练档每件成品的 `grade` ≤ M′ 实例 `grade` 的最低值；同时 C 的平均 `grade` < A 熟练档（真原料对照）。只改原料 |
| Q4b | 工具 | A 三档合计的平均手艺档 > B 三档合计。只改工具 |
| Q4c | 技能 | A 谱系中，熟练 > 缺技能，刚入门 ≥ 缺技能 − 0.15。只改技能 |
| Q5a | 报价 | 同一时刻、同一买家，真货（≥普通）留样的报价都高于仿制或粗陋留样；且按 `grade` × 手艺档价格倍率（crafting rows 的 price）排序，单件报价单调不减 |
| Q5b | 成交价 | 同上，比真成交的钱数 |
| Q7 | 守恒 | 每条谱系全程账本审计为空，逐资源守恒为空 |
| Q1*–Q5* | 覆盖 | 该组断言在至少 3 个材料族上全部成立（卡的硬要求） |
| Q0 | 族数 | 数据推出的材料族 ≥ 3 |
| V0 | 变异可载入 | 变异副本只改数据就能载入并跑通 |
| V…Q1a–Q7 | 通用性 | 变异族照样跑上面全部断言 |

**Q3a 的分类方式**（按现象，对齐卡 Q-10 的三类含义）：
- 失败而得到成品，记"部分功能"；
- 没有成品时看材料：
  - 退回的料品质（`grade`）比投入低，记"损耗"（材料退回、品质降低）；
  - 数量少了而品质没降，记"报废"（只剩按配方 `failure.recoverFraction` 的残料，或全无）；
  - 数量和品质都原样，记"无损"。

**"失败"的认定**：回执 `success===false`，或检定档含"失败"，或没有产物。
**回执里的分档字段**：引擎在结果和回执里写 `failure: 'intact'|'wear'|'ruin'|'partial'`（字符串），映射成四类记在 `engineReported` 里作对照，不参与判定。

**材料受世界供给所限**：外行自制劣工具、劣原料时取不到材料（例如第一次失败把树皮耗光），先按世界规则再去取一次：睡到次日，连外镇的持有人和采集点一起找；仍取不到，该谱系记 blocked，理由写"受阻于世界供给（非引擎缺陷）"，不算 fail。

**blocked**：前提现象用真实动作造不出来，写明卡在哪一步。例如：
- 外行自制劣工具被拒，写"前提造不出"；
- 留样里没有同时出现真货和仿制。

blocked 等同未过。

## 通用性变异（mutate.mjs）

在 `mut/` 建副本：
- 只复制 package.json、schemas、server-plugin、tests、tools、world、extension、prompt；
- node_modules 用 junction 连到基线的真实目录；
- docs 不复制：在本机上 cpSync 复制中文目录名会让 node 静默退出。

只改三份数据：
- **新自然材料**：灰纹韧皮 `item_acc_q_ashbark`。性状 fiber、bark、material，归布族。长在北林边据点，资源 30，每 3 天再生 3。
- **新产物**：韧皮提篓 `item_acc_q_bark_tote`。性状 container、fiber，耐久 90。
- **新配方**：编韧皮提篓 `recipe_acc_q_weave_bark_tote`。
  - 样板：数据里第一条有师傅、要工位、投入里有加工布料、工具可由配方做出的配方（基线上是交背麻围裙）。
  - 沿用样板的技能、工位、师傅、工具。
  - 投入：新材料 ×2，加样板的加工原料（窄幅麻布）×1。

变异族用同一套谱系和断言跑一遍，前缀 V。新材料由玩家在据点真实采集。

## 基线结果（INT t-int@7d5d06b4，--days 3 --trials 16，580 秒）

见 `acceptance-baseline.json`、`baseline.log`。结果：pass 12、fail 35、blocked 32，共 79 条。`expected.json` 有 82 条：其中 3 族的 Q5a 在基线上早早 blocked，没输出对应的 Q5b，已补上；现在的脚本会一并输出。

**pass**：
- 每族的 Q3c、Q7；
- Q0；
- V0。

失败扣料守恒、账本守恒、变异载入，本来就是好的。

**fail**：
- **Q1a**：外行一动手就被拒。理由是"尚未掌握该配方所需技能"或"尚未学会这个配方"。连不需学的 kc_* 配方也要技能。
- **Q1e**：三种物理探针都先被"技能"理由拦下，拿不到物理理由。
- **Q2、Q4c**：缺技能档没有产物。另外练 3 天后熟练档并不好于刚入门：熟练度 0 到 20 多点，手艺档平均没升。现行的手艺档基本只看检定档。
- **Q3a**：失败全是"报废"（按配方回收 0 或部分份数），没有无损、部分功能。
- **Q3b**：crafting.json 没有失败分档参数。
- **Q1*–Q5\***：覆盖断言，没有族全过。

**blocked**：
- Q1b、Q1c、Q1d：外行没有产物。
- Q4a、Q4b：外行自制劣原料、劣工具被拒，"前提造不出"。
- Q5：没有仿制留样，或者留样不足两档。

变异族（编韧皮提篓）的形态同上。

## 拿不准的地方

1. **实例用途字段名**：交付可能用别的名字。只需在 `usesOfUnit` 补一行读法。
2. **失败分档参数**：靠 id 和 key 关键字在 crafting.json 里找。交付的写法若不同，需要补关键字。
3. **"熟练"的强度**：本机 3 天只到约 20 点熟练度。Q2、Q4c 的严格比较要靠 30 天长跑才稳。本机冒烟出现熟练不如刚入门，可能只是样本噪声。
4. **原料品质的读法**：从原料实例的 `workmanship`、`quality` 读；原料没有实例时，读整堆上的同名字段。交付若把原料品质记在批次（ledger lots）上，需要补读法。
5. **不在工位的探针**：在出生聚落中心做。若交付把"借地方做"也算成可行，这条探针要改。
