# 卡 E 分销与补货（K2）：独立验收包

验收方没有读 `server-plugin/` 的规律实现，只通过引擎的公开入口驱动：
- `WorldEngine.createCharacter` 开新档；
- `reduce` 调工具面的 `world_time`（推进时间）、`world_move`、`world_trade`；
- `applyPatches` 落盘。

观察时只读存档里的 `state`、`ledger`（accounts、flows、budget）和 `records`。另外用了两样只读工具，测试里也是这么用的：
- 价格投影 `regionalTradeBase`，用法与 tests/shop-restock.test.mjs 相同；
- 守恒辅助 `auditLedger`、`driftCounts`，以及 tests/helpers/ledger-audit.mjs 的 `conservation`。

验收不直接改状态，不调用真实模型，不改仓库。仓库用环境变量 `ACC_REPO` 指定，默认是基线 `F:/dnd-wt/S5FIX`（t-s5fix@58e8d709）。

## 文件

| 文件 | 作用 |
|---|---|
| lib.mjs | 驱动层：开新档、调用工具、读持有量、位置→聚落、账本逐步差分、区域价格 |
| acceptance.mjs | 现象验收。`--part main\|mut`，`--days N`（默认 30）。结果写入 part-<part>.json，并合并成 acceptance.json（含与 expected.json 的对照） |
| mutate.mjs | 生成通用性变异副本 mut/ |
| expected.json | 卡 E 交付后应当为 pass 的 22 条断言 |

## 命令

本机冒烟（每部分 3 天，约 20 秒和 10 秒；同一时间只跑一个 node）：

```
TEMP=F:/dnd-tmp TMP=F:/dnd-tmp node F:/dnd-tmp/e-distribution-acc/mutate.mjs
TEMP=F:/dnd-tmp TMP=F:/dnd-tmp node F:/dnd-tmp/e-distribution-acc/acceptance.mjs --part main --days 3
TEMP=F:/dnd-tmp TMP=F:/dnd-tmp node F:/dnd-tmp/e-distribution-acc/acceptance.mjs --part mut  --days 3
```

**30 天正式跑（交给李白在 Linux 上执行）**。`<仓库>` 换成待验的实现树，`<包>` 换成本目录的拷贝：

```
export ACC_REPO=<仓库>
rm -rf <包>/mut && node <包>/mutate.mjs        # 用 rsync 复制、软链 node_modules，约 1 GB，1–3 分钟
node <包>/acceptance.mjs --part main --days 30   # 约 3–4 分钟（本机实测 9 天 46 秒）
node <包>/acceptance.mjs --part mut  --days 30   # 约 2–3 分钟
```

- 换一棵仓库来验之前，必须先删掉 mut/。mutate.mjs 发现 mut/ 是从别的仓库复制的，会拒绝继续。
- 全部断言都通过时，退出码为 0。

## 判定方式（22 条断言）

### 观察节奏
- 每天在 05:59、11:59、17:59、23:59 各观察一次。
- 每次观察对账本做差分，得到逐账户、逐流水的变化。
- 写入者预算 `ledger.budget.used`（键为 写入者|源|资源）只在 23:59 读，这时它是当天的累计值。

### 追溯量具（来源必须可追溯）
- **生产者**：某一步里该物有生产流入（src:craft、src:harvest、src:husbandry、src:regrowth、src:birth），这一步里该物增加的持有人记为生产者。
- **下游**：某一步里该物没有 src:import，有生产者或下游的持有人减少，同步增加的持有人记为下游。
- **承运**：账户持有人本身是一条存档记录（例如 `settlement-trade:…|cargo`），这就是在途货。
  - 记录里的起点字段（from、seller、origin…）点名的一方，算作货的来源；终点字段（to、buyer、destination…）点名的一方，算作货的去向。
  - 跨聚落但不经在途账户的转手，在记录里找"带路线或途经点、并且点名双方"的承运记录。
- 开局存量、src:import、据点再生的制成品都不算来源。
- **对照组**（不计入判定）：S5 的燕麦周贸易。跑 9 天时，4 条线路全部认出为跨聚落转手加承运，起点和终点都对。燕麦来自开局粮仓，所以"可追溯"为 0。这说明量具认得出真实承运，也不会把开局存量当成产出。

### 断言

| 组 | 断言 | 怎么判 |
|---|---|---|
| R 补货 | R1 样本 | 玩家在所在聚落按物品标签分组，每组挑总价最低的一项，用 `world_trade` 真实买空。要求 ≥5 组，不含燕麦 |
| | R2 恢复 | 买空的每一项在窗口内重新有货，或者持货人又卖出了这件货。没恢复的如果全是季节外，判 blocked 并列出明细 |
| | R3 可追溯 | 恢复的每一项，恢复那一步该物没有 src:import，并且对手方是生产者、下游或承运账户，持货人自产也算。对手方持有窗口外更早的真实产出批次（入库日早于开局，且不是开局批次）也算。追溯不到、又确实季节外的，判 blocked，写"季节外"并列出明细 |
| | R4 承运 | 跨聚落进货每一次都有承运证据 |
| | R5 自然卖空 | 持货人向第三方卖出后库存归零的，也要恢复并且可追溯。季节外的处理同 R3 |
| | R6 不只燕麦 | 可追溯恢复的非燕麦物品 ≥5 种 |
| M 商人套利 | M1 价差 | 每天读各聚落的区域价格，出现某物在两地相差 ≥25% |
| | M2 商人 | 有 NPC 在低价地进货、到高价地出货。证据可以是成交记录 market_trade 的 place，也可以是账本里这个人的进出和对手方所在聚落 |
| | M3 收窄 | 商人搬运过的物品和聚落对，窗口结束时的价差小于价差出现时 |
| S 派生商店 | S1 | 派生卖家数 >0。条件：不是 stores 里登记的店主，没有 shopType，向 ≥2 位不同买主出售（不算玩家），所售物由生产或下游补进 |
| | S2 | 玩家走到一位派生卖家那里，真实买到 1 件 |
| T 没有水龙头 | T1 | shop 的物品 src:import 为 0 |
| | T2 | 用真实玩家动作触发任务：开局玩家发一张送货委托（交付物取开局有 ≥2 位持货人的最便宜食物，基线上是干粮）；窗口里告示板一出现 NPC 发的公开任务，玩家就去接，交付类向持货人真实买齐后交付。判定：quest-sources 物品进货为 0，且玩家收到的任务交付物在当步有真实持有人减少、没有 src:import。触发不了或窗口内没有交付物流动，判 blocked 并写明原因，不判 pass |
| | T3 | works 写入者对应 world_research（写书、测绘、演出）。开局逐个真实尝试；建角色时没有识字或手艺背景可选（createCharacter 只收 name、attributes、birthplace），全被拒时就走学艺路径：从第一条拒绝理由里认出缺的手艺（基线是"识字"）→ 找本聚落 serviceCatalog 里 teach 这门手艺的人（基线是陆青）→ 拜师，有检定，没学会改天再上 → 每天 05:59 后练 3×180 分钟，练到门槛（books.minimumLiteracy=100）→ 按"缺少某物"的理由向持货人买材料（羊皮纸、墨）→ 写书，检定没成就再写 → 出版。成稿或出版提交、并且 works 物品进货为 0，才判 pass；学艺没完成判 blocked，写明阶段和熟练度 |

| G 通用变异 | G1–G3 | 见下节 |
| V 守恒 | V1、V2（两部分各判一次） | `auditLedger` 为空；`conservation` 为空；没有漂移 |

### 通用性变异（mutate.mjs）
- **新物从数据派生**：在"产出为有饱腹值食物"的配方里，取门槛最低的一条作模板（基线上是 recipe_bake_flatbread）。
- **加入的内容**：克隆出新物 `item_acc_e_novel_cake`（荞香团子），新 id、新名字，饱腹、价格、保质期都不同；再加一条新配方 `recipe_acc_e_novel_cake`。
- **配方设定**：配方无需拜师，开局没有任何人持有这件新物。
- **生产者和需求**：生产者是具备该技能和工位的人，需求来自要吃饭的家户。
- **断言**：
  - G1：新物被生产；
  - G2：新物到达产地以外的聚落；
  - G3：新物没有凭空进货，也没有开局存量。
- 新物从没出现在任何名单里。要让这三条通过，规律只能按物品属性通用地覆盖它。

## 基线结果（S5FIX，各 3 天冒烟）

pass 6 / fail 8 / blocked 8（主会话 11-04 定下 4 条口径后重跑）。另外跑过一次 9 天，用来确认燕麦对照组；那次 T4 另多出 military 军粮进口 1134 件。

- **pass（6 条）**：
  - R1：买空了 8 组样本，包括盐、树脂、苇笔、鞣皮树皮、芦苇捆、鱼、萝卜、手杖；
  - M1：燕麦在聚落间有约 28% 的价差；
  - V1、V2：主世界和变异副本各两条。
- **fail（8 条）**：
  - R2、R3、R5、R6：买空的货不补；自然卖空的只有青灯酒馆，靠 import 补回；
  - M2：有价差，但没有商人搬运；
  - S1：派生卖家 0 位；
  - T1：shop 凭空进货，3 天 19 件；
  - T4：src:import 物品流入共 19 件。
- **blocked（8 条）**：
  - T2：已真实发委托、接了一张 NPC 任务（结盟类，不是送货），3 天内没有交付物流动；
  - T3：写书、测绘、演出开局全被拒；已拜陆青学会识字（第 3 天），但熟练度还是 0/100。本机冒烟只跑 3 天，照规定判 blocked。实测从 0 练到 100 约要 16–17 天，所以 30 天正式跑里大约第 20 天能写书、出版，还剩约 10 天观察 works 的进货。写书和出版这两段只在 30 天正式跑里走得到，本机没有跑通过；
  - R4：没有补货可判；
  - M3：被 M2 卡住；
  - S2：被 S1 卡住；
  - G1–G3：变异新物无人生产。缺按需求经配方生产的规律，属于上游卡 C（K1）和卡 D（K3）。

## 口径（主会话 11-04 定）
1. **T2、T3 不许空真**。用真实玩家动作触发，触发不了就判 blocked，写明原因。
2. **军粮进口算水龙头**。T4 维持 fail；只有数据里带理由、点名具体资源的图外供给声明可以豁免，'*' 通配不算。
3. **季节**：可以追溯到窗口外更早的真实产出批次，开局存量不算。季节外的判法见 acceptance.mjs 里的 seasonInfo：
   - 该物只有带 seasons 的采集产地；
   - 没有任何配方产出它；
   - 这些产地的季节都不在窗口里（月序 ÷ 3）。

   追溯不到、又确实季节外的，判 blocked。

## 价格读法（实现方改了价格口径时要跟着核对的几行）
- **lib.mjs 第 12 行和第 67–69 行**：regionalPrice 调用只读投影 regionalTradeBase(d, engine, item, settlement)，读的是"该物在该聚落的区域基准价"，不是成交价。如果实现方把地方价格改由别的函数推导，或者签名变了，这里要换成新的只读投影。区域价格应当反映各地真实的供需。
- **acceptance.mjs 第 72 行 readPrices**：每天 23:59，对开局持货人手里的每种物品，在存档的每个聚落各读一次价格。
- **acceptance.mjs 第 245 行**：M1 判"足够大价差"的口径，是同一物在两聚落的价格比 ≥ 1.25。
- **acceptance.mjs 第 260 行**：M3 判收窄，比较的是窗口末的价格比和价差刚出现时的价格比。

## 仍拿不准的地方
1. **任务交付的观察只认一种情形**：玩家自己发的委托由 NPC 交付到玩家手里。NPC 之间互相履约时交付物的去向，没有逐笔追。quest-sources 的物品进货总量由写入者预算兜住。
2. **追溯按观察步做差分**，6 小时一步。同一步里同一物既有进口又有真实转手时，整步都按"进口"处理，偏严。在途账户的起止按记录字段配对，记录没有标准字段时，按"记录里提到"的一方配对。
3. **季节外判定只看采集产地的 seasons 字段**。农作物的生长期（rules.agriculture.crop）没有纳入；燕麦本身不在样本里。
