# 卡 C 通用初加工链：独立验收包

验收方不读 `server-plugin/` 的实现，只经引擎公开入口驱动：`WorldEngine.createCharacter` 开新档，`reduce` 跑工具面的 `world_act`（登记动作）和 `world_propose`（开放提案），`applyPatches` 落盘。
观察只读存档里的 `state`、`ledger`（`accounts`、`flows`、`crafts`）。守恒用 `ledger.auditLedger` 和 `tests/helpers/ledger-audit.mjs` 的 `conservation`。
不直接改状态，不调用真实模型，不改仓库。

## 运行

```
# 本机冒烟（≤3 天，约 1 分钟）
TEMP=F:/dnd-tmp TMP=F:/dnd-tmp node F:/dnd-tmp/c-processing-acc/acceptance.mjs --days 3
# 换被验收的树（交付后）：ACC_REPO 指向交付分支的工作树；树变了会自动重建变异副本，也可加 --rebuild
ACC_REPO=<交付工作树> TEMP=F:/dnd-tmp TMP=F:/dnd-tmp node F:/dnd-tmp/c-processing-acc/acceptance.mjs --days 3 --rebuild
```

**30 天正式跑（交李白，Linux）**：把整个 `c-processing-acc/` 目录（不含 `mut/`）拷到 Linux，K8 守门脚本若不在被测树的 `tools/` 下，用 `ACC_K8` 指过去：

```
ACC_REPO=/path/to/infinite-world ACC_K8=/path/to/k8-guard.mjs node c-processing-acc/acceptance.mjs --days 30 --rebuild
```

- 预计耗时：本机 3 天两次浸泡共约 1 分钟，每个游戏日约 2.5 秒；30 天两次浸泡（基线树 + 变异树）约 5–10 分钟，存档变大会更慢，留 20 分钟。
- 输出 `acceptance.json`（`ACC_TAG=x` 时为 `acceptance-x.json`），全过退出码 0。

| 文件 | 作用 |
|---|---|
| lib.mjs | 驱动层：开树（一个进程里可先后开基线树和变异树）、调用工具、读流量与制作记录、产出追踪、推进时间 |
| mutate.mjs | 建变异副本 `mut/`（只复制运行所需目录，node_modules 用 junction），只改数据 |
| acceptance.mjs | 现象验收，34 条断言 |
| expected.json | 卡 C 交付后应为 pass 的断言（全部 34 条） |
| acceptance-baseline-3d.json | 基线树 3 天冒烟结果 |

## 判定方式

**真实产出**：一段时间里某物品的源流入，去掉开局（`src:genesis`）、凭空进货（`src:import*`）、漂移（`src:drift`）；如果它是制成品，据点再生（`src:regrowth`）也不算。
**制成品** = 任何配方的产物或副产物，加上卡点名的九类产物。其余是自然物。
**产出追踪**（"每一单位追到配方 + 自然投入 + 劳动"）：
- 产出它的每条制作记录（`ledger.crafts`）都能认出做工者（玩家，或事件编号里的 NPC）；
- 每种投入：如果是制成品，同期真实产出必须覆盖全部制作消耗（不能靠开局存量），并且递归同样可追；如果是自然物（据点存量、林木、水、猎获、农事），同期没有凭空进货即可。
- 对照（`controls`，不计入判定）：基线浸泡里阿砚做的小工具木柄，用同一追踪器能追到"recipe_tool_handle + 木料 + 阿砚"，说明量具本身能用。

| 组 | 断言 | 怎么判 |
|---|---|---|
| S0 / S1 | 2 | 基线浸泡、变异浸泡都真实推进完成，账本审计为空，逐资源 Δ总量 = 源 − 汇 |
| P1 产量 | 18 | 九类各 2 条：①浸泡期内真实产量 > 0；②产出追踪成立。类别：羊皮纸、墨（收烟墨粉、树胶烟墨）、铁（铁料）、麻线、木板（松木短板）、木炭、皮革（鞣熟软革、薄鞣山羊革）、面粉（燕麦粉、黑麦粉）、纸（带 paper 性状、不是书、不是羊皮纸、作为配方投入的物品，从数据推出；基线上是黄表纸）。类内任一物品成立即可 |
| P2 技能书 | 2 | ①探路：用开局的纸墨（向陆青买羊皮纸、向砚者买墨粉）和买来的原本，依次试三条路——名字里有抄、誊、copy 的登记动作；产物是书的配方（先学再做）；开放提案（消耗纸墨、产出书）。书多 1 本、纸墨少了、账本守恒才算。②正式：纸墨只能向浸泡里真的做出过它们的人买，再抄。取不到料时判 blocked |
| P3 工具 | 4 | ①浸泡里有人按配方造出工具，且可追溯；②每种磨损报废的工具（sink 流出），同期配方产出 ≥ 报废数（浸泡里没有报废就 blocked）；③数据推导：配方用到的每种工具，K8 守门的产出路径分析都能走通；④卖家补货追到生产者：开局先把出生聚落一位卖家的某种工具买空；浸泡里工具的凭空进货为 0，卖家补进的每种工具同期确有配方产出（没有补货就 blocked） |
| P4 据点 | 4 | ①浸泡里制成品的据点再生为 0；②浸泡里制成品的凭空进货为 0；③数据：据点再生条目（`site.changes` 的 regrow）里没有制成品；④采空不复生：开局走到离出生地最近、带制成品再生条目的据点（基线是灰市的铁边料），进去采空，浸泡结束时存量不能涨回。浸泡天数短于该条目的再生周期时判 blocked（未到判定点） |
| V0 | 1 | 变异副本只改数据就能载入 |
| P5 变异 | 2 | 新自然材料"雾岩苔绒"（北林边据点，带再生条目）和新配方"压制苔毡"。配方的技能、工位、师傅照数据里第一条有师傅的配方（削制榫用木楔，阿砚、旧磨坊）。①玩家：采苔绒，向阿砚学，在工位做出毡片（`src:craft`），账本守恒；②NPC：变异浸泡里有 NPC 自己按新配方做出毡片，并且可追溯 |
| P6 删投入 | 1 | 候选是九类产物配方里的自然投入，按它在规则表、据点、物种里的产出条目数从少到多逐个试删（消耗语境的条目不删）。删后用 K8 确认这项投入已经"全世界都不产"，取第一个删干净的（基线上是铁料的含铁矿石，删掉了 3 条矿脉）。检出 = K8 在原树不报、在变异树报该产物；或者原树浸泡有产量、变异树为 0。两种方式任一成立即可 |

**通用性**：
- 变异只加从未出现过的数据，不改代码；
- 九类以外的判定，包括制成品、工具、据点再生条目、抄写路径、删哪项投入，全部从被测树的数据推出，不按名单；
- 九类的物品编号按卡点名取。如果交付时为这些产物新开了物品编号，要同步改 `lib.mjs` 的 `categories`。
