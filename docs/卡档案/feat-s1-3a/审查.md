## 发现与处理
结论：**必须改**

1. server-plugin/rules/act/catalog.mjs:312、server-plugin/rules/act/resolve.mjs:22、world/actions/core.json:23。问题：意图要求带 actor，但冻结的 wire（F:/dnd-tmp/draft-s1-3.md:76）和 S1-3b 的调用（feat/s1-3b:server-plugin/rules/transport/menu-entry.mjs:36）都不带，从真实菜单入口提交「等待」必被拒 E-ACT-PRECONDITION，竖切片走不通。建档后 menu(null) 为空、visible 不含化身，前端拿不到化身 id。改法（**接口归属须主会话定**）：A（推荐，S1-3b 不用动）——意图缺 actor 时，由本局玩家化身派生（已有的 avatarsOf；恰好一个时取它，零个时为 null），menu(null) 在有化身时也按该化身投影，并把化身放进 visible；B——S1-3b 的 wire 加 actor（或用 subject 代），并在 view 里给出化身 id，代价是改冻结接口，已审过两轮的 S1-3b 要重审。
2. tests/acceptance/feat-s1-3a/origin-act.test.mjs:82、:200（交出题方）。问题：没有验收「意图级拒收按请求编号进日志、复演同位同样被拒」（卷二:545、卷二十七:742）；assertRejected 在没有拒绝事件时也会通过。改法：拒收时断言恰好有一条 `kind:'event', ok:false`，其 seq 等于结果的 seq、code 等于拒收码；复演用例里先放一条被拒的意图，再断言复演后日志同位相等、saveDigest 一致。
3. tests/acceptance/feat-s1-3a/origin-act.test.mjs:100（交出题方）。问题：开关为 false 时排除对应文化这一行为没有测（docs/世界设计/14-历史传说与玩家来历.md:218–:220）。改法：在临时根把 world/rules/tables/player-origins.json 的 allowBeastkin（和 allowMonsterSocieties）分别改为 false，断言候选恰好少掉 gate 指向该开关的那些来历行；期望集合从 origin 族的 gate 字段算，不写死个数。
4. world/ontology/state-owners.json:25、:27（交写码方）。问题：登记里写的 rules.playerOrigins.backgrounds 并不存在，与实现的判据不符。改法：把含义改成实际判据（「以带 origin 的实体行为 template 新建的个体」和「origin 族条目 gate 为空或所指开关为真」）。

不阻合提示：化身靠模板派生，NPC 以后若也用带 origin 的模板实例化会被误算成化身，S2-H 建席位边时须改（server-plugin/rules/act/catalog.mjs:302）；world/actions/core.json:20 的上限键直接写了 acls_rest，与行的 class 是两处同值，将来改 class 时须同改；bg_beast_exile 的出生地限制未做；起始物与钱只登记在数据里，没有揣上身。
