## 说明

- 人与第二物种的识别全部从数据推：人 = 身体图含 null 键的物种（HUMAN_IDS），第二物种 = 其余物种（SECOND_IDS）；不写物种或身体图的 id。第 10、11 条对全部物种逐一验证，因而第二物种与人都覆盖。若将来人形与第二物种的身体图都含 null 键，则 HUMAN_IDS 会有两个成员，用例仍按 [0] 取人形，需要时由主会话另定。
- 个体创建：`submitProposal({effects:[{op:'create', kind: <物种表 kind>, template: <物种 id>, facts: {}}]})`，kind 取物种表文件的 `kind` 字段。卷文与派卡都未写明个体的 kind，此处按「模板行所在表」推断（卷二:131、kernel/dimensions.mjs:38–41）。若写码采用其他 kind，请主会话裁定。
- 视图入口：`env.views.bodyView(subjectId)`、`env.views.carcassOf({speciesId, massKg})`，即派卡约定的薄闭包形状。bodyView 的能力键同时接受维度名（body_plan 能力段的 dimKey）与能力族代号两种写法，因卷四:410 只写「<cap>」，未定键名。
- 第 12 条与第 13 条的坏数据与扩展数据只在内存副本上改（rawCopy 深拷贝 + mountKernel），不写盘、不改 world/。副本中的探针组织与探针能力取自 _vocab.json 族条目里身体图未用的那一条，探针物种 id 为表 idPrefix 加固定后缀 s2b_probe，仅存在于副本中。
