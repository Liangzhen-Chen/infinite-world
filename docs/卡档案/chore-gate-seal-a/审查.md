## 发现与处理
结论：**必须改**（2 条）。

1. tools/accept/pre-push.mjs:53 与 tools/accept/lib/card-archive.mjs:519、:535。问题：合并提交按第一父求差后，角色与验收目录核对也用这个集合——卡分支同步主线时把 master 带来的别卡验收文件算到写码头上而误拒；反过来写「角色：合并」的真合并可以在合并里夹带任意改动（含验收目录），不核身份。改法：pre-push 对合并提交另算本提交自己的改动 `git diff-tree --cc --no-commit-id --name-only -r -z <sha>`（合并结果与每个父提交都不同的文件），作为 judgeCommit 新入参（如 ownFiles）；合并提交的 touchesAccept 与角色核对改用 ownFiles；「合并」角色的 ownFiles 若碰验收目录即拒（或按出题角色核）。补正反例：写码同步主线、主线带来别卡验收文件放行；「合并」真合并夹带验收目录改动拒。第一父求差的档案触发判定保持不变。
2. tools/accept/lib/card-archive.mjs:395。问题：orca.commits 只核可达与角色行，主线上任何老卡同角色提交都能充当本卡凭证。改法：同时核该提交说明的标识行（tools/accept/lib/card-archive.mjs 里已有 normId 比较口径）须等于本卡三方标识里该角色登记的标识之一（checkParties 的 map 已算出，经 ctx 传入）；补反例：别卡写码提交作凭证拒。

不阻合提示（记后续，不在本卡改）：docs/卡档案/ 无角色约束，别卡 state.json 可被任何提交改；state.json 值核对字段名与 orca 子键在代码里；docs/卡档案/chore-gate-seal-a/反思.md 引的 tools/accept/lib/card-archive.mjs:128 行号偏（缺键不启用的代码在 tools/accept/lib/card-archive.mjs:151 附近）。
