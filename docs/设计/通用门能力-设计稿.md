## 〇、一页摘要

**主干（一句话）**：把 `sourceFor` 的 9 个特例换成一张**效果族表**——每族由世界状态（权能与持有、物品性状与阶、技能阶、地点设施、配方、物种数据、身体负重）派生来源、耗时、难度、上限和"该谁点头"；**物理上做得到的先发生**，社会许可只变成事件标签，由一个通用的"规范后果"订阅者按法典立案、并沿现有立场、记忆、传闻管线连锁；NPC 对开放提案用同一个 `npcDecision` 给出接受、还价或拒绝。同一张表同时驱动可做之事卡、构造器和将来 Jev 的选项。

**覆盖**（本批之后开放路径不再"无来源→只留痕"的效果）：
- 持有：借出、放弃、过户、份额（holding.open/close/transfer/rescale）。
- 义务：雇佣、借贷、"看铺子换米"、以物抵债（obligation.create/settle/cancel）。
- 毁坏与种群：烧信、砸物、宰自家羊（destroy、种群个体化）。
- 搬动与束缚：扶醉客进屋、把箱子推到门后、把小偷捆起来（move 他人或他物、custody）。
- 按配方制造与学习：路由到已有配方或真实教学来源，不再一刀切拒绝。
- 所有者处分权（K7）：自有物、自有活物、自有种群缺省可处分。
- 合法性是后果（K6）：约 40 处"社会许可当前提"的拒绝，归成 6 种模式迁移。

**工具面**：用 `world_propose` 替换 `world_check`，公开工具仍 27 个。静态提示估算 **10586 → 约 10521**（−65），不超 10593 基线（第七节）。

**拆卡**：4 张实现卡 + 1 天回归。
- 卡 1：骨架与后果层，串行先做。
- 卡 2：持有族、义务族与 NPC 答复。
- 卡 3：毁坏、种群、搬动、束缚与 K7。
- 卡 4：K6 迁移、配方路由与固化断言。

卡 2、卡 3、卡 4 在卡 1 之后可以并行。总工作量约 7.5–9.5 人日，日历约 5–6 天。

**最大的三个风险**：
1. 放开约 40 处前提后，法典模板里还没有新罪名（擅入、毁损他人财物、非法拘禁、擅用、盗伐、盗猎）的罚则。没有罚则时只留标签、不立案，"偷、毁、擅入"等于没有代价。
2. 种群个体化会撞上 I1 守恒、疫病隔室、畜群日结连续性和 I14 离屏等价。另外屠宰产物的数据是空的：168 种生灵里 0 种的死亡产物里有肉，宰羊只能得到一张生皮。
3. 会翻转约 22 处固化断言和一批开放路径的拒绝断言，容易出现"按测试打补丁"。另外可做之事卡要探测的族变多，可能拖慢 world_actions。

**需要用户或主会话定的事**（详见第十三节）：
- ① world_propose 是否保留"纯检定"（建议不保留）。
- ② 尸体产出的派生规律（K4 子项）要不要并入卡 3。
- ③ 新罪名罚则数据由谁、走哪条审批管线补。
- ④ 与 AUDIT2 的两处分歧：颁发施法许可判为真实限制；断言计数是 22，不是 21。
- ⑤ 所有卡默认用 Sonnet。

## 二、总体结构：效果族表

### 2.1 一张表，三处消费

新增 `world/rules/tables/open-sources/*.json`，按族分文件，便于并行改：
- holding.json
- obligation.json
- physical.json
- craft.json
- 另外把现有 9 类迁入 base.json。

每行描述"一族效果"怎样从世界状态得到来源。行的字段：

```json
{
  "id": "physical.destroy",
  "ops": ["destroy"],
  "applies": "isThing(effect.entity)",
  "power": "authority",
  "means": [{"kind": "tool", "property": "$method.property"}, {"kind": "body"}],
  "counterparty": null,
  "contested": "controllerPresent(effect.entity)",
  "time": "materialWork(effect.entity, $means).minutes",
  "difficulty": "rules.open.generic.physicalDifficulty",
  "bounds": {},
  "stage": "$means.stage",
  "reward": null,
  "legality": "authorityTags"
}
```

- 表达式一律用 RX（12 §12.8.1），或一组**有限的原生派生函数**。函数清单见 2.2，每个都是通用的，不按意图、不按 ID。
- 表里**不出现**任何物品 id、人物 id、意图词。一族只说"看什么数据"，例如"切割要有带 cut 性状的工具""搬人要比对负重和体重"。
- 消费方有三处，读的都是同一张表：
  1. **裁决**：`deriveOpenLimits().sourceFor` 改为按 op 找到族行，求出来源。现有 9 类迁成 9 行，行为不变，作为回归基线。
  2. **可做之事卡**：`entityCard` 的写死探测清单（action-affordances.mjs:342–354）改成"对此目标类适用的族行逐个探测"。
  3. **构造器和 Jev 选项**：族行的 `ops` 和 `means` 就是"做什么、用什么"的选项来源（第十二节）。

### 2.2 原生派生函数（封闭清单，卡 1 落地）

| 函数 | 读什么 | 用于 |
|---|---|---|
| `authority(actor, op, subject)` | 现有权能：owns/operates/监护/委托/职位/法典授权/决议/占有（action-authority.mjs:148） | 持有、义务、处分 |
| `physicalReach(actor, target)` | 同节点、分区距离、视线（primitiveTargetFacts） | 所有物理族 |
| `controllerPresent(subject)` | 标的的现任控制者在场且清醒（currentControllers + 在场 + capacity） | K6：控制者在场就是物理阻碍 |
| `usableMeans(actor, property)` | 随身、完好、等级够用、带指定性状的物品及其物品阶；已学技能的技能阶 | 工具和技能来源 |
| `materialOf(entity)` / `materialWork(entity, means)` | 材质表（由代码常量迁成数据）× 物品重量 × 工具阶系数 → 分钟数与抗性 | 毁坏、改物、捆绑 |
| `massOf(entity)` / `carryLimit(actor)` | 物品 weight；人物与生灵体重读物种数据，缺省读物种模板体重表；负重读 `combat.character.carryBase/carryPerStrength`（carry.mjs:23） | 搬人、搬物 |
| `recipesFor(output)` | 配方产出、行为者已知配方、技能阶、工具、工位可达性、投入持有量 | 制造路由 |
| `teachingSources(subject)` | 在场能教的人、持有可读的书、已会时的练习 | 学习路由 |
| `speciesYields(species)` | 物种 `drops` 和 `wildlife.gather` | 宰杀与取材 |
| `valueOf(resource, qty)` | `goodsWorth`（valuation.mjs:41） | 日产出天花板、NPC 成本收益 |
| `dailyIncome(actor, skill)` | `wageQuote({baseHalfDay: 由 wageCopperPerHalfDay 按技能阶插值, proficiency})` | §6.7 期望值天花板 |
| `consentOf(party, actor, scope, terms)` | consent() → requestContractConsent → npcDecision | 对方同意与答复 |

### 2.3 裁决顺序（对 06 §6.5 第 3 步的落地，不改流程）

对每个效果：
1. 找族行。找不到时**不再**说"当前手段不能产生"，而是给出世界内原因：缺的是哪类手段、哪个族未登记。这是"规则卡"，进入学习回路（第八节）。
2. **物理和生理检查**，失败才拒绝：在场与可及、手段、负重、材质、身体状态、钱物余额、空间容量。
3. **权能**：有依据 → 正常进行；没有依据但物理可行 → 照样进行，按 K6 打标签（第五节）。
4. **对方**：只有效果的成立本身需要对方的原语时才问对方。例如对方当债务人、对方接受过户、对方当租客。这时走 `consentOf`，拿到真实答复（第六节）。对他人身体、精神、自由的作用则按 06 §6.5 走"无同意即对抗"。
5. **上限**：族行的 bounds，加上日产出天花板，加上"不比最近邻注册动作更划算"（action-limits.mjs:291–301，原样保留）。
6. 难度、检定、档位、归约：现有管线不变。

## 三、来源派生规律（逐族）

每族写清：由什么数据派生，不按意图或 ID 列名单；以及"谁要点头"和"真实限制是什么"。

### 3.1 持有族（holding.open / close / transfer / rescale）

| 项 | 规律 |
|---|---|
| 来源 | `authority(actor, op, subject)` 的依据。有 owns、operates、监护、委托或决议时正常进行。只有占有、没有权能时：transfer 按 06 §6.3 已写的 `unauthorized_disposition` 成立（action-authority.mjs:230 已实现）；open 和 close 同样处理。既无权也不占有时，按"东西不在你手上"拒绝，这是物理限制。 |
| 耗时 | `generic.transferMinutes`，加上持有种类声明的 `form`。form 是种类数据新字段：需要书面文书的种类（地契、租约）读文书规则的书写时间；口头即可的为 0。 |
| 难度和检定 | 无。持有族是确定性原语（06 §6.6 末行）。 |
| 上限 | 无数量。份额改写由 I8 保证总和为 1.0；互斥和容量走现有争夺池（primitives-runtime.mjs:77–90）。 |
| 谁要点头 | 由持有种类数据新字段 `acceptance` 决定，不按意图写： |
| | open：新持有人是他人时，持有人要接受。leases、lodges、resides 由租客或住客接受；employed_by 由受雇者接受。 |
| | transfer：新持有人要接受。受赠可以拒绝。 |
| | rescale：受影响的每个持有人要同意。现有 rescaleConsent 已实现（primitives-runtime.mjs:96）。 |
| | close：本人放弃不问别人；关闭他人在自己物上的持有（赶走租客）按条款，提前解约触发违约后果，不是拒绝。 |
| 真实限制 | 标的不存在；种类不可转让（`transferable`）；两端模板不匹配；法律类持有只能由案件或有权职位开立（例外见 3.4 束缚）。 |
| 例 | "把空屋借给表哥住一个月"：holding.open(lodges, holder=表哥, subject=屋, terms{until})。表哥经 npcDecision 答复。 |
| | "宣布棚屋不要了"：holding.close(owns, reason:abandoned)。标的变成无主物，后续按法域的无主物规定处理（04 §4.4）。 |
| | "一成股份让给伙计"：holding.rescale，读章程权能和其他股东同意。 |

改动点：
- action-limits.mjs:289 不再兜底。
- open-actions.mjs:200–203 的 rescale 权能预检并入族行。
- primitives.mjs:122–154 不变（它已经统一查权能）。
- 本族唯一的新增是 `acceptance` 读取。

### 3.2 义务族（obligation.create / settle / cancel）

| 项 | 规律 |
|---|---|
| 来源 | 债务人是本人 → self。债务人是他人 → 债务人同意（第六节）。另外三种来源已在 06 §6.3 写明：代理、判决、规则来源。 |
| 条款 | 义务种类数据（world/ontology/obligations.json）新增 `terms` 和 `limits` 两个字段。terms 是条款模式，例如 loan 的 principal、interest、days，service 的 task、location、minutes、window。limits 是条款范围，例如利率区间、期限上限。提案条款越界就裁剪。 |
| 耗时 | 议定耗时 = `generic.speechMinutes`，再乘以条款项数系数。需要文书的种类（契据）加书写时间。 |
| 履行 | 新增**履行适配器**，按种类数据 `performance` 选择一种，全种类共用： |
| | ① payment：铜钱转移 + 销账（现有）。 |
| | ② delivery：把指定资源或物品交到约定地点，交给债权人或其经营者 → 销账。 |
| | ③ presence：债务人在约定时窗内实际在约定地点待满约定分钟数。依据是身体活动记录与位置，由时钟按时窗结算。"看三天铺子"就是这一种。 |
| | ④ in-kind：以物抵债。按 `valueOf` 或议定额折抵，须债权人同意或判决（06 §6.3 已写）。用来解除 primitives-runtime.mjs:252 的拒绝。 |
| 上限 | 没有直接产出，所以不进日产出天花板。互换价值由对方的 npcDecision 把关，不需要引擎再设上限。 |
| 真实限制 | 两端须存活。双方要能沟通（06 §6.3）：对方不在场又没有书信或代理时，回答"对方不在场，无从答应"。 |
| 例 | "答应替邻居看三天铺子换一袋米"：一个提案里写两条义务，原子成立。 |
| | 第一条：obligation.create(service, debtor=玩家, creditor=邻居, terms{location:铺子, window, minutes}, performance:presence)。 |
| | 第二条：obligation.create(delivery, debtor=邻居, creditor=玩家, terms{resource:米, qty:1, after: 第一条履行}, performance:delivery)。 |
| | 邻居经 npcDecision 答复：成本是米的价值；收益是劳务日值乘以时长，加上满足的需要（第六节）。 |
| | 借贷：transfer(本人→对方, 本金) + obligation.create(loan, debtor=对方)。删除 open-actions.mjs:221 的一刀切拒绝；能路由到登记借贷动作时仍优先路由。 |
| | 雇佣：obligation.create(wage) + holding.open(employed_by)，双方各自点头。 |

### 3.3 毁坏与种群（destroy / transition + 种群个体化与宰杀）

**3.3.1 物件毁坏**

| 项 | 规律 |
|---|---|
| 来源 | 两样都要有：可及（随身，或在场 1.5 米内可视），以及与材质匹配的手段。 |
| | 手段从**材质表**派生，材质表是数据。把 action-limits.mjs:15 的常量迁成数据，每种材质有：`resistance`、每公斤工作分钟数、可用方法。方法例子：纸和布可以撕或烧；木头可以砍、烧或砸；陶器可以砸；石和金属要重器加长时间。 |

**3.3.2 种群个体化（解除 primitives-effects.mjs:145）**

新增**种群存量适配器**（卡 3）。它是唯一可以改 husbandry 行 count 的开放路径写入点，在**同一事务**内完成以下步骤：

1. 从种群账户 `population_<species>|<herd>|population` 转出 n 个到 `sink:individuated`（01 §1.6 个体化守恒对）。
2. husbandry 行 count −n。按确定性顺序从隔室里扣：先扣 S（健康），再扣 R（已愈），最后扣 I（患病）。扣到 I 的个体带上"患病"状态。这样 SIR 总数和 count 保持一致（husbandry.mjs:33–35 的分组疫病推进读的就是这些）。
3. 用物种模板创建 n 个 creature。id 取 `digest(eventId, i)`。位置在畜群所在建筑；owns 持有沿用畜群的持有人（同事务 holding.open(owns)）。
4. 审计：individuated 数等于本事务创建的生灵数（I1）。

反向是"放回群里"：creature 经 transition(gone, basis: aggregated)，再从 `src:aggregated` 流入种群账户。本批只做个体化；反向留作接口，验收时只测守恒对的形状。

**3.3.3 宰杀（自有活物，K7）**

宰杀就是"个体化（若是种群）+ 致死 vital"：
- **来源**：K7 处分权（第四节）。手段读物种的 `wildlife.gather.tool` 性状（刀具），以及身体。
- **耗时**：物种取材配方的 minutes，加上体重 ÷ 负重的系数。
- **检定**：生灵被控制时（被拴、在圈内、驯服）没有对抗，是确定性的；未被控制时走现有战斗交锋，但不给野外经验（S5FIX 保留的"驯兽不给野外经验"是对的，只是"不能杀"错了）。
- **死亡**：现有 `recordWildlifeDeath` 写尸体，产物只读 `drops`（wildlife.mjs:258–264）。取材沿用现有 gather（:305–317），取材产物经 `src:harvest`。
- 狩猎和宰杀**共用一张产物表**，不会出现宰杀特例。
- **数据缺口**：drops 里没有肉。本批按真实数据结算：宰羊得生皮一张，宰雉一无所得。这样做诚实，但不够真实。要从物种体量和组织份额派生尸体产出（属于 K4），见第十三节第 2 条。

### 3.6 §6.7 期望值天花板与日产出上限（累计方式）

现状：`openUsage` 恒返回 `produced:0`（action-limits.mjs:185）；只有治疗有 dailyKey（:272）。

规律：

1. **统一计量单位是价值（铜）**。每个有收益的族行声明 `reward`，用 `valueOf` 把实际应用量换算成价值：
   - 即兴粗制品：粗劣品的估值。
   - 修复或改良：fact.set 前后估值之差。
   - 治疗：按劳务日值折算，`dailyIncome` 乘以耗时。
   - learn 的 amount 仍走 learning 表自己的日上限，不换算。
2. **日上限**：`cap_day = dailyIncome(actor, 该族行用到的技能)`。没有技能时用 `wageCopperPerHalfDay` 下限 ×2。这与 15 §15.2 的雇工报价同一个式子，所以"自己做"和"受雇做"收益上限一致，不存在雇佣套利。
3. **累计**：沿用现有滚动窗口 `open_usage:<actor>`（两天，与回执同一事务写入，primitives-runtime.mjs:59–65）。
   - `openUsageEntry` 的 `produced` 改记 `{value: 实际价值}`，算在提交时刻所属的游戏日，`day = floor(minute/1440)`。
   - `openUsage` 返回当天的 `producedByKey.value`。
   - `limitOpenEffects` 对 reward 字段先按 `(cap_day − 当天已用)` 换回本效果的数量上限，再裁剪（action-limits.mjs:138 的现有 dailyKey 分支，dailyKey 统一为 `'value'`）。
   - 治疗原来的 `vital:heal` 键并入价值键。这是行为变化，测试要按新口径改。
4. **裁剪文案**："以你的手艺，一天做不出这么多"（06 §6.7 原话）。
5. **重复衰减**（24 小时同签名减半）和"不比最近邻更划算"不变，三者取最小。
6. 确定性：价值读取发生在归约时刻的状态，同一存档同一输入得到同一结果。

### 4.2 种群的毁坏、宰杀怎样结算

- 只能经第 3.3.2 节个体化，**不存在**"直接从种群账户扣头数到 sink:death 再给肉"的捷径。原因有三：
  1. 01 §1.6 规定 `src:harvest` 只能由 transition 事件触发。
  2. 疫病隔室要跟随个体。
  3. 尸体、取材、腐坏期限已经按个体实现。
- 资源账，同事务：
  - `population_X|herd` → `sink:individuated`（n）。
  - 创建 n 个 creature。
  - vital 致死 → transition(gone, death) → 尸体 `items = drops`。
  - 取材时 `src:harvest` → 行囊。
  - 消耗走 `sink:consume`（刀具耗水），刀具磨损（wildlife.mjs:313–315）。
- 畜群的日结（husbandry.mjs:27"家畜日结不连续"）不受影响：适配器只改 count 和隔室，不改 lastDay。按日推进与一次推进的等价性（I14）由适配器写在事务内来保证（第十节）。

  - 组织份额表（肉、皮、骨、脂占比）。
  - 用性状匹配物品（food+meat、hide、bone），不按 id。

## 五、合法性是后果（K6）

### 5.1 原语层统一规律

> **物理上可行就先发生，再由规范栈定效。** 社会许可（所有者授权、通缉文书、施法许可、私宅许可、设施使用许可）不是前提，而是**标签**。标签进入事件，由通用的"规范后果"订阅者求值，得出罪名、立场、传闻和记忆。

仍然是真实限制、照常拒绝的（与卡要求一致）：
- **物理**：在场与可及、视线、遮挡、距离、容量、材质与工作量、锁和机关（锁是物理，撬锁是物理工程）。
- **生理**：身体状态、失能、负重、灵力、体力。
- **空间**：路线、分区邻接、不可瞬移。
- **钱物**：余额（I2）、存量、守恒（不能凭空造物）。
- **对方同意**：效果本身就是对方的原语时（对方的债、对方的接受、对方的教学）。没有同意即不发生，06 §6.4 `onRefusal: abort` 的缺省。
- **制度的构成性行为**：任免、颁发许可、授爵、以组织名义签字、动用公账（AUDIT2 C-f，真实）。注意："无权仍硬做"（冒任、伪造许可、挪用）是成立加罪名，见模式 F。

另加一条**控制者在场规律**（新，通用）：标的的现任控制者在场且清醒时，控制本身就是物理阻碍。行为者只能二选一：
- 请求同意（走第六节，得到真实答复）；
- 对抗：潜入或抢夺按感知对抗，强行按力量对抗。对抗失败时对方察觉，后果走立场和罪名。

控制者不在场时，先发生再定效。这条规律把"许可"按世界现实拆成两半：主人在家时进不去是真实的，主人不在时溜进去则是罪。

   - 这是对 :230 已有范式的推广，不是新机制。

   - 对带 `unconsented`、`unauthorized_disposition`、`ultra_vires`、`offense?:*` 标签的原语子事件，按数据表求出罪名。

   - 例：`{op:'destroy', ownerRelation:'other', offense:'property_damage'}`、`{op:'move', targetClass:'place:private', offense:'trespass'}`、`{op:'holding.open', kind:'guest_of:detained', offense:'unlawful_detention', unless:'wantedInReach'}`。

   - **罚则**进法典模板（world/meta/rules.json `law.templates[*].penalties`），这是法律内容，要走审批管线（第十三节第 3 条）。

## 六、NPC 答复开放提案（同一条裁决管线）

### 6.1 什么时候问 NPC

只有效果成立本身需要对方的原语时才问。由族行的 `counterparty` 声明，不按意图写：
- 对方当债务人（obligation.create）。
- 对方成为新持有人或受影响的持有人（holding.open 的 holder、transfer 的 newHolder、rescale 的股东）。
- 对方转出（transfer from 对方，"换"的另一半）。
- 对方教学（learn 的来源是人）。
- 对他人身体、精神、自由的作用：不是"问"，是 06 §6.5 的"无同意即对抗"。

提案里同时出现的 `emit(request)` 不再只是"记一笔"（primitives.mjs:168–169），而是被当作这次询问的说法，进入 npcDecision 的修正项。劝说、威胁、贿赂、欺骗的检定结果作为修正（06 §6.7"社交不越权"）。

### 6.2 怎么答

在 `consentOf` 中，把 `requestContractConsent`（action-consent.mjs:66–89）推广为**开放提案的唯一答复入口**：

1. 先读现有真实同意事件，包括代理和授权。已经同意过的，不再问。
2. 不能沟通的（不在场、没有共同语言，conversationLanguage）→ "对方不在场或听不懂，无从答应"。这是真实限制。
3. `npcDecision(subjectiveView(对方), request)`，request 从提案**派生**：
   - `kind`：义务种类、持有种类或 `exchange`，用于匹配红线、规矩 `norm:<kind>`、身份冲突。
   - `cost`：对方付出的价值（`valueOf`）、时间（条款的分钟数和时窗）、风险（对方相信的法律风险，读自己知道的法典，5.7.1）。
   - `reward`：对方得到的价值，加上互惠的劳务按 `dailyIncome` 折算。
   - `needSatisfaction`：对方当前目标的 `need`，通过一张数据表"need → 资源性状或服务"匹配本提案给对方的东西。例如 need:food 对应 food 性状，need:money 对应铜钱；看铺子对应"对方日程中离开自己经营地点的时窗"，这个时窗由对方日程和经营持有派生。不按意图写。
   - `urgency`、`tags`：从提案的 manner 和社交检定结果来。
   - 立场、记忆：npcDecision 已经读关系、信任、违约记忆和恩惠（npc-decision.mjs:9–22），不需要新写。
   - 自治规则：对方已承诺的冲突时段（knownActiveObligations）和计划优先级（:27、:36）。
4. 五种结果映射到裁决：

| outcome | 裁决 | 事件 |
|---|---|---|
| agree | 写同意事件（凭据，可重放）→ 本提案原子成立 | consent_given；各原语事件 |
| conditional | **还价**：推广现有"先付 N 文"。若提案里有可分的量，按 `floor(量 × benefit/cost)` 缩减对方付出的一侧，或加大玩家付出的一侧；不可分时要求预付差额。还价条款写进事件 | counteroffer（verbs.json 已有） |
| refuse | 拒绝并给出 npcDecision 的世界内原因（"这与我已经答应的事冲突"）；提案不执行，玩家不付代价 | refuse（verbs.json 已有） |
| defer | "稍后再说"，带 due 时刻；可以预约再问（schedule open:question） | refuse + due |
| 社交大失败（06 §6.6 request 行） | 立场 −k，拒绝并记仇 | refuse + impress（impress 归 S6；本批只记标签） |

5. 玩家接受还价：重新提交带还价条款的提案。同意事件的 terms 与之完全一致（termsMatch，action-consent.mjs:47），一次成立，不再重新判断。
6. **确定性**：npcDecision 只读主观视图（I25）；答复写入 append-only 的同意事件，重放直接读事件，不再重算决策（I31）。

### 6.3 NPC 主动发起（本批不做，留接口）

`deriveOpenLimits(…, {actor})` 和族表从一开始就按 actor 泛型写（不出现 `'player'` 字面量；现有 action-limits.mjs:213–214 已经按 actor 取身体和行囊）。将来自治候选可以直接产出开放提案，走同一管线（05 §5.7.1），这样能消除 npc-autonomy.mjs:61、:176 的私有 kind。验收里加一条"actor=NPC 的预览得到同样的来源"，保证接口不被写死。

## 十、不变量、守恒、确定性、性能与风险

### 10.1 会撞上的不变量与测试

| 不变量 | 撞点 | 保法 |
|---|---|---|
| I1 守恒 | 种群个体化；毁坏的残骸分流；以物抵债 | 个体化守恒对同事务、计数相等（3.3.2）；残骸按 04 §4.2；抵债 = transfer 加 settle 同事务。守恒审计测试加"individuated = 新建生灵数" |
| I2 非负 | 以物抵债、交换 | 余额由 transfer 原语事务内校验，不变 |
| I6 转移完备 | 宰杀后的生灵 gone | transition(death) 现有路径，尸体承接 |
| I8 份额 | rescale、holding.transfer | 现有协议不变 |
| I14 离屏等价 | 畜群 count 在两次日结之间被个体化改变 | 适配器只在事务内改 count 和隔室，日结按当时的 count 闭式推进；加一条"个体化后逐日 vs 一次推进 N 天"的等价测试 |
| I16 事件主写 | 新的规范后果、个体化 | 都经原语子事件和 registerIncident 事件，不旁路写 |

另外受影响的测试文件：
- tests/a3-tool-surface.test.mjs（:7 名单；:16 预算须 ≤10593）。
- tests/action-registry.test.mjs（外壳分类守门）。

### 10.2 确定性

- 族表和派生函数是纯函数：输入只有当前文档加提案，没有时间、随机或外部状态。
- 检定沿用以 eventId 为键的骰子；对抗沿用 `${eventId}:action-check`（primitives-runtime.mjs:170），预览与提交一致。
- NPC 答复写同意事件，重放读事件，不重算。
- 种群扣减的隔室顺序固定（S→R→I），个体 id 由 digest 生成。
- 规范后果订阅者 `order` 固定（建议 15：在关系 20、立场 60 之前立案，使立场能读到案件），结果只依赖事件内容。

### 10.3 性能

- **裁决**：族表查找 O(1)（按 op 建索引）。派生函数都是对单个标的的读取，`authority()` 已有 recordsMemo。开放提案的成本与现在同阶。
- **可做之事卡**：每个目标的探测从"写死约 5–8 项"变成"适用族 × 手段"。约束如下：
  - 新族（持有、义务、毁坏、搬动、束缚）的来源**与手段无关**（读权能和身体），每族每目标只探测 1 次。
  - 只有毁坏、改物按工具性状去重后探测。
  - 预计每目标多约 5 次 sourceFor 调用。
  - 卡 1 验收：在本机性能基准上，world_actions(target) 的 p95 不劣化超过 10%。基准沿用 PERFT 的计时脚本；PFT2 跑完后再测，不与其并行。
- **规范后果订阅者**：每个事件按标签查表 O(标签数)；立案只在有罚则时发生。不扫描全表。
- **种群适配器**：只在宰杀和购买时运行，不进日结热路径。

### 10.4 风险（按影响排序）

1. **后果无代价**。放开后，偷、毁、擅入、拘人都会"成立"。但法典模板里还没有 property_damage、trespass、unlawful_detention、unauthorized_use、illegal_logging、poaching 的罚则，`registerIncident(optional:true)` 会不立案，只留标签。另外"当场制止"只覆盖"控制者在场"的情形，旁观的第三方不会出手。缓解：罚则数据作为卡 4 的同批内容，走审批管线；旁观者干预交 S6（05 §5.6 立场与反应）。在此之前要如实记为"后果只有立场与传闻"。
2. **种群与守恒**。个体化动到 husbandry 行、SIR 隔室和日结连续性，任何遗漏都会让守恒审计或日结抛错。屠宰产物的数据缺口会让"宰羊"在玩家眼里仍然不真实。缓解：适配器单点写入；守恒与离屏等价专项测试；尸体产出规律见第十三节第 2 条。
3. **断言翻转与按测试打补丁**。22 处固化断言、一批开放路径断言、corpus-001 的 27 条一起翻转，执行者容易为某条测试写特判。缓解：
   - 每条改断言都要注明族行或规律依据；
   - 主会话合并前读 diff，跑 overfit-guard；
   - 验收用封存的从未见过的意图（第十一节）。
4. **性能**：可做之事探测变多（10.3），用性能门约束。
5. **范围外的期待**：本批不做 NPC 主动用开放路径、impress（S6）、工具 ≤16（S8）、K1–K5 的生产与分销规律。"盐、柴、燕麦粥"这类问题本批**不会**改善（AUDIT3 0.2 最后一行）。

## 十二、与 Jev 接入的接口

Jev 判断"玩家原意超出现有动作"后，交给开放路径的提案形状。设计原则沿用 10-25 实测的结论（待用户确认.md:168–174）：
- **选项由引擎出，Jev 只做选择**。
- **幅度由引擎按能力算**。
- 没提到的参数由引擎补缺省，不让 Jev 编。

**引擎给 Jev 的选项**：来自同一张族表，加上当前场景。
- 目标候选：在场实体、随身物、所在地点。
- 每个目标适用的族行：可做之事卡的 primitives。
- 每族的手段候选：usableMeans。
- 每族需要的少量离散选择，例如 destroy 的方法、move 的去处分区、义务的种类。

**Jev 交回的提案**（就是 world_propose 的参数加一个来源说明）：

```json
{
  "intent": "玩家原话",
  "source": {"kind": "jev", "judgment": "beyond_catalog", "confidence": 0.93},
  "target": "<候选 id>",
  "family": "<族行 id，例如 obligation.exchange>",
  "effects": [
    {"op": "obligation.create", "obligationKind": "service", "debtor": "self", "creditor": "<候选 id>",
     "terms": {"location": "<候选 id>", "minutes": {"mentioned": true, "value": 4320}}},
    {"op": "obligation.create", "obligationKind": "delivery", "debtor": "<候选 id>", "creditor": "self",
     "terms": {"resource": "<候选 id>", "qty": {"mentioned": true, "value": 1}}}
  ],
  "means": {"item": "<候选 id 或空>", "skill": "<候选 id 或空>"},
  "manner": "polite",
  "unmentioned": ["window"]
}
```

规则：
- `effects` 里的所有 id 必须来自引擎给的候选。候选之外的 id 按 06 §6.10.5 返回候选，不猜。
- 数量和幅度只填玩家**提到的**值，并标 `mentioned:true`。没提到的放进 `unmentioned`，由引擎按族行缺省补。缺省读条款下限，或"可用上限 × 族行缺省比例"，比例是数据。
- **不得**自报难度、上限、同意、耗时（action-limits.mjs:20–24、:87 已经拒绝）。
- 引擎按第二节走裁决。若路由命中登记动作（τ≥0.7），改走登记动作；回执里带 `routed`，供 Jev 的错判统计使用。
- Jev 判"超出"，但族表找不到族 → 回执给"规则卡"原因，记入学习回路（8.3），**不**退到"近似普通动作"。这正对应 10-25 实测里 9/15 创意意图被高把握套进近似动作的问题。
- 不开模型时，构造器产出完全相同的形状（`source.kind = 'builder'`），两层共用一个入口（06 §6.2 第 4 条）。
