## 〇、一页摘要

**接入位置（一句话）**：Jev 是放在"玩家自由输入 → 引擎"之间的**可选理解前门**，服务端在发给模型之前先问它两件事——"这句话每一步是否都属于当前场景的某个动作大类（可答都不属于）"，属于就继续选具体登记动作与实体槽位，不属于就从通用门的效果族表里选对象、效果族、手段，由引擎组装成 `world_propose`；Jev 只回选项编号，不执行、不裁决、不写状态，玩家确认后走现有的预览/确认链路。

**数据流**：
1. 引擎从玩家视角生成选项（`worldActions()` 的场景目录 + 在场对象 + 效果族表），不含任何手写意图名单。
2. Jev 请求 1：两步各选动作大类，选项里带"都不属于"和"没有第二步"。任一步选"都不属于"＝**超出**。
3. 不超出 → Jev 请求 2：在大类里选具体动作，再对每个实体槽位从引擎候选里选（含"没提到"）；数量由引擎从原话取数。结果与现有 `constructIntent()` 返回形状相同（`action-constructor.mjs:84–89`），走 `/propose` 预览（`index.mjs:140`）。
4. 超出 → Jev 请求 2'：选目标、选效果族、选手段与离散参数，引擎按族行组装 effects，走 `world_propose`（开放路径）。族表里找不到 → 返回"规则卡"原因并留痕（`open:leave_mark`），**不退到近似普通动作**。
5. 无论哪条，玩家都先看到预览再确认；Jev 的原始答复存入本回合的旁路记录，重放不再请求 Jev。

**不开模型**：Jev 关闭、没密钥、断网、超时，一律回到今天的本地路径（`constructIntent` + 构造器 + 兜底留痕），不阻塞游戏；本方案新增一项"预填构造器"，补审查清单 0.3 第 10 条。本地路径的真实水平很低（冻结题集路由 41.6%、构造器 22.1%），如实写，不靠加关键词抬分。

**数字**：
- 10-25 实测（60 回合抽样，已被调参污染，只能当开发集）：创意识别 8/8（任一步选"都不属于"）；普通句误判为创意 2/49；第一步大类选对 38/49；具体动作 42/47 选出；已提到的实体参数 23/24 选对；每次请求 0.15–0.27 秒。**样本很小**：8/8 的 95% 下界只有 68%，2/49 的上界约 14%。
- 花费：Jev 每回合 2–3 次请求，实测约 0.0013 元（普通句），开放路径估 0.002–0.006 元（未测）；对照 DeepSeek 每回合 0.09–0.14 元（待用户确认.md:133、146），Jev 占 1%–5%。
- 静态提示：Jev 方案**静态区 +0**。主仓库现测 **10587**（31761 字节，我用 `loadPromptBundle()` 实测），距基线 10593 只剩 6；通用门卡 1 完成后估 10521。

**拆卡**：5 张实现卡 + 1 张题集小卡，约 **7.5–9.5 人日**，日历约 6–7 天。**必须在通用门 4 张卡和回归之后接入**（J1 起）；J0 只读依赖，可与通用门卡 2–4 并行。

**最大风险**：Jev 会把创意意图高把握地套进近似普通动作（10-25 的 A 模式 15 个创意回合只保住原意 6 个，置信度 0.98 也拦不住）。防线是"都不属于"选项 + 任一步触发 + 偏向判超出 + 玩家确认 + 开放路径兜底，但验证样本太小，必须用没见过的新题集测。

**需要用户定的事**（详见第八节）：①是否接受"每次都先预览再确认"；②玩家原话与场景名词发给 typesafe.ai 是否可以，发布后密钥归谁；③有 LLM 时 Jev 是前门还是不进；④验收阈值与评测额度；⑤通用门卡 1 是否现在就把族行的 `slots/compose` 写进设计。

## 一、Jev 是什么、10-25 测出了什么

### 1.1 它是什么

- typesafe.ai 的 `/v1/systemone` 接口，模型 `jev-1.14.0`；脚本发 JSON：`state`（局面文字）+ `questions`。题型用到三种：`choice`（单选，带各选项概率）、`noul`（是非概率）、`score`（有序打分，未用）。返回 `answers[题].choice/confidence/probabilities` 与 `usage.input_tokens`（logs/sessions/jev/ping.mjs:1–7、group-bench2.mjs:25–32）。
- 密钥在用户环境变量 `TYPESAFE_API_KEY`（待用户确认.md:160）。国内可直连，0.15–0.27 秒/次。
- 计价：脚本按 0.042 美元/百万**输入** token × 7.2 估（group-bench2.mjs:9 的 `RATE`），**输出 token 是否另计未核**（待人判）。
- "choice 最多 255 选项、noul 是非概率、每批 128 题"来自用户给的背景，**未独立测量**（logs/sessions/jev-audit.json 的 `spec_source`）。
- 仓库里目前**没有任何 Jev 接入代码**（grep server-plugin、extension、tools、prompt 无命中）；所有实验脚本只在 logs/sessions/jev/ 和 F:/dnd-tmp/jev/。

### 1.3 失败的类型（接入设计要对着它们防）

1. **高把握套近似**：创意句被选成最像的普通动作，置信度 0.98（"净化池水装罐卖"→取水）。置信度阈值拦不住，只有"都不属于"这个选项有效。
2. **只看第一步会漏**：创意往往在第二步（捧水＝环境类、许愿变灵药＝都不属于）。必须两步各问。
3. **多步取主次**：普通句的复合意图，Jev 与标注取的"第一步"不同，算错的 9 例里有 7 例。
4. **参数的错多数不是判断错**：该由引擎补默认值的被 Jev 编了；正确选项不在候选（远处地名）。所以"没提到"选项和"远处名称由引擎按名查"是必须的。
5. **数字槽位不能做选择题**：第一版评测脚本的缺陷之一。数量由引擎取，不问 Jev。
6. **标注口径不一致**：A 模式说 60 回合里 15 个创意，v1/v2 只标出 8 个（口径不同，待人判，不影响设计但影响怎么引用数字）。
7. **10-25 批准的是"是非题判超出"（待用户确认.md:168）**，实际有效的形态是"选大类 + 都不属于"。单独的是非题（noul，"创意门"花过 0.0092 元，待用户确认.md:171）没有保存下来的结果文件，**未测**。本方案用已测形态，是非题只作可选的第二信号，在开发集上校准后再决定用不用。

### 2.2 Jev 放在哪

Jev 是**第三个"翻译者"**，与"构造器（无模型）""LLM 翻译"并列，产出同一种东西——要么 `{action, slots}`（等价 `world_act`），要么 `world_propose` 的参数。06 §6.2 第 4 条"两层共用同一个入口"原样成立。

```
玩家自由输入 T
 │ 场外句（isOutOfCharacter, extension/prompt.mjs:37）→ 不判，原流程
 ▼
S0 引擎生成选项（本地，确定性，不含隐藏事实）
 │  A 动作大类与其下具体动作：worldActions() 场景目录（family/label/slots）
 │  B 在场/随身/所在地点候选：createRoutingContext()（action-router.mjs:184）
 │  C 效果族与手段：通用门族表（按目标类适用的族行 + usableMeans）
 ▼
S1 Jev 请求 1（一次 HTTP，多题）
 │  Q1 第一步属于哪个动作大类？（选项 = A 的大类 + 都不属于）
 │  Q2 第二步属于哪个动作大类？（选项 + 都不属于 + 没有第二步）
 │  [可选 Q3 noul：原意是否超出以上动作——开发集校准后再定用不用]
 ▼
 判定：任一步为"都不属于"→ 超出；否则 → 不超出
 ├──────────────── 不超出 ────────────────┐
 │                                          ▼
 │                           S2 Jev 请求 2：大类内选具体动作（含"其他"）
 │                              再对每个实体槽位选候选（含"没提到"）
 │                              数量由引擎从原话取（通用中文数词解析）
 │                              → {action, slots, missing}  ＝ constructIntent 的返回形状
 │                              → /propose 预览 → 玩家确认 → /execute (world_act)
 ▼
S3 超出：Jev 请求 2'
    选目标 → 选效果族（族表行，逐个效果一题，含"没有更多"）
    → 选手段（物品/技能/方式，含"没提到"）→ 选离散参数（去处、义务种类等）
    引擎按族行 compose 成 effects；未提到的参数放 unmentioned，由族行缺省补
    → world_propose（预览 → 玩家确认 → /execute）
    族表里找不到合适的族 → "规则卡"原因 + 留痕兜底，记入学习回路，不退到近似动作
```

### 2.3 与三个入口的接口

| 入口 | Jev 与它的关系 | 改动 |
|---|---|---|
| `world_actions`（`/actions`，tools.mjs:43） | Jev 的选项来源，**只读复用**其输出（场景目录、槽位 options、`family`）。LLM 路径不变 | 无。通用门完成后，族行适用性也从这里出（通用门 §2.1 三处消费之一） |
| `world_act`（tools.mjs:44、139–141） | 不超出时 Jev 产出 `{action, slots}`，经 `builderToolCall()` 走与界面动作完全相同的预览/确认/执行（runtime.js:255–293）。**Jev 不直接执行** | 无 |
| `world_propose`（开放路径） | 超出时 Jev 产出 `{intent, target, effects, means, context}`，必须通过 `primitive-schema.mjs:57` 的校验；`effects` 由引擎按族行 compose，**Jev 不写 effects 字段** | 通用门卡 1 把 `world_propose` 升为静态工具后，参数形状不变 |
| 新增：服务端 `/intent/interpret` | 只给扩展用的 HTTP 端点，**不是模型工具**，不进静态区 | J2 新增 |

### 2.4 与通用门设计稿 §12 的差异（需要主会话认可）

通用门设计稿第十二节（任务卡写作"第十节"，实际是第十二节）给的提案例子把 `source/family/unmentioned/confidence` 放在提案里。但提案 schema 是封闭的（primitive-schema.mjs:57），加这些键要改 schema，而且"引擎不接受自报"的方向相反。本方案改为：**提案保持原样，来源说明放在提案之外的"解析信封"里**：

```json
{
  "judgment": {"model": "jev-1.14.0", "beyond": true, "steps": [{"group": "none_of_these"}], "requestIds": ["..."], "ms": 410},
  "candidates": [
    {"kind": "registered", "action": "core:...", "slots": {}, "missing": []},
    {"kind": "open", "proposal": {"intent": "玩家原话", "target": "<候选 id>", "effects": [], "means": {}},
     "familyRows": ["<族行 id>"], "unmentioned": ["window"]}
  ],
  "fallback": "mark" ,
  "reason": "世界内原因（规则卡/缺哪类手段）"
}
```

- 信封存入回合旁路记录（`preview.judgment`，见 3.3），不进事件、不进提案。
- 其余规则沿用通用门 §12：id 必须来自候选；候选之外的 id 返回候选、不猜；数量只填玩家提到的；不得自报难度、上限、同意、耗时；若路由命中登记动作（τ≥0.7）改走登记动作，回执带 `routed`。
- 通用门 §2.1 的族行目前只有 `ops/means`，**没有 `slots`（离散选择）和 `compose`（选择→effects）字段**。这两个字段是 Jev 开放分支的前置，同时也是无模型构造器第 1–4 步（做什么/对谁/用什么/怎么做，06 §6.9.1）本来就需要的，见第七节 J1 和第八节待定 5。

## 三、不开模型时怎么办

### 3.1 原则

产品原则一.3："不开 LLM 也能完整游玩全部玩法"。所以 Jev 是**增强件，不是依赖件**：任何时候缺失，游戏完整可玩，只是"自由输入"退回今天的本地水平。

### 3.2 降级矩阵

| 状态 | 自由输入怎么处理 | 说明 |
|---|---|---|
| 有 Jev、有 LLM | Jev 前门（第 2.2 节）；玩家确认后执行；LLM 只做叙述与审查 | 有 LLM 时是否也走前门，待用户定（第八节 3） |
| 有 Jev、无 LLM | 同上；叙述走本地模板（06 §6.9.4） | 这是 Jev 价值最大的状态 |
| 无 Jev（无密钥/断网/超时/熔断）、有 LLM | 今天的流程不变（模型自己 `world_actions` → `world_act`/`world_propose`） | 无需改动 |
| 无 Jev、无 LLM | 本地路径：`constructIntent` 候选 → "你是想……？"按钮；无候选 → **预填的构造器** + 留痕兜底选项 | 本方案补"预填" |

### 3.3 本地路径的真实水平与新增一项

- 水平：冻结题集 a3-score-v5b（231 题）路由 61.5%、构造器 22.1%（docs/A3-交付物与试玩方案.md:30）；S5 前后复跑 route 41.1%→41.6%，差距来自 A3 收口加的如实检查（docs/A3-后续阶段登记.md:131）。**本方案不承诺抬高这两个数。**抬高本地分数的办法只有往 `constructIntent` 里加词表，而那正是红线禁止的"按意图写名单"。
- 审查清单 0.3 第 10 条（关闭理解时只回一句场外话、没有本地匹配与预填构造器）：06 §6.10.7 第 2 点要求"本地目录匹配给出建议；匹配不到时打开**预填了文本线索**的构造器，并始终附带兜底选项"。现状：候选按钮有（runtime.js:525–541），**预填没有**（"打开可做之事，继续构造"只切面板）；`intent=off` 且叙述关时直接抛错（runtime.js:106）。J3 补：把 `constructIntent` 已解析出的目标/候选槽位预填进构造器，并让 `off` 档的自由输入进入本地路径而不是抛场外话。预填内容全部来自 `constructIntent` 已有的返回值（`candidates[].slots`、`missing`、提到的实体），不新增匹配规则。
- 审查清单 0.3 第 9 条（无模型对话只对掷魅力，不看说的内容）：**不在本方案范围**。Jev 盘点里"劝说内容"（jev-audit J05，V5/D4）是下一个消费者，需要 NPC 决策侧先有"有限、可解释的决策修正规则"（logs/sessions/jev-audit.final.md 第 5 条）；本方案只保证接口通用（第 3.4 节），不承诺做。
- 失败不阻塞：Jev 请求 3 秒超时、HTTP 错误、返回结构不合法、连续 3 次失败熔断 60 秒，一律当"无 Jev"处理，界面只显示一行"理解服务不可用，已用本地匹配"。判决不写世界，所以失败也不影响存档与重放。

### 3.4 其余边界

- **开关不是世界状态**：`openActions` 存在存档里（engine.mjs:305–308；ui-settings.mjs:53 说明"此设置由存档决定"），切换会写 patches。Jev 开关是客户端偏好（和 `intent`、`narration` 一样放 `ui-settings`），新增独立的 `judge: off|jev`，不借用 `intent` 的三档语义（那三档描述的是 LLM 的角色）。
- **知情边界**：选项只用玩家**已知或在场可感知**的名称与物品（`createRoutingContext` 的 presence/known 过滤），不含隐藏事实、不含其他 NPC 的私密信息（jev-audit：私密过滤在发题前完成）。
- **重放**：Jev 的原始答复（请求哈希、模型版本、各题 choice/confidence、毫秒数）存入回合旁路记录；只有玩家确认后的 `world_act`/`world_propose` 才成为事件。同一存档同一事件序列重放，**不会再请求 Jev**。模型版本钉死 `jev-1.14.0`，升级版本视为换基线、重测。
- **不在锁内发请求**：`beginConsistencyTurn` 在 `store.exclusive` 里（consistency-service.mjs:62）。Jev 请求在锁外由 `/intent/interpret` 完成，结果作为参数交给 `review/begin`，服务端**重新校验**所有 id 后才写入 `preview`，不信任客户端回传。

## 五、登记动作口径（用户已定）与"不准按意图列名单"

用户口径（docs/当前状态.md:58；通用门 §8.1）：**注册动作只作开放路径已能执行的组合的加速模板**。Jev 的"选动作"必须服从这条，具体写成可检查的约束：

1. **选项由数据生成，代码里不出现意图、动作 id、实体 id 的字面量。**登记动作选项来自 `worldActions()` 的 `family/label`（数据在 world/actions/*.json），效果族选项来自族表，目标选项来自场景。提升识别率的办法是改数据里的标签与例子（走内容审批），**不是**改 Jev 代码或加分支。
2. **题面模板固定且通用**：只有 4 个模板（大类题、动作题、槽位题、开放组合题），变量位置只填引擎给的标签。"都不属于"的说明文字是唯一的固定语义文本，一次定稿，不按失败样本改。
3. **不为个别失败样本改题面、调阈值、加例外。**调参只能在开发集上做，且改动记录要说明它覆盖的是哪一类（红线）。
4. **本地 `completeCommand` 的词表（action-constructor.mjs:27–40）只留作降级路径**，不得被复用来做 Jev 的"预筛选"或"兜底纠正"。
5. **"能用开放路径执行的，不为 Jev 补登记动作"**：Jev 的误判代价靠开放路径的能力兜住，而不是靠补登记动作。派卡时，任何"为了让 Jev 选对而新增一条登记动作"的 diff 直接判不合格（AGENTS.md:21）。
6. **度量口径**：Jev 的质量看"原意是否保住、世界效果是否等价"，不是"选中了哪条登记动作"。普通句被判成超出、由开放路径等价执行，不算错（只是少了模板数值）；创意句被判成普通动作且玩家没能看出，算最严重的错。
7. **序列识别不再新增形状写死**：open-actions.mjs:44–58 目前按效果形状识别序列，属于红线要治的写法。Jev 的两步结果走"步＝动作+槽位"或"步＝效果集合"的通用步列表（J2 扩 `executeOpenSequence` 支持步内 effects），**不新增新的形状分支**。

### 6.2 新题集 N 的规则

- 由一个**不读代码、不看 Jev 题面、不看 10-25 结果文件**的 Sonnet 子代理编写，只给 06 §6.3 和 §6.11 的写法要求，加当前场景的玩家视角名词表。

- 构成：≥30% 创意（语料规则）；其中至少 20 条是"长得像普通动作的创意"（只有后半句或第二步超出）；至少 20 条复合/条件/否定/指代句；其余覆盖交易、移动、对话、制作、学习、法律、经营等各玩法；每条标注期望处理（registered/open/fallback/infeasible）、期望大类或效果族、必须保住的原意要点。
- 场景名词表从真实开局世界取，不为题目补世界内容（产品原则三.2）。

### 6.3 判据

**机制判据（必须 100%，确定性，不依赖 Jev 答对）**——用桩替换 fetch 即可测：
1. Jev 返回的任何 id 若不在引擎候选里，100% 被拒，返回候选，不被采纳。
2. Jev 回执里不会出现 consent、难度、上限、耗时、tags（schema 与 open-actions.mjs:124、:157 已拒，补测）。
3. 没提到的参数一律由引擎缺省补，Jev 不能写数量。
4. 判决只存旁路记录；同一存档同一事件序列重放，Jev 请求次数为 0，事件逐字节一致。
5. Jev 关闭/超时/报错时，自由输入结果与未接入前逐字节一致（回归）；冻结体检集的本地路由 41.6%、构造器 22.1% 不下降。
6. 任何题的最终结果只有三种：可确认的预览、世界内原因 + 降级做法、留痕兜底。"不支持"率 0。

**质量判据（统计，在 N 上测，给区间；阈值待用户定，第八节 4）**，我的建议：
1. 创意句"被静默套进近似普通动作"率 ≤5%（点估计，同时报 Wilson 95% 区间）。这是最重要的一条。
2. 普通句被判成超出的比例 ≤10%，并且其中 ≥90% 经开放路径或路由 τ≥0.7 仍得到等价效果。
3. 已提到的实体槽位选对 ≥90%。
4. 复合句：两步都识别并保序的比例，只报告不设阈值（首次测）。
5. 平均延迟、每回合花费如实报。

**不得以分数为目标**：未达标就写未达标；不为过阈值去改题面（产品原则三.1）。

## 八、风险与需要用户定的事

### 8.1 风险（按影响排序）

1. **创意被静默套进近似动作。**10-25 已出现 9/15。防线是"都不属于"选项、两步各问、偏向判超出、预览确认、开放路径兜底。但 v2 只有 8 个创意样本，8/8 的 95% 下界仅 68%；第一步单看只有 4/8。真实水平只能靠新题集 N 才知道。
2. **验收被污染。**冻结体检集和 10-25 的 60 回合都参与过 A3 修订或调参，不能当验收。N 只能用一次；据结果改题面则作废重编。
3. **依赖通用门。**通用门不先落地，"超出"分支多数仍是留痕（Q6）；通用门族行没有 `slots/compose`，J1 要补，与通用门卡 1 的文件所有权有交叠，只能串行在其后。
4. **选项过多。**场景目录和物品可能超过 255 个选项；必须分组分轮问，不截尾。远处地名不在候选里已出现 7 次，由引擎按名查，但名称解析本身是一个未测环节。
5. **数量取数。**数量由引擎从原话取，需要一个通用的中文数词解析（"三文钱""两份""半个时辰"）；做得不好会出错，做得针对性太强又成为红线问题。J2 用通用解析，并在 N 上单独报数量正确率。
6. **三方依赖与隐私。**玩家原话与场景名词发给 typesafe.ai；服务可用性、价格、模型版本漂移（钉死 jev-1.14.0，升级＝换基线）。
7. **确认的摩擦。**每次先预览再确认，复杂玩法会让节奏变慢。
8. **序列识别沿用了形状写死。**open-actions.mjs:44–58 已经是红线要治的写法，J2 不新增、也不负责清除；是否另立卡清除待主会话定。
9. **两个理解者打架。**有 LLM 时若 Jev 前门与模型工具选择并存，可能各选各的；方案只做"Jev 前门，模型只叙述"一条路，避免并存。
10. **静态提示余量。**通用门卡 1 前只剩 6。

## 主会话审定（11-04）

方案主干采纳：Jev 作为可选的理解前门，任一步选"都不属于"就判为超出，交给开放路径；它只回答选项编号，不执行、不裁决；判决存进旁路记录，重放时不再请求 Jev；关闭或失败时退回本地路径。
- **⑤ 槽位与组装字段**：采纳。通用门族表每一行要补 slots（槽位：类型、候选来源、缺省由引擎补）和 compose（由选项组装成 effects 的规则）两个字段，由通用门卡 1 一并实现，族表数据和 Jev 共用同一份。
- **⑥ 用"选大类 + 都不属于"**，不用"是非题判超出"。两者的目标相同，都是判断意图是否超出现有动作；10-25 的实测数据支持前者。这是实现方式的选择，主会话定。
- **⑦ 新题集**：由不读代码的 Sonnet 子代理编写，只用一次；判分器冻结。采纳。
- **③ 有 LLM 时**：第一版 Jev 不进前门，只在没有 LLM 或 LLM 关闭时使用。采纳。
- **① 预览与确认**：开放路径的提案一律先预览、再确认，这是 06 章两阶段的规定；登记动作沿用现有行为。主会话定。
- **提案外的解析信封**：source、family、unmentioned 放在提案外的信封里，不改封闭的提案 schema（primitive-schema.mjs:57）。采纳，通用门第十二节按此修订。
- **②、④ 需要用户定**，已登记在 docs/待用户确认.md：
  - ② 玩家原话和场景名词发给第三方 typesafe.ai 是否可以，发布后密钥归谁；
  - ④ 评测额度：离线评测约 1–2 元，已批的 2 元余约 1.76 元；真实试玩另行报价。
