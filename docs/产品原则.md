# 《无限原野》产品原则（北极星）

（2026-10-22 主会话据用户历次决定与设计文档汇总；用户为产品经理，看效果与对后续迭代的影响。每张卡、每次审查、每个新会话先读本文。冲突时以本文为准，细则见 docs/架构设计/。）

## 一、我们要做的世界

1. **世界上最自由的文字 RPG。** 玩家想到的事，只要世界规则允许，就能做；做不到时世界给出合理反应，不是“不支持”。
2. **一个真实运转的中西合璧修仙世界。** 九省 31 郡全规模，人和精怪有自己的需要、作息、记忆与关系，玩家不在场时世界照样演化；规模不为省事而缩减。
3. **规则引擎是唯一真相。** LLM 只是可选的理解层与叙述层：只能提议，不能越过引擎写状态；叙述在结算之后，不能改变结算。不开 LLM 也能完整游玩全部玩法。
4. **后果真实、可追溯。** 钱物守恒，因果有来源事件；法律、立场、传闻、记忆会连锁；行为“先发生、后定效”。
5. **日常与传奇同等重要。** 吃、住、做工、交易、学艺、打听，和斗法、治国一样真实，按时间与工时结算。

## 二、设计原则

1. **派生优先。** 价格、工时、难度、权限、前提、身份都从世界状态推出；不写死，不按 ID 或场景特判。
2. **自由度优先。** 不用关键词、固定名单或预写动作清单给玩家封顶；按物品属性、结构化提案与效果原语推导可行性。
3. **尊重想象力。** 拒绝要给世界内原因与降级做法；任何创意至少能留下带标签的痕迹并引起系统反应。
4. **真实不粉饰。** 不伪造前提、成功、同意或权利；不知道的就是不知道（传闻与真相分离）。
5. **阶乘玩法。** 新内容写数据，玩法包靠共享词汇相乘，而不是为每个场景写代码。
6. **难度来自世界本身。** 不按玩家等级缩放敌人；成长靠真实练习与机会，边际递减，不靠刷与守点。

## 三、开发纪律（这次 A3 的教训）

1. **验收以设计与试玩为准，不以分数为目标。** 题集只做体检；合理率类指标用从未用于修订的新题测（标杆标准 §0 第 5 条）。分数下降说实话，不为保分写特判。
2. **不为测试造东西。** 测试前提用真实游戏动作产生（setup.prelude）；不加只给测试用的接口、加载器分支或世界内容；不为个别题目补世界。
3. **最小完整改动，删除优先。** 先问“它需要存在吗”；能复用就不新写；不加没人要的抽象、配置与“以后用”。
4. **竖切片推进。** 先把几条核心玩法从引擎到界面到叙述做通并真实试玩，再扩展；阶段边界硬，后续阶段的事直接登记。
5. **主会话是设计者，不是转发器。** 每次合并前读 diff，对照本文与设计清单审；子代理的结论与自设框架只是参考，用原则判断；跑背题检查（tests/overfit-guard）。
6. **三层分工。** Opus 5.5 中档 / Sonnet 5.5 中档 / DeepSeek（deepseek-flash）；默认 Sonnet 统筹、DeepSeek 写代码，内核、加载器、跨卷、改裁定、同一处错两次的交 Opus；真实模型调用如实记账。
