## 13.1 边界：收录标准与宗教尊重（用户最终规则）

**收录标准**（用户 2026-10-15 夜，覆盖此前说法）：
1. **有出处才收**：每个生灵、神职、事件母题必须对应神话或志怪原典中实际存在的记载。数据形状：`sources: [{work, section}]` 必填；加载期校验非空（E-SOURCE）；现代工具书只能用于回查，不能作为 `sources`。不编造，也不"改编"出原典没有的东西。
2. **尽量多收，但不为丰富而丰富**：原典里有、不冒犯的都收；机制无实质差异者合并为一条，各文化叫法记为别名（§13.9）。
3. **只排除可能冒犯的**：当今仍有连续传承信众的宗教中被崇拜的神、圣人、先知、圣物，以及社群明确反对外用的存在，一律不收、不改编、不作原型。已无连续传承信众、有史料可考的古代神灵（以下称"现实古神"）可以收录，但只许存在于宗教与朝拜系统之内，对玩家的互动有硬上限（见 §13.1A）。排除只记名称与理由，不设"改编路径"。
4. **泛称的地方神职与自然精灵照收**：土地、城隍、山神、河伯、灶神、门神、树精泉精山灵、各文化的家宅精灵与地方守护精灵——按**职位**（§13.8）或**精灵类型**（§13.3）收录，不描绘某一位具体受供奉的神。

**宗教尊重**（用户最终规则，写成规则与校验；2026-11-10 第四次修正，见修订记录）：
- 游戏内神灵分三类，且只有这三类：
  1. **原创神**（`kind:"original"`）：世界原有的十二位原创神，可一神多面（§13.8）、可有神迹、可有受限的直接显现；
  2. **现实古神**（`kind:"historical"`，`realWorldFigure:true`）：现实中存在过、有铭文、文献、祭坛或简牍可考的古代神灵，只存在于宗教与朝拜系统，互动上限 `interactionCap ∈ {talk, gift}`（§13.1A）；
  3. **泛称职位神**（`kind:"divine_office"`）：城隍、土地、灶神位、山神、河伯、井主等，按职位建模，持有人是亡者或精灵，可更替、可受贿、可错判，可与玩家完整互动。
- **排除名单** `blocklist.json`（L1 数据，可随引擎版本扩充）分三档：`folk_office`（允许，按职位或地点建模）；`ancient_attested`（现实古神白名单，只收 `kind:"historical"` 且带出处与上限的条目）；`orthodox_worship`（当今仍有传承信众的宗教之正统崇拜对象，一律排除）。条目含名称、别名、理由、来源传统。
- **加载期校验**（12 §12.4.1 P8 新增 E-SENSITIVE、E-DEITY-CAP）：生灵、神职、仪式、物品、地点、组织的名称与 `aliases` 命中 `orthodox_worship` 的拒载；名称命中 `ancient_attested` 的只允许出现在 `kind:"historical"` 的神灵条目与其圣所、节日、信仰记录中，出现在其他任何类型的条目（生灵、法术、物品名、职位）一律拒载。诊断给出命中项与理由；不提供"改名绕过"的建议。每条生灵数据带 `sensitivity: {reviewed: bool, note}`，未审核（`reviewed: false`）的条目只能在作者本机加载（`--allow-unreviewed`），不能进入发布包。
- **不作负面对象**：任何古神、任何真实宗教的神圣存在都不得被写成反派、怪物、可戏弄或可被击败的对象；世界内不出现"某真实宗教的神其实是我们的某神"之类断言；现实古神也不并入原创神的"面"。
- **不嘲弄或歪曲真实仪式与教义**：仪式名、咒文、经文、祷词全部原创；真实宗教（含古神）的仪式与经名不得注册为可施放的动作或法术（E-SENSITIVE 的仪式名检查）。古神的祭祀只用于叙述与场所，不进可施放的法术表。审核 L1/L2 增"宗教敏感"检查项（12 §12.7.2）。
- 第三方包同样适用（P8 对包数据同一校验）。

**§13.1A 现实古神的互动硬上限**

现实古神（`realWorldFigure:true`）对玩家与世界的互动最多是**对话**与**赐物**，上限由字段 `interactionCap` 取值 `talk` 或 `gift` 写在数据里：
- `talk`：托梦、神谕、祈祷应答、被询问时回答，只产出文字与已有的事实标记；
- `gift`：`talk` 加上从该神有限的赐物池转出一件物品，不给状态加成、不给能力。

不得：显现、召请、契约、驱使、附身、封印、诅咒、化身、借形，不得成为式神、图腾神、坐骑、伙伴、役灵或任何被持有、被绑定的对象，不得有神迹预算与直接显现，不得是任何原创神的"面"，不得有生灵模板。信徒向神职场所的供奉、布施、朝圣、入教、改宗不属于互动，一律允许。

上限按**动词类**（`worship / talk / gift / manifest / invoke / contract / command / familiar / totem / avatar / possess`）写成数据表，在持有写入、法术效果登记、原语校验、动作翻译、信仰行动这几个汇总点统一拦截，**默认拒绝**；城隍、土地等职位神不是现实信仰对象，不受此上限约束，以 `kind` 区分，不按名单特判。
- **中国民俗冥府的放宽**（用户授权主会话决定，待用户确认.md 末条）：中国部分的阴间采用传统民俗冥府结构——十殿、判官、鬼差、牛头马面、黑白无常、孟婆、奈何桥、城隍、土地等作为**职位或地点**建模（§13.7、§13.8），持有人是亡者或精灵，可更替、可受贿、可错判；轮回（投胎、孟婆汤、阳寿簿）作为世界内的冥府规则，不讲教义。**底线**：佛陀、菩萨、道教三清等正统崇拜对象不作游戏角色、不出现为实体或面；不嘲弄宗教本身。排除名单据此分两档：`folk_office`（中国民俗冥府与地方神职，允许，按职位/地点建模）与 `orthodox_worship`（正统崇拜对象，排除）；其他文化圈维持"可能冒犯即不收"，不设放宽档。

**传说与真相分离**（Q9，方案 C）：每条生灵或母题在**事实层**写真实性状（真实弱点、真实能力），在**知情层**写"人们相信什么"（传说弱点、功效、来历，作为书本与传闻条目）。世界参数 `legend.truthRatio`（按地区、文化可不同，默认约一半）只约束内容配比，不进入任何规则；具体每条由数据的 `truth` 字段决定。玩家依传说用错克制物时按真实弱点结算，并留下"传说不灵"的知情。

## 13.2 文化圈：标签层级 + 文化数据记录（Q2，方案 D）

- **文化圈是词汇层级**：`culture:*` 词带上位链（例 `culture:ms_taideng` → `sphere:beastfolk` → `sphere:*`），走 12 §12.3.3 的词汇闸门。每个具体文化是一条**文化数据记录**（lore 数据），其 id 同时是一个词（加载校验两者同步）。
- **文化记录存什么**：称谓与语域、**语言**（母语 `lang:*` 与常见第二语言，成员的语言技能由此开立初值，附录 A §A.15；该文化的文书与账簿缺省以母语写成，`language` 事实由此派生缺省值）、**单位表** `units`（斤 / 两 / 锭等显示单位与对规范单位的换算，按视角显示，15 §15.3；法典 `recognition.units` 可覆盖）、葬俗（安葬期限、葬仪族、是否转生）、**家户归属 `descent: patrilineal | matrilineal | bilateral | household_of(father | mother)`**（新生儿入哪一户，出生反应规则读它，法典民事③可覆盖，附录 A §A.7）、祭祖周期、阈限时间窗（夜半、节日、月相）、仪式集与各仪式的本地名、辟邪物与克制物、生灵先验（"不知道时以为什么"）、职业变体（§13.6）、文化亲和表（对其他文化圈的亲和系数，缺省按上位链距离派生）、禁忌（成员层规范条目）。
- **谁有文化**：地点有文化事实（可被包以 `place.culture` 槽位覆盖，附录 A §A.9）；组织与人有文化事实（作者数据）；物种有**原型文化**不可变事实（来自原典）；个体生灵的**当前归属**派生：原型文化 ⊕ 栖地文化 ⊕ 供奉者文化（按供奉流量加权，修正项）。被北境人供奉多年的游魂会逐渐"认"北境的仪式。
- **文化不是实体**：它不行动、不持有、不欠债；文化之间的冲突由组织与人承担。

## 13.3 生灵类型学：六条轴，标签层级（Q2 原则）

存储层只有 `creature`（个体）与 `population`（种群）；类型学是六条正交的标签轴，每个词都有上位词（附录 A §A.11）：

| 轴 | 族 | 系统用途 |
|---|---|---|
| 本源 | `super:dead`（下分 shade / revenant / ancestor / hungry / wrathful / bound_place）、`super:spirit`（place / nature / object / house / element）、`super:cultivated` 修成者、`super:beast` 异兽、`super:divine`（servant / demigod / local_office 神职）、`super:fiend`、`super:fae`、`super:construct`、`super:hybrid` | 克制与仪式按上位链回退匹配；一条只认 `super:dead` 的规则对新包的 `dead:xyz` 自动生效 |
| 形态 `form:*` | corporeal / incorporeal / possessing / vessel / shifting / mist | vital 能否命中、move 能否穿墙过门、感知能否看见、附身前提 |
| 依附 `anchor:*` | place / object / body / person / name / time | 出现位置；封印与驱离的对象；"移走尸骨即平息" |
| 驱力 `drive:*` | hunger / grievance / duty / attachment / desire / mischief / territory / cultivation / reciprocity | NPC 决策的需求输入（05 §5.7）；谈判筹码；满足条件 |
| 能力 `power:*` | possess / curse / glamour / shift / invisible / dreamsend / bless / plague / bind / foresee | 生灵可发起动作的前置 |
| 规矩 `bound:*` | threshold / running_water / counting / truthful_name / sunlight / iron / reciprocal / noise | 生灵自身的规范条目（成员层形状，来源 = 物种或文化），动作前置读取 |

**处境**（wandering / enshrined / sealed / commanded / contracted / rested / reborn / married）**只派生不存**：由持有（enshrined_in、seals、commands、kin:spouse）、义务（pact）与状态算出；数据文件出现这类字段即校验失败（I10）。

**物种数据**（普通动物、家畜、超自然生灵**同一 schema**——普通物种在 `ecology/species.json`，超自然在 `supernatural/beings.json`，差别只在 `origin` 与是否必须有出处；一方包与第三方同形；core 生态规则读全部已装包的物种数据，相互作用不再是 core 一张表）：

```
{id, names: {默认名, aliases: {文化: 名}}, sources: [{work, section}]（origin 为 super:* 时必填）,
 origin: "beast:*" | "livestock:*" | "super:…", form, anchors, drives, powers, bounds, culture (原型文化),
 lifecycle: {lifespan, maturity, gestation（孕期，可按季节修正）, awaken, shift, afterDeath, restCondition},
 heritable: [{attr, rule: RX(sire, dam, roll)}]（可遗传属性：繁殖 create(creature) 的 facts 由此算出）,
 goods: [goods:*]（活体与产物的商品类：通行费、关税、报价按它）,
 yields: {death: 死亡产物表（材料、尸身）, alive: [{resource, perHeadPerDay: RX（季节、饲草充足度）, mode: passive | action}]（活体产物经 `src:husbandry`，01 §1.6；旧写法的裸列表视为 death）}, maintenance: 维系存量的资源种类（饲草 / 灵力 / 香火 / 怨气；具名个体按它进食，附录 A §A.15 身体需求量）, labor?: {factor, hoursPerDay}（役畜、傀儡计入 `laborHours`，05 §5.1）,
 interactions: [{with: 物种 id 或标签, kind: predation | competition | mutualism, k, season}]（各物种自带，core 时钟读全部物种的行）,
 inheritance: false（缺省：个体死亡不建遗产、不生监护、不进继承表；具名精怪可设 true）,
 habitat, niche, intelligence, taming,
 truth: {weaknesses: [{to: "ward:*|bane:*", effect, magnitude, when}], immune: [tag], uniqueHook: "…"},
 legend: {weaknesses, abilities, origin_story}（知情层）,
 sensitivity: {reviewed, note}, archetype: 原型族 id, distinctFrom: [...]}
```

- **物种与具名个体两层**（YG-1 难点 3）：物种是模板；具名个体是 `creature` 实体（事实 `species`），可带自己的真名、驱力、冤债与历史。"两可"条目拆成物种 + 一个具名个体。普通动物与家畜同此：野兔是种群账户，被命名的猎犬、种马是 creature 个体（估值 `value` 读物种报价、品相与谱牒）。
- **年久成精**（YG-1 难点 1）：器物与建筑的年岁由创建事件或作者 `madeAt/foundedYear` 派生；时钟规则按 `lifecycle.awaken` 的闭式风险函数（年岁、人气 = 相关事件密度、灵脉、节奏槽）决定 create(creature, origin: spirit:object, anchor: 该物)；宅院里的扫帚、灯、镜由此成精，不需要野外栖地。
- **死亡产物**：`yields` 是物种数据；死亡时协议创建残骸实体（04 §4.2），反应规则按表从 `src:harvest` 流入其账户（皮、鳞、胆、骨），采集是从残骸账户的转移（源的写入权见 01 §1.6）。
- **灵智与同意**：灵智派生"能否同意、能否订约"；精神类状态对灵智生灵同样要同意或抵抗（§13.4 第 1 行）。

## 13.4 互动方式 → 已有概念（Q10 方案 c）

| 互动 | 形状 |
|---|---|
| 附身 | 持有 `possesses`（生灵 → 人或尸身 wreck，标的侧 exclusive；条款 `consensual`）；状态 `possessed`（精神状态族，读同意：附录 A §A.15——**生灵来源的无同意施加照常走对抗检定并带 `unconsented` 标签，但不构成人间罪名**（世界的危险源，法典谓词按来源跳过）；人借生灵对人施加算人对人：同样裁决，罪名由规范栈判定，强迫与改记忆是重罪）；**附身期间的行为归属**（附录 A §A.15）：宿主 `capacity` 为 none，身体所做的一切 actor = 附身生灵、`actorAs` = 宿主身份键（在场者认出的是宿主；罪名 principal 命中生灵，宿主只在 `consensual` 时为 accomplice；core 豁免 `involuntary_act` 使宿主免责，贿银等真实落入宿主账户的按民事⑨不当得利追缴；驱魂时宿主无法同意，由监护人或法典紧急条款给同意）；他人见症状 → 推断规则在"病 / 祟 / 装"间按观察者文化与知识给候选（误诊是玩法）；宿主死 → 持有关闭，生灵转为游荡；驱离仪式 = holding.close |
| 诅咒 | 状态 `cursed{liftWhen: 谓词, source}`：条件达成自动解除；可继承的诅咒 = 持有 `cursed_by`（受诅者 → 诅咒来源，持有人侧 gone 为 `succeed` 按继承表；放弃继承能否摆脱由民事②数据定；来源消失不自动解咒）；施咒多数法典有罪名（`offense:maleficium`，上位 `offense:harm`）；反咒、转嫁是仪式 |
| 迷惑与幻形 | `purports` 扩展到生灵与人（自称的样子）；感知派生在条件下（镜、犬、符、晨光）给出真形；状态 `glamoured`；识破 = 检定动作 |
| 契约 | 义务 `pact`（双向两条，带 `counterpart`；条款可含延期代价 `deferredPrice`：头生子、寿数、魂魄）；`onDebtorGone: pursue`（追到亡魂 / 转生者）；人间法典可判无效但生灵一方的规范仍认（规范栈冲突法给出结果并可解释）；契文是文书（records），可藏条款、可复核 |
| 婚配 | `kin:spouse` 两端模板放宽到 creature；条款 `taboo`（不许窥看原形、不提出身）；违犯 → 反应规则关闭婚配、生灵离开、子女留下（`super:hybrid`）；冥婚 = 一端是亡魂实体（§13.7） |
| 报恩 | 义务 `gratitude`：救命、放生、葬骨事件经反应规则自动创建（债务人 = 生灵，债权人 = 恩人）；清偿方式由驱力与能力派生；`onCreditorGone: heirs` |
| 冤屈与索命 | 义务 `grievance`：冤死、不葬、毁巢、背约创建（债权人 = 亡魂或生灵，债务人 = 加害者；是否继承到子孙按文化数据）；清偿 = 伸冤（定罪判决视为清偿）、赔礼、供奉、迁葬；长期不清偿 → 索命（vital / status 原语，自治候选）；加害者不知道自己被记了债，只有托梦、占卜、调查才进入其主观视图 |
| 作祟与安抚 | 依附于地点的生灵按驱力与存量周期产出原语（怪声 → impress，病 → status，器物损坏 → fact.set）；安抚 = 供奉 transfer 进生灵账户或立祠 create(building) + 持有 `enshrined_in`；作祟强度读槽 `super:hauntPressure`（香火、怨气、阈限时间） |
| 驯服与驱使 | 动物 `tamed_by`；灵智生灵的役使 = 持有 `commands`（主人 → 生灵；条款：供养义务、命令范围、期限、解约）；役使亡魂在多数法典与戒律中命中罪名或破戒（`offense:necromancy`）；召唤师可订约对象扩展到一切 `super:*` |
| 镇压与封印 | 持有 `seals`（封印物或地点 → 生灵）；封印强度是账户（衰减时钟，槽 `super:sealDecay`）；维护 = `upkeep` 义务（补符），可欠可违约；封印物被毁（标的 gone 的持有人侧）→ 持有关闭 → 事件 `released`；擅自揭封是罪 |
| 超度、安息、转生 | 亡魂 `transition(gone, basis: rested | reborn)`（附录 A §A.4）；条件来自仪式与驱力满足（冤已伸、骨已葬、愿已了）；转生按文化数据可选，生成新个体带 `rebirthOf` 不可变事实；义务按 `onDebtorGone: pursue` / `onCreditorGone` 分流，不留悬空端 |
| 献祭与供奉 | transfer 到 `sink:offering`，同一事务内等量从 `src:offering_realm` 流入生灵、神祇或阴间账户（守恒对，审计要求两者逐资源相等）；活物献祭：动物可；**以人献祭只能作为反派、历史与传闻出现，不注册为玩家可执行并获益的动作**（内容规则 + 合法性标注） |
| 交感媒介 | 事实 `trueName`（生灵与人皆可有讳名）；物品事实 `sympathyLink → 实体`（毛发、生辰帖、画像，创建或取得时由事件记录）；诅咒、寻踪、命令、驱离、订约的前置或难度读 `knows(actor, trueName(x))` 与链接；烧毁媒介 = 切断 |
| 禁忌 | 规范条目（来源 = 生灵、神祇或文化，适用于个人，随誓约 / 婚配 / 恩惠而来）；违犯 → 生灵一方的反应，不需要人间立案 |
| 门槛与边界 | 分区事实 `threshold`；`bound:threshold` 的生灵未经邀请不能 move 进入；邀请 = 持有 `invited`（东道 → 生灵，可撤回）；符、门神、盐线是 mark 或 item，在分区边界上产生进入难度修正项 |
| 阈限时间 | 文化记录的日历窗口（夜半、节日、月相、生辰），`window(id)` 派生；槽 `super:activity`（活跃度）与 `super:efficacy` 读它 |
| 托梦、神谕、占卜 | tell 通道 dream / oracle / omen（附录 A §A.8），可靠度派生；占卜 = 动作，输出只能是带置信度的知情或 belief（I26） |
| 召请与降临 | create（召唤物）或 move（从异界）+ upkeep；请神须神同意（神祇走 NPC 决策与神迹预算，§13.8） |
| 变形 | 个体事实 `form`（当前形）由 fact.set 改；人形与兽形是两个**身份键**（附录 A §A.15）：观察者按认出的键记忆与评价，揭穿 = `identity_linked` 事件进入其知情后合并；化名、易容、冒名同一机制 |
| 偷换与拐走 | `purports` 替换 + move 到异界地点；家人的推断规则可误判 |
| 异界之旅与出神 | 异界是地点（§13.7）；出神 = 状态 `trance`（失能类）+ 魂的位置事实另行移动；身体受伤影响魂；义务照常到期 |
| 疫病与灾异归因 | 超自然来源作为 `health:infectionRate` 等槽的修正项；民众把疫病推断为"闹鬼 / 被巫害"→ 舆论、猎巫、误伤无辜（推断规则 + 自治候选） |

每种互动都有"人对它的认识"与"它的真相"两层；每种都至少有一种不靠战斗的解法（交涉、仪式、满足需求、查明真相），推演测试在不用 vital 的条件下各解一例（SX-1 验收 39）。

## 13.5 仪式动作形状、克制表、效力派生（Q1 C+D、Q3 B、Q4 C+D）

**仪式**是动作（06 §6.4）加 `rite` 块：

```
"rite": {"family": "rite:funeral",
         "culture": "culture:river" | "any",
         "officiant": "RX 主祭资格谓词（职位 / 职业阶 / 受戒受箓 / 神的认可，读持有）",
         "roles": [{"role": "mourner", "min": 1, "filter": "kin(target)"}],
         "stages": [{"id": "prepare", "minutes": 120, "materials": [{"resource": "goods:incense", "qty": 3}], "window": "night" }, …],
         "target": "RX 对象谓词（生灵标签 / 死者）",
         "interrupt": {"status": "rite_unfinished", "effects": [...]},
         "costs": {"materials": "transfer → sink:consume", "vow": "obligation.create(vow)", "discipline": "标签", "backlash": "06 §6.6 反噬表 rite 行"}}
```

- 多阶段仪式在开始时创建 `project` 实体（临时法人）承载阶段与到期项；单阶段仪式直接结算。中断留下"未处理区"状态与数据声明的后果，可被敌人利用。
- **诊断先行**：对象谓词读行为者的**主观视图**（他以为的是祟）；真实对象由事实层决定——诊断错误时仪式无效或伤及无辜（数据）。
- 同一仪式可由不同职业主持；葬仪由祭司、僧侣、道士或殓葬师主持，效果按资格与文化修正。

**克制与辟邪**（双边标签 + 派生）：物件与仪式带 `ward:*` / `bane:*` 标签；物种事实带 `truth.weaknesses: [{to, effect, magnitude, when}]` 与 `immune`。首领现有的 `weaknesses` 迁为同一形状。新增一种带 `ward:dead` 的植物时，所有既有亡魂自动受影响。

**效力派生**（槽 `super:efficacy`，可解释）：

```
efficacy(手段, 生灵) = 标签匹配基值（手段的目标标签与生灵本源链的最近公共上位词距离，越近越强；immune → 0）
                     × 类别系数：物理与规矩类（铁、火、盐、门槛、日光）不分文化 ×1
                                 意义类（经文、神名、符、葬仪）读生灵的当前归属：认这种仪式 ×1，
                                 否则按文化亲和表（同圈 1，近圈、异圈递减，数据）
                     × 阈限时间窗 × 主祭资格 × 供品品质 × 修正项
```

道士的符对北欧式亡灵：`ward:dead` 命中 `super:dead` 基值有效；意义类按亲和表打折；物种若声明 `immune: [rite:talisman]` 则为 0。界面能列出每一项来源。

## 13.6 职业呼应

- **职业 = 认证资格职位 + 被动派生表**（03 §3.5）不变。**文化变体派生**：称呼、材料、仪式名、神名由"职业持有 × 师承 / 所属组织的文化"派生，不新增职业 id；更换师承后变体随之改变（SX-1 验收 33）。
- 仪式的主祭资格读持有：同一仪式族对应多个职业的资格谓词；"谁能做"由数据决定，不写死在职业里。
- 需求文档建议的新职业（出神者、卜者、殓葬师）与新隐藏职业（降神者、除祟、跨界安魂、真名守持）是**内容**：形状上只是新的认证资格职位、被动表、仪式资格与事迹计数（隐藏职业契机读事件计数）。设计只保证：出神是失能状态 + 魂的位置；卜者的输出只能是知情；殓葬师的能力是让死者"按文化得到安葬"（§13.7 的主闸门）。
- 元素召唤师的可订约对象扩展到一切灵智足够的 `super:*`；役使亡魂的合法性由规范栈派生。
- 生活职业承担物件：护符配方（炼金、首饰、雕刻、画师、抄写员）带 `author` 与 `authority`（受箓 / 开光派生）；伪符 = `purports` 同真符而无效，用后产生"伪符流通"的推断与传闻。

## 13.7 亡者与阴间（Q5 B、Q7 D）

**死后**：`transition(gone, death)` 完成后，文化记录的葬俗给出期限 N；反应规则按死因、未了之事（未清偿的 grievance 债权、强立场）、是否得到葬仪派生去向：
- 得到按其文化的葬仪（仪式族 funeral）→ `afterlife = rested`，无实体；
- 期限内未安葬、或有 `grievance` 债权、或死因属文化数据的"不当死亡" → **未安息**：
  - 无名者：当地 `pop:unrested_dead` 子账户 +1（来源事件 = 该次死亡，身份链接保存在事件里；物化时按种子从当地死亡记录抽取身份）；
  - 有冤、被注意、被命名者：物化为 `creature` 实体（origin `super:dead`，不可变事实 `soulOf` 指向原实体）。**亡魂是新实体**，不碰转移协议：它对旧宅的主张是 `claim`，不是 owns。
- 亡魂继承截至死亡时刻的知情集合（可指认凶手；证据效力由法典定）与立场；驱力由死因与未了之事派生。
- **祖灵**：受祭的亡者（`dead:ancestor`）以家户的祭祖义务（`upkeep` 周期转移）维系；断祀 N 周期后转为饥渴亡魂（时钟规则），作祟压力上升，恢复祭祀可回落。
- **回煞、找替身、借尸还魂、冥婚**（YG-1 母题）都是自治候选、仪式或持有：回煞 = 死后第 N 日的时钟到期项产出一次 `omen/haunt`；找替身 = 缚地亡魂的候选动作（需求 grievance/duty）；借尸还魂 = `possesses` 的标的为尸身 wreck（01 §1.3 标的模板含 wreck）：尸身随生灵行动，事件 actor = 生灵、actorAs = 死者身份键，旁人以为死者复活——与真正的 `restored`（04 §4.5.1）的区别只在真相层，推断规则与鉴定分辨它；冥婚 = `kin:spouse` 一端为亡魂。

**阴间（分级物化）**：
- 一棵异界地点子树 `loc_netherworld`（各文化的冥土是其下的地点），由冥府政体 `org:polity` governs，法典 = 阴律（罪名：擅离、越界索命、冥吏受贿、错勾魂魄；程序：申冤案件、阳寿簿核对、还阳；认可：纸钱）。**中国冥土**按民俗冥府结构（§13.1 放宽档）：十殿是地点与各殿的主判职位，判官、鬼差、牛头马面、黑白无常、孟婆是**职位**（持有人是亡者或精灵，holds_office，继任与任免走 04 §4.6，可受贿、可错判、可被罢免），奈何桥、望乡台是地点，阳寿簿是文书物品（records 可错、可改——"错勾魂魄"是簿吏的过失事件，"还阳"是案件撤销 + `restored` 回转）；轮回是冥府规则（投胎 = `reborn`，孟婆汤 = 转生者知情集合清空的规则，阳寿 = 死亡时钟规则读簿册事实）。**其他文化的冥土**名称与职位全部原创（§13.1：可能冒犯即不收）。佛陀、菩萨、三清等正统崇拜对象在任何冥土都不出现。
- 缺省只有纲要（统计层）：亡者去向由派生给出，不物化；玩家、剧情或钉住义务触及时按 07 §7.3 骨架物化局部（一个冥土郡与路线），沿用三层模拟。
- 路线边 `passage` 是开放的 RX 条件（01 §1.5）：core 预置条件词 `passage:death`（亡者）、`passage:rite`（仪式门户）、`passage:trance`（出神者的魂）、`passage:dream`（托梦），包可组合时间窗（`window('midnight')`）、`invited` 持有或引路物；鬼市一类阈限集市既可用入口边的 `passage` 条件，也可用商贩日程的阈限时间窗（05 §5.8）表达。归途禁忌（回头、食异界食物）是规范条目。
- **申冤**：亡魂向冥府报案 = 阴律法域的案件（被告是阳间人）；执行经鬼差的托梦（tell 通道 dream）、索命（vital，受阴律幅度与"冤债额"限制）或经阳间法院协查（allied_with 条款可声明阴阳协查）。
- **烧纸钱**：§13.4 献祭的守恒对；冥府账户是普通账户。
- **转生**：文化数据 `rebirth: true/false`；`reborn` 创建新个体带 `rebirthOf`；`onDebtorGone: pursue` 让"轮回还债"成立。

## 13.8 神祇与神职（Q6 B）

- **神祇**（世界原创的，`divine:deity`）是**不在场的 agent 实体**：没有位置（或位于异界地点），有香火与神力账户（只由供奉流入），只能经注册的**神迹动作**行事，每次从账户扣减，幅度上限由账户与职责派生，必须留下可追查的事件与资源损失。复活类神迹是声明 `produces: restored` 的动作（04 §4.5.1 通则：不回滚世界，已卖的铺子不回来，只给复生者一条返还债权；在不承认 `recognition.resurrection` 的法域，复生者与原实体的身份链接无效——被当作新人或亡魂附体）。**硬规则**：神祇不能成为 vital、commands、seals 的标的，不可被击杀、驱使、封印（加载期 + 事务期双重校验，E-SCHEMA / 事务拒绝）。
- **一神多面**（仅限世界原创神祇）：面是神实体的作者事实 `aspects: [{id, culture, 名号, 形象, 职能侧重, 祭仪, 禁忌, 圣物}]`（Q13 方案 a）；寺观与信众的 `devotee_of` 条款记面 id；两座不同文化的寺观向同一个神力账户供奉，神迹预算不因面多而翻倍；"是否同一神"的争论只在知情层（信念、立场、寺观竞争）。新面受每文化圈面数上限约束；新神祇必须声明为何不能作已有神的一个面。
- **地方神职是职位**：土地、城隍、山神、河伯、灶神、门神、社神等泛称神职 = `office` 实体（种类 `divine_office`，所属 = 神祇的教团、冥府或当地治理组织，由文化数据定），持有人是**亡者或精灵**（holds_office），任命、罢免、继任、俸禄（香火分成）全部复用 05 §5.3；职责是规范条目（山神统辖、河伯取水的规矩）。被长期供奉的怨灵可以从 wandering → enshrined → 取得地方神职，整个过程只经事件、持有与任命。
- **神使、半神、传说级存在**是在场的 agent，可交涉，按自己的规矩行事，受 §13.9 的配额。
- **信奉**是持有 `devotee_of`（人 / 生灵 → 教团组织），改宗 = 新开持有触发 `incompatibleWith{kind: devotee_of, policy: auto_vacate}`（教团章程可声明宽容多信，则不互斥）；出家为僧道是 `member_of`（成员）另加 `devotee_of`。改宗因此是持有变更，不是事实改变（04 §4.1 已删"入教"）。

## 13.9 防重复："宁合不拆"与配额（用户决定）

**原则**：目标是让每个存在有分量，不是增加数量。元素×关系、特征向量只用于判断两条内容是否真的不同，**禁止为填格子而造怪**；机制无实质差异即合并，各文化说法成为别名与地方传说；称呼按观察者文化派生；分立的门槛是机制差异，不是外形、颜色、出处差异。

**机制签名**（自动计算，不手填）= 条目用到的 {互动方式、持有种类、义务种类、克制与免疫、生命周期转换、规矩、能力} 的集合。**特征向量**（辅助）= {元素×关系（产生 / 吞食 / 畏惧 / 操控 / 由其所生 / 被其所缚 / 化为 / 依附于）、生态位（食性、栖地、时段、体量、群居）、互动主次、弱点、生命周期、社会性、母题、驱力}。**独有钩子**：每条保留的条目在同原型族、同地区内至少有一条独有机制或行为（`truth.uniqueHook`，作者工具能列出，覆盖率 100%）。

**原型族** `archetype`（词汇上位词，与本源轴相容）：合并的单位、跨文化规则匹配的单位、配额的单位。族内分立的条目写 `distinctFrom`。

**合并规则**：同原型族、同地区，机制签名 Jaccard ≥ 阈 或 特征距离 < δ 或无独有钩子 → 退回，附"并入 X 作为 Y 文化的别名"；合并后只有一个 id，`names.aliases[文化]` 给名字（Q12 a），各文化的传说各成一条知情层文书（Q12 b，可互相矛盾）。相似度算法：签名 Jaccard 为门槛、特征距离作预警、盲判作抽检（Q11 d）。

**配额与"尽量多收"的协调**：配额约束的是**同时存在的活动实体**，不是收录条目。
- 任何有出处、不冒犯、有独有钩子的条目都收进妖怪志 / 万灵志（知识层）并成为物种模板；配额不删条目。
- **活动实体配额**（数据参数表 `quotas.json`，由加载校验执行，设计不依赖数值）：神祇实体全局上限（默认值见待用户确认）；每文化圈面数上限；传说级存在总量按文化圈份额 × 九省分摊，每省密度上限；每地区每原型族的活动条目上限。超额时报错并列出可合并或移往他省的候选——**只针对无差异的堆叠**：候选按"独有钩子强度最低、签名最相似"排序，有出处且机制独特的条目排在最后，不会被挤掉；实在超额的条目保留为**稀有或传说状态**（只在书本与传闻中、或遇见概率极低），不删。
- **生态位竞争排斥**（Q15 c）：创作期同地区同生态位（栖地 × 食性 × 时段重合 ≥ 阈）只容一个稳定物种，否则退回"合并或换地区"；运行期部分重叠的物种经 05 §5.5 的竞争表互相挤压（系数由重合度派生），结果是世界事件与传闻。首领级个体的生态位含领地：两个首领不能同时 controls 同一领地而不冲突。
- **现有内容回溯**（Q16）：对现有怪物与首领跑同一检查，产出合并候选清单交用户确认（默认只合并机制完全相同者），不自动合并。
- 第三方包同受签名、钩子、配额、神祇上限检查（P10，E-CONFLICT-DUPLICATE / E-QUOTA），错误指出冲突的已有条目。

**可区分度指标**：标杆标准 B17.5–B17.7（盲测区分率、合并率、独有钩子覆盖率）。
