## 4.1 六种触发

| 触发 | 范围 | 例子 | 协议步骤 |
|---|---|---|---|
| gone 消失 | 实体整体 | 起因 `basis`（附录 A §A.4）：death 死亡、dissolution 组织解散、destruction 建筑毁灭/物品销毁/船沉/资源点湮灭、extinction 种群灭绝、declared 宣告死亡判决（§4.5.1）、insolvency 破产清算判决（05 §5.2.7，组织）、rested / reborn 亡魂安息与转生（13 §13.7）、pack_removed 包卸载（第12章 §12.5.4：不是死亡，不进 sink:death、不产生尸体与哀悼） | 全流程 §4.2 |
| vacated 让出 | 某一个持有 | 免职、辞职、退会、退租、放弃职业、剥夺爵位、解雇、改宗（旧 devotee_of 被 auto_vacate）、章程解任触发（§4.6） | 只走被指名持有的交接 + 发布 |
| moved 位置改变 | 位置事实 | 迁居、逃亡、玩家远行、**在途（含被风雪洪水困在路上）**、流放（banished）、出神 | 不交接（各持有按 handover.moved，多为 stay）；关闭"在场"，改法域派生；**义务照常按日程到期** |
| defected 叛离 | 成员资格持有（可连带职位与封地） | 带封地投敌、长老出走 | 会籍关闭 + 封地按表 + 追随者分流 |
| altered 改变 | 实体事实 | 村升镇、受封、转职、认证、成年、变形 | 零交接；派生值自动变；只触发"确保应有职位"等反应与不相容校验（01 §1.3 incompatibleWith）。**改宗与入教不在此列**：它们是持有变更（devotee_of / member_of），R3-E6① |
| impaired 失能 | 临时状态标记 | 昏迷、拘留、封存、重病、出神、被附身（**不含在途**） | 零交接；行为能力与同意能力派生为假；日程占用与职能暂停（由代理规则承接）；**义务照常到期**；解除即恢复 |

**宽限统一规则**（I29）：任何触发都不自动暂停义务。远行、被困、被拘留、昏迷、包隔离模式时，到期、罚息、违约计数照常进行；能让它们延后或停止的只有两处数据：①规范栈的民事条款 `grace`（例如王国法"天灾阻断道路期间，到期日顺延阻断天数，罚息不计"、"羁押期间停止计息"；条款写明适用的义务种类、触发谓词——读道路封闭持有、天气事件、拘留状态——与效果），②合同条款里约定的宽限。违约规则读 L1 查询 `grace(obligation, now)`，违约事件记录宽限依据。这样"死当日期与玩家在不在场无关"（R2-E1①）与"有宽限条款才生效"（R2-E1⑥）同时成立，也不会出现"出门就冻结全部债务"的漏洞。

## 4.2 统一流程（gone 的完整版）

协议分两段：**事务段**（冻结、承接、交接、分流，一个事务内完成并断言）与**程序段**（承接实体的阶段到期项，可被世界观察、可争议；B-S7）。

```
transition(entity, kind=gone, basis, causes)
 事务段（一个事务）
 1 冻结      标记 transitioning；日程与行为能力派生即刻为假；此后对该实体的提案引用解析到承接实体（14 §14.3）
 2 承接实体  death/declared/rested/reborn（agent）→ create(estate)；dissolution/insolvency（org）→ create(liquidation)；
             destruction/extinction（物、建筑、资源点、种群）→ create(wreck 残骸)：
               账户的可毁部分 transfer → sink:destroy，可回收部分 transfer → 残骸账户（按模板 salvage 表），
               yields 表的材料由反应规则从 src:harvest 流入残骸；位置指向该实体的内容物 reparent 到残骸或所在地点；
               残骸是 thing 实体，可被 owns、可被捡拾，无人认领时按法域规定；职位空缺不需新实体
 3 分批交接  按交接类固定顺序（见 §4.3）：权能 → 照护 → 在途 → 经营与用工 → 财产与债 → 成员与居所；
             以消失实体为**载体**的 delivery/forward 义务立即进入货损条款（shortfall / 违约），不等到期
 4 义务分流  对消失者为债务人的每个义务，取 onDebtorGone（法典条款可覆盖种类缺省，附录 A §A.4）：
               accelerate             → 列入清偿阶段
               assume_by_heirs        → 不清偿，标记"随继承转移"，连同其 pledged 持有挂在遗产上
               substitute_performance → 不清偿，标记"转给承受相应财产的继承人履行，或由遗产代为履行"
               void                   → 终止，按条款结算已付对价（退还或折算）
               pursue                 → 转给该实体的亡魂或转生实体（13 §13.7），无则 void
             对消失者为债权人的义务，取 onCreditorGone（缺省 estate：债权入遗产；heirs：直接给继承人）
 5 发布与断言 一个父事件 transition + 每步子事件（起因链指向父事件）；见证由感知派生（01 §1.5）；显著度按持有分量；
             冻结后断言 I6/I7/I8；失败整体回滚；承接实体登记第一个阶段到期项
 程序段（承接实体的阶段到期项，期限是法典程序数据，可为 0 = 简易程序；每阶段产生事件、可被见证与争议）
 6 公告 notice     承接实体公告（公开事件，进传闻与公共知情）；期间债权人可申报
 7 申报 filing     债权人申报（动作，读自己的主观视图——不知道死讯的远方债权人可能错过；法典可规定逾期申报的后果）；
                  诈害行为与偏颇清偿的撤销请求也在此阶段提出（§4.4）
 8 清偿 settlement 按 §4.4 的清偿顺序清偿"已到期 + 加速"部分；同序按比例；不足记 bad_debt；永不对死者立违约案；
                  不在场债权人的款项进其义务的托管账户（15 §15.1.1）
 9 分配 distribution 按适用法继承表把净资产（资产 − 随继承转移的义务余额）转给继承人；同时把
                  assume_by_heirs 与 substitute_performance 的义务按份额转给继承人：债务端换人、日程不变、
                  质押随行，条款快照写入 liabilityCap = 该继承人所继承财产的估值（限定继承，法典可改为无限）；
                  继承人可在法典规定期限内放弃继承（动作）→ 其份额对应的义务改为 accelerate 并回到第 8 步；
                  争议 → create(case) 并 frozen；未成年份额由监护人代管、代为履约；无继承人 → 法域规定（封存/归公），
                  此时随继承转移的义务改为 accelerate；清算实体按份额分净资产给 share 持有人
 10 关闭 closed    关闭后断言（I6）：承接实体名下无未分流义务、无未分配净资产、无未结案件；残骸可长期存在
```

**为什么是这个顺序**：权能必须先于一切（否则死者的职权还能在后续步骤里被使用）；照护先于财产（被监护人不能等遗产程序走完）；财产与债先入承接实体，再分流：不加速的长期义务不必为了"关闭遗产"而提前清偿，也不会让遗产永远挂起——它们在分配步随财产一起转给继承人（R2-E3③ 分期贷款按期续还、逾期才动质押；R2-N1④ 青苗契由承受田地的继承人交粮）；成员与居所最后（组织的反应——补缺、追随、分裂——需要知道前面的结果）。程序段让大机构倒闭不再是"一刻之间机械清偿"（R3-E1③）：公告与申报进入传闻，债权人按自己知道的消息行动。

**承接实体何时关闭**：所有已到期与加速部分清偿或记坏账、净资产分配完毕、所有随继承义务已换债务人、无争议案件。

## 4.4 承接实体（遗产、清算、残骸）的规则

- 遗产与清算是临时法人：可持有财产、可作雇主、可欠可被欠、可被起诉（民事：分产争议、诈害撤销），但不能被判违约（违约规则读债务人状态：estate → 转为 bad_debt 或清偿顺序）。残骸是物。
- 适用法由派生决定（冲突法表，法律包数据）：不动产与股份按财产所在地法，动产按婚姻缔结地法，其余按死者户籍地法；没有任何一方可以选法（R1-E10①）。PR-02 延后部分的 estateLaw 思路与此一致，吸收之。
- **清偿顺序**（唯一定义处；民事①）：(a) 质押物先归担保债权人受偿（物上优先，不进一般财产；不足部分列无担保）；(b) 一般财产按法典顺序，core 缺省为：丧葬与清算费用 → 工资 → 税 → 无担保债权；同序按比例。同一债务人同刻多债不足时也用这一顺序（14 §14.3）。
- **撤销**（民事①⑨）：消失或破产裁定前 N 天内（法典数据）无对价或明显低价的转移（诈害行为）、对个别债权人的全额清偿（偏颇清偿），由承接实体以返还义务（compensation，债务人 = 受益人）追回，纳入清偿；善意有偿取得者不追（民事⑨）。
- **同时死亡**（民事②）：同刻死亡者互为继承人时按 `simultaneousDeath` 条款，core 缺省 `presume_none`（互不继承），14 §14.4。
- `onDebtorGone` 的覆盖（例如"借贷随继承""债务一律加速"）、限定继承与否、放弃继承期限、各阶段期限（含简易程序阈值），都是法典民事与程序条款（各政体可不同）。
- 分配按继承表（family-law.json 已有九政体雏形）；未成年继承人的份额由监护人代管（custody 条款：不得转让、收益入被监护人账户，侵吞可诉），随份额转来的义务由监护人代为履行。
- 承接实体在 §4.2 所列条件满足后关闭；有争议时保持到案件结案，分红入案件托管账户，解冻后补付。
- 无继承人：按法域规定封存或归公（官府封存：雇佣由官府承接，店铺暂停；归公：转入公库）。
- 残骸：可回收账户按 salvage 表；位置在原地点；可被 owns（原所有权 `stay` 在残骸上）；无人认领超过期限按法域规定（归公或湮灭 → sink:destroy）。

## 4.5 其他触发的差异

- **vacated**：只走被指名持有的交接 + 发布。权限因持有关闭而即刻消失（R1-E03④）；任命留任（R1-E03⑤，因为任命的授予者是职位）；免职不撤既有的、在权限内成立的委托（T124 决定保留：委托是义务，不是持有）；**超出权限或章程声明需追认的行为效力待定**（05 §5.3，R3-E6⑤）。
- **defected**：会籍 close（发 defect 事件）；若持有职位则 vacate；封地 retain_disputed → create(claim)，直到主权职位持有人用动作撤销（revert）或战争/外交裁决（R1-E14③④）；追随者：反应规则对每个与叛离者有 member_of/employed_by/kin 的个体比较 standing(个体, 叛离者) 与 standing(个体, 原组织)，差值超过阈值者发 defect（R1-E14⑤、E11④）。
- **moved**：不交接。关闭"在场"，更新位置事实（迁居另有 resides 的 vacated/open；远行、在途只是位置）；义务照常到期（宽限见 §4.1）；法域按新位置派生；通缉范围由引渡关系派生决定能否执行（R1-E16①）。流放 = 判决授予 banished 持有 + moved：财产、租金、汇票都不动（R2-E19①）；是否解任由章程的解任触发决定（§4.6）。
- **altered**：零交接。职位清单、职名、额度、税率由新事实派生（R1-E03①②、E13④）；反应规则"确保该等级应有的职位存在"创建新的空缺职位实体；升格条件由动作前置（设施种类与 condition）判断（R1-E03③）。新开持有时执行不相容校验（01 §1.3），结果可能是拒绝、自动让出旧持有或打"身份冲突"标记（R2-E4②、E9②）。
- **impaired**：零交接。行为能力、同意能力派生为假（R1-E08①）；日程、服务、职能暂停（V2 拘留已做）；义务照常到期，宽限只按 §4.1；解除即恢复；死亡从 impaired 直接进入 gone。

### 4.5.1 宣告失踪、宣告死亡与撤销

- **为什么需要**：传闻与信念永远不能触发 transition（I26），所以"船沉了东家多半死了"不会让钱庄进入继承（R2-E2⑥）；但长期下落不明的人确实需要一条法律出路。
- **程序**（法律包案件种类 `declaration`，期限是法典程序数据）：利害关系人（亲属、债权人、组织）在其**主观视图**中某人下落不明满 N 天时可申请 → 公告期 → 判决"宣告失踪"（开立 `guardian_of{scope: property_only}` 给财产代管人：义务照常到期，由代管人以失踪者财产清偿，A-C19）→ 再满 M 天可申请"宣告死亡" → 判决产生 `transition(gone, basis=declared)`：走 §4.2 全流程，但**不改任何生理事实**（vital 不动，人如果活着就仍然活着）。
- **撤销**：本人归来或有确证 → 撤销宣告动作 → `transition(restored, cause=撤销判决)`：
  - 恢复法律人格：重新开立 citizen_of、resides（若住处仍在）；
  - 承接实体尚未关闭时：终止其程序（未分配财产直接回转，未清偿义务回到本人名下）；已分配的，继承人、受遗赠人对仍现存的财产负返还义务（compensation 义务，以"现存利益"为限，法典条款可改）；已被善意第三人取得的不追回（民事⑨）；
  - 职位：不恢复（已有继任者），可按章程申请；
  - 婚姻：对方未再婚则恢复 kin:spouse，已再婚则不恢复（法典条款）；
  - 已执行的清偿、记坏账的债务按事件保留，不回滚日志，只由新的义务事件调整。
- 事件只追加：宣告与撤销都是事件，历史保持可审计。

## 4.6 组织与职位的继任规则（职位实体的数据）

职位在创建时从所属组织章程或聚落等级职位表取得继任规则：

| 规则 | 行为 |
|---|---|
| deputy_then_election | 副职职位持有人代理（appointed 关系派生）；登记补选到期项（elections 包）；NPC 可自荐（自治候选："地位"需求） |
| superior_appoints | 上级职位持有人任命（治理包动作；NPC 上级由自治候选决策） |
| charter_vote | 组织投票（organizations 包；NPC 按立场表态）；投票权重由章程 `votingWeight: per_head | by_share` 派生（R2-E19②） |
| elder_council | 长老定 |
| duel | 候选人约斗（决斗动作，参与者模板 agent，不限玩家） |
| hereditary | 爵位按继承表 |
| vacant_until_claimed | 空置直到有人满足条件申请 |

**解任触发**（run-002 修订，R2-E19②）：章程或职位表可声明 `removalTriggers`——持有人满足某谓词即自动 vacated，例如"被判 banished"、"连续离境 > N 天"、"被判某类罪名"、"取得某不相容持有"（与 01 §1.3 的 auto_vacate 同一机制）、"失去本组织的 devotee_of"。未声明者不因流放、远行、失能而解任，只走代理规则。

空缺期间的职权：代理人派生为"代理"（权限子集，由数据声明哪些权能可代理）；没有代理人则该职位的权能不可用（公库不能被动用，R1-E03④、E11②）。

## 4.7 NPC 之间的转移

协议不区分玩家与 NPC。NPC 的死亡（自然、战斗、处决、谋杀）、免职（复核）、叛离（立场）、迁出（谋生/避祸/逃亡）都由对应包的规则产出 `transition` 原语。自治包的决策只负责"要不要做"，怎么交接全由协议处理，这就是 R1-E16/E18 在目标下成立的原因。

## 4.8 事件与知情

- 父事件 `transition{kind, basis, entity, causes}` + 子事件（每个交接一条，带 cause=父）；程序段每阶段一条公开事件。
- 见证：能感知到的人（分区视线、距离、遮挡、声音，01 §1.5）；私密的子事件（遗产金额、秘密债）标 `private`，只进当事人的知情集合；公开的子事件（职位空缺、店铺停业、公告）成为传闻材料（K5 规则）与统计层公共知情（07 §7.3）。承接方的账簿（文书物品）按 05 §5.4 记录与其有关的子事件，所以新掌柜翻账簿能知道前任的成交（R2-E1③）。
- 远方债权人只有在知道死讯（见证、传闻、公告、公共知情）后才会申报；玩家的"任务与约定"面板读知情集合与条款快照，不读对方的真实状态（I25）。
- 返场摘要只取玩家知情集合里的事件（R1-E12⑥、E16⑤）。

## 4.9 与现有实现的衔接（供 10 迁移路线引用）

- V2 的"三种死亡入口共用一次死亡结算"是协议步骤 1–2 的雏形；V6 的 entity-transitions 是步骤 5 的雏形；PR-01 分支的 registerObligation/settleHolderGone 是步骤 3–4 的雏形但方向反了（协议 import 了包）。目标：协议进入 L1，各包注册交接类与 onDebtorGone，PR-01 的七类义务改为声明。
- family-inheritance 的"先分后还"改为清偿在前；"只认 category==='equity'"的旧 bug 在改为 share 持有后自然消失。
- 卸载批处理（第12章 §12.5.4）是本协议以 basis=pack_removed 的批量调用。

## 4.10 同刻与并发

协议是一个事务；其反应在协议之后的阶段 4 运行；同刻多个 transition 按实体 id 顺序；互为继承人同刻死亡、冻结与绝当同日、解散与汇票提示同刻的裁决见 14 §14.4。
