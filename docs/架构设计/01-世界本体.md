# 01 世界本体：八个核心概念

本章回答"世界由什么构成、存什么、派生什么"。目标是：存储层只认八样东西，上面的一切玩法都是对这八样的数据、规则和订阅。

## 1.1 总图

```
            ┌──────────── 规则（派生 / 反应 / 时钟 / 动作）────────────┐
            │  只读视图，只产提案；提案经内核事务校验后归约成事件        │
            └───────────────────────────┬────────────────────────────┘
                                        ▼
  时钟 ──到期项──▶  事件（唯一写入载体，追加不改，带起因与见证） ──归约──▶ 状态
                                                                      │
          状态 = 实体(事实) + 持有(边) + 义务(实体化的承诺) + 账户(存量) + 地点树 + 日程
                                                                      │
          投影（视图、法域、市场、立场、知情、日程、称呼、场景卡）◀─读─┘   禁止落盘
```

核心主张：
- **图模型**。节点是实体，边是持有；义务是带日程的特殊边；地点是带包含树和路线的特殊实体；账户挂在实体上，只能靠转移改变。
- **一切身份都是边**。职位、会籍、所有权、租赁、监护、婚姻、认证、公民籍、封地、领地控制、托养——全是"持有"。"这个个体现在是什么" = 它全部存活持有的集合 + 慢变事实，由视图现算。
- **职位、遗产、案件、工程、资源点、种群都是实体**，不是人物或地点的字段。这一条消灭了 115 个模块各自处理死亡的局面：死亡只是"一个实体的持有和义务按注册规则交接"。
- **只有一本账**。钱、物、粮、木、矿、水质、污染、种群数量、香火、贡献度全是账户存量；自然的产出和消耗是显式的源汇账户；价格、短缺、税、利息、租金是账本的投影或义务的到期。

## 1.2 概念一：实体（Entity）

**定义**：有永久编号的一切。编号前缀沿用现状（npc_/loc_/bld_/item_/org_/office_/obl_/case_/estate_/node_/pop_/evt_），永不复用。规范形式为 `<命名空间>:<id>`，core 省略命名空间；包实例的 id 带代次，被卸载的实体留墓碑；每个实体带不可变事实 `origin`（core / 作者数据 / 某包某版本 / 运行期创建）（命名空间、代次与墓碑见第12章 §12.3、§12.5）。

**种类（kind）与模板**。种类开放，但每个种类必须声明自己属于哪一类模板，模板决定它能挂什么：

| 模板 | 种类举例 | 可挂账户 | 可作持有人 | 可作标的 | 可作义务两端 | 有位置 |
|---|---|---|---|---|---|---|
| 个体 agent | person、creature（精怪/首领/驯兽个体） | 是 | 是 | 是（被驯服、被监护） | 是 | 是 |
| 群体 collective | org（势力、政体、门派、商会、教派、家户、怪物社会、学堂）、settlement | 是 | 是（统治、设职、持有资产） | 是（被加入、被承认） | 是 | 聚落是 |
| 物 thing | item（个体化物品：杰作、书、契据、车船）、building、node（林地/矿脉/渔场/河段/灵脉） | 是（库存、储量） | 否 | 是 | 否（建筑可作租赁标的，义务两端是主人） | 是 |
| 群 population | population（物种×地点的种群、家畜群） | 是（数量） | 否 | 是（被持有的家畜群） | 否 | 是 |
| 地 place | loc（房间、建筑地点、聚落地点、野外、郡、省、疆域） | 否（账户挂在作为实体的聚落/资源点上） | 否 | 是（被统治、被控制） | 否 | 本身即位置 |
| 职 office | office（村长、镇长、长老、会长、祭司、爵位、认证资格） | 否 | 是（授予任命、动用公库的权能由它派生） | 是（被持有） | 是（俸禄的债权端经持有人） | 否（所属组织/聚落有） |
| 契 instrument | obligation、claim（争议主张）、permit（许可）、bill（汇票） | 是（托管） | 否 | 是（可转让的债权） | — | 否 |
| 临时法人 interim | estate（遗产）、liquidation（清算）、case（案件）、project（工程） | 是（托管账户） | 是（遗产承接财产、雇佣、债） | 否 | 是 | 否 |

**存什么（事实）**：
- 不可变事实：出生日期、性别、物种/模板、文化、材质、坐标、建筑类型、创建事件。
- 慢变事实（只因事件改变，不因身份改变）：condition、健康/生命/魔力、状态标记（昏迷、拘留、封存、重病等**失能类**状态）、位置（所在节点；在路上时为"所在路线段 + 进度"——**在途是位置，不是状态标记**，见 04 §4.1）、技能熟练度与突破记录、灵智等级与成长值、性格与价值排序（含"发展记录"追加）、作品署名、物品品质与耐久、聚落行政等级、组织章程（含门规戒律等成员规范）、法典正文（规范条目，见 05 §5.2）。
- 物品的表象事实（run-002 修订）：`purports`（物品自称是什么：汇票、盐引、地契、官印、名家作品……及其条款）与真实事实分开存；真货的 `represents` 指向它所代表的义务或持有，伪造物 `represents` 为空。文书类物品另有 `records: [事件编号 + 版本文本]`，阅读即产生转述（05 §5.4）。
- 作者数据（world/people、world/geo 等）在开局、首次物化或 `pack.install` 纪元边界注入时（第12章 §12.5.2）转换成持有与账户："home" 成居住持有，"workplace/occupation" 成雇佣或经营持有，"wealth.property" 成所有权持有，"coins/inventory" 成账户，"relationships" 的亲属项成亲属持有，态度项成初始印象事件。作者文件不改，转换器带来源标记 `authored`。

**禁止存（必须派生）**：称呼与职称、职权与权限、任务额度、俸禄、服务清单与价格、日程、店主身份、所在法域、立场数值、识字率、人口数、是否成年、可进入的地点、股份价值、可采量。数据校验器对这些字段名设黑名单（见 02 不变量 I10）。

**与其他概念的关系**：实体是所有边的端点；账户属于实体；事件的发起者、对象、见证者都是实体；规则读实体视图。

## 1.3 概念二：持有（Holding）

**定义**：有向、带时间区间的边 `持有人 ─[种类, 条款, 授予者, 起, 止, 终止原因]→ 标的`。

**为什么叫"持有"而不叫"关系"**：结构性关系（亲属、婚姻、成员、雇佣、监护、居住、所有）决定交接和派生，必须是边；态度性关系（信任、亲近、敬畏、欠情、恋慕、竞争）是对事件的印象汇总，是投影"立场"，不是存储概念（见 05 §5.6）。两者分开后，转移协议只需遍历持有。

**每种持有在注册时必须声明**（缺一则启动失败）：
- `holderKinds` / `subjectKinds`：允许的两端模板。
- `exclusive`：同一标的同一时刻是否只能有一个持有人（职位、所有权默认是；股份、会籍不是）。
- `sum`：同一标的的份额之和约束（股份 = 1.0）。
- `grantedBy`：由谁授予（职位授予的任命，授予者记职位实体而非当时的人）。
- `handover`：持有人消失（gone）、让出（vacated）、迁出（moved）、叛离（defected）、失能（impaired）时的交接类（见 04 转移协议）。
- `onSubjectGone`：标的消失时怎么办（建筑烧毁：所有权留在废墟实体上；租赁按毁损条款）。
- `derives`：这种持有派生出哪些身份值（职权、称呼、额度、日程片段、服务）。
- `visibility`：公开 / 仅当事人 / 仅成员（影响知情与场景卡）。
- `incompatibleWith`（可空，run-002 修订）：与哪些**其他种类**的持有不相容，`[{kind, subjectFilter?, policy: forbid | auto_vacate | needs_permission | flag}]`。在 holding.open 的事务内校验：forbid 拒绝并给世界内原因；auto_vacate 在同一事务里关闭旧持有（vacated）；needs_permission 要求某职位的许可持有；flag 允许但派生出"身份冲突"标记，供额度、派任务、立场等视图读取。组织章程与法典可以对同一组合再声明一层（例如行会章程 `expelOn`、法典的"兼任"条款），裁决顺序见 05 §5.3。这样"出家 × 行会猎户""男爵 × 村正"不需要任何一个包知道另一个包。

**初始持有种类目录**（数据文件 `ontology/holdings.json`，可扩）：

| 种类 | 持有人 → 标的 | 要点 |
|---|---|---|

| guest_of 做客/留置 | person/creature → agent/org（东道） | run-002 修订：条款 `{mode: voluntary | detained, until?}`；派生日程（并入东道日程）、所在位置、对外通信能力；detained 且未经同意时由规范层判断是否构成非法拘禁（E15②） |

| pledged 质押 | obligation → item/building | 违约处置的标的 |
| frozen 冻结 | case → holding/account | 争议期间禁止转让与分红 |
| permit 许可 | office → person（限时） | 采矿许可、施法许可、私宅许可、据点许可 |
| companion 同行 | agent → agent | 带路/护送期间；移动工具同时移动 |

**派生**：身份（"现在是什么"）、权限、额度、俸禄、称呼、居住地、工作地、日程、可进入处、可提供的服务、可投票的议事、法域、立场传导路径。

## 1.4 概念三：义务（Obligation）

**定义**：实体化的承诺。字段：种类、债务人、债权人（可为不记名=持票人）、标的（资源与数量，或行动与完成条件）、日程（一次性 / 分期 / 持续累计）、清偿方式、违约规则、担保（pledged 持有）、状态、`accruedTo`（累计到何时）、来源事件、条款快照（签约时冻结，历史合同不随后来的派生改写；含签约地与当时适用的规范栈版本、宽限条款、继承后的 `liabilityCap`）。

**义务种类必须声明的两端消失规则**（run-002 修订，04 §4.2）：
- `onDebtorGone`：`accelerate`（加速到期，遗产一次清偿）/ `assume_by_heirs`（按继承份额由继承人按原日程承担，以所继承财产为限 = 限定继承，质押随义务一起走）/ `substitute_performance`（履行类义务：转给承受相应财产的继承人履行，或由遗产雇人代为履行）/ `void`（人身性义务：授课、护送、陪伴、服役等，终止并按条款结算已付对价）。法典的民事条款可以覆盖种类缺省（05 §5.2）。
- `onCreditorGone`：`estate`（缺省：债权入遗产）/ `void`（以债权人本人为对象的服务）。
- **宽限不是协议缺省**：债务人在途、被困、被羁押、昏迷时，到期与违约**照常**计算；只有规范层的宽限条款（天灾阻断宽限、羁押停息……）或合同条款能延后到期或停止罚息。违约规则读 `grace(obligation, now)` 这一 L1 条款查询（05 §5.2），不读位置或状态。

**票据**：bill、盐引、地契之类可流通的票据 = 义务（或持有）+ 一件代表它的物品个体（`represents` 指向义务）；持票人 = 物品的 owns 持有人。以票据结算是"交付票据 + 附条件清偿"，票据兑付或被识破时才最终确定（05 §5.1）。伪造票据是 `purports` 有、`represents` 空的物品，不是义务。

**累计不逐日写**：`amountDue(t) = f(条款, accruedTo, t)` 在读取时按闭式算出；清偿或结息事件把 `accruedTo` 推进。离开 360 天不产生 360 次写入，而且与逐日结果相等。

| compensation 赔偿/抚恤 | 责任人 → 受害人 | 一次或分期 | 转移 | 同上 |
| upkeep 维持（召唤、契约、会费） | 持有人 → 组织/召唤物 | 持续 | 转移 | 契约终止、欠费除名 |
| project 工程 | 承建方 → 出资方 | 工期按能做工的日推进 | 完工事件（创建设施/恢复 condition） | 停工 |

**关系**：两端是持有（债权人持有债权、债务人承担债务），转移协议一视同仁；清偿是转移；到期是时钟日程项；违约是事件，是否构成罪名、能否起诉由规范层判定（05 §5.2）。

## 1.5 概念四：地点（Place）

**定义**：包含树上的节点，加路线边。
- 包含树：房间 ⊂ 建筑 ⊂ 聚落 ⊂ 郡 ⊂ 省；野外、矿口、林地、河段、巢穴、关卡也是节点，各有父节点；政体疆域不是树节点，而是 `governs` 持有覆盖的节点集合。
- 路线边：陆路、河道、海路、山径；长度、通行方式、季节封闭规则、桥路设施引用。河段之间的边是有向的（顺流），用于污染与水量传递。**收费与风险不存在边上**（run-002 修订）：关税与通行费由沿途各节点的规范栈税表与 `controls` 持有（关卡、山寨收买路钱）派生；风险由沿线 `controls` 持有人（首领、山贼、敌军）的威胁、近期 harm 事件密度与天气派生。

**空间与方位**（2026-10-15 用户要求：文字也是有方位的；空间是世界的一部分，不是只为画面准备的数据）：
- **路线边带方位**：每条边存方位（八方位或角度）、距离与通行耗时（耗时仍按通行方式、路况、天气派生修正）。
- **分区**：聚落、建筑、野外节点内部再分为**分区**（zone，地点包含树的叶层：铺面、门口、街心、后院、茶摊、柜台后、山道口……）。分区之间有**邻接边**：方位、距离（步数或丈）、遮挡（墙、门——门的开关是建筑事实——、人群、树丛）、视线等级（通视/部分/无）、声音衰减系数。分区是地点，账户与持有照旧挂在作为实体的建筑、聚落上。
- **站位**：实体此刻在哪个分区，是**派生投影**：由日程（05 §5.8）、当前活动（正在进行的动作与它占用的分区）、最近一次 move 原语的目标分区得出，不落盘（I10）。玩家与在场 NPC 的分区内移动是 move 原语（分区边耗时，按步计，可被打断）。
- **坐标与网格可选**：分区可带局部坐标、占地、朝向、出入口；地点可带网格尺寸。它们是更细的可选数据，主要给画面客户端（08 §8.8）；规则只读分区粒度。
- **缺数据时自动生成布局**：确定性布局规则按地点类型（集镇、村、寺、山道、码头……）与建筑清单生成分区与邻接（同一战役种子同一结果），保证每个地点都有方位（I30）；作者数据与第三方包（第12章"布局"扩展点）可整体覆盖或补充。
- 相乘：见证与知情按感知判定（下文"在场"）；潜行、偷窃、偷听读站位、遮挡与声音；战斗读分区距离与遮挡；NPC 决策可选择走近或避开；场景文字按方位组织（08 §8.2、§8.5）。

**存**：父节点、坐标、地形、气候带、生物群落、路线边（含方位）、分区与邻接（作者数据或生成规则的种子）、设施清单（引用建筑实体）、感官素材（作者数据）、可选的布局细节与素材键（08 §8.8）。

**派生**：
- 法域：从节点向上找最近的被某政体 `governs` 覆盖的节点，得到**主权法典**；找不到 → 数据错误，生成器拒绝创建该节点（不兜底到五村法典）。完整的适用规范是**规范栈**（05 §5.2）：沿包含树收集主权法典、各级次级规范（郡法、镇规、村规，以及第 12 章的地方法典绑定）、行为者的成员规范（门规、戒律）与有关政体的域外管辖条款，按层级排序。
- 通行性：边的 condition + `controls` 持有的封闭标记 + 季节 + 天气。
- 在场与感知：**不再是"同一地点即见证"**。`perceives(观察者, 事件)` = 视觉（分区路径上的视线等级、距离、光照/昼夜、天气、遮挡）或听觉（声音强度按动作的音量标签 − 分区边衰减累计 − 环境噪音 ≥ 观察者听力阈）或触觉（同分区接触）；潜行动作的检定结果以修正进入感知阈。见证集合 = 事件发生时满足 perceives 的实体（冻结写入事件）。同一节点内远处、隔墙者可能只"听见动静"（见证版本为不完整的听觉版本）或完全不知道。
- 服务：本地存活的 `operates` 持有 + 营业时间（日程派生）。
- 容量：栖地容量、住房容量、仓容（设施 + condition）。
- 人口：`resides` 持有计数（智能/规则层）+ 统计层聚合账户。
- 聚落同时是地点与实体：地点身份管包含与路线，实体身份管账户（公库、粮仓）、事实（行政等级）、持有（被统治、被管理）。

## 1.6 概念五：账户与转移（Account & Transfer）

**定义**：账户 = (实体, 资源种类, 用途)，存量一个数（整数，单位由资源种类定）；转移 = (来源账户, 去向账户, 资源, 数量, 起因事件)。

**资源种类**（`ontology/resources.json`，开放）：
- 货币：按政体铸币分种（王国铜/部盟铜……），兑换是两笔带手续费的转移；100 铜 = 1 银 = 0.01 金 只是显示换算。
- 可计量物品：按物品模板（item_wood、item_iron_ore、item_bread……）；物品个体（有编号的杰作、书、契据、车船、署名成品）不是数量，是实体，用 `owns` 归属，用 `located_in` 定位。
- 粮（foodUnit）、木材、矿石储量、药材、水量、水质指标、污染量、香火、贡献度、种群数量（物种×地点）、饲草、燃料。
- 身体资源不是账户：生命、魔力是慢变事实（钳制在 0..上限），由 `vital` 原语改。

**批次**（run-002 修订，E20③）：资源种类可声明 `lots: true`（粮、药材、鲜货、酒、灵丝等会腐坏或陈化的东西）。此时账户键扩展为 (实体, 资源, 用途, 批次)，批次带元数据：入库日、品质、暴露量（受潮、受热累计）。批次不是实体，只是账户键的一部分；它的元数据只能经 fact.set 的批次白名单字段（品质、暴露量）或转移时自动携带。转移缺省先进先出，也可指定批次。腐坏是时钟规则：按资源种类的保质曲线（入库日、温湿度、暴露量）闭式算出应腐坏数量，转移到 `sink:decay`（I1 守恒、I14 精确等价）。市场投影按品质档聚合批次。未声明 `lots` 的资源（矿石、铜钱）仍是一个数。

**群体子账户**：种群与统计层人口可以按状态拆成子账户（例如疫病的易感/感染/康复 = 用途 `disease:<病种>:S|I|R`），总数是子账户之和（05 §5.5、07 §7.3）。

**源汇账户**（显式、可审计）：`src:regrowth`（再生）、`src:birth`（生育/繁殖）、`src:weather`（降水）、`src:mint`（铸币，仅政体）、`sink:consume`（消耗）、`sink:decay`（损耗/腐烂）、`sink:destroy`（损毁/烧毁）、`sink:death`（死亡）、`sink:export`（离开模拟范围）、`src:genesis`（作者数据与包安装的初始存量，受合理性表约束）、`src:pack_converted` / `sink:pack_removed`（包升级、卸载时的折算与移除，见第12章 §12.5）。再生不是凭空加数，是从 `src:regrowth` 按规则流入；烧掉的粮是转移到 `sink:destroy`。于是守恒机械可验，"盗采也扣储量"不需要任何人记得——矿脉只有一个账户。

**禁止**：任何代码直接改存量；任何实体同一资源同一用途有两个账户（组织公库与首领私囊是两个实体的账户；势力时钟公库与组织公库必须是同一账户——V4 已经这样做）。

**派生**：价格、短缺、财富区间、公库能否拨款、股份价值（组织净资产 × 份额）、可采量、害兽压力、识字率之外的一切"有多少"。

## 1.7 概念六：事件（Event）

**定义**：唯一的写入载体，追加不改。字段：编号、时间、动词、发起者、对象、主体、地点、起因事件（cause）、携带的原语列表（转移、持有变更、事实变更）、见证人（由感知派生 perceives，§1.5，事件发生时冻结写入，可带"只听见/只看见"的不完整版本）、可见性（公开/私密/仅成员）、标签（性状、罪名 offense:*、harm/gift、显著度、工具/动作来源）、提案原文（动作层：意图文本、原语提案、骰值）。

**与现状的方向相反**：现状是"工具改状态 → 事后从前后差分推导世界事件"（K3 deriveWorldEvents）；目标是"提案 → 事件 → 归约出状态"。迁移期两者并存（见 10 迁移路线），迁移完成后差分推导只剩校验用途。

**幂等与起因链**：每个事件带起因；同一起因对同一规则只触发一次（幂等键 = 规则 × 起因事件）。这是"旱灾和污染各自结算、产量被重复扣减"类错误的机制性解法：产量派生只读一次输入，反应规则对同一起因只发一次。

**转述也是事件**：`tell(讲者, 听者, 说法版本, 源)`。源可以是事件（见证后转述）、`belief` 事件（讲者自己的推测）或文书物品（阅读）。失真发生在转述事件上（由讲者性格与立场的失真表生成），不在谁的脑子里。谎言是带 `lie` 标签的转述，真相链接保留（U8 已有雏形）。

**信念也是事件**：`belief(持有者, 命题, 置信度, 依据)` 由推断规则产生（05 §5.4），可错，只进入持有者的主观视图；它永远不改变真实状态，也不能触发 transition（I26）。

**派生**：NPC 记忆与知情集合、主观视图、传闻、编年史、立场、名声、案件证据、隐藏职业契机、灵智成长、作品传播、历史。

## 1.8 概念七：规则（Rule）

四种形状，全部只读视图、只产提案：

1. **派生规则**：纯函数 `视图 → 值`。法域、价格、俸禄、权限、产量、感染率、同意能力、日程、称呼。查表部分是数据（俸禄表、税表、容量表），组合是代码。
2. **反应规则**：`当 事件匹配(动词/标签/地点谓词/参与者谓词) 则 效果原语列表`。火势蔓延、征税、立案、立场印象、传闻生成、停工、追随者分流都是反应规则；条件与参数是数据（JSON 谓词 DSL），原语执行是代码。
3. **时钟规则**：`每 日/月/季/年，在 层级（智能/规则/统计），对 某类实体 执行 效果原语`，并声明 `closedForm`（可一次算 N 天）或 `tolerance`（迭代近似的容差）。
4. **动作规则**：玩家或 NPC 可发起的规则：参与者槽位、前置条件、同意、代价、检定、按档位的效果原语、可见性、叙述模板（详见 06 动作层）。

**三种声明式规则形状**（run-002 修订）。run-002 暴露出三类"只靠四种形状写代码就只能改别的包"的需求。它们都由上面四种规则执行，存放在已有概念里（法典与章程是组织实体的事实，修正项与推断规则是包数据），**不是新的存储概念**，但属于新增的规则形状，必须有固定 schema：

| 形状 | 是什么 | 谁执行 | 存在哪 | 详见 |
|---|---|---|---|---|
| 规范条目 norm clause | (来源组织, 适用谓词, 层级, 内容：罪名谓词 / 民事条款 / 程序条款 / 税表 / 授权表) | L1 规范栈解析（派生）+ 法律包立案（反应）+ 各包读条款（派生） | 政体、治理组织、门派、寺院等组织实体的"法典/章程"事实；第三方包的法典（见第12章） | 05 §5.2 |
| 修正项 modifier | `{target: 派生的修正槽, when: 谓词, op: add|mul|clamp, value}` | 派生规则在合成时按槽位声明的顺序应用 | 包数据 | 05 §5.9 |
| 推断规则 inference | `{premise: 期望未发生 / 观测到异常 的谓词（读主观视图）, candidates: [命题, 按性格的权重], confidence}` | 反应或时钟规则，唯一允许的输出是 `belief` 事件 | 包数据 | 05 §5.4 |

**效果原语**是规则能做的全部动作（完整表见 06 §6.3）：transfer、holding.open/close/transfer、obligation.create/settle/cancel、fact.set、vital、status、move、create、destroy、emit（含 tell/impress/request）、schedule、transition、learn、time。指南 7.6 的法术原语、K2 交互表、K6 效果表都是它的子集或参数表。

**提案与事务**：规则产出提案 → 内核在一个事务里解析引用、校验不变量、执行原语、写事件；失败整体回滚并返回可改正的错误（给工具/LLM/界面）。

## 1.9 概念八：时钟（Clock）

**定义**：单一世界时间（分钟）+ 到期日程堆 + 各地区的模拟层级与"已结算到何时"。

**到期项**：义务分期、时钟规则下次唤醒、势力计划阶段、再生检查点、作物生长阶段、案件程序期限、空缺补选期限、许可到期、效果到期、托养到期。

**推进 N 天** = 依次弹出 N 天内到期项处理（每项产生事件）→ 各地区按层级把时钟规则补算到当前时刻（闭式一次算，迭代按步长）→ 没有到期项且没有时钟规则的东西不会被碰。这是离屏便宜的根本原因，也是"回放一致"的基础（到期项顺序确定，骰值由战役种子 + 对象 + 日期决定，沿用 T130/T131 做法）。

**层级**沿用指南 5.9 与 P3 的三层：智能层（玩家所在郡及相邻）、规则层（同省/两跳）、统计层（更远）。层级由注意距离派生，不写进人物。

## 1.11 存与派生的分界（给校验器的规则）

- **存**：只因事件改变的量——存量、condition、熟练度、健康、灵智成长、起止时间、条款快照、`accruedTo`、程序阶段、作者文本。
- **派生**：因"当前是谁 / 在哪 / 属于谁 / 何时"而变的量。数据文件和存档出现这类字段名即校验失败（黑名单：monthlyQuotaD、salary、powers、title、publicRole、shopKeeper、services(派生部分)、jurisdiction、population(聚落)、literacyRate、isAdult、standing(数值)……，由 A1 名单起草）。
- **覆盖**：确需手填的，字段名加 `override`，附理由；视图输出附来源标记 `authored | override | derived | cached`。
- **缓存**：投影缓存允许，但带版本键（依赖的持有种类/账户/事件动词各有版本号），测试随机重建比对（02 不变量 I17）。

## 1.12 与候选概念清单的取舍

- "职位/角色"：不是独立概念，是实体种类 office + 持有 holds_office。理由：职权属于职位而非人（Crusader Kings 的头衔模型），任命由职位发出，这样免职不影响任命、死亡不带走职权。
- "市场"：不是存储概念，是账户+路线上的投影。理由：价格一旦存储就会和存量脱节（run-001 的"议和当场恢复物价"正是存了价格状态的结果）。
- "辖区"：不是概念，是地点树上的派生。
- "资源存量与流量"：合并为账户与转移；"流量"就是按日程发生的转移序列。
- "关系"：拆为持有（结构）与立场投影（态度）。
- "效果"：不是概念，是规则的输出词汇（原语）。
- "动作"：是规则的第四种形状，不另立概念。
- "规范层""主观视图""修正项"（run-002 后加入）：不是存储概念。规范条目存为组织实体的法典/章程事实；主观视图是知情集合 + belief 事件之上的投影；修正项是包数据。它们是新增的**规则形状**（§1.8），理由：没有它们，新禁令、新影响因素、谣言驱动的行为都只能靠改别的包的代码实现，违背"包靠词汇相乘"。
- "批次"：不是实体，是可腐坏资源的账户键维度（§1.6）。
