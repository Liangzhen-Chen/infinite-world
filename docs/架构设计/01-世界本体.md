# 01 世界本体：八个核心概念

本章回答"世界由什么构成、存什么、派生什么"。目标是：存储层只认八样东西，上面的一切玩法都是对这八样的数据、规则和订阅。枚举与术语的唯一定义处是附录 A；本章只引用。

（修订历史见 修订记录.md。）

## 1.1 总图

```
            ┌──────────── 规则（派生 / 反应 / 时钟 / 动作）────────────┐
            │  只读视图，只产提案；提案经内核事务校验后归约成事件        │
            └───────────────────────────┬────────────────────────────┘
                                        ▼
  时钟 ──到期项──▶  事件（唯一写入载体，追加不改，带起因与见证） ──归约──▶ 状态
                                                                      │
          状态 = 实体(事实) + 持有(边) + 义务(实体化的承诺) + 账户(存量) + 地点树 + 日程
                                                                      │
          投影（视图、法域、市场、立场、知情、日程、称呼、场景卡）◀─读─┘   禁止落盘
```

核心主张：
- **图模型**。节点是实体，边是持有；义务是带日程的特殊边；地点是带包含树和路线的特殊实体；账户挂在实体上，只能靠转移改变。
- **一切身份都是边**。职位、会籍、所有权、租赁、监护、婚姻、认证、公民籍、封地、领地控制、托养、信奉、附身、封印——全是"持有"。"这个个体现在是什么" = 它全部存活持有的集合 + 慢变事实，由视图现算。
- **职位、遗产、案件、工程、资源点、种群都是实体**，不是人物或地点的字段。这一条消灭了 115 个模块各自处理死亡的局面：死亡只是"一个实体的持有和义务按注册规则交接"。
- **只有一本账**。钱、物、粮、木、矿、水质、污染、种群数量、香火、贡献度、怨气全是账户存量；自然的产出和消耗是显式的源汇账户；价格、短缺、税、利息、租金、汇率、利率是账本的投影或义务的到期（15 章）。
- **哪类东西用哪种概念**：附录 A §A.2 判别表。

## 1.2 概念一：实体（Entity）

**定义**：有永久编号的一切。编号前缀沿用现状（npc_/loc_/bld_/item_/org_/office_/obl_/case_/estate_/node_/pop_/evt_），永不复用。规范形式为 `<命名空间>:<id>`，core 省略命名空间；包实例的 id 带代次，被卸载的实体留墓碑；每个实体带不可变事实 `origin`（core / 作者数据 / 某包某版本 / 运行期创建）（命名空间、代次与墓碑见第12章 §12.3、§12.5）。

**种类（kind）与模板**。种类开放，但每个种类必须声明自己属于哪一类模板，模板决定它能挂什么：

| 模板 | 种类举例 | 可挂账户 | 可作持有人 | 可作标的 | 可作义务两端 | 有位置 |
|---|---|---|---|---|---|---|
| 个体 agent | person、creature（精怪/首领/驯兽个体/亡魂/神祇；每个 creature 指向一条物种数据，§1.10） | 是 | 是 | 是（被驯服、被监护、被附身、被封印；creature 另可被 owns，条件物种 `ownable`，§1.3） | 是 | 是（神祇不在场，13 §13.8）。模板标志 `inheritance`：person 缺省 true，creature 缺省 false（物种数据可改）——为 false 的个体死亡不建遗产、不生成监护、不进继承表。creature 是否算"人"（入户、起诉、不可被 owns）不是模板字段，是视角法域的承认 `recognized(x, j, 'personhood')`（附录 A §A.7） |
| 群体 collective | org（势力、政体、门派、商会、教派、家户、怪物社会、学堂、钱庄、冥府）、settlement | 是 | 是（统治、设职、持有资产） | 是（被加入、被承认、被信奉） | 是 | 聚落是 |
| 物 thing | item（个体化物品：杰作、书、契据、车船、符；模板标志 `illusion: {source, expiresAt}` 的幻象物——无账户、不能作配方投入、真实 `value` 为 0、到期项 destroy，可被 pledged 或出售但按 purports 成交，损失按民事⑥）、building、node（林地/矿脉/渔场/河段/灵脉/田地）、wreck（残骸，04 §4.2）、mark（兜底的带标签实体，06 §6.9.5：有位置、可 owns、无账户）、spell（法术定义实体：只作 `registered` 的持有人与 `teaches` 的指向，无账户、无位置） | 是（库存、储量） | 是（仅 `seals`：封印物持有被封者；`registered`：item / spell 对登记机关；容器与内容物的关系是位置事实，不是持有） | 是 | 否（建筑可作租赁标的，义务两端是主人） | 是（spell 除外） |
| 群 population | population（物种×地点的种群、家畜群、未安息亡者） | 是（数量） | 否 | 是（被持有的家畜群） | 否 | 是 |
| 地 place | loc（房间、建筑地点、聚落地点、野外、郡、省、疆域、异界） | 否（账户挂在作为实体的聚落/资源点上） | 是（仅 `seals`、`invited` 的授予方经东道） | 是（被统治、被控制） | 否 | 本身即位置 |
| 职 office | office（村长、镇长、长老、会长、祭司、爵位、认证资格、地方神职、冥府职位） | 否 | 是（授予任命、动用公库的权能由它派生） | 是（被持有） | 是（俸禄的债权端经持有人） | 否（所属组织/聚落有） |
| 契 instrument | obligation、claim（争议主张，案件解决它）、bill（汇票）、warrant（盐引类凭证）——许可 permit 不是实体，是持有 | **否**（托管款挂在保管人实体的用途账户 `escrow:<义务 id>` 上，位置随保管人，附录 A §A.15 托管与代收） | 是（仅 `pledged`：义务持有其质押物；`frozen` 的持有人是 case，属 interim） | 是（可转让的债权） | — | 否 |
| 临时法人 interim | estate（遗产）、liquidation（清算）、case（案件）、project（工程、长仪式）、motion（议案，05 §5.2.5） | 是（托管账户） | 是（遗产承接财产、雇佣、债；case 与 motion 持有 `frozen`） | 否 | 是 | 否——但有**执行人与 seat**（附录 A §A.15 执行人）：在场校验按执行人位置或托管账户所在建筑判，`located(x)` 返回 seat；非聚落 collective 同此 |

**存什么（事实）**：
- 不可变事实：出生日期、性别、物种/模板、文化（13 §13.2）、材质、坐标、建筑类型、创建事件、`soulOf` / `rebirthOf`（亡魂与转生，13 §13.7）、神祇的 `aspects`。
- 慢变事实（只因事件改变，不因身份改变）：condition、健康/生命/魔力、状态标记（昏迷、出神、被附身等**失能类**状态——疾病是否失能由状态数据 `capacity` 声明，"重病但清醒"缺省不失能——拘留、羁押、软禁、人质不是状态，是持有 `guest_of{mode: detained}` 派生的**受限**形态（附录 A §A.3）——以及受诅、封存等其他状态）、**语言技能**（技能族 `lang:*`，熟练度 0..3，母语由文化记录给出；沟通度派生见附录 A §A.15）、**包的扩展事实**（第三方包对 core 种类声明的带命名空间字段，如 `xiuxian:realm`，白名单与范围由包声明、黑名单检查照旧，卸载按 dormant / fallback / drop 处置，12 §12.2.3）、**位置**（一切有位置的实体——人、生灵、物、建筑、残骸——的位置是慢变事实，取值为：地点节点或分区；"所在路线段 + 进度"（**在途是位置，不是状态标记**，见 04 §4.1）；某个 agent（随身）；某个 item（容器内）。物在随身者或容器中时，其有效位置随载体派生，不另存；载体消失时协议把内容物 `reparent` 到载体所在地点或残骸（04 §4.2）。视图谓词 `located(x)` 读它。出神者的魂另有位置）、技能熟练度与突破记录、灵智等级与成长值、性格与价值排序（含"发展记录"追加）、**计划**（NPC 的多步图谋，05 §5.7.2）、当前形（`form`，变形生灵）、真名（`trueName`）、**身份键** `identities`（附录 A §A.15：缺省恰一个本名；化名、易容、变形后的另一副面孔各是一个键；事件按行为者当时的键记 `actorAs`，观察者按认出的键记忆与评价）、作品署名、物品品质与耐久、物品的 `sympathyLink`（交感媒介指向的实体）、聚落行政等级、组织章程（含门规戒律等成员规范）、法典正文（规范条目，见 05 §5.2）。
- 物品的表象事实：`purports`（物品自称是什么：汇票、盐引、地契、官印、名家作品……及其条款）与真实事实分开存；真货的 `represents` 指向它所代表的义务或持有，伪造物 `represents` 为空。文书类物品另有 `records: [事件编号 + 版本文本]` 与 **`language: lang:*`**（文书用什么文字写，缺省为写作者母语；译本另带 `translatedFrom` 与译者署名），阅读即产生转述（05 §5.4），前置是 `canRead`（识字 ∧ 该语言熟练度，附录 A §A.15）。`purports` 同样用于会变形、会幻形的生灵与人（13 §13.4），以及可替代物的批次（§1.6）。
- 作者数据（world/people、world/geo 等）在开局、首次物化或 `pack.install` 纪元边界注入时（第12章 §12.5.2）转换成持有与账户："home" 成居住持有，"workplace/occupation" 成雇佣或经营持有，"wealth.property" 成所有权持有，"coins/inventory" 成账户，"relationships" 的亲属项成亲属持有（并由 kin:parent 对未成年子女生成双亲各一条 `guardian_of`，非互斥，scope person_and_property；出生反应规则同样开立；法典监护顺位只作候补），态度项成初始印象事件；**`citizen_of`（标的 = 政体组织）由转换器按作者 `home` 所在聚落的主权政体开立，`resident_of`（标的 = 聚落）按 home 开立**（法典可改为按父母籍或出生地），远方名册种子物化与出生反应规则同样开立。作者文件不改，转换器带来源标记 `authored`；作者数据中属于派生黑名单的字段由转换器忽略并在转换报告列出差异（§1.11）。

**禁止存（必须派生）**：称呼与职称、职权与权限、任务额度、俸禄、服务清单与价格、日程、店主身份、所在法域、立场数值、识字率、人口数、是否成年、可进入的地点、股份价值、可采量、生灵的处境（游荡/受供/被封……）。数据校验器对这些字段名按记录类别设黑名单（见 02 不变量 I10）。

**与其他概念的关系**：实体是所有边的端点；账户属于实体；事件的发起者、对象、见证者都是实体；规则读实体视图。

## 1.3 概念二：持有（Holding）

**定义**：有向、带时间区间的边 `持有人 ─[种类, 条款, 授予者, 起, 止, 终止原因]→ 标的`。

**为什么叫"持有"而不叫"关系"**：结构性关系（亲属、婚姻、成员、雇佣、监护、居住、所有）决定交接和派生，必须是边；态度性关系（信任、亲近、敬畏、欠情、恋慕、竞争）是对事件的印象汇总，是投影"立场"，不是存储概念（见 05 §5.6）。两者分开后，转移协议只需遍历持有。

**每种持有在注册时必须声明**（缺一则启动失败）：
- `holderKinds` / `subjectKinds`：允许的两端模板。
- `exclusive`：同一标的同一时刻是否只能有一个持有人（职位默认是；所有权、股份、会籍不是——所有权用份额表达共有）。
- `sum`：同一标的的份额之和约束（所有权与股份 = 1.0；单一持有人时份额为 1.0）。
- `grantedBy`：由谁授予（职位授予的任命，授予者记职位实体而非当时的人）。
- `handover`：持有人消失（gone）、让出（vacated）、叛离（defected）三项必填，取附录 A §A.4 的钩子模板（它们是 `holder.gone`、`self.closed(vacated)`、`holder.holdingClosed(member_of, defected)` 三条钩子的简写）。**在途、失能、受限不是交接列**：它们的效果由 `effective(holding)` 与 `canAct()` 派生（附录 A §A.3、§A.15），持有不动。
- `onSubjectGone`：标的消失时怎么办，取附录 A §A.4 的四个模板（建筑烧毁：所有权留在残骸实体上 `stay`；雇主死亡：雇佣换到其遗产 `estate`）。
- `hooks`（可空）：其余协议后续 `[{on, when?, do}]`（附录 A §A.4）——标的的 governs 换了持有人、持有人被判破产、持有人的另一条持有因某 reason 关闭、某事件发生……都在这里声明，不新增触发。
- `concluded`（由内核在开立时写入）：缔结快照 `{place, lawVersion, time, form, inName?}`，承认派生 `recognized(h, j)` 读它（附录 A §A.15）；只对由一次行为开立的结构性持有有意义（婚姻、认证、许可、登记、买卖取得的所有权、公民籍），转换器开立的作者数据持有记开局。
- `derives`：这种持有派生出哪些值——职权与**权能** `authority`、称呼、额度、**日程片段** `schedule`、服务、**立场传导系数** `conduction`（05 §5.6；core 为 member_of / kin / household / allied_with / citizen_of / resident_of / holds_office / devotee_of / 种群 / employed_by / operates 声明；与 05 §5.6 同一清单）；钉住侧不在 derives 内，是独立字段 `pins`（下文）；任一种类都可声明任一项，core 消费者读"全部已注册持有种类的声明"而不是固定清单。
- `visibility`：公开 / 仅当事人 / 仅成员（影响知情与场景卡）。
- `pins`（缺省 `none`；钉住侧枚举 `holder | subject | both`）：这种持有的哪一侧被**钉住**（附录 A §A.15：不参与聚合、至少按规则层处理）。core：holds_office（holder）、controls（holder）、wanted（subject）、banished（subject）、guest_of{detained}（holder；东道为 person 时 both）、custody_of（holder）、companion（both）、frozen（subject：被冻结持有的持有人与账户所属实体）、pledged（subject：质押物的 owns 持有人）。
- `contest`（可空）：同刻多个提案争夺同一互斥标的时的裁决规则（附录 A §A.15 争夺；未声明时的缺省与 core 各标的的声明值以 14 §14.2 缺省表为唯一定义）。
- `incompatibleWith`（可空）：与哪些**其他种类**的持有不相容，`[{kind, subjectFilter?, policy: forbid | auto_vacate | needs_permission | flag}]`。在 holding.open 的事务内校验：forbid 拒绝并给世界内原因；auto_vacate 在同一事务里关闭旧持有（vacated）；needs_permission 要求某职位的许可持有；flag 允许但派生出"身份冲突"标记，供额度、派任务、立场等视图读取。组织章程与法典可以对同一组合再声明一层（例如行会章程 `expelOn`、法典的"兼任"条款），裁决顺序见 05 §5.3。这样"出家 × 行会猎户""男爵 × 村正""改宗"不需要任何一个包知道另一个包。
- `parent`（可空）：上位持有种类（如包的 `hantan:disciple_of` 以 core `mentor_of` 为上位）；core 消费者（回避 `recusal`、传导、继承表的排除、日程片段）按上位回退读声明，未声明的字段继承上位的值；`tags` 不是持有种类的字段。

**初始持有种类目录**（数据文件 `world/ontology/holdings.json`，可扩；钩子注册表在 04 §4.3）：

| 种类 | 持有人 → 标的 | 要点 |
|---|---|---|
| resides 居住 | person → place（房间/建筑/家户） | 派生在场默认位置、私宅进入权、户籍 |
| household_member 家户成员 / household_head 户主 | person → org(家户) | 继承与监护顺位从亲属持有与家户派生 |
| kin 亲属（父母/子女/配偶/兄弟姐妹/过继） | person/creature → person/creature | 不可转移；婚姻是双向 kin:spouse 两条边，缔结快照记缔结地与形式要件，各法域经 `recognized` 决定承认与否；两端模板放宽到 creature（人妖婚配、冥婚，13 §13.4），条款可带 `taboo`；creature 一端只在其物种 `inheritance: true` 时进继承与监护——牲畜血统用物种 `heritable` 与谱牒文书，不用 kin |
| owns 所有 | agent/collective/interim → item/building/node/population/**creature**（物种 `ownable: true`：普通动物与家畜缺省 true、灵智生灵缺省 false；被视角法域承认人格者 `recognized(owns, j) = void`） | **exclusive: false，sum: 1.0**（共有即多条份额边，单一所有人份额 1.0）；进遗产；**转移与出质的权能**见 06 §6.3：无权但占有者的处分成立并标 `unauthorized_disposition`（附录 A §A.15 占有） |

| leases 租赁 | agent/collective → building/land | 条款：租金、期限、毁损条款；租金义务由此派生 |
| operates 经营 | agent → building/business | 派生店主身份、动用经营账户的权限（事件记 `actedAs`） |
| employed_by 雇佣 | **person（雇员）→ org/agent/business（雇主）** | 工资义务累计；派生工作地与日程片段；雇主消失时标的侧 `estate`（04 §4.3） |
| holds_office 任职 | person/creature → office | exclusive；派生职权、俸禄、额度、称呼；空缺由职位的继任规则处理；地方神职与冥府职位的持有人可以是亡魂或精灵（13 §13.8） |
| appointed 任命 | office(授予者) → office(被设职位) / person | 任命的授予者是职位，故免职不影响任命 |

## 1.4 概念三：义务（Obligation）

**定义**：实体化的承诺。字段：种类、债务人、债权人（可为不记名=持票人，或**开放**：`creditor: {open: true, firstToSatisfy: 谓词}`——悬赏类义务在完成事件发生时才确定债权人，同刻多人完成按争夺裁决（附录 A §A.15；缺省见 14 §14.2 缺省表），不按阶段先后与实体 id；可选 **承接 `claim`**（见下表 bounty 行））、标的（资源与数量，或行动与完成条件）、日程（一次性 / 分期 / 持续累计）、清偿方式、违约规则、担保（pledged 持有）、状态、`accruedTo`（累计到何时）、来源事件、条款快照（签约时冻结，历史合同不随后来的派生改写；含签约地、当时适用的规范栈版本——**只用于效力判定与审计**，宽限、清偿顺序、程序按查询时的栈——、所用历法与换算成天数的期限 `calendar` / `days`、宽限条款、继承后的 `liabilityCap`、以谁的名义签订 `actedAs` 与所用身份键 `inName`）。

**义务种类可声明互斥**：`exclusive: {on: subject | (debtor, subject), among: [义务种类或上位词], policy: forbid | supersede}`——同一标的（车货、人、建筑）同时只能有一条该族义务；`among` 按词汇上位词匹配，所以两个包各自的护送 / 保险义务只要挂在同一上位词（`contract:escort`、`contract:insurance`）下就互斥，不必相知；forbid 在事务内拒绝第二条并给世界内原因（"这批货已有镖局押运"），supersede 关闭旧的（记 cancelled，起因指向新义务）。core 把 escort、delivery、custody 类声明为 forbid；`promise{kind: betrothal}` 声明 `exclusive{on: debtor, among: [promise:betrothal], policy: forbid}`，所以同时与两人订婚在事务内被拒（重婚另由 kin:spouse 的 `incompatibleWith` 挡住）。I8 断言。

**义务种类必须声明的两端消失规则**（04 §4.2；枚举见附录 A §A.4）：
- `onDebtorGone`：`accelerate` / `assume_by_heirs`（限定继承，质押随义务一起走）/ `substitute_performance` / `void`（人身性义务）/ `pursue`（追到亡魂或转生实体，无则 void；13 章）。法典的民事条款可以覆盖种类缺省（05 §5.2）。
- `onCreditorGone`：`estate`（缺省：债权入遗产）/ `void`（以债权人本人为对象的服务）/ `heirs`（直接转给继承人，报恩等）。
- **宽限不是协议缺省**：债务人在途、被困、被羁押、昏迷时，到期与违约**照常**计算；只有规范层的宽限条款（天灾阻断宽限、羁押停息……）或合同条款能延后到期或停止罚息。违约规则读 `grace(obligation, now)` 这一 L1 条款查询（05 §5.2），不读位置或状态。

**票据**：bill、盐引、地契之类可流通的票据 = 义务（或持有）+ 一件代表它的物品个体（`represents` 指向义务）；持票人 = 物品的 owns 持有人，条款 `bearer: true` 的不记名票据则 = 物品的 `possessor`（附录 A §A.15）。以票据结算是"交付票据 + 附条件清偿"，票据兑付或被识破时才最终确定（05 §5.1）。伪造票据是 `purports` 有、`represents` 空的物品，不是义务。

**累计不逐日写**：`amountDue(t) = f(条款, accruedTo, t)` 在读取时按闭式算出；清偿或结息事件把 `accruedTo` 推进。离开 360 天不产生 360 次写入，而且与逐日结果相等。**闭式的时间输入是天数 `days` 或锚计数**：条款金额二选一——`per: day`（输入天数）或 `per: anchor`（按锚计额：每个历法月锚计足一期，不足一期按历法 `rateBasis` 折日，`anchorsBetween` 给出 `{full, remDays}`，统一闭式与算例见附录 A §A.15 期间口径）；"按月"的锚按条款快照所记历法取下一个历法月的同日；闰月的处理、`anchorsBetween` 的确定算法与算例**只在附录 A §A.15 期间与折算口径定义**（本节不另述）；改元改历不改既有义务。

| upkeep 维持（召唤、契约、会费、祭祖、补符） | 持有人 → 组织/召唤物/祖灵/封印 | 持续 | 转移 | 契约终止、欠费除名、断祀、封印衰减 |
| project 工程 | 承建方 → 出资方 | 工期按能做工的日推进；**新建工程开工即 `create(building, condition: 0, status: under_construction)`**，工程进度 = 该建筑 condition 的 `fact.set`（半成品是世界对象：可被看见、烧毁、占分区、按天气损耗，07 §7.3）| 完工事件（`condition` 达设计值、去掉 `under_construction`；修缮同为恢复 condition） | 停工：建筑留在当时 condition 继续损耗 |

**关系**：两端是持有（债权人持有债权、债务人承担债务），转移协议一视同仁；清偿是转移；到期是时钟日程项（缺省时刻为到期日最后一刻，14 §14.2）；违约是事件，是否构成罪名、能否起诉由规范层判定（05 §5.2）。

## 1.5 概念四：地点（Place）

**定义**：包含树上的节点，加路线边。
- 包含树：房间 ⊂ 建筑 ⊂ 聚落 ⊂ 郡 ⊂ 省；野外、矿口、林地、河段、巢穴、关卡也是节点，各有父节点；政体疆域不是树节点，而是 `governs` 持有覆盖的节点集合；异界（阴间）是另一棵子树（13 §13.7）。
- 路线边：陆路、河道、海路、山径；长度、通行方式、季节封闭规则、桥路设施引用。**路线边与分区邻接是地点的慢变事实**：包的 `routes` 只是纪元边界注入的初值；运行期由工程完工事件（运河、修路、架桥的 project 完工 outcomes）、判决、灾害时钟经 `fact.set` 增删改（新建河道边、塌方封闭、改道），不需要预置 condition 为 0 的边。**派生路线**：地点或地区可声明 `derivedRoutes: [{mode: air | sea | overland, when: RX（天气、地形）, costRx}]`，两点间按坐标与 mode 派生隐式边；`move` 的 mode 须由坐骑 / 车船的物种或模板 `capabilities` 支持；隐式边不经节点，因此不经关卡与税表（空运绕关是结构结果）。河段之间的边是有向的（顺流），用于污染与水量传递；河段多条出边时按河段事实 `outflow: [{edge, share}]`（和为 1，缺省均分）分水，闸门、运河等设施以修正项改 share（槽 `hydrology:split`，05 §5.5）。**地点对原语的限制**：地点慢变事实 `primitiveLimits: {vital?: none | bounded(k), create?: none | mark_only, transfer?: none | within}` 由事务校验读所在地点（06 §6.3）——梦境、异界、圣域可声明"不受伤、不造物"，不需要给每个动作打补丁。通往异界或阈限地点的边带 `passage` 条件——**开放的 RX 谓词**，core 预置条件词 `passage:death`、`passage:rite`、`passage:trance`、`passage:dream`，可与时间窗 `window(id)`、持有（`invited`）、物品（引路符）组合；路线边是包的扩展点字段（12 §12.2.3）。**收费与风险不存在边上**：关税与通行费由沿途各节点的规范栈税表与 `controls` 持有（关卡、山寨收买路钱）派生；风险由沿线 `controls` 持有人（首领、山贼、敌军）的威胁、近期 harm 事件密度与天气派生。

**空间与方位**（2026-10-15 用户要求：文字也是有方位的；空间是世界的一部分，不是只为画面准备的数据）：
- **路线边带方位**：每条边存方位（八方位或角度）、距离与通行耗时（耗时仍按通行方式、路况、天气派生修正）。
- **分区**：聚落、建筑、野外节点内部再分为**分区**（zone，地点包含树的叶层：铺面、门口、街心、后院、茶摊、柜台后、山道口……）。分区之间有**邻接边**：方位、距离（步数或丈）、遮挡（墙、门——门的开关是建筑事实——、人群、树丛）、视线等级（通视/部分/无）、声音衰减系数。分区可带事实 `threshold`（门槛，13 §13.4）与 `liminal`（阈限）。分区是地点，账户与持有照旧挂在作为实体的建筑、聚落上。
- **站位**：实体此刻在哪个分区，是**派生投影**：由日程（05 §5.8）、当前活动（正在进行的动作与它占用的分区）、最近一次 move 原语的目标分区得出，不落盘（I10）。玩家与在场 NPC 的分区内移动是 move 原语（分区边耗时，按步计，可被打断）。
- **坐标与网格可选**：分区可带局部坐标、占地、朝向、出入口；地点可带网格尺寸。它们是更细的可选数据，主要给画面客户端（08 §8.8）；规则只读分区粒度。
- **缺数据时自动生成布局**：确定性布局规则按地点类型（集镇、村、寺、山道、码头……）与建筑清单生成分区与邻接（同一战役种子同一结果），保证每个地点都有方位（I30）；作者数据与第三方包（第12章"布局"扩展点）可整体覆盖或补充。
- 相乘：见证与知情按感知判定（下文"在场"）；潜行、偷窃、偷听读站位、遮挡与声音；战斗读分区距离与遮挡；NPC 决策可选择走近或避开；场景文字按方位组织（08 §8.2、§8.5）。

**存**：父节点、坐标、地形、气候带、生物群落、文化（13 §13.2，可被 `place.culture` 槽位覆盖）、路线边（含方位）、分区与邻接（作者数据或生成规则的种子）、设施清单（引用建筑实体）、感官素材（作者数据）、可选的布局细节与素材键（08 §8.8）。

**派生**：
- 法域：从节点向上找最近的被某政体 `governs` 覆盖的节点，得到**主权法典**；找不到 → 数据错误，生成器拒绝创建该节点（不兜底到五村法典）。**途中位置**（"所在路线段 + 进度"）按路线边事实 `jurisdictionRule: from | to | nearest | split(进度阈)`（缺省 `nearest`：取两端节点中按进度较近者）解析到一个节点，再按节点上溯；河道、海路同此（界河可 `split(0.5)`），所以劫道、船上分娩、路上签约的 `normStack` 与行为地都有定义。完整的适用规范是**规范栈**（05 §5.2）：沿包含树收集主权法典、各级次级规范（郡法、镇规、村规，以及第 12 章的地方法典绑定）、行为者的成员规范（门规、戒律、生灵规矩）与有关政体的域外管辖条款，按层级排序。
- 通行性：边的 condition + `controls` 持有的封闭标记 + 季节 + 天气。
- 在场与感知：**不再是"同一地点即见证"**。`perceives(观察者, 事件)` = 视觉（分区路径上的视线等级、距离、光照/昼夜（读历法 `anchors.daylight` 的 `daylight(place, t)`，附录 A §A.15）、天气、遮挡、无形生灵的形态）或听觉（声音强度按动作的音量标签 − 分区边衰减累计 − 环境噪音 ≥ 观察者听力阈）或触觉（同分区接触）；潜行动作的检定结果以修正进入感知阈。见证集合 = 事件发生时满足 perceives 的实体（冻结写入事件）。同一节点内远处、隔墙者可能只"听见动静"（见证版本为不完整的听觉版本）或完全不知道。离屏层级的见证近似见 07 §7.2.1。
- 服务：本地存活的 `operates` 持有 + 营业时间（日程派生；时辰区间左闭右开，端点口径与缺省表在附录 A §A.18）；每个服务提供者的**服务容量**（每日可接次数）由技能阶、助手、设施派生并开放槽 `service:capacity`，超容量的请求按紧迫度排队（附录 A §A.15）。
- 容量：栖地容量、住房容量、仓容（设施 + condition）、**采掘容量**（矿口、巷道、码头等"通道类"设施的 condition 决定资源点的可采量上限，槽 `facilities:extraction`；巷道塌陷 → 可采量 0、储量不变）。
- 人口：`resides` ∪ `resident_of` 持有计数（智能/规则层；持有人为 person 或被视角法域承认人格的 creature）+ 统计层聚合账户。聚落跨过法典 `schedule.settlementRank` 等级线的 `rx`（人口、设施种类与 condition、税基的合取，附录 A §A.7）→ 阈值事件 `threshold_crossed(settlement:rank)`（附录 A §A.15），宽限期满后反应规则 fact.set 行政等级（升降同一机制）；升格申请 = 治理议案，前置读**同一条 `rx`**，通过即不等宽限（09 E03）。
- 聚落同时是地点与实体：地点身份管包含与路线，实体身份管账户（公库、粮仓）、事实（行政等级）、持有（被统治、被管理）。

## 1.6 概念五：账户与转移（Account & Transfer）

**定义**：账户 = (实体, 资源种类, 用途)，存量一个数（整数，单位由资源种类定）；转移 = (来源账户, 去向账户, 资源, 数量, 起因事件)。

**资源种类**（`world/ontology/resources.json`，开放）：
- 货币：各政体的各种铸币各是一种资源，带货币事实 `money: {metal, fineness, weight, issuer, backedBy?}`（金属、成色、重量、发行者；`metal: none` 的信用货币——可兑现纸币、冥币——另带 `backedBy`，定价走 15 §15.3 的信用分支）。**没有固定换算**：计价单位由法域法典指定，铜银金之间的比价是市场投影（15 §15.3）；兑换是两笔带手续费的转移；合同只记资源种类与数量。私铸的"轻钱"与伪币不是另一种资源种类的必然：core 铸币声明 `lots: true`，批次的 `origin`（铸造事件、铸造者、`counterfeit`）与 `purports`（自称的成色档）表达它们（下文"批次"）；作者数据也可把轻钱声明为单独的资源种类（`issuer: none`，成色低）。
- 可计量物品：按物品模板（item_wood、item_iron_ore、item_bread……）；物品个体（有编号的杰作、书、契据、车船、署名成品）不是数量，是实体，用 `owns` 归属，用位置事实定位（视图谓词 `located(x)`，§1.2）。
- 粮（foodUnit）、木材、矿石储量、药材、水量、水质指标、污染量、香火、贡献度、怨气、灵力、封印强度、种群数量（物种×地点）、饲草、燃料。
- 身体资源不是账户：生命、魔力与**身体需求量**（体力、饱食、口渴、疲劳，附录 A §A.15）是慢变事实（钳制在 0..上限），由 `vital` 原语改（需求量用 `type: body:<need>`，按活动类闭式消耗、进食与睡眠恢复）；食物资源种类带 `nutrition: {satiety, hydration}`。

**批次**：资源种类可声明 `lots: true`（粮、药材、鲜货、酒、灵丝、皮毛等会腐坏、陈化或需要追溯来源的东西； core 铸币也声明 lots，见下）。此时账户键扩展为 (实体, 资源, 用途, 批次)，批次带元数据：入库日、品质、暴露量（受潮、受热累计）、**`origin`**（产地、物种、来源事件；铸币为铸造事件、铸造者、`counterfeit` 标记）、**`taint`**（赃物 / 违禁来源的份额，来源事件引用）与 **`purports`**（该批次自称的资源种类或成色档，缺省等于真实；持有者的主观视图按它显示，除非知情集合含 origin 事件或鉴定事件；结算永远按真实种类，附录 A §A.15）。批次不是实体，只是账户键的一部分；它的元数据只能经 fact.set 的批次白名单字段（品质、暴露量、掺假动作写 purports）或转移时自动携带；批次合并时品质取加权、taint 按比例传播、purports 不同者不合并。**`taint` 的写入者**：只有 legal 类反应规则——嫌疑记录成立（05 §5.2.7）且该事件携带取得批次的 transfer 时，同一反应对该批次 `fact.set(taint: {share: 1, event})`；此后转移、拆分、合并按比例自动携带，配方产物继承投入的加权 taint（加工不洗白）；屠宰、拆解走 `src:harvest` / 配方时同此。taint 是真相，不读知情；销赃罪名 `offense:fencing` 另读 `knows(actor, origin 事件)`，善意取得按民事⑨。转移缺省先进先出，也可指定批次。腐坏是时钟规则：按资源种类的保质曲线（入库日、温湿度、暴露量）闭式算出应腐坏数量，转移到 `sink:decay`（I1 守恒、I14 精确等价）。市场投影按品质档聚合批次。**铸币的批次**按 (发行者, 成色档, purports) 合并，正常铸币全部落在一个批次里，所以批次数不膨胀；私铸轻钱与伪币各成批次。未声明 `lots` 的资源（矿石、水量）仍是一个数，不跟踪来源（追赃靠赔偿义务与判决金额，15 §15.9）。

**群体子账户**：种群与统计层人口可以按状态拆成子账户（例如疫病的易感/感染/康复 = 用途 `disease:<病种>:S|I|R`、未安息亡者 `pop:unrested_dead`），总数是子账户之和（05 §5.5、07 §7.3、13 §13.7）。

**源汇账户**（显式、可审计）：`src:regrowth`（再生：资源点储量，含田地的作物储量按积温流入，05 §5.5）、`src:birth`（生育/繁殖）、`src:weather`（降水；流入量经槽 `weather:precipitation`，附录 A §A.16）、`src:mint`（铸币；使用者由法典认可条款 `recognition.issuers.mint` 给出，缺省只有发行政体，附录 A §A.7）、`sink:melt`（回炉 / 退出流通的铸币；与 `src:mint` 构成**改铸守恒对**：同一事务内按金属含量等量从 `src:mint` 流入新币，审计要求金属量相等，15 §15.3）、**`src:craft`**（**制造源**——工坊、厨房、酿造、私铸等按配方的计量产出；只能由引用了某条配方的生产规则或动作使用，与配方声明的投入消耗（transfer → `sink:consume`，或投入物料直接计入产物）在同一事务内构成**制造守恒对**：审计要求产出量 = 配方 `yields` 对投入量的函数，不得多产；配方是数据 `backedBy.ratio` 转入其 `reserve` 用途账户（纯信用货币 ratio 为 0，则只记发行量）；兑付 = 货币 → `sink:redeem` 并从准备金转出挂钩铸币；`issued(currency)` = Σ 发行 − Σ 兑付，`reserveRatio` = 准备金 ÷ issued；使用者由 `recognition.issuers.notes` 给出；超发不被 `offense:overissue`）、`sink:consume`（消耗）、`sink:decay`（损耗/腐烂）、`sink:destroy`（损毁/烧毁）、`sink:death`（死亡）、`sink:export`（离开模拟范围）、`src:genesis`（作者数据与包安装的初始存量，受合理性表约束）、`src:pack_converted` / `sink:pack_removed`（包升级、卸载时的折算与移除，见第12章 §12.5）、`sink:offering` / `src:offering_realm`（供奉焚化的守恒对：同一事务内两笔等量转移，审计要求两者逐资源相等，13 §13.4）、`src:harvest`（**只能由 transition 事件（death / destruction / extinction）触发的反应规则引用**：按物种或物品模板的 `yields.death` 表把皮、鳞、胆、残木、废铁流入残骸实体的账户）、**`src:husbandry`**（**活体产物源**——时钟规则按物种 `yields.alive`（13 §13.3：`{resource, perHeadPerDay: RX（季节、饲草充足度）, mode: passive | action}`）× 头数闭式流入 owns 持有人指定的账户（缺省畜群所在建筑的库存：鸡窝里的蛋）；`mode: action` 的（挤奶、剪毛）只在引用本源的动作里流入；**人口副产物同源**：person 的物种数据（`ecology/species.json` 的 `person` 行）可声明 `yields.alive`（夜香、灰烬等），按 `resides` 该建筑的人数 × `perHeadPerDay` 流入**所居建筑**的账户（无 owns 持有人时以居所为缺省账户），统计层按 `resident_of` 计数聚合——于是粪肥有源、清洁术取代挑粪工可算；每条规则声明每日预算，统计层 `aggregate: auto`）、**`sink:individuated` / `src:aggregated`**（**个体化守恒对**——种群账户的一个计量单位变成 creature 实体（捕获、驯化、化形显形、被命名）时，同一事务内 population −1 → `sink:individuated` 并 `create(creature)`；反向（放归、并群、化形者回归种群）= creature `transition(gone, basis: aggregated)` 并 population +1 ← `src:aggregated`；审计要求两端计数相等；与 07 §7.3 人口的借出并回同形。繁殖的 `create(creature)` 仍经 `src:birth`）。再生不是凭空加数，是从 `src:regrowth` 按规则流入；烧掉的粮是转移到 `sink:destroy`。**污染没有独立的源**：污染物是带 `pollutant` 标签的资源（酒糟、矿渣、粪水），只经配方 `byproducts`、`yields.alive` 副产物（经 `src:husbandry`）或灾害 `fact.set` 进入账户，倾倒 = transfer 到河段 / 地块实体的账户，水质与土壤派生读带该标签的存量并顺流传递（05 §5.5）。于是守恒机械可验，"盗采也扣储量"不需要任何人记得——矿脉只有一个账户。**每条使用 `src:*` 的规则声明每日总量预算**（12 §12.8.3），超出即熔断。**写入权**：开放提案（玩家构造器、LLM 的 `world_propose`）不得以 `src:*` 为来源；`sink:*` 只能作为发起者自有资源的去向（消耗、销毁）；`src:*` 只能由注册时声明了该源的时钟规则、反应规则或**注册动作**引用（制作动作引用 `src:craft` 且必须指明配方，铸币与发行动作引用 `src:mint` / `src:issue` 且受认可条目 `issuers` 限制）——即兴制作走 `create` 的"即兴制作"规则或路由到配方动作，不能凭空产出计量物。

**承租人在所租建筑内的存货**：`leases` 持有人放在标的建筑内的计量物记在**承租人实体**的账户、用途 `stored:<building id>`（不是建筑账户），价值位置取该建筑（15 §15.1.1），租约关闭后按民事⑥ `lien` / ⑩ 无人认领处置；寄存（bailment）才记在保管人建筑账户的 `held:*`。两者的分工：谁有处分权就记在谁的账户上。

**消失实体的账户**：实体 gone 时其账户必须由承接实体（遗产、清算、残骸）接走或转入对应的汇（04 §4.2 第 2 步），I6 对账户同样断言。

**禁止**：任何代码直接改存量；任何实体同一资源同一用途有两个账户（组织公库与首领私囊是两个实体的账户；势力时钟公库与组织公库必须是同一账户——V4 已经这样做）。

**派生**：价格、汇率、利率、银根、短缺、财富区间、公库能否拨款、股份价值（组织净资产 × 份额）、可采量、害兽压力、识字率之外的一切"有多少"（15 章）。

## 1.7 概念六：事件（Event）

**定义**：唯一的写入载体，追加不改。字段：编号、**序号 `seq`**（全局单调，14 §14.2）、时间、**纪元 `epoch`**、动词、发起者、**`actedAs`**（以谁的名义、经哪条持有的权能，05 §5.3；**可见性随事件**：公开事件的 actedAs 对见证者可见——以职位名义的签字人人看得见；事件 `private` 或 actedAs 标 `private`（匿名代理、暗中代办）时只进当事人知情，见证者只看到行为者本人；委托义务本身 visibility 仅当事人）、对象、主体、地点、起因事件 `causes: [{event, weight}]`（主因在首位，权重之和为 1；幂等键用主因；归因系数沿各因分配，05 §5.6。**多因权重的缺省算法**：规则或动作可声明 `causeWeights: RX`；未声明时，若各因对结果量有可度量的贡献（heal 的 delta、伤害量、转移数量）按贡献占比分配，否则按时间倒序以 `1/2^k` 衰减后归一（最近的因为主因）；时钟规则的 `causes` 选择器同此；归功、归责、悬赏 `firstToSatisfy` 的拆分都读这一权重）、携带的原语列表（转移、持有变更、事实变更）、见证人（由感知派生 perceives，§1.5，事件发生时冻结写入，可带"只听见/只看见"的不完整版本）、可见性（公开/私密/仅成员）、**显著度**（`salience`，0..1 定点数，归约时按附录 A §A.15 的公式冻结写入）、标签（性状、罪名 offense:*、harm/gift、工具/动作来源）、提案原文（动作层：意图文本、原语提案、骰值）。

**与现状的方向相反**：现状是"工具改状态 → 事后从前后差分推导世界事件"（K3 deriveWorldEvents）；目标是"提案 → 事件 → 归约出状态"。迁移期两者并存（见 10 迁移路线），迁移完成后差分推导只剩校验用途。

**幂等与起因链**：每个事件带起因；同一起因对同一规则只触发一次（幂等键 = 规则 × 起因事件）。这是"旱灾和污染各自结算、产量被重复扣减"类错误的机制性解法：产量派生只读一次输入，反应规则对同一起因只发一次。

**转述也是事件**：`tell(讲者, 听者, 说法版本, 源, 通道)`。源可以是事件（见证后转述）、`belief` 事件（讲者自己的推测）或文书物品（阅读）；通道见附录 A §A.8（含托梦、神谕、异象）。失真发生在转述事件上（由讲者性格与立场的失真表生成），不在谁的脑子里。谎言是带 `lie` 标签的转述，真相链接保留（U8 已有雏形）。

**信念也是事件**：`belief(持有者, 命题, 置信度, 依据)` 由推断规则产生（05 §5.4），可错，只进入持有者的主观视图；它永远不改变真实状态，也不能触发 transition（I26）。

**阈值跨越也是事件**：派生值跨过声明的阈值时，框架发 `threshold_crossed{thresholdId, entity, from, to}`（附录 A §A.15）；它是钩子与反应规则唯一能订阅"派生值变了"的方式，派生值本身仍不落盘。

**市况也是事件**：每个有市集的聚落每个集日发一条公开的 `market_report`（当日报价快照，显著度按变动幅度），它是 NPC 得知异地价格的唯一来源（05 §5.4）。

**派生**：NPC 记忆与知情集合、主观视图、传闻、编年史、立场、名声、案件证据、隐藏职业契机、灵智成长、作品传播、历史。

## 1.8 概念七：规则（Rule）

四种形状，全部只读视图、只产提案：

1. **派生规则**：纯函数 `视图 → 值`。法域、价格、俸禄、权限、产量、感染率、同意能力、日程、称呼、效力。查表部分是数据（俸禄表、税表、容量表），组合是代码。派生函数属 L1（03 §3.1）。
2. **反应规则**：`当 事件匹配(动词/标签/地点谓词/参与者谓词) 则 效果原语列表`，并声明优先级类（附录 A §A.5）与索引键（07 §7.5）。火势蔓延、征税、立案、立场印象、传闻生成、停工、追随者分流都是反应规则；条件与参数是数据（JSON 谓词 DSL），原语执行是代码。
3. **时钟规则**：`每 日/月/季/年，在 层级（智能/规则/统计），对 某类实体 执行 效果原语`，并声明 `closedForm`（可一次算 N 天）或 `tolerance`（迭代近似的容差）；概率型规则可声明 `paceable`（受世界节奏，14 §14.8）与 `major`（与玩家相关的重大事件，慢档下有预兆并延后）；声明 **`causes`**（输出事件的起因选择器：规则读到的最近相关事件——设施 condition 变更、未完工 project、天气；缺省为规则读取的输入事件），使概率型事件（溃堤、火灾）的起因链能被归责与归因读到。"月 / 季 / 年"按历法投影取锚（§1.9）。
4. **动作规则**：玩家或 NPC 可发起的规则：参与者槽位、前置条件、同意、代价、检定、按档位的效果原语、可见性、叙述模板（详见 06 动作层）；仪式是带 `rite` 块的动作（13 §13.5）。

**四种声明式规则形状**。它们都由上面四种规则执行，存放在已有概念里（法典与章程是组织实体的事实，修正项、推断规则、自治候选是包数据），**不是新的存储概念**，但属于新增的规则形状，必须有固定 schema：

| 形状 | 是什么 | 谁执行 | 存在哪 | 详见 |
|---|---|---|---|---|
| 规范条目 norm clause（含补丁） | (来源组织或包, 适用谓词, 层级, 内容：`clause:*` 族——罪名谓词 / 民事条款 / 程序条款 / 税表 / 授权表 / 豁免 / 认可……)；补丁是对任何已注册定义（条款、动作前置、持有不相容、义务条款范围）选中结果的受控修改（05 §5.2.8） | L1 规范栈解析（派生）+ 法律包立案（反应）+ 各包读条款（派生） | 政体、治理组织、门派、寺院、冥府等组织实体的"法典/章程"事实；第三方包的法典与补丁（见第12章） | 05 §5.2 |
| 修正项 modifier | `{target: 派生的修正槽, when: 谓词, stage: add|mul|max|min, value}` | 派生规则在合成时按槽位声明的阶段顺序应用（附录 A §A.9、§A.16） | 包数据 | 05 §5.9 |
| 推断规则 inference | `{premise: 期望未发生 / 观测到异常 的谓词（读主观视图）, candidates: [命题, 按性格的权重], confidence}` | 反应或时钟规则，唯一允许的输出是 `belief` 事件 | 包数据 | 05 §5.4 |
| 自治候选 autonomy candidate | `{need, goal, action, applicability, utility, risk, horizon}`：某种需求下 NPC 或组织可能自己选择的动作 | 自治包的决策时钟读全部已注册候选 | 包数据 | 05 §5.7 |

**效果原语**是规则能做的全部动作（完整表见 06 §6.3，枚举见附录 A §A.6）。指南 7.6 的法术原语、K2 交互表、K6 效果表都是它的子集或参数表。

**提案与事务**：规则产出提案 → 内核在一个事务里解析引用、校验不变量、执行原语、写事件；失败整体回滚并返回可改正的错误（给工具/LLM/界面）。事务的嵌套与同刻顺序见 14 §14.2–§14.3。

## 1.9 概念八：时钟（Clock）

**定义**：单一世界时间（分钟）+ 到期日程堆 + 各地区的模拟层级与"已结算到何时"+ 世界节奏档位（14 §14.8）+ **历法数据**（附录 A §A.15：`world/ontology/calendar.json`——月序与月长、闰月规则、年号序列、节庆锚；可多部，法域经 `recognition.calendar` 选用；月、年、节日、年号都是投影，时钟本身只认分钟，I13 / I31 不受历法影响）。

**到期项**：义务分期、时钟规则下次唤醒、势力计划阶段、再生检查点、作物生长阶段、案件程序期限、空缺补选期限、许可到期、效果到期、托养到期、封印维护到期、批复期限、预兆后的延后事件。

**推进 N 天** = 逐刻按 14 §14.2 的五个阶段处理：依次弹出到期项（每项产生事件）→ 各地区按层级把时钟规则补算到当前时刻（闭式一次算，迭代按步长）→ 反应级联 → 断言；没有到期项且没有时钟规则的东西不会被碰。这是离屏便宜的根本原因，也是"回放一致"与"同刻全序"（I31）的基础：到期项顺序确定，骰值由战役种子 + 规则 + 对象 + 时刻 + 序号决定。

**层级**沿用指南 5.9 与 P3 的三层：智能层（玩家所在郡及相邻）、规则层（同省/两跳）、统计层（更远）。层级由注意距离派生，不写进人物；各层运行什么见 07 §7.2.1。

## 1.11 存与派生的分界（给校验器的规则）

- **存**：只因事件改变的量——存量、condition、熟练度、健康、灵智成长、起止时间、条款快照、`accruedTo`、程序阶段、计划、作者文本。
- **派生**：因"当前是谁 / 在哪 / 属于谁 / 何时"而变的量。黑名单**按记录类别（实体种类或存档 category）限定**，不是裸字段名：例如 `settlement.population`、`person.salary`、`office.powers`、`creature.situation`、`location.jurisdiction`。存档快照与包数据出现这类 (类别, 字段) 即校验失败；core 作者数据（world/）中的历史字段（如 `locations.residents`、`settlements.jurisdiction`）**不重写**（11 §11.1），由转换器忽略，转换报告列出"作者值 vs 派生值"的差异供内容校正（A1 名单起草初始黑名单，S0 已落为 `world/ontology/derived-fields.json`）。
- **覆盖**：确需手填的，字段名加 `override`，附理由；视图输出附来源标记 `authored | override | derived | cached`。
- **缓存**：投影缓存允许，但带版本键（依赖的持有种类/账户/事件动词各有版本号），测试随机重建比对（02 不变量 I17）。

## 1.12 与候选概念清单的取舍

- "职位/角色"：不是独立概念，是实体种类 office + 持有 holds_office。理由：职权属于职位而非人（Crusader Kings 的头衔模型），任命由职位发出，这样免职不影响任命、死亡不带走职权。地方神职（城隍、土地）同样是职位（13 §13.8）。
- "市场"：不是存储概念，是账户+路线上的投影。理由：价格一旦存储就会和存量脱节（run-001 的"议和当场恢复物价"正是存了价格状态的结果）。货币、汇率、利率同理（15 章）。
- "辖区"：不是概念，是地点树上的派生。
- "资源存量与流量"：合并为账户与转移；"流量"就是按日程发生的转移序列。
- "关系"：拆为持有（结构）与立场投影（态度）。
- "效果"：不是概念，是规则的输出词汇（原语）。
- "动作"：是规则的第四种形状，不另立概念。
- "规范层""主观视图""修正项""自治候选"：不是存储概念。规范条目存为组织实体的法典/章程事实；主观视图是知情集合 + belief 事件之上的投影；修正项与自治候选是包数据。它们是新增的**规则形状**（§1.8），理由：没有它们，新禁令、新影响因素、谣言驱动的行为、NPC 主动选择新动作都只能靠改别的包的代码实现，违背"包靠词汇相乘"。
- "批次"：不是实体，是可腐坏或需追溯来源的资源的账户键维度（§1.6）；批次的 `purports` 让可替代物也有"表象"，与物品个体的 `purports` 同一思路。
- "受限 / 拘留"：不是状态，是持有 `guest_of{detained}` 派生的形态（附录 A §A.3）。理由：被关的人仍能思考、说话、同意、签约、结社、脱逃；把它做成失能状态会让监狱玩法消失。失能只留给"不能思考与同意"的情形。
- "配方"：不是概念，是数据表（§1.6 `src:craft` 的守恒对参数）。理由：制造产出必须有源，但源只有一个（`src:craft`），差别全在配方。
- "职能有效"：不是存储字段，是对持有的派生（附录 A §A.15 `effective()`）。理由：持有的存续（交接类）与持有的可用（在场、未失能、未受限、未停职）是两件事；混在一起就会出现"被拘留的官员照领俸禄"。
- "文化圈"：不是实体，是标签层级 + 文化数据记录（13 §13.2）；文化不行动、不持有。
- "计划"（NPC 多步图谋）：不是实体，是 NPC 的慢变事实（05 §5.7.2）；每一步仍是普通动作。
- "亡魂"：不是原实体的状态，是带 `soulOf` 的新实体（13 §13.7），所以转移协议不变。
- "历法""年号"：不是概念，是时钟之上的数据与投影（附录 A §A.15）。理由：时钟只认分钟才能守住 I13 / I31；月与年是人为约定，各政体可不同。
- "身份 / 化名"：不是实体，是人的身份键事实 + 观察者的 `identify()` 派生。理由：真相只有一个实体才能守住守恒与义务两端；"别人以为他是谁"是视角问题。
- "视角"：不是概念，是读 API 的参数（附录 A §A.15）。理由：主观视图、规范栈、行为时法、聚合变体本来就是同一件事的四个轴，合成一个参数后，新的"按谁看"需求不再各造一套。
- "钩子"：不是第五种规则形状，是持有 / 义务 / 实体种类注册的字段。理由：它只在协议事务内运行、只产原语，与交接类同性质；有了它，"触发"不必再增加。
- "估值"：不是每类东西各一个派生，是一个派生加一张表。理由：当铺、拍卖、遗产、地价、畜价、工价读同一来源才不会互相矛盾。
- "行为能力""效力""占有""执行人"：都不是存储字段，是派生（附录 A §A.15）。理由：失智、未成年、附身、越权、无权处分在世界里都**确实发生了**行为，内核只记事件与标签，"算不算数"由法域求值——与承认同一思路；若在事务里拒绝，这些玩法（争产、追索、善意取得）就不存在。
- "阈值事件"：不是新概念，是框架对派生值的一种事件（附录 A §A.15）。理由：成年、降级、破产线需要挂点，但派生值不能落盘；事件是唯一写入载体，所以挂点只能是事件。
- "物种"：普通动物与超自然生灵是同一种数据。理由：差别只在 `origin` 与是否要出处，机制（繁殖、产物、相互作用、估值）相同。
