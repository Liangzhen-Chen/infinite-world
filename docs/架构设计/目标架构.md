## 0.1 一页摘要

**八个核心概念（存储层只认这八样）**：实体、持有、义务、地点、账户与转移、事件、规则、时钟。其余一切——身份、权限、俸禄、额度、税率、价格、法域、立场、知情、日程、称呼、人口、识字率、服务、可做之事——都是读取时从这八样派生出来的投影，禁止落盘。

**一句话模型**：世界是一张图。节点是实体（人、精怪、种群、物品、建筑、聚落、组织、职位、遗产、案件、资源点都是实体）；边是"持有"（谁持有什么、从何时起、按什么条款、持有人消失时怎么交接）和"义务"（谁欠谁什么、按什么日程清偿）；一切价值放在账户里、只能靠"转移"移动；一切变化都是事件；规则只读视图、只产提案；时钟只在到期点唤醒规则。

**动作层的两层结构（用户决定）**：
- 不接入 LLM = 注册动作（纯引擎结算）+ 动作构造器（玩家选"做什么/对谁/用什么/怎么做"，组合为效果原语）+ A 式快捷按钮；对话、交涉、战斗、治理、法律、经营全部可玩。
- 接入 LLM = 玩家自由叙述意图，LLM 翻译成效果原语提案；引擎校验裁剪、派生难度与上限、d20 裁决、按档位应用；LLM 再叙述。
- 两层共用同一套原语、校验与裁决，写同一套事件；叙述只是投影。动作清单不是自由的上限：未注册的意图走通用原语组合，频繁出现的组合回流为注册动作。

**最关键的不变量**（第 2 章共 20 条）：
1. 守恒：每笔价值变化都是账户到账户的转移，自然的产出与消耗是显式的源汇账户，任意两时刻全局账目平。
2. 单一写入点：状态只在内核归约事件时改变；规则、玩法包、工具、LLM、界面都只能提交提案。
3. 每种持有声明交接规则；转移协议执行后，消失/被免者名下没有任何存活的持有与权能；义务两端永远解析到存活实体或遗产/案件托管。
4. 由身份、归属、所在地、季节决定的值一律派生；存储层对这类字段设黑名单，手填只能作标注的覆盖项。
5. 每个地点都能沿包含树解析出法域；每条"某人知道某事"都能追溯到见证或一条转述链；每个提案的每个原语幅度 ≤ 规则与状态派生的上限。

**与现状最大的三处不同**：
1. **职位、遗产、案件、资源点是实体，不是人物或地点的字段。** 职权属于职位，人只是持有人；死者的财产和债务进遗产这个实体；矿脉、林地、河段各有账户。于是"死亡"只在一处处理（转移协议），而不是 115 个模块各处理一份。
2. **只有一本账，而且先有事件后有状态。** 钱、物、粮、木、矿、水质、种群数量都是账户存量，只能靠转移改变；价格、短缺、税、利息、租金、工资全是对这本账的派生或按日程到期的义务，22 处价格计算、41 处债务处理合并为一个市场投影和若干义务种类。现状是"处理器改状态 → 事后差分推导事件"，目标是"提案 → 事件 → 归约状态"。
3. **玩法系统不再互相调用，动作不再塞进大工具。** 每个系统是一个包：声明持有种类、义务种类、资源种类、派生规则、订阅标签、时钟规则、动作；包之间只通过共享词汇相乘，新内容只写数据。25 个工具 × 265 个操作改为 ≤ 16 个工具 + 数据声明的动作目录（场景检索暴露），界面与 LLM 都从同一目录取动作。

## 0.2 核心概念速览

| 概念 | 一句话 | 存 | 派生（禁止存） |
|---|---|---|---|
| 实体 | 有永久编号的一切，按模板决定能挂什么 | 编号、种类、不可变与慢变事实、作者文本 | 称呼、职称、权限、额度、俸禄、服务、日程、法域、立场、人口、识字率、成年 |
| 持有 | 有向带时间的边：谁持有什么、按什么条款、怎么交接 | 两端、种类、条款、授予者、起止、终止原因 | 身份、权限、居住地、工作地、可进入处、立场传导路径 |
| 义务 | 实体化的承诺：债务人、债权人、日程、清偿、违约、担保、accruedTo | 条款快照与状态 | 累计金额（闭式）、到期提醒、欠薪停工 |
| 地点 | 包含树 + 路线边（河段有向） | 父节点、坐标、地形、路线、设施 condition | 法域、通行性、在场、服务、容量、人口 |
| 账户与转移 | (实体, 资源, 用途) 的存量；转移是唯一改法；源汇显式 | 存量、转移记录（在事件里） | 价格、短缺、财富、可拨款、股份价值、可采量 |
| 事件 | 唯一写入载体，带起因、见证、原语、提案原文 | 全部 | 记忆、知情、传闻、立场、编年史、名声、证据 |
| 规则 | 派生 / 反应 / 时钟 / 动作 四种形状，只读视图只产提案 | 数据表与代码 | — |
| 时钟 | 单一时间 + 到期日程堆 + 地区层级 | 时刻、日程、地区进度 | 层级（按注意距离） |

## 0.3 玩法包与动作的标准形状（摘要）

包 = 词汇扩展 + 持有种类 + 义务种类 + 派生规则 + 反应规则 + 时钟规则 + 动作 + 数据 + 测试；只读视图，只产提案；包之间不 import（第 3 章）。动作 = 参与者 + 槽位 + 前置 + 同意 + 代价 + 检定 + 五档效果原语 + 可见性 + 叙述模板 + 同义词（第 6 章 §6.4）。效果原语 18 个、12 族：transfer、holding.open/close/transfer、obligation.create/settle/cancel、fact.set、vital、status、move、create、destroy、emit(tell/impress/request)、schedule、transition、learn、time（§6.3）。

## 0.4 走查结论与迁移摘要

- run-001 的 20 个事件全部由八个概念 + 转移协议 + 投影 + 动作层算出；需要新增的全是数据（法典条款、章程、速率表、失真表、模板），没有一处需要新核心概念（第 9 章）。
- 迁移绞杀式，每阶段只迁一个概念，双写对账，基线 23 项预期失败不动；动作层与界面从 S0/A1 起并行（第 10 章）：S0 骨架与度量 → A1 动作目录与界面可操作 ∥ S1 账本 → S2 持有与协议 → A2 对话与 NPC 决策 → S3 义务 → A3 原语与开放动作 → S4 地点与法域 → S5 市场与生态 → S6 知情 → A4 学习回路 → S7 离屏与存档 → S8 收尾。
- 验收：每阶段复跑 run-001r + 新题，合理率为架构指标（目标 S2 后相关题 ≥ 80%，收尾 ≥ 85%）；意图语料三档验证（路由 ≥ 90%、签名 ≥ 85%、越界 0 漏网）；指南 11.3 的 L/T/S/F 场景改为无 LLM 的确定性测试。

## 0.5 最难的部分（第 11 章）

跨法典的清偿/继承/冲突法数据完整性；开放动作的裁剪与平衡；离屏等价（耦合迭代规则只能容差等价）；绞杀式迁移的双写期归因；派生读的性能（版本键缓存）；自治包决策输入的合理性；无 LLM 对话模板的覆盖面。
