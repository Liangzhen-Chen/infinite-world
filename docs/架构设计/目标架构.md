## 0.1 一页摘要

**八个核心概念（存储层只认这八样）**：实体、持有、义务、地点、账户与转移、事件、规则、时钟。规则有四种形状（派生/反应/时钟/动作），另有四种声明式规则形状（规范条目含补丁、修正项、推断规则、自治候选），存放在已有概念里（01 §1.8）。其余一切——身份、权限、俸禄、额度、税率、价格、汇率、利率、法域、立场、知情、日程、称呼、人口、识字率、服务、生灵处境、可做之事——都是读取时从这八样派生出来的投影，禁止落盘。

**一句话模型**：世界是一张图。节点是实体（人、生灵、种群、物品、建筑、聚落、组织、职位、遗产、案件、议案、资源点、残骸都是实体）；边是"持有"（谁持有什么、从何时起、按什么条款、持有人消失时怎么交接）和"义务"（谁欠谁什么、按什么日程清偿）；一切价值放在账户里、只能靠"转移"移动，而且价值有位置；一切变化都是事件，事件有全序；规则只读视图、只产提案；时钟只在到期点唤醒规则。

**动作层的两层结构（用户决定）**：
- 不接入 LLM = 注册动作（纯引擎结算）+ 动作构造器（玩家选"做什么/对谁/用什么/怎么做"，组合为效果原语）+ A 式快捷按钮；对话、交涉、战斗、治理、法律、经营、仪式全部可玩。
- 接入 LLM = 玩家自由叙述意图，LLM 翻译成效果原语提案；引擎校验裁剪、派生难度与上限、d20 裁决、按档位应用；LLM 再叙述。
- 两层共用同一套原语、校验与裁决，写同一套事件；叙述只是投影。动作清单不是自由的上限：未注册的意图走通用原语组合，频繁出现的组合回流为注册动作。

**最关键的不变量**（第 2 章共 32 条）：
1. 守恒：每笔价值变化都是账户到账户的转移，自然的产出与消耗是显式的源汇账户，任意两时刻全局账目平；账户永不为负。
2. 单一写入点：状态只在内核归约事件时改变；规则、玩法包、工具、LLM、界面都只能提交提案；L4 是唯一的提交入口。
3. 转移只有两条协议（实体消失、持有变更），一切后续是持有 / 义务 / 实体种类声明的**钩子**；协议执行后，消失/被免者名下没有任何存活的持有、权能、日程与账户；义务两端永远解析到存活实体、承接实体或开放债权人占位。
4. 由身份、归属、所在地、季节决定的值一律派生；存储层对这类字段按记录类别设黑名单，手填只能作标注的覆盖项；历法、身份键、物种、估值、单位都是数据，不是核心公式的分支。
5. 一切"在谁看来、在哪个法域、什么时候、在哪一层"有效的问题都是**视角 frame** 下的派生（附录 A §A.15）：NPC 与玩家的决策只读主观视图（自知域只含此刻能直接感知的；可观测域；知情域；先验域），他人按认出的身份键出现，传闻与信念永不改变事实，立场的传导也只沿持有者知道的持有；规范按固定层级叠加（合同、次级、主权、成员、属人）并经受控的补丁，外地的持有、凭证、货币、认证是否算数由法典承认条目决定；罪与效力按行为时、程序按查询时；义务不因在途、失能或受限（拘留）自动暂停，宽限只来自法典或合同。
6. 每个地点都有分区与方位，见证由感知派生；每个地点都能沿包含树解析出法域；每条"某人知道某事"都能追溯到五种来源之一；每个提案的每个原语幅度 ≤ 规则与状态派生的上限；给定存档与输入，事件序列逐字节确定；节奏档位只改概率与频率，不改因果。

**与现状最大的三处不同**：
1. **职位、遗产、案件、议案、资源点、残骸是实体，不是人物或地点的字段。** 职权属于职位，人只是持有人；死者的财产和债务进遗产这个实体并按程序阶段清偿分配；矿脉、林地、河段各有账户。于是"死亡"只在一处处理（转移协议），而不是 115 个模块各处理一份。
2. **只有一本账，而且先有事件后有状态。** 钱、物、粮、木、矿、水质、种群数量、香火、怨气都是账户存量，只能靠转移改变；价格、汇率、利率、短缺、税、租金、工资全是对这本账的派生或按日程到期的义务，22 处价格计算、41 处债务处理合并为一个市场投影和若干义务种类。现状是"处理器改状态 → 事后差分推导事件"，目标是"提案 → 事件 → 归约状态"。
3. **玩法系统不再互相调用，动作不再塞进大工具。** 每个系统是一个包：声明持有种类、义务种类、资源种类、扩展事实、派生规则、订阅标签、时钟规则、动作、规范条目与补丁、修正项、推断规则、自治候选；包之间只通过共享词汇、修正槽与扩展事实相乘，新内容只写数据。25 个工具 × 242 个操作改为 ≤ 16 个工具 + 数据声明的动作目录（场景检索暴露），界面与 LLM 都从同一目录取动作。

## 0.3 玩法包与动作的标准形状（摘要）

包 = 词汇扩展 + 持有种类（含钩子）+ 义务种类 + 扩展事实 + 派生规则 + 反应规则 + 时钟规则 + 动作 + 规范条目与补丁 + 修正项 + 推断规则 + 自治候选 + 数据表（物种、配方、估值、历法……）+ 测试；只读视图，只产提案；包之间不 import，只经八种连接点相乘（第 3 章）；扩展缺省开放（附录 A §A.9 开放性宪章：表、族、派生、定义补丁、钩子），core 派生值的 bounds 与候选输入写在契约附表 B/C（附录 A §A.16–§A.17）。动作 = 参与者 + 槽位 + 前置（含他包补丁追加的前置）+ 同意（裁决输入，附录 A §A.15） + 代价 + 检定 + 五档效果原语 + 可见性 + 叙述模板 + 同义词 + `patchable`（+ 仪式块）（第 6 章 §6.4、第 13 章 §13.5）。效果原语 **19 个、14 族**（附录 A §A.6）：transfer、holding.open/close/transfer/rescale、obligation.create/settle/cancel、fact.set、vital、status、move、create、destroy、emit(tell/impress/request)、schedule、transition、learn、time（06 §6.3）。
