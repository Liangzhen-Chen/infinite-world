本章在目标架构定稿后读 docs/system-map.json、server-plugin/、extension/ 写成，回答：现有 186 个模块、70 余种 state.records 类别、25 个工具落到目标的哪一层哪个概念；哪些保留、改造、替换；怎样分阶段迁移并保持全部现有测试与基线 23 项预期失败不变；怎样用事件推演合理率与意图语料验收。

## 10.1 现状结构（代码事实）

- 规模：server-plugin 186 模块约 2.92 万行；extension 2,034 行；tests 272 个测试文件；world/meta/rules.json 51 个顶层规则块（389KB）；world 数据 455 地点、459 路线、12 聚落档、251 家户、548 名册、275 完整档、49 势力。
- 内核：storage.mjs（CampaignStorage、PatchCursor、事件日志 + 快照 + 原子写）；engine.mjs（WorldEngine.reduce：工具分派 → 处理器 → 前后差分 → deriveWorldEvents → 订阅者；737 行）；advance-registry.mjs（57 个推进项）+ advance-layers.mjs（三层 + 补算）；effect-registry/effects.mjs（K6）；magic-effects.mjs + magic-primitives.mjs（M4）；interactions.mjs + world/design/interaction-rules.mjs（K2）；traits.mjs（K1）；world-events.mjs（K3：SOCIAL_VERBS 24 个动词、见证派生、订阅者注册、传闻生成）；standing.mjs（K4：归一与传导）；entity-view.mjs（V1：person/group/place/population/item 视图，459 行）；entity-transitions.mjs（V6：转移事件发布，25 行）；group-account.mjs（V4：统一公库）；checks.mjs（d20 五档、对抗、协助、工具加值、隐藏被动）。
- 状态：state.records 是事实上的平行账本集合（扫描到 70 余种 category：debt、contract、legal_case、organization、governance_office、title、territory、diplomacy、pledge、guardianship、physical_feature、authorization、transport、war…），另有 state.npcs/player/effects/creatures/itemInstances/settlements/skills/projects/family/inventory/buildings/professions/obligations/quests/created/remote/pets 等分区。
- 工具：25 个，operation 枚举 221 项（world_settlement 84、world_field 45、world_trade 40、world_law 18、world_companion 17）+ task/choice/action 二级枚举；resolveToolCall 把分组工具映射回内部工具；/execute 路由执行工具调用；界面面板只读（/read）。
- 写入方向：处理器直接 d.set 状态 → 事后差分推导世界事件。与目标相反。
- 循环依赖：PR-01 分支在 entity-transitions 里登记义务交接导致 import 环；RW-07 合并时效果注册表也曾因环移入无依赖模块。
