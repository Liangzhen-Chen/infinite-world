# 11 取舍与风险

## 11.1 故意不通用化的地方

- **战斗交锋、寻路、选举计票、决斗结算、天气马尔可夫链**保留为专用求解器：它们是算法不是账目，只要求输入读视图、输出是原语与事件。
- **工具面固定 ≤ 16 个**，包只注册动作；静态区不随系统增长——这是硬约束，也是防止"系统相乘"把 LLM 接口撑爆的闸门。
- **态度性关系做成可重建缓存**而非每次从事件重算：严格派生在规模上不可行，用"缓存 = 重算"测试守住语义。
- **统计层只模拟聚合与稀疏义务**，不模拟个体；接受"远方个体在被看见前没有历史细节"，与用户已定的按需生成一致。
- **物品分两档**：可计量的是账户数量，有身份的才是实体；否则 410 种物品会把存档撑满。
- **作者数据不重写**：world/people 等保持现有格式，开局转换为持有与账户；内容流水线不变。
- **NPC 对话的无 LLM 文本只求可读与不出戏**，不追求文学性；文学性由可选的 LLM 层提供。
- **effectSpec 格式保留**：150 法术不重写，经适配器映射原语。
- **法律不拦截动作**：违法行为照常裁决并打标签，由法律包反应；拦截会把"自由度"变成"许可清单"。

## 11.2 最难的部分

1. **转移协议里跨法典的清偿顺序、继承表与冲突法选择**：规则是数据，但要为九省各政体（含非人）各写一套并保证互相可解析；错一处就回到 27%。对策：法典数据校验器（每个政体必须有完整的七类民事规则），缺项拒绝构建。
2. **开放动作的裁剪与平衡**：幅度上限表与难度派生要覆盖全部原语族 × 目标类，且不能让通用组合比注册动作划算；LLM 提案的错误形态多。对策：两阶段查提、affordance 卡、意图语料三档验证、学习回路持续补注册动作。
3. **离屏等价**：闭式部分可证明；价格/疫病/迁徙/污染这类耦合迭代规则只能做容差等价，玩家逼近时的补算必须不产生可见跳变。对策：规则声明 tolerance，等价测试自动纳入，超容差即失败。
4. **绞杀式迁移的双写期**：旧账与新账并存时对账失败归因成本高；183 模块上任何写入点漏改都会破坏 I1/I3。对策：每阶段只迁一个概念；import 图与黑名单扫描阻止回流；对账测试报告具体差异路径。
5. **派生读的性能**：一切派生意味着热路径上大量视图计算；版本键缓存失效策略要做对，否则日推进会更慢而不是更快。对策：投影声明依赖、版本号失效、回合末预热、scale 测试守预算。
6. **自治包的决策输入**（需求、性格、机会、立场）是 NPC 之间犯罪、卷款、报复、改宗、自荐的来源；输入派生错了，世界会"合理地"做出荒谬的事，而且难以用不变量抓住。对策：推演题库持续扩充，含 NPC 行为合理性题；决策规则的输入可解释（返回各项得分）。
7. **无 LLM 对话的覆盖面**：打听、请求、议价、劝说的模板要覆盖十八文化 × 语域 × 答复，工作量在数据；对策：先做五村与白石镇的文化，远方按文化回退到通用模板。

## 11.3 对用户几条原则的落实

- 派生优先：I10/I11 + 黑名单 + 视图来源标记；适用于人、精怪、物品、建筑、聚落、势力（01 §1.10）。
- 阶乘玩法：包只靠词汇相乘（03 §3.2）；新内容写数据（03 §3.5）。
- 规模不缩减：九省 31 郡全展开由层级与聚合账户承载（07）。
- 不开 LLM 也能完整游玩：第一层 + 快捷栏（06 §6.9）；LLM 为可选理解与叙述层（06 §6.10、08）。
- 自由不被动作清单封顶：原语 + 开放动作 + 学习回路（06 §6.3、§6.5、§6.12）。
- 不损坏存档、不降低测试标准：S1–S6 不改格式；基线保留；目标测试只升不降（02 §2.2、10 §10.5）。
