# 11 取舍与风险

（修订历史见 修订记录.md。）

## 11.1 故意不通用化的地方

- **战斗交锋、寻路、选举计票、决斗结算、天气马尔可夫链、布局生成**保留为专用求解器：它们是算法不是账目，只要求输入读视图、输出是原语与事件。
- **工具面固定 ≤ 16 个**，包只注册动作；静态区不随系统增长——这是硬约束，也是防止"系统相乘"把 LLM 接口撑爆的闸门。
- **态度性关系做成可重建缓存**而非每次从事件重算：严格派生在规模上不可行，用"缓存 = 重算"测试守住语义。
- **统计层只模拟聚合与稀疏义务**，不模拟个体；接受"远方个体在被看见前没有历史细节"，与用户已定的按需生成一致；但统计层有公共知情，不是信息真空（07 §7.3）。
- **物品分两档**：可计量的是账户数量，有身份的才是实体；否则 410 种物品会把存档撑满。可追溯来源的计量物用批次 origin/taint，不实体化。
- **作者数据不重写**：world/people 等保持现有格式，开局转换为持有与账户；内容流水线不变；黑名单只拦存档与包数据，作者数据中的派生字段由转换器忽略并报告（I10）。
- **NPC 对话的无 LLM 文本只求可读与不出戏**，不追求文学性；文学性由可选的 LLM 层提供。
- **effectSpec 格式保留**：150 法术不重写，经适配器映射原语。
- **法律不拦截动作**：违法行为照常裁决，罪名由规范栈判定，由法律包反应；拦截会把"自由度"变成"许可清单"。
- **规范层不是通用逻辑引擎**：规范条目的谓词只能读事件原语、持有、状态、知情与地点（RX 子集），不能读另一条规范的结论（除 `inherit` 回落、授权表与补丁外）；层与层之间不做"推理"，只按固定顺序取条款。这样规范冲突可在加载与议案时检测，而不是在运行中出现悖论。
- **主观视图只到"事实版本"粒度**：不建模 NPC 对 NPC 的心智（"他以为我以为"）；信念是命题级的 belief 事件，不做概率推理网络。计划（05 §5.7.2）给阴谋与结盟一个最小形状，但不引入嵌套信念。
- **空间只到分区粒度**：规则（感知、潜行、战斗、移动）只读分区与邻接；格子坐标只给画面客户端；不做格子级寻路、光照传播、声音随时间传播（B 专项⑦ 第 6 条：对文字媒介收益低、成本可预见）。藏匿点与掩体由分区的遮挡属性表达。
- **经济不做订单簿与代理人报价**：市场是按数量出清的投影（15 §15.2），持有者行为只到"自用保留"；劳务同理，只到工资行情 `wageQuote`（供需稀缺项），不做劳务订单簿与逐人议价模型（议价只在雇佣动作里）；不做无准备金的信用创造（钱庄贷款只贷手里的钱）与衍生品，但**做**有发行守恒对与准备金账户的可兑现纸币、纯信用货币及其贬值与挤兑（15 §15.3）。
- **货币不做面额与可分性**：每种铸币或纸币是一个整数量资源，最小单位就是一枚 / 一文 / 一张，没有面额表与找零算法；"小额找零困难"只能表现为兑换服务的容量与手续费，不表现为交易做不成。
- **制造链只到配方的投入—产出**：配方给投入、工具、工时、技能阶、产出、副产品与损耗（01 §1.6），不做工序、机器、流水线与运输带（Factorio 式），不做质量在工序间的逐步继承（品质由配方的 `quality` RX 一次给出）。
- **不做叙事者 / 导演层**：不投放事件、不管理张力（RimWorld storyteller 的路径与"涌现来自世界内因果"的目标相悖，标杆 B01.4）；"世界节奏"只是速率修正项与世界内预兆（14 §14.8），不是脚本。任务、剧情、故事线一律是义务与事件，不另设概念。不做开局前的长历史生成（DF 式）：世界历史从作者数据与开局起累积。
- **画面客户端不持有规则**：任何渲染引擎（含 RPG Maker）只能作为显示器，不采信客户端本地状态。
- **不对第三方开放 JS 与求解器**：第三方包只用数据与 RX（第12章 §12.8）；求解器只由引擎提供。也不开放对他人数据的任意补丁（XPath 式）：唯一的"修改既有定义"途径是修正项与补丁（含追加前置），都有声明的槽、幅度与 `patchable`（05 §5.9、§5.2.8）。
- **本地化：架构按区域键（locale）组织，v1 只交付中文**：一切玩家可见文本来自模板与词条 label（事件流模板、对话模板、方位词、称呼、计量单位、数字格式按 `locale` 目录分层，缺省回落到 zh），词条 label 可多语言；但 v1 不翻译内容。可访问性：界面投影不以颜色为唯一信息载体，文字优先的界面天然可读屏；其余（字体、对比度、读屏标注）是客户端事务，不在本设计内（B 专项⑦ 第 9 条）。
- **数值平衡不做自动求解**：上限表、合理性表、"不比注册动作划算"、刷取探测器是护栏；参数化仿真与平衡报告是工具（标杆 B04.4、B17.8），不是设计的一部分。
- **军事只到军团级**（05 §5.10）：军力是派生、战役是 project、战斗结算是专用求解器；不做阵型、逐兵移动、战术 AI、攻城器械的物理；参数对包开放，算法不开放。
- **语言只到"能否沟通、能否读懂"**（附录 A §A.15）：语言是技能、沟通度是派生、通译是 companion 的 actedAs；文书带语言属性，阅读前置 = 识字 ∧ 该语言熟练度，译本与代读是另一份文本或一次转述（可失真可改译），"以哪份文本为准"是法典条款；不做语法、方言连续体、玩家可见的外语文本（外语文书对不识者只显示"看不懂"），不做口语与书面语各自独立的熟练度（同一 `lang:*` 熟练度加识字技能）。
- **受限只到"拘禁制度"**：受限者可做什么由东道的 regime 数据决定，脱逃是一次对抗检定；不做牢房分区级的看守巡逻路线、狱中经济或挖地道工程（这些可由包作为动作与修正项补充，形状已足够）。
- **法律程序成本只到讼费、担保、败诉承担、滥诉**：不做律师市场、法院排期、陪审；法院容量用服务容量同形表达。
- **同意只到"有 / 无 / 代理 / 紧急"四态**：不做部分同意、条件同意的谈判树；条件同意用 npcDecision 的"有条件同意"答复（开价）表达。
- **历法只到月序、闰月、年号与昼长表**（含 `anchors.daylight` 查表与折日基数 `rateBasis`）：不做天文模型（日食由时钟规则按天文表产生事件、日出日落是按季节与气候带的查表）、不做多重纪年的换算工具；历法是数据，日期是投影，时钟只认分钟。
- **身份只到身份键与认人**：`identify()` 读外貌事实与链接事件；不做易容技能树、不做"像不像"的连续相似度；变形、幻形、冒名复用同一机制。
- **承认只到条目**：`recognized()` 是法典 `recognition` 条目对缔结快照的谓词；不做法域之间的"承认谈判"过程（那是条约动作与补丁）。
- **估值只到一个派生加一张表**：不做评估师市场与个体化估价模型；成交价仍由动作决定。
- **钩子只在协议事务内**：`do` 只能是模板或原语列表，不能读随机、不能跨事务；复杂后续写成反应规则。
- **开放性宪章的边界**：缺省开放的是表、族、派生、定义补丁、钩子；原语、求解器、存储概念、不变量、L0 仍封闭（第12章 §12.1）；安全边界（bounds、预算、`reserved`、`closed`）不开放。
- **多人**：用户已排除。

## 11.2 最难的部分

1. **转移协议里跨法典的清偿顺序、继承表与冲突法选择**：规则是数据，但要为九省各政体（含非人与冥府）各写一套并保证互相可解析；错一处就回到 27%。对策：法典数据校验器（每个政体必须有完整的十类民事规则、程序阈值与程序成本），缺项拒绝构建。
2. **开放动作的裁剪与平衡**：幅度上限表与难度派生要覆盖全部原语族 × 目标类，且不能让通用组合比注册动作划算；LLM 提案的错误形态多。对策：两阶段查提、affordance 卡、意图语料三档验证、学习回路持续补注册动作。
3. **离屏等价**：闭式部分可证明；价格/疫病/迁徙/污染/传闻这类耦合迭代规则只能做容差等价，玩家逼近时的补算必须不产生可见跳变。对策：规则声明 tolerance，等价测试自动纳入（含降级等级与并回聚合），超容差即失败。
4. **绞杀式迁移的双写期**：旧账与新账并存时对账失败归因成本高；218 模块上任何写入点漏改都会破坏 I1/I3。对策：每阶段只迁一个概念；import 图与黑名单扫描阻止回流；对账测试报告具体差异路径。
5. **派生读的性能**：一切派生意味着热路径上大量视图计算；版本键缓存失效策略要做对，否则日推进会更慢而不是更快。对策：成本模型与索引键、分投影命中率目标、降级阶梯（07 §7.5）、scale 测试守预算。
6. **自治包的决策输入**（需求、性格、机会、立场、候选效用）是 NPC 之间犯罪、卷款、报复、改宗、自荐、结盟的来源；输入派生错了，世界会"合理地"做出荒谬的事，而且难以用不变量抓住。对策：推演题库持续扩充，含 NPC 行为合理性题；决策与计划的输入可解释（`explain()`）；候选效用有上下限与预算。
7. **规范栈的数据完整性与解释成本**：五层规范、授权表、补丁、角色条件让"这件事算不算罪、归谁管"可以由数据回答，但数据量与校验成本上升；授权表写错会让村规静默失效或越权。对策：议案与加载时的越权检查给世界内原因；规范栈解析可解释（返回各层命中的条目与补丁）；推演题库保留 R2-E4/E10/E16/E17/N7 作回归。
8. **主观视图的性能与一致性**：每个决策都读"某人相信的世界"，热路径更重；belief 过多会让 NPC 行为难以解释；自知域收窄后"自己不知道自己的远方生意已黄"要让玩家觉得合理而不是被坑。对策：惰性、按字段、分片版本键缓存（07 §7.5）；推断规则的置信度衰减与被见证推翻；决策输出附"依据哪条说法"；面板明确标注"据你所知"。
9. **修正项与补丁叠加失控**：多个包对同一槽位乘系数，可能把火灾概率、价格或税率推到荒谬值。对策：槽位声明 bounds、每槽修正项数与总幅度预算、法典 `patchable` 的幅度区间（第12章 §12.8.3）；推演合理率不降的验收。
10. **跨层聚合变体的等价**：S/I/R 与个体病例、聚合收货与个体收货、公共知情与个体知情、聚合犯罪率与个体案件之间的转换只能容差等价；物化瞬间不能出现可见跳变。对策：注册时强制声明聚合变体与转换（I28），等价测试自动纳入。
11. **继承中长期义务的边界情形**：限定继承、放弃继承、继承人为未成年或已消失、跨法典的 onDebtorGone 覆盖、同时死亡、不可分履行义务的分担，组合多。对策：法典完整性校验要求写明这些条款或显式 inherit；协议对每种组合有脚本化测试。
12. **自动布局的质量**：确定性布局规则生成的分区与方位要"像那么回事"，否则文字描述会别扭。对策：按地点类型的布局模板库先覆盖五村与白石镇的常见类型，作者数据优先；布局模板也可由包提供；标杆 B11.5 盲评。
13. **RX 表达力、词汇治理、卸载长尾、原生包信任**：见第12章 §12.12。
14. **无 LLM 对话的覆盖面**：打听、请求、议价、劝说的模板要覆盖十八文化 × 语域 × 答复，工作量在数据；对策：先做五村与白石镇的文化，远方按文化回退到通用模板。
15. **同刻全序与并行**：五阶段与排序键让结果可复现，但分片并行只能用于声明 local 的时钟规则；想要更多并行就要证明无序依赖。对策：I31 测试把串行作为基准；并行化是性能优化而非设计前提。
16. **货币市场的稳定性**：铸币作商品定价后，金属存量、充裕度与信用三项相乘可能振荡或极端。对策：稀缺曲线钳制、修正槽 bounds、以粮为主的价值单位篮子、S5 实测标定；合同只记数量不换算是防线。
17. **两步立案与裁量的可玩性**：嫌疑记录私密、指控可错、职位持有人可裁量，让法律有了腐败与诬告，但也让"玩家被冤枉"成为可能。对策：证据评分可解释、上诉与翻案路径、诬告罪名、标杆 B06.6 不卡死；法典可规定必须受理的罪名族。
18. **计划（多步图谋）的可解释与失控**：NPC 的多步计划若效用估错会出现离奇图谋。对策：计划存依据、每步重算效用、步数上限、推演题含图谋题。
19. **收录规模与宗教边界的内容纪律**：几千条有出处的生灵与神职要同时满足"有出处、不冒犯、有独有钩子、配额内"，排除名单与两档分类（中国民俗冥府放宽 / 正统崇拜排除）要逐条落实。对策：出处与敏感度字段必填、加载期 E-SOURCE/E-SENSITIVE、L1 相似度与钩子检查、合并清单交用户确认（13 §13.1、§13.9）。
20. **同意改为裁决输入后的可玩性**：无同意的精神类施法会发生并立案，玩家可能"读心一次就成重犯"，NPC 也可能对玩家施加。对策：罪名分级是法典数据（读心轻罪、强迫与改记忆重罪）、对抗检定失败即目标察觉、证据评分与裁量仍适用、叙述宪章对玩家-NPC 心智控制给世界内劝阻；推演题库加"同意"题组。
21. **契约附表把 core 派生"钉死"**：§A.16/§A.17 是对 core 的承诺，core 改派生公式时必须保持槽与消费者关系。对策：附表随契约版本，构建期校验 core 派生方声明的槽与附表一致（I27 测试），改附表 = 契约次版本。
22. **争夺池与阶段 3′**：把争夺从"先到先得"改为刻末裁决，实现上要延迟结算互斥提案，复杂度在调度器。对策：争夺只对声明 `contest` 的持有 / 义务 / 账户 / 动作启用，其余提案仍即时结算；争夺以整提案为单位；I31 夹具含争夺。
23. **信用货币的稳定性**：可兑现纸币的价值 = 挂钩价值 × 兑付信心 × 充裕度，三项都会随发行量与挤兑 belief 变化，可能出现自我强化的贬值螺旋（这是历史上交子的真实结局，也是玩法）。对策：bounds 与 k_floor 钳制、`minReserveRatio` 的罪名、停兑动作与破产案件作为终点、S5 平衡仿真加"超发"情境；不做央行式干预。
24. **劳务报价的量纲**：`wageQuote` 的稀缺项读"招工请求流量 ÷ 可雇人数"，可雇人数的派生（谁算"可雇"）决定行情是否合理；对策：先用技能族 × 阶的粗粒度，B18.8 用推演题标定；不做个体层的工作匹配。
25. **受限与法律状态的权限表**：哪些职位能收监、释放、押解、准探监是治理包与法律包的数据（职权表），写错会让囚犯"无人能放"或"人人能放"；对策：法典完整性校验加"每个法域至少一个有释放权能的职位或到期项路径"，B18.10 推演题覆盖替身、劫狱、越狱、探监。
26. **开放性宪章的平衡**：每个派生缺省开槽、每张表缺省可加行，多包叠加面比早期固定的 30 个槽宽得多。对策：缺省 bounds `mul ∈ [0.5, 2]`、每槽修正项数与总幅度预算（12 §12.8.3）、`exclusiveGroup`、平衡仿真报告的"槽叠加极值"对全部派生抽样；核心公式本身封闭。
27. **视角 API 的成本**：每个读 API 带 frame，`recognized()` 与 `identify()` 在热路径上各加一次查表（规范栈缓存键含 jurisdiction；`identify` 的缓存键含知情版本）；07 §7.5 的成本模型须把两者计入主观视图预算；若超出，先缩小 `identify` 的候选集（只对在场者求值）。
28. **钩子的可解释与可终止**：钩子的 `do` 是原语列表，可能互相触发。对策：钩子只在协议事务内按固定顺序执行一次、不递归（同一事务内由钩子产生的持有变更不再触发钩子，其后续进阶段 4 反应），I6–I8 在事务末断言；`why()` 返回命中的钩子与条件。

## 11.3 对用户几条原则的落实

- 派生优先：I10/I11 + 黑名单（按记录类别）+ 视图来源标记；适用于人、精怪、物品、建筑、聚落、势力、生灵处境（01 §1.10）。
- 阶乘玩法：包只靠词汇相乘（03 §3.2 的八种连接点，含契约附表的修正槽与扩展事实）；新内容写数据（03 §3.5）。
- 规模不缩减：九省 31 郡全展开由层级、聚合账户与公共知情承载（07）。
- 不开 LLM 也能完整游玩：第一层 + 快捷栏（06 §6.9）；智能层永远开启，LLM 只是可选提案来源（07 §7.2.1）。
- 自由不被动作清单封顶：原语 + 开放动作 + 学习回路（06 §6.3、§6.5、§6.12）。
- 尊重玩家想象力：不出现"不支持"；世界内原因 + 降级做法 + 兜底带标签实体；不支持率 0、兜底反应率 100%（06 §6.2 第 7 条、§6.9.5、§6.11）。
- 状态决定的值必须派生：在途、失能不再"冻结"义务，宽限由法典条款派生（04 §4.1）；兼任、身份冲突、改宗由持有与章程派生（05 §5.3）。
- 文字也有方位：空间是本体的一部分，文字投影按方位组织，画面是同一数据的另一种投影（01 §1.5、08 §8.8）。
- 开放扩展：第12章；缺省开放（附录 A §A.9 开放性宪章），修改既有定义只经补丁（05 §5.2.8）。
- 世界节奏：速率修正项 + 预兆与延后 + 回程见闻；默认适中（14 §14.8）。
- 法律行为"先发生、后定效"：限制能力、无权处分、越权代理的行为在世界里成立并打标签，效力由 `validity` 按法域事后求值（附录 A §A.15）；代价是更多可撤销状态要被程序收拾，收益是争产、追索、善意取得这些玩法存在。
- 超自然与职业呼应、妖怪志与万灵志、防重复"宁合不拆"、宗教尊重与收录标准：13 章。
- 设计关口与标杆：连续两轮新题 ≥ 95%、无矛盾、回归不降（PLAN AR）；标杆标准全部可自动测。
- 不损坏存档、不降低测试标准：S1–S6 不改格式；基线保留；目标测试只升不降（02 §2.2、10 §10.5）。
