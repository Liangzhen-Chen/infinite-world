# 11 取舍与风险

（2026-10-15 修订：加入 run-002 审查后新增规则形状的取舍与风险、空间与方位、第12章要求的条目。）

## 11.1 故意不通用化的地方

- **战斗交锋、寻路、选举计票、决斗结算、天气马尔可夫链**保留为专用求解器：它们是算法不是账目，只要求输入读视图、输出是原语与事件。
- **工具面固定 ≤ 16 个**，包只注册动作；静态区不随系统增长——这是硬约束，也是防止"系统相乘"把 LLM 接口撑爆的闸门。
- **态度性关系做成可重建缓存**而非每次从事件重算：严格派生在规模上不可行，用"缓存 = 重算"测试守住语义。
- **统计层只模拟聚合与稀疏义务**，不模拟个体；接受"远方个体在被看见前没有历史细节"，与用户已定的按需生成一致。
- **物品分两档**：可计量的是账户数量，有身份的才是实体；否则 410 种物品会把存档撑满。
- **作者数据不重写**：world/people 等保持现有格式，开局转换为持有与账户；内容流水线不变。
- **NPC 对话的无 LLM 文本只求可读与不出戏**，不追求文学性；文学性由可选的 LLM 层提供。
- **effectSpec 格式保留**：150 法术不重写，经适配器映射原语。
- **法律不拦截动作**：违法行为照常裁决，罪名由规范栈判定，由法律包反应；拦截会把"自由度"变成"许可清单"。
- **规范层不是通用逻辑引擎**：规范条目的谓词只能读事件原语、持有、状态、知情与地点（RX 子集），不能读另一条规范的结论（除 `inherit` 回落与授权表外）；层与层之间不做"推理"，只按固定顺序取条款。这样规范冲突可在加载与议案时检测，而不是在运行中出现悖论。
- **主观视图只到"事实版本"粒度**：不建模 NPC 对 NPC 的心智（"他以为我以为"）；信念是命题级的 belief 事件，不做概率推理网络。
- **空间只到分区粒度**：规则（感知、潜行、战斗、移动）只读分区与邻接；格子坐标只给画面客户端；不做格子级寻路与视线投射。
- **画面客户端不持有规则**：任何渲染引擎（含 RPG Maker）只能作为显示器，不采信客户端本地状态。
- **不对第三方开放 JS 与求解器**：第三方包只用数据与 RX（第12章 §12.8）；求解器（战斗、寻路、选举、布局生成）只由引擎提供。

## 11.2 最难的部分

1. **转移协议里跨法典的清偿顺序、继承表与冲突法选择**：规则是数据，但要为九省各政体（含非人）各写一套并保证互相可解析；错一处就回到 27%。对策：法典数据校验器（每个政体必须有完整的七类民事规则），缺项拒绝构建。
2. **开放动作的裁剪与平衡**：幅度上限表与难度派生要覆盖全部原语族 × 目标类，且不能让通用组合比注册动作划算；LLM 提案的错误形态多。对策：两阶段查提、affordance 卡、意图语料三档验证、学习回路持续补注册动作。
3. **离屏等价**：闭式部分可证明；价格/疫病/迁徙/污染这类耦合迭代规则只能做容差等价，玩家逼近时的补算必须不产生可见跳变。对策：规则声明 tolerance，等价测试自动纳入，超容差即失败。
4. **绞杀式迁移的双写期**：旧账与新账并存时对账失败归因成本高；183 模块上任何写入点漏改都会破坏 I1/I3。对策：每阶段只迁一个概念；import 图与黑名单扫描阻止回流；对账测试报告具体差异路径。
5. **派生读的性能**：一切派生意味着热路径上大量视图计算；版本键缓存失效策略要做对，否则日推进会更慢而不是更快。对策：投影声明依赖、版本号失效、回合末预热、scale 测试守预算。
6. **自治包的决策输入**（需求、性格、机会、立场）是 NPC 之间犯罪、卷款、报复、改宗、自荐的来源；输入派生错了，世界会"合理地"做出荒谬的事，而且难以用不变量抓住。对策：推演题库持续扩充，含 NPC 行为合理性题；决策规则的输入可解释（返回各项得分）。
7. **规范栈的数据完整性与解释成本**（run-002 新增）：四层规范、授权表、角色条件让"这件事算不算罪、归谁管"可以由数据回答，但数据量与校验成本上升；授权表写错会让村规静默失效或越权。对策：议案与加载时的越权检查给世界内原因；规范栈解析可解释（返回各层命中的条目）；推演题库保留 run-002 的 E4/E10/E16/E17/N7 作回归。
8. **主观视图的性能与一致性**：每个决策都读"某人相信的世界"，热路径更重；belief 过多会让 NPC 行为难以解释。对策：惰性、按字段、版本键缓存（07 §7.5）；推断规则的置信度衰减与被见证推翻；决策输出附"依据哪条说法"。
9. **修正项叠加失控**：多个包对同一槽位乘系数，可能把火灾概率或价格推到荒谬值。对策：槽位声明 bounds、每槽修正项数与总幅度预算（第12章 §12.8.3）；推演合理率不降的验收。
10. **跨层聚合变体的等价**：S/I/R 与个体病例、聚合收货与个体收货之间的转换只能容差等价；物化瞬间不能出现可见跳变。对策：注册时强制声明聚合变体与转换（I28），等价测试自动纳入。
11. **继承中长期义务的边界情形**：限定继承、放弃继承、继承人为未成年或已消失、跨法典的 onDebtorGone 覆盖，组合多。对策：法典完整性校验要求写明这些条款或显式 inherit；协议对每种组合有脚本化测试。
12. **自动布局的质量**：确定性布局规则生成的分区与方位要"像那么回事"，否则文字描述会别扭。对策：按地点类型的布局模板库先覆盖五村与白石镇的常见类型，作者数据优先；布局模板也可由包提供。
13. **RX 表达力、词汇治理、卸载长尾、原生包信任**：见第12章 §12.12。
14. **无 LLM 对话的覆盖面**：打听、请求、议价、劝说的模板要覆盖十八文化 × 语域 × 答复，工作量在数据；对策：先做五村与白石镇的文化，远方按文化回退到通用模板。

## 11.3 对用户几条原则的落实

- 派生优先：I10/I11 + 黑名单 + 视图来源标记；适用于人、精怪、物品、建筑、聚落、势力（01 §1.10）。
- 阶乘玩法：包只靠词汇相乘（03 §3.2）；新内容写数据（03 §3.5）。
- 规模不缩减：九省 31 郡全展开由层级与聚合账户承载（07）。
- 不开 LLM 也能完整游玩：第一层 + 快捷栏（06 §6.9）；LLM 为可选理解与叙述层（06 §6.10、08）。
- 自由不被动作清单封顶：原语 + 开放动作 + 学习回路（06 §6.3、§6.5、§6.12）。
- 尊重玩家想象力：不出现"不支持"；世界内原因 + 降级做法 + 兜底带标签实体；不支持率 0、兜底反应率 100%（06 §6.2 第 7 条、§6.9.5、§6.11）。
- 状态决定的值必须派生：在途、失能不再"冻结"义务，宽限由法典条款派生（04 §4.1）；兼任、身份冲突由持有与章程派生（05 §5.3）。
- 文字也有方位：空间是本体的一部分，文字投影按方位组织，画面是同一数据的另一种投影（01 §1.5、08 §8.8）。
- 开放扩展：第12章。
- 不损坏存档、不降低测试标准：S1–S6 不改格式；基线保留；目标测试只升不降（02 §2.2、10 §10.5）。
