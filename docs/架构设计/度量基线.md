## 口径说明

- **import 图**：解析 server-plugin/ 与 extension/ 的静态 import、`export … from`、字面量动态 import 与 ui-* 目录加载器。层按第 10 章 §10.2 归组（tools/arch-layers.mjs，未逐一列出的模块按职责补归并注明）。违例 = 低层 import 高层（L0→L1…L4 只许向下）或两个不同玩法包互相 import；world/ 数据与 tools/ 不计。违例集中在 engine/activities/advance-registry（L0 直接 import 各包的处理器与推进项，约 170 条）与包间直接调用（239 条），这正是 S1–S8 要消除的形状。
- **派生黑名单**：字段表在 world/ontology/derived-fields.json（01 §1.11 与 A1 审计名单）。写入点 = `d.set([...'state'...], 值)` 的路径末段或值对象的键，以及 `{category:'…', …}` 记录字面量的顶层键；作者数据 = world/（不含 drafts、design、ontology、美术音频，也不含 rules.json——它是派生用的数值表）中 scope=all 的字段。经变量间接拼出的写入不计，是近似值。
- **推演脚本**：能用现有引擎构造的情境实测（E02、E03、E04、E06、E08、E11、E12 共 37 条，沿用核对者 probe-001-scratch-a/-b 的情境）；构造不出的情境按现有机制（规则数据、导出函数、工具枚举、源码）判定，机制出现后脚本会改判为“部分”提示补实测。每条预期一个判定函数，返回合理/部分/错误/缺失并附证据。与人工核对（28/42/6/29）相比，脚本化后部分 +3、缺失 −3，都来自核对之后合入主线的卡：E04③ 因 R10A，矿口法域已可解析（缺失→部分）；E08④、E15③ 因 RW-06，已有非魔法诊疗与消耗真实药材的义诊（缺失→部分）。
- **意图语料**：格式见 06 §6.11 与 tests/intents/corpus-001.json 的说明；签名元素为 `原语|目标模板|字段或资源`，路由为 docs/actions.json 的动作 id。T0 桩翻译器只回显语料期望（不做翻译），用于跑通评分管线；“当前引擎不支持率”= 期望处理不是“已存在的注册动作”的条目占比（world_propose、兜底 create(artifact)、不可行原因/降级协议都要到 A3）；“兜底实体无系统反应率”= 兜底条目中当前没有任何系统按其标签起反应的占比（引擎尚无 create(artifact,tags) 原语与按标签订阅）。两项目标均为 0，A3 退出时复测。
- **命名空间**：词汇、动作 id 均以 `core:` 为核心命名空间，可省略；内容包以自己的命名空间登记（tests/fixtures/packs/demo 为示例）。只有已声明的命名空间才算限定前缀，标签族（offense:、org: 等）不受影响，包名不得与标签族同名。三项静态度量都能对单个包目录运行：`node tools/ontology.mjs --pack <目录>`、`node tools/import-graph.mjs --dir <目录>`、`node tools/derived-scan.mjs --dir <目录>`，报错指出文件与字段。
