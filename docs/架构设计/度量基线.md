## 口径说明

- **import 图**：解析 server-plugin/、extension/ 与 packs/（尚无）的静态 import、`export … from`、字面量动态 import 与 ui-* 目录加载器。层按第 10 章 §10.2 归组（tools/arch-layers.mjs，未逐一列出的模块按职责补归并注明）。违例 = 低层 import 高层（L0→L1…L4 只许向下）或两个不同玩法包互相 import；world/ 数据与 tools/ 不计。违例集中在 engine/activities/advance-registry（L0 直接 import 各包的处理器与推进项，约 170 条）与包间直接调用（239 条），这正是 S1–S8 要消除的形状。
- **派生黑名单**：字段表在 world/ontology/derived-fields.json（01 §1.11 与 A1 审计名单）。写入点 = `d.set([...'state'...], 值)` 的路径末段或值对象的键，以及 `{category:'…', …}` 记录字面量的顶层键；作者数据 = world/（不含 drafts、design、ontology、美术音频，也不含 rules.json——它是派生用的数值表）中 scope=all 的字段。经变量间接拼出的写入不计，是近似值。
- **推演脚本**：能用现有引擎构造的情境实测（E02、E03、E04、E06、E08、E11、E12 共 37 条，沿用核对者 probe-001-scratch-a/-b 的情境）；构造不出的情境按现有机制（规则数据、导出函数、工具枚举、源码）判定，机制出现后脚本会改判为“部分”提示补实测。每条预期一个判定函数，返回合理/部分/错误/缺失并附证据。与人工核对（28/42/6/29）相比，脚本化后部分 +3、缺失 −3，都来自核对之后合入主线的卡：E04③ 因 R10A，矿口法域已可解析（缺失→部分）；E08④、E15③ 因 RW-06，已有非魔法诊疗与消耗真实药材的义诊（缺失→部分）。
- **意图语料**：格式见 06 §6.11 与 tests/intents/corpus-001.json 的说明；签名元素为 `原语|目标模板|字段或资源`，路由为 docs/actions.json 的动作 id；罪名不进签名（修订后由规范层判定，05 §5.2.3），期望的法律后果写在 `offense`；兜底条目写形态、`mark:*` 与性状标签和应起反应的系统。T0 桩翻译器只回显语料期望（不做翻译），用于跑通评分管线；“当前引擎不支持率”= 期望处理不是“已存在的注册动作”的条目占比（world_propose、兜底 create(kind: mark)、不可行原因/降级协议都要到 A3）；“兜底实体无系统反应率”= 兜底条目中当前没有任何系统按其标签起反应的占比（引擎尚无 create(kind: mark) 原语与订阅 `mark:*` 的反应规则）。两项目标均为 0，A3 退出时复测。
- **命名空间**：词汇、动作 id 均以 `core:` 为核心命名空间，可省略；内容包以自己的命名空间登记（tests/fixtures/packs/demo 为示例）。只有已声明的命名空间才算限定前缀，标签族（offense:、org:、mark:、goods: 等）不受影响，包名不得与标签族同名。词条可带 `broader`（上位词，包词汇必填）、`aliases`、`scope`（core/shared/private）、`definition`、`distinctFrom`（12 §12.3.3）。三项静态度量都能对单个包目录运行：`node tools/ontology.mjs --pack <目录>`、`node tools/import-graph.mjs --dir <目录>`、`node tools/derived-scan.mjs --dir <目录>`，报错指出文件与字段。

## S0 期间发现的设计文档问题（待主会话裁定，未改设计文档）

1. **原语族数**：目标架构 §0.3 与 06 §6.3 称“18 个、12 族”，按表实为 14 族（transfer、holding、obligation、fact、vital、status、move、create、destroy、emit、schedule、transition、learn、time）。
2. **动词重名**：06 §6.3 的 `transfer` 原语事件与现有社会动词 `transfer`（转让/交接，entityTransition 用）同名不同义；词汇表暂合为一条，S1 写事件主写时须改名（如原语事件用 `transferred`）。
3. **L4 的允许依赖**：03 §3.1 写 L4 只依赖“L2 动作目录、L3”，但工具面与 /execute 必须调用 L0 的事务入口；import 图按“只许向下”计，未把 L4→L0/L1 算违例。建议 03 改为“L0–L3 只读入口 + L2 动作目录”。
4. **立场模块归层**：10 §10.2 把 standing/reputation*/public-opinion 列在 L1 表里，目标却写“立场投影（L3）”；归层表按 L3 计。
5. **黑名单与作者数据**：02 I10“黑名单字段不出现在作者数据”与 11 §11.1“作者数据不重写、开局转换”冲突——locations.residents（357 处）、settlements.jurisdiction（4 处）、NPC 的 age 都是作者数据。另外 rules.json 的俸禄/额度表本身就含 monthlyQuotaD 等键（是派生用的数值表），按字段名一刀切会误报；黑名单应按实体种类/记录类别限定，而非裸字段名（`title` 因此未纳入）。
6. **交接按端区分**：04 §4.3 的 employed_by 交接写成“estate（雇主侧）/ close（雇员侧）”，但 01 §1.3 的 handover 只有一张按触发的表，没有持有人端/标的端之分；词汇表暂用 `subjectGone` 表达标的端，规范需补“端”维度。
7. **located_in 未进目录**：01 §1.10 多处用 `located_in`，§1.3 的持有目录没有它；词汇表已补。
8. **数字过时**：06 §6.1、10 §10.1 的“operation 枚举 221 项、约 265 个动作、186 模块”已过时（现 226 个子操作 + 16 个无子操作工具 = 242 个动作；server-plugin 188 个文件）。
9. **包词汇文件位置**：12 §12.2.1 用单个 `vocabulary.json`（term/scope/broader/label/aliases 词条格式）加 `ontology/*.json`，01 写 `ontology/holdings.json` 等不带 world/ 前缀；S0 的核心词汇放 world/ontology/、按种类分文件，包目录接受 `ontology/` 与 `vocabulary/`，尚未支持 12 章的 term 词条格式（加载器阶段统一）。
10. **对话无注册动作**：06 §6.9.2 的对话动作组目前一条注册动作都没有（无 talk/ask），意图语料里社交类只能标为 open；A1 退出标准里的 L/T 场景若含对话，须等 A2。
