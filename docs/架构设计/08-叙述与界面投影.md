# 08 叙述与界面投影：引擎事实如何投影给 LLM 与玩家，并守住知情边界与提示预算

（修订历史见 修订记录.md。）

## 8.1 原则

- 引擎是唯一事实来源；LLM 与界面都只读 L3 投影；叙述在结算之后，不能改变结算。
- 两种模式用同一投影代码：无 LLM 时投影渲染成模板文本与面板；有 LLM 时投影进入场景卡与叙述约束。将来的画面客户端是同一空间数据的又一种投影（§8.8）。
- 每条投影到卡上的事实带来源事件编号（审计用，渲染前隐藏）；知情边界由知情集合保证（I12）。
- **传闻与真相分离**：投影给玩家的是玩家的主观视图；NPC 说的话来自 NPC 的主观视图（亲见、传闻、自己的推测、谎言）。真相只出现在玩家确实知道的范围；叙述不得把传闻写成事实，也不得替 NPC "知道"他不知道的事。

## 8.2 场景卡（动态尾部，≤ 2,500 token）

沿用 9.5 的布局，变化：
- 【此处】按方位组织：玩家所在分区；各方向相邻分区上玩家能感知到的实体与活动（看见的写动作，只听见的写声音，"东侧铁铺门口：王二在打铁；北面小路通往山上；身后茶摊有人低声说话（听不清）"）；出口与通往何处。
- 【在场】每人一行：称呼与职称（派生；按玩家认出的身份键显示，附录 A §A.15——不认得本名者只显示其自称）、所在分区与此刻在做（日程派生）、对你（立场投影口语化）、你们之间（共同事件摘要，来自双方知情集合交集）、说话方式、禁区、**TA 不知道**（玩家知情集合 − 该 NPC 知情集合在当前话题上的差）、**TA 以为**（该 NPC 主观视图中与玩家所知不同的说法，例如"以为东家已溺亡"——只列玩家知道是错的或与玩家所知冲突的条目，来源注明"传闻/推测"）。玩家自己对不在场之事的认识同样只到"据你所知"（05 §5.4 自知域），卡上不出现玩家不可能知道的远方状态。
- 【预兆】慢节奏档下与玩家相关的预兆事件（14 §14.8）按它的可感知形式进入【此处】或【近期】，不单列、不标"预兆"。
- 【进行中】义务与任务（到期排序）。
- 【可做之事】在场实体与地点的高相关注册动作（id + 一句话，单条 LLM 文本 ≤ 60 token），≤ 600 token；更多靠 world_actions。
- 【近期】最近 3 个场景摘要 + 当日日志（编年史投影）。
- 【相关旧事】检索结果（每个检索分块 ≤ 300 token），每条注明来源与时间；传闻用 tell 事件的版本文本，不用真相文本。
- 【本回合提醒】只放相关规则卡（例如在法庭时的程序卡）。
- 返场摘要与**回程见闻**（U14、14 §14.8）只取玩家知情集合在离开期间新增的事件（公告、信件、所见景象、回程沿途可感知的景象与告示），不给数字；慢节奏档下回程见闻更长（长离屏的等待以见闻填补）。
- 【任务与约定】读玩家的主观视图：不在场义务只显示条款快照与"据你所知"的状态；远方悬赏被他人完成，玩家得知前不变（I25）。
- 场景卡对包内容不加权（第12章 §12.6）。

## 8.3 静态区（≤ 12,000，当前 10,522）

- 宪章、世界纲要、规则摘要、文风、示例不变。
- 工具定义：≤ 16 个，一句话描述，枚举全部移出 → 预计 −1,200 token。
- 新增：原语语法与 world_propose 示例 ≈ 600 token；裁决规则一段（"提案只是提议，结果以回执为准；被拒时照实写失败并给世界内原因；任何创意都可以留下痕迹"）≈ 120 token。
- 包不得增加静态提示（manifest 的 staticTokens 必须为 0，构建期校验）。

## 8.4 叙述约束与一致性审查

- 工具回执带 `narrate.must / mustNot`（06 §6.10.3）；审查的确定性部分核对叙述含 must、不含 mustNot、不含未应用的转移与持有变化、不含非知情内容、**方位与站位和投影一致**（不把茶摊写到西边，不让隔墙的人"看见"）、**不把传闻或 NPC 的推测写成事实**；模型审查部分保留，输入改为 applied 列表而非前后状态差分（更小更准）。
- 严重不符：自动改写一次；仍不符：显示模板文本（无 LLM 文本）并记入问题日志；不停整场（M2P 口径）。
- 系统提示（12.2）由事件模板生成，不由模型写。
- 拒绝与降级的文字只用世界内原因，不出现"不支持""无法执行"之类场外语句（06 §6.2 第 7 条）。

## 8.5 界面投影（无 LLM 与有 LLM 共用）

- 顶栏、面板按 12.3–12.4，全部读投影；新增：动作目录菜单、对话面板、构造器（含方位与分区选择）、事件流（模板文本）、提案预览。
- 场景描述按方位组织（同 §8.2【此处】），无 LLM 时由方位模板直接生成；玩家可点方位或分区做动作（"走到茶摊旁边""从后院绕过去"）。
- 事件流模板：每个动词一条数据模板，槽位为称呼/数量/地点/方位；私密事件只对当事人显示；传闻显示"据说"，推测显示"有人猜"。
- 人物面板显示"玩家最后一次见到此人时的状态"（T164 决定），用知情集合的最新相关事件实现。
- 地图迷雾：亲历（知情集合中在场事件）、可靠转述（tell 来自亲历者）、传闻（二手以上）。
- 文书阅读：显示文书 records 的版本文本（可能是伪造或过时的）；玩家不识该文书的语言（`canRead` 为假）时只显示"一份某文写的文书，你看不懂"，并列出在场可代读者与译本（05 §5.4）。
- 受限（在押、被扣、软禁）时的场景头注明东道、拘禁制度允许的事与刑期 / 到期项；目录按制度过滤（06 §6.9.1）。
- 数量、价格按玩家所在法域的单位表显示，日期与年号按该法域的历法显示（15 §15.3、附录 A §A.15）；存量与时刻本身只有规范单位与分钟。
- 调试模式之外不显示编号与 JSON。

## 8.6 智能层（离屏 NPC 行动）的投影

- 开 LLM 时，智能层把 8–20 名 NPC 的**主观视图**（不是真实状态）、近期记忆（知情集合）、他们相信的当地局势批量交给模型，返回结构化行动提案；每条经 06 的裁决管线（在场、能力、守恒、人设禁区、决策规则），通过的成为事件。所以模型不会让村民去精怪处找人，除非村民相信她在那里。
- 无 LLM 时，智能层照常运行，NPC 的行动提案全部来自自治包的规则决策（需求 → 候选 → 计划 → 动作，05 §5.7），同样只读主观视图，结果合法但"主意"更少（运行矩阵见 07 §7.2.1）。
- 两种模式的事件进入同一记忆与传闻机制。

## 8.7 预算守卫

- 构建期：静态区 token 统计（现有 build-card 检查）；包 staticTokens=0；单条动作 LLM 文本 ≤ 60 token；检索分块 ≤ 300 token。
- 运行期：场景卡 ≤ 2,500，"可做之事" ≤ 600，返场摘要 ≤ 5 条；超出按相关度截断。
- 缓存命中率 ≥ 70%（9.1）：静态区不含任何动态内容，历史成批截断（现有做法）。

## 8.8 空间投影与画面客户端预留

用户 2026-10-15："哪怕没有真的动画画面，我就想一模一样全部用文字展现，文字也是有方位的。"空间（01 §1.5 的路线方位、分区、邻接、站位）是世界本体的一部分，文字投影直接使用；将来的画面（网页插画 + 可点地图、浏览器图块俯视图、独立客户端、RPG Maker 试验版——方案未定）只是同一空间数据的另一种投影。原则：渲染无关、只加数据和投影、不改核心概念。

**1. 空间数据（本体，01 §1.5）**
- 必有：路线边方位与距离；分区与邻接（方位、距离、遮挡、视线、声音衰减）；站位（派生，不落盘）。缺数据时由确定性布局规则生成。
- 可选（画面用）：分区局部坐标、网格尺寸、出入口位置、朝向；建筑在聚落内的位置与占地。规则不读这些字段；缺省时客户端按分区邻接自动排布（同样确定性）。
- 第三方包可提供布局与素材键（第12章"布局与素材"扩展点）。

**2. 素材键**
- 实体种类与个体、地点与分区、动作、事件动词、状态可声明素材键：`{portrait, sprite, tile, icon, sfx, ambience}` 的键名（例如 `art:portrait/merchant_old_male`），**不含素材本身**。
- 解析顺序：个体键 → 种类键 → 模板类别默认键（person/creature/building/item……）；客户端缺素材时按此回落，永不报错。素材键是作者数据，不进存档状态，不进提示。

**3. 画面投影接口**（L3 投影 + L4 路由，客户端只读）
- `scene(viewer)`：当前地点的场景投影——分区与邻接（含可选坐标）、viewer 能感知到的在场实体及其站位与活动、可交互对象及其"可做之事"（动作目录投影，与 §8.5 菜单同源）、天气、昼夜、光照、素材键。只含 viewer 知情与感知范围内的内容（I12、I30）。
- `events.subscribe(viewer, since)`：事件流增量（与文字事件流同一模板数据：动词、参与者、方位、素材键），只推 viewer 可感知或知情的事件。
- 操作：全部走同一动作目录（world_act / world_actions；走到某分区是 move 原语）。客户端不持有规则、不写状态、不缓存权威数据；RPG Maker 之类引擎只能作为显示器，其本地事件、开关、数值不被引擎采信。

**4. 性能**
- 投影按视野裁剪（viewer 的感知范围与当前地点），增量推送；分区级而非格子级；离屏地区不算站位。
- 动画插值（走动、转身）只在客户端，不回写。

**5. 文字与画面一致**：文字投影与画面投影读同一 `scene()` 结果；一致性审查对方位的核对（§8.4）因此同时保证文字与画面不矛盾。

## 8.9 玩家角色的接续

玩家控制哪个实体是**会话事实 `avatar`**，不是世界事实：世界里没有"玩家"这一种实体，只有被 avatar 指向的 person / creature。avatar 所指实体 gone 后，界面给出接续选项，全部来自世界已有机制：①**继承人**——继承表顺位中的在世实体（可以是 8 岁孩子：其 `capacity` 为 limited、由监护人代管，玩家以受监护人身份游戏，附录 A §A.15）；②**转生者**——文化 `rebirth: true` 时 `reborn` 创建的新个体（带 `rebirthOf`；知情集合按冥府规则清空，13 §13.7）；③**任一在世 NPC**（作者或包可用标签限制范围）。接续只改 avatar：世界不回滚、不复制，前世的持有、账户、职位、立场都留在原实体与其遗产上；玩家的知情集合 = 新 avatar 的知情集合（I12：前世知情不带入；转生者"记得前世"只能来自冥府规则声明的保留项，作为作者知情种子写入，别人听到也只是一条自述，采信经 `credence`）。所有面板、场景卡、回程见闻随 avatar 切换；切换是输入事件 `avatar_set`，进存档，重放一致。
