# 08 叙述与界面投影：引擎事实如何投影给 LLM 与玩家，并守住知情边界与提示预算

## 8.1 原则

- 引擎是唯一事实来源；LLM 与界面都只读 L3 投影；叙述在结算之后，不能改变结算。
- 两种模式用同一投影代码：无 LLM 时投影渲染成模板文本与面板；有 LLM 时投影进入场景卡与叙述约束。
- 每条投影到卡上的事实带来源事件编号（审计用，渲染前隐藏）；知情边界由知情集合保证（I12）。

## 8.2 场景卡（动态尾部，≤ 2,500 token）

沿用 9.5 的布局，变化：
- 【在场】每人一行：称呼与职称（派生）、此刻在做（日程派生）、对你（立场投影口语化）、你们之间（共同事件摘要，来自双方知情集合交集）、说话方式、禁区、**TA 不知道**（玩家知情集合 − 该 NPC 知情集合在当前话题上的差）。
- 【进行中】义务与任务（到期排序）。
- 【可做之事】新段：在场实体与地点的高相关注册动作（id + 一句话），≤ 600 token；更多靠 world_actions。
- 【近期】最近 3 个场景摘要 + 当日日志（编年史投影）。
- 【相关旧事】检索结果，每条注明来源与时间；传闻用 tell 事件的版本文本，不用真相文本。
- 【本回合提醒】只放相关规则卡（例如在法庭时的程序卡）。
- 返场摘要（U14）只取玩家知情集合在离开期间新增的事件（公告、信件、所见景象），不给数字（E12⑥、E16⑤）。

## 8.3 静态区（≤ 12,000，当前 10,522）

- 宪章、世界纲要、规则摘要、文风、示例不变。
- 工具定义：≤ 16 个，一句话描述，枚举全部移出 → 预计 −1,200 token。
- 新增：原语语法与 world_propose 示例 ≈ 600 token；裁决规则一段（"提案只是提议，结果以回执为准；被拒时照实写失败"）≈ 100 token。
- 包不得增加静态提示（manifest 的 staticTokens 必须为 0，构建期校验）。

## 8.4 叙述约束与一致性审查

- 工具回执带 `narrate.must / mustNot`（06 §6.10.3）；审查的确定性部分核对叙述含 must、不含 mustNot、不含未应用的转移与持有变化、不含非知情内容；模型审查部分保留（8.5），输入改为 applied 列表而非前后状态差分（更小更准）。
- 严重不符：自动改写一次；仍不符：显示模板文本（无 LLM 文本）并记入问题日志；不停整场（M2P 口径）。
- 系统提示（12.2）由事件模板生成，不由模型写。

## 8.5 界面投影（无 LLM 与有 LLM 共用）

- 顶栏、面板按 12.3–12.4，全部读投影；新增：动作目录菜单、对话面板、构造器、事件流（模板文本）、提案预览。
- 事件流模板：每个动词一条数据模板，槽位为称呼/数量/地点；私密事件只对当事人显示；传闻显示"据说"。
- 人物面板显示"玩家最后一次见到此人时的状态"（T164 决定），用知情集合的最新相关事件实现。
- 地图迷雾：亲历（知情集合中在场事件）、可靠转述（tell 来自亲历者）、传闻（二手以上）。
- 调试模式之外不显示编号与 JSON。

## 8.6 智能层（离屏 NPC 行动）的投影

- 开 LLM 时，智能层把 8–20 名 NPC 的视图、近期记忆（知情集合）、当地局势批量交给模型，返回结构化行动提案；每条经 06 的裁决管线（在场、能力、守恒、人设禁区、决策规则），通过的成为事件。
- 无 LLM 时，智能层由自治包的规则决策替代（需求 → 目标 → 动作），结果合法但"主意"更少。
- 两种模式的事件进入同一记忆与传闻机制。

## 8.7 预算守卫

- 构建期：静态区 token 统计（现有 build-card 检查）；包 staticTokens=0。
- 运行期：场景卡 ≤ 2,500，"可做之事" ≤ 600，返场摘要 ≤ 5 条；超出按相关度截断。
- 缓存命中率 ≥ 70%（9.1）：静态区不含任何动态内容，历史成批截断（现有做法）。
