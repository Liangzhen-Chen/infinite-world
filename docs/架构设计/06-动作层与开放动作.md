# 06 动作层与开放动作：注册动作、动作构造器、LLM 提案与统一裁决

（2026-10-15 修订：写入用户"尊重玩家想象力"原则——§6.2 第 7 条、§6.9.5 兜底、§6.10.4/§6.10.6/§6.10.7、§6.11 指标、§6.12；罪名改由规范层判定（§6.5 第 3 步）；空间与方位进入构造器与裁决；配合第12章：RX、命名空间、合法性标注扩展点。）

本章是用户追加的核心需求。中心问题：**动作清单不能成为自由的上限**。接入 LLM 时像 DnD 一样"只要 d20 能过就能做"；不接入 LLM 时也要有充分的自由，并且全部玩法可玩。两层共用同一套效果原语、校验与裁决流程，区别只在"意图由谁翻译成原语"（玩家用构造器 / LLM 翻译）；两层最终都写同一套核心概念与事件，叙述只是投影。

## 6.1 现状与问题

- 25 个工具，operation 枚举 221 个（world_settlement 84、world_field 45、world_trade 40、world_law 18、world_companion 17），加 task/choice/action 二级枚举约 265 个动作；每加一个系统就往大工具里塞子操作，工具描述靠一句话解释几十个操作。
- 玩家叙述一个引擎没有专门动作的行为时，模型只能调 world_check：掷骰并记录成败（state.checks），成功后的世界后果没有写入口；叙述层的一致性审查又拦下账本里没有的结果。于是"d20 过了但世界不变"。
- 界面全是只读面板（创建角色除外）；一切改变世界的动作都要经模型选工具，每回合都花模型费用，模型不可用时游戏不可玩。
- 已有三个雏形可以升格：K2 交互表（元素/动作 × 性状 → 倍率与状态）、K6 效果注册表（时钟效果 kind → validate/apply）、M4 法术效果 effectSpec（kind + power + 参数，含注册表）。它们各管一片，没有统一的"原语"与"校验"。

## 6.2 目标（用户决定）

1. **B：不开 LLM 也能完整游玩**。对话、交涉、战斗、治理、法律、经营、制作、学习……全部玩法在纯界面下可玩；LLM 是可选的理解层与叙述层。
2. **A 式快捷按钮并存**：交易、移动、等待、制作、账目、休息、观察等常用操作一键入口。
3. **开放动作**：任何意图都能分解为少量效果原语在核心概念上的组合；注册动作只是预先写好的常用组合模板（带更好的数值与叙述）；未注册的意图走通用组合。
4. **两层结构**：
   - 第一层（无 LLM）= 注册动作（纯引擎结算）+ 动作构造器（玩家选"做什么/对谁或对什么/用什么/怎么做"，组合为原语，引擎按通用规则派生难度与幅度、d20 判定并应用；优先路由到匹配的注册动作）。
   - 第二层（有 LLM）= 自由叙述意图，LLM 提议效果组合，引擎校验裁剪后应用。
5. **裁决像 DM**：意图 → 提议的效果组合与难度 → 引擎按不变量校验可行性并给出难度与代价 → d20 → 按成败档位应用 → 事件、传闻、法律与立场连锁。LLM 只能提议，不能越过校验直接写状态；被拒时返回原因让叙述照实写。
6. 动作层与界面从一开始就按此目标做，不是后期阶段。
7. **尊重玩家想象力**（用户 2026-10-15）：给了玩家想象力就要尊重，不能出现玩家想到有意思的动作却被告知"不支持"。落实为五条硬规则：
   - "不支持"是缺陷，不是答复。做不到的事一律给**世界内原因**（"门是铁皮包的，徒手撬不动"）与**降级做法**（"用撬棍要半个时辰，会有响动"、"可以先去铁铺借工具"）。
   - **兜底原语"创造带标签的实体"**（§6.9.5）：任何创意至少能在世界里留下持久痕迹（崖上刻字、门口摆的石阵、编的一首讽刺歌），带 `mark:*` 与性状标签，各系统按标签反应。
   - 无 LLM 时，构造器兜底并**记录意图**，同时给出就近的注册动作作替代。
   - 学习回路把高频兜底意图补成注册动作（§6.12）。
   - 评估：意图语料 ≥ 30% 为刁钻创意意图，"不支持率"目标 0，且**每个兜底实体必须至少引起一个系统反应**（§6.11）。

## 6.3 效果原语（完整而最小的一组）

原语是规则、动作、提案能做的全部动作。每个原语：参数、校验项、幅度上限的来源、产生的事件。

| 原语 | 参数 | 校验（事务内） | 幅度上限来源 | 事件 |
|---|---|---|---|---|
| transfer | resource, from, to, qty | 两端账户存在；from 余额 ≥ qty 或有授信；from 属于发起者或经同意/经判决/经经营持有的动用权 | 发起者可支配余额；他人账户只能经同意、盗窃动作、判决、经营权 | transfer |
| holding.open | kind, holder, subject, terms, grantedBy | 种类已注册；两端模板匹配；互斥与份额；授予者有权（职位/所有者/法域） | 无数量；权限由持有派生 | holding_opened |
| holding.close | holding, reason | 存在；发起者是持有人/授予者/法域机构 | — | holding_closed |
| holding.transfer | holding, newHolder, consideration? | 可转让种类；对价（转移）同事务 | — | holding_transferred |
| obligation.create | kind, debtor, creditor, terms | 种类已注册；两端存活；债务人同意（本人/代理/判决） | 条款范围由种类数据限定（利率区间、期限上限） | obligation_created |
| obligation.settle | id, amount, partial? | 到期或提前；资金由 transfer 同事务 | — | settled / overdue |
| obligation.cancel | id, reason | 发起者是债权人或双方同意或判决 | — | cancelled |
| fact.set | entity, field, value/delta | 字段在该实体种类的可写白名单；范围；发起者有能力（技能/工具/时间） | 白名单 + 范围 + 能力表（例：condition 每小时最多 -k/技能阶） | fact_changed |
| vital | target, delta, type | 目标在场可及（近战须同分区或相邻，投射读距离与遮挡）；伤害经 K2 倍率与防护；治疗需同意规则 | 武器/法术/体术伤害公式；治疗按阶 | harm / heal |
| status | target, status, duration, magnitude | 状态已注册；叠加规则；精神类需同意 | 持续与强度按来源阶 | status_applied / removed |
| move | entity, to（地点或分区，或"朝某方位/走近某人"）, mode | 路线或分区邻接存在且可通行；耗时由路线/分区距离派生；同行者随行；进入权限；分区内移动可被打断 | 不可瞬移；速度表 | moved |
| create | kind, template, facts, materials | 种类/模板存在；材料经 transfer 消耗；名称碰撞；署名；**兜底形式** `create(kind: mark, tags: [mark:*、性状], facts: {intent, form, location/zone, author})` 无需模板、不带资源与数值效果，只要标签在词汇表内且所用材料（若有）真实 | 只能按配方/模板/即兴规则；不能凭空造有价之物；兜底实体价值为 0 | created |
| destroy | entity | 发起者是所有者或经判决/灾害；进入 transition(gone) | — | destroyed |
| emit | verb, actor, target, tags, payload, visibility | 动词在词汇表；payload 子类：tell(版本,源)、impress(delta,reason)、request(kind,terms)、claim | impress 幅度 ≤ 事件权重表；request 不决定对方答复 | 该动词 |
| schedule | at, rule/action, args | 规则存在 | — | scheduled |
| transition | entity, kind, cause | 见 04 | — | transition |
| learn | entity, subject(skill/spell/recipe), amount, source | 来源存在（导师/书/研究）；前置；每日上限与衰减 | practice 规则 | learned |
| time | minutes | 单调 | 由动作派生，不由提案自定 | — |

与现有雏形的关系：
- 提案不能产出 `belief`：信念只能由推断规则产生（05 §5.4）；玩家想让 NPC 相信某事，要用 tell/deceive（emit），结果进入对方主观视图由其自行判断。
- K2 交互表是 `vital`/`status`/`fact.set` 对材质与元素的物理规则（倍率、点燃、冻结、留痕）——保留为原语内部的参数表。
- K6 效果（报价、开灵、野物躁动、迁移、传闻、立场、环境、关系、争端、贸易）全部可写成上述原语：报价 → 市场投影输入事实；开灵 → fact.set(灵智)；躁动/迁移 → transfer(population)；传闻 → emit(tell)；立场 → emit(impress)；环境 → status/fact.set；关系/争端 → fact.set(组织关系)；贸易 → transfer。时钟规则改为直接产出原语，效果注册表退役为兼容适配器。
- M4 法术 effectSpec（damage/heal/status/protection/transfer/object-state/light/mind/movement/summon/area/growth/message/care/ritual……）映射到原语组合：damage → vital；heal/care → vital(+同意)；status/protection → status；transfer(水土) → transfer(资源)；object-state(dry/repair) → fact.set(condition/标签)；light/optics → status(区域)；mind → status(+同意+合法性标签)；movement → move；summon → create(实体)+obligation(upkeep)；area → schedule(周期 vital/status)；growth → fact.set(生长阶段, 上限)；message → emit(tell)。effectSpec 的数据格式保留（150 法术不重写），由适配器翻译；法术阶段决定幅度上限。

## 6.4 动作注册表（注册动作 = 带数值与叙述的原语模板）

动作是规则的第四种形状，由玩法包以数据声明，自动进入目录、界面、LLM 工具面和意图匹配。字段：

```json
{
  "id": "lend",
  "pack": "lending",
  "verb": "借钱给",
  "group": "经营",
  "participants": {"actor": ["person"], "target": ["person", "org"]},
  "slots": [
    {"name": "target", "kind": "entity", "filter": "present && adult && !impaired"},
    {"name": "amount", "kind": "quantity", "resource": "coin", "max": "actor.account(coin)"},
    {"name": "terms", "kind": "choice", "options": "rx: termOptions(actor, target)"}
  ],
  "preconditions": ["actor.present(target)", "actor.account(coin) >= amount", "standing(target, actor) > -20"],
  "consent": {"from": "target", "decide": "npcDecision(request:lend, terms)"},
  "cost": {"time": 10, "resources": []},
  "check": null,
  "outcomes": {
    "accepted": [{"op": "transfer", "resource": "coin", "from": "actor", "to": "target", "qty": "amount"},
                 {"op": "obligation.create", "kind": "loan", "debtor": "target", "creditor": "actor", "terms": "terms"}],
    "conditional": [{"op": "emit", "verb": "counteroffer", "payload": "decision.terms"}],
    "refused": [{"op": "emit", "verb": "refuse", "payload": "decision.reason"}]
  },
  "visibility": {"catalog": "present(person|org)", "witness": "public"},
  "narration": {"template": "你把{amount}铜交给{target}，约定{terms}。", "tags": ["finance"]},
  "llm": {"synonyms": ["放贷", "借给", "周转"], "examples": ["我借给老秦一百两，分十二期"]},
  "ui": {"quick": false, "icon": "coin", "form": "amount,terms"}
}
```

要点：
- 动作 id 允许命名空间（`hantan:join_sect`），槽位选项、前置、幅度都用 RX 或 L1 库函数（第12章 §12.8.1），不引用包内 .mjs；叙述模板与事件流模板必填。
- **检定可有可无**：交易、移动、等待、制作（按配方）是确定性动作，`check: null`；撬锁、劝说、潜行、狩猎有检定，`check` 声明属性/技能/难度派生式或对抗对象。
- **同意走 NPC 决策规则**（05 §5.7），动作只声明"向谁请求什么"。
- **档位效果**：有检定的动作声明 fumble/failure/partial/success/critical 五档的原语列表或倍率；缺省按通用档位表（§6.6）。
- **可见性**决定目录投影：何时出现在"此处可做/对 TA 可做"，以及事件的见证范围。
- **叙述模板**供无 LLM 模式与系统提示；有 LLM 时作为"必须包含的事实"约束。
- 现有 265 个操作在迁移第一步由脚本从 tools.mjs 枚举 + 引擎处理器自动生成动作清单（最小元数据：id、所属工具与 operation、参数 schema），之后逐包补齐前置/同意/可见性/模板。

## 6.5 统一裁决流程

```
意图（玩家构造器 / LLM 提案 / 注册动作直接调用 / NPC 自治）
  │
  ▼ 翻译：构造器把选择组合成原语；LLM 输出 world_propose；注册动作展开模板
提案 {intent, participants, effects[], means, context}
  │
  ▼ 1 解析：所有引用解析到实体（EntityResolver，歧义返回候选，不猜）
  ▼ 2 路由：与注册动作匹配（§6.8）→ 命中则改走该动作（带回 routed 标记）
  ▼ 3 校验与裁剪：
       存在与在场（目标在同一节点，按分区距离与视线可见/可及；需要靠近的动作先走 move 到相邻分区）
       能力（技能/职业/身体状态/工具/魔力/负重）
       同意（对他人身体、财产、精神、私宅：本人/监护人/法典紧急条款；NPC 决策规则给出答复）
       守恒（资源来源真实；create 需材料/模板）
       合法性（不阻止：动作附加描述标签——unconsented、deceive、forced、stealth……；第12章"合法性标注"规则对提案原语与持有状态求谓词；预览用规范栈给出"在此地会构成什么罪、谁会看见"，正式立案在归约后由法律包对事件求规范栈谓词，05 §5.2）
       物理（路线、分区与方位、距离、遮挡与视线、容量、材质、天气、光线）
       幅度上限（每个原语按 §6.7 派生的上限裁剪，裁剪项带原因返回）
  ▼ 4 难度与代价派生：难度 = 原语族基础 + 目标抗性 + 幅度比 + 情境(±5，须理由)；代价 = 时间 + 资源 + 风险；写入提案
  ▼ 5 检定：沿用 checks.mjs 的 d20 与五档（大失败/失败/勉强/成功/大成功）、对抗、优势劣势、协助、工具加值、隐藏被动；确定性动作跳过
  ▼ 6 按档位应用：大失败 = 反噬列表（通用：时间加倍 + 自伤/暴露/损坏）；失败 = 仅代价 + 暴露；勉强 = 幅度 ×0.5；成功 = ×1；大成功 = ×1.25 + 额外（省时/不留痕）
  ▼ 7 归约：一个父事件（提案原文、骰值、裁剪记录）+ 原语子事件；反应规则自动产生法律、立场、传闻、记忆、停工等连锁——提案者不需要也不能提议连锁
  ▼ 8 返回：applied / trimmed(原因) / check / consequences / narrate{must, mustNot}
```

NPC 自治包的行动走同一管线（意图来自需求→目标→动作），所以 NPC 可以做玩家能做的一切（犯罪、卷款、逃亡、自荐、决斗）。

## 6.6 通用档位与反噬表（数据）

| 原语族 | 大失败 | 失败 | 勉强 | 成功 | 大成功 |
|---|---|---|---|---|---|
| fact.set（改物） | 工具损耗 ×2、物件 condition 额外 -k、留痕 | 无效果、耗时、留痕 | 效果 ×0.5 | ×1 | ×1，耗时 ×0.5，不留痕 |
| vital（攻击） | 自伤或失衡状态 | 未中 | ×0.5 | ×1 | 暴击倍率（combat 规则） |
| emit(request)（社交） | 对方立场 -k，拒绝并记仇 | 拒绝 | 有条件同意 | 同意 | 同意 + 立场 +k |
| move（潜行/越障） | 被发现 + 摔伤 | 被发现 | 到达但被怀疑 | 到达 | 到达且无人察觉 |
| create（即兴制作） | 材料全失 | 材料半失 | 粗劣品 | 普通品 | 精良品 |
| learn（自学） | 误解：熟练度 -k | 无进展 | 半收益 | 正常 | 加倍（受每日上限） |

## 6.7 防滥用与平衡：幅度上限与难度派生

- **上限来自规则与状态，不来自提案者**：
  - vital：武器/体术/法术阶段的伤害公式（combat/magic 数据）。
  - transfer：自己账户任意；他人账户只能经同意（NPC 决策）、盗窃动作（检定 + 价值上限 maximumTheftCoins/重量）、判决、经营权（economy 数据的动用上限）。
  - fact.set：按实体种类的白名单字段与范围；破坏/改造物件按"技能阶 × 工具 × 时间"的工作量表折算，所以"砸开城门"会被折算成需要 N 小时与工具的工程，不是一次检定。
  - create：只能按配方（材料、工具、时间）或"即兴制作"规则（材料需具备所需性状标签，产物 crude 品级、低耐久），不能凭空；新命名实体经 world_create 登记但不带资源；兜底的带标签实体（§6.9.5）不带资源、不带数值效果，所以不会比任何注册动作更划算。
  - emit(impress)：幅度 ≤ 事件权重表（K4 已有权重）；emit(request) 不决定答复。
  - status：持续与强度按来源阶；精神类必须同意（C1）。
  - learn：每日上限与重复衰减（practice 规则）。
  - time：由动作与路线派生，提案不得自报耗时（7.3 原则）。
- **难度派生**：`难度 = 基础(原语族 × 目标类) + 抗性(材质硬度 / NPC 灵智与立场 / 守卫警觉) + 幅度比(请求幅度 ÷ 上限 的分段加值) + 情境(±5，须理由，现有规则) `；对抗检定沿用对手属性/技能 + 适应加值（屡用同一手法被识破）。
- **不能比注册动作更划算**：对每个开放提案找最近邻注册动作（按原语签名与目标种类）；代价取 max(注册代价, 通用代价)，收益取 min(注册收益, 通用收益)；无最近邻时用通用表（刻意保守：难度 +2、耗时 ×1.5）。
- **期望值天花板**：按技能阶段的典型日收入表（3.13）设每日产出上限；超过的提案被裁剪并提示"以你的手艺，一天做不出这么多"。
- **重复衰减**：同签名提案 24 小时内收益逐次减半（沿用练习衰减）。
- **社交不越权**：说服、威胁、贿赂、欺骗都是 emit(request/deceive) + 对抗检定，结果进入 NPC 决策规则作修正项；提案不能直接 holding.open(别人的门禁) 或 transfer(别人的钱)。
- **法律不拦截但必记**：违法提案照常裁决，事件带描述标签与（按感知派生的）见证，罪名由规范栈判定；玩家得到"会被谁看见、在此地构成什么"的预览（构造器）或 consequences（LLM）。

## 6.8 优先路由到注册动作

- 签名 = {(op, 目标种类, 字段/资源类)} 多重集。
- 候选 = 参与者模板匹配且可见性成立的注册动作。
- 得分 = 0.6 × 签名 Jaccard + 0.4 × 意图文本匹配（动作名、同义词、示例，用 retrieval.mjs 的二元切词 BM25）。
- 得分 ≥ τ（初值 0.7）→ 路由：按该动作的槽位从提案抽参数（缺槽返回候选让提案者补），用该动作的数值与叙述模板；返回 `routed: action id`。
- 得分 < τ → 开放路径，但最近邻仍用于"不更划算"比较。
- 路由结果可解释：返回"按'撬锁'结算"，LLM 与界面都能显示。

## 6.9 第一层：不接入 LLM 的完整可玩

### 6.9.1 动作目录的界面投影
- **对象菜单**：点人物 → "对 TA 可做"（交谈、交易、雇佣、借钱、告发、拜师、送礼、挑战……按可见性过滤）；点地点/设施 → "此处可做"（进入、观察、采集、买粮、办事……）；点物品 → 使用、交给、出售、典当、阅读、修理。
- **推荐**：由场景派生——到期义务（"今天该还钱了"）、任务进度、需求（饥饿→吃饭、夜晚→住宿）、未读信件、待批事项。
- **最近常用**与**搜索**（本地 BM25 同一索引）。
- **快捷栏（A 式）**：交易（打开与在场商人的交易面板）、移动（地图选目的地，显示耗时花费风险）、等待（时长/到钟点）、制作（配方面板）、账目（账户与义务）、休息、观察四周、说/做切换。
- **动作构造器**只出现在"其他…"：四步选择——做什么（原语族的玩家用语：改变/破坏/搬动/拿取/交给/隐匿/调查/劝说/威胁/即兴制作/**留下点什么**……）→ 对谁或对什么（按可及性过滤的实体选择器，也可选分区与方位："茶摊旁边""东侧墙根"）→ 用什么（持有的物品、会的技能/法术）→ 怎么做（谨慎/迅速/强硬/隐秘/巧妙 → 映射到属性/技能/风险）。构造器组合成原语提案，经 §6.5 管线；**预览**显示难度、耗时、代价、会被谁看见、法律后果、预期效果、是否路由到某注册动作（"这相当于：撬锁"），确认后结算。玩家不会迷失，因为入口是对象与场景，构造器是兜底。

### 6.9.2 对话与交涉（无 LLM）
对话是一组注册动作（组 交谈），界面为对话面板：
- 寒暄：按立场回应；立场够高时带出"此刻最挂心的事"（目标进度派生）。
- 打听 X：X 从玩家知道的实体与本地话题中选；NPC 从自己的主观视图回答（亲见 / 传闻版本 / 自己的推测 / 不知道，05 §5.4）；诚实倾向可能说谎（谎言 tell，失真模板生成）。
- 请求（带路/送货/借物/借钱/帮忙/让路/放行/引见）：NPC 决策规则给出四种答复之一；有条件同意显示条件（价格、前提），玩家可接受/还价。
- 议价：出价/还价回合，接受阈值由人物议价规则与立场派生。
- 劝说/威胁/贿赂/欺骗：对抗检定 → 决策修正；贿赂与威胁打罪名标签。
- 承诺：创建玩家为债务人的义务。
- 告知/传话：tell 事件（玩家可散布消息）。
- 学艺/求诊/雇佣/交易：转到对应面板。
- 道别。
NPC 台词由模板库拼装：`templates/dialogue/<文化>/<语域>/<动作>_<答复>.json`，槽位填名字、价格、理由、替代方案（"该找谁"由本地职位与服务派生）、人物数据的样例台词与谚语作风味句。质量目标是"可读、符合人设、不出戏"，不追求文学性；开 LLM 时同一答复与事实交给模型改写成散文，答复本身不变。

### 6.9.3 其他玩法的无 LLM 形态
- 战斗：已是引擎交锋；交锋读分区距离与遮挡（近身、投射、掩体、退入门内）；界面给意图（攻/防/脱离/推搡/移位）与战术选择；敌方战术由规则（士气、灵智、适应）选；文字来自交锋模板。
- 施法/制作/学习/研究：表单（目标、材料、来源），结果模板。
- 治理/组织/法律：提案、表态、任免、入会、起诉、上诉都是表单动作；引擎拒绝时给世界内原因。
- 任务/义务/信件/公告：面板已规划（12.4）；接受/交付是动作。
- 远方与旅行：地图规划（12.5）直接出发，不再"填进输入框由玩家发送"。
- 离屏：无 LLM 时只跑规则层与时钟层（指南 5.9 允许），智能层关闭；回访摘要用模板。

### 6.9.4 没有叙述时信息怎样呈现
- 场景头（时间、天气、地点路径）+ 地点描述，**按方位组织**：玩家所在分区 → 各方向相邻分区上能感知到的实体与活动（"东侧铁铺门口：王二在打铁；北面小路通往山上；身后茶摊有人低声说话（听不清）"），文字由方位模板直接生成，只含玩家能感知的内容；再加作者的感官素材（季节×时段×天气）与此处可做。
- 在场人物与状态行（"林穗在擦柜台"，日程派生）。
- 事件流：每个动词有模板（数据），槽位填实体称呼与数量："你付给林穗 6 铜。""吴朔说：……（他说是听来的）"。
- 系统提示卡片（12.2）照旧。
- 面板（角色、技能、行囊、人物、任务与约定、地图、领地、编年史、传闻）全部读投影。
- 知情边界天然保持：界面只渲染玩家知情集合；对话选项只来自 NPC 知情集合；与 LLM 模式用同一投影代码。

### 6.9.5 兜底：任何创意都留下痕迹

- **触发**：构造器四步组合出的原语提案校验全部失败、或玩家的意图（自由文本或构造器"留下点什么"）不对应任何原语组合时，不回答"不支持"，而是：①给世界内原因与降级做法；②列出最近邻注册动作；③提供兜底选项"就这样做，留下痕迹"。
- **兜底原语**：`create(kind: mark, ...)`。玩家（或 LLM）为它选：形态（刻痕、摆放物、涂画、歌谣、口号、仪式残迹、陷阱样的布置……）、位置（分区）、标签（从 `mark:*` 族与 K1 性状中选，例如 `mark:insult`、`mark:sacred_symbol`、`mark:warning`、`mark:frost`、`flammable`），意图原文存为事实。可消耗真实材料（墨、石、花），不带资源与数值效果。
- **系统反应**：反应规则订阅 `mark:*`——看到者（感知派生）产生立场印象与 tell；宗教包对 `mark:sacred_symbol`、法律包对 `mark:defacement`（毁损公物谓词）、精怪对 `mark:offering`、门派包对 `mark:sword_carving`（第12章 §12.2.3）……每个 core 的 `mark:*` 标签都必须至少有一条反应规则订阅（构建期校验），所以兜底实体至少引起一个系统反应。
- **记录意图**：每次兜底写入提案日志（意图原文、选择的标签、最近邻、后续反应），供学习回路聚类。
- 有 LLM 时同一兜底可由模型提议（§6.10.6 所有档位开放），模型只能选标签与形态，不能附加效果。

## 6.10 第二层：接入 LLM

### 6.10.1 工具面（≤ 16，静态提示不随动作数增长）
| 工具 | 职责 | 备注 |
|---|---|---|
| world_query | 实体当前视图、可及性与可做之事（affordance 卡）、账户 | 合并 world_read |
| world_search | 长期事实与原聊天文本检索 | 保留 |
| world_catalog | 规则、文化、势力、历史、地区分页 | 保留 |
| world_actions | 动作目录检索（按目标/关键词/场景），返回槽位 schema | 新 |
| world_act | 执行注册动作：{action, slots} | 新；承接 265 个操作 |
| world_propose | 开放动作：{intent, effects[], means, context} | 新；§6.10.3 |
| world_move / world_time / world_talk / world_trade / world_combat / world_cast / world_craft / world_learn | 高频动作的固定 schema 别名（调用正确率高） | 内部都是 world_act |
| world_create | 登记叙述中新出现的具名实体（不带资源） | 保留 |
| world_remember | 有源事实、传闻、谎言与揭穿（知识原语的壳） | 保留 |

退役：world_check（并入 world_propose，effects 为空即纯检定）、world_relation（立场只能由事件派生）、world_attributes/world_revival/world_profession/world_quest/world_promise/world_research/world_settlement/world_field/world_companion/world_law（全部成为注册动作，经 world_act；旧调用名在回放与过渡期由 resolveToolCall 映射）。

静态区：工具一句话描述（≈500 token）+ 原语语法与一个 world_propose 示例（≈600 token）；枚举全部移出。动态尾部：场景卡新增"可做之事"段（≤ 600 token：在场实体与地点的高相关注册动作 id 与一句说明），更多靠 world_actions 检索。

### 6.10.2 两阶段协议：先查再提
1. **查**：模型对打算影响的实体调 world_query，得到 affordance 卡：该实体当前状态摘要 + 对发起者可行的原语与上限 + 相关注册动作 id。例："仓房门：locked=true；可做：撬锁(action:break_in，需敏捷/开锁，难度15)；破门(fact.set condition，需工具与约30分钟，会有声响)；不可：进入（无许可）"。
2. **提**：调 world_act（命中注册动作）或 world_propose。
这避免了最常见的错误：对不存在/不在场的目标提议、凭空造物、无视门禁。

### 6.10.3 world_propose 的格式
请求：
```json
{
  "intent": "趁夜撬开仓房的门锁",
  "effects": [{"op": "fact.set", "target": "bld_hw_granary", "field": "locked", "value": false}],
  "means": {"skill": "skill_lockpick", "tools": ["item_lockpick"], "manner": "stealthy"},
  "context": {"modifier": 2, "reason": "夜深无人"},
  "expect": "进入仓房"
}
```
响应：
```json
{
  "routed": "break_in",
  "applied": [{"op": "fact.set", "target": "bld_hw_granary", "field": "locked", "value": false}],
  "trimmed": [],
  "check": {"die": 14, "modifier": 5, "difficulty": 15, "degree": "成功"},
  "consequences": ["耗时 8 分钟", "无人察觉（后院无视线，打更人在街心听不到）", "按本地法典构成 offense:break_in（无见证不立案）"],
  "narrate": {"must": ["门锁被撬开"], "mustNot": ["仓房里的粮食归你", "有人看见"]}
}
```
`narrate.must/mustNot` 是叙述约束；一致性审查按它核对。

### 6.10.4 失败、部分成功与拒绝
- 五档结果按 §6.6 应用；叙述约束随档位生成（失败："锁没开，撬棍滑了一下"）。
- 拒绝（校验不过）返回世界内原因、降级做法与可选替代（最近邻注册动作、缺的前提："需要先取得林穗的许可"）以及兜底选项（§6.9.5）；永远不返回"不支持/无法执行此类动作"这类场外语句；叙述必须照实写失败，不得写成成功（宪章 + 审查）。
- 歧义返回候选，不猜。

### 6.10.5 错误防护
- 选错目标：解析到候选而非猜测；affordance 卡在提案前暴露目标状态。
- 凭空造物：create 必须有模板/配方与材料；transfer 来源必须有余额；未知实体必须先 world_create（且不带资源）。
- 遗漏连锁：提案者不负责连锁；法律、立场、传闻、停工、记忆由反应规则产生；提案里若包含连锁（例如自报立场变化），按幂等键去重或裁剪。
- 幅度越界：裁剪并返回原因。
- 叙述 ≠ 已应用效果：一致性审查（8.5）的确定性部分从"叙述 vs 账本差分"改为"叙述 vs applied + must/mustNot + 方位事实"，更精确；严重不符自动改写一次，仍不符则显示模板文本（无 LLM 模式的文本）作为兜底。
- 可重放：提案原文、骰值、裁剪记录写入事件；重放不再调用模型。可撤销：沿用消息删除后按锚点回滚。

### 6.10.6 模型能力分级（配置）
- `openActions: off`：world_propose 不提供，模型只能 world_act / 别名工具 / world_actions 检索（低能力模型）；兜底经 world_act 的通用动作 `leave_mark` 仍可用。
- `openActions: limited`：允许 fact.set/vital/move/emit(request/tell)/learn 与兜底 `create(kind: mark)`，不允许其他 create、holding.open、obligation.create（这些走注册动作）。
- `openActions: full`：全部原语。
- `narration: off | async | sync`：无叙述 / 先结算后异步补写 / 同回合。
- `intent: off | match | propose`：自由文本是否被模型理解；`match` 模式下模型只做目录匹配（输出动作 id 与槽位）。

### 6.10.7 混合回合流程（两层共存）
1. 界面动作 → 引擎结算 → 模板文本立即显示 → 若开叙述：把事件与约束交给 LLM 异步补写 → 散文到达后替换/叠加模板文本 → 审查；模型失败或超时，模板文本留着，游戏不等模型。
2. 自由文本 → 若开 LLM：模型查/提 → 结算 → 同回合叙述 → 审查；若不开：本地目录匹配给出"你是想……？"的动作建议；匹配不到时打开预填了文本线索的构造器，并始终附带兜底选项"就这样做，留下痕迹"（§6.9.5），意图原文记入日志。不出现"这里做不到"式的场外答复；确实不可能的事以世界内原因说明并给降级做法。
3. 两种入口写同一事件日志；面板永远显示同一事实。

## 6.11 评估方法

- **意图语料** `tests/intents/*.json`：≥ 200 条自由意图（来自指南 11.3 的 F5 "用净水术卖干净水"等场景、run-001/run-002 的主动事件、日志里的真实提案），其中 **≥ 30% 为刁钻创意意图**（不对应任何注册动作、组合奇特、借用场景里的偶然物件、带方位的行为如"走到茶摊旁边偷听"），由未参与设计者编写；每条标注：期望路由（注册动作 id、open 或 mark 兜底）、期望原语签名、允许的最大幅度、期望的拒绝/裁剪原因与降级做法。
- **三级运行**：T0/T1 用桩翻译器（直接取语料的签名）只测引擎侧：路由、裁剪、档位、连锁、叙述约束；T2 用真实模型跑翻译，统计路由准确率、签名匹配率、越界裁剪率、拒绝正确率、叙述一致率；T3 加浸泡。
- **指标**（初值）：路由准确率 ≥ 90%；签名匹配 ≥ 85%；越界全部被裁剪（0 漏网）；拒绝正确 ≥ 95%；叙述一致 ≥ 95%（含方位一致）；**不支持率 = 0**（任何意图都得到结算、降级做法或兜底，不出现"不支持"）；**兜底实体反应率 = 100%**（每个兜底实体在 7 天推进内至少引起一个系统反应：印象、tell、立案、宗教或精怪反应……）；无 LLM 模式下 11.3 的 L/T/S/F 类场景可用界面动作脚本化为确定性测试并 100% 通过。
- **事件推演扩展**：run-00N 增加"意图推演"题（玩家叙述一件未注册的事），核对者判定裁决是否合理。
- **分级验证**：同一语料在 off/limited/full 三档下跑，确认低档不出现越权原语。

## 6.12 学习回路

- 每个开放提案记录：意图文本、原语签名、目标种类、是否路由、裁剪原因、结果档位、玩家是否重试。
- 兜底意图单独聚类：同类兜底（按意图文本与所选标签）出现 ≥ N 次即生成候选注册动作卡，优先于普通开放提案。
- 周期报告按（签名, 目标种类）聚类；出现 ≥ N 次或被拒绝 ≥ M 次的簇生成"候选注册动作卡"（数据草案：槽位、前置、数值建议来自实际裁决），经内容流水线 L1/L2 审名称与描述后入库。
- 拒绝原因聚类暴露缺失的可及性（例如"没有'爬窗'的物理规则"），作为规则数据的补充依据。
- 注册动作的调用频率反过来决定"可做之事"的排序与快捷栏默认。

## 6.13 与现有系统的衔接（供 10 迁移路线引用）

- resolveToolCall 的分组映射（world_field/companion/law → 内部工具）已经是"注册表 → 处理器"的雏形：第一步把全部 25 工具 × 操作自动导出为动作清单，world_act 经同一映射执行；旧工具名保留为别名供回放。
- /execute 路由已能执行工具调用，界面无需模型即可调用——无 LLM 第一层的后端入口现成，缺的是界面与模板文本。
- checks.mjs 的骰子、五档、对抗、协助、工具加值、隐藏被动全部复用为裁决第 5 步。
- consistency-review 的确定性检查改读 applied/must/mustNot。
- prompt/ 静态区缩减枚举后，为原语语法腾出预算。
