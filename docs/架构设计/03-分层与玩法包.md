# 03 分层、依赖方向与玩法包的标准形状

（2026-10-15 修订：吸收 run-002 审查第 2、3、5、7 条与第12章 §12.11 的配合修改。）

## 3.1 五层

| 层 | 职责 | 允许依赖 | 禁止 |
|---|---|---|---|
| L0 内核 | 事件日志与归约、事务与不变量校验、账户与转移（含批次键）、实体/持有/义务存储与索引（按持有人、按标的、按地点、按到期）、时钟与日程堆、规则注册表（按纪元重建）、效果原语执行器、掷骰（战役种子 + 对象 + 日期）、RX 求值器（第12章 §12.8.1） | 无 | 任何领域词汇：内核不知道什么是"死亡""税""租金" |
| L1 本体 | 标准实体模板与种类、持有种类目录与交接类、义务种类基类（含 onDebtorGone 枚举）、资源种类表、事件动词与标签词汇表、地点树与**规范栈解析**（主权法典 + 次级规范 + 成员规范 + 域外条款，条款查询 API `norms.clause()` / `grace()`）、转移协议、实体视图（统一读 API）、**主观视图 API**（知情集合 + belief 覆盖）、**修正槽注册与派生合成器**、NPC 决策规则骨架（5.7 顺序，只读主观视图）、作者数据→持有/账户的转换器 | L0 | import 任何玩法包；内置具体数值表（数值在包的数据里） |
| L2 玩法包 | 经济、法律、治理、家族、组织、宗教、教育、医疗、运输、生态、魔法、战斗、职业、NPC 自治、远方生成……每个包 = 数据 + 规则 + 订阅 + 动作（+ 规范条目、修正项、推断规则） | L0、L1 | 包与包互相 import；直接读写内核存储；新增工具；私造词汇 |
| L3 投影 | 实体视图的组合、市场报价、立场、知情集合与记忆流的缓存、日程、编年史、场景卡素材、返场摘要、动作目录投影（界面菜单/可做之事）、存档快照与分片 | L0–L2 只读 | 写状态 |
| L4 接口 | 工具面（≤ 16 个）、LLM 提示组装、界面（面板、菜单、动作构造器、对话面板）、离屏调度驱动、一致性审查、存档读写与迁移、包加载器（第12章） | L2 动作目录、L3 | 包含规则 |

说明：知情集合与主观视图的**派生函数**属 L1（决策骨架要读它们，L1 不能依赖 L3）；它们的**缓存**与场景卡组合在 L3。规范栈同理：解析与条款查询在 L1，立案与审判流程在法律包。

## 3.2 依赖规则（消除循环）

1. **方向只向下**。L2 向 L1 注册（持有种类、义务种类、资源种类、规则、动作、词汇扩展、规范条目、修正项、推断规则），L1 只调用注册表，从不 import 包。这是"待吸收"里 entity-transitions ↔ obligations 循环的根治：交接规则由各包注册，协议本身不认识任何包。effect-registry（K10 已把注册表移入无依赖模块）是同一思路的雏形。
2. **包之间不通信**。A 包想影响 B 包，只能经五种连接点：
   - 发带标准标签的事件（B 订阅）；
   - 改共享账户（B 的派生读到）；
   - 开关共享持有（B 的视图读到）；
   - **向 B 的派生开放的修正槽注册修正项**（05 §5.9；例：堪舆包对设施包的 `facilities:fireRisk` 乘系数）；
   - **声明规范条目**（05 §5.2；例：盐引包声明"无引运盐"的罪名谓词，作用于运输包产生的 move/transfer 原语，运输包零改动）。
   医疗包订阅一切 `harm:injury`（来自战斗、火灾、坠崖、野兽），法律包对一切事件求规范栈中的罪名谓词，立场包订阅一切带见证的 harm/gift，市场投影读一切账户与未到期交付义务。新包加入时老包零改动即被"相乘"。
3. **词汇表是包之间唯一的契约**，放在 L1 数据文件：事件动词与标签、持有种类、资源种类、商品类（`goods:*`）、性状标签（K1）、罪名标签、状态标记、兜底标签族（`mark:*`）。加词汇要过校验；私有词须带命名空间，共享词须挂在已有族下并过同义检查（第12章 §12.3.3）——现状两套元素词表、七份态度账的病根就是私造同义词。
4. **自动守卫**：一条 import 图测试解析所有模块（含动态 import），向上或包间的边即失败（I19）。
5. **注册时机与纪元**：注册表只在**纪元边界**变化。纪元边界是：开局；以及存档中的 `pack.install`、`pack.upgrade`、`pack.uninstall`、`world_upgrade` 事件——这些事件只能在载入存档流程中、经玩家确认后、第一个回合之前产生，规则、动作、工具、LLM 都不能产生。每到一个边界，注册表按依赖拓扑序（同层按包 id 字典序）一次性重建：拒绝重复 id、缺字段、未知词汇、未声明依赖的引用、槽位冲突；重建完成后冻结，直到下一个边界。回合、推进与离屏期间不能增、改、删任何定义。卸载或升级不删除定义：被移除的定义转为**退役条目**（定义快照写入存档的退役表），退役条目参与解析、归约与历史渲染，不参与任何新提案。每个事件记录所属纪元，从而任意时刻的注册表都可由存档唯一重建（第 12 章 §12.5.5）。
   - 注：议案通过后改变的是组织实体的法典/章程**事实**（规范条目的内容），不是注册表里的定义；它是普通事件，不需要纪元边界（05 §5.2）。

## 3.3 玩法包的标准形状

一个包是一个目录 `packs/<name>/`，含 `manifest.json`（声明）、`rules/*.json`（数据，表达式用 RX）、`tests/`；`*.mjs` 只在一方包或 trust=native 的包中允许（第12章 §12.8.1），且只能 import pack-api。manifest 的完整字段（format、version、engine、contract、vocabulary、license、dependencies、slots、uninstall……）以第12章 §12.2.2 为准，下面只展示与规则相关的部分。声明示例（以"放贷"包为例）：

```json
{
  "id": "lending",
  "version": "1.0.0",
  "vocabulary": {
    "obligationKinds": ["loan"],
    "verbs": ["lend", "repay", "overdue", "default"],
    "tags": ["finance", "breach"]
  },
  "holdings": {},
  "obligations": {
    "loan": {
      "schedule": {"kind": "installments|single", "period": "month"},
      "accrual": {"closedForm": "principal*rate*days/360"},
      "penalty": {"closedForm": "overdueDays(grace)*penaltyRate"},
      "settle": [{"op": "transfer", "resource": "coin", "from": "debtor", "to": "creditor", "amount": "due"}],
      "shortfall": [{"op": "obligation.settle", "partial": true}, {"op": "emit", "verb": "overdue"}],
      "default": {"after": 3, "readsGrace": true, "effects": [{"op": "emit", "verb": "default", "tags": ["breach"]}, {"op": "holding.transfer", "kind": "pledged", "to": "creditor"}]},
      "handover": {"creditor": "estate", "debtor": "estate"},
      "onDebtorGone": "assume_by_heirs",
      "onCreditorGone": "estate"
    }
  },
  "derivations": {
    "interestRate": {"rx": "clamp(base.rate * standingFactor(creditor, debtor), terms.minRate, terms.maxRate)", "slots": ["lending:interestRate"]}
  },
  "modifiers": [],
  "inferences": [
    {"id": "missed-installments", "premise": "overdueCount(obligation) >= 2 && knows(self, obligation)", "candidates": [{"belief": "debtor_insolvent", "weight": "1 - trait(self,'trusting')"}], "confidence": 0.6}
  ],
  "norms": [],
  "reactions": [],
  "clock": [],
  "actions": ["actions/lend.json", "actions/repay.json", "actions/forgive.json"],
  "data": ["rules/lending.json"],
  "reads": ["view.person", "view.account", "view.place", "norms.clause"],
  "prompt": {"staticTokens": 0}
}
```

与初版的差别（run-002 修订）：
- 删掉了 `handover.impaired: "suspend"`：失能与在途不暂停义务；`default.readsGrace` 表示违约计数读规范栈的宽限条款（05 §5.2、I29）。
- 新增 `onDebtorGone` / `onCreditorGone`（04 §4.2）。
- 立案不再写在放贷包里：违约事件带 `breach` 描述标签，是否构成罪名、能否起诉、适用哪部法，由法律包按规范栈判定（§3.4）。
- 派生用 RX 表达式并声明自己开放的修正槽；`modifiers`、`inferences`、`norms` 三个键是新增的规则形状入口（01 §1.8）。

要点：
- **声明决定接入**：包声明的持有/义务/动作/订阅/修正项/规范条目决定它"接"上什么，而不是它调用了谁。
- **读**：只经实体视图、主观视图、账户查询、规范条款查询（L1/L3 的只读 API）。
- **写**：只产提案（原语列表）。
- **时钟**：绝大多数包不需要时钟规则，因为到期项由义务日程登记；只有真正的周期过程（再生、生长、腐坏、计划阶段、状态评价）登记时钟规则。
- **动作**：包把玩家/NPC 可发起的行为声明为动作数据（06 动作层），不新增工具。
- **提示预算**：包声明自己的静态提示增量（必须为 0）；动作的 LLM 可见描述只在目录检索时进入动态尾部。
- **测试**：包自带 `tests/`（累计闭式 = 逐日累加；死亡后无对死者的 default；修正项不影响未命中实体），由 `pack test` 执行（第12章 §12.7）。

## 3.4 三个包的形状速写

**火灾（在设施包内）**
- 词汇：标签 `fire`、`burning`、描述标签 `cause:negligence`；动词 `ignite`、`spread`、`burn_out`。
- 派生：`fireRisk(building)` 开放修正槽 `facilities:fireRisk`（材质、风、炉火、邻近；堪舆、消防设施等其他包可往里乘系数）。
- 反应：`当 事实 forge.lit=true 且 经营者不在场(日程派生) 且 风速≥阈 → 概率(fireRisk) 提案 emit(ignite, tags:[cause:negligence])`；`当 ignite/spread 于建筑 B → 对相邻边距离≤d·风向系数 的建筑按材质性状(K1)与雨(天气)决定 spread`；`当 burning 持续 t → fact.set(condition -= k)，库存 transfer → sink:destroy`。
- 数据：蔓延距离表、材质易燃表（复用 K2 interaction-rules 的 flammable）、风向系数。
- 不写：租金、价格、案件、罪名——它们是其他包对 `condition`、账户的反应，以及规范栈对 `ignite ∧ cause:negligence` 的罪名谓词（各法典的 negligent_fire 条目）。

**法律（法律包）**
- 词汇：罪名标签族 `offense:*`、案件阶段动词、案件种类（刑事、民事、宣告失踪、宣告死亡、撤销宣告）。
- 持有：`frozen`、`permit`、`wanted`（通缉是法域对人的持有，范围由引渡派生）、`banished`。
- 反应（立案）：对每个事件，取 `normStack(行为者, 事件地点, 事件时刻)`，在栈中逐层求罪名谓词（05 §5.2）：`谓词(事件原语, 持有状态, 知情) 命中 ∧ (见证非空 ∨ 证据链非空) → create(case{来源规范条目与版本, offense, 各角色当事人, evidence})`。成员规范层命中 → 交由来源组织的内部程序（戒律、门规），不是政体案件。
- 时钟：案件阶段到期项（报案→缉捕→审判→执行→上诉；宣告失踪/死亡的公告期）。
- 派生：法域、规范栈、适用法（冲突法表）、引渡关系（allied_with 条款与政体关系投影）。
- 动作：报案、自首、起诉、上诉、聘讼师、贿赂、申请宣告失踪/死亡、申请撤销宣告。
- 不写：任何别的包的动作里的罪名判断。新禁令 = 新规范条目数据。

**治理（治理包）**
- 实体种类：office（村长/镇长/管事/登记员/执法者……由等级职位表派生应有职位）。
- 持有：holds_office、appointed、citizen_of/resident_of、administers。
- 义务：salary（公账 → 持有人）、tax。
- 派生：职权表、额度表、俸禄表、税表（按职级 × 聚落等级）、兼任规则（读规范栈的 plurality 条款）。
- 反应：`当 settlement.rank 改变 → 确保该等级应有职位存在（创建空缺）`；`当 holds_office 关闭 → 职位进入继任规则（副职代理 / 补选时钟 / 上级任命）`。
- 动作：提案、表态、任免、授爵/除爵（经任免流程）、升格申请、公库支取（权限派生自职位）。**议案通过**的效果 = 对本治理组织的次级规范 fact.set 一条规范条目（05 §5.2），范围与权限由上级授权表限定。

## 3.5 包与内容的关系

内容（物品、法术、怪物、首领、法典、章程、职位表、礼俗、神迹、疾病、节日）只是包的数据文件。新内容写数据：一个新法术 = 效果原语参数 + 阶段上限 + 合法性数据（需登记、需同意的规范条目）；一个新政体 = 法典（规范条目集合：罪名谓词、程序、民事条款、冲突法、税表、授权表、域外条款）+ 继承表 + 职位表；一个新门派或寺院 = 组织 + 章程（含门规戒律这类成员规范）；一个新影响因素（风水、蚕病、农具）= 修正项 + 必要的事实字段；一个新怪物 = 物种性状 + 容量需求 + 可驯条件；一个新职业 = 认证资格职位 + 被动派生表 + 名额表。内容流水线（第 10 章）不变；第三方作者的入口见第12章。
