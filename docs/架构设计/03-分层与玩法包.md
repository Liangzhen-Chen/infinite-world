# 03 分层、依赖方向与玩法包的标准形状

（修订历史见 修订记录.md。第五轮：连接点中"规范补丁"泛化为"补丁"（附录 A §A.9 第 4 条）；示例改为文件布局引用（R7-X5）；§3.5 加历法、物种、身份、承认、钩子的"新内容 = 什么数据"。）

## 3.1 五层

| 层 | 职责 | 允许依赖 | 禁止 |
|---|---|---|---|
| L0 内核 | 事件日志与归约、事务与不变量校验、账户与转移（含批次键）、实体/持有/义务存储与索引（按持有人、按标的、按地点、按到期）、时钟与日程堆、**同刻调度器**（阶段、排序键、序号，14 章）、规则注册表（按纪元重建）、效果原语执行器、掷骰（战役种子 + 规则 + 对象 + 时刻 + 序号）、RX 求值器（第12章 §12.8.1）、整数舍入 | 无 | 任何领域词汇：内核不知道什么是"死亡""税""租金" |
| L1 本体与派生库 | 标准实体模板与种类、持有种类目录与钩子模板、义务种类基类（含 onDebtorGone 枚举）、资源种类表、事件动词与标签词汇表、地点树、转移协议、作者数据→持有/账户的转换器；**全部派生函数**：实体视图（统一读 API）、法域与**规范栈解析**（条款查询 `clause()` / `grace()`、补丁合成）、**市场投影**（报价、出清、劳务报价、汇率（含信用货币分支）、利率、购买力，15 章）、**立场**（传导按知情门控）、**日程**、知情集合与**主观视图**、**职能有效 `effective()` 与受限制度**（附录 A §A.15）、修正槽注册与派生合成器（含节奏系数）、效力派生（13 章）、NPC 决策骨架（5.7 顺序，只读主观视图）与自治候选评估 | L0；经注册表读 L2 注册的数据与规则（不 import 包） | import 任何玩法包；内置具体数值表（数值在包的数据里） |
| L2 玩法包 | 经济、法律、治理、家族、组织、宗教、教育、医疗、运输、生态、魔法、战斗、职业、NPC 自治、远方生成、超自然……每个包 = 数据 + 规则 + 订阅 + 动作（+ 规范条目与补丁、修正项、推断规则、自治候选） | L1 的只读 API 与提案构造器（原生包经 pack-api） | 包与包互相 import；直接读写内核存储；新增工具；私造词汇 |
| L3 投影与缓存 | 派生结果的**缓存**（版本键）与**组合**：场景卡素材、面板数据、编年史、返场与回程见闻、动作目录投影（界面菜单/可做之事）、`scene()` 空间投影、存档快照与分片 | L0（只读）、L1、L2 的动作目录（只读） | 写状态；定义任何派生公式 |
| L4 接口 | 工具面（≤ 16 个）、LLM 提示组装、界面（面板、菜单、动作构造器、对话面板）、离屏调度驱动、一致性审查、存档读写与迁移、包加载器（第12章） | **L0 的事务提交入口与时钟驱动入口**（整个系统唯一的写入口，只接受提案）、**L1 的注册入口**（仅加载器，仅在纪元边界）、L2 动作目录、L3 | 包含规则；绕过事务写状态 |

说明：
- "派生函数在 L1、缓存在 L3"对一切派生成立：知情集合、主观视图、立场、报价、日程、法域都是 L1 的纯函数；L3 只负责按版本键缓存与组合成卡片、面板、快照。这样 L1 的决策骨架读立场、L2 的放贷包读 `standingFactor` 与价格都是向下依赖，不再有环（run-003 C3）。
- L4 是唯一能调用 L0 事务入口的层：工具、界面、加载器、离屏驱动都经它提交提案或驱动时钟；L2 的规则由 L0/L1 的引擎在事务内调用，包自己没有入口（I3、I19）。
- 规范栈的解析与条款查询在 L1，立案与审判流程在法律包；市场投影在 L1，交易动作在经济包。

## 3.2 依赖规则（消除循环）

1. **方向只向下**。L2 向 L1 注册（持有种类、义务种类、资源种类、规则、动作、词汇扩展、规范条目与补丁、修正项、推断规则、自治候选），L1 只调用注册表，从不 import 包。这是"待吸收"里 entity-transitions ↔ obligations 循环的根治：交接规则由各包注册，协议本身不认识任何包。effect-registry（K10 已把注册表移入无依赖模块）是同一思路的雏形。
2. **包之间不通信**。A 包想影响 B 包，只能经八种连接点：
   - 发带标准标签的事件（B 订阅）；
   - 改共享账户（B 的派生读到）；
   - 开关共享持有（B 的视图读到）；
   - **向 B 的派生开放的修正槽注册修正项**（05 §5.9；core 的槽清单是契约附表 B，附录 A §A.16；例：堪舆包对设施包的 `facilities:fireRisk` 乘系数，修仙包对 `life:lifespan` 取 max）；
   - **在 core 实体上声明扩展事实**（12 §12.2.3；A 包写 `xiuxian:realm`，B 包的修正项或候选经 `fact()` 读它）；
   - **声明规范条目**（05 §5.2；例：盐引包声明"无引运盐"的罪名谓词，作用于运输包产生的 move/transfer 原语，运输包零改动）；
   - **声明补丁**（05 §5.2.8；对规范条款、动作前置、持有不相容、义务条款范围的受控修正，附录 A §A.9 第 4 条；例：驿商包给一切政体税表加"持驿商认证者关税减半"，行会包给 core 认证动作追加"须拜师三年"的前置——各受目标 `patchable` 约束，追加型缺省允许）；
   - **声明自治候选**（05 §5.7；例：活契包把"签活契"登记为"钱"需求下的候选，自治包自动考虑）。
   医疗包订阅一切 `harm:injury`（来自战斗、火灾、坠崖、野兽），法律包对一切事件求规范栈中的罪名谓词，立场包订阅一切带见证的 harm/gift，市场投影读一切账户与未到期交付义务。新包加入时老包零改动即被"相乘"。
3. **词汇表是包之间唯一的契约**，放在 L1 数据文件 `world/ontology/*.json`：事件动词与标签、持有种类、义务种类、资源种类、商品类（`goods:*`）、性状标签（K1）、罪名标签、状态标记、兜底标签族（`mark:*`）、超自然标签族（13 §13.10）。加词汇要过校验；私有词须带命名空间，共享词须挂在已有族下并过同义检查（第12章 §12.3.3）——现状两套元素词表、七份态度账的病根就是私造同义词。包的词条写在包目录的 `vocabulary.json`（12 §12.2.1），种类写在 `ontology/*.json`。
4. **自动守卫**：一条 import 图测试解析所有模块（含动态 import），向上或包间的边即失败（I19）。
5. **注册时机与纪元**：注册表只在**纪元边界**变化。纪元边界是：开局；以及存档中的 `pack.install`、`pack.upgrade`、`pack.uninstall`、`world_upgrade` 事件——这些事件只能在载入存档流程中、经玩家确认后、第一个回合之前产生，规则、动作、工具、LLM 都不能产生。每到一个边界，注册表按依赖拓扑序（同层按包 id 字典序）一次性重建：拒绝重复 id、缺字段、未知词汇、未声明依赖的引用、槽位冲突；重建完成后冻结，直到下一个边界。回合、推进与离屏期间不能增、改、删任何定义。卸载或升级不删除定义：被移除的定义转为**退役条目**（定义快照写入存档的退役表），退役条目参与解析、归约与历史渲染，不参与任何新提案。每个事件记录所属纪元，从而任意时刻的注册表都可由存档唯一重建（第 12 章 §12.5.5）。
   - 注：议案通过后改变的是组织实体的法典/章程**事实**（规范条目的内容），不是注册表里的定义；它是普通事件，不需要纪元边界（05 §5.2）。节奏档位改变同理（`pace_set` 事件，14 §14.8）。

## 3.3 玩法包的标准形状

一个包是一个目录 `packs/<name>/`，含 `manifest.json`（声明）、`vocabulary.json`（词条）、`ontology/*.json`（种类）、`rules/*.json`、`law/*.json`、`autonomy/*.json`、`actions/*.json`、`tests/`；`*.mjs` 只在一方包或 trust=native 的包中允许（第12章 §12.8.1），且只能 import pack-api。manifest 的完整字段以第12章 §12.2.2 为准；下面只展示与规则相关的部分。声明示例（以"放贷"包为例）：

`manifest.json`（字段以 12 §12.2.2 为准；内容不内联在清单里，R7-X5）：

```json
{
  "id": "lending", "version": "1.0.0", "contract": "^1.0.0", "vocabulary": "^1.0.0", "tier": "rules",
  "provides": {"kinds": [], "holdings": [], "obligations": ["loan"], "resources": [], "statuses": [], "facts": [],
               "places": false, "entities": false, "law": false, "autonomy": true, "supernatural": false, "lore": false,
               "rules": ["derivations", "inferences", "modifiers", "tables"], "actions": true, "narration": true, "ui": false},
  "prompt": {"staticTokens": 0}
}
```

`ontology/obligations.json`（义务种类；累计以天为底，"按月"只是到期锚，01 §1.4）：

```json
{"obligationKind": "loan",
 "schedule": {"kind": "installments|single", "anchor": "month"},
 "accrual": {"closedForm": "principal*rate*days/360"},
 "penalty": {"closedForm": "overdueDays(grace)*penaltyRate"},
 "settle": [{"op": "transfer", "resource": "coin", "from": "debtor", "to": "creditor", "amount": "due"}],
 "shortfall": [{"op": "obligation.settle", "partial": true}, {"op": "emit", "verb": "overdue"}],
 "default": {"after": 3, "readsGrace": true, "effects": [{"op": "emit", "verb": "default", "tags": ["breach"]}, {"op": "holding.transfer", "holdingKind": "pledged", "to": "creditor"}]},
 "onDebtorGone": "assume_by_heirs", "onCreditorGone": "estate",
 "terms": {"rate": [0.005, 0.05], "maxDays": 1080}}
```

其余各在自己的文件：`rules/derivations.json` 一条 `interestRate`（RX `interestRate(creditor, debtor)`，缺省即开槽 `lending:interestRate`）；`rules/inferences.json` 一条 `missed-installments`（premise `overdueCount(obligation) >= 2 && knows(self, obligation)` → belief `debtor_insolvent`，权重 `1 - trait(self,'trusting')`）；`autonomy/candidates.json` 一条 `borrow-when-short`（need `need:money`、action `lend`、applicability 与 utility 读 `subjective(self)`）；`actions/lend.json`、`repay.json`、`forgive.json`；`rules/tables/lending.json`。

要点：
- **声明决定接入**：包声明的持有/义务/动作/订阅/修正项/规范条目与补丁/自治候选决定它"接"上什么，而不是它调用了谁。
- 义务种类的两端消失只由 `onDebtorGone` / `onCreditorGone` 决定（04 §4.2），没有 `handover` 键（run-003 C18）；`default.readsGrace` 表示违约计数读规范栈的宽限条款（05 §5.2、I29）；立案不写在放贷包里：违约事件带 `breach` 描述标签，是否构成罪名、能否起诉、适用哪部法，由法律包按规范栈判定（§3.4）。
- 派生用 RX 表达式，缺省即开槽、可被他包修正（附录 A §A.9 第 3 条）；利率公式本身在 L1（15 §15.5），包只声明区间与 bounds。
- **读**：只经实体视图、主观视图、账户查询、规范条款查询、市场投影（L1 的只读 API）。
- **写**：只产提案（原语列表）。
- **时钟**：绝大多数包不需要时钟规则，因为到期项由义务日程登记；只有真正的周期过程（再生、生长、腐坏、计划阶段、状态评价、年久成精）登记时钟规则，并声明 closedForm / tolerance、索引键与（可选）paceable / major。
- **动作**：包把玩家/NPC 可发起的行为声明为动作数据（06 动作层），不新增工具；NPC 会不会主动去做，由自治候选决定（可内联在动作的 `satisfies` 字段）。
- **包档**：只有内容、不声明规则的包是 content 档（12 §12.8.6），自测只跑内容类检查。
- **提示预算**：包声明自己的静态提示增量（必须为 0）；动作的 LLM 可见描述只在目录检索时进入动态尾部。
- **测试**：包自带 `tests/`（累计闭式 = 逐日累加；死亡后无对死者的 default；修正项不影响未命中实体），由 `pack test` 执行（第12章 §12.7）。

## 3.4 三个包的形状速写

**火灾（在设施包内）**
- 词汇：标签 `fire`、`burning`、描述标签 `cause:negligence`；动词 `ignite`、`spread`、`burn_out`。
- 派生：`fireRisk(building)` 开放修正槽 `facilities:fireRisk`（材质、风、炉火、邻近；堪舆、消防设施等其他包可往里乘系数）。
- 反应：`当 事实 forge.lit=true 且 经营者不在场(日程派生) 且 风速≥阈 → 概率(fireRisk) 提案 emit(ignite, tags:[cause:negligence])`（时钟规则，paceable）；`当 ignite/spread 于建筑 B → 对相邻边距离≤d·风向系数 的建筑按材质性状(K1)与雨(天气)决定 spread`；`当 burning 持续 t → fact.set(condition -= k)，库存 transfer → sink:destroy`；建筑烧毁 → `transition(gone, destruction)`（04 §4.2：残骸承接可回收物）。
- 数据：蔓延距离表、材质易燃表（复用 K2 interaction-rules 的 flammable）、风向系数。
- 不写：租金、价格、案件、罪名——它们是其他包对 `condition`、账户的反应，以及规范栈对 `ignite ∧ cause:negligence` 的罪名谓词（各法典的 negligent_fire 条目）。

**法律（法律包）**
- 词汇：罪名标签族 `offense:*`、案件阶段动词、案件种类（附录 A §A.7：刑事、民事、破产、宣告）。
- 持有：`frozen`、`permit`、`wanted`、`banished`。
- 反应（立案）：对每个事件，取 `normStack(行为者, 事件地点, 事件时刻)`，在栈中逐层求罪名谓词（05 §5.2）：`谓词(事件原语, 持有状态, 知情) 命中 ∧ (见证非空 ∨ 证据链非空) → create(case{来源规范条目与版本, offense, 各角色当事人, evidence})`。状态类罪名（囤积）由规范层的周期时钟求值。成员规范层命中 → 交由来源组织的内部程序（戒律、门规），不是政体案件。
- 时钟：案件阶段到期项（报案→缉捕→审判→执行→上诉；宣告失踪/死亡的公告期；破产的债权申报期）。
- 派生：法域、规范栈、适用法（冲突法表）、引渡关系（allied_with 条款与政体关系投影）、证据评分。
- 动作：报案、自首、起诉、上诉、聘讼师、贿赂、申请宣告失踪/死亡、申请撤销宣告、申请破产、追认或撤销代理行为。
- 不写：任何别的包的动作里的罪名判断。新禁令 = 新规范条目数据。

**治理（治理包）**
- 实体种类：office（村长/镇长/管事/登记员/执法者……由等级职位表派生应有职位）。
- 持有：holds_office、appointed、citizen_of/resident_of、administers。
- 义务：salary（治理组织公库 → 持有人，R7-X9）、tax、approval（批复）。
- 派生：职权表、额度表、俸禄表、税表（按职级 × 聚落等级）、兼任规则（读规范栈的 plurality 条款）。
- 反应：`当 settlement.rank 改变 → 确保该等级应有职位存在（创建空缺）`；`当 holds_office 关闭 → 职位进入继任规则（副职代理 / 补选时钟 / 上级任命）`。
- 动作：提案、表态、任免、授爵/除爵（经任免流程）、升格申请、公库支取（权限派生自职位）、批复。**议案**的结果有三种（附录 A §A.7）：改规范（对本治理组织的次级规范 fact.set 一条规范条目，范围与权限由上级授权表限定）、执行（以组织权能执行一个注册动作：拨款、拆除、征发，必要时先经上级批复）、任免（05 §5.2.5）。
- 自治候选：组织层面的需求（公库、安全、威望）→ 议案、征发、赈灾。

## 3.5 包与内容的关系

内容（物品、法术、怪物、首领、法典、章程、职位表、礼俗、神迹、疾病、节日、生灵、仪式、文化记录、配方、拘禁制度、失真表）只是包的数据文件。新内容写数据：一个新法术 = 效果原语参数 + 阶段上限 + 合法性数据（需登记、需同意的规范条目）；一个新制品 = 资源种类（或物品模板）+ 配方（投入、工具、工时、技能阶、产出，01 §1.6）+ 制作动作；一种新货币 = 资源种类（货币事实）+ 法典认可条目（法定货币、发行者）；一座新监狱 = 建筑 + 拘禁制度数据 + 典狱职位与职权表；一个新政体 = 法典（规范条目集合：罪名谓词、程序与程序成本、民事十类、冲突法、税表、授权表、域外条款、认可条款含改币）+ 继承表 + 职位表；一个新门派或寺院 = 组织 + 章程（含门规戒律这类成员规范）；一个新影响因素（风水、蚕病、农具）= 修正项 + 必要的事实字段；一个新怪物或生灵 = 物种数据（六轴标签、真实与传说弱点、出处、独有钩子）+ 容量需求 + 可驯或可订约条件；一个新职业 = 认证资格职位 + 被动派生表 + 名额表 + 仪式资格；一个新契约 = 义务种类 + 签约动作 + 合同效力条款 + 自治候选；一个新特权、豁免或前置 = 补丁（附录 A §A.9 第 4 条）；一部新历法或年号 = 历法数据 + 法典 `recognition.calendar`；一种新动物或家畜 = 物种数据（与超自然生灵同 schema，13 §13.3）；化名与易容 = 身份键事实，不加概念；"外地的某持有在本地算不算" = 法典 `recognition` 条目；一种新的转移后果（赦免、复籍、赎身）= 钩子；一种新的可定价物 = 估值表一行。内容流水线（第 10 章）不变；第三方作者的入口见第12章；收录与宗教尊重规则见 13 §13.1。
