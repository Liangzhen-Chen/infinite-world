# 03 分层、依赖方向与玩法包的标准形状

## 3.1 五层

| 层 | 职责 | 允许依赖 | 禁止 |
|---|---|---|---|
| L0 内核 | 事件日志与归约、事务与不变量校验、账户与转移、实体/持有/义务存储与索引（按持有人、按标的、按地点、按到期）、时钟与日程堆、规则注册表、效果原语执行器、掷骰（战役种子 + 对象 + 日期） | 无 | 任何领域词汇：内核不知道什么是"死亡""税""租金" |
| L1 本体 | 标准实体模板与种类、持有种类目录与交接类、义务种类基类、资源种类表、事件动词与标签词汇表、地点树与法域派生、转移协议、实体视图（统一读 API）、NPC 决策规则骨架（5.7 顺序）、作者数据→持有/账户的转换器 | L0 | import 任何玩法包；内置具体数值表（数值在包的数据里） |
| L2 玩法包 | 经济、法律、治理、家族、组织、宗教、教育、医疗、运输、生态、魔法、战斗、职业、NPC 自治、远方生成……每个包 = 数据 + 规则 + 订阅 + 动作 | L0、L1 | 包与包互相 import；直接读写内核存储；新增工具；私造词汇 |
| L3 投影 | 实体视图的组合、市场报价、立场、知情集合与记忆流、日程、编年史、场景卡素材、返场摘要、动作目录投影（界面菜单/可做之事）、存档快照与分片 | L0–L2 只读 | 写状态 |
| L4 接口 | 工具面（≤ 16 个）、LLM 提示组装、界面（面板、菜单、动作构造器、对话面板）、离屏调度驱动、一致性审查、存档读写与迁移 | L2 动作目录、L3 | 包含规则 |

## 3.2 依赖规则（消除循环）

1. **方向只向下**。L2 向 L1 注册（持有种类、义务种类、资源种类、规则、动作、词汇扩展），L1 只调用注册表，从不 import 包。这是"待吸收"里 entity-transitions ↔ obligations 循环的根治：交接规则由各包注册，协议本身不认识任何包。effect-registry（K10 已把注册表移入无依赖模块）是同一思路的雏形。
2. **包之间不通信**。A 包想影响 B 包，只能：发带标准标签的事件（B 订阅）、改共享账户（B 的派生读到）、开关共享持有（B 的视图读到）。医疗包订阅一切 `harm:injury`（来自战斗、火灾、坠崖、野兽），法律包订阅一切 `offense:*`，立场包订阅一切带见证的 harm/gift，市场投影读一切账户。新包加入时老包零改动即被"相乘"。
3. **词汇表是包之间唯一的契约**，放在 L1 数据文件：事件动词与标签、持有种类、资源种类、性状标签（K1）、罪名标签、状态标记。加词汇要过校验；不许私造同义词（现状两套元素词表、七份态度账的病根）。
4. **自动守卫**：一条 import 图测试解析所有模块（含动态 import），向上或包间的边即失败（I19）。
5. **注册时机**：包在启动时按声明顺序注册；注册表拒绝重复 id、缺字段、未知词汇；注册完成后冻结。运行期不能加规则（内容更新走 world_upgrade，仍在启动时注册）。

## 3.3 玩法包的标准形状

一个包是一个目录 `packs/<name>/`，含 `manifest.json`（声明）、`rules/*.json`（数据）、`*.mjs`（派生函数、复杂求解器、原语参数计算）、`tests/`。声明示例（以"放贷"包为例，字段即规范）：

```json
{
  "id": "lending",
  "vocabulary": {
    "obligationKinds": ["loan"],
    "verbs": ["lend", "repay", "overdue", "default"],
    "tags": ["finance"]
  },
  "holdings": {},
  "obligations": {
    "loan": {
      "schedule": {"kind": "installments|single", "period": "month"},
      "accrual": {"closedForm": "principal*rate*days/360"},
      "penalty": {"closedForm": "overdueDays*penaltyRate"},
      "settle": [{"op": "transfer", "resource": "coin", "from": "debtor", "to": "creditor", "amount": "due"}],
      "shortfall": [{"op": "obligation.settle", "partial": true}, {"op": "emit", "verb": "overdue"}],
      "default": {"after": 3, "effects": [{"op": "emit", "verb": "default", "tags": ["offense:breach"]}, {"op": "holding.transfer", "kind": "pledged", "to": "creditor"}]},
      "handover": {"creditor": "estate", "debtor": "estate", "impaired": "suspend"}
    }
  },
  "derivations": {
    "interestRate": "lending.mjs#interestRate"
  },
  "reactions": [
    {"id": "default-to-case", "when": {"verb": "default", "creditorKind": ["person", "org"]}, "then": [{"op": "create", "kind": "case", "args": {"law": "jurisdiction(debtor.location)", "offense": "breach"}}]}
  ],
  "clock": [],
  "actions": ["actions/lend.json", "actions/repay.json", "actions/forgive.json"],
  "data": ["rules/lending.json"],
  "reads": ["view.person", "view.account", "view.place"],
  "prompt": {"staticTokens": 0}
}
```

要点：
- **声明决定接入**：包声明的持有/义务/动作/订阅决定它"接"上什么，而不是它调用了谁。
- **读**：只经实体视图与账户查询（L1/L3 的只读 API）。
- **写**：只产提案（原语列表）。
- **时钟**：绝大多数包不需要时钟规则，因为到期项由义务日程登记；只有真正的周期过程（再生、生长、计划阶段）登记时钟规则。
- **动作**：包把玩家/NPC 可发起的行为声明为动作数据（06 动作层），不新增工具。
- **提示预算**：包声明自己的静态提示增量（目标 0）；动作的 LLM 可见描述只在目录检索时进入动态尾部。
- **测试**：包自带不变量（累计闭式 = 逐日累加；死亡后无 default），加入 `tests/invariants/packs/`。

## 3.4 三个包的形状速写

**火灾（在设施包内）**
- 词汇：标签 `fire`、`burning`、`offense:negligent_fire`；动词 `ignite`、`spread`、`burn_out`。
- 反应：`当 事实 forge.lit=true 且 经营者不在场(日程派生) 且 风速≥阈 → 概率提案 emit(ignite)`；`当 ignite/spread 于建筑 B → 对相邻边距离≤d·风向系数 的建筑按材质性状(K1)与雨(天气)决定 spread`；`当 burning 持续 t → fact.set(condition -= k)，库存 transfer → sink:destroy`；`当 ignite 且起因是人的疏忽 → emit(offense:negligent_fire, 见证=在场)`。
- 数据：蔓延距离表、材质易燃表（复用 K2 interaction-rules 的 flammable）、风向系数。
- 不写：租金、价格、案件——它们是其他包对 `condition`、账户、`offense:*` 的反应。

**法律（法律包）**
- 词汇：罪名标签族 `offense:*`、案件阶段动词。
- 持有：`frozen`、`permit`、`wanted`（通缉是法域对人的持有，范围由引渡派生）。
- 反应：`当 事件带 offense:X 且 法域(事件地点).法典.罪名表含 X 且 (见证非空 或 证据链非空) → create(case)`。
- 时钟：案件阶段到期项（报案→缉捕→审判→执行→上诉）。
- 派生：法域、适用法（冲突法表）、引渡关系（政体关系投影）。
- 动作：报案、自首、起诉、上诉、聘讼师、贿赂（emit + 标签 offense:bribery）。

**治理（治理包）**
- 实体种类：office（村长/镇长/管事/登记员/执法者……由等级职位表派生应有职位）。
- 持有：holds_office、appointed、citizen_of/resident_of。
- 义务：salary（公账 → 持有人）、tax。
- 派生：职权表、额度表、俸禄表、税表（按职级 × 聚落等级）。
- 反应：`当 settlement.rank 改变 → 确保该等级应有职位存在（创建空缺）`；`当 holds_office 关闭 → 职位进入继任规则（副职代理 / 补选时钟 / 上级任命）`。
- 动作：提案、表态、任免、授爵/除爵（经任免流程）、升格申请、公库支取（权限派生自职位）。

## 3.5 包与内容的关系

内容（物品、法术、怪物、首领、法典、章程、职位表、礼俗、神迹、疾病、节日）只是包的数据文件。新内容写数据：一个新法术 = 效果原语参数 + 阶段上限 + 合法性标签；一个新政体 = 法典数据 + 继承表 + 冲突法表 + 职位表；一个新怪物 = 物种性状 + 容量需求 + 可驯条件；一个新职业 = 认证资格职位 + 被动派生表 + 名额表。内容流水线（第 10 章）不变。
