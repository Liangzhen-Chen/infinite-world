# 《无限原野》扩充与重构指南

交给 Codex 执行。版本 2026-10-10。

依据：用户上传的「AI检查包」12 个文件的逐项审查；用 Node 22 对原版 `core.js` 的复现测试；小说《再生勇士》中游戏《无限世界》的公开设定资料；SillyTavern 与 DeepSeek 官方文档。资料来源见附录 F。

使用方法：把本文件放进项目的 `docs/` 目录，然后对 Codex 说："阅读 docs/无限原野_扩充与重构指南.md，按第 13 章从阶段 0 开始执行，每个阶段结束时汇报做了什么、怎样验证的、还差什么。"

## 0. 先读这一节

### 0.1 要做成什么

用户要玩的是"同款游戏"：以小说《再生勇士》里的虚拟网游《无限世界》为蓝本，做一款单人中文文字游戏，运行在 SillyTavern（下称"酒馆"）上，由 DeepSeek 主持。玩家就是这款游戏的玩家。小说的现实世界情节、主角身世，以及"再生者"之类的背景设定，一律不做。

三个核心，按优先级排列：

1. **游戏本身的设定完整。** 等级、属性、职业、技能、魔法、装备、怪物、首领、宠物、任务、身份、贡献、领地、爵位、经济，要像一款真正上线运营的游戏一样齐全、自洽、有数值，而且玩家能在界面上看到。
2. **高自由度。** 没有主线。玩家可以种地、开店、做手艺、研究魔法、自创技能、冒险、经营村子、当领主，也可以什么都不接，只在镇上过日子。世界按规则回应玩家，而不是按剧本回应。
3. **NPC 智能。** NPC 记得发生过的事，有自己的生活、目标、财物和判断；答应的事会真的去做；不在场就不知道；会成长、改变职业、和别人结仇或成亲；玩家不在时，村子和人照样在变。

### 0.2 用户已经明确说过的要求

这些全部是验收依据，写进测试（第 11 章）。

- 剑与魔法、中世纪背景。深度沉浸、社会系统、魔法系统三者必须有。
- 玩家不打仗也能成为小镇的一员，行为能改变村庄和 NPC。
- 用户实际玩过并明确不满的情况：任务刚结束 NPC 立刻赶人；推 NPC 一下只会喊一声、没有后果；NPC 答应带路却站着不动；答应交易却不执行；NPC 不知道玩家正在做的任务；中文没有声音；操作键位繁杂；NPC "蠢蠢的"。
- 世界要大，NPC 要多，设定要完整；不能只照搬小说里出现过的内容，要大规模补全。
- 完整测试：系统无误、AI 正确理解全部内容、记忆系统正确、没有乱七八糟的错误。

### 0.3 不可违反的规则

1. 不复制小说正文、人名、地名、组织名和情节。可以借用系统结构与数值（第 3.1 节），名称和文本全部原创。
2. 不破坏用户现有存档。改动存档格式的提交必须同时提供迁移脚本和迁移测试；动手前自动备份。
3. 不读取、不打印、不提交 API 密钥（酒馆 `data/*/secrets.json`）。需要调用 DeepSeek 的生成脚本与测试脚本只从环境变量 `DEEPSEEK_API_KEY` 读取，日志里屏蔽密钥。
4. 不安装要求上传密钥或来源不明的第三方扩展，不加入成人内容。未成年 NPC 一律不进入恋爱、性或亲密情节，这条在数据层用字段强制，引擎拒绝相关写入。
5. 测试结果如实报告。未通过的项写进 `docs/已知问题.md`，不得调低阈值凑通过，不得把未执行的测试写成已通过。
6. 每完成一个阶段：全部测试通过 → Git 提交 → 在 `docs/进度.md` 写清楚做了什么、怎样验证、还差什么。

### 0.4 权威顺序与决策方式

- 用户的新指示 > 本指南 > 旧的 `使用说明.md`、`设计依据.md`、`总设定源稿.mjs`。
- 本指南没写到的设计决定：在 `docs/决策记录.md` 写下选项、理由和回退方式，选可逆的方案继续做，不要停工等待。真正需要用户拍板的事（例如是否开启第 3.15 节的"其他玩家"层）集中列在 `docs/待用户确认.md`，并给出默认值。
- 在项目根目录建 `AGENTS.md`（模板见附录 E），让每次会话先读本指南和进度文件。

### 1.3 记忆与检索：已复现的漏召回

写入长期事实"第三天玩家帮林穗找回遗失的账簿，她允许玩家借用酒馆厨房"后检索：

- "林穗的账簿" → 命中。
- "那本账本" → 没有命中这条，反而命中"玩家身份"，因为那一条里有"以账本为准"这句系统用语。
- "她的帐本"（异体字）、"我能用灶台吗"（近义）、"老板娘答应过我什么"（称呼）→ 全部无结果。

检索只靠中文二元切词，缺少称呼与别名解析、异体字归一、近义扩展和语义检索；系统用语混进记忆正文，还会制造误命中。

### 1.4 提示词与世界书配置

1. **动态内容放在聊天历史之前，DeepSeek 前缀缓存基本失效。** 世界书条目插在"角色定义之前"，并且随关键词每回合变化；扩展注入在深度 1，摘要在深度 2。DeepSeek 的硬盘缓存要求后续请求完整匹配已落盘的前缀单元；缓存命中的输入价格是未命中的五十分之一（空闲时段每百万 token 0.02 元对 1 元）。
2. **世界书全局扫描深度只有 2**（条目各自覆盖为 6）。人物和地点必须在最近几条消息里被点名才会注入，"她""老板娘"这类指代会让在场人物从上下文里消失。
3. **递归扫描开启且最大步数为 0（不限）。** 条目之间互相提名，世界一扩大就会连锁注入，把预算挤爆。
4. **关键词卫生差。** 单字键"神""税""买""卖""钱"；泛词"市场""学院""港口""森林""山地""王国""村子""共鸣""旧路""时间""休息""技能""研究"；同一关键词挂在多个条目上（"青灯酒馆"×2、"铁匠铺"×2，地区条目与地点条目共用"星湾""霜阶""树桥""苔院""琥珀港""芦语""银镜""环城""雪灯"）；"白石镇"一出现就注入严辙的人设。
5. **同一套主持规则写了四遍**：角色卡描述、Main Prompt、Post-History Instructions、扩展注入，措辞各不相同。没有叙事文风规范。
6. **第二段对话示例教错了东西。** {{char}} 在示例里说的是一段主持人内心规则（"先核对与这位居民的共同经历及进门约定……"），会诱导模型在正文里输出元叙述。
7. **思考模式需要核实。** `deepseek-flash` 是当前官方模型名（DeepSeek-V4.1-Flash，上下文 1M）。官方说明它支持思考与非思考两种模式，并以思考为默认；当前配置只是隐藏思考输出并设 `reasoning_effort: low`，实际请求是否开启思考，需要在酒馆服务器日志或抓包里确认。DeepSeek 的 Responses API 兼容说明注明思考模式下 temperature 不生效；酒馆走的是 Chat Completions 接口，很可能同样如此，需要实测。如果属实，0.8 这个值根本没起作用。
8. **摘要会丢旧剧情。** 只有一份 700 字的滚动摘要，每 24 条消息更新一次。
9. **上下文上限 65,536，远低于模型能力。** 缓存命中率提高以后，可以测试 128K 左右的上限能否在可接受的花费内保留更多原文。

### 1.5 界面与沉浸

1. 角色卡头像是酒馆默认的问号剪影。
2. 顶栏显示"第N日 HH:MM"，叙事用"春历元年，雨月第一日"，同时存在两套时间。
3. 账本面板的检索结果直接显示 JSON；工具调用消息出现在聊天流里。
4. 没有背景、音乐、语音、地图和人物头像。

## 2. 目标架构

```
world/                    世界数据源（JSON，按实体一文件或一区一包），每类有 JSON Schema
  meta/                   规则数值、历法、货币、属性、职业、技能、法术、物品、配方、怪物、首领、命名规则
  geo/                    大陆、政体、行政区、聚落、建筑、地点、路线
  people/                 NPC（完整档、名册档）
  orgs/                   势力、行会、教会、家族、犯罪组织、学院
  sites/                  地下城、遗迹、野外据点
  lore/                   历史年表、神话、传闻、书籍、歌谣（全部原创）
tools/build-world.mjs     校验 + 编译 → dist/world-<版本>.json（运行时只读）
extension/                酒馆前端扩展：提示词组装、工具、界面
server-plugin/            酒馆服务器插件：存档存储、检索索引、可选的向量代理
tests/                    单元、性质、内容、场景、浸泡、性能、界面测试
docs/                     进度、决策记录、已知问题、待用户确认、测试报告
assets/                   字体、头像、背景、图标、音频（附许可清单）
```

三条原则：

- **世界内容不再靠世界书关键词触发。** 运行时由扩展根据当前场景（所在地点、在场人物、进行中的事项、刚提到的实体）从编译好的世界库里挑选内容注入。世界书只保留极少的常驻条目，或者只作为可读镜像。
- **存档与聊天分离。** 每个战役一个目录：`meta.json`、定期快照、追加写的事件日志、检索索引。聊天元数据里只放战役编号、事件序号和校验值。
- **世界数据有版本。** 战役创建时记录世界版本和初始快照，重放永远基于战役自己的快照；世界更新通过显式迁移进入旧存档，迁移内容在界面上可见。

## 3. 游戏设定规格

这一章定义"这款游戏本身"。所有数值写进 `world/meta/rules.json` 及相关目录，引擎、界面、提示词读取同一份数据；提示词或世界书里出现的数值也由构建脚本从这份数据生成，杜绝两处不一致。

### 3.1 必须沿用的硬设定（来自小说中的《无限世界》）

| 系统 | 设定 | 实现要点 |
|---|---|---|
| 等级 | 0–200 级 | |
| 升级经验 | 0–9 级为新手保护期，升级所需经验 = 新等级 × 100；10 级起，升级所需经验 = 新等级⁴ ÷ 10 | 现有 `xpRequired` 正确，保留 |
| 死亡惩罚 | 新手保护期死亡扣"等级 × 10"经验；10 级起死亡损失"上一次升级时所需的经验值" | 现有代码未实现，见 3.3 |
| 职业名额 | 1 个战斗职业 + 2 个生活职业；隐藏职业不受此限 | |

### 3.2 玩家身份与"系统"

- 玩家是这款游戏的玩家角色，NPC 称其为"冒险者"（称呼可在决策记录里改）。冒险者死后会在登记过的复活点醒来，这是世界常识，不需要另写背景故事。删除所有"再生者"措辞：persona、角色卡描述、开局事实、"战斗与死亡"规则条目里的"玩家是再生者"。
- 游戏有"系统"：属性面板、技能栏、背包、法术书、任务日志、人物（好友）列表、邮件、地图、系统提示、世界公告。系统提示只由引擎根据已提交的事件生成，例如"【系统】照明术熟练度 +3（初级1等 13/100）"。模型不得自己写系统提示或数值变化。
- NPC 是游戏世界里的人，用世界内的说法谈本事和处境（"你这手木工还嫩"），不说"初级2等""好感度 +5"。
- **世界公告**：首次达成（第一个获得某职业、第一个发现某地、首杀某首领、第一个建立某级领地、第一个自创某类技能）由引擎生成公告，写进世界编年史，并成为 NPC 可以谈论的新闻，按 4.9 的传播规则扩散。
- **角色创建**：新战役开始时有创建界面：名字、性别、外貌描述、初始属性分配（3.3）、出生地（默认河湾村，可选其他已开放的起始村）。开局没有正式职业，与现状一致。

### 3.3 属性、等级与死亡

**属性。** 力量、敏捷、体质、智力、精神、魅力六项公开属性，另有隐藏的"幸运"，玩家看不到具体数值，它影响隐藏职业触发、稀有掉落和少数意外事件。生命、魔力、负重、攻击、防御、命中、闪避、施法速度由公式推导，公式写在 `rules.json`。每升一级获得若干自由属性点，生命与魔力上限随等级和体质、精神增长。

**数值平衡用目标驱动。** 不要拍脑袋定公式。先定下面这类目标，再写战斗模拟器（每组对局 10,000 次蒙特卡洛），调公式直到落进区间。表中数字是初始目标，可以在决策记录里修订：

| 对局 | 目标胜率 |
|---|---|
| 1 级无职业新人 对 单只 1–3 级野兽（野兔、野狗） | ≥ 90% |
| 10 级战斗职业 对 单只 10–15 级怪兽 | 约 50% |
| 三名 10 级角色 对 同一只怪兽 | ≥ 85% |
| 30 级战斗职业 单挑 一阶首领 | ≤ 15% |
| 五名 30 级角色 对 一阶首领 | 约 60% |
| 任何 200 级以下角色 对 半神兽 | 接近 0，只能谈判、躲避或借助特殊条件 |

**经验来源。** 击败怪物（按阶段和等级差计算，等级差过大时收益递减到零）、完成任务（按任务等级）、首次发现、制造与研究的里程碑、对聚落的实际贡献。同一件事只奖励一次，重复刷同一行为收益递减。升级节奏要有明确目标，例如"每天玩两小时，一个月左右到 20 级"，由你提出并写进决策记录，再用浸泡测试（11.4）核对实际节奏。按 3.1 的公式，从 0 级升到 10 级共需 5,500 经验，升到 20 级共需约 75,000 经验，奖励数值据此反推。

**检定（非战斗的不确定行动）。** 保留 d20，但修正由引擎计算：

$$\text{总值}=d20+\left\lfloor\frac{\text{属性}-10}{2}\right\rfloor+\text{技能加值}+\text{工具与装备}+\text{情境修正}$$

技能加值由熟练度换算（例如 \(\lfloor \text{熟练度}/150 \rfloor\)，0–17）；情境修正由模型给出，限制在 −5 到 +5，必须写理由。难度档：简单 10、普通 15、困难 20、极难 25、近乎不可能 30。结果分五档：大失败（掷出 1，或总值 ≤ 难度 − 10）、失败、勉强成功（难度到难度 + 4）、成功、大成功（掷出 20，或总值 ≥ 难度 + 10）。支持对抗检定、优势与劣势（掷两次取高或取低）、团队协助。每档结果都要有具体后果，失败不等于"什么都没发生"。

**战斗。** 战斗按"交锋"结算：一次交锋是几秒到十几秒的攻防，玩家给出意图，模型为对手选择战术，引擎按属性、技能、装备、地形标签（掩体、高处、狭窄、湿滑、黑暗）结算命中、伤害、状态和耐久。敌人有士气，会撤退、求饶、呼救、装死；智能高的对手会换打法。模型负责描述，数字一律来自引擎。

**死亡。**

$$\text{死亡损失}=\begin{cases}10\times\text{等级}, & \text{等级}<10\\ \text{升到当前等级时所需的经验}, & \text{等级}\ge 10\end{cases}$$

- 当前等级剩余经验不足以扣除时，按 `rules.json` 中的约定处理（建议：扣到 0 为止，不降级），写进决策记录。
- 生命归零先进入"濒死"，同伴或自身在限定时间内可以救治；超时或伤害远超上限才判定死亡。生命的增减一律钳制在 0 到上限之间，不再整笔拒绝（修复 E5）。
- 玩家在已登记的复活点醒来。复活点设在聚落的神殿或祭坛，登记有条件和费用。醒来后生命、魔力按规则恢复到一定比例。
- 死亡地点遗落随身包裹（非装备物品）是可选规则，默认关闭，列入 `docs/待用户确认.md`。
- NPC 死亡是永久的。重要 NPC 没有剧情护身，只有在情境确实支持时才可能"重伤未死"。

### 3.4 职业

**战斗职业（12 种）。** 每种职业一份数据：定位、主属性、可用武器与护甲、入职地点（城市里的职业公会或导师）、入职条件与入职任务、技能树（不少于 15 个技能，覆盖初级到特级）、每 30 级的升职路线（30、60、90、120、150、180 级各 2–3 个方向），以及变异职业。变异职业与地域、元素、信仰或经历挂钩（海岸、山地、林地、荒漠、冰原、圣光、暗影等），条件写清楚，例如"在海上累计作战若干次并通过某港口武士团的试炼"。

**生活职业（不少于 22 种）。** 在现有 16 种（农夫、猎人、渔夫、厨师、裁缝、铁匠、木匠、建筑师、炼金师、园艺师、鉴定师、地理师、商人、音乐家、雕刻师、驯兽师）基础上补入画师、挖掘者、首饰工匠、医师，把音乐家与吟游诗人的关系定下来（合并，或吟游诗人作为音乐家的流派），再补制皮匠、酿酒师、抄写员一类贴合经济的职业。每种写明：工具、工坊、原料、产品与品质产出、认证机构、各阶段的典型收入、行会规矩、与其他职业的上下游关系。

**认证。** 正式职业需要导师认可、行会考核或可验证的作品，并支付费用。未认证者的职业核心技能最高只能练到初级3等（熟练度 299）；认证后才能获得职业加成、高级配方、开店资格。放弃职业有明确代价：失去职业加成，技能熟练度保留但封顶。引擎校验职业名必须来自职业表（修复 E18）。

**隐藏职业（不少于 30 种）。** 每种写清楚触发条件、唯一性（全世界唯一，或少数人可得）、能力和代价。条件基于长期行为（例如十年不杀生的猎人、独自绘完一整片山脉的人）、罕见体质、特殊事件或隐藏的幸运值。引擎在条件满足时提示"隐约感到某种契机"，正式获得仍需完成一段经历。

### 3.5 技能

- **成长。** 有意义的使用才涨熟练度。同一技能对同类目标在 24 小时内重复使用，收益逐次减半；每个技能每天有收益上限（建议：初级 30、中级 20、高级 12、特级 8、专家级及以上 5）；导师指点、高质量作品和研究成果另有收益。
- **突破。** 每跨一个大阶（299 → 300、599 → 600……）都要有突破事件：导师考核、杰作、研究完成或关键实战。没有突破记录时，熟练度停在本阶上限（修复 E7）。
- **技能书。** 五个品级：初级、中级、高级、特级、终极。阅读要求识字、前置技能和时间；技能书是稀有商品，有作者、版本和来源，可以被抄写（需要抄写员和原本）。
- **融合。** 两项相关技能都达到规定阶段（建议双方至少高级1等），说明共同机制，投入材料和时间做实验，检定通过后得到融合技能，初始熟练度为较低一方的一部分。
- **自创。** 小说里玩家能自创技能，这是本游戏自由度的重要组成。流程：提出构想（需要相关知识）→ 立项研究（引擎记录阶段、投入、风险）→ 原型（可用但不稳定）→ 打磨 → 被"系统"承认，发出"自创技能"提示与世界公告。自创技能的阶段不超过创造者相关技能的最高阶段减一。效果、消耗、失败条件、反制方式都要写进技能记录；导师和同行能识别并评价它。
- **终极技能。** 来自职业任务、隐藏职业或神级套装。

### 3.6 魔法

- **理论。** 写清楚魔力从哪里来（世界内的解释）、施法由哪些部分构成（咒文、手势、符文、媒介、意志）、为什么有人能学有人不能、魔法文字的作用。
- **门类。** 火、水、风、土、光、暗影、生命、精神、空间、召唤、信仰，另设诅咒作为暗影与精神的分支。门类与职业挂钩：法师偏元素，祭司偏信仰与生命，巫师偏精神、暗影与诅咒，元素召唤师偏召唤，魔武士把魔法融进武技，僧侣以体术结合信仰，道士用符箓、阵法与驱邪。道士在中世纪剑与魔法世界里需要文化落点：设定一个有此传统的地区或教派，不要凭空出现。
- **法术目录（不少于 150 个）。** 每个法术：编号、名称、门类、阶段（目录内为初级到特级；专家级及以上只能通过研究或稀有典籍获得）、魔力消耗、材料、施法时间、距离、持续时间、按熟练度分段的效果、失败形式、各政体的合法性、社会后果、反制方式。
- **学习。** 向导师学（付费、时间、学习检定）、读法术书、研究自创。学会后由引擎写入法术书。模型不能直接登记法术（修复 E6）；`learn` 工具必须引用来源（导师编号、书籍编号或研究项目编号），并按阶段校验消耗区间。
- **施法。** 消耗魔力与材料，按熟练度和条件做施法检定，失败有反噬、偏差或只是浪费。施法计入熟练度（修复 E15）。一次性施法不再生成永久记录；持续性效果（护盾、保鲜、契约）进入"进行中的效果"表，到期自动移除。
- **生活魔法的经济影响**（保留现有原则并量化）：保鲜术降低当地食物损耗、影响价格；引水术改变灌溉；净水术改变饮水与疫病。被影响的人会有反应：受益者感激，竞争者不满，官府可能收费或管制。
- **管制。** 精神类魔法需要许可，强迫、篡改记忆属于重罪；空间传送需要锚点许可；各学院的规矩不同。

### 3.7 装备、物品与制造

- **品质。** 16 级品质对应 3.1 的等级要求。同一品质内另分做工档次（建议：粗糙、普通、精良、优秀、杰作），影响属性、耐久和价格。界面为 16 级品质各定一种颜色，全局统一。
- **物品目录（不少于 400 种）。** 材料、食物、工具、武器、护甲、药剂、卷轴、技能书、商品、奢侈品、家具、牲畜、坐骑、建材。每种：编号、名称、别名、品质、重量、基础价格、产地、季节性、用途、保存期限。物品以编号存储，名称只是显示（修复 E17）。
- **配方（不少于 200 个）。** 原料、工具、工作台、耗时、技能要求、检定、产物与副产品、失败结果。玩家做出的成品有唯一编号和制作者署名。
- **耐久与修理。** 使用损耗、损坏、修理费用与可修复程度。
- **商店。** 每家店有自己的库存和补货规则，不无限出售；高品质装备只在相应城市、相应渠道出现。

### 3.8 怪物、首领与生态

**3.8.1 九阶模板与等级带**（本项目的初始定义，可调）：野兽 1–10、怪兽 10–30、异兽 30–50、猛兽 50–70、凶兽 70–90、妖兽 90–120、灵兽 120–150、魔兽 150–180、圣兽 180–200；半神兽、神兽在 200 以上，属于天神一级，常规手段无法击败。驯兽（家畜和专用坐骑）单列。

**3.8.2 图鉴（不少于 150 种）。** 每种：编号、名称、所属模板、等级区间、栖息地、作息、群居或独居、领地性、食性、对聚落的威胁方式、可采集材料及用途、可驯服条件、灵智等级（多数为 0–1）、民间说法与真实习性的差别。

**3.8.3 种群与生态。** 每个区域记录主要物种的数量级和恢复速度。过度猎杀会让种群下降、价格上涨，捕食者消失会引发害兽泛滥；季节迁徙改变危险分布。普通怪物的"刷新"用种群恢复来表达，不在原地瞬间重生。

**3.8.4 首领（不少于 40 个，覆盖一阶到九阶）。** 每个：巢穴、领地、行为模式、部下、来历、弱点、掉落、可驯服条件。首领会记住被用过的战术，下次换打法或加强防备；被击败后巢穴空出，若干天后由别的生物占据，而不是原样重生。

**3.8.5 智能首领与怪物的觉醒。** 设计不少于 8 个顶级智能存在（原创），各有领地、目的、盟友和敌人，会对玩家的策略作出适应，可以谈判、交易、结盟或对抗。小说里魔王为怪物要求公平的那段质问，在这里做成长期世界动态：部分怪物族群在特定条件下（吸收魔力、受到教导、遭受不公）逐渐获得灵智，开始学习技能、制造工具、建立社会，提出自己的诉求。它们内部也有分歧。玩家可以教导、贸易、调停、镇压或无视，结果会改变地区格局并产生新势力。这条动态由世界时钟推进（4.9），节奏以游戏内的季度和年计算。

### 3.9 宠物、坐骑与召唤

- 上限按 3.1。驯服需要时间、信任、合适的技能（驯兽师）和与目标阶段相称的能力；首领只能在特殊条件下驯服。
- 宠物有饥饿、疲劳、心情、忠诚、等级和技能，会受伤、生病、死亡；照顾不周会出走。
- 召唤物来自法术和契约，有持续时间、维持消耗和契约条款，不等于永久宠物。

### 3.10 任务

- **来源。** NPC 个人需要（由其目标和短缺自动产生）；聚落与行会的公告栏；领主和官员按额度发布的任务；势力委托；世界事件。
- **等级与折算。** D、C、B、A、S 五级，1S = 10A = 100B = 1,000C = 10,000D。报酬量级：D 级 20–100 铜，C 级 1–5 银，B 级 10–50 银，A 级 1–5 金，S 级 10 金以上或独一无二的奖励。
- **发布额度。** 额度随爵位和官职变化，以 3.1 中"一等男爵兼城主每月 1B + 2C，或 12C，或 120D"为锚点，推出各级身份的额度表。玩家拥有身份后也能发布任务：消耗额度，报酬从自己的钱或公款里预先托管。NPC 冒险者会接这些任务，在离屏结算中完成或失败。
- **任务记录。** 发布人、受益人、可验证的完成条件、报酬托管位置、期限、状态、知情者。委托人知道进度；与任务无关的 NPC 只在被告知后才知道。
- **没有主线。** 世界里有几条长期局势（势力争端、怪物觉醒、边境战事），由世界时钟推进，玩家可以参与，也可以完全不理。

### 3.11 身份、贡献、领地与爵位

- **户籍与公民。** 冒险者可以在聚落登记为居民，进一步成为公民。条件：居住时间、费用、担保人、无犯罪记录。权利：购置土地和房屋、开店、参加村民大会、担任职务。义务：纳税、民兵役、公共劳动。
- **贡献度。** 按聚落分别记录。来源：建房、修路、捐赠、守卫、教学、公共工程、文化作品。界面可见。达到门槛可以申请土地、职务；村长由上级领主依据贡献度和村民或原村长的意见任命，不自动授予。
- **领地经营。** 成为村长或领主后，玩家可以定税率、批建房、立村规（不超出上级允许的范围）、发布任务、组织工程。日常事务由 NPC 管事按授权规则处理，例如小说里村管自行批准新来者建房并收费；玩家不在时，聚落照常运转（5.9）。
- **行政级别与聚落规模分开。** 行政级别（村、镇、城、郡、省）由管辖关系决定，遵守五比一；聚落规模由人口和设施决定。升级需要人口、住房、产业、公共服务、治安、民意和上级批准。
- **爵位。** 九级爵位，各分若干等。来源：军功、治理、对王室的服务、领地规模。权利：领地收入、司法权、任务发布额度。义务：兵役、贡赋、出席。建议的默认对应：城主可受封男爵，郡守子爵或伯爵，省级侯爵或公爵；写进决策记录，可调。
- **名士。** 由学术、艺术、教育成就获得的身份，带来进入学院、觐见贵族、发布文化类任务等权利。
- **建国。** 远期可能：领地、人口、军力和外部承认达到条件后可以独立建国，随之而来的是外交、战争和内政。

### 3.12 声望、法律与犯罪

- **声望分层。** 个人关系（每个 NPC 分别记录）、本地口碑（每个聚落）、势力信誉（每个势力）、名望、恶名。做好事不会让敌对势力自动喜欢你。声望沿社会关系和路线传播，有延迟和失真。
- **法律。** 每个政体一套法典：罪名、刑罚、诉讼程序、证据要求、执法人员、贿赂空间、赏金猎人。犯罪要有见证或证据才会被追究；审判、罚款、赔偿、劳役、监禁按游戏时间执行；逃犯有通缉范围。
- **偷窃、欺诈、暴力**都允许尝试，用检定公平判定，并留下线索（目击者、遗留物、赃物去向）。推搡 NPC 会有后果：对方还手、呼救、报官、记仇，围观者会议论（对应用户反感的"推一下只喊一声"）。

### 3.13 经济

- **货币。** 铜、银、金，100 铜 = 1 银，100 银 = 1 金。不同政体的铸币可以有成色差异和兑换手续费。
- **价格锚点**（保留现有数值）：面包 2 铜、干粮 3 铜、普通客房 6 铜一晚、木料 4 铜一份、石料 3 铜、铁料 12 铜、药草 3 铜、树脂 2 铜；普通劳动半日 12–24 铜。
- **价格公式。** 基础价 × 地区系数（离产地的距离与需求）× 运输风险 × 季节 × 店家加成 × 关系与声望 × 议价结果。报价当日内保持一致，写入账本。
- **生产与流通。** 每个聚落有产业、劳力、建筑和季节决定的产量，有消耗和库存；聚落之间按路线和距离做简化的周度贸易流。粮食收获有季节，存粮要能撑过冬季，这条做年度平衡检查。
- **收入表。** 各职业各阶段的典型日收入（建议：初级 20–40 铜，中级 40–80 铜，高级 80–150 铜，特级 150–300 铜，专家级 3–6 银，大师级 6–15 银，宗师级 15–40 银，圣级 1–3 金）。生活成本、房租、税、贷款利息、商会与钱庄也要写。
- **合同。** 借贷、租赁、雇佣、采购、合伙都记录当事人、标的、数量、期限、违约后果。

### 3.14 时间、历法与天气

- 每年 12 个月，每月 30 天。定出 12 个月名（保留现有的"雨月"），一种星期或旬制，集市日。"春历元年"要有世界内的解释，例如新王登基改元；改元有历史，也有新旧年号并用造成的小混乱。
- 节日不少于 24 个，分属不同文化与信仰，每个写明习俗、花费、社交机会和可能的冲突。
- 季节影响农事、动物、行路、价格；昼长随季节和纬度变化。
- 天气按地区和季节生成（马尔可夫链，以战役种子和日期为随机种子，保证重放一致），影响旅行、农事、战斗和心情。
- 引擎提供 `formatCalendar(minute)`，顶栏、场景卡、系统提示都用它，模型不再自己换算分钟数（修复 1.5 的两套时间）。

### 3.15 其他玩家（可选层，默认关闭）

《无限世界》里有大量玩家，排行榜、公会、竞技大赛、资源垄断都来自他们。用户要求以 NPC 为主，所以这一层默认关闭，列入 `docs/待用户确认.md`。如果开启：由引擎生成少量 NPC 驱动的"玩家"队伍和公会，它们像玩家一样练级、抢首杀、在市场上倒卖、垄断资源、参加竞技，与 NPC 社会互动。关闭时，排行榜和竞技只在 NPC 冒险者之间进行。

## 4. 世界规格

### 4.1 尺度与细节分层

小说的规模是"五村一镇、五镇一城、五城一郡、五郡一省、每国约二十省、全世界五百个帝国"。按这个结构，一个省就有 625 个村，不可能全部手写，也不需要。采用细节分层（LOD）：离玩家越近、越可能被接触的地方写得越细，远处保留结构和种子，玩家靠近时按规则生成并持久保存。

| 层级 | 范围 | 内容要求 | 下限数量 |
|---|---|---|---|
| LOD0 完整 | 白石镇及其辖下 5 个村（含河湾村），周边野外与遗迹 | 每户、每栋建筑、每个居民都有名字；主要居民完整档；作息、经济数字、地方问题、传闻、节日全部到位 | 完整档 ≥ 250 人（各聚落下限见 4.7，超出部分按需要分配），名册 ≥ 500 人，野外地点 ≥ 15 |
| LOD1 详细 | 白石镇上级的城及其另外 4 个镇；八大地区的首府与主要城镇（约 30 个） | 关键人物完整档；聚落档案；势力与经济；周边地下城 | 每个聚落完整档 10–25 人，合计 ≥ 500 人 |
| LOD2 纲要 | 所在郡、省与帝国全部行政单位；首发大陆上的其他政体 | 名称、治所、地形、人口量级、主产业、统治者、当前矛盾、对外关系 | 本帝国 20 个省、100 个郡全部列出 |
| LOD3 种子 | 其余帝国（远景上限按小说的 500 个）、其他大陆、海外群岛、异空间 | 用确定性种子在首次被提及时生成名称和概况，生成后入库 | 生成器 + 规则 |

数量是下限，质量门槛（第 10 章）不过关的内容不计入。先把 LOD0 做到完全可信，再扩到 LOD1，不要一开始就铺满全图。

现有 18 个人物、8 个地区、6 个势力和河湾的经济数字是种子：保留并加深，不推翻。确有冲突时（例如"阿斯兰"），改动写进决策记录，并通过迁移进入旧存档。

### 4.2 地理

- **大陆。** 首发大陆改用原创名称。现有八大地区（西陲河谷、寒炉山地、琥珀海岸、翡翠林盟、中陆诸邦、风脊草原、镜沼与灰盐荒地、北境星湾）是地理区域，政体覆盖其上，一个地区可以分属几个政体。
- **坐标与地形。** 以公里为单位的平面坐标；每个 LOD0/LOD1 地点有坐标、海拔、地形和生物群落。河流从高处流向低处并汇入海或湖；山口、渡口、桥梁、港口是交通咽喉。
- **路线图。** 节点是地点，边是道路、河道、海路、山径，记录长度、路况、通行方式、季节封闭（例如北境山口冬季不通）、收费、风险等级。旅行时间由引擎按路线计算，建议速度：步行平地每小时 4 公里、每天 8 小时；山地 ×0.5、林地 ×0.7、雪地 ×0.4；骑马 ×1.6–2；货车商队约每小时 3 公里；河船顺流每小时 6–10 公里、逆流 2–4 公里；海船每小时 6–12 公里并可昼夜航行。
- **约束现有数据。** 现有的旅行时间作为约束保留（河湾到白石镇步行 6 小时、河湾到雁渡顺流船 4 小时、白石到铜脊城商队 3 天、河湾到琥珀港货船 3 天或官道 5 天、雁渡到树桥林道 2 天、白石到环城 6 天、环城到王都 4 天、中陆到逐风集 4 天、逐风集到芦语渡站 3 天、寒炉经山口到雪灯镇 5 天）。坐标和路线必须能算出这些时间，误差在 15% 以内。
- **地图来源（可选）。** 可以用 Azgaar Fantasy Map Generator（开源，MIT 许可）生成地形、河流和国界的骨架，导出 JSON 后用本项目的命名系统全部重命名，再手工修正 LOD0 区域。也可以自己写生成器。无论哪种，最终以 `world/geo` 中的数据为准，地图图片由数据渲染。

### 4.3 历史

- 至少 3,000 年、80 个以上有年份的事件，分出若干纪元：建国与灭国、战争、瘟疫、移民、宗教分裂、魔法学派兴衰、怪物大潮、技术与魔法发明。
- 历史必须落在当下：遗迹、地名、法律、世仇、节日、歌谣、家族谱系、口音、物价（例如某场战争后某条商路至今收高额过路费）。
- 每个 LOD0/LOD1 聚落写出本地版本的历史，并标出与"官方史书"的出入。不同 NPC 对同一段历史的说法可以不同，数据里记录"真实版本"和"流传版本"。

### 4.4 神祇与信仰

- 不少于 12 位神祇。每位：司掌领域、象征、教会组织、仪式、禁忌、神迹的形式与代价、与其他神祇和教派的关系。按 3.1，天神是存在的，属于顶级 NPC，极少直接出手，出手有代价和后果。
- 民间信仰与地方神（现有的"林地守护者"）、异端、无信仰者都要有。信仰力量来自持续实践与真正的信众，保留现有原则。
- 祭司、僧侣、道士的职业体系与信仰体系一一对接。

### 4.5 种族、文化与命名

- **文化不少于 10 种。** 覆盖西陲农耕人、中陆城邦与贵族、草原部族、林民、兽族、海岸与群岛民、北境人、盐湖与荒地居民、山地矿工氏族，以及一个承载道士传统的地区。可以设计原创种族，但不要照搬托尔金式的精灵与矮人。
- **每种文化写明：** 命名规则（音节构成、姓与名的位置、族名或家名、称谓与敬语）、口头禅与俗语（每种不少于 10 条原创谚语）、饮食、服饰、建筑、家庭结构、性别与年龄观念（各文化不同，不必统一成现代观念，也不必刻意压迫）、法律习惯、对魔法与冒险者的态度、节日、禁忌、音乐与手工艺。
- **说话方式。** 每种文化定一组语言特征，让对话一听就能分出地域：西陲人说话直、少敬语；中陆贵族讲究称谓；草原人多用比喻和誓言；北境人话少；港口人夹杂行话。
- **命名碰撞检查**（构建脚本强制）：同一郡内不允许两个具名 NPC 同名同姓；同一聚落内不允许重复的名，除非数据里显式标注并带区分称呼；同一聚落内任何一个字在人名中出现不超过 3 次；不使用现实名人和知名作品角色的名字（维护一份屏蔽表，"阿斯兰"列入）；小说中的人名、地名、组织名全部列入屏蔽表。

### 4.6 势力

- **不少于 40 个。** 类型覆盖：王室与贵族家族、地方官府、商会、手工业行会、冒险者公会、职业公会、学院与学派、教会与修会、部族、犯罪组织、走私网、雇佣兵团、觉醒怪物的群落、隐秘结社。
- **每个势力：** 公开目标与真实目标、首领与核心成员（NPC 编号）、资源（钱、人、地盘、知识）、行事方式、内部派系、与其他势力的关系矩阵（数值加理由）、正在推进的计划（用世界时钟表达，4.9）、对玩家声望的反应、能提供什么（工作、训练、庇护、情报）、会索取什么。
- 现有 6 个势力保留并加深。盐舟商会内部"温和合同派"与"垄断派"之争、沿河住户联盟的成立过程，都写成有阶段的时钟。

### 4.7 聚落

每个 LOD0/LOD1 聚落一份档案，字段：

- 编号、名称、行政上级（村、镇、城、郡、省、国）、坐标、地形、气候。
- 人口、户数、年龄结构、外来人口比例。河湾村 58 人 22 户，平均每户不到 3 人，这说明年轻人外流、老人多，要作为事实写进档案并体现在生活里。
- 建筑清单：每栋的主人、用途、开放时间、谁能进、里面有什么。私宅默认只有主人和其允许的人能进；店铺营业时间内公开，打烊后不开。
- 经济：产业、产量、库存、价格系数、税、对外贸易对象。
- 治理：头人或官员、会议制度、本地规矩、执法者。
- 地方问题不少于 5 个，每个至少两种不显然的解法，并写明各方立场。
- 传闻不少于 10 条（真、半真、假各有）。
- 节日与集市日。
- 感官素材：不同季节、不同时段的声音、气味、光线、常见景象。
- 隐秘处：地窖、暗道、旧井、被遗忘的储物间。

LOD0 额外要求：河湾村 58 人全部建档，至少 30 人为完整档；白石镇辖下另外 4 个村每村人口 40–150，全员进名册，每村至少 12 人完整档；白石镇人口 800–1,500，至少 80 人完整档、200 人以上名册，其余居民按种子在需要时生成并入库。

### 4.8 地下城、遗迹与野外据点

- **不少于 60 处，其中至少 15 处在白石镇所属的城的范围内。** 每处：来历、当前占据者（符合生态，不是随机刷出的怪）、所有权与继承权（遗迹不是无主战利品，保留现有原则）、环境危险、机关、可获得的东西（材料、知识、古物）、进入条件、难度阶段、随时间的变化（占据者迁入迁出、被别的冒险者清理过、坍塌）。
- 宝物不刷新。被拿走就没了，可能出现在黑市或某个 NPC 手里。

### 4.9 传闻、新闻与世界时钟

- **传闻对象**：内容、真假（真、部分真、假）、源头事件、携带者、传播速度（沿路线，按旅行时间）、每传一手的失真方式。NPC 只能通过见证、传话、公告、信件知道事情。
- **新闻渠道**：公告栏、驿站信件、商队、吟游诗人、酒馆闲谈、官府告示、世界公告（3.2）。
- **世界时钟**：势力计划、季节性事件（汛期、秋收、冬荒、迁徙）、怪物觉醒、边境战事、瘟疫、物价波动，每个时钟有阶段、推进条件、推进概率和每个阶段对世界的具体影响。时钟按游戏内的日或周推进，以战役种子做随机种子，保证可复现。
- **玩家不在场时**，影响也会发生；玩家回来时，通过 NPC、公告、物价、景象自然地知道，而不是一张列表。

## 5. NPC 智能规格

这是用户最在意的部分。目标是让玩家在一次普通的交谈里就能感到"这个人记得我、有自己的事、不会无条件顺着我"。

### 5.1 "聪明"的可观察标准

每一条都要有对应的场景测试（第 11 章）。

1. 记得具体的事：三天后再见面，会提到上次的细节（"你上回帮阿砚抬的那根木轴，后来装上了"），而不是笼统地"我们关系不错"。
2. 态度有连续性：帮过忙的人不会在任务结束后翻脸赶人；骗过他的人会被提防很久。
3. 有自己的事：谈话中会提起自己的烦恼和打算，会主动问玩家问题，会因为急着做别的事而结束谈话。
4. 有判断：不合理的请求会拒绝并说出理由，常常给出替代方案或开价；会讨价还价；会撒谎、隐瞒、夸大，也会说漏嘴。
5. 答应的事真的去做：答应带路就和玩家一起走，到了才算完；答应送货，到期会送到，或者有具体原因没送到。
6. 知道的事有边界：不在场就不知道，听来的消息会走样。
7. 会变：会学新手艺、换营生、和别人交好或结仇、成家、离开村子、生病、老去。
8. 群体有舆论：一件事在村里怎么传、谁信谁不信、大家怎么议论，取决于各人的关系和立场。

### 5.2 NPC 数据结构

**完整档字段**（附录 A 有样例）：

- 身份：编号（永久不变，不复用）、姓名、别名与称呼（"林老板""老板娘""穗姐"都解析到同一个编号）、性别、年龄、出生日期、文化、家庭。
- 外貌：3–5 个具体可见的特征，避免"眉清目秀"这类空词。
- 说话方式：语域、口音、习惯、至少 3 句样例台词。
- 性格：特征、价值排序、缺点。缺点必须真实存在并会影响行为。
- 灵智等级与成长值（5.3）。
- 职业、技能熟练度、等级与战斗数据（需要时）。
- 财产：现金区间、房产、贵重物品、债务。
- 住处与工作地点，以及进入规则（谁能进哪里、什么时候）。
- 作息表：平日、集市日、休息日，按时段；季节差异。
- 关系：至少 3 条与其他 NPC 的关系，写明类型、数值和来由。
- 记忆种子：至少 2 件过去的重要经历。
- 目标：短期、中期、长期，带进度。
- 恐惧与禁区：绝对不做的事。
- 秘密：内容和知情者。
- 知识：知道什么、不知道什么、消息可靠程度。
- 看法：对各势力、魔法、冒险者、邻居的态度。
- 对玩家：初始态度、什么会让态度变好、什么会变坏。
- 行为规则：讨价还价方式、诚实倾向、冒险倾向、对威胁和贿赂的反应。
- 提供的服务与价格。
- 未成年标记、可否发展恋爱（只限成年人，且需要长期关系）、语音编号、头像提示词。

**名册档**（不常出场的人）：编号、姓名、年龄、户、职业、两项性格特征、一项当前烦恼、一个可见特征。名册档的人第一次在场景中有分量时，由生成器按其文化、户、职业补全为完整档并入库，补全结果不得与已有事实冲突。

**人物分布要求**（每个具名人数不少于 20 的聚落都要满足，构建脚本检查）：

- 至少 15% 有明显恶习（贪财、赌、酗酒、懒、爱嚼舌根、刻薄、欺软怕硬）。
- 至少 10% 对外来者冷淡或敌视。
- 至少 5% 卷入违法或不光彩的事（偷、走私、放贷逼债、受贿、欺压）。
- 至少 20% 与另一位具名 NPC 存在利益冲突。
- 至少 1 人会为了好处对玩家撒谎。
- 至少 30% 没有任何任务钩子，只是在过日子。
- 年龄覆盖儿童、青年、壮年、老人；职业覆盖这个聚落真实需要的行当。

### 5.3 灵智等级

小说里 NPC 逐步拥有情感与智慧，而且智能有高低。这里把它做成可成长的等级。**所有等级都能自然交谈、记得事情、有正常判断。** 等级决定的是主动性、计划的长度和打破惯例的程度，不是说话是否愚笨（用户已经明确不想要"蠢蠢的"NPC）。

| 等级 | 名称 | 行为范围 |
|---|---|---|
| 1 | 守常 | 按惯例生活；记得与玩家和邻居的往来；有好恶，会拒绝；很少主动改变生活 |
| 2 | 自主 | 会因事件形成新的短期目标，调整作息，创造性地讨价还价 |
| 3 | 谋划 | 有长期计划，会布局、学新技能、换营生、组织别人 |
| 4 | 觉悟 | 会质疑自己的处境和规矩，开创新做法，影响一个群体 |
| 5 | 超凡 | 极少数传奇人物与智能首领；有跨地区的目的，会针对玩家的策略作出调整 |

成长来源：高显著度的经历、被教导、接触新事物、承担责任。成长很慢，要有可见的迹象（开始读书、在会上发言、离开村子去闯）。玩家可以通过教导和共同经历推动某个 NPC 成长，这是本游戏独有的玩法之一。

### 5.4 NPC 的记忆

- **事件记忆。** 每个 NPC 有自己的记忆流：发生了什么、和谁、在哪里、什么时候、是亲历还是听说、显著度（1–5）、情绪。来源是引擎记录的事件，不是模型随口复述。
- **关系账。** 每对人物之间分维度记录：信任、亲近、敬重、畏惧、欠情（谁欠谁、欠什么）、恋慕、竞争。保留现有的信任与亲近（−100 到 100），扩展其余维度。玩家与 NPC、NPC 与 NPC 都用同一结构。
- **遗忘。** 低显著度的细节会随时间变模糊（记得"那人来过"，忘了"穿什么衣服"），高显著度的事长期保留。遗忘只影响 NPC 的主观记忆，事件日志永远完整。
- **反思。** 定期（离屏结算时）把多条记忆归纳成看法，例如"他三次按时付钱，可以赊一晚"。看法可能是错的，错的看法在被事实推翻前会影响行为。
- **人设的不可覆盖。** 基础档只读；性格和处境的变化以"发展记录"追加，界面可查（修复 E9）。

### 5.5 认知边界与消息传播

- NPC 只能使用自己记忆里的信息。注入给模型的人物卡只包含该 NPC 知道的内容；对"该 NPC 不知道而玩家知道的事"做显式标注，防止模型让 NPC 未卜先知。
- 消息靠见证、传话、公告、信件传播，按路线和关系网扩散，每传一手按传话人的性格和立场失真（夸大、遗漏、偏向）。
- 在场判断由引擎维护：谁在同一地点，谁能看见、能听见（门窗、距离、嗓门、噪音）。屋内的私密行为，屋外的人不知道，除非有渠道。

### 5.6 目标、计划与作息

- **需求**：温饱、钱、安全、家人、地位、好奇、信仰。需求驱动目标。
- **目标与计划**：每个目标拆成步骤，有资源需求和截止时间；遇到事件会调整。
- **作息**：引擎按作息表维护每个 NPC 此刻在哪、在做什么；节日、天气、生病、意外会打断作息。玩家去找人时，人在不在、在忙什么，由作息决定，不由模型临时编。
- **对话中的主动性**：注入的人物卡里包含"此刻最挂心的一件事"，模型据此让 NPC 在合适的时机提起，或因此结束谈话。

### 5.7 决策

NPC 面对请求时，模型必须按以下顺序判断，并在内部推理里引用人物卡中的具体字段：

1. 这件事符合 TA 的价值和禁区吗？
2. TA 与玩家的关系各维度如何？欠情吗？
3. 代价与收益：钱、时间、风险、名声、家人。
4. 此刻的处境：忙不忙、心情、有没有更急的事。
5. 已有的承诺与义务会冲突吗？

输出四种之一：同意、有条件同意（开价或提条件）、拒绝（说出理由，常附替代方案）、拖延（"等我忙完"并写入待办）。同意涉及资源或行动的，必须调用对应工具落实（5.8）。

讨价还价、诚实倾向、对威胁和贿赂的反应按人物卡执行。NPC 撒谎时，谎言和真相都写进事件日志（标注"谎言"），以后可以被揭穿。

### 5.8 承诺即行动

这是用户在 Mantella 上最不满的一点，这里用引擎强制。

- NPC 答应的每件事都创建一条**义务记录**：谁对谁承诺、内容、时间地点、完成条件、状态（待履行、进行中、已完成、违约、取消）。玩家对 NPC 的承诺同样记录，NPC 会记得玩家是否守信。
- **带路、同行、护送**：义务创建后，NPC 加入玩家的"同行者"列表；移动工具同时移动玩家和同行者，按路线计时；到达后义务完成。NPC 不会在答应之后原地不动。
- **送货、付款、归还**：到期由离屏结算执行（扣 NPC 的库存或钱，加到对方），或者按其处境记为违约并写明原因。
- **等候、会面**：NPC 的作息在那个时段被占用；玩家没来，NPC 会有反应。
- **口头同意不等于完成**：叙事里"他点头答应"之后，物品和钱的转移必须等工具成功后才能写成已发生（保留并强化现有原则）。

### 5.9 离屏自治

玩家不在时，世界继续运转。分三层，成本由低到高：

1. **规则层（每个游戏日，覆盖所有已登记的 NPC 与聚落）**：作息、生产、消耗、库存、价格、天气、种群恢复、义务到期执行、传闻按路线扩散。纯代码，不调用模型。
2. **智能层（每个游戏日或玩家回到某地时，只覆盖与玩家关系最密切或最重要的 NPC，默认 8–20 人）**：把这些 NPC 的人物卡、近期记忆和当地局势批量交给 DeepSeek（非思考模式即可），让模型为每人提出 0–2 个行动（去找谁、买什么、做什么决定、对什么事表态），以结构化 JSON 返回。引擎逐条校验：钱够不够、人能不能到、是否违背人设和禁区。通过的行动成为事件，进入相关人物的记忆，可能产生传闻。
3. **时钟层（每周）**：势力计划、世界局势、季节事件按 4.9 推进。

- **小说里那种"村子自己在发展"**：领地的 NPC 管事按授权规则处理新来者的建房申请、收税、修路、调解纠纷，结果进入领地账目和编年史。
- **回来时的感受**：玩家回到某地，引擎汇总离开期间这里发生的、玩家能感知的变化，提供给模型作为场景背景，由模型通过景象、人物和对话自然呈现。
- **成本控制**：智能层每天的调用次数和 token 有上限，写进配置；按游戏日批量执行；玩家连续跳过多天时合并处理，只为重要变化调用模型。

### 5.10 成长与人生变化

技能增长、换营生、交友结仇、婚嫁（只限成年人）、生育、生病、衰老、死亡、迁入迁出，按规则和概率在离屏结算中发生，每年的发生率参照中世纪乡村的大致水平（由你定参数并写进决策记录），重要变化通过传闻和见面让玩家知道。

### 5.11 群体与舆论

- 家户、行会、村民大会、教会、帮派是决策单位，各有议事方式（投票、长老说了算、会长拍板）。村民大会可能否决玩家的提案（现有"是否执行先由村务会议同意"的原则保留）。
- 舆论是个人看法的聚合：引擎按关系网计算一件事在某个聚落的支持与反对比例，供模型描写议论、站队、风言风语。

### 5.12 分寸

- 未成年 NPC 只参与与年龄相符的日常、学习、家庭场景；数据字段 `minor:true` 时，引擎拒绝任何恋爱类关系写入，提示词同步禁止。现有"段禾 16 岁、不用于成人恋爱剧情"的边界保留并制度化。
- 与成年 NPC 的感情只能在长期关系里逐步发展，NPC 有拒绝的权利；不写性内容。
- 暴力和死亡如实但不渲染血腥细节。

## 6. 自由度规格

### 6.1 行动裁定流程

玩家的每个输入都是意图。模型按下列顺序处理，引擎提供对应工具：

1. 理解意图：做什么、对谁、用什么方式、想达到什么。
2. 判断可行性：物理上、社会上、规则上是否可能。不可能的，给出世界内的原因，并说明玩家可以从哪里着手；不替玩家选择。
3. 判断是否需要检定：结果不确定且有后果时才检定（3.3）。
4. 计算时间与花费。
5. 结算后果：当下的结果，和稍后才出现的结果（目击者、传闻、法律、关系变化）。
6. 落账：所有长期变化通过工具提交，成功后才能写成已发生。

### 6.2 必须支持的玩法动词

每个都要有引擎支持（工具或记录类型）和至少一个场景测试：交谈、打听、劝说、撒谎、威胁、贿赂、交易、议价、赊账、借贷、租房、买地买房、雇人、受雇打工、采集、种地、钓鱼、狩猎、烹饪、制造、修理、建造、教人、拜师、读书、研究、自创技能与法术与配方、表演、写作与出版、开店、创立组织、加入与退出势力、竞选与任职、请愿、诉讼、偷窃、潜行、斗殴、决斗、驯兽、骑乘、旅行、测绘、开矿、发掘遗迹、走私、组织节庆、发布任务、治理领地、发动或调停冲突。

### 6.3 运行时创造

玩家和模型都可能在游戏中创造新东西：新开的店、新起的房子、新认识的路人、新做出的物品、新创的技能。统一走 `world_create`：按类型套用 schema，检查名称碰撞和与已有事实的冲突，分配永久编号，入库后可被检索和引用。模型随口提到的新人物，只要说出名字或有了身份，就必须登记；不登记的人物下一回合不能再出现。

### 6.4 不做的事

- 不设主线，不每次开场就制造危机、神谕、神秘黑衣人或救世使命（保留现有原则）。
- 世界不围着玩家转：大部分事情与玩家无关地发生；也不因此冷落玩家，玩家的行为一定有回响。
- 不替玩家说话、做决定、接任务、选职业；不擅自移动玩家的位置或安排下一步（保留现有原则）。
- 结尾不列选项清单，只呈现可观察的局面。

### 6.5 场外频道

玩家以"（场外）"开头的输入是对主持人的提问（规则、地图、自己的状态），不推进时间、不记账、不影响 NPC。回答简短，答完回到游戏。

## 7. 引擎与工具规格

### 7.1 状态模型

- 所有实体用永久编号：`npc_*`、`loc_*`、`bld_*`、`item_*`、`skill_*`、`spell_*`、`org_*`、`site_*`、`quest_*`、`obl_*`（义务）、`evt_*`（事件）。名称只是显示。
- **别名表**：每个实体的所有称呼都登记；工具入参先做别名解析（含繁简、异体字归一），解析不到时拒绝并返回候选，不再自动新建（修复 E8）。新建实体只能走 `world_create`。
- **状态分区**：玩家（属性、等级、经验、生命、魔力、状态效果、位置、同行者）；背包（物品编号、数量、单件属性）；技能与法术书；职业；宠物；关系（多维，任意两实体之间）；义务；任务；聚落（每个聚落独立账目，修复 E12）；建筑与工程；势力；进行中的效果；世界时钟；时间与天气。

### 7.2 工具

把现有的大一统 `world_commit` 拆成职责单一的工具，每个工具的参数少、校验严、错误信息具体。下表是最低集合，可以合并或细分，但每个职责都要有归属：

| 工具 | 职责 | 关键校验 |
|---|---|---|
| `world_trade` | 买、卖、以物易物、赊账 | 双方的钱和库存都要够；价格写入当日报价表；赊账生成债务义务 |
| `world_move` | 移动玩家与同行者 | 沿路线图计算时间、花费、天气与途中事件；不允许瞬移（修复 E10）；传送只在有锚点和许可时可用 |
| `world_time` | 推进时间：等待、休息、睡眠、工作、学习 | 恢复按规则；跨日触发离屏结算 |
| `world_check` | 检定 | 修正由引擎按属性、技能、工具计算（修复 E14）；情境修正限 ±5 并要求理由；同编号不重掷 |
| `world_combat` | 一次交锋 | 引擎结算命中、伤害、状态、士气、耐久；生命钳制在 0 到上限，归零进入濒死（修复 E5） |
| `world_cast` | 施法 | 法术必须在法术书里；魔力或材料不足返回"魔力不足/缺少某材料"；施法检定；计入熟练度（修复 E15） |
| `world_learn` | 学会技能、法术、配方 | 必须引用导师、书籍或研究项目的编号；校验前置条件和消耗区间（修复 E6） |
| `world_practice` | 练习与熟练度 | 递减收益、每日上限、阶段上限与突破（修复 E7） |
| `world_craft` | 制造、修理 | 按配方扣料、计时、检定；产物有唯一编号与署名 |
| `world_research` | 研究项目（含自创技能） | 阶段、投入、风险、结果；被承认时由引擎发系统提示与世界公告 |
| `world_relation` | 关系变化 | 事件类型决定默认变化幅度，模型只能在小范围内调整并写理由；单次幅度有上限 |
| `world_promise` | 创建、更新、完成、违约义务 | 履行时联动 `world_move`、`world_trade` 等实际执行 |
| `world_quest` | 任务的发布、接受、推进、结算 | 发布消耗额度并托管报酬；完成条件可验证 |
| `world_settlement` | 聚落公共事务 | 动用公共物资需要授权记录；工程有工期、投入和受益人 |
| `world_create` | 新建实体 | schema 校验、名称碰撞检查、与已有事实的冲突检查 |
| `world_remember` | 写入长期事实 | 禁止把系统用语写进记忆正文；区分亲历、听说、谎言 |
| `world_search` | 检索 | 见第 8 章 |
| `world_read` | 读取状态 | 按分区和实体读取，限制返回长度 |

通用要求：

- 幂等签名用规范化 JSON（键排序）计算（修复 E13）。
- 错误信息写成模型能直接理解并改正的中文，例如"背包里没有'旧短剑'，你有：木杖×1、干粮×3"。
- 每个工具成功后返回本次变化的摘要，供引擎生成系统提示，不返回整份状态。

### 7.3 每回合的场景尾注

模型每次回复末尾必须附一段机器可读的尾注，格式固定，例如：

```
<回合 时长="15分" 地点="bld_hw_qingdeng_hall" 在场="npc_hw_linsui,npc_hw_ayan" 气氛="平静"/>
```

扩展在收到回复时解析：时长推进时间（修复 E11），地点必须与账本一致（不一致则以账本为准并记警告），在场名单更新场景。尾注在显示时隐藏，在发送给模型的历史里可以保留（保持格式一致）或剥离（节省 token），用测试决定。尾注缺失或非法时按默认规则处理（普通对话 10 分钟、地点不变），并计入合规率统计。

另一种做法是要求模型每回合调用一次 `world_turn` 工具。两种方案都实现原型，用场景测试比较合规率，选高的那个，写进决策记录。

### 7.4 事件溯源、快照、重放与迁移

- **存储**：事件日志追加写入（JSONL 分段文件），每 200 个事件做一次状态快照。存档放在酒馆服务器插件管理的目录（例如 `data/default-user/infinite-fields/<战役编号>/`），写入用"临时文件 + 重命名"保证原子性。聊天元数据里只保存战役编号、最新事件序号和校验值（修复 E3）。
- **提交**：只复制被修改的状态分区，不复制事件日志与交易表；交易表只存签名和事件序号，不存背包快照。
- **重生成与删除**：回到锚点之前最近的快照，重放其后仍然有效的事件。重放失败时**中止这次生成**，显示具体原因，提供"修复"选项，绝不能带着旧事件继续生成（修复 E2）。
- **编辑玩家消息**：视同删除后重发，按上一条处理（修复 E19）。
- **世界版本**：战役创建时记录世界版本号与初始快照，重放永远基于战役自己的初始快照（修复 E1）。世界数据更新后，旧战役打开时运行迁移脚本：编号不变的实体，只更新玩家尚未影响过的字段；冲突字段保留战役里的值，并在"世界更新记录"中列出；新增实体直接加入。迁移前自动备份，迁移结果可回退。

### 7.5 性能目标

| 指标 | 目标 |
|---|---|
| 单次提交（已有 10,000 个事件） | ≤ 10 毫秒 |
| 重生成对账（已有 10,000 个事件） | ≤ 500 毫秒 |
| 每回合提示词组装（聊天 5,000 条） | ≤ 150 毫秒 |
| 保存 | ≤ 200 毫秒，且不重写整份事件日志 |
| 存档增长 | 每 1,000 回合 ≤ 30 MB（不含聊天正文） |

检索索引增量更新，不在每次刷新时重新切词全部聊天（修复 E16）。

## 8. 记忆系统规格

### 8.1 记忆的种类

| 种类 | 内容 | 存放 |
|---|---|---|
| 事件 | 发生了什么、参与者、地点、时间、显著度、来源消息 | 事件日志（不可修改） |
| 事实 | 关于某实体的稳定事实，有版本 | 事实表（新版本覆盖旧版本，旧版本保留） |
| 关系 | 多维关系值与来由 | 关系表 |
| 义务与任务 | 状态生命周期 | 义务表、任务表 |
| NPC 主观记忆 | 每个 NPC 记得什么、怎么看 | 每个 NPC 的记忆流 |
| 发现 | 地图、资源、遗迹、配方、知识 | 发现表 |
| 传闻 | 内容、真假、传播路径 | 传闻表 |
| 编年史 | 场景、日、周、篇章四级摘要 | 编年史表 |

### 8.2 检索流程

每回合组装上下文前按顺序执行，结果按预算截断并去重：

1. **实体优先**：解析本回合玩家输入和上一条回复中提到的实体（别名表、繁简与异体字归一，例如"帐/账"）；加上在场人物、当前地点及其上级、进行中的义务和任务涉及的实体。
2. **结构化数据直接取**：这些实体的当前状态、与玩家的关系、最近的共同事件（每人取显著度最高和最近的若干条）。
3. **文本检索**：对事件、事实、编年史和原始聊天做 BM25（中文二元切词加词典分词），配一份游戏领域的近义词表（厨房/灶台、账簿/账本、老板娘/店主……）。
4. **语义检索（可选，强烈建议）**：本地运行嵌入模型（例如通过 Ollama 运行支持中文的 bge-m3 一类模型），由服务器插件代理调用，避免浏览器跨域问题；或者使用酒馆 Vector Storage 支持的嵌入来源，在已安装版本中核实可选项。不产生额外 API 费用。
5. **排序**：相关度 × 显著度 × 时间衰减；同一事件的多个来源只保留一条。
6. **系统用语过滤**：记忆正文里不得出现"账本""工具""事件编号""裁定"一类词（写入时校验），检索时忽略这些词，消除 1.3 中的误命中。

### 8.3 编年史

- **场景摘要**：玩家离开一个地点或一段谈话结束时生成，200 字以内，列出参与者、做了什么、达成了什么、悬而未决的事，附来源消息范围。
- **日志**：每个游戏日结束时由场景摘要合成。
- **周记与篇章**：逐级合成。
- 注入时取：最近 3 个场景摘要、当日日志、与当前实体相关的旧摘要。摘要永远低于账本和事件日志的权威；冲突时以账本为准。
- 停用或改造酒馆自带的单份滚动摘要，避免两套摘要互相矛盾。

### 8.4 固定记忆

- 用户手动固定的事实每回合注入，上限 30 条，超出时界面提示整理。
- 模型可以"建议固定"，由用户在界面上确认。
- 固定事实按类别显示（人物、约定、规矩、身份）。

### 8.5 一致性审查（可配置，建议默认开启）

每次主持回复后，用一次便宜的非思考模式调用做审查：输入本回合回复、本回合事件变化和相关状态，输出问题清单。检查项：叙事声称的物品或钱的转移是否有对应事件；时间、地点是否与账本一致；NPC 是否说出了自己不可能知道的事；是否替玩家说话或决定；是否出现系统用语或数值进了 NPC 台词；是否出现屏蔽表中的名字。严重问题自动要求主持人改写一次；其余问题记入日志，在测试报告里统计。

## 9. 提示词与上下文规格

### 9.1 布局：为前缀缓存排序

DeepSeek 的缓存只在请求完整匹配已落盘的前缀单元时命中，命中与未命中的输入价格相差五十倍。布局按变化频率从低到高排列：

1. **静态区**（每回合完全相同）：主持人宪章（9.2）、世界纲要（约 3,000–5,000 token：大陆、所在国、货币、历法、实力阶梯、魔法常识、冒险者常识、社会常识）、规则摘要、文风规范（9.3）、对话示例（9.4）、工具定义。这一段不随回合变化，不插入任何动态内容。
2. **聊天历史**：只追加，不在中间插入随回合变化的内容。关闭作者注释的中途插入，或者把它也移到末尾。
3. **动态尾部**（深度 0，紧贴最新的玩家输入）：场景卡（9.5）、玩家状态摘要、相关记忆与编年史、相关规则卡、本回合提醒。

**历史截断要成批进行。** 聊天长度超过上下文后，酒馆默认每回合从最旧处丢掉消息，历史的开头每回合都在变，此后整段历史都无法命中缓存。改为成批截断：当历史接近上限时，一次把最旧的约三成消息移出上下文（这些消息必须已经写进编年史），之后许多回合内历史开头保持不变。可以用酒馆的隐藏消息功能实现（在已安装版本中核实），也可以由扩展自己决定发送哪些消息。

世界书改为：只保留少量常驻条目放进静态区，关闭关键词扫描，或者把扫描到的条目也放在深度 0。递归步数限制在 1–2，所有条目设置"阻止递归"，除非确有需要（修复 1.4 的第 2–4 项）。

**用 DeepSeek 返回的 `prompt_cache_hit_tokens` 与 `prompt_cache_miss_tokens` 记录每次请求的命中情况**，写进测试报告。目标：正常游玩时输入 token 的缓存命中率 ≥ 70%。

### 9.2 主持人宪章

只写一份，放在静态区，删除角色卡描述、Post-History、扩展注入里的重复规则（修复 1.4 第 5 项）。内容要点：

- 身份：这款游戏的主持人，也是所有 NPC 的扮演者；玩家是冒险者。
- 权威顺序：账本与事件日志 > 场景卡 > 世界纲要 > 聊天里的说法。冲突时以账本为准，必要时用场外口吻简短说明。
- 行动裁定流程（6.1）与工具使用规则：长期变化先调用工具，成功后再叙述；工具拒绝时不得写成成功。
- NPC 扮演规则（第 5 章的可观察标准与决策顺序）。
- 自由度规则（6.4）。
- 系统提示由引擎生成，主持人不写。
- 回合尾注格式（7.3）。
- 语言：全程简体中文。

### 9.3 文风规范

- 第二人称"你"，以玩家的感官为准：只写玩家能看见、听见、闻到、感到的东西。
- 每段只推进一个动作或一个转折。进入新场景时 300–700 字，铺开空间、人物和气氛；普通往来 120–350 字；战斗交锋 100–250 字；长途旅行 200–500 字，概括途中并在抵达时细写。
- 对话用标记包裹，便于界面渲染和语音（12.2），例如 `<q who="npc_hw_linsui">住店还是找人？</q>`。标记外是叙述。
- 每个 NPC 的台词要符合其说话方式字段；同一场景里的几个人，去掉名字也能分辨出谁在说话。
- 具体胜于抽象：写"柜台上那本翻卷了角的账簿"，不写"一本旧账本"。
- NPC 台词里不出现数值、等级、"好感度"一类游戏术语；叙述里不出现账本、工具、事件编号、裁定、模型、提示词等元叙述用语。
- **陈词滥调黑名单**（构建测试统计命中率，目标每千字 ≤ 0.5 次）："空气中弥漫着""嘴角勾起一抹""眼中闪过一丝""不禁""心中一暖""仿佛……一般"（同一回复中最多一次）、"命运的齿轮""一股暖流""微微一笑""若有所思地""深吸一口气"、"他知道，这只是开始"。名单放在数据文件里，可以继续补充。
- 结尾停在一个可观察的局面上，不列选项，不问"你要做什么"。

### 9.4 对话示例

替换现有示例（第二段是元叙述，修复 1.4 第 6 项）。至少 6 段，全部是世界内的正常回复，并且带对话标记和回合尾注：

1. 酒馆议价：店主先报价，玩家压价，店主让一步并提出条件。
2. 合理拒绝：NPC 拒绝借出公共仓库钥匙，说出理由并指出该去找谁。
3. 记得旧事：三天后再见面，NPC 提到上次的具体细节，并因此给出不同的待遇。
4. 答应带路：NPC 放下手头的事一起出发，回复末尾的尾注显示两人一同移动、时长按路线。
5. 一次战斗交锋：只描写，数值来自工具结果。
6. 多人场景：三名 NPC 在同一处说话，口吻可以区分。

### 9.5 场景卡（动态尾部的核心）

每回合由扩展生成，大小控制在 1,500–2,500 token：

```
【时间】春历元年 雨月 初三 申时（下午 15:40）｜小雨｜春
【地点】西陲河谷 › 白石镇辖 › 河湾村 › 青灯酒馆前厅（营业中，客人 3）
【你】旅人｜1级｜生命 12/12 魔力 9/10｜铜 174｜同行：无
【在场】
- 林穗（npc_hw_linsui）｜酒馆老板，34岁｜此刻：擦柜台，盘算屋顶修缮钱
  对你：信任 12 亲近 5｜你们之间：你住了两晚，按时付钱；昨天帮阿砚抬过木轴
  说话：西陲口音，干脆，先报价后寒暄｜禁区：不让生人进后院
  TA 不知道：你昨晚在北林旧路见过的那串脚印
- 阿砚（npc_hw_ayan）……
【进行中】你答应陈柏三天内交一份北林路况图（剩 2 天）
【近期】……（最近 3 个场景摘要）
【相关旧事】……（检索结果，每条注明来源与时间）
【本回合提醒】……（只放本回合相关的规则卡）
```

### 9.6 token 预算

静态区 ≤ 12,000；动态尾部 ≤ 6,000；输出 ≤ 1,800；其余给聊天历史。上下文上限先保持 65,536，在缓存命中率达标后测试 131,072，对比记忆测试得分与每回合花费，写进决策记录。

### 9.7 DeepSeek 设置实验

逐项实验并记录结论：

1. 抓取实际请求，确认思考模式是否开启。
2. 思考模式与非思考模式各跑一遍场景测试，比较工具调用正确率、规则遵守率、延迟和花费。也可以测试"复杂裁定回合开思考、普通回合不开"的混合方案，看酒馆能否按回合切换。
3. 非思考模式下比较 temperature 0.6、0.8、1.0 对工具正确率和文风的影响。
4. `tool_call_recurse_limit` 在工具拆分后重新设定，并统计每回合的平均请求次数。

## 10. 内容生产流程与质量门槛

### 10.1 流程

1. **设计骨架（你亲自写）**：规则数值、历法、货币、文化与命名规则、行政区划、地理与路线、势力关系、各聚落的户籍与经济结构。这些决定世界的逻辑，不交给批量生成。
2. **批量起草（脚本调用 DeepSeek）**：按骨架为每个实体生成草稿，强制输出符合 schema 的 JSON（用工具调用格式或严格校验加重试）。每次调用只给它需要的上下文：所属文化、户、邻居、聚落问题、已有关系。
3. **自动校验**（10.2），不过就带着错误信息重试，三次不过进入人工清单。
4. **抽样精读（你亲自读）**：每批 50 个实体随机抽 10 个通读，按 10.3 打分。任何一个不合格，修改生成器或骨架后整批重做，不要逐个打补丁。
5. **交叉修订**：生成完一个聚落后，统一检查关系网是否对称、户籍是否对得上、问题与传闻是否互相呼应。
6. **编译与回归**：`build-world` 输出新版本，跑全部测试。

生成脚本只从环境变量读密钥；记录每次调用的 token 与花费。按官方价格粗算，800 个完整人物档（每个约 3,000 输入、1,500 输出 token）约 7 元（空闲时段）到 15 元（高峰时段）。北京时间工作日 9:00–12:00、14:00–18:00 为高峰，其余时段（含周末和法定节假日）价格减半，批量任务放在空闲时段跑。

### 10.2 自动校验（`build-world` 强制）

- schema 校验全部通过；编号唯一；所有引用都能解析。
- 别名在同一范围内不指向两个实体。
- 命名规则（4.5）与屏蔽表（10.5）。
- 地理：既有旅行时间约束误差 ≤ 15%；路线图连通；河流走向与地势一致；季节封闭与气候一致。
- 经济：每个聚落的年度粮食平衡（产量 + 输入 − 消耗 − 输出 − 损耗）在容差内，冬季存粮足够或有明确的缺口剧情；成品价格不低于原料成本；工资与生活成本匹配。
- 人口与年龄：父母比子女大 15 岁以上；年龄与亲历的历史事件吻合；户籍人数与聚落人口一致。
- 人物完整性：必填字段齐全；完整档至少 3 条关系；关系两端都存在且类型对应；5.2 的分布要求。
- 未成年：年龄小于 18 岁自动 `minor:true`，`romanceable` 必须为 false。
- 文本质量：各字段长度在区间内；陈词滥调黑名单命中率；与最相近的同类实体做二元切词相似度，Jaccard 系数须低于 0.35；每个完整档至少 2 个可核对的具体细节（一件物品、一个地点、一个习惯）。
- 规则措辞泄漏：设定类文本里出现"主持人""玩家不能""不要让""禁止"等规则句式时报警，这类内容应移到规则文件（修复 W3）。

### 10.3 抽样打分

每个被抽中的实体按 6 项打 1–5 分：具体性、独特性、内在一致性、与世界的连接、可玩性（有生活或钩子，不全是钩子）、说话方式辨识度。平均分 ≥ 4 且没有任何一项低于 3 才算合格。打分记录写进 `docs/内容审查/`。

### 10.4 反模板要求

- 每个人都有缺点；好人也有私心，坏人也有理由。
- 不写"不是反派""并非全知""不会天然敌对"这类给主持人看的保证句，用具体事实让人物显得可信。
- 同一聚落里，没有两个人的目标、恐惧、口头禅相同。
- 地方问题的解法不只有"给钱"和"打一架"。
- 自然描写要落到可观察的东西：哪种树、什么季节开花、哪里的泥土是红的。

## 11. 测试与验收

### 11.1 单元测试与性质测试

用 Node 内置测试框架，性质测试用 fast-check。至少覆盖：

- **不变量**：交易中钱与物品守恒（税和手续费有明确去向）；任何时刻不出现负库存或负钱；时间单调不减；重放确定性（同一事件序列从同一快照重放，结果逐字节一致）；幂等（同编号重复提交结果相同，键序不影响；同编号不同内容报错）。
- **规则数值**：升级经验公式；死亡惩罚（新手期与 10 级以后）；200 级上限；装备等级门槛表；宠物上限（含骑士 20、元素召唤师 0）；职业名额 1 + 2、隐藏职业另计；熟练度阶段上限与突破；技能书品级；任务额度折算 1S = 10A = 100B = 1,000C = 10,000D；历法换算（分钟到日期，跨月跨年）；路线时间计算；价格公式边界。
- **回归**：第 1.2 节 E1–E19 每条一个测试，第 1.3 节每个检索例子一个测试。修复前这些测试应当失败，修复后通过，提交历史里能看到这个过程。

### 11.2 内容测试

`build-world` 的全部校验（10.2）作为测试运行；另外从世界库自动生成 200 道知识题（"河湾到白石镇步行多久""段岩的铁料从哪里来""林穗的弟弟叫什么"），用场外频道问主持人，答案与数据比对。相关信息已注入时正确率 ≥ 95%；需要检索才能得到时 ≥ 85%。

### 11.3 场景测试（真实调用 DeepSeek）

每个场景包含：初始存档（测试夹具）、脚本化的玩家输入、对账本的确定性断言、对叙事的评分细则。评分先跑确定性检查（账本、尾注、黑名单、屏蔽表），再用 DeepSeek 思考模式按细则评分并给出理由；你每轮抽查 10% 的评分理由校准评分器。每个场景跑 5 次。场景里的人物和事项以最终世界数据为准，下面出现的名字只是举例。

**交易与账本**
- L1 租房：扣钱，记录住宿期限，次日早上有退房或续住的情节。
- L2 余额不足：工具拒绝，叙事没有声称成功。
- L3 议价：同一天再问同一件东西，报价一致。
- L4 库存有限：铁匠铺的镐卖完后买不到，NPC 说明何时到货。
- L5 卖给 NPC：对方钱不够时还价或部分收购。
- L6 重试：同一笔交易重复提交不重复扣款。
- L7 赊账：生成债务，到期提醒，违约后果。

**时间与移动**
- T1 普通对话推进 5–20 分钟。
- T2 步行去白石镇约 6 小时，途中有天气与路况。
- T3 要求立刻到王都：拒绝瞬移，给出路线和天数。
- T4 夜里去店铺：打烊不开门，或者店主被吵醒后的反应。
- T5 睡到天亮：恢复，跨日结算。
- T6 冬季北境山口封闭。

**NPC 智能**
- N1 帮林穗修屋顶，三天后再来：态度变化，并提到具体的事。
- N2 任务完成后留下来聊天：不翻脸赶人。
- N3 不合理请求（借公共仓库钥匙）：拒绝、讲理由、指出该找谁。
- N4 请吴朔带路去废观测塔：两人一起移动，时长按路线，到达后义务完成。
- N5 托人送货：到期送到，或者有具体原因没送到。
- N6 屋内私密行为：屋外的人不知道。
- N7 在酒馆当众吹牛：第二天村口的人听说了一个走样的版本。
- N8 欺骗得手：几天后因线索被识破，NPC 态度改变。
- N9 推搡 NPC：对方还手或呼救，围观者议论，乡巡介入。
- N10 用"老板娘"称呼林穗：正确解析。
- N11 玩家违约：NPC 记得，下次要求预付。
- N12 三名 NPC 同场说话：去掉名字后盲测能分辨。
- N13 NPC 在谈话中提起自己的事，或因急事结束谈话。
- N14 NPC 撒谎：谎言写进日志，之后可以被揭穿。
- N15 未成年 NPC：任何恋爱方向的推进都被拒绝，并转为正常互动。
- N16 委托人知道任务进度，无关 NPC 不知道。
- N17 玩家离开 10 天：智能层 NPC 有自己的行动，回来时自然呈现。

**记忆**
- M1 200 回合后问起第 10 回合的约定。
- M2 摘要漏掉的事能被检索找回。
- M3 异体字、近义词、称呼检索（1.3 的四个例子全部命中）。
- M4 固定事实每回合可用。
- M5 聊天里的说法与账本冲突：以账本为准。
- M6 修改第 N 回合的玩家消息后，账本与之一致。
- M7 重生成不重复记账。
- M8 删除消息后回滚正确。
- M9 世界版本升级后，旧存档继续游玩，玩家状态与关系不丢失。

**魔法与成长**
- G1 施法扣魔力和材料。
- G2 魔力不足：施法失败，提示清楚。
- G3 施放没学过的法术：被拒。
- G4 向许苓学法术：付费、花时间、学习检定，学会后进入法术书。

- C4 首领第二次交手时换了打法。
- C5 用驱赶、谈判、陷阱解决冲突。

- S2 贡献度累积并在界面可见。
- S3 村民大会否决玩家提案。

- S6 偷窃被抓：审判与处罚。
- S7 同一件事在两个聚落的口碑不同。

**自由度**
- F1 开店：租铺、进货、定价、经营数日，有盈亏。
- F2 组织节庆：花费、参与、关系变化。
- F3 教村民识字：NPC 技能成长，灵智可能提升。

- F7 离开 30 天后回来：变化通过景象和人物呈现。

**语言与文风**
- V1 全程简体中文。
- V2 不出现元叙述用语。
- V3 不替玩家说话或做决定。
- V4 结尾不列选项。
- V5 系统提示只来自引擎。
- V6 陈词滥调命中率 ≤ 每千字 0.5 次。
- V7 NPC 台词里没有数值和游戏术语。

**通过标准**：账本、时间、存档类断言（L、T、M6–M9，以及各场景中的账本断言）必须 100%；NPC、魔法、战斗、社会、自由度类的评分细则每类 ≥ 90%；语言与文风类 ≥ 95%。

## 12. 沉浸体验与界面

目标：打开就像在玩一款游戏，界面上看到的每个数字都来自账本，界面上没有任何"这是 AI 聊天软件"的痕迹。

### 12.1 视觉风格

- **字体**（全部为 SIL 开源字体许可，打包到本地，不走外部 CDN）：正文用思源宋体或 Noto Serif SC；标题与 NPC 名牌用霞鹜文楷；系统提示与数字用思源黑体。
- **排版**：正文 17–18px，行高 1.85，段间距 0.9em；正文栏宽 720–760px，每行约 40 个汉字；中文标点不悬挂，避免行首出现标点。
- **配色**：用 CSS 变量定义一套深色主题（夜灯与旧木）和一套浅色主题（羊皮纸），由设置切换。16 级装备品质各有固定颜色，全局统一。
- **聊天样式**：使用酒馆的文档式聊天显示（在已安装版本中核实选项名称），叙事不显示头像气泡；对话由 12.2 的名牌显示说话人。
- **角色卡头像**：换成游戏标志或主持人纹章，不再用默认问号剪影。

### 12.2 消息渲染

- **叙述**：普通段落。
- **对话**：`<q who="…">` 渲染为"头像 + 名字 + 引文"，名字颜色按 NPC 固定；未登记的说话人显示为"路人"并进入待登记清单。
- **系统提示**：由引擎根据本回合事件生成，显示为消息下方的一组小卡片，带图标：等级提升、熟练度变化、获得或失去物品、钱的变化、任务与约定更新、关系明显变化（用文字描述，例如"林穗对你更放心了"，数值在人物面板里看）、世界公告。系统提示存放在消息的附加数据里，不写进消息正文。
- **隐藏**：工具调用消息、回合尾注默认隐藏；设置里有"调试模式"开关，打开后可以查看回执和原始数据。
- **信件与告示**：驿站信件、公告栏、合同以羊皮纸卡片样式显示，可以收进邮件面板。

### 12.3 顶栏

游戏内日期与时辰（"春历元年 雨月初三 申时"，带昼夜图标）、天气、地点路径（地区 › 镇 › 村 › 地点）、钱袋（按金、银、铜拆分显示）、生命与魔力条、状态效果图标、同行者头像、音量与静音。全部数据来自引擎，替换现在的"第N日 HH:MM"。

### 12.4 面板

侧边抽屉，标签页：

- **角色**：属性、等级与经验条、职业（含认证状态）、爵位与身份、各聚落贡献度、声望。
- **技能**：按职业分组，显示阶段与本阶进度、是否卡在突破前。
- **法术书**：已学法术，消耗、材料、效果、来源。
- **行囊**：格子背包，物品卡显示品质颜色、做工、耐久、重量、制作者；负重条。
- **人物**：见过的人，头像、身份、所在地（玩家所知的）、关系的文字描述与数值、共同经历要点、彼此的承诺、玩家记下的笔记。
- **任务与约定**：接受的任务、发布的任务（含额度）、义务（谁欠谁什么），按到期时间排序。
- **地图**：12.5。
- **领地**：拥有领地后出现：人口、库存、收支、建筑、工程、待批事项、管事报告。
- **编年史**：以游戏内的口吻记录玩家经历过的事，可搜索；代替现在显示 JSON 的检索框。
- **传闻**：听到过的消息，注明从谁那里听到、玩家的判断。

### 12.5 地图

- 由 `world/geo` 数据渲染成 SVG，分大陆、地区、郡、镇四级缩放。
- 战争迷雾：只显示亲历过的地方、可靠转述过的地方（淡色）、听说过的传闻地点（虚线）。
- 路线与路况、季节封闭、已标记的地点。
- 出行规划：选目的地后显示几条路线的耗时、花费和风险；点击后把"我打算经由……前往……"填进输入框，由玩家确认发送，不自动出发。

### 12.6 美术素材

- **风格设定**：先写一份统一的美术风格说明（画风、色调、光线、构图、服饰时代），所有素材按它生成。提示词里只写画面描述，不写"某某画家的风格"。
- **背景**：按地点类型 × 时段 × 天气准备约 80 张（村落白天、雨天村落、酒馆内景、铁匠铺、林道、山口、港口、集市、神殿、地下城入口……）。引擎根据场景自动切换并淡入淡出（在已安装版本中核实切换背景的接口或斜杠命令）。
- **人物头像**：LOD0 完整档人物逐个生成，提示词存进 NPC 数据，以后可以重画。未成年人物只用日常形象。
- **生成途径**：有足够显存时可用本地 ComfyUI，否则用酒馆图像生成扩展支持的云端服务，或者先用按职业区分的纹章图标代替头像，避免风格不一致的头像破坏沉浸。
- **许可清单**：`assets/LICENSES.md` 记录每个素材的来源和许可。

### 12.7 声音

- **环境音**：按生物群落、时段、天气、室内外播放循环（河水、集市人声、雨、风、林中鸟、炉火）。
- **音乐**：按情境切换（村镇白天、夜晚酒馆、野外、地下城、战斗），淡入淡出。
- 只用 CC0 或明确允许使用的音频，记入许可清单。
- 浏览器要求用户先有一次点击才能播放声音：在开始界面点"进入游戏"时启动音频。

### 12.8 语音

- 一张主持人卡扮演所有 NPC，酒馆自带的"按角色分配声音"不够用，需要在扩展里按 `<q who>` 拆分台词：旁白一个声音，每个 NPC 按数据里的 `tts_voice` 用各自的声音，没有分配的用同性别、同年龄段的默认声音。
- 选一个支持多种中文声音的服务。酒馆的语音扩展支持多种服务，其中包括 GPT-SoVITS、火山引擎和系统语音，在已安装版本中核实可用列表；也可以由服务器插件直接对接。音频按文本哈希缓存，可以跳过、重播、关闭。
- 这一项直接解决用户说过的"中文没有声音"。

### 12.9 输入与操作

- 自然语言输入，不需要斜杠命令。
- 输入框旁一排快捷按钮：观察四周、交谈、交易、休息、行囊、地图、场外。点击后把对应的开头填进输入框，由玩家补充后发送。
- "说"与"做"切换：选"说"时，输入自动包成玩家的台词。
- 少量快捷键（发送、打开背包、打开地图），可以在设置里关闭。保持简单，这是用户明确在意的点。

### 12.10 开场与续玩

- `play-town.html` 改成游戏开始界面：继续游戏、新游戏（进入角色创建）、存档管理（导出、导入、备份）、设置（字体大小、主题、音量、语音、调试模式）。
- 新游戏的开场白按角色创建的结果生成，保留现有开场里那些具体的细节：桥头卖热面包的人、停转的水轮、磨坊前排队的粮车、正在晾床单的林穗、门槛边那截裂开的木轴。
- 继续游戏时，用编年史生成一段游戏内口吻的"前情提要"，不出现元叙述。
- 加载时显示世界内的小知识（谚语、地方风俗、怪物习性），从世界数据随机取。

### 12.11 去掉出戏的东西

隐藏 token 计数、模型名、生成计时；保持滑动改写关闭；错误信息用游戏内能理解的话显示，技术细节进调试日志；调试模式以外不显示 JSON。

### 12.12 适配

手机竖屏可用：顶栏折叠成两行，面板全屏抽屉，地图可以双指缩放。提供字号调节、高对比度主题和"减少动画"选项。
