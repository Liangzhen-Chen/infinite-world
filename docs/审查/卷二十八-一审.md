### T1 审批记录的“内容指纹”按行计算，与卷十二的唯一定义不符；且绑定的是原始行，不是有效值
- 位置：§2.6 第 198 行（`contentPrint`）；R28-5.2 第 527 行；A28-5.2 第 553 行；C28-6 第 758 行。
- 证据：卷十二:1326 术语表定义“内容指纹 = 仓库外的门禁工具对要跑的**全部内容**算的指纹……全卷只用这一个词”；卷十二:940 R12-9.3 与 :1301 Q12-4 都是对一次提交/卡的整体内容。卷二十八要的是“对该行的数据与它在各已发布语言里的显示文字”算指纹，由仓库内 `tools/content/approve.mjs` 写记录——卷十二没有行级输入，也没有仓库内调用口。另一面：R28-5.3 的 `real_quantity`、R28-5.6 的 `caution_value` 读的是**展平与补丁之后的有效值**，而“行的数据”若指文件里的原始行，父类别行或别包补丁改了有效值时，原始行不变、指纹不变、旧批准不失效，`requiredTier` 却可能已升级——A28-5.2“只随该行数据……而变”与 R28-5.6 自相矛盾。

## 五、四个待李白定的开放问题（只分析后果，不替李白定）

### Q28-1 已有世界能否换包并延续
- 甲 不开放（本稿默认）：确定性最强——世界数据副本开局后不变，正合卷二十七:482“只写一次”，复演不需要旧副本，`rulesDigest` 终身不变；存档格式不动；统一底层上不需要卷二 §2.6 的例外（`terminate` 仍只由规则层提案调用），不需要换包复查登记点。代价：老世界加不了新内容，只能新开。
- 乙 开放完整换包（R28-6.6）：确定性可以守住，但要：副本切换成为入日志的事件，旧副本多版本保留以供复演，提交强制快照，`dataDigest` 在世界中途改变；存档格式多一节、doc_data 不再只写一次（C28-5 的全部内容）；统一底层上开内核直接调 `terminate` 的口子，新增一类登记点。且按 T4，现设计在物品、库存、账户、残骸处必然失败，开放前须先补。
- 丙 只开放“只增不删”的换包（加包、换版时不移除行）：无终止、无占用检查（第 ③④⑤ 步为空），没有 T4 的缺口；仍需副本切换、旧副本保留与“改动”行的复查（C5 一类）。是甲、乙之间的折中。
- 建议：首版取甲；若产品确要老世界加内容，取丙；乙须先修 T4 再议。

### Q28-2 包能否用补丁改全局规则表键
- 允许（本稿）：确定性无损（加载期一次求值，先后由包序给定）；存档无影响（值冻进副本，旧世界不变）；统一底层上同一个键可能有多处“整值来源”，靠 R28-3.5 先后规则约束，硬下限键靠自身校验。风险是一个包可改全局手感，使别包的平衡前提失效且无从察觉。
- 禁止：标定值只有本体一个来源，最纯；“难度/手感”类包做不了，只能改核心。
- 折中：规则表登记的结构描述加一个布尔“可由包覆写”，默认假，由键的归属卷逐键声明（数据声明，不在本卷点名键）；补丁只许打到声明为真的键。
- 建议：折中。它与 T3 的“多来源合并”是同一处登记，一次定两件事。

### Q28-3 包能否停用或移除本体与别包的行
- 不许（本稿）：确定性、存档都无影响；与台账 X-39“补丁只产生偏离行，不得引入新的覆盖语义”一致。代价：总转换类包做不了（本体恒在首位，R28-1.1）。
- 新增“停用”操作：加载期把行从合并结果拿掉，引用它的行随即 E-DIM-REF-MISSING，作者要把引用链一并停用；已有世界不受影响（副本冻结）。但这是新的覆盖语义，须改台账 X-39 与卷二 §1.3 覆盖顺序。
- 走数据维度：由归属卷给需要的表登记一个“可用性”类存储维度（生成器、开局、交易等读它），包用普通 `set` 补丁关掉；不新增语义，符合统一底层。
- 建议：维持不许删除；若产品需要，用“可用性维度 + set 补丁”，不加新操作。

### Q28-4 第三方包入库是否强制模型审与人工审
- 不强制（本稿）：确定性、存档无关；统一底层上流水线对本体与第三方一视同仁，区别只在“过哪道门”（R28-5.11），没有按包身份分支。风险：第三方叙述文字只经屏蔽词机判，质量与事实正确性无人把关；世界内能否引用受限对象仍由第 ⑦ 步 E-RESPECT-TIER 拦。
- 强制：玩家本地多半没有模型额度与独立审查人，第三方包实际装不进，扩展生态停摆；若要求包随附审批记录，记录须随包分发（现定在 `tools/content/`，§2.6 第 192 行），并要定信任来源。
- 折中：不强制；库写者读包随附的审批记录（若有）只用于显示层标示“已审到哪一级”，规则与流水线不读。
- 建议：不强制或折中；任何方案都不得让规则层或流水线读审批状态（S28-2）。
