# 卷十九 areaM2 行种类核查（11-13）

核查对象是李白的裁定：卷五 `created.*.props.areaM2` 的改写登记，行范围只写 `inside: [comp_facility]`。这个写法成立的前提是：建筑之内凡带 `areaM2` 的行，只有 `comp_zone` 一种。
核查范围是 `F:/dnd/docs/统一底层设计/卷*.md` 的正文，不含版本快照、审查和素材包。只用了 Read 和 Grep，没有改任何卷的正文。

## 结论：除 comp_zone 外，还有别种行（需报李白）

正文写明，`comp_facility` 行（地窖、矿井巷道这类建筑实例）可以挂在地面建筑行之下。这种行带 `areaM2`，而 `inside: [comp_facility]` 会把它们和它们的房间一起圈进 `construction.mjs` 的改写范围。卷五第 264 行括注说这个写法"恰好只圈建筑之内的行，即房间行"，与正文不符。**需报李白**。按裁定，我不擅自扩名单，也不擅自收窄名单。

## 依据（file:line）

**一、带不带 areaM2**
- 卷五-地点地形与资源场.md:90：`areaM2` 的必填是 `always`。所以凡是 place 行都带 `areaM2`，问题只剩"哪些种类的行能落在 `comp_facility` 行之内"。

**二、能落在 comp_facility 之内的行种类**

| 行种类 | 能否落在建筑之内 | 依据 |
|---|---|---|

| `comp_facility`（地窖、矿井巷道等建筑实例） | **能** | 卷五:501"矿井、地窖是带围护的建筑实例"；卷二十-时间日历天气与环境.md:790"地下的围合空间（地窖、巷道）即使挂在地面建筑之下"；卷五:484 把地窖与巷道列为"围合、在地下"一类（房间没有自己的围护，只取建筑的值，卷十九:315） |

**三、受影响的现行措辞**
- 卷五:264 括注说"只写它恰好只圈建筑之内的行，即房间行"。有地窖这类嵌套建筑行时，这句话不成立。
- 卷五:142、245、248 和卷十九:501、772 都写成"建筑之内的房间行"或"即建筑之内的行"，同样的口径落差也在这几处。
- 实际后果：嵌套建筑行（地窖）的 `areaM2`、它下面房间的 `areaM2`，都会被登记成 `construction.mjs` 可改写，因此不再是静态维度（卷二十按卷五:243 的声明判定静态量）。外层建筑原地翻修时，写权上并不拦着它去写里层建筑的面积；现在只靠 A19-10.2 的调用点计数来约束。

**可选的修法（供李白裁定，本次不动）**：
- ① 行范围写成 `inside: [comp_facility]` 再加上"`comp_zone` 且父行是 `comp_facility`"一类的合取条件。这要求卷二 `rewriteRows` 支持合取，目前它是"任一满足"。
- ② 正文明令禁止建筑行挂在建筑行之下，把地窖改成 `comp_zone` 加地下房间。但房间没有自己的围护，地窖要有围护，所以这条路要改卷五 §4.5 和卷二十:790。
- ③ 接受嵌套建筑行在范围内，把卷五:264 的括注改成如实描述。
