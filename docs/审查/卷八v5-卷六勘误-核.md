### P1 执业“恒一致”不成立（类别 4、7；须李白定）

- 位置：卷八 :1093 “执业派生的职业是集合、不作分组键，没有可与之冲突的键值，执业边恒为一致”。
- 证据：
  1. 卷二十七 :144 字段表给 `keyHoldings` 的定义是“**由分组键表达**、不构成钉住的持有种类”。R27-2.3 第 2 项（:331）的“与分组键一致”是在这个定义下的判断：边的内容要由某一维键值表达，才谈得上一致。职业不在任何分组键里，执业边不被任何键表达，按 :144 不该列入；作者的“没有可冲突的键所以恒一致”是空真推理，照此任何种类只要不对应键都可列入 `keyHoldings`，`keyHoldings` 就退化成任意豁免清单。
  2. 作者称“照示例 1 的写法”，但卷二十七示例 1（:361）是 `keyDims` = 物种、**职业**，`keyHoldings` = **居住类**——职业是作为分组键表达的，执业并不在 `keyHoldings` 里。示例只支持居住一项的列法。
  3. 卷十四 :519 改 `pins` 的目的写的是“卷八居民聚合体才能**按职业分组**”，与本卷“职业不作键、执业恒一致”的做法也对不上。
  4. 后果：执业边带个人历史（卷十四 :574 `terms.since`、`terms.origin`），有执业边的人照样折叠，统计层职业构成仍报未知（:1105），等于把个人状态挂在“无个人历史”的成员身上。
- 选项（属结构或已封卷，超出只改列出项）：甲 执业移出 `keyHoldings`（从业者被钉住，写进 §8 并告知卷十四 :519 目的不成立）；乙 职业作分组键（卷二 :1394 它是 `set<ref>`，须先定集合型能否作键，卷二十七 :143 只许枚举型或引用型）；丙 卷二十七 :144/R27-2.3 补“不对应任何键的种类视为一致”（改已封卷，且须说明为何不违背“由分组键表达”）。

### P2 信仰作分组键，但实体化后成员的信仰为空（类别 4、7；新矛盾，须李白定）

- 位置：卷八 :1093（信仰键“经信奉边派生”）、R8-16.2 :1107 末句、:1105。
- 证据：卷二 :1393 个体 `faith` 是 `derived ref faith nullable（经持有 devotee_of）`，卷七 R7-1.4（:445）“没有信奉边则为空”。卷二十七 R27-2.2（:326）在实体化时只按分组键**重算写入型维度**（如 `culture`），R27-2.6（:343）“实体化只建立基本行”——没有任何一处在实体化时按信仰键开信奉边。于是：从未实体化过的成员、以及经改宗流改记的成员（R8-16.2 关掉旧信奉边、不开新边），实体化后 `faithOf` 为空，而 `popView().byFaith` 聚合部分仍按键计为某信仰（:1105）。同一个人，卷八说他信 X、卷七说他无信仰；单元进入个体层时卷七的信众作用域（`believers`）、祭仪、虔诚全部按无信仰处理。A8-16.2 要求的层间信仰构成一致（:1132）在个体层读边时不成立。
- 这是 R1 把派生维度放进 `keyDims` 后才出现的；文化没有这个问题，是因为它是写入型维度（卷二 :1392）。
- 方向（须李白定）：甲 卷二十七 R27-2.2/R27-2.6 补一句“分组键里经 `keyHoldings` 种类派生的维度，实体化时按键值开该种边”（改已封卷）；乙 信仰退出分组键、改宗流回到只在个体层生效（即二审 R1 的后一选项）。
