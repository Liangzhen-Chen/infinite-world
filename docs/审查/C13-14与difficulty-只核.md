## 二、deed_role 停下（核实）

属实：

1. 卷十四表 B（:328）与 `deed_role`（:202）只认 `actor`/`target`/`beneficiary`；HO-1（:950）只写"主体按 `role` 取事件的对应一方"。
2. 四类事件的载荷字段代号是 `subject`、`by`、`winner`、`sides`，没有 `actor`/`target`；这些字段也都不在表 B，事迹过滤式读不到。
3. 卷十三全卷没有写这四类事件记录的 `actor`、`targets` 填什么；卷九 `emit`（:573）只带 `verb`、`visibility`，卷九全卷无 `targets` 的取法。所以事迹按 role 取不到主体。

主会话改法评估（由卷十三在各事件处写明 `actor`、`targets` 各取哪个载荷字段）：

- **只用已有结构**：是。`actor`、`targets` 是卷一 §2.8 / 卷二十四表 A（:136、:138）已有的事件记录列；不新增枚举、不新增栏。措辞更正：这两列是 nullable/`gap`，不是"必填列"，指令里写"已有列"即可。
- **能让事迹取到主体**：能。卷二十四表 B `payloadShape` 说明（:162）固定映射 `actor`→actor、`targets`→target，与 `deed_role` 的 actor、target 同名对应；`beneficiary` 这四类不用。
- **与卷二十四 :162 一致**：一致。
- 须一并写明的牵连（不加结构，只需说明）：
  - 卷十四表 B 的 `target` 是单个 EntityId，事件记录 `targets` 是列表；HO-1 宜补一句"role 为 target 时对 `targets` 中每个 id 各计一次"（卷十四一句，或主会话认定由 :162 映射已覆盖）。
  - `targets` 填上后，`headSlot` 为 null 的这几行动词按 R24-2.4 的 `heads`、R24-4.3 催化、R24-8.2 `mentions` 会随之计入这些人。这是对的方向，但卷十三这四行动词的 `headSlot`、`tallies` 应顺带核一遍，以免与载荷里的人数字段重复计。
  - `winner` 的类型在卷十三未写（R13-19.1 快照里也只写 `winner nullable`），是方序号还是实体 id 不清；决斗的 `actor` 要由它取，须同处写明。

建议逐事件对应：

| 事件 | `actor` | `targets` |
|---|---|---|
| R13-1.11 伤害结算 | `by`（出手者） | `[subject]`（受击者） |
| R13-17.5 决斗结果 | 胜方成员（`winner` 所指那一方；该方只有一人时取其 id；无胜方或胜方多人时为 null） | 其余各方成员（发事件的同一事务读遭遇记录 `sides[].members`，按 id 序去重） |
| R13-18.6 制服与就擒 | `by`（收俘者） | `[subject]`（被制服者） |
| R13-18.8 遭遇结束 | null | 各方 `members` 的并集（即载荷 `sides[].members`，按 id 序去重） |

遭遇结束事件只能数"参战"，数不了"胜负"（表 B 没有胜方字段）；要数胜仗，得给表 B 增字段，那是机制变更，不在这次改法内。
