## 四、新矛盾（改动带出；新真问题，需报李白）

### N1 亲子条目标为史实，聚合入口却仍指向持有边（类别 5）——新真问题，需报李白
- 位置：157 行 `rel_parent`：`"persistence": "historical"`，但 `"via": "holdings.byRel", "inputs": ["holdings.*.*"]`。对照 159 行 `rel_wed`（同为史实）用的是 `relationFacts.byRel`、`relationFacts.*`。
- 证据：364 行规定史实记录存在 `state.relationFacts`，"不是持有边"。卷二 §1.12 的聚合原语按 `via` 取数，亲子关系经它聚合时会到持有边里找，结果为空；依赖闭包 `inputs` 也指错路径。
- 建议：`rel_parent` 的 `via`、`inputs` 改为与 `rel_wed` 相同；加载期校验 `persistence` 为史实的条目 `via` 必须指向 `relationFacts`。

### N2 加载检查 C6 会拒收合法的存档（类别 5）——新真问题，需报李白
- 位置：914 行 C6、233 行 E-REL-MINOR-LOAD 对照 897 行不变量、920 行"中止"、901 行 ②。
- 证据：不变量只约束"现役且未中止"的受检关系；C4、C5、C9 会合法地产生中止的边（例如 952 行：已婚者被变回幼年形态，婚姻边转中止）。但 C6、E-REL-MINOR-LOAD 的条件是"有受检关系的任一端 `intimateEligible` 不为真"即整份拒载，没有排除中止的边，也没有排除史实记录——婚史记录 `rel_wed` 的 `marital` 为真（159 行），按 ② 属受检，而史实记录"不受中止影响"（920 行）。所以这样的存档保存后再读就被拒载。
- 建议：C6 与 E-REL-MINOR-LOAD 的条件改为与 897 行不变量同口径：只查现役且未中止的边；史实记录只在建立时（C1）检查，加载时不复查当前年龄。

### N3 动作的 `intimate` 字段出现两个存放处（类别 5）——新真问题，需报李白
- 位置：1072 行规定 `intimate` 是"动作目录条目自身的必填字段"（归卷九，见 1168）；1100 行数据实例却在本卷社交规则块里放了 `"actionCatalogIntimate": {"act_example_chat": false, ...}`，以动作 id 为键另存一份；§2.4 规则表（175–205）也没有这个键。
- 证据：同一个判定输入有两处来源，C2 与 E-REL-INTIMATE-FIELD 读哪一份不明，违背"一个字段一个写者"（3 行模板头⑤）。
- 建议：删掉 1100 行这一键；示例改为写在动作目录条目上（注明是卷九的数据），或只在文字里说明三个动作条目的 `intimate` 取值。
