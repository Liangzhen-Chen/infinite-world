## 二、作者自报偏离：R8b-1.16 同样适用于目录表法典根

判断：**接受，不算越权，不与已封卷冲突**，但须报李白知悉。
- 不冲突"目录行不可终止"：卷八 L203/L477 的"不可终止"说的是职位表、政体表不走终止协议；law_code 目录行在这里也没有被终止，只是在 `state.repeals` 记一条废止。对表行记废止在第二版 R8b-1.11 已允许（"表行与运行期条目同一写法"），1.16 没有新开写法。触发者是组织（可终止实体类），合卷二 §2.6。
- 不碰已封卷：改动只在卷八b；卷二 §5.20、卷八无相反规定（卷八未写法典承继）。
- 为什么必须同样适用：若只对运行期根废止，就是按来源分支，违反 §2.2"别处不按 src 分头"与统一底层原则；且理由③（死政权的法典挡住栈后法典、受理执行永远求不到 hasPower）对目录表根同样成立。
- 行为影响（报李白）：开局目录里的某国法典，在该国组织终止时随之出栈；后继要沿用须 `enactLaw` 重立。这是裁定(1)"政权灭亡去向"的自然覆盖，属行为口径扩大，不是新机制。

## 三、卷五 L748 引 R8b-7.2 能否打破环

能。卷五 §4.9 规则 2（L736）控制度目标读治安值，写法是"每日向目标靠拢 `control += …`"；R8b-7.2（L794，本版未改）规定治安值的 `C` 读 `control` 当前存储值，并写明"每日结算先由控制度目标读治安值、后写 `control`"。同一地点内是先读后写的固定求值序，无代数环，不需滞后常数。附注（非问题）：当日 `control` 写入之后别处再读治安值，读到的是当日新值；次序固定，仍确定。

## 五、改动引出的新真问题

**N1（中）废止法典根后，其下条目挂的修正项不撤。** R8b-1.16 让"法典根被废止"从罕见的手动操作变成每次政权终止都发生的路径。但 R8b-1.11 只在"条目失效（到 `untilDay` 或被废止）"时按来源撤修正项，A8b-1.2 也只按"该条目生效期"判；条目的生效期（R8b-1.5、`provisionView`）只取条目自身的 `untilDay` 与条目自己的 `state.repeals`，不计其法典根的废止日。后果：已灭亡政权立的宵禁、禁运、隔离令等措施条目（`untilDay` 空的）在其法典根出栈后仍永久挂着修正项，且承办组织已终止，无人能 `repealLaw` 撤掉。需在 `provisionView` 一处写明：条目的生效止日再取其 `book` 所指法典根的废止日中较早者，使 R8b-1.11 的撤下与 A8b-1.2 自动覆盖（一处定义，不在 1.16 里另写撤除）。

**N2（小）Q19 牵连清单不全。** 卷二 §5.20（L1626）`analogyOf` 仍登记 `ref law_code`，且卷二 §5.20 没有 `book` 行；卷八b 现写 `lawRef`（struct）。目录数据只许 `lawsrc_table`，语义上等价，但目录 JSON 里 `book`/`analogyOf` 写的是裸 id 还是 `{src, id}` 未定。按"跨卷裁定附牵连清单一次改清"，Q19 应补列卷二 §5.20 这一项并写明目录数据的写法（如：目录里写裸 id，加载时一律解析为 `{src: lawsrc_table, id}`），随 Q19 一并待定。
