## 二、真问题

### N1 §2.8 的适用范围没有内核边界，规则按字面执行会把必需代码全判违例（L439–443、L209、L240、L243、L1259 (b)(c)、L1258 ①②）
- §2.8 L439 把"规则层"定义为五个模块组之外的全部 server-plugin 代码，L443 规定对 string 的一切操作（含 `.length`、`+` 拼接、模板插值、非句柄字串作 Map 键或对象键）都是 E-VIEW-TEXT-MATCH。S13 的两条豁免只有 (b)（三个文件里的代号格式正则）与 (c)（注释、`console.*`、`throw new Error` 文案）。
- 但这个范围内有一批无法避免的字串操作：
  - 实体 id 是运行时才产生的字串（`npc_…`、生成地点），`kindOf(id)` 查 `idIndex`（L209）、`state.npcs[id]` 一类按 id 取值，都是以非句柄字串为键的查表；句柄 `V.<族名>.<id>` 只覆盖词表条目，覆盖不了实体 id。
  - 种子键拼接 `template.seed + "|" + kind + "|" + instanceId + "|" + dimension`（L240）与 `seedKey + "|" + i`（L243）是 `+` 拼接。
  - 修正键 `"facility_type.upkeepPerDay[class_fuel]"`（§3.1/§3.2）与声明节点名 `"view:placeView"`（§2.3）需要解析与注册表查表。
  - 校验器、加载器的报错输出与路径拼接。
- 按 L443 这些全是违例，S13 的目标"规则层 0"无法达到，也就是验收条款无法执行。
- 改法：在 §2.8 明确三类：① **不透明代号**——类型为 `ref:<kind>` 的实体 id（`pathTypes`/Fact 声明为 ref 者）允许作相等比较、Map 键、对象键、原样传递，不允许任何字串方法（它是标识，不是文字）；② **内核组**——kernelApi 所在文件加存储层（L406）单列为第六组"内核"，闭集只列种子键拼接、修正键解析、注册表查表这几个登记函数；③ 其余规则层照 L439–443。并把 L209、L240、L243 涉及的函数名登记进该闭集。

### N2 `matchBlocklist` 的坐标系与多命中没有定义（L425、L426、L453）
- L425：`matchBlocklist(text, lang) → {hit, start, end}`，先 NFC、再大小写折叠、再 `indexOf`，所以 `start/end` 是**规范化后字串**里的位置。L453：outputGate 按 `{start,end}` 用替换记号 `slice` 两端拼接，没说切哪个字串。NFC 会改变字串长度（如分解形式的 é），若切原文，位置错位，会漏掉或截坏文字；若切规范化文字，则显示文字被改写成规范化形态，原文丢失，也要明说。
- 只返回第一个命中。一段文字含两处屏蔽词时，只替换一处，另一处漏过。没有规定循环到无命中，也没有规定替换记号本身含屏蔽词时的终止条件。
- 这是闸的核心行为，两个实现会产出不同字串，属于不确定性。
- 改法：规定 `matchBlocklist` 返回命中列表（`[{start,end}]`，按 start 升序、重叠合并），坐标定义在"规范化文本"上，outputGate 的替换对象明确为规范化文本（或返回原文到规范化文本的映射表）；并加夹具断言（两处命中、重叠命中、组合字符各一）。

### N3 aiGate 的"id 泄漏检查"没有合法实现（L427、L454、L1266）
- L427 与 S19 L1266：aiGate 的 id 泄漏检查"按代号格式判定（§1.9 正则），不拿 labels 去匹配"。但 §2.8 L454 给 aiGate 的闭集只有：调用 `matchBlocklist`、`.length` 比较、码点范围表（`codePointAt`，仅 `charset.mjs`）、schema 校验器调用，没有正则，也没有子串查找；L416 还特地规定"字符集按码点范围表判定而非正则"。
- 在自由文本里找"形似 id 的片段"本质是模式搜索，既不属于上述闭集，也与"禁正则"冲突；若改用 `indexOf` 查全部实体 id 作 needle，则与"needle 只能取自 blocklist"（L419）冲突。
- 改法：要么把 id 泄漏检查从 aiGate 移出（由 schema 保证 AI 输出的字段本来就不含 id，自由文本字段由 `pathTypes` 限制为 textPaths 并整体不参与规则），要么在 L454 为 aiGate 闭集增加一项"id 形态扫描"并给出不用正则的确定性定义（如按码点类别扫描 `[a-z0-9_]` 连续段，长度与前缀表比对）。

### N4 "逐码元"与 CaseFolding 的码点映射不一致（L220、L450、L1281）
- CaseFolding.txt 的 C、S 条目是**码点**到码点的映射。L220 与 L450 写"按 casefold 表逐码元映射"，L220 又写"逐码元相等"。JS 字串的码元是 UTF-16 单元，补充平面字符（如 Deseret 字母 U+10400）是两个码元的代理对；若按码元映射，这些字符不会被折叠，两种实现（按码点与按码元）对同一输入一个命中、一个退回菜单，破坏 zh/en 结果集同构（B10(h)）。White_Space 裁剪同理按码点。
- 改法：把 L220、L450、B10(a) 的"逐码元"统一改成"逐码点"，并在 `casefold.json` 的说明里写明映射与比较按码点（`for…of` 迭代）。

### N5 组件类条目放在 `class` 族里，前缀却是 `comp_`，与族前缀登记矛盾（L200、L208、L1349、L1356–1357）
- L208 把 `class→class_` 与 `component→comp_` 登记为两个独立族；L200 却说"`class` 族条目带 `table/requires/enables` 即为组件类，前缀 `comp_`"；附录 A L1348–1357 的 `_vocab` 片段把 `comp_service_host`、`comp_facility` 放在 `class` 族，而该族前缀写的是 `class_`。按 L204 的前缀规则（条目 id 须以族前缀开头），这两条会被报 E-DIM-VOCAB-PREFIX；D.2 脚本第 7 项只检查 `table`/`requires`，不检查条目前缀，所以"PASS"并不能证明这一点。
- 改法：二选一——组件类放进独立的 `component` 族（前缀 `comp_`，L208 已登记），`classes` 数组可引用两族（用 `refs`），并改附录 A 片段；或取消 `component` 族，规定 `class` 族允许两个前缀。建议前者。

## 六、结论

真问题 5 条（N1–N5）：N1 是规则边界问题，须在 §2.8 写出内核与不透明代号的例外后才能验收；N2、N3 是闸的行为定义不全；N4 是一字之差但会影响 zh/en 对等；N5 是词表族前缀自相矛盾。五审 T1–T6 全部解决。按约定存在真问题，故判"有条件通过"；N1–N5 改完后只需核对 §2.8、§2.7 权限表、§1.9 第 3 条与附录 A 的 `_vocab` 片段，无需再整轮审。
