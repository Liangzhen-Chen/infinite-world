1. 强转豁免文件表（十一审B Q1）
   去掉“全书唯一强转”的说法，改为一张精确的豁免文件表，逐个文件列出：
   - textcore/brand.mjs：RawText → Text
   - kernel/handles 中的构造函数：string → Handle / EntityId 等各类键
   - 各登记加载器的 narrow：unknown → SchemaOut
   表外的任何强转一律违例，检查器按文件路径判定。
   另外，RawText 要登记在类型表里。

2. 全局白名单写成闭集（十一审B Q2；十一审A V4）
   - 白名单里不得出现“等”字。
   - 明确禁止：eval、Function、new Function、动态 import()、with。
   - TextEncoder、TextDecoder、Buffer 只许 textcore 使用，用于 Sealed 的编解码。
   - console 只许登记过的 report 模块使用，其余一律不得直接调用。

3. 出口表覆盖全部对外输出（十一审B Q3）
   出口表要列全以下各项：存档写盘（kernel/save）、日志与控制台（report 模块）、HTTP 响应、DOM、AI 请求。
   aiGate 的收与发登记为同一个模块，或登记为一对“入口 + 出口”，并注明二者配对。

4. 凭证由 kernel 签发（十一审A V1）
   kernelApi 增加 issueCredential(scope)，只有 aiGate 可以调用（按 import 矩阵）。aiGate 不得自己签发凭证。

5. 显示前屏蔽有类型保证（十一审A V2）
   gate 筛查后产出 Screened<Text>，display 和 outputGate 的 release 只接收 Screened<Text>。
   这样，没经过筛查的文字在类型上就到不了出口。

6. 起名流程闭合（十一审A V3）
   完整流程：
   1) 规则层发出命名槽请求 {targetId, slotCode}；
   2) inputEdge 收到玩家输入，取得 RawText；
   3) gate 用 blocklist 筛查，命中就退回菜单；
   4) aiGate 调用 writeText(targetId 的 displayNames 路径, seal(Text))，带上 kernel 签发的凭证；
   5) 规则层只看到“已命名”标记或句柄，看不到 Text。
   时机：在命名菜单动作结算之内、提交之前完成。admitName 要带 targetId 参数。
