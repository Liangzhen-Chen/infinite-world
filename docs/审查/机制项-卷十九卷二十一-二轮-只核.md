## 1 R21-8.2 诊断命题（第一轮真问题 1）

改动：`subject` 改为目标实例所挂的主体；`dimKey` 改为新起的派生维度 `statusRow`，按实例 id 加下标写作 `statusRow[实例id]`；§5.3 卷二行请卷二在"主体所在实体表"登记这个维度。

**必要性：确有必要，现有维度都不能用。**
- 卷二十二要求 `subject` 是实体，`dimKey` 是维度代号（:134 `fclass.dimKeys: set<维度代号>`；:135；A22-1.3）。状态实例的 id 是 EventId，不是 `EntityId<K>`（卷二 :687 列的是 22 类 kind 加 effect、note），所以 `subject` 只能是挂实例的实体。
- 挂实例的实体上，没有哪个已登记维度能表达"这个实例是哪一行"：
  - `struct:statusInstance.status` 是 state 结构里的字段，不是维度（卷二 :306）。
  - `statusView` 只出实例、档和修正集合（卷二 :391），没有维度。
  - 卷二十一已有的派生量 `chronic` 是实例视图上的字段；`needRecover`、`crowding` 两个维度与此无关。
- 维度必须带"哪个实例"这个下标。不带的话，同一主体身上两个实例的认定会落到同一个 factKey `(claim, subject, dimKey)` 上（卷二十二 :169）。
- 派生维度还能顺带让 `claimHolds` 有一个真值可读（R22-4.4）。

因此这是必要的新设计，不算多余。但这是修改轮里新加的一个派生维度，其键类型又依赖第一轮已列为须报李白的 `EventId` 登记，须报李白（见 §6）。

**下标写法：不合卷二十二口径（真问题 1）。**
- 卷二十二全书的 `dimKey`、`fclass.dimKeys`、检索键 `dims` 都写作"维度代号"（:134、:135、:302、:315、:971），唯一的命题示例也是裸维度名 `material`（:342）。卷二十二没有任何地方接受 `<kind>.<dimension>[<key>]` 这种带下标的写法，也没说 `fclass.dimKeys`、`dims` 遇到带下标的 dimKey 时按什么匹配。全书其他卷也没有带下标 dimKey 的先例（已 Grep）。
- R21-8.2 写的是"照卷二十二 A22-1.3"，又借卷二 `DimKey` 的文法（卷二 :687、:1127）来支撑下标写法，但卷二十二并没有采纳这个文法。
- 勘误表这一行把卷二十二只列为"读者"，没有向卷二十二提出请求，牵连漏了。
- 须做的事：请卷二十二写明，命题的 `dimKey` 可以带卷二 `DimKey` 的 `[<key>]` 下标，并写明 `fclass.dimKeys`、`dims` 按去掉下标后的维度代号匹配；同时在卷二十一 §5.3 加一行卷二十二请求，并在勘误表的读者栏里列出。卷二十二若不接受，就得另定取法。
