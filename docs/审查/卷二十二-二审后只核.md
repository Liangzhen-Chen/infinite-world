## 二、新真问题

**X1 释放条件只看足迹，漏了 R27-2.4 其余钉住条件（类 5，N2 未堵全）**。R22-5.7 :473 释放条件为"有效层非个体层＋足迹（除本卷两文件路径）为空＋无秘传边"。卷二十七 R27-2.4（:337）`pinned` 还因"没有成员身份"（`pin_identity`，:329 世界数据手写个体恒钉住）、"玩家控制"而为真。这类人满足本卷条件会被释放，但永不折叠：投影已覆盖的条目删掉尚可经先验域补回；未覆盖的条目"给他所属聚合体加一人份"——他没有聚合体，并入对象无定义，删除后变回不知，违反 A22-1.2（:335）。改法（局部）：条件改为"释放后按 R27-2.4 `pinned` 为假"（含成员身份、非玩家控制），否则整人不释放。

**X2 `shift_ref` 写入的仍是 EntityId；释放条件的排除范围把它漏看（类 4/5，N1 遗漏，情形 (c) 未堵）**。R22-4.2 :429 `shift_ref` 把事件角色或命题取值"换成同一父级里另一个"个体，落在听者版本的 `overrides`（§2.3 :168 未覆盖 `overrides`），即别人名下以 EntityId 指向第三人。R22-5.7 条件"足迹除去本卷 knowing.mjs、lore-holding.mjs 所写路径"按文字连**别人名下**的 knowing.mjs 路径一起除去，于是该第三人通过条件、被释放，释放后足迹仍含此引用，`pinned` 为真不折叠，物化且变回不知。改法（局部）：`shift_ref` 换人后存听者所认之键（照 R22-1.5，`keys` 同步）；排除范围限"他本人名下"的路径。

**X3 `state.projects` 仍以 EntityId 指人，与 §2.3 新宣称"本卷容器不以 EntityId 指个体"矛盾（类 4，N1 遗漏）**。:175 `lead`、`members`、`target.subject` 均为 EntityId。`target.subject`（谋划对象、研究 `fact` 类的对象）可换键而未换，使被谋划者一直钉住；`lead`、`members` 设计上要钉住（矩阵"成员不折叠"），属"换不成键的类别"，按裁定须照③给上界并**停报李白**，现文既没写上界也没停报。

**X4 读入口签名未随 N1 改（类 4）**。:246 `linkKnown` 返回仍写"Fact（个体 id 或未知）"，与 R22-1.5（:313）"返回所信的本名键与闭包；要个体时读时解析"相反；卷八b 填被告读它。`beliefOf(holder, subject, dimKey)`（:249）与 `knowsFact` 的命题事实键，个体 `subject` 形参如何换成持有者所认之键没写（只给了 `recallFacts` :312、`publicShare` :476 两处）。改法（局部）：照 R22-1.4 同式补"个体形参先换成 `identify(h, ·)` 及其 `sameBearer` 闭包"，并改 :246 返回形状。

**X5 读时解析依赖本名键在折叠后再实体化时不变，无出处（类 4，跨卷，须停报）**。键冲突有定义：卷四:816 `keyId` 全世界唯一、键挂在单一个体名下，解析至多一人，成立；不在场解析为空，R22-1.5、R22-4.4 已写。但统计层成员折叠后再实体化（R27-2.2 同 id 同属性）时，卷四 K-1（:825）只说"实例化时得到恰一个本名键"，卷二十七、卷四都没把 `identities.*` 写成可由成员身份重算、`keyId` 怎样确定性重取。若重取不同，`heir`、`keyBearer` 取值、`source` 中存的旧键再也解析不到此人，N1 的"读时解析到当前物化实体"对折叠过的人失效。属卷四／卷二十七口径，本卷不能自定，须停报。

**X6 R22-10.8 的删除口径悬空（类 4）**。:675"删除快照与死者名下未被引用（R22-5.7 的引用口径）的条目"——R22-5.7 改后只有整人口径（"直接引用的人照足迹钉住"），不再定义条目级"被引用"。改法：直接写出哪些条目算被引用（在办案件指控、证人所涉事实等），或删去括注。

**X7 R22-6.6 对卷三乙 `contentRef` 下窄定义，与卷三乙封卷勘误 K2 冲突（类 4，对齐⑥）**。R22-6.6（:512，本轮改过的行）仍写"卷三乙的 `contentRef` 只指文字作品的显示内容，不承载事实"；卷三乙:2841（K2）已删去这半句，理由是 `contentRef` 含义归卷二十三、别卷不得另下更窄定义。改法：只留"不承载事实"。
