## 逐问

1. **五个文件的位置与 import 方向。** 位置对：K6-82 列了五个文件，卷二 :579 的 outputGate 组覆盖它们。不对的是 import 方向。卷二 §2.7 矩阵 :809 写 outputGate 对 kernel 是“只经 kernelApi”，S19 :2438 写“跨组 import 的名字不在 kernelApi 或 groupApi 里 = 0”。五个文件却 import 了 `kernel/errors.mjs#KernelError`、`kernel/error-codes.mjs#REGISTERED_CODES`、`kernel/handles/vocab-handle.mjs#CODE_RE`、`kernel/handles/markers.mjs#T`，这四个都不在 kernelApi :587–:658 里（display-load.mjs:9–12、envelope-exit.mjs:9–12、reply-composer.mjs:11、select.mjs:7、templates.mjs:8）。另外，卷二 :869 规定代号正则只在 `kernel/handles/*` 等处，:876 规定 outputGate 的字串运算闭集，可 outputGate 组内用了 `CODE_RE.test` 去解析代号（display-load.mjs:43、:48、:53、:61，envelope-exit.mjs:50）。门禁没报，是因为 api-callers 只核 params.entries 里列出的入口，并不是这样写被允许。

   回落链对：templates.mjs 的 `labelText` 按“有该形态用该形态 → 用 label → 用代号本身”回落，照卷二十九 R29-1.6 :499。但 reply-composer.mjs:40 只取了 `.text`，丢掉了 `untranslated`，renderTpl 返回的 untranslated 也没有进行。R29-1.6 ③ 要求节点带“未译”类名代号，见必须改 5。

2. **reply-channel.mjs 的位置与 serve。** 位置照卷文，不归 6-19：卷二 :945 原句是回应通道本身就是 `kernel/transport/reply-channel.mjs`，通路表 :951–:955 也这么列。`serve` 在入口处理结束仍无回应时代投 error，这是卷文原意，不是自补：卷二 :969 违例项写“kernel 这时自己投一条只含错误代号的 ReplyResult”，附录 :3136 写“运行期已有兜底”。写成工厂加默认实例，属于可接受的自定。

   测试确实覆盖了四路各恰一次与同一句柄二次使用（output-gate.test.mjs:226–:307），用的是通道加测试自写的入口。真入口文件要到 6-19、6-20 才有。有一个缺陷，见必须改 3。

3. **kernelApi 新增的四条。** 与卷二 :633、:634、:650、:651 逐字一致，是卷文本来就有的行，state-owners.json 只是补齐，不是新开口子。`compileRX` 只开给 display-load.mjs，加载期编译；`evaluateRX` 只开给 select.mjs，运行期只拿冻结的 rxTree 求值。这照卷二 :809 与 :1205 显示档一段，不违反 B2-W3。可封。

4. **markers.mjs 的三个枚举。** 取值与卷二十九 §2.1 :124–:153 的 label_form、tpl_kind、fill_kind 三个枚举逐一相同，不是假常量。criteria 17 类各 rev+1，是经登记器盖的。但是写者把 V-25.a 的字串字面量比较换成了跨组 import `T`，等于用一个违例换掉另一个，见必须改 2。另外，同属卷文封闭枚举的 `segment_kind`（卷九 :147）在 reply-composer.mjs:18–19 仍然写成字面量 `'narration'`、`'dialogue'`，口径不一致。

5. **挂卡项是否如实、是否走了捷径。** “没注入 screen 就不出文字”这一条确实做到了 fail closed。但 envelope-exit.mjs:18–43 自己造了 `Screened`（模块私有 WeakSet），又用 UTF-16 的 `slice` 加 `+` 做命中段替换。这是用替身顶替 `gate/screen.mjs` 和 `output-gate/redact.mjs`，等于变相绕过显示闸，违反以下卷文：
   - 卷二 :937 第 1 步：Screened 由 gate 的 `screen` 得到；
   - S19 :2438：“screen 之外产出 Screened<Text> = 0”（E-TSC-ESCAPE-ASSERT）；
   - :876：取段只在 redact.mjs 里用 sliceByCodePoints 按码点做。

   回报说 gate 卡建好后“只改适配一处”，这不对：私有登记和替换逻辑都得整体搬走。同类问题还有 templates.mjs:60、:69 用 `+=` 拼接（应该调 `concatText`），以及 :50 用 `String(v)`（应该调 `intDigits`，并按显示语言行的数字分组，见 R29-2.4 :560、卷二 :667、:876）。

   “显示档 RX 未建时带 when 即加载失败”如实。但 templates.mjs:100 传给选择器的绑定写死成 `{ slot: {} }`，这是占位值。R29-2.6 规定 when 只读本行槽位的值，所以显示档 RX 建好后本文件必须改，回报里“不用改”的说法不成立。“槽位只做 ref、num”这一项如实。

6. **没有模板时玩家看到什么。** 回报说“玩家看到的是语言包里的显示名（labels.zh.json 已有）”，不对。现在没有 labels 加载器，`textcore/labels.mjs` 未建，labels 只能靠装配注入；而且 world/i18n/labels.zh.json 的形状是“代号 → 字串”，`labelText` 要的是“代号 → 形态 → 字串”。所以即使装配好，现在也只会显示代号。挂 6-16 只解决模板内容，解决不了 labels 加载器。我查了 docs/迁移体检/块6.md 和 docs/PLAN.md，都没有哪张卡认领 gate/screen.mjs、textcore/labels.mjs、textcore/ops.mjs。块 6 要“能玩”，玩家能读到文字离不开这三样，这是排卡缺口。

## 必须改（逐条）

1. **显示闸替身（等主会话或李白排卡）。** 删掉 envelope-exit.mjs:18–43 的 `createScreener` 和私有 `SCREENED`，改成 `Screened` 只来自 gate/screen.mjs，命中段替换归 output-gate/redact.mjs。templates.mjs:50、:60、:69 改调 textcore 的 concatText、intDigits。依据：卷二 :937、:876、:2438，卷二十九 R29-7.6 :784。前提是先有人建 gate/screen.mjs、redact.mjs、textcore ops 与 labels；块 6 目前没有这样的卡。主会话可以选：把 6-17 扩大，或者在 6-17 前插一张卡。由主会话定，不该由写者用替身先跑起来。
2. **跨组 import kernelApi 以外的名字。** 五个文件对 `KernelError`、`REGISTERED_CODES`、`CODE_RE`、`T` 的 import 要去掉（行号见逐问 1）。有现成途径的照途径改：错误码走 kernelApi `E`（:625，callers `*`），代号收窄走 kernelApi `narrow`（:632）。outputGate 取代码内封闭枚举、构造登记码错误，卷二 kernelApi 没有给途径，属于卷文推不出，要报李白，由勘误加 kernelApi 行，或者另给做法。不得自己补。依据：卷二 :809、:869、:876、:2438。
3. **serve 与 postReply 没管 save_export 一路。** reply-channel.mjs:109、:111、:114 只看 `posted`。save_export 成功时只 `send`、不调 postReply（卷二 :967），`serve` 会误投一条 error，随后 send 第二次被拒。另外 :95 的 postReply 没有拒“已 send 过的句柄”，而卷二 :969 写明“save_export 一路两样各一次”就是违例。要改成：已回应按 `posted || sent` 判；postReply 遇到已 send 的句柄报 E-WIRE-REPLY。两条各补一个测试。
4. **选择器绑定是占位值。** templates.mjs:100 要把本行已填的槽位值交给 `selectRows`（R29-2.6 :562）。reply-composer.mjs:38 的轮换序号要先取事件 id 序号，没有事件时才取行序号（R29-2.3 :559）。如果从 EventId 取序号需要内核解析、卷文推不出，就照实写进挂卡，不能说“内核建好后不用改”。
5. **丢了未译标记。** reply-composer.mjs:40–41 的行要带上 labelText 和 renderTpl 的 untranslated 标记（R29-1.6 ③ :499）。
6. **自补的显示名键格式。** reply-composer.mjs:20、:60 的 `'reply_result.'` 前缀是自造的，outputGate 里还拼了代号字串。卷二十九 §2.4 :240–:245 与 R29-1.5 :498 写的是“键是一个登记过的代号、封闭枚举的值”，没有写前缀，不能自补。:18–19 的 `segment_kind` 要和其他三个枚举同一口径（依据卷九 :147）。
7. **mountOutput 放错文件。** reply-composer.mjs:72 的 `mountOutput` 在卷二 groupApi :683 里是 `output-gate/mount.mjs#mountOutput`。要么从本卡删掉留给 6-19，要么照登记放进 mount.mjs。
8. **回报更正。** 改正回报第 5 条：现在玩家只见代号，原因是没有 labels 加载器，而且 labels.zh.json 的形状不同。第 1 条里 gate、textcore 的挂卡要写到真实存在的卡号，或者写明“未排卡，等主会话”。
