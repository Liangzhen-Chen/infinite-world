### P1 `intDigits(n): Text` 做不出数字分组（局部缺口）
卷二十九 R29-2.4 规定 `num` "按显示语言行的数字分组"（`digitGroup`，:208）；R29-6.8 规定代码里不拼标点，分隔符只能来自语言包，再用 `concatText` 拼。`templates.mjs` 要分组，只能把整数按 10^digitGroup 拆成几段，每段调 `intDigits`。但非首段要补前导零（1005 → "1" "005"），`intDigits(5)` 只出 "5"；`sliceByCodePoints` 又只给 `redact.mjs`。按现在的签名，R29-2.4 的分组做不出来。
建议只改这一处签名：`intDigits(n, minWidth)`，按同一十进制位表补前导零；负号如需要，走 `format` 模板，不进函数。改动在 §2.8 textcore 行与豁免表同一句，不改结构。

## ④ 第 3 项：`DisplayLang` 声明文件与构造点（供李白裁定）

先看事实（卷二 §1.9 :242–:253、§2.9 第 2 条 :896–:920、§2.8 第 1 条 :668；卷二十九 :202、:314、:360、:433、§2.3）。哪些地方要用到 `DisplayLang`：
- 服务端：kernel 收窄上行头部 `locale`，`router-caps` 把它带到 outputGate、aiGate；state 里存 `displayNames.*.lang`（kernel 写），叙述记录也存（C29-4）；inputEdge 用 `lookupByLabel(lang)`；gate 加载 `blocklist.<lang>.json` 并提供 `matchBlocklist(text, lang)`；textcore labels 加载 `labels/templates.<lang>.json`；outputGate 读 `gram.<lang>.json`、`locales.json`；aiGate 读 `charset.<lang>`。
- 客户端：`PrefCap` 存 `locale`，经 `narrowWire` 按 `ui-pref-v1` 收窄；下行载荷带 `locale`。
- 约束：规则层不得读它（R29-1.3）；从裸字串造代号类品牌只有 kernel 能做（§2.8 kernel 行）；声明文件闭集五份。
- `kernel/types.d.ts` 规则层看得见；`kernel/text-types.d.ts` 只有 kernel、textcore 和四个服务端非规则组看得见。

**方案甲（建议）**
- 声明：服务端放 `kernel/text-types.d.ts`，客户端放 `extension/textcore/types.d.ts`（"客户端用到的代号品牌"已在其列）。
- 构造：服务端只有 kernel 一处构造。`kernel/load` 加载期读 `locales.json`（不含文字）建冻结名单，强转放在 kernel/handles 下一个登记文件里（豁免表加一行，"按代号正则校验并在 `locales.json` 名单内"，与 `Handle` 查词表同一个做法）。收窄上行头部、给 labels/gate/outputGate/aiGate 按语言枚举文件，都从这份名单取。客户端只有 `narrowWire`（下行与 `ui-pref-v1`）一处构造。
- 后果：规则层看不见；"造品牌只在 kernel"不破例；值一造出来就是已登记语言。代价有三：`locales.json` 多一个读者（kernel/load），入口表要加一行；`text-types.d.ts` 的说明要加"显示语言代号"；`display-load.mjs` 读 `locales.json` 的其他列时，按 kernel 给的名单查表取值，不自己转型。kernel 读的是不含文字的登记表，不进摘要。显示层拔掉后，aiGate、gate、`displayNames.lang` 照样要用这个类型，所以名单放在 kernel 反而不受拔插影响。

**方案乙**
- 声明：放 `kernel/types.d.ts`，和 `Handle` 一起，字面上最合"代号类品牌"。构造同甲。
- 后果：规则层的 tsconfig 能看见这个类型。要靠另加一条 lint 禁规则层使用，才守得住 R29-1.3。等于把一条由类型保证的约束降成扫描保证的约束，不建议。

**方案丙**
- 声明：同甲。
- 构造：强转仍在 kernel，但名单由 `display-load.mjs`（`locales.json` 现在唯一的读者）在装配期经新 kernelApi（例如 `registerDisplayLangs`）交给 kernel。
- 后果：`locales.json` 仍只有一个读者，kernel 不碰显示配置文件。代价是加一个 kernelApi，还要定装配次序：inputEdge、gate、aiGate、labels 加载前，必须先跑完 outputGate 的 `display-load`。下层的合法性要靠上层初始化，方向反了。拔掉显示层，aiGate、gate 就拿不到名单。

建议甲：改动只有声明说明一句、豁免表一行、入口表一行、kernelApi 一项（交名单），这些都是登记。
