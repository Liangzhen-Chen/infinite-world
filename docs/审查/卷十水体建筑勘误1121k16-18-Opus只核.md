## 一、必须改

**M1 表序"相邻两项四邻相接"和本卷自己的排序打架，宽河也做不到**（卷五 :491；卷十 :436、:467）
卷五 :491 要求 `boundary` 表序里相邻两项四邻相接。卷十 :436 的排序是"先按最近中心线格的下标，再按 (x, y) 字典序"。拿 A10-2.4 ③（:470）手算：下标 0 这一组是 (1,2)、(2,1)、(2,2)、(2,3)，(1,2) 后面紧跟 (2,1)，两格只是斜着挨。所以生成的窄带一出来就报 E-GRID-WATER-BAND。而且只要宽度 ≥ 2，"每两项相接"就等于要求作者把河画成一笔走完的路径，作者画的宽河也过不了。
改法：把校验改成"首格之外，每格都和表序里排在它前面的某一格四邻相接"（前缀连通），同时换一种能证明满足这条的排序（比如加入"到中心线的距离"作次键），证明写进条文，A10-2.4 ③ 列出逐格表序。这样卷五 :661 的前缀最小也才有意义。

**M2 "宽度恒为 2r+1、四邻连通"在有裁剪时不成立，r 的取法也可能没有上界**（卷十 :436、:467）
窄带要去掉父足迹外的格和已被别的行占去的格，去掉之后宽度不再是 2r+1。被去掉的格还可能把带切成几块：从带内一格走向中心线，途中经过的格可能正好被兄弟占了。中心线走成阶梯时，"宽度"本身也没有定义。另外，作者给了 `targetAreaM2` 时取"格数不超过目标的最大 r"：带被父足迹截满以后格数就不再增长，如果目标大于父足迹，r 就没有上界。
改法二选一：
- 不裁剪：带上任一格出父足迹或已被占，即报 E-GEN-WATER-FOOTPRINT；
- 照旧裁剪，但只取含中心线的那个四邻连通块，删掉"恒为 2r+1"，A10-2.2 改成可测的说法（例如"中心线上每格沿垂直方向两侧各 r 格都在带内，除非被裁"）。

r 的搜索要写明在哪里停（格数不再增长就停，或给一个上界）。

**M3 支流汇入、跨父地点、下游有作者 `boundary` 这三种情况，"上下游足迹相接"不成立**（卷十 :436、:437）
- 河汇进河：如果下游河 D 的 id 更小、半宽 ≥ 1，D 的窄带先占了下游种子 t 四邻的格。上游中心线的末格必须落在 t 的四邻上，于是撞上"已被 id 更小的兄弟窄带占去"，报 E-GEN-WATER-FOOTPRINT。也就是说，普通的支流汇入一律失败。
- D 不在本行的父足迹里（河跨郡、跨省是常态）：t 在父足迹外，中心线必然出父足迹，同样报错。
- D 有作者 `boundary`：中心线目标仍取 D 的 `coord`，而卷五 :490 规定种子不在覆盖区内，`coord` 未必和 D 的足迹相接。这时上游的带碰不到 D 的足迹，与 :437"上下游足迹相接"矛盾。

裁定原话是"河道按下游链连成窄带足迹"。改法：中心线的目标改成"D 的足迹"——流水 D 取它的首格，有 `boundary` 的 D 取按固定次序最近的一格；中心线一旦和 D 的足迹（或 D 的带）四邻相接就停。跨父的情况要写出确定的接法；推不出就写"等李白裁定"，不能让它默认报错。

**M4 生成的流水水体行没有 `boundary`，加载必然报错**（卷五 :491、:661；卷十 :432、:433）
R10-2.12 让命中 `rules.gen.water.rows` 的地表存量单元直接变成水体。这些行的 `waterKind` 可以是任何 `water` 条目，包括 `flowing` 为真的河、溪，足迹沿用骨架阶段种子长出的团块，`boundary` 为空。R10-2.17（:433）又明写不管这类行。卷五 :491 规定流水行足迹只来自 `boundary`、为空即报 E-GRID-WATER-BAND；:661 的河床也要按 `boundary` 表序取前缀最小。结果是：任何生成出河的世界都加载不过，河床也无从计算。
裁定要求"整类规则，河湖海一视同仁"。所以必须给生成的流水行也确定足迹形状和表序（例如同样沿 `downstream` 生成窄带），或者在卷五 :491、:661 写明它们怎样取表序。推不出就等李白裁定，不能只修手写行。

**M5 阶段次序错位：补足迹太晚；投影时生成的 `downstream` 还不存在**（卷十 :343–:344、:433、:439–:440）

## 二、写者自定的两处

**① 跨父河道（卷十 :436、§8 第 27 条 :1183）：卷文推得出，必须写实，不能列"待裁"。**
推理三步：
1. 子足迹必须落在父足迹之内（卷五规则 3），窄带因此只能落在河自己的 `parent` 足迹里。
2. `parent` 是作者数据，生成器不得覆盖作者值（R10-1.7 手写优先，否则 E-GEN-OVERRIDE-AUTHORED）。所以"生成自动把父行上提"违反现行规则，它不是一个待选的接法。
