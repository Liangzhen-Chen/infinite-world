## 0. 口径

- "必改"取审查文件里编了号的必改项（A 用 M/N 编号，B 用 M/N 或汇总的"必改点"）。建议项、轻微项不计。
- 第一版没有快照，无法逐条对照，所以第一轮 14 条全部归"首轮基线"，来源按 (a) 填，但在统计里单列，不当作"上轮漏查"。
- 来源：(a) 上一版就有、上轮没查出；(b) 本轮修改新引入，含"改一处漏一处"和"上轮修补不彻底的余项"；(c) 主会话新裁定扩范围；(d) 与卷一冲突或卷一同时变动；(e) 审查标准前后不一。
- 性质：矛盾 = 自相矛盾；接口 = 系统间接口对不上；缺维度 = 缺维度/缺类型/缺实体类；写死 = 隐式默认或写死；读文字 = 读文字判断；确定性；其他 = 设计取舍/验收口径。"纯措辞排版"一栏在 52 条里是 0 条，审查员已经把纯措辞问题放进了建议项。
- A、B 两位审查员在同一轮可能报同一个问题，表里按各自编号分别列，并在备注标重复。

## 3. 根子在哪

按占比排序：

1. **修改方式只打补丁、不做全文同步：约 68%（26/38）是 (b)，覆盖了绝大多数"矛盾"类。** 典型例子：
   - 惩罚表越界在 L448、L457、L458 三处三种说法（三审A-M1）。
   - 附录 B 按旧顺序算，规则顺序改了之后数值差 0.0001（三审A-M2），是人手算附录与脚本不同步。
   - 上轮修 modifiable 允许 map，只改了 L107，没改校验码 L476/L506（复审B-M4）。
   - 上轮加了 onUnknown 规则，§5 二十二张表没加列（三审A-M7）。
   - 前缀改名只改一半，缩写与族名并存（四审A-N4）；新错误码没进错误码表（四审B-M2）。
   - 同一个修补连续被打回：依赖声明 M1→N1→三审M3→四审N1；实体行 三审M4→四审N2、N6；类型文法 N7→三审M9→四审N3；扫描白名单 复审B-M3→三审N1→四审M3。
2. **草稿结构：同一个概念在多处各写一遍，是 (b) 的放大器。** 叠加惩罚公式在 §0、§3.3、附录 B、附录 E 四处出现；onUnknown 在表头、§1.6、§5 每张表、A5 出现；卷一编号在正文和附录 F 各一份。结构上没有"单一定义点 + 其余只引用"，所以任何改动都要手工同步 N 处。这一条在统计里不单独占一个来源格，而是 b 的成因。另外 a 里的"实体行结构""派生显式写值"说明第一版缺了基础结构，一直到第三、四轮才补出来，这是首轮审查清单覆盖面不足（a 占二至四轮 5%，量不大）。
3. **范围不断扩大：16%（6/38）是 (c)，集中在第四轮（3 条）。** 输入边六条、输入规范化、生成名只存代号、两道安全闸，每条裁定都给卷二新增条款，而新增条款又需要新的校验码、扫描口径、验收断言，这些落地件本身就是下一轮的新必改。第二轮的 (c) 是 2 条，第三轮 1 条，第四轮 3 条，没有出现"冻结"的轮次。
4. **两卷并行写同一个概念：5%（2/38）是 (d)。** 都在附录 F 与卷一编号、字段、类型数对不上（卷一同时重编了 3A.x，卷一仍写"十一种"类型，卷二已是 14 种）。占比小，但每次修复靠人工对表，且在第三、四轮都出现，没有固定的同步机制。
5. **审查标准前后不一：5%（2/38）是 (e)。** 量小，但代价大：G4 一条就让作者白改一轮。另外一条旁证：第二轮 A、B 两位审查员对同一个系数表值的核对结论相反（A 算出 0.8691 指为错，B 复算称 0.8694 一致），第三轮证明 A 对。靠人手心算做裁判，本身会制造反复。

小结：根子是 1 加 2（补丁式修改加概念多处重复，合计 b 占 68%），3 是外部放大器（16%），4、5 是次要因素（各 5%）。"审查没查全"（a）只占 5%，说明审查本身不是主要问题，问题在作者侧每版引入的新错。

## 4. 流程改法（每条对应来源）

1. **先定"谁定义什么"，每个概念只在一处写全，其余只引用（对 b 的 68%、c 与 d）。**
   - 做一张"概念定义台账"：概念名、唯一定义位置、允许引用的位置。叠加公式、onUnknown、类型文法、前缀表、错误码表、卷一卷二分工 7 项各占一行。
   - 正文其他位置只写"见 §x"，数值与公式的唯一出处是 §3.3 与 stacking.mjs。
   - 卷一卷二的 7 项分工先落台账，卷一、卷二各自只写自己名下的条目，对方条目只引用不复述。
2. **作者提交前的全文一致性自查，作为必交附件（对 b，尤其矛盾 47% 与确定性 8%）。**
   - 每次改版交一张"改动影响面表"：改了哪个名称、数字、错误码、字段、编号，全文 grep 的命中处全部列出并标"已同步"。
   - 自动化三件：附录 A 夹具跑自己的校验器（L0–L3 通过）；附录 B 与系数表数值由脚本生成而不是手算；错误码表、前缀表、类型清单由正文机器核对（正文出现的码必须在表里）。
   - 在影响面表没填全前，不送审。这条直接对应第二至四轮 26 条 (b)。
3. **新裁定攒批、按版冻结，并附"裁定追溯表"（对 c 的 16%）。**
   - 一个版本送审期间不插入新裁定；新裁定进下一版，开头列出本版纳入哪几条。
   - 每条裁定要同时落三件：条款、校验码或扫描口径、验收断言，三件齐全才算纳入，避免第四轮这种"裁定进了、落地件缺"。
   - 审查员对本版增量只查追溯表对应的条款，不用整份再审一遍新标准。
4. **审查口径固定：回归 + 增量，禁止对未改章节追加新要求（对 e 与 a）。**
   - 每轮只做两件：上轮必改是否落实；本版 diff 引入的新问题。要翻上轮要求时，必须在审查里写明"推翻上轮第几条，理由"，由主会话判是否采纳。
   - 首轮用固定清单覆盖结构项（实体行/类别行/偏离行结构、每表 onUnknown 列、类型文法闭合、前缀表全登记、校验码对账），清单一次定稿，避免 a 类到第三、四轮才补。
   - 数值类核对一律用脚本出结果，两位审查员不再各自心算。
5. **卷一卷二编号用稳定 ID 引用，卷一改动触发卷二同步检查（对 d 的 5%）。**
   - 附录 F 改成机器可核的对齐表：卷一条目 ID、卷二条目 ID、字段清单；卷一任何重编号、字段变更，同一提交里更新对齐表，不允许"待卷一同步"悬着。
   - 本卷收口前，卷一对应章节需处于冻结状态。
