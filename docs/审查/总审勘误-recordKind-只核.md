## （1）收录名单与“不另造枚举”

**逐项 Grep 定义处。** 卷二 :249 的名单列了 17 项。其中 16 项是 `state.*` 表行，都在所称的卷里有定义行：

第 17 项“卷六 §2.4 合同记录”也确有定义，但没写键。卷六 :291 登记的键是 `contracts.*`，名单里其他各项都写了键，只有这一项没写，不一致。

**漏收（真问题 1）。** 名单写的是“现有名单”，收录口径是“各卷已定义、以自身记录键为键”。照这个口径，至少还漏了：

- **义务记录**：卷六 §2.4 的第二种记录，键为 `obligations.*`（卷六 :291），以 `ObligationId` 为键，也是卷一 §4.1 的第 3 个存储概念。它和合同同节定义，确定是漏收。
- **`state.enacted[provisionId]`**（卷八b :264）：运行期立法条目，以条目自身 id 为键，按口径也应收。
- 边界项，须写明收或不收的理由：`state.proposals[actorId][proposalId]`、`state.marks[onId][markId]`（卷九），第一段是实体，第二段是记录自身的键。

**“不另造枚举”与新建族。** 裁定原话是“在卷二 §1.9 登记一行词表族前缀……只收各卷已定义的记录类型名”。登记词表族前缀本身就是开一个开放词表族（§1.9 的格式就是“族名 → 前缀”），所以新建 `record_kind`/`reckind_` 和“登记词表族前缀”是一回事，不矛盾。条目只有 `stateKey` 一个字段，只引用已登记的 `stateKeys`，没有在 §2.7 加字段，也合裁定。另外说明一点：裁定举的例子是 `recordKind.*`，现文前缀写成 `reckind_`，符合全书 `xxx_` 前缀的惯例，不算偏离。

## （2）写法照 code 槽先例

`slots` 结构里加了 `recordKind?: ref vocab record_kind`，与 `entityKind?`、`vocab?` 并列，三者恰填一个；线上只传候选编号，不传记录键，与通用槽位 `invite`（卷九 :1298，待应答记录不上线）同法。这部分照先例写了。

**多改（真问题 2）。** 新加的“`recordKind` 非空时 `filter` 必填且非空”在先例里没有：`entityKind`、`vocab` 两种槽位的 `filter` 都是选填。裁定说的是“沿用 entityKind/vocab 的写法”，也没要求这一条，勘误行也没写必要理由。须删掉，或者补写必要理由报李白。

**小项 a。** 候选生成的单点定义 R9-1.2（:504）仍写“实体类加 `target_filter` 的 `whenRX` 从 view 生成候选”，`slots` 行也仍写“候选由 §4.5 从 view 或词表生成”，都没有覆盖记录槽。宜在 R9-1.2 补一句，说明 `recordKind` 槽的候选从哪里来。`vocab` 槽原本就没写进去，可以一并补。

## （3）改名、阈值

- 全书 Grep `plot_invite`：除 `act_plot_invite` 外 0 处。`invite_plot` 只出现在卷二十二 :303、:310 与勘误行，引用同步。
- `act_plot_invite` 段（:294–:312）与 R22-7.5 都没有“阈值”一词。取舍改为直接引 R9-12.7：U 最大，承诺期内须高出 `rules.npc.switchMargin`。
- **标出（不判）：** “`U` > 0”不在 R9-12.7 原文里。R9-12.7（:1032）只写“取最大者”和 switchMargin。已报李白待定，本次不据此判不可封。

**真问题 3：`tf_plot_invitee` 把应答方的门控挪到了发起方的筛选里。** :309 写的是候选人须“过卷十八 R18-11.4 参与阴谋的门控读档（R22-7.5 现有条件，不新增数值）”。可是 R22-7.5 的原文是“被邀者答不答应是他在卷九决策管线里的决策，**其**门控读卷十八 R18-11.4”。这个门控是被邀者应答时用的，不是发邀的条件。写进发起方的候选筛选，有两个后果：

- 会过门控就拒绝的人永远不会被邀请。R22-7.5“拒绝者已知其事，是否告发是他的决策”这条线就少了一大类来源，世界行为变了。
- 发起方等于直接读了对方的内在档位。`tf_plot_open` 写明了“只读行动者主观视图”，这一条却没写。

所以“R22-7.5 现有条件”这个说法不成立。21:50 ③ 所说“满足 R22-7.5 条件才进评分”，按原文只能指发起方是成员、人数未满这两条，再加上候选人不是成员。宜删掉门控这一项，或者报李白定。

候选提供行 `invite_plot` 的四个字段与卷九 :1018 行表 `{id, actionId, slotGen, whenRX, maxCandidates}` 对得上；`decision` 的形状与卷九 :200 一致；`tf_` 两行的 `slot` 取 `scope`，合卷九 :118。
