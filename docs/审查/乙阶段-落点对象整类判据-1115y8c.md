## 判据一：迁到或交给别卷的，取接收卷的系统键

来源：李白 17:0x 第二条第 2 款（审查/李白裁定-1115-1705-待裁3行与不在六类.md），"落点锚点所在那一卷"。

- **范围**：落点对象认不出的行；以及落点栏带"原对象栏写"（已按 17:0x 整类改写过）、对象是系统键的行。旧表名改表代号的行、待补占位（M11-7 那类"照旧待补"）不在范围。
- **判法**（只读落点栏文字，先去掉末尾"；原对象栏写 …"的说明）：
  1. 落点里有"迁 / 迁到 / 交 / 交给 / 归 / 移交 + 卷X"的，取卷X；
  2. 否则取落点里第一个节号引用：写成"卷X §n"的取卷X，裸"§n"取本卷；
  3. 落点里没有节号引用的，取本卷。
  卷号的写法读 `gen-卷十一-inputs.json` 的 volCode，系统键按卷读 `乙4补-systems补全.json`，不手填。
- **对原实现的改动**：apply-1115y7.mjs 里按行号列的接收卷表（三行）删去，改调同一个判法。
- **重判结果**：范围内 51 行（17:0x 改写的 58 行去掉 7 行旧表名），与现行对象全部一致，0 行要改。M20-11 由"迁卷二十七"判出 sys.offscreen_save，M20-31 由"交卷十七"判出 sys.travel，M13-24 由第一个节号引用"卷九 §2.2"判出 sys.ai_interface，都和现在一样。M3b-6（"方法行在卷五 §4.8"在主锚点之后）、M8-19、M8-29 仍判本卷。

## 判据二：锚点在服务端的，不判 display

来源：卷二 §2.9 第 0 条进程分组表（服务端根目录 `server-plugin/**`，成员 kernel、规则层、inputEdge、gate、outputGate、aiGate；客户端根目录 `extension/**`，成员 host、display）与同节"路径写法"（不带根目录的路径一律相对 `server-plugin/`，客户端文件一律以 `extension/` 开头写全）；卷二 §2.7 outputGate 注"显示闸"。

- **范围**：落点对象是上表成员的模块组键、且至少有一个代码锚点（.mjs、.js）的行。数据文件锚点不判进程。
- **判法**：
  1. 每个代码锚点按根目录判进程；不带根目录的按"路径写法"属服务端。不按同名文件猜目录：旧仓里 `extension/` 与 `server-plugin/` 下都有 ui-map.mjs、ui-history.mjs，卷文不带前缀就是服务端那份。
  2. 对象按进程分组表判进程。
  3. 对象在客户端、代码锚点全在服务端的，判不一致：显示职责的对象 display 改为服务端的显示闸 outputGate；客户端的其他组（host）没有对应组，列给李白。
  4. 代码锚点跨两个进程的，不改，列出。
  5. 锚点在客户端、对象是服务端组的，不算不一致：这是 §2.9 第 0 条"客户端不留"的方向，把客户端的逻辑迁入服务端（例如模型调用归 aiGate）。
- **全书重判，改动 4 行**（display → outputGate）：
  - M22-15：代码锚点 engine.mjs（eras.json 是数据文件，不判）；
  - M22-18：ui-map.mjs、ui-history.mjs，与卷二十九 M29-28 一致；
  - M23-6：works.mjs:41，与同规则号 R29-2.6 的 M29-2 一致；
  - M24-18：applied-effects.mjs、state-notices.mjs，与卷二十九 M29-26 一致。
  上一轮 M29-4、M29-21、M29-28 已是 outputGate，本判据下仍一致。M22-15 不在单核点名的三行里，是本次全书判新判出的。
- **列出不改的 4 行**：跨进程 M29-8（outputGate）、M28-16（kernel，另一端是 tools 离线文件）；迁入服务端 M29-38（aiGate）、M29-44（outputGate）。
