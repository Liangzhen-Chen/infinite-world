# 卷十九 统计层建筑增减提案 只核

核者：Opus 5.5 中档，只读。对象：`审查/卷十九-统计层建筑增减提案.md`。依据：`收尾待办.md` :469（李白 11-14 二③）。

## 结论：不通过（方向与必需性成立；判据与"减"的论证有真问题，改后单核）

## 2. 只补"增"、"减"走实物规则 —— 方向合理，但离屏时"减"不成立（真问题）

不按人口自动减、留空房、让空房吸引迁入回流，这个理由成立。但提案说"减走卷十九既有的劣化/失修/拆除"，这条路在离屏时走不通：
- **开局未物化建筑没有劣化起点**（卷十 R10-3.8 :444），离屏多少年都不老化，提案自己把它列进了记账 ⑦-2。后果是：人口衰退的离屏聚落里建筑数和床位**永远不减**，`popCapacity` 的床位项永不下降，空城几百年后仍满床、仍按满床吸引迁入。这正是本条要找的"不现实后果"，而且它和本提案"减由实物规则保证"的结论直接冲突，不能只记账了事。
- 甲案里，物化出来的建筑靠 `settleFacilities` 劣化，但它的离屏形态没有声明（提案 ⑦-1；卷十九 :390），维护在统计层由谁做、做不做也没有定义。于是要么离屏繁荣城的房屋也一律失修倒塌（没人维护），要么永不老化，两头都不现实。甲案好处里写的"减自然成立"缺这个前提。
- 要求：本提案要么一并给出未物化建筑的劣化起点和统计层维护形态，要么明确把它定为同批必改项（并写进牵连清单），不能当作提案以外的事。

## 3. 增建判据 —— 结构合规，但有三处真问题

合规部分：只读已登记入口（已逐项核行）；阈值进规则表键 `statBuild.minGap`；来源靠 `demandSources` 名单按代号调用，没有类型特例；不读文字；有扫描断言（设施类型字面量为 0）。

真问题：
- **(a) 和个体层不同式。** 卷六 :627 运行期立项判据是"建造成本 ≤ `investHorizonDays` 内预期利润"，提案改成"可花余额 ≥ 建造成本"。`viableStations` 只判单个工位有没有利润，不等于投资回本的判据。这样统计层会建出个体层不会建的生产设施，违背提案 ⑥ 自己引的"同式，只是主体换成聚合体"的先例。生产、店铺类来源应沿用卷六的利润判据，"付得起"只作附加条件。
- **(b) "付得起"的口径没定。** 价格入口写清了（卷六规则 11 的成本式：`priceFor` 现价 + 工钱行情）。账户也写清了：聚合账户或组织账户，扣除 `purpose_unmaterialized` 分区（卷六 :356）。但"可花余额"是一个多种资源的账户，拿它和一个估值比大小，须指明比的是哪个数：是计价资源（`unitOfAccount`）的余额，还是把可花资产按 `priceFor` 折价后的合计，还有备料从哪种资源扣。现在未写，结果不唯一。
- **(c) 住处来源返回的形状语义冲突。** 统一返回字段 `needed` 指"应有座数"，执行器再算 `g = needed − 现有座数`。可住处来源算出来的是缺户数 `ceil(缺床 ÷ size)`，本身已经是缺口。照现在的写法会被再减一次现有住处数，导致少建、甚至不建。须改为返回"现有住处数 + 缺户数"，或者给来源单独定义一个缺口字段。
- **(d) 个体层没有对应的住处建造规律。** 卷六规则 11 只覆盖生产工位，住处在个体层只靠 NPC 决策（全书没有按住处缺口立项的规则）。统计层新增住处来源，个体层没有同源规则，层间可观测量（人数、床位）会分叉，违反卷二十七按基准核对层间一致的要求。须写明个体层也读同一来源（例如作为 NPC 立项候选），或者说明两层怎样对齐。

## 4. 甲、乙两案代价 —— 大体写全，推荐成立；待选确属须选

- 甲：整站物化不可回收、离屏成本增长、上界登记，这三项写全了。还缺一项：§2 所说"物化后靠失修来减"依赖离屏结算和维护形态，目前这两样都未定，须补进甲的代价。
- 乙：放宽 R27-2.10、卷六另开份额来源、卷十四条跟改、增建行同样没有完好度，写全了。
- 推荐理由成立：甲不放宽已批规则，乙的好处只在性能，可以先靠上界登记和标定实测量出来。
- 待选确属须选：乙要放宽李白已批的 R27-2.10，这属于放宽硬规则，必须报李白；甲、乙也正是本提案按裁定要交李白审的接口分歧。

## 5. 确定性与折叠、先例、牵连

- 确定性与折叠：成立。整拍边界执行（R27-1.6 :281）；固定次序；`after` 由卡账写者分配（卷十一 R11-3.14 :483）；物化形制只由（世界种子、地点）定（R10-3.8）；工程键不进个体足迹（R27-2.3 :354）。
- 先例抽查属实：卷六 :557 `statBatchGrain`（定义在 :216）、:630、:782；卷十七 :335 R17-1.11、:833 统计商贩；卷十 :628 R10-7.6；卷二十七 :443 R27-3.9。
- **牵连清单有遗漏（真问题）：**
  - 卷八b §4.6：卷十九 §4.4 规则 2 的前状态要求"当事人对 `site` 持有处分权"（:500）。生成期可以豁免（C10-7），运行期由聚合体或组织出资时，处分权怎样认定须卷八b 给出。清单里没有卷八b。
  - 卷十九 §4.4 规则 5 与 `contributeBuild(buildProjectId, actorId, minutes)`（:238）：原文要求主匠在形制 `skill` 上达到 `skillMin` 才能开工，`actorId` 取聚合体、技能读 `stratumSkill`，须在这两处跟改。卷十九那一行没有列出规则 5 与入口签名。
- 有无提案外新增：没有。新增的两个规则表键、钩子、规则 10、住处来源、矩阵行、上界登记都在裁定要求的范围内。
