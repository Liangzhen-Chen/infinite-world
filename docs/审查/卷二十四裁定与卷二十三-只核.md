## 二、新真问题（5 条）

### 1. 内核事件 id 与善后链下一条撞号（R24-1.1 新写法；类别：确定性 R27-8.9）
- R24-1.1（:362）：内核事件 id 的规则代号取所在事务事件的 `cause`，链首主体取事务事件 id，位次恒为 `pos.only`。
- 卷九 §2.9 善后行（:374）：同一类善后多条时，第 2 条 = (同一 `aft.*` 代号, 第 1 条事件 id, 同刻, `pos.only`)。如果第 1 条善后事务（例如多目标反噬）触发了终止，它的内核事件 = (`aft.*`, 第 1 条 id, 同刻, `pos.only`)，五段全同，就撞号了。`ntf.activity` 链（:377）是同一写法，也有同样的风险。
- 改法：内核事件用一个专用位次代号（如 `pos.kernel`，由卷二十四登记），不再借 `pos.only`。卷九 §2.9 是本卷事件的表，不必补行；卷二十七 §8 第 13 条宜指向 R24-1.1。

### 2. 同一事务内的持有变化、常住变化事件没有和 N1 一起覆盖（N1 同类）
- R18-1.11（卷十八 :448）、R18-1.10 规定：写者在同一事务内另发事件。卷二十四自己的免职例（:381）正是这样：一笔事务一条免职事件，再加一条持有变化事件。
- 新 R9-2.3 与 R24-1.1 只把卷二 §2.6 的终止、复生内核事件列为“另计”。持有变化、常住变化事件的 `primitives` 取什么（表 A 此栏 onUnknown 为 error）、id 怎样取、算不算在“恰一条”之外，都没写。A24-1.2 也只断言了内核事件。
- 改法：把“另计”写成一类，即“写者协议在事务内另发的事件（卷二终止、复生；卷十八持有变化、常住变化）”，`primitives` 为空，id 同用真问题 1 的专用位次。这超出了 N1 裁定的字面（裁定只说内核协议事件），须报李白或由主会话判定是否属同一裁定。

### 3. 卷二十三与卷二十四对表 C 三栏的读法不一（02:41 表 C 乙）
- 卷二十四（表 C :181、C24-17）：`startVerb/stageVerb/endVerb` 是 `ref vocab verb` 的子类型动词，由登记该行的卷登记，只填进通用事件载荷 `kind`，按 `kindFrom = kind` 合看；C24-17 请卷二十三把 `showAnnounced/showOpened/showEnded` 改为子类型动词。
- 卷二十三（§2.5 :201–202、R23-4.1、修订记录 :922）：三栏直接填卷二十四的三个通用动词，“子类型为本行”（指事件类型行，不是动词），并删去全部演出始末动词行，不登记子类型动词。
- 按卷二十四的定义，演出开始事件的 `kind` 会等于通用动词本身。订阅方无法按 `kind` 把演出和别的活动分开，`perceivable/senses/visibilityAllowed` 等表 B 必填项也找不到所属的行。
- 改法：卷二十三登记三个子类型动词行（补表 B 必填项）填进这三栏；本卷不作发出者。

### 4. `comp_adornment` 没有 `enables attach`，固结附件规则管不到它
- 卷三乙 §4.14.1（:1510，f7febe17）按“组件类 `enables` 含 `attach`”判定附件，并举卷二十三 `comp_adornment` 为例。可卷二十三 §2.5 组件行（:199）只写了 `requires coverShare`、不带 `fitsSlot`，没写 `enables`（对照：`comp_attachment` 写了 `enables attach`，卷三乙 :1508）。
- 按现文，装饰件不被判为附件，`canAttach`、`item-attach.mjs` 的固结分支、G-5 不可拆、随宿主终止都不适用于它。R23-2.1 与 C23-2 ② 依赖的前提不成立。
- 改法：组件行补“enables `attach`”。

### 5. 卷八b `bountyPost`、`bountyClaim` 两个动词悬空
- 卷八b §2.6 `law.roles.verbs`（:290）仍列这两项，可本卷已无写入口，发布、交差走卷二十四的告示动词与交差动作。全书再无发出者和读者，与 R24-1.3“每个动词行登记恰好一个发出系统”不合。
- 勘误者已在卷八b 勘误说明里自记为“记账，未改”，但这是 T7 合一的直接残留，按“收卷前清同类”不宜留账。
- 改法：删去两项（或注明已退役）。这超出了裁定所列的四条加入口表，须报李白补批一行。
