## 二、判据与解析口径

1. 来源有三处：① 卷二 §2.7 `state-owners.json` 示例里的 `stateKeys.<键>.writers`；② 各卷正文的写者表，即表头同时有"写者/模块"列和"状态/路径/写什么"一类状态列的表，取写者列里的 `.mjs` 模块与状态列里的 state 路径；③ 仓库里的 `state-owners.json`，查无此文件。
2. 写者列没有 `.mjs` 的行（如"卷二登记的持有写者""只经转移"）是引用别处的写者，不算声明。只在说明栏顺带提到的 state 键，也不算声明。
3. 路径归一：去掉 `state.` 前缀；`[x]`、`<x>` 段记为 `*`；只写顶层键的记为整键 `X.*`。
4. 判失败的条件：同一条归一路径，声明来自两卷以上，并且写者模块（按文件名计）不止一个。下面两种情况不判撞键：
   - 同一模块被多卷引述，例如卷二十六引述 `status.mjs` 写 `state.statuses`。
   - 同一顶层键下的不同子路径各有写者。按卷二 §2.7"路径模式匹配语义"，最具体的模式优先，这是合法分工（例如 `created.*.props.*` 归 dimension-writers，`created.*.props.parent` 另有建行写者与改写写者）。

## 四、局限

- 只抓表格形式的写者声明。如果写者只写在条款正文里（例如"由 X.mjs 写 `state.Y`"），本次抓不到。
- 表头里状态列的名字按现有各卷用法列举（状态、状态路径、路径、路径模式、模式、写什么、被写的东西、运行态路径）。以后哪卷换了列名，要补进脚本。
- 子路径与整键之间的覆盖关系（例如别卷对 `X.a` 的声明落在某卷的整键 `X.*` 之内）按"最具体模式优先"不判撞键。卷二条文如果另有规定，判据随之改。
