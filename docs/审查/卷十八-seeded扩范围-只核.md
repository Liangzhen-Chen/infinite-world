## 二 真问题

1. **婚姻、情人所在的种类行写不上 `origin`。** `rel_spouse` 与 `rel_wed` 都是 `consent: regime`，`kind: hk_kin`（:168–169）；`rel_lover` 是 `consent: mutual`，`kind: hk_bond`（:170）。可是 `hk_kin` 的 `termsKeys` 是 `["rel","adoptive"]`（:565），`hk_bond` 是 `["rel"]`（:566），都没有 `origin`。这样卷十 R10-4.10 带来的开局婚姻边写不上 `seeded`，跟 R18-1.5 自己“`termsKeys` 须含 `origin`”的要求矛盾，也跟 §5.2 :1323“开局婚姻记 seeded”矛盾。再者，R18-1.5 末句的“凡会被生成路径带来、又本应要求同意的种类行”没法从行上静态判断。建议改成静态整类条件：`concluded` 为真，或者有 `consent` 不是“不需同意”的关系条目以它为 `kind`，这样的种类行 `termsKeys` 必须含 `origin`；缺了就在加载时报错（并入 E-HK-PROTOCOL）。数据块里 `hk_kin`、`hk_bond` 按这个条件补上 `origin`，§5.2 的列举也随改。（`hk_guardian_of`、`hk_companion` 所带的条目都是 `consent: none`，不用补。）
2. **关系条目的 `consent` 落在史实记录上时，没有地方记 `seeded`，需要新增一个字段。** 婚史记录 `state.relationFacts[factId]`（:462）只有 `consentAct: EventId nullable`，没有 `origin`。开局婚姻会同时带来婚姻边和 `rel_wed` 婚史记录（`record: "rel_wed"`，`consent: regime`）。裁定写的是“边或关系条目统一记 `origin`=`seeded`”，但这条记录现在只能留一个空的 `consentAct`，不能表示前史缔结。**要加的新字段只有一个：** 在 relationFacts 记录结构里加 `origin: enum edge_origin nullable`。规则是：`consentAct` 为空、而条目要求同意的记录，`origin` 必须为 `seeded`。A18-1.8 也要把史实记录写进去，同样要求建立在生成或物化路径事务内。
3. **本卷还有两处窄版残留，和例外直接冲突。** 一处是 E-REL-CONSENT（:279）：“写入一条须同意的关系时 `consentAct` 查不到对应的同意事件”就报错，没有排除 `seeded`。另一处是 A18-5.4（:863）：“每条 `consent` 不取‘不需同意’的现役边，`consentAct` 都能查到一个双方同意的事件”。照这两处，开局记 `seeded` 的婚姻边会报错或者断言失败。两处都要改成引用 R18-1.5：`consentAct` 非空，或者 `origin` 为 `seeded`。
