## 二、李白条件 2 的两条

### 1. 回应通道（卷二 §2.9 第 0 条，L679–695）

| 环 | 调用 | 凭什么可调 | 核对 |
|---|---|---|---|
| 1 | `router-caps.mjs` → 入口处理函数 | 能力对象回调（`RequestCap` 经 `mountMenuEntry`/`mountInput` 交入） | kernel 不 import inputEdge；矩阵 kernel 行 L547 只有自身 |
| 2a | `menu-entry.mjs` → `postReply` | kernel 组内 import | 同组 |
| 2b | `input/http-entry.mjs` → `postReply` | kernelApi L498 `callerFiles` 仅此文件；矩阵 L550 写明 | 合规 |
| 3 | `reply-channel.mjs` → 订阅函数 | 登记回调；`onReply` L499 只对 `output-gate/reply-composer.mjs` 开放；矩阵 L552 写明 | 方向反转靠回调，kernel 不 import outputGate，**无反向 import** |
| 4 | `reply-composer.mjs` → `respond` | outputGate 组内 | 文字只在这一环出现 |
| 5 | `envelope-exit.mjs` → `ReplyCap.send` | 能力对象（经 `mountOutput` 交入） | 与 L711 交付对象一致 |
| 6 | `router-caps.mjs` → 客户端 `net.mjs` | HTTP | 与通道表 L667 一致 |

- 前四环交出的类型只有 `unknown`、`ReplyHandle`、`ReplyResult`、`responseId`，不含 `Text`/`Sealed`；`ReplyResult` 无文字字段（L680），kernel 可持有。
- inputEdge 与 outputGate 互不 import（L550、L552 对应格为空），kernel 行除自身外为空。
- 删输入边后只少 2b 环，菜单通路不依赖 inputEdge（L695）。
- 结论：这条通路成立。遗漏 save_export 一条路由，见 X1。

### 2. 子串函数签名表与 `TurnText` 来路（卷二 §2.9 第 6 条，L900–922）

- 签名表恰三个函数，都在 `gate/matcher.mjs`，与 `groupApi` L519–521 一致。`matchBlocklist`、`matchIdLeak` 没有 needle 形参；`containsCodePoints(turn: TurnText, quote: AiQuote)` 两个形参都是从 `RawText` 直接品牌化出的专用类型（L795–796）。labels 的值类型是 `Text`（L758），传不进任何 needle 位置，**类型上挡住**；`BlockNeedle` 与 `Text` 互不相容，gate 不能 import labels（L513）。
- `TurnText`：唯一产出者 `brandTurn`，只对 `input/http-entry.mjs` 开放（L505）。aiGate 中带 `TurnText` 形参的入口只有 `interpret`、`narrateTurn`，都只对该文件开放（L526–527、L550）。位置规则（L795）禁止落到模块级变量、属性或返回值上。`matchQuote(q, q)` 是类型错误（L921）。
- 试过一条洗白路径：在 http-entry 里把 labels 的 `Text` 赋给 `unknown` 变量，再 `narrow` 后 `brandTurn`。这条路被 §2.8 第 4 条的位置白名单挡住：`Text` 只能赋给同品牌目标，赋给 `unknown` 即违例。来路闭合。
- 结论：两点都由类型和 `groupApi` 卡住。L848 有一处旧说法残留，见 X2。

## 三、新真问题（需报李白）

### X1【新真问题，需报李白】save_export 路由在回应通道之外，`ReplyHandle` 没有来路（类 4、5）
- 位置：卷二 L661、L668（`wire_route` 三个值，含下行 `save_export`）；L711（`ReplyCap` 交 `kernel/save.mjs`，`RequestCap` 只交 menu-entry 与 http-entry）；L680（`ReplyHandle` 每次请求一个，由 router-caps 生成后交给入口）；L685–691（第 1 环只列 `menu` 与 `input`）；L694（同一句柄回应两次，或 `postReply` 的调用者不在第 2 环，都算 E-WIRE-REPLY）；L774（出口表 save.mjs 行"经 `ReplyCap`"）。
- 问题：第十四版规定 `ReplyCap.send(reply, body)` 必须带 `ReplyHandle`，而句柄只经 `RequestCap` 交给两个入口。`kernel/save.mjs` 拿不到任何句柄，存档导出发不出去。如果改成由菜单动作触发，同一句柄就要被 `postReply` 和 save.mjs 各用一次，正好违反 E-WIRE-REPLY。第十三版没有句柄概念，这个缺口是本次加入 `ReplyHandle` 时带出来的。
- 建议：在第 1 环补 `save_export` 路由，入口为 `kernel/save.mjs`（`RequestCap` 交付对象加它）。另写一环"save.mjs 直接经 `ReplyCap.send` 发字节，不经 `postReply`"，E-WIRE-REPLY 对这一路另列一条判据；S19 与脚本第 29 项同步改。

### X2【新真问题，需报李白】起名第 2 步仍写 http-entry 调 `brand`，与 `groupApi` 相反（类 5）
- 位置：卷二 L848"`input/http-entry.mjs` 把文字 `narrow` 成 `RawText`、`brand` 成 `Text`"；L609（§2.8 inputEdge 行"编号表…由 textcore `brand` 标记"）。对照：L504 `brand` 的 callers 只有 textcore、gate、aiGate；L550 矩阵 inputEdge 行 textcore 格没有 `brand`；L696、L761、L916 写的是 `brandTurn` → `TurnText`；L830 写编号表的键由 `menuIndexKeys` 生成。
- 问题：按 `groupApi` 写成的门禁会把 L848 写的做法判为 E-VIEW-INPUT-IMPORT。第 31 项"旧签名无残留"也没有查到这一处。
- 建议：L848 改为"`brandTurn` 成 `TurnText`（可当 `Text` 用）"；L609 改为"由 textcore `menuIndexKeys` 生成"。只改措辞，不动机制。

### X3【新真问题，需报李白】`narrateTurn` 只能从输入路由调用，菜单回合没有 AI 叙述的入口（类 4）
- 位置：卷二 L527、L550、L918（`narrateTurn` 只对 `input/http-entry.mjs` 开放）；L920（"没有玩家键入文字时的后台叙述"，但全文没有写它由谁调用）；L685–690（菜单请求进 kernel，回应交 outputGate，两者都不能 import aiGate）。对照卷一 §7.2 L592：R2 叙述在第七层，输入是"已 committed 回执"，与有没有键入文字无关。
- 问题：开着 AI、只用菜单玩，或删掉输入边（G4）时，没有任何合法调用链能触发 R2 叙述；L920 举的"后台叙述"也找不到调用者。名字本身没有冲突，问题在调用范围：现在叙述绑在输入边上，与卷一 R2 的定位不符。
- 建议（二选一，由李白定）：① 叙述入口不带 `TurnText`，另设 `narrate(result: ReplyResult)`，经装配文件以能力对象注入 `reply-composer.mjs`，写法与 `PromptRenderCap` 对称；`narrateTurn` 只保留"带本轮原文、可带引文字段"的那一种。② 明确写成"AI 叙述只在输入路由发生"，并在卷一 §7.2 和卷九对齐。何时调用仍归卷九。
