- 【v8 改】实际覆盖率 cov = 探针输出的**池覆盖率**字段 poolCoverage = Σ holdActual ÷ Σ holdTarget（同一可食池、同一口径，含粮仓燕麦当量、货架与居民在售，按饱腹）。`granary.coverageOfReserve`（只含粮仓）降为只记录，**不参与**夹具判定、组内排序、R1、R2、R6。**缺口越大 = cov 越小**，缺口的排序只按实际 cov，不按名义档位；cov 并列时按名义档位从大到小排。夹具设定：探针设粮仓持有 = level × Σ holdTarget（池内其它固定持有，如货架，另加，故池 cov = level + 固定持有 ÷ Σ holdTarget，见 R5⑤）。【v8 改】理由：v7 的 cov 取粮仓一项，与定价实际读的池口径不同（市场判定 R1 审查 B3），"cov 1.0 时稀缺度约 1"只有在池口径下才成立；因此 R1 基线只看实测的 relPrice，不假定设计值。
- **advance 与行的对应**：cell 行里没有数值 advance 字段，由 phase 推出：phase=before-advance 即 advance=0；phase=after-advance 即 advance=其 `advance.days`，该值必须为 8（测试设计参数，冻结前定：略多于 famine 钟 intervalDays 7，rules.json:8807，使钟至少检查一次，见"档位与参数"），否则该行记"夹具不可信"。start 行（含 limits）与 cell 行按 case 名关联；同一次运行的 before 行与 after 行按 case 名、pairKey、**mode** 三者一并关联（pair 情形里同一 case、同一 pairKey 下有 with、without 两份）。
- 档位 level 是名义值。**夹具不可信**（分两类行，口径不同）：
 · advance=0 行（before-advance，设定值即实际值）：所属 case 的 after 行 fixtureUntrusted 非空（before 行本身没有该字段，由 after 行继承，一并记不可信），或 |cov − level| > 0.25×level（cov 为池 cov；0.25 是测试设计参数，冻结前定、非世界数据，理由见"档位与参数"），或 level>0 而 cov ≤ 0；
 · advance=8 行（after-advance）：cov 已被 8 天消耗改变，名义档位不再适用，**不查 |cov − level|**；只查 fixtureUntrusted 非空，或 level>0 而 cov ≤ 0（仓已见底、该行不再反映缺口梯度），或对应 before 行不可信。
 不可信的输出记"夹具不可信"，不作规律证据，不得判通过，修夹具重跑。
- 相对容差一律 1e-9（与探针 pairRun 里 close() 的容差一致）。**"相等"**：|P_a − P_b| ≤ 1e-9×max(|P_a|,|P_b|)。**"上涨"**：P_a 大于 P_b 且不相等。**"不下降"**：P_a 上涨或相等。**"下降"**：P_a 小于 P_b 且不相等。
- **"在顶"**：ratioClamped 与 start 行 `limits[1]`（现为 3）相等（容差同上）。**"在地板"**：atFloor 为真，或 ratioClamped 与 `limits[0]`（现为 0.5）相等。两个界限只读 start 行的 limits，不在规则里写死数值。
- **组**：分组键 = (settlement, season, phase, item)（上文取行范围内、mode 为 without）；**不按 pairKey 分组**——pairKey 含档位，档位只是组内的成员，同组跨档位。组内全部可信输出按实际 cov 从大到小排成 o1、o2、…、on（n 为组内可信输出数）；phase 即 advance（before-advance=0，after-advance=8）。"相邻对"指 (o_i, o_{i+1})，后者缺口更大。
- **封顶与触顶缺口区间**：组内从缺口小到大看，第一个"在顶"的输出记为 o_k，从 o_k 起连续在顶的输出组成封顶段。**触顶缺口报区间**：上一档 o_{k-1}（不在顶）与 o_k 之间——"从 cov(o_{k-1}) 到 cov(o_k) 之间开始顶住"，写出两个 cov、两个名义档位与对应的缺口 1−cov；o1 就在顶（k=1）则写"不晚于 cov(o1) 顶住，更小缺口无数据"。组内没有在顶输出，记"未封顶"。封顶段内**只受 a) 约束**（不下降），价格相等或微升都不判不通过，仅记录；封顶段之后若又出现不在顶的输出，按 R2 a) 逐对判，不另作推断。**封顶不算不达标，但必须报告触顶缺口区间。**
- **封底与离底缺口区间（下限对称）**：组内从缺口最小的 o1 起，连续"在地板"的输出组成封底段，段内最后一个记为 o_j。**离底缺口报区间**：o_j 与下一档 o_{j+1}（首个不在地板）之间——"从 cov(o_j) 到 cov(o_{j+1}) 之间离开地板"，写出两个 cov 与档位；封底段延伸到 on（整组在地板）则写"缺口至 cov(on) 仍在地板，未离底"；o1 不在地板则记"未封底"。封底段内只受 a) 约束，相等或微升只记录；封底段之后按 R2 a) 逐对判。**封底不算不达标，但必须报告离底缺口区间。**
- 价格方向的唯一判据是供给、需求、供需比的变化方向与来源；不与任何旧倍数的数值（1.1 到 1.6、季节系数等）比较，不要求接近，不得把旧倍数当期望。

## 规则（机械可判）
R1 冬荒高于平时【v8 改】（无倍数，winter 矩阵 advance=0）：对两个聚落、四个物品逐个。冬季取可信的、cov < 0.5 的所有输出（矩阵里为 level 0.4、0.2、0.05；0.5 是测试设计参数：缺口超过一半；【v9 改】v8 曾以 famine 阶段条件 45 ÷ reserveDays 90 = 0.5 作出处，该条件现读 foodStockDays（池持有 ÷ 餐口），不再与池 cov 同尺度，那条推导作废）；基线 = 同聚落、同物品、**平时（秋，season 字段为 normal）、advance=0、level 1.0** 的那一个输出，只此一个，且须可信。基线在顶或在地板，该物品记"不可测"，**不得改取其它输出**。冬季没有可信的 cov<0.5 输出，也记"不可测"。成立条件：①**基线恒等式**（比值形式，浮点容差 1e-9）：基线输出的 |relPrice ÷ (scarcity × quality × depth × spread × relation) − 1| ≤ 1e-9（字段名取 explanationParts 实际字段；listPrice = 目录基价 × environment × 这五项之积，regionalBase = 目录基价 × environment，故 relPrice 恰为这五项之积；若 explanationParts 里有加性修正项（value.contributions 与 price.contributions 各项的数值字段，探针原样输出并求和为 additiveSum），恒等式改为 |((listPrice − additiveSum) ÷ regionalBase) ÷ (五项之积) − 1| ≤ 1e-9；基线行若有加性项，R1 记"不可测（有加性修正）"，不得判通过），且 scarcity = clamp(holdTarget ÷ holdActual, limits)（R3 补充条）；非稀缺项必须等于目录派生值：quality = 引擎 marketGrade 对该物品目录品质的返回，spread = 商号 markup 夹取或 rules 的 spread.buy，depth = 1 + depthImpact × net ÷ opening（未成交时为 1），三者由探针经引擎同一函数另行输出为 qualityExpected、spreadExpected、depthExpected，与 explanationParts 实测值相对 1e-9 相等；relation 取实测值并记录来源（standing），**不设"偏离上限"**（relation 是买方身份修正，由 R5②、R4②、R9④ 比去 relation 分量并单独记录，不在此处设阈值）；不满足 → R1 记"不通过"，分诊实现缺陷（价格里有未登记的因子）；基线稀缺度与 1 的接近程度（设计含义 cov≈1.0 → 稀缺度≈1）只记录 scarcity 与 poolCoverage；②每个冬季输出的价格 P 都**上涨**于基线价格（严格大于，相等不算）。冬季输出在顶的不因此判不通过，但按"封顶"口径报告其触顶缺口区间；冬季输出在地板则不通过（缺口大的一端不可能在地板）。【v8 改】理由：基线覆盖率取 1.0，依据是设计含义"正常年平时库存约等于储备目标"（reserveDays 90 即聚落平时要备的天数），稀缺度 = 1 在 [0.5, 3] 正中，不在地板也不在顶；v7 取平时最大 cov（1.5，盈余端）作基线，必落地板，回退又落在顶。①用比值恒等式而不是"各偏离量之和"：价格是各因子之积，求和会漏掉交叉项而误杀正确实现；非稀缺项的取值是世界数据，规则只核对"等于目录派生值"，不凭空给阈值。
R2 越缺越贵（无倍数；winter 与平时各自判；advance=0 与 advance=8 各判一次；按组判）：每组至少 3 个可信输出才判，否则"不可测"。组内逐个相邻对 (o_i, o_{i+1})（o_{i+1} 缺口更大）依次检查：
 a) **不下降**：P(o_{i+1}) 不得下降于 P(o_i)；不管缺口多大，任何一对下降即该组不通过；封顶段、封底段内同样只受这一条约束；
 b) **未封顶必上涨**：对"不是两者都在顶、也不是两者都在地板"的相邻对（含 o_{i+1} 不在顶、o_i 不在地板的所有对），要求 P(o_{i+1}) **上涨**，相等即该组不通过；两者都在顶或都在地板的相邻对不要求上涨也不要求相等（只记录价格是否相等）；
 c) **封顶与封底单记**：每组必须在报告里写出触顶缺口区间（或"未封顶"）与离底缺口区间（或"未封底"），封顶段、封底段本身不算不达标；
 d) **整组封顶或整组封底**（所有输出都在顶，或都在地板）：没有任何一对可检查上涨，记"整组封顶/封底，不可测"，不得判通过。此类结果预期会出现（缺口大的档位集中在顶），属预期的"不可测"，不是缺陷，也不得因此改判通过。
 e) 【v8 新】**梯度可测**：每组须至少有 3 个可信的"内部输出"（既不在顶也不在地板），且内部输出按组内排序取子序列，子序列内相邻的输出满足 a)、b)；内部输出不足 3 个的组记"梯度不可测"，不得判通过。（3 是测试设计参数，冻结前定、非世界数据：3 个内部输出 = 两对相邻内部输出，使 b) 在无悬崖的区间内被检验至少两次；档位个数 7 与 advance=8 的设计见"档位与参数"。）理由：v7 验收里 32 组全靠"地板 → 顶"一步通过，b) 只被一对检验，等于没检验到渐变。
 f) 【v8 新】**连续性与独立量检验**（防"单调但跳变"，也防非稀缺项随持有悄悄变化）：①R2 的全部可信输出（不只基线行）：quality、spread、depth 必须等于探针经引擎同一函数输出的目录派生值 qualityExpected、spreadExpected、depthExpected（相对 1e-9）——这是"价格只由稀缺度变化"的机械判据；relation 取实测并记录，不设阈值（买方身份修正，见 R5②）；②对内部输出子序列的每个相邻对：|(relPrice_{i+1} ÷ relPrice_i) ÷ [((holdTarget_{i+1} ÷ holdActual_{i+1}) ÷ (holdTarget_i ÷ holdActual_i)) × ((quality、depth、spread 的目录派生值之积)_{i+1} ÷ (…)_i) × (relation_{i+1} ÷ relation_i)] − 1| ≤ 1e-9。手推的稀缺度之比**只用探针输出的原始持有量 holdTarget、holdActual**，不用引擎算好的 scarcity 字段；非稀缺项用目录派生值而不是 explanationParts 实测值，所以这是对独立量的检验，不是引擎自除自；内部输出不夹取、不取整，没有已登记的离散来源，容差只有浮点 1e-9；若 contributions 非空，按 R1 ① 的加性项口径先扣除。理由：relPrice 恰为 scarcity × quality × depth × spread × relation 之积，scarcity 又由持有量之比决定（R3 补充条）；价格跳变、或非稀缺项随持有悄悄变化，都会使左边偏离右边。用乘积而不用"各相对差之和"，因乘积展开有交叉项，求和会误杀正确实现。
 组内全部相邻对满足 a)、b)，c) 已报告，且 e)、f)【v8 新】满足，该组通过。
R3 稀缺度同向（不含待替换项情形）：无倍数，winter 矩阵按 cov 相邻输出，及 drought、flood、bs-tight 的 series 按相邻两天，对同一物品：若 ratioClamped 上升则 relPrice 不下降；下降则不上升；相等则 relPrice 相对差 ≤1e-9。
 【v8 新】R3 补充条（公式一致）：每个 cell 行、每个物品：scarcityRaw = holdTarget ÷ max(holdActual, poolWeight)（相对 1e-9；分母保护见下一条登记；holdActual 为 0 的行见 R10），ratioClamped = scarcityRaw 夹入 [limits[0], limits[1]]，且 scarcityCap 等于 limits[1]。理由：李白批准的修法把稀缺度定义为这个比值，需要一条机械核对实现与定义一致，且读的是持有量字段，不循环读 ratioClamped。设计预期点只供审查，不另判：cov 1 → 1，cov 1.5 → 约 0.67，cov 0.5 → 约 2，cov ≤ 约 0.33 → 顶（以物品的 holdTarget、holdActual 为准，若物品持有口径与粮仓 cov 不同则预期点随之改读）。 另：holdTarget、holdActual 必须取自引擎同一报价调用的返回，不得由探针独立重算（否则本条自证）；holdActual 为 0 的行见 R10。
 【v9 新】**登记离散来源——分母保护 max(1 件, 供给)**：引擎把稀缺度算成 clamp(需求 ÷ max(1, 供给), limits)，需求与供给都以报价货的件数表达（饱腹单位持有量 ÷ poolWeight），故在饱腹单位上分母保护为 max(holdActual, poolWeight)（一件货的折算量）。位置：market.mjs:391（marketQuote，报价与成交）、market.mjs:379（liquidationValue）、market.mjs:169（质押估值）与 currency.mjs:65-66（贵金属估值，denominator = 供给 > 1 ? 供给 : 1，同一保护）。它是引擎公式的一部分，不是容差：holdActual ≥ poolWeight 时不起作用（R1、R2、R6 的恒等式与夹具都在这一段）；holdActual < poolWeight 时 scarcityRaw = holdTarget ÷ poolWeight，ratioClamped 仍夹入 limits。R3 补充条与 R10 引用这一位置：恒等式里的 scarcity 一律读作 clamp(holdTarget ÷ max(holdActual, poolWeight), limits)。【v9 改】理由：v8 的 tiny-hold 4 行按字面不满足（scarcityRaw = holdTarget ÷ poolWeight 而非 holdTarget ÷ holdActual），是规则漏登了引擎公式里本来就有的分母保护，不是价格错误（价格因夹入上限而不受影响）。
