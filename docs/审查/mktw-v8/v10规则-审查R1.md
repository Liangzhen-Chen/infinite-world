## 三、新表达能否机械执行
可以。
- 引擎实现与规则文字一致：food-stock.mjs 的 `shortThresholdDays(d,engine,place,days)`：农事聚落（在 `rules.agriculture.settlements` 里）返回 `days / reference * own.reserveDays`，非农事聚落返回 `days / reference * resupplyDays(...)`，其中 reference = `farm[0].reserveDays`；seasonal-hazards.mjs 的 `granary_short` 分支用 `value < threshold`（value = foodStockDays）。规则写"规则 days ÷ reserveDays × 本聚落储备视野"，与代码的 `days / reference * 视野` 同式。
- 探针输出字段 13 新增 `threshold`，判定者直接读它，不需要自行换算。
- 小提示 N-1（可选）：规则写的"÷ reserveDays"在代码里是 `farm[0].reserveDays`（loc_hw 的 90），不是"该聚落自己的 reserveDays"；四个农事村与 hw 的 reserveDays 都是 90（rules.json:5663、5698、5755、5812、5869），所以没有差别。若以后有聚落的 reserveDays 不同，两种读法才会分叉。建议在第 121 行补"分母取农事档案首项的 reserveDays（现为 90）"，或在闸门处写"以探针输出的 threshold 为准，并断言 hw、yupo、sangban 的 threshold = 45（famine）、90（tight）"。这样 reserveDays 将来变动时，闸门不会悄悄漂移。

## 四、hw、yupo、sangban 的闸门仍为 45
