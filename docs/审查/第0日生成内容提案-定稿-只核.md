## 真问题

**T1 裁定一 ② 要求“写进性能门槛”，但牵连清单里没有落点。** §11 推出了 `state.enacted ≤ P_max × C_max`、聚合体个数 `|S_U|×(1+L_f)×(|F_U|+1)×2`、住处行数不增三项上界，并写明“照卷二十七 R27-3.9、R27-3.10 的登记写法”。可是 §9 卷二十七两行只列了 pathTypes、R27-2.2 出生键和 `settleOut`，没有“卷二十七 §4.x 新增上界登记条（与 R27-3.9/3.10 同位：只登记上界，成本式不改，标定时作基线实测）”这一项。照现稿派正文，上界就只留在提案里，进不了性能门槛。改法：§9 卷二十七补一行，列出这三项上界的登记条。

**T2 §11 第 1 项给 `rules.gen.skeleton.levels` 加的取值域限制前提不对，是多出来的设计，而且没进 §9。** 原文说“无 `clamp` 的 normal、lognormal 不许用”，理由是要让 `max(children_L)` 有限。但卷二 §1.10 :272 规定 normal 分位数表在 j=0 与 4096 处钳为 ±3.9000，所以 normal 上端恒为 `mean + 3.9·sd`，lognormal 上端恒为 `exp(mu + 3.9·sigma)`，不加 clamp 也有限（之后还要按 precision 截断再 clamp）。这条限制既不是推出上界的必要条件，也改了卷十已登记键的取值域（卷十 :153），却不在 §9 卷十行里。改法：删掉这条限制，`max(children_L)` 按“各分布族的上端”写（uniform/triangular 取 `max`；normal、lognormal 取 clamp 上限与 ±3.9 分位的较小者；categorical 取最大键）。只读已登记参数，不改取值域。

**T3 统计层入籍流（裁定三）没有照 R7-9.4 写全，目标组织取不到唯一值。**
- R7-9.4 :766 是“对统计层的**每个地点**、每对（桶，目标）”取 `flowRows`，固定刻求值（:424 钩子），余数存登记过的状态路径 `state.conversionRem`。
- 提案 §2.3 代价 3 写的是“目标组织取该单元现时的主权组织（`governorOf` 给出的组织沿 `realm` 上溯）”。但 `governorOf` 的入参是地点（卷八 :408、R8-5.1），而提案 §2.1 自己就指出一个单元可以跨多个落位政区。所以“单元的主权组织”不唯一，开局阶段为此用了主份规则，这里却没有给。
- 固定刻用哪个钩子、余数存在哪条状态路径（名称、写者），提案都没写，§9 卷八b 行也只写了“§4.14 加新流”，没有状态路径和钩子。
- 改法：照 R7-9.4，改为“对统计层每个地点 p：桶取 p 所在单元内 `citizenOf` 键为空的成员，目标取 `governorOf(p).org` 沿 `realm` 上溯所得主权组织”。另外写明钩子和余数状态路径（如 `state.naturalizeRem`，写者 estate 侧），并补进 §9 卷八b 行。
