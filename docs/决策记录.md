# 决策记录

## D000 阶段 0 的失败测试

指南 0.3 要求阶段结束全部测试通过，13 章又明确要求阶段 0 回归测试失败。阶段 0 保留 npm test 的真实失败，同时用 test:baseline 核对缺陷编号和失败清单；此项明确记录为阶段 0 例外，阶段 1 后不得沿用。这样提交历史保留修复前后的证据。

## D001 原版保护与部署

原版 core.js、index.js 与种子放在 tests/fixtures/legacy。阶段 1 之前不替换运行中的扩展；重构源代码写在 extension 和 server-plugin，部署脚本必须先备份并保留回退目录。

## D002 DeepSeek 验证边界

不读取已有密钥文件。阶段 0 抓取酒馆浏览器请求，并用已安装后端的真实转换函数向本地接收器发请求，核对出站 thinking 字段。不会把这种本地传输测试称为真实 DeepSeek 模型测试。后续模型测试与批量生产仅从 DEEPSEEK_API_KEY 环境变量取凭据；缺失时记录未执行，继续独立开发。

## D003 新旧回归测试

阶段 0 的原版断言永久保留在 tests/baseline，test:baseline 显式执行并继续证明 23 项失败。新版接口用永久编号和单一职责工具，新的 engine/storage/retrieval/runtime 测试逐项覆盖相同行为，npm test 执行新版测试。不能为通过测试恢复不安全的 world_commit 或按显示名存储；对应关系写入进度。

## D004 重放与世界版本

日志保留语义命令与补丁，删除早期事件后必须重新执行语义命令，否则后期补丁会带回旧的绝对余额。每个战役引用世界内容的 SHA-256，原世界存放在独立归档目录，导出时附带所需的世界版本。旧战役不读取新世界的人设或规则。

## D005 阶段 1 的最小内容种子

现有 18 人和已有物品先建立永久编号及兼容数据，用于引擎验证。没有把这些最小目录称为完整世界内容；人物扩充和未知年龄的详细核实留到阶段 3。装备、属性及法术平衡留到阶段 2。旧档生命与魔力原值保留，新增属性初始化为 10。

## D006 分阶段源代码与在线部署

第13章阶段1的退出要求为新版测试、性能和旧档迁移，并未要求先交付最终界面。阶段1冻结可部署源包并在隔离目录验证，在线暂保留旧扩展，阶段6统一接入。实际激活时先备份，独立快照包避免后续开发修改正在运行的插件；回退需保留新版战役后恢复旧扩展与聊天备份，不能把格式2引用交给原版引擎。

## D007 自动世界版本更新

每次打开战役核对发布世界的内容哈希；差异以无聊天锚点的语义迁移事件执行，前置便携备份。既有编号与称呼保留，动态字段与旧版初始值一致时才更新，否则列入世界更新记录并保留。删除更早事件后重新判断冲突。导出包含迁移前后所用归档，回退使用更新前便携备份导入独立战役。
