## §0 卷首

### 0.1 范围

本卷定义“谁和谁是什么关系、谁怎么看谁、这些关系怎样形成、转移和消失”。共十二个子系统：持有种类表与两条转移协议（种类部分）；家户、亲属、婚配、继承、分家、监护；家族与传承；立场数轴；关系、记忆、认知与谎言；舆论与群体行为触发；威望、名望、名士与荣誉；阶层流动；婚配制度、性风俗、儿童与老人；外来者待遇与立场基线；恐惧值；社交互动、斗殴与相容性。

不在本卷：

- 持有边的结构、写者与终止五步：卷二 §2.6（写者与三接口）、卷二 §2.7（系统声明表）。本卷只定种类表。
- 组织的统一结构与 orgKind 词表族：卷八 §4.1（组织统一结构）。家户与家族是组织行，本卷只登记两条 orgKind 条目并定义家户、家族特有的规则。
- 合同状态机与义务种类表：卷六 §4.16（合同状态机）。婚约、监护、赡养只登记种类行。违约与救济：卷八b §4.15（民事与救济）。
- 入籍的资格与事件、身份等级的取值：卷八b §4.14（身份等级与入籍）。本卷只定外来者待遇、立场基线和流动的触发。
- 已知事件集合、推断、传闻失真、秘密：卷二十二 §4.1（主观视图）、卷二十二 §4.3（推断）、卷二十二 §4.4（传闻）、卷二十二 §4.7（秘密）。
- 人格、价值的定义与心情：卷二十六 §4.1（人格向量与联合分布）、卷二十六 §4.4（想法与心情）。年龄、成年、生育力：卷四 §4.4（年龄、成长、寿命、出生与死亡率）。
- 遭遇与谈判的结算流程、战功快照、决斗：卷十三 §4.18（遭遇与谈判结算）、卷十三 §4.19（战功）、卷十三 §4.11（决斗）。
- 影响力（政体层非金账户）：卷八 §4.19（影响力）。

## §1 领域总述

### 1.1 真实世界怎样运转

1. 人的身份几乎都是关系：某家的孩子、某人的配偶、某行会的成员、某地的居民。关系有起止时间，一端消失时另一端要有着落。
2. 亲属制度因地而异，但都在回答同几个问题：孩子归哪一边、婚后住哪里、可以有几个配偶、近亲到几等不能通婚、谁先继承、怎么分。
3. 一个人对另一个人的看法由三类东西叠加：两人是谁（文化、信仰、亲疏）、对方做过什么（事件，会淡忘）、对方属于谁（爱屋及乌）。
4. 名声可以积累也可以花掉；家族的名声比个人的寿命长。
5. 害怕和喜欢是两回事：人可以因为害怕而服从一个自己厌恶的人。
6. 孩子和失能者要有人照管；未成年人不进入婚配与亲密关系。这条在各文化里年龄线不同，但都有下限。

### 1.2 本作现状

- 立场有单一读模型，但 18 个文件直接调写入函数，旧存储仍有 7 份；立场档位用中文键名加手填常数。
- 家户与亲属只有一套制度；状态、监护账目种类、关系类型都是中文字面量。
- 记忆流被 22 个模块直写；认知与谎言靠对记忆文字做正则。
- 声望、名士各自定义清醒判定；名士状态与丑闻种类是中文；举荐靠对理由文字做正则。
- 威慑直接导入一份平衡表；首领谈判用中文状态加睡眠正则。
- 舆论有聚合投影，没有群体行为触发。

### 1.3 本卷的总机制

一切社会事实只落在四样东西上，其余全部派生：

1. **关系表**，分两种存续方式（§4.1.1 单点定义）。**现役持有边**：配偶、成员、户主、监护、名士在册、荣誉，都是带种类的有向边，种类表（§4.1）规定每种边在任一端消失时怎么办。**史实记录**：亲子、婚史是只追加、永久保留的记录，实体终止不关闭它们；继承、户主继任、按亲等破平分、禁婚都读史实记录。
2. **立场条目**：每条记下“观察者因哪一行来源、哪一次事件、在何时，对谁有多少看法”。读数 = 静态来源（由双方维度与关系算出）+ 条目按时间的闭式衰减 + 传导。没有可以直接加减的立场数。
3. **账户余额**：威望、名望是非金资源，只经账本转移变动。
4. **制度行**：婚配制度、继承制度、归属制度是数据行，由文化给缺省、信仰与法律用修正项覆盖。规则只读行上的字段。

家户与家族是组织行；记忆是已知事件集合上的派生显著度；舆论是成员立场的聚合；声望档、恐惧档、待遇档、阶层流动资格都是派生量。

### 3.6 条件类规则的求值时刻（单点定义）

凡是“某个条件由假转真（或由真转假）就做某事”的规则，条件读的又是连续变化的派生量，一律只在**固定刻**求值。固定刻由卷二十 §2.1（规则表 `rules.clock`（调度））登记的 `cadence` 与 `phaseOffset` 决定，即满足 `(minute − phaseOffset) mod cadence = 0` 的刻，见卷二十 §4.1（刻、同刻全序、调度器与到期语义）的“钩子节拍对齐绝对分钟”。本卷为此登记一个钩子（`rules.social.watch.hook`），下列规则共用它：

| 规则 | 条件 | 固定刻上做什么 |
|---|---|---|
| R18-2.6 | 家户人数超过上限 | 提出分家 |
| R18-2.7、R18-9.5 | `dependent` 转真或转假 | 指定或关闭监护 |
| R18-3.5 | 立支条件成立 | 允许提出立支 |
| R18-5.1、R18-5.2 | 关系条目的 `form`、`drop` | 提出或解除关系边 |
| R18-6.2 | 触发行的 `when` | 发群体行为事件 |
| R18-7.5 | 名士列册条件不再满足 | 转除名 |
| R18-8.2 | 流动行条件转真或转假 | 登记或撤销持续期到期项 |
| R18-9.6 | `careDuty` 的条件 | 生成或解除赡养义务 |

三条约束：

1. 条件只在固定刻被发现。两个固定刻之间条件转真又转假，不产生任何后果。由条件派生的到期项（持续期、审定期）自发现它的那个固定刻起算。
2. 固定刻上对哪些主体求值，只由世界内在量决定：主体所在的层，以及该规则在数据上的前置字段是否适用；与推进请求的长度、类别、边界无关。统计层不逐人求值，按 §5.3 的统计形态。
3. 不得在推进请求的边界求值，也不得在“一次推进结束时”求值。因此一次推进 N 天与分段推进合计 N 天，发现条件的刻相同，存档摘要相同。

由事件直接推动的规则（出生入户、终止后的继承、成婚、得知事件后生成立场条目）不属于这一类，仍在事件发生的刻执行。

## §4 子系统

### 4.1 持有种类表与两条转移协议

#### 4.1.1 维度

种类行字段：`hyper: ref vocab holding_kind nullable`（上位词）；`from / to: set<实体模板>`（卷一 §4.1（八个存储概念）的模板名）；`exclusive: boolean`（同一标的至多一条现役边）；`holderEnd: struct{gone, vacated, defected: enum handover nullable}`；`subjectEnd: enum subject_end`；`concluded: boolean`（须经缔结动作成立）；`functional: boolean`（持有者丧失行动能力时边不生效）；`membership / headship: boolean`（算作成员、算作代表人）；`carriesRel: boolean`（边的 `terms.rel` 必填，取 relation 族）；`conduct / conductBack / adopt: number`（立场传导系数，见 §4.4）；`pins: enum pin_side`。

一审后补的列（旧表有而第一版漏迁的，以及新裁定需要的；逐字段去向见 §7）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `intimate` | boolean，必填 | 这种边本身是否属于亲密或人身依附性质；为真即受 R18-9.1 检查，不论是否带关系 |
| `bodyControl` | boolean | 持有者借这条边使用标的的身体（附身、操控）。R18-9.1 据此找“参与的身体” |

| `excludes`、`grantsEntry` | boolean | 这种边把标的排除在持有者的地界之外；这种边给标的进入许可。待遇表只读这两列 |
| `visibility` | enum edge_visibility | 谁可知这条边（公开、仅成员），供卷二十二读 |
| `contest` | enum edge_contest nullable | 互斥标的有多人竞争时怎样裁决（按 `terms.rank`、按骰值键抽） |

`struct:holding_terms`（回填卷二 §1.5（类型清单））= 公共键加各种类登记的键。公共键：`since: integer minute`、`until: integer minute nullable`、`endReason: ref vocab end_reason nullable`、`suspended: boolean`、`consentAct: EventId nullable`。其余键只有列在种类行 `termsKeys` 里才可出现；键的类型登记在一张键表里，谁登记种类谁给类型。本卷用到的键：`rel: ref vocab relation`、`rank: integer`、`share: number`、`scope: 代号`、`phase: 封闭枚举`、`adoptive: boolean`、`honor: ref vocab honor`、`asOf: integer minute`。全部是代号或数值，没有字符串。

**存续方式（单点定义；主会话一审后裁定第 1 条）**。关系条目的 `persistence` 取两个值：

- `active`（现役）：关系落在一条现役持有边上，种类取条目的 `kind`。它随两条转移协议关闭；终止原语关闭的只是这一类。例：婚姻、监护、朋友，以及不带关系的雇佣、拥有。
- `historical`（史实）：关系落在一条史实记录上，不是持有边。记录 `state.relationFacts[factId] = {rel, from, to, since, until: integer minute nullable, endReason: ref vocab end_reason nullable, adoptive: boolean, consentAct: EventId nullable}`，全是代号与数值。只追加；`until` 与 `endReason` 只能由空填写一次；永不删除。实体终止不改它，端点可以是已终止的实体（实体 id 永不复用，仍可查）。它不算持有边，卷二的“不存在指向已终止实体的持有边”不涵盖它。例：亲子、婚史。

现役条目的 `record` 非空时（例如婚姻指向婚史），关系写者在建立现役边的同一笔里追加一条史实记录；现役边关闭时，回填那条记录的 `until` 与 `endReason`。史实条目的 `kind` 不产生边，只表示它借用该种类行的传导系数。

#### 4.1.2 统一入口

读：`holdingKind`；史实记录经 `kinView`、`kinDegree`、`heirsOf`、`related` 读，别处不直接读 `state.relationFacts`。写：种类表是数据，没有运行期写者。边的写入只经卷二登记的持有写者，它在写入前调本节的校验；带关系的边与史实记录只经内核的关系写者（§3.3）。

#### 4.1.3 规则

- **R18-1.1 登记现役**：每条边的种类必须在表里；新增种类只加行并挂上位词。规则按字段或按上位词链判断，不点名种类。
- **R18-1.2 协议甲（持有者一端）**：持有者终止、离任、脱离三种触发，各按 `holderEnd` 对应格的处置执行：关闭、不动、按候补顺序移交、转入承接实体、空出职位、回到授予者、保留实控并立主张、暂停。持有者终止时不得取“不动”。机制与每个处置码的执行语义归卷二 §2.6（写者与三接口）（台账 X-21）；本卷只填列。
- **R18-1.3 协议乙（标的一端）**：标的终止时按 `subjectEnd` 执行。四个取值的含义（提请卷二写进终止第 4 步，取代“以它为标的的边一律解除”；见 §5.2）：关闭；改指后继——标的换成终止第 2 步定出的后继实体，清算模式或没有单一后继时关闭；留在残骸——只有后继模式是残骸时改指残骸实体，其余模式关闭；移到父节点——标的换成它在地点树上的父节点，没有父节点时关闭。四种处置之后都不存在指向已终止实体的现役边，与卷二的不变量、本卷 A18-1.2 一致。
- **R18-1.4 两条协议只由终止原语与持有写者调用**：卷二 §2.6（写者与三接口）的终止第 4 步读本表；领域卷不自写交接。
- **R18-1.5 互斥、上限与缔结**：`exclusive` 为真的种类，新边成立前旧边必须先按协议甲的“离任”格处置；`holderMax` 非空的种类，写入后持有者一端超限即拒写（E-HK-HOLDER-MAX）；`concluded` 为真的种类只能由动作目录里带同意条款的动作成立。带关系的边另看关系条目的 `consent`：取“双方同意”的须有双方当事人的同意动作；取“按制度”的，同意方读有效婚配制度行的 `consentBy`。同意事件的编号记在 `terms.consentAct`（E-REL-CONSENT）。`intimate` 或 `marital` 为真的条目不得取“不需同意”。
- **R18-1.6 带关系的边**：`carriesRel` 为真的边，种类必须等于 `terms.rel` 所指条目的 `kind`（E-REL-KIND）。条目 `symmetric` 为真时，写者成对写入两条边，成对关闭。`terms.rel` 不得原地改写：换关系类型等于关闭旧边再建立新边（E-REL-REWRITE）。受检写入先过 R18-9.1。
- **R18-1.7 终止只关现役**：终止原语第 4 步只处置现役持有边。史实记录不动；只有当被关闭的现役边带 `record` 时，关系写者回填对应史实记录的 `until`（取终止时刻）与 `endReason`（取 `byTermination` 为真的那条原因）。所以终止事件发出之后，`kinDegree`、`heirsOf`、禁婚亲等、户主候补顺序照常可算，不依赖终止前的快照。
- **R18-1.8 候补顺序的出处**：取“按候补顺序移交”的格，候补顺序由种类行的 `succeedBy` 指明：按继承制度行的 `headBy`；按继承制度行的 `guardianOrder`；按 `heirsOf` 的顺位；按终止第 2 步定出的后继；按授予者指定。每个取值对应一个登记的顺序提供入口（纯读函数，读史实记录与制度行）；终止原语经登记表调用它，不 import 领域文件，也不点名种类。提供入口返回空表时，该边按“关闭”处置。
- **R18-1.9 事件触发的处置**：种类行的 `hooks` 列出终止以外的触发。事件类型匹配 `on`、且事件的当事实体是这条边的 `role` 一端（持有者或标的）时，持有写者按 `do` 处置这条边。破产判决把财产类的边转入清算承接实体、主权易手时职位与许可怎么办、离队时同行关系关闭，都是这一列的行，不写在规则里。

#### 4.1.4 交互

卷二（边结构、写者、终止原语）；卷八（职位、头衔、领地持有权的种类行登记到本表）；卷八b（人质、囚犯、奴役、通缉、处分权的种类行登记到本表；处分权读本表的边）；卷七（信奉边的种类行；改宗规则在卷七 §4.9（改宗与异端））；卷二十五（驯服边）；卷二十七（`keyHoldings` 只可引用 `pins` 不取“都不钉”的行，见 §5.3）；卷八b（留置是人身依附，不是社会关系：旧表做客种类下的留置变体改为一条独立种类行，由卷八b 登记，`intimate` 必填）；卷十四（卷二 §5.5（个体 `person`）的 `profession` 经“执业”种类的持有派生，该种类行由卷十四登记到本表，标的模板由它定）。

- A18-1.5（不变量式）：史实记录只增不减；任一记录除 `until`、`endReason` 由空变为非空一次外，逐字段不变（相邻两个存档逐条比对）；每条带 `record` 的现役边恰有一条未结束的对应史实记录，每条已结束的这类记录都查不到现役边。任取一个已终止的个体，`kinDegree` 对他与其在世子女返回 1。
- A18-1.3（不变量式）：对每个种类行，三种触发乘持有者模板的每个格都有处置或显式为空（该端不适用），加载期核对（E-HK-PROTOCOL）。
- A18-1.4（扩展性式）：新增一种持有（例如一种新的庇护关系）只加一行并挂上位词，不改任何 .mjs；A18-1.2 仍通过，立场传导按该行系数自动生效。

### 4.2 家户、亲属、婚配、继承、分家、监护

#### 4.2.1 维度

家户 = 组织行，`entityKind` 为 org，`orgKind` 在 `orgTraits` 里 `domestic` 为真（与卷零第六版 Z-04 一致）。成员 = `membership` 为真、标的是该组织的边；户主 = `headship` 为真的边。户主边本身 `membership` 为真，所以户主不另写成员边；`memberCount` 按持有者去重（§2.1），户主不会被算两次。家户成员种类与户主种类的 `holderMax` 都是 1，“每人至多属于一个家户”由持有写者在写入时保证。家户的账户、住所、预算读组织行与卷六 §4.12（家户预算）。

亲属只存两种事实，都是史实记录（§4.1.1）：亲子记录（`kinStep` 非空的条目；`adoptive` 标收养）与婚史记录（`marital` 为真的史实条目）。现役的婚姻另有一条婚姻边。兄弟姐妹、祖孙、姻亲一律由 `kinDegree` 与沿记录遍历派生，不存。父母去世后亲子记录仍在，兄弟姐妹之间的亲等照常可算。收养被解除时，记录以 `voids` 为真的原因结束，从此不计入亲等。

归属制度的两个字段在 `descentTraits`（§2.4）：`lineVia`（孩子归哪一边的家族：生育方、非生育方、双方、都不归）与 `residence`（婚后住处：随生育方亲属、随非生育方亲属、另立、分居）。“生育方”读卷四 `sex` 条目的 `bears` 字段，不读性别名。

继承制度行：`heirOrder: list<struct{line: enum kin_line, maxDegree: integer, filter: rx nullable, weightRX: rx}>`（可读变量见 §2.4）；`partition: enum partition`（独得、均分、按权重）；`spouseShare: number`；`indivisible: enum indivisible_mode`（不可分割的遗产怎样分）；`headBy: enum kin_line 的有序表`；`escheat: 代号`（无人继承时的去向，取账本登记的汇或上级组织）；`guardianOrder`（同 `heirOrder` 的形状）；`splitOnHeadDeath: boolean`。

#### 4.2.2 统一入口

读：`kinView`、`kinDegree`、`heirsOf`、`related`。写：kin.mjs（系统键 kin，推进阶段 social）只产提案；边由持有写者写，组织行由组织写者写，钱物经账本。

#### 4.2.3 规则

- **R18-2.1 出生入户**：订阅出生事件。为新生儿写亲子记录，出生事件载明几位亲本就写几条（关系句柄取 `roles.rels.parentage`；条数不得超过物种行允许的亲本数，E-KIN-CYCLE）；按生母所在家户写成员边；按有效 `descent` 的 `lineVia` 写家族成员边（指向所归一方亲本的世系类组织；“双方”写两条；“都不归”不写）。边的种类取 `roles.kinds` 的对应键。
- **R18-2.2 求偶**：在 `kin.seekDue` 的到期时点，对满足 R18-9.1、无现役婚姻边数已达上限的个体，候选集 = 同聚落内已知、满足双方制度行、亲等不在禁婚范围内者；按 `score = wRegard × min(双向好感) + wCompat × compatScale × (compat − compatMid) + wRank × 等级差 + wGuardian × 监护人或户主对候选者的好感` 排序（各系数都在 `kin.accept`），平分用骰值键裁决。最高分不低于 `acceptMin` 时提出婚约。
- **R18-2.3 婚约与成婚**：婚约是卷六合同种类行，当事方由制度行的 `consentBy` 决定（本人、户主、双方）；条款含聘礼或嫁妆的转移（方向与数额读制度行）。合同履行时，写入制度行 `spouseRel` 所指的婚姻关系：一对现役婚姻边，加该条目 `record` 所指的婚史记录；同意事件（婚约的订立事件）的编号记进 `consentAct`。再按 `residence` 迁移成员边或触发 R18-2.6。违约转卷八b §4.15（民事与救济）。婚约本身不是亲密关系；成婚是受检写入，须过 R18-9.1。
- **R18-2.4 离异与丧偶**：离异由制度行 `divorce` 的发起方与条件决定，是一个动作；财产按制度行的 `divorceSplit` 经账本分割，婚姻边成对关闭，子女成员边按 `lineVia`。丧偶时婚姻边按协议甲关闭。两种情形下婚史记录都回填 `until` 与 `endReason`，记录本身保留；“距上次婚姻结束多久”读该人各条婚史记录 `until` 的最大值。
- **R18-2.5 继承**：订阅个体终止事件（此时现役边已关闭，史实记录完好，见 R18-1.7）。`heirsOf` 沿 `heirOrder` 逐行取满足 `line`、`maxDegree`、`filter` 的在世亲属，亲等与亲属线一律读史实记录；第一条非空的行即继承人集合。配偶 = 婚史记录因被继承人终止而结束（`endReason` 的 `byTermination` 为真、`until` 等于其终止时刻）的另一方，先取 `spouseShare`；其余按 `partition` 与 `weightRX` 分。可分的遗产（账户余额、份额持有）按定点整除，余数给 R18-2.9 全序的第一人。不可分的遗产（对一件物、一处地产的单条所有边）按制度行的 `indivisible` 处置：转为份额持有，各人按应得比例持份；或按卷六的估值从高到低排列，继承人按 R18-2.9 的全序轮流各取一件，差额以钱找补；或全归全序第一人，由他向其余人按估值找补。找补经账本，找补不足的部分成为继承人之间的债务合同。遗产（终止原语交给承接实体的账户与所有边）在终止事件所在的同一刻经账本与持有写者分出。无人继承走 `escheat`。
- **R18-2.6 分家**：三种触发，全读数值——婚后住处为“另立”（成婚事件触发）；家户人数超过 `kin.householdCapRX`（固定刻求值，§3.6）；户主终止且 `splitOnHeadDeath` 为真（终止事件触发）。分出的新家户是一条生成的组织行，财产按继承制度的权重分割，住所经卷十九 §4.8（住宿、租房、床位）取得。
- **R18-2.7 监护**：在固定刻（§3.6），`dependent` 为真且无现役监护边的个体，按 `guardianOrder` 取 R18-2.9 全序下第一位有行动能力的成年亲属；没有则落到兜底职位——其家户所在聚落里，职位行 `guardianOfLastResort` 为真的职位（该布尔字段由卷八登记在职位行上，本卷只读字段，不点名职位）。监护合同下被监护人的财产记在用途为监护的账户里；监护人从该账户的转出只许落在合同登记的用途代号上，其余转出即构成罪名的事实要件（罪名行归卷八b）。固定刻上 `dependent` 为假的，监护边关闭、账户用途转回。
- **R18-2.8 户主继任**：户主边按协议甲“按候补顺序移交”时，候补顺序由 R18-1.8 的提供入口给出：`headBy` 列出的亲属线依次展开，线内按 R18-2.9 排序，只取家户的在世成员；亲属线相对已故户主计算，读的是史实记录。无合格成员则家户终止（清算式），成员按 R18-2.7 或并入近亲家户。
- **R18-2.9 通用全序（一切“取第一位”“平分怎么办”都用它）**：候选人先比权重（`weightRX`，没有权重的场合视为相等），大者在前；再比亲等，小者在前；再比出生时刻 `birthMinute`，早者在前；最后比实体 id 的字典序。继承余数、不可分遗产的轮取、监护人、户主候补、家族首领的平分，都按这一条，不依赖遍历次序。

#### 4.2.4 交互

卷四（出生、死亡事件；生育候选对由本节的婚姻边与亲密关系边给出）；卷六（合同、家户预算、账本）；卷七（`descent` 取值、人生礼仪：成婚与丧葬的礼仪动作在卷七 §4.19（人生礼仪））；卷八 §4.16（人口统计层与人口承载力）（统计层的成婚率、分户率由该节的统计形态给出，读同一批制度行）；卷八b（法律用 `set` 修正覆盖个体的制度行；家事诉讼走罪名与程序）；卷十九（住所）。

### 4.3 家族与传承

#### 4.3.1 维度

家族 = 组织行，`orgKind` 在 `orgTraits` 里 `descentGroup` 为真；可经组织行的 `parent` 字段分支（支系指向本家）。成员由 R18-2.1 的归属边给出。家族首领 = `headship` 为真的边。名望是家族账户（§4.7）。传承行见 §2.2 的 `legacy` 族。

#### 4.3.2 统一入口

读：`orgView`、`kinView().lineage`、`esteemOf`。写：传承解锁是动作，名望经账本转入汇，修正项由卷二登记的修正写者写入。

#### 4.3.3 规则

- **R18-3.1 成员与除名**：归属由出生与收养给出；成婚是否改归属读 `descent` 的 `lineVia` 与婚配制度行的 `spouseJoins`。除名是首领的动作（须过同意与权能，见卷九 §4.6（同意与权能）），关闭成员边并发事件。
- **R18-3.2 首领继任**：按家族组织行的继任职位规则；缺省用成员中 `esteemTier` 最高者，平分按 R18-2.9 的全序（亲等相对前任计算，读史实记录，前任已终止也可算）。
- **R18-3.3 名望来源**：成员每得一笔威望，名望来源另向家族账户铸入 `lineageShare` 比例的名望（§4.7 R18-7.2）；成员所持职位、头衔的等级按来源行逐年铸入。
- **R18-3.4 传承**：首领以名望解锁传承行：须满足该行 `requires`、同一 `track` 内 `order` 较小的行已解锁；`cost` 经账本转入汇。解锁即写入永久修正项（作用域为成员），来源记为该家族与该传承行。已解锁集合由这些修正项的来源派生，不另存。
- **R18-3.5 分支**：`lineage.branchRX` 在固定刻（§3.6）对一个支系为真时，可由支系首领提出立支：生成一条 `parent` 指向本家的组织行，成员边迁移；传承修正沿 `parent` 链继承（作用域解析见卷二 §3.5（作用域与状态键表））。
- **R18-3.6 绝嗣**：家族没有在世成员时按组织终止处理；名望账户按资源行的 `onTerminate` 转给 `parent`，没有则入汇。

### 4.4 立场数轴（来源表、衰减、单入口）

#### 4.4.1 维度

轴见 §2.2 的 `stance_axis`。来源行（`rules.social.stance.sources`，全书唯一的立场来源表；别卷只向它登记行）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `axis` | ref vocab stance_axis | 作用的轴 |
| `form` | 封闭枚举：static / event | 静态（每次读取时算）或事件（生成条目） |
| `applies` | rx | 观察者与对象的适用条件，只读维度与关系存在性 |
| `valueRX` | rx | 静态行的值 |
| `verb`、`role` | ref vocab verb、封闭枚举（target / actor / witness / related / informed） | 事件行：哪类事件、观察者在其中的角色 |
| `value`、`valueScale` | number、map<ref vocab value, number> | 事件行的初值，及按观察者价值轴缩放 |
| `towards` | 封闭枚举（actor / target / owner） | 条目指向事件里的谁 |
| `decayDays` | integer nullable | 线性衰减到零的天数；空为永久 |
| `stackLimit`、`group` | integer、ref vocab stack_group | 同对、同行的条目上限；同组只取绝对值最大者 |

运行态：`state.stance[observerId][targetId][] = {row, event, v0, since}`，全是代号与数值。观察者与对象可以是个体，也可以是组织。

#### 4.4.2 统一入口

读：`stance(engine, state, observerId, targetId, axisHandle)`。写：stance.mjs 订阅事件后按来源行生成条目；没有接受任意增量的函数。

#### 4.4.3 规则

- **R18-4.1 读数公式**：`stance = clamp(neutral + S + E + C, min, max)`。`S` = 适用的静态行 `valueRX` 之和，加两人之间每条有效关系的 `stanceBase[axis]`；有效关系指现役且未中止的关系边，以及 `until` 为空的史实记录。`E` = 该对条目的现值之和；`C` = 传导（R18-4.4）。另有一个变体读数 `stanceExcluding(rel)`：算 `S` 时不计指定关系条目自己的 `stanceBase`，只供 R18-5.2 判解除用，由同一入口的可选参数给出。
- **R18-4.2 条目只由事件生成**：观察者得知一件事（卷二十二的已知事件集合新增一项）时，对每条 `verb` 与 `role` 匹配且 `applies` 为真的事件行生成一个条目，`v0 = value × (1 + Σ valueScale[k] × 观察者的有效价值[k])`，按 §2.1 的精度向零截断后存入；`since` 取得知时刻（整数分钟）。超过 `stackLimit` 时丢弃现值绝对值最小的一条，平分按事件编号序。
- **R18-4.3 闭式衰减**：记 `decayMinutes = decayDays × 每日分钟数`（加载期算好的整数）。条目现值 `v(t) = v0 × max(0, decayMinutes − (t − since)) ÷ decayMinutes`，先乘后除，按 §2.1 的精度向零截断；`decayDays` 为空则恒为 `v0`。到期时刻 `since + decayMinutes` 登记为到期项，由调度器在该刻删除条目。因此读数只取决于世界时刻，与推进怎样分段无关；没有逐日的衰减拍。
- **R18-4.4 传导（一跳，不递归）**：记 `D(a,b)` 为不含传导的直接读数（`S + E`）。`C_t` = 对象作为持有者的每条现役边：`conduct × D(观察者, 该边标的)`，加对象作为标的的每条现役边：`conductBack × D(观察者, 该边持有者)`。`C_o` = 观察者作为持有者的每条现役边：`adopt × D(该边标的, 对象)`。`C = clamp(C_t + C_o, −conductCap, +conductCap)`。只对轴条目 `conducts` 为真的轴计算。两端都在世、`until` 为空的史实记录按一条边计入，系数取其条目 `kind` 所指种类行的三个系数；中止的边不传导。
- **R18-4.5 档位**：`tier = first(rules.social.stance.tiers[axis])`。一切门控（服务、价格、通婚、外交）读档或读数，不另存“态度”。
- **R18-4.6 组织之间**：组织对组织的立场用同一张表、同一个入口；条约与同盟是持有边，经 `conduct` 起作用。“阵营关系”就是组织之间的立场读数，不另立实体。
- **R18-4.7 别卷登记来源行**：文化接纳、信仰敌意、行为评价、战力对比、作品传播等，各由其定义卷向本表登记行（静态行读它们的派生维度；事件行引它们的动词）。登记方不得自存立场数。

#### 4.4.4 交互

卷七（文化接纳与信仰敌意登记为静态行；评价行决定 `valueScale` 的轴）；卷八（外交、派系读组织间立场，见卷八 §4.14（外交与使节））；卷十三（战力对比登记为恐惧轴的行）；卷十六（怪物阵营是组织行加本节读数）；卷二十二（“得知”这一刻由它给出）；卷二十六（想法的 `stanceWeight` 读本入口）；卷二十七（矩阵行：个体层与规则层都是事件驱动加到期项，统计层的观察者是聚合体所属的组织，条目记在组织上）。

#### 4.4.6 验收断言

- A18-4.1（扫描式，判据即 S18-1 的三条）：状态登记表里，“实体 id 到实体 id 到数值”类型的路径只有 `state.stance` 一条（按声明类型扫，不按字段名；旧的信任、好感、敬重、恋慕四维证据表与 7 份旧存储都会被这条类型判据扫出）；`state.stance` 的登记写者只有 stance.mjs，别的文件不对它调读写接口；stance.mjs 的导出函数没有数值类型的形参；档位表的键全部是 `stance_tier` 族句柄。
- A18-4.2（不变量式）：任意时刻任意一对的读数等于按 R18-4.1 从条目、维度、关系重算的值（不存缓存值）；读数落在轴的 `[min, max]` 内；每个条目的 `row` 与 `event` 都能查到。
- A18-4.3（不变量式，交卷十二执行）：同一世界一次推进 N 天与分段推进合计 N 天，存档摘要相同；特别是条目的删除时刻相同。
- A18-4.4（扩展性式）：新增一条轴（例如“敬畏”）加一条轴条目、一张档位表和若干来源行，不改 .mjs；`stance` 可读，A18-4.2 通过。
- A18-4.5（扩展性式）：别卷新增一条来源行（例如一种新的冒犯事件）后，相关事件发生即生成条目，不改 stance.mjs。

### 4.5 关系、记忆、认知与谎言

#### 4.5.1 维度

非亲属的私人关系（朋友、对头、情人等）是 `carriesRel` 为真的持有边；形成与解除的阈值在关系条目的 `form / drop`。

记忆不另存：一个人记得什么 = 卷二十二的已知事件集合；本节只定义**显著度**。`memory.salience` 行：`{verb, role, base: number, stanceWeight: number}`。`memory.forgetCurve` 是自得知起的天数到保留比例的曲线。

谎言账：`state.lies[lieId] = {liar, claim: struct{event: EventId nullable, subject: EntityId, dimKey: 代号, value: 代号或数值}, toldTo: set<EntityId>, since, phase: enum lie_phase}`。命题是结构化的，不含文字。

#### 4.5.2 统一入口

读：`related`、`recall`、谎言经 `liesAbout(engine, state, subjectId)`（lies.mjs）。写：关系边经持有写者；谎言账只由 lies.mjs 写。

#### 4.5.3 规则

- **R18-5.1 关系形成**：在固定刻（§3.6），对自上一个固定刻以来有过社交互动事件的每一对，逐个 `form` 非空的关系条目求值：若双向读数都满足 `form` 的比较，且两人间已知的互动事件数不少于 `contacts`，则条件成立。条目 `consent` 取“不需同意”的，直接提出该关系边；取“双方同意”的，只生成一个可选的缔结动作（卷九的同意条款），双方都同意后才写入，同意事件记进 `consentAct`。亲密关系因此不会只凭好感达标就自动成立。受检写入先过 R18-9.1。
- **R18-5.2 关系解除**：在每个固定刻，对每条 `drop` 非空的现役关系边求值；任一方的 `stanceExcluding(该关系)` 满足 `drop` 即成对关闭关系边并发事件。比较用的读数不含这条关系自己的 `stanceBase`，否则基数会把解除阈值垫高到永远够不着。因为是在固定刻对现役边整体求值，条目线性衰减越线、静态部分变化（文化接纳、别的关系基数）、传导部分变化（对方入会、离会）都会被同一处发现，不需要逐个来源登记触发点。
- **R18-5.3 显著度**：`recall(p, e) = clamp(base × (1 + stanceWeight × |p 对事件受事者的好感| ÷ 好感轴条目的 max) × lookup(forgetCurve, 距得知天数), 0, 1)`。纯函数，不落盘。低于 `recallMin` 的事件不进入决策与对话的检索结果（检索键与取数归卷二十二 §4.1（主观视图））。
- **R18-5.4 认知只读结构**：一个人对“某人是否守约、是否欠债、是否伤害过我”的判断，一律是对已知事件按动词、角色、当事人过滤后的计数与求和，再乘显著度；不对任何文字做匹配。
- **R18-5.5 转述与保留**：转述某事件给听者时，保留度 = `lies.discloseRX`（读转述者的人格、价值、对听者的信任读数、事件的保密标记）。保留度低于 `lies.discloseMin` 则不转述；不存在“按性格文字省略数量”的分支。
- **R18-5.6 说谎**：说谎是动作。发生条件读 `lies.propensityRX` 与动机（由决策管线给出）。说谎即在谎言账登记一条，`phase` 为未揭穿；听者的已知集合里写入的是带可信度的命题（写入与可信度归卷二十二 §4.3（推断））。
- **R18-5.7 揭穿**：听者经推断得到与命题矛盾且可信度更高的事实时，卷二十二发出矛盾事件；lies.mjs 把对应条目转为已揭穿并发“谎言揭穿”事件。立场与威望的后果由各自来源行处理（引用谎言 id，不引用文字）。

#### 4.5.4 交互

卷二十二（已知集合、推断、传闻；谎言登记带 id 供其引用）；卷九（决策与对话检索读 `recall`，见卷九 §4.12（NPC 决策管线））；卷二十五 §4.6（驯服、宠物、坐骑）（宠物关系是带关系的持有边）；卷二十六（事件驱动的想法与本节读同一已知集合）。

#### 4.5.6 验收断言

- A18-5.1（扫描式）：全库不存在 `memoryStream` 的读写；memory、cognition、lies 三个系统文件里没有正则字面量、没有对字符串内容的方法调用；谎言账各字段类型不含字符串。
- A18-5.2（不变量式）：`recall` 对同一（人、事件、时刻）恒返回同值，且不改状态；每条 `symmetric` 关系边成对；每条已揭穿的谎言都能关联到一个矛盾事件。
- A18-5.4（不变量式）：每个固定刻结束时，没有任何现役关系边的任一方满足该条目的 `drop`（读数按 R18-5.2 的口径）；每条 `consent` 不取“不需同意”的现役边，`consentAct` 都能查到一个双方同意的事件。
- A18-5.3（扩展性式）：新增一种私人关系（例如结义）只加一条关系条目，形成、解除、立场基数自动生效，不改 .mjs。

### 4.6 舆论与群体行为触发

#### 4.6.1 维度

舆论不存分数。对象引用 `subjectRef` = 一个实体或一个事件，检索键沿用卷二十二的“提及加维度代号”。触发行（`rules.social.opinion.triggers`）：`{axis, groupFilter: rx, when: rx（可读变量见 §2.4）, emits: ref vocab verb, cooldownDays: integer, drawSite: 代号 nullable}`。运行态只有冷却时刻 `state.opinion.lastFired[groupId][subjectRef][triggerRow]`，冷却按（群体、对象、触发行）三者记，同一群体对不同对象互不压制。

群体的公共维度（`groupFilter` 只读这些，组织群体与地点群体都有值）：`group.basis: enum group_basis`（群体是组织的成员集合，还是地点的居民集合）、`group.size`（人数）。组织才有的字段（如 `orgKind`）不进 `groupFilter`；确需按组织性质区分的触发行，用 `group.basis` 先分开。

#### 4.6.2 统一入口

读：`opinionOf`。写：opinion.mjs 只写冷却时刻并发事件。

#### 4.6.3 规则

- **R18-6.1 投影**：`informedShare` = 群体成员中已知该对象相关事件者的比例（统计层取卷二十二 §4.5（公共知情与统计层）的知情率）；`mean` = 知情成员对该对象在该轴上的读数均值；`pressure = informedShare × mean`。群体 = 任一组织的成员集合，或一个地点的居民集合。
- **R18-6.2 触发时点**：只在固定刻（§3.6）求值，求值范围是两类（群体、对象）对——自上一个固定刻以来，群体里有成员新得知与该对象相关事件的；冷却到期项在这段时间内到期的（到期项带着群体、对象、触发行三个键，所以知道该重算谁）。不做全量扫描。
- **R18-6.3 触发**：某行 `groupFilter` 与 `when` 为真且该（群体、对象、触发行）不在冷却内，即发出 `emits` 所指的事件（请愿、抵制、驱逐、庆贺、聚众等，各是事件类型行，后果由事件类型的定义卷处理），记下冷却时刻，并登记一条冷却到期项。
- **R18-6.4 群体对个人的反馈**：群体行为事件本身又是立场来源表里的事件，参与者与对象之间的条目照常生成。舆论不直接改任何人的立场数。
- **R18-6.5 统计层同式**：统计层的群体用聚合体的组织级条目与知情率求同一个 `pressure`；阈值不因层而变。

#### 4.6.4 交互

卷二十二（知情率、检索键）；卷二十四（群体行为的事件类型行与后续局势）；卷八（民心、治理读 `opinionOf`；骚乱对治安的影响在卷八b）；卷二十七（矩阵行与层间一致性）。

#### 4.6.5 数据实例

```json
{
 "triggers": {
  "crowd_example_petition": {"axis": "saxis_regard", "groupFilter": "group.size >= 20", "when": "pressure <= -25", "emits": "verb_example_petitioned", "cooldownDays": 90, "drawSite": null},
  "crowd_example_feast": {"axis": "saxis_regard", "groupFilter": "true", "when": "pressure >= 40 && informedShare >= 0.5", "emits": "verb_example_feted", "cooldownDays": 180, "drawSite": null}
 }
}
```

- 【西陲】某村 40 人（地点居民集合，`group.size` 40，过 `groupFilter`），30 人知道税吏克扣一事，知情者对税吏的好感均值 −40：`pressure = 0.75 × (−40) = −30`，不高于 −25，在下一个固定刻触发请愿，这个村对这位税吏的请愿进入 90 天冷却；同村对另一位税吏的请愿不受影响。
- 【非西陲】海港行会 200 人对一位船长：知情率 0.6、均值 +70，`pressure = 42`，触发庆贺。
- 【非人类】一处鼠人巢群对闯入者的 `pressure` 达到驱逐行阈值，发出驱逐事件；用的是同一张触发表，群体是巢群组织的成员。
- 【超自然】信众对一位神祇显圣的知情率与好感达到阈值，触发庆贺事件；后续的虔诚变化归卷七。

#### 4.6.6 验收断言

- A18-6.1（扫描式）：全库没有落盘的舆论分数字段；opinion.mjs 里没有事件动词字面量，`emits` 只来自触发行。
- A18-6.2（不变量式）：`opinionOf` 是纯函数；同一（群体、对象、触发行）在冷却期内不重复发事件，不同对象之间互不压制；群体行为事件的时刻都落在固定刻上；一次推进 N 天与分段推进触发的事件序列相同。
- A18-6.3（扩展性式）：新增一种群体行为，只加一条事件类型行与一条触发行，不改 .mjs。

### 4.7 威望、名望、名士与荣誉

#### 4.7.1 维度

威望与名望是资源种类行（§2.3）。来源行（`esteem.sources`）：`{verb, role, resource, amountRX, cap: struct{perDays, max} nullable}`。档 `esteem_tier` 由余额派生。

“在某群体中的声望”不是新量：它就是该群体（组织）对此人在好感轴与信任轴上的立场读数（§4.4）。

名士 = 一条名士在册边（持有者为个体，标的为授予认可的组织），`terms.phase` 取 `notable_phase`（待审、在册、除名）。荣誉 = 一条荣誉边，`terms.honor` 指向 `honor` 族条目。

#### 4.7.2 统一入口

读：`esteemOf`；名士与荣誉读持有边。写：esteem.mjs 经账本；名士与荣誉边经持有写者。

#### 4.7.3 规则

- **R18-7.1 威望只由来源行铸入**：事件发生且匹配来源行时，从登记的来源向当事人账户转入 `amountRX`；`cap` 限制同一行在窗口内的累计。战功（卷十三 §4.19（战功）的参战快照）、作品传播（卷二十三 §4.5（出版、抄写、传播））、任职、主持礼仪等都以来源行登记。
- **R18-7.2 家族分成**：每笔威望铸入，同时向其所归家族的名望账户另铸 `lineageShare` 比例（不从个人账户扣）。
- **R18-7.3 花费与消退**：威望、名望可作为动作的代价转入汇（传承、举荐、请托等，代价写在各动作行上）。每个历年边界按 `upkeepPerYear` 比例转入汇；这是日历锚定的到期项，与推进分段无关。
- **R18-7.4 档位**：`esteemTier = first(rules.social.esteem.tiers)`。档条目的 `modifiers` 生效于持有人。门控读档，不读余额字面阈值。
- **R18-7.5 名士**：个体满足 `notable.listRX`（可读威望档、技能认证、作品数、所在组织对其的立场读数）且有人举荐（举荐是动作，带举荐类别代号）时，写入待审的名士边，并登记 `reviewDays` 后的到期项；到期时条件仍满足则转在册，否则关闭。在册期间，当事人成为一件 `scandal` 为真的事件的行为人（`scandal: boolean` 是事件类型行上的字段，请卷二十四收录，见 §5.2；这是事件驱动），或在固定刻（§3.6）发现条件不再满足，转除名。名士边的种类取 `roles.kinds.notable`。
- **R18-7.6 荣誉**：授予是组织首领或职位的动作，受者须满足荣誉条目的 `requires`；`cost` 由授予方支付。荣誉边（种类取 `roles.kinds.honor`）带来条目上的修正项。授予方终止时，按该种类行的 `subjectEnd`，荣誉边的标的改指授予方的后继；清算或没有单一后继时荣誉边关闭，修正项随之撤销。任何时候都不留指向已终止组织的边。
- **R18-7.7 访客与声望档**：来访者能否被接待、见到谁，读 `treatment`（§4.10）与来访者的 `esteemTier`；不另设访客专项。

#### 4.7.4 交互

卷六（账本、来源与汇）；卷八（正统性、任职资格读档）；卷十三（战功来源行）；卷十四（认证与考试是名士条件的输入）；卷二十三（作品传播来源行）；卷二十二（丑闻与假身份：来访者的假身份归该卷的秘密与身份键）。

#### 4.7.5 数据实例

```json
{

 "lineageShare": 0.2,
 "upkeepPerYear": 0.05,
 "sources": {
  "esrc_example_victory": {"verb": "verb_example_battle_won", "role": "actor", "resource": "res_example_prestige", "amountRX": "50 * event.meritShare", "cap": null},
  "esrc_example_work": {"verb": "verb_example_work_copied", "role": "author", "resource": "res_example_prestige", "amountRX": "2", "cap": {"perDays": 360, "max": 80}}
 },
 "honor": {
  "honor_example_champion": {"requires": "subject.esteemTier.order >= 1", "cost": 100, "modifiers": [{"target": "person.gaugeTarget[gauge_example_morale]", "scope": "self", "stage": "add", "value": 0.05}], "labels": {"zh": "勇武之誉", "en": "Champion"}}
```

- 【西陲】民兵队长独占一场胜仗的战功份额：威望 +50，所归家族名望 +10；余额由 80 到 130，跨过 100，档升一级。
- 【非西陲】海港抄书坊一年内抄了一位学者的作品 60 份：`2 × 60 = 120`，受 `cap` 限制只入 80。

- 【超自然】一位显圣的地祇按来源行得到威望；它的“在信众中的声望”仍是信众组织对它的立场读数。

#### 4.7.6 验收断言

- A18-7.1（扫描式）：威望、名望账户的写点只在 esteem.mjs 且全部经账本；名士系统文件里没有中文状态、没有对举荐理由的正则；没有本地清醒判定。
- A18-7.2（不变量式）：威望、名望的全局总量 = 来源累计 − 汇累计（账本源汇报告）；名士边的 `phase` 只沿待审到在册到除名的方向变化。
- A18-7.3（扩展性式）：新增一种荣誉或一条威望来源行，只加数据行，不改 .mjs。

### 4.8 阶层流动

#### 4.8.1 维度

身份等级的取值与写者归卷八b §4.14（身份等级与入籍）。本节的流动行（`mobility.rows`）：`{from: rx（读当前等级的序）, to: 等级的位移（整数）, when: rx, sustainDays: integer, proposes: ref vocab verb}`。`when` 可读：账户余额与资产估值（卷六）、`esteemTier`、所持职位与认证、婚姻边另一方的等级、有罪判决计数。

#### 4.8.2 统一入口

读：等级经 `personView`；资格经 `mobilityOf(engine, state, personId)`（mobility.mjs）。写：本节不写等级，只发“阶层变动提议”事件，由卷八b 的写者按其程序受理。

#### 4.8.3 规则

- **R18-8.1 资格派生**：`mobilityOf` 返回当前所有 `from` 与 `when` 为真的行。
- **R18-8.2 持续条件**：条件只在固定刻（§3.6）求值。某个固定刻发现一行的条件为真而没有在途到期项，就登记一条自该固定刻起 `sustainDays` 后的到期项；某个固定刻发现条件为假，撤销到期项；到期时仍为真才发提议。“全程为真”的含义因此是：持续期内每个固定刻都为真。净资产随价格逐日变化，也只在固定刻被读到，结果与推进怎样分段无关。
- **R18-8.3 上行与下行同式**：升与降是同一张表里位移符号不同的行（破产、定罪、失去职位都可以是下行行的条件）。
- **R18-8.4 通婚与继承带来的流动**：成婚、继承、收养后，相关个体的 `when` 重新求值；等级是否随婚姻、出生取得，由卷八b 的等级行规定，本节只提供事实。
- **R18-8.5 统计层**：统计层用卷八 §4.16（人口统计层与人口承载力）的分组分布，按同一批行的条件对分组求转移比例。

#### 4.8.4 交互

卷八b（等级取值、受理程序、法律门控）；卷十四 §4.7（考试认证）（认证是上行条件的输入）；卷六（资产估值）；卷八（职位）。

#### 4.8.5 数据实例

```json
{
 "rows": {
  "mobrow_example_rise_wealth": {"from": "subject.rank.order <= 2", "to": 1, "when": "subject.netWorth >= 5000 && subject.esteemTier.order >= 1", "sustainDays": 360, "proposes": "verb_example_rank_proposed"},
  "mobrow_example_fall_ruin": {"from": "subject.rank.order >= 2", "to": -1, "when": "subject.netWorth < 0", "sustainDays": 180, "proposes": "verb_example_rank_proposed"}
 }
}
```

- 【西陲】一位行商净资产连续 360 天不低于 5000 且威望档至少一级：到期发上行提议，由卷八b 的程序决定是否受理。
- 【非西陲】海港没落船东净资产为负满 180 天：发下行提议。
- 【非人类】依附于人类聚落的掘地族个体同样按行求值；能否受理取决于卷八b 的等级行对其身份的规定。
- 【超自然】受封为地方守护的精怪因所持职位满足上行条件，流程相同。

#### 4.8.6 验收断言

- A18-8.1（扫描式）：mobility.mjs 不写任何等级字段；规则层没有等级代号字面量。
- A18-8.2（不变量式）：每个提议事件都能对应到一条在持续期内每个固定刻都为真的行；到期项的登记时刻都落在固定刻上；同一人同一行在一次持续期内至多一个提议。
- A18-8.3（扩展性式）：新增一条流动途径（例如凭认证上行），只加一行，不改 .mjs。

### 4.9 婚配制度、性风俗、儿童与老人

#### 4.9.1 维度

婚配制度行：`spouseRel: ref vocab relation`（本制度下成婚写入哪一种关系；该条目须 `marital` 为真、`persistence` 为现役、`record` 非空，加载期校验）；`spouseCap: map<ref vocab sex, integer>`（每种性别条目可同时拥有的配偶数）；`minRelMaturity: number`（校验不低于硬下限）；`forbiddenDegree: integer`（此亲等以内禁婚）；`consentBy: enum consent_by`（成婚须经谁同意，结构化代号；婚姻关系条目的 `consent` 取“按制度”时读它）；`transfer: struct{direction: enum transfer_direction, amountRX: rx}`（聘礼、嫁妆）；`divorce: struct{allowed: boolean, initiators: enum divorce_initiator, whenRX: rx}`；`divorceSplit: number`；`spouseJoins: boolean`；`pairFilter: rx`（配偶双方维度须满足的条件，例如性别组合，只读条目字段）；`remarryAfterDays: integer`。

个体的有效制度行 = `person.marriageRegime`（文化缺省，信仰信条与法典可用 `set` 修正覆盖）。

风俗（婚前、婚外、多偶、同住等行为在某文化里算美德还是耻辱）不在本卷另立表：它们是卷七 §4.26（评价行）里以动作或事件为对象的评价行；本卷提供被评价的事实（关系边、社交互动事件）。

照管：`dependent` 派生维度（§2.1）；赡养与抚养是义务种类行，条件写在制度行的 `careDuty: list<struct{line, maxDegree, whenRX}>`。

#### 4.9.2 统一入口

读：制度行经 `kinView().regime`；`intimateEligible`、`intimateAllowed`。写：无自有状态；关系的中止与恢复由内核关系写者写 `terms.suspended`。

#### 4.9.3 规则

- **R18-9.1 未成年人硬下限（写入不变量；全书唯一实现；数值判定；主会话一审后裁定第 2 条）**

  **不变量**：任一时刻，不存在一条现役且未中止的受检关系，其任一参与身体的 `intimateEligible` 不为真；也不存在一个已提交的亲密动作事件，其任一参与身体在事件时刻不合格。

  **单人谓词**：`intimateEligible(p)` 为真，当且仅当 p 的 `adult` 为真，且 p 的 `relMaturity` 不低于 `minor.intimateMinRelMaturity`。两项都读身体所有者自己的年龄维度（卷四），按各物种的成熟龄相对化。任一输入未知或求值报错，即为假。

  **受检对象**（按字段判定，不点名）：① 关系条目 `intimate` 为真的一切关系；② 关系条目 `marital` 为真的一切关系，不论它的 `intimate` 标成什么；③ 种类行 `intimate` 为真的一切持有边，不论是否带关系；④ 动作目录条目 `intimate` 为真的一切动作。这三处的 `intimate` 都是必填字段，缺了加载失败（E-REL-INTIMATE-FIELD）。所以不存在“没挂社会属性行就不受检”的动作，也不存在“没带关系就不受检”的种类。

  **参与的身体**：当事人 p 参与的身体 = p 自己，加上 p 作为持有者、种类 `bodyControl` 为真的每条现役边的标的。判定对双方全部参与的身体逐个调单人谓词。附身与操控不改变判定主体：被使用的身体按它的所有者的年龄维度判，控制者的年龄不能替它过关；控制者自己也要合格。

  **检查者**：内核的关系写者（§3.3）是关系表的唯一写者，它在下表每条写入路径上执行检查；卷九的动作裁决在提交亲密动作前调同一个谓词。

  | 写入路径 | 检查点 | 何时检查 | 不合格时 |
  |---|---|---|---|
  | 建立 | C1 | 写入受检关系的现役边或史实记录之前（成婚履行、R18-5.1 的缔结、任何动作或提案） | 拒写，E-REL-INTIMATE-MINOR |
  | 建立 | C2 | 提交 `intimate` 为真的动作之前 | 拒绝动作，同码 |
  | 变形或补丁 | C3 | 试图原地改写现役边的 `terms.rel` | 一律拒写，E-REL-REWRITE；换关系只能关旧建新，新边走 C1 |
  | 变形或补丁 | C4 | 个体的物种、身体、出生时刻被改写（变形、物种变更、偏离行）的同一事务内 | 该个体的全部现役受检关系转中止 |
  | 变形或补丁 | C5 | 内容包补丁改了物种成熟龄、关系条目或种类行的 `intimate` 与 `marital`、硬下限键；补丁应用完成时对全部现役受检关系复查 | 不合格的转中止 |
  | 加载与实体化 | C6 | 加载世界数据、存档、内容包自带的边与记录时逐条检查 | 拒载，E-REL-MINOR-LOAD |
  | 加载与实体化 | C7 | 人物档案入库前（卷十的生成写回、卷一规定的档案校验）：档案里任一关系行受检而本人不合格 | 拒收档案，同码 |
  | 加载与实体化 | C8 | 统计层实体化成个体时，产出的关系经关系写者写入，走 C1；统计层的成婚与结伴比率对未达硬下限的年龄档恒为 0 | 拒写；比率非零即加载失败，E-REL-MINOR-LOAD |
  | 附身或操控 | C9 | 建立 `bodyControl` 为真的边之后的同一事务内，复查控制者与宿主各自的现役受检关系 | 不合格的转中止 |
  | 附身或操控 | C10 | 亲密动作的参与者正使用别人的身体 | 按“参与的身体”判，同 C2 |

  **中止**：年龄或身体发生变化，使一方不再合格时，关系写者在同一事务内把该关系的边置 `terms.suspended` 为真，并发“关系中止”事件。中止的边对 `related`、生育候选对、亲密动作的前提、立场基数与传导一律视同不存在，但仍占 `spouseCap` 的名额。此后在 C4、C5、C9 的任一检查点发现双方重新合格，写者解除中止并发“关系恢复”事件。史实记录不受中止影响。

  **不可绕过**：这条不受文化、信仰、法典、修正项、玩家或文字模型输出的影响。`adult` 不可被修正；硬下限键校验不低于 1；制度行与修正项不得调低（E-KIN-REGIME-AGE）。把一个物种的成熟龄登记得异常小来规避，由卷二十八的内容审批做数值校验（读物种维度，不点名物种），请求见 §5.2。外貌是否需要数值判定见 §8 Q11。

- **R18-9.2 文字半边不在本卷；数值半边只有一个谓词**：涉及未成年人的亲密题材在输入边与显示闸的拦截，按卷二 §2.9（外部边界与 Text 模型）与卷九 §4.19（守门）执行。它们读的数值半边、卷一规定的档案校验、卷零把数值半边归给卷四的那一行，一律调单人谓词 `intimateEligible`，不各自读 `adult` 或年龄常数；卷四 §4.4（年龄、成长、寿命、出生与死亡率）里“守门读 `adult`”的说法改为引用本谓词（请求见 §5.2）。旧的 `ROMANCE` 正则删除：它的数值半边 = 关系代号（条目的 `intimate`、`marital`）加 `intimateEligible`，落在检查点 C7；文字半边交守门的未成年题材拒收代号。与卷零、卷一、卷二对该正则的处置一致。
- **R18-9.3 婚配资格**：双方各自按自己的有效制度行检查：`relMaturity ≥ minRelMaturity`；现役婚姻边数（含中止的）小于 `spouseCap`；`kinDegree` 为空或大于 `forbiddenDegree`（读亲子史实记录，父母已故的同胞照样挡得住）；`pairFilter` 为真；当前时刻减去本人各条婚史记录 `until` 的最大值，不少于 `remarryAfterDays` 折成的分钟数（没有已结束的婚史记录则此项通过）。所在法域的法典若设门控，再过卷八b §4.4（法律门控）。两套制度都通过才可缔结。
- **R18-9.4 未成年婚约**：制度行 `consentBy` 允许户主代订时，婚约可以在当事人未成年时订立；它只是家户之间的合同，不产生任何亲密关系边与亲密互动，履行条件必含 R18-9.1。
- **R18-9.5 抚养与监护**：`dependent` 为真的未成年人由 R18-2.7 得到监护人；监护人负有抚养义务（义务种类行），其日常消耗并入家户预算。
- **R18-9.6 赡养**：在固定刻（§3.6），`careDuty` 的 `whenRX` 对某长辈为真（通常读其 `relAge` 与 `dependent`）时，对 `line` 与 `maxDegree` 内的成年亲属生成赡养义务；固定刻上转假的，义务解除。履行经家户预算或账本转移，不履行转卷八b 的救济。
- **R18-9.7 生育候选对**：卷四的受孕判定读本卷给出的候选对：现役且未中止的婚姻边，或 `intimate` 为真的现役且未中止的关系边，且双方同住或同处一地。给出候选对时，在受孕判定的那一刻现场调 `intimateAllowed`，不为真的对不给出；不依赖“边存在即合格”。

#### 4.9.4 交互

卷四（`adult`、`relMaturity`、`sex` 条目、受孕与分娩）；卷七（评价行、人生礼仪）；卷八b（法典的门控与覆盖）；卷九（守门的数值半边读 `intimateEligible`；动作目录条目必填 `intimate`）；卷十与卷一（档案校验调 C7）；卷十五、卷十六（变形与物种变更触发 C4）；卷二十七（实体化走 C8）；卷二十八（补丁触发 C5；成熟龄下限的内容审批）；卷六（义务、家户预算）；卷二十六（照管与被照管对心理需求的满足）。

#### 4.9.6 验收断言

- A18-9.1（扫描式，判据即 S18-8）：除 kin.mjs 的两个亲密谓词与内核关系写者外，没有任何函数体既读 `adult` 或 `relMaturity` 维度键、又读任一条目的 `intimate` 或 `marital` 字段；全库没有对 `flags.minor`、`flags.romanceable` 的读写（这两个字段在状态类型表里不存在）；没有名为 `ROMANCE` 的正则，没有对关系名或文字做匹配来判断亲密或未成年的代码；没有以年计的婚龄、成年常数（S18-5）。全部持有种类行、动作目录条目、社会关系条目都有 `intimate` 字段。
- A18-9.2（不变量式）：R18-9.1 的不变量。任一时刻，遍历全部种类行、全部关系条目、全部动作条目定出受检集合，其中每条现役且未中止的边，双方全部参与的身体 `intimateEligible` 均为真；每个亲密动作事件同此。性质测试对随机生成的世界与任意制度行、修正项、法典组合，逐条打写入路径：建立（C1、C2）、原地改写（C3）、变形与偏离（C4）、调大成熟龄的补丁（C5）、带违例边的存档与内容包（C6）、带违例关系行的档案（C7）、实体化（C8）、附身与操控（C9、C10）；另测“把婚姻条目标成非亲密”与“不挂社会属性行的亲密动作”两种构造。违例数为 0；C4、C5、C9 之后受影响的边都处于中止。
- A18-9.5（不变量式）：单人谓词对未知输入返回假；`intimateAllowed(a,b)` 恒等于双方全部参与身体的单人谓词之与；守门、档案校验、关系写者、动作裁决四处的调用点都解析到同一个导出（引用扫描）。
- A18-9.3（不变量式）：每人的现役婚姻边数不超过其有效制度行的 `spouseCap`；配偶间 `kinDegree` 大于 `forbiddenDegree`。
- A18-9.4（扩展性式）：新增一种婚配制度（例如访婚：`spouseJoins` 为假、分居）只加一行，求偶、成婚、分家、继承不改 .mjs；A18-9.2 仍通过。

### 4.10 外来者待遇与立场基线

#### 4.10.1 维度

待遇档 `treatment`（有序；条目字段 `access`、`serviceFactor`、`guestRight`、`modifiers`）。规则表 `rules.social.treatment` 是有序规则表。`when` 只读 `treatment` 入口在求值前绑定好的量（§2.4 的变量表），不调方法、不点名种类：

- `guestExcluded`：存在一条现役边，持有者是主方、标的是来客，种类行 `excludes` 为真（被逐、通缉这类种类由卷八b 登记并把该列填真）。
- `guestMember`：存在一条现役边，持有者是来客、标的是主方，种类行 `membership` 为真。
- `guestPermitted`：存在一条现役边，标的是来客，持有者是主方或主方的职位，种类行 `grantsEntry` 为真。
- `stanceTierOrder`：主方对来客在好感轴上的立场档的 `order`；`guestEsteemOrder`：来客 `esteemTier` 的 `order`；`acceptance`：主客文化的接纳度。

立场基线不是新存储：它就是 R18-4.1 里的静态部分 `S`。

#### 4.10.2 统一入口

读：`treatment(engine, state, hostId, guestId)`；`hostId` 是组织或地点所属的治理组织。写：无自有状态。

#### 4.10.3 规则

- **R18-10.1 待遇派生**：`treatment = first(rules.social.treatment)`。进入、服务、价格、借宿、求见各自读档条目的字段；本卷不写这些系统的规则。
- **R18-10.2 基线来源**：陌生人之间没有事件条目时，读数只来自静态行：文化接纳、信仰敌意、主方组织之间的关系传导、身份等级差。这些行由各定义卷登记（R18-4.7）。
- **R18-10.3 入籍的效果自动出现**：入籍（事件与资格归卷八b）写入的是一条成员类持有边。边一成立，`treatment` 的 `when` 与立场传导 `adopt / conduct` 的结果随之改变，不需要另写“改基线”的动作。本卷订阅入籍事件只为生成一条“被接纳”的事件条目（来源表里的一行）。
- **R18-10.4 客人权利**：`guestRight` 为真的档，主方对来客负有庇护的义务种类行；侵犯客人是立场来源表与评价行里的事件。
- **R18-10.5 驱逐与通缉**：被逐、通缉是持有边（种类行由卷八b 登记）；它们使 `treatment` 落到最低档，靠的是种类行的 `excludes` 列与规则表里读 `guestExcluded` 的那一行，不点名种类。新增一种排除性的边，只要把 `excludes` 填真。

#### 4.10.4 交互

卷八b（入籍、驱逐、通缉、等级）；卷五（进入权读 `access`，见卷五 §4.13（进入权与私宅许可））；卷六（服务与价格读 `serviceFactor`）；卷七（接纳度、信仰敌意、尊重与排除三档）；卷十九（借宿）。

- A18-10.1（扫描式）：treatment.mjs 在状态登记表里没有任何可写路径。所扫系统键：卷五的进入权、卷六的服务与定价、卷十九的借宿这三组系统文件；判据：这些文件里返回准入结果或价格系数的函数，凡读来客的 `culture`、`species`、所在地点或任何持有边的，必须是经 `treatment` 的返回值读档条目字段；函数体内直接读这些维度键即命中。待遇表的 `when` 编译后的树里，叶子只有 §2.4 变量表列出的量。
- A18-10.2（不变量式）：`treatment` 是纯函数；入籍事件提交后同一拍内重读即得新档。
- A18-10.3（扩展性式）：新增一个待遇档或一种许可，只加条目与规则表行，不改 .mjs。

### 4.11 恐惧值

#### 4.11.1 维度

恐惧是立场数轴的一条轴（轴条目 `min` 为 0、不传导），来源行在同一张来源表里。胆量：`boldness = fear.boldBase + fear.boldScale × 观察者的有效人格[fear.boldAxis]`，其中 `boldAxis` 是规则表里的一个人格轴引用。恐惧档 `fear_tier` 的阈值在 `fear.tiers`，档条目带 `modifiers` 与 `complyFactor: number`。

#### 4.11.2 统一入口

读：`stance(…, 恐惧轴)` 与 `dread`。写：同 §4.4，只由事件生成条目。

#### 4.11.3 规则

- **R18-11.1 恐惧来源**：处决、酷刑、屠戮、示威等事件以事件行登记，角色可为受事、目击、听闻；仁慈之举以负值行登记。战力对比由卷十三 §4.18（遭遇与谈判结算）登记为静态行（读它定义的威慑量派生维度）。
- **R18-11.2 回归**：恐惧条目按 R18-4.3 线性衰减，自然回到 0；没有单独的回归拍。
- **R18-11.3 畏惧判定**：`dread = stance(o, t, 恐惧轴) − boldness(o)`；`tier = first(fear.tiers)`，读 `dread`。
- **R18-11.4 后果只经字段**：谈判与遭遇读 `tier` 条目的 `complyFactor`；在场时对士气的影响，由遭遇开始事件触发写入档条目的 `modifiers`（期限到遭遇结束事件），经卷二登记的修正写者；阴谋、抗命等动作的门控读 `tier` 的序。本卷不写这些系统的结算。
- **R18-11.5 恐惧与好感独立**：两条轴各算各的；同一事件可以同时命中两条轴的行（处决既加恐惧又按价值轴减好感）。

#### 4.11.4 交互

卷十三（威慑量来源行；遭遇与谈判读 `dread`）；卷二十六 §4.8（个人士气）（修正项目标）；卷八（暴政、抗命、派系不满读恐惧档）；卷二十二 §4.7（秘密）（参与阴谋的门控读档）。

#### 4.11.6 验收断言

- A18-11.1（扫描式）：全库没有第二份恐惧或威慑存储；deterrence 与谈判文件不导入平衡表、没有中文状态比较与睡眠正则；规则层没有人格轴 id 字面量（胆量轴只经规则表引用）。
- A18-11.2（不变量式）：恐惧读数恒在轴条目的 `[min, max]` 内。事件部分单调回零：固定一份状态快照（条目集合不变），取两个时刻 t1 < t2 分别算恐惧轴的事件部分 `E`，逐条目有 `|v(t2)| ≤ |v(t1)|`，且过了各自的到期时刻后为 0。静态部分（威慑量差）与胆量（有效人格）会随装备、伤情、修正项到期而变，不在这条断言之内；`dread` 整体不保证单调。
- A18-11.3（扩展性式）：新增一种恐怖手段（例如公开示众）只加事件类型行与来源行，不改 .mjs。

### 4.12 社交互动、斗殴与相容性

#### 4.12.1 维度

社交互动是动作目录条目（卷九定义）；本卷在其上登记社会属性 `social_act`：`{valence: number −1..1, needsConsent: boolean, satisfies: map<心理需求代号, number>, minTier: integer nullable, escalates: boolean}`。互动的立场后果由其事件动词在来源表里的行给出，不写在动作上。

`intimate: boolean` 不放在可选的社会属性行上，而是**动作目录条目自身的必填字段**（请卷九收录，见 §5.2）：目录里每个动作都必须表态，缺了加载失败（E-REL-INTIMATE-FIELD）。没有登记社会属性行的动作同样受 R18-9.1 检查。

相容性权重 `social.compat = {persWeights: map<ref vocab pers, number>, valueWeights: map<ref vocab value, number>, prefWeight: number}`。斗殴参数 `social.brawl = {regardMax: number, chanceAxis: ref vocab pers, chanceCurve: curve, cooldownDays: integer}`：概率是受事者某条人格轴有效值上的一条曲线，不用表达式。

#### 4.12.2 统一入口

读：`compat`。写：无自有状态；互动经卷九的动作裁决，关系与立场经各自写者。

#### 4.12.3 规则

- **R18-12.1 相容性**：`compat(a,b) = Σ_k w_k × (1 − |x_a[k] − x_b[k]| ÷ 2) ÷ Σ_k w_k`，k 遍历权重表里的人格轴与价值轴，`x` 取有效值（轴域 −1..1）。对称、纯函数。
- **R18-12.2 对象选择**：空闲社交时，对象从同处一地、互相已知者中按 `权重 = social.pickBase + compat + 好感读数 ÷ 好感轴条目的 max` 抽取（权重为负按 0 计），骰值键用本卷登记的社交流。是否去社交由决策管线按心理需求决定。
- **R18-12.3 互动裁决**：互动走卷九的统一裁决；`needsConsent` 为真的走同意条款；动作目录条目 `intimate` 为真的先过 R18-9.1 的 C2（按参与的身体判）；`minTier` 非空时要求对方对发起者的好感档不低于它。成功度影响事件的幅度字段，来源表的 `value` 乘以该幅度。
- **R18-12.4 需求满足**：互动事件按 `satisfies` 经效果族满足双方的心理需求（需求定义见卷二十六 §4.3（心理需求））。
- **R18-12.5 斗殴**：一次 `escalates` 为真且 `valence` 为负的互动之后，若受事者对发起者的好感不高于 `regardMax`，按 `lookup(chanceCurve, 受事者在 chanceAxis 上的有效人格值)` 给出的概率抽一次（心情、醉酒等状态经修正项改变有效人格值，从而改变概率）；命中则发“斗殴开始”事件，战斗结算交卷十三；同一对在 `cooldownDays` 内不再触发。决斗是正式动作，归卷十三 §4.11（决斗），接受与否读人格维度与恐惧档，不读文字。
- **R18-12.6 对话**：对话与交涉的状态机归卷九 §4.13（对话与交涉状态机）；它读本卷的 `stance`、`dread`、`treatment`、`recall`，不另存态度。

#### 4.12.4 交互

卷九（动作、裁决、同意、对话）；卷十三（斗殴与决斗的战斗结算）；卷二十六（需求、心情、人格）；卷七 §4.19（人生礼仪）（失礼是带负 `valence` 的互动事件，评价归卷七）；卷二十一（醉酒等状态经修正项影响斗殴曲线的输入）。

#### 4.12.5 数据实例

```json
{
 "compat": {"persWeights": {"pers_example_warmth": 1, "pers_example_order": 1}, "valueWeights": {}, "prefWeight": 0},
 "pickBase": 0.5,
 "brawl": {"regardMax": -20, "chanceAxis": "pers_example_calm", "chanceCurve": [[-1, 0.25], [0, 0.05], [1, 0.05]], "cooldownDays": 30},
 "actionCatalogIntimate": {"act_example_chat": false, "act_example_insult": false, "act_example_court": true},
 "social_act": {
  "sact_example_chat": {"valence": 0.3, "needsConsent": false, "satisfies": {"need_example_social": 0.2}, "minTier": null, "escalates": false},
  "sact_example_insult": {"valence": -0.8, "needsConsent": false, "satisfies": {}, "minTier": null, "escalates": true},
  "sact_example_court": {"valence": 0.6, "needsConsent": true, "satisfies": {"need_example_social": 0.3}, "minTier": 3, "escalates": false}
 }
}
```

- 【西陲】两位村民两条人格轴差 0.4 与 1.0：`compat = ((1 − 0.2) + (1 − 0.5)) ÷ 2 = 0.65`。求偶打分用 §4.9.5 的 `kin.accept`（`wRegard` 1、`wCompat` 0.5、`compatScale` 100、`compatMid` 0.5、`wRank` 1）：相容项为 `0.5 × 100 × 0.15 = 7.5`；双向好感取小 30、等级差项 −10，合计 27.5，不低于 `acceptMin` 25，提出婚约。
- 【非西陲】海港酒馆里一次辱骂：受事者好感 −35 不高于 −20，沉稳轴 −0.5，曲线在 −1 与 0 之间线性插值，`chance = 0.25 − 0.5 × (0.25 − 0.05) = 0.15`，按骰值键抽取，命中则斗殴。
- 【非人类】两头公鹿的威吓是同一类 `escalates` 互动，升级为争斗的判定走同一条规则；没有“动物打架”专项。
- 【超自然】凡人向精怪求爱：该动作目录条目 `intimate` 为真，先过 R18-9.1 的 C2（双方按各自物种成熟龄，被附身的身体按宿主判），再过同意与 `minTier`；其余与凡人之间相同。

#### 4.12.6 验收断言

- A18-12.1（扫描式）：social 系统文件里没有人格、关系、动作 id 的字面量；没有读人格 JSON 文本或记忆文字的正则；互动的立场后果只出现在来源表。
- A18-12.2（不变量式）：`compat(a,b) = compat(b,a)` 且落在 [0,1]；每个斗殴事件之前同一刻都有一次满足 R18-12.5 条件的互动事件。
- A18-12.3（扩展性式）：新增一种社交互动（例如赠礼）只加动作目录行、社会属性行与来源行，不改 .mjs。
