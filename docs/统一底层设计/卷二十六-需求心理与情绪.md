## §1 领域总述

### 1.1 真实世界怎样运转

1. **气质相对稳定，且各维相关。** 胆大的人多半不谨慎，勤勉的人多半有节制。群体（物种、文化）只移动分布的中心，不决定个人。
2. **价值是后天的。** 人从所处文化继承一套"什么要紧"，再按自己的气质偏离一些。
3. **需要不止于吃睡。** 长期无人说话、无事可乐、所处环境丑陋、无处敬神，人都会难受，只是难受得慢。
4. **心情是被推着走的量。** 每件事推一下，推力随时间消退，同样的事重复发生推力递减；同一件事落在不同人身上，推力大小甚至方向都不同。
5. **长期难受会积成压力，压力过线人会失常。** 失常有轻重，重的若无人照看会要命。
6. **心情很好时偶尔有超常发挥。**
7. **临阵的斗志是另一个量**，受伤亡、指挥、同伴去留左右，与平日心情相关但不相同。
8. **人不是最优化机器。** 同样处境下的选择有随机成分，心乱时更随机。

### 1.3 本卷的总机制（一句话：三种数据行加一条推进规则）

```
人格 personality ─┐                                    ┌→ 容器档上的修正项 ─→ 任何已登记的修正键
价值 values ──────┼→ 想法行 thought ─→ 心理量 gauge ───┤   （驱力权重、决策噪声、身体能力、技能、过程槽）
偏好 preference ──┘     （推多少）       （容器实例）   └→ 发作行 episode ─→ 另一个容器实例（崩溃、疯狂、灵感）
事件、现状、身体状态 ─→ 想法行的触发                         驱力权重 + 噪声 ─→ 卷九决策管线
```

- **心理量 gauge**：一个 0–1 的量，存为一个心智类状态容器实例。心理需求、心情、压力、士气都是心理量，区别只在数据。
- **想法行 thought**：一条"在什么条件下、对哪个心理量、推多少"的数据。想法不落状态，由事件与现状算出。
- **发作行 episode**：一条"某个心理量落在某个区间时，按危险率触发一段有时限的失常或超常"的数据。崩溃、疯狂、灵感、奇想是同一种行。
- **推进规则只有一条**（R26-4.4），对全部心理量、全部个体相同。
- 心理状态对外只有两个出口：容器档上的修正项（经卷二 §3.3（求值管线）求值），与本卷登记的视图输出（如有效士气、有效压力；口径只在 §3.1"心理视图输出"一段定义）。别卷可以对视图输出做算术和比较；心理容器的内部字段（severity、档、发作字段）对别卷一律禁读，由 §3.5 的 P26-7、P26-8 两项扫描把守。本卷不新增任何状态顶层键。
- 人格与价值是存储维度：生成时按种子抽出基础值，之后基础值不变；群体基线、后天变化一律是修正项，读的是有效值（R26-1.2、R26-2.2）。

### 2.3 本卷登记的状态容器行

格式按卷二 §1.11（状态容器），本卷只登记行并遵守以下约束（校验码 E-PSY-GAUGE-STATUS）：

1. `target` 为心智类；`severity` 取值 [0,1]；`contagion`、`immunity` 为空；`duration` 为空（发作的时长只写在发作行）。
2. 每个心理量行恰好对应一个容器行，每个发作行恰好对应一个容器行，互不共用。
3. 容器档的 `modifiers` 可指向任何已登记的修正键；本卷的规则不规定指向哪里，唯一的限制写在第 7 条（心理量容器的档修正不得指向心理量基线的两个键）。`stages[].id` 取自 pstage 族。
4. 容器所属的族由行数据给出；规则只读族条目的三个布尔字段，不点名族。本卷需要一个"清醒但不能发起行动"的新族（见卷末代号表与 §8 Q5）。
5. **初值只有一处**：一律是容器行的 `severity.initial`。累积型心理量的容器、发作的容器必须填；追随型心理量的容器必须为空（它的初值是建实例那一拍的目标，R26-3.2）。心理量行、发作行上没有初值字段。
6. **升降速率**：心理量的容器 `severity.perDay` 必须为空，它只由 R26-4.4 推进（字段怎样锁见第 7 条）。发作的容器必写 `severity.perDay` 的 `untended` 与 `tended` 两项（照卷二十一 §2.1（状态表 `status`：身体类行的字段含义）：`untended` 必写，不变写 0；`tended` 可写 null，null 的含义照卷二十一 §2.1（状态表 `status`：身体类行的字段含义）；`immune` 写 null），按卷二十一 R21-1.2 的病程律升降：卷二十一 R21-1.1 写明病程律对心智类行同样生效，照护取卷二十一 R21-9.1 的照护水平（取值 [0,1]；本卷说的"有人照看、无人照看"是它取 1 与 0 的两端）；`untended` 写 0、`tended` 写 null 的发作容器 severity 不随时间变。发作容器的 severity 还可以被任何效果族的 status 输出增减（诊治、安抚、法术）。本卷不为发作另写推进规则。发作容器的推进同样只在整拍边界结算，路径无关与存法、误差界都由病程律一侧保证（卷二十一 R21-1.2；见 §8 Q4）。
7. **心理量容器的字段白名单与封闭清单（唯一定义处；写法照卷二十一 R21-4.2 的亏空行白名单，用白名单、不用禁填清单。R26-3.4、R26-3.7、R26-4.4、R26-4.8 只引用本条）。**
   - **认法**：心理量容器 = 被 gauge 族条目的 `container` 字段指到的容器行。按这个引用认，不按族认，不读行的代号，与卷二十一 R21-1.1 是同一认法。发作容器不被 gauge 条目指到，不在本条之内，照常走病程律，`severity.perDay`、`responds`、`tendable`、档上的 `lifeThreatening` 都可以填。
   - **白名单（共 4 项）**：心理量容器行只许填 `family`、`target`、`severity.initial`（按第 5 条）、`stages`；`stages` 的每一档只许填 `id`、`minSeverity`、`modifiers` 三项。状态表的其余字段一律锁死，行上或档上非白名单字段非空即加载失败（E-PSY-GAUGE-STATUS）。`severity.perDay`（三个键任一）、`severity.lethal`、`responds`、`tendable`、`immunity`、`contagion`、`duration`、`driveRX`、`driveOnset`、`tends`、`sequela`、`persistent`、档上的 `effects` 与 `lifeThreatening` 等都因不在白名单而被拦，不逐个设禁；状态表今后新加的字段默认锁住，要放开须改本白名单。出处注记 `basis`、`status` 与显示名不是规则字段，不在判定之内。
   - **档修正的目标**：心理量容器档上的 `modifiers` 不得以 `person.gaugeTarget[…]`、`person.gaugeInflow[…]` 为目标（任何心理量键都不行），违者同码。心理量容器自己的档不能直接推别的心理量。心理量之间的影响清单（全部列在这里）：以想法行为主（R26-3.7、R26-4.5）；另有两条登记通道——视图输出（R26-3.7：登记为 `exposed` 的心理量经 `psychOut` 进别卷修正项的条件）与发作容器档上的修正项与 `effects`（心理量落在区间里触发发作，发作容器不是心理量容器：它的档修正按 R26-4.8 可以指向这两键；它档上的 `effects` 照卷二 §1.11（状态容器）的容器格式可以填，其中的 status 输出按 R26-3.5 带 `direction`，可以增减心理量容器的 severity，即下面封闭清单的第三类写入）。发作档上的 `effects` 只有这一条登记路径：加载期对它与对别处的效果族 status 输出同样校验，指向心智类容器而缺 `direction`，或 `direction` 与 `severityDeltaRX` 的符号不一致、判不出来，即 E-PSY-DELTA-DIRECTION（§2.6，现有码，不另设）；发作档上不存在不带 `direction` 而写到心理量容器 severity 的输出。判据只读修正键的维度名与 gauge、`container` 这几个固定代号。
   - **由此得到的封闭清单**：心理量容器 severity 的写入只有三类——建实例时落初值（R26-3.2）、R26-4.4 的整拍推进、带 `direction` 的效果族 status 输出（R26-3.5）。推进式的读数只有三个——行上的 `baseRX`、`gaugeTarget` 或 `gaugeInflow` 上的修正项（R26-4.8）、成立想法的推力之和（R26-4.1 至 R26-4.3）。**不受影响的项**：照护水平、药性浓度、免疫记录、病种族的好转与恶化倍率、传染，都进不了心理量容器——病程律不对它执行（卷二十一 R21-1.1），行上也没有能接住它们的字段。诊治与照护的通用路径（§3.1 闭集表）读到心理量容器时因此无事可做，这不靠那条路径认出"是心智类"。

**心理量的容器是常驻容器**（二审 N2 裁定）：凡被心理量行的 `container` 指到的容器，实例在 `applies` 为真期间一直存在，severity 降到 0 也不移除，0 处的档照常生效，下一拍从 0 接着推进；只有 `applies` 转假才撤（R26-3.2）。容器实例的生命周期（何时建、何时移除，发作容器在内）一律以卷二 §1.11（状态容器）的容器规则为准，本卷不写"数值到某点即移除"一类条文（§8 Q4）。

### 2.5 联合分布

## §3 统一入口

### 3.1 读入口

本卷不新增 view。心理读数是人物的一部分，一律经卷二 §2.1（入口清单）登记的 `personView`；容器实例经 `statusView`。

实现文件 `server-plugin/psych.mjs`（规则层），其读函数登记在 `view:personView` 的实现函数组里，依赖声明按卷二 §2.3（记忆与依赖声明）。

**`psych` 的读者是闭集**，登记在卷二 §2.7（系统声明表 `state-owners.json`）系统 `psych` 的 `psychReaders` 一栏，闭集外的读取按 P26-8 报错。每个读者能做什么也写死：

|---|---|---|

| 诊治与照护（卷二十一） | 容器实例 | 只经对一切容器族相同的通用代码路径；该路径不得以"是心智类"为条件 |

除此之外，任何规则要让心理状态起作用，只有两条路：读被修正后的普通维度（驱力权重、决策噪声、身体能力、技能等），或读下面登记的心理视图输出。

**心理视图输出**（二审 N1 裁定。这条口径只在本段定义，别处一律引用本段）

1. 心理量对外只经视图输出暴露。视图输出就是 `personView().dims.psychOut[<心理量代号>]`，键域是心理量行上 `exposed` 为真的那些心理量。登记一个视图输出，就是把该行的 `exposed` 写为真，不改 `.mjs`。首批登记两个：有效士气、有效压力（数据见 §4.8.5、§4.5.5）。
2. 值是该心理量最近一次整拍结算后的值（R26-4.4），取值 [0,1]，以 Fact 返回。它已经含全部想法推力与基线修正项的作用，所以叫"有效"。主体没有该心理量实例即未知，不以 0 代替。读取不触发推进，也不临时另算。
3. 别卷读视图输出，可以对它做算术、比较、分支，也可以写进自己数据行的 RX。视图输出不是心理内部字段，P26-7、P26-8 不拦它。
4. 心理容器的内部字段对别卷一律禁读：`personView().psych` 的全部字段，以及 `statusView` 返回的心智类容器实例的 `severity`、档、`since`。例外只有上表闭集里的三类读者，各按写死的用途。扫描以此为界：P26-8 的污点只从内部字段起算，经别名、解构、函数返回值、算术运算一路传播，没有出口；视图输出由 `view:personView` 实现函数组在入口内算出，不带污点。
5. 卷十三读哪个：军团士气的聚合与溃散判定都读成员的有效士气，即 `psychOut` 里以个人士气心理量为键的那一项。用哪个心理量的代号由卷十三的规则表给出；该代号若不是 `exposed` 的心理量，读数恒为未知并记缺口。卷十三不再列入 `psychReaders`，不读 `psych`。
6. 牵连清单（随本口径同步改过的各处）：§1.3 第五条；§2.1 `psychOut` 行；§2.2 心理量行的 `exposed` 字段与行内 RX 说明；本节读入口表、闭集表（去掉军团聚合一行）；§3.5 心理维度名单、P26-8 及其后说明；§4.5.5 压力行与末条；§4.8.4、§4.8.5 士气行、A26-8.S；§5.1；§5.3；§7 M26-10、M26-17；术语表。

## §4 子系统

### 4.1 人格向量与联合分布

#### 4.1.1 维度

读：`personality`（§2.1）；pers 族条目；`personality_default` 联合分布；物种行与文化行的 `personalityBias`。

#### 4.1.2 统一入口

读：`personView().dims.personality`（有效值）与其 `base`（基础值）。写：基础值没有运行期写者，采样不落状态；一切后天变化都是修正项，写者是修正写者（§3.3）。

#### 4.1.3 规则

- **R26-1.1 基础值的采样**（派生形状，纯函数）。加载期对 `corr` 做一次定点下三角分解 `corr = L·Lᵗ`（整数开方用卷二 §1.10（随机实例化）已有的牛顿法）。分解允许零主元，判据与卷二同为半正定：某主元小于 0 即 E-DIM-SAMPLE-CORR；主元等于 0 时该列其余元素取 0，不做除法。结果冻结。对个体：按卷二 §1.10（随机实例化）的联合种子键取第 k 个标准正态数 `z_k`（k 为该轴在 `axes` 列表中的序号，§2.5）；`x = L·z`；`personality` 的基础值第 k 项 = `clamp(mean_k + sd_k × x_k, 取值域)`。全程定点。这就是卷二 §5.5（个体 person）那一行 `sample` 的实现；卷二所说"首批按 marginals 独立采样"由本条取代。
- **R26-1.2 群体基线是常驻修正项**。加载器为每个带 `personalityBias` 的物种行、文化行的每条所写轴各生成一条修正项（缺键按不加项处理，§2.1）：目标 `person.personality[<轴>]`，阶段 add，值为该行所写的数，`unpenalized`，来源为该行，作用域为"物种是该行的个体"或"`culture` 解析到该行的个体"（作用域解析按卷二 §3.5（作用域与状态键表））。做法与卷四 §4.3（属性（身体 / 精神））由加载器生成随龄修正项相同。某一来源未知的个体没有对应那条修正项，不以 0 代替。有效值 = 基础值经卷二 §3.3（求值管线）叠加这些与其他修正项，钳到 [-1,1]。
- **R26-1.3 暂时改变**只经修正项：任何来源（状态容器档、信条、传统、职位、附魔）都可以挂以 `person.personality[<轴>]` 为目标的修正项，由唯一管线求值。
- **R26-1.4 永久改变**也只经修正项：一条时长为空的运行态修正项，由效果族输出、修正写者写入。基础值生成后不再改写。本版不设自发漂移规则。
- **R26-1.5 分档只属显示层。** 规则只读数值；"胆大""怯懦"之类的称呼由显示层按语言包的档位表给出，规则不得读。
- **R26-1.6 轴的顺序只增不改。** 新轴追加在 `axes` 末尾，并使表头的采样版本号加一。

#### 4.1.4 交互

- 卷四：物种行提供 `personalityBias`；人物本体提供物种与出生地。卷七：文化行提供 `personalityBias`。
- 本卷内：`personality` 供 §4.2 的价值派生、§4.4 的想法缩放、§4.9 的驱力与噪声。

#### 4.1.6 验收断言

- **A26-1.S 扫描式**：P26-1、P26-2、P26-3 对人格相关路径与 pers 族为 0；旧文字数组读点为 0。
- **A26-1.I 不变量式**：同种子同个体两次读取逐位相同；以 `rules.psych.statSeed` 为夹具种子生成 `rules.psych.statSampleN` 个个体，其人格**基础值**的样本相关矩阵与 `corr` 各元素之差不超过 `rules.psych.corrTolerance`；基础值与有效值全部在 [-1,1]；`explain()` 逐段复算（基础值加各修正项）等于有效值；任何推进之后基础值逐位不变；`dims.personality` 的来源标记为采样（与卷二附录 B8 的断言一致）。
- **A26-1.X 扩展性式**：追加一条 pers 轴（词表条目、`axes` 末尾一项、边缘分布、相关行列）而不改 `.mjs`，新轴出现在每个个体的向量里，并可立即被想法行的 `persScale` 与驱力行的 `persLoad` 引用。

### 4.2 价值与偏好

#### 4.2.1 维度

读：`values`、`prefOffset`、`preference`（§2.1）；pers 条目的 `valueLoad`；文化行的价值缺省值，轴词表见卷七 §4.25（价值轴词表）；文化对各类事物的偏好权重，经卷七 §4.28（文化偏好输出接口）。

#### 4.2.2 统一入口

读：`personView().dims.values`（有效值）与其 `base`、`.preference`，`preferenceOf()`。写：价值的基础值没有运行期写者，后天变化只经修正项；偏好的永久改变只经 `prefOffset` 的偏离行。

#### 4.2.3 规则

- **R26-2.1 个人价值基础值的采样**（派生形状，纯函数）：对价值族的每个键独立取正态数，均值取主体文化行在该轴上的缺省值，标准差 `rules.psych.valueSd`，钳到取值域；惰性按键求值，种子键的维度部件带上该键。文化未知，或文化行在该轴上没有缺省值，则该键不采样、读数未知，按 `gap` 处置，不以 0 代替。"分布的均值取自别的行的维度"是卷二 §1.10（随机实例化）已有的做法（属性的分布取自物种行），本条沿用；需要卷二补的一句见 §8 Q3。
- **R26-2.2 人格对价值的牵引是常驻修正项**。加载器为每条人格轴 p（照 §2.2 pers 行）、其中每个所写价值键 v 生成一条修正项（缺键按不加项处理，§2.2）：目标 `person.values[v]`，阶段 add，值 = `valueLoad_p[v] × 主体人格第 p 轴的基础值`，`unpenalized`，来源为该人格轴条目。这里读人格的**基础值**而不是有效值，两个理由：牵引说的是气质对价值形成的长期作用，不该随一时的附身或醉酒而动；修正项的值不读别的维度的有效值，求值没有先后依赖。价值的有效值 = 基础值经卷二 §3.3（求值管线）叠加这些与其他修正项（信条、传统、法术），钳到 [-1,1]。基础值未知的键，有效值也未知。
- **R26-2.3 个人偏好偏离的采样**（派生，纯函数）：对键域里的每个键独立取正态数，均值 0、标准差 `rules.psych.prefSd`；惰性按键求值，种子键的维度部件带上该键。
- **R26-2.4 个人偏好**（派生）：`preference[c] = clamp(rules.psych.prefCultureGain × f_c + prefOffset[c], [-1,1])`，`f_c` 是文化对 c 的偏好权重除以同一权重表的最大值（0–1）；文化未给 c 权重或文化未知时该项不计入；权重表的最大值为 0 时不做除法，同样整项不计入。
- **R26-2.5 对一个具体对象的偏好**：取该对象全部类别、材料类别、分类学类别、审美代号（含上位链）在 `preference` 中绝对值最大的一项；并列取代号字典序最小者；全部未知则未知。
- **R26-2.6 喜恶门槛**：绝对值不低于 `rules.psych.prefThreshold` 才算喜或恶，只供显示与 §4.7 的取材使用，不另存。
- **R26-2.7 作用途径只有三条**：经想法行的 `valueScale`、`prefWeight` 与 `conduct` 触发进入心理量（§4.4）；经驱力行的 `valueLoad` 进入驱力权重（§4.9）；经 `preferenceOf()` 供决策管线给候选加权。价值与偏好不直接改任何别的量。

#### 4.2.6 验收断言

- **A26-2.S 扫描式**：`.mjs` 中 value 族字面量为 0；`preference` 在任何数据行里手填为 0（码 E-DIM-DERIVED-WRITTEN）；`values` 的实体行显式值都带 basis；本卷数据里不出现价值轴的定义字段（轴只在卷七）。
- **A26-2.I 不变量式**：夹具里把一个个体的 `culture`（建行时写入的出生事实）换成另一文化、其余（含种子键）不变，且两个文化行都不带 `personalityBias`：`values` 每个键的基础值与有效值的变化量都恰等于两文化在该键上的缺省值之差（钳位前，定点下严格相等）。两个文化行带不同 `personalityBias` 时，上式仍然成立，因为牵引只读人格基础值（R26-2.2），而基础值不随文化变；此时变的只有 `personality` 的有效值，变化量等于两行基线之差。文化未知的个体 `values` 为未知而非 0。任何推进之后价值基础值逐位不变。
- **A26-2.X 扩展性式**：卷七新增一条价值轴后不改 `.mjs`，每个有文化的个体自动得到该轴的值；新增一个物品类别后，每个个体对它自动有偏好读数。

### 4.3 心理需求

#### 4.3.1 维度

读：need 族、gauge 族及其容器行；`gaugeTarget`、`gaugeInflow`；主体所在地点的维度（如房间美观聚合值，见卷十九 §4.11（房间评价））；效果族表。

#### 4.3.2 统一入口

读：`personView().psych.gauges`；`needSatisfiers()`。写：只经 `status.mjs`（§3.3）。

#### 4.3.3 规则

- **R26-3.1 心理需求就是登记在 need 族的心理量。** 它的匮乏程度是该心理量容器实例的 severity：0 为满足，1 为极度匮乏。需求没有自己的状态字段。
- **R26-3.2 谁有这种需求**由该心理量行的 `applies` 决定：为真而无实例则建（累积型初值取容器行的 `severity.initial`，追随型初值取当拍目标；初值只有这一处，§2.3 第 5 条），为假而有实例则撤。
- **R26-3.3 匮乏怎样变化**按 R26-4.4：累积型需求按 `gaugeInflow` 的修正后值每日增长；追随型需求向 `gaugeTarget` 的修正后值靠拢。存法（扩展标度）与误差界按 R26-4.4 的存法一段，本条不另写。
- **R26-3.4 需求怎样被满足**只有三条路，三条都在 §2.3 第 7 条的封闭清单上：一是指向该心理量的想法行（环境持续供给，如所处场所的美观）；二是效果族输出里对该容器的 severity 减量（动作、设施服务、物品使用、仪式都经卷二 §3.9（效果族表）的同一形状）；三是挂在该需求基线上的修正项（R26-4.8：累积型挂 `gaugeInflow`，追随型挂 `gaugeTarget`；法术、附魔、职位、信条都走这里），它改的是匮乏涨落的速率或去向，不直接写 severity。没有第四条：容器行的其余字段按白名单锁死，照护、药性、免疫、病种倍率都作用不到它（§2.3 第 7 条"不受影响的项"）。
- **R26-3.5 满足途径的索引是派生的，只读一个枚举字段**：效果族的 status 输出凡指向心智类容器，必须带封闭枚举字段 `direction`（raise 使 severity 升，lower 使它降）。加载期扫描效果族表，凡有 `direction` 为 lower 的输出指向某需求容器的族，计入 `needSatisfiers(need)`。索引不去判断 RX 的正负。`direction` 与 RX 是否一致由校验器另查：对 `severityDeltaRX` 做区间求值，每个参数取其 `domain` 的两个端点，`magnitude` 取 `magnitudeRX` 在同样端点上的值域；全部端点组合的结果都不大于 0 才配 lower，都不小于 0 才配 raise；区间求值只对由常数、参数、`magnitude` 经加、减、乘以常数构成的式子做；RX 含别的运算、读了别的变量，或端点结果有正有负，即判不出来，报 E-PSY-DELTA-DIRECTION。作者不手写"某需求靠什么满足"。
- **R26-3.6 需求怎样催人行动**：只经该容器各档上的修正项去抬高相应的驱力权重（§4.9）。没有"需求到目标"的专用分支。
- **R26-3.7 需求怎样影响心情**：以 `state` 触发的想法行读该需求心理量并推心情（§4.4）为主，另有下面明列的两条登记通道（清单单点在 §2.3 第 7 条"档修正的目标"）。把守在 §2.3 第 7 条：需求容器是心理量容器，它的档修正不得以 `gaugeTarget`、`gaugeInflow` 为目标，档上不得有 `effects`，所以它没有绕开想法行去推别的心理量的写法；别卷数据行的 `when` 与 RX 读不到它的 severity（P26-8）。明列的另两条通道：一是视图输出——需求心理量若登记为 `exposed`，别卷可按 §3.1 读它的视图输出并写进自己修正项的条件，那是登记过的公开读数，不算绕过；首批四种需求都不登记。二是发作容器档上的修正项与 `effects`——需求心理量落在发作行 `gate` 的区间里触发发作（R26-5.3），发作容器不在 §2.3 第 7 条之内，它的档修正按 R26-4.8 可以指向心情的基线，它档上 `effects` 的 status 输出按 R26-3.5 带 `direction`、可以增减心情容器的 severity（缺 `direction` 或与式子符号不一致即 E-PSY-DELTA-DIRECTION）；这是登记过的数据通道，同样不算绕过。
- **R26-3.8 身体需要不在此列。** 它们的容器、数值、阈值分别归卷二、卷四、卷二十一；它们对心情的影响，通道有两条：一是 `status` 触发的想法行（R26-4.1）；二是身体类状态行（含卷二十一的亏空行）的档修正指向心理量基线，属 R26-4.8 的第三条路，准许。谁能给 `gaugeTarget`、`gaugeInflow` 挂修正项由本卷 R26-4.8 定，不交卷二十一。

#### 4.3.6 验收断言

- **A26-3.S 扫描式**：`.mjs` 中 need、gauge 两族字面量为 0；代码里不存在按需求种类分支的 `switch` 或等值比较；本卷数据不登记身体需要的容器行（饥、渴、疲劳、睡眠各族的容器行数为 0）。
- **A26-3.I 不变量式**：首批登记的每个 need 代号都有需求行，每个 gauge 代号都有心理量行，每个心理量行所指的容器行都存在（加载期 E-PSY-GAUGE-STATUS；卷末自检第 12 项对本卷数据做同一检查）；每个心理需求恰对应一个心理量、一个容器；`applies` 为假的主体没有实例；夹具里把一个累积型需求的 severity 降到 0，容器实例仍在，下一拍从 0 接着累积而不回到初值（常驻容器，§2.3）；severity 恒在 [0,1]；每个需求的 `needSatisfiers` 非空或有供给它的想法行（否则 W-PSY-NEED-UNSATISFIABLE）；`needSatisfiers` 的结果只取决于各输出的 `direction` 字段，把某输出的 RX 换成另一条同号的式子，索引不变。白名单（§2.3 第 7 条）：夹具里给一条心理量容器行逐个填上 `severity.perDay`、`responds`、`tendable`、档上的 `effects`，或让它的档修正指向 `gaugeTarget`、`gaugeInflow`，每一种都加载失败（E-PSY-GAUGE-STATUS）；给状态表新加一个字段而不改白名单，把它填在心理量容器行上同样加载失败；同样的字段填在发作容器行上照常通过。夹具里给主体加满照护、药性浓度与病种族倍率修正，心理量容器的 severity 逐位不变。
- **A26-3.X 扩展性式**：只加四行数据（需求、心理量、容器、一个效果族或一条供给想法行），新需求即对全部适用个体生效、进入决策候选，并在面板上以代号或显示名出现，不改 `.mjs`。

### 4.4 想法与心情

#### 4.4.1 维度

读：thought 族；心情心理量及其容器；主体的状态实例；主体已知的事件集合及知悉时刻，见卷二十二 §4.1（主观视图）；立场数轴，见卷十八 §4.4（立场数轴）；行为的价值评价行，见卷七 §4.26（评价行）；`personality`、`values`、`preference`。

#### 4.4.2 统一入口

读：`personView().psych.thoughts`（活跃想法及各自推力）、`.psych.gauges`。写：心情容器只经 `status.mjs`。想法没有写者，因为想法不落状态。

#### 4.4.3 规则

- **R26-4.1 想法何时成立**（派生）。按行的触发种类：
  - `state`：`when` 为真（为 null 即恒真）且 `xRX` 已知，即成立一条，`x = xRX`。
  - `status`：主体每有一个属于行上所写族的状态实例，成立一条，`x` = 该实例 severity。身体需要、伤病、药效经想法行影响心理走这里；另一条是它们的档修正挂在心理量基线上（R26-4.8）。
  - `event`：主体已知的每个事件，若动词等于行上所写动词、且主体在事件中的角色等于行上所写角色，成立一条；`related` 角色要求事件受事者与主体之间存在行上所写关系（`relation` 为 null 则任何受事者都算）。已过时长从知悉时刻起算，超过 `durationDays` 即不成立。
  - `conduct`：对主体作为施事的每个已知事件，先经该事件的类型行（卷二十四 §4.2（事件类型注册表））上登记的动作代号或罪名代号，到卷七 §4.26（评价行）取评价行（评价行以这两种代号为键，台账 S-27）。取不到评价行的事件**不成立**（吃饭、走路这类没有评价行的日常事件不产生条目）；取到则价值向量为 `e`，`x = Σ_v e_v × values_v`（对已知项求和），正为合乎本人价值，负为违背；`values` 全部未知时不成立。已过时长与 `event` 同样从知悉时刻起算。
- **R26-4.2 推力**（派生，定点）：`m = (基础推力 + prefWeight × 对象偏好) × P × V × R × D × K`。记不含 K 的乘积为 `m0`。七个因子（基础推力、偏好加项、P、V、R、D、K）逐条经 `psych.thoughts[].factors` 给出。
  - 基础推力：`curve` 在 x 处的值，或 `value`。
  - `P = clamp(1 + Σ_p persScale_p × personality_p, rules.psych.scaleMin, rules.psych.scaleMax)`；`persScale` 为空映射时 Σ 为 0，P = 1。
  - `V = Σ_v valueScale_v × values_v`；`valueScale` 为 null 则为 1（§2.2）；`values` 未知而行上 `valueScale` 非 null，该条不成立。
  - `R = stanceWeight × 主体对事件受事者的立场（归一到 [-1,1]）`（归一的除数：立场读数 ÷ 该立场轴条目的 `max`，负值 ÷ `|min|`，`min` 为 0 时负侧不出现；`max` 为正、`min ≤ neutral ≤ max` 由卷十八 §2.2（本卷登记的词表族与条目字段）`stance_axis` 条目的加载校验保证，本卷只引用）；`stanceWeight` 为 null 则为 1（§2.2）；行上 `stanceWeight` 非 null 而立场读数未知，该条不成立。
  - `D` = `decay` 在"已过时长 ÷ durationDays"处的值；`decay` 为 null 则为 1（§2.2）。
  - `K = rules.psych.stackTable[k]`。k 的排法：只在同一行、`m0` 不为 0 的成立条目之间排序号，`m0` 为 0 的条目不占名额、推力为 0；次序依次按 `|m0|` 从大到小、知悉时刻从新到旧、事件 id 升序，三级比较保证全序，结果与遍历次序无关。序号达到 `stackLimit` 或超出表长的条目 K 取 0。这样占住名额的总是分量最重的几条：五个陌生人的死讯（立场 0，`m0` 为 0）挤不掉一位亲属的死讯，三顿饭也挤不掉一次欺诈。
  - 对象偏好按 R26-2.5 取事件所涉对象；未知则该加项不计。
- **R26-4.3 同组取一**：同一 `group` 内只保留绝对值最大的一条；并列取想法行代号字典序最小者。
- **R26-4.4 心理量的推进**（时钟形状；全书心理量唯一的推进规则）。
  - **拍只在绝对时间的整拍边界上**：心理量 g 的结算时刻是世界时刻（分钟）能被该行 `tickMinutes` 整除的那些时刻，拍长 `Δt` 恒为 `tickMinutes` 折成的日数，没有不满一拍的结算。`psychTick` 收到推进区间 (t0, t1] 时，对落在区间内的每个结算时刻按时刻升序各结算一拍；区间内没有结算时刻就什么都不做，零头自然留给以后的推进。结算时刻的集合只由 t0、t1 与行数据决定，把同一段时间切成几次推进，得到的是同一组时刻、同一串结算。
  - 在结算时刻 t，对每个适用个体、每个在 t 结算的心理量 g，记 `S_g` 为 t 时刻指向 g 的全部成立想法的推力之和：
    - 追随型：`目标 = clamp(modified(gaugeTarget[g]) + S_g, [0,1])`；`sev' = sev + (目标 - sev) × (1 - exp(-ratePerDay × Δt))`。
    - 累积型：`sev' = clamp(sev + (modified(gaugeInflow[g]) + S_g) × Δt, [0,1])`。
  - `exp` 用卷二 §3.3（求值管线）"定点指数与整数次幂"一段的 `fixedExp`（算法就是卷二 §1.10（随机实例化）的定点指数表）；`Δt` 对每个心理量是常数，系数可在加载期算好。`ratePerDay × Δt` 须落在 `fixedExp` 的取值域内，越界按该函数的越界处置，即错。
  - **存法与误差界（只引卷二 §3.3（求值管线）"存量与余数结转"第 6 条及其中"m 的口径（唯一定义）"，本卷不另立口径）。** 心理量容器实例的 `severity` 与卷二十一病程律推进的是同一个字段，已按 `stockMode: extScale`、`precision: 8` 登记（卷二十一 R21-1.2 的存法一段），本卷不另登记。本规则的每拍更新全程在 10⁸ 标度下做，只用该条列出的内核函数：行数据与修正后读数（10⁴）先升标度；推力按 R26-4.2 的式子从左到右依次相乘，每次用 `fixedMultiply8`；曲线按 10⁸ 读法查；想法读到的别的容器 severity 取 10⁸ 存储值，不先截到 10⁻⁴；`psych.thoughts[]` 的 `magnitude` 与 `factors` 给的就是这组 10⁸ 标度的数。档门槛、发作区间升标度后比较；视图输出、档修正、显示按使用处的精度截断，存储值不截。一次写入的误差量 m 是确定式，以 10⁻⁸ 为单位；记号照卷二同条（`e` 是误差界，`B` 是上界，`E` 是存储值到上一次写入为止的累计误差界），放大系数的上界逐项注明给法：标"域"的按取值域界，其余按这一次写入时的参考值。参考值是同一条式子不截断算出的值；离散判定（`applies`、`when`、想法是否成立、同组取一、K 的排序、落在哪一档）取与定点实现相同的分支，误差界只管连续量。误差界说的是定点值与参考值之差，与下一条的路径无关是两回事：路径无关仍是逐位相同，没有容差。

  - **路径无关**：本规则不读推进请求的长度、类别、切分方式，只读世界状态与结算时刻。本规则不声明闭式解，声明为"非闭式，只能逐拍"：想法会消退、会过期、会互读别的心理量，区间内输入并不恒定，所以不提供"一步跨多拍"的近似。按写卷须知补充裁定，一次推进 N 天与分段推进合计 N 天必须得到同一份存档摘要；本规则满足它的方式就是上面两条，没有容差。个体处在哪一层由卷二十七 §4.1（三层模拟运行矩阵）按存在状态里的档位决定，粗层的结算区间同样止于整拍边界（R27-1.6、R27-1.11）；被折叠进聚合体的个体没有心理量实例，实体化时按 R26-3.2 取初值。
  - **需要快反应的心理量用小拍长**：拍长是行上的数据。临阵士气这类要在一场战斗里起落的量，把 `tickMinutes` 写小、`ratePerDay` 写大即可（§4.8），不需要第二条推进规则，也不需要读取时另算。
- **R26-4.5 同拍快照**：同一结算时刻要结算的所有心理量都从该时刻结算前的快照读彼此的值，写出的增量在该时刻末一并生效；结果与心理量的遍历顺序无关。
- **R26-4.6 想法不落状态。** 活跃想法是事件日志、知情记录与现状的纯函数；复演不需要额外数据。按台账的判别口诀"能由别的维度算出即派生"，想法不登记容器实例；登记为容器实例的是心理量与发作。
- **R26-4.7 心情怎样起作用**：只经心情容器各档上的修正项。本规则不规定心情好坏改什么。
- **R26-4.8 外部来源怎样推心理量**：除想法行外，任何来源都可以挂以 `person.gaugeTarget[<心理量>]` 或 `person.gaugeInflow[<心理量>]` 为目标的修正项；这就是 R26-3.4 的第三条路。唯一的例外是心理量容器自己的档修正，它不得指向这两个键（§2.3 第 7 条）。键域按 §2.1：追随型只有 `gaugeTarget`，累积型只有 `gaugeInflow`。

- **A26-4.S 扫描式**：`.mjs` 中 thought 族字面量为 0；`psych.mjs` 里不存在按动词、按状态族、按想法代号的分支；想法没有任何状态路径（`pathTypes` 中无想法项）；`psych.mjs` 的推进函数不读推进请求的长度、类别字段（这些字段本就不传入规则层，卷二十七 R27-3.2）；P26-7、P26-8 为 0。
- **A26-4.I 不变量式**（均为验收测试，交卷十二执行）：
  - 路径无关：从同一存档出发，一次推进三十日，与按任意切分（逐日、逐六小时、不整齐的若干段、中途存读档）分段推进合计三十日，存档摘要相同，没有容差。
  - 打乱心理量遍历顺序、打乱同一行条目的遍历顺序，结果相同（R26-4.5、R26-4.2 的全序）。
  - 删除语言包再推进三十日，存档摘要不变。
  - 任一活跃想法满足 `magnitude = (factors.base + factors.pref) × factors.P × factors.V × factors.R × factors.D × factors.K`，定点下严格相等，其中 `factors.pref` 是偏好加项（`prefWeight × 对象偏好`）。
  - 夹具：同一行同时成立"一条 `m0` 非零加若干条 `m0` 为零"的条目，非零那条的 `factors.K` 恒等于 `stackTable[0]`；没有评价行的事件不产生 `conduct` 条目。
  - severity 恒在 [0,1]。
  - 误差界（R26-4.4 的存法一段；口径只引卷二 §3.3（求值管线）"存量与余数结转"第 6 条）：心理量容器实例的 severity 以 10⁸ 标度存，登记为 `stockMode: extScale`、`precision: 8`。夹具覆盖追随型与累积型各至少一个、拍长折成日数写得尽与写不尽各一个、带四种触发的想法、互读别的心理量的想法、效果族写入、钳到 0 与 1；逐拍推进 n 拍，定点实现与高精度参考值（同一条式子不截断，离散判定取定点一侧的分支）之差不超过该段的 `E_n × 10⁻⁸`，并且按卷二同条逐步递推出的误差不超过该段的确定式（确定式没有漏项）。追随型的 `E_n` 不随 n 增长。验算脚本的输出须附在本卷附录（已附，见附录六）。
- **A26-4.X 扩展性式**：加一条想法行（任一触发种类）不改 `.mjs` 即生效；别卷新增一个状态族或一个动词后，只加一条想法行就能让它影响心情。

### 4.5 压力累积与崩溃

#### 4.5.1 维度

读：压力心理量（累积型）及其容器；episode 族；`personality`、`values`；主体的技能等 map 维度（供 `binds`）。

#### 4.5.2 统一入口

读：`personView().psych.gauges`、`.psych.episodes`。写：容器实例只经 `status.mjs`；绑定修正只经 `modifier.mjs`；开始与结束各发一个事件。

#### 4.5.3 规则

- **R26-5.1 压力是一个累积型心理量**，推进按 R26-4.4。它的来源全是数据：读心情的 `state` 想法行（心情低则流入为正、高则为负）、`conduct` 想法行的负半边（违背本人价值）、心理量行 `baseRX` 给出的自然消解。
- **R26-5.2 发作的资格**（时钟）。判定只在世界时刻能被 `rules.psych.episodeTickMinutes` 整除的边界上做，`Δt` 恒为这一拍长折成的日数；推进区间内的各个边界按时刻升序逐个判定，与 R26-4.4 同样路径无关。在每个边界，对每个个体、每个 `exclusive` 组：若该组已有进行中的发作则跳过；否则候选 = 同时满足下列三条的发作行：`applies` 为真；`gate` 所指心理量的 severity 落在 `[minSeverity, maxSeverity)` 内；它的每个绑定项都取得出来（R26-5.5 的"可取"条件）。
- **R26-5.3 是否触发与触发哪一条**。每个候选的整数权重 `w = floor(hazardRX × rules.psych.pickScale)`（未知或非正的候选权重为 0，不计）。`H = Σw ÷ rules.psych.pickScale`（`pickScale` 作除数，规则表键的取值域下限为 1，加载校验）；触发概率 `1 - exp(-H × Δt)`。两次抽取都用 §2.2 抽取点表登记的五段骰值键，世界时刻段取该判定边界：先用"是否触发"抽取点取一个均匀数判定；触发了，再用"触发哪一条"抽取点，按卷二 §1.10（随机实例化）的 categorical（非负整数权重、候选按代号升序累加、均匀数对权重和取模命中）选出一条。本卷不另造按比例抽签的算法。
- **R26-5.4 开始**。输出清单：挂上该行的容器实例（初始 severity 取容器行的 `severity.initial`）；用"时长"抽取点按 `duration` 取时长并声明到期，由调度器执行，本卷不自写计时；发开始事件；有绑定项则按 R26-5.5 处理。
- **R26-5.5 绑定**。对发作行的每个绑定项，先定候选键集：主体该 map 维度的全部键，按 `families`（键所属的族在所列之内）与 `under`（键的上位链含该条目）过滤。
  - 加权：键的整数权重 = `floor(max(该键的有效值, 0) × rules.psych.pickScale ÷ 该维度取值域上界)`（绑定项所写维度的取值域上界须为有限正数，加载校验，不满足即加载失败），使取值域是 [-1,1] 的维度与取值域上千的维度都得到有区分度的整数。"可取"条件：权重为正的键不少于 `count` 个。抽取：用"绑定"抽取点取一个 64 位均匀整数 `u`；在剩余候选上按卷二 §1.10（随机实例化）的 categorical 以 `u` 对权重和取模命中第一个；把命中的键从候选中去掉，`u` 整除以刚才的权重和，再同法取下一个，直到取满 `count` 个。全程只抽一次，不用序号。
  - 取顶：取基础值不低于 `rules.psych.prefThreshold` 的键里基础值最大的 `count` 个（并列按代号升序）。"可取"条件：这样的键不少于 `need` 个（`need` 为 null 则不少于 1 个）；不足 `count` 个时有几个取几个。取顶不抽签、不落状态，读时现算；它用基础值，所以发作期间不会变。
  - 绑定项 `stage` 与 `value` 非 null：为每个取中的键写一条运行态修正项，目标为"该维度[该键]"，来源为本发作的容器，随容器撤销。
  - 取中的键经 `psych.episodes[].picks` 读出，每项带绑定项序号、维度、键、`matchDim`。
- **R26-5.6 结束**，下列任一成立：到期；达成 `exitOnVerb` 的结束条件；`exitOnGateLeave` 为真且心理量离开区间；容器实例被容器写者移除（被诊治、被别的效果移除，或按卷二 §1.11（状态容器）的容器生命周期规则移除；本卷不另定移除条件）。结束时：移除容器实例与来源为它的运行态修正项，执行 `aftermath`，发结束事件。
  - **`exitOnVerb` 的结束条件是可判定的结构化条件**：主体作为施事发生了该动词的事件；并且，若发作行有带 `matchDim` 的绑定项，则该事件的产物实体必须对**每一个**这样的绑定项都匹配。一个绑定项匹配，指它取中的键里至少有 `need` 个出现在"产物实体 `matchDim` 维度的代号集合连同这些代号的上位链"里。产物实体取事件类型行登记的产物角色（卷二十四 §4.2（事件类型注册表））；事件没有产物，或产物没有该维度，即不匹配。判定只比较登记代号，不读任何文字。
  - 不匹配的同动词事件不结束发作，发作照常继续（随手做一件不相干的东西不算数）。
- **R26-5.7 转入**。因到期而结束、行上有 `failTo`、且期间 `exitOnVerb` 的结束条件从未达成：立即对 `failTo` 所指发作行执行 R26-5.4，不再判定资格。
- **R26-5.10 发作的 severity 怎样升降**：按 §2.3 第 6 条，只有两个来源——容器行自带的 `severity.perDay`（无人照看取 `untended`，满照护取 `tended`，两者之间按卷二十一 R21-9.1 的照护水平取），按卷二十一 R21-1.2 的病程律推进，存法与误差界也按该条；以及效果族的 status 输出。升过某档的 `minSeverity` 即进该档、挂该档的修正项。发作容器何时被移除以卷二的容器生命周期规则为准，本卷不规定；被移除了就按 R26-5.6 结束。"无人照看则恶化、有人照看则好转"因此只是容器行上的两个数。
- **R26-5.8 发作怎样改变行为**：只经其容器档上的修正项，以及容器所属族的布尔字段。档上的 `effects` 照 R26-3.5：其中指向心智类容器的 status 输出必带 `direction`，加载期按该条校验（E-PSY-DELTA-DIRECTION），它在心理量之间的影响清单上的位置见 §2.3 第 7 条"档修正的目标"。本卷没有"崩溃时做某事"的分支；闹事、出走、暴食都是驱力权重被修正后由决策管线选出来的。
- **R26-5.9 崩溃分轻重**只是数据：不同发作行的 `gate` 区间不同。

#### 4.5.4 交互

- 卷九：执行输出清单；决策管线读被修正后的驱力权重。
- 卷二十：到期。卷二十四：开始、结束两个动词行由本卷登记（§2.2，表 B），见卷二十四 §4.2（事件类型注册表）。
- 卷二十一：诊治可降低或移除发作容器，见卷二十一 §4.8（医疗诊治与手术质量）；本卷只提供容器的可诊治标记。
- 卷十八：他人目睹发作后的立场变化由卷十八按事件来源行处理。
- 卷十五：压力容器档上以卷十五过程槽 `process.consentBar`（施术配合门槛）、`process.riteDisturb`（仪式受扰量）为目标的修正项由本卷登记（§4.5.5），两槽的含义与读者归卷十五 R15-4.4、R15-7.4（封卷后勘误，C15-14）。
- 通道：事件、声明写者。

#### 4.5.6 验收断言

- **A26-5.S 扫描式**：`.mjs` 中 episode 族字面量为 0；`psych.mjs` 的 import 全在 P26-9 的白名单内（白名单外为 0）；不存在以发作代号为条件的分支；危险率、时长的数值字面量为 0（P26-6）；本卷的每个抽取点都在种子键登记表里有一行，键成分里没有计数器或序号（P26-5）。
- **A26-5.I 不变量式**：同一主体同一 `exclusive` 组进行中的发作至多一个；每个进行中的发作恰有一个容器实例，反之亦然；来源为某发作容器的运行态修正项在该容器移除后数量为 0；同种子复演，以及一次推进与任意分段推进，发作的开始时刻、种类、时长逐位相同；同一主体同一边界上两个排他组的判定互不影响（对象段不同，键不同）；以 `rules.psych.statSeed` 为夹具种子、`rules.psych.statSampleN` 个个体在恒定危险率下的单拍触发频率，与 `1 - exp(-H×Δt)` 之差不超过 `rules.psych.freqTolerance`；夹具里一条带多档的发作容器在 `perDay.untended` 为正时逐日升档、改为有人照看后逐日降档。
- **A26-5.X 扩展性式**：加一条发作行与一条容器行，不改 `.mjs`，该发作即可被触发、挂修正、到期、执行善后。

### 4.6 疯狂

#### 4.6.1 维度

读：episode 族中 `duration` 为空的行及其容器；压力心理量；容器的可诊治标记与危及生命档。

#### 4.6.2 统一入口

同 §4.5.2。

#### 4.6.3 规则

- **R26-6.1 疯狂不是另一套机制**：它是 `duration` 为空的发作，即不会自行到期。进入途径两条，都已在 §4.5 定义：别的发作经 `failTo` 转入（R26-5.7），或自身的 `gate` 与危险率直接触发（R26-5.3）。
- **R26-6.2 退出途径**只有 R26-5.6 中不含到期的三条：容器实例被移除（移除条件以卷二 §1.11（状态容器）的容器生命周期规则为准，含诊治与别的效果移除）；`exitOnVerb` 的结束条件达成；`exitOnGateLeave` 为真且心理量离开区间。
- **R26-6.6 轻重会变**：疯狂容器的 severity 按 R26-5.10 升降。无人照看时按容器行的 `perDay.untended` 上升，升过高档的门槛就进高档；有人照看时按 `perDay.tended` 下降。高档能不能到、多久到，全看这两个数与各档的 `minSeverity`，校验器对"初值低于某档门槛而 `untended` 不为正、又没有任何 raise 方向的效果族指向它"的容器行给出警告（该档到不了）。
- **R26-6.3 致命性是涌现的**：疯狂的容器档只挂修正项（压低进食与自保驱力、抬高攻击驱力、使人不能行动等），死亡由身体规则、战斗规则、治安规则各自得出。本卷不写"疯者某日后死亡"。
- **R26-6.4 疯狂期间其余心理量照常推进**；同一 `exclusive` 组不再触发新的发作（R26-5.2）。
- **R26-6.5 是否算疯**只由数据决定（行的 `duration` 为空），代码里没有"疯狂"这个类别。显示层按发作行的显示名呈现。

#### 4.6.4 交互

- 卷二十一：诊治与照护；照护水平由卷二十一 R21-9.1 给出（取值 [0,1]），病程律（卷二十一 R21-1.2）据此在 `untended` 与 `tended` 之间取速率；容器的危及生命档由卷二十一的照护规则经对一切容器相同的通用路径读（§3.1 闭集表）。
- 卷八b：疯者伤人的责任与处置按法典条目，本卷不参与。
- 卷十六：超自然个体"失常后变为另一物种"是 `aftermath` 里的效果族调用，转化规则归卷十六。
- 通道：事件、声明写者。

- **A26-6.S 扫描式**：代码中不存在区分"崩溃"与"疯狂"的分支或常量；不存在按发作时长为空与否走不同写入路径的代码（只有"是否声明到期"一处差别）；`psych.mjs` 里没有推进发作容器 severity 的代码（升降只在容器写者的通用推进与效果族输出里）。
- **A26-6.I 不变量式**：`duration` 为空的发作不会因到期而结束；`failTo` 链无环（加载期 E-PSY-EPISODE-GATE）；疯狂期间主体的死亡事件其原因代号恒来自身体、战斗或治安规则，不来自本卷；夹具里一个 `untended` 为正的两档疯狂容器，无人照看时在 `(第二档门槛 - 初值) ÷ untended` 日后（向上取到容器推进的整拍）进入第二档，改为照看后 severity 单调下降；容器被移除的那一拍发结束事件（移除条件按卷二的容器生命周期规则）；首批数据里每个多档发作容器的每一档都可达（没有"该档到不了"的警告）。
- **A26-6.X 扩展性式**：加一种新的疯狂只需一条发作行加一条容器行；给某种既有发作加"无人照看则恶化、有人照看则好转"只需在它的容器行填 `severity.perDay` 的两个数，不改 `.mjs`、不加规则。

### 4.7 灵感与奇想

#### 4.7.1 维度

读：episode 族中 `gate` 指向心情高区间的行及其 `binds`；主体的技能 map，技能定义见卷十四 §4.3（技能与熟练）；`preference`；主体所在地点的维度（如人口）；事件的产物实体上用来比对的代号集合维度（归卷二十三，见 §8 Q13）。

#### 4.7.2 统一入口

同 §4.5.2；所系对象经 `personView().psych.episodes[].picks`。

#### 4.7.3 规则

- **R26-7.1 灵感是 `gate` 指向高心情区间的发作**，资格、触发、开始、结束全按 R26-5.2 至 R26-5.6。
- **R26-7.2 灵感系于哪项本事**由一个绑定项给出：在行上所写的 map 维度里按有效值加权抽取（R26-5.5 加权），熟练的更容易被抽中；抽中的键得到一条运行态修正项，发作结束即撤。代码不知道那个维度是技能。
- **R26-7.3 奇想是带 `exitOnVerb`、`failTo` 与带 `matchDim` 的绑定项的灵感**。
  - 发作期间容器档把创作驱力抬到压倒其余。
  - **奇想的内容是一组代号**，由若干取顶的绑定项从本人 `preference` 得出（R26-5.5 取顶），不落状态。每个绑定项用 `families` 与 `under` 限定从哪一类键里取，用 `matchDim` 指明这些键约束产物的哪个维度。首批奇想行写三项：要做的作品类别（只在作品类别的子类里取）、要用的材料类别（只在材料类别族里取）、要用的做法（只在审美与做法族里取，对应创作动作的意图选择）。三项分别约束"做什么、用什么料、怎么做"，偏好因此同时约束材料与做法。
  - **完成条件按 R26-5.6 判定**：主体完成了一件作品，且这件作品在三个 `matchDim` 上都与奇想的内容匹配——类别对得上、用到的材料类别里至少有 `need` 种是他要的、意图选择里含他要的做法。任意一件不相干的作品不算。达成即成功结束并执行 `aftermath`；到期仍未达成则经 `failTo` 转入行上所指的发作。
  - 凑不出内容的人不会进入奇想：某个绑定项取不到足够的键（没有哪类材料是他真正喜欢的），按 R26-5.2 该行不是候选。
- **R26-7.4 作品本身不由本卷产生，本卷只给意图一侧**。北极星规定产物由材料属性、职业技能、意图三者共同推出；这三者在奇想里各自的来处是：
  - 意图：`picks`。卷九的候选生成在发作期间为主体生成创作候选时，把每个带 `matchDim` 的取中键原样填进创作动作——作品类别项定候选要做的东西；材料类别项成为该动作取料的需求块约束（需求块格式见卷二 §1.13（需求块（CDDA 02 §7；卷一 3A.7 指定本卷定义）））；做法项填进制造上下文的意图选择（制造上下文与意图槽位见卷三乙 §4.8（配方通用规则（继承、产率、递归）））。本卷不规定配方。
  - 材料属性：仍由实际取到的那批材料的属性决定，本卷不碰。喜欢某类材料只决定他去找哪一类，成品多好看、多结实仍看那批料本身。
  - 职业技能：仍读主体的技能有效值；奇想不直接改技能，成功后的 `aftermath` 才给长进。
  - 玩家角色的动作由玩家选（§8 Q8）；玩家做的作品不匹配，同样不满足完成条件。
- **R26-7.5 触发门槛都是行上的数据**：对技能水平、聚落人口的要求写在 `applies` 或 `hazardRX`，对心情区间的要求写在 `gate`。

#### 4.7.4 交互

- 卷十四：技能 map 的键与数值；灵感的修正项经唯一管线作用于技能读数。技能维度是否可修正、取哪种叠加，见 §8 Q14。
- 卷二十三、卷三：创作动作经卷九读到 `picks`，按 R26-7.4 用作需求与意图；作品完成事件的产物实体提供用来比对的三个代号集合维度（§8 Q13）；传奇作品的升级见卷二十三 §4.6（传奇）。
- 卷二十四：作品完成事件的类型行登记产物角色。
- 卷九：决策管线读被抬高的驱力权重；候选生成读 `picks`（§3.1 闭集表）。

  - 加权抽取的结果对同一骰值键恒定；以 `rules.psych.statSeed` 为夹具种子做 `rules.psych.statSampleN` 次抽取，各键被抽中的频率与其权重占比之差不超过 `rules.psych.freqTolerance`。
  - 值域为 [-1,1] 的维度与值域为 [0, 2700] 的维度做加权绑定，都得到不全为 0 的整数权重；权重为正的键不足 `count` 个的主体，该发作行不出现在候选里（加载与运行都不报 E-DIM-SAMPLE-WEIGHTS）。
  - 取顶的 `picks` 等于过滤后的键里基础值不低于门槛者按值降序、代号升序的前若干项；发作期间 `picks` 不变。
  - 完成条件的真值表：夹具产物在三个 `matchDim` 上"全匹配、缺类别、缺材料（匹配数为 `need - 1`）、缺做法、无产物"五种情形，只有第一种结束发作并执行 `aftermath`；其余四种发作继续，到期后转入 `failTo`。
  - 发作结束后来源为它的修正项为 0。
- **A26-7.X 扩展性式**：加一条绑定项指向另一个 person map 维度的发作行（例如指向可修正的属性维度）不改 `.mjs` 即可用；卷十四新增一项技能后，它自动成为灵感可系的对象；卷二十三给产物实体新增一个代号集合维度后，只在奇想行加一个带该 `matchDim` 的绑定项，完成条件即多一项约束。

### 4.8 个人士气

#### 4.8.1 维度

读：士气心理量（追随型）及其容器，容器所属族按台账为士气族；指向它的想法行；`gaugeTarget` 上来自所属队伍、指挥者、恐惧值的修正项。

#### 4.8.2 统一入口

读：`personView().psych.gauges`。写：只经 `status.mjs`。军团士气不在本卷，聚合入口归卷十三 §4.8（军团士气）。

#### 4.8.3 规则

- **R26-8.1 个人士气是一个追随型心理量**，推进按 R26-4.4。它与心情是两个量；二者的联系只是一条读心情、推士气的 `state` 想法行。
- **R26-8.7 士气跟得上战斗的时间尺度，靠的是行上的两个数**：士气心理量行的 `tickMinutes` 写成几分钟、`ratePerDay` 写成每拍走完大半差距的量级（首批数据：5 分钟一拍，一拍走 63%）。同伴倒下的事件被主体知悉后，最迟在下一个 5 分钟边界士气就向新目标移动，档随之变化，档上的修正项立刻进入他的驱力权重；卷十三在战斗中读到的就是这个值。结算仍只在绝对时间的整拍边界，路径无关不受影响（R26-4.4）。本卷不提供"读取时临时推算"的值，也不允许战斗模块自行调用推进。
- **R26-8.2 临阵的推力全是想法行**：同伴倒下、敌人溃退、己方获胜是 `event` 触发（角色为亲历）；自身伤痛是 `status` 触发；饥寒同理；欠俸、领俸这类平日的事也是 `event` 触发的想法行。卷十三补登的主将倒下、被围、断粮三项同属 `event` 触发的想法行，触发动词由卷十三登记（卷十三 R13-8.2、R13-14.6），本卷照上面的触发种类写行，不另设机制（封卷后勘误，C13-12）。
- **R26-8.3 队伍对个人的影响只经修正项**：队伍组织行、指挥者职位行可挂作用域为成员、目标为 `person.gaugeTarget[<士气心理量>]` 的修正项，作用域解析按卷二 §3.5（作用域与状态键表）。恐惧值对士气的影响由卷十八以同样形状登记，本卷不读恐惧值。
- **R26-8.4 士气怎样改变行为**：只经容器各档的修正项（抬高自保驱力、压低攻击驱力、改变战斗相关维度）。逃跑、投降是决策管线在这些权重下选出的动作，不是本卷的规则。
- **R26-8.5 谁没有士气**由心理量行的 `applies` 决定；没有实例的个体不参与军团聚合。
- **R26-8.6 士气的种类可加**：需要另一种"斗志"（如守城意志、围猎兴奋）时，加一个心理量行与若干想法行，机制不变。

#### 4.8.4 交互

- 卷十三：军团士气 = 成员个人士气的聚合加指挥与伤亡修正，由卷十三定义；它读成员的有效士气（视图输出 `psychOut`，§3.1），聚合与溃散判定都可以对它做算术和比较，不读 `psych`；要聚合哪个心理量由它自己的规则表给出代号。战斗事件的动词由卷十三登记，含主将倒下、被围、断粮三个触发动词（R26-8.2）。统计形态下，卷十三 R13-8.4 自己对聚合体的代表成员求值士气心理量行的基线与 R26-8.3 的个人士气修正项，是本卷士气心理量行与这些修正项的读者；本卷不为聚合体建心理量实例（R26-4.4 末不变）（封卷后勘误，C13-12）。
- 卷十八：恐惧值以修正项形式进入。卷八：指挥者职位行的修正项。

### 4.9 决策噪声接口

#### 4.9.1 维度

读：`driveWeight`、`decisionNoise`（§2.1）；drive 族条目；pers 条目的 `noiseLoad`；`rules.psych.noiseBase`、`rules.psych.driveMax`。

#### 4.9.2 统一入口

读：`personView().dims.driveWeight`、`.dims.decisionNoise`、`decisionJitter()`、`preferenceOf()`、`needSatisfiers()`。写：无。唯一使用方是卷九 §4.12（NPC 决策管线）。

#### 4.9.3 规则

- **R26-9.1 驱力权重的基值**（派生）：`driveWeight[d] = clamp(base_d + Σ_p persLoad_d[p] × personality_p + Σ_v valueLoad_d[v] × values_v, [0, rules.psych.driveMax])`（`persLoad`、`valueLoad` 缺键按不加项处理，§2.2），人格与价值读有效值（附身、信条等对人格与价值的修正因此会传到驱力）；`values` 某键未知时该键的价值项不计入。风险取舍不另设字段：它就是自保驱力（谨慎抬高、胆量压低）与决策噪声在同一条管线里的结果。
- **R26-9.2 驱力权重的修正**：心理需求的匮乏、心情、压力、发作、士气，以及信条、传统、职位、附魔，一律以修正项作用于 `person.driveWeight[<驱力>]`，经唯一管线求值。这是心理状态进入决策的唯一通道。
- **R26-9.3 决策噪声的基值**（派生）：`decisionNoise = clamp(rules.psych.noiseBase + Σ_p noiseLoad_p × personality_p, [0,1])`，人格读有效值；修正同上（压力、发作、醉酒等容器档可抬高它）。
- **R26-9.4 扰动函数**（派生，纯函数）：`decisionJitter(主体, 决策时刻, 候选 id) = decisionNoise（有效值） × z`。`z` 为标准正态数，由 §2.2 抽取点表登记的"决策扰动"抽取点的五段骰值键（世界种子；流代号；对象段取主体 id 后接候选 id；世界时刻段取决策时刻；抽取点代号）经卷二 §1.10（随机实例化）的分位数表得出。候选 id 由卷九 §4.12（NPC 决策管线）给出，是候选的稳定标识（动作代号加对象 id），不是候选在列表里的序号；所以候选集增删、重排都不改变其余候选的扰动值。键里没有序号、计数器。噪声为 0 时扰动恒为 0。
- **R26-9.5 与决策管线的分工**：候选怎样生成、每个候选对各驱力的贡献、成本、效用怎样合成、并列怎样取舍，归卷九 §4.12（NPC 决策管线）。本卷的承诺只有三条：权重非负且有上界；同一 `(主体, 决策时刻, 候选 id)` 的扰动恒定；本接口不读候选内容（只把候选 id 当作键的成分）。
- **R26-9.6 旧的人格打分全部并入这条通道**：是否应战、是否铤而走险、有无立国之志，都是决策管线里的普通候选，由驱力权重与扰动决定；不存在针对某一种决定的专用分值。

- **A26-9.S 扫描式**：`.mjs` 中 drive 族字面量为 0；`duels.mjs`、`npc-crime.mjs`、`nation-founding.mjs`、`npc-cognition.mjs` 中对人格的文字匹配与手填分值为 0；规则层全部模块（卷二 §2.7（系统声明表 `state-owners.json`）登记的规则层模块组）中 `Math.random` 为 0；返回值的 Fact 品牌指向 §3.5 所列"心理维度"的导出函数，只存在于 `view:personView` 的实现函数组（按卷二 §2.2（签名与返回形状）的 Fact 品牌与实现组登记判定，组外为 0）；规则层不存在名为风险厌恶、风险偏好的字段读取，也不存在以价值轴显示名为实参的调用（P26-3）。
- **A26-9.I 不变量式**：权重恒在 `[0, rules.psych.driveMax]`；噪声为 0 的个体扰动恒为 0；把候选列表重排、或增删别的候选，任一候选的扰动值不变；同种子复演三十日，全部 NPC 的决策序列逐事件相同；开与不开 AI 档，决策序列相同（扰动不读任何模型输出）。
- **A26-9.X 扩展性式**：加一条驱力行不改 `.mjs`，每个个体即有该驱力的权重；加一条以某驱力为目标的修正项（挂在任一容器档、信条或职位上），对应个体的选择分布随之改变。
