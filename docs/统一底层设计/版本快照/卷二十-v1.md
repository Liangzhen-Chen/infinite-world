## §1 领域总述

### 1.1 真实世界怎样运转

1. **时间只有一条轴**。年、月、节气、年号都是人对这条轴的不同切法。同一天，两个文化的日期不同，但太阳的位置相同。所以物理量（日照、气温、季节）应当由天文相位算出，日历只是投影。
2. **季节来自倾角与纬度**。同一时刻南北半球季节相反；近赤道的地方没有四季，只有干湿两季；极圈内有极昼极夜。这些都能由纬度和太阳相位算出，不需要逐地点写。
3. **天气有持续性**。今天下雨，明天下雨的可能比平日大；哪种天气常见由气候带决定，哪天出现由偶然决定。
4. **温度是叠加**：年均温、季节摆动、昼夜摆动、海拔递减、当日天气。室内温度由围护的散热能力和室内热源共同决定，稳定后是"室外温度 + 热源功率 ÷ 散热能力"。
5. **水是守恒的**：降水进入流域，一部分渗走，一部分顺流而下，一部分蒸发，一部分被人取走。结冰不是水消失，只是换了相态。
6. **火、烟、气味是场**：有强度，会衰减，会蔓延，由源头持续排放；雨能压火，风能带味。
7. **光与声按距离衰减**：光按距离平方衰减，声音每远十倍降一个固定量，墙体再隔掉一部分。
8. **灾害是环境量越过阈值**：久不下雨是旱，水漫过容量是涝。粮价上涨是歉收之后供需的结果，不是灾害自带的乘数。

## §4 子系统

### 4.1 刻、同刻全序、调度器与到期语义

#### 4.1.1 维度

`rules.clock`（§2.1）；状态 `clock.minute`、`clock.seq`、`due.*`；各表里声明时长的字段（`struct:duration`、`cooldownDays`、`durationDays`，字段名与单位归卷二 §1.5）；层步长读卷二十七 §4.1 的矩阵。`struct:dueItem = {dueMinute: integer, kind: enum due_kind, owner: EntityId, ref: Handle, enqueuedSeq: integer}`，无字串字段。

#### 4.1.2 统一入口

读：`clockView`。写：`kernel/scheduler.mjs` 是 `clock.*` 与 `due.*` 的唯一写者；其他模块只能调用 `schedule(owner, kind, delayMinutes, ref)` 与 `cancel(handle)` 两个内核 API 提出登记。

#### 4.1.3 规则

1. **刻**：一刻 = 一分钟，整数。日 = 1440 分钟，是单位换算（`_units.json`），不是规则常数。时钟不认识月、年、节日（卷一 §8.4）。
2. **推进不逐分钟走**：`advance(target)` 反复取 `next = min(到期堆顶, 各钩子下一个节拍, target)`，把时钟跳到 `next` 并处理这一刻。
3. **钩子节拍对齐绝对分钟**：钩子 h 在满足 `(minute − phaseOffset[h]) mod cadence[h] = 0` 的刻运行。节拍只由分钟决定，与"上一次什么时候推进过"无关。
4. **同刻全序**：一刻内全部待处理项按下列键的字典序执行——`(stage, phase, sortKey, layerRank, objectKey, enqueuedSeq)`。`stage` 是代码内封闭枚举 `tick_stage`（external due clock contest reaction assertion，沿用现调度器六段）；`phase` 与 `sortKey` 取 `state-owners.json` 的声明（卷二 §2.7，封闭 8 个阶段）；`layerRank` 取卷二十七的层序；`objectKey` 是按卷一 §8.2 格式、不含序号的骰值键；`enqueuedSeq` 是存档内单调序号。六项都确定，所以顺序唯一。
5. **到期语义**（台账 S-07）：
   - 时长只在表里声明；开始时由拥有者调 `schedule`，调度器算出 `dueMinute` 入堆。
   - 有效区间是左闭右开 `[since, dueMinute)`；`minute ≥ dueMinute` 的第一刻，在 `due` 段发出到期事件（动词 `verb_due_elapsed`，带 `kind` 与 `owner`），由拥有者的订阅者处理后果。调度器不知道后果是什么。
   - `untilEvent` 型时长不入堆，由调度器订阅该动词，事件到达即发同一个到期事件。
   - 取消只打墓碑，堆顶弹出时丢弃；不改已发事件。
   - 节奏缩放只在入堆时做一次（§4.10），入堆后改档不追溯。
6. **抽签键的序号有两种**：动作与反应用存档单调序号（同一刻多次掷骰互不相同）；**环境与时钟规则的抽签用 `rules.clock.drawSlots` 登记的固定位次**，不取存档序号。因此玩家做了多少动作，都不改变天气与灾异的随机流。键格式、派生函数、PRNG 只在卷二 §1.10。
7. **上限**：反应队列深度与单刻提案数超过 `reactionDepthMax`、`proposalMax` 即中止本刻并报错，不静默截断。

规则形状：时钟。

#### 4.1.4 交互（含与卷二十七的分工）

|---|---|---|

- 扫描式：§3.4 的 T-1、T-2、T-5 命中数为 0；`kernel/scheduler.mjs` 中十进制数值字面量只剩白名单（卷一 I39），`advance-registry` 的 81 个整数清零。

- 扩展性式：新增一个带 `cooldownDays` 的效果族行，不改代码，其冷却由调度器到期；在声明表里新登记一个钩子与节拍，不改调度器。

### 4.2 历法数据与周期日规则格式

#### 4.2.1 维度

词表族 `calendar`（§2.3）；`struct:recurrence`（§2.4）；`culture.calendar`（卷二 §5.13）；`rules.astro`；状态 `eras.*`。

#### 4.2.2 统一入口

读：`calendarView`、`recurrenceNext`。写：`eras.*` 的唯一写者 `calendar-era.mjs`。显示用的月名、年号名、节日名全部在语言包与卷二十九的模板里，本卷入口不产出字串。

#### 4.2.3 规则

1. **历法投影**：`calendarView` 由 `epochMinute`、`months`、`intercalation` 按周期整除算出年、月、日序号，全程整数。一日的起点由 `dayStart` 决定（午夜、日出、日落三种，日出日落时刻读 `env.daylightMinutes`）。
2. **哪部历法**：地点的历法 = 该地文化槽解析到的文化行的 `calendar`（文化槽解析归卷五 §4.12）；合同、义务自带历法引用，不随地点变（现 `obligation-calendar.mjs` 的分离保留）。
3. **年号**：`era.mode` 为 regnal 时，纪元起点 = 该法域内最近一次 `resetOn` 所列动词的事件时刻；`calendar-era.mjs` 订阅这些动词写 `eras.*`。年号叫什么是显示层的事。
4. **周期日规则的八种锚点**（`recur_anchor`）：
   - `cycle`：每 `periodDays` 天一轮，命中 `offsets` 所列日序；轮的起点可取历法纪元、年初或月初。
   - `calendar`：第几月第几日；闰月的处置由 `leapPolicy` 给出。
   - `solar`：太阳相位到达某个分数（分至点及其等分），可按半球翻转。
   - `lunar`：朔望相位到达某个分数，可指定"某锚点之后第 n 次"。
   - `season`：当地季节方案中某季的起、中、止。
   - `agro`：某类作物在当地的某个物候阶段（读卷二十五 `plantView` 与本卷 `envAccum`）；作物类由 `paramRX` 从文化的饮食权重算出。
   - `event`：某动词事件的周年。
   - `relative`：另一锚点加减若干日。
5. **节日日期由文化维度推出**：一条规则行是否适用于某文化由 `appliesRX` 读该文化、信仰、地点的维度决定；锚点参数由 `paramRX` 从同一批维度算出。同一条"收获后庆祝"的规则行，种稻的文化与种麦的文化得到不同日期；同一条"白昼最短日"的规则行，南北半球得到相差半年的日期。求值器里没有任何节日或文化的代号。
6. **市集日同理**：是锚点为 `cycle` 的规则行，周期可由 `paramRX` 读历法的 `weekDays`；规则行由卷七 §4.18 登记。现"全世界 5/15/25"是把习俗写进了历法文件，退役。
7. **校验**：`tracksSolar` 为真的历法，其一个闰周期的平均年长与 `rules.astro.yearDays` 之差超过容差即警告；允许声明不追太阳的历法（节日会在季节里漂移，这是真实现象）。

规则形状：派生（投影）＋ 反应（年号）。

#### 4.2.4 交互

卷七 §4.18 按本格式登记节日与市集日规则行，本卷不登记任何一行；卷九 §4.19 的时间槽位读 `calendarView`；卷六合同计息读 `rateBasis`；卷二十四 §4.6 活动订阅周期日的到来（调度器在锚点时刻发 `verb_recurrence_started`）。通道：事件。

#### 4.2.5 数据实例（示意行）

- 现缺省历法迁入：12 个月，大小月 30/29 相间，19 年 7 闰，闰月 29 日。一个闰周期 = 19 × 354 + 7 × 29 = 6929 日，共 235 个月，平均年长 6929 ÷ 19 ≈ 364.68 日。
- 【非西陲】一部不置闰的纯朔望历（`tracksSolar` 为假）：12 个月共 354 日，年初每年在季节里前移约 10.68 日；其文化的 `calendar` 类锚点节日随之漂移，`solar` 类锚点节日不漂移。只加一行历法数据。
- 【非人类/超自然】一个不见天日的地下物种文化：`dayStart` 取午夜，`weekDays` 取 8，节日规则行只用 `lunar` 之外的 `cycle` 与 `event` 锚点（其 `appliesRX` 读文化支柱维度）；不需要为它改求值器。

#### 4.2.6 验收断言

- 扫描式：T-3、T-8 为 0；`calendarView` 与 `recurrenceNext` 的返回值类型中无 string；历法文件中不再有市集日字段。
- 不变量式：① `calendarView` 对分钟单调——分钟增大，`(year, month, day)` 字典序不减；② 往返一致——由 `(year, month, day)` 反算的日起始分钟再投影回原值；③ 更换地点的文化（从而更换历法）不改变任何事件的分钟与状态哈希中的非历法部分（卷一 §8.4）；④ `recurrenceNext` 的结果严格大于 `fromMinute`。
- 扩展性式：新增一部历法行并让一个文化引用它，该文化所在地点的日期投影、节日日期、市集日全部随之变化，代码零改动；新增一条 `agro` 锚点规则行，种不同主粮的文化自动得到不同日期。

### 4.3 天气状态与地区现象

#### 4.3.1 维度

词表族 `weather`、`phenomenon`（§2.5）；群落行的 `weatherCommonality`；`place` 的 `weatherCell` 与 `env.weather / precipMm / windMps / cloud / snowMm / phenomena`（§2.7）；`rules.weather`；`rules.clock.drawSlots`。

#### 4.3.2 统一入口

读：`placeView().dims['env.*']`（当前）与 `envAt`（任意时刻）。写：无。天气不存状态；运行态对天气的干预只能是以 `env.*` 为 target 的修正项，经卷二 §3.3 管线叠加。

#### 4.3.3 规则

1. **天气不是事件类型，是地点的环境状态**（台账 X-33）。每个地点沿包含树解析到一个天气单元（挂 `comp_weather_cell` 的祖先）；抽签以单元为对象，单元内各地点只做确定的细化。
2. **确定性**：单元 c 在第 d 日的天气是 `(战役种子, c, d)` 的纯函数。
   - 把日序按 `anchorDays` 切成锚段；段首日的状态按权重直接抽；段内第 k 日的状态按"权重 × 持续性"抽，其中与前一日相同的状态乘其 `persistence`，其余乘 `persistBase`。
   - 每次抽签的骰值键 = 卷一 §8.2 的格式，其中规则 id 为天气日抽签的登记前缀，对象 id 为单元，时刻为该日起始分钟，**序号取 `drawSlots` 的固定位次**（状态、降水量、风各占一位）。
   - 求某一日只需从所在锚段的段首递推，至多 `anchorDays` 步；结果按（单元，锚段）记忆，不入存档。
   - 因此：同一种子在任何机器、任何推进方式、任何玩家行为下得到同样的天气；跳过一百天与一天一天走到同一天，结果相同。
3. **权重**：状态 s 的权重 = 单元群落行的 `weatherCommonality[s]` × `weightRX_s` 的定点整数值。`weightRX` 只读单元的基准气温、太阳相位、降水季节份额等维度。权重全为零 → 当日天气未知，按 `gap` 处置并记缺口，不拿某个状态兜底。
4. **当日量**：降水量、风速由该状态的分布按固定位次抽出；降水的相态由当地 `env.tempC` 与降水材料的熔点（读卷三 `materialView`）比较得出，本卷不写冰点常数。
5. **积雪**：`env.snowMm` 是锚段内逐日"降雪 − 融化"的折叠，初值取单元的 `perennialSnowMm`；折叠只用纯函数的天气序列，所以仍是纯函数。锚段起点取单元最暖的太阳相位，使跨段结余为零。
6. **地区现象**：`phenomenon` 行的 `whenRX` 在环境维度上成立时，该现象进入 `env.phenomena`，并挂出该行的修正项与效果。极夜、封山、沙尘都是这样的行：分别由日照分钟、积雪与海拔、风速与地表维度的条件给出。求值器遍历全部现象行，不点名任何一行。
7. **干预**：求雨、法术改天等一律是效果族行产出的、以 `env.precipMm` 等为 target 的修正项（卷二 §3.9）；本卷不认识其来源种类。现 `water-cycle.mjs:185` 的点名分支退役。

规则形状：派生。

#### 4.3.4 交互

卷五读 `env.*`（§4.16 地点环境状态读取）；卷十七读积雪与现象决定通行（路况系数归卷五 §4.10，本卷只供量）；卷二十五读降水与日照；卷十五的法术只登记效果族行。天气状态变化时由调度器的日结钩子发 `verb_weather_changed`（事件类型行在 §4.9 登记）。通道：事件。

#### 4.3.5 数据实例（示意行，数值待标定）

- 一行降水状态：`wx_rain_steady`，`persistence` 3，降水量分布为对数正态，`cloud` 0.9，`sightFactor` 0.6，`weightRX` 随基准气温与降水季节份额上升。
- 【非西陲】一行风沙状态：`wx_dust`，`weightRX` 读风速基值与单元的森林覆盖率、年降水量（越干越秃权重越高）；它在湿润林区权重为零，不需要写"哪个省有沙尘"。配一行现象 `phen_whiteout_pass`：`whenRX` 为积雪超过阈值且海拔高于阈值，修正项把所在边的通行系数置零。
- 【非人类/超自然】一行超自然状态：`wx_miasma_fog`，`weightRX` 读单元的污秽场基值；`emits` 向地点排放一种致病场。它与普通雾走同一求值器。

#### 4.3.6 验收断言

- 扫描式：T-4、T-5、T-8 为 0；天气与现象求值文件中无 `state` 写入；`seasonal-hazards.mjs:374` 的睡眠正则删除，改调卷二 §2.5 谓词。
- 不变量式：① 同种子、同单元、同日，`envAt` 在本机与云上逐字节相同；② 先求第 d+100 日再求第 d 日，与顺序求值结果相同；③ 插入任意多的玩家动作，不改变任何一日的天气基值；④ 各状态权重为非负整数。
- 扩展性式：新增一行天气状态并在某群落行给出非零权重，该群落的全部单元自动出现这种天气；新增一行现象，不改代码即对全世界满足条件的地点生效。

### 4.4 季节词表与联动

#### 4.4.1 维度

词表族 `season`（§2.6）；`place` 的 `latitudeDeg`、`env.solarPhase`、`env.season`、`env.daylightMinutes`；天气单元的 `seasonScheme`；`rules.astro`、`rules.season`。

#### 4.4.2 统一入口

读：`placeView().dims['env.season']`；RX 里的 `clock.season`（卷二 §2.2）求值为**求值主体所在地点**的 `env.season`。写：无。

#### 4.4.3 规则

1. **太阳相位**：`solarPhase = frac((minute − phaseEpochMinute) ÷ 年长分钟)`，年长取 `rules.astro.yearDays`，有理数整数运算。它与任何历法无关。
2. **半球归一**：纬度为负的地点相位加二分之一后取小数部分。南北半球季节相反由此得出。
3. **季节**：地点的季节 = 其单元 `seasonScheme` 下，区间 `[phaseFrom, phaseTo)` 含归一相位的那一行。四季、干湿两季、极地长冬各是一个方案，都是数据。`seasonScheme` 由 `rules.season.schemeRules` 按纬度与降水季节性派生，可在单元行显式指定（卷二 §1.6 的 `allowExplicit`）。
4. **日照**：`daylightMinutes` 由纬度、倾角、太阳相位按球面公式算出（三角函数用卷二十七 §4.5 的定点实现）；公式自然给出极昼（1440）与极夜（0）。
5. **联动只改维度**：季节行的 `modifiers` 只许指向 `allowedTargets` 列出的命名空间（环境量、作物生长系数等）。气温与日照的季节摆动来自第 1–4 条的连续公式，不来自季节标签。**季节不带价格乘数**；价格由卷六供需推出（卷零 §4 行 6.18）。
6. 现 `effects.mjs` 的季节效果表逐项迁成季节行的修正项或删除（凡作用于价格的删除）。

规则形状：派生。

#### 4.4.4 交互

卷二十五读 `season` 与日照定农时；卷三配方的 `season` 条件、卷二 `plant` 行的时令字段都引用本族代号；卷六只读由此变化的供给。通道：无写入，纯读。

#### 4.4.5 数据实例（示意行）

- 四季方案四行：`phaseFrom` 依次为 0、0.25、0.5、0.75（以春分为相位 0）。
- 【非西陲】干湿两季方案两行，供低纬季风单元使用；该单元的作物行按"湿季"代号定播种窗，无需代码区分。
- 【非人类/超自然】高纬单元：纬度 70 度、倾角 23.44 度，冬至日照为 0 分钟（极夜），由公式得出；同一时刻纬度 35 度处日照约 579 分钟。夜行物种的活动窗由卷四读同一个 `env.daylightMinutes`。

#### 4.4.6 验收断言

- 扫描式：T-3、T-6 为 0；全仓库不再有"月份整除得季节"的算术；季节行 `modifiers` 的 target 全在 `allowedTargets`。
- 不变量式：① 任一方案的区间恰好铺满 [0, 1)；② 纬度互为相反数的两地，同一时刻归一相位相差二分之一；③ 分点时任意纬度日照为 720 分钟（容差在规则表）；④ 更换历法不改变任何地点的季节。
- 扩展性式：新增一个季节方案及其行，把某单元指向它，该单元的季节、作物时令、配方季节条件全部跟随，代码零改动。

### 4.5 温度量纲与热交换

#### 4.5.1 维度

`place` 的 `env.tempC`；单元的 `annualMeanTempC`、`tempAmpC`、`diurnalAmpC`、`elevationM`；`comp_enclosure` 的 `envelopeUaWPerK`、`aperture`；热源功率（卷十九 §4.7 的设施维度、§2.8 场的 `heatWPerScore`、卷四物种的代谢产热）；`rules.thermal`。量纲：温度一律摄氏度（`celsius`），功率瓦，散热能力瓦每开。

#### 4.5.2 统一入口

读：`placeView().dims['env.tempC']`（室外地点给室外温度，围护内的地点给室内温度）；主体的环境侧体感 `feltTempC(engine, state, subjectId)` 是本卷唯一的体感入口。写：无。

#### 4.5.3 规则

1. **室外温度**五项相加：单元年均温；海拔修正 `lapseCPerM ×（地点海拔 − 单元海拔）`；季节摆动 `−tempAmpC × cos(2π ×（归一相位 − thermalLagPhase))`；昼夜摆动 `diurnalAmpC ×（1 − cloud × cloudDamp）× cos(2π ×（地方时 − diurnalPeakMinute）÷ 1440)`；当日天气的 `tempOffsetC`。再叠加以 `env.tempC` 为 target 的修正项。
2. **室内温度取稳态**：`室内 = 室外 +（围护内热源功率合计）÷ envelopeUaWPerK`。散热能力由卷十九从围护材料的导热（卷三 §4.11）、面积、厚度、完好度与开口派生；本卷只读这个数。不做每刻逐物换热（调研 01 §6 第 6 条）。
3. **未知不兜底**：围护的散热能力未知 → 该地点 `env.tempC` 未知，按 `gap` 记缺口；不拿室外温度代替。
4. **环境侧体感**：`feltTempC = env.tempC − windChillCurve(风速 ×（1 − 遮蔽）) − wetChillCurve(淋湿程度) + radiantCurve(日照与邻近场的辐射)`。遮蔽取所在地点的 `aperture`。
5. **分工**（台账 S-21）：服装保暖、物种舒适区、越界后的中暑与失温状态归卷三 §4.13、卷四、卷二十一 §4.7，它们读 `feltTempC`；物品自身的升降温与相变归卷三 §4.11，读所在地点的 `env.tempC`。本卷不写任何伤害阈值。

规则形状：派生。

#### 4.5.4 交互

卷三 §4.11、卷十九 §4.7、卷二十一 §4.7 只读；水体结冰（§4.6）、作物积温（§4.11）读同一温度。通道：无写入。

#### 4.5.5 数据实例（示意行，数值待标定）

- 一间有炉的屋子：室外 −5 度，热源合计 3000 瓦，散热能力 150 瓦每开，稳态室内 = −5 + 3000 ÷ 150 = 15 度。
- 【非西陲】高山隘口：单元基准 12 度、海拔 400 米，隘口海拔 2400 米，递减率每米 0.0065 度，海拔修正 = −0.0065 × 2000 = −13 度，未计摆动时为 −1 度。
- 【非人类/超自然】一处有地火的洞穴：洞穴是 `aperture` 很小的围护，地火是一个持续排放的场，其 `heatWPerScore` 计入热源；冷血物种在此的活动由卷四读同一 `feltTempC`。

#### 4.5.6 验收断言

- 扫描式：T-4 为 0；`env.tempC` 无声明写者；本卷文件中不出现任何伤害阈值或物种、服装代号。
- 不变量式：① 热源为零时室内等于室外；② 热源功率增大，室内温度不减；③ 同一时刻同一单元内，海拔更高的地点室外温度不高于更低的（递减率为正时）；④ `env.tempC` 是（种子、分钟、表、修正项）的纯函数。
- 扩展性式：新增一种导热更低的建材（只加卷三材料行），用它建的房屋散热能力自动下降、室内更暖；新增一个带产热维度的设施类型行，放入房间即抬高室温。

### 4.6 水循环与水量

#### 4.6.1 维度

`comp_waterbody` 的 `liquid capacityL catchmentM2 surfaceM2 runoffCoef downstream`；派生 `fillRatio`、`iceFraction`、`pollutant.*`（浓度 = 污染物余额 ÷ 液体余额）；`rules.water`；地点的 `elevationM`（卷五 §4.3）。存量本身是账本账户：`(水体地点, 液体材料, 存量)`、`(水体地点, 液体材料, 冰)`、`(水体地点, 污染物材料, 溶解)`。

#### 4.6.2 统一入口

读：`placeView` 的派生维度。写：只有账本转移（卷六 §4.1）；`water-cycle.mjs` 是提案方，不持有任何私有状态字段。现 `water-cycle:<id>` 记录退役。

#### 4.6.3 规则

1. **日结**，在 `environment` 阶段、按绝对日对齐。水体图按 `downstream` 拓扑序处理；加载期有环即 E-WATER-CYCLE。
2. **收支**（全部是带源汇标记的转移，整数升）：
   - 入：降水 = `env.precipMm × catchmentM2 × runoffCoef`（来源：降水源）；上游来水。
   - 出：蒸发 = `evapCurve(env.tempC, 风速) × surfaceM2`（去向：蒸发汇）；下渗份额；取用（卷五 §4.8 取用律发起的转移）；超过 `capacityL` 的部分转给下游，没有下游的转入漫溢汇并计为洪量。
3. **守恒**：对任一水体、任一日，`期末 = 期初 + 入 − 出`；全世界 `Σ存量 + Σ汇 − Σ源` 不变。由账本保证，不靠水循环模块自查。
4. **冻结**：冰与液是同一材料的两个用途之间的转移；目标冰份额 = `freezeCurve(低于该液体熔点的累计度日)`，熔点读卷三材料行。封冻禁航由卷十七 §4.5 读 `iceFraction`。
5. **污染**：污染物是独立的材料余额，随水按比例转移（分水、混水守恒）；浓度是派生量。致病、异味等后果由污染物材料的维度与卷二十一决定，本卷不写。
6. **海拔、码头、求雨三处写死的改法**：流向只看 `downstream` 与 `elevationM`（`water-cycle.mjs:13` 的地形文字解析删除）；是否临水设施读建筑的设施类型维度（`:33` 的用途文字删除）；求雨是 §4.3.3 第 7 条的降水修正（`:185` 的点名删除）。
7. 井、泉是 `catchmentM2` 取补给区、收入只来自下渗份额的水体，同一规则。

规则形状：时钟（日结）＋ 派生。

#### 4.6.4 交互

卷五 §4.7、§4.8（资源场与取用律作用于水体账户）；卷六 §4.22（源汇月报收录降水源、蒸发汇、漫溢汇）；卷十七 §4.5；卷二十五（灌溉是取用）；§4.9 的旱涝事件读 `fillRatio` 与洪量。通道：账本。

#### 4.6.5 数据实例（示意行，数值待标定）

- 一口塘：容量 500000 升，期初 300000 升；当日降水 20 毫米、汇水面积 10000 平方米、径流系数 0.4，入 = 20 × 10000 × 0.4 = 80000 升；蒸发 3 毫米 × 水面 2000 平方米 = 6000 升；取用 4000 升；期末 = 300000 + 80000 − 6000 − 4000 = 370000 升，未满不外溢。
- 【非西陲】高纬河段：累计冻结度日越过曲线后 `iceFraction` 升至阈值以上，卷十七据此禁航；开春度日回落自动解冻。无"某河冬季封冻"的写法。
- 【非人类/超自然】一处尸毒渗入的井：污染物是一种超自然材料（卷十五 §4.13 登记行），以余额形式进入水体账户，随取水按比例被带走；浓度降到阈值以下后果自然消失。

#### 4.6.6 验收断言

- 扫描式：`water-cycle.mjs` 中无对地形、用途等显示字段的读取（T-7）；无对记录类别代号的点名分支（T-8）；除账本转移外无状态写入。
- 不变量式：① 逐水体逐日守恒；② 全局守恒（源汇月报中水的差额为零）；③ 任一余额非负；④ `fillRatio` 不超过 1 的部分才留在本水体。
- 扩展性式：给任意地点挂 `comp_waterbody` 并填维度，它自动参与降水、蒸发、下游传递与冻结；新增一种液体材料（如盐水，熔点不同）作为某水体的 `liquid`，其冻结温度自动不同。

### 4.7 环境场与排放衰减

#### 4.7.1 维度

词表族 `field` 与 `struct:emission`（§2.8）；状态 `fields.<地点>.<场>`；派生 `env.fieldIntensity`；`rules.fields`；地点的可燃量等由 `fuelDim` 指向的维度（卷三 §4.11 提供）。

#### 4.7.2 统一入口

读：`placeView().dims['env.fieldIntensity']`。写：`env-fields.mjs` 是 `fields.*.*` 的唯一写者；其他模块只能通过"带 `emits` 的行"或效果族输出向场排放，不能直接写强度。

#### 4.7.3 规则

1. **步进**：每 `stepMinutes` 一步，绝对分钟对齐，`environment` 阶段。对每个地点的每个场：
   `新强度 = 旧强度 ×（1 − decayPerStep）+ Σ排放 − quenchPerMm × 当步降水 − 蔓延出 + 蔓延入`。
2. **排放源是数据**：物品、设施类型、状态、物种、天气行都可带 `emits`；有 `chance` 的排放用固定位次的骰值键抽签（对象为排放者，时刻为该步）。
3. **蔓延**：强度的 `spread.ratePerStep` 份额沿相邻分区与边流出，乘以 `edgeOpenness`；目标须满足 `spread.whenRX`（例如目标处 `fuelDim` 所指的量大于零）。带 `advectedByWind` 的场按风向偏置。
4. **耗料与副产物**：有 `fuelDim` 的场按强度消耗该量（消耗是卷三 §4.11 燃烧规则发起的转移，本卷只给出强度）；料尽则排放归零。`byproducts` 按份额把强度转给别的场（火生烟）。
5. **分层后果**：场行的 `tiers` 按强度取档，对所在地点的主体挂该档的修正项与效果。**免疫按维度判**：主体在 `resistDim` 所指维度上的值不低于 `resistMin` 即不受该档影响；不看物种。
6. **对环境量的贡献**：`heatWPerScore` 计入 §4.5 的热源，`lumenPerScore`、`opacityPerScore`、`soundDbAtRef` 计入 §4.8，`channel` 非空的场是该感知通道的环境量（气味即此）。
7. 强度低于 `epsilon` 即删除该项。爆燃（卷三 §4.11 按材料维度派生的反应）的产物就是向若干场的一次性排放（卷零 §5）。

规则形状：时钟（步进）＋ 反应（后果）。

#### 4.7.4 交互

卷三 §4.11（燃烧发起耗料转移、读场强度）；卷十三 §4.2（场的后果以效果族输出伤害类型）；卷二十一（致病场挂状态）；卷五 §4.2（读气味通道的场值）；卷十九（设施行的 `emits`）。通道：事件（场生成、熄灭各发一个动词）。

#### 4.7.5 数据实例（示意行，数值待标定）

- 一行火场：`field_fire`，`fuelDim` 指向地点可燃量，`byproducts` 含烟，`quenchPerMm` 为正，`tiers` 三档。强度 80、每步衰减 0.25、无补充时三步后 = 80 × 0.75³ = 33.75。
- 【非西陲】一行盐雾场：`field_salt_spray`，由沿海天气行的 `emits` 排放、`advectedByWind` 为真，`tiers` 给金属材料加锈蚀修正（读卷三材料的耐蚀维度）；内陆没有排放源，自然没有。
- 【非人类/超自然】一行瘴气场：`field_miasma`，由某类物种行的 `emits` 持续排放，`tiers` 的 `resistDim` 指向主体的毒抗维度；不呼吸的亡灵因该维度值高而不受影响，没有"亡灵免疫"的分支。

#### 4.7.6 验收断言

- 扫描式：`env-fields.mjs` 之外对 `state.fields` 的写入为 0；步进器内无按场 id 的分支（T-8）；无物种代号。
- 不变量式：① 强度非负；② 无排放、无蔓延入时强度单调不增；③ 同一步内蔓延出的合计等于各目标蔓延入的合计（乘开放度后的差额计入衰减）；④ 同种子下带 `chance` 的排放序列可复现。
- 扩展性式：新增一行场（如酸雾）并在某物品行加 `emits`，不改代码即可排放、衰减、蔓延并产生分层后果；给任一设施类型行加 `emits`，该类设施全部成为排放源。

### 4.8 光照、声音与气味（场值与衰减）

#### 4.8.1 维度

`place` 的 `env.lux`、`env.soundDb`、`env.sightM`；`env.daylightMinutes`、`env.cloud`；围护的 `aperture`；物品与场的发光量（流明）、声源级（分贝）；材料的隔声维度（卷三）；`rules.light`、`rules.sound`。

#### 4.8.2 统一入口

读：`placeView().dims['env.lux' | 'env.soundDb' | 'env.sightM']`；点到点的传播量 `propagate(engine, state, channel, fromPlace, toPlace)` 是本卷唯一的传播入口，返回到达处的量值。写：无。**"是否感知到"不在本卷**：通道词表与判定在卷五 §4.2，感官阈值在卷四 §4.1（台账 X-14）。

#### 4.8.3 规则

1. **天然光**：`solarLuxCurve(太阳高度角) ×（1 − cloud 的遮挡）`，夜间取 `moonLuxCurve(朔望相位)`；太阳高度角由纬度、太阳相位、地方时算出。
2. **室内光**：天然光 × `aperture` + 光源合计；光源在分区内按 `流明 ÷（zoneSpread × 分区面积）` 折成照度，点到点按距离平方衰减。
3. **声**：到达量 = `声源级 − dbPerDecade × log10(距离 ÷ refDistanceM) − 途中围护材料的隔声量`；多个声源按能量相加；环境底噪取 `ambientByWeatherCurve(降水, 风速)`。
4. **气味**：是 `channel` 为嗅觉通道的场（§4.7），随风平流；传播量读场强度。
5. **能见距离**：`env.sightM = min(sightByLuxCurve(env.lux), 基准 × 天气的 sightFactor, 由场不透明度折算的距离)`。现 `environment.mjs` 的 `localSightClear` 改读它。
6. 现"有人的室内环境照度"规则改为由光源物品的流明与 `aperture` 算出，不设"有人即亮"的常数。

规则形状：派生。

### 4.9 世界时钟事件与灾异（行数据）

#### 4.9.1 维度

`event_type` 表（卷二 §5.22）的字段：`family triggerRX weightRX cooldownDays stages valuationRX subjectKinds`。本卷只规定灾异类行的 RX 可读哪些环境变量：`env.*`、`envAccum(...)`、水体的 `fillRatio` 与洪量、`env.fieldIntensity`、`env.phenomena`。

#### 4.9.2 统一入口

读：`eventTypeView`（卷二 §2.1 第 22 行）。写：事件实例的唯一写者在卷二十四（事件主写）；本卷**只登记行**，不建注册表、不写事件状态（台账零#6、X-33）。

#### 4.9.3 规则

1. **检查节拍**：灾异行按 `rules.clock.cadence` 中登记的日结钩子检查 `triggerRX`，绝对日对齐。
2. **抽签**：`weightRX` 给出的概率用固定位次的骰值键抽（对象为事件主体地点，时刻为该日）；现 `world-clock.mjs` 的自拼键退役，改用卷二 §1.10 的键。
3. **灾异是环境量越阈**：旱 = 时段降水累计低于气候常值的某份额；涝 = 洪量大于零或 `fillRatio` 超过 `floodRatio`；寒潮、热浪 = 气温偏离；火灾 = 场强度越档。阈值都在行的 RX 与规则表里。
4. **后果只改维度**：各阶段的 `modifiers` 与 `effects` 指向环境量、作物生长系数、路段通行、设施完好度等维度。**不得指向价格**（T-6）。歉收之后粮价上涨由卷六从供需得出；现 `hazard-calendar.mjs:88` 的价格乘数入口与冬荒的手写乘数删除。
5. **年长**：`hazard-calendar.mjs:28` 的 360 改为 `rules.astro.yearDays`；按季节限定的行用 `clock.season`。
6. **阶段时长**走调度器到期（§4.1）；"预兆到主事件的间隔"属延迟类，随节奏缩放；灾异的年基率属均衡类，不随节奏变（§4.10）。
7. 天气变化事件（`verb_weather_changed` 对应的事件类型行）也在此登记，仅作通知，不带后果。

规则形状：时钟（检查）＋ 反应（阶段）。

#### 4.9.4 交互

### 4.10 世界节奏 pace

#### 4.10.1 维度

词表族 `pace_level`（§2.10）；`pace_class`；`rules.clock.dueKinds`（每类到期项的节奏类与下界）；状态 `pace.level`、`pace.awayOverride`。

#### 4.10.2 统一入口

读：`paceView`。写：`pace.mjs`，只响应节奏设置事件（`verb_pace_set`）。

#### 4.10.3 规则

1. **两类**：延迟类（事情多快展开）随档缩放；均衡类（决定长期存量与年统计的率）不随档。
2. **缩放**：延迟类到期项入堆时 `延迟 = max(下界, floor(原延迟 × den ÷ num))`，其中 `num/den` 是当前档的 `factor`，下界由 `floorRX` 给出（如传闻每跳不低于行程时间）且不小于 1 分钟。
3. **必须分类**：`rules.clock.dueKinds` 对每个 `due_kind` 给出类别，缺失即加载失败（E-PACE-UNCLASSIFIED）。现 `pace.json` 里用中文成员名单登记两类的做法退役，改为按 `due_kind` 代号登记。
4. **离开期间**：玩家离开时可设 `awayOverride`，返场清除；它只影响其后入堆的延迟类项。
5. 节奏不改变任何概率、产量、价格回复率；不改变节拍与同刻全序。

规则形状：派生（入堆时一次）。

#### 4.10.4 交互

卷二十七 §4.3 的降级阶梯可以读 `paceView`，但降级改的是层与精度，不改节奏档；卷九、卷二十二、卷二十四的延迟（计划步间隔、传闻跳延迟、预兆间隔）经 `schedule` 自动受缩放。通道：事件。

#### 4.10.5 数据实例（示意行）

- 五档系数 1/4、1/2、1、2、4（沿用现表）。一个 4320 分钟的延迟类项在系数 2 下入堆延迟 = 4320 ÷ 2 = 2160 分钟。
- 【非西陲】远方一条传闻的每跳延迟属延迟类，下界读卷十七的行程时间；在最快档下也不会早于信使能到的时刻。
- 【非人类/超自然】"年久成精"的年基率属均衡类：任何档下一百年内成精的期望数相同。

#### 4.10.6 验收断言

- 扫描式：`schedule` 之外不得读 `pace.*` 做算术（卷十二按读者表扫）；`pace.json` 中无文字成员名单。
- 不变量式：① 换档不改变均衡类统计量的长期均值（浸泡指标，容差在规则表，卷十二 §4.8）；② 缩放后的延迟不小于下界；③ 系数为 1 的档下，延迟等于原值。
- 扩展性式：新增一档（只加一行 `pace_level`），不改代码即可选用；新登记一个 `due_kind` 并标为延迟类，其全部到期项自动随档缩放。

### 4.11 农时钟接口

#### 4.11.1 维度

`rules.agroclock.accumKinds`（封闭的累计量代号：积温、降水合计、霜日数、日照分钟合计）；`env.tempC`、`env.precipMm`、`env.daylightMinutes`、`env.season`。作物的基准温度、成熟所需积温、耐霜、光周期等是 `plant` 表字段，归卷二十五 §4.1。

#### 4.11.2 统一入口

读：`envAccum(engine, state, placeId, accumKind, fromMinute, toMinute)`，本卷为农时提供的唯一入口。写：无。

#### 4.11.3 规则

1. `envAccum` 对闭区间内各日的环境基值按 `accumKind` 的定义折叠：积温 = Σ max(0, 日均温 − 调用方给的基准温度)；霜日数 = 日最低温低于调用方给的阈值的日数；其余为求和。
2. 因为天气与温度是分钟的纯函数，任意区间的累计都能一次算出，**不需要逐日推进，也不需要存状态**。离屏一个生长季的作物进度，由卷二十五用一次 `envAccum` 得到。
3. 运行态修正（求雨、灾异的降水修正）按其有效区间计入：`envAccum` 读修正项的起止分钟，对区间内的日加上修正后的值。
4. 本卷提供"钟"，不提供"农事"：何时播、何时收、产量多少、缺水减产多少，全在卷二十五。农事日结钩子的节拍登记在 `rules.clock.cadence`，与其他钩子同一调度。
5. 现 `weather.mjs:211` 的 `cropProduction` 退役，其内容迁往卷二十五。

规则形状：派生。

#### 4.11.4 交互

卷二十五 §4.1、§4.2 调 `envAccum`；§4.2 的 `agro` 锚点经卷二十五的物候结果间接使用它；§4.9 的旱情行直接使用它。通道：无写入。

#### 4.11.5 数据实例（示意行）

- 五日日均温 12、15、9、18、20 度，基准温度 10 度，积温 = 2 + 5 + 0 + 8 + 10 = 25 度日。
- 【非西陲】干湿两季单元：卷二十五的某作物行以"湿季起点后的降水合计"作播种条件，调用同一入口。
- 【非人类/超自然】一种只在极夜生长的菌类（`plant` 行的光周期字段取反向）：卷二十五用"日照分钟合计"为零的日数作生长量，仍是这一个入口。

#### 4.11.6 验收断言

- 扫描式：卷二十五及其他卷不得自行对逐日天气求和（卷十二扫 `envAt` 在循环内被累加的形态，除 `envAccum` 实现外为 0）；本卷文件中无作物、产量代号。
- 不变量式：① 区间可加——`[a, b]` 的累计等于 `[a, c]` 与 `(c, b]` 之和；② 离屏一次求值与在线逐日累加结果相同；③ 积温非负且对区间单调不减。
- 扩展性式：在 `accumKinds` 新增一种累计量的定义行，各卷即可调用；卷二十五新增任意作物行，不需要本卷改动。
