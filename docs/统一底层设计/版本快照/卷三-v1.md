## §0 卷首

### 0.1 范围

一切实物的共同属性与行为：材料是什么、物品由什么做成、能当什么用、怎样做出来、怎样变旧变坏、值多少、怎样替代、怎样搬运。本卷是北极星"产物由材料属性、职业技能、意图三者共同推出"中**材料与物品一侧**的唯一定义处：

- 材料属性表（全书共用一张，台账 S-01）；
- 物品通用字段、类别与用度类九维；
- 容器与批次元数据；品质档；工具能力 `ability`；
- 需求块的内容与用法（格式在卷二 §1.13（需求块））；
- 配方通用规则：继承、产率、递归（行格式在卷二 §5.18（配方 recipe），台账 X-01）；
- 拆解、修理、故障；耐久与劣化；热属性与燃烧（物品侧）；腐坏与保质；
- 服装分层与护甲物性；附件与改装槽；书与文书物性；
- 单件物估值公式与稀缺度派生；可替代折算；运法与货值密度。

不在本卷：价格形成与价格四角色路由（卷六 §4.21）；承载能力与负重公式（卷四 §4.6）；伤害结算与减伤（卷十三 §4.1–§4.3）；缺乏症阈值与身体后果（卷二十一 §4.4）；环境温度场与热交换（卷二十 §4.5）；知识的持有与失传（卷二十二 §4.10）；配方知识的传授限制（卷十四 §4.10）；作品美观值（卷二十三 §4.1）；超自然材料的行（卷十五 §4.13，字段由本卷定，台账 X-35）；资源场与取用律（卷五 §4.7/§4.8）；账本与资源种类表（卷六 §4.1）。

## §1 领域总述

### 1.1 真实世界怎样运转

1. **东西的脾性来自材料。** 一把刀能不能磨快、会不会锈、掉进火里怎样，是铁决定的；换成青铜，同一个形状就是另一件东西。所以属性写在材料上，物品只说"我由哪些材料、各占多少、做成什么形状"。
2. **形状决定用法，材料决定好坏。** 刀形给出"能切"，材料给出"切得多快、能用多久"。因此"能做什么"（能力代号与等级）挂在物品模板，"做得多好"由材料维度经同一条求值管线算出。
3. **做东西是三方合力。** 用什么料、手艺多高、想做成什么样，三者一起决定成品。同一块铁，学徒打出来能用，匠师打出来能传家；同一位匠师，赶工与细做也不同。
4. **料会跟着走。** 铁矿炼成铁，铁打成刀，刀断了回炉还是铁。产物的材料从投入继承，营养从配料继承，价值从成本继承。
5. **东西会旧、会坏、会烂、会烧。** 用一次磨一点，放着也会锈、会蛀；食物按温度变质；可燃物到燃点就烧，放热、留下炭或灰；少数东西一点就炸。这些都是材料属性加时间加环境的结果。
6. **用度是分档的。** 盐和柴一天不能少，灯油少了只是早睡，丝绸没有也能活。缺什么、缺了会怎样、能拿什么顶替，决定了家户怎么花钱、商人运什么货。
7. **值多少看四样。** 料贵不贵、工花了多少、做得好不好、还剩几成新；再加上稀不稀罕。贵而轻的货走远路，贱而重的货只在本地转。

派生式（卷二 §1.12（派生与聚合原语））：

- `hardness = Σ_k strength[k] × rules.materials.strengthSummary.hardness[k]`；`toughness` 同式取 `.toughness[k]`。权重表每行之和为 1。
- `charYield = reactionYield[rules.materials.charReaction]`；该键不存在则不适用。

### 4.2 物品通用字段

#### 4.2.1 维度

- **必有三样**：`massKg`（单件质量）、`material`（材料组成，份额和为 1）、`classes`（类别与组件类，卷二 §5.0）。其余全部派生或按组件类要求。
- **派生**：`density = wsum(material,'material','density')`；`volumeL = massKg / density`；`sizeClass = lookup(rules.items.sizeClasses, volumeL)`（卷二 §5.1 已给式子）。
- **可换材质**：`acceptsMaterial` 非空的模板，其 `material` 是"参考组成"；实例可以带材料偏离行（`itemInstances.<id>.props.material`），但每份材料的 `categories` 必须与 `acceptsMaterial` 相交。
- **计量口径**：账户数量一律按"件"，可为小数（可分物）；质量 = 件数 × `massKg`。旧 `unit` 字段（份、斤、条）废除，换算进 `massKg`（卷二 §6.1）。
- **三种存在形态**：模板（`item.json` 的行）；存量（账户余额加批次，§4.4）；实例（`itemInstances`，带实例维度）。
- **组件集**：物品的全部行为由 `classes` 里的组件类开启。物品表组件类：`comp_consumable comp_tool comp_weapon comp_wearable comp_container comp_readable comp_document comp_attachment comp_crafted comp_work comp_relic comp_vehicle comp_livestock`，各自的 `requires / enables` 写在所属小节。
- **材料派生组件**：`comp_burnable`、`comp_edible`、`comp_drinkable`、`comp_rottable`、`comp_durable`、`comp_deflagrant` 六个由材料决定，物品行不手写；物品"具有"其中某个，当且仅当其 `material` 中挂该组件类的份额之和 ≥ `rules.items.materialCompMin[该组件类]`（§8 Q-02）。

#### 4.2.2 统一入口

`itemView`（§3.1）。判断"某 id 是不是物品"只用 `kindOf`（卷二 §1.9），不看 id 前缀。

#### 4.2.3 规则

| 编号 | 形状 / 通道 | 规则 |
|---|---|---|
| I-1 | 派生 / 读 view | 密度、体积、尺寸档只由 `massKg` 与 `material` 推出，任何行不得手填 |
| I-2 | 派生 / 读 view | 是否必须实例化：模板挂的组件类里，只要有一个在表头 `instanceDimensions` 中有 `byClass` 必填项，该物品的每一件都是实例；否则只以存量存在 |
| I-3 | 动作 / 声明写者 | 实例的材料偏离只在制成时（§4.8 R-3）或改装时（§4.14）由唯一写者写入；偏离后 `massKg` 按 `参考体积 × 新密度` 重算并一并写入偏离行 |
| I-4 | 派生 / 读 view | 物品向承载方只提供三个数：`massKg`、`volumeL`、容器的内容物合计（§4.4 K-2）。"背不背得动、走多慢"的公式只在卷四 §4.6（台账 X-13），本卷不写 |

- **扩展性式** V3-4.2-E：只在 `item.json` 加一件物品（三样必填加一个组件类），不改 `.mjs`：它自动有密度、体积、尺寸档、运法、估值，并出现在对应库存槽（卷二 §七 B1）。

### 4.3 物品类别与用度类（九维）

#### 4.3.1 维度

三套旧分类合成一套，分工固定（卷二 §1.3 分类机制判定表）：`classes` 回答"是什么"；`tags` 回答"沾什么主题"；`categoryKind` 是由前两者派生出的**经济大类**，只有一个值。

| 九维 | 字段 | 含义 |
|---|---|---|
| 一 来源 | `sourceMode`、`origin` | 这东西从哪来：采集、种植、畜产、制造、只能买入、超自然；`origin` 只表示出处地点 |
| 二 用度 | `usageClass`、`usagePer`、`dailyUse` | 属于哪种日用消耗、按谁计、每单位每天耗多少 |
| 三 必需程度与缺量后果 | `necessityTier`；用度类条目的 `tier`、`shortage` | 缺了多要紧；缺了发生什么（一组 effectCall） |
| 四 可替代折算 | `substitutePool`、`substituteKey` | 能与谁互相顶替、按哪个量折算（§4.17） |
| 五 物理 | `massKg`、`volumeL`、`sizeClass`、`fragility`、`matterState` | 多重多大、怕不怕磕、是不是液体 |
| 六 季节 | `produceSeason`、`seasonUseFactor` | 哪季出产、哪季多用 |
| 七 自产 | `selfMakeRecipe` | 家户能不能自己做（派生自配方表） |
| 八 耐久 | `wearResistance`、`wearPerUse`、`lifeDays`、`shelfLifeDays` | 能用多久、能放多久 |
| 九 运法 | `transportMode`、`valueDensity` | 怎么运、值不值得运（§4.18） |

#### 4.3.2 统一入口

`itemView(...).dims.<九维字段>`。用度类条目的字段经 `vocab(engine,'usage',id)` 读（卷二 §2.1 横切入口）。

#### 4.3.3 规则

| 编号 | 形状 / 通道 | 规则 |
|---|---|---|
| C-1 | 派生 / 读 view | `categoryKind = first(rules.items.categoryRules)`。规则表每条 `{when: RX, value: 类别代号}`，`when` 只能读物品的 `classes`、`abilities` 是否非空、`usageClass`、材料派生组件；不得读 id。全部未命中 → 实体行显式写值加 `basis`（卷二 §1.6 末条） |
| C-2 | 派生 / 读 view | `sourceMode = first(rules.items.sourceRules)`。`when` 用 `exists(rel)` 读关系：有配方产出它、有资源场产它、有物种或作物产它；都没有 → 显式写"只能买入" |
| C-3 | 派生 / 读 view | `necessityTier = max(用度类条目的 tier, rank(maxOf(rel_downstream_recipes, necessityTier), -1))`：自己是日用就取日用档；否则比"用它做出来的东西里最要紧的那件"低一档（卷二 §5.1 已给式子，递归沿下游配方关系） |
| C-4 | 派生 / 读 view | 单位日耗 = `dailyUse × seasonUseFactor[当季]`（当季代号读卷二十 §4.4）；乘以"每人、每户、每畜、每工位"的数量由卷六 §4.12 做，本卷只给单位量 |
| C-5 | 反应 / 事件订阅 | 缺量后果：卷六 §4.12 结算出某用度类的缺量比例后发事件；用度类条目的 `shortage` 是一组 effectCall，以缺量比例为幅度参数求值（卷二 §3.9）。本卷不写"缺盐会怎样、缺柴会怎样"，那是 `shortage` 里的数据，身体后果的容器实例由卷二十一登记 |
| C-6 | 派生 / 读 view | 库存槽：类别条目 `stockSlot` 为真者各开一槽；聚落与家户的库存按 `categoryKind` 聚合，四个旧槽退役 |
| C-7 | 校验 | 挂 `comp_consumable` 的物品 `usageClass` 必填；`usageClass` 条目的 `pool` 非空时，物品的 `substitutePool` 必须与之相同 |

### 4.4 容器与批次

#### 4.4.1 维度

- 容器（`comp_container`，requires `volumeCapacity`、`maxLoadKg`、`sealed`，enables `contain`）：另有 `accepts`（可装什么）、`preserveMult`（对内容物腐坏率的乘子，1 表示无保护）。"容量"一词在全书有五义（台账 S-28），本卷只用 `volumeCapacity`，指容积。
- 批次：§2.3 批次结构。批次是账户内部的分批记录，不是实体。
- 实例与批次共用的两项元数据：`taint`（赃物份额）与 `purports`（表象）。

#### 4.4.2 统一入口

`containerView(engine,state,instanceId)` → `{contents: [{item, qty}], usedL, usedKg, freeL, freeKg}`（各为 Fact）；`lotsView(engine,state,holderId,itemId,purpose)` → 批次清单；装入判定 `canContain(engine,state,containerId,itemRef,qty)` → `{ok, reason}`，`reason` 是代号（`volume / load / accepts / leak`）。

#### 4.4.3 规则

| 编号 | 形状 / 通道 | 规则 |
|---|---|---|
| K-1 | 派生 / 读 view | 能否装入：内容物体积合计不超 `volumeCapacity`；质量合计不超 `maxLoadKg`；`accepts` 非空时，物品的 `classes` 或材料大类须与之相交；物态为液或气的东西只能装进 `sealed` 为真的容器 |
| K-2 | 派生 / 账本转移 | 容器内的东西 = 以该容器实例为持有人的账户；装入、取出都是账本转移。容器毛重 = 自重 + 内容物质量合计，嵌套容器逐层求和（层数上限在规则表，超限不可装） |
| K-3 | 动作 / 账本转移 | 批次拆并：转出时默认先出腐坏进度最高的批次（先陈后新）；转入时，`source / qualityTier / purports / batchTag / material` 全同的批次合并，`spoilage` 与 `taint` 按数量加权平均，`enteredDay` 取较早者；其余情况分立 |
| K-4 | 派生 / 账本转移 | 赃物份额守恒：转移不改变 `taint`；合并取加权平均；制造产物的 `taint` = 各投入按估值加权的平均（§4.8 R-7）。"洗白"只能通过法律程序（卷八b），物理加工洗不掉 |
| K-5 | 派生 / 读 view | 表象：`purports` 记录"它自称是什么"。真实维度不受影响；`itemView` 带视角参数（卷二 §2.1 的 frame）时，未识破的观察者看到表象的模板与品质，识破者看到真实值。识破与否是知情（卷二十二），鉴定是检定（卷九 §4.3），难度由 `forgeryGrade` 经 `rules.documents.forgeryDetectCurve` 给出 |
| K-6 | 派生 / 读 view | 库存分类：仓、窖、货栈都是容器或设施账户；"哪类东西放哪里"由 `accepts` 与类别决定（DF#36），不设按 id 的摆放表 |
| K-7 | 派生 / 读 view | 容器对腐坏与温度的影响只通过 `preserveMult` 与 `sealed` 两个维度进入 §4.11、§4.12 的公式 |
| K-8 | 校验 | `taint ∈ [0,1]`；`purports.item` 若非空须是物品模板；批次数量之和 = 账户余额（I 类断言） |

| 对方 | 方向 | 内容 |

| 卷六 §4.1 | 本卷经账本 | 账户三元键、守恒、资源种类登记；批次随转移走 |

### 4.5 品质档

#### 4.5.1 维度

- `qualityTier`：有序枚举 `quality`，七档；只存在于实例与批次上，模板不带。
- `rules.quality.tiers[档][修正键]`：每档对各修正键的乘子（卷二 §3.8）。哪些维度受品质影响，由这张表的列决定，不写在代码里。
- `maker`、`madeDay`：谁在哪天做的；供名望来源（卷十八 §4.7）与年久成精（卷十六 §4.12）读取。

#### 4.5.2 统一入口

读：`itemView(实例).dims.qualityTier`；受品质影响的维度直接读 `itemView(实例).dims.<维度>`，已含品质乘子。滚档：只在 `craftOutcome`（§4.8）内部发生，别处不得写 `qualityTier`。

#### 4.5.3 规则

| 编号 | 形状 / 通道 | 规则 |
|---|---|---|
| Q-1 | 派生 / 读 view | 品质 = 修正项来源：对表 `rules.quality.tiers` 中该档的每个键产生一条 `stage:mul` 修正，来源是实例自身，`unpenalized`；经卷二 §3.3 唯一管线求值。品质不是独立阶段，本卷不做任何乘法 |
| Q-2 | 动作 / 声明写者 | 滚档只在制成时做一次：期望分 = `lookup(配方.qualityCurve, 制作者技能值)` + `rules.quality.inputWeight ×（投入料平均档位序 − 常档序）` + `rules.quality.toolBonus × 工具能力等级富余` + `lookup(rules.crafting.careQualityCurve, 用心程度)`；以期望分为输入调卷九 §4.3 的通用检定（骰值键按卷二 §1.10）；检定余量经 `rules.quality.thresholds` 查出档位 |
| Q-3 | 不变量 | 档位一经写入不再改变；修理、改装、转手都不动它。东西变差靠耐久与劣化等级（§4.10），不靠降档 |
| Q-4 | 派生 / 读 view | 散货的等级用同一词表，记在批次 `qualityTier` 上；合并规则见 K-3 |
| Q-5 | 不变量 | 品质不改变质量、体积与材料组成 |
| Q-6 | 校验 | `rules.quality.tiers` 七档齐全；每列在档位序上单调不降；"常"档各列乘子为 0（即不变） |

北极星的三方在这里的落点：**材料**经投入料档位与材料维度进入；**技能**经 `qualityCurve` 与检定进入；**意图**经用心程度与取向（§4.8 R-5）进入。

### 4.6 工具能力

#### 4.6.1 维度

- `abilities: map<ability, 等级 1–3>`（`comp_tool`，requires `abilities`、`wearPerUse`，enables `provide_ability`）。
- `ability` 族条目：`{maxLevel, bodyProvidable}`。能力是"能做哪类操作"，不是物品类别；一件工具可有多项能力，一项能力可由许多种工具提供（CDDA 02 §6）。
- 术语：`ability` 专指工具能力；肢体行动能力叫 `capability`，归卷四 §4.2（台账 S-17）。

#### 4.6.2 统一入口

`abilityLevel(engine,state,actorId,abilityId,ctx)` → Fact（整数等级，0 表示没有）。`ctx` 给出可用范围（随身、所在工位）。需求块里只写能力代号与最低等级（§4.7）。

#### 4.6.3 规则

| 编号 | 形状 / 通道 | 规则 |
|---|---|---|
| A-1 | 派生 / 读 view | 某人对某能力的等级 = 三个来源的最大值：① 可用范围内未毁坏的物品实例经 `itemView` 读到的 `abilities[该能力]`（已含劣化与故障修正）；② 所在工位的固定装置提供的能力（卷十九 §4.3 在设施类型行上登记）；③ 身体自带（条目 `bodyProvidable` 为真时，读 `bodyView` 给出的身体能力映射，字段归卷四，§8 Q-08） |
| A-2 | 派生 / 读 view | 需求满足 ⇔ 等级 ≥ 所需等级。不做"名单匹配"，不看物品 id |
| A-3 | 反应 / 声明写者 | 每次因满足需求而被用到的工具实例受一次磨损（§4.10 D-1）；配方行的 `toolWear` 存在时取它，否则取物品的 `wearPerUse` |
| A-4 | 派生 / 读 view | "等级→动作"是反查索引：加载期遍历全部需求块（配方、取用方法、建造、诊治、仪式），得到 `(能力, 等级) → 可解锁条目` 的只读索引 `abilityIndex`。能力条目上不手写动作清单 |
| A-5 | 派生 / 读 view | 等级富余 = 实际等级 − 所需等级，进入品质期望（Q-2）与工时（§4.8 R-4） |
| A-6 | 派生 / 读 view | `abilities` 是可修正维度（`item.abilities[<能力>]`，stacking none）：劣化等级与故障以修正项降低等级，降到 0 即失去该能力 |
| A-7 | 校验 | `abilities` 的值不超过条目 `maxLevel`；每项能力至少被一个需求块引用，否则告警（无消费者的能力） |

### 4.7 需求块（内容与用法）

#### 4.7.1 维度

格式归卷二 §1.13（需求块）：`groups` 是"组的列表"，组间全满足，组内任选其一；每个候选项带选择器、`qty`、`consumed`。本卷规定选择器的含义与全书用法。术语：本卷的"需求块"是 `requirement`，与市场需求 `demand`、身体需要 `bodyNeed`、心理需求 `need` 是四个不同概念（台账 S-28）。

| 选择器 | 含义 | `qty` 的口径 |
|---|---|---|
| `items` | 指名物品模板集合，任一即可 | 件 |
| `classes` | 类别集合，物品的 `classes` 沿上位链展开后与之相交即可 | 千克；若该类别的物品共用一个替代池，则按池的折算键计（§4.17 S-2） |
| `matcats`【请卷二回填】 | 材料大类集合，物品 `material` 中属于这些大类的份额计入 | 千克（只算命中的份额） |
| `abilities` | 工具能力与最低等级 | 不计量，`consumed` 恒为假 |
| `where`【请卷二回填】 | 一条 RX，只读候选物的基值维度，用来写"熔点高于某值""硬度不低于某值"这类属性谓词（DF 01 §3.3） | 沿用同项其他选择器的口径 |
| 嵌套 `{req, times}`【请卷二回填】 | 引用另一个命名需求块并整体乘以 `times` | 被引用块内各项 `qty × times` |

#### 4.7.2 统一入口

- `requirementCheck(engine,state,reqRef,ctx)` → `{ok, missing: [{group, selector 代号, shortBy}]}`，纯读。`ctx = {actor, sources: [账户或容器], site: 工位, times: 倍数}`。
- `requirementPlan(engine,state,reqRef,ctx)` → 一份确定性的取料方案 `[{account, item, lot, qty}]` 与工具清单；同输入同输出。
- 消耗的执行：调用方把方案交给原语执行器（卷九 §4.2），以账本转移入"消耗"汇；本卷函数不写状态。

#### 4.7.3 规则

| 编号 | 形状 / 通道 | 规则 |
|---|---|---|
| N-1 | 派生 / 读 view | 匹配次序固定：先能力，再不消耗的工具项，再消耗项（CDDA 02 §12.4）。任一组无候选满足即整体不满足，返回缺口代号 |
| N-2 | 派生 / 读 view | 组内选哪个候选：按候选在组内的书写顺序取第一个满足者；同一候选有多批可用时按 K-3 的"先陈后新" |
| N-3 | 派生 / 读 view | 倍乘：`ctx.times` 与嵌套的 `times` 相乘后只作用于 `consumed` 为真的项；能力与不消耗的工具不随批量增加 |
| N-4 | 派生 / 读 view | 替代：按类别或材料大类选中的东西天然可互替；按 `items` 指名时不允许替代。旧规则"替代品须具备原物全部用途类别"由 `classes` 选择器的相交语义实现 |
| N-5 | 派生 / 读 view | 同一件实例不能在一次求值里同时满足两个消耗项；一件工具可以同时满足多项能力 |
| N-6 | 派生 / 读 view | 拆解需求不手写：由制作需求按 §4.9 X-1 自动导出 |
| N-7 | 校验 | 嵌套展开无环（E-DIM-REQ-CYCLE）；`qty > 0`；`where` 可编译且只引用物品或材料表的维度键；被两条以上数据行逐字重复的内联块，校验器提示提为命名块 |

全书用法（各处只引用，不另写条件格式）：

| 用在 | 引用方 | 备注 |
|---|---|---|
| 配方投入 | 卷二 §5.18 `inputs`；本卷 §4.8 | 产物继承按"输入槽序号" = 组的序号 |
| 建造 | 卷十九 §4.4 | 建材按材料大类与 `where` 写 |
| 修理 | 本卷 §4.9 | 由材料的 `repairedWith` 生成 |
| 拆解 | 本卷 §4.9 | 自动导出 |
| 诊治 | 卷二十一 §4.8 | 器械能力与药料类别 |
| 仪式、祭品 | 卷十五、卷七 | 祭品按类别与属性写 |
| 取用方法 | 卷五 §4.8 | 能力与等级 |
| 效果族前置 | 卷二 §3.9 `requirement` | — |
| 技能、知识前置 | 卷十四 §4.4、卷二十二 §4.10 | 这两处的前置是对人的条件，格式同为需求块，选择器由各自卷扩展，本卷不定义 |

#### 4.7.4 交互

见上表。本卷是内容与用法的定义方；卷二是格式的定义方；其余都是使用方。

#### 4.7.5 数据实例

- 例 1【西陲】`req_basic_forging`：`{groups:[[{abilities:{ability_hammer:2}}],[{abilities:{ability_grip_hot:1}}],[{matcats:[matcat_metal], where:"candidate.meltPoint >= rules.crafting.forgeMinMelt", qty:1.2, consumed:true}],[{classes:[class_fuel], qty:14, consumed:true}]]}`；燃料项属于燃料替代池，`qty` 按总热量（MJ）计，烧柴烧炭烧竹炭都行。

#### 4.7.6 验收断言

- **扫描式** V3-4.7-S：仓库中除卷二定义的解析器外，没有第二处解析"投入、工具、条件"的代码（特征：对 `materials / tools / workstation` 旧字段的遍历为 0）；需求块文本里的 `where` 不含实体 id。
- **不变量式** V3-4.7-I：`requirementCheck` 为真 ⇒ `requirementPlan` 给出的方案逐项可执行且执行后各账户非负；同一状态下两次求 `requirementPlan` 结果相同。
- **扩展性式** V3-4.7-E：新增一个命名需求块并被一条新配方引用，不改 `.mjs`：检查、取料、消耗、缺口提示全部成立；再让一个建造条目引用同一块，行为一致。

### 4.8 配方通用规则（继承、产率、递归）

#### 4.8.1 维度

行格式归卷二 §5.18（配方 recipe），本卷不重列字段；台账 X-01 裁定全书只有本节这一套规则，冶炼、烹饪、酿造、制药、战利品加工都只是配方行。本卷对行格式有三处补充请求【请卷二回填】：

| 补充 | 用途 |
|---|---|
| `outputs` 的条目加 `reaction: ref vocab reaction nullable` | 产物材料 = 投入材料经该反应的产物（R-3） |
| `outputs` 的条目允许不指名物品（`item` 为空），此时产物模板取继承后材料的 `rawForm` | 一条"冶炼""烧炭"配方覆盖所有同类原料（DF 01 §3.3） |
| 行加 `yield: fraction`（台账 X-01 已按此字段名裁定，卷二现稿未列） | 配方层的基础产率 |

**意图**是制作动作的参数，不是配方行的字段：

| 意图参数 | 类型 | 取值域 | 作用 |
|---|---|---|---|
| 选哪条配方、每组用哪个候选 | 配方 id；每组候选序号（可省，省则按 N-2） | 可行集合内 | 决定形状与用料 |
| `times` | integer | [1, 规则表上限] | 批量 |
| `care` | number | `rules.crafting.careRange` | 用心程度：越高越慢、期望品质越高 |
| `emphasis` | ref vocab emphasis nullable | 词表 | 取向：在几个成品维度之间此消彼长，写在实例的 `emphasis` 上 |

这四项是输入边译出的槽位，槽位登记归卷九 §4.19（§8 Q-09）。

#### 4.8.2 统一入口

`recipeView`（读行）。唯一结算函数：

`craftOutcome(engine,state,recipeId,ctx)` → `{ok, reason, plan, minutes, outputs: [{item, qty, material, qualityTier, emphasis, taint}], byproducts, residues, toolWear: [{instance, delta}]}`

- `ctx = {actor, site, sources, intent: {choices, times, care, emphasis}}`。
- 纯函数，只产提案；执行（扣料、入账、建实例、磨损）由原语执行器经账本与声明写者完成（卷九 §4.2）。NPC 与玩家、近处与远处同一函数（远处按卷二十七的降级矩阵取期望值，仍由这些维度算）。

#### 4.8.3 规则

| 编号 | 形状 / 通道 | 规则 |
|---|---|---|
| R-1 | 动作 / 读 view | 开工条件（全真才行）：`requirementCheck(inputs)`；制作者该技能值 ≥ `skillMin`；`workstation` 非空时，所在建筑的设施类型或其固定装置代号与之相等（读 `facilityView`，不读用途文字）；`toolAbilities` 各项 `abilityLevel` 达标；`learnFrom` 非空时制作者持有其中任一知识（读卷二十二的持有入口）；`season` 非空时当季在其内 |
| R-2 | 派生 | 产物模板：条目指名物品则用它；`item` 为空则取"继承并经反应映射后份额最大的材料"的 `rawForm`；该材料无 `rawForm` → 配方行加载期报错 |
| R-3 | 派生 | **材料继承**：`inheritMaterialFrom = k` 的产物，材料组成 = 第 k 组**实际消耗掉的东西**按质量加权的材料组成；条目有 `reaction` 时，其中每种材料 m 换成 `m.reactionProducts[reaction]`（没有该键的材料保持原样）；小于 `rules.crafting.minPortion` 的份额并入最大份后归一。只对 `acceptsMaterial` 非空的模板或不指名物品的条目允许写 `inheritMaterialFrom`，否则加载期报错 |
| R-4 | 派生 | **递归**：产物的营养、热值、强度、价值倍率、腐坏率等全部由 R-3 得到的材料组成经 `materialView` 算出，所以继承自动多级传递（面粉→面团→饼；矿→锭→刀）。任何产物行都不手写这些量。烹饪折损是"熟料"材料行相对"生料"材料行的偏离（卷二十五 §4.9 登记），不是另一套公式（台账 X-09） |
| R-5 | 派生 / 读 view | **工时** = `minutes × lookup(batchFactor, times) × lookup(rules.crafting.careTimeCurve, care)`，作为过程槽 `process.craftMinutes` 的基值进入求值管线；工具等级富余、设施、状态都以修正项作用于该槽（卷二 §3.7） |
| R-6 | 派生 | **产率**：产出件数 = `qty × times × yield × lookup(rules.crafting.skillYieldCurve, 技能值 − skillMin) ×（1 − wasteFraction）`；条目有 `reaction` 时，产出质量再乘所消耗各材料 `reactionYield[reaction]` 的质量加权平均。初加工与精炼的产率就是这里的 `yield` 与 `reactionYield`，卷六不另写 |
| R-7 | 派生 | **随料传递的三样**：品质（Q-2 的投入料档位项）；赃物份额（各投入按估值加权平均，K-4）；表象不传递（产物是新东西） |
| R-8 | 派生 | **取向**：`emphasis` 条目的 `shift` 是一组对成品修正键的增减，各项之和为 0；写在实例上，作为修正来源长期有效。没有"白拿的好处" |
| R-9 | 派生 | **副产物与残渣**：`byproducts` 按 `times` 倍出；反应中未转成产物的质量（`1 − reactionYield`）按该材料 `reactionProducts[rules.crafting.residueReaction]` 出残渣，无此键则入"损耗"汇。对 `conservesMass` 为真的反应，产物、副产物、残渣、损耗的质量之和等于消耗质量 |
| R-10 | 派生 | **失败**：`failureRX` 为真（变量只有技能值、用心程度、难度与检定余量）时不出产物；投入按 `rules.crafting.failureSalvage × 各材料 salvageFraction` 以 `rawForm` 退回，其余入损耗汇 |
| R-11 | 校验 | **可得性**：加载期沿配方图检查每个消耗项，至少有一个候选物的 `sourceMode` 不是"只能买入"，或其上游可追到资源场、作物、畜产；追不到的列入报告（改前 210 条配方属此类），由内容卡补来源，不在规则里兜底 |
| R-12 | 校验 | 配方图上"产物价值由成本推"的递归以基础材料外生为界，有环即 E-DIM-DERIVED-CYCLE（卷二 §1.12） |

三方合力的落点：材料 → R-3、R-4、R-6；技能 → R-1、R-6、Q-2、R-10；意图 → 选配方与候选、`times`、`care`（R-5、Q-2）、`emphasis`（R-8）。

#### 4.8.6 验收断言

- **不变量式** V3-4.8-I：对每条 `conservesMass` 反应的配方做一次试算，质量收支严格平衡；同一 `(配方, 状态, 意图, 骰值键)` 下 `craftOutcome` 逐位相同；`taint` 的估值加权和在制造前后相等。
- **扩展性式** V3-4.8-E：只在 `material.json` 加一种新矿石材料（带冶炼反应的 `reactionProducts / reactionYield`）与其产物金属材料，不改配方表、不改 `.mjs`：现有冶炼配方能炼它，现有锻造配方能用它，成品的硬度、耐磨、估值随新材料变化（卷二 §七 B2 的配方项）。

### 4.9 拆解、修理、故障

#### 4.9.1 维度

材料：`salvageFraction`、`rawForm`、`repairedWith`、`repairDifficulty`。物品模板：`faultSet`。实例：`durability`、`faults`。词表 `fault` 条目：`{modifiers, repair, weightRX}`。规则表 `rules.repair.*`。

#### 4.9.2 统一入口

- `disassemblyOf(engine,state,itemRef)` → `{requirement, outputs: [{item, qty}], minutes}`，只读。
- `repairPlan(engine,state,instanceId,ctx)` → `{ok, reason, requirement, minutes, restoreTo, clearsFaults}`，只读。
- 故障的发生在 `wearStep`（§4.10）里判定；清除经 `repairPlan`。

#### 4.9.3 规则

| 编号 | 形状 / 通道 | 规则 |
|---|---|---|
| X-1 | 派生 | **按配方拆**：模板有产出它的配方，且该配方产物条目无 `reaction`（可逆）→ 拆解产出 = 制作时的消耗项 × 各自材料的 `salvageFraction` × `durability`；所需能力 = 制作所需能力各降 `rules.repair.disassemblyLevelOffset` 级（不低于 1）；工时 = 制作工时 × `rules.repair.disassemblyTimeFactor`。多条配方产出同一模板时取 `skillMin` 最低者，平局按代号字典序 |
| X-2 | 派生 | **按材料拆**（无配方、或经过不可逆反应）：每份材料出 `质量 × 份额 × salvageFraction × durability` 的 `rawForm`；这也是"拆布""回炉"和 M-5 残余的同一条式子 |
| X-3 | 动作 / 声明写者 | **修理**：对实例中挂 `comp_durable` 的每份材料，用料 = 类别 `repairedWith` 的料 `（1 − durability）× 质量 × 份额 × rules.repair.materialPerDamage` 千克（写成需求块）；所需技能取 X-1 选出的那条配方的 `skill`，难度由 `repairDifficulty` 的加权值给出，走卷九 §4.3 检定；成功把 `durability` 提到 `min(1, 现值 + lookup(rules.repair.restoreCurve, 余量))`；无任何产出配方的模板不可修理 |
| X-4 | 时钟 / 声明写者 | **故障发生**：每次使用后，以 `lookup(rules.wear.faultCurve, durability)` 为概率（品质以修正项调整）判定一次；发生时在模板 `faultSet` 中按各条目 `weightRX` 的值作整数权重抽一个，写入实例 `faults`。随机数取骰值键（卷二 §1.10） |
| X-5 | 派生 / 读 view | **故障的效果**：故障条目的 `modifiers` 作为修正来源作用于该实例；同一故障不重复叠加 |
| X-6 | 动作 / 声明写者 | **排除故障**：满足故障条目的 `repair` 需求块并通过检定后，从 `faults` 移除；不改 `durability` |
| X-7 | 反应 / 事件订阅 | **毁坏**：`durability` 降到 0 时发"物品毁坏"事件；实例按实体终止协议结束（台账 N-06），残余按 X-2 入账 |

| 对方 | 方向 | 内容 |
|---|---|---|
| 卷九 §4.2/§4.3 | 本卷调用 | 原语执行、检定 |
| 卷六 | 对方读 | 修理的工钱与工坊费走价格与合同，不在本卷；本卷只给用料与工时 |
| 卷四 §4.8、卷十七、卷十九 | 对方调用 | 尸体以外的残骸、沉船、塌屋的可回收量用 X-2（打捞比例由材料与残骸类型给出，不由调用方传参） |
| 卷十三 | 对方订阅 | 战斗中的装备损坏只写 `durability`，后果走本节 |

#### 4.9.5 数据实例

- 例 1【西陲】一把 `durability:0.5` 的铁斧（铁 0.6、橡木 0.4，1.6 kg）：修理用料 = 金属料 `0.5 × 1.6 × 0.6 × materialPerDamage` 千克加木料同式；拆解按 `recipe_forge_axe` 反推，得铁料与木料各乘打捞比例再乘 0.5。
- 例 2【非西陲】一只竹篓（无 `reaction`，有编织配方）：拆得竹篾 `0.5 kg × 0.4 × durability`；竹的 `salvageFraction` 低，所以拆竹器不划算，这是数据的结果。
- 例 3【非人类】一副牛轭带故障 `fault_loose_fitting`：条目 `{modifiers:[{target:"item.encumbrance", stage:"mul", value:0.3}], repair:"req_refit_basic", weightRX:"3"}`；牛戴着更累赘（卷四读到的是修正后的值），紧一紧就好，不动耐久。

#### 4.9.6 验收断言

- **扫描式** V3-4.9-S：打捞、拆解比例作为函数参数由调用方传入的调用点为 0（`transition.mjs:579–591` 的写法退役）；`repair.mjs` 内的十进制字面量为 0；按物品 id 写的拆解对照表为 0。
- **不变量式** V3-4.9-I：任一物品"制作后立刻拆解"得到的各材料质量不超过投入质量；修理后 `durability ≤ 1`；`faults ⊆ 模板 faultSet`。
- **扩展性式** V3-4.9-E：加一个故障条目并把它写进某类别行的 `faultSet`，不改 `.mjs`：该类全部实例可能发生它、发生后维度按 `modifiers` 变化、满足 `repair` 后消失。

### 4.10 耐久与劣化

#### 4.10.1 维度

- 模板：`wearResistance`（派生 = `wsum(material,'material','wearResistance')`）、`wearPerUse`、`dailyUses`、`lifeDays`（派生，卷二 §5.1 已给式子）。
- 实例：`durability`（1 为全新，0 为毁）；`wearLevel`（派生 = `lookup(rules.wear.levels, durability)`，五档）。
- 规则表：`rules.wear.levels[档] = {minDurability, modifiers: list<修正项>}`、`faultCurve`、`envCurve`。

#### 4.10.2 统一入口

`wearStep(engine,state,instanceId,cause)` → `{delta, fault}` 提案；`cause` 是代号（`use / worn / passive / damage`）。读劣化：`itemView(实例).dims.durability / wearLevel`。

#### 4.10.3 规则

| 编号 | 形状 / 通道 | 规则 |
|---|---|---|
| D-1 | 反应 / 声明写者 | **用损**：每用一次，`durability` 减 `wearPerUse ÷ wearResistance`（两个量都读修正后值，品质与材料经此进入）；即 `wearPerUse` 的含义是"耐磨为 1 的料每用一次损耗的份额"，与卷二 §5.1 的 `lifeDays` 式一致 |
| D-2 | 时钟 / 声明写者 | **自然劣化**：每日减 `wsum(corrosionRate) × lookup(rules.wear.envCurve, 所在地湿度场值) × 所在容器的 preserveMult`；声明 `closedForm`（条件不变时线性外推），供跳时与远处模拟一次算完（环境场读卷二十） |
| D-3 | 派生 / 读 view | **劣化等级**的效果 = `rules.wear.levels[档].modifiers`，作为修正来源作用于该实例的能力等级、防护、保暖等（对估值的影响走 §4.16 的成色曲线，不在这里重复）；本卷不为任何一种物品写"旧了会怎样" |
| D-4 | 反应 / 声明写者 | **穿用**：处于穿戴持有关系的实例，每日按 `dailyUses` 次用损结算（穿戴关系的种类行登记在卷十八 §4.1） |
| D-5 | 派生 | **不建实例的耐用物**（远处、统计层）：日均损耗件数 = 存量 ÷ `lifeDays`，与 D-1 同源，不另设"寿命年数"常数 |
| D-6 | 校验 | `rules.wear.levels` 的 `minDurability` 严格递减；最低档的修正须把全部能力降到 0 |

#### 4.10.4 交互

| 对方 | 方向 | 内容 |
|---|---|---|
| 卷二十 §4.5/§4.7 | 本卷读 | 湿度、温度等环境场值 |
| 卷六 §4.12 | 对方读 | 耐用品的重置需求 = D-5 |
| 卷十三 | 对方写入口 | 战斗损伤以 `cause: damage` 调 `wearStep` |
| 卷二十七 | 对方读 | `closedForm` 声明 |
| 卷十八 §4.1 | 本卷登记 | 穿戴、装备两种持有种类行 |

#### 4.10.5 数据实例

- 例 1【西陲】铁斧：`wearResistance = 0.6×60 + 0.4×30 = 48`，`wearPerUse:0.002`，`dailyUses:40` → `lifeDays = 48 ÷ (0.002 × 40) = 600`（卷二 §5.1 式）。
- 例 2【非西陲】竹刀：`wearResistance = 22`，`wearPerUse:0.02`，`dailyUses:20` → `lifeDays = 55`；湿热地带的湿度场值高，竹的 `corrosionRate` 再乘 `envCurve`，放着也坏得快。
- 例 3【超自然】一件材料含卷十五登记的不朽类超自然材料的器物：该材料 `corrosionRate:0`、`wearResistance:100`，于是 D-2 为 0、D-1 极小；"神器不坏"是材料行的数值，不是豁免条款。

#### 4.10.6 验收断言

- **扫描式** V3-4.10-S：`advanceDurableWear` 出现 0 次；"寿命年数"一类不经维度的常数为 0；本节模块无十进制字面量（P-5）。
- **不变量式** V3-4.10-I：`durability` 只在登记的四种 `cause` 与修理下变化，且除修理外单调不升；`wearLevel` 与 `durability` 的对应满足阈值表。
- **扩展性式** V3-4.10-E：在 `rules.wear.levels` 某档加一条针对新修正键的修正项，不改 `.mjs`：所有处于该档的实例立即反映。

### 4.11 热属性与燃烧

#### 4.11.1 维度

材料：热四点、`specificHeat`、燃烧组、爆燃组、`noiseFactor`（§4.1）。物品模板：`matterState`（派生）。实例：`temperature`（空 = 与所在地同温）、`burn`。规则表 `rules.thermal.*`。温度量纲与环境温度场归卷二十 §4.5，本卷只定物品一侧。

#### 4.11.2 统一入口

- `thermalStep(engine,state,ref,minutes)` → 提案 `{temperature, stateChange, ignite, deflagrate, damage}`；`ref` 是实例或批次。
- `burnOutcome(engine,state,ref,minutes)` → `{consumedKg, heatMJ, products: [{item, qty}], spread}`。
- 只有"活跃"的东西才逐步求值：`temperature` 非空或 `burn` 非空者；其余一律视为与环境同温，不占计算。

#### 4.11.3 规则

| 编号 | 形状 / 通道 | 规则 |
|---|---|---|
| T-1 | 时钟 / 声明写者 | **物温**：受热（置于热源、炉膛、火场）时写入 `temperature`；此后向环境温度回落，剩余温差比例 = `lookup(rules.thermal.heatExchangeCurve, 经过时间 ÷（质量 × specificHeat）)`；回落到与环境相差小于规则表阈值时清空 |
| T-2 | 派生 / 读 view | **物态**：`matterState` 由当前物温与份额最大材料的 `meltPoint`、`boilPoint` 比较得出；模板上的 `matterState` 按 `rules.thermal.refTemp` 求 |
| T-3 | 反应 / 账本转移 | **相变后果**：固体实例变液 → 实例终止，按 X-2 留下 `rawForm`（熔毁）；液体或气体所在容器 `sealed` 为假 → 按规则表速率转入"流失"汇 |
| T-4 | 时钟 / 声明写者 | **热损与冻损**：物温高于 `heatDamagePoint` 或低于 `coldDamagePoint` 时，以 `cause: damage` 调 `wearStep`，量由规则表曲线给出 |
| T-5 | 反应 / 声明写者 | **点燃**：具有 `comp_burnable` 的东西，物温 ≥ `ignitePoint` 即起火；与正在燃烧的东西同处一个账户、容器或地点时，每分钟以 `flammability × lookup(rules.thermal.spreadCurve, 邻火热量)` 的概率被引燃 |
| T-6 | 时钟 / 账本转移 | **燃烧**：每分钟烧掉 `burnRate × 剩余可燃质量`；放热 = 烧掉的质量 × `heatValue ×（1 − moisture）`，作为热源项交给所在地的环境场（卷二十 §4.7）或所在炉窑（卷十九 §4.7）；按 `reactionProducts[rules.thermal.burnReaction]` 与对应产率留下灰烬类产物；不可燃份额按 T-4 受热 |
| T-7 | 反应 / 事件订阅 | **爆燃自动派生**：具有 `comp_deflagrant` 的东西，物温 ≥ `deflagThreshold` 或被 T-5 引燃时，不走 T-6，而是瞬间释放 `能量 = 质量 × 份额 × deflagEnergy`，随后该份质量清零。后果是规则表 `rules.thermal.deflagEffects` 里的一组 effectCall，参数由维度算：冲击幅度 = `lookup(blastRadiusCurve, 能量)`；碎片幅度 = `fragmentFactor × 所在容器材料的 hardness` 经 `fragmentCurve`；声响 = `能量 × noiseFactor` 经 `noiseCurve`。这些效果族产出的是卷十三 §4.2 伤害类型的区域伤害与卷二十 §4.7 环境场的脉冲 |
| T-8 | 派生 | **蔓延到建筑**：火场向所在设施的失火风险槽贡献热量（设施槽归卷十九），是否烧屋由对方规则决定 |
| T-9 | 派生 | **当燃料用**：任何具有 `comp_burnable` 的东西都能当燃料，折算见 §4.17；炉窑"够不够热"比较的是燃料 `heatValue` 派生的炉温上限与被加工料的 `meltPoint`，式子在卷十九 §4.7 |

- 例 1【西陲】`item_split_firewood`：材料全为橡木（`heatValue:17.5, ignitePoint:300, burnRate:0.02, moisture:0.2`）；10 kg 烧尽放热 `10 × 17.5 × 0.8 = 140 MJ`，留灰按橡木的燃烧反应产率。

#### 4.11.6 验收断言

- **扫描式** V3-4.11-S：规则层按材料或物品 id 判断"能不能烧、会不会炸"的分支为 0；只认某一种燃料或炭的字面量为 0；本节模块无十进制字面量。
- **不变量式** V3-4.11-I：一次燃烧全过程，烧掉质量 + 产物质量 + 入汇质量 = 初始质量；放热总量 = Σ 烧掉质量 × 热值 ×（1 − 含水）；不挂 `comp_deflagrant` 的材料在任何温度下都不触发 T-7。
- **扩展性式** V3-4.11-E：见 §6 E-3（材料表加一行挂爆燃组件的材料、物品表加一件含它的投射物，不改 `.mjs`，自动获得爆燃、区域伤害、声响与辟邪输出）。

### 4.12 腐坏与保质

#### 4.12.1 维度

材料：`rotRate`（在 `rules.rot.refTemp` 下每日腐坏进度）。物品模板：`shelfLifeDays`（派生）。批次与可腐实例：`spoilage`（0 新鲜，1 全坏）。容器：`preserveMult`、`sealed`。规则表：`rules.rot.tempCurve`、`rules.rot.stages[档] = {minSpoilage, modifiers, onConsume: list<effectCall>}`。

#### 4.12.2 统一入口

`rotStep(engine,state,lotRef,days)` → `{spoilage, stage, transform}` 提案；读：`lotsView(...)[i].spoilage`、`expiresDay`（外推投影）。食物被吃时的营养读 `materialView`，已含腐坏档的修正。

#### 4.12.3 规则

| 编号 | 形状 / 通道 | 规则 |
|---|---|---|
| P-1 | 时钟 / 声明写者 | **进度**：每日 `spoilage` 增加 `wsum(rotRate) × lookup(rules.rot.tempCurve, 所在处温度) × 所在容器 preserveMult`（不在容器内则乘子为 1）；声明 `closedForm`（条件不变时线性） |
| P-2 | 派生 | **保质日数** `shelfLifeDays = 1 ÷ wsum(rotRate)`（参考温度、无容器）；`allowExplicit`：材料 `rotRate` 未知时可显式写，已知时两者须相等（卷二 §1.2） |
| P-3 | 派生 / 读 view | **腐坏档**：`spoilage` 落在哪一档，就把该档 `modifiers` 作为修正来源加到这批货上（降低营养、估值）；吃下去时触发该档 `onConsume` 的 effectCall（身体后果的容器实例由卷二十一登记） |
| P-4 | 反应 / 账本转移 | **坏透**：`spoilage ≥ 1` 时整批按 `reactionProducts[rules.rot.rotReaction]` 与产率转成腐殖类产物，无此键则入"损耗"汇 |
| P-5 | 派生 | **腌、晒、熏、酿不是标记**：它们是配方（§4.8），产物是另一种材料（由 `reactionProducts` 指向），那种材料的 `rotRate` 更低。没有"已保存"布尔字段 |
| P-6 | 派生 | **冷藏、冰窖、地窖**：只是所在处温度低或容器 `preserveMult` 小；`tempCurve` 在冰点以下趋近 0，于是冻住的东西几乎不坏 |
| P-7 | 校验 | `rules.rot.stages` 的 `minSpoilage` 严格递增且首档为 0；`tempCurve` 单调不降 |

#### 4.12.4 交互

| 对方 | 方向 | 内容 |
|---|---|---|

#### 4.12.5 数据实例

- 例 1【西陲】鲜羊肉批次：材料 `rotRate:0.33` → `shelfLifeDays ≈ 3`；放进 `preserveMult:0.5` 的釉陶瓮得 6 天；冬季所在处温度低，`tempCurve` 给 0.2，得 15 天。
- 例 2【非西陲】沿海鱼露：鲜鱼经发酵配方变成"发酵鱼料"材料，`rotRate:0.002` → 约 500 天；这是 P-5，不是给鱼露写了特例。
- 例 3【非人类】青贮草料（给牲畜吃的）：`rotRate:0.01`，密封窖 `preserveMult:0.3`；坏到第二档时 `onConsume` 的效果族作用在吃它的牲畜身上，同一张 `stages` 表。

#### 4.12.6 验收断言

- **扫描式** V3-4.12-S：规则层按物品 id 或类别代号字面量决定"会不会坏、坏多快"的分支为 0；"已腌制、已晒干"一类布尔标记字段为 0。
- **不变量式** V3-4.12-I：`spoilage` 单调不降且在 [0,1]；`shelfLifeDays × wsum(rotRate) = 1`（定点误差内）；坏透转化前后质量守恒（含入汇）。
- **扩展性式** V3-4.12-E：加一种挂 `comp_rottable` 的材料和一件由它做的食物，不改 `.mjs`：会随温度变质、进容器变慢、分档降营养、坏透转化。

### 4.13 服装分层与护甲物性

#### 4.13.1 维度

`comp_wearable`（requires `layer`、`covers`、`coverage`、`thicknessMm`、`fitBody`、`fitSize`；enables `wear`、`insulate`、`protect`）。可选 `armorFactor`。派生四项：

- `warmth = wsum(insulation) × thicknessMm × rules.apparel.warmthPerMm × coverage × 覆盖部位的面积权重之和`（部位面积权重读身体图，卷四 §4.2）；
- `breathability = wsum(breathabilityBase) × lookup(rules.apparel.breathCurve, thicknessMm)`；
- `protection[d] = armorFactor × wsum(armorMult[d]) × lookup(rules.apparel.thicknessArmorCurve, thicknessMm)`，对 `damage` 词表每个键 d；`armorFactor` 不适用时 `protection` 不适用；
- `encumbrance = lookup(rules.apparel.encumbranceCurve, massKg) × 层位条目的系数`。

`comp_weapon` 的 `attacks`（卷二 §5.1：是否带刃、接触面积、穿深、速度倍率）是形制物性；刃的锋利读 `materialView(实例).sharpnessMax`。**减伤公式、层间如何叠、武器类别都归卷十三 §4.1–§4.5，本卷只给物性。**

#### 4.13.2 统一入口

- `canWear(engine,state,actorId,instanceId)` → `{ok, reason}`，`reason` 是代号（`body / size / layer_full`）。
- `wornProfile(engine,state,actorId)` → 每个身体部位一条：`{part, layers: [{instance, layer, coverage, protection, warmth, breathability}]（按层位由内到外）}`，另给 `warmthTotal`、`encumbranceTotal`。

#### 4.13.3 规则

| 编号 | 形状 / 通道 | 规则 |
|---|---|---|
| W-1 | 派生 / 读 view | **穿得上吗**：实例的 `fitBody` 等于穿戴者的身体图（读 `bodyView`）；尺码差按 `rules.apparel.fitPenalty` 查表，超出表域即不可穿，表内的差距变成累赘与保暖的修正项；同一部位同一层位已穿件数未达层位条目的 `slotsPerPart` |
| W-2 | 派生 / 读 view | **分层**：`wornProfile` 只按层位序排列并逐层给出物性，不求和防护；保暖逐层相加得 `warmthTotal`，交卷二十一 §4.7；累赘逐件相加得 `encumbranceTotal`，交卷四 §4.6 |
| W-3 | 派生 / 读 view | **材质与品质**：四个派生量都从材料算，品质、劣化等级、故障、附件经修正项进入；换材质（皮甲换成铁片甲的同形制）只是实例材料不同 |
| W-4 | 派生 / 读 view | **湿**：材料 `absorbs` 为真的衣物在潮湿状态下的保暖变化，由卷二十登记的环境状态以修正项给出，本卷提供修正键 `item.warmth` |
| W-5 | 派生 / 读 view | **风格**：服饰器物的地区风格只是 `tags` 里卷七词表的标签，偏好权重在卷七 §4.28；不影响物性 |
| W-6 | 校验 | `covers` 的部位都在 `fitBody` 的身体图里；`coverage ∈ (0,1]`；挂 `comp_wearable` 的模板必须能算出 `encumbrance` |

#### 4.13.4 交互

| 对方 | 方向 | 内容 |
|---|---|---|
| 卷十三 §4.3/§4.5 | 对方读 | `wornProfile` 的分层物性；武器 `attacks` 与材料量 |
| 卷二十一 §4.7 | 对方读 | `warmthTotal`、`breathability` |
| 卷四 §4.2/§4.6 | 本卷读 / 对方读 | 身体图、部位面积权重；`encumbranceTotal` |
| 卷七 §4.28 | 对方读 | 风格标签 |
| 卷十八 §4.1 | 本卷登记 | 穿戴持有种类 |

#### 4.13.5 数据实例

- 例 1【西陲】`item_sheepskin_coat`：`{classes:[class_garment,comp_wearable,comp_crafted], massKg:2.8, material:{mat_sheepskin:1}, layer:layer_outer, covers:[bpart_torso,bpart_arm_l,bpart_arm_r], coverage:0.95, thicknessMm:12, fitBody:body_humanoid, fitSize:size_medium, armorFactor:0.3}`
- 例 2【非西陲】`item_silk_robe`（东部丝袍）：`{..., massKg:0.6, material:{mat_silk:1}, layer:layer_mid, covers:[bpart_torso,bpart_arm_l,bpart_arm_r,bpart_leg_l,bpart_leg_r], coverage:0.9, thicknessMm:0.6, fitBody:body_humanoid, fitSize:size_medium}`；薄所以不暖、透气高、无 `armorFactor` 所以无防护，值钱来自丝的 `valueMult`。
- 例 3【非人类】`item_horse_barding`（马铠）：`{..., massKg:28, material:{mat_wrought_iron:0.7,mat_leather:0.3}, layer:layer_armor, covers:[bpart_neck,bpart_chest,bpart_flank], coverage:0.7, thicknessMm:2, fitBody:body_equine, fitSize:size_large, armorFactor:1}`；同一套 `protection` 公式，穿在马身上。

#### 4.13.6 验收断言

- **扫描式** V3-4.13-S：`wearItem` 旧入口里按名称或 id 判断部位、层位的代码为 0；本卷模块内不出现减伤计算（特征：对 `protection` 做跨层合并的表达式为 0）。
- **不变量式** V3-4.13-I：任一主体任一部位每个层位的已穿件数 ≤ `slotsPerPart`；`warmthTotal` 等于各件 `warmth` 之和；`protection` 的键集合 ⊆ `damage` 词表。
- **扩展性式** V3-4.13-E：加一个新身体图的物种（卷四）与一件 `fitBody` 指向它的衣物，不改 `.mjs`：该物种能穿、别的物种不能穿，保暖与防护照算。

### 4.14 附件与改装槽

#### 4.14.1 维度

- 宿主模板：`modSlots`（槽位种类 → 个数）、`modBudget`（可承受的改装预算）。
- 附件模板 `comp_attachment`（requires `fitsSlot`、`modCost`、`attachModifiers`；enables `attach`）。
- 宿主实例：`attachments`（已装附件实例的列表）。
- 词表 `attach_slot` 条目：`{install: ref vocab requirement, minutes: integer}`（装上所需的工具、手艺与工时）。

#### 4.14.2 统一入口

`canAttach(engine,state,hostId,attachmentId)` → `{ok, reason}`，`reason` 为代号（`slot / budget / held`）。装、拆是两个动作（登记在卷九 §4.1 动作目录），前置是槽位条目的 `install` 需求块。读：`itemView(宿主).dims.*` 已含附件修正；`itemView(宿主).attachments`。

#### 4.14.3 规则

| 编号 | 形状 / 通道 | 规则 |
|---|---|---|
| G-1 | 派生 / 读 view | **能装**：附件的 `fitsSlot` 与宿主 `modSlots` 有共同槽位且该槽位未满；已装附件 `modCost` 之和加新件不超过宿主 `modBudget`（读修正后值） |
| G-2 | 派生 / 读 view | **效果**：附件的 `attachModifiers` 是修正项，来源为附件实例，作用域为"持有它的宿主"，只在装着时生效；经卷二 §3.3 管线，与品质、材料同等对待 |
| G-3 | 派生 / 读 view | **质量与估值**：宿主毛重 = 自重 + 附件质量（与 K-2 同一求和）；宿主估值含附件估值（§4.16 V-4） |
| G-4 | 派生 / 读 view | **衣物改造**：加口袋、加衬、加甲片都是附件；附件自己挂 `comp_container` 时，宿主经它获得容积（内容物记在附件实例名下） |
| G-5 | 动作 / 声明写者 | **拆下**：附件回到拆卸者名下；宿主与附件各按 `rules.attach.removeWear` 受一次用损 |
| G-6 | 不变量 | 附件不改变宿主的品质档与材料组成；附件自己的品质、耐久、故障独立结算 |
| G-7 | 校验 | `modBudget` 存在 ⇔ `modSlots` 非空；附件的 `attachModifiers` 目标键必须是物品表的可修正维度 |

载具的可换部件、法器的镶嵌位都用这一套槽（槽位条目分别由卷十七、卷十五登记），不另立机制。

| 对方 | 方向 | 内容 |

| 卷九 §4.1 | 本卷登记 | 装、拆两个动作条目 |
| 卷十七 §4.2 | 对方登记 | 载具部件的槽位条目 |
| 卷十五 | 对方登记 | 镶嵌类槽位条目与附件；附魔本身归卷十五 |
| 卷十三 | 对方读 | 经 `itemView` 读到已含附件修正的武器甲胄维度 |

#### 4.14.5 数据实例

- 例 1【西陲】`item_leather_grip_wrap`：`{classes:[class_fitting,comp_attachment,comp_crafted], massKg:0.05, material:{mat_leather:1}, fitsSlot:[aslot_haft], modCost:5, attachModifiers:[{target:"item.wearPerUse", stage:"mul", value:-0.1}]}`；缠在斧柄上，斧子每次用损少一成。
- 例 2【非西陲】`item_hidden_pocket`（东部丝袍暗袋）：`{classes:[class_fitting,comp_attachment,comp_container], massKg:0.03, material:{mat_silk:1}, fitsSlot:[aslot_lining], modCost:10, attachModifiers:[], volumeCapacity:0.5, maxLoadKg:0.5, sealed:false, preserveMult:1}`

#### 4.14.6 验收断言

- **扫描式** V3-4.14-S：规则层没有按宿主或附件 id 写的"某物可装某物"对照；附件效果只经修正项，不存在直接改宿主字段的写入点。

### 4.15 书与文书物性

#### 4.15.1 维度

- `comp_readable`（requires `language`、`teaches`、`difficulty`；enables `read`）；另 `readMinutes`。
- `comp_document`（requires `docKind`；实例 requires `issuer`；enables `attest`）。词表 `dockind` 条目 `{needsSeal, transferable}`。
- 实例：`issuer`、`sealOf`、`copyOf`、`copyGeneration`、`purports`；内容指针 `contentRef`（`comp_work`，含义归卷二十三）。
- 载体没有专门字段：纸、简、帛、皮、石都是材料，轻重、怕不怕火、放多久由材料维度给出。

#### 4.15.2 统一入口

`documentStanding(engine,state,instanceId,frame)` → `{legible: Fact, original: Fact, sealed: Fact, apparentIssuer: Fact}`。本入口只回答物的状况；"读不读得懂、学到什么"归卷二十二 §4.6，"有没有法律效力"归卷八b 与卷六 §4.16。

#### 4.15.3 规则

| 编号 | 形状 / 通道 | 规则 |
|---|---|---|
| B-1 | 派生 / 读 view | **可读性** = `lookup(rules.documents.legibilityCurve, durability)`；低于规则表阈值即不可读。书旧了、烧了半边、泡了水，都只是耐久下降 |
| B-2 | 派生 / 读 view | **阅读门槛的物性部分**只有两条：读者持有或正在接触该实例；实例可读。语言、识字、等级、前置由卷二十二 §4.6 与卷十四判定，旧的合并门槛函数拆开 |
| B-3 | 动作 | **抄本**：抄写是一条配方（空白载体按类别选，原件是不消耗项，要求书写能力）。产物实例 `copyOf` 指向原件，`copyGeneration` = 原件代数 + 1，`teaches` 与 `language` 照原件；每一代给 `difficulty` 加一条修正 `rules.documents.copyLossPerGeneration × 代数`（传抄讹误） |
| B-4 | 派生 / 读 view | **原件**：`copyOf` 为空即原件。文书种类 `needsSeal` 为真时，`sealed` 为真当且仅当 `sealOf` 非空且等于 `issuer` 所属或本身的组织 |
| B-5 | 派生 / 读 view | **伪造**：伪造的文书是带 `purports` 的实例（自称的签发者与伪造水准）；`apparentIssuer` 对未识破者返回表象值。识破规则同 K-5 |
| B-6 | 反应 / 事件订阅 | **毁失**：文书实例毁坏（烧、烂、磨尽）时发事件；凭证丢失的经济后果由卷六订阅，知识载体灭失对失传的影响由卷二十二 §4.10 订阅 |
| B-7 | 校验 | `teaches` 的每个知识条目存在；`language` 在语言词表；`copyGeneration ≥ 0` 且原件为 0 |

### 4.16 估值公式与稀缺度派生

#### 4.16.1 维度

- 模板：`valueBase`（派生，`allowExplicit`）。材料：`valueMult`。实例与批次：`qualityTier`、`durability`、`spoilage`、`purports`、`attachments`；`beauty`（含义归卷二十三 §4.1，本卷只读）。
- 规则表：`rules.valuation.unitValue`（每"千克 × 价值倍率"折多少铜）、`conditionCurve`、`freshnessCurve`、`scarcityCurve`、`scarcityHorizonDays`、`beautyValue`；`rules.crafting.laborRate`、`valueAdd`。
- **稀缺度 `scarcity`**：派生量，不是手填维度（台账 S-19）。与"传说级配额"（卷十六 §4.2）不同轴。

#### 4.16.2 统一入口

- `valuation(engine,state,subjectRef,ctx)` → `Fact{value: 铜, explain: [{term 代号, factor}]}`。`subjectRef` 可以是物品模板、实例、批次，也可以是别类实体；`ctx = {role, frame, place}`。全书估值只有这一个入口（台账 I-02）；各类实体的估值器用 `registerValuer(kind, fn)` 按 `kindOf` 登记，本卷登记物品一类。
- `scarcity(engine,state,itemId,scopePlaceId)` → Fact（覆盖天数比，越小越稀缺）。
- `role` 是卷六 §4.21 登记的价格角色代号；本卷函数**不含任何角色常数**，四角色的加减（强卖折价、税基口径、赃物折价、赔偿口径）由卷六 §4.21 在路由后套用。别卷一律经卷六 §4.21 路由调用，不直接调本函数。

#### 4.16.3 规则

| 编号 | 形状 / 通道 | 规则 |
|---|---|---|
| V-1 | 派生 | **基础价值** `valueBase = first(...)`：① 有产出它的配方（多条取 `skillMin` 最低者，平局按代号字典序）→ `（Σ 各消耗项首选候选的 valueBase × 用量（按 §4.7 的口径换成件数）+ minutes × rules.crafting.laborRate[技能阶]）×（1 + rules.crafting.valueAdd）÷ 产出件数`；② 否则 → `massKg × wsum(valueMult) × rules.valuation.unitValue`。递归沿配方图，原料以 ② 为界（R-12）。两式都未命中（材料价值未知）时才允许显式写值 |
| V-2 | 派生 / 读 view | **单件估值** = `valueBase（读修正后值）× 材质项 × 成色项 × 新鲜项 + 装饰项`，再乘**稀缺项**。品质、取向、故障对价值的影响全部是 `item.valueBase` 上的修正项（品质表里有这一列），所以"品质乘子"不单列 |
| V-3 | 派生 | 各项定义：材质项 = 实例材料的 `wsum(valueMult)` ÷ 模板参考材料的 `wsum(valueMult)`（无偏离为 1；模板按 ① 定价时才乘，按 ② 定价的直接用实例材料算 ②）；成色项 = `lookup(conditionCurve, durability)`（不适用则不乘）；新鲜项 = `lookup(freshnessCurve, spoilage)`（不适用则不乘）；装饰项 = `beauty × beautyValue` + 文物名气加成（调卷二十三 §4.7 的入口）；稀缺项 = `lookup(scarcityCurve, scarcity)`（未知则不乘并记缺口） |
| V-4 | 派生 | **整体估值**：容器 = 自身 + 内容物；带附件者 = 自身 + 各附件；批次 = 件数 × 单件 |
| V-5 | 派生 / 读 view | **稀缺度** `scarcity(物, 范围)` = 范围内可得存量 ÷（范围内日需求 × `scarcityHorizonDays`）。存量是账本在该范围的聚合（卷六 §4.1），日需求读卷六 §4.4；物品属于替代池时，两者都按池单位对整池求。世上只此一件的实例（存量 1、需求未知）按存量一侧的极小值查曲线。稀缺度不落盘，每次由存量算 |
| V-6 | 派生 / 读 view | **表象**：`ctx.frame` 的观察者未识破时，以 `purports` 给出的模板与品质代入上面各式；识破后用真实值 |
| V-7 | 不变量 | 估值是纯函数：无随机、无写入；同一状态同一参数逐位相同；`explain` 各项连乘加总严格等于结果 |
| V-8 | 派生 | **没有回退**：估不出来就返回未知并记缺口，由调用方按自己的规则处理；不许回退到某一种具体物品的价格。类别行上的 `valueBase` 值经正常的类别继承生效，那是数据，不是回退 |

别类实体的估值器（地产读用地代号、事件估值、财富汇流）由各自定义卷登记到同一入口，本卷不写其公式。

#### 4.16.5 数据实例

- **不变量式** V3-4.16-I：`explain` 复算严格相等；对任一配方，产物 `valueBase` ≥ 各消耗项价值之和（工与加成非负）；`scarcity` 对存量单调不降。
- **扩展性式** V3-4.16-E：加一种 `valueMult` 很高的新材料和一件用它的物品，不改 `.mjs`：模板与实例估值自动体现；把它加进一条现有配方的可选料，产物估值随所用料变化。

### 4.17 可替代折算

#### 4.17.1 维度

- `substitutePool`（写在类别行上最好，物品行继承）；池条目 `{key, unit}`：`key` 指向物品表的一个数值维度，`unit` 是池单位。`substituteKey` 改为派生 = 所属池条目的 `key`【请卷二回填】。
- 三个折算键都是派生量：
  - `fuelEnergyMJ = massKg × Σ 可燃份额 × heatValue ×（1 − moisture）`（燃料按热值）；
  - `satietyTotal = massKg × Σ 可食份额 × edibleFraction ×（1 − moisture）× energyDensity`（食物按饱腹）；
  - `warmthTotal`：成衣取 `warmth`；布料取 `areaM2 × wsum(insulation) × rules.apparel.warmthPerArea`（御寒按保暖）；布料另可直接按 `areaM2`（按幅面）。
- 金属料、纤维等按质量折算的池，`key` 指 `massKg`。

#### 4.17.2 统一入口

`substituteQty(engine,state,itemRef,poolId)` → Fact（每件折合多少池单位；不属该池则不适用）。池成员清单是加载期只读索引。

#### 4.17.3 规则

| 编号 | 形状 / 通道 | 规则 |
|---|---|---|
| S-1 | 派生 / 读 view | 每件折合量 = 物品在池条目 `key` 所指维度上的值（读修正后值；批次带腐坏档修正时随之下降） |
| S-2 | 派生 / 读 view | 需求块按类别选料且该类别行带替代池时，`qty` 以池单位计（§4.7）；于是"要 14 MJ 的燃料""要够十人吃一天的主食"可以直接写 |
| S-3 | 派生 | 需求方（卷六 §4.4/§4.12）先把需要量换成池单位，再在池成员里挑；怎么挑（按价、按习惯、按文化偏好）是卷六与卷七的事，本卷只给折算 |
| S-4 | 校验 | 一件物品至多属于一个替代池；池条目的 `key` 必须是物品表的数值维度，其单位与池 `unit` 一致；池成员在 `key` 上未知的记缺口并排除出候选 |

#### 4.17.4 交互

| 对方 | 方向 | 内容 |
|---|---|---|
| 卷六 §4.4/§4.12 | 对方读 | 池成员与折合量 |
| 卷十九 §4.7 | 对方读 | 炉窑燃料按总热量扣 |
| 卷七 §4.28 | 对方读 | 池内选择的偏好权重 |
| 卷二十五 | 对方读 | 饲料池、主食池的成员来自其作物与畜产行 |

#### 4.17.5 数据实例

- 例 1【西陲】燃料池：10 kg 橡木柴 = `10 × 17.5 × 0.8 = 140 MJ`；3 kg 木炭（`heatValue:30, moisture:0.05`）= `85.5 MJ`。炉子要 140 MJ，烧 10 kg 柴或约 4.9 kg 炭都行。
- 例 2【非西陲】主食池：南方稻米与西陲燕麦各按 `satietyTotal` 折算；一个南方来的人在西陲吃燕麦，身体得到的由营养维度算，他乐不乐意吃是卷七的偏好。
- 例 3【非人类】饲料池（按"每畜"计耗）：干草与燕麦按同一折算键互替，消费者是牲畜；牲畜能吃哪些东西由其物种食性决定（卷四），池只管折算。

#### 4.17.6 验收断言

- **扫描式** V3-4.17-S：只认一种粮、一种柴的字面量为 0（`settlement-trade.mjs:92/:216/:305`、`stock.mjs:31` 的写法退役）；规则层没有手写的"甲顶几份乙"换算常数。
- **不变量式** V3-4.17-I：池内任意两成员的互换比 = 两者折合量之比；物品行与池条目的键一致（派生后恒成立）。
- **扩展性式** V3-4.17-E：加一个新替代池条目并在一个类别行上引用它，不改 `.mjs`：该类物品互替、需求块可按池单位写、家户日耗与周贸易按池结算。

### 4.18 运法与货值密度

#### 4.18.1 维度

- `valueDensity = valueBase ÷ massKg`（铜每千克；读基值，不含稀缺项）。
- `transportMode = first(rules.items.transportRules)`：规则表每条的 `when` 只读 `sizeClass`、`massKg`、`fragility`、`matterState`、`shelfLifeDays`、是否挂 `comp_livestock`；值是 `transport` 词表代号，条目带 `needsContainer`、`selfMoving`。
- `fragility`：路上磕碰的易损度，只是输入，损耗怎么算在卷十七。

#### 4.18.2 统一入口

`itemView(...).dims.valueDensity / transportMode / fragility`。成批货物：`shipmentProfile(engine,state,lots)` → `{massKg, volumeL, valueTotal, valueDensity, modes, fragileShare, minShelfDays}`（各为 Fact），供承运与风险计算一次读全。

#### 4.18.3 规则

| 编号 | 形状 / 通道 | 规则 |
|---|---|---|
| Y-1 | 派生 / 读 view | 货值密度与运法都是派生量，任何行不手填；物品换了材料或配方成本变了，二者自动变 |
| Y-2 | 派生 / 读 view | 一批货的货值密度 = 总估值 ÷ 总质量（含容器自重）；运法取各成员运法中条件最严者（词表条目有序） |
| Y-3 | 派生 / 读 view | 需容器的东西（液、粉、散粒）未装进合规容器时，`shipmentProfile` 返回不可运的缺口代号 |
| Y-4 | 派生 | 自走的东西（牲畜）不占载重；其行进速度与损耗归卷十七与卷二十五 |
| Y-5 | 派生 | "值不值得运到那里"由卷六用两地价格与卷十七的运费、风险算；本卷提供的只有质量、体积、货值密度、易损、保质日数这五个输入 |

#### 4.18.4 交互

| 对方 | 方向 | 内容 |
|---|---|---|
| 卷十七 §4.6（路途风险律） | 对方读 | `valueDensity`、`fragileShare`、`minShelfDays` |
| 卷十七 §4.1/§4.8 | 对方读 | 质量、体积、运法 |
| 卷六 §4.6 | 对方读 | 商队装载与选货 |
| 卷四 §4.6 | 对方读 | 人畜能背多少由对方算 |

#### 4.18.5 数据实例

- 例 1【西陲】铁锭：`valueDensity` 低、`fragility:0`、固体 → 运法命中"车载"；只在邻近聚落间流动，这是货值密度低的结果。
- 例 2【非西陲】东部生丝：`valueDensity` 高、体积小 → 运法命中"驮载"；值得走远路，也更招劫（卷十七读货值密度）。
- 例 3【非人类】活羊：挂 `comp_livestock` → 运法命中"自走"，不占车；路上要吃草料，那是 §4.3 的"每畜"日耗。
- 例 4【超自然】`item_spirit_incense`：质量 0.05 kg、含高价值倍率的超自然材料 → 货值密度极高、运法"随身"；没有为它写任何运输特例。

#### 4.18.6 验收断言

- **扫描式** V3-4.18-S：规则层按物品 id 或类别字面量决定运法、运费的分支为 0；`transportRules` 的 `when` 不含实体 id。
- **不变量式** V3-4.18-I：每件物品 `transportMode` 恰有一个值；`valueDensity × massKg = valueBase`（定点误差内）；`shipmentProfile` 的总质量 = 各批质量与容器自重之和。
- **扩展性式** V3-4.18-E：在 `transport` 词表加一种运法并在规则表加一条命中条件，不改 `.mjs`：满足条件的物品运法改变，卷十七的承运判定随之变化。

- 例 3【超自然】**一把灵香**（超自然耗材）。材料含三成雷击木炭（行由卷十五登记，继承自普通木炭）：可燃（T-5、T-6，热值按份额加权）；雷击木炭的辟邪标签经 `materialView` 的并集规则出现在香上（§3.1、M-4）；用度类是祭用、按"每次仪式"计耗（C-4），缺了的后果是用度类条目里的 effectCall（C-5）；仪式的需求块按材料大类"超自然"或类别"香"二选一（§4.7 例 3）；货值密度极高、随身携带（Y-1）；伪造的灵香是带表象的普通线香（K-5、V-6）。
