## §0 卷首

### 0.1 范围

本卷回答六个问题：
1. 统一底层要达到什么（§1）；
2. 底层分几层、每层管什么、读写边界在哪、禁止什么（§2；§3A 只写共享设施的原则并指向卷二）；
3. 亮圳 11-13 定的规矩怎样落成可执行、可扫描的条文（§3）；
4. 现有代码里哪些是骨架要留、哪些要改造、哪些要重做（§5）；
5. 为什么前九轮没落实、这次怎样在结构上堵住（§6）；
6. 三十一卷之间怎样依赖、按什么顺序读与写、全书怎样验收（§11、§12）。

本卷**不定义任何领域维度**，也**不定义任何数据格式**（格式归卷二），只定义"维度是什么、谁能读、谁能写、违反了怎样被机器抓住"。

### 0.2 依赖与被依赖

- 依赖：产品原则；PLAN 11-13 规矩；调研 01–10；李白 11-13 两次裁定；卷二（格式定义方）。
- 被依赖：全部卷。卷二落成 §2.3、§3A、§4.4、§4.5 指向的格式与校验器，以及 §2.8 字符串类型规则（本卷只引用）；卷九落成 §7 与 R-2 第 5–10 条（输入边、AI 边）；卷十一落成 §6.4–§6.6；卷十二落成 §3、§3.1、§3.2、§10、§12 的扫描实现与**绕法测试集**；卷二十九落成 §2.9（显示层、显示闸、语言包）；卷二十七落成 §8；卷零逐处标 06b 219 行的处置。

### 0.3 读法

- 条文编号：`L-n` 分层契约（§2.1）、`R-n` 硬规矩（§3）、`I-n` 不变量（I1–I32 沿用架构设计 02；I33 起本卷新增）、`A-n` 反模式（§10）、`V-n` 验收（§12）。各卷只引编号。
- "维度"指程序可读并参与判断的、带固定代号或数值的字段；"显示字"指只给人看的文字。两者分界是本卷最重要的一条线（R-2、§4.4）。
- "专项规则"指只对一个或少数具体实例成立的分支；对一个类别（由维度表定义）成立的规则不算专项。
- "规则层"指**第一至第六层**的全部代码，**含 consistency-review 等审查模块**；**第〇层是 kernel 组，不属规则层**，另受卷二 §2.8 kernel 行与 §2.9 约束（同样不读任何语言；与卷二"规则层 = kernel、textcore 与六个非规则组之外"同一口径）。本卷写"第〇至第六层"时指"kernel 组加规则层"。"输入边"指把玩家文字或模型文字变成封闭代号的模块组（§2.10），不属于任何层，可整体拔除。"显示闸"指第七层内处理安全类文字检查的模块组（§2.9.2）。
- 引用卷二写 `卷二 §3.3`；引用调研写 `06a §2`；引用代码写 `文件:行`。

### 0.4 写进每卷模板头部的硬约束（卷目 10 §3.1 已定，此处定稿为条文）

1. **禁具体 id**：规则代码不出现任何实例 id 字面量，也不得从 id 字符串反推类别（R-4）。
2. **禁读自然语言**：规则层一行不读任何语言；字符串字面量只许是登记过的代号（R-2、§3.1）。
3. **禁专项规则**（R-4）。
4. **常数只在规则表**（R-6）。
5. **一系统一读入口、一字段一写者**（L-3、L-6；格式见卷二 §2.1、§2.3、§2.6）。

## §1 设计目标

### 1.1 一句话

> 一个**完整、真实运转**的世界，可以**无限随机生成**，新增物品、神、地区、职业、文化、设施、怪物、法术只需**填数据**，不加一行代码；底层**与语言、表现形式无关**，SillyTavern 只是第一个前端。

### 1.2 四个可检验的目标

| # | 目标 | 可检验的说法 | 落实卷 |
|---|---|---|---|
| G1 | 完整真实的世界 | 卷零覆盖表里 10 号文档总表 223 行（纳入 167 + 已有 41 + 不适合 15）每行有处置；每个子系统五小节齐全；五款游戏 335 条每条有处置 | 卷零、领域卷 |
| G2 | 可无限随机生成 | 生成物与手写内容同格式、同加载器、同校验器（R-7）；"无限"靠种子分区 + 按需物化 + 离屏聚合（卷十 §3、卷二十七 §1–§2）；同种子同输出（I31、I50、V-27）。“无限”的含义是细节无限（同一世界按需物化，可一直往下细化）加换种子（换一个种子得到另一个世界）（封卷后勘误 1115j6） | 卷十、十六、二十四、二十七 |
| G3 | 加内容只填数据 | 分阶段扩展性测试（V-6，按卷二 §七 B1/B2 逐类断言）：在已定稿的表里加一行，不改 `.mjs`，该类行为自动获得。神、法术、怪物能"只填数据"依赖 §3A 的共享设施（修正键、效果族表、领域词表） | 卷二、卷十二、领域卷 §6 |
| G4 | 与语言和表现无关 | 规则层代号只以同族句柄 `V.<族名>.<id>` / `E.<code>` 出现，裸字符串字面量一律计入（V-2/V-20，附录甲 C-1）；任意两语言包下存档哈希相同（I40、V-4；哈希口径卷二 §2.9 第 3 条）；三种前端读同一投影接口，`scene()` 经模式校验无语言字段（V-5）；输入边整体拔除后靠菜单完整游玩（V-21） | 卷二十九、卷九、卷十二、卷二十七 |

### 1.3 不是目标

不追求 DF 的物理精度（取结构不取精度，01 §8.2 第 6 条）；不做旧存档兼容、不加复演版本标记（R-8）；不做"只有引擎的天国拯救"——领域卷必须写到真实内容实例。

- **L-0 读向下**：第一至第七层每层只读自己以下的层；第〇层是基座，各层经第二层读它的状态，只有第〇层事务能写它。**共享计算设施（§3A：求值管线 `dim / modified / explain`、效果族求值 `effects()`、继承展平、校验器）属于第〇层内核**（李白裁定），不属于第三层；第二层 view 调用求值管线是"向下调用内核"，不是向上调用，L-0 没有例外。求值管线读的修正项与效果族行是第三层登记的**数据**（卷二 §3.2、§3.9），由内核读取，不是第三层代码被调用。**内核对上层的依赖只限数据文件，不 import 任何上层模块**（第〇层 = 卷二 kernel 组；谁能 import 谁以卷二 §2.7 的 import 矩阵为唯一定义，服务端那张的 kernel 行只有自身一格，kernel 也不得 import textcore 共享库；违例码 E-KERNEL-UPWARD-IMPORT、E-TEXTCORE-IMPORT，卷二 §4.3、§2.9 第 2 条）。内核对 textPaths 上的文字只存、搬运、算哈希（`Sealed`，卷二 §2.9 第 3 条），读取内容即 E-SEAL-READ。输入边与作者边不是层：输入边只向第〇层事务提交封闭代号集合内的动作代号加参数；作者边只向第一层写经校验的数据。
- **L-1 三个语言位置**：自然语言只允许存在于三处——输入边（文字→代号）、AI 边的输出守门（AI 文字入库前查词表，§2.9.2）、第七层（代号→文字，含显示闸）。第〇至第六层之间没有任何自然语言流动，也没有任何代码对字符串做 R-2 第 1 条形式清单里的任何操作。
- **L-2 单写路**：任何状态改变 = 第〇层一条事件 + 其原语列表（I16）；原语是 `world/ontology/primitives.json` 的封闭清单；第二层以上只产提案，由第〇层事务（primitives.mjs:236–237）归约。
- **L-3 一系统一读入口**：22 类实体各一个 view（卷二 §2.1）；通用谓词 `can(engine,state,subject,capabilityId)` 与派生谓词 `awake / capacity`、已终止谓词 `terminated`（别名 `dead`）只在 action-capacity.mjs（卷二 §2.5）；view 只做字段查找、持有解析、来源标记与**向下调用内核求值管线**（`View.dims` 惰性调 `modified`，`dim()` 只查字段，卷二 §2.2、§3.3），不含领域规则、不直接读规则表常数、不产提案。判据：产提案的是第三层；只读不写、不产提案、只向下调用的是第二层。
- **L-4 规则只读维度**：第三层规则只经第二层入口读；只对维度表的类别或全体成立；只产提案；常数只经 `engine.rules`。**import 规则**（I19 的确切口径）：以卷二 §2.7 的**两张 import 矩阵**（服务端一张、客户端一张；行 = 调用方，列 = 被调用方；各有哪些行列、装配文件那一行怎么写，以卷二为准，本卷不复述）为唯一定义，现有 tests/arch-metrics.test.mjs、tests/metrics/import-graph.baseline.json、tools/arch-layers.mjs 为检查起点；规则层那一行是：只许 import kernel（且只经 `state-owners.json → kernelApi.exports`）与规则层自身，`state` 只传给入口、kernelApi、声明节点三类对象（卷二 §2.3）。**调用路径**：派生规则取修正后值走 `view(...).dims.<dim>`（惰性调 `modified`）或直接 `modified(kind,id,dim)`；动作 / 反应 / 时钟规则把效果族行展开为原语列表走 `effects(engine,state,familyId,ctx)`（纯函数，返回输出清单），再作为提案交事务；两者都是向下调用内核。**规则层任何模块不得 import 输入边、显示层组、AI 输出边守门、显示闸、host、语言包**（卷二 E-VIEW-INPUT-IMPORT），也不得 import textcore（E-TEXTCORE-IMPORT，卷二 §2.9 第 2 条），因此 `Text` 对规则层不可见。**两进程各有一张 import 矩阵和一张全局白名单**（服务端：kernel、规则层、inputEdge、gate、aiGate、outputGate 与服务端版 textcore；客户端：host、display 与客户端版 textcore；卷二 §2.9）；两进程之间没有 import，只有 HTTP 通道上的登记入口与登记出口。服务端可用的 `node:*` 内置模块与 npm 包按组列在该矩阵的白名单里，JSON import 只许出现在登记过的加载器里；`tools/` 是离线组，有自己的白名单，**运行时任何组不得 import 它**（卷二 §2.9）。
- **L-5 表的所有权分裂**：维度表的 schema、代号规范、显示字段声明是第一层**数据**（卷二 §1）；执行校验的**校验器 L0–L5 是第〇层内核设施**（`server-plugin/kernel/validate/dimensions-validate.mjs`，卷二 §4.1；它是卷二 §2.9 第 1 条登记边界入口表的一项，`narrow` 的实现在同目录 `kernel/validate/narrow.mjs`；离线校验器归 tools 组，不在 kernel/validate）；维度表的行归第四层各领域卷。
- **L-6 一字段一写者**：每个可变字段、持有来源、派生事实、源汇恰一个写者，加载时声明（卷二 §2.3 `declareInputs`、§2.6、§2.7 `state-owners.json` 的 `stateKeys[*].writers` 与 `declareStateWriter`）；未声明的写即 E-VIEW-UNDECLARED-WRITE，同字段两个写者即 E-WRITER-DUPLICATE；推进阶段与排序键 `phase/sortKey` 在 `systems[*].phase` 登记，同阶段同键即 E-PHASE-DUPLICATE（卷二 §2.7）。
- **L-7 接口四通道**：跨领域写只走三类（账本转移、事件订阅、声明写者）；跨领域读只走对方 view()。推进次序不是通道：时钟规则与 advance hook 在 `state-owners.json → systems[*].phase` 声明 `phase`（卷二 §2.7 封闭的 8 个阶段：clock、environment、body、needs、economy、society、events、projection）与 `sortKey`，第〇层调度器据此排序，注册顺序不影响结果；I31 的同刻五阶段是调度器内部的归约阶段，与此 8 个推进阶段是两级。
- **L-8 投影不落盘**：第六层只产投影与事件分发，投影可随时丢弃重建（I17）；事件物理写入属第〇层，第六层拥有事件的定义与分发。
- **L-9 显示层只读**：第七层只读第六层投影与第一层语言包；不持有规则、不缓存权威数据。**display 只负责渲染**：玩家的点选与键入由客户端 **host** 的事件入口接收——对**可用动作投影**的点选由 host 变成代号发往服务端（不经输入边），键入的文字由 host 以 `RawText` 发往服务端 inputEdge 的登记入口（卷二 §2.9）；点选代号的服务端入口不属于 inputEdge 组，所以拔掉输入边后点选照常可用（V-21）。**宿主能力不经全局访问**：客户端只有 host/bootstrap 一个文件可以直接访问 `window`、`document` 与 SillyTavern 上下文，它把需要的能力打包成能力对象、以参数交给 display；其余模块凡经属性访问宿主全局（`window.x`、`getContext` 等）一律违例（判定与违例码在卷二 §2.9）。
- **L-10 四段同卡**：一张实现卡 = 维度表行补齐 + 数据补齐 + 读取方改造 + 旧路径删除（拆分规则 §6.6）。
- **L-11 不迁移的读法**：不做一次性全量迁移；每个领域在其卡内完成退役；不存在"先双写、以后收口"（A-11）。账本双写由母卡 LEDGER-1 承办（§6.5）。
- **L-12 门禁先行**：卷二定稿后、任何领域实现卡之前，五项扫描与校验器进 CORE 并登记基线；基线只降不升（I43）。
- **L-13 安全类功能的落脚（两道闸）**：注入防线属 AI 边（玩家文字进入模型之前，在 aiGate 完成，§2.10）；屏蔽词 / 真实人物 / 文字类未成年检查设**两道闸**——第一道 **AI 输出边守门**（AI 产出的任何文字、玩家起名与玩家手记**入库之前**查语言包词表，命中即 `reject:*` 代号，不入库、不进哈希、不进后续提示；population.mjs:409 "生成时就拒收"是**位置与时机**的范本，不是写法范本），第二道 **显示闸**（呈现前兜底；裁决集合与替换后复核唯一定义在卷二 §2.9 第 6 条，本卷不另列代号）；**生成名不过运行时守门**：生成名在 state 中只存成分代号 `nameParts`（计入哈希；玩家起的名存 `displayNames`，不计入哈希；世界状态不随语言包而变），屏蔽词检查在内容构建时由校验器离线检查名字成分表的组合，运行时只由显示闸替换，不换种子、不写回 state（李白裁定）；未成年人情节检查按数值维度（年龄、关系代号、动作标签、场景标签）判断的部分属第三层规则。词表只在语言包，规则层不读；两道闸都在 §3.2 排除清单内、各有扫描条；三类功能都不得删除（§2.9.2、§2.10）。

### 2.2 第〇层 内核与状态

**职责**：持有运行期可变状态；执行唯一写路径（事务）；调度；骰值。

**数据形态**：`state`、`holdings`、`ledger`（ledger.mjs:4）、事件日志、元数据；事务 primitives.mjs:236–237；调度器 advance-registry.mjs:97；骰值 §8。运行态状态实例（`state.statuses`、`state.modifiers`、`state.displayNames`、`state.created`）都在这一层，各有唯一写者（卷二 §1.9、§1.11、§3.2、§2.7）。**共享计算设施也在这一层**（§3A，李白裁定）：求值管线 `dim / modified / explain`（卷二 §3.3，现 derived.mjs 升级）、效果族求值 `effects()`（卷二 §3.9）、继承展平（卷二 §1.3）、校验器（卷二 §4）；它们是纯函数，读第一层数据与第三层登记的修正项 / 效果族行，不写状态。

**读写边界**：写者只有事务；读者只有第二层入口；状态对象在归约之外冻结（I3；开发模式的越界读写探测仅调试，实现手段以卷二 §2.2 为准）。

**禁止**：规则 / 工具 / AI / 界面直接改状态；用 `records` 当自由文本消息总线（A-10）；事务外 `Math.random`；**读墙钟**——世界时间一律由卷二十的时钟推进；墙钟定时器只许客户端 host 与服务端 `kernel/scheduler`（AI 超时、心跳）使用，并且经能力对象注入，其他任何组使用即违例（卷二 §2.9）。**墙钟只能触发"请求推进"，不能决定推进多少，也不能写状态**：心跳到点只向内核投递一条推进请求，推进多少由世界时钟与规则表步长决定，这条请求与玩家请求同样记进输入序列，所以同一份输入序列仍得同一结果（I31）；机制唯一定义在卷二 §2.9 第 0 条"心跳推进"项，本卷不复述（第十五版；接缝清单 ①-2）。

**骨架**：ledger.mjs、holding-sources.mjs、primitives*.mjs、advance-registry.mjs、storage.mjs（digest :14）、digest-exclude.mjs。**这些文件现在都在 `server-plugin/` 根目录，按卷二"代码文件按所在目录归组"的规则属规则层，不享有 kernel 权限**；它们（以及求值管线 derived.mjs、rx.mjs、seed-keys.mjs）的**目标路径一律在 `server-plugin/kernel/**`**，搬迁之后才是第〇层成员（逐文件去处见 §5.1 表后"目标路径"条）。

### 2.9 第七层 显示层（含显示闸）

#### 2.9.1 显示层

**职责**：渲染第六层投影给人——文字（按显示语言代号）、画面、声音。**菜单、构造器、候选按钮是第六层"可用动作投影"的渲染**：显示名由语言包按动作代号给出，玩家点选由客户端 host 的事件入口变成代号发往服务端，**不经输入边**（L-9；display 只渲染，不接事件、不产代号）。这就是"拔掉输入边，菜单照常可玩"的结构保证（R-2 第 8 条、V-21）。

**两进程中的位置**（唯一定义在卷二 §2.9，本卷只引用）：display 组只在**客户端进程**（浏览器扩展）。服务端把要显示的文字拼好、过显示闸，由 outputGate 把 `Screened<Text>` 序列化为"已筛信封" `{screenId, text, digest}` 并从登记出口发出；客户端只能经 host 的登记入口接收信封，由客户端版 textcore 校验 `screenId` 与 `digest` 后还原为客户端的 `Screened<Text>`，再交 display 写 DOM；**DOM 出口归客户端 display 组**。信任边界在两进程之间的 HTTP 通道。菜单请求与输入请求的处理结果怎样回到客户端（"回应通道"），唯一定义在卷二 §2.9 第 0 条"回应通道"项，本卷只引用、不写通路；原则只有一句：kernel 与 inputEdge 的处理结果只以代号形态交给 outputGate，由 outputGate 拼文字、筛查后从登记出口发出，二者都不 import outputGate（违例码 E-WIRE-REPLY，卷二 §4.3）。存档、读档、导出、导入的结果怎样回到玩家（"存档四路"），以及只点选不键入时 AI 的叙述与对白从哪里进来（"菜单回合的叙述与对白"），同样只在卷二 §2.9 第 0 条的同名两项定义，本卷只引用；原则各一句：存档类动作的结果与别的请求走同一条回应通道（卷二 §2.9 第 0 条），引擎不读墙钟；AI 叙述不绑在输入路由上，菜单回合与输入回合都有。摘要用 sha256，只在服务端计算（来源 `node:crypto`，仅服务端版 textcore 可用）；客户端只做核对（`SubtleCrypto`，仅客户端版 textcore 可用）。

**数据形态**（由卷二十九 §2.1、§2.3 至 §2.6 定稿，本段只作索引；C29-9）：语言包按显示语言代号分文件，本体在 `world/i18n/`、扩展包在包内 `i18n/`——显示名 `labels.<显示语言代号>.json`，模板文本 `templates.<显示语言代号>.json`，槽位是代号或数值；与语言无关、不含文字的显示配置（模板结构行 `templates.json` 等）在 `world/display/`；命名拼法规则（nameParts → 字串）；素材键的通道 `{portrait, sprite, tile, icon, sfx, ambience, backdrop, music}`（`backdrop`、`music` 对应背景图与音乐选择）；单位与历法按法域显示。

**读写边界**：L-9。显示层模块组的成员清单见附录甲 C-4（卷二 §2.7 `display.modules`：客户端 `extension/**` 中除 host 组 `extension/host/**` 与客户端版 textcore `extension/textcore/**` 之外的文件；与其余各组、两份共享库文件级不相交，E-GROUP-OVERLAP），**登记在册**（§3.2 排除清单）。display 与服务端各组之间没有 import（不同进程），它拿到的只有两样：host/bootstrap 以参数交来的能力对象，与经 host 登记入口收到、已由客户端版 textcore 校验还原的 `Screened<Text>`；display 不得 import gate 或 outputGate，不做判定，不直接访问宿主全局（L-9）。客户端内谁能 import 谁按卷二 §2.9 客户端那张 import 矩阵；服务端规则层不得 import 任何非规则组（E-VIEW-INPUT-IMPORT）。host 组（第七个模块组，**只在客户端**，`extension/host/**`：扩展启动、DOM 挂载、事件接线、收发信封，不含规则、不做判定与产出）见卷二 §2.9。语言包只由服务端版 textcore 的 labels 加载器读，display 不读（卷二 §2.9 第 1、2 条）；textPaths 上的 `Sealed` 由谁 `unseal`、解封后怎样经显示闸成为信封，以卷二 §2.9 第 3 条与两进程模型为准。`lookupByLabel` 反查与键入文字的解释都不在显示层组，属输入边（附录甲 C-4）。

- **不开 AI 时**：没有 AI 文字，守门只对玩家起名运行（"入库守门"不限 AI 文字）；display 不签发、不申请凭证，也不做判定。

**第二道：显示闸（属第七层模块组；卷二 §2.7 `outputGate.modules`）**
- **位置**：呈现前兜底，覆盖已入库的历史文本（例如词表更新之前入库、当时没有命中的文字）与运行期拼装的字串（含 `nameParts` 渲染结果）。

### 2.10 输入边（不是层；可整体拔除）

**职责**：只做一件事——**文字 → 固定代号**。输入是玩家自由文字或模型文字；输出是 `{action: <目录代号>, slots: {<槽位代号>: <候选编号 | 数值>}}` 或封闭 schema 的 proposal（primitive-schema.mjs:57），或 `menu_fallback` 代号（退回菜单）；文字槽位（如起名）在输出里的值形态以卷二 `schema:input-edge-v1` 为准，输出里没有文字本身。**所在进程**：输入边在服务端进程；玩家键入的文字由客户端 host 以 `RawText` 发到服务端 inputEdge 的登记入口（卷二 §2.9）。

**允许的文字操作**：inputEdge 组对 `string` 的允许用法是卷二 §2.8 该组闭集（唯一规范化函数 `normalizeInput(text)` 于 `server-plugin/input/normalize.mjs`；`===` 整串比较；两张冻结 Map——显示名→代号、编号字串→代号——的查表；原样传递），清单外即 E-INPUT-FUZZY（V-23 = 卷二 S18）。规范化结果查的是语言包里"菜单项显示名 → 代号"与"菜单候选编号 → 代号"两张表（卷二 §1.9 第 5 条 `lookupByLabel(lang, text)`）。其他任何以该变量为接收者或参数的字符串方法、正则、模板拼接、`obj[text]` 动态取键，一律违例。

**规范化口径**（李白裁定，唯一定义在卷二 §1.9 第 3 条，中英同一套，写进 R-2 第 7 条）：① NFC；② 裁首尾 Unicode White_Space（卷二 §1.9 第 3 条的冻结表）；③ 简单大小写折叠（卷二 §1.9 第 3 条的 casefold 表）；④ 逐码点相等。边界预期见附录甲 C-3。**不折叠全半角，不做别名，不做部分 / 前缀 / 最长匹配**——全半角不同、标点不同、多一字少一字、整句含菜单项名、含关键词、近似拼写，一律 `menu_fallback`。**允许键入菜单候选编号**（ASCII 数字查表，不是文字理解）。翻不出时退回菜单并**展示完整菜单**（可点选或输入编号），退回不是报错。**键入只是便利路径，主路径是点选**（R-2 第 7 条）。语言包里菜单项显示名以 NFC、无首尾空白存储，由校验器保证（I47）；同一菜单里两项折叠后相同是运行期才知道的事，按卷二 B10 (e) 返回 `ambiguous` 并退回菜单，不设加载期检查。

**判据：什么文件算输入边**：① 文件级清单以卷二 §2.7 `inputEdge.modules` 为准（附录甲 C-4 为索引；全部在服务端 `server-plugin/input/` 一个目录下；`extension/input-view.mjs` 的 DOM 挂载部分留在客户端属 display 组，"规范化 + 查表 → 代号"是 `server-plugin/input/` 里的代码——卷二 §2.7、§6.11 迁移行），`outputSchema: schema:input-edge-v1`，文件数 ≤ 8（E-GROUP-SIZE），增项须李白批；七组（含 kernel、host）文件级不相交（E-GROUP-OVERLAP）；② 依赖约束——**输入边能 import 谁，唯一定义是卷二 §2.7 import 矩阵 inputEdge 行，本卷不另列清单**（原则只有一条：它不得经任何途径写状态，也不得让规则反过来依赖它）；③ 输入只能是玩家文字或模型文字，输出只能是封闭 schema；④ **不被任何规则直接依赖**（规则层 import 输入边 = E-VIEW-INPUT-IMPORT，卷二 S16）。凡处理世界状态、或其结果被规则当文字用的模块，**不得靠划入输入边消账**，必须改读代号。

**注入防线**（L-13）：位置**在 aiGate，不在 inputEdge**。本卷只写位置；做法（玩家文字怎样放进提示、做不做"剥离"、"剥离"一词在两卷里指什么）唯一定义在卷二 §2.9 第 0 条"注入防线与剥离口径"项（口径一句：不剥离，只隔离），本卷不写做法。输入边拔除后没有玩家文字进入模型，这段不再运行。

**AI-R1 的实现路径**：inputEdge 自己不调用模型（它没有任何网络能力，卷二 §2.9 全局白名单）。发给模型的请求只经 aiGate 的登记出口，模型返回只经 aiGate 的登记入口；inputEdge 只经卷二 §2.7 矩阵允许的 aiGate 接口把"玩家文字 + 候选集"交过去、取回封闭代号（接口名与签名以卷二 §2.9 为准）。**AI-R1 的输出**同受约束：每个 id 来自候选集，否则 `menu_fallback`；有歧义时 AI 输出 `ambiguous` 代号，引擎退回菜单；AI 不可用（无密钥、断网、超时）→ `menu_fallback`。**超时怎样判定**：墙钟定时器只许服务端 `kernel/scheduler` 与客户端 host 使用，且经能力对象注入；AI 超时由 `kernel/scheduler` 的定时能力给出，时长在规则表（卷二 §2.9）。

**验收**：V-23（输入边扫描）、V-26（输入边承诺的性质测试）。

**条文**：

3. 所有前置失败带 `code`（`E-*`），调用方只比较 `error.code`。

### R-4 不得为具体物品、神、地区写专项规则；系统间走统一接口；行为由通用规则从维度算出

### 3.1 扫描的最低技术要求（卷十二实现，不可降的底线）

1. **代号的合格判据（上下文白名单，按被比较维度的词表族；李白裁定，卷二 S13 (a)、A16 为可验收口径）**：规则层使用代号的**唯一合法形式**是加载期从 `_vocab.json` / 维度表生成的冻结句柄 `V.<族名>.<id>`（族键就是词表族的全名，不写前缀缩写，卷二 §1.9；如 `V.status_family.sfam_sleep`）与 `E.<code>`（错误码里有连字符，写成合法标识符的映射规则以卷二 §4.2 为准，句柄生成器按它生成）；句柄对象带 `family`。扫描器对 `===/!==/includes/switch/对象键查找` 的两侧做**类型归因**：一侧是 `dim()/modified()/View.dims` 返回的 Fact（声明类型 `enum <family>` 或 `ref vocab <family>`）、`state-owners.json` 登记的状态路径、`error.code`、`event.verb`、原语 `op`、持有 / 义务 `kind` 等有声明类型的来源，另一侧必须是**同族**句柄，否则 E-VIEW-FAMILY-MISMATCH；**任何裸字符串字面量参与比较一律计入**（卷二 S13 ④），不论它是否恰好是某个登记代号（`'sleep'`、`'sfam_sleep'` 都报）；**左侧解析不出所属维度的比较，一律违例**。**不使用全局平铺名单**：卷二第三版的 `scan-allowlist.json` 已被句柄机制取代。代号格式正则（卷二 §1.9）本身只许出现在卷二 S13 (b) 登记的 kernel 文件里，名单以卷二为准，本卷不列。**本卷不设"JS 语言记号"例外**：`typeof x === 'string'` 这类与裸字串比较的写法在规则层同样违例；确需的类型收窄只在卷二 §2.9 登记的 `narrow` 内部做。
   - **正例**（卷二 A16、§2.8 正反例表）：`if (st.dims.family.value === V.status_family.sfam_sleep)`（`st.dims.family` 声明为 `enum status_family`，句柄同族）合格；`if (err.code === E.<该错误码的句柄>)`（两侧都是 `ErrorCode`）合格；`switch (event.verb) { case V.verb.verb_transfer: … }` 合格（verb 族条目带 `verb_` 前缀，卷二 §1.9）。
   - **反例**：`if (st.family === 'sleep')`、`x === 'sfam_sleep'`（裸字面量，S13 ④）违例；`['sleep','dead'].includes(x)` 违例；`x === V.terrain.terrain_hill` 而 `x` 声明为 `status_family` → E-VIEW-FAMILY-MISMATCH；`text.includes('sleep')`（左侧是文字）违例；从 `id.startsWith('npc_')` 推出 kind 再做比较违例（E-VIEW-ID-PARSE，kind 只能由 `kindOf(id)` 给出）；中文字面量永远违例。
2. **类型感知，而非纯 AST**（卷二 §2.8、附录 F #11）：扫描器 = `tsc --checkJs`（品牌类型 JSDoc）+ typescript-eslint 类型感知规则；判定依据是表达式的**静态类型与节点位置**，不是方法名清单；无类型标注、解构丢失类型、跨函数传参后无法归因的值一律按 string 处理并报 E-VIEW-FAMILY-UNRESOLVED（宁可误报不放过）；品牌值只能由 kernel 组构造（E-KERNEL-ONLY）。绕法用例集归卷十二。
3. **显示字段按 schema 路径判定，不按全局字段名**：`state-owners.json` 的 `display` 集合（登记项以卷二 §2.7 为准，现行 `displayNames.*.text` 与 `playerNotes.*.text`；`npcs` 的 display 为空，`nameParts` 是代号数据进哈希——附录甲 C-6）与维度表 string 类型字段路径 `<kind>.<field>`（卷二 §1.5 E-DIM-STRING-NOT-DISPLAY），是"显示字"的唯一来源（卷二 §2.4、§6.11）。读到这些路径即 E-VIEW-DISPLAY-READ。本卷 §4.4 只列路径族与原则，不列全局名；`engine.rules`、修正项的 `source`、常数条目的 `basis` 都不在显示路径里，不受影响。
4. **数据引用不误报**：对 `world/` JSON 的读取不算字面量；只统计代码。
5. **口径明文**：注释、`console.*` 日志、`throw Error(文案)` 的文案（code 必须另带）、tests/ 夹具不是代码判断，不计；它们不是"豁免"，是判定对象之外。
6. **输出逐行清单**：文件、行、节点类型、所属类（A–F / 实例 / 直写 / 常数 / 语言判断 / 显示路径读 / id 反推），供基线比对与"只降"判定。
7. **进 CORE**：任一分量高于上次合入即失败（I43）；不是 `k8-guard` 式只报不拦。
8. **排除清单核对**：§3.2 六个非规则组成员清单来自数据文件，每组有自己的扫描条；成员数量受控，增项须李白批。

### 4.4 维度类型与显示字段（原则；清单由数据声明）

- **维度类型**：以卷二 §1.5 为唯一定义——**封闭集合 14 种**（number、integer、boolean、string、enum、ref、union、set、map、list、struct、curve、distribution、rx；扩展须改卷二并报李白）。本卷早先的"code"即 enum，"vector"即 `list<number>` 带 `length`；`string` 类型字段即显示字段。卷一不另列类型表。
- **显示字段**：由数据声明，不是手写名单（卷二 §2.4）。两个来源：① `state-owners.json → stateKeys[*].display` 的状态路径集合——卷二现行登记 `displayNames.*.text` 与 `playerNotes.*.text`；`npcs` 的 display 为空（拼好的名字是投影层产物，不在 state；`nameParts` 是代号数据，进哈希），本卷不另枚举，其余由领域卷按卷二登记；② 维度表里类型为 string 的显示字段路径 `<kind>.<field>`（卷二 §6.11 迁出清单：目录 `name/purpose/description`、ontology `label`、professions `aliases`、material-props `appearance[].term`、`sources[].name/citation`）；**string 类维度不得出现在任何运行期可写路径上**：偏离行 `state.created[*].props` 不得写 string 维度（自然语言只能在 textPaths，经守门入库；判定与违例码 E-TEXT-UNGATED 在卷二 §2.7），因此不存在"偏离行里的显示字段"，哈希排除表里也没有这一项。
- **待退役的文字字段**（按路径族列，卷二 §6.11 与卷零逐处处置；在此之前规则层读它们计入基线）：`buildings.*.purpose`、`npcs.*.activity`（文字值）、`locations.*.terrain / climate / industry`（文字值）、`npcs.*.occupation / personality`（散文）、`settlements.*.polity`（名称）、`offices.*.title`、`records.*.content / reason`、`args.contextReason`、`orgs.*.rules`（章程文字）、`error.message`、模型叙述正文。
- 原则：规则层读的每个字段都必须在某张维度表登记为维度类型；不在任何维度表的字段不许读。

### 4.5 系统声明表（卷二 §2.7 `state-owners.json`）

唯一声明表是卷二 §2.7 的 `state-owners.json`：`stateKeys[<key>] = {readers, writers{<path>: module}, display[]}`；`systems[<id>] = {view, predicates, tables, writers, sources, sinks, phase{<hook>: {phase, sortKey}}, inputs（加载期由 declareInputs 写回的只读镜像）}`；**七个模块组** `kernel / inputEdge（≤ 8）/ display / gate / outputGate / aiGate / host`（host 见卷二 §2.9 第 1 条），各为 `{modules: list<glob>, process}`（`process` 标明该组在服务端还是客户端），`inputEdge` 另有 `outputSchema`；两份共享库 `textcore`（服务端版）与 `clientTextcore`（客户端版），都不是模块组（卷二 §2.9 第 2 条）；服务端装配文件 `assembly`（单个文件，不是模块组；带 `calls`，即它可调用函数的封闭清单；卷二 §2.9 第 0 条"装配文件"项）；待删目录 `retired`；七组、两份共享库与装配文件文件级互不相交，且与规则层不相交（E-GROUP-SIZE、E-GROUP-OVERLAP）；**两张 import 矩阵**（两进程各一张，谁能 import 谁的唯一定义）；`kernelApi.exports`（内核对外 API 的闭集，逐个导出名带 callers 与 acceptsState）；`groupApi.exports`（非 kernel 组与共享库的跨组导出表，格式同 kernelApi，表外的名字别的组不得 import；卷二 §2.7）；`dataFiles`（非代码文件的登记；每个文件都有归属，否则 E-FILE-UNASSIGNED）；`textPaths` 与 `textWriters`（文字路径及其唯一写者——写者只在 aiGate 组内，凭证由 kernel 签发、只有这些写者文件可申请；路径上存 `Sealed`，卷二 §2.9 第 3 条；`created.*.props.basis` 为 `struct:basis`，不在其中）；`pathTypes`（每个 state 路径的值类型，路径模式匹配语义同节）；`phases`（封闭 8 个）。两进程各自的组、import 矩阵与全局白名单见卷二 §2.9。错误码一律以卷二 §4.3 为准，本节涉及的有：E-WRITER-DUPLICATE、E-WRITER-MISSING、E-VIEW-UNDECLARED-WRITE、E-PHASE-DUPLICATE、E-VIEW-INPUT-IMPORT、E-KERNEL-UPWARD-IMPORT、E-KERNEL-ONLY、E-TEXT-UNGATED、E-PATH-UNDECLARED、E-PATH-OVERLAP、E-DIGEST-EXCLUDE-DRIFT、E-TEXTCORE-IMPORT、E-SEAL-READ、E-SEAL-DIGEST、E-TEXT-EXIT、E-GLOBAL-UNLISTED、E-FILE-UNASSIGNED。**本卷不另设任何登记文件**；模块组成员清单以卷二 §2.7 为准，附录甲 C-4 是按进程排列的索引。

### 6.4 阶段退出标准（实条款）

阶段 P1 … Pn 由卷十一定义。每阶段退出须同时满足：
1. **扫描数单调且达标**：对基线元组每一分量 c，`T(P_k, c) = T(P_{k−1}, c) − 登记退役数(P_k, c)`，`T(P0, c) = B0(c)`；实际 `S(P_k, c) ≤ T(P_k, c)` 且 `S(P_k, c) ≤ S(P_{k−1}, c)`。**硬上限公式**（卷十一只可收紧）：`U(k) = floor(B0(c) × (1 − k/n)²)`，`S(P_k, c) ≤ U(k)`；n = 5 时 U = 0.64、0.36、0.16、0.04、0 × B0；`U(n) = 0`。**三者取最严**。公式比第二版的手填序列（0.6/0.35/0.15/0.05）在 P1–P3 略松、P4 更严，取公式是为了 n ≠ 5 时无歧义可算；B0 很小的分量（如版本分叉首测）floor 后在 k < n 即为 0，等于要求 P1 清零，这是有意的严格。公式不动，适用口径如下（卷十一 R11-5.3；C11-2）：硬上限 U(k) 只对接收卡在阶段 ≤ k 的位置组的子基线生效，最终阶段即全量；n 取卷十一的派生值。
2. **退役数兑现**：实际删除数 = 登记退役数。
3. **扩展性门（分阶段）**：该阶段定稿并上线的每张表通过 V-6（按卷二 §七 B1/B2 的逐类断言）。

5. **卷零回填**。

- **哪些不进哈希**（卷二 §2.9 第 3 条）：只有三样——① 显示时现拼的文字（语言包拼出的名字、模板填槽结果；它们本来就不在 state）；② 玩家起的名 `displayNames.*`；③ 玩家手记 `playerNotes.*`（玩家自己键入、规则层读不到、不影响世界演化）。所以排除表 = `state-owners.json` 的 `display` 字段集合 ∪ `displayNames.*` ∪ `playerNotes.*`，由这三项**生成**（组成照录卷二 §2.9 第 3 条，本卷只在本条写这一次，其余处一律引用本条；两卷不一致时以卷二为准）；生成器在 CI 重新生成并与入库的 `digest-exclude.json` 做 diff，不一致即 E-DIGEST-EXCLUDE-DRIFT（卷二 §4.3）；I40 的"排除表相等"断言指此 diff，不是自证。现行 `digest-exclude.json` 里与这一口径不符的层（把叙述排除在外的那一层）随本条改掉，文件的分层写法以卷二为准。
- **哪些进哈希**：state 中非 display 的数值与代号字段、holdings、ledger、事件日志（含 rollKey）、`nameParts` 成分代号、`origin`、`created.*.props.basis`（`struct:basis`，代号 + 种子键 + 写者，kernel 直写，卷二 §2.7）；**AI 写入的文字记录**（`narration.*` 等 textPaths；运行期不存 AI 记录文字，卷九 R9-9.9）在 state 内是 `Sealed`，属于存档内容、与语言包无关，其 `Sealed.digest` **进哈希**。
- **由此得到的三条性质**：语言包互换不改变哈希（I40、V-4）；玩家起不同的名、写不同的手记不改变哈希；AI 叙述不同则哈希不同——叙述是存档的一部分，所以"同种子同哈希"在不开 AI 的 T0 档成立，开 AI 时在 AI 输出相同的前提下成立（卷二 §2.9 第 3 条）。"AI 不入逻辑"因此不用哈希相等来验，而用"事件流与 textPaths 之外的状态逐值相等"来验（V-13）。
- **名字的两种归属**：见附录甲 C-6（`nameParts` 进哈希；`displayNames` 不进哈希；`npcs.*.name` 已删除）。V-4 在两语言下玩家命名不同亦可比。
- **I40 补充**：id 生成、排序、分组不以显示字为输入；`sort()` 比较键必须是 id 或数值。名字归属的唯一写全处是附录甲 C-6。

### 8.4 历法与语言不进时钟；8.5 每个世界保存自己的数据副本
时钟只认分钟，月、年、节日、年号是按法域历法的投影，语言是显示层偏好，改语言不改任何事件；每个世界保存自己的数据副本（DF 01 §8.1 第 10 条），不做版本迁移（R-8）。
