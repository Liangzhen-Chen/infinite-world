## §0 卷首

### 0.1 范围

本卷回答六个问题：
1. 统一底层要达到什么（§1）；
2. 底层分几层、每层管什么、读写边界在哪、禁止什么（§2；§3A 只写共享设施的原则并指向卷二）；
3. 亮圳 11-13 定的规矩怎样落成可执行、可扫描的条文（§3）；
4. 现有代码里哪些是骨架要留、哪些要改造、哪些要重做（§5）；
5. 为什么前九轮没落实、这次怎样在结构上堵住（§6）；
6. 三十一卷之间怎样依赖、按什么顺序读与写、全书怎样验收（§11、§12）。

本卷**不定义任何领域维度**，也**不定义任何数据格式**（格式归卷二），只定义"维度是什么、谁能读、谁能写、违反了怎样被机器抓住"。

### 0.2 依赖与被依赖

- 依赖：产品原则；PLAN 11-13 规矩；调研 01–10；李白 11-13 两次裁定；卷二（格式定义方）。
- 被依赖：全部卷。卷二落成 §2.3、§3A、§4.4、§4.5 指向的格式与校验器，以及 §2.8 字符串类型规则（本卷只引用）；卷九落成 §7 与 R-2 第 5–10 条（输入边、AI 边）；卷十一落成 §6.4–§6.6；卷十二落成 §3、§3.1、§3.2、§10、§12 的扫描实现与**绕法测试集**；卷二十九落成 §2.9（显示层、显示闸、语言包）；卷二十七落成 §8；卷零逐处标 06b 219 行的处置。

### 0.3 读法

- 条文编号：`L-n` 分层契约（§2.1）、`R-n` 硬规矩（§3）、`I-n` 不变量（I1–I32 沿用架构设计 02；I33 起本卷新增）、`A-n` 反模式（§10）、`V-n` 验收（§12）。各卷只引编号。
- "维度"指程序可读并参与判断的、带固定代号或数值的字段；"显示字"指只给人看的文字。两者分界是本卷最重要的一条线（R-2、§4.4）。
- "专项规则"指只对一个或少数具体实例成立的分支；对一个类别（由维度表定义）成立的规则不算专项。
- "规则层"指第〇至第六层全部代码，**含 consistency-review 等审查模块**。"输入边"指把玩家文字或模型文字变成封闭代号的模块组（§2.10），不属于任何层，可整体拔除。"显示闸"指第七层内处理安全类文字检查的模块组（§2.9.2）。
- 引用卷二写 `卷二 §3.3`；引用调研写 `06a §2`；引用代码写 `文件:行`。

### 0.4 写进每卷模板头部的硬约束（卷目 10 §3.1 已定，此处定稿为条文）

1. **禁具体 id**：规则代码不出现任何实例 id 字面量，也不得从 id 字符串反推类别（R-4）。
2. **禁读自然语言**：规则层一行不读任何语言；字符串字面量只许是登记过的代号（R-2、§3.1）。
3. **禁专项规则**（R-4）。
4. **常数只在规则表**（R-6）。
5. **一系统一读入口、一字段一写者**（L-3、L-6；格式见卷二 §2.1、§2.3、§2.6）。

## §1 设计目标

### 1.1 一句话

> 一个**完整、真实运转**的世界，可以**无限随机生成**，新增物品、神、地区、职业、文化、设施、怪物、法术只需**填数据**，不加一行代码；底层**与语言、表现形式无关**，SillyTavern 只是第一个前端。

### 1.2 四个可检验的目标

| # | 目标 | 可检验的说法 | 落实卷 |
|---|---|---|---|
| G1 | 完整真实的世界 | 卷零覆盖表里 10 号文档总表 223 行（纳入 167 + 已有 41 + 不适合 15）每行有处置；每个子系统五小节齐全；五款游戏 335 条每条有处置 | 卷零、领域卷 |
| G2 | 可无限随机生成 | 生成物与手写内容同格式、同加载器、同校验器（R-7）；"无限"靠种子分区 + 按需物化 + 离屏聚合（卷十 §3、卷二十七 §1–§2）；同种子同输出（I31、I50、V-27） | 卷十、十六、二十四、二十七 |
| G3 | 加内容只填数据 | 分阶段扩展性测试（V-6，按卷二 §七 B1/B2 逐类断言）：在已定稿的表里加一行，不改 `.mjs`，该类行为自动获得。神、法术、怪物能"只填数据"依赖 §3A 的共享设施（修正键、效果族表、领域词表） | 卷二、卷十二、领域卷 §6 |
| G4 | 与语言和表现无关 | 规则层代号只以同族句柄 `V.<族名>.<id>` / `E.<code>` 出现，裸字符串字面量一律计入（V-2/V-20，附录甲 C-1）；任意两语言包下规则可读状态哈希相同（I40、V-4）；三种前端读同一投影接口，`scene()` 经模式校验无语言字段（V-5）；输入边整体拔除后靠菜单完整游玩（V-21） | 卷二十九、卷九、卷十二、卷二十七 |

### 1.3 不是目标

不追求 DF 的物理精度（取结构不取精度，01 §8.2 第 6 条）；不做旧存档兼容、不加复演版本标记（R-8）；不做"只有引擎的天国拯救"——领域卷必须写到真实内容实例。

分层契约逐条：

- **L-0 读向下**：第一至第七层每层只读自己以下的层；第〇层是基座，各层经第二层读它的状态，只有第〇层事务能写它。**共享计算设施（§3A：求值管线 `dim / modified / explain`、效果族求值 `effects()`、继承展平、校验器）属于第〇层内核**（李白裁定），不属于第三层；第二层 view 调用求值管线是"向下调用内核"，不是向上调用，L-0 没有例外。求值管线读的修正项与效果族行是第三层登记的**数据**（卷二 §3.2、§3.9），由内核读取，不是第三层代码被调用。**内核对上层的依赖只限数据文件，不 import 任何上层模块**（第〇层 = 卷二 kernel 组；谁能 import 谁以卷二 §2.7 六组 import 矩阵为唯一定义，kernel 行只有自身一格；违例码 E-KERNEL-UPWARD-IMPORT，卷二 §4.3）。输入边与作者边不是层：输入边只向第〇层事务提交封闭代号集合内的动作代号加参数；作者边只向第一层写经校验的数据。
- **L-1 三个语言位置**：自然语言只允许存在于三处——输入边（文字→代号）、AI 边的输出守门（AI 文字入库前查词表，§2.9.2）、第七层（代号→文字，含显示闸）。第〇至第六层之间没有任何自然语言流动，也没有任何代码对字符串做 R-2 第 1 条形式清单里的任何操作。
- **L-2 单写路**：任何状态改变 = 第〇层一条事件 + 其原语列表（I16）；原语是 `world/ontology/primitives.json` 的封闭清单；第二层以上只产提案，由第〇层事务（primitives.mjs:236–237）归约。
- **L-3 一系统一读入口**：22 类实体各一个 view（卷二 §2.1）；通用谓词 `can(engine,state,subject,capabilityId)` 与派生谓词 `awake / capacity` 只在 action-capacity.mjs（卷二 §2.5）；view 只做字段查找、持有解析、来源标记与**向下调用内核求值管线**（`View.dims` 惰性调 `modified`，`dim()` 只查字段，卷二 §2.2、§3.3），不含领域规则、不直接读规则表常数、不产提案。判据：产提案的是第三层；只读不写、不产提案、只向下调用的是第二层。
- **L-4 规则只读维度**：第三层规则只经第二层入口读；只对维度表的类别或全体成立；只产提案；常数只经 `engine.rules`。**import 规则**（I19 的确切口径）：以卷二 §2.7 **六组 import 矩阵**（行 = 调用方，列 = 被调用方；kernel / 规则层 / inputEdge / display / gate / outputGate / aiGate / tests-CLI）为唯一定义，现有 tests/arch-metrics.test.mjs、tests/metrics/import-graph.baseline.json、tools/arch-layers.mjs 为检查起点；规则层那一行是：只许 import kernel（且只经 `state-owners.json → kernelApi.exports`）与规则层自身，`state` 只传给入口、kernelApi、声明节点三类对象（卷二 §2.3）。**调用路径**：派生规则取修正后值走 `view(...).dims.<dim>`（惰性调 `modified`）或直接 `modified(kind,id,dim)`；动作 / 反应 / 时钟规则把效果族行展开为原语列表走 `effects(engine,state,familyId,ctx)`（纯函数，返回输出清单），再作为提案交事务；两者都是向下调用内核。**规则层任何模块不得 import 输入边、显示层组、AI 输出边守门、显示闸、语言包**（卷二 E-VIEW-INPUT-IMPORT）。
- **L-5 表的所有权分裂**：维度表的 schema、代号规范、显示字段声明是第一层**数据**（卷二 §1）；执行校验的**校验器 L0–L5 是第〇层内核设施**（卷二 §4）；维度表的行归第四层各领域卷。
- **L-6 一字段一写者**：每个可变字段、持有来源、派生事实、源汇恰一个写者，加载时声明（卷二 §2.3 `declareInputs`、§2.6、§2.7 `state-owners.json` 的 `stateKeys[*].writers` 与 `declareStateWriter`）；未声明的写即 E-VIEW-UNDECLARED-WRITE，同字段两个写者即 E-WRITER-DUPLICATE；推进阶段与排序键 `phase/sortKey` 在 `systems[*].phase` 登记，同阶段同键即 E-PHASE-DUPLICATE（卷二 §2.7）。
- **L-7 接口四通道**：跨领域写只走三类（账本转移、事件订阅、声明写者）；跨领域读只走对方 view()。推进次序不是通道：时钟规则与 advance hook 在 `state-owners.json → systems[*].phase` 声明 `phase`（卷二 §2.7 封闭的 8 个阶段：clock、environment、body、needs、economy、society、events、projection）与 `sortKey`，第〇层调度器据此排序，注册顺序不影响结果；I31 的同刻五阶段是调度器内部的归约阶段，与此 8 个推进阶段是两级。
- **L-8 投影不落盘**：第六层只产投影与事件分发，投影可随时丢弃重建（I17）；事件物理写入属第〇层，第六层拥有事件的定义与分发。
- **L-9 显示层只读**：第七层只读第六层投影与第一层语言包；它把玩家对**可用动作投影**的点选直接变成代号（不经输入边），把玩家自由文字交输入边；不持有规则、不缓存权威数据。
- **L-10 四段同卡**：一张实现卡 = 维度表行补齐 + 数据补齐 + 读取方改造 + 旧路径删除（拆分规则 §6.6）。
- **L-11 不迁移的读法**：不做一次性全量迁移；每个领域在其卡内完成退役；不存在"先双写、以后收口"（A-11）。账本双写由母卡 LEDGER-1 承办（§6.5）。
- **L-12 门禁先行**：卷二定稿后、任何领域实现卡之前，五项扫描与校验器进 CORE 并登记基线；基线只降不升（I43）。
- **L-13 安全类功能的落脚（两道闸）**：注入防线属输入边；屏蔽词 / 真实人物 / 文字类未成年检查设**两道闸**——第一道 **AI 输出边守门**（AI 产出的任何文字**入库之前**查语言包词表，命中即 `reject:*` 代号，不入库、不进哈希、不进后续提示；population.mjs:409 "生成时就拒收"是**位置与时机**的范本，不是写法范本），第二道 **显示闸**（呈现前兜底，只输出 pass/replace/block）；**生成名不过运行时守门**：生成名只存成分代号 `nameParts`，屏蔽词检查在内容构建时由校验器离线检查名字成分表的组合，运行时只由显示闸替换，不换种子、不写回 state（李白裁定）；未成年人情节检查按数值维度（年龄、关系代号、动作标签、场景标签）判断的部分属第三层规则。词表只在语言包，规则层不读；两道闸都在 §3.2 排除清单内、各有扫描条；三类功能都不得删除（§2.9.2、§2.10）。

### 2.2 第〇层 内核与状态

**职责**：持有运行期可变状态；执行唯一写路径（事务）；调度；骰值。

#### 2.9.2 安全两道闸：AI 输出边守门 + 显示闸（L-13）

只在显示层拦不够：违规文字若已写进存档（叙述记录、生成的档案 / 碑文、玩家命名），下一轮会作为提示再发回 AI。因此设两道闸，词表都是语言包数据（位置与 schema 见 §2.3 第 7 条；规则层不读它；代码里零字面量）。闸的操作分**判定**与**产出**两类，算法、needle 来源与各组权限的唯一定义是卷二 §2.7 权限表与 §2.8（附录甲 C-5 只作索引）。

**第一道：AI 输出边守门（aiGate，属 AI 边模块组；卷二 §2.7 `aiGate.modules`）**
- **位置**：AI 产出的任何文字（叙述、对白、结构化声明里的文字字段、R4 起草的档案润色）在**入库之前**。**唯一入库写入 API**（卷二 §2.7）：state 内允许存自然语言的全部路径登记为 `textPaths`（现行 `displayNames.*.text`、`narration.*`、`records.*.text`；**`created.*.props.basis` 不是文字路径**——它已定为 `struct:basis`（代号 + 种子键 + 写者节点名），由 kernel 的 `dimension-writers.mjs` 直接写、无需凭证，卷二 §2.7），每路径一写者 `textWriters`；路径模式按卷二 §2.7"路径模式匹配语义"（`*` 恰一段，最具体者优先，同等具体重叠 → E-PATH-OVERLAP）；写入必须经 `writeText(credential, path, text)`，`credential` 只由 aiGate 组（AI 文字，须先过守门：屏蔽词、id 泄漏、长度、字符集、schema）或 display 组（玩家命名）签发；无凭证写入、或在 textPaths 之外存自然语言 → E-TEXT-UNGATED；写入 `pathTypes` 未声明的路径 → E-PATH-UNDECLARED；textPath 缺 `textWriters` 写者 → E-WRITER-MISSING（卷二 §2.7、§4.3；扫描 + 运行时拒写）。

### 2.10 输入边（不是层；可整体拔除）

**职责**：只做一件事——**文字 → 固定代号**。输入是玩家自由文字或模型文字；输出是 `{action: <目录代号>, slots: {<槽位代号>: <候选编号 | 数值>}}` 或封闭 schema 的 proposal（primitive-schema.mjs:57），或 `menu_fallback` 代号（退回菜单）。

**允许的文字操作**：inputEdge 组对 `string` 的允许用法是卷二 §2.8 该组闭集（唯一规范化函数 `normalizeInput(text)` 于 `server-plugin/input/normalize.mjs`；`===` 整串比较；两张冻结 Map——显示名→代号、编号字串→代号——的查表；原样传递），清单外即 E-INPUT-FUZZY（V-23 = 卷二 S18）。规范化结果查的是语言包里"菜单项显示名 → 代号"与"菜单候选编号 → 代号"两张表（卷二 §1.9 第 5 条 `lookupByLabel(lang, text)`）。其他任何以该变量为接收者或参数的字符串方法、正则、模板拼接、`obj[text]` 动态取键，一律违例。

**规范化口径**（李白裁定，唯一定义在卷二 §1.9 第 3 条，中英同一套，写进 R-2 第 7 条）：① NFC；② 裁首尾 Unicode White_Space（卷二 §1.9 第 3 条的冻结表）；③ 简单大小写折叠（卷二 §1.9 第 3 条的 casefold 表）；④ 逐码点相等。边界预期见附录甲 C-3。**不折叠全半角，不做别名，不做部分 / 前缀 / 最长匹配**——全半角不同、标点不同、多一字少一字、整句含菜单项名、含关键词、近似拼写，一律 `menu_fallback`。**允许键入菜单候选编号**（ASCII 数字查表，不是文字理解）。翻不出时退回菜单并**展示完整菜单**（可点选或输入编号），退回不是报错。**键入只是便利路径，主路径是点选**（R-2 第 7 条）。语言包里菜单项显示名以 NFC、无首尾空白、折叠后唯一存储，由校验器保证（I47）。

**判据：什么文件算输入边**：① 文件级清单见附录甲 C-4（全部在 `server-plugin/input/` 一个目录下；`extension/input-view.mjs` **拆两份**：DOM 挂载部分留 extension 属 display 组，"规范化 + 查表 → 代号"部分迁入 `server-plugin/input/input-view.mjs` 属 inputEdge——卷二 §2.7、§6.11 迁移行），全部登记在 `state-owners.json → inputEdge.modules`，`outputSchema: schema:input-edge-v1`，文件数 ≤ 8（E-GROUP-SIZE），增项须李白批；六组（含 kernel）文件级不相交（E-GROUP-OVERLAP）；② 依赖约束——只许 import 语言包读取器、动作目录投影、候选集投影、`primitive-schema`；**不得 import 任何第〇至第六层的状态读取**；③ 输入只能是玩家文字或模型文字，输出只能是封闭 schema；④ **不被任何规则直接依赖**（规则层 import 输入边 = E-VIEW-INPUT-IMPORT，卷二 S16）。凡处理世界状态、或其结果被规则当文字用的模块，**不得靠划入输入边消账**，必须改读代号。

**注入防线**（L-13）：玩家文字进入模型前的隔离与剥离（分隔符、角色标记、工具调用指令的剥离）在输入边 / AI 边完成，随输入边拔除而不再需要。

**AI-R1 的输出**同受约束：每个 id 来自候选集，否则 `menu_fallback`；有歧义时 AI 输出 `ambiguous` 代号，引擎退回菜单；AI 不可用（无密钥、断网、超时）→ `menu_fallback`。

**验收**：V-23（输入边扫描）、V-26（输入边承诺的性质测试）。

### R-2 程序不读任何自然语言，只读数值维度和固定代号（含李白 11-13 裁定）

3. 所有前置失败带 `code`（`E-*`），调用方只比较 `error.code`。
4. 内容校验工具比对结构化字段，不从正文抽数字、时长、工序判断对错（08 §三 例 10）。
5. **现有 74 行解析的处置**（06b 待定 1）：三条出路——(a) **删除**：凡用正则 / 关键词 / 模糊匹配理解玩家文字的（action-router、action-constructor、retrieval-lexicon、action-time 的时间词表等），因输入边禁正则（第 6 条），**不得移入输入边，只能删除**，T0 由菜单承接，有 AI 时由 AI-R1 承接；(b) **改读代号**：凡处理世界状态或结果被规则使用的（scene-card 按问话选段、population 核对人物档、high-nobility:48 官职中文名、npc-memory、education、activities、consistency-evidence），改读代号与数值；(c) **移入输入边**：仅"整串精确查表"可以。consistency-review 解析模型叙述的 44 行改为：**要求 AI 直接输出固定代号格式的结构化声明**（付款额、次数、成败、实体 id、方位代号，schema 封闭），规则层只校验代号是否在合法集合内、数值是否与已结算回执逐字段相等。卷零逐处标这 74 行的去向；V-2 对它们**单列追踪**（§6.3 基线元组分量 `L74`），不得因移入输入边从分母消失。

### 3.1 扫描的最低技术要求（卷十二实现，不可降的底线）

1. **代号的合格判据（上下文白名单，按被比较维度的词表族；李白裁定，卷二 S13 (a)、A16 为可验收口径）**：规则层使用代号的**唯一合法形式**是加载期从 `_vocab.json` / 维度表生成的冻结句柄 `V.<family>.<id>`（如 `V.sfam.sfam_sleep`）与 `E.<code>`；句柄对象带 `family`。扫描器对 `===/!==/includes/switch/对象键查找` 的两侧做**类型归因**：一侧是 `dim()/modified()/View.dims` 返回的 Fact（声明类型 `enum <family>` 或 `ref vocab <family>`）、`state-owners.json` 登记的状态路径、`error.code`、`event.verb`、原语 `op`、持有 / 义务 `kind` 等有声明类型的来源，另一侧必须是**同族**句柄，否则 E-VIEW-FAMILY-MISMATCH；**任何裸字符串字面量参与比较一律计入**（卷二 S13 ④），不论它是否恰好是某个登记代号（`'sleep'`、`'sfam_sleep'` 都报）；**左侧解析不出所属维度的比较，一律违例**。**不使用全局平铺名单**：卷二第三版的 `scan-allowlist.json` 已被句柄机制取代。代号格式正则（卷二 §1.9）本身只许出现在 `dimensions-validate.mjs`、`vocab-load.mjs`、`seed-keys.mjs` 三个文件（卷二 S13 (b)）。JS 语言记号（`typeof` 结果、编码名、`JSON`/`Date` 格式名）由卷十二登记为封闭小表。
   - **正例**（卷二 A16）：`if (st.dims.family.value === V.sfam.sfam_sleep)`（`st.dims.family` 声明为 `enum sfam`，句柄同族）合格；`if (err.code === E.E_ROUTE_SEASON_CLOSED)` 合格；`switch (event.verb) { case V.verb.transfer: … }` 合格。
   - **反例**：`if (st.family === 'sleep')`、`x === 'sfam_sleep'`（裸字面量，S13 ④）违例；`['sleep','dead'].includes(x)` 违例；`x === V.terrain.terrain_hill` 而 `x` 声明为 `sfam` → E-VIEW-FAMILY-MISMATCH；`text.includes('sleep')`（左侧是文字）违例；`kind === V.kind.npc` 若 `kind` 来自 `id.startsWith('npc_')` 违例（E-VIEW-ID-PARSE）；中文字面量永远违例。
2. **类型感知，而非纯 AST**（卷二 §2.8、附录 F #11）：扫描器 = `tsc --checkJs`（品牌类型 JSDoc）+ typescript-eslint 类型感知规则；判定依据是表达式的**静态类型与节点位置**，不是方法名清单；无类型标注、解构丢失类型、跨函数传参后无法归因的值一律按 string 处理并报 E-VIEW-FAMILY-UNRESOLVED（宁可误报不放过）；品牌值只能由 kernel 组构造（E-KERNEL-ONLY）。绕法用例集归卷十二。
3. **显示字段按 schema 路径判定，不按全局字段名**：`state-owners.json` 的 `display` 集合（现行只有 `displayNames.*.text`；`npcs` 的 display 为空，`nameParts` 是代号数据进哈希——附录甲 C-6）与维度表 string 类型字段路径 `<kind>.<field>`（卷二 §1.5 E-DIM-STRING-NOT-DISPLAY），是"显示字"的唯一来源（卷二 §2.4、§6.11）。读到这些路径即 E-VIEW-DISPLAY-READ。本卷 §4.4 只列路径族与原则，不列全局名；`engine.rules`、修正项的 `source`、常数条目的 `basis` 都不在显示路径里，不受影响。
4. **数据引用不误报**：对 `world/` JSON 的读取不算字面量；只统计代码。
5. **口径明文**：注释、`console.*` 日志、`throw Error(文案)` 的文案（code 必须另带）、tests/ 夹具不是代码判断，不计；它们不是"豁免"，是判定对象之外。
6. **输出逐行清单**：文件、行、节点类型、所属类（A–F / 实例 / 直写 / 常数 / 语言判断 / 显示路径读 / id 反推），供基线比对与"只降"判定。
7. **进 CORE**：任一分量高于上次合入即失败（I43）；不是 `k8-guard` 式只报不拦。
8. **排除清单核对**：§3.2 五组成员清单来自数据文件，每组有自己的扫描条；成员数量受控，增项须李白批。

### 4.4 维度类型与显示字段（原则；清单由数据声明）

- **维度类型**：以卷二 §1.5 为唯一定义——**封闭集合 14 种**（number、integer、boolean、string、enum、ref、union、set、map、list、struct、curve、distribution、rx；扩展须改卷二并报李白）。本卷早先的"code"即 enum，"vector"即 `list<number>` 带 `length`；`string` 类型字段即显示字段。卷一不另列类型表。
- **显示字段**：由数据声明，不是手写名单（卷二 §2.4）。两个来源：① `state-owners.json → stateKeys[*].display` 的状态路径集合——卷二现行只登记 `displayNames.*.text`；`npcs` 的 display 为空（拼好的名字是投影层产物，不在 state；`nameParts` 是代号数据，进哈希），本卷不另枚举，其余由领域卷按卷二登记；② 维度表里类型为 string 的显示字段路径 `<kind>.<field>`（卷二 §6.11 迁出清单：目录 `name/purpose/description`、ontology `label`、professions `aliases`、material-props `appearance[].term`、`sources[].name/citation`）；**偏离行 `state.created[*].props` 内的 string 维度一律视为显示字段并进哈希排除**。
- **待退役的文字字段**（按路径族列，卷二 §6.11 与卷零逐处处置；在此之前规则层读它们计入基线）：`buildings.*.purpose`、`npcs.*.activity`（文字值）、`locations.*.terrain / climate / industry`（文字值）、`npcs.*.occupation / personality`（散文）、`settlements.*.polity`（名称）、`offices.*.title`、`records.*.content / reason`、`args.contextReason`、`orgs.*.rules`（章程文字）、`error.message`、模型叙述正文。

### 8.3 规则可读状态哈希（V-4、I40 的字段集合）

- **算法**：`storage.mjs:14 digest()` 作用于排除后的文档；排除口径是 `world/rules/tables/digest-exclude.json`（digest-exclude.mjs 校验）。
- **排除集合的机器口径（卷二 §2.7）**：`digest-exclude.json` 五层中，**`names` 与 `narration` 两层由 `state-owners.json` 的 `display` 字段集合与 `textPaths` 生成**（现行 `displayNames.*.text`、`narration.*`、`records.*.text`，加 §4.4 的偏离行 string 维度；**`created.*.props.basis` 是 `struct:basis`（代号 + 种子键 + 写者），由 kernel 直写，不在 textPaths，留在哈希内**，卷二 §2.7）；`labels`、`provenance`、`clientPrefs` 三层不对应状态路径，**手写登记**；两部分合并成入库的 `digest-exclude.json`。**生成与核对**：生成器在 CI 重新生成并与入库文件 diff，不一致即 E-DIGEST-EXCLUDE-DRIFT（卷二 §4.3）；I40 的"相等"断言指此 diff，不是自证。
- **排除层**：`narration`（AI 文字及其指纹、模型标识）、`names`（display 集合：玩家命名文字、偏离行 string 维度）、`labels`（语言包快照与运行期拼装的名字字串缓存）、`provenance`（润色来源、素材键、语言包版本、两道闸判定）、`clientPrefs`（aiProfile、语言、界面偏好）。
- **名字的两种归属**：见附录甲 C-6（`nameParts` 进哈希；`displayNames` 不进哈希；`npcs.*.name` 已删除）。V-4 在两语言下玩家命名不同亦可比。
- **保留在哈希内**：state 中非 display 的数值与代号字段、holdings、ledger、事件日志（含 rollKey）、`nameParts` 成分代号、`origin`。
- **I40 补充**：id 生成、排序、分组不以显示字为输入；`sort()` 比较键必须是 id 或数值。名字归属的唯一写全处是附录甲 C-6。

### 8.4 历法与语言不进时钟；8.5 每个世界保存自己的数据副本
时钟只认分钟，月、年、节日、年号是按法域历法的投影，语言是显示层偏好，改语言不改任何事件；每个世界保存自己的数据副本（DF 01 §8.1 第 10 条），不做版本迁移（R-8）。
