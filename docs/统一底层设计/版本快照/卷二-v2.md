## 读法

- 本卷是全部领域卷（卷三至卷二十九）的**格式母本**：维度表怎样写、怎样读、怎样校验、修正值怎样叠加、随机实例怎样生成。各卷只在本卷的格式里填自己的维度与规则，不另起格式。
- "维度"= 一个有固定代号、单位、取值域的可比较量；"维度表"= 一类实体全部维度的定义加类别行与实例行；"入口"= 读取某类实体任一维度的唯一函数；"修正键"= 可被外力改动的维度。
- 锚点写法沿用 10：`DF 01 §2.1`、`CDDA 02 §7`、`RW 03 §3.2`、`EVE 04 §2.4`、`CK3 05 §2.8`；仓库代码写 `文件:行`；审查意见写 `A-M1`（审查 A 必改 1）、`B-二.3`（审查 B 第二节第 3 条）。
- 规矩三档：**必须**（校验器硬拦或门禁阻断）、**应当**（扫描告警、基线只降）、**可以**（建议）。未标注的句子一律"必须"。
- 本卷所辖子系统（对卷零对照表）：维度表加载与取值、extends 展平、随机实例化、派生与聚合、修正求值、校验器、入口与缓存、写者声明、显示名隔离与输入边。
- 与卷一：卷一定六层（本体→维度→规则→原语→投影→显示）与四条规矩，本卷落实第二层与二、三层之间的读取契约。与卷十二：本卷 §7 的断言由卷十二机器化。

## 〇 本卷的八个结论（先看）

1. **一种文件格式服务全部实体类**：`world/ontology/dimensions/<kind>.json`，表头声明维度（单位、取值域、缺失处置 `onUnknown`、可否修正、是否可随机），表体是类别行与实例行。取值顺序固定：实例覆盖 > 已展平的类别行（按 precedence 从具体到一般）> 派生公式 > 采样 > 未知；**代码里没有默认值**，缺失怎样处理由表头 `onUnknown` 声明（A-M4）。
2. **代号全 ASCII、显示名全在显示层**：实体 id 与枚举值 `^[a-z][a-z0-9_]*$`，维度键 lowerCamel；静态显示名在 `world/i18n/labels.<lang>.json`，生成名只存 `nameParts`，玩家命名只存 `state.displayNames`（display-only）；**规则层一行都不读任何语言**，输入边只做"文字→封闭代号集合"，翻不出就退回菜单（李白裁定）。
3. **22 类实体各一个入口**，签名 `xxxView(engine,state,id,options?)`，返回 `fact` 形状；入口**纯读**（采样是纯函数，不写回）；依赖声明 `declareViewInputs(name,{own,uses})`，最终依赖由注册表对 `uses` 做传递闭包生成并冻结，不手写并集（A-M1）。
4. **修正键 = 注册开放枚举**：集合开放于数据（`modifiable:true` 的 number/integer 维度即修正键），封闭于代码（代码不得出现键字面量，校验器拒绝未注册键）；运算 `add/mul/max/min/set` 与作用域封闭。
5. **求值管线定点、确定**：基值 → add → mul（叠加惩罚查**预算好的定点系数表**，n 从 0 起，不用浮点 exp）→ max → min → set → post 曲线 → clamp → 取整；全序键 `(priority 降序, |value| 降序, source, id)`（A-M2）。
6. **派生有封闭的聚合原语**（加权和、exists、count、最近祖先、众数、按键取值），派生依赖图做环检测；派生变量一律读基值（A-M3）。
7. **校验器 L0–L4 硬拦、L5 报告**，错误码 `E-DIM/E-MOD/E-VIEW-*` 一种格式；首期实现 L0–L3 与三条关键不变量，其余"应当"（B-五.1）；量纲推导降为可选（B-五.2）。
8. **迁移先补维度再改读者**：physicalMetal 的名称字词匹配**删除不搬**；物品→材料映射由离线脚本一次产出、人工核对后写成显式数据（A-M7）。

```json

 "kind": "material", "namespace": "core", "version": 1,
 "entity": {"idPrefix": "mat_", "classPrefix": "class_",
            "instanceTable": "world/meta/mechanics/items.json#/<item_id>/props"},

  "heatValue": {"type":"number","unit":"MJ_per_kg_dry","domain":[0,60],"precision":2,

                "sample":null,"source":"DF 01 §2.1；CDDA 02 §3.1 fuel_data","owner":"卷三 §11"},
  "density":   {"type":"number","unit":"kg_per_L","domain":[0.01,25],"precision":3,
                "required":"always","onUnknown":"error","modifiable":false},
  "volumeL":   {"type":"number","unit":"L","domain":[0,100000],"precision":3,
                "derived":"massKg / density","required":"never","onUnknown":"gap","modifiable":false},
  "sphere":    {"type":"set","of":{"ref":"vocab:sphere"},"domain":{"maxSize":3},"required":"never","onUnknown":"skip"}

                      "physical": ["class_timber","class_wood","class_wax","class_leather","…"]},

 "classes": {"…":"类别行，见 1.3"},

}
```

| 字段 | 必须 | 含义 | 校验 |
|---|---|---|---|
| `kind/namespace/version` | 是 | 实体类代号（22 之一，与文件名一致）；`core` 或扩展包名（扩展包只加行、加维度，不改 core 维度定义）；整数版本，只认当前版（no-old-save-compat） | E-DIM-SCHEMA-KIND / -NAMESPACE / -VERSION |
| `entity.idPrefix` | 是 | 实例 id 前缀（可为集合，如 person 的 `["npc_","creature_"]` 加显式 `"player"`）；`classPrefix` 类别行前缀；`instanceTable` 实例偏离行所在（JSON 指针模板） | E-DIM-ID-FORMAT |
| `dimensions.<key>.type` | 是 | `number / integer / boolean / enum / ref / set / map / curve / distribution / rx`（§1.5） | E-DIM-SCHEMA-TYPE |
| `.unit` | number/integer 必须 | `_units.json` 中的 id；只查存在性（量纲推导为可选，§1.4） | E-DIM-UNIT-UNKNOWN |
| `.precision` | number 必须 | 小数位数；取值、采样、求值结果都按它舍入（定点，§3.3） | E-DIM-SCHEMA-PRECISION |
| `.domain` | 是 | 取值域（§1.5） | E-DIM-DOMAIN-* |
| `.required` | 是 | `always / never / byClass:<class> / ifPresent:<dim>`（§1.6；组件即类别，故无单独 byComponent） | E-DIM-REQUIRED-MISSING |
| `.onUnknown` | 是 | `skip / gap / error`：非必填维度缺失时**消费者唯一允许的处理**（§1.6） | E-DIM-ONUNKNOWN-MISSING |
| `.derived` | 可选 | 派生公式（RX + §1.12 聚合原语）；有则不得手填，不得同时有 `sample` | E-DIM-DERIVED-WRITTEN / -VAR / -CYCLE / E-DIM-SAMPLE-DERIVED |
| `.modifiable` | 是 | 是否为修正键；只允许 number/integer（map 的值为 number 时可按子键寻址，§3.2） | E-DIM-MODIFIABLE-TYPE |
| `.stacking / .bounds` | modifiable 时必须 | `none / penalized`；修正后钳位区间 | E-MOD-STACKING / -BOUNDS |
| `.sample` | 可选 | 缺省分布（§1.10）；只对 `required:never` 且无 `derived` 的维度 | E-DIM-SAMPLE-* |
| `.ordered` | enum 可选 | 有序枚举（允许 max/min/±1 运算，如 necessityTier） | E-DIM-DOMAIN-ENUM |
| `.source / .owner` | 是 | 设计出处；细化卷与 § | W-DIM-SOURCE |
| `instanceDimensions` | 可选 | 只在实例上存在的维度（品质档、耐久、作者、附魔槽…），格式同 `dimensions` | 同上 |
| `precedenceGroups` | 有类别行时必须 | 一组或多组全序；`default` 必有 | E-DIM-PRECEDENCE-* |
| `precedenceOf` | 多组时必须 | 维度 → 组名（未列的用 default）；material-props 现有三段 precedence 由此表达（§6.2） | E-DIM-PRECEDENCE-GROUP |

### 1.3 行：类别行、实例行、extends 与 precedence 的求值顺序

**两种行。**
- **类别行**（`classes.<class_id>`）：按类写，不针对实例。类别键必须在 `_vocab.json` 登记为标签族 `class`（含组件类，§1.8）；未登记即 E-DIM-CLASS-UNKNOWN。
- **实例行**：某实体的个别偏离，在 `instanceTable` 指向的位置，或表 `generated` 节 / 存档 `state.created`；每条带 `basis` 与（真实量时）`sources`（E-DIM-INSTANCE-BASIS）。

**成员关系只有一种来源**（A-M5）：实例自己声明 `classes`（含组件类）与 `tags`；类别行**不**列 members。material-props 的 `memberItems` 改名 `memberLinks`，只用于成员偏差检查（§1.7），不参与成员判定。`tags` 沿 `_vocab.json` 的 `broader` 上位链展开后参与 `memberOf`。

**第一步：加载期把 extends 展平成"有效行"**（A-M5、B-一.1）：
- `extends` 目标必须是同表类别行且为 `abstract:true` 或出现在同一 precedence 组（E-DIM-EXTENDS-TARGET）；链深 ≤4、无环（E-DIM-CYCLE）。
- 展平规则：标量维度子覆盖父；set/map 维度默认整值替换，子行可改用 `<dim>+:[…]`（extend，并入）与 `<dim>-:[…]`（remove，剔除）（B-一.3；CDDA extend/delete）；同一维同时写整值与 +/− 即 E-DIM-EXTEND-CONFLICT。
- 展平后 `extends` 字段消失；`abstract` 行丢弃，不进 precedence 匹配（引用了 abstract 的 precedence 即 E-DIM-ABSTRACT-IN-PRECEDENCE）。

**第二步：取值**（唯一算法，所有表相同）：
```
value(kind, id, dim):
  own = instanceRow(id)[dim];            if own != undefined → own (source=instance)
  group = precedenceOf[dim] ?? 'default'
  chain = precedenceGroups[group].filter(c => memberOf(id,c) && flat[c] exists)
  for c in chain:  v = rowValue(flat[c], dim)   # 直接写了，或由行内 sources 推出
                   if v != undefined → v (source=class c)
  if dimensions[dim].derived → evalDerived(id, dim)  # §1.12；依赖未知则未知
  if dimensions[dim].sample  → sample(id, dim)       # §1.10 纯函数
  → {known:false}                                    # 按 onUnknown 处置
```
- 多类别冲突取 precedence 更前者，不求平均、不取最大；两个互不相含的类别同时命中同一维且值不同时，校验器报 W-DIM-PRECEDENCE-TIE（B-一.2）。
- **precedence 是每组一个全局全序**，表达不了"A 在此维更具体、在彼维更一般"；需要时开新组（`precedenceGroups`），不改算法（B-一.2 明示限制）。
- precedence 的默认顺序由标签 `broader` 的深度派生（深者先）；手写顺序只在同深度打破平局；校验器检查手写顺序与 broader 深度不矛盾（E-DIM-PRECEDENCE-BROADER）。

**三层展平与取值轨迹示例**（附录 A 的表）：`class_workshop_hot extends class_workshop extends class_public_building`。展平：workshop_hot 的有效行 = public_building{public:true,lodging:false,allowedMaterials:[woody,stony],wearPerDay:0.0003} ← workshop{public:false,capacityBase:2} ← workshop_hot{fixtures:[forge,hearth],allowedMaterials:[stony],upkeepPerDay:{class_fuel:12}} = {public:false,lodging:false,allowedMaterials:[stony],wearPerDay:0.0003,capacityBase:2,fixtures:[…],upkeepPerDay:{…}}。实例 `bld_hw_forge` 的 classes=[class_workshop_hot]，props{capacityBase:3}。取 `capacityBase`：实例 3（source=instance）。取 `wearPerDay`：实例无 → precedence default 中命中 class_workshop_hot 的有效行 → 0.0003（source=class_workshop_hot，经展平来自 public_building）。取 `allowedMaterials`：有效行 [stony]（子整值替换）。若子行写 `allowedMaterials+:[matcat_earthen]` 则得 [woody,stony,earthen]。

**覆盖顺序总表（高→低）**：存档 `state.created` 偏离行 > 作者实例行 > 表 `generated` 节 > 展平后的类别行（按组内 precedence）> 派生 > 采样 > 未知。扩展包不得改写 core 类别行的值（E-DIM-NAMESPACE-OVERRIDE）。

**分类机制判定表**（B-五.4，六套收敛为四套；`components` 字段废除，组件即类别）：

| 要表达 | 用 | 不用 |
|---|---|---|
| 实体"属于哪类"，决定取哪些类别行与必填 | `classes`（含组件类 `comp_*`） | tags |
| 跨实体类的主题/关系标签（领域、风味、批次） | `tags`（族由 `_vocab.json` 定，`sphere` 是其中一族） | classes |
| 一个类别行想复用另一行的数据 | `extends`（只在类别行之间） | 在实例上写 extends |
| 两个类别都命中时谁赢 | `precedenceGroups`（默认由 broader 深度派生） | 在代码里比较 |

### 1.4 单位

- `_units.json` 封闭；每条 `{id, dimension, si, calibrate?}`。首批单位同第一版（kg、L、m、kg_per_L、MJ_per_kg_dry、satiety_per_kg_dry、fraction、percent、score、axis、count、day、minute、year、celsius、copper、per_day、per_year、kg_per_day、m_per_minute）；`satiety_per_kg_dry`、`copper`、`score`、`axis` 标 `calibrate:true`（世界内量表）。
- **必须**：维度 `unit` 存在于词表（E-DIM-UNIT-UNKNOWN）。**可以**：对 `derived` 公式做量纲签名比对（W-DIM-UNIT-DIM，首期不实现；B-五.2、A"其余"）。
- 存储值一律 SI 口径；出处原值可用出处单位但须在表头 `sourceUnits` 登记换算。无量纲系数一律是带名字的规则表常数。

### 1.5 取值域

| type | domain 写法 | 说明 |
|---|---|---|
| `number` / `integer` | `[min,max]`（`null` 为无界） | 与 `precision` 配合 |
| `boolean` | 无 | |
| `enum` | `{"vocab":"<family>"}`；可 `ordered:true` | 值全是 ASCII 代号；维度名不得当枚举值（见 `substituteKey`） |
| `ref` | `{"kind":"<entity kind>"}` / `{"vocab":"<family>"}` / `{"dim":"<kind>"}` | 第三种引用某表的维度键（如 `substituteKey` 引 `item` 表的 number 维度），校验器检查存在且类型为 number（E-DIM-REF-DIM） |
| `set` | `{"of":<type>,"maxSize":n}` | 存储为排序数组；显式 `[]` = 确知为空，缺字段 = 未知（A-M4） |
| `map` | `{"key":<ref/enum>,"value":<type>}` | 如 `{material:portion}`、`{season:factor}` |
| `curve` | `{"x":<unit>,"y":<unit>,"points":[[x,y]…],"monotone":bool}` | 分段线性 |
| `distribution` | §1.10 | |
| `rx` | `{"schema":{…}}` | 受限表达式 compileRX |

- 季节、四档、七档一律是词表族（`season_spring…`、`tier_none<tier_discomfort<tier_health<tier_lethal` ordered），不写 `array[4]`（A"取值域"）。

### 1.6 缺省与缺失处置（A-M4）

- 表头 `default` 字段取消（第一版的 `none/empty/derive` 已被 `derived`、set 的显式 `[]`、`onUnknown` 覆盖）。**任何常量缺省都不合法**，无论在表头还是代码。
- `required` 决定缺失是否为加载错误：`always`（E-DIM-REQUIRED-MISSING）、`byClass:<class>`（属该类别/组件时必填）、`ifPresent:<dim>`、`never`。
- `onUnknown` 是**数据声明的唯一处置**，消费者只能照做：
  - `skip`：该实体在依赖此维度的规则里**不参与**（如无 `sphere` 的神不进领域匹配）；
  - `gap`：规则照常运行但把缺口记进 L5 齐全率与 `state.gaps`（卷十二读），不改变行为（如无 `fragility` 的货不计易碎损耗，且被记为缺口）；
  - `error`：读到即抛（用于一旦缺就不该到运行期的量）。
- 规则层读到 `known:false` 却未按 `onUnknown` 分支（自行补常数、自行"当作 0"）即 E-VIEW-FALLBACK（卷十二扫描 `??`、`|| 常量` 作用于 Fact.value）。
- 由此，第一版 §6.1 的"无来源 = buy_only"、`categoryKind` 的 `other` 兜底桶**废除**：推不出的物品必须显式写 `sourceMode:"buy_only"` / `categoryKind:"non_economic"` 并带 basis；规则表 `rules.items.categoryRules` 只含正向推导，没有兜底项。
- 规则表里的数值一律称"标定值"并带出处，不称"缺省"（如 `rules.modifiers.stackingTable`）。

### 1.7 出处与标定

同第一版：类别行与实例行带 `basis`；number 维度优先由 `sources[]` 推出（deriveFromSources 推广），推出值与直写值并存必须相等（E-DIM-SOURCE-MISMATCH）；成员偏差超过 `memberDeviationThreshold` 的成员须有实例行（E-DIM-MEMBER-DEVIATION，成员链接读 `memberLinks`）；真实量须 `citation`；世界内量表 `calibrate:true`；`status: verified/approximate/placeholder`，placeholder 进 world/ 即 E-DIM-SOURCE-PLACEHOLDER；verified-sources.json 冻结规则对所有表生效。`sources[].name`、`citation` 是文档性字串，不被规则读；校验器按字段集合排除它们（§2.4）。

### 1.8 组件 = 带 requires/enables 的类别

- 组件（RW Comp、CDDA subtypes）不再是独立字段：`_vocab.json` 的 `class` 族条目若带 `requires`（本表维度列表）与 `enables`（规则族列表）即为组件类，id 前缀 `comp_`。实体把它写进 `classes`。
- `required:byClass:comp_x` 由此与组件 requires 等价；校验器检查 `requires` 中的维度存在于该表（E-DIM-COMPONENT-REQUIRES），`enables` 中的规则族已注册（E-DIM-COMPONENT-ENABLES），`conflicts` 不同挂（E-DIM-COMPONENT-CONFLICT）。
- 规则层按组件类遍历（"所有 comp_rottable 的实体每日按 rotRate 腐坏"），不按实体类或 id。
- 首批组件类：`comp_burnable, comp_edible, comp_drinkable, comp_rottable, comp_wearable, comp_container, comp_tool, comp_weapon, comp_readable, comp_durable, comp_consumable, comp_raw_material, comp_crafted（实例有品质档）, comp_work（作品：author, contentRef, beauty）, comp_relic（文物：rarity, slots, enchantments）, comp_vehicle（载具：loadKg, speedBase, parts, fuelClass）, comp_livestock, comp_sapient, comp_settlement, comp_region（政区）, comp_facility（建筑实例）, comp_jurisdiction`（B-四.5/6）。

### 1.9 代号、显示名与语言边界

**代号**（A-M6 拆两条正则）：
- 实体 id、类别 id、枚举值：`^[a-z][a-z0-9_]*$`，2–48 字符；维度键：`^[a-z][a-zA-Z0-9]*$`（lowerCamel）。
- 前缀表由各表头 `idPrefix` 与 `_vocab.json` 各族 `prefix` 声明；首批：`item_ mat_ species_ plant_ body_ npc_ creature_ loc_ bld_ fac_ recipe_ org_ office_ polity_ law_ deity_ faith_ culture_ profession_ skill_ know_ offense_ status_ evt_`；词表 `class_ comp_ terrain_ biome_ sphere_ ability_ layer_ matcat_ fixture_ season_ tier_ service_ damage_ taxon_ tissue_ sense_ attr_ pers_ value_ ethic_ doctrine_ tenet_ tradition_ power_ labor_`。
- **kind 只能由 idPrefix 反查**（`kindOf(id)` 读表头前缀表）；代码里 `startsWith('bld_')` 之类（derived.mjs:107）即 E-VIEW-ID-PARSE。`player` 是 person 表的显式无前缀实例；`faction_*` → `org_*`，`monster_*` → `species_*`，`profession_life_N` → `profession_<domain>_<role>`，加载器拒绝旧名。
- 代号不编码语义以外内容（序号、地区、语言、版本）。

**静态显示名**：`world/i18n/labels.<lang>.json` 以 id 为键，多形态 `{label, short, adj, plural…}`，形态可按语言增减。ontology 现有 `label` 字段、professions 的 `aliases`、物品/地点/物种目录的 `name/purpose/description`、material-props 的 `appearance[].term`、`sources[].name/citation` 等全部属显示或文档字段，迁出或标记（§6.11）。

**生成名**（A-M6.1）：程序生成的人名、地名、物品名**不存字符串**，实体存 `nameParts:{bank:ref vocab namebank, pattern:ref, parts:[{slot, wordId}], seq}`；显示名由投影层按当前语言用 labels 词库拼装，中英切换时随之切换；重名判断、按名查人等一律比较 `nameParts` 或 id，不比较拼出的字串。

**玩家命名**（A-M6.2）：店铺、船、组织、自创物的自由命名存 `state.displayNames[id] = {text, lang}`；在 `state-owners.json` 标 `display:true`，规则层禁读（E-VIEW-DISPLAY-READ）；唯一写者 display-names.mjs；它不是代号，不参与任何判断。

**语言边界（李白【11-13】裁定，本卷落实处）**：
1. 规则层（含 consistency-review）**一行都不读任何语言**：规则、原语、入口、校验器不读 labels、displayNames、nameParts 拼装结果、任何 `display:true` 字段；AI 叙述解析改为要求 AI 输出固定代号格式的结构化结果，规则只校验代号合法。
2. **输入边**只做"文字 → 封闭代号集合"：输出必须是动作目录（卷九）中的动作代号加参数代号；翻不出或有歧义就**退回菜单**让玩家选，不猜、不填默认值。
3. 默认不开 AI 时只走菜单与结构化代号；语言包只做菜单项显示名的**整串精确对应**（玩家输入与某菜单项显示名完全相等才算），禁止关键词、正则、从整句猜意图。自由打字的理解只在玩家自己开 AI 时由 AI 承担。
4. 输入边可整体拔掉，拔掉后靠菜单仍可完整游玩；中英两份对等。
5. 入口的反查接口 `lookupByLabel(lang, text)` 只在 projection/input 目录存在，内部是精确等于比较，返回代号或 `null`；引擎目录 import labels 即 E-VIEW-LABEL-READ（S7）。
6. 卷零对照表为现有 74 行语言解析逐处标处置（移出 / 改代号 / 删除）；卷十二扫描：规则目录内出现文字匹配、正则或中英字面量参与判断即不通过。

### 1.10 随机实例化（B-三）

**分布对象**：同第一版（normal、lognormal、uniform、triangular、categorical、curve、joint、ref）。**首批实现** `uniform/normal/lognormal/triangular/categorical/curve`；`joint` 只定格式，由卷二十六实现（B-五.5）。`categorical.weights` 和为 0 即 E-DIM-SAMPLE-WEIGHTS；`clamp` ⊂ domain（E-DIM-SAMPLE-DOMAIN）。

**种子键**（A"其他"、B-三.1/3）：
- 单维：`seedKey = sha256(utf8(template.seed + "|" + kind + "|" + instanceId + "|" + dimension))`；`joint`：`dimension` 换成**组 id**（`joint:<groupId>`），一次抽出整个向量再分发到各维（相关性不丢）。各部件都是 ASCII 且不含 `|`（由 id 规范保证），编码无歧义。
- `instanceId` 本身必须确定性导出（坐标、父 id、序号），由卷十规定并在 seed-keys.json 登记 role `id`；本卷只约束"种子键的任何部件不得来自 AI 输出或 Math.random"。
- 登记：`dimension-sample.mjs` 的键进 seed-keys.json（role `seed`），受 E-SEED-KEY 双向比对。

**自带 PRNG 与精度**（B-三.2）：
- 均匀数：取 seedKey 前 16 个十六进制字符为 64 位整数 u，`U = u / 2^64`；需要多个均匀数时用计数器 `sha256(seedKey + "|" + i)`。
- 超越函数不用 `Math.exp/log/cos`：normal 用 Wichura AS241 有理逼近（纯加乘除，定点可实现）或预算好的分位数表（4096 点线性插值，写进 `_distributions.json`，首批采用后者）；lognormal = exp(normal) 同样查表；结果按维度 `precision` 舍入为定点。跨机（本机与腾讯云）逐位一致由此保证。
- 采样是**纯函数** `sample(engine, kind, id, dim) → value`，不写状态（消除第一版 §2.2 与 §1.10 的矛盾，B-三.5）。

**只存偏离值**（B-三.4）：
- 采样值不写回；每次读取重算（有 WeakMap 记忆）。只有当实例**偏离**采样值（受伤、成长、玩家改造）时，由对应的声明写者把新值写进 `state.created[id].props[dim]`（成为实例行，覆盖采样）。存档大小随偏离而非随探索增长；stateMemo 不会在读路径被写入失效。
- `sample` 只对"实例无值、类别行无值、无 derived"的维度生效，故类别行有值时不采样。

**生成不写任何显示文本**；名字只写 `nameParts`（§1.9）。

### 1.11 状态容器与受控词表（格式；内容归卷二十一、卷七）

状态容器 `status.json` 的行格式同第一版（family、target、bodyPart、contagion、severity、immunity、stages[]{minSeverity, modifiers[], lifeThreatening}、tendable、sources、duration）；每档 `modifiers[]` 的 `target` 必须是注册修正键，**能力类目标写 `body.<capability>`**（§3.6）。运行态实例存 `state.statuses`，唯一写者 status.mjs。

受控词表 `_vocab.json`：每族 `{closed, prefix, fields?:{…schema…}, entries}`；**条目可带字段**（B-四.11）：`ability` 族条目 `{levels}`、`damage` 族 `{armorStat}`、`season` 族 `{order}`、`language` 族 `{family}`、`class` 族 `{broader, requires, enables, conflicts}`；字段 schema 由族声明，校验器据此检查（E-DIM-VOCAB-FIELD）。领域族 `sphere` 带父子/友好/不相容四表。`closed:true` 的族只 core 可改（terrain、component、operator、scope、stage、season）。

### 1.12 派生与聚合原语（A-M3）

`derived` 公式 = RX 表达式 + 封闭的聚合原语集合（`_vocab.json` `aggregate` 族，closed）：

| 原语 | 签名 | 用途 |
|---|---|---|
| `wsum(map, otherKind, dim)` | Σ portion × dim(otherKind, key) | 物品密度 = wsum(material, 'material', 'density') |
| `exists(relation, filter?)` | 关系（配方产出此物、资源场含此物、据点资源、畜产）是否存在 | sourceMode |
| `count(relation, filter?)` | 关系计数 | 下游需求加权引用 |
| `nearest(tree, dim)` | 沿包含树向上取最近有值祖先 | lawCode、annualMeanTempC 继承 |
| `mode(relation, dim)` | 关系对象中该维众数 | place.culture = 居民多数 |
| `maxOf/minOf(relation, dim)` | 关系对象中最大/最小 | necessityTier 链式继承 = maxOf(downstreamRecipes, tier) − 1 |
| `lookup(curve, x)` | 查曲线 | 年龄体型 |
| `rank(enumValue, ±k)` | 有序枚举位移 | tier − 1 |

- 关系（`relation`）来自持有表、包含树、配方表的输入/输出索引、资源场登记，在 `_vocab.json` `relation` 族（closed）登记，每条写明读哪些状态键，供依赖闭包（§2.3）使用。
- **派生变量一律读基值**（§1.3 的 value，不含修正）；修正只施于最终被读的维度。因此 `volumeL` 被修正时，依赖它的 `sizeClass` 看到的仍是未修正体积——这是本卷明示的限制；需要"修正后再派生"的量，用修正项直接挂在下游维度上。
- **派生依赖图环检测**：加载期对所有表的 `derived` 公式建图（含跨表 wsum/relation 边），有环即 E-DIM-DERIVED-CYCLE（L2）；`valueBase` 由配方成本推时（卷六）同样进此图，配方互为原料的环由此暴露，卷六须用"基础材料外生"打破。
- 公式引用的变量必须是本表维度或原语参数指向的他表维度（E-DIM-DERIVED-VAR）。
- 派生结果也按 `precision` 定点舍入。

### 2.2 签名与返回形状

```js
export function itemView(engine, state, id, options = {}) → View | null
Fact = {known, value, base?, unit?, source, current, chain?}
View = {kind, id, dims:{<dimension>: Fact}, …派生字段(Fact)}
```
- `View.dims` 给**修正后值**（`modified`），`Fact.base` 给基值；`dim()` 只给基值（A-M3 钉死）。
- 实体不存在返回 `null`；维度未知返回 `{known:false}` 并按表头 `onUnknown` 处置。
- 入口**纯读**：不写状态，不采样写回（采样为纯函数）。

### 2.3 记忆与依赖声明（A-M1：由被调用方组合）

```js
declareViewInputs('placeView', {
  own:  [['created','*'], ['buildings','*','owner'], ['settlements','*'],
         {path:['records'], categories:['service_ticket','facility_region']}],
  uses: ['dim:place', 'facilityView', 'modified:place', 'statusView']
});
export function placeView(engine,state,id){
  return stateMemo(state, engine, [placeViewMemo, id], () => readPlaceView(engine,state,id), viewDeps('placeView'));
}
```
- `own`：本入口函数体直接读的状态路径；`uses`：它调用的其他入口、`dim:<kind>`、`modified:<kind>`、`relation:<name>`。
- `dim:<kind>` 的依赖由**维度表与 state-owners.json 机器生成**：该 kind 实例偏离行的位置（`created.<prefix>*.props`）+ 其 `derived` 公式用到的 relation 所声明的状态键；`modified:<kind>` 再并上 `modifiers`、`statuses`、`holdings` 与作用域索引用到的键（§3.5）。
- 注册表在加载期对 `uses` 做传递闭包（有环即 E-VIEW-DEPS-CYCLE），得到最终依赖数组，**算一次、冻结、按名复用**（`viewDeps(name)` 返回同一对象），从而 storage.mjs:275 `groups.get(dependencies)` 的身份键命中，不泄漏。
- **静态检查**（必须）：入口函数体中出现的 `state.<key>` 字面量必须 ∈ own ∪ 闭包（E-VIEW-UNDECLARED-READ）；声明了但函数体与闭包都不读的报 W-VIEW-OVERDECLARED。运行态读取追踪**不作为验证手段**（B-五.3），只在校验夹具里作交叉核对（可以）。
- 目录态值用 WeakMap 按 world 记忆；入口不假设有索引（recordIndexDepth 为 0 时直接 build）。

### 2.4 禁止绕过入口直读状态字段

- `state-owners.json` 每个状态顶层键登记：`readers`（入口文件）、`writers`（声明写者）、`display`（显示字段集合，如 `displayNames.*.text`、`npcs.*.name`、`created.*.nameParts` 的拼装结果…）。
- 扫描：`state.<key>` 直读只许在 readers/writers（E-VIEW-BYPASS）；`engine.byId.get(id).<field>` 只许在 catalog.mjs 与入口文件（E-VIEW-BYPASS-CATALOG）；对 `display` 集合内字段的任何读取（E-VIEW-DISPLAY-READ）与任何文本匹配（E-VIEW-TEXT-MATCH：`/…/.test、includes、startsWith、indexOf、===` 作用于字串字段）= 0。**描述字段集合由数据声明，不是脚本里手写名单**（A-M6.3）。
- 基线：06a §二.6（npcs 55 模块 196 处、records 89 模块 311 处、memoryStream 22 模块）、06b 219 行；只降不升。

### 2.6 写者声明与三接口

## 三 修正值体系

### 3.1 结论：注册开放枚举

（利弊表同第一版：CK3 05 §2.8 封闭枚举——每加一种可被信仰/文化/状态改的量都要改引擎；EVE 04 §2.2–2.4 开放集合——错字即新键、无单位无边界。）

**决定**：
1. 键集合**开放于数据**：任何维度表里 `modifiable:true` 的 number/integer 维度即修正键，键名 `<kind>.<dimension>`，map 维度的 number 值按子键寻址 `<kind>.<dimension>[<key>]`（B-二.3）。
2. 键集合**封闭于代码**：代码不得出现修正键字面量（S8）；校验器拒绝未注册键（E-MOD-KEY-UNREGISTERED）。
3. 运算（`add/mul/max/min/set`）、阶段、作用域是封闭枚举。
4. 单位、精度、边界、叠加规则是键的元数据（表头），修正项不自带。
5. 两个命名空间不是实体表却可注册键：`body.<capability>`（§3.6）与 `process.<slot>`（§3.7）。

### 3.2 修正项的格式

```json
{
 "id": "mod_faith_ascetic_food_need",
 "target": "person.dailyFoodNeed",          // 或 "facility_type.upkeepPerDay[class_fuel]"
 "scope": "believers",
 "stage": "mul",                            // add | mul | max | min | set | post（stage 即运算，无单独 op；A-M2、B-二.1）
 "value": -0.15,                            // 或 "valueRX": "…"；post 阶段写 "curve": "<curve id>"
 "when": "subject.age >= 16",               // 可选 RX；可读 clock.day / clock.season
 "source": {"kind":"faith","id":"faith_ash_way","via":"tenet_asceticism"},
 "stackGroup": "faith_tenet",               // 同组只取序最高者
 "priority": 0,                             // 全序第一键
 "unpenalized": false,                      // true 则此条不受叠加惩罚（B-二.4）
 "duration": null,                          // null 永久；{"days": n} / {"untilEvent": "<verb>"}
 "basis": "苦修信条：进食需求 −15%（卷七标定）"
}
```
- 来源四处（维度表行、规则表 modifiers/*.json、运行态 `state.modifiers`（唯一写者 modifier.mjs）、物品实例的品质/附魔）格式相同。
- `value` 语义按 stage：`add` 绝对量（单位同目标）；`mul` 相对因子（0.2 = +20%，−0.15 = −15%）；`max/min` 绝对阈值；`set` 绝对覆盖值（石化、封印等"必须是 X"，B-二.5）；`post` 无 value，用 `curve`。
- 修正项不含目标的数值（EVE：效果不含数字）。
- `valueRX` 只能经 `dim()` 读来源与对象的**基值**。

### 3.3 求值管线（定点、全序、确定）

沿用 derived.mjs 的定点工具（rx.mjs `fixedUnits/fixedMultiply/checkedFixed/fixedNumber`）与"无修正时保持原生值"（derived.mjs:244–250）：

```
modified(target, subject):
  base   = dim(subject, dimension)                       # 0 基值（定点化）
  rows   = applicable(target, subject)                   # when 为真、scope 命中、未过期；(source,target,subject) 去重
  rows   = dedupe by stackGroup → keep max by order      # 全序键 order = (priority desc, |value| desc, source id asc, id asc)
  if rows is empty → return native base (不取整)
  v = base
  v = v + Σ add                                          # 1 add：绝对，不受罚
  P = pos mul sorted by order; N = neg mul sorted by order
  v = v × Π_i (1 + P_i · S[i_pen]) × Π_j (1 + N_j · S[j_pen])   # 2 mul：正负分开；i_pen 是该条在"受罚条"中的序号（从 0 起）；unpenalized 的条不占序号且 S=1；维度 stacking=none 时全部 S=1
  v = max(v, max_k) for k in max rows by order           # 3 max
  v = min(v, min_k) for k in min rows by order           # 4 min
  if set rows → v = set row with highest order           # 5 set（覆盖）
  v = curve_k(v) for k in post rows by order             # 6 post
  v = clamp(v, bounds)                                   # 7 clamp
  return round(v, precision)                             # 8 取整
```
- **叠加惩罚系数表** `rules.modifiers.stackingTable`（标定值，出处 EVE 04 §2.4 的 `exp(−(n/2.67)²)`，离线算好、写成 4 位定点）：`S[0..7] = [1.0000, 0.8694, 0.5706, 0.2830, 0.1060, 0.0300, 0.0064, 0.0010]`，`n ≥ 8` 取 0。求值只查表，不算 exp；同种子同存档跨机逐位一致。本卷 §0 第 5 条、本节、附录 B、断言 B3 全部按"n 从 0 起、第 n 条受罚乘 S[n]"同一写法（A-M2）。
- 阶段顺序与 derived.mjs 现有 `STAGES=['add','mul','max','min','clamp']` 兼容，中间插入 `set` 与 `post`。
- `explain(target, subject)` 返回 `[{stage, id, source, value, penalty, before, after}]`，供 why() 与面板；链逐段复算等于结果（定点下严格相等，B5 不再用浮点容差）。

### 3.4 递减规则

- 维度 `stacking:penalized`：防护/抗性、感知、速度、产率倍率、说服与观感倍率、价格倍率等"堆同类边际递减"的量；`none`：容量、计数、绝对寿命、日耗。各卷逐维声明。
- 来源豁免用 `unpenalized:true`（如种族基线、技能本身），豁免条不占受罚序号（EVE 技能与部分植入体不受罚的通用化）。
- 第三种曲线用 `post` 表达，不开新 stacking 值。
- 同一 `(source.id, target, subject)` 只计一条；严重度变化走状态容器 severity。

### 3.5 作用域与索引方向（B-二.6）

| scope | 含义 | 解析方向 |
|---|---|---|
| `self` | 来源自身 | 直接 |
| `holder` | 持有来源的实体 | 由 subject 向下：subject 的持有表 → 其持有物的修正项 |
| `located` | 位于来源地点（含子地点）的实体 | 由 subject 向上：沿包含树祖先 → 各祖先地点的修正项 |
| `members` | 来源组织成员 | subject 的 `member_of` 持有 → 组织 → 修正项（含上级组织） |

| `jurisdiction` | 来源法域内实体 | subject 的地点 → nearest(lawCode) → 法典/法令修正项 |

| `global` | 全世界 | 常量集合 |

- 统一采用"**从主体出发找来源**"方向：每次求值只遍历 subject 的少量链（持有 O(持有数)、祖先 O(深度)、组织/信仰 O(层数)），不扫全体 NPC。

### 3.6 `body.<capability>` 的归属（A-M8、B-二.2）

## 四 校验器

### 4.1 分级、时机与分期

校验器 `server-plugin/dimensions-validate.mjs` 在 `loadWorld` 时跑 L0–L4，任一 error 即加载失败；内容管线调用同一函数；运行态写回（偏离行）调用同一函数，**失败即拒写并发 `dimension_write_rejected` 事件**，状态不变（A"校验器"9）。

| 级 | 名 | 检查 | 首期 |
|---|---|---|---|
| L0 | 语法 | JSON 可解析且**无重复键**（自写解析器或逐字符扫描，E-DIM-DUPLICATE-KEY）；表头四字段；id 格式与前缀 | 必须 |
| L1 | 结构与取值域 | 类型、单位存在、precision、domain、enum/ref 格式、set 唯一与大小、显式 `[]`、curve 单调、distribution 参数与 clamp、`onUnknown` 存在、`derived` 可编译且变量存在、`modifiable` 仅 number/integer、`sample` 与 `derived` 不并存、extends 目标合法、+/− 不与整值并存 | 必须 |
| L2 | 引用闭合 | 所有 ref 指向存在（含 generated/created）；类别键在词表；precedence 行存在、不含 abstract、与 broader 深度一致；extends 无环；**派生依赖图无环**；修正项 target 注册、stage/scope 合法、valueRX 可编译；`uses` 闭包无环；词表字段按族 schema | 必须 |
| L3 | 必填完整 | `required` 四策略；组件 requires；实例行 basis/sources；sources 推出值 = 直写值；成员偏差；全局 id 唯一（跨表，E-DIM-ID-DUPLICATE） | 必须 |
| L4 | 跨表不变量 | 首期三条：MASS-VOLUME（质量 = 密度×体积，容差按 precision）、PORTION-SUM（material map 和 = 1）、REF-CLOSURE（已在 L2）；其余（SEVERITY-ORDER、职业 workstation 是 facility_type、文化 language 在词表、罪名 act 是动词、修正预算 totalBounds…）为"应当"，分批进 CORE | 三条必须，其余应当 |
| L5 | 齐全率 | 不阻断；每表每维 known/total 与来源分布；写 `logs/dimensions-coverage.<date>.txt` | 应当 |

- 禁止回退：校验器与入口都不得在缺字段时解析文本补值。`required` 让缺字段在加载期暴露，E-VIEW-TEXT-MATCH 兜底。
- 校验器自身：只读维度表、词表、单位表、规则表、存档 created 与 state-owners.json；不读 labels 内容；规则里不含实体 id 字面量，前缀表来自表头；输出按 (table,row,dim) 排序，确定。

### 4.2 报错格式

```json
{"code":"E-DIM-DOMAIN-RANGE","severity":"error","level":"L1",

 "got":75,"want":"[0,60] MJ_per_kg_dry","message":"取值越界","hint":"木材高位热值约 19–21；核对 sources 单位"}
```
一行人读：`E-DIM-DOMAIN-RANGE  material/class_timber.heatValue  got 75  want [0,60] MJ_per_kg_dry  — <path>  (hint)`。规则：`code` 形如 `E-<区>-<名>`/`W-…`，区 `DIM/MOD/VIEW/SEED/I18N`；`path` 为 JSON 指针或 `文件:行`；`got/want` 必填；同 (code,table,row,dim) 只报一次；一行多错全报；末行 `errors=N warnings=M tables=22 rows=R known=K/T`。message/hint 是校验器自身输出，允许中文（不是运行态规则读的量）。
