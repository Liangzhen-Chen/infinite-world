## §1 领域总述

### 1.1 真实世界怎样运转

1. **世界不因没人看而停。** 远处的庄稼照样成熟，远处的人照样生老病死、欠债还钱。观察者不在场，改变的只是他知道多少，不是事情发不发生。
2. **远处的事只以总量为人所知。** 一个人对邻村知道张三李四，对邻省只知道“今年歉收、人口约几万”。总量由个体加总得到，不是另一套规律。所以粗算必须是细算的加总，两者不许各走各的规律。
3. **守恒不分远近。** 钱、粮、人不会因为离得远就凭空多出或消失。
4. **同因同果，但结果是分布。** 同样的起点、同样的偶然，结局相同；换一组偶然，结局在一个合理范围内散开。个别不合常理的结果可以有，整体分布不许偏。
5. **记录是发生过的事的账。** 一本只往后写、不涂改的流水账，加上隔一段时间盘一次的存量，就能回到任何一次盘点之后的任何时刻。

### 1.3 进程归属（待卷二收口后对齐）

本卷按下列划分写，卷二收口后若写法不同，以卷二为准，本卷只改引用：

- **Node 服务端进程**：权威状态、推进、聚合、成本判定、存档读写、复演，全部在这里（kernel 组与规则层）。
- **浏览器扩展进程**：只有 display 组与 host 组文件（卷二 §2.7）；不持有权威数据（卷一 L-9）；不向规则层提供时钟、随机数或任何熵；跨进程只经卷二 §2.9 第 1 条登记的入口与出口传代号结构和已筛查文字。

## §4 子系统

### 4.1 三层模拟运行矩阵

#### 4.1.1 维度

`unitAdminLevel`、`individualMaxHops`、`ruleMaxHops`、`ruleSharedAncestorLevel`、`cadenceMinutes`、`matrix`、`observables`、`driftTolerance`；状态 `simProgress.<unit>.through`。

#### 4.1.2 统一入口

`simUnitOf`、`simTierOf`、`advancePlan`；写者 `sim-advance.mjs`。

#### 4.1.3 规则

- **R27-1.1 模拟单元**：每个地点属于恰一个模拟单元（`simUnitOf`）。单元之间的邻接由地点之间的边（卷五 §4.1）提升得到：两个单元有任一对成员地点直接相连即相邻。不再读手写的邻接清单。
- **R27-1.2 观察锚**：观察锚 = 当前由输入边会话控制的实体所在的单元集合。锚可以有多个。
- **R27-1.3 层的判定**（纯函数，只读拓扑、锚与规则表）：设 h = 单元到最近观察锚的跳数，不连通记为无穷大。h ≤ `individualMaxHops` 为个体层；否则 h ≤ `ruleMaxHops`，或 `ruleSharedAncestorLevel` 非空且与某个锚在该级有共同祖先，为规则层；其余为统计层。阈值取降级后的有效值（§4.3）。锚所在单元恒为个体层，降级不得改变这一点。
- **R27-1.4 层不落盘**：层随时由 R27-1.3 算出，不写进状态，也不写到任何实体身上。落盘的只有每个单元的 `through`。
- **R27-1.5 运行矩阵**：每个系统对每一层声明一个形态。`simform_individual`：逐实体、按到期项结算。`simform_batch`：逐实体、按该层节拍整拍结算。`simform_stat`：逐聚合体、按该层节拍整拍结算，只读写人数、聚合账户与聚合维度。`simform_frozen`：不随时间变；仅当该系统在该层没有登记任何时钟形状的规则时合法，否则 E-SIM-FORM-INVALID。新系统不声明矩阵行即加载失败。
- **R27-1.6 节拍桶对齐**：粗形态只在绝对时间的整拍边界上结算，桶号 = 时刻整除节拍。任何一次推进把区间拆成“桶”逐个处理；起止不在边界上的零头留到下一次，由 `through` 记住。因此一次走完与分几次走完，结果逐字节相同（A27-1.3）。
- **R27-1.7 追赶**：单元因观察锚靠近而变细时，先按它原来的粗形态把 `through` 追到当前时刻所在的桶边界，再换形态。没人看的那段时间按粗形态算，这是既定事实，不回头重算。
- **R27-1.8 钉住个体不随层变粗**：统计层或规则层单元里被钉住的个体（§4.2）仍按个体形态结算，结算时刻取自身最早到期项。
- **R27-1.9 层间一致性**：同一系统的粗形态必须是细形态的加总——守恒量逐笔守恒（经账本，卷六 §4.1）；`observables` 列出的可观测量，在同一单元、同一组种子下分别按个体层与统计层推进同样时长，两者的分布之差不超过 `driftTolerance`。超出即判为“缺规律”，修在该系统的规则层，不许调容差掩盖（调容差须李白批）。

#### 4.1.4 交互

- 卷二十 §4.1 调度器：拿 `advancePlan` 的结果排入同刻全序；本卷不排序。
- 卷二十二 §4.5、卷八 §4.16：各自的系统在矩阵里声明形态，读 `simTierOf`。
- 卷五 §4.1、§4.14：提供包含树、边、行政层级词表。
- §4.3：提供有效阈值。§4.6：执行层间一致性基准。

#### 4.1.5 数据实例

| # | 标记 | 维度取值 | 结果 |
|---|---|---|---|
| 1 | [西陲] | 观察锚所在单元，h=0 | 个体层；全部系统按 `simform_individual` |
| 2 | [西陲] | 与锚隔一个单元，h=2，同一上级祖先 | 规则层；按日整拍 |
| 3 | [非西陲] | 隔海另一大区的港口单元，h=7，无共同祖先 | 统计层；按周整拍，人口以聚合体存在 |
| 4 | [非人类] | 无聚落的荒野单元，主体是兽群；h=1 | 个体层半径内，兽群成员实体化；同一规则表，不为兽群另写阈值 |
| 5 | [超自然] | 与凡间无边相连的秘境单元，h=无穷大 | 统计层；一旦有观察锚进入即 h=0，先追赶再转个体层 |

#### 4.1.6 验收断言

- **A27-1.1（扫描式）**：S27-1 命中数为 0；规则层与内核中行政层级族条目的字面量为 0，层判定只经 `simTierOf`。
- **A27-1.2（不变量式）**：对任意状态，`simTierOf` 只依赖拓扑、观察锚与规则表；同一状态调用两次结果相同，改动任何非锚实体不改变任何单元的层。
- **A27-1.3（不变量式，分段无关）**：对任意 a<b<c，从同一状态推进 a 到 c，与先推进 a 到 b 再推进 b 到 c，规则可读状态哈希相等。
- **A27-1.4（不变量式，层间一致）**：R27-1.9 的基准对矩阵里每个声明了 `observables` 的系统都通过。
- **A27-1.5（扩展性式）**：新增一个系统，只加系统声明行与矩阵行，不改 `sim-tiers.mjs` 与 `sim-advance.mjs`，A27-1.2 至 A27-1.4 仍通过。
- **A27-1.6（扩展性式）**：换一张拓扑完全不同的世界（非西陲、含不连通区域），不改任何代码与规则表，A27-1.2、A27-1.3 通过。

### 4.2 聚合变体、等价、钉住

#### 4.2.1 维度

聚合种类表字段 `aggKind`、`subjectKind`、`keyDims`、`keyHoldings`、`pooledResources`、`shareRule`、`shareDist`；状态 `aggregates.<aggregate>.{kind, key, members, nextOrdinal}`。

#### 4.2.2 统一入口

`pinned`、`aggregateView`；写者 `aggregate.mjs`；两个动作 `fold`（折叠）与 `materialize`（实体化）都以一条事件加原语列表提交。

#### 4.2.3 规则

- **R27-2.1 聚合变体是什么**：一个聚合体代表若干个“没有个人历史”的同类个体。它只存分组键、成员区间和下一个序号；人数 = 成员区间长度之和，是派生量。
- **R27-2.2 成员身份**：每个成员由（来源种子键, 序号）唯一标识，终身不变。个体的实例 id 由这一对按卷十的实例 id 导出规则确定性得到；个体的各维度由卷二 §1.10 的采样函数从实例 id 算出，不落盘。所以同一个成员无论被实体化多少次，都是同一个 id、同一组属性。
- **R27-2.3 等价**：一个个体与聚合体中的一个成员等价，当且仅当它的**足迹为空**。足迹 = 下列各项的并集：
  1. 状态中以该 id 为路径段、或以引用类型指向该 id 的全部路径（按 pathTypes 判定，卷二 §2.7），聚合机制自身的路径除外；
  2. 以该 id 为端点的未结束持有边，种类在 `keyHoldings` 内的除外；
  3. 引用该 id 的未了结义务；
  4. 到期堆中以该 id 为对象的条目；
  5. 该 id 名下余额非零的账户，资源在 `pooledResources` 内的除外。
  足迹由内核维护的反向索引得出；索引是投影，可随时丢弃重建，不落盘。
- **R27-2.4 钉住**：`pinned` 为真，当且仅当足迹非空，或该实体是观察锚，或它所在单元是个体层。`reasons` 给出命中的类别代号，只用于解释；任何代码不得按原因代号分支。**不存在逐条手写的钉住条件清单**：哪个系统在个体身上留了状态，哪个系统就自动把他钉住。
- **R27-2.5 折叠**：只在该层节拍的整拍边界、对 `pinned` 为假的个体执行。折叠 = 把 `pooledResources` 的余额经账本转入聚合账户，把成员序号并回成员区间，删除实体行。对足迹非空的个体折叠即 E-AGG-FOLD-FOOTPRINT。
- **R27-2.6 实体化**：需要个体时（单元转个体层、或某条规则要对聚合体中的某一个成员写入个人状态），从成员区间取出一个序号，建立实体行，按 `shareRule` 从聚合账户转出份额：`share_percapita` 为聚合账户余额整除当前人数，余数留在聚合账户；`share_sampled` 为按 `shareDist` 抽取并钳在聚合账户余额之内。取哪个序号由骰值键抽取决定，键里含聚合体 id 与桶号。
- **R27-2.7 统计形态下的增减与迁移**：减员按骰值键在有序成员表上抽位置；增员取 `nextOrdinal` 并加一；在聚合体之间迁移时成员保留原来的（来源种子键, 序号），只换所属聚合体。成员区间保持有序、互不重叠（否则 E-AGG-MEMBER-OVERLAP）。
- **R27-2.8 分组键只用已声明维度**：`keyDims` 必须是该实体类已登记的枚举型或引用型维度；用未登记维度即 E-AGG-KEY-UNDECLARED。聚合种类表不出现任何具体实体 id。
- **R27-2.9 可折叠的前提是“随时间变的事实由时钟派生”**：凡希望其主体可折叠的系统，空闲时不得在个体身上留增量状态；年龄这类量由出生时刻与时钟派生（卷二 §1.12）。留了状态不是错误，只是该个体会被钉住。

#### 4.2.4 交互

- 卷八 §4.16、卷二十二 §4.5、卷十 §4.3 以及任何需要群体形态的领域卷：向聚合种类表登记行，不写聚合代码。
- 卷六 §4.1：聚合体作为账户持有人（§8 开放问题 4）。卷十：实例 id 的导出规则。卷二 §1.10：采样。
- 卷九 §4.2：折叠与实体化所用原语取自封闭原语目录（§8 开放问题 5）。

#### 4.2.5 数据实例

| # | 标记 | 聚合种类行的取值 | 说明 |
|---|---|---|---|
| 1 | [西陲] | `subjectKind` = 个体类；`keyDims` = 所在单元、物种、职业；`keyHoldings` = 居住类；`pooledResources` = 通用货币、口粮；`share_percapita` | 普通居民 |
| 2 | [非西陲] | 同一行，不新增行；`key` 里的所在单元取另一大区的单元 | 同一聚合种类对任何地区成立 |
| 3 | [非人类] | `subjectKind` = 个体类；`keyDims` = 所在单元、物种、年龄段；`keyHoldings` = 栖居类；`pooledResources` 为空 | 兽群；没有账户，折叠时无转账 |
| 4 | [超自然] | `subjectKind` = 个体类；`keyDims` = 所在单元、物种、所属组织；`keyHoldings` = 从属类；`share_sampled` | 受召唤而存在的群体；带着未到期的存续状态的成员足迹非空，自动钉住 |

#### 4.2.6 验收断言

- **A27-2.1（扫描式）**：`aggregate.mjs` 中对持有种类、义务种类、状态族、记录种类的句柄字面量为 0（钉住只由足迹推出）；S27-2 命中数为 0。
- **A27-2.2（不变量式，往返恒等）**：对任一足迹为空的个体，折叠后立即实体化同一序号，规则可读状态哈希与折叠前相等。
- **A27-2.3（不变量式，守恒）**：任意折叠、实体化、迁移前后，每种资源的全局总量不变；全局人数 = 实体行数 + 各聚合体成员区间长度之和，只在出生与死亡事件上变化。
- **A27-2.4（不变量式，身份稳定）**：同一（来源种子键, 序号）在任意多次实体化之间，实例 id 与全部采样维度相同。
- **A27-2.5（扩展性式）**：新增一个在个体身上留状态的系统，不改 `aggregate.mjs`，带该状态的个体自动 `pinned` 为真。
- **A27-2.6（扩展性式）**：新增一种聚合种类（任意实体类、任意分组键），只加一行，A27-2.2 至 A27-2.4 通过。

### 4.3 成本模型与降级阶梯

#### 4.3.1 维度

`coef`、`budgetCu`、`chunkMinutes`、`ladder`；派生量 `costUnits`、`degradeLevel`（都不落盘）。

#### 4.3.2 统一入口

`costPlan`；`advancePlan` 内部调用它取有效阈值。

#### 4.3.3 规则

- **R27-3.1 成本是算出来的，不是量出来的**：一次推进的预计成本 = 对计划内每个单元、每个系统求和：主体数 × 要走的桶数 × `coef[system][form]`。主体数对个体与批量形态是该单元内该系统主体类的实体行数，对统计形态是聚合体个数。全部整数运算。
- **R27-3.2 降级判定不读墙钟**：`degradeLevel` 只由 R27-3.1 的预计成本与 `budgetCu` 得出。实测耗时、内存、机器负载、AI 额度、网络状况一律不得进入这个判定，也不得进入任何状态。理由：降级会改变哪些单元按哪种形态结算，如果它取决于机器快慢，同一种子在本机与云上就会走出不同的世界（违反卷一 I50）。
- **R27-3.3 取档**：从 0 档起逐档套用 `ladder`，取使预计成本不超预算的最小档。到了最高档仍超预算，按最高档执行，并经内核报告出口记一条 E-COST-OVER-BUDGET（告警级，不改状态）。
- **R27-3.4 阶梯操作**（累加）：`deg_individual_hops` 把个体层半径减去 `amount`，下限为 0；`deg_rule_hops` 把规则层半径减去 `amount`，下限为个体层半径；`deg_drop_shared_ancestor` 停用共同祖先条件。节拍不在可降之列——改节拍就是改规律。
- **R27-3.5 长推进分块**：区间长于 `chunkMinutes` 时按块推进，每块重新取档。由 R27-1.6，分块不改变结果。块与块之间让出执行权归 host（待卷二收口后对齐）。
- **R27-3.6 系数是世界数据的一部分**：`coef` 由基准标定后入库（§4.6），随世界数据副本一起存进存档（§4.4）。所以重新标定只影响新开的世界，已有世界的降级行为不变。
- **R27-3.7 单向读**：卷九 §4.14 可以读 `degradeLevel` 来调低 AI 档位；反过来，AI 档位、费用账、模型可用性不得被本节读取（卷一 I42）。

#### 4.3.4 交互

卷九 §4.14（读档位）；卷二十 §4.10（节奏参数决定一次动作推进多少分钟，是 `costPlan` 的输入之一）；§4.1（有效阈值）；§4.6（标定系数、核对预计成本与实测的相关性）。

#### 4.3.5 数据实例

| # | 标记 | 输入 | 结果 |
|---|---|---|---|
| 1 | [西陲] | `adv_turn`；锚周围单元实体行少，预计成本低于预算 | 0 档，阈值取表值 |
| 2 | [非西陲] | `adv_skip`；锚在人口稠密的大城单元，预计成本超预算 | 逐档收缩个体层半径直至不超；锚所在单元仍为个体层 |
| 3 | [非人类] | `adv_turn`；锚在兽群密集的荒野单元 | 与实例 2 走同一条阶梯；没有“兽群专用降级” |
| 4 | [超自然] | `adv_offline`；无观察锚的无人值守推进 | 全部单元为统计层，预计成本只含聚合体个数项 |

#### 4.3.6 验收断言

- **A27-3.1（扫描式）**：S27-3 命中数为 0；`cost-model.mjs` 与 `sim-tiers.mjs` 的输入声明（卷二 §2.3）里没有 AI、费用账、旁路记录相关的状态键。
- **A27-3.2（不变量式）**：同一状态、同一请求，`costPlan` 在本机与云上、在两个 Node 版本下返回值逐位相同。
- **A27-3.3（不变量式）**：任意档位下，观察锚所在单元的层为个体层；任意档位下 A27-2.3 的守恒成立。
- **A27-3.4（不变量式）**：`degradeLevel` 对预算单调——预算调大，档位不升。
- **A27-3.5（扩展性式）**：新增一个系统，只加系数行即进入成本模型；缺行即加载失败，不存在“默认零成本”。
- **A27-3.6（扩展性式）**：在阶梯里增删一档只改规则表，A27-3.2 至 A27-3.4 仍通过。

### 4.4 存档（事件日志加快照、分片）

#### 4.4.1 维度

`shards`、`snapshotEveryEvents`、`segmentEvents`、`keepSnapshots`。清单字段：`rulesDigest`、`dataDigest`、`snapshotIndex`、`clockMinute`、`shardDigests`、`logSegments`、`saveDigest`、`ruleStateDigest`。

#### 4.4.2 统一入口

卷二 §2.9 第 1 条登记的内核读档入口与存档写盘出口；本卷不新增文件边界。扫描 S27-7。

#### 4.4.3 规则

- **R27-4.1 逻辑文档与物理布局分离**：存档在逻辑上是一份文档——世界数据副本、状态、持有、账本、事件日志。两种哈希（存档哈希、规则可读状态哈希）都对逻辑文档计算，口径与排除表完全按卷二 §2.9 第 3 条，本卷不另立口径。物理上怎样切片不影响任何一种哈希。
- **R27-4.2 每个世界自带数据副本**：开局时把当时的维度表、规则表、词表冻结成一份副本存进存档（卷一 §8.5），其摘要为 `dataDigest`。世界此后只读自己的副本。语言包不在副本内，换语言包不改任何摘要。
- **R27-4.3 规则指纹**：`rulesDigest` 由内核与规则层的源码摘要和 `dataDigest` 合成。读档时只做一次相等比较：不等即拒绝加载（E-SAVE-RULES-MISMATCH），不迁移、不尝试修补，也不改不删该存档文件。显示层、语言包、host 的改动不进 `rulesDigest`。
- **R27-4.4 字段序列化声明读 pathTypes**：哪些路径存、存成什么类型，唯一依据是卷二 §2.7 的 pathTypes。任何系统不写自己的序列化函数；没有声明的路径写不进状态，自然也进不了存档。
- **R27-4.5 事件日志加快照**：日志只追加，每 `segmentEvents` 条封成一段；每 `snapshotEveryEvents` 条事件做一次快照。恢复 = 最近一个完好快照 + 其后的日志段按 `replay_apply` 重放（§4.7）。
- **R27-4.6 分片**：`shards` 把状态路径划成若干片，每条路径恰属一片（路径匹配语义用卷二 §2.7）。`part_single` 整片一个文件；`part_by_unit` 按模拟单元再切；`part_by_segment` 用于日志。同一个 Sealed 值不跨片拆开。
- **R27-4.7 写时复制**：每个分片文件按内容摘要寻址。存档时只写摘要变了的片；没变的片不重写。远处统计层单元的片很少变，所以一次存档的写入量与“变了多少”成正比，不与世界总量成正比。分片摘要只用于完整性与去重，不是两种哈希之一。
- **R27-4.8 原子提交**：先写齐新分片，最后以原子改名提交清单。清单是唯一的提交点；清单引用的片缺失或摘要不符即 E-SAVE-SHARD-DIGEST，回退到上一个完好清单并报 E-SAVE-TORN。
- **R27-4.9 保留与修剪**：保留最近 `keepSnapshots` 个快照及其后的日志段。修剪只在快照点、只由规则表参数触发；不由磁盘余量、墙钟或手动时机触发。不被任何保留清单引用的分片文件才可回收。
- **R27-4.10 墙钟只在清单的显示字段里**：存档时间等给玩家看的信息放在清单的显示字段，不进逻辑文档，因而不进任何一种哈希。
- **R27-4.11 进程归属**（待卷二收口后对齐）：存档读写只在 Node 服务端进程。扩展进程不保存任何权威数据，其本地偏好属于客户端偏好层（卷一 §8.3 排除层）。

#### 4.4.4 交互

卷二 §2.9（哈希口径、Sealed、读写边界）；卷二 §2.7（pathTypes）；卷二十八 §4.6（同版安装、升级、卸载时调读档入口，并遵守 R27-4.3）；§4.7（复演）；§4.1（按单元切片）。

#### 4.4.6 验收断言

- **A27-4.1（扫描式）**：S27-7 命中数为 0；规则层中“序列化”“反序列化”职责的函数为 0（按是否向存档出口传参判定）；分片表覆盖 pathTypes 的全部顶层键，无重叠。
- **A27-4.2（不变量式，分片无关）**：同一逻辑文档换任意合法分片表存盘再读回，两种哈希都不变。
- **A27-4.3（不变量式，存读恒等）**：任意时刻存盘后读回，继续推进同样的指令序列，与不存盘直接推进相比，规则可读状态哈希在每个快照点相等。
- **A27-4.4（不变量式，中断安全）**：在写盘的任一步骤中断，读档得到的要么是新清单的完整状态，要么是上一个清单的完整状态。
- **A27-4.5（不变量式，语言无关）**：换语言包、换显示层版本后读同一存档，`rulesDigest` 与两种哈希不变（接卷一 I40）。
- **A27-4.6（不变量式，拒绝而不破坏）**：`rulesDigest` 不符时读档失败，存档目录下所有文件的字节与修改前相同。
- **A27-4.7（扩展性式）**：新增一个系统及其状态键，只在 pathTypes 与分片表登记，不改存档读写文件，A27-4.2、A27-4.3 通过。

### 4.5 确定性数值

#### 4.5.1 维度

`mathAllow`、`safeIntMax`；卷二 §1.5 各数值类型的 `precision`（引用）。

#### 4.5.2 统一入口

求值走卷二 §3.3 管线；超越函数只经内核的定点数学设施（现 det-math.mjs，归入 kernel 组）；集合遍历只经内核提供的按键排序遍历；扫描 S27-3、S27-4。

#### 4.5.3 规则

- **R27-5.1 状态里的数只有两种**：整数（绝对值不超过 `safeIntMax`），或按维度 `precision` 的定点数。非有限值、负零不得进入状态（E-DET-NONFINITE）。超出安全整数范围的量按定点整数串存。
- **R27-5.2 运算**：规则层的数值运算只有三条路——卷二 §3.3 求值管线；内核定点数学设施（指数、对数、三角、开方、幂，全部查表加整数运算）；`mathAllow` 列出的整数安全成员（取整、绝对值、最大最小、符号一类）。其余数学成员在规则层出现即 E-DET-FLOAT。
- **R27-5.3 顺序**：凡结果依赖遍历顺序的地方，顺序必须由 id 的码点序或数值键决定。排序必须给出全序比较函数，比较键只能是 id 或数值（卷一 I40）；不得使用依赖区域设置的比较；不得依赖对象键的插入顺序来自何处。违例 E-DET-ORDER。
- **R27-5.4 同步**：规则层与内核的结算是同步的；结果不得依赖异步回调的完成先后。计时器与墙钟不在可用全局之内（卷二 §2.9 第 1 条）。
- **R27-5.5 时钟**：规则只认分钟时钟（卷二十 §4.1）。墙钟不进状态、不进键、不进任何判定。
- **R27-5.6 同刻全序**：同一分钟内的结算次序由调度器的全序键唯一决定（卷二十 §4.1、卷二 §2.7 的阶段与排序键），与注册顺序、文件加载顺序无关。
- **R27-5.7 跨环境**：同一输入在本机与云、在项目支持的每个 Node 版本下结果逐位相同。凡做不到这一点的语言特性，一律列入禁用并由 S27-4 扫描。
- **R27-5.8 哈希的实现与断言**：哈希排除表由卷二 §2.9 第 3 条的规则生成；本卷负责把生成器接进门禁并断言入库文件与生成结果一致（E-DIGEST-EXCLUDE-DRIFT，卷二 §4.3）。

#### 4.5.4 交互

卷二 §3.3、§1.5、§2.9；卷二十 §4.1；卷六（价格等定点量使用同一设施，不自带分母常数——现行分母常数迁入规则表，归卷六登记）；卷十二（扫描实现）。

#### 4.5.5 数据实例

| # | 标记 | 情形 | 按本节的处理 |
|---|---|---|---|
| 1 | [西陲] | 作物产量乘以若干修正 | 走求值管线，定点截断，不出现浮点乘法 |
| 2 | [非西陲] | 跨海运价按距离取幂 | 幂经内核定点设施查表；规则层不直接调用数学成员 |
| 3 | [非人类] | 兽群增长按指数律整拍结算 | 指数查表；人数为整数，余量按骰值键抽取进位 |

#### 4.5.6 验收断言

- **A27-5.1（扫描式）**：S27-3、S27-4 命中数为 0。
- **A27-5.2（不变量式）**：任意状态的全部数值路径满足 R27-5.1；存盘读回后逐位相等。
- **A27-5.3（不变量式）**：把系统注册顺序、数据文件加载顺序、状态集合的插入顺序各自打乱后重跑同一指令序列，事件流逐字节相同。
- **A27-5.4（不变量式）**：同一指令序列在本机与云、在每个受支持的 Node 版本下，事件流与规则可读状态哈希逐字节相同（卷一 I50）。
- **A27-5.5（扩展性式）**：新增一个需要超越函数的规则，只调内核设施；新增一张查找表只加数据，A27-5.4 仍通过。

### 4.6 性能门与基准

#### 4.6.1 维度

`scenarios`、`budgets`、`regressRatio`、`scaleRatioMax`、`runs`；族 `perfmetric`。

#### 4.6.2 统一入口

基准执行器在 tools 组，不在运行时；结果写基线文件，由门禁读取。规则层与内核不得读基线文件。

#### 4.6.3 规则

- **R27-6.1 两类指标分开拦**：
  - **计数类**（`pm_cost_units`、`pm_event_count`、`pm_save_bytes`）：与机器无关、逐位可复现，进核心门禁，每次合入都拦。
  - **计时类**（`pm_turn_ms`、`pm_advance_day_ms`、`pm_save_ms`、`pm_load_ms`、`pm_heap_mb`）：只在云上的参考环境跑，每场景跑 `runs` 次取中位数，在阶段收口与大改动时拦。
- **R27-6.2 三道判据**：绝对预算（`budgets`）；相对基线的回退上限（`regressRatio`）；规模判据——同一场景把 `sizeClass` 翻倍，计数类指标的增幅不得超过 `scaleRatioMax`，用来在合入时就拦住平方级以上的写法。
- **R27-6.3 基线**：计数类基线只降不升；计时类基线在通过后更新为新中位数。基线文件入库。
- **R27-6.4 场景是数据**：一个基准场景 = 一行（世界种子、规模、推进时长、推进类别）。场景表必须包含至少一个非西陲世界、一个以非人类主体为主的场景、一个无观察锚的长时推进场景。
- **R27-6.5 层间一致性基准**（`pm_tier_drift`）：R27-1.9 的比较在这里执行，容差取 `driftTolerance`。
- **R27-6.6 标定**：`coef` 由基准对每个（系统, 形态）单独测得每实体每拍的耗时中位数，取整入库；同时核对预计成本与实测计时的相关性，低于规则表门槛即要求重新标定。带“待标定”的预算在第一次标定后填入，并写明标定环境与日期（basis）。
- **R27-6.7 分段记账**（待卷二收口后对齐）：`pm_turn_ms` 只量服务端从收到指令到产出投影这一段；传输与扩展渲染另由显示层卷记账。
- **R27-6.8 守恒是性能门的前置条件**：基准场景结束时调用卷六 §4.22 的源汇报告，任何一种资源不平即该次基准作废，不记成绩。

#### 4.6.4 交互

卷十二 §4.8（门禁实现、浸泡指标）；卷六 §4.22（源汇报告）；§4.3（标定系数）；§4.1（层间一致性）。

|---|---|---|---|
| 1 | [西陲] | 标准规模；`adv_turn`；推进一日 | 回合耗时与事件数 |
| 2 | [非西陲] | 另一张世界；规模翻倍；`adv_skip`；推进一季 | 规模判据与降级后的成本 |

### 4.7 复演与规则只一版

#### 4.7.1 维度

族 `replaymode`；清单字段 `rulesDigest`（§4.4）。

#### 4.7.2 统一入口

`replay_apply` 在读档入口内部；`replay_verify` 在 tests 与 tools 组。扫描 S27-5。

#### 4.7.3 规则

- **R27-7.1 规则只有一版**（卷一 R-8）：代码里不存在“按存档版本走不同分支”的任何写法。事件、义务、记录上不带复演版本标记；整份存档只有一个 `rulesDigest`。
- **R27-7.2 两种复演**：`replay_apply` 把日志里记录的原语列表原样施加，用于读档恢复；`replay_verify` 从快照出发，只取日志里的玩家指令与外来输入，重新跑规则，要求重新产生的事件流与日志逐字节相同，用于验证确定性。任一事件不同即 E-REPLAY-DIVERGE，报告第一处分歧的事件序号与原语序号。
- **R27-7.3 外来输入全部入日志**：能影响规则状态的外来输入只有玩家指令（封闭代号集合内的动作代号加参数）。AI 文字不影响规则状态（卷一 I42）；`replay_verify` 遇到文字路径时从存档取已有的 Sealed，不重新调用模型（录制回放归卷九 §4.18）。
- **R27-7.4 不迁移**：不存在迁移表、兼容层、旧引擎。`rulesDigest` 不符的存档不能加载（R27-4.3）。“不动原存档”的含义仅是不改、不删存档文件。
- **R27-7.5 同版之内的内容变更归卷二十八**：同一 `rulesDigest` 之下安装、卸载扩展包的做法由卷二十八 §4.6 定；任何使 `dataDigest` 改变的操作都产生一个新世界，不是原世界的升级。
- **R27-7.6 开局缺省**：新世界的缺省值全部来自卷十 §4.12；不存在“为旧存档补缺省”的路径。
- **R27-7.7 复演是日常门禁**：每个基准场景（§4.6）结束后都对其日志做一次 `replay_verify`。

#### 4.7.4 交互

卷二十八 §4.6；卷九 §4.18；卷十 §4.12；卷十一（退役 §7 所列目录与文件）；卷十二（S27-5 与 `replay_verify` 进门禁）。

|---|---|---|---|
| 1 | [西陲] | 同版存档，读档 | `replay_apply` 重放日志尾段，哈希与存盘时相等 |
| 2 | [非西陲] | 另一张世界跑完十年基准 | `replay_verify` 从每个快照出发都逐字节复现 |
| 3 | [非人类] | 兽群聚合体的减员与迁移 | 复演时抽到同样的成员序号（A27-2.4） |

- **A27-7.1（扫描式）**：S27-5 命中数为 0；仓库中 legacy、compat、migrations 目录不存在；对这三者的 import 为 0。
- **A27-7.2（不变量式）**：任意存档从任意保留的快照做 `replay_verify`，事件流逐字节相同。
- **A27-7.3（不变量式）**：状态与日志中不存在任何名称或取值表示“规则版本”“复演版本”的路径（按 pathTypes 清单核对）。

### 4.8 种子键与骰值键（确定性约束与验收）

格式、派生函数、PRNG 一律见卷二 §1.10 与卷一 §8.2；本节只规定必须满足的约束和怎么验。

#### 4.8.1 维度

族 `seedrole`；现有种子键登记表的各列（文件、种类、表达式、次数、前缀、角色）——表的格式归卷二 §1.10，本节只读。

#### 4.8.2 统一入口

抽取只经卷二 §1.10 的采样函数与内核的骰值键包装；种子键类型只由内核构造（卷二 §2.9 第 2 条）；扫描 S27-6。

#### 4.8.3 规则

- **R27-8.1 全登记**：规则层与内核的每一个随机抽取点、每一个由种子派生 id 的点，都在登记表里有一行；源码与登记表双向比对，任一侧多出即 E-SEED-KEY（沿用现有机制）。
- **R27-8.2 键的成分只能是代号、id、整数**：种子键与骰值键的任何成分不得来自文字、AI 输出、墙钟、内存地址、遍历次序或调用计数。类型上由“种子键只由内核按文法构造”保证；另由 `replay_verify` 动态核对。违例 E-SEED-COMPONENT。
- **R27-8.3 分流（流独立）**：随机数按键即取即算，不存在跨调用共享的随机数流或游标。因此新增、删除、重排任何一个抽取点，不改变其他抽取点得到的值。出现带游标的随机数对象即 E-SEED-STREAM。
- **R27-8.4 域分隔**：不同用途的抽取点前缀不同；登记表中角色为 `role_seed` 的行，前缀两两不同。同一世界内两次不同用途的抽取得到同一个键即 E-SEED-COLLISION（静态查前缀，动态在 `replay_verify` 中查重）。
- **R27-8.5 序号成分**：骰值键末段的序号是同一（规则, 对象, 时刻）之下的次序，由调度器全序给出；不得用全局计数器。
- **R27-8.6 聚合抽取**：统计形态的抽取，键含聚合体 id 与桶号；实体化抽取，键含聚合体 id 与桶号加同桶内的次序。由此分段无关（A27-1.3）与身份稳定（A27-2.4）才成立。
- **R27-8.7 熵的去处**：`role_entropy`（非确定来源）只允许出现在 aiGate 与 host 组，且其值不得流入规则层与内核。规则层与内核中该角色的行数为 0。
- **R27-8.8 分布质量**：对卷二 §1.10 的每种首批分布，离线抽取大样本做拟合度检验，并核对不同键之间的相关性不显著；门槛在规则表。规律是分布：验的是整体，不是单次。

#### 4.8.4 交互

卷二 §1.10（格式与采样）；卷十 §4.12（登记生成期键域）；卷九 §4.18（费用账与录制回放不得成为键的成分）；卷二十 §4.1（序号来源）；§4.7（动态核对）。

|---|---|---|---|

#### 4.8.6 验收断言

- **A27-8.1（扫描式）**：S27-6 命中数为 0；登记表与源码双向比对无差；规则层与内核中 `role_entropy` 行数为 0。
- **A27-8.2（不变量式，插入无关）**：在任意位置新增一个抽取点后重跑，除该点自身引起的后果外，其余抽取点的取值与新增前逐个相同（用只读取不使用的探针点验证：事件流逐字节不变）。
- **A27-8.3（不变量式，无碰撞）**：任意基准场景的 `replay_verify` 中，不同（规则, 对象, 时刻, 序号）产生的键两两不同。
- **A27-8.4（不变量式，同种子同输出）**：同一世界种子两次生成并推进，事件流逐字节相同（卷一 I50）；换种子后 `observables` 的分布落在 R27-8.8 的门槛内。
- **A27-8.5（扩展性式）**：新增一个带随机性的系统，只登记行并调用统一包装，A27-8.2 至 A27-8.4 不改测试代码即覆盖到它。
