## §0 卷首

### 0.1 范围

本卷定义“一个世界种子加一套数据表，怎样变成第 0 日的整个世界，以及远处的地方怎样在需要时展开成行”。共十二个子系统：生成总流程；省郡骨架；远方聚落按需物化；名册与人口配额；命名生成算法；栖地派生（生成期）；聚落街区、布局与商店派生；物品生成组；生成物写回同一数据格式；程序生成生物接口；历史生成接口；开局缺省与生成期键域。

## §1 领域总述

### 1.1 真实世界怎样运转

一片土地先有地势、水和气候，再有长在上面的草木鸟兽；人到了能养活人的地方住下，人多了才有村、镇、城。一个地方有多少人、干哪些行当、盖什么样的房、店里卖什么，都是土地出产、手艺与来往买卖的结果，不是谁规定的。名字跟着说话的人群走。远方的城在没人去看的时候照样存在、照样有那么多人和货；有人走近，只是看得更细，并没有多出什么。

### 1.2 本作现状

- 省郡纲要九省 31 郡、地点 458 处已是数据（world/geo/regions.json、locations.json），读它的代码里有地形文字到群落的对照与政体文字判断（regions.mjs:44、regions.mjs:58）。
- 远方聚落的运行时生成全部写在一个文件里（remote-generation.mjs，919 行）：实例 id 字面量 65 处、十进制常数 56 个；按文化代号分支（:109–111、:149–150）；物种 id 常量表（:146）；用名字首字判物种（:149）；命名字库与姓氏表在代码（:200–209）；三类店的货单是三十多个物品 id（:279–281）；按固定地点 id 定人口（:407、:423）；按郡名的文字改种族比例（:411）；各文化职业清单在代码（:416–417）；大纲里的中文数字当人口（:120）；名字结尾的字定聚落级别（:238）；描述句里的字定性别与年龄（:538、:539）。
- 名册按需建档已实现（population.mjs），首次对话时由模型起草人物档，再用正则核对年龄与亲属声称（:384、:392），并带屏蔽词表参数（:62、:99、:371）。
- 栖地由地点的地形与群落文字匹配推出（wildlife-habitats.mjs）。
- 命名的结构与音节数读数据（world/lore/cultures.json 的 `naming`），字库在代码。
- 开局出生地有缺省的固定地点；迁移与兼容代码 3 处。
- 物品生成组、生成物写回标记、程序生成生物、历史的动态生成：未实现。

### 1.3 三条总则

1. **世界在第 0 日就整个存在。** 世界生成（`worldgen` 相）一次定下全部影响规则的事实：每个政区、每块存量单元、每个站点、每个站点的人口聚合体、建筑清单、职业配额、店铺清单、各账户的开局余额。第 0 日之后不再有任何来源腿。
2. **物化只换表示，不添东西。** 远处的站点平时只有摘要与聚合体；需要时（`materialize` 相）把第 0 日定下的清单展开成分片、建筑、房间、店铺与个体的行。展开的结果只由（世界种子、地点）决定，与哪里先被看见、推进怎样分段无关；物化前后各项可观测量相等，账本只有转移与成对的转换。
3. **生成器只读表，只经写回器写。** 生成器是一组纯函数，输入是数据表、世界种子和已生成的行，输出是与手写内容同格式的行；它不含任何内容。文化、物种、职业、货品、名字全部来自各卷的表，代码里没有它们的代号。

北极星在本卷的落点：生成出来的每栋建筑由当地料、当地匠人技能与设施意图经卷十九的同一个纯计算推出；生成出来的每件器物由当地料、阶层技能代表值与意图经卷三乙的 `craftOutcome` 推出；没有按产物名写的材料或品质。

### 2.4 结构

- `struct:manifestRow = {ordinal: integer, intendedType: ref facility_type, form: ref vocab bform, areaM2: number, storeys: integer, wallThicknessM: number, materialKg: map<ref material, number>, zoneRole: ref vocab zrole nullable, ownerRef: struct:ownerKey, fixtures: list<ref vocab fixture>}`。`ownerKey = {aggregate: ref nullable, org: ref nullable}`，两者恰一个非空。
- `struct:shopRow = {ordinal: integer, shopkind: ref vocab shopkind, venue: integer（指向 manifestRow.ordinal）, operator: struct:ownerKey}`。
- `struct:rosterSpec = {species, culture, birthplace, bornMinute, sex, profession: ref profession nullable, origin: SeedKey, ordinal: integer}`：`instantiatePerson` 的入参，只有代号与数值。
- `item_group` 条目：`{mode: enum group_mode, entries: list<struct:groupEntry>}`；`struct:groupEntry = {pick: enum pick_kind, item: ref item nullable, itemRX: rx nullable, group: ref vocab item_group nullable, weight: integer ≥ 1, probPermille: integer [0, 1000], count: distribution（integer，下限 ≥ 0）, intent: 意图代号 nullable, containerRX: rx nullable}`。`pick` 取哪个值，对应的那一个字段非空，另两个为空。
- 表行的 `generated: struct{by: ref vocab gstage, seedKey: SeedKey, at: integer}`：字段名与位置归卷二 §1.2（表头）的公共字段表，本卷只定三个成员填什么（R10-9.2）。

### 2.5 运行态路径

| 路径 | 类型 | 唯一写者 | 含义 |
|---|---|---|---|
| `state.genesis` | struct{epochMinute: integer, openingMinute: integer} | `worldgen-writeback.mjs`（世界创建事务内一次写入，之后无改写写者） | 第 0 日时刻与开局时刻 |
| `state.genDone[placeId]` | set<ref vocab gstage> | `worldgen-writeback.mjs` | 这处地点已经做过哪些物化阶段；只增不减 |

`state.genDone[placeId]` 是以地点为键的领域记录，按卷二 §2.6（写者与三接口）“领域记录的去留”登记：地点终止时 `keep`，复生时 `keep`（毁掉的地方不会再物化一遍）。

### 2.6 存法登记

本卷没有逐次改写的数值存储量：`state.genesis` 一次写入；`state.genDone` 只做集合加入；`gen.*` 维度是静态的。本卷没有 `extScale` 字段、没有余数字段、没有锚点字段。凡把一个整数总量分给若干份的地方（人口、面积、基点、货量），一律按卷二 §3.3（求值管线）第 3 条：前几份向下取整、末份取差，各份之和恒等于总量，误差为 0；份的次序在各条规则里写明。

### 2.7 错误码

格式按卷二 §4.3（错误码表）；调用方只比较代码。

| 码 | 何时 |
|---|---|
| E-GEN-STAGE-UNKNOWN | 阶段条目引用了不存在的阶段或生成器 |
| E-GEN-STAGE-CYCLE | 阶段的 `after` 成环，或 `materialize` 相的阶段排在 `worldgen` 相之前 |
| E-GEN-ROW-INVALID | 生成的行没有通过与手写行相同的校验 |
| E-GEN-OVERRIDE-AUTHORED | 写回器要写的维度在作者数据里已有值 |
| E-GEN-BYPASS | 写回器之外的模块写生成行、`gen.*` 维度或本卷的运行态路径 |
| E-GEN-BRANCH-ORIGIN | 规则层按行是否带生成标记走不同分支 |
| E-GEN-ID-COLLISION | 两个不同的（父、位次、序位）导出了同一个 id，或导出的 id 与作者 id 相同 |
| E-GEN-SKELETON | 骨架不满足卷五的不变量 |
| E-GEN-REJECT | 世界命中 `rules.gen.reject.rows` 的某一行 |
| E-GEN-NAME-EMPTY | 某个必填槽在预算内没有候选成分 |
| E-GEN-GROUP-ROW | 物品生成组条目不合 §2.4 |
| E-GEN-GROUP-CYCLE | 物品生成组嵌套成环或超过深度上限 |
| E-GEN-LATE-SOURCE | 第 0 日之后的生成路径出现来源腿 |
| E-GEN-MANIFEST-DRIFT | 物化建行的明细与第 0 日清单不逐料相等 |
| E-GEN-DEFAULT | 开局缺省值来自代码常量或固定实体 id |
| E-GEN-NOT-MATERIALIZED | 规则要写一处尚未物化的地点之下的行而没有先请求物化 |

### 2.8 抽取点与位次登记

键的组成只按卷二十七 §4.8（种子键与骰值键（确定性约束与验收））的五段；流代号、抽取点代号、实例位次代号登记进种子键表。登记表在 §4.12.1，本节不重列。

#### 4.1.2 统一入口

读：`genPlan()`、`openingOf()`。写：`generateWorld()`（世界创建，一次）；`requireMaterialized()`（物化）。两者内部都只做“按 `genPlan()` 的次序调生成器、把提案交写回器”。

#### 4.1.3 规则

- **R10-1.1 流程是数据**：生成流程就是 `gstage` 族的全部条目。全序 = 先 `worldgen` 相后 `materialize` 相，相内按 `after` 的拓扑序，同层按代号升序。`after` 成环、或某个 `materialize` 相的条目出现在某个 `worldgen` 相条目的 `after` 链上，即 E-GEN-STAGE-CYCLE。代码里没有写死的阶段清单与次序。
- **R10-1.2 两相**：`worldgen` 相在世界创建时整相运行一次，全部写入发生在同一笔世界创建事务里，时刻为 `state.genesis.epochMinute`（第 0 日）。`materialize` 相在第 0 日之后按 §4.3 的触发逐地点运行。除此之外没有第三个生成时机。
- **R10-1.3 生成器是纯函数**：每个阶段的生成器签名是“（engine，作用域主体 id）→ 行提案与调用提案的列表”。它只读四样：数据表；世界种子；先行阶段已经写下的行与 `gen.*` 维度；`worldgen` 相里先行阶段在本事务内建立的第 0 日状态（开户余额、聚合体）。它不写任何东西；写入一律由写回器在核对之后完成（§4.9）。
- **R10-1.4 作用域与换序无关**：阶段按 `scope` 对每个主体各运行一次（世界一次；每个政区、每个模拟单元、每个站点、每块存量单元各一次），主体按 id 升序遍历。一个主体的结果只可依赖先行阶段的产出与本主体自己的抽取，不得依赖同一阶段里别的主体的产出；因此把遍历次序任意打乱，产出逐字节相同（A10-1.2）。需要“看邻居”的阶段读的是邻居在先行阶段的值。
- **R10-1.5 次序的道理写在 `after` 里**：先自然量，后群落（卷五派生，不占阶段），再矿物与生物，再开户；有了出产才定人口与站点；有了人才有邻省条款、设施、职业与财物；最后是历史预跑与开局。新增内容的卷只登记条目并写明 `after`，不改别的条目。
- **R10-1.6 阶段的适用条件**：`whenRX` 非空时，只对使它为真的主体运行；它只读该主体的基值维度与规则表键。骨架来自手写数据的世界里，骨架阶段就是靠这一条不运行的，没有“西陲专用流程”。
- **R10-1.7 手写优先，生成补缺**：作者数据里已有值的维度，生成器把它当输入读，不出提案；已有的行，生成器不再出同一序位的行。写回器收到与作者值冲突的提案即 E-GEN-OVERRIDE-AUTHORED。所以同一套流程既能从零生成一个世界，也能给手写世界补齐缺的部分。
- **R10-1.8 不合格即拒绝，不重掷**：`worldgen` 相的阶段全部跑完后，对 `rules.gen.reject.rows` 逐行求值（只读世界汇总量：政区数、站点数、总人口、未知维度计数等登记过的读数）；任一行为真即以该行的错误码结束，世界不创建。同一个世界种子永远只有一个结果；想要另一个世界就换种子。不存在“换一组随机数再试”的路径，键里也没有尝试次数。
- **R10-1.9 产出去哪里**：`worldgen` 相产出的行写进新世界自己的数据副本各表的 `generated` 节，此后与手写行经同一个加载器读入；第 0 日的账户余额、聚合体、存量开户在存档的状态里。`materialize` 相产出的行是 `state.created` 的偏离行。
- **R10-1.10 生成不读“被看见”**：任何生成器不读观察锚、有效层、世界时钟、事件日志与被时钟推进改写的状态路径（S10-8）。何时物化由世界内的事决定（R10-3.7），物化出什么与何时无关。
- **R10-1.11 成本口径**：`worldgen` 相不为任何居民、建筑、房间、店铺建行，它的工作量与政区数、存量单元数、站点数成比例；逐个体、逐建筑的工作量全部推迟到物化。这是“世界可以很大”的来源，降级与预算归卷二十七 §4.3（成本模型与降级阶梯）。

#### 4.1.4 交互

卷二 §1.3（行、继承与取值顺序）（三种行与覆盖顺序）；卷二 §2.7（系统声明表 `state-owners.json`）（建行写者登记）；卷二十七 §4.7（复演与规则只一版）（世界创建事务入日志）；卷二十七 §4.3（成本模型与降级阶梯）；卷十六 §4.11（程序生成怪物）、卷二十四 §4.7（历史生成）与卷七、卷八、卷八b（各登记自己的阶段条目）；卷二十八 §4.5（离线校验）（生成器产出的表在世界创建后可离线复核）。通道：声明写者、账本转移、派生读取。

#### 4.1.5 数据实例

- 【西陲】手写世界：`rules.gen.skeleton.source` 取 `authored`，骨架阶段的 `whenRX` 为假，不运行；自然量阶段只给缺 `stratum` 的存量单元补值；经济阶段照常给 31 个郡的全部站点算清单与配额。流程与新世界是同一份 `genPlan()`。
- 【非西陲】从一个新种子生成的世界：十三个 `worldgen` 相阶段依次运行，产出 3 个王国级政区、11 个省、40 个郡、320 块存量单元、96 个站点的行；没有一个居民行、没有一个建筑行。
- 【超自然】卷十六登记的程序生成怪物阶段排在自然量之后、开户之前：它产出的物种行带 `habitats`，开户阶段按卷五的规则把它们算进存量，不需要改流程代码。

#### 4.1.6 验收断言

- 扫描式：A10-1.1 生成流程代码里阶段代号字面量为 0；`generateWorld` 与 `requireMaterialized` 之外调用生成器的位置为 0；S10-1、S10-8 计数为 0。
- 不变量式：A10-1.2 同一世界种子、同一套数据表，两次世界创建得到的各表 `generated` 节与第 0 日存档摘要逐字节相同；把任一阶段内主体的遍历次序打乱后仍相同；命中拒绝行的种子两次都被拒绝且错误码相同。
- 扩展性式：A10-1.3 只加一条 `gstage` 条目与它的生成器文件（不改流程代码与别的条目），新阶段出现在 `genPlan()` 的正确位置并被执行；其余阶段的产出逐字节不变。

### 4.2 省郡骨架

#### 4.2.1 维度

`rules.gen.skeleton.*`、`rules.gen.classify.rows`、`rules.gen.border.rows`（§2.3）；`gfield` 族（§2.1）；`skeleton_source`、`classify_mode`；政区、存量单元、自然相邻边三种实例位次（§4.12.1）。地点行的字段、`juris` 族、`clause` 族、`borderTerms` 的格式全部归卷五 §4.14（省郡骨架、行政层级词表与邻省条款），本节不重定义。

#### 4.2.2 统一入口

读：`placeView()`（卷五；核对不变量时读 `tree`、`neighbors`、`regionLevel`）。写：骨架、自然量、邻省条款三个阶段的提案经写回器写地点行（卷五已把本卷的写回器登记为这些模式的建行写者）。

#### 4.2.3 规则

- **R10-2.1 两种来源，同一种行**：`authored` 时政区与存量单元来自手写数据，本节只补缺；`generated` 时按 R10-2.2 至 R10-2.5 生成。两者写成的都是卷五的地点行，规则层分不出来源。
- **R10-2.2 政区树**：从世界根开始，沿 `rules.gen.skeleton.levels` 自上而下逐级展开。对每个父政区，子政区个数 `n` 按该级的 `children` 分布抽取（键的对象是父政区 id）；第 `i` 个子政区（`i` 从 0 到 `n − 1`）的 id 由 `instanceIdOf(政区位次, 父 id, i)` 给出，`regionLevel` 取表里下一级的层级代号。表按 `juris.rank` 严格递减排列由加载校验保证，所以卷五“层级沿树严格递增”自动成立。
- **R10-2.3 存量单元**：最低一级政区之下，按 `rules.gen.skeleton.tracts` 抽取存量单元个数，id 由 `instanceIdOf(存量单元位次, 父 id, i)` 给出，挂存量单元的组件类（句柄 `rules.gen.roles.tract`）。地下存量单元、水域存量单元由分类规则（R10-2.7）命中相应条件时加挂组件类，不另立流程。
- **R10-2.4 面积与坐标**：每个子地点按 `rules.gen.skeleton.shareWeight` 抽一个整数权重 `w_i`（键的对象是子地点 id）。子地点面积按卷二 §3.3（求值管线）第 3 条分父面积：前 `n − 1` 份取 `floor(父面积 × w_i ÷ W)`，末份取差；`W` 是各权重之和，每个权重下限为 1，`W` 不小于 `n`，除数恒为正。坐标按网格排：列数 `k` 取满足 `k × k ≥ n` 的最小正整数，第 `i` 个子地点在第 `i mod k` 列、第 `floor(i ÷ k)` 行（除数 `k` 是正整数），格心坐标由父地点的范围等分得出。根的面积取 `rules.gen.skeleton.rootAreaM2`。
- **R10-2.5 自然相邻边**：同一父地点下，网格上四邻的两个子地点之间建一条边；两个相邻的父地点之间，在各自的子地点里取格心距离最小的一对建一条边，并列时取两端 id 字典序最小的一对。边的通路类型取 `rules.gen.roles.adjacentEdge`。政区是否相邻仍由卷五从边派生，本卷不写邻居字段。道路、渡口、干道不在本节：站点之间的路网归卷十七 §4.9（远方路网），本卷只把站点集合与自然相邻边交给它。
- **R10-2.6 场沿包含树逐级加偏差**：对每个 `gfield` 条目 `f` 与每个作用域内的地点 `p`，`值 = 钳到 f.range 之内（Σ 对 p 的祖先链上每个地点 a，含 p 自己：dev(a, f)）`。`dev(a, f)` 是按 `f.levels[a 的层级代号]` 的分布、以（`a` 的 id，`f` 的代号）为键经卷二 §1.10（随机实例化）的采样函数取得的偏差；`f.levels` 没有该层级时偏差为 0。同省的地点共享省一级的偏差，所以相近的地方相似，这就是“分形填充”，没有另造的噪声函数与格点键。结果写进 `f.target` 所指的地点维度（海拔、露天比例、森林覆盖等卷五规定手填的自然量）；作者已填的不写。
- **R10-2.7 枚举维度由分类规则定**：`rules.gen.classify.rows` 按 `target` 分组。`mode` 为 `first` 的组（地形、岩层一类单值维度）：取 `whenRX` 为真的行里 `priority` 最大者的 `value`，并列取代号字典序最小；没有任何行为真时该维度记未知，若它是必填维度则该行不过校验（E-GEN-ROW-INVALID），不拿常量兜底。`mode` 为 `all` 的组（水体可及一类集合维度）：取全部为真的行的 `value` 之集合。`whenRX` 只读本行已写的数值维度、父行的维度、以及相邻行同名维度经卷二 §1.12（派生与聚合原语）的聚合读数。群落不在这里定：它由卷五从这些自然量派生。
- **R10-2.8 天气单元行的静态字段同一机制**：卷二十登记在天气单元行上、要求世界生成时填的静态字段，各由一条 `target` 指向它的 `gfield` 条目给值，走 R10-2.6；本卷不持有气候算式。
- **R10-2.9 邻省条款的开局值**：对每一对相邻的同级政区（有序对，条款可以不对称）与 `rules.gen.border.rows` 的每一行，`valueRX` 对“这一对政区”求值，可读的变量是登记过的数值：两方主文化的接纳系数（卷七的 `acceptance().factor`）、是否有共同的上一级政区、两方边境指数。结果写进 `borderTerms`。本阶段排在开局人口之后，因为主文化由居民构成派生。
- **R10-2.10 生成后核对**：骨架、自然量两阶段结束时，写回器对产出核对卷五 §4.14（省郡骨架、行政层级词表与邻省条款）与卷五 §4.1（地点包含树与坐标）的不变量（层级单调、每个非根地点恰属于每个更高层级的至多一个政区、同父非地下子地点面积和不超过父地点、地表存量单元互不嵌套）；任一不成立即 E-GEN-SKELETON。
- **R10-2.11 政体不在骨架里**：政区行不存“谁统治它”。开局的政体、持有与职位由卷八登记的阶段按维度生成（§5.3）。

#### 4.2.4 交互

卷五 §4.1（地点包含树与坐标）、卷五 §4.3（地形、群落与海拔维度表）、卷五 §4.14（省郡骨架、行政层级词表与邻省条款）；卷二十 §4.3（天气状态与地区现象）（天气单元行的静态字段）；卷七 §4.23（接纳、融合与分化）（接纳系数）；卷十七 §4.9（远方路网）；卷八 §4.4（头衔与法理）（读层级）；卷二十七 §4.1（三层模拟运行矩阵）（模拟单元取自骨架）。通道：声明写者、派生读取。

#### 4.2.5 数据实例

- 【西陲】九省 31 郡是手写行，`source` 为 `authored`：政区树与面积不生成；自然量阶段只为缺岩层的存量单元按分类规则补 `stratum`；邻省条款原有的文字改成条款代号到数值之后也是作者值，条款阶段不覆盖。
- 【非西陲】新世界的一个省抽得 `n = 4` 个郡：列数 `k = 2`，序位 3 的郡在第 1 列第 1 行。四个权重抽得 3、1、2、2，`W = 8`；省面积 80000（示例单位），前三份为 30000、10000、20000，末份 80000 − 60000 = 20000。海拔场在省一级偏差 +400、郡一级 −120、存量单元一级 +35，该单元海拔为 315（未触及钳位）。
- 【超自然】一条 `target` 指向地点超自然浸染基值的 `gfield` 条目，只在最低两级有偏差分布：个别存量单元抽到高值，卷五的群落包络据此派生出异化群落。骨架代码不知道“浸染”这回事。

#### 4.2.6 验收断言

- 扫描式：A10-2.1 生成器里政区名、政体名、地形文字的匹配为 0；层级代号、地形代号、条款代号的字面量为 0；地点行上手写的邻居字段为 0。
- 不变量式：A10-2.2 任一种子生成的骨架满足 R10-2.10 的四条；各子地点面积之和恒等于父面积；任一地点的任一场值只依赖它的祖先链与场条目，与兄弟地点的个数和次序无关；同一对相邻政区的条款值两次生成相同。
- 扩展性式：A10-2.3 在 `rules.gen.skeleton.levels` 中间插入一个新层级（卷五加一条 `juris` 条目），不改代码：生成的树多出一层，场的偏差、模拟单元、邻省条款自动适用；新增一条 `gfield` 条目，对应维度即被填值。

### 4.3 远方聚落按需物化

#### 4.3.1 维度

站点行上的 `gen.share`、`gen.layout`、`gen.manifest`、`gen.quota`、`gen.shops`（§2.2）；`state.genDone`（§2.5）；`rules.gen.site.*`（§2.3）；`materialize` 相的阶段条目（§4.1.1）；站点位次（§4.12.1）。站点类型条目归卷五 §4.6（站点类型）。

#### 4.3.2 统一入口

读：`genView()`、`materialized()`、`manifestOf()`。写：`requireMaterialized()`（唯一物化入口）。

#### 4.3.3 规则

- **R10-3.1 站点在第 0 日就是行**：选址阶段为全世界每个站点建一行地点行（挂聚落组件类，句柄 `rules.gen.roles.settlement`；`parent` 是它坐落的存量单元），写站点类型、发展度、控制度、面积、`nameParts` 与 `gen.*` 维度。站点之下的分片、建筑、房间、店铺、居民在第 0 日都不是行。
- **R10-3.2 选址读土地，不掷骰**：对每个模拟单元 `U`（卷二十七的 `simUnitOf`），站点数 `K = lookup(rules.gen.site.perUnit, 潜力人数(U))`（潜力人数见 R10-4.1）；候选是 `U` 内的地表存量单元，各按 `rules.gen.site.scoreRX` 求得分（可读该单元的资源场汇总、水体可及、坡度、相邻边数等登记过的读数）；取得分最高的 `K` 块，并列按 id 升序；候选不足 `K` 块时全取。第 `j` 个入选单元上的站点 id 为 `instanceIdOf(站点位次, 存量单元 id, 0)`。
- **R10-3.3 站点份额**：入选站点按得分分 10000 基点，写进 `gen.share`：得分换成整数权重后按卷二 §3.3（求值管线）第 3 条分（站点按 id 升序，末份取差）；全部得分为 0 时各站点权重取 1。得分之和为 0 的情形已由“权重取 1”覆盖，权重和不小于站点数，除数恒为正。站点的开局人数 = 所在单元各居民聚合体人数按 `gen.share` 分得的份额之和，只在生成期用来定类型、清单与配额；运行期“这里有多少人”只读卷八的 `popView`。
- **R10-3.4 站点类型同律**：站点类型取卷五 `site` 族里资格对该站点成立（人口区间、是否常住、是否要求围护）的条目中 `rank` 最大者，并列取代号字典序最小；判法与卷五运行期的升降是同一个资格函数。没有任何条目成立的候选站点不建，它的权重从 R10-3.3 中去掉后重分一次，其余站点重选一次类型；重分后仍有站点无条目成立即 E-GEN-ROW-INVALID（`site` 族没有覆盖这个人口区间，是数据缺口）。
- **R10-3.5 发展度与控制度的开局值**：由 `rules.gen.site.developmentRX`、`rules.gen.site.controlRX` 对站点求值（可读开局人数、站点类型的 `rank`、到上级政区内 `rank` 最大站点的距离等登记过的读数），写进卷五的两个维度；之后的变化归卷五 §4.9（发展度与控制度）。
- **R10-3.6 物化分阶段、可重入**：`requireMaterialized(place, stage)` 先对 `stage` 的 `after` 链上属于 `materialize` 相的阶段递归调用，再运行本阶段的生成器、把提案交写回器、把 `stage` 加入 `state.genDone[place]`。已在集合里的阶段直接返回，不重做。首批四个阶段：分片（§4.7）、建筑与房间（§4.7）、店铺（§4.7）、居民安置（§4.4）。
- **R10-3.7 触发只有两种，都是世界里的事**：① 站点所在模拟单元的有效层成为个体层（与卷二十七 R27-2.6“全部成员实体化”同一时刻、同一事务）：对该单元每个站点（按 id 升序）请求全部物化阶段。② 某条规则要在一处未物化的站点之下建行、或要拿到其下某一行的 id（指名一栋建筑、向一家店下订单、让一名成员分户入住）：该规则先调 `requireMaterialized` 请求它所需的阶段；不请求而直接写即 E-GEN-NOT-MATERIALIZED。两种触发都发生在引起它的那笔事务里，在同刻全序中的位置由那笔事务决定，与推进请求怎样切分无关。
- **R10-3.8 物化出什么只由（世界种子、地点）定**：物化阶段的生成器只读该站点的 `gen.*` 维度、数据表与世界种子（R10-1.10）。物化那一天当地实际有多少人、有什么料、世界日是几，都不进生成器。所以先物化甲再物化乙、或次序相反、或相隔十年，产出的行与 id 逐字节相同。
- **R10-3.9 物化只有转移，没有来源**：建筑建行时，墙料与未物化建筑份额从所在地点聚合账户的未物化预置分区记出、实例的建筑份额成对记入，记账口径全部归卷六 §4.1（账本三元键与守恒）规则 5“物化建行”；店铺货架、家户家当、个人行囊都是从阶层聚合账户到新账户的转移（卷二十七的分户）。任何物化路径出现来源腿即 E-GEN-LATE-SOURCE。
- **R10-3.10 物化等价**：对任一站点、任一物化阶段，物化前后下列读数相等：`popView` 的总人数与物种、文化构成；每种资源在该站点包含树内全部账户的余额之和；按设施类型计的设施数（未物化时由清单经卷十九同一个类型派生函数计，§5.3）。
- **R10-3.11 物化不回收**：地点、建筑、房间、店铺的行一经建立不因单元离开个体层而删除；居民个体是否折叠回聚合体归卷二十七 §4.2（聚合变体、等价、钉住）。
- **R10-3.12 手写站点同路**：作者写的站点可以带作者的 `gen.manifest`，也可以不带、由经济阶段补；作者已经写成行的建筑、店铺占掉清单里与之 `ordinal` 相同的序位，物化时跳过。全部内容都已手写的站点，第 0 日即把四个物化阶段记入 `state.genDone`。
- **R10-3.13 哪里有什么怪物不在本卷存表**：远方出没什么生物，由物种行的 `habitats` 与卷五的存量派生给出；传说与索引归卷十六 §4.4（妖怪志与传说真相层）。本卷不存“地区到物种”的对照。

#### 4.3.4 交互

卷二十七 §4.1（三层模拟运行矩阵）、卷二十七 §4.2（聚合变体、等价、钉住）（触发 ① 与实体化同一事务；居民用卷八登记的聚合种类行，本卷不登记新行）；卷五 §4.6（站点类型）（资格函数）、卷五 §4.9（发展度与控制度）；卷六 §4.1（账本三元键与守恒）、卷六 §4.22（源汇标记与月度经济报告）（第 0 日入账与物化记账）；卷十九 §4.4（建造需求与地形前后）（物化建行）；卷十七 §4.9（远方路网）；卷十四 §4.11（教育与童年）（物化时的初始技能）；卷七 §4.20（文化五支柱）（按文化行生成，不按文化代号分支）；卷十六 §4.4（妖怪志与传说真相层）。通道：声明写者、账本转移、派生读取。

#### 4.3.5 数据实例

- 【西陲】远方一个郡（一个模拟单元）开局 3200 人、4 个站点，份额 5000、2500、1500、1000 基点；份额 2500 的集镇开局人数 800，站点类型取人口区间含 800 的条目里 `rank` 最大者，清单 180 行。玩家进入该郡的那一刻，单元成为个体层，四个站点依次物化四个阶段；物化后 `popView` 仍是 3200，账本各资源总量不变。
- 【非西陲】海岛上一座渔村一直处在统计层。大陆一名商人向它的鱼行下远期订单：成交规则调 `requireMaterialized(渔村, 店铺阶段)`，递归做完分片、建筑与房间，再建店铺行；居民安置阶段没有被请求，村民仍是聚合体成员。
- 【非人类】一座地下巢城：站点类型是卷五的巢穴类条目，居民是非人物种的聚合体，清单里的形制是该物种自带技能的巢室形制。它与人类集镇走同一组阶段、同一个 `requireMaterialized`。

#### 4.3.6 验收断言

- 扫描式：A10-3.1 生成与物化代码里的地点 id、物种 id、文化 id、物品 id 字面量为 0；对地点显示名、大纲文字的读取为 0；`requireMaterialized` 之外建立站点后代行的生成路径为 0；S10-7 计数为 0。
- 不变量式：A10-3.2 物化等价（R10-3.10）对随机抽取的站点与阶段成立；任意两种物化次序、任意物化时刻得到的行集合逐字节相同；重复请求同一阶段不改变状态；一次推进 N 天与分段推进合计 N 天得到同一份存档摘要。
- 扩展性式：A10-3.3 新增一条文化行（带命名库、`gen.homelandRX`、`gen.speciesWeights`）、一条物种行、一条职业行、一条 `shopkind` 条目，不改代码：新世界里出现该文化的站点，居民、职业、店铺、名字都按新行生成；生成 100 个这样的站点并全部物化，全部通过与手写内容相同的校验。

### 4.4 名册与人口配额

#### 4.4.1 维度

`gen.speciesWeights`、`gen.homelandRX`、`gen.homelandWeight`、`gen.quota`（§2.2）；`struct:rosterSpec`（§2.4）；`rules.gen.pop.*`（§2.3）。居民聚合种类行归卷八 §4.16（人口统计层、承载力、迁徙、移民波次），成员身份归卷二十七 §4.2（聚合变体、等价、钉住）。本卷向卷九 §4.11（一致性审查）的声明种类注册表登记两行（人物档文字里的年龄声称与亲属声称）：

```json
  "ck_person_age": {"detect": "ledger", "subjectKind": ["person"], "predicates": ["age"], "valueType": "integer", "evidence": "evidence_person_age", "labels": {"zh": "年龄声称", "en": "Age claim"}},
  "ck_person_kin": {"detect": "ledger", "subjectKind": ["person"], "predicates": ["kin"], "valueType": "ref", "evidence": "evidence_person_kin", "labels": {"zh": "亲属声称", "en": "Kin claim"}}

```

#### 4.4.2 统一入口

读：`rosterOf()`、`quotaOf()`、`ageStructure()`、`genView().potentialPop`。写：开局人口经卷八的 `popApply` 提交；个体经卷四的 `instantiatePerson`；技能初值经卷十四的 `seedSkills`。本卷不写人物表的任何维度。

#### 4.4.3 规则

- **R10-4.1 潜力人数由土地出产推出**：对模拟单元 `U`，`潜力人数 = floor(日可食能量(U) ÷ 人均日需能量(U))`。日可食能量 = `U` 内各存量单元各资源场的可持续日产（卷五 §4.7（资源场、再生律与栖地容量）规则 7 的同一个量）× 该存量对象可食产物的能量密度（卷三乙的营养读数），再加可耕地按卷二十五生长函数给出的年产折成的日量（§5.3）。人均日需能量 = `Σ（w_s × 物种 s 的日需能量）÷ Σ w_s`，`w_s` 取落位在 `U` 的文化的 `gen.speciesWeights`，日需能量读卷四 §4.7（代谢）经 `rules.gen.pop.needRole` 指定的量；`Σ w_s` 由 §2.2 的校验保证大于 0，日需能量的取值域下限大于 0，两个除数都恒为正。`U` 没有落位文化时潜力人数未知，不建站点，不拿 0 以外的数顶替。
- **R10-4.2 文化落位**：在 `rules.gen.pop.cultureLevel` 这一级的每个政区上，候选是 `gen.homelandRX` 对该政区为真的文化行；按 `gen.homelandWeight` 做加权抽取（卷二 §1.10（随机实例化）的 categorical，键的对象是政区 id），抽中者是该政区的开局主文化。没有候选时该政区无人定居。手写世界里地点已有的居民与文化是作者值，本条不运行（R10-1.7）。
- **R10-4.3 开局人数**：`总人数(U) = floor(潜力人数 × 充盈度)`，充盈度按 `rules.gen.pop.fillDist` 抽取（键的对象是 `U`），定点乘后向下取整。
- **R10-4.4 构成**：先分文化，再分物种，两步都按卷二 §3.3（求值管线）第 3 条分整数（按代号升序，末份取差）。文化权重（基点）照卷五 §4.15（边境混居与迁徙表达）规则 2：邻方权重 = 边境指数 × 接纳系数，各层级相加，边境指数未知的层级不参加；主文化取 10000 减去各邻方之和，不足 0 时取 0 并把邻方按比例压到合计 10000。每个文化内按它的 `gen.speciesWeights` 分物种。每个（物种，文化）得到一个居民聚合体，这就是卷八那一行的分组键。权重和为 0 的文化不参加分配（§2.2 的 gap），不做除法。
- **R10-4.5 开局年龄结构由生死率推出**：`ageStructure(species, n)` 对 `rules.gen.pop.bandsRole` 所指年龄段表的每一段 `b`，取卷四 `vitalRates` 在该段下界的年死亡率，算出“活到该段起点的比例 × 段宽”作为该段的整数权重（定点连乘，截断后钳到不小于 1），再把 `n` 按权重分给各段（末份取差）；权重各不小于 1，权重和恒为正。各段成员的出生时刻取 `epochMinute` 减去该段下界年龄对应的分钟数。没有手写的年龄金字塔；寿命长的物种自然老人多。
- **R10-4.6 写成聚合体**：开局人口阶段把每个聚合体的各年龄段人数与出生时刻作为一份“开局建群”提案交卷八的 `popApply`（该提案种类由卷八增设、只许在世界创建事务内使用，§5.3）；成员序号从 0 起由卷二十七的聚合写者发放。手写的具名个体不在成员区间里，按卷八 R8-16.1 另计：他们常住的单元里，对应（物种，文化）的生成人数先减去手写人数，减到 0 为止。
- **R10-4.7 职业配额是工位的结果**：经济阶段对每个站点读卷六的 `stationPlan`，把各活动的实际工位数换成职业：一项活动所要的服务代号与工作站，对应卷十四 `professionView` 中提供该服务的职业行；同一本体有文化变体时，取 `cultures` 含站点主文化的变体，没有则取本体。再加上清单里各设施按卷十九工位表所需的从业者、店铺的经营者（R10-7.6）、站点类型 `governed` 为真时卷八给出的治理席位。逐职业求和写进 `gen.quota`。没有按文化写的职业清单。
- **R10-4.8 名册条目是成员身份的纯函数**：`rosterOf(aggregate, ordinal)` 返回的物种与文化取聚合体的分组键；出生时刻取成员区间；出生地按所在单元各站点的 `gen.share` 加权抽取；名册职业只对卷四判为成年的成员给出，按出生地站点的 `gen.quota` 加权抽取，另有一项“无名册职业”的权重 = 该站点开局成年人数 − 配额之和（为负取 0）。两次抽取的键的对象都是该成员的实例 id（R10-12.2），所以同一个成员无论何时、被实体化几次，名册条目都相同。配额之和与无职业权重都为 0 时不抽，职业为空。
- **R10-4.9 实体化是别卷的事**：卷二十七实体化一名成员时，以 `rosterOf` 的结果调卷四的 `instantiatePerson`；未给的维度由卷四按遗传或采样取值；技能初值由卷十四的 `initialSkills` 算、`seedSkills` 写；名字由 §4.5 给出。本卷不存名册，不存人物档。
- **R10-4.10 居民安置阶段**：对站点里已实体化的成员，按卷十八提供的家户与亲属派生函数（§5.3）建立家户与亲属边，经卷十八的关系写者写入并过它的检查点；按实例 id 升序把有名册职业的成年成员配到清单里同职业的工位（工位按清单序位升序），经卷六的合同入口签雇佣；住处按家户配到清单里的住处（同样按序位）。配不上的留作无业或无固定住处，由运行期的劳动市场与租房规则接手。
- **R10-4.11 模型不写人物档的规则字段**：凡影响规则的字段（人数、构成、年龄、亲属、职业）一律由上面各条按种子键得出。模型只能为一名已实体化的个体写介绍文字，走文字路径、过卷九 §4.19（输入边译码器与入库前守门）。文字里关于年龄与亲属的说法由模型以结构化声明给出，种类即 §4.4.1 登记的两行，由卷九 §4.11（一致性审查）拿 `personView` 的年龄与卷十八的 `kinView` 比对数值与代号；不一致时文字不入库，规则状态不变。规则层不解析这段文字。
- **R10-4.12 校验器不带词表**：生成名只存成分代号，名字的屏蔽词检查在内容构建时离线完成（卷二十八 §4.5（离线校验））；人口模板与生成档案校验器不带任何词表参数与 `blocked` 字段。职务与头衔由持有与任职边保证，不靠背景文字里出现头衔字样。

#### 4.4.4 交互

卷八 §4.16（人口统计层、承载力、迁徙、移民波次）（`popApply`、`popView`、`stratumSkill`）；卷二十七 §4.2（聚合变体、等价、钉住）（成员身份、实体化）；卷四 §4.4（年龄、成长、寿命、出生与死亡率）、卷四 §4.10（人物本体与 personView）；卷五 §4.15（边境混居与迁徙表达）；卷六 §4.7（生产组织：资源、劳动到物品）（`stationPlan`）、卷六 §4.11（劳动市场与工作分配）；卷十四 §4.1（职业维度表与服务词表）、卷十四 §4.2（职业文化变体）、卷十四 §4.11（教育与童年）；卷十八 §4.2（家户、亲属、婚配、继承、分家、监护）、卷十八 §4.9（婚配制度、性风俗、儿童与老人）；卷九 §4.11（一致性审查）、卷九 §4.19（输入边译码器与入库前守门）；卷二十八 §4.5（离线校验）。通道：声明写者、派生读取。

#### 4.4.5 数据实例

- 【西陲】一个郡开局 3200 人。主文化 8200 基点、邻省文化 1800 基点：`floor(3200 × 8200 ÷ 10000) = 2624`，末份 3200 − 2624 = 576。主文化的物种权重 62、32、6：`floor(2624 × 62 ÷ 100) = 1626`，`floor(2624 × 32 ÷ 100) = 839`，末份 2624 − 1626 − 839 = 159。这三个数从文化行的维度来，换一个郡名不会变。
- 【非西陲】草原上的一个模拟单元：出产以牧草存量为主，潜力人数低；站点类型里只有“非常住”的营地类条目资格成立；`stationPlan` 给出的工位几乎全是放牧，`gen.quota` 因而以牧人为主。没有“草原文化职业清单”。
- 【非人类】一种寿命三百年的长寿物种：`vitalRates` 在各年龄段的死亡率都低，`ageStructure` 给出的各段人数接近均匀；同一条规则对寿命四十年的物种给出明显偏年轻的结构。
- 【超自然】一名成员被实体化后，模型为他写介绍，声明里带 `{predicate: age, value: 19}`，而 `personView` 的年龄是 43：审查判不一致，这段文字不入库；人物的年龄仍是 43，名册与存档摘要不受影响。

#### 4.4.6 验收断言

- 扫描式：A10-4.1 生成代码里按地点 id、政区名定人口或比例的分支为 0；物种 id 常量表、各文化职业清单为 0；从名字、描述、大纲文字推物种、性别、年龄、人口的读取为 0；人口模板与校验器的词表参数为 0；S10-9 计数为 0。
- 不变量式：A10-4.2 每个模拟单元第 0 日各聚合体人数之和加手写个体数等于 R10-4.3 的总人数（手写多于生成时等于手写数）；各文化、各物种、各年龄段的份数之和恒等于被分的总数；`rosterOf` 是纯函数，同一成员任意次调用结果相同；开着与不开文字模型，除文字路径外全部状态逐值相等。
- 扩展性式：A10-4.3 新增一条物种行并在某文化行的 `gen.speciesWeights` 里给权重，不改代码：新世界里该文化的站点出现这个物种的聚合体，实体化出的个体通过卷四的全部校验；把一个手写个体换成同键的生成成员，卷四、卷十四对个体的全部断言仍通过。

### 4.5 命名生成算法

#### 4.5.1 维度

`rules.gen.name.*`（§2.3）；命名位次的抽取点（§4.12.1）。命名库、结构、成分三族与文化行的 `naming` 归卷七 §4.27（语言与命名表）；`nameParts` 的结构归卷二 §1.9（代号、显示名与语言边界）。本节不新增任何存储。

#### 4.5.2 统一入口

读：`composeName()`（全书唯一的命名生成入口）；它读卷七的 `nameTable()`。写：无；`nameParts` 由建行的写者随行写入。

#### 4.5.3 规则

- **R10-5.1 入参只有代号**：`composeName(engine, entityKind, cultureId, instanceId)`。实体类是卷二的 22 类代号；文化取该实体的文化（个体取名册条目的文化，地点、店铺、组织取所在站点的主文化）。没有文化的实体取 `rules.gen.name.fallbackBank` 所指的命名库。
- **R10-5.2 选结构**：在 `nameTable(culture)` 展开的命名库里，取 `entityKind` 等于入参的全部结构项，按结构代号升序排，以各项的 `weight` 做整数加权抽取（卷二 §1.10（随机实例化）的 categorical；权重各不小于 1，和恒为正）。该库对这类实体没有任何结构项时即 E-GEN-NAME-EMPTY；卷七的加载校验已保证这种情形不进世界数据。
- **R10-5.3 逐槽填成分**：按结构的槽位次序处理第 `j` 个槽（`j` 从 0 起，不超过 `rules.gen.name.maxSlots`，超过即加载失败）。可选槽先用第 `j` 个“出现”位次抽一个千分数，不小于 `rules.gen.name.optionalPermille` 时跳过该槽。候选 = 声明自己可填这个库、这个槽的成分条目中，音节数满足预算者，按成分代号升序排；用第 `j` 个“取词”位次的均匀整数对候选个数取模得到下标（候选个数不小于 1 才取模；为 0 时，可选槽跳过，必填槽 E-GEN-NAME-EMPTY）。
- **R10-5.4 音节预算是筛选，不是重掷**：候选的音节数须使“已用音节 + 它 + 其余必填槽各取最少音节”不超过库的音节上限，且“已用音节 + 它 + 其余全部槽各取最多音节”不低于库的音节下限。预算只缩小候选集，每个槽只抽一次；不存在“抽到不合适就再抽”的循环。每个结构在预算内至少有一种填法由内容构建时的离线校验保证（卷二十八 §4.5（离线校验），§5.3）。
- **R10-5.5 `seq`**：地点、店铺、组织这类在同一笔事务里成批建立的实体，同一父地点下成分完全相同者按实例 id 升序依次得 0、1、2……；个体的 `seq` 恒为 0，重名是允许的，区分靠 id。`seq` 不进入任何抽取键。
- **R10-5.6 不检查屏蔽词、不换种子**：运行期命名不读任何屏蔽词表，不因任何显示上的考虑改抽取结果；这条禁令与显示闸的替换归卷二 §1.9（代号、显示名与语言边界）。
- **R10-5.7 名字跟着实例 id 走**：全部抽取的键的对象是实例 id（R10-12.2），所以同一个成员无论何时实体化都是同一个名字；`nameParts` 在建行时随行写入，计入存档摘要，拼出的文字不在状态里。
- **R10-5.8 手写名不重生成**：作者给了 `nameParts` 或静态显示名的实体不调本入口（R10-1.7）。
- **R10-5.9 规则层只见成分代号**：本节任何一步不读成分的显示文字、不读语言包；换一种显示语言，世界状态与存档摘要不变。

#### 4.5.4 交互

卷七 §4.27（语言与命名表）（`nameTable`、三族）；卷二 §1.9（代号、显示名与语言边界）（`nameParts` 结构与禁令）；卷二十九 §4.1（显示层隔离契约）（拼装）；卷二十八 §4.5（离线校验）（成分、组合与可填性）；卷四 §4.10（人物本体与 personView）、卷五 §4.1（地点包含树与坐标）、卷六 §4.5（店铺经营与补货）、卷八 §4.1（实体与组织统一结构）（各类建行时调本入口）；卷七 §4.8（创建与改革仪轨）、卷七 §4.11（神祇）（新建的信仰行与神祇行同样调本入口）。通道：只读。

#### 4.5.5 数据实例

- 【西陲】河谷文化的人名结构是两个必填槽：姓、名。姓槽候选 40 条，取词位次的均匀整数为 1000003：`1000003 mod 40 = 3`，取升序第 4 条成分；名槽照此。得到的 `nameParts` 里只有两个成分代号。
- 【非西陲】草原文化的人名结构是“名、父名”，没有姓槽；库的音节上限为 4，名槽取了 3 音节的成分后，父名槽的候选只剩 1 音节的成分。算法没有任何一行知道“草原”。
- 【超自然】一位生成的神祇：结构里有一个可选的称号槽，出现位次抽得 412，`rules.gen.name.optionalPermille` 为 300，412 不小于 300，称号槽跳过。同一位神在任何时候被读到，都是这同一组成分。

#### 4.5.6 验收断言

- 扫描式：A10-5.1 代码里的字库、姓氏表、按文化代号选命名规则的分支为 0；`composeName` 之外对命名三族的抽取为 0（S10-6）；本节文件 import 语言包、屏蔽词表为 0；命名路径上的循环重抽为 0。
- 不变量式：A10-5.2 `composeName` 是纯函数；产出的每个成分都声明可填所在库的所在槽；必填槽全部有成分；总音节数在库的上下限之内；切换显示语言前后存档摘要相同；新增一个与命名无关的抽取点不改变任何已有名字。
- 扩展性式：A10-5.3 新增一条命名库及其结构与成分并让一条文化行指向它，不改代码：该文化的新实体按新库得名；给已有库加一条结构项，只有抽到它的实体的名字结构变化。

### 4.6 栖地派生（生成期）

#### 4.6.1 维度

本节不新增维度。读卷五 §4.3（地形、群落与海拔维度表）的地点侧字段与群落条目、卷五 §4.4（地质与矿脉）的矿物赋存行；赋存项位次与两个抽取点见 §4.12.1。

#### 4.6.2 统一入口

读：`placeView()`（`biome`、`stocks`、`habitatCapacity`、`resourceFields` 全部由卷五派生）。写：矿物键经写回器（建行写者）；开户调卷五的 `openStocks`；耕作记录调卷二十五的入口。

#### 4.6.3 规则

- **R10-6.1 本卷不算栖地**：一块地上长什么、养什么、容量多少，全部由卷五从自然量与群落条目派生。生成期只做三件事：写自然量（§4.2）、写矿物键（R10-6.2）、请卷五开户（R10-6.4）。本卷没有“地形到栖地”的对照，也不读地点的任何文字。
- **R10-6.2 矿物键按赋存行生成**：对每块存量单元与卷五矿物赋存表的每一行，先看该行的岩层、地形、水体条件对这块单元是否成立；成立时以“赋存项”为对象抽一个万分数，小于该行 `frequency` 换成的基点即有此矿物。赋存项的 id 由 `instanceIdOf(赋存项位次, 存量单元 id, 该行在表内的序位)` 给出，序位是数据表的行序，不是调用计数。有矿时再以同一对象、另两个抽取点按该行的 `richness`、`depthM` 分布取丰度评分与埋深，写进 `deposits` 与 `depositDepthM`。储量换算与入账归卷五。
- **R10-6.3 岩层**：存量单元的主岩层类由分类规则（R10-2.7，`target` 为岩层维度）从场值与地形得出。
- **R10-6.4 全世界在第 0 日开户**：开户阶段对每个模拟单元，在其全部地点行写完之后，按存量单元 id 升序各调一次 `openStocks`；每个账户的初始余额由卷五按（世界种子、存量单元、存量对象）给出。第 0 日之后本卷不再调它：运行期多出的存量对象由卷五的每日结算开户。
- **R10-6.5 巢穴没有专条**：非人物种的据点是卷五站点类型的一行，住在里面的是该物种所属文化的居民聚合体，走 §4.3、§4.4 的同一条路；不通人言的野兽是卷五的存量，不建站点。本卷不为“已播种的巢穴”保留任何单独的流程。
- **R10-6.6 开局耕地用同一判据播下**：经济阶段里，`stationPlan` 给出耕作类活动的工位时，调卷二十五的耕作开工入口在相应存量单元上建立耕作记录，判据与运行期开工相同（§5.3）；本卷不设“农田”这种地点，也不直接写在田作物的余额。
- **R10-6.7 生成期与运行期读同一入口**：任何要在生成期知道“某物种在某地的容量”的规则只读 `placeView().habitatCapacity`，与运行期是同一个函数；规则表键 `habitatDerivation` 与文字匹配退役。

#### 4.6.4 交互

卷五 §4.3（地形、群落与海拔维度表）、卷五 §4.4（地质与矿脉）、卷五 §4.7（资源场、再生律与栖地容量）（`openStocks`、容量派生）；卷四 §4.1（物种统一 schema）（`habitats`）；卷十六 §4.11（程序生成怪物）（生成的物种行同样带 `habitats`）；卷二十五 §4.2（农事历、播种收割与歉收）（耕作记录）；卷六 §4.22（源汇标记与月度经济报告）（初始储量的开局来源）。通道：声明写者、账本转移、派生读取。

#### 4.6.5 数据实例

- 【西陲】一块河谷存量单元：场值经分类规则得平原类地形，卷五派生出温带草地类群落，`openStocks` 为该群落的野生植物与食草兽开户。某条铁矿赋存行的条件成立，`frequency` 为 0.25 即 2500 基点，抽得 2100，小于 2500：有矿，再抽丰度与埋深。
- 【非西陲】一块高纬山地存量单元：手填量只有海拔与同省别处不同，卷五派生出高山冻原类群落，开户的对象随之不同。生成代码对两块单元做的事完全相同。
- 【非人类】一处洞穴存量单元挂在山地单元之下：分类规则命中“埋深大于 0”的条件后加挂地下属性，卷五派生无光群落，洞居物种因 `habitats` 含该群落而开户。附近若有以它为居民的巢穴站点，那是 §4.3 选址的结果。

#### 4.6.6 验收断言

- 扫描式：A10-6.1 本卷文件里的群落代号、物种 id、矿物 id 字面量为 0；对地点地形文字、群落文字的匹配为 0；`placeView` 之外的栖地推导函数为 0；第 0 日之后调用 `openStocks` 的生成路径为 0。
- 不变量式：A10-6.2 每块存量单元的 `deposits` 键都是某条条件成立的赋存行的键；同一种子两次生成的矿物键、丰度、埋深与全部初始余额相同；在赋存表末尾加一行不改变已有各行的抽取结果。
- 扩展性式：A10-6.3 新增一条群落条目与一条 `habitats` 含它的物种行，不改代码：新世界里包络成立的存量单元自动为该物种开户；新增一条赋存行，条件成立的单元按频度出现该矿物。

### 4.7 聚落街区、布局与商店派生

#### 4.7.1 维度

站点行的 `gen.layout`、`gen.manifest`、`gen.shops`（§2.2）；`struct:manifestRow`、`struct:shopRow`（§2.4）；`rules.gen.layout.*`、`rules.gen.dwelling.*`（§2.3）；分片、建筑、店铺三种实例位次（§4.12.1）。布局模板 `layout` 与分片角色 `zrole` 两族的格式归卷十九 §4.6（聚落布局模板）；`shopkind` 族归卷六 §4.5（店铺经营与补货）。本卷按卷七 §4.28（文化偏好输出接口）R7-28.5 向 `pref_kind` 族登记一条“聚落布局”偏好种类：

```json
{
  "pref_layout": {"field": null, "keyFamilies": ["layout"], "unknownWeight": 1, "labels": {"zh": "聚落布局", "en": "Settlement layout"}}
}
```

#### 4.7.2 统一入口

读：`genView()` 的 `layout`、`manifest`、`shops`；`manifestOf()`。写：经济阶段经写回器写三个 `gen.*` 维度并经卷六的 `post` 入第 0 日的账；物化的三个阶段经卷五的分区建行、卷十九的建行函数、卷六的店铺登记写行。

#### 4.7.3 规则

- **R10-7.1 选模板**：候选是 `applies` 对该站点为真的 `layout` 条目（判法归卷十九）。在候选里取 `culturePref(站点主文化, rules.gen.layout.prefKind 所指种类, 模板代号).weight` 最大者，并列取代号字典序最小；该偏好种类登记了非空的 `unknownWeight`，所以没填偏好的文化也能选出模板。没有候选时 `gen.layout` 为空，这座站点不分片，建筑直接挂在站点下。选模板不掷骰。
- **R10-7.2 有几座设施由需求求和，不写在模板里**：清单的行来自五处，逐处相加。① 生产：卷六 `stationPlan(站点)` 各活动的实际工位数，除以该活动所需设施类型的单座工位数后向上取整，得该类设施的座数（单座工位数是卷十九类型行的字段，取值域下限为 1，除数恒为正）。② 店铺场所：R10-7.6 的每家店一处提供零售服务的场所。③ 礼拜类设施与龛祠：卷七的 `shrineDemand(站点)`。④ 住处：站点开局人数按卷八 R8-16.10 的户数式折成的户数，每户一处。⑤ 治理与公共设施：站点类型 `governed` 为真时，卷八 §4.18（聚落治理、升格、选举）给出的席位所需的场所（§5.3）。模板只回答“落在哪一片”。
- **R10-7.3 每一栋怎么盖，由料、技能、意图推出**：对清单的每一行，意图 `intendedType` 来自 R10-7.2 的出处；面积来自该意图所需的功能量（生产类按工位数乘卷十九类型行的每工位面积，住处按户均人数乘 `rules.gen.dwelling.areaPerMemberM2`）；形制、层数、墙厚与各料质量由卷十九的 `chooseForm` 与 `buildPlan` 在第 0 日的世界上算出：可取料范围是开户之后当地的存量与聚合账户，匠人技能读卷八的 `stratumSkill`，文化偏好读站点主文化。`chooseForm` 返回空形制的行不进清单，原因代号记在 `genView()` 里；它本该提供的工位与床位随之没有，R10-4.7 的配额按进了清单的行算。没有“默认建筑”，也没有地区到形制的对照。
- **R10-7.4 清单定稿与第 0 日入账**：清单各行按（意图代号，归属主体，同组内的生成次序）排好后依次得 `ordinal`，写进 `gen.manifest`。同一事务里，对清单每一行，把它的各料质量与一万基点未物化建筑份额以开局来源记到所在地点聚合账户的未物化预置分区（卷六 §4.1（账本三元键与守恒）规则 5“物化建行”）。清单一经写入不再改：它是静态维度，没有改写写者。
- **R10-7.5 站点面积由占地反推**：每行按卷十九 `zrole.typeAffinity` 归到对其意图亲和度最高的分片角色（并列取代号字典序最小；模板里没有任何角色对它有亲和度时归份额最大的角色）。角色 `z` 的占地 = 归入它的各行“楼面面积 ÷ 层数”之和（层数不小于 1）。`站点面积 = 对模板里每个角色取 ceil(占地_z ÷ (份额_z × rules.gen.layout.coverage))，再取最大值`；模板各角色的份额由卷十九的校验保证和为 1，占地为 0 的角色不参加，参加者的份额须大于 0（否则该模板对这座站点不适用，回到 R10-7.1 取次优），`coverage` 取值域下限大于 0，除数恒为正。不分片的站点取 `ceil(全部占地 ÷ coverage)`。这样每个分片都放得下归入它的建筑。算出的面积超过所在存量单元面积即 E-GEN-ROW-INVALID。
- **R10-7.6 派生店的家数**：对每条 `shopkind` 条目，`家数 = floor(站点对其品类的有效需求日量 ÷ 该条目的单店惯常成交量)`，算式与除数下界归卷六 §4.5（店铺经营与补货）规则 7，需求读卷六的 `demand`。每家店在 `gen.shops` 里占一行：店铺种类、它的场所（清单里的一行）、经营者所属的聚合体或组织。运行期开新店用的是同一比较。
- **R10-7.7 开局货架不是货单**：一家店第 0 日的货 = 它的品类（`shopkind.assortmentRX` 为真且当地有效需求大于零的物品）各按卷六的目标库存式算出的量；每种货的材料与品质按 R10-8.4 推出。这些货在第 0 日以开局来源记到经营者所属的聚合账户，物化店铺阶段再转入货架账户。代码与数据里都没有按店铺写的物品清单。
- **R10-7.8 物化的三个阶段**：① 分片：按 `gen.layout` 的模板为每个分片建一行分区（句柄 `rules.gen.roles.zone`），id 为 `instanceIdOf(分片位次, 站点 id, 分片在模板内的序位)`，面积按份额分站点面积（末份取差），相邻要求落成边。② 建筑与房间：对清单每一行调卷十九的建行函数，id 为 `instanceIdOf(建筑位次, 站点 id, ordinal)`，`parent` 是它的分片；建行交出的砌入明细须与该行的 `materialKg` 逐料相等，否则 E-GEN-MANIFEST-DRIFT；记账按 R10-3.9。房间行由卷十九同一个函数生成。③ 店铺：对 `gen.shops` 每一行向卷六登记一家店（经营者、场所、货架账户），货从聚合账户转入货架。
- **R10-7.9 手工店、手写建筑与派生的同一格式**：作者写的店与建筑就是同样的行；它们占掉对应序位（R10-3.12），派生的家数与座数先减去已有的。
- **R10-7.10 地图附加物也是清单行**：路边的神龛、界碑、哨棚这类零散设施不另设机制：它们是某个意图的设施，出处是 R10-7.2 的 ③ 或 ⑤，落点是模板里对它亲和的角色。

#### 4.7.4 交互

卷十九 §4.2（设施类型维度表）、卷十九 §4.3（工位与工作站服务）、卷十九 §4.4（建造需求与地形前后）、卷十九 §4.5（建筑形制按文化与材料）、卷十九 §4.6（聚落布局模板）、卷十九 §4.8（住宿、租房、床位）；卷六 §4.1（账本三元键与守恒）、卷六 §4.4（市场需求）、卷六 §4.5（店铺经营与补货）、卷六 §4.7（生产组织：资源、劳动到物品）；卷五 §4.2（分区、方位与感知通道）；卷七 §4.16（宗教场所密度派生与微型龛祠）、卷七 §4.28（文化偏好输出接口）；卷八 §4.16（人口统计层、承载力、迁徙、移民波次）、卷八 §4.18（聚落治理、升格、选举）。通道：声明写者、账本转移、派生读取。

#### 4.7.5 数据实例

- 【西陲】一座 800 人的集镇，户均 5 人：住处 `floor(800 ÷ 5) = 160` 处。杂货类有效需求日量 420 件，单店惯常成交量 150 件：`floor(420 ÷ 150) = 2` 家。模板是沿河条带式，三个角色份额 0.5、0.3、0.2，`coverage` 为 0.4；三片占地 9600、3000、600 平方米：`9600 ÷ (0.5 × 0.4) = 48000`，`3000 ÷ (0.3 × 0.4) = 25000`，`600 ÷ (0.2 × 0.4) = 7500`，站点面积取 48000 平方米。
- 【非西陲】同一文化迁到缺木多石的山地站点：`chooseForm` 的备料可得度变了，清单里的住处从木构形制变成石砌形制，墙料质量随之不同；生成代码没有任何一行提到这座山。
- 【非人类】地下巢城：模板是垂直分层的巢城模板，角色是育幼、储藏、通道；清单的形制是蜡质巢室，技能是该物种自带的筑巢技能；`shopkind` 各条目的有效需求都为 0，店铺行数为 0。

#### 4.7.6 验收断言

- 扫描式：A10-7.1 生成代码与数据里以站点 id 为键的布局表、店铺货单、建筑清单模板为 0；形制代号、设施类型代号、店铺种类代号、物品 id 的字面量为 0；地区或文化到形制、到店铺种类的硬对照为 0。
- 不变量式：A10-7.2 物化后每个分片内建筑占地之和不超过分片面积，各分片面积之和等于站点面积；物化建行的砌入明细与 `gen.manifest` 逐料相等，与第 0 日预置逐料相等；物化后按类型计的设施数等于清单经同一类型派生函数计出的数；店铺家数等于 `gen.shops` 的行数。
- 扩展性式：A10-7.3 新增一条布局模板、一条形制条目、一条 `shopkind` 条目，不改代码：`applies` 成立的新站点可按新模板分片，有料有匠人的地方出现新形制，需求足够的站点出现新店。

### 4.8 物品生成组

#### 4.8.1 维度

`item_group` 族与 `struct:groupEntry`（§2.4）；`group_mode`、`pick_kind`、`scale_by`；`rules.gen.endow.rows`、`rules.gen.group.depthMax`（§2.3）；授予项位次与四个抽取点（§4.12.1）。

#### 4.8.2 统一入口

读：`rollGroup(engine, groupId, ctx)`，`ctx = {holder, place, scale, subject}`，返回要给的物品种类与件数；它是纯函数，不入账。写：第 0 日的入账只经卷六的 `post`，由开局财物阶段调用。

#### 4.8.3 规则

- **R10-8.1 组是数据，两种模式**：`collection` 的每个条目各自独立决定出不出；`distribution` 在全部条目里按 `weight` 恰好取一个。条目的权重各不小于 1，和恒为正。
- **R10-8.2 条目取什么**：`item` 指一条物品行；`rx` 指 `itemRX` 对物品九维与类别代号为真的物品行集合，按物品代号升序排后用一个均匀整数对个数取模取一条（个数为 0 时该条目不出，不取模）；`group` 指另一个组，递归求值。嵌套成环或深度超过 `rules.gen.group.depthMax` 在加载时即 E-GEN-GROUP-CYCLE。
- **R10-8.3 `scale` 为 1 的求值**：`collection` 的条目先抽一个千分数，小于 `probPermille` 才出；件数按 `count` 分布取。`distribution` 先按权重取条目，再取件数。
- **R10-8.4 器物的材料与品质由料、技能、意图推出**：条目只定“哪一种物品”，不定材料、不定品质。每件要入账的器物，其实例维度取卷三乙 `craftOutcome` 的产出提案，输入是：配方取该物品在当地可行的首选配方，候选料取 `ctx.place` 的存量汇总与聚合账户里有的料；技能取持有人所属聚合体的 `stratumSkill`；意图取条目的 `intent`，为空取缺省意图。当地没有任何可行配方的物品，这个条目在此地不出东西。没有配方的原料类物品按卷五取用律的产物口径取。同一条目在铁矿边上给出铁器，在海岛上给出骨器或贝器，在什么都做不出的地方什么也不给。
- **R10-8.5 `scale` 大于 1 的求值（给一群人发）**：`collection` 的条目，出货的份数 `= floor(scale × probPermille ÷ 1000)`（除数是常数 1000），余下的千分余数再抽一次决定是否加 1；件数只抽一次，总件数 = 份数 × 件数。`distribution` 把 `scale` 按各条目的 `weight` 分成整数份（卷二 §3.3（求值管线）第 3 条，按条目次序，末份取差），不掷骰。聚合体里的人没有个人历史，所以同一聚合体内各份同量；谁最终拿到什么在分户时由卷二十七的份额规则定。
- **R10-8.6 发给谁**：开局财物阶段对每个模拟单元里的每个持有人（居民聚合体、清单里的归属组织），按 `rules.gen.endow.rows` 的行序逐行看 `holderRX`（可读持有人的分组键、所在单元的汇总读数、组织种类）；为真的行，以 `scaleBy` 定的 `scale`（1、成员数、或户数）求值它的组，结果以开局来源记到持有人的账户。每一行对每个持有人是一个“授予项”，其 id 为 `instanceIdOf(授予项位次, 持有人 id, 行序)`，本次求值的全部抽取以它为对象。
- **R10-8.7 容器**：带 `containerRX` 的条目另按同样的份数入账一件满足条件的容器类物品；谁装着谁在分户物化时按卷三乙的容器规则落实（§8）。
- **R10-8.8 第 0 日之后只算不给**：别卷（搜刮、遗落、地图上的散件）可以调 `rollGroup` 得到“该出哪些东西”，抽取对象用它自己的事件 id；但第 0 日之后把东西放进世界必须有对手腿或卷六登记的物理来源，本卷不提供来源。
- **R10-8.9 店铺不用组定货**：店里卖什么由 R10-7.7 定；组只用于家当、行囊、库存这类“一个持有人开局带着什么”。

#### 4.8.4 交互

卷三乙 §4.5（品质档）与卷三乙的 `craftOutcome`；卷五 §4.8（取用律）；卷六 §4.1（账本三元键与守恒）、卷六 §4.22（源汇标记与月度经济报告）；卷八 §4.16（人口统计层、承载力、迁徙、移民波次）（`stratumSkill`、户数）；卷二十七 §4.2（聚合变体、等价、钉住）（分户份额）；卷十三、卷十六（遗落与搜刮调 `rollGroup`，§5.3）。通道：账本转移、派生读取。

#### 4.8.5 数据实例

- 【西陲】农户家当组里一个 `rx` 条目“农具类”，`probPermille` 900，发给 160 户：`floor(160 × 900 ÷ 1000) = 144` 份，千分余数为 0，不再抽；件数抽得 2，共 288 件。当地有铁矿场与林木，首选配方做出铁刃木柄的农具，品质由该阶层的技能代表值给出。
- 【非西陲】同一个组发给海岛渔村的聚合体：当地没有铁，首选可行配方的候选料是骨与贝，入账的是骨贝农具；一个要求琉璃的条目在当地没有可行配方，不出东西。
- 【超自然】一群精怪的聚合体 37 名成员，拿到一个 `distribution` 组，三个条目权重 5、3、2：`floor(37 × 5 ÷ 10) = 18`，`floor(37 × 3 ÷ 10) = 11`，末份 37 − 18 − 11 = 8。组的求值与持有人是不是人无关。

#### 4.8.6 验收断言

- 扫描式：A10-8.1 代码里的物品清单、货单、按店铺或按文化写的物品 id 列表为 0；组条目里出现材料或品质字段的计数为 0；第 0 日之后由本卷文件发起的来源腿为 0（S10-7）。
- 不变量式：A10-8.2 `rollGroup` 是纯函数；`distribution` 模式各条目份数之和恒等于 `scale`；每件第 0 日入账的器物，其材料都在当地存量汇总或聚合账户里出现过；第 0 日全世界各资源的开局来源总量两次生成相同；在 `rules.gen.endow.rows` 末尾加一行不改变已有各行的求值结果。
- 扩展性式：A10-8.3 新增一个组与一条指向它的授予行，不改代码：`holderRX` 成立的持有人第 0 日得到该组的东西；新增一条物品行，只要满足某个 `rx` 条目的条件且当地做得出，就可能被取到。

### 4.9 生成物写回同一数据格式

#### 4.9.1 维度

表行公共字段 `generated` 的三个成员（§2.4）；运行态偏离行的 `basis`（卷二 §2.7（系统声明表 `state-owners.json`）的 `struct:basis`，种类取 `generated`；这个种类枚举见卷二 §1.9（代号、显示名与语言边界））；`gstage.writesKinds`；错误码 E-GEN-ROW-INVALID、E-GEN-OVERRIDE-AUTHORED、E-GEN-BYPASS、E-GEN-BRANCH-ORIGIN、E-GEN-ID-COLLISION。

#### 4.9.2 统一入口

写回器 `worldgen-writeback.mjs` 是生成器产出落盘的唯一通道；它没有对外的读入口。校验调卷二的同一个维度校验器。

#### 4.9.3 规则

- **R10-9.1 提案先过同一个校验器**：生成器交出的每一条行提案（表、id、各维度的整值、`nameParts`、阶段代号），写回器先交卷二的维度校验器按与手写行完全相同的分级校验（必填、类型、取值域、引用闭合、不变量）。任一条不过即 E-GEN-ROW-INVALID：在 `worldgen` 相整个世界创建失败，在 `materialize` 相该笔事务回滚。没有“生成行从宽”的校验档。
- **R10-9.2 生成标记填什么**：`generated` 节的每一行带 `generated = {by: 产生它的阶段代号, seedKey: 它的实例位次键, at: epochMinute}`；`state.created` 的生成行带 `basis = {kind: generated, seedKey: 同上, writer: 写者节点名}`。两处都只有代号与数值。标记只供追溯与校验，不是规则的输入。
- **R10-9.3 同一加载器、同一代码路径**：`generated` 节由加载手写行的同一个加载器读入，进同一个索引；任何 view、任何规则读到一行时不知道它是手写还是生成。规则层按生成标记分支即 E-GEN-BRANCH-ORIGIN（S10-3）。
- **R10-9.4 生成行只写整值**：按卷二 §1.3（行、继承与取值顺序），生成的偏离行写完整的值，不用继承写法；作者已有值的维度不写（R10-1.7）。
- **R10-9.5 引用闭合随阶段推进**：一个阶段的产出可以引用手写行与先行阶段的生成行；写回器在每个阶段结束时做一次引用闭合校验，所以后行阶段读到的世界总是自洽的。
- **R10-9.6 id 唯一**：写回器对每个新 id 核对它不与任何已有行（手写或生成）相同；相同即 E-GEN-ID-COLLISION。
- **R10-9.7 互换判据**（卷一 §3（硬规矩条文）R-7 的判定）：把任一手写实例换成同类别的生成实例，该类别所在领域卷的全部验收断言仍通过。本卷据此不设任何“仅生成物有”的字段：`gen.*` 维度作者同样可以手填。
- **R10-9.8 不写任何显示文字**：生成物没有名称字串、描述字串；名字只有 `nameParts`，描述由显示层按代号与数值拼。
- **R10-9.9 可生成的实体类由阶段条目声明**：一个阶段能写哪些实体类，以它的 `writesKinds` 为准；写回器拒绝范围之外的提案。全书“哪些东西可以被生成”就是全部条目 `writesKinds` 的并集，不另列名单。
- **R10-9.10 世界自带它的生成结果**：`generated` 节属于这个世界的数据副本，随世界保存；读档不重新生成。数据表改动后旧世界怎样处置归卷二十八与卷二十七（§8）。

#### 4.9.4 交互

卷一 §3（硬规矩条文）（R-7）；卷二 §1.2（表头）、卷二 §1.3（行、继承与取值顺序）、卷二 §2.7（系统声明表 `state-owners.json`）、卷二 §4.1（分级、时机与分期）；卷二十八 §4.5（离线校验）；卷十六 §4.11（程序生成怪物）；卷十二 §4.6（扩展性与验收套件）（互换判据机器化）。通道：声明写者。

#### 4.9.5 数据实例

- 【西陲】手写的一座铁匠铺与远方物化出的一座铁匠铺：两行的字段集合相同，后者多一条 `basis`；卷十九对设施的全部断言对两者同样成立。
- 【非西陲】新世界的 96 个站点行全部在 place 表的 `generated` 节，各带 `generated.by` 为选址阶段的代号；删去标记后它们与手写站点行逐字段同形。
- 【超自然】卷七登记的阶段生成 100 位神祇的行，全部通过神祇表的校验，必填缺失为 0；其中任何一位都能被信仰行引用、被 `composeName` 命名。

#### 4.9.6 验收断言

- 扫描式：A10-9.1 S10-1、S10-3 计数为 0；校验器里按生成标记放宽的分支为 0；生成器产出中字符串类型的名称、描述字段为 0。
- 不变量式：A10-9.2 生成 100 个站点、100 个物种、100 位神祇，全部通过与手写行相同的校验，必填缺失计数为 0；每个生成行的 `generated.seedKey` 或 `basis.seedKey` 能由（位次、父、序位）重算得出；互换判据成立。
- 扩展性式：A10-9.3 给任一表新增一个必填维度并在生成器里给出它的来源，不改写回器；漏给来源时，世界创建以 E-GEN-ROW-INVALID 失败而不是带着缺口运行。

### 4.10 程序生成生物接口

#### 4.10.1 维度

本卷只定接口：一条 `gstage` 条目（由卷十六登记）、物种位次（§4.12.1）、`gstage.writesKinds` 含物种类。物种行的 schema 归卷四 §4.1（物种统一 schema）；怎样由部件、材料与领域拼出一种怪物归卷十六 §4.11（程序生成怪物）。

#### 4.10.2 统一入口

读：无本卷专有入口（生成后的物种只经卷四的 `speciesView` 读）。写：卷十六的生成器出提案，经本卷写回器写 species 表的 `generated` 节。

#### 4.10.3 规则

- **R10-10.1 它是流程里的一个阶段**：`worldgen` 相、世界作用域、排在自然量之后与开户之前；本卷的流程代码不认识它。
- **R10-10.2 输入**：世界种子；卷十六与卷四的数据表；先行阶段写下的自然量与由此派生的群落分布（各群落的存量单元数与面积，读 `placeView`）。生成几种、各偏向哪些群落，由卷十六的规则表与这些读数决定。
- **R10-10.3 输出是普通物种行**：必须通过卷四的物种校验（身体图、属性分布、`habitats`、食性等必填齐全），`habitats` 只引用已登记的群落条目；名字经 `composeName` 以物种类取得。
- **R10-10.4 id**：第 `i` 种的 id 为 `instanceIdOf(物种位次, 世界根 id, i)`，`i` 是卷十六规则表里生成槽的行序。
- **R10-10.5 之后一视同仁**：开户、栖地容量、存量、取用、传说索引、个体化都读同一张物种表；本卷与卷五没有“生成物种”的分支。
- **R10-10.6 数值从部件与材料推出**：生成怪物的体重、能力、伤害、弱点不逐项掷骰，由它的身体图部件与部件材料经卷四的派生得出；这一条的落实归卷十六，本卷只在写回时拒绝未过校验的行。
- **R10-10.7 手写世界可以一种都不生成**：个数为 0 时阶段无产出，流程照常。

#### 4.10.4 交互

卷十六 §4.11（程序生成怪物）、卷十六 §4.4（妖怪志与传说真相层）；卷四 §4.1（物种统一 schema）、卷四 §4.2（身体部件图与肢体能力）；卷五 §4.3（地形、群落与海拔维度表）、卷五 §4.7（资源场、再生律与栖地容量）；卷二 §5.3（物种 `species`（卷四、卷十六））。通道：声明写者。

#### 4.10.5 数据实例

- 【西陲】手写世界：卷十六规则表的生成槽为 0 行，阶段无产出；全部怪物都是手写物种行。
- 【非西陲】新世界生成 6 种怪物：其中一种的 `habitats` 指向高山冻原类群落，开户阶段为它在 14 块冻原存量单元上开户；它的名字是三个成分代号。
- 【超自然】一种只栖于深洞无光群落、带某一超自然领域标签的巨兽：它是 species 表的一行，容量由卷五的捕食项算出，传说由卷十六的索引引用；生成流程对它没有任何专门处理。

#### 4.10.6 验收断言

- 扫描式：A10-10.1 本卷文件里对物种 id、怪物类别代号的字面量引用为 0；卷五、卷二十五文件里按物种行生成标记的分支为 0。
- 不变量式：A10-10.2 生成的每条物种行通过卷四的全部加载校验；同一种子两次生成的物种行逐字节相同；`habitats` 无悬空引用。
- 扩展性式：A10-10.3 卷十六在规则表里加一个生成槽，不改本卷与卷五的代码：新世界多出一种物种，并自动进入开户与栖地容量。

### 4.11 历史生成接口

#### 4.11.1 维度

`rules.gen.history.years`（§2.3）；`state.genesis.epochMinute` 与 `openingMinute`（§2.5）；一条 `gstage` 条目（历史预跑）。事件、编年史、纪元的格式归卷二十四 §4.7（历史生成）。

#### 4.11.2 统一入口

读：`openingOf()`。写：预跑就是一次普通的推进请求，由世界创建流程向内核提交；本卷不写任何事件。

#### 4.11.3 规则

- **R10-11.1 历史是同一套规则的无人值守预跑**：历史预跑阶段把世界时钟从 `epochMinute` 推进到 `openingMinute`。`openingMinute = epochMinute + rules.gen.history.years × 一年的分钟数`，年长读卷二十的历法。这段时间里状态中没有玩家控制的实体，观察锚为空集，全部模拟单元处在统计层（卷二十七 §4.1（三层模拟运行矩阵）），生死、迁徙、生产、站点升降、政治与信仰的变化都由各卷的同一套规则算出。没有专用的“历史生成规则”。
- **R10-11.2 记下什么归卷二十四**：预跑中各卷照常发事件；哪些事件进编年史、怎样分纪元、怎样投影成可读的历史，归卷二十四 §4.7（历史生成）。本卷不筛事件、不写史。
- **R10-11.3 手写的史事是静态行**：作者写的纪元与史事是卷二十四的数据行，时刻早于 `epochMinute`；预跑从 `epochMinute` 起，不改写它们。
- **R10-11.4 年数可以为 0**：`years` 为 0 时 `openingMinute` 等于 `epochMinute`，阶段无动作。
- **R10-11.5 预跑入日志**：这次推进的目标分钟作为世界创建流程的一项参数写进日志，复演时照日志推进（卷二十七 §4.7（复演与规则只一版）R27-7.3）。
- **R10-11.6 预跑里没有开局来源**：开局来源只在 `epochMinute` 的世界创建事务里出现；预跑期间的一切增减走各卷的物理律通道（S10-7）。
- **R10-11.7 预跑里的物化**：没有观察锚，所以 R10-3.7 的第 ① 种触发不发生；第 ② 种照常（某条规则需要一行时请求物化）。
- **R10-11.8 玩家在 `openingMinute` 进入世界**：开局阶段在预跑之后运行；角色创建可选的出生地、可见的站点类型与人口，都是预跑之后的世界。

#### 4.11.4 交互

卷二十四 §4.7（历史生成）、卷二十四 §4.2（事件类型注册表）；卷二十 §4.1（刻、同刻全序、调度器与到期语义）、卷二十 §4.2（历法数据与周期日规则格式）；卷二十七 §4.1（三层模拟运行矩阵）、卷二十七 §4.3（成本模型与降级阶梯）、卷二十七 §4.7（复演与规则只一版）；卷八 §4.16（人口统计层、承载力、迁徙、移民波次）；卷五 §4.6（站点类型）。通道：事件、派生读取。

#### 4.11.5 数据实例

- 【西陲】手写世界：`years` 为 0，作者写的 80 条史事是早于第 0 日的静态行；`openingMinute` 等于 `epochMinute`。
- 【非西陲】新世界 `years` 为 50：预跑中一处营地类站点的人口越过区间上界并持续够久，按卷五的升降规则升为村落类；一条商路上的两个站点因往来增多发展度升高。编年史里有这些事，是因为它们真的在规则里发生过。
- 【超自然】预跑第 31 年某省气候场越过阈值引发旱灾事件，信众人数随迁徙变化后卷七发出请愿建庙事件；这些与玩家在场时走的是同一条路。

#### 4.11.6 验收断言

- 扫描式：A10-11.1 规则层里按“是否处在预跑期”分支的代码为 0；只在预跑中启用的规则为 0；写死年份、地名、人名的史事生成代码为 0。
- 不变量式：A10-11.2 同一种子，“预跑 N 年后开局”与“`years` 取 0 开局后无人值守推进 N 年”得到同一份存档摘要；预跑期间开局来源的发生额为 0；预跑的日志可被 `replay_verify` 逐字节复现。
- 扩展性式：A10-11.3 任何卷新增一条时钟规则或事件类型，不改本卷：它自动在预跑中生效并可进入编年史。

#### 4.12.3 规则

- **R10-12.1 实例位次导出**（卷二 §1.10（随机实例化）把 `instanceId` 的导出交给本卷）：`instanceIdOf(slot, parentId, ordinal)` 调内核的 `entityId`，成分恰为四样：世界种子、位次代号、父 id、序位。序位必须是世界内在的整数：卷二十七发放的成员序号、数据表的行序、清单与模板里的序位、R10-2.2 的子序位。调用次数、循环中会随别的主体变化的下标、世界时刻、物化的先后，都不得作序位。位次条目的 `kind` 决定 id 的类前缀（为空的位次导出的 id 只作抽取对象，不建实体）；`parentKinds` 非空时父的实体类须在其内。
- **R10-12.2 聚合体成员的实例 id**：成员的 id 为 `instanceIdOf(成员位次, 该成员来源聚合体的 id, 成员序号)`，与卷二十七 R27-2.2 的（来源种子键，序号）一一对应；成员迁到别的聚合体后 id 不变，因为取的是来源聚合体。
- **R10-12.3 生成期抽取键的五段**：世界种子；上表的流代号；对象取“被生成的那个东西”的 id（实例 id、父地点 id、模拟单元 id、授予项 id）；时刻段恒取 `epochMinute`；抽取点取上表的固定代号。`materialize` 相同样取 `epochMinute`，物化发生的时刻不进键，这是 R10-3.8 在键上的落实。键里没有任何计数。
- **R10-12.4 全登记**：本卷每一个抽取点、每一个位次都在 §4.12.1 的两张表里；源码与种子键表的双向比对归卷二十七 §4.8（种子键与骰值键（确定性约束与验收））R27-8.1。别卷登记的生成阶段用到新的抽取点或位次时，自己加行，流代号以 `stream.gen.` 起头。
- **R10-12.5 开局缺省只有三个来路**：数据表行上的值；规则表 `rules.gen.*`；世界模板的参数（世界种子、骨架来源、所用数据包、起始分钟）。生成与开局代码里出现作缺省用的数值字面量、固定实体 id、固定地点，即 E-GEN-DEFAULT。卷二十七 R27-7.6 所说“新世界的缺省值”就是这三处。
- **R10-12.6 没有缺省出生地**：角色创建可选的出生地由卷四 §4.12（玩家角色创建、出身、母语）从开放范围内的地点按出身的筛选条件给出；未选则退回菜单。旧代码里固定出生地的缺省删除，不留替代常量。
- **R10-12.7 开局阶段做三件事**：把 `openingMinute` 写进 `state.genesis`；对每个地点求 `rules.gen.opening.openRX` 并把结果写进卷五的开放范围维度；核对 R10-1.8 的拒绝行。它不建任何实体。
- **R10-12.8 不为旧存档补缺省**：不存在迁移、兼容与“读档时补字段”的路径；规则摘要不符的存档不能加载，归卷二十七 §4.7（复演与规则只一版）。
- **R10-12.9 新增抽取点不扰动旧值**：键里没有计数，所以给流程加一个阶段、给名字加一个槽、给授予表加一行，都只多出新键，已有的每个值不变（A10-12.2）。

卷二 §1.10（随机实例化）（键格式、采样、`instanceId`）；卷二十七 §4.2（聚合变体、等价、钉住）（成员身份）、卷二十七 §4.7（复演与规则只一版）、卷二十七 §4.8（种子键与骰值键（确定性约束与验收））；卷四 §4.12（玩家角色创建、出身、母语）；卷五 §4.1（地点包含树与坐标）（开放范围）；卷二十 §4.2（历法数据与周期日规则格式）（起始分钟对应的历日）；卷九 §4.18（录制回放与费用账）（不得成为键的成分）。通道：派生读取、声明写者。

#### 4.12.5 数据实例

- 【西陲】手写世界开局：世界模板给世界种子、`authored`、起始分钟；出生地菜单列出开放范围内满足出身条件的地点，不预选任何一个。旧的固定出生地不再出现在任何表或代码里。
- 【非西陲】另一张世界只差世界种子：同一个郡位次、同一个父、同一个序位导出的 id 不同，所有抽取随之不同；两张世界互不影响。
- 【非人类】一个兽人聚合体的第 57 号成员：id 由（成员位次，来源聚合体 id，57）导出；他第一次被实体化在第 3 年，折叠后第 9 年再次实体化，两次的 id、名字、名册职业、各采样维度完全相同。
- 【超自然】给神祇名字的结构加一个称号槽：只多出一个出现位次与一个取词位次的键；世界里已有的全部人名、地名逐字节不变。

#### 4.12.6 验收断言

- 扫描式：A10-12.1 生成与开局代码里的固定出生地、固定实体 id、作缺省用的数值字面量为 0；legacy、compat、migrations 目录与对它们的 import 为 0；未登记的 `stream.gen.` 抽取点为 0；键的成分里出现计数、时刻（`epochMinute` 以外）、墙钟为 0。
- 不变量式：A10-12.2 `instanceIdOf` 对不同的（位次，父，序位）给出不同的 id；同一成员任意次实体化 id 相同；新增一个抽取点或位次后，全部既有抽取值与 id 逐字节不变；换世界种子后同一位次的抽取分布通过卷二十七的分布质量检验。
- 扩展性式：A10-12.3 新增一条 `idslot` 条目与一个用它的生成阶段，不改内核与本卷代码：新实体得到确定的 id，种子键表比对通过。

## §8 开放问题

须李白定的设计取舍（本卷已按所述方案写，定了相反结论要改的章节一并列出）：

1. **世界有界**。按卷六“开局只在第 0 日”，本卷让整个世界在第 0 日入账，所以一个世界的政区与站点数在创建时就定了，“无限”只体现在可以无限地换种子开新世界、以及远处不占逐个体的成本。若要一个世界在第 0 日之后向外扩出新的政区，就需要第 0 日之后的开局来源，与卷六 §4.22 规则 3 冲突。牵连：§1.3、R10-1.2、R10-3.9。
2. **历史 = 同一套规则的无人值守预跑**，不另写历史生成器。好处是没有第二套规则、历史与现状必然自洽；代价是开新世界要多跑 `years` 年的统计层，且历史的戏剧性取决于各卷规则本身。牵连：§4.11；卷二十四 §4.7 尚未成稿，需与它对齐。
3. **不合格的世界直接拒绝，不换随机数重做**。同一种子只有一个结果；代价是有的种子开不出世界，要由界面提示换种子。牵连：R10-1.8。
4. **卷零 B 表 6.1“世界生成总流程”由已有升级为纳入**（素材包注明需报李白）：本卷按纳入写，流程与内容全部退出代码。

待后续版本或别卷回答：

5. 清单在第 0 日定稿后是静态的；经过多年预跑或长期离屏，站点人口变了而未物化的清单不变。未物化站点在统计层怎样增减建筑，卷十九、卷二十七尚未给出（C10-8）。
6. 潜力人数只按食物能量算，与卷八 `popCapacity` 的“各项需要取小”口径不同；本卷把它只当开局初值，之后由卷八的规则把人口拉向它的口径。两者差得多时开局头几年会有明显的人口调整。
7. 水体的走向、下游与汇水面积第一版只靠分类规则加挂水域属性，没有给出河流连通的生成规则；卷五 §8 也记了“水井、水体数据作者容易建错”。
8. 姓氏随亲本继承：卷七的结构条目只有槽位与是否可选，没有“取自亲本”的字段；现在亲子可能不同姓。需要卷七与卷二定是否给槽位加继承来源。
9. 没有文化的实体（不通人言的生物个体、无主的地点）是否必须有 `nameParts`：卷二公共字段表写“生成实体必有”，本卷用 `rules.gen.name.fallbackBank` 满足它；是否改成可空待卷二定。
10. 铸币等非物品资源的开局量不走物品生成组（条目只取物品行）；由卷六给出来路（C10-6）。
11. 容器类条目的“谁装着谁”在聚合账户里无法表达，推迟到分户；卷三乙的容器规则是否支持分户时落实待定（C10-14）。
12. 第 0 日没有成交历史，`demand` 的习惯项、惯常成交量、预期价格的冷启动口径归卷六（C10-6）；它直接决定清单与店铺家数。
13. `gen.manifest` 对大站点可能有上万行，全部存在世界数据副本里；是否改成“只存每类座数与归属、物化时重算形制与用料”取决于卷十九的纯计算能否只读第 0 日的静态量，现按卷六、卷十九“第 0 日清单”的写法存全。
14. 台账没有“实例位次与实例 id 导出”“生成阶段表”两个概念的行；卷二 §1.10 明文把前者交给本卷，本卷已写全，请收尾时补进台账。
15. `idslot` 条目里父为聚合体、模拟单元或派生 id 时不核对实体类（`parentKinds` 写空集）；聚合体与模拟单元是否算卷二 22 类之外的 id 类别，待卷二、卷二十七统一。
