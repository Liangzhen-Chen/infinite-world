## §0 卷首

### 0.1 范围

本卷回答六个问题：
1. 统一底层要达到什么（§1 设计目标）；
2. 底层分几层、每层管什么、读写边界在哪、禁止什么（§2 分层；§3A 共享计算设施）；
3. 亮圳 11-13 定的规矩怎样落成可执行、可扫描的条文（§3 硬规矩）；
4. 现有代码里哪些是骨架要留、哪些要改造、哪些要重做（§5）；
5. 为什么前九轮没落实、这次怎样在结构上堵住（§6）；
6. 三十一卷之间怎样依赖、按什么顺序读与写、全书怎样验收（§11、§12）。

本卷**不定义任何领域维度**（那是卷二到卷二十九的事），只定义"维度是什么、谁能读、谁能写、违反了怎样被机器抓住"。

### 0.2 依赖与被依赖

- 依赖：产品原则（全部）；PLAN 11-13 规矩；调研 01–10；李白 11-13 输入边裁定。
- 被依赖：**全部卷**。卷二把 §2.1、§2.3、§3A、§4.4、§4.5 落成文件格式、校验器与声明表；卷九把 §7 与 R-2 第 5–10 条落成输入边与 AI 接口；卷十一把 §6.4、§6.6 落成卡清单与阶段退出标准；卷十二把 §3、§3.1、§10、§12 机器化为扫描；卷二十九把 §2.9 与 R-2 第 7 条（语言包精确对应）落成显示层契约；卷二十七把 §8 落成确定性与存档规范；卷零逐处标出 06b 219 行（含输入边 74 行）的处置。

### 0.3 读法

- 条文编号形式：`L-n`（分层契约，§2.1 逐条独立）、`R-n`（硬规矩，§3）、`I-n`（不变量，沿用架构设计 02 的 I1–I32，新增从 I33 起）、`A-n`（反模式禁令，§10）、`V-n`（验收总纲条，§12）。各卷引用时写编号，不抄原文。
- "维度"指**可由程序读取并参与判断的、带固定代号或数值的字段**；"显示字"指只给人看的文字（名称、描述、叙述）。两者的分界是本卷最重要的一条线（R-2、§4.4）。
- "专项规则"指**只对一个或少数具体实例成立的分支**（点名某个物品 id、某位神、某个地区、某个聚落）；对一个**类别**（由维度表定义）成立的规则不算专项。
- "规则层"指第〇至第六层的全部代码（§2.1），**含 consistency-review 等审查模块**；"输入边"指把玩家操作或模型输出变成结构化代号的模块组，不属于任何层，可整体拔除（R-2 第 8 条）。
- 本卷引用调研文档时写 `06a §2`、`07 §三 C4` 等；引用代码写 `文件:行`。

### 0.4 写进每卷模板头部的硬约束（卷目 10 §3.1 已定，此处定稿为条文）

每一卷、每一张卡在开头必须复述并遵守以下五条，缺一条不收：

1. **禁具体 id**：规则代码不出现任何实例 id 字面量，也不得间接点名（R-4）。
2. **禁读自然语言**：规则层一行都不读任何语言；只读维度表登记的字段；显示字（§4.4 清单）对规则层不可见（R-2）。
3. **禁专项规则**：不得为具体物品、神、地区、聚落、人物写只对它成立的分支（R-4）。
4. **常数只在规则表**：规则代码不含手填的十进制常数（R-6 白名单除外），常数一律在 `engine.rules` 可达的规则表里并带名字、单位与出处。
5. **一系统一读入口、一字段一写者**：每个系统的状态只经一个 view 函数读、只经声明过的写者写（L-3、L-6）。

## §1 设计目标

### 1.1 一句话

> 一个**完整、真实运转**的世界，可以**无限随机生成**，新增物品、神、地区、职业、文化、设施、怪物、法术只需**填数据**，不加一行代码；底层**与语言、表现形式无关**，SillyTavern 只是第一个前端。

### 1.2 四个可检验的目标

| # | 目标 | 可检验的说法 | 由哪几卷落实 |
|---|---|---|---|
| G1 | 完整真实的世界 | 卷零覆盖表里 10 号文档总表 223 行（纳入 167 + 已有 41 + 不适合 15）每行有处置：208 行有归卷与 §，15 行有不适合理由；每个子系统五小节齐全（维度、入口、规则、交互、实例）；五款成熟游戏 335 条系统每条都有处置 | 卷零、卷三–卷二十九 |
| G2 | 可无限随机生成 | 生成器只是"会写数据的程序"：生成物写回与手写内容同一数据格式、同一加载器、同一校验器（DF `GENERATED` 模式，01 §5）；"无限"靠**种子分区 + 按需物化 + 离屏聚合**（卷十 §3、卷二十七 §1–§2）：任一地点在首次被注意时由其所在分区的种子键确定性生成，未被注意的地区只有统计层账户；同种子同输出（I31）；生成内容与手写内容享有同样的系统覆盖 | 卷十、卷十六、卷二十四、卷二十七 |
| G3 | 加内容只填数据 | 扩展性测试（V-6，分阶段）：在已定稿的维度表里新增一行（一个物品类别 / 一种设施 / 一种职业 / 一种地形 / 一位神 / 一个地区 / 一种怪物 / 一种法术），不改任何 `.mjs`，该表声明的行为自动获得。神、法术、怪物的行为之所以能"只填数据"，依赖 §3A 的共享计算设施（开放属性 + 效果族表 + 领域词表推导），不是靠泛禁 | 卷二、卷十二、全部领域卷 §6 |
| G4 | 与语言和表现无关 | 规则层零语言字面量、零对显示字的读取（06b 219 行 → 0，无任何豁免）；同一存档在任意两个显示语言包下规则可读状态哈希相同（I40，哈希范围见 §8.3）；文字、画面、声音三种前端读同一投影接口，`scene()` 输出经模式校验且不含语言字段（V-5）；输入边整体拔除后靠菜单仍可完整游玩（V-21） | 卷二十九、卷九、卷十二、卷二十七 |

### 1.3 不是目标

- 不追求 DF 的物理精度（六种应力三参数、每刻热交换）。按"规律是分布，允许随机与个别不合常理"的原则，取其**结构**（维度 → 公式 → 行为），不取其精度（01 §8.2 第 6 条）。
- 不做旧存档兼容、不加复演版本标记（长期备忘 no-old-save-compat）；只保证**同版确定性**。
- 不做"又一个只有引擎的天国拯救"（PLAN 11-10 亮圳）：细规则引擎是世界的一部分，领域卷必须写到真实内容实例，不止写接口。

## §2 统一底层的分层

### 2.1 总图与分层契约 L-0 … L-12

```
            作者边 ─────────────────────────────────────────────────┐    输入边（可整体拔除）────────┐
            手写数据 · 生成器(卷十/十六/二十四) · 内容审批(卷二十八) · AI-R4   │    菜单 · 构造器 · AI-R1 理解层  │
            只写第一层(经校验器)                                      │    只产 封闭代号集合内的动作+参数 │
                                                                    ▼                                ▼
```

分层契约逐条（各卷只引编号）：

- **L-0 读向下**：第一至第七层每层只读**自己以下**的层；第〇层是基座，所有层都可经第二层读它的状态，但**只有第〇层事务能写它**。第一层静态数据运行期只读，由作者边写。输入边与作者边不是层，是两条进入点：输入边只向第〇层事务提交封闭代号集合内的动作代号加参数；作者边只向第一层写经校验的数据。
- **L-1 两端论**：自然语言只允许存在于输入边与第七层。第〇至第六层之间没有任何自然语言流动，也没有任何代码读显示字（§4.4）或对任何字符串做语言意义上的判断。输入边的职责与限制见 R-2 第 5–10 条。
- **L-2 单写路**：任何状态改变 = 第〇层一条事件 + 其原语列表（I16）；原语是 `world/ontology/primitives.json` 的封闭清单（19 个 14 族）；第二层以上只产提案，由第〇层事务（primitives.mjs:236–237）校验并归约。
- **L-3 一系统一读入口**：每个系统恰一个 view 函数（卷二 §7 清单）；每个状态谓词全库恰一处定义；view 只做**字段查找与合成**（取数据行、取有效持有、解析引用、附来源标记），**不含公式、不读规则表常数**。需要常数或修正槽的值是第三层派生，view 调用派生规则取值并原样返回。判据：一个函数若读 `engine.rules` 或 `derived()`，它属于第三层；若只读第〇层状态与第一层数据，它属于第二层。
- **L-4 规则只读维度**：第三层规则只经第二层入口读；只对维度表的**类别或全体**成立；只产提案；常数只经 `engine.rules`。import 图上规则模块只能指向入口层、§3A 设施与本体工具（I19；现有 tests/arch-metrics.test.mjs + tests/metrics/import-graph.baseline.json + tools/arch-layers.mjs 是检查工具的起点，卷十二接管）。**规则层任何模块不得 import 输入边模块**。
- **L-5 表的所有权分裂**：维度表的 **schema、校验器、显示字清单、代号规范**归第一层（卷二定）；维度表的**行**（内容）归第四层各领域卷。领域卷不得改 schema 规则，第一层不得写行。
- **L-6 一字段一写者**：每个可变字段、每种持有来源、每个派生事实、每个源汇恰一个写者模块，在加载时登记到写者声明表（§4.5 最小字段）；未声明的写在开发模式抛错、在扫描计数。
- **L-7 接口四通道**：跨领域**写**只走三类（账本转移、事件订阅、声明写者）；跨领域**读**只走对方的 view()；没有第五种。推进次序不是通道：时钟规则的相对次序由第〇层调度器按 I31 五阶段与排序键统一排，规则在注册时**声明阶段与排序键**，不靠注册顺序。
- **L-8 投影不落盘**：第六层只产投影与事件分发，投影可随时丢弃重建（I17）；事件的物理写入属第〇层，第六层拥有事件的**定义**（动词表、形状、起因、见证）与**分发**。
- **L-9 显示层只读**：第七层只读第六层投影与第一层显示词表；它的唯一"写"是把玩家操作变成结构化输入交输入边；不持有规则、不缓存权威数据。
- **L-10 四段同卡**：一张实现卡 = 维度表行补齐 + 数据补齐 + 读取方改造 + 旧路径删除，四段同卡，缺一段不算完（拆分规则见 §6.6）。
- **L-11 不迁移的读法**：不做一次性全量迁移；每个领域在其卡内完成退役；不存在"先双写、以后收口"的中间状态（A-11）。跨领域的账本双写由唯一责任卡承办（§6.5）。
- **L-12 门禁先行**：卷二定稿后、任何领域实现卡之前，五项扫描与维度表校验器进 CORE 并登记基线；基线只降不升（I43）。

### 2.2 第〇层 内核与状态

**职责**：持有运行期可变状态，执行唯一的写路径（事务），调度时间，产生骰值。它是"写只有一条路"的执行者。

**数据形态**：存档文档 = `state`（npcs、settlements、buildings、records、effects…）+ `holdings`（持有与实体化事实）+ `ledger`（账户与源汇，ledger.mjs:4 与 state 并列）+ 事件日志 + 元数据；事务 = `planPrimitives / commitPrimitives`（primitives.mjs:236–237）；调度器 = `runAdvance`（advance-registry.mjs:97）与到期堆；骰值 = 种子键（§8）。

**读写边界**：
- 写者：**只有事务**。事务在一个归约里解析引用、校验不变量（I1–I4）、执行原语、写事件；失败整体回滚。
- 读者：第二层入口（唯一直接读者）。第三层以上**不得直接取 `state.xxx`**。
- 状态对象在归约之外冻结（I3；开发模式 Proxy 抛错，仅限开发模式，扫描是唯一门禁——见 I34）。

**禁止事项**：规则 / 工具 / AI / 界面直接改状态对象；用 `records` 当自由文本消息总线（A-10）；事务之外的 `Math.random`。

**现有骨架**：ledger.mjs、holding-sources.mjs、primitives.mjs、primitives-runtime.mjs、advance-registry.mjs、storage.mjs（digest :14）、digest-exclude.mjs 全部保留。

### 2.3 第一层 维度与数据层

**职责**：用固定代号与数值把世界里"一切东西是什么"描述清楚，使所有上层判断都有可读的字段，不必猜。

**数据形态**（卷二定稿文件格式；此处定契约）：

1. **维度表 schema**（`world/ontology/dimensions/<表名>.json`，当前不存在，卷二首批**九张**：物品类别/材料、地形/群落/海拔、设施类型、职业、人格、文化、政体、罪名、状态；09 §二十四 第 2 条）：每张表定义字段清单——字段名、类型（§4.4 六种）、单位、取值域、缺省、出处、校验规则、是否必填、**该表声明的行为清单**（供 V-6 断言）。
2. **实例数据**（`world/meta/*.json`、`world/ecology`、`world/geo`、`world/law`、`world/lore`、`world/people` 等已有目录）：每条实例按所属维度表填字段，带 `origin: authored | generated | pack:<id>`（统一命名为 `origin`，不再用 `generated` 布尔）。实例可以带显示字（§4.4 清单），显示字**对程序不可见**。
3. **实例继承与可复用块**（CDDA 02 §14、§18 第 2、5 条；RW 03 §11、§16 第 7 条）：
   - `copyFrom: <id>`、`abstract: true`、`extend / delete`（容器型字段增删）、`relative / proportional`（数值偏移与乘系数）。**继承由第一层加载器统一实现一次**，对所有表生效，不允许每类加载器各自实现、支持程度各异（CDDA 教训）。
   - **需求块 requirement**：可命名、可嵌套（`list`）、可倍乘（`using: [id, n]`）的"工具能力 + 材料类别 + 数量"组合，独立于配方存在；配方、拆解、建造、修理、治疗、仪式、法术耗材共用（卷三 §7 定格式）。需求块只引用**类别与能力代号**，不引用实例 id。
4. **规则表**（`world/meta/rules.json` 57 个顶层键、`world/rules/tables/*.json`、`world/meta/mechanics/*.json`）：公式常数、阈值、曲线、折算系数、RX 表达式。每个常数条目有 `name、unit、source`；代码只经 `engine.rules` 读（R-6）。
5. **本体表**（`world/ontology/*.json`：entity-templates、holdings、obligations、primitives、verbs、tags、statuses、offenses、resources、derived-fields、calendar）：定义八个存储概念的词汇（§4.1）。保留。
6. **受控词表**（tags.json 480 个标签；卷二新增领域 sphere 词表；职业、价值、伦理、能力、伤害类型、修正键等词表）：**全部开放可增删行**（DF 01 §6 第 4 条"枚举表全在代码里"是教训；A-18）。词表条目须挂上位词并经同义检查（I18 的"现役注册"）。
7. **显示词表**（按语言码索引：`labels[<lang>][<code>]`，`<lang>` 为 BCP-47 码如 `zh-CN`、`en`；不在条文里固化两种语言；文件布局卷二十九定）：代号 → 文字，错误码 → 文案，名字成分 → 拼法，**菜单项代号 → 显示名**（R-2 第 7 条的精确对应表）。**权威是显示词表**；作者数据里的 `name` 只是中文输入，加载时转成 `labels['zh-CN']`，运行期规则层没有 `name` 字段可读。中英两份词表**对等**：每个代号在两份里都有条目，缺一即校验失败 E-LABEL-MISSING。

**代号规范**（卷二细化，此处定原则）：
- 所有枚举值、状态、类型、用途、代号一律 **ASCII 小写蛇形或点分**（`sleep`、`capacity:none`、`E-ROUTE-SEASON-CLOSED`）。06b 待定 2 的约 1,100 行中文枚举比较（`status==='濒死'`、`type==='送货'`）全部换成 ASCII 枚举 + 显示词表。
- 实例 id 前缀沿用（`item_/loc_/npc_/bld_/org_/office_/culture_/deity_/monster_/skill_/profession_`），永不复用；**id 不由显示字派生**（I40）；id 只在数据里互相引用，规则代码里不出现（R-4）。
- **名字是成分代号，不是成品字符串**：生成器产出的名字（人名、地名、器名、神名）写成 `nameParts: [成分代号…]` 加命名模板代号，显示层按语言的拼法规则（词库 + 组合规则，卷十 §5、卷二十九 §6）渲染。规则层不读名字；名字不进哈希（§8.3）。DF 的"词 / 符号组 / 翻译"（01 §2.7）是范本。

**读写边界**：
- 读者：第二层入口（唯一直接读者）。
- 写者：作者边——手写、生成器（卷十；写回同一格式并带 `origin: generated`）、内容审批管线（卷二十八 L1/L2/L4）、AI-R4 草稿（只进 drafts）。运行期**没有任何代码写第一层**。
- 加载：一个加载器、一个继承实现、一个校验器流水线；**缺字段直接报错，禁止回退去解析文字或补默认值**（A-7）。

**禁止事项**：
- 同一概念多张表（06a §2：物品类别三套、食物价值三套读法；地形解析六套、文化解析四套）。卷二为每个维度指定唯一表，其余退役。

- 维度表缺行时由代码兜底。

**现有骨架**：`world/ontology/*.json` 全部保留；`world/meta/mechanics/material-props.json` 的材料属性行是物品维度表的雏形（item-class.mjs:279 `MATERIAL_DIMENSIONS`；:275–278 注释写明"没有任何来源的维度返回 {known:false}，不给默认值"，实现在同文件后段）；`world/rules/tables/seed-keys.json`、`digest-exclude.json` 保留；`world/ontology/derived-fields.json` 派生黑名单（26 个字段）保留并由卷二扩展。

### 2.4 第二层 统一入口层

### 2.5 第三层 通用规则层

**职责**：从维度算出行为。规则**只读维度、遍历类别或全部实例**，对一类东西一次成立。这一层是亮圳四条规矩里"行为由通用规则从维度算出"与"禁止专项规则"的落点；§3A 的共享计算设施（属性与修正求值、效果族表、需求块）也在本层。

**数据形态**：规则四种形状（架构 01 §1.8），全部只读视图、只产提案：

| 形状 | 写法 | 例（示意，不是名单） | 常数在哪 |
|---|---|---|---|
| 派生 | 纯函数 `视图 → 值`，缺省带修正槽（I27、§3A.2） | 价格、工价、法域、称呼代号、可采量、同意能力 | 规则表键 |
| 反应 | `当 事件匹配(动词/标签/地点谓词/参与者谓词) 则 原语列表` | 征税、立案、立场印象、传闻生成、火势蔓延 | 规则表 + 谓词 DSL（数据） |
| 时钟 | `每 日/月/季/年，在 层级，对 某类实体 执行 原语`，声明 `closedForm` 或 `tolerance`、阶段与排序键（L-7） | 日耗、再生、腐坏、热忱回升、作物生长、**叙事调度**（卷二十四）、**历史生成**（卷十 / 卷二十四：时钟规则的离线批量运行） | 规则表 |
| 动作 | 槽位、前置、同意、代价、检定、按档位效果、可见性 | 全部玩家 / NPC 可发起行为 | 动作目录 + 规则表 |

叙事调度（按世界状态加权抽取事件）与历史生成（创世前逐年推进）**都是时钟规则**，属本层；第六层不含调度。

规则写法的三条通用形式（卷二 §9 落成校验）：
1. **"每个有 X 字段的 Y 都……"**：`每个有日耗率的物品类别每天按户扣`、`每个有再生率的资源场按 renewable 律生长`（renewable.mjs:1–2 已写明 "no resource or site id appears here"，是范本）。
2. **"按维度查表"**：`罚则 = 罪名维度表[offense].penaltyClass × 法域规则`，而不是四张表串查（law.mjs:104）。
3. **"关系从维度差算"**：`信仰敌意 = f(教义差异)`、`文化接纳 = Σ 支柱重合`（CK3 05 §3.1、§3.3），不手填关系矩阵。

**读写边界**：L-4。

**禁止事项**：A-1 点名实例；A-2 只覆盖部分类别（日耗只有 fuel/salt item-class.mjs:118–124、库存四槽 stock.mjs:44–50、周贸易只配 item_oats rules.json:6265 + settlement-trade.mjs:92）；A-3 手填倍数（冬荒 price_shift ×1.6/1.2）；A-4 读显示字；A-5 常数散落；**A-21 以专用代码类承载内容行为**（环世界 ThingComp / StatWorker / 专门 C# 类的教训，03 §14、§16 第 8 条；CDDA iuse.cpp 61 个 itype_id 常量，02 §16 第 1 条）——领域不得为某类物品、法术、设施、怪物写专门类或专门 handler，只能组合四形状与 §3A 设施。

### 2.9 第七层 显示层

**职责**：把第六层投影与第一层代号渲染给人——文字（任意语言包）、画面（图块、立绘、地图）、声音（环境音、音效）。SillyTavern 扩展是第一个前端；浏览器图块客户端、独立客户端是后来的前端；它们读同一接口。

**数据形态**（卷二十九定稿）：
- **显示词表**：`labels[<lang>][<code>]`，缺键回落到键名并计数，永不报错阻塞；中英两份对等（E-LABEL-MISSING）。
- **文本模板**：每个事件动词一条模板（`world/actions/locale/<lang>/events.json` 已有 zh-CN 版），槽位是称呼 / 数量 / 地点 / 方位的**代号或数值**，由显示层按语言填词。
- **命名拼法规则**：名字成分代号 → 该语言的拼写（卷十 §5 词库、卷二十九 §6 拼法）。
- **菜单与构造器**：全部菜单项、构造器槛位、候选按钮都是代号，显示名查词表；玩家点选产出的就是代号，不经任何文字解析（R-2 第 7 条）。
- **素材键**：`{portrait, sprite, tile, icon, sfx, ambience}` 的键名，不含素材（架构 08 §8.8 第 2 条）；解析顺序个体键 → 种类键 → 模板类别默认键。

**读写边界**：L-9。显示层**不持有规则、不写状态、不缓存权威数据**（08 §8.8 第 3 条："RPG Maker 之类引擎只能作为显示器"）。

**禁止事项**：
- 显示层回读文字做逻辑（06b extension 26 行：ambient-audio 按地点/天气文字选音轨 14 行、message-view 把报错文字映射成提示 7 行、runtime.js 用角色卡名字判断扩展启用 2 行）。改读 biome 代号、weather code、error.code、角色卡扩展字段。

**验收**：V-4 任意两语言包哈希一致；V-2 底层零语言字面量；V-5 `scene()` 模式校验；V-21 拔除输入边仍可完整游玩。

## §3 硬规矩条文

以下条文是全书最高约束，与产品原则冲突时以产品原则为准，与任何领域卷冲突时以本节为准。每条给：条文、来源、机器判定方式（卷十二实现）、现状基线。

### R-1 系统内统一维度、统一入口

**条文**：每个系统的每个可判断概念都对应维度表中的一个字段；每个系统恰一个读函数、每个字段恰一个写者；同一概念在全库只有一张表、一个名字、一个入口。

**来源**：亮圳 11-13 02:3x 规矩第 1 条；产品原则二.1 派生优先。

**判定**（分两段）：P0 可判：卷二 §7 入口清单与 §4.5 写者声明表存在且机器可读；扫描"同一字段多模块写"= 0；"本地重定义已有谓词"= 0。卷零成后可判：入口清单覆盖卷零全部子系统。

**基线**：有统一入口且维度不缺的子系统 26 / 234（09 §二十三）；本地 awake 31 处；睡眠正则 83 行 / 62 文件；状态列表 118 处（06a §6）。

### R-2 程序不读任何自然语言，只读数值维度和固定代号（含李白 11-13 输入边裁定）

**条文**：
1. **规则层一行都不读任何语言**。第〇至第六层的任何代码（**含 consistency-review 等审查模块**）不得读取 §4.4 显示字清单中的字段，也不得对任何字符串做语言意义上的匹配判断（正则 `test/match/replace` 用于分支、`includes/startsWith/endsWith/indexOf` 接文字字面量、`===` 比较非 ASCII 字面量、数组 `.includes(字段)` 的数组含非 ASCII 元素、中英文字面量参与判断）。**判定采用白名单式**：规则层只许读维度表登记为维度类型（§4.4 六种）的字段；不在任何维度表里的字段一律不许读。**没有任何一行豁免**。
2. 一切枚举值、状态、类型、代号为 ASCII；文字只在显示词表。
3. 所有前置失败带 `code`（`E-*`），调用方只比较 `error.code`。
4. 内容校验（工具层）比对结构化字段，不从正文抽数字、时长、工序判断对错（08 §三 例 10）。
5. **现有 74 行解析的处置**（06b 待定 1：action-router、action-constructor、action-time、retrieval-lexicon、scene-card、population、consistency-review 等）：全部移出规则层进入输入边，或改为只读固定代号。其中 **consistency-review 解析模型叙述的 44 行**改为：要求 AI 直接输出**固定代号格式的结构化结果**（付款额、次数、成败、引用的实体 id、方位代号等，schema 封闭），规则层只校验这些代号是否在合法集合内，不再读正文。卷零逐处标出这 74 行的去向；本卷只定规则。
6. **输入边只做一件事：文字 → 固定代号**。输出必须是**封闭代号集合内的动作代号加参数**（`{action: <目录代号>, slots: {<槛位代号>: <候选编号或数值>}}`，或封闭 schema 的 proposal，primitive-schema.mjs:57）。翻不出、或有歧义，就**退回菜单让玩家选**，不猜，也不填默认值。输入边不读世界状态做判断，只读引擎给出的候选集与动作目录投影。
7. **不开 AI 时只走菜单和结构化代号**。T0 档没有自由文字理解；语言包只允许"**菜单项显示名完全一致**"的精确对应（词表 `labels[<lang>][<menuCode>]` 的整串相等），**禁止关键词匹配、正则、从整句里猜意图**。自由打字的理解只在玩家自己开了 AI 时由 AI-R1 承担，且 R1 的输出仍受第 6 条约束。
8. **输入边可以整体拔掉**。拔掉后靠菜单与构造器仍能完整游玩全部玩法（V-21）；中文、英文两份对等（E-LABEL-MISSING）。输入边模块组由 import 图隔离：规则层任何模块不得 import 它（L-4）。

10. 理解层对 AI 文字的解析也只在输入边（§7）；AI 的结构化输出同样只能是代号。

**来源**：亮圳 11-13 03:5x 硬规矩第 1 条；李白 11-13 裁定（乙方案收紧）；长期备忘 no-natural-language-logic。

**判定**：卷十二扫描 2（V-2，语法树级，§3.1）：规则层计入行 = 0；extension = 0；tools 内容校验脚本读正文判断 = 0；非 ASCII 字面量（注释与测试夹具除外）= 0。V-20 规则目录文字匹配 / 正则分支 / 语言字面量判断 = 0。V-21 拔除输入边后无 AI 通关套件全过。

**基线**（P0 须先补成逐行清单才能"只降不升"）：server-plugin 219 行已逐行（A 睡眠 117、B 设施 27、C 地形 13、D 职业 15、E 性格等 36、F 错误消息 11；输入边 74 行含在内，全部计入）；extension 26 已逐行；**tools 333 与中文枚举约 1,100 行尚未逐行判读**——P0 第一项任务是把这两组补成逐行清单并登记为基线（§6.3）。

### R-3 底层与语言、表现形式无关

## §3A 共享计算设施（第三层的一级公共设施，卷二落成）

成熟游戏的"统一底层"不只是"数据化 + 禁写死"，而是几套**所有领域共用的计算机制**：EVE 的 dogma（属性 + 效果，04 §2.2–2.4）、CK3 的修正键表（05 §2.8）、环世界的 Stat 求值顺序与 Hediff（03 §3.2、§7）、CDDA 的需求块、附魔值与条件效果（02 §7、§10、§11）、DF 的交互与综合征（01 §2.8）。没有它们，V-6 对神、法术、怪物不可能成立——行为只能靠写代码（审查 B 第一 1、2）。本节立为契约，卷二 §2–§6 落成格式与求值器。

### 3A.1 属性与效果分离（开放属性集）

- **属性 attribute** 是一个开放集合：每个属性一行 `{id, unit, default, min, max, stackable, highIsGood, roundTo}`（EVE dgmAttributeTypes 的字段集合）。新增能力 = 新增一行属性 + 给相关实例赋值；不改代码。
- 实例按维度表给属性赋值；**效果 effect 不含数字**，只声明"读哪个来源属性、改哪个目标属性、用哪种运算、作用域与过滤器"（`{source, target, op: add|mul|postPercent|max|min|set, domain, filter}`）。
- 同一条效果被任意多个实例复用，各自读自己的属性值（EVE 04 §2.3 结论）。

### 3A.2 唯一求值管线（升级 I27）

- 全库只有一个求值函数（现 derived.mjs:269 `derived()` / :206 `explainDerived()` 升级为它），任何派生值都经它。
- **固定求值顺序**（RW 03 §3.2 两阶段的合并，卷二定稿不得增删阶段）：基值 → 加性偏移（add）→ 乘性因子（mul，受叠加惩罚）→ 材质 / 品质乘子（§3A.3）→ 组件与状态容器修正 → 后处理曲线（curve）→ max / min → 取整 → 钳位 [min, max]。
- **叠加规则**：同一属性多个乘性修正按 `stackable` 元数据决定是否衰减；衰减函数是规则表里的一条曲线（EVE 的 `exp(−((n−1)/2.67)²)` 是参照，不写死）；max/min 阶段多来源取极值不叠加（I27）。
- **来源可追溯**：`explain()` 返回每一步的来源（哪条效果、来自哪个实例、哪条规则表键），显示层可渲染，审查可核（EVE 04 §11 第 12 条"估值要可解释"）。
- **修正键命名**：`<scope>.<attribute>.<op>`，scope 为实体模板类别或领域代号（CK3 05 §2.8 的 `<scope>_<what>_<add|mult>` 约定），占位符按词表实例化（`<damageType>.resist.mul` → `cut.resist.mul`）。键表开放（A-18）。

### 3A.3 材质 × 品质 两个独立乘子

- 成品不写数；成品只写"材质效果倍率 + 材质类别 + 工时 + 用量"；材质写"做成此物时的乘数 / 偏移"；品质写"每类属性的档位乘数表"（RW 03 §16 第 2 条）。N 种物品 × M 种材料 × 7 档品质不需要任何逐一定义。
- 价值、护甲、保暖、锋利、耐久、美观全部走此路（卷三、卷十三、卷十九）。

### 3A.4 状态容器（唯一容器）

- 伤、病、药效、成瘾、环境状态、法术状态、诅咒、热忱、士气全用同一结构：`{id, stages[{threshold, modifiers[], capacity, awake, duration}], source, bodyPart?, decay}`（RW Hediff 03 §7、CDDA effect_type、DF syndrome 01 §2.8）。
- 容器实例由领域卷定义（第四层），容器格式与求值归第三层；`capacity`、`awake`、`mode` 是机器字段，供第二层谓词读（取代 118 处中文状态列表）。

### 3A.5 效果族表（物品、法术、设施、怪物共用）

- `world/rules/tables/open-sources/*.json`（通用门设计稿 §2.1 已定名"效果族表"）从"只服务 AI 开放路径"扩为**全部效果的唯一来源表**：每行一族效果怎样从世界状态派生来源与幅度。
- 物品的"使用动作"、法术的效果、设施的服务、怪物的特殊攻击、仪式的后果，都只是效果族行 + 需求块 + 属性值的组合（CDDA 02 §15 第 6 步"需要新动作先找 actor"的数据版；堵住 iuse.cpp 式写死）。
- 领域不得为某类内容写专门 handler（A-21）；效果族表缺某族时，加一行族定义（经 L1/L2/L4 审批），不加代码分支。

### 3A.6 需求块与继承

见 §2.3 第 3 条：需求块（requirement）与实例继承（copyFrom / abstract / extend / delete / relative / proportional）由第一层统一实现，§3A 的求值器读它们展开后的结果。

### 3A.7 封闭与开放的分界（回答审查 A 第六 4）

| 封闭（代码定义，改需改引擎并报李白） | 开放（数据定义，加行即生效，须注册） |
|---|---|
| 原语 op 清单（19 个 14 族，primitive-schema.mjs:6） | 属性集合、修正键表（3A.1、3A.2） |
| proposal 字段集合（primitive-schema.mjs:57）；输入边输出 schema | 词表条目：职业、领域 sphere、价值、伦理、能力、伤害类型、标签、状态、罪名 |
| 规则四形状、接口四通道、维度六类型 | 维度表的行；效果族行；需求块；动作目录条目；菜单项代号 |
| 求值管线的阶段顺序（3A.2） | 事件动词、持有种类、义务种类、资源种类（I18：须注册现役并挂上位词，但集合开放） |

### 4.1 八个存储概念（存储层只认这八样）

### 6.4 阶段退出标准（实条款）

阶段由卷十一定义（P1 … Pn，n 由卷十一定，最后一阶段记 Pn）。每个阶段退出时必须同时满足五条：

1. **扫描数单调且达标**：对基线元组每一分量 c，设 B0(c) 为基线，`登记退役数(P, c)` 为该阶段派出的全部卡在派卡时登记的"将删除的旧写点数"之和。退出目标 `T(P, c) = T(P−1, c) − 登记退役数(P, c)`，其中 `T(P0, c) = B0(c)`；实际扫描值 `S(P, c) ≤ T(P, c)`；且 `S(P, c) ≤ S(P−1, c)`。**硬上限**（卷十一不得放宽，只可收紧）：`S(P1, c) ≤ 0.6·B0(c)`、`S(P2, c) ≤ 0.35·B0(c)`、`S(P3, c) ≤ 0.15·B0(c)`、`S(P4, c) ≤ 0.05·B0(c)`、`S(Pn, c) = 0`。若卷十一定的阶段数 n ≠ 5，按阶段序号 k/n 线性插值取上限。
2. **退役数兑现**：该阶段卡清单登记的旧写者、旧字段、旧正则全部删除，`实际删除数 = 登记退役数`，不接受"待下阶段"。
3. **扩展性门（分阶段）**：该阶段定稿并上线的每张维度表都通过 V-6（对该表加一行，不改代码，该表声明的行为清单逐项断言通过）。未定稿的表不测。
4. **遗留登记**：所有"归后续"项都有接收卡号与阶段；登记表为空或全部有卡号，否则不准收口。
5. **卷零回填**：该阶段覆盖的卷零行"改后状态"三列已填。

只看这五条，**不看测试通过数**。按"选项"收口（A-14）无效。

### 6.6 卡的范围与拆分规则（回答审查 A 第四 3、C8）

5. **AI 文字不进哈希**（§8.3）。
6. **失败就降级，不阻塞**（RL-10）；降级的终点是菜单，不是另一套文字解析。
7. **密钥玩家自带**（RL-9）。

## §8 确定性、种子键与哈希范围

### 8.1 同版确定性
给定存档与输入序列，任意两次推进（逐日 vs 一次、串行 vs 分片、不同平台）产生的事件序列逐字节相同（I31）。

### 8.2 骰值键
`战役种子 + 规则 id + 对象 id + 时刻 + 序号`；种子键前缀登记在 `world/rules/tables/seed-keys.json`，加载校验 E-SEED-KEY 禁止未登记前缀（AI-04 §6.1）；规则代码不出现 `Math.random`（VAI-00-5）。生成器用同一体系；生成物带 `origin` 与种子，可复现（R-7）。

### 8.3 规则可读状态哈希（V-4、I40 的字段集合，明定）

- **算法**：`storage.mjs:14 digest()`（sha256 over canonical JSON）作用于**排除后的文档**；排除口径是唯一数据表 `world/rules/tables/digest-exclude.json`（digest-exclude.mjs 校验其格式：layers、rules{layer, prefix, keys, source}）。
- **排除层**（现有两层 + 本卷新增三层，卷二十七定稿）：`narration`（AI / 叙述文字及其指纹、模型标识）、`names`（显示名）、**`labels`**（任何语言的显示词表快照与成品名字字符串）、**`provenance`**（润色来源、素材键、语言包版本）、**`clientPrefs`**（aiProfile、语言、界面偏好——按 AI-00 §3.3 本不进存档，列入以防万一）。
- **保留在哈希内**：state 全部数值与代号字段、holdings、ledger、事件日志（含 rollKey）、nameParts 成分代号、origin。
- **I40 补充**：id 生成、排序、分组都不以显示字为输入；任何 `sort()` 的比较键必须是 id 或数值。

### 8.4 历法与语言不进时钟
时钟只认分钟；月、年、节日、年号是按法域历法的投影；语言是显示层偏好。改语言不改任何事件。

### 8.5 每个世界保存自己的数据副本
DF 模式（01 §8.1 第 10 条），保证同版复演；不做版本迁移（R-8）。卷二十七落实数值纪律、存档分片、性能门。
