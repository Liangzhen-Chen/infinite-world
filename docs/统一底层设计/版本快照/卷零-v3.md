### 0.4 处理列的四个值
- **纳入**：本作缺、未实现、或“部分”且缺核心段；该卷重新设计。
- **已有→改建**：09 标“已实现”或 10 标“已有”的；该卷只做“补维度表、走统一入口、行为由规则从维度推出”，不重设计玩法。改建受李白三条硬条件约束（§4 开头）。
- **不适合**：不进本作；通用部分归哪一卷在备注写明。
- **流程**：不是世界系统，是门禁/测试设施，归卷十一或卷十二。

- 裁定（PLAN【11-13】★硬规矩补充★ 条，当前 PLAN:259–266）：规则层（含 consistency-review）一行都不读任何语言；输入边只做“文字 → 封闭代号集合”，翻不出或有歧义就退回菜单，不猜、不填默认值；**不开 AI 时**只走菜单与结构化代号，语言包只允许菜单项显示名的精确对应（`===`），禁关键词、正则、最长匹配、整句猜意；**开 AI 时**由 AI 输出封闭集合里的动作代号与参数，规则只校验代号合法；输入边可整体拔掉，拔掉后靠菜单仍能完整游玩。
- 处置只有三种：**移出规则层**、**改成只读固定代号**、**删除**。每行按“不开 AI / 开 AI”两种模式分别写明。
- 三个承接层（都不是规则层，不参与世界逻辑判断，所以允许读文字；均须在卷二 §4.9 写者声明登记，产出只能是封闭代号）：

### 3.5.4 声明代号结构：扩展现有 claimSchema（审查 B M3；不新造专项字段）

consistency-review.mjs:308–316 已有 `claimKinds`（10 个）、`modalities`（fact/intention/reported/question/figurative）、`temporalModes`（current/past/future/timeless）、`verdict`，:440–447 是校验。处置方案是**扩展这一套通用结构**，不按领域新造 craftClaims/paymentClaims 之类字段：
- `kind`：取自规则表里的 **kind 注册表**（现有 10 个 + 本表用到的 search/stock/craft/fee/payment/debt/knowledge/naming/meta/clock/agency 等各占一行；每行登记允许的 predicate 集合与 value 类型）。新增一种叙述错误 = 注册表加一行，不加字段。
- `subject`：必须是 entityId / obligationId / 其它登记 id（现为 boundedText，改）。
- `predicate`：必须是**维度代号**（由各领域维度表登记取值：物品维度→卷三、账本字段→卷六、年龄→卷四……）。
- `value`：数值或代号（现有 `quantity`、`object` 并入；`object` 不再是自由文字）。
- `modality`：沿用现有五值并新增 `hypothetical`（假设/条件，承接 :13、:157、:214 的“如果/假如”，不再塞进 intention 或 question；复审 B 建议）；`time.mode`、`time.at/until`、`verdict`、`references`：沿用现有。
- 自报类标记：`kind:'meta'` 与 `modality:'figurative'` 是 AI 给自己文字打标，AI 不打标即绕过；注册表里标明“自报类，只许产生 warning 级问题”，不得作为 error 依据。
- 新增枚举字段 `polarity:'affirm'|'deny'`（承接 :14、:177、:219、:269、:274 等否定判断）。
- `quote`/`segmentId`/`start`/`end`：沿用；校验只做位置与字符串同一性（S2 登记例外）。
- 校验器通用化：按“subject + predicate”读对应卷的 view()，与 `value` 比较；`kind` 不在注册表、`predicate` 不在该 kind 允许集、`subject` 不是登记 id → 整条拒收，不回退读正文。

### 5.3 结论
1. **火器不作本作系统**：世界设定正文（E1–E4）没有火药与火器；1.15 维持“不适合”，理由从“火器不在设定”改为**引证**：“世界设计 00–14 册对火药/火器/硝石/硫磺零命中（E1）；战斗体系的远程原型只有弓（E4）；材料表无火药行（E3）。”
2. **但架构需求里列有“爆竹”作辟邪媒介（E5；世界设计册本身无），草稿史料有“惧爆竹声/火药熏洞”（E6）**，且架构已把火器当扩展包示例（E7、E8）。结论维持：**不适合、预留材料属性与通用规则**。因此**投射与爆炸两种机制必须通用化**，放进材料属性与通用规则，让扩展包只加数据就能装上火器、也让爆竹辟邪不用专项：
   - **投射**：卷十三 §4.4 远程/投射武器——参数全部来自物品维度（物品阶 stage、初动量、精度、穿甲）与使用者属性/技能，不区分弓、弩、火铳；火器只是“高 stage、低技能要求”的一行物品数据（E7）。
   - **爆燃/爆炸**：卷三 §4.1 材料属性表增 `combustion`（燃点、热值、燃速）与 `deflagration`（爆燃阈值、释能、碎片系数）两组字段，缺省为 0 的材料不爆；卷三 §4.11 热属性与燃烧的“燃烧”规则按 `deflagration>0` 自动派生“爆燃”反应（反应规则形状），产物是卷二十 §4.7 环境场（火、烟、冲击）与卷十三 §4.2 伤害类型（冲击/灼烧）的区域 vital；火灾蔓延沿用设施槽 `facilities:fireRisk`（E8 ③）。
   - **声响辟邪**：爆竹作为“声音与火”媒介的辟邪效果读卷十六 §4.5 克制与辟邪双边标签（生灵 `bane:noise` × 物品 `ward:noise` 由材料 `deflagration` 与 `noise` 属性派生），与鼓、钟同一规则（E5）。
   - **管制**：持有火器/私造火药若扩展包引入，走卷八b §4.2 罪名谓词（状态类/事件类），不写专项（E8 ④）。
3. **扫描断言（卷十二 S6 扩展性）**：在材料表加一行 `deflagration>0` 的材料、在物品表加一行 `stage` 高于弓的投射物品，不改任何 .mjs，应自动获得：爆燃反应、环境场、伤害结算、火灾风险修正、辟邪 noise 标签、法典可登记罪名。本断言写进卷三 §6、卷十三 §6、卷十六 §6。
4. 妖怪志草稿（E6）的“惧爆竹/火药熏洞”标签在进入 world/ 正式数据时按卷十六 §4.5 转为 `bane:noise` / `bane:smoke` 双边代号，不保留中文母题文字作判断依据。
