## §1 领域总述

### 1.1 真实世界怎样运转

1. **地面先于人**。纬度、海拔、离海远近决定气温和降水；气温、降水、地势、土壤决定长什么植被；植被决定养得起多少动物。人只能在这张底图上选址。
2. **资源是地形的后果**。浅海加干热有盐滩，沉积岩层里有岩盐、煤、铁矿，河流冲积处有砂金和黏土，森林出木材与猎物。没有人会"规定某地产盐"，是那里的地质与气候让盐可以被取出。
3. **资源场的大小是需求的后果**。同样有盐滩，周围三百里没人买就只有几户晒盐；通了大路、有了城市，就变成大盐场。存量设上限，需求定规模。
4. **可再生的东西按密度长**。林、鱼、兽在存量低时长得慢，中等时最快，接近容量时停；取得太狠会伤到繁殖群，之后很久恢复不了；取光了就没有了。矿不会长。
5. **地点一层套一层**。房间在屋里，屋在村里，村在郡里；法律、口音、治安都是"往上找最近的那一层"。路把地点连起来，路况由沿途地形决定。
6. **人到了地方才有站点**。村、镇、城、营寨、巢穴的差别在人口、功能、围护和归属，会随时间升降。发展度是长期积累，控制度是眼下谁说了算。
7. **边境是渐变的**。两地之间的人口互相渗透，越靠近边界越混杂；迁徙沿路走，被吸引力和阻力决定。

### 1.2 本作现状（出处见素材包 §3）

- 地点 458 个，`terrain` 是文本 458 处，结构化标签只有 24 处；程序里有六套各自的地形解析（卷零 167 行所列六处），互不一致。
- 资源点 124 行、再生 44 行全部手写在地点上；林场的产物、鱼的产物以物品 id 写死在代码里（卷零 169 行）；通用再生律纯函数已写好但没有接线（卷一 §5.1 列为保留骨架）。
- 栖地按地形文字匹配（卷零 138 行）；采集只有玩家会做，NPC 不采。
- 法域绑定 180 条已有，但终审地点按一个地点 id 写死 10 处，政体靠名称首词判断。
- 文化有四套解析，绑定 0 条。
- 进入权、感知有入口，但用活动文字和睡眠正则判断在场与清醒。
- 省郡纲要 40 行，邻省条款是文字。
- 发展度、控制度、地质、地下层、气味：没有。

结论：现有数据是"每个地点写一段话"，本卷把它改成"每个地点填十来个数，其余全部由规则推出"。

## §4 子系统

### 4.1 地点包含树与坐标

#### 4.1.1 维度

`parent`、`coord`、`areaM2`、`elevationM`；`edges` 节的 `from`、`to`、`distanceM`、`terrainMix`、`waterway`。组件类决定一行是哪一级：`comp_region`（政区）、`comp_settlement`（站点）、`comp_facility`（建筑实例，归卷十九）、`comp_zone`（分区，§4.2）、`comp_route`（路线段）。没有组件类的 place 行是自然地块（荒野、水域、地下空间）。

#### 4.1.2 统一入口

`placeView().tree`、`routeView()`。关系 `rel_contains`（卷二 §1.12（派生与聚合原语））由本卷实现并声明为节点 `relation:rel_contains`，读 `created.*.parent`。

#### 4.1.3 规则

1. **单根树**：全表恰有一行 `parent` 为 null；任一行沿 `parent` 有限步到根。
2. **层级不靠名字**：一行是什么层级只看组件类与 `regionLevel`，不看 id、不看显示名。
3. **坐标与面积约束**：子地点的 `coord` 到父地点 `coord` 的距离不超过父地点等效半径（由 `areaM2` 算）；同父子地点 `areaM2` 之和不超过父地点。
4. **边是无向的结构事实**：一条边只存一次，`from` 的 id 字典序小于 `to`。边的两端可以在树的任意位置；跨父边是合法的（两村之间的路）。
5. **距离**：有边时用 `distanceM`；无边的两点没有"可走距离"，只有坐标直线距离（供感知与气候用，不供行程用）。行程合成归卷十七 §4.1。
6. **当前地点是结构化字段**：回合里的地点只接受地点 id，缺失即退回重请，不合成默认值（实现归卷九 §4.9，本卷只给约束）。
7. **秘境与传送**：分层地点是普通 place 行，挂在各自的父节点下；它与常世的连接是一条 `distanceM` 为 0 的边，通行条件写成边上的需求块（卷二 §1.13（需求块）），内容由卷十五 §4.15 登记。

#### 4.1.4 交互

- 卷十七 §4.1 读 `routeView` 合成钟点；卷二十九 §4.4 读 `tree` 与 `coord` 做地图投影；卷十 §4.1 生成时写入行与边。
- 修正作用域 `located`（卷二 §3.5（作用域与状态键表））沿本树解析。
- `nearest(rel_contains, …)` 的全部使用方（气温、法域、文化缺省）都走这棵树。

#### 4.1.5 数据实例

- 西陲一座河谷村：`parent` 为‹地点：所属郡›，`comp_settlement`，`areaM2` 与 `coord` 已知；其下有 `comp_facility` 的房屋行与 `comp_zone` 的分区行。
- 非西陲一处海岛港镇：`parent` 为‹地点：群岛郡›；它与大陆之间只有一条 `waterway: true` 的边，`terrainMix` 全部为 `terrain_coast`。
- 超自然一处秘境：`parent` 为‹地点：秘境层根›，与常世某洞穴之间有一条 `distanceM` 为 0 的边，边上挂需求块（由卷十五登记）。

#### 4.1.6 验收断言

- 【扫描】A5-1.1：仓库内出现以地点 id 字面量作比较的代码行数为 0（S5-3）。
- 【不变量】A5-1.2：加载后根恰一个；每行到根的步数有限；每条边两端存在且 `from` 小于 `to`；同父子面积和不超过父。
- 【扩展性】A5-1.3：新增一个大陆（一行 `comp_region` 加若干子行与边），不改任何代码，`placeView`、`routeView`、`located` 作用域对新行全部可用。

### 4.2 分区、方位与感知通道

#### 4.2.1 维度

- 分区是挂 `comp_zone` 的 place 行，`parent` 是站点或建筑；分区之间的连通是 `edges`，带 `aperture`。
- 方位不是存储维度：`placeView().zones` 给出每条分区边的 `bearingDeg`（由两端 `coord` 算，0–360，单位见 §8 Q2）。显示层把角度变成方位词。
- `sense` 族条目字段（本卷定义）：`needsLine: boolean`（是否要直线通视）、`passesAperture: boolean`（是否受开敞比例衰减）、`lingerDays: number`（信号在原地残留的天数，气味类大于 0）。
- 信号结构 `signal = {channel: ref vocab sense, sourcePlace, strength: number, emittedDay, subject: EntityId nullable}`，全部代号与数值。

#### 4.2.2 统一入口

`perceive(engine, state, observerId, signal)`。它是全书唯一的"是否感知到"判定（台账 X-14）。

#### 4.2.3 规则

1. **三方分工**（台账 X-14）：环境量与传播衰减由卷二十 §4.7/§4.8 计算，本卷调它的入口取"信号到达观察者所在分区时的强度"；感官阈值读 `speciesView().dims.senses`（卷四 §4.1）；清醒与感官能力读卷二 §2.5（状态谓词单点）的 `awake` 与 `bodyView` 的对应能力值。
2. **本卷提供传播所需的结构**：分区图、每条边的 `distanceM` 与 `aperture`、每个分区的 `skyExposure`。卷二十按 `sense` 条目的 `needsLine`、`passesAperture` 字段决定怎样用这些量，不按通道代号分支。
3. **判定式**：`margin = 到达强度 × 感官能力值 − 阈值(物种, 通道) − perception.json.marginBase[通道]`；`perceived = awake 或该通道条目允许非清醒感知时，margin ≥ 0`。全部经卷二 §3.3（求值管线）求值，可被修正项改变。
4. **残留**：`lingerDays` 大于 0 的通道，信号在源分区按天线性衰减到 0；观察者之后到达仍可判定（追踪气味的基础）。残留量的存储与衰减执行归卷二十，本卷只定判定。
5. **加一种通道只加一行**：新通道（震动、灵觉等）是 `sense` 族的一行加物种表里的阈值，判定式不变。
6. **判定结果不写知情**：`perceive` 纯读；卷二十二 §4.2 订阅并写入知情。

#### 4.2.4 交互

卷二十（环境量）、卷四（阈值）、卷二十二（知情写入）、卷十三（潜行与伏击读 `margin`）、卷八b（目击证据读判定结果）。

#### 4.2.5 数据实例

- 一间酒馆分成厅、灶间、楼上三个分区，厅与灶间的边 `aperture` 高、厅与楼上的边 `aperture` 低；厅里的说话声在灶间可感知、在楼上余量为负。
- 非西陲一处峡谷站点：两个分区直线距离近但没有边，`needsLine` 的通道（光）可达，`passesAperture` 的通道按最短边路衰减。
- 非人类一只嗅觉阈值很低的兽：对 `lingerDays` 大于 0 的通道，在信号发出两天后进入源分区仍得到非负余量；同处的人得到负余量。

#### 4.2.6 验收断言

- 【扫描】A5-2.1：感知与进入权相关模块内本地清醒、睡眠判断为 0（S5-5）；判定式实现中不出现任何 `sense_` 代号字面量。
- 【不变量】A5-2.2：其余不变时，`aperture` 增大则 `passesAperture` 通道的到达强度不减；`perceive` 调用前后状态哈希不变。
- 【扩展性】A5-2.3：新增一个通道行与一个带该通道阈值的物种行，不改代码，`perceive` 对新通道给出判定。

### 4.3 地形、群落与海拔维度表

#### 4.3.1 维度

- 地点侧：`terrain`、`elevationM`、`slope`、`skyExposure`、`annualMeanTempC`、`annualPrecipMm`、`waterAccess`、`forestCover`、`aspect`、`biome`（派生）、`wildness`（派生）。
- `biome` 族条目字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `envelope` | struct{tempC:[min,max], precipMm:[min,max], elevationM:[min,max], skyExposure:[min,max], terrains: set<enum terrain>, waterAny: set<ref vocab water>, aspectMin: map<ref vocab sphere, score>} | 该群落成立的条件包络；缺项表示不限制 |
| `priority` | integer | 多个包络同时成立时取大者 |
| `floraKgPerM2` | number（单位见 §8 Q2） | 满覆盖时野生植物可持续现存量 |
| `faunaKgPerM2` | number | 第一营养级动物可持续现存量 |
| `canopy` | fraction | 冠层遮蔽，供卷二十算光照 |
| `seasonDensity` | map<ref vocab season, fraction> | 各季生长密度系数，供 §4.7 再生律 |

#### 4.3.2 统一入口

`placeView().dims.biome` 等。全书只有这一处把自然量变成群落代号；卷十 §4.6 的生成期栖地派生、卷二十 §4.5 的温度、卷二十五的作物适生都读它。

#### 4.3.3 规则

1. **填什么**：地点行只手填 `terrain`、`elevationM`、`skyExposure`、`waterAccess`、`forestCover`（以及可选的 `slope`、`aspect`）；气温与降水只在政区级填，其余全部派生。
2. **气温按海拔修正**：`annualMeanTempC = nearest(rel_contains, 区域气温) − (elevationM − 区域参考海拔) × climate.json.lapseRate`。
3. **群落派生**：候选集 = 包络对该地点全部已知自然量成立的 `biome` 条目；结果 = 候选中 `priority` 最大者，并列取代号字典序最小。实现为卷二 §1.12 的 `first(rules)`，规则列表由加载器按 (`priority` 降序, 代号升序) 从 `biome` 族条目生成；没有兜底项，无候选即未知（`gap`）。包络引用的任一量未知时，该条按未命中处理（卷二 §1.12 未知传播总则）。
4. **地形与群落的分工**：`terrain` 回答"地势是什么"（封闭 10 项，决定路况与防御）；`biome` 回答"长什么、养什么"（开放，决定资源与栖地）。两者不互相替代，规则不得用其一推断另一的职责。
5. **野性**：`wildness = lookup(climate.json.wildnessCurve, 人口压力)`，人口压力 = 本地点及其后代的人口数 ÷ `areaM2`（人口读卷八 §4.16 统计层）。
6. **超自然浸染**：`aspect` 的基值在地点行，可被以地点为对象的状态容器实例（卷二 §1.11（状态容器），内容由卷十五登记）修正。群落包络的 `aspectMin` 读修正后的值，所以浸染加深可以让一处地点的群落改变，不需要专门规则。
7. **性状视图**：旧的"地形性状"（卷零 129 行）改为读 `terrain`、`biome`、`aspect` 的代号，词表机制归卷二。

#### 4.3.4 交互

卷十 §4.6（生成期读）、卷二十 §4.3/§4.5（天气与温度读 `biome`、`elevationM`、`skyExposure`）、卷二十 §4.6（水循环读 `elevationM`、`waterAccess`）、卷二十五（作物适生读 `biome`、`soilFertility`）、卷四与卷十六（物种 `habitats` 引 `biome` 代号）。

#### 4.3.5 数据实例

- 西陲一处河谷：`terrain_plain`、低海拔、区域气温温和、降水中等、`forestCover` 低 → 派生出一个温带草地类群落。
- 非西陲一处高纬山地：`terrain_mountain`、高海拔；区域气温经递减率修正后低于树线包络 → 派生出高山冻原类群落；同郡低处的地点派生出针叶林类群落。两处手填值只差 `elevationM`。
- 超自然一处被浸染的林地：自然量与邻近林地相同，`aspect` 中某一领域分值高于某群落条目的 `aspectMin` 且该条目 `priority` 更大 → 派生出异化林群落；浸染状态结束后自动回到普通林群落。

#### 4.3.6 验收断言

- 【扫描】A5-3.1：`placeView` 之外的地形、海拔、群落解析函数数量为 0；对地点显示字段的任何匹配为 0（S5-1、S5-2）。
- 【不变量】A5-3.2：同一组自然量在任何地点得到同一 `biome`；`biome` 结果只依赖包络列出的量；任何地点行无手填 `biome`。
- 【扩展性】A5-3.3：新增一个 `biome` 条目（只加数据），所有包络成立的地点自动改用它，且其上的栖地容量、资源场潜力随之重算，不改代码。

### 4.4 地质与矿脉

#### 4.4.1 维度

- 地点侧：`stratum`、`deposits`（矿物键）、`depositDepthM`。
- 矿物赋存行（`geology-occurrence.json`）：`{key: ref refs[kind material, vocab matcat], strata: set<enum stratum>, form: enum dform, frequency: fraction, richness: distribution score, depthM: distribution m, terrains: set<enum terrain>, waterAny: set<ref vocab water>}`。键可以是一个材料类别，也可以是一种材料；这是数据行的键，不是规则里的 id。
- 储量换算：`renewal.json.reserveCurve`（丰度评分 → 每平方米千克数）。

#### 4.4.2 统一入口

`placeView().dims.deposits`、`placeView().stockRows`（矿物存量的 `renewable` 为 false）。

#### 4.4.3 规则

1. **赋存由岩层决定**：一处地点能有哪种矿，只由赋存行的 `strata`、`terrains`、`waterAny` 对该地点成立与否决定。卷十在生成期按 `frequency` 抽取是否存在，按 `richness`、`depthM` 抽取评分与埋深，种子键按卷二 §1.10（随机实例化）。
2. **校验**：手写内容里的矿物键若不满足任何赋存行，加载报错（错误码由卷二 §4.3（错误码表）新增，见 §8 Q1）。这保证"有盐滩的地形才有盐"对手写与生成内容同样成立（卷一 §3 R-7）。
3. **初始储量**：`储量千克 = lookup(reserveCurve, 评分) × areaM2 × dform.continuity`。首次读取时由 `resource-field.mjs` 以"地质来源"入账到该地点的储备账户，之后只减不增。
4. **埋深决定取法**：`depositDepthM` 为 0 可露天取；大于 0 时取用方法的需求块须含地下通达（§4.5）。埋深只进入需求与工时，不另写规则分支。
5. **矿石到金属**不在本卷：那是配方行（卷三 §4.8 的通用规则）。
6. **未探明**：存量存在与"有人知道"是两回事；知情归卷二十二，探矿归卷十七的探索。`placeView` 给规则层真值，投影层按知情过滤。

#### 4.4.4 交互

卷十（按赋存行生成）、卷三（材料行与类别）、卷六 §4.7（产业选址读 `fields`）、卷二十 §4.6（`stratum.aquifer` 供水循环）、卷二十二（探明与否）。

#### 4.4.5 数据实例

- 一种蒸发盐类材料的赋存行：`strata` 含沉积类，`form` 为层状，`terrains` 含 `terrain_coast` 与 `terrain_desert`；西陲任何满足条件的地点都可能被抽中，不点名哪一处。
- 非西陲一处火成岩山地：一条键为金属矿类别的赋存行成立，`form` 为脉状，`depthM` 分布偏深 → 该地点得到带埋深的矿物键。
- 超自然材料的赋存行：`strata` 不限，`terrains` 只含 `terrain_cave`，另由卷十五登记的行补充条件；材料行本身由卷十五 §4.13 登记。

#### 4.4.6 验收断言

- 【扫描】A5-4.1：规则层与本卷规则字段中材料 id 字面量为 0；采矿相关代码不再出现以任务显示名判断的分支（卷零 06b D 类）。
- 【不变量】A5-4.2：每个矿物键都至少满足一条赋存行；矿物储备账户余额单调不增；余额不为负。
- 【扩展性】A5-4.3：新增一种矿物 = 一行材料加一行赋存，生成器自动在合适岩层放置，资源场类型按材料属性自动匹配（§4.7），不改代码。

### 4.5 地下层与洞穴

#### 4.5.1 维度

没有专用字段。地下地点是 `skyExposure` 为 0、`elevationM` 低于其地表祖先的 place 行；洞穴用 `terrain_cave`。派生 `depthM = 最近的 skyExposure 大于 0 的祖先的 elevationM − 自身 elevationM`（`placeView` 派生字段）。

#### 4.5.2 统一入口

`placeView().dims`（含 `depthM`）与 `routeView()`（上下连通的边）。

#### 4.5.3 规则

1. **地下是地点，不是聚落类型**：现状把营窟当聚落类型；改为"站点类型是什么"与"是否在地下"两个独立维度。
2. **地下气温**：`skyExposure` 为 0 的地点，气温 = 地表祖先的年均气温 + `depthM × climate.json.geothermalGradient`，不随季节变（季节振幅归卷二十 §4.5，按 `skyExposure` 缩放）。
3. **地下群落**用同一派生：包络里的 `skyExposure` 区间取 0 的条目才会命中，所以地下自然得到无光群落，不需要第二张表。
4. **通达**：地下地点与外界只靠 `edges` 连通；没有边就不可达。取深部矿体须存在一条到达该埋深的连通路径（由矿井这类建筑实例提供，建造归卷十九）。
5. **分层**：多层地下就是多级 `parent`，层数不设上限。

#### 4.5.4 交互

卷二十（光照为 0、气温恒定、水位）、卷十六（巢穴选址读 `depthM` 与 `biome`）、卷十九（矿井、地窖是建筑实例）、卷十五（秘境可挂在地下）。

#### 4.5.5 数据实例

- 西陲一处山腹矿洞：`terrain_cave`、`skyExposure` 0、比洞口低数十米；与洞口之间一条边。
- 非西陲一处三级深洞：三行逐级为 `parent`，越深气温越高，最深一级命中另一无光群落。
- 非人类一处地下巢穴：`comp_settlement`，`siteType` 取巢穴类条目，居民为非人物种；它与地表人类村落用同一套维度。

#### 4.5.6 验收断言

- 【扫描】A5-5.1：代码中以聚落类型或显示名判断"是否在地下"的分支为 0；判断只读 `skyExposure` 与 `depthM`。
- 【不变量】A5-5.2：`skyExposure` 为 0 的地点 `depthM` 大于 0；地下地点至少有一条边或被标记为封闭（无边）且此时任何行程不可达。
- 【扩展性】A5-5.3：给任一现有地点加一行地下子地点与一条边，群落、气温、栖地容量自动派生，不改代码。

### 4.6 站点类型

#### 4.6.1 维度

- 地点侧：`siteType`（挂 `comp_settlement` 时必填）。
- `site` 族条目字段：`popRange: [min,max]`（常住人口）、`needsEnclosure: boolean`（是否要求围护设施）、`permanent: boolean`、`governed: boolean`（是否有治理席位，供卷八读）、`accessDefault: enum access`、`promotesTo` 与 `demotesTo: ref vocab site nullable`、`rank: integer`。
- 滞回阈值在 `site-rules.json`。

#### 4.6.2 统一入口

`placeView().dims.siteType`；写入口 `reclassifySite`。

#### 4.6.3 规则

1. **站点类型回答"这是什么地方"**（台账 X-26）；建筑干什么用是设施类型（卷十九 §4.2），庙与神殿是设施类型，整座寺院是一个站点类型行加其建筑的设施类型；圣地是地点上的信仰修正（卷七 §4.4）。本卷不另立场所表。
2. **资格由维度定**：一处地点能否是某类型，只看条目字段对该地点成立与否（人口区间、是否有围护、是否常住）。谁喜欢住哪类站点是物种行与组织行引用 `site` 代号的偏好（归卷四、卷八），本卷不写。
3. **升降**：`reclassifySite` 在调度日（周期归卷二十 §4.1）检查人口是否越出 `popRange` 并超过滞回量持续满 `site-rules.json.holdDays`；满足则沿 `promotesTo` 或 `demotesTo` 改写并发出事件（事件类型行由本卷向卷二十四 §4.2 登记）。没有后继类型的条目不升降。
4. **废弃**：常住人口归零且持续满期限，转为该条目的 `demotesTo`（通常是遗址类）。遗址是站点类型的一行，不是特殊逻辑。
5. **生成同律**：卷十物化远方聚落时用同一资格判断选类型，写回同一字段（卷一 §3 R-7）。

#### 4.6.4 交互

卷八 §4.5（领地持有读 `siteType.governed`）、卷十 §4.3（物化）、卷十九（围护设施的存在供 `needsEnclosure` 判断）、卷十六（巢穴是站点类型行，巢穴内容归该卷）、卷二十四（升降事件）。

#### 4.6.5 数据实例

- 西陲一个村：人口在村类条目区间内；人口增长越过上界加滞回并保持满期限后，转为镇类条目。
- 非西陲一处游牧营地：条目 `permanent` 为 false、`needsEnclosure` 为 false；迁走后原地点人口归零，按规则 4 处理。
- 非人类一处兽群巢穴：条目 `governed` 为 false；与人类站点共用 `popRange`、升降规则。

#### 4.6.6 验收断言

- 【扫描】A5-6.1：代码中出现站点类型显示名或 `site_` 代号字面量作分支的行数为 0（规则只读条目字段）。
- 【不变量】A5-6.2：每个 `comp_settlement` 行的人口在其类型 `popRange` 加滞回范围内，或正处于持续期计时中；`promotesTo`/`demotesTo` 图无环。
- 【扩展性】A5-6.3：新增一个站点类型条目并接入升降链，现有聚落到达区间后自动转入，不改代码。

### 4.7 资源场、再生律与栖地容量

#### 4.7.1 维度

- 地点侧：`deposits`、`stocks`（派生）、`habitatCapacity`（派生）、`fields`（派生）。
- 运行态：存量账户余额 `visible`；`fieldState.<地点>.<存量> = {persistence: integer（百万分比）, growthAnchors, lastSettledDay}`。
- `field` 族条目（资源场类型行）字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `stockKinds` | set<enum kind> | 适用的存量对象种类（材料、植物、物种） |
| `stockWhen` | rx | 对存量对象自身维度的条件（类别、物性、体型、食性等） |
| `placeWhen` | rx | 对地点维度的条件（地形、水体、露天比例、气温、降水、埋深等） |
| `methods` | set<ref vocab hmethod> | 此类资源场可用的取用方法 |
| `facilityType` | ref facility_type nullable | 成规模开发时对应的设施类型（行归卷十九） |
| `minCapacityKg` | number | 容量低于此值不成场 |

- 再生参数读存量对象自己的行：植物的 `regrowRate`、`habitats`、`yieldPerM2`（卷二 §5.19）；物种的 `habitats`、`bodyMassKg`、`diet`、成熟与繁殖字段（卷二 §5.3）。本卷不给这两张表加字段；缺的参数见 §8 Q3。

#### 4.7.2 统一入口

读：`placeView().stockRows`、`.dims.fields`、`.dims.habitatCapacity`。写：`settleStocks`（再生结算）、`take`（§4.8）。存量的唯一扣减路径是 `take`（台账：读存量；只经取用律扣减）。

#### 4.7.3 规则

1. **存量集合由地点推出**：`stocks(地点) = deposits 的矿物键 ∪ {野生植物 p | biome ∈ p.habitats} ∪ {物种 s | biome ∈ s.habitats}`。地点行不列"这里有什么动植物"。
2. **栖地容量**（`habitatCapacity`，单位千克现存量）：
   - 野生植物：`areaM2 × biome.floraKgPerM2 × 份额(p) × 丰度系数`；份额 = 该群落中同类植物均分（按 `taxon` 分组后组内均分，分组与均分的权重表在 `renewal.json`）；丰度系数 = `deposits` 有该键时 `lookup(richnessCurve, 评分)`，否则为 1；乔木类再乘 `forestCover`。
   - 第一营养级动物：`areaM2 × biome.faunaKgPerM2 × 份额(s)`。
   - 更高营养级：`Σ(其食物对象的当前现存量) × renewal.json.trophicEfficiency × 份额(s)`，食物对象由 `diet` 代号与对方的类别代号匹配得出。捕食者容量因此随猎物多寡自动涨落。
   - 水生对象把 `areaM2` 换成该地点可及水体面积（来自卷二十 §4.6 的水量入口）。
3. **再生律**（保留现有通用再生律纯函数为骨架，卷一 §5.1）：以世界日为步长，逻辑斯蒂增长；增长率取存量对象行的参数乘以当季 `biome.seasonDensity`；有效容量 = `habitatCapacity × persistence`；繁殖群未灭绝时以对象行的最小重启量为增长基数，灭绝后不再生长。再生量以"再生来源"入账到储备账户（卷六 §4.1）。矿物没有再生。把一段时间切成更小的区间结算，结果相同。
4. **资源场类型由地区资源推出**：`fields(地点) = {(t, x) | x ∈ stocks(地点)，kindOf(x) ∈ t.stockKinds，t.stockWhen(x) 为真，t.placeWhen(地点) 为真，容量(x) ≥ t.minCapacityKg}`。这是派生维度，任何地点行不得手填"此处有某某场"。同一种存量在不同地形可成不同类型的场（同一种盐类材料：滨海露天加干热成晒盐类场，埋藏在沉积层里成井矿类场），区别全在 `placeWhen`。
5. **规模由需求推出**：资源场的开发规模（工位数）不是地点维度，是建在该地点上的设施实例的工位数（卷十九）。本卷给出规模律，生成期（卷十）与运行期（卷六 §4.7 的开工决策）用同一式：
   - `可持续日产 = 再生对象：增长率 × 有效容量 ÷ 4；矿物：当前储量 ÷ renewal.json.depletionHorizonDays`；
   - `可达需求日量 = 运输成本可及范围内对该场各产物的市场需求（读卷六 §4.4）`；
   - `目标工位数 = min(可达需求日量, 可持续日产) ÷ 单工位日取量（§4.8 取用律在标准技能与工具下的值）`，向下取整。
   没有需求的资源场潜力存在但工位数为 0；需求上升后开工决策按同式扩建。
6. **扩散与迁徙**：相邻地点（有边且对该对象 `habitats` 成立）之间，现存量与有效容量之比超过 `renewal.json.dispersalThreshold` 的一方向比值低的一方按差值比例转移（账本转移，守恒）。季节性迁徙是物种行上的季节栖地偏好引起的同一扩散，路径取位沿用现有迁徙模块，计划内容归卷十六。
7. **个体与存量的对应**：被物化成个体的动物（卷四）计入存量；个体出生与死亡事件由 `resource-field.mjs` 订阅并与账户对平。离屏聚合归卷二十七。
8. **规律是分布**：生成期的丰度、扩散的取整余数用卷二 §1.10 的种子键抽取，允许个别地点偏离均值；不为任何地点写特例。

#### 4.7.4 交互

卷二十五 §4.8（方法行、食物链含义）、卷十 §4.6（生成期只调本节的派生，不另算）、卷六 §4.1/§4.4/§4.7（账本、需求、开工）、卷十九（设施实例与工位）、卷二十（季节、水量）、卷四与卷十六（物种行）、卷二十七（离屏聚合）。

#### 4.7.5 数据实例

- 西陲一处林地：群落为温带林类，若干野生乔木的 `habitats` 含该群落 → 自动得到木材存量与林场类潜力；附近村镇的柴薪与建材需求决定伐木工位数。
- 非西陲一处干热海岸：`deposits` 有一种蒸发盐类材料键（由赋存行生成），`placeWhen` 对晒盐类场成立 → 得到该场潜力；若可达范围内无城镇，工位数为 0，城镇出现后按规模律扩建。
- 非人类一处沼泽：群落养得起一种大型食草兽，其现存量又决定一种捕食怪物的容量；猎人把食草兽取到繁殖群受损后，捕食者容量随之下降并向邻地扩散。

#### 4.7.6 验收断言

- 【扫描】A5-7.1：规则层与本卷规则字段中物品、材料、植物、物种 id 字面量为 0；`take` 与 `settleStocks` 之外写存量账户的调用点为 0（S5-3、S5-4）；地点行无手写资源或再生字段。
- 【不变量】A5-7.2：对每个地点每种存量，期末余额 = 期初 + 再生入账 + 扩散净入 − 取用转出；余额在 [0, 有效容量 + 最小重启量] 内；分段结算与整段结算结果相同；矿物余额单调不增。
- 【扩展性】A5-7.3：新增一种野生植物行（带 `habitats`）与一行资源场类型，所有群落匹配的地点自动出现该存量与该场潜力，NPC 可按规模律开工，不改代码。

### 4.8 取用律

#### 4.8.1 维度

`hmethod` 族条目（取用方法行）字段。行由卷二十五 §4.8（狩猎、捕鱼、采集）与卷六 §4.7（采矿、伐木等产业方法）登记；字段含义只在本节。

| 字段 | 类型 | 含义 |
|---|---|---|
| `stockKinds` | set<enum kind> | 可作用的存量对象种类 |
| `stockWhen` | rx | 对存量对象维度的条件（体型区间、类别、硬度等） |
| `requirement` | ref vocab requirement | 工具与能力要求（卷二 §1.13；能力代号归卷三 §4.6） |
| `capabilities` | set<ref vocab capability> | 身体行动能力要求（卷四 §4.2） |
| `skill` | ref skill | 所用技能 |
| `rateKgPerMinute` | number | 标准条件下的取量速率 |
| `densityExponent` | number | 速率随"现存量÷有效容量"下降的指数 |
| `skillCurve` | curve | 技能值 → 速率系数 |
| `damageShare` | fraction | 取量中伤及繁殖群的比例 |
| `spareCurve` | curve | 技能值 → 可避免的伤害比例 |
| `parts` | set<ref vocab plant_part> | 取植物的哪些部位；空表示整株 |
| `alive` | boolean | 取出的动物是否为活体 |
| `emits` | map<ref vocab sense, number> | 取用时发出的信号强度（供 §4.2） |

#### 4.8.2 统一入口

`take(engine, state, {actor, place, stock, method, effortMinutes})`。全书凡"从资源场取出东西"只有这一个入口（台账 X-10）：矿、木、猎、渔、采同律；玩家、NPC、离屏聚合同律。

#### 4.8.3 规则

1. **可行性**（任一不满足即返回失败与原因代号，不扣时间以外的任何东西）：`(方法, 存量)` 属于该地点 `fields` 中某个资源场类型的 `methods`；`method.stockWhen` 对该存量成立；取用者满足 `requirement`（读其持有物的能力）、`capabilities`（卷二 §2.5 的 `can`）；取用者位于该地点；埋深大于 0 的矿物须有通达路径（§4.5 规则 4）。
2. **取量**：`taken = min(账户余额, effortMinutes × rateKgPerMinute × (现存量 ÷ 有效容量)^densityExponent × lookup(skillCurve, 技能值) × 工具系数)`。工具系数 = 所持能力等级超出 `requirement` 最低等级的部分经 `harvest-methods.json.toolCurve` 查得。整个乘积作为过程槽 `process.takeYield`（卷二 §3.7（旧派生槽的对照与过程主体槽））求值，职业、天气、设施、信仰的影响都以修正项进入，不改本式。
3. **扣减与入账**：一次账本转移，从地点储备账户转到取用者；守恒由账本保证。取用者受雇时归属按其雇佣合同条款（卷六 §4.16），本卷不判断。
4. **产物**：存量对象到物品的映射读对象自己的行，不读 id：植物按 `parts` 与植物行的 `products`（卷二 §5.19）；动物 `alive` 为真得活体个体，否则得尸体并走卷四 §4.8 的尸体产出；矿物得该材料的原料形态物品（卷三）。产物的材料属性、品质由卷三 §4.8 的通用继承规则给出，职业技能通过 `skillCurve` 与品质修正进入，意图通过所选方法与 `parts` 进入（北极星：材料属性、职业技能、意图三者共同推出产物）。
5. **伤及繁殖群**：对可再生存量，`persistence` 减少 `damageShare × (1 − lookup(spareCurve, 技能值)) × taken ÷ (栖地容量 × persistence)`，下限 0；同一方法、同一技能下多次取用的伤害可加（沿用现有再生律骨架的性质）。
6. **合法与可行分开**：有没有取用权（林权、矿权、渔猎许可，是登记在卷十八 §4.1 的持有种类行）不影响 `take` 能否成功，只决定是否产生一条"无权取用"的事实供卷八b 认定。世界允许偷猎与盗采，后果由法律与知情决定。
7. **NPC 同律**：NPC 的取用是卷九动作目录里的同一动作，执行器调同一 `take`；NPC 是否去取由其职业、家户需要与价格决定（卷六、卷九），本卷不设"NPC 专用产出"。
8. **信号**：取用期间按 `emits` 在该分区发出信号，供 `perceive`。

#### 4.8.4 交互

卷二十五 §4.8、卷六 §4.7（登记方法行、调入口）；卷九 §4.1/§4.2（动作与执行器）；卷三 §4.6/§4.8（工具能力、产物继承）；卷四 §4.8（尸体产出）；卷十四 §4.3（技能）；卷十八 §4.1（取用权种类行）；卷八b（无权取用的认定）；卷二十七（离屏时以聚合工时调同一入口）。

#### 4.8.5 数据实例

- 一条伐木方法行：`stockKinds` 含植物，`stockWhen` 要求乔木类，`requirement` 要求劈砍能力达到某级，`parts` 为主干；西陲任何有林场类潜力的地点都可用。
- 非西陲一条冰面凿洞捕鱼方法行：`stockWhen` 限定水生且体型区间，`requirement` 含凿与钩线两组能力；只在 `placeWhen` 允许此方法的资源场类型下可用（该类型的地点条件含低气温与静水）。
- 非人类取用者：一头有劈砍能力肢体的怪物对同一林地调用 `take`，能力来自其身体部件（卷四），规则与人相同；它不持有取用权同样产生"无权取用"事实。

#### 4.8.6 验收断言

- 【扫描】A5-8.1：`take` 之外从地点储备账户转出的调用点为 0；采集、伐木、采矿、钓鱼各模块中技能 id、属性显示名、物品 id 字面量为 0（卷零 138、169 行所列写死全部消失）。
- 【不变量】A5-8.2：每次 `take` 前后，地点储备减少量 = 取用方增加量 = `taken`；`taken` 不超过调用前余额；`persistence` 在 [0, 1 000 000]；同输入同种子结果逐位相同。
- 【扩展性】A5-8.3：新增一条方法行并写进某资源场类型的 `methods`，玩家与 NPC 立即可用该方法，不改代码；新增一种带合适能力的非人物种，无需任何专项规则即可取用。

### 4.9 发展度与控制度

#### 4.9.1 维度

`development`、`control`（score，只挂 `comp_settlement`）。政区没有这两个存储维度；`placeView().regionProgress` 给出其下站点按人口加权的平均（派生字段）。常数在 `progress.json`：`devTargetCurve`（人口密度 → 目标发展度）、`devRatePerDay`、`devDiffusion`、`devTradeWeight`、`controlRatePerDay`、`controlDropOnTransfer`、`controlTargetWeights`。

#### 4.9.2 统一入口

读 `placeView().dims.development/control`（修正后值）；写 `stepProgress`。

#### 4.9.3 规则

1. **发展度是慢变量**：`目标 = lookup(devTargetCurve, 人口 ÷ areaM2) + devTradeWeight × 过境贸易量指数（读卷六的流量报告）`，再经修正管线（地形、站点类型的修正模板，§4.10）；每日 `development += devRatePerDay × (目标 − development) + devDiffusion × max(0, 有边相邻站点的均值 − development)`。向上慢、可向下：破坏类事件按事件类型行给出的幅度参数直接扣减（订阅卷二十四的事件）。
2. **控制度是快变量**：`目标 = 100 × Σ controlTargetWeights[i] × 因子_i`，因子全部读别卷入口并归一到 [0,1]：持有者正统性（卷八 §4.7）、治理席位在任比例（卷八 §4.2）、驻防力量与人口之比（卷十三）、到持有者驻地的行程钟点经曲线换算（卷十七）、治安值（卷八b §4.7）。每日向目标靠拢 `controlRatePerDay`。持有者变更事件发生时立即乘以 `controlDropOnTransfer`。
3. **后果一律是修正项**：发展度、控制度对补给、税、征召、建造、迁入吸引力的影响，写成 `progress.json.modifierTemplates` 里的修正项模板（卷二 §3.2（修正项的格式）），`valueRX` 读来源地点的 `development` 或 `control` 基值，`scope` 为 `located` 或 `jurisdiction`；目标键由拥有该量的卷登记（税与征召卷八 §4.11、补给卷十三、建造卷十九），本卷不定义这些键。
4. **无人之地**没有这两个维度（不挂 `comp_settlement` 即不适用），不是 0。

#### 4.9.4 交互

卷八 §4.16（人口）、§4.7、§4.11；卷六（贸易流量）；卷十三（驻防、补给）；卷十七（行程）；卷八b §4.7（治安值，并反过来读 `control`）；卷二十四（破坏事件、持有者变更事件）。环：治安值读 `control`、控制度目标读治安值——以"读前一日值"打破，写入 `progress.json.lagDays`。

#### 4.9.5 数据实例

- 西陲一座通商镇：人口密度中等、过境贸易量高 → 目标发展度高于同密度的闭塞镇，逐年上升并向相邻村扩散。
- 非西陲一处新征服的山城：持有者变更当日控制度乘以转移系数骤降；驻防比高但离新持有者驻地远，之后缓慢回升到一个不满的目标值。
- 非人类一处怪物族群控制的旧矿镇：同样有 `control`，因子读的是该族群组织的正统性与席位；人类政区对它的 `control` 不适用。

#### 4.9.6 验收断言

- 【扫描】A5-9.1：`place-progress.mjs` 之外写这两个维度的调用点为 0；代码中不出现发展度、控制度的系数字面量（S5-7）。
- 【不变量】A5-9.2：两值恒在 [0,100]；无事件时 `development` 的日变化绝对值不超过 `devRatePerDay × 100 + devDiffusion × 100`；`regionProgress` 等于其下站点人口加权平均。
- 【扩展性】A5-9.3：在 `controlTargetWeights` 加一个因子（指向一个已登记的维度键）或加一条修正项模板，全部站点生效，不改代码。

### 4.10 地形修正

#### 4.10.1 维度

- `terrain` 条目字段 `paceFactor`、`roughness`、`coverScore`；边的 `terrainMix`、`speedFactor`（派生）。
- `terrain-modifiers.json`：`{byTerrain: map<enum terrain, list<修正项模板>>, byBiome: map<enum biome, list<…>>, bySite: map<enum site, list<…>>, slopeCurve, wetCurve}`。模板字段与卷二 §3.2 相同，缺 `source`（展开时填地点）。

#### 4.10.2 统一入口

读 `routeView().speedFactor`；其余地形后果经卷二 §2.1 的 `modified(...)` 自动生效，没有专门入口。

#### 4.10.3 规则

1. **路况系数**（台账 X-13 判给本卷的唯一量）：`speedFactor = wsum(terrainMix, terrain, paceFactor) × lookup(slopeCurve, |ascentM| ÷ distanceM)`；`waterway` 为真的边不乘坡度项。它只描述路，不含行者、载具、负重、天气——那些由卷四 §4.6、卷十七 §4.1/§4.8、卷二十在合成时相乘。
2. **展开**：加载期对每个地点，按其 `terrain`、`biome`、`siteType` 的代号取模板，生成 `source` 为该地点、`scope` 为 `located` 的修正项，进入卷二 §3.3 的唯一管线。地形对建筑、补给、防御的影响全部是这样的修正项；目标键由卷十九 §4.4、卷十三 §4.9、卷八登记。
3. **不写地形分支**：代码不得出现"若为山地则…"式分支；地形只通过条目字段与模板起作用。
4. **混合地形**：站点只有一个主地形；边用 `terrainMix` 比例加权。战场地形读交战地点的 `terrain` 条目字段 `roughness`、`coverScore`（卷十三 §4.9 定用法）。

#### 4.10.4 交互

卷十七（合成行程、路途风险读 `speedFactor`、`terrainMix`）；卷十三 §4.9；卷十九 §4.4（可建与造价）；卷八（补给上限）；卷二十（`wetCurve` 所需的湿度量由卷二十提供，作为模板的 `when` 条件）。

#### 4.10.5 数据实例

- 一条平原占七成、丘陵占三成的边：`speedFactor` 为两种 `paceFactor` 的加权值乘坡度项。
- 非西陲一座沼泽中的城：`byTerrain` 中沼泽的模板给建造工时一条乘性修正、给防御一条加性修正，对城内全部建造与守方生效。
- 超自然一处群落为异化林的地点：`byBiome` 中该群落的模板给位于其内者的某项身体能力一条负修正（目标键 `body.*`，卷二 §3.6）；离开即失效。

#### 4.10.6 验收断言

- 【扫描】A5-10.1：全仓库以地形显示文字或正则定路速、定海拔的代码为 0（卷零 1105 行所列一处消失）；`terrain_` 代号字面量不出现在规则层分支里。
- 【不变量】A5-10.2：`terrainMix` 各项和为 1；`speedFactor` 大于 0；同一地点同一目标键的地形修正只经卷二 §3.3 的管线求值，`explain` 逐段复算等于结果。
- 【扩展性】A5-10.3：给某地形加一条模板（例如对某过程槽的修正），所有该地形地点立即生效；新增群落条目可带自己的模板，不改代码。

### 4.11 法域槽派生

#### 4.11.1 维度

`lawCode`（派生 ref law_code）；`placeView().lawSlots: list<{place, binding}>`。绑定记录的格式与内容归卷八b §4.1；本卷只要求它以地点 id 为键。

#### 4.11.2 统一入口

`placeView().dims.lawCode` 与 `.lawSlots`。修正作用域 `jurisdiction` 的解析（卷二 §3.5）调同一实现。

#### 4.11.3 规则

1. **沿树解析**（台账 X-23）：`lawSlots` = 从本地点起沿 `rel_contains` 向上，每遇到有绑定的祖先取一项，自近及远排列；`lawCode = nearest(rel_contains, 绑定)` 即列表首项。
2. **只解析，不解释**：多项之间谁优先、怎样叠成规范栈，是卷八b §4.1 的事；本卷保证顺序与完整。
3. **无绑定是合法结果**：到根仍无绑定 → 未知（`gap`）；"无法之地"的后果由卷八b 定。
4. **特殊地位不靠地点 id**：终审所在、都城之类的地位，一律由"哪个职位席位设在此地、该职位的辖区层级是什么"读出（`officeView`，卷八），不出现任何地点 id；政体种类读 `polityView` 的种类代号，不读名称。
5. **飞地与治外**：飞地就是其祖先链上较近处另有绑定；对特定人群的治外待遇是规范栈的适用条件（卷八b），不改变槽的解析。

#### 4.11.4 交互

卷八b §4.1（读 `lawSlots`）、§4.7；卷六 §4.20、卷二十一 §4.6（违禁按法域）；卷八（职位辖区）。

#### 4.11.5 数据实例

- 西陲一间私宅分区：自身无绑定，向上经房屋、村、郡，在郡上遇到绑定，再上在王国级政区遇到第二项 → `lawSlots` 两项。
- 非西陲一座自治港：港自身有绑定 → 首项为港法，其后才是所属政区的。
- 非人类一处巢穴地点：祖先链上只有人类王国级绑定；巢穴内居民是否适用由卷八b 的适用条件决定，槽照常解析。

#### 4.11.6 验收断言

- 【扫描】A5-11.1：全仓库地点 id 字面量用于法域、终审、都城判断的行数为 0（卷零 170 行所列 10 处消失）；按政体名称首词判断的行数为 0。
- 【不变量】A5-11.2：`lawSlots` 中地点严格自近及远且都是本地点的祖先或自身；子地点的 `lawSlots` 以父地点的 `lawSlots` 为后缀。
- 【扩展性】A5-11.3：给任一地点加一条绑定，其全部后代的 `lawCode` 自动改变；新增一个政区层级不改解析代码。

### 4.12 文化槽派生

#### 4.12.1 维度

`culture`（派生 ref culture）；`placeView().cultureMix: map<ref culture, fraction>`。

#### 4.12.2 统一入口

`placeView().dims.culture` 与 `.cultureMix`。这是全书唯一的"某地是什么文化"的解析，取代现有四套。

#### 4.12.3 规则

1. **主文化**：`culture = first([mode(rel_residents, culture), nearest(rel_contains, culture)])`。有常住居民时取居民文化众数（并列取代号字典序最小，卷二 §1.12）；无人之地取最近有值祖先的主文化；自引用按卷二 §1.12 的 `recursive` 声明沿 `rel_contains` 展开。
2. **构成**：`cultureMix` = 本地点及其后代常住人口按文化的占比，读卷八 §4.16 统计层；各项和为 1；无人口时未知。
3. **不存结果**：两者都不落盘；居民迁入迁出后自动变化。主文化发生变化时由 `place-progress.mjs` 在当日比对并发出事件（供卷七 §4.24 订阅），不写任何维度。
4. **只解析，不解释**：文化的内容、接纳度、融合分化归卷七；本卷只回答"是哪一个、各占多少"。
5. **信仰构成**用同一聚合由卷七读取统计层自行得出，本卷不另设槽。

#### 4.12.4 交互

卷七 §4.20、§4.23、§4.24；卷八 §4.16；卷十（生成时按 §4.15 的梯度安置居民）；卷三、卷十九（按文化偏好选形制，读本槽）。

#### 4.12.5 数据实例

- 西陲一村：居民九成属一种文化 → 主文化为它，`cultureMix` 两项。
- 非西陲一片无人荒原：无居民 → 主文化取所属郡的主文化；`cultureMix` 未知。
- 非人类与人混居的山寨：非人族群文化占六成 → 主文化为该族群文化；人类少数在 `cultureMix` 中可见，供卷七算接纳。

#### 4.12.6 验收断言

- 【扫描】A5-12.1：`placeView` 之外的地点文化取值函数为 0（卷零 171 行所列四处消失）；任何地点行无手填 `culture`。
- 【不变量】A5-12.2：`cultureMix` 各项和为 1 或整体未知；有居民时 `culture` 是 `cultureMix` 的最大项之一。
- 【扩展性】A5-12.3：新增一种文化并安置居民，相关地点的两个派生量自动更新，不改代码。

### 4.13 进入权与私宅许可

#### 4.13.1 维度

`accessClass`（enum access，有序；`access` 条目字段 `rank`、`needsGrant`）。进入许可本身不是地点维度，是持有边（卷二 §2.7；种类行归卷十八 §4.1）。本卷对种类表提出一列要求：`grantsEntry: boolean`（见 §8 Q5）。

#### 4.13.2 统一入口

`canEnter(engine, state, actorId, placeId)`。

#### 4.13.3 规则

1. **逐层判断**：从目标地点向上到它与行为者当前地点的最近公共祖先，路径上每个 `needsGrant` 为真的地点 P 都须满足：行为者本人、其家户或其所属组织，在 P 或 P 的某个祖先（不越过公共祖先）上持有一条 `grantsEntry` 为真的持有边。全部满足 → `ok`；否则返回第一个不满足的地点与原因代号。
2. **主人许可**：对 P 有进入权且位于 P 内、且 `awake`（卷二 §2.5）的人，可以发起"许可进入"动作（卷九动作目录），给他人写一条带到期日的客人类持有边。是否在场读人物位置，是否清醒读谓词；不读活动文字。
3. **营业时段**是同一机制：设施对公众的定时进入许可由卷十九按服务时段写带到期的持有边，本卷不设时段字段。
4. **合法与可行分开**：`canEnter` 只回答"是否有权"；门锁、围墙是否挡得住是设施状态与行动能力的事（卷十九、卷九）。无权而进入成功 → 产生一条"无权进入"事实，认定与后果归卷八b §4.6。
5. **缺省档**由站点类型条目的 `accessDefault` 与设施类型行给出，经类别行继承（卷二 §1.3）；个别地点可写偏离行。

#### 4.13.4 交互

卷十八 §4.1（持有种类）、卷八b §4.6（处分权、侵入认定）、卷九（动作与裁决调 `canEnter`）、卷十九（时段许可、门禁设施）、§4.8（取用前先过本判断）。

#### 4.13.5 数据实例

- 西陲一户私宅：`accessClass` 为需许可档；屋主持有所有类持有边 → 屋主及其家户 `ok`；访客须屋主在场且清醒时许可。
- 非西陲一座行会会馆：需许可档；行会成员经组织成员关系满足；会馆内的账房分区另为更高档，只有持特定职位持有边者满足。
- 超自然一处结界内的地点：需许可档；许可是结界主人写给来者的持有边，或卷十五登记的需求块在边上放行；规则与私宅相同。

#### 4.13.6 验收断言

- 【扫描】A5-13.1：进入权模块内读活动文字、睡眠正则的行数为 0（卷零 165、172 行所列三处消失）；实现中不出现 `access_` 或持有种类代号字面量。
- 【不变量】A5-13.2：对某地点 `ok` 则对其全部 `needsGrant` 为假的后代 `ok`；`canEnter` 调用不改变状态；许可到期后同一调用返回不满足。
- 【扩展性】A5-13.3：新增一种 `grantsEntry` 为真的持有种类（例如通行凭证），持有者立即可进入对应地点，不改代码。

### 4.14 省郡骨架、行政层级词表与邻省条款

#### 4.14.1 维度

- `juris` 族（台账 S-09 判给本卷）：条目字段 `rank: integer`（数值越大层级越高）。首批条目由内容卡按现有省、郡两级加王国级与世界根登记；族开放，可加层级。
- 政区是挂 `comp_region` 的 place 行，带 `regionLevel`。
- `borderTerms: map<ref place, map<ref vocab term, number>>`：对每个相邻同级政区，一组条款代号到数值（布尔写 0 或 1；税率、费率写数）。条款代号的含义由拥有它的卷登记（通行与引渡卷十七 §4.7，关税卷八 §4.11）。

#### 4.14.2 统一入口

读 `placeView()`（`regionLevel`、`tree`、`borderTerms`、派生的 `neighbors` 与 `products`）；写 `setBorderTerm`。

#### 4.14.3 规则

1. **层级单调**：`comp_region` 行沿 `parent` 向上，`rank` 严格递增；站点与自然地块挂在某个政区下。
2. **相邻是派生的**：两个同级政区相邻，当且仅当存在一条边，两端分别是它们的后代。地点行不手填邻居。
3. **条款结构化**：现有的邻省条款文字全部改为条款代号到数值；规则层只读数。条款可以不对称（甲对乙与乙对甲各存一份）。运行期变更只经 `setBorderTerm`，由卷八的外交结算在合同（卷六 §4.16）生效或终止时调用。
4. **物产是派生的**：政区的物产 = 其后代地点 `fields` 的资源场类型与存量对象的汇总，按容量排序；不手填"某省产某物"。
5. **骨架生成**归卷十 §4.2，按本节不变量写入；省郡纲要现有 40 行按卷二 §6.3 迁入 place 表。
6. **政体与政区分开**：政区是地理与行政骨架；哪个组织统治它是持有与职位（卷八）。政区行不存政体名称。

#### 4.14.4 交互

卷八 §4.4、卷八b §4.1（读层级词表）；卷十 §4.2；卷十七 §4.7（关卡读条款）；卷六（关税计税读条款）；卷二十九（地图分层）。

#### 4.14.5 数据实例

- 西陲一省：`regionLevel` 为省级条目，下辖数个郡级行；与东邻省之间因有跨界道路而相邻，`borderTerms` 含通行与关税两项条款值。
- 非西陲一个群岛政区：只通过 `waterway` 边与大陆某郡相邻；条款只有一项引渡值。
- 非人类一片精怪领地：`comp_region`，层级为郡级条目，挂在某省下；与相邻人类郡的 `borderTerms` 中通行条款为 0。它与人类郡是同一种行。

#### 4.14.6 验收断言

- 【扫描】A5-14.1：邻省条款、省郡纲要中用于判断的文字字段读取为 0；政区名称、政体名称的前缀或包含判断为 0（卷零 174 行所列消失）。
- 【不变量】A5-14.2：政区层级沿树严格递增；`borderTerms` 的键都是派生相邻集的成员；每个非根地点恰属于每个更高层级的至多一个政区。
- 【扩展性】A5-14.3：在省与郡之间插入一个新层级（一条 `juris` 条目加若干行），法域槽、文化槽缺省、边境指数、地图分层全部自动适用，不改代码。

### 4.15 边境混居与迁徙表达

#### 4.15.1 维度

`frontierIndex: map<enum juris, fraction>`（派生）；`placeView().cultureMix`（§4.12）；`placeView().migrationPull: {headroom, development, security, frontier}`（派生字段组，全部数值）。曲线在 `frontier.json`。

#### 4.15.2 统一入口

`placeView()` 的上述字段。

#### 4.15.3 规则

1. **边境指数**：对每个行政层级 L，`frontierIndex[L] = lookup(frontier.json.distanceCurve, 沿边到最近的、在层级 L 上属于另一政区的站点的路程)`；无此类站点可达则为 0。它是纯地理量，不读文化。
2. **混居的生成表达**：卷十安置居民时，一处站点的居民文化构成 = 本政区主文化与相邻政区主文化的混合，邻方权重 = `frontierIndex[L] × 接纳系数`（接纳系数读卷七 §4.23 的入口）。接纳低的两文化即使相邻也少混居；这是生成期的初值规则，之后构成只随真实迁徙变化。
3. **迁徙的地点侧表达**：`migrationPull` 给出目的地吸引力的地点侧分量——`headroom`（人口承载力余量，读卷八 §4.16）、`development`、`security`、`frontier`；迁徙流量公式与写入归卷八 §4.16，本卷不算流量。
4. **迁徙改变槽**：迁入迁出改变常住关系 → `cultureMix` 与主文化自动变化（§4.12 规则 3 发事件）。不存在"边境地区专用规则"；边境的特殊性全部来自指数与构成这两个数。
5. **跨郡文化亲和**（卷零 175 行所缺）= 卷七的接纳度在相邻政区主文化之间的取值，按相邻关系（§4.14 规则 2）查，不另存。

#### 4.15.4 交互

卷八 §4.16（迁徙流量读 `migrationPull`）、卷七 §4.23（接纳、融合订阅主文化变化）、卷十（生成安置）、卷十七（边境关卡）。

#### 4.15.5 数据实例

- 西陲一座离省界一日路程的镇：省级指数高、郡级指数更高；生成时居民里有邻省文化的少数。
- 非西陲两国之间的山口站点：两文化接纳系数低 → 尽管指数接近 1，混居比例仍低，`cultureMix` 接近单一。
- 非人类领地边上的人类村：对方主文化为非人族群文化；接纳系数由卷七按两文化的支柱算出，规则与人类之间相同。

#### 4.15.6 验收断言

- 【扫描】A5-15.1：代码中以政区或地点 id、名称判断"是否边境"的行数为 0；边境相关系数字面量不在规则表之外出现。
- 【不变量】A5-15.2：`frontierIndex` 各项在 [0,1]；层级越低的项不小于层级更高的项（低层级边界更近）；其余不变时路程增大指数不增。
- 【扩展性】A5-15.3：新增一条跨界道路，两侧站点的指数与此后生成的混居比例自动变化，不改代码。

### 4.16 地点环境状态读取

#### 4.16.1 维度

本卷不拥有任何环境量。`placeView().env` 是只读字段组：`{weather, tempC, light, sound, scent, waterLevel, statuses}`，每项是卷二十对应入口返回的事实原样转出；`statuses` 是以该地点为对象的状态容器实例列表（读 `statusView`）。本卷为它提供的地点侧维度是 `skyExposure`、`elevationM`、`biome.canopy`、`waterAccess`、`stratum.aquifer` 与包含树。

#### 4.16.2 统一入口

`placeView().env`。需要地点环境的规则读这里，不直接调卷二十的内部函数，也不读天气状态键。

#### 4.16.3 规则

1. **值来自卷二十**（台账：值来自卷二十）：天气状态机 §4.3、温度 §4.5、水循环 §4.6、环境场与光声气味 §4.7/§4.8。本卷不缓存、不改写、不补缺省；卷二十返回未知，这里就是未知。
2. **室内与地下的折算不在本卷**：本卷只保证 `skyExposure` 与父子关系可读；户外量怎样折进室内由卷二十按这些维度算。
3. **依赖声明**：`view:placeView` 的 `uses` 列入卷二十的入口节点，使记忆失效随天气变化（卷二 §2.3（记忆与依赖声明））。
4. **场景卡的地点段**从这里取数，段注册归卷九 §4.10。

#### 4.16.4 交互

卷二十（唯一来源）、卷二十一（温度伤害读 `env.tempC`）、卷二十五（农事读天气与水）、卷九（场景卡）、§4.2（感知用环境量）。

#### 4.16.5 数据实例

- 西陲一处露天集市分区：`skyExposure` 为 1 → `env` 各项等于所在站点的户外值。
- 非西陲一间雪原上的屋内分区：`skyExposure` 为 0 → `env.tempC` 是卷二十折算后的室内值，`env.weather` 仍为所在地天气但对室内者的影响由卷二十按露天比例给出。
- 超自然一处被施加了黑暗类状态容器的地点：`env.statuses` 含该实例，其修正项降低 `env.light`；本卷无专门处理。

#### 4.16.6 验收断言

- 【扫描】A5-16.1：卷二十模块之外直读天气、温度、水量状态键的行数为 0（经 `placeView().env`）；本卷模块对这些键的写入为 0。
- 【不变量】A5-16.2：`env` 每项与同一时刻卷二十入口的返回逐位相同；读取不改变状态。
- 【扩展性】A5-16.3：卷二十新增一种环境量并登记后，在 `env` 的字段登记表加一行即可被所有规则读到，不改本卷代码。
