## §0 卷首

### 0.1 范围

本卷定义“人和货怎样从一地到另一地，要多久，路上会出什么事”。共十一个子系统：行程合成（路线、距离、速度、钟点）；载具；车行、运单、货损、索赔、护卫；承运与邮递；水运、海运、封冻禁航；路途风险律；关卡、通行条款、引渡；负重、体力与行程；远方路网；旅行危险按地形；探索与未知地点。另按卷四 §8 Q-16、卷十九 §8 Q24 的移交，本卷持有个体位置的唯一写入口与“某实体此刻在哪个地点行”的唯一读入口（§3）。

不在本卷：

- 边的结构、几何最短路与距离、路况系数 `speedFactor`：卷五 §4.1（地点包含树与坐标）、卷五 §4.10（地形修正）。本卷只读。
- 承载能力与“负重到速度、体力”的公式、步态：卷四 §4.6（步态、移动、负重），全书唯一（台账 X-13）。本卷只调入口，再乘路况与环境。
- 物品的质量、体积、运法、货值密度、易损度：卷三乙 §4.2（物品通用字段）、卷三乙 §4.18（运法与货值密度）。耐久与故障：卷三乙 §4.10（耐久与劣化）、卷三乙 §4.9（拆解、修理、故障）。

## §1 领域总述

### 1.1 真实世界怎样运转

1. 走多快取决于四样东西：谁在走（身体与步态）、带了多少（负重）、路怎么样（地形、坡度、路面）、天怎么样（雨雪、冰、风、昼夜）。队伍的速度由最慢的那个决定。
2. 车和船把“驮在身上”换成“拉着走”或“浮着走”：同样的力能带动更多的货，但车要路，船要水，各有走不了的地方和季节。车船的好坏取决于用什么料、谁造的、照什么样式造。
3. 一天能走多久受天光与体力限制；冬天日短，路程也短。
4. 水路在水量、冰情、风向都合适时最省力；河面封冻后船走不了，冰够厚时人和车反而能从冰上过。
5. 路上有三类损失：货自己坏（颠簸、腐坏）、人祸（劫掠、查扣）、天灾与意外（迷路、陷车、翻船、野兽）。治安好的地方劫掠不划算，所以运费里的风险钱少。
6. 托人运货靠契约：约定地点、期限、运费、出了事谁赔、承运人押多少。信件与口信走得不会比送信的人快。
7. 边界上的关卡收费、查货、认人；邻邦之间的通行、关税、引渡靠条约。
8. 路是走出来、修出来的：来往多的两地之间才有好路；没人去过的地方，地图上是空的。

### 1.2 本作现状

出处见素材包 §3，逐行处置在 §7。

- 行程与载具已实现，但钟点写死（固定出发时刻与每日行进分钟数），载具造价只认两种具体材料，承运人资格用职业名正则判断，运输数值由模块直接导入平衡表。
- 运单、货损、索赔已实现，依赖链上有睡眠正则与中文状态。
- 邮递已实现，收信人是否在场清醒用正则判断。
- 水运只有文字；封冻禁航没有规则；季节封路与战事封路按季节序号与名单写死；天气对通行的系数挂在天气行上，按四种出行方式分列。
- 路途风险只有山贼强度一项，没有货值、治安、护卫三者的关系。
- 邻省条款是文字。
- 安全负重由身体派生，但直接导入平衡表。
- 远方路网按地形文字正则定路速，按聚落名字的末字定级别。
- 玩家地图知识用文字表示可靠程度。没有探索机制。

### 1.3 本卷的总机制

1. **位置只有一种存法**。个体存一个地点 id（唯一写者在本卷，§3.3）；物品与载具不存位置，沿承载链派生（谁带着它、它装在哪、它放在哪）；舱室与营帐这类能住人的内部空间是地点行，随卷二的行改挂换地方，里面的人位置不用逐个改。
2. **行程是一串段，一段对应一条边**。走一段是卷九的一条持续活动：工量是这段路的标准分钟数，节奏是队伍此刻的速度与基准速度的商。何时重算节奏、何时重查前提、何时中断，全照卷九 R9-1.12；本卷只提供速度、通行判定和段末落位。
3. **速度是乘出来的**：自行者的速度取卷四（已含自身负重）；载具的速度由推进来源、牵引者、车体承载余量算出；再乘卷五的路况系数、本卷的通行方式对地形与环境量的系数、行进窗。任一因子为 0 即走不了，没有另设的“封路”开关。
4. **载具是物品加组件**：样式（形制）是意图，骨架与部件的材料给强度与重量，制作者的技能经品质进入修正管线。承载、容积、速度上限、耗料全是派生量。
5. **路上出的事都由读数推出**：劫掠是劫者拿卷八b 的账与本卷的“可得手货值、胜算”作决策；统计层按同一组读数抽取。意外按地形、环境、路况、领路技能的读数抽取。结局都是记账或效果族调用。
6. **关卡是设施，条款是数**：过关时读邻省条款数值、收通行费、调税种表、按检定查验；绕不绕路是选路的结果。
7. **知道才走得到**：选路只用行者知情集合里的地点与边；到达、望见、测绘各给一档知情。

### 3.4 位置的读法（单点定义）

1. 个体：`location` 的存储值。它可以是任何未终止、不离场的地点行，包括载具内部的舱室行。
2. 物品实例与载具：不存位置。沿承载链取：被人持有的取持有者的位置；装在容器或载具货舱里的取容器的位置；安装在设施上的取设施行；放在某地的（持有者是地点或地点上的账户）取该地点。链上任何一环终止前，卷十九 §4.10（可移动建筑与微型龛祠）规则 8 的清理函数照此读“终止前所在的地点行”。
3. 批次货（不逐件建实例的）：账户持有人的位置；在途用途分区的货取承运行程的当前地点。
4. 展开着的可移动设施的承载物：位置就是该设施行的 `parent`，不在任何人手里（答卷十九附录所记第 3 条未写项）。
5. 链走不到地点行（循环、悬空）即返回空并报 E-TRIP-LEG；读到空的规则按未知处理，不拿别的量顶替。

## §4 子系统

### 4.1 行程合成（路线、距离、速度、钟点）

#### 4.1.1 维度

`state.trips`；`tmode`、`pacing`、`tprofile` 三族；`trip_phase`、`halt_cause`、`pass_state`；`rules.travel.refSpeedMpm`、`march.*`、`dwell.*`、`batch.maxLegs`。读卷五的 `routeView().edge`（`distanceM`、`terrainMix`、`speedFactor`、`waterway`、需求块）、卷四的 `moveSpeedOf` 与 `loadOf`、卷二十的 `envAt`。

#### 4.1.2 统一入口

读：`partyView`、`passOf`、`legSpeed`、`tripPlan`、`tripMinutes`、`tripView`、`whereOf`。写：`tripStep`、`settleTrips`、`placeSubject`。

#### 4.1.3 规则

- **R17-1.1 队伍与自行单位**：队伍 = 领队、成员、载具、随行畜群、所带的货。自行单位是队伍里靠自己接触路面或水面前进的东西：步行的个体、驮着人或货的坐骑、一辆车连同它的牵引者、一条船。乘者、货、被驮的东西不是自行单位，位置随承载者。每个自行单位有一个通行方式：不经载具的个体取其所用步态所属的 `tmode` 条目；载具取其形制的 `tmode`。能不能骑只读卷二十五的 `canRide`。
- **R17-1.2 一段只走一种通路**：一段对应卷五的一条边，按两端加通路类型定位（卷五 §4.1（地点包含树与坐标）规则 4 的平行边通则；这也回答卷十九 §8 Q25）。队伍在一段里的全部自行单位须属于同一种通路：通行方式的 `waterway` 与该边的 `waterway` 相同。唯一例外是 `iceBearCurve` 非空的陆上方式可以走封冻的水路边（R17-5.4）。陆路换水路须在两段之间的地点换自行单位（车上船即成为货）。
- **R17-1.3 通行判定**：`passOf` 按固定顺序求值，第一项不过即返回：① 通路不合（R17-1.2）为 `closed`；② 边的需求块（卷二 §1.13（需求块））对队伍不满足为 `needs`，`missing` 给出缺项；③ 任一自行单位的地形系数 `wsum(terrainMix, terrain, terrainPass)` 为 0 或任一环境曲线取值为 0 为 `closed`；④ 任一自行单位速度为 0（驮不动、无人牵引、无风无桨、缺燃料）为 `closed`；⑤ 段的任一端地点的被围标志为真（卷十三 `siegeView().phase`）而队伍没有围方的放行同意边为 `needs`；⑥ 目的端的进入判定（卷五 §4.13（进入权与私宅许可））不过为 `needs`；⑦ 边上有关卡的为 `needs`，由 §4.7 办理。没有按季节、按名单封路的规则。
- **R17-1.4 段速**（台账 X-13：主体速度、负重系数、路况三者相乘，本卷不另写负重公式）：自行单位 u 在边 e、时刻 t 的速度 `v(u) = 基速(u) × e.speedFactor × wsum(e.terrainMix, terrain, tmode(u).terrainPass) × Π lookup(tmode(u).envCurves[k].curve, 环境量 k) × pacing.speedMult`。基速：不经载具的个体取卷四 `moveSpeedOf(个体, 步态)`（已含其负重）；载具取 R17-2.4。环境量 k 读 `envAt(该段取值地点, t)`：陆路边取两端中 id 字典序较小的一端，水路边取该边所跨的水体行。`terrainMix` 各项之和为 1 由卷五加载校验保证，`wsum` 不做除法。队伍段速 `legSpeed` 取各自行单位速度的最小值；随行畜群按 R17-8.5 给出的速度同样参加取最小。
- **R17-1.5 一段是一条活动**：走一段是卷九动作目录里的一条持续动作（句柄 `rules.travel.roles.acts.march`；乘者用 `.ride`，不要求移动能力）。工量 `workTotal = ceil(distanceM ÷ refSpeedMpm)`（除数 `refSpeedMpm` 取值域下限为 1，加载校验）；`distanceM` 为 0 的边工量为 0，是瞬时动作。节奏的基值 = `legSpeed ÷ refSpeedMpm`（同一除数），行进窗之外为 0（R17-1.6）。队伍里每名个体各持一条活动，同队各人的工量与节奏读同一份队伍读数，所以同一分钟收工。推进时刻、重查、中断、续做全照卷九 §4.1（动作目录与当前活动）R9-1.12：负重、成员、载具状态经执行器改变的，当次事务末步重算节奏；行进窗的开闭、环境量跨日更替是能算出时刻的变化，按该条（丙）路在越界时刻插推进点；通行判定转为 `closed` 经动作类的 `interruptRX` 中断。本卷不设第二套推进。卷九现行“工量取动作行常数”须放宽为可取自开工槽位（配合项 C17-1）。
- **R17-1.6 行进窗（钟点）**：一个世界日里，节奏不为 0 的时段是从“当日昼段起点加 `march.dawnOffsetMinutes`”起、长 `env.daylightMinutes × pacing.marchShareBps ÷ 10000` 分钟的一段（除数是常数一万）；`pacing.nightTravel` 为真的走法窗长改按整日分钟数乘同一基点。昼段起点与昼长读卷二十的环境量，所以冬天日短路程也短。没有写死的出发钟点与每日行进分钟数。窗外队伍在原地，身体需要照卷二十一、卷二十六结算；体力不支而提前停下是活动重查的结果（R17-8.4），不是本条。
- **R17-1.7 选路**：`tripPlan` 在行者知情集合内的边上（R17-11.2；规则层内部代为求值、不代表某个行者时用全图）求耗时度量最小的路径。一段的度量 = `timeWeightBps × 段分钟数 + riskWeightBps × 段的损失期望折算 + tollWeightBps × 段的通行费折算`，三个权重取队伍的 `pacing` 条目，折算都用卷六 `priceFor` 的估值角色换成同一计价单位；段分钟数按“到达该段起点的那一刻”的速度逐段前推算出（天气是时刻的纯函数，将来的值现在就能算）。`passOf` 为 `closed` 的段不可用；`needs` 的段可用，但计划里标出缺项。并列取法与卷五几何最短路相同（边数少者、途经地点 id 序列字典序小者、陆路先于水路）。它不必等于几何最短路。结果只由状态、种子与参数决定。
- **R17-1.8 行程状态机**：`tripStep` 的迁移：`planned` 经出发到 `moving`；`moving` 在一段收工时落位（下条）后，若还有下一段且 `passOf` 不是 `closed` 则开下一段的活动，否则转 `halted` 并记原因；`halted` 在原因消除后由领队的续行意图回到 `moving`；最后一段落位后转 `arrived`；领队放弃或成员全部离队转 `aborted`。每次迁移发对应动词的事件。段数超过 `batch.maxLegs` 的计划拆成首尾相接的多条行程。
- **R17-1.9 段末落位与进入事件**：一段收工的事务里，`tripStep` 对队伍里 `location` 不在舱室行内的每名个体按 id 升序各调一次 `placeSubject` 落到该段终点；舱室内的人随舱室行改挂（R17-2.9）。终点所属的存量单元与起点所属的不同时，发 `verb_tract_entered`，载荷 `{trip, leader, tract, enteredAt, pathM}`：`pathM` = 入边 `distanceM` 折半加下一段出边 `distanceM` 折半（整数折半向下取整；没有下一段的该项为 0）；出发时对起点所属单元同样发一条，`pathM` 取首段折半。队伍停在一个单元里每满 `dwell.reenterMinutes`（从 `enteredAt` 起按世界分钟数，不随推进切分变）再发一条，`pathM` 取 `dwell.equivPathM`（答卷十六 §8 Q16-6）。卷十六的路遇、本卷的意外与统计层劫掠都以这条事件的（领队、单元、进入分钟）为抽取对象与时刻，一次进入各恰抽一次。
- **R17-1.10 标准行者的行程分钟数**：`tripMinutes` 用 `tprofile` 条目虚拟一个单人队伍（物种、步态、负重基点、走法），在全图上按 R17-1.7 只以时间为度量求值，返回分钟数；不通返回空。卷八b 的治安响应、卷十三的场外任务、卷五的控制度、卷二十的传闻延迟下界、卷八的不在辖区时长都读它或对真实队伍调 `tripPlan`；它们各自的 `tprofile` 句柄写在各自的规则表里。
- **R17-1.11 非个体层的行程**：模拟单元不在个体层时，行程不逐段开活动：出发时由 `tripPlan` 得到 `etaMinute`，登记一条到期项，`batch` 置真；到期时 `settleTrips` 按计划里各段的进入时刻依次重放进入事件、抽取与记账，然后一次落位。途中单元换层按卷二十七 §4.1（三层模拟运行矩阵）R27-1.7 追赶：把已过去的段按批量形态结清到换层那一刻，其余的段转为逐段活动。两种形态用同一组键抽取，结果的差别只来自个体层里的决策。
- **R17-1.12 与推进方式无关**：行程的一切时刻（出发、行进窗开闭、推进点、段末、到期）都是世界分钟，由状态与种子算出；一次推进 N 天与分段推进合计 N 天得到同一份存档摘要。

- 扫描式：A17-1.1 S17-1 至 S17-5 计数为 0；`transport.mjs:98`、`post.mjs:58` 一类睡眠正则、固定出发钟点与每日行进分钟数的字面量在本卷模块中为 0；按季节序号、路线名单判断封路的分支为 0。
- 不变量式：A17-1.2 任一时刻每名未终止个体的 `location` 是一个未终止、不离场的地点行；行程相邻两段首尾相接且每段对应卷五一条边；队伍段速不大于其任一自行单位的速度；任一因子为 0 时 `passOf` 不为 `open`；同一次进入单元恰有一条进入事件；一次推进 N 天与分段推进合计 N 天得到同一份存档摘要（验收测试，交卷十二）。

### 4.2 载具

#### 4.2.1 维度

物品模板的 `vform`、`fuelClass` 与派生的 `frameMassKg`、`maxLoadKg`、`cargoVolumeL`、`speedCapMpm`；`vform`、`propel` 两族；`force_source`；槽位三类（句柄 `rules.travel.roles.slots.*`）；搭载、挽具两条持有种类；`rules.travel.vehicle.*`。材料的 `density`、`toughness`、`heatValue` 读卷三甲材料表（经卷三乙入口）；`durability`、故障读卷三乙。

#### 4.2.2 统一入口

读：`itemView(...).dims`（上列派生维度）、`aboardOf`、`partyView`。写：载具自身没有专用写入口——造、修、拆走卷三乙的配方与修理；装卸、上下、套挽是动作行，经卷九执行器的 `transfer` 与 `holding.*` 原语；劣化只调卷三乙 `wearStep`。

#### 4.2.3 规则

- **R17-2.1 载具是物品加组件**：挂 `comp_vehicle` 的物品实例就是载具（卷二 §5.23（未单独成表的实体与归属），台账 E-24）。它由形制（`vform`，制作者的意图）与装在槽里的部件组成；部件是普通物品，各有材料、品质与耐久。规则里没有任何载具 id、形制代号或材料代号；造车船的用料由配方的需求块按材料属性选（卷三乙 §4.8（配方通用规则（继承、产率、递归））），只认两种具体材料的旧写法退役。
- **R17-2.2 承载由材料、形制、技能共同推出**：`maxLoadKg` 的基值 = `vform.loadCoef × frameMassKg × lookup(vehicle.strengthCurve, 骨架韧度读数 × 1000 ÷ 骨架密度读数)`（除数是骨架各部件按质量聚合的密度读数；它为 0 时不做除法，基值取 0，即这副骨架什么也载不了）。韧度与密度读数按卷三乙的材料聚合规则取骨架槽各部件材料的有效值。基值再经修正管线：品质档的乘子（制作者技能的落点，卷一 §3A（共享计算设施）第 3A.4 项）、附件的修正项、当前 `durability` 对应的劣化档。同一形制换一种更强韧的料，承载上升；同料同形制，手艺好的更能载。
- **R17-2.3 载具的负重读卷四**：载具的所负之重与负重比只调 `loadOf(载具实例)`（台账 X-13：载具承载是同一公式的载具实例）；卷四按承载者实体类取承载维度，对载具应取本卷的派生 `maxLoadKg`（配合项 C17-2）。体积另受 `cargoVolumeL` 与卷三乙容器规则约束。
- **R17-2.4 载具的基速**：对形制 `propels` 里每条此刻可用的推进分别算，取最大者，再乘 `loadOf(载具).speedFactor`，并以 `speedCapMpm` 为上限。
  - 人畜力且 `walks` 为真：各牵引者（挽具边的持有者）调 `moveSpeedOf`（其负重含 R17-8.3 的牵引等效负重），取最小值；没有牵引者时不可用。
  - 人畜力且 `walks` 为假（划、撑、蹬）：`baseMpm ×` 各出力者 `loadOf(...).speedFactor` 的最小值；出力者不足形制 `crewMin` 时不可用。
  - 风力：`baseMpm × lookup(curve, 环境量 inputKey)`。
  - 燃料：货舱里有 `fuelClass` 的可燃料且够走完下一个推进间隔时为 `baseMpm`，否则不可用；耗料见 R17-2.5。
  - 自行：`baseMpm`，仅当载具实例自己通过 `can()` 的行动能力判断（它同时是一个有行动能力的实体，由卷十五、卷十六登记）。
  - `speedCapMpm` 的基值取形制字段，经修正管线（行走机构槽部件的品质与劣化档）。
- **R17-2.5 耗料**：燃料来源的推进，每次活动结清时按已走路程扣料：所需能量 = `propel.energyPerKgM × 总重 × 结清的米数`；扣料质量 = 所需能量 ÷ 该料的 `heatValue`（除数是所烧材料的热值；它为 0 的料不算燃料，不做除法，也不会被选中）。扣料是一笔到卷六登记的燃烧去处的账本转移；料尽即该推进不可用，速度按 R17-2.4 重算。
- **R17-2.6 走路也磨损**：每走完一段，对每件在用载具累计等效里程 = 该段 `distanceM × wsum(terrainMix, terrain, vehicle.roughness)`；与行程记录里该载具的余数相加后，用次数 = floor(合计 ÷ `vehicle.wearRefDistanceM`)（除数取值域下限为 1，加载校验），余数写回 `wearRem`；按用次数调卷三乙 `wearStep`（原因取使用）。故障的发生与排除全在卷三乙 §4.9（拆解、修理、故障）；载具带着使其不能行走的故障时，R17-2.4 的对应推进不可用，行程因 `breakdown` 停歇。
- **R17-2.7 毁坏与沉没不另写流程**：载具 `durability` 到 0 的毁坏、意外条目的效果族造成的损毁，都按卷三乙 §4.9（拆解、修理、故障）与卷二 §2.6（写者与三接口）的终止协议结束，本卷只登记触发条件（意外的效果族调用）。终止时搭载边、挽具边按卷十八种类行的处置结束，货舱内容按卷三乙容器的终止处置；乘者留在当时的地点行（在水域里的，会不会溺亡是卷四有无相应步态与卷二十一的事），行程因 `stranded` 停歇。残骸可回收量读卷三乙的打捞规则（台账 N-06）。
- **R17-2.8 搭载集合**：`aboardOf(承载者)` = 搭载边指向它的个体，加位于以它为承载物的可移动设施行子树内的全部个体与存物。卷四求所负之重时“搭载其上的个体”取这个集合（配合项 C17-2）。上车、下车是开立、关闭搭载边的动作；骑乘是坐骑为承载者的同一种边。
- **R17-2.9 带舱室的载具与住户**：能住人的内部空间（船舱、车厢、驮轿）是卷十九可移动形制的设施行，载具实例就是它的承载物（卷十九 `carrierItem`）；舱室行里的人 `location` 指向舱室行，可以以它为常住标的。载具每走完一段，段末落位的同一事务里须让该设施行换到新终点之下：本卷调卷十九提供的“展开着换地点”入口，由它调卷二 `relocate(设施行, 新父行, placement, 原因代号)`。这次改挂 `newParentId` 非空且不等于原 `parent`，所以调用方须照卷十八 §4.1（持有种类表与两条转移协议）R18-1.10“改挂带走住户”一段，在同一事务内、`relocate` 成功之后，对标的落在被改挂子树内的每条现役常住边各发一条常住变化事件 `verb_domicile_changed`，`place` 取站点级新位置，`since` 取改挂当刻，`until` 为空。不发则住在船上、车上的人换了站点而无人得知（卷七的融入度、卷九 R9-1.12 的前提失效通知都订阅它）。卷十九现稿没有这个入口（配合项 C17-3）；在它补上之前，带舱室的载具只能先收起再展开，不能载着住户行进。本卷任何路径都不直接调 `relocate`，也不用“终止旧行、另建新行”表示搬动（S17-4）。
- **R17-2.10 操驾要人要技能**：形制 `crewService` 非空的载具，须有 `crewMin` 名在其上的个体通过卷十四 `canOffer(个体, 该服务, ctx)`，否则各推进不可用。技能高低经修正管线作用在 `speedCapMpm` 与意外的危险读数上（修正项由服务条目的效果给出），不在本卷写系数。

#### 4.2.5 数据实例

- 【西陲】一辆‹形制：双轮货车›：骨架槽装两种木料的部件，行走机构槽装带铁箍的轮。把骨架换成更强韧的木料重造，`maxLoadKg` 按 R17-2.2 上升；同一副料由学徒造出的品质档低一档，承载按品质乘子下降。规则没有读任何材料代号。
- 【非西陲】一条‹形制：竹筏›：形制的通行方式是水上条目，推进含人畜力（撑）与无；骨架密度读数低、韧度读数中等，承载由同一条 `strengthCurve` 得出。没有为竹子写规则。
- 【非人类】‹物种：驮象›背上的‹形制：驮轿›：驮轿是挂 `comp_vehicle` 的物品，推进为空，承载者是象；轿内是一间可移动形制的设施行，住在里面的驯象人以它为常住标的，象每走一段照 R17-2.9 发常住变化事件。
- 【超自然】一条‹形制：骨舟›：推进来源是自行，载具实例自身有行动能力（卷十六登记的行）；被驱散而失去行动能力时该推进不可用，船停在水上，乘者处境同 R17-2.7。

#### 4.2.6 验收断言

- 扫描式：A17-2.1 `transport.mjs:170–172` 一类按具体物品 id 造车船的写法为 0；本卷模块中形制、推进、材料代号字面量为 0；直接调 `relocate` 的调用点为 0；S17-4、S17-6 计数为 0。
- 不变量式：A17-2.2 固定形制与品质，骨架材料读数升高时 `maxLoadKg` 不降；固定材料与形制，品质档升高时 `maxLoadKg` 不降；任一载具 `loadOf` 的所负之重等于货舱内容、搭载集合及其随身物的质量之和；带舱室的载具每次段末落位后，被改挂子树内每条现役常住边恰对应一条该事务内的 `verb_domicile_changed`，其 `place` 等于从新父行起向上第一个站点级地点（没有则为根）；载具搬动前后设施行的 id 不变、`state.terminated` 无新增。
- 扩展性式：A17-2.3 新增一条形制条目、一条推进条目与一条用它们的物品模板（如雪橇、热气球），不改代码：承载、速度、耗料、通行判定全部可求值；新增一种材料行后用它造的载具承载自动不同。

### 4.3 车行、运单、货损、索赔、护卫

#### 4.3.1 维度

合同种类行四条（句柄 `rules.travel.roles.ckinds.waybill`、`.escort`、`.passage`，邮件见 §4.4）；`cargo_fate`；`rules.travel.damage.curve`；通行方式的 `jolt`。读卷六的合同与在途用途分区、卷三乙的 `shipmentProfile`。

#### 4.3.2 统一入口

读：`contractView`（卷六）、`tripView`、`routeRisk`。写：一律经卷六 `contractStep` 与 `post`；本卷的 `tripStep` 在出发、段末、到达时提交这些提案。

#### 4.3.3 规则

- **R17-3.1 运单是合同种类行**：角色为托运人、承运人、收货人；条款含起讫地点、货批引用、运费（数值由卷六 §4.6（分销、承运与商队）规则 12 定，本卷不定价）、申报货值、交付期限分钟、赔付基点、承运人押金、免赔的 `cargo_fate` 集合。义务模板：承运人的交付义务（需要在场）、托运人的运费义务、承运人的赔付义务（由 `verb_cargo_fate` 触发，数量 = `priceOf(申报估值用途, 标的) × 赔付基点 × 损失基点 ÷ 10000 ÷ 10000`，除数是常数一万；`conditionRX` 只读事件载荷里的 `cargo_fate` 代号是否在免赔集合内）、逾期的违约。押金与运费按 `escrowRule` 托管（EVE 的运输合同抵押）。状态机、托管、到期全在卷六 §4.16（合同状态机），违约之后全在卷八b §4.15（民事与救济）；本卷没有运单专用的状态与分支。
- **R17-3.2 谁能承运**：承运人资格 = 卷十四 `canOffer(个体或其所属组织的在场成员, 承运服务, ctx)`，按职业名正则判断的写法退役。车行是卷八的组织行，名下持有载具、牲畜与雇工；它“是车行”只因为它的成员能提供承运服务并对外报价，没有车行类型字段。
- **R17-3.3 发车与在途**：发车时货从托运人转入承运人的在途用途分区（卷六 §4.17（远期、托运与在途）规则 5），装载分配按 R17-8.2；行程记录的 `waybills` 记下所载运单。在途货的位置按 §3.4 第 3 条取行程的当前地点。
- **R17-3.4 到达即记账**：行程到达运单的讫点时，`tripStep` 提交卷六 §4.17（远期、托运与在途）规则 6 的到达记账提案并履行交付义务；收货人不在场的处置照该条。本卷不另写保管费。
- **R17-3.5 颠簸货损**：每段末对所载每批货算毁损基点 = `lookup(damage.curve, wsum(terrainMix, terrain, tmode.jolt)) × 该批 fragileShare`，经修正管线（容器与附件的修正项可降低它）；毁损量 = floor(批量 × 基点 ÷ 10000)（除数是常数一万），零头累计在批次余数里，不丢。毁损的货转入卷六登记的毁损去处，并发 `verb_cargo_fate`（`damaged`）。腐坏照卷三乙 §4.12（腐坏与保质）在途照算，本卷只在到达时把已腐坏量汇成一条 `spoiled` 事件供赔付义务读。
- **R17-3.6 被劫、被扣、遗失**：劫掠得手的货按 R17-6.4 转入劫者名下或 `sink_seized`，发 `robbed`；关卡罚没的发 `seized`（R17-7.5）；意外条目带 `cargoFate` 的按其 `lossBps` 处置。每条事件带运单 id、货批、损失基点与原因代号，索赔只读事件，不读任何描述。
- **R17-3.7 索赔**：索赔不是新机制：赔付义务由上述事件触发生成，承运人按义务给付；不付即违约，救济、时效、善意取得照卷八b §4.15（民事与救济）。承运人监守自盗是把货移出在途分区的一笔转移，产生一条供卷八b 认定的事实。
- **R17-3.8 护卫与客运**：护卫合同的义务是“在行程期间随队”（需要在场，窗口取行程起讫）；护卫入队后其威慑量进入 R17-6.2 的读数，所以雇护卫降低风险金是算出来的。客运合同的义务是把乘客带到讫点，乘客是搭载集合的成员。两者都只是种类行。

#### 4.3.4 交互

卷六 §4.6（分销、承运与商队）、卷六 §4.16（合同状态机）、卷六 §4.17（远期、托运与在途）；卷八b §4.15（民事与救济）；卷三乙 §4.4（容器与批次）、卷三乙 §4.12（腐坏与保质）、卷三乙 §4.18（运法与货值密度）；卷十四 §4.1（职业维度表与服务词表）；卷八 §4.1（实体与组织统一结构）；卷十三 §4.18（遭遇与谈判结算）；§4.1、§4.6、§4.7、§4.8。通道：声明写者（合同，经卷六）、账本转移、事件。

#### 4.3.5 数据实例

- 【西陲】一家车行承运一批陶器：走山路的那一段 `jolt` 读数高，易损份额高，段末按曲线毁损若干件，转入毁损去处并触发赔付义务；托运人事先把陶器装进带衬垫修正项的箱子，毁损基点经管线下降。
- 【非西陲】一份海运运单把风暴造成的 `lost` 列入免赔集合：船在风暴意外中失货，赔付义务的条件不成立，损失由托运人承担；他另买的保单（卷六的保险种类行）照赔。
- 【非人类】一支‹物种：穴居矮人›的驮兽队接运单：资格判断只调 `canOffer`，没有“限人类”的条件；它们走地下层的边，同一套规则。
- 【超自然】托运人雇一名‹物种：守墓石像›作护卫：它的威慑量照卷十三读，护卫合同与凡人护卫是同一条种类行。

#### 4.3.6 验收断言

- 扫描式：A17-3.1 `transport.mjs:183` 一类职业名正则为 0；运单、义务的状态比较中非代号字面量为 0；按合同种类代号写的分支为 0；本卷模块里没有运费的计算式。
- 不变量式：A17-3.2 任一运单：发运量 = 送达量 + 各 `verb_cargo_fate` 事件的损失量之和 + 仍在途量（逐批、逐单位对账，经卷六账本）；在途货只在承运人的在途用途分区里；每条赔付给付都能对到一条触发事件；分段推进与整段推进的货损量逐位相同。
- 扩展性式：A17-3.3 新增一条合同种类行（如“分段接力承运”，带两名承运人角色），不改代码即可签、可运、可赔；给 `cargo_fate` 之外不加值的前提下，新增一条意外条目带 `cargoFate`，赔付自动覆盖它。

### 4.4 承运与邮递

#### 4.4.1 维度

邮件合同种类行（句柄 `rules.travel.roles.ckinds.courier`）；邮件通道行（`rules.travel.roles.channels.mail`）；`rules.travel.post.sealBreakFact`。信件是卷三乙 §4.15（书与文书物性）的文书物品，封缄读其容器或文书的 `sealed`。

#### 4.4.2 统一入口

读：`contractView`、`tripMinutes`。写：经 `contractStep`、`post` 与卷二十二的知情写入口（入口名待该卷成稿，Q17-6）。寄、送、拆是动作行。

#### 4.4.3 规则

- **R17-4.1 信是带知情快照的物品**：寄信时，寄信人把选定的一组事实 id（他知情集合的子集）记进信件实例的内容字段（结构归卷二十二与卷三乙，本卷不定义），此后不随寄信人后来的知情变化而变。规则层不读信的文字；文字只是这组事实的显示。
- **R17-4.2 送信是一份合同加一趟行程**：邮件合同的角色为寄件人、送信人、收件人；义务是在期限前把该物品实例当面交给收件人（需要在场：双方在同一地点行且收件人通过 `can()` 的清醒判断，读卷二 §2.5（状态谓词单点），不读活动文字）。收件人不在的，按合同条款留置于其常住处或带回。
- **R17-4.3 收到才知道**：收件人拆读时，信中事实经邮件通道进入其知情集合，来源记为寄件人、通道记为邮件；失真与可信度归卷二十二。消息到达的时刻不早于信件实例到达的时刻，这由“信是物品、随行程移动”自然保证；别卷要下界时读 `tripMinutes`。
- **R17-4.4 私拆**：任何持有信件的人都可以做拆封动作；拆封把 `sealed` 置假并记一条事迹（句柄 `post.sealBreakFact`），拆者同样经邮件通道得知内容。封缄已破在交付时可被收件人察觉（感知判定归卷五）；后果由合同违约与卷八b 的认定处理。
- **R17-4.5 丢信与截信**：信件是货批的一种，路上的结局与一般货物同律（R17-3.6、§4.6）。截获者拆读即得知内容。
- **R17-4.6 驿递是涌现的**：驿站是提供送信、换乘服务的设施；沿途换新的坐骑使每段都由不疲劳的自行单位来走，所以接力比一人一马走到底快。这是 R17-1.4 与卷四体力规则的结果，本卷不设“驿递速度”。
- **R17-4.7 口信与代办**：口信是不带物品的同种合同，知情快照记在合同条款里（事实 id 列表），送信人自己先经托付通道得知这些事实；其余同上。

#### 4.4.4 交互

卷二十二 §4.2（知情来源与通道）（未成稿，按台账标题）；卷六 §4.16（合同状态机）；卷三乙 §4.15（书与文书物性）；卷二 §2.5（状态谓词单点）；卷十四 §4.8（隐藏职业契机）（读私拆事迹）；卷二十 §4.10（世界节奏 pace）（传闻延迟下界读本卷）；卷八b §4.15（民事与救济）；§4.1、§4.3、§4.6。通道：声明写者（合同）、事件、知情写入（经卷二十二）。

#### 4.4.5 数据实例

- 【西陲】郡守寄信给邻郡：信使骑马走三段，收信人夜里睡着，交付义务的在场条件不成立；信使等到次日对方清醒再交。判断只读谓词。
- 【非西陲】海商托船长带口信到‹站点：群岛渔港›：船被风困了十日，消息也晚十日；岛上的价格在这十日里不知道大陆的变故。
- 【非人类】‹物种：信鸦›作送信人：它是个体，飞行步态，走同一张边图；它通不过“当面交付需要在场清醒”以外的任何额外条件，因为没有额外条件。
- 【超自然】一封被‹物种：狐妖›半路截下拆读的密信：封缄已破、事迹已记；狐妖从此知情，收信人察觉封破与否走感知判定。

#### 4.4.6 验收断言

- 扫描式：A17-4.1 `post.mjs:58` 一类睡眠正则为 0；本卷模块对信件文字、活动文字的读取为 0；邮递模块里没有按收件人身份或物种写的分支。

### 4.5 水运、海运、封冻禁航

#### 4.5.1 维度

`waterway` 为真的通行方式与其 `envCurves`、`iceBearCurve`；水上形制与推进条目。读卷二十 `envAt` 对水体行返回的 `fillRatio`、`iceFraction`、`floodL` 与风的环境量；读卷五水路边。

#### 4.5.2 统一入口

读：`passOf`、`legSpeed`（同 §4.1，不另设水运入口）。写：无专用写入口。

#### 4.5.3 规则

- **R17-5.1 水运没有另一套规则**：水路是 `waterway` 为真的边，船是形制的通行方式为水上条目的载具；速度、通行、磨损、货损、风险全用 §4.1、§4.2、§4.3、§4.6 的同一组入口。河、湖、海的差别只在水体行的环境量与边的地形构成。
- **R17-5.2 封冻禁航是曲线上的零点**：水上通行方式的 `envCurves` 含一条以冰份额为横轴的曲线，冰份额越过某点后取值为 0，于是 `passOf` 为 `closed`。冰份额读卷二十 §4.6（水循环与水量）的冻结规则给出的 `iceFraction`，它由净冻结度日算出，开春自行回落。没有“某河冬季封冻”的名单，也没有按季节的禁航期。
- **R17-5.3 枯水与洪水同理**：同一族曲线可以取 `fillRatio`（水浅走不了吃水深的船）与 `floodL`（漫溢时陆路边的系数下降）为横轴。吃水深浅的差别是不同通行方式条目各自的曲线。
- **R17-5.4 冰上行**：`iceBearCurve` 非空的陆上通行方式可以走水路边，条件是该自行单位的总重不超过 `lookup(iceBearCurve, iceFraction)`；过了则 `closed`。于是河面封冻后人能过、重车要等冰更厚，开春最先走不了的是重车。这一段的地形系数取该方式对冰面所属地形代号的 `terrainPass`。
- **R17-5.5 风与桨**：帆船的速度读风的环境量与推进条目的曲线；无风时风力推进取值为 0，带桨的形制退到人畜力推进。风向与流向对速度的作用本版不计（Q17-3）。
- **R17-5.6 港与渡**：码头、渡口是卷十九的设施，提供装卸、摆渡服务；没有码头的岸边能否靠泊写在水路边的需求块里。摆渡是一段很短的水路行程，渡船是普通载具，渡资是该设施的服务费。
- **R17-5.7 海上的危险**：风暴、雾、暗礁带来的损失由 §4.10 的意外条目按水上通行方式的 `hazard` 与环境量读数给出；翻沉的后果照 R17-2.7。

#### 4.5.4 交互

卷二十 §4.6（水循环与水量）、卷二十 §4.3（天气状态与地区现象）；卷五 §4.1（地点包含树与坐标）（水路边与平行边）、卷五 §4.3（地形、群落与海拔维度表）；卷十九 §4.3（工位与工作站服务）；卷六 §4.6（分销、承运与商队）（水运运费低是到岸成本式的结果）；§4.1、§4.2、§4.10。通道：派生读取。

#### 4.5.5 数据实例

- 【西陲】一条内河航段入冬：净冻结度日上升，`iceFraction` 越过船的曲线零点，货船停航；再冷十余日，冰份额越过步行方式的承重曲线，行人改从冰上过河；重载的车还要再等。全部由同一个读数驱动。
- 【非西陲】高纬海湾的渔港：冬季港内结冰而外海不冻，港口那条边 `closed`，外海各边照常；渔船被困在港里不是因为“禁航令”。
- 【非人类】‹物种：水獭人›的皮筏：形制的通行方式吃水极浅，`fillRatio` 很低时仍可通行，枯水期只有它们的筏子还在走货。
- 【超自然】一片被‹物种：寒潭蛟›盘踞的湖：蛟的领域效果（卷十五的效果族）挂修正项压低该水体的温度，冰份额因此常年偏高；船走不了，是环境量变了，不是给这片湖写了规则。

#### 4.5.6 验收断言

- 扫描式：A17-5.1 本卷模块里季节序号、月份、水体 id、“封冻”“禁航”一类状态字面量为 0；水运与陆运不存在两套速度或通行函数（`legSpeed`、`passOf` 各只有一个实现）。
- 不变量式：A17-5.2 固定其余条件，`iceFraction` 升高时水上方式的段速不升；陆上方式在水路边上可通的总重上限随 `iceFraction` 单调不降；任一时刻同一条水路边不会对“水上方式”与“未达承重的陆上方式”之外的方式开放。
- 扩展性式：A17-5.3 新增一条通行方式条目“破冰船”（冰份额曲线的零点更靠后）与一条用它的形制，不改代码：封冻期只有它能走；新增一条以水位为横轴的曲线，枯水断航自动成立。

### 4.6 路途风险律

#### 4.6.1 维度

`rules.travel.raid.*`；读卷三乙 `shipmentProfile`（`valueDensity`、总质量、总值）、卷八b `securityOf`、`responseOf`、`crimeProspect`，卷十三 `deterrenceOf`，卷四 `loadOf`，卷十六 `encounterReading`。抽取点 `site.road.raid`、`site.road.raider`（流代号 `travel`）。

#### 4.6.2 统一入口

读：`raidAppraisal`、`routeRisk`。写：无专用写入口；动手经卷十三 `encounterStep`，货的转移经卷六 `post`。

#### 4.6.3 规则

- **R17-6.1 数值链**：治安值定响应时间，响应时间定劫者能搬多久，能搬多久与货值密度定可得手货值，可得手货值与护卫强弱定值不值得动手。链上每一环都是读数，没有“安全区不许动手”的规则（卷八b R8b-7.9）。
- **R17-6.2 劫者的估算**：`raidAppraisal(劫者, 队伍, 地点)` 给出：
  - `windowMinutes`：`responseOf(地点).dispatch` 为真时取其 `minutes`，否则取 `raid.maxWindowMinutes`；
  - 可搬质量 = min(劫者一方各成员 `loadOf` 的承载余量之和, `raid.haulKgPerMinute` × 劫者人数 × `windowMinutes`, 货的总质量)；
  - `takeLots`：把货批按 `valueDensity` 降序装进可搬质量（同值按资源键字典序），`takeValue` 是它们的估值之和——货值密度高的货同样的时间能搬走更多的钱；
  - `winBps = lookup(raid.winCurve, 劫方威慑量 × 10000 ÷ (劫方威慑量 + 队伍威慑量))`（除数是双方威慑量之和；和为 0 时不做除法，`winBps` 取曲线在 5000 处的值），威慑量读卷十三 `deterrenceOf`，护卫在队即计入；
  - `taker`：得手后货归谁——劫者个体、其所属组织，或统计层的聚合账户。
- **R17-6.3 个体层：劫不劫是决策**：有名有姓的劫者把 `takeValue × winBps ÷ 10000`（除数是常数一万）作为“所图”交给卷八b `crimeProspect`，与被抓基点、刑罚代价一起进入卷九的决策管线；选了动手就是卷十三的一场遭遇，结局由遭遇结算给出。本卷不替他掷骰。
- **R17-6.4 统计层：同一组读数抽取**：队伍进入一个存量单元时（R17-1.9 的进入事件），对该单元内卷八b 统计层作案流里类别为路劫的聚合体，以其人数与平均威慑量按 R17-6.2 求估算；动手基点 = `lookup(raid.actCurve, 净所得)`，净所得 = `takeValue × winBps ÷ 10000 −` 卷八b 给的刑罚代价期望（除数是常数一万）；以 `site.road.raid` 抽取，命中则再以 `winBps` 定得手与否。得手的 `takeLots` 转入 `taker` 名下；没有可归属主体时记入卷六的 `sink_seized`。键五段取（世界种子、`travel`、领队 id、进入分钟、抽取点代号）。
- **R17-6.5 怪物一项不另算**：野兽与怪物造成的路遇读卷十六 `encounterReading`，由卷十六订阅进入事件自行抽取并建立遭遇；本卷的 `routeRisk` 只把它的期望读数并入 `parts.beast`。
- **R17-6.6 给卷六的损失期望**：`routeRisk(计划, 货, 护卫)` 沿计划各段的存量单元，把 R17-6.4 的“动手基点 × 得手基点 × 可得手货值占总值的基点”、卷十六的读数、§4.10 的意外损失基点、R17-3.5 的颠簸毁损基点，按“各单元互不相关”合成总损失基点 `lossBps`：`剩余 = 10000`，对每一项 `剩余 = 剩余 × (10000 − 该项基点) ÷ 10000`（除数是常数一万），`lossBps = 10000 − 剩余`。可得手货值占总值的基点 = `takeValue × 10000 ÷ 总值`（除数是货的总值；为 0 即空车，不做除法，该项取 0）。卷六的风险金、保险费率都读这个数；它是期望读数，不落盘。
- **R17-6.7 每单位护卫可载货值**：对给定路线，使 R17-6.4 净所得不大于 0 的最大货值是护卫威慑量的函数；它是 `routeRisk` 的反函数读法，供界面与商贩决策显示“这点护卫能押多少钱的货”，不另存表。
- **R17-6.8 风险会回落**：治安值上升使响应加快、窗口缩短、被抓基点升高，净所得下降，路劫减少；护卫便宜了，运费里的风险金随之下降。这是卷八b R8b-11.9 与本条读数相扣的结果，本卷不存“路段风险值”。

#### 4.6.4 交互

卷八b §4.7（治安值与治安力量响应）、卷八b §4.11（犯罪生态、黑市与走私罪名侧）；卷三乙 §4.18（运法与货值密度）；卷十三 §4.18（遭遇与谈判结算）；卷十六 §4.6（巢穴、探巢、赶路遭遇）；卷六 §4.6（分销、承运与商队）（风险金、劫者主体）、卷六 §4.16（合同状态机）（保险费率）；卷九 §4.12（NPC 决策管线）；卷二十七 §4.8（种子键与骰值键（确定性约束与验收））；§4.1、§4.3、§4.10。通道：派生读取、事件、账本转移（经卷六）。

#### 4.6.5 数据实例

- 【西陲】两支车队走同一条山道：一支拉铁锭，一支拉生丝。同样的窗口与可搬质量下，生丝的 `takeValue` 高出许多，净所得为正，被劫的多是丝车；铁锭车很少有人动。没有任何“丝绸招劫”的规则。
- 【非西陲】‹站点：大陆郡城›周围治安值高，响应时间短于装走一车货所需的时间：窗口内可搬质量很小，净所得为负，城郊无路劫；同一伙人在边远山口就划算。
- 【非人类】一支‹物种：豺人›的匪帮：它是卷八的组织行，成员威慑量照卷十三读；它劫到的货进它的账户，拿去销赃时照卷八b 的收赃规则。
- 【超自然】商队雇了一名能令人畏惧的‹物种：守墓石像›：队伍威慑量大增，`winBps` 下降，统计层的动手基点随之下降；风险金由同一式子算低。

#### 4.6.6 验收断言

- 扫描式：A17-6.1 本卷模块中“路段风险”“山贼强度”一类手填常数与地点 id 字面量为 0；抽取键含计数或序号的为 0；按货物类别或物品 id 决定是否被劫的分支为 0。
- 不变量式：A17-6.2 固定其余条件：货值密度升高时 `takeValue` 不降；治安值升高（响应分钟数减少）时 `windowMinutes` 与 `takeValue` 不升；队伍威慑量升高时 `winBps` 不升；`lossBps` 恒在 [0, 10000]；被劫的每一单位货都有去向（某账户或 `sink_seized`），全程账本守恒；同一次进入事件在个体形态与批量形态下用同一个键。
- 扩展性式：A17-6.3 新增一种高货值密度的物品模板，不改代码即比同路的低密度货更常被劫；把某地治安值的来源（驻防、执法者）增加，不改代码该地路劫下降、`routeRisk` 下降。

### 4.7 关卡、通行条款、引渡

#### 4.7.1 维度

设施行的 `gateTerms`；`gate_result`；本卷向 `clause` 族登记的条目（句柄 `rules.travel.roles.clauses.passage`、`.tollCap`、`.inspect`、`.extradite`、`.armedPassage`）；`rules.travel.gate.*`；查验服务句柄 `rules.travel.roles.services.inspect`；抽取点 `site.gate.inspect`。读卷五 `borderTerms`、卷八 `taxesFor`、卷八b `contrabandAt`、`safetyOf`、`lawGate`、`custodyOf`。

#### 4.7.2 统一入口

读：`gateQuote`、`passOf`。写：`setGateTerms`、`gateStep`（只出提案）。条款值的变更只经卷五 `setBorderTerm`，由卷八的外交结算调用，本卷不写条款。

#### 4.7.3 规则

- **R17-7.1 关卡是设施**：一座关卡是挂在某条边一端地点之下、提供查验服务的设施实例（卷十九）；该边的需求块引用“经本设施放行”。哪座设施是关卡只看它的服务集合，不看类型名。设施持有者经 `setGateTerms` 设通行费与查验基点，须有处分权；通行费不得超过所在政区对来者政区的 `tollCap` 条款值（无此条款即不设上限）。
- **R17-7.2 条款是数**（台账 X-15：通行费是设施服务费，不是税；税种表只在卷八）：邻省条款是卷五 `borderTerms` 里的代号到数值；本卷登记五个条目的含义：通行（0 不许、1 许）、通行费上限、查验强度（基点，作 `inspectBps` 的下限）、引渡（0 或 1）、武装过境（0 或 1）。规则只读数；条款可以不对称。关税不是本卷的条款，归卷八。
- **R17-7.3 过关的固定顺序**：队伍走到带关卡的一段前因 `gate` 停歇，`gateStep` 在一笔事务里依次：
  1. 通行：来者所属政区对本政区的通行条款为 0，且卷八b `lawGate` 对来者没有给出许可（通行文书、使节身份都是它读的持有边与证件代号）时，结果 `refused`；队伍带武装（卷十三的在编成员）而武装过境条款为 0 时同样 `refused`。
  2. 认人：对每名成员读 `safetyOf(成员, 本地法域)`；有在本地算数的通缉边的，提交卷八b 的收押提案，结果 `held`（只扣此人，其余继续）。通缉在本地算不算数由卷八b R8b-8.7 的 `reach` 定，其中“与之有引渡约定”读的就是本卷登记的引渡条款值。
  3. 通行费：`toll = tollPerHead × 人数 + tollPerKg × 总重千克`，付给设施持有者，是一笔服务费的账本转移，价格用途句柄 `rules.travel.roles.puses.toll`；付不起为 `refused`。
  4. 关税：以过关为触发、所载货批与申报货值组成税单草稿，调卷八 `taxesFor`，按返回的应缴行逐笔转移。本卷不存税率。
  5. 查验：见下条。
  结果发 `verb_gate_checked`，载荷带各步的代号与数额。`passed` 的队伍续行。
- **R17-7.4 查不查、查不查得出**：查验基点 = max(`gateTerms.inspectBps`, 条款的查验强度)；当值的查验者（在场、清醒、`canOffer` 查验服务）为空时不查。以 `site.gate.inspect` 抽取（键的对象取领队 id，时刻取到关分钟）决定是否开箱。开箱后，对每个货批做一次卷九的对抗检定：查验方读数是查验者的查验技能有效值，藏匿方读数 = 藏匿者的藏匿技能有效值 + 容器与附件给的藏匿修正项 − `lookup(gate.volumeCurve, 该批体积)`；查获基点 `detectBps = lookup(gate.detectCurve, 查验方读数 − 藏匿方读数)`。`gateQuote` 把同一式子的期望值报给卷六 §4.20（走私与违禁品（经济侧））算走私的到岸成本。
- **R17-7.5 查出之后**：查出的批次若 `contrabandAt(本地, 批次)` 为禁，或申报货值低于实值，由执行器记一条查验所见的事实（卷八b R8b-2.3），罪名、罚没、刑罚全归卷八b；罚没的货发 `verb_cargo_fate`（`seized`）。没有查出的，什么都不发生：状态类罪名只在查验点成立。
- **R17-7.6 绕关是选路**：关卡只管它所在的那条边。选路时带关卡的段以通行费、关税与查获损失期望计入度量（R17-1.7），绕行的小路更慢、更险；走私者绕不绕由这笔账定。判定针对实际走过的边，不针对意图。
- **R17-7.7 引渡的执行**：被 `held` 的人若通缉来自邻政区且引渡条款为 1，本地承办组织与对方之间的移交是卷八b 的羁押转移加一趟押解行程（普通行程，被押者是搭载或随行成员）；条约的缔结与废止归卷八 §4.14（外交与使节）。

- 扫描式：A17-7.1 对邻省条款文字的读取为 0（`regions.json` 的条款文字全部迁为代号到数）；本卷模块中税率字面量为 0；按政区 id、政体名判断的分支为 0；`smuggling.mjs` 的睡眠正则与章程文字正则为 0。
- 不变量式：A17-7.2 每次过关恰有一条 `verb_gate_checked`；通行费不超过条款上限；过关付出的每一笔都有收款账户；固定其余条件，藏匿方读数升高时 `detectBps` 不升、货批体积增大时 `detectBps` 不降；没有经过任何关卡边的行程不产生关税与通行费。
- 扩展性式：A17-7.3 向 `clause` 族新增一条条目（如“检疫”）并在需求块或 `whenRX` 里引用它，不改代码即可在过关时生效；新增一个政区层级后，条款与关卡规则对新层级自动适用。

### 4.8 负重、体力与行程

#### 4.8.1 维度

无新增存储。读卷四 `loadOf`（`ratio`、`speedFactor`、`staminaFactor`）、步态条目的 `exertion`，`pacing.exertionMult`；`towShareOf`；形制的 `dragShare`。

#### 4.8.2 统一入口

读：`partyView`（装载分配结果、各承载者负重比）、`towShareOf`。写：装、卸、分担是动作行，经卷九执行器的 `transfer` 与持有原语。

#### 4.8.3 规则

- **R17-8.1 负重公式不在本卷**：能背多少、背多了慢多少、累多少，只调卷四 §4.6（步态、移动、负重）的 `loadOf` 与 `moveSpeedOf`（台账 X-13）。本卷只做三件事：把货分给承载者、把拉车折成等效负重、把体力倍率交给身体需要。直接导入平衡表算安全负重的旧写法退役。
- **R17-8.2 装载分配**（卷四 M-6 交本卷的分配规则）：一批货分给多个承载者（人、畜、车、船）时，先按各货批的运法（卷三乙 `transportMode`）筛出能承它的承载者；再按“使各承载者负重比相等”分：承载者 i 分得 = 该批质量 × `loadCapacityKg(i)` ÷ 各合格承载者 `loadCapacityKg` 之和（除数是合格承载者承载能力之和；为 0 时不做除法，这批货无人能带，`partyView` 标出缺口）。不可分的整件按质量降序依次给当前负重比最低的承载者。零头按承载者 id 升序补。自走的牲畜不占载重（卷三乙 Y-4）。分配是 `partyView` 的派生结果；玩家或 NPC 可以用装卸动作改成别的分法，规则照实际持有读。
- **R17-8.3 拉车折成等效负重**：一辆车的牵引等效负重 = 车的总重（自重加 `loadOf` 的所负之重）× 形制的 `dragShare`；按 R17-8.2 同式分给各牵引者（把“合格承载者”换成挂挽具边的牵引者；牵引者承载能力之和为 0 时不做除法，无人能拉，该推进不可用）。`towShareOf(牵引者)` 返回他分得的千克数，卷四求其所负之重时计入（配合项 C17-2）。于是轮子的好处就是 `dragShare` 小于 1：同一头牲口拉的比驮的多。
- **R17-8.4 体力与行程**：行进中每个自行个体的体力消耗倍率 = 卷四给的“步态消耗 × `staminaFactor`”再乘 `pacing.exertionMult`，由行进动作行的效果交给卷二十一的身体需要结算；本卷不存体力值。体力见底使 `can()` 的移动能力判断不过，活动按卷九 R9-1.12 中断，行程因 `rest` 停歇；歇够了再续。所以赶路走法（`speedMult` 大、`exertionMult` 大）快而不能久，这是结算出来的。
- **R17-8.5 随行畜群**：赶着走的牲畜批次不占载重，速度读卷四按物种与步态给出的典型速度（畜群不是个体，卷四现行 `moveSpeedOf` 不接受，配合项 C17-4），参加队伍取最小；它们的草料是卷六的给养、卷二十五的放牧取用。迁牧就是带畜群的普通行程。
- **R17-8.6 超载的后果是连续的**：负重比越过卷四速度曲线的零点即 `passOf` 为 `closed`（走不动），之前只是越来越慢、越来越累；本卷没有“超载”布尔，也没有负重上限的硬拒绝。丢货是一笔转移。

#### 4.8.5 数据实例

- 【西陲】三名脚夫与一头驴分担一批粮：按承载能力分，各自负重比相同，队伍速度由这个共同的负重比定；其中一人中途受伤，承载能力下降，执行器末步重算分配与节奏。
- 【非西陲】南方河谷的纤夫拉船逆水：纤夫是挽具边的牵引者，船的 `dragShare` 很小，同样人数能带动的货远多于肩挑；这是同一条 R17-8.3。
- 【非人类】一头‹物种：驮象›与四匹‹物种：矮种马›同队：象的承载能力大，分得的货多，五者负重比相同；没有为象写分配规则。
- 【超自然】一具‹物种：石质守卫›拉车：它的代谢倍率为 0，体力倍率照算而没有身体后果（卷四已定），于是可以昼夜不歇；行进窗仍受走法的 `nightTravel` 约束。

#### 4.8.6 验收断言

- 扫描式：A17-8.1 `carry.mjs:8` 一类直接导入平衡表为 0；本卷模块里没有负重到速度、负重到体力的曲线或公式（只出现对 `loadOf`、`moveSpeedOf` 的调用）；S17-2 计数为 0。
- 不变量式：A17-8.2 装载分配后各货批分给各承载者的质量之和等于该批质量；自动分配下任意两个合格承载者的负重比之差不超过一个不可分整件所致的量；牵引等效负重之和等于车总重乘 `dragShare`（定点误差内）；增加货重时队伍段速不升。
- 扩展性式：A17-8.3 新增一个物种行（带承载倍率与步态）并把它编入队伍，不改代码：分配、速度、体力全部可求值；新增一条走法条目，不改代码即改变日程与体力消耗。

### 4.9 远方路网

#### 4.9.1 维度

`roadgrade` 族；生成阶段条目 `gstage_roads`；`rules.travel.roads.*`。读卷十交来的站点集合与自然相邻边、卷五的站点类型与面积、卷八 `popView`。

#### 4.9.2 统一入口

读：`routeView().edge`（卷五）、`tripPlan`。写：生成器 `worldgen/roads.mjs` 只出提案，由卷十的写回器交卷五、卷十九的建行写者落行。

#### 4.9.3 规则

- **R17-9.1 路网阶段**：本卷向卷十 `gstage` 族登记一条阶段条目 `gstage_roads`：相位为世界生成，排在站点选址与站点面积两阶段之后，范围为政区，生成器 `worldgen/roads.mjs`，写地点类。它做两件事（下两条）。阶段的调度、写回、校验归卷十 §4.1（生成总流程）。
- **R17-9.2 入站边**：每个站点与它坐落的存量单元之间建一条陆路边，`distanceM` 取站点等效半径（由面积按卷五的同一算法求，整数开方）；站点坐落的单元与某个水体单元相邻、且站点类型的资格含临水的，再建一条到该水体单元的水路边。卷十只在存量单元之间建自然相邻边（该卷 R10-2.5），站点靠这些入站边接入同一张图。
- **R17-9.3 哪两地之间有路，由来往潜力定**：对每个站点，按行程分钟数从近到远取至多 `roads.maxPairsPerSite` 个别的站点成对；每对的来往潜力 = `lookup(roads.potentialCurve, 两站点开局人数之积 ÷ 两站点间标准行者的行程分钟数)`（除数是 `tripMinutes` 的结果；两站点同处一个单元而结果为 0 时不做除法，取曲线末端的值；不通的站点对不成对）。潜力达到某路级 `minPotential` 的，取 `rank` 最大的那一级，沿该对之间的最省时路径的每条边安装该路级的固定装置（卷十九的装置实例，带一条抬高该边 `speedFactor` 的修正项，经卷五 §4.10（地形修正）进入路况）。同一条边被多对站点覆盖时取最高路级。没有手写的干道名单，也不按站点名字或类型名定级。
- **R17-9.4 路是会坏、会修的东西**：路面装置按卷十九 §4.9（公共设施维护）劣化，缺维护则修正项随劣化档减弱；运行期修路、升级是卷六 §4.19（公共工程与公库拨款）的工程，产物是同一种装置。来往多的地方修得起路，是公库收入与工程决策的结果。
- **R17-9.5 远方不特殊**：未物化的站点照常是图上的地点行，行程可以到达、经过它；只有要在它之下建行或取其下某行 id 时才触发卷十 §4.3（远方聚落按需物化）的物化。路速只读边的 `speedFactor` 与通行方式字段，按地形文字正则定路速、按聚落名字末字定级别的写法退役。
- **R17-9.6 生成确定**：本阶段不掷骰；并列一律按 id 字典序。同一世界种子与数据得到逐字节相同的边与装置。

#### 4.9.4 交互

卷十 §4.1（生成总流程）、卷十 §4.2（省郡骨架）、卷十 §4.3（远方聚落按需物化）；卷五 §4.1（地点包含树与坐标）、卷五 §4.6（站点类型）、卷五 §4.10（地形修正）；卷十九 §4.9（公共设施维护）、卷十九 §4.14（机关、陷阱、机械）；卷六 §4.19（公共工程与公库拨款）、卷六 §4.23（贸易枢纽涌现（验收））；卷八 §4.16（人口统计层、承载力、迁徙、移民波次）；§4.1。通道：声明写者（别卷）、派生读取。

#### 4.9.5 数据实例

- 【西陲】郡城与三个集镇之间潜力高，生成时沿最省时路径装上较高路级的路面；偏远的山村只够最低一级。玩家看到的“官道”是这样算出来的。
- 【非西陲】群岛上各渔村之间陆上不连通，`tripMinutes` 对步行的标准行者返回空，站点对不成对；它们各自的入站水路边把它们接到海上，往来靠船。
- 【非人类】一座地下巢城与地表集镇之间只有一条经洞口的边：潜力按同一式子算，够级就在那条边上装路面；巢城居民是什么物种不进式子。
- 【超自然】一处经零距离边与常世相连的秘境站点：入站边照建；它与外界的“路”就是那条带需求块的零距离边，潜力式里行程分钟数取到达入口的分钟数。

#### 4.9.6 验收断言

- 扫描式：A17-9.1 `remote-generation.mjs:263` 的地形文字路速正则、`:238` 的名字定级正则为 0；本卷生成器中地点 id、站点名、路线名单字面量为 0；生成器对状态的直接写入为 0（只出提案）。
- 不变量式：A17-9.2 生成后每个站点至少有一条入站边；任一路面装置所在的边都在某对站点的最省时路径上；同一种子两次生成的边与装置逐字节相同；固定其余条件，两站点人数增大时其间路级不降。
- 扩展性式：A17-9.3 新增一条路级条目（带装置模板与门槛），不改代码：新世界里出现该路级；新增一个站点类型或一个行政层级，路网阶段照常运行。

### 4.10 旅行危险按地形

#### 4.10.1 维度

`mishap` 族；通行方式的 `hazard`；`rules.travel.mishap.*`；路级的 `hazardCut`；领路服务句柄。抽取点 `site.road.mishap`、`site.road.which`。读卷五地形构成、`development`、`control`，卷二十环境量与现象。

#### 4.10.2 统一入口

读：`routeRisk().parts.mishap`。写：无专用写入口；后果是效果族调用（经卷九 `execute`）与账本转移。

#### 4.10.3 规则

- **R17-10.1 危险读数**：队伍进入一个存量单元时，危险读数 = 各自行单位 `wsum(该段 terrainMix, terrain, tmode.hazard)` 的最大值 × 环境修正（经修正管线；卷二十的现象行可以带以本读数为目标的修正项，暴风雪、浓雾因此加大危险）× `lookup(mishap.developmentCurve, 该单元上级站点的 development)` × `lookup(mishap.controlCurve, control)` ×（1 − 该段路级的 `hazardCut`，无路面取 1）× `lookup(mishap.guideCurve, 队中领路服务提供者的技能有效值最大者)`（无人领路取曲线在 0 处的值）。这就是 CK3 式“危险读地形、建设、控制”的落点，全部是读数。
- **R17-10.2 抽一次**：出事基点 = `lookup(mishap.curve, 危险读数)`；以 `site.road.mishap` 抽取（键：世界种子、`travel`、领队 id、进入分钟、抽取点代号），命中再以 `site.road.which` 在 `whenRX` 成立的意外条目中按 `weight` 抽出是哪一种（合格条目权重全为 0 或没有合格条目时不抽，不出事）。一次进入恰抽一次，与推进切分无关。
- **R17-10.3 后果是数据**：意外条目的 `effects` 是效果族调用（受伤、染病、载具受损、迷路延误……），对象集合与幅度由效果族按队伍读数算出；`cargoFate` 与 `lossBps` 给出货的结局（照 R17-3.6 记账）；`haltMinutes` 大于 0 的令行程停歇相应分钟。本卷代码不认识任何一种意外。
- **R17-10.4 迷路**：迷路是一种意外条目，后果是停歇分钟数，或把下一段换成一条相邻的别的边（由效果族按知情档与领路技能给出）；对所在单元与边的知情档越高、领路技能越高，危险读数越低（R17-10.1、R17-11.4）。
- **R17-10.5 安全是速度之外的第二个量**：对一条计划，`routeRisk` 给出的 `lossBps` 及其各部分就是这条路的“安全”读数；选路权重（`pacing` 的三个权重）让谨慎的走法绕开危险段、赶路的走法不绕。界面显示的旅行安全度是它的投影。
- **R17-10.6 统计层同式**：批量形态在到期重放进入事件时用同一读数、同一键抽取（R17-1.11）；后果里针对个体的效果族调用落在聚合体上的方式归卷二十七 §4.2（聚合变体、等价、钉住）。

#### 4.10.4 交互

卷五 §4.3（地形、群落与海拔维度表）、卷五 §4.9（发展度与控制度）；卷二十 §4.3（天气状态与地区现象）、卷二十 §4.9（世界时钟事件与灾异（行数据））；卷二 §3.9（效果族表）；卷二十一 §4.1（身体类状态实例）；卷十四 §4.3（技能与熟练）；卷十六 §4.6（巢穴、探巢、赶路遭遇）（同一进入事件上的另一项抽取，抽取点不同，互不影响）；卷二十七 §4.2（聚合变体、等价、钉住）；§4.1、§4.3、§4.6、§4.11。通道：效果族、事件、派生读取。

#### 4.10.5 数据实例

- 【西陲】雪天翻越山口：山地的 `hazard` 高，暴风雪现象行的修正项加大读数，无人领路；出事基点高，抽中“失足坠伤”条目，效果族给一名成员一处伤，行程停歇。
- 【非西陲】热带河口行船遇雾：水上方式对河口地形的 `hazard` 本来不高，浓雾现象加大读数；抽中“搁浅”条目，载具受损、停歇半日，货无损。
- 【非人类】由‹物种：山羊人›领路的队伍：领路技能有效值高，同一段山路的危险读数经曲线折减；领路人是什么物种不进式子，只读技能值。
- 【超自然】途经一片带瘴气场的洼地：瘴气是卷二十的环境场，卷十五登记的现象行给危险读数加修正项，并使“染瘴”意外条目的 `whenRX` 成立。

- 扫描式：A17-10.1 本卷模块中意外条目代号、地形代号、天气 id、现象代号字面量为 0；按人物特质或物种写的旅行事件分支为 0；抽取键含计数的为 0。
- 不变量式：A17-10.2 固定其余条件：`development`、`control`、路级、领路技能任一升高时危险读数不升；一次进入单元至多一次意外；同一行程一次推进与分段推进得到的意外序列逐位相同；意外造成的每一单位货损都有去向。
- 扩展性式：A17-10.3 新增一条意外条目（带 `whenRX`、效果族调用与权重），不改代码即可发生并有后果；新增一种地形条目并在通行方式的 `hazard` 里给值，危险读数自动覆盖。

### 4.11 探索与未知地点

#### 4.11.1 维度

`explore_grade`；地点行的 `hiddenness`；`rules.travel.explore.*`；亲历与测绘两条通道行；抽取点 `site.explore.find`；勘察服务与技能句柄。知情集合本身归卷二十二。

#### 4.11.2 统一入口

读：`exploreGrade`。写：经卷二十二的知情写入口记事实（“某人于某时对某地点或某边达到某档”）；勘察是动作行。

#### 4.11.3 规则

- **R17-11.1 知情档是派生的**：`exploreGrade(观察者, 目标)` 取观察者知情集合里关于该地点或该边的事实所给的最高档：经传闻通道得知的为 `rumored`；经亲历、邮件、地图得知位置的为 `located`；做过测绘的为 `surveyed`；没有任何相关事实为 `unknown`。用文字表示“传闻、可靠”的旧字段退役。
- **R17-11.2 知道才选得到**：以某个行者的身份调 `tripPlan` 时，只用其知情档不低于 `located` 的边与地点；目的地不在其内即无计划。不知道路的人仍然可以走：朝相邻的、看得见的单元走一段是普通的行进动作，不需要计划。
- **R17-11.3 走到与望见**：队伍进入一个存量单元，成员对该单元、所走的边按 `explore.arriveGrade` 记档；对从该单元经卷五感知判定看得见的相邻单元与其上不隐蔽的站点按 `explore.sightGrade` 记档。`hiddenness` 大于 0 的地点不因路过而被记档，须勘察。
- **R17-11.4 勘察**：勘察是持续动作，对象是所在单元；收工时对该单元内每个 `hiddenness` 大于 0 而观察者尚未知其所在的地点、矿脉存量、隐蔽的边，各以 `site.explore.find` 抽一次（键的对象取“观察者与目标”确定性派生的 id，时刻取收工分钟）：发现基点 = `lookup(explore.findCurve, 勘察技能有效值 + 工具能力给的修正 − hiddenness)`。发现即记档并发 `verb_place_explored`。卷五 §4.4（地质与矿脉）规则 6 说的“探矿归卷十七”就是这一条：存量一直在，发现的是知情。
- **R17-11.5 测绘与地图**：测绘是另一条持续动作，把对一个单元及其各边的知情升到 `surveyed`，产物可以是一件地图物品（文书，带一组事实 id，同 R17-4.1）；读图者经地图通道得到 `located`。地图可以卖、可以偷、可以是假的（假不假归卷二十二的可信度）。
- **R17-11.6 知情影响安全**：对所走的边与单元知情档越高，R17-10.1 的危险读数越低（由档位给出的修正项进入管线）；`surveyed` 的路线迷路条目的权重更小。
- **R17-11.7 未知之地的收益是涌现的**：治安值低、路远、无人测绘的地方，资源场少有人取用、存量充盈；先到的人取得多。本卷不设“探索奖励”。
- **R17-11.8 群体的知情**：统计层聚合体的知情按卷二十二的公共知情形态处理；商路、航线“为人所知”是该地居民公共知情的派生读数，本卷不存“已发现”标志。

#### 4.11.4 交互

卷二十二 §4.2（知情来源与通道）（未成稿，按台账标题）；卷五 §4.2（分区、方位与感知通道）、卷五 §4.4（地质与矿脉）、卷五 §4.5（地下层与洞穴）；卷十四 §4.3（技能与熟练）；卷三乙 §4.15（书与文书物性）；卷九 §4.1（动作目录与当前活动）；卷二十九（地图界面按知情过滤，该卷未成稿）；§4.1、§4.4、§4.10。通道：知情写入（经卷二十二）、事件、派生读取。

#### 4.11.5 数据实例

- 【西陲】一名猎户只到过本郡三处：他对邻郡的边没有任何事实，`tripPlan` 给不出去邻郡郡城的计划；他向行商买了一张地图，读后得到 `located`，计划可求。
- 【非西陲】一支船队沿未测绘的海岸航行：每进入一个海域单元即对它记到达档、对望得见的海岸单元记望见档；随船的测绘者把它们升到 `surveyed`，回港后地图成了值钱的货。
- 【非人类】‹物种：穴居矮人›的探矿者在山里勘察：一处 `hiddenness` 较高的矿脉被发现，记档并发事件；矿一直在那里，变的是谁知道。
- 【超自然】一处秘境的入口是一条 `hiddenness` 很高的零距离边：不勘察看不见；发现它的人可以把它画进地图，也可以守口如瓶。

#### 4.11.6 验收断言

- 扫描式：A17-11.1 `map-state.mjs:6`、`:8` 一类用文字表示可靠程度的字段读取为 0；本卷模块中不存在“已发现”布尔的存储；按玩家与非玩家区分知情的分支为 0。
- 不变量式：A17-11.2 任一行者身份的计划所用的边都在其知情档不低于 `located` 的集合内；知情档只由知情集合里的事实推出，删去全部相关事实后必为 `unknown`；发现前后目标的存量与维度逐位不变；固定其余条件，`hiddenness` 升高时发现基点不升。
- 扩展性式：A17-11.3 新增一条通道行（如“向导口述”）与其给出的档位，不改代码即可让人经它获得知情；给任一地点填上 `hiddenness`，不改代码它就需要勘察才能被知道。
