## §0 卷首

### 0.1 范围

本卷回答一件事：全书各卷写下的验收断言与扫描条，怎样变成机器执行、拦得住的门禁。内容是：

- 四类代码扫描各自的实现要求：点名实例（§4.1）、读文字（§4.2）、写入归属（§4.3）、规则来源与常数（§4.4）；
- 校验器与不变量怎样进必过集合（§4.5）；
- 扩展性测试、确定性验收、场景与试玩套件（§4.6）；
- 卷零覆盖核对（§4.7）；
- 基线元组、逐行清单与"只降"判定（§4.8）；
- 两轮审查绑定内容、各道关口与云测试台（§4.9）；
- 谁来跑、报告与提交信息写什么（§4.10）；
- 全书断言与扫描条的统一格式与登记表（§4.11）；
- 对设计文稿本身的扫描与封卷关口（§4.12）；
- 绕法用例集（§4.13）；
- 判据修订与误报处置（§4.14）。

本卷不写：任何判据的定义本身。字符串能做什么、各模块组的闭集、错误码，唯一定义在卷二 §2.8（字符串类型规则）、卷二 §2.9（外部边界与 Text 模型）、卷二 §4.3（错误码表）；各组为什么存在、扫描的技术底线在卷一 §3.1（扫描的最低技术要求）、卷一 §3.2（封闭的排除清单）；各领域的断言在各领域卷。本卷只定：这些判据怎样登记、怎样执行、在哪道关口拦、结果怎样报。

闸内匹配算法的定义在卷二 §2.9（外部边界与 Text 模型），实现只有 gate 组里的那一个匹配文件；本卷的扫描器与门禁脚本在离线组 `tools/`，不在 gate 组，只扫描它，不实现它（全书概念台账 X-19）。

## §1 领域总述

### 1.1 真实世界怎样运转

工厂的出厂检验有几条老规矩。检验规程写成条文，每一条说清量什么、用什么量、合格是多少，不写"看着差不多"。量具要定期拿标准件校：该判不合格的标准件必须判不合格，该放行的必须放行。检验员不是操作工本人。不合格就不出厂，不是记一笔下次注意。量具量错了，办法是校量具，不是在规程后面贴一张"这几件不用量"的单子。

软件的门禁相同。本作此前的教训是反过来的每一条：守门工具只报不拦，判据散在各个脚本里，测试通过数被当成完工，范围一大就按选项放宽（卷一 §6.1（九条原因）的 C4、C5）。

### 1.2 本作现状

来自素材包 §3，均为静态读数：

- 守门只报不拦：现有守门工具退出码恒为 0，只查测试与参数消费者；禁 id、禁自然语言的自动扫描尚未实现（09 的 21.2、21.5）。
- 校验分散：若干规则模块各带一个加载期校验函数，统一校验器的错误码多数未实现（09 的 20.2）。
- 测试与不变量：测试目录 607 项；不变量测试目录下 5 个；事件推演题集 11 套，带提出者与核对者两份提示词。
- 试玩、浸泡、指标工具有十余个脚本，各自约定输入输出。
- 两轮审查绑定内容的云门禁已实现并在用（09 的 21.1）。
- 各扫描项的旧基线：id 字面量 198 处、读文字 219 行、钱币直写 52 处、规则表直接 import 11 处、十进制字面量 294 个，等等；全表在卷一 §6.3（门禁先行的顺序、建造与基线）。
- 门禁脚本另有一组在仓库外的工具目录里：合入门禁、性能门、提交前过拟合守门、卡门禁入口，以及一份按"文件加匹配串"跳过子测的名单（6 条）；合入门禁与性能门现在在本机跑测试与性能对比（逐个见 §7 的 M12-16 至 M12-20）。
- 设计文稿这一侧：全书一致性脚本现有二十余个（除数下界、双写、越系统写、后门、重名、豁免依据、误差界、单边假设、选材与组合、判据单点定义等），每卷另有一份手写的自检脚本；其中三个脚本带着"逐条看过、判为不属同类"的名单（`scan-adjacency` 带同目录的名单文件，`scan-cap-required`、`scan-single-edge` 把名单写在脚本里），两个按卷名分桶（`check-sameclass-19`、`check-sameclass-19v7`），三个按卷专写（`scan-vol2rev-sameclass`、`scan-vol6v3-sameclass`、`scan-vol6v4-sameclass`）。
- 各卷的条目编号不统一：已写各卷里，扫描条的前缀有三种写法，断言的写法至少四种，有五卷写明"扫描代号由卷十二分配"。

### 1.3 四条总则

1. **先登记，后执行**。一条断言或扫描条，登记进条目表、有了封闭的期望值与执行方法，才算存在。没登记的不执行，也不算数。
2. **判据通用，不点名**。检测器只认结构：类型、节点位置、路径、import 边、登记项。范围与参数从声明表与登记表来，检测器里没有文件名单、条目名单。
3. **命中只有两条出路**。改被查的对象，或者改准判据。没有"这一条不用管"的第三条路（§4.14）。
4. **门禁是拦，不是报**。关口上任一必过条目不过，动作就不发生：不提交、不上云、不合入、不封卷。

### 3.4 禁止的旁路（扫描式写法，本卷自己实现）

- **S12-1** 运行时代码 import `tools/accept/` 下任何文件的次数为 0（就是卷二的 E-PROC-IMPORT，本卷不另立码）。
- **S12-2** 登记器、执行器与批准提交入口之外，写 §2.11 各文件的位置为 0。判法：离线组里文件写入函数（内建文件模块的写、追加、改名、删除类成员）的调用者用 `call_edge` 限定为登记器与执行器两个文件；登记器、执行器之外的离线文件调用这些函数时，目标路径须能经常量折叠证明落在 §2.11 的路径模式之外，证明不了（含拼接、变量等算不出常量的路径）即计入（`lit_scope`），不得漏。另有一种可证明法（封卷后勘误 1117lb1，李白 11-17 21:2x 裁定）：写入路径＝仓库根＋若干常量前导段＋可变尾段，且常量前导段本身已能证明不可能落进 §2.11 任何路径模式（前导段与每个模式逐段比对必有一处对不上；前导段为空即首段可变，不证明），同时可变尾段不可能逃出前导目录（尾段不得含路径分隔符、`..`、绝对路径；靠一个共用的离线路径段校验函数保证，该函数与仓库根函数作为门禁设施登记 `gatefac`，检测器经登记识别，不在检测器源码里写文件名字面量，守 S12-5；不用按路径或行号的排除名单，守 S12-6），这样算已证明在 §2.11 之外，不计入；尾段未经登记的校验函数、首段可变、常量前导段命中 §2.11 模式的仍计入。§4.14 的用例：必须不报（`logs/` 前缀加日期尾段、`backups/` 前缀加时间尾段）与必须报（首段可变、尾段含 `..` 或分隔符、未过校验函数、常量前缀命中 §2.11 模式）。批准记录不在版本库里，只经云门禁的批准提交入口写。

## §4 子系统

### 4.1 点名实例扫描

对应卷零代号 S1。

#### 4.1.1 维度

扫描类别 `instance_name`、`id_parse`（§2.4）；检测器 `lit_scope`、`typed_pos`、`data_shape`（§2.3）；分量 `c_instance_id`、`c_id_parse`（§2.5）。

#### 4.1.2 统一入口

执行经 `accRun`；读结果经 `accHits(filter)`、`accBaseline()`。

#### 4.1.3 规则

- **R12-1.1 判据不在本卷**：什么算点名实例、什么算 id 反推，条文在卷一 R-4 第 1、7 条与卷一 §3.1（扫描的最低技术要求），验收口径在卷二 §7（本卷的验收断言）的 S1、S12。本卷只定怎样实现。
- **R12-1.2 前缀从数据来**：实体前缀取自各维度表表头登记的前缀与声明表登记的单例 id；词表族前缀取自词表文件。扫描器里没有前缀清单。表多了一张，覆盖自动跟上。
- **R12-1.3 查的是值，不是写法**：字面量、拼接、模板、从字符码构造、动态键、常量文件、跨文件 import 的常量，都先做常量折叠与别名溯源，落到带登记前缀的字串就计入。换一种写法到达同一个值，不能少计。
- **R12-1.4 id 反推按类型判**：对实体 id 这种品牌值做的任何字符串操作都计入，不看方法名。类别只能从卷二指定的类别读入口得到。
- **R12-1.5 规则表的键也查**：规则表的键里出现带实体前缀的字串，计入。以实体为行的实例数据表不在此列，它们本来就按实体 id 分行。规则表的值里出现实体 id 的情形（开局配置一类）怎样登记，见 Q12-6。
- **R12-1.6 范围分三处，各成分量**：运行时代码、离线工具、测试各自计数，不混在一起。测试夹具里的 id 不是代码判断（卷一 §3.1 第 5 条），不计入规则层分量；它们另受卷十一 §4.6（测试重推口径）约束。待删目录在删空前单列计数（`c_retired_` 各分量），替代其读者的卡合入那一次该目录分量须为 0（R12-8.7）。
- **R12-1.7 各卷的同类扫描条都是同一个检测器**：各卷写的"本卷某几族的条目代号在代码里出现次数为 0"，一律登记成 `lit_scope` 加族键集合的参数。族键集合取自该卷的登记，扫描器不为任何一卷写专用逻辑。

#### 4.1.4 交互

卷一 R-4 与卷二 S1、S12 给判据；卷二 §1.2（表头）给前缀登记；各领域卷给族键集合；卷十一 §4.2（每卷迁移清单汇总）拿逐行清单做认领。

#### 4.1.5 数据实例

- 【西陲】把开局主粮写成一个物品常量的那一处（卷一 R-4 第 3 条举的例）：字面量经别名溯源落到带物品前缀的字串，计入 `c_instance_id`；改成从配置读以后消失。
- 【非西陲】远方生成里按名称、首字、拼接间接点名的三处（卷一 R-4 第 1 条举的例）：靠 R12-1.3 的折叠与溯源计入，不靠人认出来。
- 【非人类】用 id 字串的开头判实体类型的写法，卷零补充口径给的参考数是 103 处、51 个文件：全部落在 `c_id_parse`，由类型位置检测器报出。

#### 4.1.6 验收断言

- 扫描式：A12-1.1 S12-5 计数为 0；`c_instance_id`、`c_id_parse` 两分量在末阶段为 0。
- 不变量式：A12-1.2 同一内容，任意打乱文件遍历次序，逐行清单逐字节相同；往规则层任一文件加进一个带登记前缀的字串，不论用 R12-1.3 列的哪种写法到达，`c_instance_id` 恰好加一。
- 扩展性式：A12-1.3 卷二新登记一张表、表头带一个新前缀，不改扫描器，规则层里带这个前缀的字串即被报出。

### 4.2 读文字扫描

对应卷零代号 S2、S2b。

#### 4.2.1 维度

扫描类别 `text_judge`、`display_read`、`escape_hatch`、`nl_literal`（§2.4）；检测器 `typed_pos`、`path_access`、`file_set`、`lit_scope`；分量：组 × 类别派生的 `c_text_` 各分量，合计读数 `c_text_judge`、`c_text_display`、`c_text_tools`，单列的 `c_l74`、`c_cn_enum`（§2.5）。

#### 4.2.2 统一入口

执行经 `accRun`；范围展开经 `accScope(itemKey)`；读结果经 `accHits(filter)`。

#### 4.2.3 规则

- **R12-2.1 判据不在本卷**：机制唯一定义在卷二 §2.8（字符串类型规则）与卷二 §2.9（外部边界与 Text 模型），验收口径是卷二 §7 的 S13、S18、S19，技术底线在卷一 §3.1。本卷不重写正反例，只定实现与归组。
- **R12-2.2 实现形态**：类型检查加一条自写的类型感知规则（"同一品牌加节点位置白名单"现成规则做不了，卷二已把这件工作判给本卷）。判定依据是表达式的静态类型与节点位置，不是方法名清单。它们依赖的外部包逐个登记在离线组白名单里。
- **R12-2.3 文件到模块组，按磁盘真实文件算**：每个文件属于哪一组，由声明表的各组成员模式对磁盘上的真实文件全集展开得出，不用代表路径。每组用卷二 §2.8 表里该组那一行的闭集。闭集与文件限定必须以机器可读的登记给出，扫描器只读登记（C12-3）。
- **R12-2.4 覆盖门禁**：类型检查与语法检查各自处理的文件清单，要与磁盘清单相等；忽略项与排除项为空。有文件没被查到，本身就是不通过。
- **R12-2.5 归不了因就报**：类型标注缺失、解构后丢了类型、跨函数后归不了因的值，一律按字串处理并报出（卷一 §3.1 第 2 条）。消除办法是改写法让类型归得上，不是加名单。
- **R12-2.6 边界各组各有扫描条**：输入边、显示层组、显示闸、入库前守门、闸内判定各按自己的闭集扫（卷一 §12.1（扫描式）的 V-23、V-24、V-25、V-29、V-31）；译码与守门的判据取卷九 §4.19（输入边译码器与入库前守门）。不开文字模型时，输入边的文字操作只有规范化加整串查表。host、textcore、clientTextcore 与 kernel 四组同样各按卷二 §2.8（字符串类型规则）表中该组的逐文件闭集扫；aiGate 另扫引文同一性只经 `matchQuote` 一处。卷二 §2.9（外部边界与 Text 模型）第 6 条的文字检查例外清单（三项）与子串函数签名表是本条各组判据的来源，卷零 §0.5 S2 的例外②（引文同一性）也指向它们，本卷只引用，不另立。
- **R12-2.7 那 74 行单列**：`c_l74` 单独追踪。其中改为移入输入边的行，不因换了目录就从计数里消失（卷一 R-2 第 5 条）。
- **R12-2.8 非 ASCII 枚举值**：`c_cn_enum` 单独成分量，终值 0。
- **R12-2.9 离线组读文字的闭集（李白 11-13 裁定 Q12-3：按类别登记）**：离线组允许读文字的程序是一个按类别登记的闭集，只有三类——① 文稿类检测器（§2.3 的 `doc_struct`、`doc_candidate`，含登记器解析各卷条目编号的那一步）；② 内容构建校验器（`tools/content-build-check.mjs`）；③ 命名校验器（`tools/name-blocklist-check.mjs`，卷二 §1.9（代号、显示名与语言边界）指定，全书拼装显示名做比对的只有它）。入闭集的条件四条同时满足：只离线；不进运行时（运行时任何组不 import）；只产出候选位置或结构结果；不判世界逻辑。闭集的成员按结构键登记在声明表的离线组项下，增项要过审并改本条。内容构建校验仍按卷零 15.7 行的方向改为读结构化字段，它读文字的部分只降不升。闭集之外的离线程序拿文字判逻辑的写法，终值为 0；离线组四类分量（`c_text_` 离线组各类）只降不升，合计读数是 `c_text_tools`。
- **R12-2.10 显示路径**：哪些路径算显示字，只取声明表的显示集合与维度表里字串类型字段的路径（卷一 §3.1 第 3 条），不按全局字段名。读错误对象的文案同样计入。
- **R12-2.11 只扫描，不实现闸**：闸内匹配的实现只有 gate 组那一个文件。本卷的扫描器不含匹配算法的第二份实现；文稿类检测器读的是设计文稿，不是玩家或模型的文字。
- **R12-2.12 输出边零写死文字（李白 11-14 裁定 Q29-6；卷二十九 C29-7）**：自然语言字面量单成扫描类别 `nl_literal`（§2.4），口径照卷二十九 §4.8（显示层验收）的 R29-8.1，本卷不另立：计数范围是两个进程的全部运行时代码文件，输出边三组（outputGate、host、display）同样计入，不放行；字串字面量含中日韩表意文字、假名、谚文码点的一律计入；其余字串字面量归不进登记代号、文件路径、schema 名、结构键四类之一的计入；注释不计。结构键只指登记 schema 里的字段名（卷二 §2.7 声明表与各卷维度表登记的字段），本卷不另列名单。检测器是 `lit_scope`，字面量类别取"非 ASCII"与"归不进登记键类的字串"两类，范围按 R12-2.3 由声明表的组对磁盘真实文件展开。分量按组派生（§2.5），终值 0，迁移期间只降不升（卷二十九 S29-1，E-DISPLAY-LITERAL）。卷零 S2b 原写的输出边"允许出现自然语言字面量"，本卷按"允许文字类型的值流经"执行（卷二十九 R29-7.2；卷零措辞由卷二十九 C29-10 请改）。

#### 4.2.4 交互

卷二 §2.7、§2.8、§2.9 给组、闭集与边界登记；卷九 §4.19 给译码与守门判据；卷零 §3.5（输入边与模型叙述解析 · 逐处处置）给那 74 行的逐处去向；§4.13 的用例集做回归。

#### 4.2.5 数据实例

- 【西陲】06b 的 B 类 27 行：用文字判设施、地点、爵位、物品类别。全部在 `c_text_judge`，改读代号后消失。
- 【非西陲】06b 的 C 类 13 行：用文字判地形、气候、产业；远方生成里另有按名称判的写法。同一分量。

#### 4.2.6 验收断言

- 扫描式：A12-2.1 各组各类在末阶段为 0；R12-2.4 的两份清单与磁盘清单的差为空；`c_l74` 的行数不因目录变动而减少，只因逐处处置完成而减少。
- 不变量式：A12-2.2 用例集里读文字类的 `must_fail` 全部报出、`must_pass` 全部不报；把任一 `must_fail` 片段放进规则层任一文件，`c_text_judge` 恰好增加该片段登记的命中数。

### 4.3 写入归属扫描

对应卷零代号 S3。跨模块直写、双写、越系统写、未声明读写都在本节。

#### 4.3.1 维度

扫描类别 `cross_write`、`dual_write`、`undeclared_io`、`module_edge`、`transitional`（§2.4）；检测器 `path_access`、`decl_cmp`、`call_edge`、`import_edge`、`data_shape`；分量 `c_write_` 加声明项键、`c_legacy_shell`、`c_adapter_calls`（§2.5）。

#### 4.3.2 统一入口

执行经 `accRun`；读结果经 `accHits(filter)`。

#### 4.3.3 规则

- **R12-3.1 判据不在本卷**：一字段一写者、三条写通道、写路径按登记写者核对，定义在卷二 §2.6（写者与三接口）与卷二 §2.7（系统声明表 `state-owners.json`）。
- **R12-3.2 三种情形都按声明表判**：越系统写，是写入点所在文件不是该路径的登记写者，又不经三条写通道。双写，是同一路径模式登记了两个以上改写写者，或者实现里同一路径有两处不经同一个写入口的写入。未声明读写，是调用图里实际的读写超出了声明。三种都不列字段名单：路径、写者、通道全部来自声明表。
- **R12-3.3 分量按声明项派生**：每个写者声明项一个分量（§2.5）。新增一个声明项，就多一个分量。
- **R12-3.4 动态访问一律计入**：用变量当键访问状态、把状态展开、把状态传给登记之外的函数，都计入。否则写入点归不到路径上，前三种判定都会漏。
- **R12-3.5 声明与实现比对**：每个声明节点的实现函数与它调用图内的同仓库函数，实际读到的状态路径要落在声明的范围之内（卷二 §2.3（记忆与依赖声明）的叶子核对，卷二已把这件工作判给本卷）。
- **R12-3.6 调用者闭集与读者闭集**：各卷写的"某入口只许某些模块调用""某路径只许某些模块读"，一律登记成 `call_edge`、`import_edge` 或 `path_access` 加参数。闭集本身必须登记在声明表或该卷指定的登记字段里，不写在扫描器里，也不写在条目参数里。闭集外的调用就是代码侧的后门。
- **R12-3.7 过渡设施**：旧处理器外壳的登记动作数、账本适配器的调用点数，各是一个分量，只降不升（卷十一 §4.5（阶段退出标准）的 R11-5.5）。适配器过渡期的起止在卷一 §6.5（账本双写的唯一责任母卡 LEDGER-1）。
- **R12-3.8 判边，不判名字**：本地谓词、绕过入口一类的禁令，按 import 图与调用图上的读取边判，不按函数叫什么名字判。

#### 4.3.4 交互

卷二 §2.6、§2.7 给写者、通道与闭集登记；卷十一拿各分量的逐行清单做认领与退出检查；各领域卷给读者、写者、调用者闭集。

#### 4.3.5 数据实例

- 【西陲】钱币直写 52 处、公库直写 12 处（卷一的旧基线）：各落在钱与公库两个声明项的分量里，随账本母卡清零。
- 【非西陲】记录写点 311 处、人物写点 196 处：远方生成写回的部分也在其中，与本地的写点同一分量，没有"远方的另算"。
- 【非人类】卷二十的水体污染物随取水转出，那个写者在两卷的写者表里各登记了一次：文稿侧由 `doc_dual_write` 报出候选；代码侧若实现成两处写入，由 `dual_write` 报出。
- 【超自然】效果族的产出要改别的系统的维度：只能产提案，由目标写者落盘。效果实现文件里直接写目标路径，报 `cross_write`。

#### 4.3.6 验收断言

- 扫描式：A12-3.1 各写入归属分量与两个过渡设施分量在末阶段为 0；闭集登记在扫描器源码或条目参数里的条数为 0。
- 不变量式：A12-3.2 逐行清单里每一行的路径都能在声明表里查到所属声明项；每个声明项恰有一个分量；任意两次相邻合入之间，两个过渡设施分量不上升。
- 扩展性式：A12-3.3 声明表新增一个写者声明项，不改扫描器，多出一个分量，对该路径的登记外写入即被报出。

### 4.4 规则来源与常数扫描

对应卷零代号 S4。

#### 4.4.1 维度

扫描类别 `const_literal`、`rules_import`、`fallback`（§2.4）；检测器 `lit_scope`、`import_edge`、`typed_pos`、`data_shape`；分量 `c_const_literal`、`c_rules_import`；`rules.accept.basisSamplePermille`（§2.10）。

#### 4.4.2 统一入口

执行经 `accRun`；读结果经 `accHits(filter)`。

#### 4.4.3 规则

- **R12-4.1 判据不在本卷**：白名单与口径在卷一 R-6，常量折叠的验收口径在卷二 §7 的 S10。本卷不扩白名单。
- **R12-4.2 按折叠后的值判**：凡静态能求出值的表达式都算，求出的值不在白名单里就计入；换算式、位运算、取长度凑出来的数同样计入。
- **R12-4.3 规则数据只有一个来源**：直接 import 规则数据文件的次数计入 `c_rules_import`；规则数据只经规则入口读。
- **R12-4.4 出处抽检**：审查对本次新增或改动的规则表数值条目抽检出处。抽检条数不少于改动条数乘以 `rules.accept.basisSamplePermille` 再 ÷ 1000 后向上取整（除数是常数 1000，恒为正）；改动条数不为 0 时至少抽 1 条。抽检只在第二轮做（李白 11-13 裁定二审余项 B 取乙）：抽检种子 = 第二轮审查记录号加定稿内容指纹（即该第二轮记录绑定的指纹），由执行器（脚本）计算，按条目键的固定次序选出抽中条目；第二轮记录号在第二轮记录经批准提交入口提交后才生成，内容此时已定稿，再改任何内容指纹即变、该批准即 `stale`，所以实现者事先算不出、事后也挑不动。同一内容指纹下有多条第二轮记录时，只认记录号最小的一条（记录号按逐字节字典序比较；记录号由提交入口生成且不重复，次序唯一）：种子按这一条的记录号与 `contentPrint` 算，抽中条目由该种子派生；同指纹后续的第二轮记录不另抽，`sampleSeed`、`sampledKeys` 照抄这一条的值。实现者与审查者都不准换种子重算后挑结果。种子与抽中条目由执行器算出后写入第二轮记录（§2.7 `sampleSeed`、`sampledKeys`），第二轮审查者再对抽中条目逐条作答出处核对（R12-9.6），答完之前这条批准不生效。第一轮记录不做抽检，不需要自己的种子。现有批准提交入口（M12-14）只追加、只收固定字段，写不进 `sampleSeed`、`sampledKeys`；由解冻后的门禁卡扩 `review-put.sh` 支持这两个字段（李白 11-13 裁定），写入方式由该卡定，不改已提交的记录。扩之前，本条机判报 `not_run`，不得算通过，并在报告里列为公开缺口。机判：取该内容指纹下记录号最小的第二轮记录，按它的记录号与 `contentPrint` 重算种子与集合；该指纹下每条第二轮记录的 `sampleSeed` 须等于这一重算种子，`sampledKeys` 须等于由它派生的集合；不符即 E-ACC-REVIEW-CHECKLIST。同一记录号、同一内容两次选出的相同，不读随机源。
- **R12-4.5 内核登记常数**：内核里登记过的算法常数逐条在登记表里，文件里出现表外的数照报（卷二 S10）。
- **R12-4.6 数据里的手填难度一类**：数据表里按规则应由派生算出、却手填了数的字段，由 `data_shape` 报出（卷一 R-6 第 5 条），类别 `handfill_derived`，分量 `c_difficulty` 的旧基线 26 取自卷一 R-6"判定"一段。
- **R12-4.7 非规则组同口径**：入库前守门、显示闸、输入边里的数同样要来自规则表（卷二 S19）。
- **R12-4.8 兜底回退**：对缺失的维度值用常量替代，报 `fallback`，不因为替代值恰好在白名单里而放过（卷一 R-6 第 4 条）。

### 4.5 校验器与不变量进必过集合

对应卷零代号 S5、I。

#### 4.5.1 维度

条目的 `state`（`in_core`）、`stage`、`gates`（§2.2）；方法 `load_check`、`property_test`、`unit_test`。

#### 4.5.2 统一入口

读 `accItems(filter)`；执行经 `accRun`。校验器本身的入口在卷二 §4.1（分级、时机与分期）。

#### 4.5.3 规则

- **R12-5.1 必过集合**：状态为 `in_core` 的条目构成必过集合。提交关口与合入关口执行其中 `gates` 含该关口的全部条目，一条不过即拒。"进 CORE"在全书就是这个意思。
- **R12-5.2 校验器是卷二的，本卷只把它接进关口**：提交关口对全部维度表、公共表、规则表、声明表跑卷二 §4.1 的 L0 至 L4，错误数为 0 才过。L5 齐全率不阻断，读数进报告，并与卷二 §6.12（齐全率总表）的下限比对。
- **R12-5.3 校验入口只有一个**：规则模块自带的加载期校验函数是旧物（§7 的 M12-7）。规则表的结构校验改由统一校验器按登记的结构描述完成；规则层文件在登记边界入口之外读数据文件，本来就被卷二的边界规则报出，本卷不另立判据。
- **R12-5.4 不变量按期进集合**：卷一 §9（不变量总表）的分期表转录成各条目的 `stage`。到了阶段 k 的退出关口，`stage` 不大于 k 的条目必须全部 `in_core`，否则 E-ACC-ITEM-UNIMPLEMENTED，阶段不退出。
- **R12-5.5 各卷的不变量同法**：各卷不变量式断言与各卷登记的跨表不变量码，一样登记、一样按期。不变量测试没有随数据改变的期望值，失败一律是实现的缺陷（卷十一 R11-6.9）。
- **R12-5.6 不变量的输入**：用 §4.6 登记的场景加性质测试，不在测试里写某个实例应该是多少。
- **R12-5.7 错误码都要登记**：代码与条目里出现的每个错误码，都能在卷二 §4.3（错误码表）或某卷的错误码表里查到；查不到即 E-ACC-CODE-UNLISTED。
- **R12-5.8 校验器自身确定**：同一输入两次运行，输出逐字节相同（卷二 §7 的 A7）；登记为一条方法是 `digest_compare` 的条目。

#### 4.5.4 交互

卷二 §4.1、卷二 §4.2（报错格式）、卷二 §4.3 给校验器、报错格式与错误码；卷一 §9 给不变量与分期；卷二十八的加载校验流水线（该卷未写）成稿后把它的检查登记为条目；卷十一 §4.5 在阶段退出时读 R12-5.4 的结果。

#### 4.5.5 数据实例

- 【西陲】物品表与地点表（卷二记的行数是 486 与 458）：首卡合入后，这两张表过 L0 至 L3 成为提交关口的必过条目。
- 【非西陲】生成 100 个远方聚落，全部经同一个校验器零报错（卷一 R-7 的判定 ①）；个数取 `rules.accept.generatedSample`。
- 【超自然】生成 100 位神祇同法；再做互换：把手写的神换成生成的神，该类别的全部断言仍过（卷一 R-7 的判定 ②）。
- 【非人类】生成 100 个怪物同法；物种行缺必填维度时加载失败，路径指到该行该维。

#### 4.5.6 验收断言

- 扫描式：A12-5.1 到期而未进必过集合的条目数为 0；E-ACC-CODE-UNLISTED 为 0；提交关口的校验器错误数为 0。
- 不变量式：A12-5.2 必过集合只增不减，除非条目随它的定义处一起退役；任一次合入之后，必过集合里的条目全部为 `pass`。

#### 4.6.2 统一入口

#### 4.6.3 规则

- **R12-6.2 扩展性测试的固定步骤**：① 记下代码文件集合的指纹；② 用数据包往表里加临时的新行；③ 过加载校验；④ 推进规定的时长；⑤ 按该表表头列出的行为逐项断言；⑥ 再记一次代码文件集合的指纹，与 ① 相同才算数，不同即 E-ACC-EXT-CODE-CHANGED；⑦ 撤掉数据包重跑，事件流与从未加过时相同。

- **R12-7.3 三列要独立重算一遍**：卷十一由卡账算出三列。本卷不调卡账，按版本库与逐行清单再算一次：写死零，按 R12-7.2 表最后一列；入口一，当且仅当该行迁移行登记的旧入口符号在版本库里的定义点与引用点数为 0（检测器 `sym_exists`，参数是迁移行键，符号取自卷十一的迁移行，不手列）；维度齐，当且仅当该行所属的表过了必填完整一级且齐全率不低于卷二 §6.12（齐全率总表）的下限——下限须登记成规则表键（C12-3），登记之前这一项算 `blocked`，不回填"是"。两边算出的不一样，E-ACC-ZERO-MISMATCH。
- **R12-7.4 反向**：各卷 §0 自报承接的卷零行，行号都存在；卷零 §7（缺漏自检）列出的没有行引用的子系统，在所属卷的 §0 都有自报。
- **R12-7.5 逐处处置**：卷零 §3.5 的每一处，其迁移行锚点上对应分量的行数为 0，才算完成。
- **R12-7.6 "已有"不免查**：卷零 §4（已有 41 项 · 李白三条硬条件核查栏）的各行，与别的行一样要有条目与扫描读数。
- **R12-7.7 核对结果是数据**：核对输出各项的计数与不符的行号，进报告；不手写结论。

#### 4.7.4 交互

卷零给行、代号与三列；卷十一 §4.9（卷零回填与全书收口）给 `migBackfill`，它的 S11-10 与本节的 R12-7.3 互为对账；卷一 §12.5（全书收口）用本节的结果。

#### 4.7.5 数据实例

- 【西陲】卷零"物品本体"一行：验收扫描列的代号各有条目指向它；物品类 id 字面量所在位置全删后，本卷独立算出的写死零与卷十一回填的一致。
- 【非西陲】卷零世界生成组里远方聚落那一行：远方生成文件删除后，该行锚点文件已不存在，对应分量行数为 0，写死零与入口一同时成立。
- 【超自然】卷零信仰组各行：按显示名找神的读者改完之前，入口一不成立；若卡账先填了"是"，本节报 E-ACC-ZERO-MISMATCH。
- 【非人类】卷零生物组的物种行：物种表过必填完整一级且齐全率达标，维度齐才成立；首卡回退后本节重算，结果随之变回不成立。

#### 4.7.6 验收断言

- 扫描式：A12-7.1 卷零验收扫描列里没有条目对应的代号数为 0；E-ACC-ZERO-MISMATCH 为 0；自报行号不存在的条数为 0。
- 不变量式：A12-7.2 卷零任一格为"是"，当且仅当本节独立算出的条件成立；全书收口时三列全部为"是"且逐处处置全部完成。
- 扩展性式：A12-7.3 卷零新增一行并写了验收扫描代号，只要有条目的 `zeroRows` 含它，核对即覆盖它，不改代码。

### 4.8 基线只降、上升即拒

#### 4.8.1 维度

基线分量（§2.5）；逐行清单行（§2.6）；执行记录的 `components`、`newRowKeys`、`goneRowKeys`（§2.7）；方法 `soak`、`bench`。

#### 4.8.2 统一入口

读 `accBaseline()`、`accHits(filter)`；写只经执行器。

#### 4.8.3 规则

- **R12-8.1 分量的值就是行数**：每个分量的现值等于逐行清单里属于它的行数。旧基线里按模块数、按处数给的数，都以按本条口径重数的结果为准。
- **R12-8.2 行键不含行号**：行键由分量代号、文件路径、所在符号链、节点种类、同符号内的序号拼成（§2.6）。文件里别处增删代码，行号会变，行键不变。文件搬迁时按卷二 §6.11（显示字段、语言解析与派生槽的迁出）的文件搬迁表把旧路径换成新路径后再比（搬迁表唯一定义在卷二 §6.11，李白 11-13 裁定；卷十一只持它的机读形式）。符号改了名，行键会变：这时同一分量里消失一个、新出现一个，报 E-ACC-ROWKEY-DRIFT，由认领它的卡确认是不是同一处；确认前该行不算已删。
- **R12-8.3 B0 的来源与锁定**：照卷一 §6.3 的锁定规则。读文字类分量的 B0 以 G-3 完成后的逐行清单数为准；其余分量按 §2.5 表里写的来源。锁定之后，B0 只有经判据修订流程才可重数（R12-14.6）。
- **R12-8.4 只降判定**：提交关口上，任一分量高于上次合入的值，拒绝（E-ACC-BASELINE-UP；卷一 I43）。行集合的差另列进执行记录：新出现的行键逐条写出，按位置分两种处理（李白 11-13 裁定 Q12-1 折中）：① 新行键落在任何迁移行的锚点范围之外（卷十一 R11-2.6 的锚点），提交关口机器直接拒，E-ACC-NEWROW-UNANCHORED——把写死的东西挪到新文件属于这一种，不再等阶段退出时的 E-MIG-SCAN-UNCLAIMED；② 落在某条迁移行锚点之内的，交两轮审查逐条看过并在审查记录里作答。函数改名、拆函数造成的新行键走 E-ACC-ROWKEY-DRIFT，确认前旧行不算已删；文件搬迁先按 R12-8.2 重定位，不算新行键。
- **R12-8.5 合入后更新**：合入关口通过后，执行器把各分量现值写成本次实测、记下合入号。合入是串行的，所以每次只有一个"上次合入"（卷十一 R11-4.5）。别的途径改基线文件，或改已锁定的 B0，是 E-ACC-BASELINE-EDIT。
- **R12-8.6 回退**：卡回退时，执行器按回退后的内容重数，基线随之回到那张卡合入前的值（卷十一 R11-8.3）。不手改。
- **R12-8.7 待删目录**：登记为待删的目录在删空前单列计数（`c_retired_` 各分量），不并进规则层分量。删空时点已裁定（李白 11-13，Q12-2）：登记待删，替代其读者的卡合入后删（卷二 §6.11）。本卷只定计数：删空之前单列；替代卡合入那一次，合入关口要求该目录分量为 0，不为 0 即合入不过（卷二的 E-FILE-UNASSIGNED）。
- **R12-8.8 给阶段退出检查的读数**：每个阶段退出时，把各分量的实测存一份阶段快照。卷十一的 `migExit` 从 `accBaseline()` 与这些快照取 B0 与各阶段实测；目标与硬上限由卷十一算，本卷不算。
- **R12-8.9 新分量**：登记一个新分量时，对基线提交数出 B0，再对当前内容数出现值，两个数一起登记；之后与别的分量同受约束。
- **R12-8.10 浸泡指标与性能门**：浸泡指标、性能基准登记为条目，方法是 `soak`、`bench`。指标的定义、门槛、参考环境、计数类与计时类的区别都在卷二十七 §4.6（性能门与基准）；本卷只管执行与把结果写进报告：计数类读数进报告正文，计时类读数（取多次中位数，两次执行不会相同）写进计时附表，不进报告正文（R12-10.5）。门槛还是待标定的条目为 `blocked`，到所属阶段的退出关口仍未标定即 E-PERF-UNCALIBRATED，阶段不退出（R12-4.9）。性能基线文件登记在 §2.11，唯一写者是执行器，只在合入关口写；它的每一处升高须对上同一次合入的新增登记或标定依据，否则 E-PERF-BASELINE-UNJUSTIFIED（卷二十七 R27-6.3），这是合入关口的必过条目（S12-15）。

#### 4.8.4 交互

卷一 §6.3、卷一 §6.4（阶段退出标准（实条款））给基线元组与退出五条；卷十一 §4.5 读分量、§4.2 认领逐行清单、§4.8（回滚、冻结与解冻）在分量上升时冻结；卷二十七 §4.6 给指标与门槛。

#### 4.8.5 数据实例

- 【西陲】一张地点表的后续卡把写死的地点 id 从一个文件挪到新文件：`c_instance_id` 总数不变，但执行记录里出现新行键，审查逐条看时认出是挪动而不是删除，打回（卷十一 §4.8（回滚、冻结与解冻）数据实例里的同一例）。
- 【非西陲】远方生成文件整体删除的那张卡合入：该文件上的全部行从逐行清单消失，几个分量同时下降，执行器写入新值；下一张卡以它为上次合入。
- 【超自然】卷七的卡给效果实现文件里的一个函数改了名：两行行键漂移，报 E-ACC-ROWKEY-DRIFT；卡确认是同一处且尚未处理，该行继续算作未删。
- 【非人类】换一档推进速度后均衡类统计量的长期值（卷二十的浸泡指标）：登记为 `soak` 条目，容差键归卷二十，比较方法用卷二十七登记的代号。

#### 4.8.6 验收断言

- 扫描式：A12-8.1 S12-7 计数为 0；任一合入提交相对上次合入有分量上升的次数为 0；行键里含行号的行数为 0。
- 不变量式：A12-8.2 每个分量的现值等于逐行清单中该分量的行数；只在文件别处增删代码、不动命中节点所在的函数时，全部行键不变；一张卡合入再回退，基线各值与合入前逐个相等。
- 扩展性式：A12-8.3 登记一个新分量（给出类别与范围），不改执行器，它出现在提交关口的判定、报告与 `accBaseline()` 的输出里。

### 4.9 两轮审查绑定内容哈希与门禁

#### 4.9.1 维度

`gate_point`、`review_verdict`、`bench_kind`（§2.1）；审查批准记录与执行记录（§2.7）；测试台登记（§2.8）；`rules.accept.reviewRounds`（§2.10）。

#### 4.9.2 统一入口

读 `accReviewOk(subject, contentPrint)`、`accGate(gate, subject, contentPrint)`；批准记录只经云门禁的批准提交入口写。

#### 4.9.3 规则

- **R12-9.1 六道关口各拦什么**：

| 关口 | 什么时候 | 执行什么 | 在哪跑 |
|---|---|---|---|
| `pre_commit` | 每次提交 | 必过集合里的静态条目；校验器；绕法用例回归；只降判定；仓库内内容行达到应过级别（R12-9.12） | 本机静态 |
| `pre_test` | 任何云上执行之前 | 两轮批准是否有效 | 云门禁入口 |
| `pre_merge` | 卡合入前 | 全部静态条目；受影响的测试；该卡验收判据所列条目；批准有效；提交信息读数；仓库内内容行达到应过级别（R12-9.12） | 云上参考环境 |
| `phase_exit` | 阶段退出 | 全量测试；全部条目中 `stage` 不大于本阶段者；卷零核对 | 云上参考环境 |
| `seal` | 一卷封卷 | 全部文稿类条目在该卷上的命中为 0；该卷自检 | 本机静态 |
| `book_close` | 全书收口 | 卷一 §12.5（全书收口）各条 | 两处都要 |

- **R12-9.2 两轮**：第一轮审代码与它牵连的调用，重点看性能与规则是否通用；改完之后第二轮复核最终内容。批准成立要同时满足（照现行云门禁写死，只许收紧）：① 当前内容指纹下有一条第二轮批准记录；② 它引用的第一轮记录存在、确是第一轮；③ 两轮审查者互不相同，且都不在两轮记录的实现者名单里（R12-9.5）；④ 同一内容指纹下没有任一轮的打回记录（R12-9.3）。
- **R12-9.3 批准绑定的是内容**：只有第二轮记录必须绑定当前内容指纹，由它单独决定放行哪个版本；第一轮记录只需存在并被第二轮引用，可以对应改动之前的另一个指纹、结论不限，但若与当前是同一指纹则必须是批准（不满足即 E-ACC-REVIEW-MISSING）。打回一票否决：同一内容指纹下有任一轮的 `rejected` 记录，该版本不得放行，E-ACC-REVIEW-VETO，要改内容（指纹随之变）再审。内容指纹覆盖实际要跑的全部内容：未提交的改动、测试、运行脚本都在内；覆盖范围按现行门禁的约定（待补清单第 1 项）：不计依赖安装目录、输出与临时目录、版本库目录与文件权限位，文本先把 CRLF 换成 LF 再算；范围内的内容一变，指纹即变，此前绑定旧指纹的第二轮批准对新内容即 `stale`，拿它过关口是 E-ACC-REVIEW-STALE。同一算法另有一种输入形式“行主体”（卷二十八 C28-6）：输入是一行内容，覆盖范围按卷二十八 §4.5（内容审批管线）的 R28-5.2，即该行在当前包集合下展平并编译补丁之后逐维的有效值与来源标记，加上各已发布语言里以该行代号为键的语言包条目；这些输入一变，该行的指纹即变。两种形式只是输入不同，算法只有这一种，不另立第二种指纹。内容指纹是仓库外的门禁工具对一批文件算的指纹，行主体形式在离线工具里按行算，都不在世界状态里，不在两个运行时进程里，规则层读不到，与存档摘要无关（李白 11-13 裁定 Q12-4）。
- **R12-9.4 硬拦截**：云测试台的入口在执行前调 `accReviewOk`，不成立就拒绝，不给跳过的参数。换一个入口上云执行是 E-ACC-GATE-BYPASS；执行记录没有绑定内容指纹是 E-ACC-RUN-UNBOUND。主会话自己改了内容也要重审，不得改完直接测。
- **R12-9.5 审查者独立**：两轮审查者的身份代号相同，或任一轮审查者出现在两轮记录任一份的实现者名单里，即 E-ACC-REVIEW-SELF，该对记录不构成批准。判定只按记录里登记的身份代号做；身份本身不经认证（R12-9.13）。
- **R12-9.6 审查记录要逐条作答**：审查记录分阻断项与非阻断项。方法为 `human_review` 的全部条目都是人工审查项，由登记派生，别卷新增的人工项登记后即进入，不在本条逐个列名；审查记录里逐条答是或否，缺答即 E-ACC-REVIEW-CHECKLIST。首批来源有：卷一 §10（反模式清单）里识别列写着人工的各条；卷十一 R11-6.3 的四种打回情形；R12-4.4 的出处抽检（第二轮，对抽中条目作答）；R12-8.4 落在锚点之内的新行键逐条说明；R12-11.11 登记行期望、阶段、关口与定义处的逐条对照。
- **R12-9.7 哪些在本机、哪些上云**：推进世界的测试、块验收与守恒长测一律上测试台（腾讯云）；不推进世界、几秒内跑完的纯函数/校验器测试可登记 `local_static` 在本机跑（李白 11-18 06:41 裁定②；与 AGENTS.md 测试节 11-17 所定一致，整类适用；封卷后勘误 1118k14）。静态条目（不起世界推进的）在本机跑；量性能的，一律在登记为启用的测试台跑，不得在开发用的本机跑正式性能对比。每条条目的 `runsOn` 写它最低需要哪种测试台：`local_static` 的条目本机与云上测试台都能跑，`cloud_ref` 的只在云上测试台跑；某一关口实际在哪跑由 R12-9.1 表的"在哪跑"一列定，云上关口（如 `pre_merge`、`phase_exit`）把它要执行的 `local_static` 条目一并在测试台跑。上传、同步、磁盘空间检查、旧副本清理等运维做法沿用现有约定，不在本卷规定。
- **R12-9.8 测试台是登记项**：测试台登记在 §2.8 的表里，执行器里没有任何测试台的名字。跨环境一致性的条目（`det_cross_env`）要在登记为启用的每个测试台、每个支持的运行时版本上各跑一遍再比（李白 11-13 裁定 Q12-5）。卷一 V-27、卷二 G3、卷二十七 A27-5.4 写的"本机与云"，在本卷映射为"玩家平台测试台与云参考测试台"；玩家平台测试台现未启用（§2.8），这期间凡要它参与的比较一律报 `not_run`，并在报告里列为公开缺口；不得以"只有云一台"当作比过了。卷一、卷二正文不改。
- **R12-9.9 设计文稿的审查**：各卷文稿的两轮审查规矩在《审卷须知》，本卷不重写。本卷只管封卷关口里能机判的部分（§4.12）。文稿审查的批准绑定该版快照文件的内容。
- **R12-9.10 两次不过即停**：同一对象在同一关口连续不过的次数达到 `rules.migration.maxFails`，停下，查到文件与行，报李白；不换个办法试下一次（卷十一 R11-8.5）。
- **R12-9.11 门禁自己的改动也过门禁**：改检测器、执行器、登记表、判据的提交同样要两轮审查。它不得与靠它放行的领域改动放在同一张卡里，免得自己给自己放行。
- **R12-9.12 内容审批管线**：内容的分级审批归卷二十八 §4.5（内容审批管线）。它里面能机判的校验登记为本卷条目；仓库内的每一行内容（本体与随本体发布的包）在 `pre_commit`、`pre_merge` 上要达到卷二十八 R28-5.3 由数据推出的应过级别（`requiredTier`），即有绑定该行当前行主体指纹（R12-9.3）、级别不低于它的批准记录，不达即 E-CONTENT-TIER（卷二十八 C28-6）；级别、批准记录与码义以卷二十八 §2.6（审批记录 `approvalRecord` 与级别规则 `tierRule`）、§2.9（错误码）为准，本卷只在关口上执行，不按包、按表、按行分支。它现有脚本里拿错误文案做匹配的三处按 §7 的 M12-11 处置。
- **R12-9.13 门禁的前提（不由本卷机判）**：现行云门禁只防意外与抄近路，不防有意作恶。下列前提成立，§4.9 各条才有效；前提被破坏不由 E-ACC 各码报出，靠运维与审查守：① 审查者与实现者的身份代号是自由文本、不经认证，E-ACC-REVIEW-SELF 只按登记的代号判；② 同一系统用户能读到门禁、审查与管理三把私钥，持钥的执行者可以伪造记录；③ 测试台未加固时，被审的测试以有提权的用户运行，可以改写审查记录与门禁脚本，审查者须读出这一点，加固要亮圳批准；④ 门禁密钥之外的任何无限制密钥或控制台登录都能绕过门禁且不留日志，S12-9 与 E-ACC-GATE-BYPASS 只覆盖经门禁密钥的执行；⑤ 内容指纹不覆盖顶层依赖包目录、输出与临时目录、版本库目录、文件权限位，文本按换行统一后计算（覆盖范围以现行门禁的清单口径为准，待补清单第 1 项）。约定的出处是现行门禁目录里的说明文件（C12-11）。

#### 4.9.4 交互

卷十一 §4.3（卡清单）的卡状态从 `review` 到 `merged` 要求本节的 `pre_merge` 通过；卷十一 §4.4（并行规则）规定重新对齐后批准失效，与 R12-9.3 一致；卷十一 §4.8（回滚、冻结与解冻）在关口两次不过时冻结；现有云门禁设施是本节的实现载体。

#### 4.9.5 数据实例

- 【西陲】一张经济类卡第二轮批准之后，实现者又改了一个测试文件：内容指纹变了，批准成 `stale`，云门禁入口拒绝执行；重审后才放行。
- 【非西陲】生成流程卡的审查记录里，新行键 5 条只答了 3 条：E-ACC-REVIEW-CHECKLIST，合入关口不过。
- 【超自然】卷七文化表首卡新增 12 个规则表数：按 R12-4.4，下限是 12 乘以 100 再 ÷ 1000（除数是常数 1000）后向上取整，得 2 条；第二轮审查记录里写入了由种子派生的 2 条，审查者并各写了出处核对结果。
- 【非人类】物种表首卡的两轮记录出自同一个身份、且就是实现者：两条构不成批准，E-ACC-REVIEW-SELF 加 E-ACC-REVIEW-MISSING。另一张怪物表卡第二轮批准了，但同一指纹下第一轮审查者事后补了一条打回：E-ACC-REVIEW-VETO，不放行。

#### 4.9.6 验收断言

- 扫描式：A12-9.1 S12-8、S12-9 计数为 0；已合入的卡里批准不足、批准失效、自审、缺答的条数为 0。
- 不变量式：A12-9.2 每条云上执行记录的内容指纹下，都有一条第二轮批准记录绑定这同一指纹，它引用的第一轮记录存在，两轮审查者互不相同且都不在实现者名单里，同一指纹下没有打回记录，且这些记录都先于该执行记录登记；内容每变一次，绑定旧指纹的第二轮批准对新内容全部为 `stale`。
- 扩展性式：A12-9.3 测试台登记表加一行并标为启用，不改执行器，`det_cross_env` 的条目自动多出这一环境的一遍；把一行标为不启用，它不再参与执行，依赖它的比较报 `not_run`。

### 4.10 主会话亲跑与报告

#### 4.10.1 维度

执行记录（§2.7）；`verdict`（§2.1）；报告字段（R12-10.3）。

#### 4.10.2 统一入口

执行经 `accRun`；读 `accReport(runId)`。

#### 4.10.3 规则

- **R12-10.1 谁跑**：各关口的执行由主会话亲自发起（卷一 §12.4（流程式）的 V-10）。执行者在自己的回报里写的扫描读数只作参考，不作数；作数的只有执行记录。
- **R12-10.2 一个入口**：各关口都调 `accRun`。没有"小范围先跑一下"的另一个入口；要少跑，就用关口与条目过滤的参数，照样出执行记录。
- **R12-10.3 报告的字段是封闭的**：

```text
内容指纹 / 关口 / 对象 / 测试台代号 / 执行器与各判据的版本号
条目：总数、pass、fail、not_run、blocked 各多少；每条不过的条目键与错误码
分量：每个分量的 B0、上次合入值、本次实测、差
行集合：新出现的行键、消失的行键、漂移待确认的行键
未处置命中数（按类别）
批准：两轮记录号、是否独立、是否有效
卷零核对各项计数（阶段退出与收口时）
计数类指标读数；计时附表的文件号（附表本身不在报告正文）
公开缺口：因测试台未启用而 not_run 的条目键；抽检核对 not_run（待解冻后门禁卡扩 review-put.sh，R12-4.4）
```

  缺字段、多出未登记字段，即 E-ACC-REPORT-FORM。"每条不过的条目键与错误码"一栏照 §2.12 "无码状态不许出现"整类规则写码：测试类条目不过报 E-ACC-TEST-FAIL，必过条目未跑或 blocked 报 E-ACC-REQUIRED-NOT-RUN（定义处 §2.12，此处只引用）。报告里没有显示文字参与判定；给人看的一行摘要由报告字段经语言包拼出。
- **R12-10.4 提交信息里的读数行**：合入提交的信息里带固定格式的读数行：每个有变化的分量一行，写分量代号、本次实测与相对上次合入的差；另有一行写内容指纹与执行记录号。读数行由执行器生成，手写的与执行记录不一致即 E-ACC-COMMIT-MSG。
- **R12-10.5 报告是确定的**：同一内容、同一关口、同一测试台，两次执行的报告正文除计时类条目的结论外逐字节相同。列表按条目键、行键升序。报告正文里没有时刻。确定性范围只含非计时类条目的结论（`verdict`）与计数类读数；计时类读数（卷二十七 R27-6.1 的 `metricClass` 为计时类的指标，多次运行取中位数）写进计时附表，附表不在确定性范围内，也不参与 E-ACC-REPORT-FORM 的"同内容两次不相同"判定。计时类条目的通过与否同样不算进确定性范围：它的 `verdict` 照常进报告正文并参与关口判定，但"同内容两次不相同"的比对只比非计时类条目。
- **R12-10.6 不拿通过数当结论**：测试的结果以条目为单位进报告。报告里没有"测试通过若干条"这样一个可以拿来报完成的总数；完成与否只看关口判定（卷十一 R11-5.7）。
- **R12-10.7 没跑的要写出来**：没执行的条目列为 `not_run`，前置不满足的列为 `blocked`，都不许省略。关口判定把必过集合里的 `not_run` 与 `blocked` 都当不过；关口上该对象还有未处置的命中，是 E-ACC-HIT-OPEN，同样不过。
- **R12-10.8 向人汇报取自报告**：向李白与亮圳的汇报，数字取自报告，写明内容指纹与执行记录号；区分拟采用、已实施、已验证、已交付。

#### 4.10.4 交互

卷一 V-10 定主会话亲跑；卷十一 R11-5.11 定阶段退出检查由主会话运行并写进计划文档；§4.9 的关口产出执行记录；卷九 §4.18 的费用账读数在真实模型试玩条目执行时并进报告（C12-10）。

#### 4.10.5 数据实例

- 【西陲】一张市价类卡合入：提交信息里有三行读数，分别是常数分量、规则来源分量与钱币直写分量的实测与差，末行是内容指纹与执行记录号。
- 【非西陲】远方生成卡的执行者回报"扫描全为 0"，主会话亲跑得到一个分量为 2：以执行记录为准，卡打回。
- 【超自然】卷七阶段的退出检查里，神迹类扩展性条目的场景参数键还没填：报告把它列为 `blocked`，关口不过，不因"其余都过"而放行。
- 【非人类】物种表卡的合入关口上，受影响的测试有一条没跑完：列为 `not_run`，关口不过。

#### 4.10.6 验收断言

- 扫描式：A12-10.1 S12-10、S12-11 计数为 0；E-ACC-REPORT-FORM 为 0；报告字段里出现测试通过总数的次数为 0。
- 不变量式：A12-10.2 同一内容、关口、测试台两次执行，报告正文逐字节相同（计时附表与计时类条目的结论除外）；报告里各状态的条目数之和等于该关口应执行的条目数；提交信息的每个读数都能在同一内容指纹的执行记录里查到相等的值。
- 扩展性式：A12-10.3 登记一个新分量或一条新条目，不改报告生成的代码，它出现在报告与读数行里。

### 4.11 条目统一格式与登记表

#### 4.11.1 维度

条目登记行（§2.2）；`acc_form`、`acc_method`、`acc_target`、`acc_expect`、`reg_state`（§2.1）。

#### 4.11.2 统一入口

读 `accItems(filter)`、`accItem(itemKey)`、`accScope(itemKey)`；写者是登记器。

#### 4.11.3 规则

- **R12-11.1 四种形式，一种格式**：全书的验收条目只有四种形式：扫描式、不变量式、扩展性式、流程式。不论哪卷、原来怎样编号，登记时都写全 §2.2 的必填字段。读起来是这样一张单子：

```text
条目键 / 所属卷与原编号 / 定义处（卷、节）
形式 / 方法 / 对象
检测器或模板 / 参数（只许登记键）
期望（封闭值）/ 基线分量（有则填）
卷零行号 / 从哪个阶段起必过 / 在哪些关口执行 / 在哪跑
```

- **R12-11.2 条目键**：条目键是卷代号加该卷正文里写的原编号。程序不从条目键里拆信息，要什么读字段。各卷原有的编号写法不必为登记而改；原编号在卷内必须唯一、稳定。
- **R12-11.3 转录一次，按条数对账**：各卷的条目一次转录成登记行，之后程序只读登记行，不读正文。转录对不对，先按条数对：登记行数等于该卷正文里带编号的条目数，否则 E-ACC-ITEM-COUNT；正文里有而登记表里没有的编号是 E-ACC-ITEM-UNREGISTERED，登记表里有而定义处找不到的是 E-ACC-ITEM-ORPHAN。数编号、比编号不是读文字。
- **R12-11.4 必须可机判**：一条条目填不出方法与封闭的期望值，就是不可机判，退回来源卷改写（E-ACC-ITEM-FORM）。形式与方法的相容关系：扫描式只配三种静态方法与流程记录核对；不变量式配加载校验、单点测试、性质测试、摘要比对、场景推进、浸泡、基准、独立验算；扩展性式配场景推进与摘要比对；人工审查项只许出现在流程式里。期望值 `report_only` 只许用于定义处带有登记标记的条目——由来源卷在条目处写明它是对照报告、不作判据（如卷六的旧价格校准参考、卷十四的成长标定）；登记器核对这个标记，没有标记而填 `report_only` 即 E-ACC-ITEM-FORM。
- **R12-11.5 参数只许是登记键**：参数的值只能是模块组键、表代号、词表族键、状态路径模式、入口名、规则表键、场景代号、迁移行键（`sym_exists` 从卷十一的迁移行取旧入口符号）。出现文件名单、实例 id、行号，即 E-ACC-ITEM-PARAM。条目要查的文件集合由 `accScope` 从这些键展开。
- **R12-11.6 阶段与关口**：每条条目写明从哪个阶段起必过、在哪些关口执行。卷一 §11.2（依赖图）的波号是写卷顺序，不是迁移依赖序（李白 11-13 裁定），不得拿来当阶段。写不出阶段的，按卷十一 R11-7.1 的派生口径取：该条目所守对象（入口、表、系统登记项）最早接入的那张卡的阶段号；连这个也定不出的，退回来源卷补写（E-ACC-ITEM-FORM）。门禁自身的条目（本卷 §3.4 的 S12-*，以及守门禁设施的 A12-*）为阶段 0。
- **R12-11.7 状态机**：

```text
registered ──► implemented ──► in_core ──► retired
```

  `registered` 到 `implemented`：实现文件已在，且 §4.13 里属于它类别的用例全过。`implemented` 到 `in_core`：它在当前主干上为 `pass`，或者它是 `le_baseline` 且基线已登记。`retired`：它的定义处已从来源卷删除。没有别的转移。
- **R12-11.8 判据只写在定义处**：登记表里没有判据文字。判据要改，改定义卷；登记行只跟着改代号与参数。
- **R12-11.9 没有编号的由本卷给**：来源卷写明"代号由卷十二分配"或条目没有编号的，登记器按该卷正文里的先后给序号（解析正文编号的这一步是文稿类检测器 `doc_struct` 的执行，属 R12-2.9 的闭集），写成"S 加卷代号加序号"或"A 加卷代号加节号加序号"，并回报来源卷在收尾时写回正文（C12-5）。写回之前，登记行的 `localNo` 用正文里现有的记号。
- **R12-11.10 后交的卷**：一卷封卷或改版，重跑登记器。已 `in_core` 的条目若定义处没变，登记行不变。
- **R12-11.11 条目不得悄悄降级**：转录只按条数对账，拦不住把条目填成更松的期望、更晚的阶段或更少的关口。所以登记行的 `expect`、`stage`、`gates` 三项，首次登记之后的任何改动都按判据修订处理（R12-14.3）：该类别判据版本号加一，过两轮审查，并列为人工审查项，审查记录逐条答"与定义处是否一致"；没有对应修订记录的改动即 E-ACC-ITEM-DOWNGRADE（S12-16）。首次登记时这三项同样列为人工审查项，逐条对照定义处。

#### 4.11.4 交互

各领域卷给条目；卷一 §12 给总纲各条（也各登记一行）；卷十一 §4.3 的卡在验收判据里只写条目键（卷十一 R11-3.8），键在本表里查不到即那一卷的 E-MIG-ACCEPT-FORM。

#### 4.11.5 数据实例

- 【西陲】卷五的一条扫描条写的是"规则表不得以实体 id 作键"：登记为扫描式、数据核对、检测器 `data_shape`、期望 `zero`，参数是规则表的范围键。条目里没有任何地点的名字。
- 【非西陲】卷十写的"互换判据与换序测试"：互换登记为不变量式加场景推进，换序登记为模板 `det_order` 加参数。
- 【超自然】卷七的一条不变量式里写着"卷十二固定种子场景"：登记时场景代号填本卷场景表里的一行，容差键归卷七；键没填，条目是 `blocked`。
- 【非人类】卷四、卷二十一写明"扫描代号由卷十二分配"的各条：按 R12-11.9 给序号，登记行的原编号暂用正文里的记号。

#### 4.11.6 验收断言

- 扫描式：A12-11.1 S12-3、S12-4 计数为 0；E-ACC-ITEM-PARAM 为 0。
- 不变量式：A12-11.2 条目键全表唯一；把各卷的读入次序任意打乱，登记表逐字节相同；每条条目的定义处都能在来源卷找到同一个编号。
- 扩展性式：A12-11.3 新交一卷的条目（按 R12-11.1 的格式），只重跑登记器，登记表多出该卷的行，其余各行不变；其中用到现有检测器与模板的条目不需要新写任何代码。

### 4.12 文稿扫描

#### 4.12.1 维度

文稿类扫描类别（§2.4 第二张表）；检测器 `doc_struct`、`doc_candidate`；逐行清单行里 `nodeKind` 的三个文稿取值（§2.6）；关口 `seal`。

#### 4.12.2 统一入口

执行经 `accRun`，关口取 `seal`；读结果经 `accHits(filter)`。

#### 4.12.3 规则

- **R12-12.1 对象与地位**：文稿扫描查的是全书设计文稿本身，在写卷阶段用。它属离线工具组，可以读文稿的文字；它的产出是候选位置，是否真是问题由人判。它不进运行时，不决定世界里任何行为。它属 R12-2.9 闭集的第一类（李白 11-13 裁定 Q12-3：按类别登记，只离线、不进运行时、只出候选位置或结构结果、不判世界逻辑）；"程序不读自然语言"管的是程序判定世界逻辑。
- **R12-12.2 类别登记**：每个文稿类别登记一行（§2.4），写明同类定义的出处。扫描器按类别代号取检测器，没有按卷名的分支；"某卷正在改，单独分桶"、"跳过某几卷"、"为某一卷专写一个同类脚本"这几种做法都不保留，现有按卷分桶或按卷专写的脚本收编时去掉分桶、并进对应类别（§7 的 M12-12）。
- **R12-12.3 排除区是结构，全书一份**：哪些区域不查（附录、迁移清单、开放问题、修订记录、自检输出等），按标题层级登记成一份排除区定义，各文稿类别共用。它按结构判，不按卷、不按行。
- **R12-12.4 命中只有两条出路**：一处命中，要么改文稿使它不再命中（包括按判据要求把理由写进正文，例如写明除数的正下界），要么按 §4.14 改准判据。不设"已判不属同类"的名单。
- **R12-12.5 封卷关口**：一卷封卷，要求全部已登记的文稿类别在该卷上的未处置命中为 0（E-ACC-DOC-SEAL）。扫描命中必须在该卷收卷前同一批改完，不准收卷之后再局部重开。
- **R12-12.6 同类清查通则**：审查发现一个真问题，先写出它的同类定义（什么结构算同一类），登记成一个文稿类别并实现检测器，全书扫一遍，命中在各卷收卷前同批改完。只改被点到的那一处不算处理完。
- **R12-12.7 封卷后再现同类**：已封卷的卷又扫出同类，先停下报李白，查判据为什么漏；不自动按勘误处理。
- **R12-12.8 漏报**：人工发现扫描器该报没报的位置，把它做成 `must_fail` 用例加进用例集，补齐判据后全书重扫。全书重扫的漏报为 0 是封卷的前提。
- **R12-12.9 命中在别卷**：扫描某类时命中落在别的卷，转交那一卷的作者；不代改别卷。
- **R12-12.10 依赖未落稿定义的卷**：一卷依赖的共用定义还没落稿，在该定义落稿、本卷改为引用之前，不得封卷。
- **R12-12.11 自检与验算脚本收编**：各卷的自检脚本里通用的各项（章节齐全、六小节、三式断言、无实例 id、台账概念写全、编号连续不悬空）抽成通用的 `doc_struct` 条目，按卷参数化；各卷特有的算术验算登记为 `calc_check` 条目，验算不得调用被验的实现（卷十一 R11-6.4）。收编的时点见 Q12-9。
- **R12-12.12 文稿扫描同样确定**：同一批文稿两次扫描，逐行清单逐字节相同；输出格式与代码扫描的报告相同。

#### 4.12.4 交互

《写卷须知》规定每卷交稿前跑自检与全书检查；《审卷须知》规定文稿的两轮审查；全书概念台账给"每个概念只在一处写全"的依据；各卷作者接收转交的命中。

#### 4.12.5 数据实例

- 【西陲】某卷一条市场规则写了按总量摊分而没写总量为 0 时怎么办：`doc_divisor` 报出；作者在正文补上总量为 0 时不做摊分的分支，重扫不再命中。
- 【非西陲】某卷写着远方聚落的某个量"只经这一个入口变化"，同卷另有一个可修正维度能作用到它，又没有加载校验把守：`doc_backdoor` 报出候选。
- 【非人类】物种行里一个以扩展标度存的量，误差界只算了逐拍推进这一个写入入口，漏了另一个写入入口：`doc_err_bound` 报出候选。
- 【超自然】神迹的效果写目标维度，在两卷的写者表里各登记了一个改写写者：`doc_dual_write` 报出；两卷作者按台账的归属定一个，另一卷改为引用。

#### 4.12.6 验收断言

- 扫描式：A12-12.1 已封卷各卷的 E-ACC-DOC-SEAL 为 0；文稿类检测器的输入里按卷、按行列出的排除项数为 0（S12-6）。
- 不变量式：A12-12.2 同一批文稿两次扫描结果逐字节相同；任一卷封卷时，全部已登记文稿类别在它上面的未处置命中为 0；用例集里文稿类的 `must_fail` 全部报出。
- 扩展性式：A12-12.3 登记一个新的文稿类别并加上它的检测器，不改执行器，它在下一次封卷关口对全部卷生效；新写的一卷不需要任何专门配置就被全部文稿类别覆盖。

### 4.13 绕法用例集

#### 4.13.1 维度

绕法用例行（§2.9）；`case_polarity`（§2.1）；`tests/accept/bypass/` 下的片段文件。

#### 4.13.2 统一入口

读 `accCases(filter)`；写者是登记器；回归经 `accRun` 在提交关口执行。

#### 4.13.3 规则

- **R12-13.1 归本卷所有**：针对各类判据的规避写法用例库归本卷（全书概念台账 §2.1（内核与机制）正表"绕法用例集、验收扫描代号、两轮审查与门禁"一行，定义方卷十二）。卷一、卷二不再维护用例清单；卷二 §2.8 表里的代表性正反例是首批种子，照录进用例集，不在本卷正文重列。
- **R12-13.2 一例一片段**：每个用例是一个代码片段（文稿类是一段文稿片段），配一个极性与应报的错误码。`must_fail` 的片段必须被报出且码相符；`must_pass` 的片段必须不被报。
- **R12-13.3 两种极性都要有**：每个扫描类别至少各有一个 `must_fail` 与一个 `must_pass`。只有反例没有正例的类别，查不出"全都报"这种坏扫描器。
- **R12-13.4 按模块组放置**：同一个片段在不同模块组里结论可以不同（某组闭集允许的操作，在规则层就是违例）。用例写明放在哪个组的位置上判；回归时把片段放进该组的临时文件里扫。
- **R12-13.5 新绕法当场入集**：审查、试玩、扫描中每发现一种新的绕法，在同一张卡或同一批修改里加一个 `must_fail` 用例。只修那一处、不加用例，审查打回。
- **R12-13.6 回归**：提交关口对全集回归，任一用例的结果与极性不符即 E-ACC-BYPASS-REGRESSION，拒绝。
- **R12-13.7 用例是类，不是件**：一个用例代表一种写法。片段里用占位的族与条目（夹具词表里的），不用世界数据里的真实条目；用例数不随世界内容增长。
- **R12-13.8 用例只增**：删除用例只有一种情形：它所属的判据在定义卷被废除。判据修订使某个 `must_fail` 不再该报，按 §4.14 处理，不直接删。
- **R12-13.9 各卷的反例收进来**：各卷写明"由卷十二绕法用例集收录"的反例（如卷二十七 §6 列的各条）逐条登记，`origin` 指回原处。
- **R12-13.10 边角与性能**：卷二记给本卷的两件——命中段落在未合成的组合序列中间留下孤立组合符、大量代号作查找目标时的性能——前者登记为显示闸的用例，后者登记为 `bench` 条目。

#### 4.13.4 交互

卷二 §2.8 给首批种子并在本卷提交新用例时核对机制是否覆盖；卷二十七 §6（扩展性测试）的反例、各卷审查记录给新用例；§4.14 在判据修订时用本集做前后对照。

#### 4.13.5 数据实例

- 【西陲】把一个代号拆成两段再拼起来与状态族比较：`must_fail`，类别 `text_judge`，放在规则层判，应报卷二登记的文字匹配码。
- 【非西陲】用带品牌的句柄与同族维度值作相等比较：`must_pass`，放在规则层判，不得报。它防止扫描器把合法写法也拦下。
- 【非人类】对实体 id 取开头几个字符判类别：`must_fail`，类别 `id_parse`。
- 【超自然】在显示闸之外的组里用子串查找比对文字：`must_fail`，类别 `text_judge`，放在入库前守门组判，应报闸组的闭集外操作码；同一片段放在 gate 组的匹配文件位置上是 `must_pass`。

#### 4.13.6 验收断言

- 扫描式：A12-13.1 E-ACC-BYPASS-REGRESSION 为 0；缺任一极性的扫描类别数为 0；用例片段里出现世界数据真实条目的条数为 0。
- 不变量式：A12-13.2 用例集的条数在任意两次相邻合入之间不减少（判据废除除外）；每个 `must_fail` 用例应报的错误码都已登记。
- 扩展性式：A12-13.3 加一个用例只加一个片段文件与一行登记，不改回归程序；新登记一个扫描类别后，没有两种极性的用例它就不能转为 `implemented`。

### 4.14 判据修订与误报处置

#### 4.14.1 维度

判据版本登记（§2.11 的 `criteria.json`：类别代号、版本号、修订记录）；`hit_state` 的 `criterion_revised`（§2.1）；绕法用例的 `addedAtRev`（§2.9）。

#### 4.14.2 统一入口

读 `accHits(filter)`、`accCases(filter)`；写者是登记器。

#### 4.14.3 规则

- **R12-14.1 不设例外名单**：本卷没有任何"这几处不用查"的名单。按文件加行号、按单条行键、按条目名排除命中，一律是 E-ACC-SCAN-NAMELIST。
- **R12-14.2 误报靠改准判据消除**：一处命中经判断不是问题，说明判据把两种结构混成了一种。办法是找出区分它们的结构特征，写进判据。这个特征必须是对一类写法成立的（类型、节点位置、路径模式、登记字段、章节结构），不能是只对这一处成立的。
- **R12-14.3 修订要带两样东西**：一是把这处误报做成 `must_pass` 用例；二是原有全部 `must_fail` 用例仍然报出。两样都满足，修订才能登记，判据版本号加一。检测器的判定逻辑变了而版本号没加，是 E-ACC-CRITERION-UNVERSIONED。
- **R12-14.4 修订前后全量对照**：用旧判据与新判据各对同一内容全量扫一遍，比较两份逐行清单。消失的每一行都必须符合这次修订写明的那个结构特征；有一行不符合，即 E-ACC-CRITERION-LOOSENED，修订不成立。
- **R12-14.5 补漏报同一流程**：判据漏报时反过来做：把漏掉的位置做成 `must_fail` 用例，补判据，全量对照；新出现的每一行都应符合补上的特征。
- **R12-14.6 修订与基线**：判据修订单独成一次提交，其中被查的内容不变。修订后各分量按新判据重数：对基线提交重数出 B0，对当前内容重数出现值，一起登记。重数使数字上升的（补了漏报），照登记，并写进报告；使已锁定分量的 B0 下降的（消了误报），要附 R12-14.4 的对照结果报李白批。只降判定在修订提交上比的是"同一判据版本下"的前后两数。
- **R12-14.7 结构登记不是例外名单**：卷一 §3.2（封闭的排除清单）的各模块组、卷二的各组闭集与豁免文件表、各卷登记的读者与调用者闭集，是判据的输入：它们定义在卷一、卷二与各领域卷，登记在声明表里，每组另有自己的扫描条，是"换一套判据查"，不是"不查"。本条与 R12-14.1 的分界是：成员按结构键登记、增项要过审并改定义卷的，是结构登记；为消掉某一条命中临时加的，是例外名单。
- **R12-14.8 理由写在正文里的类别**：有的类别的判据本身规定了"写明理由即不算命中"（除数下界：写明除数的正下界）。这仍是改对象：理由写进了文稿，扫描器按判据读到了它。理由必须是判据列出的几种形式之一；写一句"此处无需处理"不算。
- **R12-14.9 不为过关改判据**：判据修订的起因只能是发现了误报或漏报的结构。阶段退出、封卷、合入不过时，不得以修订判据来过关；修订提交与靠它过关的提交不得同卡（R12-9.11）。
- **R12-14.10 白名单文件不保留**（卷二附录 D.3 交本卷定）：卷二 S13 所用的白名单文件 `scan-allowlist.json` 不保留。它剩下的 (b)(c) 两项都是结构：(b) 是代号格式正则只许出现的几个内核文件，属卷二 §2.8 kernel 行与 §2.9 豁免表的闭集；(c) 是注释、内核报告文件里的控制台调用、抛错文案、测试夹具，按节点种类与模块组判。两项都并进声明表的结构登记（按 R12-14.7，增项要过审并改卷二），由扫描器读声明表，不另设名单文件；文件名从全书删去随卷二收卷对齐。

#### 4.14.4 交互

各判据的定义卷：判据文字在定义卷，修订要改定义卷并登记版本；§4.13 的用例集提供前后对照的固定样本；卷十一 R11-8.10 规定基线口径的任何放宽都要李白批，R12-14.6 是它在判据修订上的落实。

#### 4.14.5 数据实例

- 【西陲】除数扫描把"按某量分组"这种不含除法的说法报成了命中：修订判据，按句子结构区分分组与相除；这一处做成 `must_pass`；全量对照里消失的行全是同一结构。
- 【非西陲】现有三个文稿脚本带着"逐条看过、判为不属同类"的名单（素材见 §7 的 M12-12）：名单里的每一条都要么归纳成判据里的一个结构特征，要么回到未处置；名单本身删除。
- 【超自然】点名实例扫描把词表里一个恰好以实体前缀开头的族条目报了出来：不是加名单，而是按 R12-1.2 让前缀集合与族前缀集合都取自登记，由卷二的前缀冲突校验保证两者不相交。
- 【非人类】读文字扫描对解构出来的物种维度值报了"归不了因"：按 R12-2.5 这不是误报，办法是改代码写法；不修订判据。

#### 4.14.6 验收断言

- 扫描式：A12-14.1 S12-6、S12-13 计数为 0；E-ACC-CRITERION-LOOSENED 为 0；没有对应 `must_pass` 用例的 `criterion_revised` 命中数为 0。
- 不变量式：A12-14.2 每次判据修订前后，全部 `must_fail` 用例都报出；每个状态为 `criterion_revised` 的命中，在新判据下重扫确实不再命中，且符合该次修订登记的结构特征。
- 扩展性式：A12-14.3 修订一个类别的判据，只改该类别的检测器、加用例、版本号加一；其余类别的逐行清单逐字节不变。

## §6 扩展性测试

1. **加一卷**：新交一卷的条目，只重跑登记器：登记表多出该卷的行，文稿扫描与封卷关口自动覆盖它（A12-11.3、A12-12.3）。
2. **加一张表**：卷二登记新表与前缀，点名实例扫描自动覆盖新前缀；该表到期要有一条扩展性条目（A12-1.3、A12-6.2）。
3. **加一个模块组或改一个闭集**：只改卷二的登记，读文字扫描按新登记判（A12-2.3）。
4. **加一个写者声明项**：多出一个写入归属分量并受只降约束（A12-3.3、A12-8.3）。
5. **加一个规则表键**：经规则入口读不产生命中，直接写进代码即被报（A12-4.3）。
6. **加一条不变量或一条确定性断言**：登记即按期进必过集合；确定性断言指明模板即可执行（A12-5.3、A12-6.3）。
7. **加一个测试台**：登记一行，跨环境条目自动多跑一遍（A12-9.3）。
8. **加一个扫描类别**：登记一行、加一个检测器模块与两种极性的用例，执行器、报告、关口都不改（A12-12.3、A12-13.3）。
9. **修一个判据**：只动该类别的检测器、用例与版本号，别的类别结果不变（A12-14.3）。

九条都不改执行器、登记器与报告生成的代码。其中第 8、9 条要新写或改动检测器模块，这是本卷唯一需要随类别增长而写的代码；检测器之外没有按类别、按卷、按表的分支（S12-5）。
