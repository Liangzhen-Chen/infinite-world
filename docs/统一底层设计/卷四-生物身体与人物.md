## §0 卷首

### 0.1 范围

本卷回答三个问题：世界上的活物是什么（物种）、它的身体怎样决定它能做什么（身体图、能力、属性、年龄、代谢、负重、死亡）、一个具体的人或生灵作为实体由哪些字段构成（人物本体、身份键、角色创建）。

本卷**写全**的概念（全书概念台账 §五 卷四条）：物种 schema；身体部件图、肢体能力 `capability`、`body.*` 的来源；属性词表 `attr`；年龄、寿命与成年年龄；承载能力与负重公式；代谢；死亡结算与尸体产出；身份键与认出；人物本体；角色创建、出身、母语。另有只在本卷内使用的外貌与遗传（§4.5），以及两个供别卷按北极星推产物的身体侧输入：活体可再生产出的可采量（§4.7）、身体能力与属性对制作和劳作的投入量（§4.11）。

本卷**不定义**：清醒、行动能力、死亡谓词（`can`/`awake`/`capacity`/`terminated`（别名 `dead`），定义方卷二 §2.5（状态谓词单点））；状态容器的格式（卷二 §1.11（状态容器））与身体类状态实例的内容（卷二十一 §4.1）；人格取值（卷二十六 §4.1）；价值轴（卷七 §4.25）；技能与职业行（卷十四）；持有种类（卷十八 §4.1）；实体终止协议（台账 N-06，唯一定义在卷二 §2.6（写者与三接口）：`terminate` 五步、三种后继方式、E-TERM-RESIDUE；本卷只登记个体的终止条件与尸体产出，§4.8）；当前活动代号（卷九 §4.1）。这些在本卷只出现引用句。

### 0.5 读法

先读 §0.6 的十一条结论，再读 §2 的三张表；实现 `body.*` 的人读 §4.2 与 §4.11；做迁移卡的人读 §7（其中 §7.3 是睡眠类文字判断的逐行处置）。各子系统小节顺序固定：维度、统一入口、规则、交互、数据实例、验收断言。数据实例里的 id 与数值都是示例，校验状态一律 `vstat_placeholder`，真值由内容管线填。

### 0.6 本卷的十一条结论

1. **一张物种表**。人、家畜、野兽、怪物、精怪、傀儡都是 `species` 表的行；品种与变体是 `extends` 另一行的行，不是新表也不是新字段。
2. **身体是结构，不是血量**。身体 = 部件图 × 组织比例 × 材料。本卷不提供生命值存量；伤落在部位上，以状态实例表示。
3. **`body.*` 的来源恰有五项，顺序固定**（§4.11）：结构基值、部位折算项、能力依赖项、登记的修正项、管线钳位。前四项都以修正项的形式进入卷二 §3.3（求值管线）的唯一管线，没有第二条求值路。
4. **本卷不写任何谓词**。清醒、能否行动、死没死，一律由卷二 §2.5（状态谓词单点） 用本卷给出的 `body.*` 值与状态族字段算。本卷只保证这些值对每个有身体的主体都算得出来。
5. **属性是开放词表**，条目自带字段（是否身体类、是否隐藏、遗传率、随龄曲线）；规则读字段，不点名任何一项属性。
6. **年龄一律相对化**。阶段、成长、风险、生育都以"年龄 ÷ 成熟龄"或"年龄 ÷ 寿命"为自变量，一张阶段表、一组曲线服务所有物种；生活水准是曲线的输入。
7. **遗传只有一条律**。凡声明可遗传的维度（外貌轴、属性、成年体重）用同一个式子从双亲与物种分布得出。基础值只在生成时产生一次；后天的成长与漂移一律是修正项，不改基础值。
8. **负重公式只此一处**。承载者可以是个体，也可以是载具；"负重→速度、体力"两条曲线全书共用。
9. **死亡单入口，收尾全走实体终止协议**。`die` 只做"身死"（第一段：写入终止类状态实例、发死亡事件）并判断何时发起终止；"终止"（第二段）就是调用卷二 §2.6（写者与三接口）的 `terminate`，五步收尾、后继方式、残留校验都是协议的，本卷不另写。有有效复生点的主体在窗口期内停在第一段。尸体与本卷的全部清理都在协议的后继步骤内、写终止标记之前完成；终止之后本卷不再写该个体的任何东西。尸体是一件由身体算出重量与材料构成的物品。
10. **身份键是不透明的整数键**。认出只比较键、外貌键与两个数值，不比较名字文字。外貌键是由结构化代号与档号拼成的元组，逐项比较，不是哈希。
11. **玩家不是特例**。玩家角色与任何个体走同一张表、同一个实例化例程；创建只是把一部分"采样"换成"选择"。

## §1 领域总述

### 1.1 真实世界怎样运转

1. **物种是一组可遗传的参数**。体型、寿命、成熟期、食性、感官、栖地、繁殖方式在物种内围绕均值分布，在物种间差几个数量级；差别主要是数值，不是结构。
2. **身体是分工的部件**。每个部件承担若干功能（支撑、抓握、看、呼吸、泵血），功能的丧失与部件的损坏成比例；有的部件一失即死，有的失去只是残疾。功能之间有依赖：血泵不动，意识很快消失。
3. **身体由组织构成，组织是材料**。皮、肉、骨、甲壳各有密度与强度；活着时它们决定抗打击能力，死后它们就是皮料、肉、骨料。把组织换成石头或金属，同一套结构就是石像与铁人。
4. **尺度律**。代谢率约按体重的四分之三次方增长，力量约按三分之二次方增长，所以小动物吃得相对多、扛得相对多，大动物相反。
5. **生命是一条相对时间轴**。幼年、成长、成年、衰老的比例在物种间相近；背景死亡风险呈两头高中间低的形状，并随生活水准整体升降；生育率在成年后一段窗口内最高，也随生活水准变化。
6. **子女像父母，但向群体均值回归**。可遗传的数量性状 = 群体均值 + 遗传率 ×（双亲均值 − 群体均值）+ 随机余量。
7. **负重降低速度、加快疲劳**，超过某个比例就走不动。
8. **死亡是一个事件，不是一个字段**。它留下一具由身体决定的尸体，触发继承、职位出缺、祭葬与传闻；在有复生手段的世界里，死亡与"法律上的终结"之间可以有间隔。
9. **人被认出靠的是外貌与旁人已有的认识**，不是名字本身。同一个人可以有多个身份；旁人把两个身份连起来需要证据。

**判死（本卷单点，别处只指回这里）**。"这个主体是否已死"只有一种问法：调用卷二 §2.5（状态谓词单点）的谓词 `terminated(subject)`（别名 `dead`）。它由 action-capacity.mjs 提供，读的是终止协议的结果；判据写在卷二，本卷不复述、不另写等价判断。包括 death.mjs 在内，本卷没有任何模块为了判死去读 status_family 条目的 `terminal` 字段、去数终止类状态实例或直接读 `state.terminated`（P-5 (b) 不为判死开豁免）。"已身死、还没被终止"（复生窗口期）不是判死，是 death.mjs 自己的簿记：有 `deaths.<主体>` 记录即是（§4.8 D-2、D-6）。牵连清单：§0.1；§3.5 P-5；§4.8.1；§4.8.3 D-2；§5.2 卷二 §2.5（状态谓词单点）行；§5.4 回填；§7.3 Z1；§7.5 lifecycle-state.mjs 行；§7.7 Y1、Y3；§8 Q-10。

## §4 子系统

### 4.1 物种统一 schema

#### 4.1.1 维度

§2.1 全表。组件类：有心智的物种挂 comp_sapient，家畜挂 comp_livestock（两者在卷二 §1.8（组件）已登记）；怪物专属的组件类与其 `requires` 由卷十六 §4.1 登记，取值填在同一张表的行上。物种行不含任何显示文字；名称、描述、图鉴文字在语言包。

#### 4.1.2 统一入口

读：`speciesView`。遍历：经 kernel 的行枚举按组件类、`taxon` 上位链或维度条件过滤，不按 id 前缀或名称。写：物种行是静态数据，运行期只有程序生成怪物（卷十六 §4.11）经内容加载器写入表的 `generated` 节，走同一校验器（卷一 R-7）；规则层无写者。

#### 4.1.3 规则

- **S-1 拼装**。物种行的有效值 = 自身值 → `extends` 展平 → 类别行（按 `taxon` 对应类别的深度优先）→ 派生。物种行不写任何可由身体图、组织材料或别的维度算出的量。
- **S-2 变体即行**。品种、亚种、巨型、驯化型、觉醒型都是 `extends` 原种并用相对或比例写法改动若干维度的行（卷二 §1.3（行、继承与取值顺序）的 `~`、`*`、`+`、`-`）。不存在"变体"字段，也不存在以原种 id 为条件的规则。
- **S-3 派生量**。`meanMassKg` = `bodyMassKg` 分布的均值；`bodyDensity` = `wsum(身体图.tissueFractions 经 tissues 映射到材料, material, density)`；`bodyVolumeL` = `meanMassKg ÷ bodyDensity`；`sizeClass` 用卷三 §4.2 的尺寸档规则表对 `bodyVolumeL` 查档。四者都是表头 `derived`，手填即错。
- **S-4 能力基线**。`capabilityBaseline[c]` = 身体图各部位对 c 的贡献之和（0 或 1）。规则判断"这种生物会不会飞、有没有手"只读它与 `gaits`，不读分类。
- **S-5 无实体**。`tissues` 为显式空映射的物种没有质量构成：不产生尸体（§4.8），`bodyDensity` 不适用。是否受物理伤害由卷十三据 `damageResist` 与六轴判，本卷不设"灵体"布尔。
- **S-6 同表同权**。任何以物种为输入的规则对表内每一行都必须可求值；某维度对某行不适用时按卷二 §1.6（缺失处置）的三态处理，不得用"是不是怪物""是不是人"分支。

#### 4.1.6 验收断言

- 扫描式：server-plugin 规则层内不存在任何物种行 id 的字面量；不存在对名称、图鉴文字或 id 前缀的读取来判定物种或类别（现 remote-generation.mjs 的两处归零）。
- 扫描式：全仓只有一个物种数据源与一个加载器；旧 `monsters.json` 与旧 `species` 数组不被任何模块读取。
- 不变量式：对表内每一行，`speciesView` 的全部 always 维度 `known:true`；`sapient` 与组件类一致；`tissues` 键集与身体图组织键集一致；`dietShares` 之和为 1。
- 不变量式：任取两行 A、B 且 B `extends` A，展平后 B 的每个未改写维度与 A 逐位相等。
- 扩展性式：新增一行物种（引用已有身体图与材料），不改任何 .mjs，即可被生成、遭遇、驯养、战斗、屠宰、移动各规则求值，各自的夹具断言通过（卷二 V-6 口径）。

### 4.2 身体部件图与肢体能力

#### 4.2.1 维度

§2.2 全表；`capability`、`body_part`、`tissue` 三族（§2.4）。首批身体图由内容管线给出，数量不设上限；首批能力见卷末代号表，与卷二 §3.6（`body.<capability>`）所列一致，新增能力 = 加一个族条目与表头一项。

#### 4.2.2 统一入口

读：`bodyView(engine, state, subjectId)`，全书唯一能给出 `body.*` 的地方。写：身体图是静态数据；主体的部位完好度没有直接写者，只能通过 status.mjs 写入或移除挂部位的状态实例来改变。

#### 4.2.3 规则

- **B-1 结构基值**。主体 s 的能力 c 的基值 `base_c` = 其物种身体图中各部位 `contributes[c]` 之和。只取决于身体图，不随伤病变化。
- **B-2 部位完好度**。`partIntegrity[p]` 的基值恒为 1。对它的修正只有一个来源：挂在部位 p 上的状态实例（实例的 `bodyPart` = p），其当前档 `modifiers` 中以 `body_plan.partIntegrity` 为目标的修正项。数据侧这类修正项不写子键；`bodyView` 收集主体的状态实例时，用实例的 `bodyPart` 补成 `body_plan.partIntegrity[p]` 再送入管线。行级 `bodyPart` 为空的容器不得含此目标（E-BODY-INTEGRITY-TARGET）。**来源 id 逐实例不同**：这类修正项的 `source` 取 `{kind: 状态, id: (状态行, 部位, 实例的 since) 组成的复合键, via: 状态行}`。卷二 §3.3（求值管线）按 `(source.id, target, subject)` 去重，所以同一状态行落在两个部位、或同一部位先后受的两处伤，各是各的来源，不会被合成一条。status.mjs 对同一主体不产生 `(状态行, 部位, since)` 三项全同的两个实例（同刻同处的再次受伤并入已有实例的严重度；提请卷二确认，§5.4）。
- **B-3 丧失与传播**。部位 p 的有效完好度 `eff(p)`：若 p 或其任一祖先的 `partIntegrity ≤ rules.body.integrity.lostBelow`，取 0（部位丧失，子部位随之丧失）；否则取 `partIntegrity[p]`。上游的部分损伤不向下传播。
- **B-4 部位折算项**。对每个部位 p 与每个 `contributes[p][c] > 0` 的能力 c，`bodyView` 生成一条修正项：目标 `body.c`，阶段 `add`，值 `−contributes[p][c] × (1 − eff(p))`，`source = {kind: 身体图, id: (身体图行, 部位 p) 组成的复合键, via: 部位 p}`。**每个部位用各自的来源 id**：左手与右手对同一能力的两条折算项来源不同，管线去重时互不合并，扣减量相加。它们与其他修正项一起进入管线。
- **B-5 能力依赖项**。按 capability 族 `limitedBy` 的拓扑序求值；对能力 c 的每个限制者 k（权重 w），生成一条修正项：目标 `body.c`，阶段 `mul`，值 `−w × (1 − v_k ÷ base_k)`，`unpenalized`，`source = {kind: 能力依赖, id: (能力 c, 限制者 k) 组成的复合键, via: 限制者 k}`，其中 `v_k` 是 k 已求出的最终值。只对 `base_k > 0` 的限制者生成：身体图上本来就没有的能力不构成限制（没有肺的生物不因"不呼吸"而失去意识）。
- **B-5a 合成项与卷二"来源"的对齐**。B-4、B-5 的项不存放在任何地方，由 `bodyView` 每次求值时现场合成，属于卷二 §3.2（修正项的格式）所列"来源五处"之外的第六种：**读入口在求值时合成的派生项**。它们遵守同一格式，只有三点特别，一并提请卷二接收（§5.4、§8 Q-4）：(a) `source.id` 是上述复合键（由代号句柄组成的元组，按分量逐项比较与排序），不是单个行 id；(b) 只带算好的数值 `value`，不带 `valueRX`，所以"`valueRX` 只能读基值"的约束对它们不适用；数值由 `bodyView` 按拓扑序先算出（B-4 读部位的有效完好度，B-5 读限制者的最终值）再交给管线；(c) 不登记进 `state.modifiers`，没有写者，依赖声明见 §4.11 C-6。E-BODY-CAP-CYCLE 保证拓扑序存在。
- **B-6 登记的修正项**。以 `body.c` 为目标、对主体适用的全部修正项：整体状态实例的档（睡眠、醉、病、痛、药效）、生命阶段行（§4.4）、装备与义肢、效果族输出、物种或品种行。它们的内容不归本卷，本卷只保证它们被收集。
- **B-7 求值**。`v_c = modified(base_c, B-4 ∪ B-5 ∪ B-6)`，即卷二 §3.3（求值管线）的九步管线，钳位到 [0, 1]。`bodyView().dims[c]` 的 `base` 是 B-1 的值，`value` 是 `v_c`，`chain` 可由 `explain` 逐条复算。没有任何能力值在管线之外被改写。
- **B-8 致命部位**。某个 `vital` 部位的 `eff` 变为 0 时，本卷的反应规则调用 `die`（§4.8），`cause` 取 `rules.death.vitalLossCause`（verb 族句柄），`source` 取造成该部位折损最大的状态实例所属的状态行（并列取代号字典序最小者）。其余致死途径（状态严重度到达致死值、背景死亡）分别由卷二十一与 §4.4 调同一个 `die`。
- **B-9 部位的质量与材料**。部位质量 = 主体 `massKg × sizeFraction`；部位某组织的材料 = `tissueOverride` 中该组织的值，缺则取 `species.tissues`；组织层序读 `tissue.depthOrder`。卷十三选命中部位的权重 = `sizeFraction × [eff > 0]`。
- **B-10 部位合法性**。运行态状态实例的 `bodyPart` 必须是主体当前身体图中的一个具体部位，或为空（整体状态），否则写入被拒（E-BODY-PART-TARGET）。容器行上允许的 `any`（卷二 §1.11（状态容器））只是"施加时再定部位"的记号，**不得进入运行态实例**：由施加方在写入前定成具体部位（卷十三按 B-9 的命中权重选，卷二十一按其病程规则选）。主体物种变更时未能对应的挂部位实例如何处置见 §8 Q-5。

- 扫描式：capability、body_part、tissue 三族的条目代号在 .mjs 中出现次数为 0。
- 不变量式：对任意主体与任意状态实例集合，`0 ≤ v_c ≤ 1`；撤销全部状态实例后 `v_c = base_c`；`explain` 逐条复算与结果严格相等。
- 不变量式：部位 p 丧失 ⇒ 其全部后代的 `eff` 为 0；`vital` 部位丧失 ⇒ 同一推进步内主体出现终止类状态实例。

- 扩展性式：新增一张身体图（含一项新能力条目），不改 .mjs；以它为身体的物种在 `bodyView` 下各能力可求值，丧失承担新能力的部位后该能力下降而其余不变。

### 4.3 属性（身体 / 精神）

#### 4.3.1 维度

`attr` 族（§2.4）；`species.attributesBase`、`person.attributes`、`person.attrMod`（§2.1、§2.3）；`rules.attr.*`（§2.5）。"属性"一词在全书专指本族（台账 S-16），表字段称"维度"。

#### 4.3.2 统一入口

读：`personView().dims.attributes[k]`（修正后）与 `.attrMod[k]`；物种分布读 `speciesView`。写：个体属性的基础值只在 `instantiatePerson` 内产生一次（采样或遗传），这是该维度唯一的写入点，此后任何模块都不再写它。后天的成长（训练、历练）是卷十四 §4.12 登记的修正项：以 `person.attributes[k]` 为目标，需要持久的部分存运行态 `state.modifiers`（唯一写者 modifier.mjs，卷二 §3.2（修正项的格式）），来源记为卷十四的成长记录。卷十四不是本维度的写者，一个字段只有一个写者。读到的 `attributes[k]` 是基础值经管线叠加后的有效值。

#### 4.3.3 规则

- **A-1 基值**。个体属性 k 的基值：有不少于 `rules.heredity.minParents` 个已知亲本时按 §4.5 的遗传律，否则由 `species.attributesBase[k]` 按卷二 §1.10（随机实例化）的种子键采样。
- **A-2 随龄**。加载器为 attr 族的每个条目生成一条修正项：目标 `person.attributes[k]`，阶段 `mul`，值由该条目 `agingCurve` 指向的曲线对主体 `relAge` 查得再减 1，`unpenalized`，条件为主体物种 `ageless` 为假。身体类与精神类衰退的早晚只体现在各条目指向的曲线不同。
- **A-3 修正与钳位**。属性是修正键，受卷二 §3.3（求值管线） 管线与 `rules.attr.bounds` 钳位；状态、装备、信条等对属性的影响都是登记的修正项。
- **A-4 修正值**。`attrMod[k] = lookup(rules.attr.modCurve, attributes[k])`，读修正后的属性。检定与产出不直接用属性值：属性一侧用 `attrMod`，身体能力一侧用动作行、配方行、技能行所声明能力的投入系数，两者由 §4.11 C-7 的 `workInputs` 一并给出。
- **A-5 隐藏**。`hidden` 为真的属性不进入面板投影与创建分配；这是显示与输入的约束，规则求值不区分。
- **A-6 规则不点名属性**。任何公式需要"某一项属性"时，由规则表或数据行给出属性代号（如 `rules.body.carry.attr`、技能行的主属性），代码里没有属性字面量。

#### 4.3.4 交互

卷九 §4.3（检定读 `attrMod` 与 `workInputs`）；卷十三 §4.1（攻防读属性）；卷十四 §4.3/§4.12（技能行声明主属性与能力权重；成长是登记的修正项，不写基础值）；卷三 §4.8（配方产率与品质读 `workInputs`）；卷二十一（状态档以属性为修正目标）；卷二十九（面板按 `hidden` 过滤）。

### 4.4 年龄、成长、寿命、出生与死亡率

#### 4.4.1 维度

`species` 的 `lifespanYears / maturityYears / gestationDays / litterSize / birthIntervalDays / ageless / sexes / crossbreeds`；`person` 的 `birthMinute / ageYears / relMaturity / lifespanYears / relAge / lifeStage / adult / adultMassKg / massKg / sex`；`life_stage`、`sex` 两族；`rules.life.*`。**成年年龄 `adultAge` = `species.maturityYears`**，是物种维度；`age` 作为叙述声明的 predicate 代号（卷零 §3.5.6）指 `person.ageYears`。

#### 4.4.2 统一入口

读：`personView().dims`；群体层 `vitalRates(engine, speciesId, {relAge, relMaturity, living}) → {deathPerYear, birthPerBearerPerYear}`（纯函数，供卷八 §4.16 的统计层按年龄档调用；两项都是 Fact；`living` 由卷六定义，未知时的处置见 §0.2，不以任何常数代替）。写：`lifeTick`（§3.3），每日一次，属推进阶段 `body`。

#### 4.4.3 规则

- **L-1 阶段**。阶段表每行只有两个数值下界。`lifeStage` = 表中满足 `relMaturity ≥ relMaturityMin 且 relAge ≥ relAgeMin` 的最后一行的 `stage`。阶段表对所有物种是同一张。未成年各行只用 `relMaturityMin`（`relAgeMin` 为 0）；成年各行的 `relMaturityMin` 都是 1，彼此只靠 `relAgeMin` 区分，所以老年行的条件就是"已成年且相对年龄达到某值"。这些都是逐行的数值检查（E-LIFE-STAGES），校验器不需要理解任何表达式。再加上物种行的 E-SPECIES-MATURITY（成熟龄小于寿命下限乘以最小的老年下界），任何个体在 `relMaturity` 到 1 的那一刻 `relAge` 必小于老年下界，一定先进入第一个成年行，不会跳过。`adult` 读阶段条目字段。阶段行的 `modifiers` 是登记的修正项（如幼体的操作与移动能力折减），经 §4.2 B-6 生效。
- **L-2 成长**。`massKg = adultMassKg × lookup(rules.life.growthCurve, relMaturity)`。体型随年龄连续变化，没有按阶段写死的体重。
- **L-3 背景死亡率**。年率 `h = (lookup(earlyHazard, relMaturity) + [非 ageless] × lookup(senescenceHazard, relAge)) × lookup(hazardByLiving, living)`。`living` 是主体所在家户的生活水准，由卷六定义，本卷只引用；未知时的处置以卷六为准（§0.2），不以任何常数代替。本曲线只含**未被单独建模的死因**；疾病、饥渴、伤、刑由各自的状态与规则致死，标定时须从曲线中扣除。
- **L-4 个体判定**。`lifeTick` 对每个在个体层模拟的活体取日概率 `h ÷ 每年日数`（线性折算，上限 1），用骰值键（主体、日序、用途代号）取均匀数，命中则调 `die`，`cause` 为 `rules.life.naturalCause`。离屏与统计层的主体不逐个判定，由卷二十七的分层与卷八 §4.16 用 `vitalRates` 处理。
- **L-5 生育力**。可育的前提：`lifeStage` 条目 `fertile` 为真、`sex` 条目 `bears` 为真、距 `life.<person>.lastBirthMinute` 不少于 `birthIntervalDays`（无此记录视为满足）、`conceptions.<person>` 不存在。每日受孕机会 = `lookup(fertilityCurve, relAge) × lookup(fertilityByLiving, living) ÷ birthIntervalDays`。`living` 未知时与 L-3 同样处置（以卷六为准，§0.2），不以任何常数代替。谁与谁可能生育（配偶、亲密关系、畜群配种）由卷十八、卷二十五给出候选对；本卷只在双方同物种，或一方物种行的 `crossbreeds` 含对方时给出非零机会，子代物种分别取同种或 `crossbreeds` 的值。
- **L-6 妊娠与分娩**。受孕时做两件事：经 status.mjs 写入 `rules.life.gestationStatus` 所指状态行的实例（容器行归卷二十一，§8 Q-2）；写 `conceptions.<生母> = {otherParent, offspringSpecies, sinceMinute}`，把另一亲本与按 L-5 定下的子代物种记住（状态实例的结构里放不下这两项）。妊娠时长 = 子代物种行的 `gestationDays`，从 `sinceMinute` 起算。期满 `lifeTick` 按子代物种的 `litterSize` 采样胎数，对每个子代调 `instantiatePerson`（物种取记录里的 `offspringSpecies`；亲本取生母与记录里的 `otherParent`，后者此时已不存在或未知则按单亲处理），然后移除妊娠实例、删除该记录、写 `life.<生母>.lastBirthMinute`，并发出生事件。出生地 = 从生母当时所在地点起沿包含树向上，第一个挂 `rules.life.birthplaceClass` 所指组件类的地点；一直到根都没有（野外出生的兽类）时取生母所在地点本身。生母在妊娠期间死亡并被终止时，记录随之删除，不分娩。
- **L-7 成年的用途**。本卷只给出 `adult` 与 `adultAge` 两个量。法定行为能力的年龄线（缔约、婚配、任职）由法典条目以 `relMaturity` 或 `ageYears` 为输入规定（卷八b §4.4）；未成年人不得进入亲密主题这一规则的数值半边 = `adult` 为假（卷零 §3.5 population:407 行），文字半边在两道闸。

#### 4.4.4 交互

- 扫描式：规则层 .mjs 中，年龄量与数字字面量的比较次数为 0。"年龄量"按数据流定：`personView().dims` 的 `ageYears`、`relAge`、`relMaturity` 三个键的读取结果，以及旧函数 `personAge`、`npcAgeAt`、`actionAge`、`lifeAge` 的返回值（迁移期间仍在时）；它们作为比较运算的一个操作数、另一个操作数是数字字面量即命中。年龄线只能来自规则表或法典条目的键。现有基线见 §7.7 第 2 组。
- 扫描式：`rules.life.*` 各键的 kernel 读取调用只出现在 life.mjs 与 person.mjs；`life_stage`、`sex` 两族的条目代号在 .mjs 中为 0。
- 不变量式：对任意通过校验的物种行与任意采样到的个体寿命，年龄从 0 增大时 `lifeStage` 在阶段表里的行号单调不减，且经过第一个成年行（不跳过）；`massKg` 单调不减且在 `relMaturity ≥ 1` 后等于 `adultMassKg`。
- 不变量式：同一物种、同一 `living`、同一年龄档，个体层逐日判定的年死亡期望与 `vitalRates` 的 `deathPerYear` 的相对差不超过 `rules.tolerance.vitalRateRel`（同一组曲线两种求值）。
- 不变量式：任一主体的 `conceptions` 记录存在 ⇔ 它身上有妊娠状态实例；分娩后两者同时消失且 `lastBirthMinute` 等于分娩时刻。
- 不变量式：同种子同输入重跑，`lifeTick` 的全部判定逐位相同。
- 扩展性式：新增一个寿命与成熟龄相差两个数量级的物种行，不改 .mjs 与规则表，其个体的阶段、成长、背景死亡、生育均可求值。

### 4.5 外貌与遗传

#### 4.5.1 维度

`trait` 族（§2.4）；`species.traitsBase`；`person.traits`、`person.adultMassKg`、`person.lookKey`；`rules.heredity.*`、`rules.identity.lookQuantum`。可遗传的维度 = `person.traits[t]`、`person.attributes[k]` 的基础值、`person.adultMassKg`。三者的遗传率与余量系数各有定义处：外貌轴在 trait 条目，属性在 attr 条目，成年体重在 `rules.heredity.massHeritability / massResidualFactor`（§2.5）；三处同受 E-HEREDITY-FACTOR 校验。外貌的**描述词**只存在于语言包，按（轴代号，档号）取，规则层不可见。

#### 4.5.2 统一入口

读：`personView().dims.traits / lookKey`。写：只在 `instantiatePerson` 内产生；之后外貌轴的改变（伤疤、染发、易容）不改基值，而是修正项或身份键上的外貌键（§4.9）。

#### 4.5.3 规则

- **H-1 遗传律（唯一）**。可遗传维度 x，物种分布均值 μ、遗传率 h²、余量系数 r：`x_child = μ + h² × (mid − μ) + r × (draw − μ)`，其中 `mid` 是已知亲本该维度**基值**的平均，`draw` 是按子代种子键从物种分布采的一个值。亲本不足 `rules.heredity.minParents` 时 `x = draw`。`r² = 1 − h⁴ ÷ 2`（E-HEREDITY-FACTOR），使群体方差代际不漂移。
- **H-2 杂交**。子代物种按 §4.4 L-5 确定后，μ 与分布取子代物种行；亲本基值先按各自物种分布标准化到子代分布再求平均。
- **H-3 只传基础值**。`mid` 用的是亲本偏离行里存的先天基础值。因为成长、衰老、伤、病、装备一律是修正项而从不改写基础值（§4.3.2、§4.10 P-1），基础值与后天变化在存储上本来就是分开的，`mid` 直接读基础值即可，不需要再"排除"什么。
- **H-4 外貌键**。`lookKey` 是一个 `struct:lookKey` 元组（§2.6）：`{species, sex, lifeStage, bands}`，前三项是代号句柄，`bands` 是各 `visible` 外貌轴（按族内登记序）的量化档号，档号 = 把该轴值域 [−1, 1] 等分为 `rules.identity.lookQuantum` 份后轴值所在的序号。**不做任何哈希**（全书只有存档摘要一种哈希，规则层不读）。两个外貌键相等 ⇔ 四项逐项相等，所以它是无损的：不同的（物种、性别、阶段、档号序列）必得不同的键，不存在碰撞；外貌相近到每条轴都同档才同键。它是"看上去是不是同一个人"的可比较量。
- **H-5 显示**。档号 = 把轴值域等分为该条目 `bands` 份所得的序号；语言包以（轴，档号）给词。显示层读档号，规则层不读词。

#### 4.5.4 交互

卷二十五 §4.5（育种：畜群选育读、写亲本，遗传律同一条）；§4.9（外貌键）；卷二十九（描述词）；卷十（奠基者采样的种子键）；卷七（文化对外貌的偏好属评价行，不改本节）。

#### 4.5.6 验收断言

- 扫描式：个体状态内无外貌文字字段；规则层无对语言包外貌词的读取；`trait` 族条目代号在 .mjs 中为 0。
- 不变量式：按 `rules.tolerance.heredityDrift` 给定的群体规模与代数，对随机婚配的封闭群体做模拟，各可遗传维度末代的群体均值与物种分布均值之差不超过 `meanInSd` 个物种标准差，方差与物种分布方差的相对差不超过 `varianceRel`（方差不塌缩、不发散）。
- 不变量式：`lookKey` 是单射编码——两个个体的键相等，当且仅当物种、性别、生命阶段相同且每条可见轴的档号相同；任一输入变化到跨档时键必变，未跨档时键不变。
- 扫描式：外貌键的构造与比较路径（person.mjs、identity.mjs）不 import 任何摘要或哈希函数；全仓对哈希函数的 import 只出现在存档摘要模块（卷二 §2.9（外部边界与 Text 模型）口径）。
- 扩展性式：`trait` 族新增一条目并在某物种 `traitsBase` 补一键，不改 .mjs，该轴即被采样、遗传、计入外貌键并在显示层出词。

### 4.6 步态、移动、负重

#### 4.6.1 维度

`species.speedBase / gaits / carryMult`；`person.loadCapacityKg / moveSpeed / massKg`；`gait` 族；`rules.body.carry`。承载的定名为 `loadCapacity`（台账 S-28），与容积、栖地容量、人口承载力不同义。

#### 4.6.2 统一入口

- `loadOf(engine, state, carrierId) → {carriedKg, loadCapacityKg, ratio, speedFactor, staminaFactor}`（各项为 Fact）。
- `moveSpeedOf(engine, state, subjectId, gaitId) → Fact m_per_minute`。

两者是全书唯一给出"负重→速度、体力"的地方（台账 X-13）；卷十七把它的结果乘以路况系数合成行程，不另写负重公式。`loadOf` 的 `carrierId` 可以是个体，也可以是载具物品实例。`moveSpeedOf` **只接受个体**：载具自己没有步态与身体，它的行进速度（牵引者是谁、多头牵引取谁、车体的速度上限）归卷十七 §4.2；卷十七对牵引的个体调本入口取速度，对载具调 `loadOf` 取 `speedFactor`，再按它自己的规则合成。对非个体调 `moveSpeedOf` 返回 `known:false`。

#### 4.6.3 规则

- **M-1 所负之重**。`carriedKg` = 承载者经持有边携带、穿戴、驮载的全部物品 `massKg`（卷三 §4.2）之和，加骑乘或搭载其上的个体的 `massKg` 与他们各自的 `carriedKg`。未知重量的物品按 `gap` 处置并使结果标缺口，不当 0。
- **M-2 承载能力**。个体：`loadCapacityKg = lookup(carry.allometry, massKg) × species.carryMult × lookup(carry.attrCurve, attributes[carry.attr]) × body[carry.cap 的 dimKey]`，再经修正管线。载具等非个体承载者：取 `carry.capacitySource` 按承载者实体类给出的那个维度的值。
- **M-3 负重比与两条曲线**。`ratio = carriedKg ÷ loadCapacityKg`；`speedFactor = lookup(carry.speedCurve, ratio)`；`staminaFactor = lookup(carry.staminaCurve, ratio)`。两条曲线对一切承载者相同；速度曲线在某一比值处降到 0 即"走不动"，没有另设的超载布尔。
- **M-4 移动方式**。个体会不会某种移动方式 = `species.gaits` 有无该键。`moveSpeed[g] = species.speedBase × gaits[g] × body[gait g 的 drivenBy 的 dimKey] × speedFactor`，再经修正管线。断腿影响由行走能力驱动的方式，折翼影响由飞行能力驱动的方式，各不相干。
- **M-5 体力消耗**。单位时间体力消耗倍率 = `gait.exertion × staminaFactor`，交给卷二十一的身体需要与卷十七的行程结算；本卷不保存体力值。
- **M-6 共担**。多人合抬、牲畜分担是把同一批货物分配到多个承载者后各自求 M-2、M-3，分配规则归卷十七 §4.8。

#### 4.6.4 交互

卷十七 §4.1/§4.8（调两个入口，乘路况）；卷五 §4.10（路况系数；路段允许的移动方式集合由边结构给）；卷三 §4.2（物品重量）、卷十七 §4.2（载具承载维度）；卷六 §4.6（商队只读）；卷二十一 §4.4（体力消耗倍率）；卷十三（战斗内移动读 `moveSpeed`）。

- 扫描式：对规则表键 `rules.body.carry.*` 的 kernel 读取调用只出现在 load.mjs；对维度键 `species.speedBase`、`species.gaits`、`species.carryMult` 的读取只出现在 load.mjs 与 species.mjs。卷十七、卷六的模块对这些键的读取边数为 0，只能 import `loadOf`、`moveSpeedOf`。无模块直接 import 平衡表（§3.5 P-4）。

### 4.7 代谢

#### 4.7.1 维度

`species.metabolismMult / sleepHoursPerDay / diet / dietShares`；`person.dailyFoodNeed / dailyWaterNeed / dailySleepNeed`；阶段行的 `foodFactor / sleepFactor`；`diet` 族的 `feeds`；`rules.body.metabolism`；活体产出一侧是 `species.renewables`、`renewable` 族与运行态 `renewables.*`。本卷只给**需要的速率**、**能吃什么**与**身上积存了多少可采的材料**；需要未满足的累积、缺乏症与后果是身体需要 `bodyNeed`（卷二十一 §4.4），食物的营养值在材料与物品上（卷三 §4.1）。

#### 4.7.2 统一入口

读：

- `personView().dims` 的三个率；`edibleBy(engine, speciesId, itemId) → Fact boolean`。
- `groupNeeds(engine, state, {members: list<个体 id>} | {speciesId, count, stageMix: map<life_stage, fraction> nullable}) → {food, water, sleep}`（各项为 Fact）：群体需要的唯一求和入口（T-5），供卷二十五、卷六、卷十三、卷八 §4.16 调用。
- `renewableOf(engine, state, {subjectId, renewableId} | {speciesId, renewableId, massKg, days}) → {material: ref material, availableKg: Fact kg}`：活体身上此刻积存的可采量（T-7）。第二种写法供未个体化的畜群按物种均值估算。

写：`takeRenewable`（§3.3），采收方在产物入库的同一事务内调用。代谢三率无写者。

#### 4.7.3 规则

- **T-1 能量**。静息日需 `dailyFoodNeed = lookup(metabolism.energyCurve, massKg) × species.metabolismMult × 阶段行.foodFactor`，再经修正管线。曲线按体重的四分之三次方标定，一条曲线服务所有物种。
- **T-2 活动**。劳作、行军、战斗对能量与饮水的加成不是本式的项，而是登记的修正项：动作目录的行（卷九 §4.1）与 §4.6 M-5 的体力倍率以 `person.dailyFoodNeed`、`person.dailyWaterNeed` 为目标给出修正；冷热的影响由环境状态（卷二十）同样给出。
- **T-3 饮水与睡眠**。`dailyWaterNeed = lookup(metabolism.waterCurve, massKg) × species.metabolismMult`；`dailySleepNeed = species.sleepHoursPerDay × 阶段行.sleepFactor`；均经修正管线。
- **T-4 可食**。`edibleBy` 为真 ⇔ 物品的类别集合（沿上位链展开）与该物种 `diet` 各条目 `feeds` 的并集相交。放牧、投喂、觅食、偷食都问这一个函数，不读食性的名称。
- **T-5 聚合**。群体（畜群、聚落统计层、军队、商队）的需要只经 `groupNeeds` 算：成员已个体化时 = 成员各率之和；未个体化时 = 头数 × 该物种按分布均值体重算出的率，给了 `stageMix` 就按各阶段行的 `foodFactor / sleepFactor` 加权。多个物种的群体由调用方按物种分别调用后相加。不得把不同物种的头数相加后乘同一个人均数。求和用卷二 §3.3（求值管线）的定点加法，同一批成员逐个求再相加与一次求和严格相等。
- **T-6 零代谢**。`metabolismMult = 0` 的物种三率恒为 0；卷二十一的需要容器对率为 0 的主体不累积。不为"不吃饭的东西"写分支。
- **T-7 活体可采量（身体侧）**。物种行的 `renewables` 只说生理速率。个体 s 的某项产出 r 此刻积存的可采量：`availableKg = ratePerKgPerDay × massKg × body[该条目 harvestCap 的 dimKey] × min(storeDays, 自 renewables.<s>.<r>.sinceMinute 起经过的日数)`；条目没有 `harvestCap` 时不乘能力项；`when` 不成立（例如未到可育阶段、不是怀胎一方）时为 0；没有 `sinceMinute` 记录时从出生时刻起算。体重、能力值取采收当时的值。这个量只由世界时刻与个体维度算出，不逐日累加，所以一次推进多日与分段推进得到同一个数。材料 = 该项的 `material`。
- **T-8 采收（三要素齐全）**。活体产出变成什么物品、得多少，不在本卷，也不在物种行，由采收方的配方或采收动作推出（卷三 §4.8 的配方管线；畜牧上的编排在卷二十五 §4.5）：**材料** = `renewableOf` 给出的材料及其属性（卷三 §4.1）；**技能** = 饲养者或采收者的技能（卷十四）与身体投入（§4.11 C-7 的 `workInputs`），决定采得比例与品质；**意图** = 所选的配方或采收动作，决定同一份材料出成哪类物品、要不要采。采得比例记为 f（0 到 1），采收方把 f × `availableKg` 的产物经账本入库，并在同一事务内调 `takeRenewable(subject, r, f)`。
- **T-9 采走之后**。`takeRenewable` 把积存起点改为 `此刻 − (1 − f) × 已积存日数`（已积存日数 = T-7 式中 `min(...)` 的值）：全采走就从此刻重新积存，采一半就留下一半。不采不会无限积存，上限是 `storeDays`。物种行没有该项、或 `when` 不成立时调用被拒。产出与采收都不凭空造物：入库的质量恒等于 f × `availableKg`，由卷三的守恒校验核对。

#### 4.7.4 交互

卷二十一 §4.4（读三率，定义缺乏阈值与后果）；卷二十五 §4.5（饲料需求 = T-5；放牧可食 = T-4；挤、剪、拾、割等采收的编排，调 `renewableOf` 与 `takeRenewable`）；卷三 §4.1/§4.8（活体产出的材料属性；按材料、技能、意图出物品的配方管线）；卷十四（采收所用技能行，及其声明的能力与属性权重）；卷六 §4.12（家户口粮预算调 `groupNeeds`）；卷九 §4.1（动作行的消耗修正）；卷二十（环境状态的修正）；卷十三 §4.9（军粮）。

#### 4.7.6 验收断言

- 扫描式：对规则表键 `rules.body.metabolism.*` 的 kernel 读取调用只出现在 person.mjs；对维度键 `species.metabolismMult`、`species.sleepHoursPerDay`、`species.renewables` 的读取只出现在 person.mjs、life.mjs 与 species.mjs。别的模块要群体需要只能 import `groupNeeds`，要单个主体的率只能经 `personView`：import 图上，`person.dailyFoodNeed`、`dailyWaterNeed`、`dailySleepNeed` 三个维度键的读取方若不在这两条路上即违规。
- 扫描式：无对食性名称或描述的匹配（现 husbandry.mjs:45 归零，由 §3.5 P-8 覆盖）；`diet`、`renewable` 两族条目代号在 .mjs 中为 0；物种数据行中不出现物品 id（校验器对 `renewables` 的值只接受 `ref material`）。
- 不变量式：同物种同阶段，`massKg` 增大时 `dailyFoodNeed` 单调不减而 `dailyFoodNeed ÷ massKg` 单调不增。
- 不变量式：`groupNeeds({members})` 与逐成员读 `personView` 的三率后用定点加法求和，结果严格相等。
- 不变量式：`availableKg` 不超过 `ratePerKgPerDay × massKg × storeDays`；一次推进 N 日后读到的可采量，与分 N 次各推进一日后读到的严格相等；`takeRenewable(f)` 之后立即再读，可采量等于采前的 `(1 − f)` 倍（定点截断意义下）。
- 扩展性式：给某物种行加一项 `renewables`（引用已有材料），不改 .mjs，该物种个体即有可采量，卷三按材料匹配的已有配方即可对它出产物。
- 扩展性式：新增一种食性条目与一个只吃该食性的物种行，不改 .mjs，投喂、放牧、觅食规则对它求值正确。

### 4.8 死亡结算、尸体、复生点

#### 4.8.1 维度

本节没有自己的表，也没有自己的收尾流程：个体的终止直接用卷二 §2.6（写者与三接口）的实体终止协议（`terminate` 五步、三种后继方式 `inherit / liquidate / wreck`、不变量 E-TERM-RESIDUE）。本卷在这件事上只登记两样东西：**终止条件**（D-3）与**尸体产出**（D-4）。

- 规则表 `rules.death`；运行态 `deaths.*`、`revivals.*`（§2.6）。
- **尸体**是 `item` 表的实例，组件类由 `rules.death.corpseClass` 指向（新登记，`requires` = `massKg`、`material` 与本卷新增的实例维度 `ofSpecies: ref species`、`ofPerson: ref person nullable`、`diedMinute: integer`）。
- **复生点**是一种持有边。哪些持有种类算复生点不由规则表点名：本卷向持有种类表（卷十八 §4.1）登记一个维度 `revival: struct{windowDays: integer, cooldownDays: integer, cost: struct{resource, amountRX}, effects: list<effectCall>, clearFamilies: set<ref vocab status_family>} nullable`，该维度非空的种类行就是复生类种类。窗口期、冷却、费用、后果、复生时清掉哪些状态族，都是每一行自己的值。
- **后继方式**不由本卷的代码决定：协议第 2 步读个体所属类别行的 `termination` 字段（卷二 §5.0（公共字段））。本卷只负责在数据上填它：挂有心智组件类的类别行填 `{mode: inherit, successorRX: 卷十八 §4.2 给出的继承人表达式}`；其余生灵的类别行不填，取协议缺省 `wreck`。
- 生死本身不是字段。判"是否已死"一律调用卷二 §2.5（状态谓词单点）的 `terminated(subject)`（别名 `dead`），本节不另写判据（§3.2）。"已身死、尚未终止"由 `deaths.<主体>` 记录标识，这是 death.mjs 自己的簿记。

#### 4.8.2 统一入口

写：`die`、`revive`、`deathSweep`（§3.3），全在 death.mjs。`die` 是全书致死的唯一入口，`revive` 是复生的唯一入口；以个体为对象调用 `terminate` 的只有 death.mjs。读：`carcassOf(engine, state, {subjectId} | {speciesId, massKg}) → {massKg, material: map<ref material, fraction>}`。

#### 4.8.3 规则

- **D-1 单入口**。任何致死途径（致命部位丧失、状态严重度到达致死值、背景死亡、处决、献祭、效果族输出）最终都调 `die(subject, {cause, source})`。`cause` 是 verb 族句柄，与协议 `terminate` 的 `cause` 同型，原样传下去；`source` 可空，是致死的状态行或事件类型行的代号，只作记录（写进终止类实例的 `source` 字段与死亡事件载荷）。`die` 之外没有任何代码发起对终止类状态实例的写入。
- **D-2 第一段：身死**（本卷做，不属于协议）。依次：`terminated(主体)` 为真（卷二 §2.5（状态谓词单点），§3.2），或已有 `deaths.<主体>` 记录（已身死、尚未终止），则无操作返回，这一步不读 `terminal` 字段；经 status.mjs 写入 `rules.death.terminalStatus` 所指状态行的实例；写 `deaths.<主体> = {diedMinute, cause, expiresMinute}`，`expiresMinute` = 身死时刻加上主体当前各有效复生点边所属种类行 `windowDays` 的最大值，一条有效边都没有时就等于身死时刻；发死亡事件，载荷只有代号与数值（主体、`cause`、`source`、地点、时刻、`expiresMinute`）。第一段不生成尸体，不转移任何持有、账户与义务：主体仍是一个实体，只是身上有终止类实例，`can`/`awake` 对它一律为否。随后在同一事务内按 D-3 检查一次。
- **D-3 终止条件**（本卷向协议登记的内容）。对每个有 `deaths` 记录的个体，下列任一成立，death.mjs 即调 `terminate(state, 主体, 记录里的 cause)`：
  - (a) 世界时刻 ≥ `expiresMinute`。没有复生点的主体在 `die` 的同一事务内就满足；有复生点的主体由 `deathSweep` 在每个日界扫描 `deaths.*` 时发现。
  - (b) 主体已没有任何有效的复生点边。`deathSweep` 订阅持有边终止事件：某条复生点边被撤销或到期时，对其持有者重算，仍有别的有效边则把 `expiresMinute` 重算为余下各边窗口的最大值，一条不剩则在同一推进步内终止。
  到期与否只比较世界时刻，不看本次推进请求有多长：一次推进 N 日与分段推进合计 N 日，终止落在同一个世界日。
- **D-3a 第二段：终止 = 协议的五步**。本卷不写其中任何一步，只说明各步在个体身上是什么：第 1 步写终止标记；第 2 步按类别行的 `termination` 定后继（有心智者的继承人、其余生灵的残骸）；第 3 步账户分流，打捞比例是资源种类与材料的维度；第 4 步持有边转移或解除（随身物、职位、义务都在这里随各持有种类行的转移协议走）；第 5 步清掉状态实例（含本卷写的终止类实例）与以它为来源的修正项，发 `entity_terminated {id, cause, mode, successorId}`。继承人解析、遗产分配、职位出缺、义务承继由协议与订阅方（卷十八、卷八、卷六）完成。**本卷在第二段里自己做的只有尸体产出（D-4）与本卷簿记的清理，两者都由协议在后继步骤内触发**：本卷把 `settleBody` 登记为个体类的清理函数，协议定出后继（第 2 步）之后、写终止标记之前，在同一事务内调用它。此时个体尚未被标记，状态实例也还在，`carcassOf` 可以直接算，不需要预存。`settleBody` 做三件事：按 D-4 产出尸体；删除 `deaths`、`presenting`、`revivals`、`conceptions`、`life`、`renewables` 下以该个体为键的路径；给它的各身份键填 `until`。**终止标记写下之后，本卷没有任何对该个体的写入**，也不靠订阅 `entity_terminated` 做清理（卷二的拒写规则，E-TERM-RESIDUE）。协议各步的编号以卷二为准；"标记在后继步骤的清理之后"这一顺序列入 §5.4 回填。
- **D-4 尸体产出**。在 `settleBody` 内（协议后继步骤内、标记之前）：`mode` 为 `wreck` 的，协议第 2 步原地生成的那个残骸实体**就是**尸体，本卷不另造，只经物品写者给 `successorId` 所指实体补上 `rules.death.corpseClass` 所指组件类与其 `requires` 各维度；`mode` 为 `inherit` 或 `liquidate` 的，协议没有生成残骸，本卷经物品写者在个体终止时所在地点新建一件尸体物品。两种情形都恰好一具，不会出现残骸与尸体两份遗骸。`carcassOf` 的质量 = 主体 `massKg ×` 参与部位的 `sizeFraction` 之和（`rules.death.lostPartsExcluded` 为真时不计已丧失部位）；材料构成 = 参与部位按大小加权的 Σ `tissueFractions[t]`，归到各组织对应的材料（§4.2 B-9）。物种无实体（§4.1 S-5）时 `carcass` 为空：不新建尸体，`wreck` 模式下的残骸实体不补尸体组件类。尸体的腐坏、可燃、价值、可否入药完全由其材料经卷三的规则得出。
- **D-5 屠宰与收获的输入**。卷二十五 §4.7 以尸体物品（或对未个体化畜群调 `carcassOf({speciesId, massKg})`）为输入，按材料、技能、工具出产物；出什么由材料与配方决定，不由物种 id 决定。尸体上的 `ofSpecies` 供禁食禁屠、亵渎类规则读其物种的 `sapient` 等维度。
- **D-6 复生**。`revive(subject, edgeId)`，下面的 `revival` 指该边所属持有种类行的同名维度。前置：主体有 `deaths` 记录（已身死、尚未终止）；`edgeId` 是主体持有的一条有效复生点边；世界时刻小于身死时刻加 `revival.windowDays`；距 `revivals.<主体>.lastMinute` 不少于 `revival.cooldownDays`（无记录视为满足）；`revival.cost` 能经账本从主体付给该边的对方（提供复生的场所或组织）。执行：付费；经 status.mjs 移除终止类实例与 `revival.clearFamilies` 各族的实例；删除 `deaths` 记录；写 `revivals.<主体>.lastMinute`；经卷十七的位置写入口把主体移到该边所指地点（入口名待卷十七成稿，§8 Q-16；本卷不直接写位置字段）；施加 `revival.effects`（效果族调用）；发复生事件。身死期间主体的随身物、账户、义务原样未动，所以复生后无须归还，现场也没有尸体留下。此规则对任何持有复生点边的个体成立，没有玩家专用路径。
- **D-7 订阅方**。亡魂是否产生（卷十五 §4.10）、丧葬与祭祀（卷七）、传闻（卷二十二）、凶案立案（卷八b）订阅死亡事件；继承、出缺一类订阅 `entity_terminated`。未葬判定：窗口期内读身死个体所在地点，终止后读尸体物品是否仍在、位于何处。
- **D-8 范围**。组织解散、建筑损毁、载具损毁不经本节，直接走终止协议。

#### 4.8.4 交互

卷二 §2.6（写者与三接口）（`terminate` 与 `entity_terminated`；本卷是个体终止的唯一发起方，并登记后继步骤内的清理函数 `settleBody`）、卷二 §1.11（状态容器）（status.mjs 写者）；卷十八 §4.1/§4.2（持有种类表的 `revival` 维度；各种类行的转移协议；继承人表达式）；卷二十五 §4.7（屠宰）；卷三 §4.1/§4.12（尸体材料、腐坏、打捞比例维度）；卷十五 §4.10（亡者）；卷十九 §4.12（提供复生服务的场所，以效果族建立持有边，收取费用）；卷十七（复生后的位置写入口）；卷二十（日界）；卷二十四 §4.2（死亡、复生事件类型行）。

#### 4.8.6 验收断言

- 扫描式（调用图）：以 `rules.death.terminalStatus` 所指状态行为参数调 status.mjs 写入导出的调用点只在 death.mjs 的 `die`；移除终止类实例的调用点只有 death.mjs 的 `revive` 与 kernel/terminate.mjs 的第 5 步；实参为个体的 `terminate` 调用点只在 death.mjs。death.mjs 不 import 持有写者，对账本的调用只有 `revive` 付费一处：继承、分流、转移的代码不在本卷。
- 扫描式：无任何模块比较表示生死的文字（现 transition.mjs、holdings.mjs、revival.mjs 的相关行归零，§7.1；判据是 §3.5 P-8）；`die`、`revive` 的实现内无个体单例 id 的比较；打捞比例不出现在调用参数中。
- 不变量式：`die` 幂等；第一段前后全世界各资源账户余额与持有边集合逐项不变。
- 不变量式（触发）：没有复生点边的主体，身死与终止在同一事务；有复生点边的主体，世界时刻越过 `expiresMinute` 后的第一个日界处理完毕时必已终止，处于"有终止类实例而未终止"的时长不超过其各边 `windowDays` 的最大值加一日；最后一条有效复生点边终止的那个推进步结束时必已终止。一次推进 N 日与分段推进合计 N 日，终止落在同一世界日，存档摘要相同。
- 不变量式（协议对接）：个体终止的事务提交后 E-TERM-RESIDUE 成立；`deaths` 记录不存在；有实体的个体恰有一件 `ofPerson` 指向它的尸体物品，`wreck` 模式下这件物品就是协议定出的 `successorId`；`state.terminated` 写入之后，写集里没有任何以该个体为键的路径（本卷的清理全部发生在标记之前）；尸体质量 ≤ 主体死时 `massKg`，材料份额之和为 1。
- 不变量式：已终止的主体不可 `revive`；`revive` 成功后主体无终止类实例、无 `deaths` 记录，账本上恰有一笔等于该边种类行 `revival.cost` 的转移，世界上没有 `ofPerson` 指向它的尸体。
- 扩展性式：新增一个组织全为某种金属的物种行，不改 .mjs，其个体死后尸体即为该金属构成的物品，并可被熔炼配方（按材料匹配）接受。
- 扩展性式：新增一行复生类持有种类（另一组窗口期、冷却、费用、后果），不改 .mjs，不改 `rules.death`，持有该种边的个体即按新参数停留与复生。

### 4.9 身份键、化名、认出

#### 4.9.1 维度

`identity` 族（§2.4）；运行态 `identities.<person>.*` 的 `struct:identityKey` 与 `presenting.<person>`（§2.6）；`person.identityKeys`（种类集合，派生）；`person.lookKey`（`struct:lookKey` 元组）；`rules.identity`。键号 `keyId` 是全世界唯一的整数，对规则不透明：不能从键号推出个体。

#### 4.9.2 统一入口

- 读：`identitiesOf(engine, state, subjectId, {at}) → list<identityKey>`；`presentedKey(engine, state, subjectId) → keyId`；`identify(engine, state, observerId, subjectId) → keyId`。
- 写：`assumeIdentity(engine, state, subjectId, {kind, lookKey, maskQuality})`、`dropIdentity(engine, state, keyId)`、`presentIdentity(engine, state, subjectId, keyId)`，唯一写者 identity.mjs。化名的名字经命名槽入库（卷二 §1.9（代号、显示名与语言边界）的玩家命名路径）或由生成名段给出。

#### 4.9.3 规则

- **K-1 本名键**。每个个体在实例化时得到恰一个 `legal` 为真的键，终身有效（E-IDENTITY-LEGAL）。其余键按需建立与终止。
- **K-2 示人键**。`presentedKey` = `presenting.<主体>` 所记的键号；没有这条记录时 = 本名键。`presentIdentity(subject, keyId)` 把它改成主体任一当前有效的键，包括改回本名键；`assumeIdentity` 建立新键时同时把它设为示人键；`dropIdentity` 终止的若正是示人键，记录删除，回到本名键。所以长期并存多个身份的人（如持法号的僧人）可以随时以俗名示人，不必先丢掉别的键。示人键的选择不看 `since`。
- **K-3 当前外貌**。示人键自带 `lookKey` 时取它（易容、面具、变形后的样子），否则取个体的 `person.lookKey`。
- **K-4 认出**。`identify(observer, subject)`：观察者即主体时返回本名键。否则在主体的全部键中，取观察者**已知**（卷二十二 §4.1 的知情查询，按键号）且满足下列任一条件者：(a) 就是示人键；(b) 观察者持有把它与示人键连起来的"同属一人"事实（取传递闭包；事实的获得与撤销归卷二十二）；(c) 它的外貌键与当前外貌逐项相等（§4.5 H-4），且观察者对它的熟悉度减去示人键的 `maskQuality` 不低于 `rules.identity.familiarityFloor`（熟悉度是卷二十二给出的数值）。有多个时返回 `since` 最大者；一个都没有时返回示人键本身。**任何情况下不因系统知道真相而返回被隐藏的键。**
- **K-5 按键记事**。知情、记忆、传闻、名望、通缉、好恶的对象一律是键号；同一个体的两个键在旁人那里是两个人，直到有人获得连结事实。
- **K-6 不产生第二个经济实体**。账户、持有、义务始终挂在个体上；以某键缔约时义务记录另存 `asKey`，对手方看到的当事人是 `identify` 的结果。追偿与继承按个体，是否追得到取决于有没有连结事实（卷八b）。
- **K-7 名字不参与判定**。键的名字只是显示；重名、同名查人比较生成名段或键号（卷二 §1.9（代号、显示名与语言边界））。把玩家输入的称呼解析成个体只发生在输入边的候选集内（卷九 §4.19），规则层收到的已是键号或个体 id。

#### 4.9.4 交互

卷二十二 §4.1（知情按键号存；连结事实；熟悉度）；卷九 §4.19（称呼→候选编号；现 engine.resolve 的名字解析迁至输入边）；卷八b §4.9（通缉对象是键）；卷十八 §4.7（名望挂键）；卷十六 §4.9（夜生物的潜藏身份 = 一个 `concealing` 键加一个不同的外貌键）；卷十五（变形术给示人键写外貌键）；卷二十九（显示名拼装）。

#### 4.9.6 验收断言

- 扫描式：身份键结构与 `identities.*` 路径内无任何字符串字段；规则层无名字文字的比较与包含判断；`identity` 族条目代号在 .mjs 中为 0。
- 扫描式：名字→个体的解析函数只存在于输入边模块组。
- 不变量式：任一时刻每个个体恰有一个有效的本名键；键号全局唯一且不复用；`identify` 是纯函数。
- 不变量式（不泄密）：观察者不是主体本人、对主体的各键没有任何连结事实、且 K-4 的条件 (c) 对主体的每个非示人键都不成立时，`identify(observer, subject)` 严格等于 `presentedKey(subject)`。这是等式断言，对一切种类的被隐藏键（本名键、化名键、潜藏键，不论 `concealing` 取何值）都成立；另以 §4.9.5 的反例夹具单测一条。
- 不变量式：`presentedKey` 恒为主体当前有效的键之一；`presentIdentity` 指向已终止或不属于该主体的键时被拒。
- 扩展性式：`identity` 族新增一个种类条目（如法号），不改 .mjs，可被建立、示人、切回本名、被认出、被连结。

### 4.10 人物本体与 personView

#### 4.10.1 维度

§2.3 全表。人物本体的字段分三类：**自有维度**（物种、性别、出生、属性、外貌、寿命等，本卷定义）；**别卷定义、挂在本表的维度**（`personality` 卷二十六、`values` 卷七与卷二十六、`skills` 卷十四）；**不存而派生的**（文化、信仰、职业、任职、家户、亲属、年龄、体重、能力）。

#### 4.10.2 统一入口

读：`personView(engine, state, personId)`，全书读取个体的唯一入口；身体、状态、持有、账户分别经它转引 `bodyView`、`statusView`、持有表入口、账本，不在本入口内另算。写：`instantiatePerson`（§3.3），个体偏离行的唯一写入时机。此后没有任何模块再写个体的基础值：属性成长（卷十四）、人格与价值观的漂移（卷二十六）都是以相应维度为目标的修正项，叠加在基础值之上，读到的是有效值（写卷须知补充裁定；卷二 §5.5（个体）维持 `personality`、`values` 为存储维度）。

#### 4.10.3 规则

- **P-1 个体只存不可再算的东西**。偏离行里只有：物种、性别、出生时刻、出生地、出身、经遗传或选择得到而无法由种子重算的基础值。基础值生成时写一次，之后不改。成长与漂移不进偏离行：它们是修正项，需要持久的存 `state.modifiers`（写者 modifier.mjs），来源分别记卷十四、卷二十六的记录。不存：年龄数、体重、能力、职业、文化、名字字串、状态文字、活动文字、生命值。
- **P-2 职业与任职是结构**。`occupation = {professions: set<ref profession>, employments: list<{employer: 实体 id, profession: ref profession nullable}>, offices: set<ref office>, primary: ref profession nullable}`，全部由持有边派生（从业、受雇、任职三类边的种类行在卷十八 §4.1，各带标明其角色的字段）；`primary` 的选取规则归卷十四 §4.1。谁能登记田地、谁能承运、谁算农户，读职业行的维度（卷十四），不拆任何句子。给人看的"某某家的雇工"由投影模板拼。
- **P-3 人格与价值是向量**。`personality`、`values` 是代号到轴值的映射；决斗、犯罪、建国等规则读轴值（卷二十六），本卷只保证字段存在且已采样。
- **P-4 实例化**。`instantiatePerson(spec)`，`spec` 只含代号与数值：物种、出生时刻、出生地为必给；性别、亲本、出身、若干维度的指定值可给。未给的维度按"遗传（有亲本）→ 采样（种子键）"取值；亲属边由调用方经卷十八的写者建立。手写的具名个体、运行期生成的居民、新生儿、玩家角色都走它（卷一 R-7）。
- **P-5 玩家非特例**。玩家角色是 `person` 表的一个单例 id，仅此而已。规则层不得以"是不是玩家"决定取数路径或规则分支；只对玩家生效的东西（面板、存档槽、输入）在显示层与输入边。
- **P-6 视角**。带观察者视角调用时，身份一律以 `identify` 的结果给出，自有维度中不可观察的（真实年龄、隐藏属性、本名键）按卷二十二的主观视图裁剪；裁剪规则不归本卷。
- **P-7 未个体化的居民**。名册中只有计数的居民在首次需要个体时调 `instantiatePerson`，其物种、年龄档、出生地由名册条目给出（卷十）；个体化前后群体统计量不变（卷二十七）。

#### 4.10.4 交互

卷十四 §4.1（职业行、`primary`）；卷二十六 §4.1/§4.2（人格、价值）；卷十八（三类持有边、亲属、家户）；卷七（文化行、语言）；卷十（名册个体化）；卷二十二（主观视图）；卷二十九（面板与称谓模板）；卷二 §2.7（系统声明表）（`npcs`、`created` 等状态键的读者登记）。

#### 4.10.6 验收断言

- 扫描式：除 §5.3 列出的 species.mjs、body.mjs、person.mjs 外，无模块直读个体容器的字段（§3.5 P-1）；无模块以单例 id 分支（P-2）；`personOccupation` 及其四处拆句调用为 0。
- 扫描式：对 `created.<person>.props.*` 的写入调用点只在 person.mjs 的 `instantiatePerson`（经 kernel/dimension-writers）；卷十四、卷二十六的模块对该路径的写入边数为 0。
- 扫描式：个体状态路径的 pathTypes 中没有 `string`，也没有 §3.5 P-7 所列字段。
- 不变量式：对任意个体，`personView` 的全部 always 维度 `known:true`；同种子重建同一个体，全部采样与遗传所得维度逐位相同。
- 不变量式：`occupation` 与持有表一致——任一从业、受雇、任职边的建立或终止后，下一次读取即反映，且不存在独立存放的职业字段。
- 扩展性式：把玩家角色换成另一物种的个体（只改创建选择），不改 .mjs，全部以个体为主体的规则可求值。

### 4.11 行动能力：`body.*` 的来源（只供值，不定义谓词）

#### 4.11.1 维度

身体图表头 `capabilities` 段的各能力维度（§2.2）。卷二 §2.5（状态谓词单点）的三个谓词读其中三项：`body.consciousness`、`body.moving`、`body.manipulation`；阈值表 `rules.capacity` 归卷二，本卷不读、不写、不复述其值。

#### 4.11.2 统一入口

`bodyView(engine, state, subjectId).dims`。这是 `body.*` 的唯一出处；action-capacity.mjs 是它的使用者，不是它的一部分。本卷不在任何文件导出 `can`、`awake`、`capacity` 或同义函数。

另有一个只读入口把身体能力与属性送进制作和劳作（C-7）：`workInputs(engine, state, subjectId, {capabilityWeights: map<ref vocab capability, fraction>, attrWeights: map<ref vocab attr, fraction>}) → {capabilityFactor: Fact fraction, attrTerm: Fact number}`，在 work.mjs。它不是谓词：不回答"能不能做"，只给出"身体让这件事做成几成"。

#### 4.11.3 规则

- **C-1 五项来源，顺序固定**。对每个能力 c：① 结构基值（§4.2 B-1）；② 部位折算项（B-2 至 B-4：挂部位的状态实例 → 部位完好度 → 按贡献折算的 `add` 项）；③ 能力依赖项（B-5：受限于别的能力的 `mul` 项）；④ 登记的修正项（B-6：整体状态档、生命阶段、装备与义肢、效果族输出、物种行）；⑤ 管线钳位（B-7）。②③④ 都是修正项，同入卷二 §3.3（求值管线）的管线；此外没有任何途径能改变 `body.*`。
- **C-2 总有值**。凡有身体图的主体，三项恒 `known:true`。身体图对某项的贡献和为 0 时该项基值为 0（没有手的生物操作能力恒为 0），这是确知的 0，不是未知。
- **C-3 睡眠不在本卷**。睡着、昏迷、濒死、死亡是状态实例；它们让谓词为假，靠的是状态族条目的三个布尔字段（卷二 §1.11（状态容器））与各自档上的 `body.*` 修正。本卷不设"是否睡着"的字段，也不设活动文字。
- **C-4 不属于 `body.*` 的四类限制**，本卷明确不承担，调用方各找其主：(a) 羁押、拘禁对行动种类的限制——持有边及其条款（卷八b §4.12）；(b) 法定行为能力的年龄线——法典条目读 `relMaturity`（卷八b §4.4，§4.4 L-7）；(c) 在途、正忙、作息窗口——当前活动与日程槽上的动作代号（卷九 §4.1）；(d) 是否在场——地点。现 `capacity()` 把 (a)(b) 与身体混在一个函数里，改建时拆开（§7.5）。
- **C-5 可解释**。`bodyView().dims[c].chain` 列出每条生效修正项的来源代号；谓词返回的原因代号由卷二从状态实例 id 或能力代号取，本卷不产出任何文字原因。
- **C-6 依赖声明**。`bodyView` 的依赖 = 个体偏离行、物种与身体图表、`statuses`、`modifiers`、日序（卷二 §2.3（记忆与依赖声明））；状态实例或修正项变化后首次读取即为新值，不设缓存字段。
- **C-7 身体对制作与劳作的投入**（北极星：产物由材料、技能、意图推出，技能要经身体落地）。谓词只是门槛，过了门槛之后身体的好坏还要连续地进入产物，否则少一只手的铁匠与健全人产出相同。接口如下，本卷写定量的出处与取值域，怎样消费归对方卷：
  - **权重由数据行声明**。动作行（卷九 §4.1）、配方行（卷三 §4.8）、技能行与职业行（卷十四 §4.3、§4.1）可带两个字段：`capabilityWeights: map<ref vocab capability, fraction>`（各值 > 0，和为 1；这件事靠哪些身体能力、各占几成）与 `attrWeights: map<ref vocab attr, fraction>`（各值 > 0，和为 1；靠哪些属性）。字段由各表所属卷登记，形状以本条为准。代码里不出现任何能力或属性的代号。
  - **`capabilityFactor`** = Σ `capabilityWeights[c] × body.c 的当前值`，值域 [0, 1]；权重为空映射时恒为 1（这件事不靠身体）。它读的是 `bodyView` 的最终值，伤、病、幼体、义肢、疲劳对产物的影响全部经此一处进入。
  - **`attrTerm`** = Σ `attrWeights[k] × attrMod[k]`，值域同 `rules.attr.modCurve` 的值域；权重为空时为 0。力量、灵巧一类属性经此进入。
  - **谁必须读它**。凡产出的数量、品质或工时取决于人或役畜劳作的规则，都把执行者的 `workInputs` 作为输入之一：卷三 §4.8 的配方管线（产率、品质）、卷十四的技能检定与劳作产出、卷九 §4.3 的检定、卷二十五的采收（§4.7 T-8）、卷十九的工位产出。消费方式（作为修正项进入对方的目标键，或作为检定的加值）由对方卷定，但不得绕过本入口自己拿 `body.*` 或属性去算。
  - 多人协作时对每个执行者各调一次，合成规则归对方卷。
- **C-8 门槛与投入用同一组数**。`can` 的阈值判断与 `capabilityFactor` 读的是同一次 `bodyView` 求值的同一组 `body.*`，不存在两套身体。

#### 4.11.6 验收断言

- 扫描式（import 图与调用图，判据全文见 §3.5 P-5）：`rules.capacity` 各键的读取边、status_family 条目 `terminal / incapacitating / suppressesAwake` 三字段的读取边，起点全部在 action-capacity.mjs，其余模块为 0；`bodyView` 返回的能力值流入比较运算的位置，除 action-capacity.mjs 与 P-5 列出的闭集豁免外为 0。这条不按函数名判，改名、包装、搬家都不改变读取边。
- 扫描式：全仓以 `body.` 开头的修正键字面量只出现在数据文件；.mjs 中除卷二 §2.5（状态谓词单点） 实现读取的三项外为 0。
- 扫描式（模式类别，判据全文见 §3.5 P-8）：规则层 .mjs 中，带非 ASCII 字符的字符串或正则字面量出现在比较、包含、匹配、`switch` 分支位置的次数为 0；对个体与日程槽 `status`、`activity` 文字路径的读取与写入为 0。§7.3、§7.4、§7.7 的行号表是工作清单：迁移完成时这三张表里的每一行都应不再命中上述模式，但验收只认模式命中数，不认行号。
- 不变量式：`capabilityFactor` 在 [0, 1]；身体完好且无修正的主体对任何权重恒为 1；对任一能力 c，`body.c` 下降而其余不变时 `capabilityFactor` 单调不增，降幅 = 权重 × 能力降幅。
- 扩展性式：给一条已有配方行补上 `capabilityWeights`，不改 .mjs；执行者失去一只手后，该配方经卷三管线算出的产率按声明的权重下降，未声明权重的配方不变。
- 不变量式：对任意主体，三项均 `known:true` 且在 [0, 1]；移除某状态实例后，三项的变化量恰等于该实例各修正项在 `explain` 中的贡献。
- 不变量式：两个状态集合相同、身体图相同的主体，三项逐位相同（与物种 id、是否玩家无关）。
- 扩展性式：卷二十一新增一个状态容器行（整体或挂部位），不改 .mjs，其对三项的影响即经本节生效并可被 `explain` 列出。

### 4.12 玩家角色创建、出身、母语

#### 4.12.1 维度

`origin` 族（§2.4）；`person.origin / birthplace / nativeLanguage`；`rules.chargen`；可扮演物种由物种行挂的组件类标明（新登记的可扮演组件类；代码经 `rules.chargen.playableClass` 取它，不写字面量）。

#### 4.12.2 统一入口

写：`createCharacter(engine, state, choices)`，内部调 `instantiatePerson`。读：`chargenOptions(engine, state) → {species, origins, birthplaces(originId), attributeBudget}`，供菜单生成；全部是代号与数值。

#### 4.12.3 规则

- **G-1 选择只有代号与数值**。`choices = {species, sex, origin, birthplace, attributeDeltas: map<attr, integer>, traitBands: map<trait, integer>, ageYears}`。名字经命名槽（卷二 §1.9（代号、显示名与语言边界））；不接受任何自由文字进入规则可读状态。
- **G-2 可选集由数据给出**。物种：挂 `rules.chargen.playableClass` 所指组件类的行。出身：`origin` 族条目。出生地：满足所选出身的 `placeFilter`、且在世界当前开放范围内的地点（开放范围是 place 的维度，卷五）。`placeFilter` 只读 place 的基值维度与 `rules.chargen.placeSets` 下的具名集合，不读别的规则表键。**没有缺省出生地**：未选则返回菜单；不开 AI 时凭菜单可完成创建。
- **G-3 属性分配**。各项基数 = 所选物种该属性分布的均值；`attributeDeltas` 之和 = `rules.chargen.freePoints`，每项在 `perAttr` 区间内；`hidden` 属性不可分配，按采样。结果作为个体的指定值传入 `instantiatePerson`。
- **G-4 文化与母语**。前提读物种维度，不点名物种：物种 `sapient` 为真的个体，文化沿出生地派生（卷二 §5.5（个体）），`nativeLanguage` = 该文化行的语言；`sapient` 为假的个体，`nativeLanguage` 记 gap，本条其余部分不执行（`culture` 是卷二的派生维度，同一前提提请卷二写进它的派生式，§5.4）。实例化时，对技能表中标为语言且语言等于 `nativeLanguage` 的技能行，由 `instantiatePerson` 调卷十四 §4.3 的初始熟练度写入口，传入 `rules.chargen.nativeProficiency`；`skills` 的写者始终只有卷十四，本卷不写该维度。本条在 `instantiatePerson` 里触发，所以一切有心智的个体（不只玩家）都有母语。
- **G-5 出身给予**。`origin.grants` 的效果族调用在创建末尾执行：家当经账本从登记的源转入，身份（家户成员、学徒等）经持有写者建立。来历事件的接入归卷二十四 §4.10。
- **G-6 年龄与外貌**。`ageYears` 须落在成年阶段内，转成 `birthMinute`；`traitBands` 给出各可见外貌轴的档号，取该档中点为基值；未选的轴采样。
- **G-7 同一例程**。创建 = 选择 + `instantiatePerson` + G-5。创建出的角色与同参数生成的居民在规则层不可区分。

#### 4.12.4 交互

卷二十四 §4.10（来历接入）；卷七 §4.20/§4.27（文化、语言）；卷十四 §4.3（语言技能行）；卷五（地点开放范围、`placeFilter` 读的维度）；卷六 §4.1（初始家当的源）；卷十八（初始身份边）；卷二十九 §4.7（创建菜单）；卷二 §1.9（代号、显示名与语言边界）（命名槽）。

#### 4.12.6 验收断言

- 扫描式：chargen.mjs 与 person.mjs 内无任何带表前缀或族前缀的代号字面量（地点、物种、出身、组件类一律来自参数或 `rules.chargen.*`、`rules.life.*` 的键）；这两个模块不 import 文字库（textcore）与语言包，`choices` 与 `spec` 的入参模式里没有字符串类型的字段（名字只经命名槽）。
- 扫描式（调用图）：对 `created.<person>.props.*` 的写入调用点只在 `instantiatePerson`；`instantiatePerson` 的调用方只有 `createCharacter`、`lifeTick` 与 §5.1 登记的使用卷模块。对 `skills` 维度的写入边在本卷模块内为 0。
- 不变量式：对任意个体，`nativeLanguage` 为已知值 ⇔ 其物种 `sapient` 为真且出生地能派生出文化；`sapient` 为假的个体没有任何由 G-4 写入的语言技能。
- 不变量式：以同一组选择创建的玩家角色与以同参数、同种子 `instantiatePerson` 的居民，`personView` 的全部维度逐位相同。
- 不变量式：创建前后各资源账户总量之差恰等于出身给予从源转入的量。
- 扩展性式：`origin` 族新增一个条目、给某物种行挂可扮演组件类，不改 .mjs，菜单即出现该选项并可完成创建。
