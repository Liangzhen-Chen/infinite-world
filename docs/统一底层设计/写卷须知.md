# 写卷须知（第一波起各卷作者共用，11-13）

## 红线
- 本机只允许：静态读文件；git/gh 只读；用 Write/Edit 写文件；先写成文件、再在本机用 node 运行的小核算脚本（放在 F:/dnd-tmp/vols/）。
- 禁止：node -e、python -c、把 heredoc 喂给解释器、跑测试、读密钥、提交 git。
- 模型与档位：起草、修改用 claude-fable-5-2 中档；审查用 claude-opus-5-5 中档。

## 硬规矩（违反任何一条即不合格）
1. 统一底层：
   - 系统内统一维度、统一入口；系统间走统一接口；行为由通用规则从维度推出。
   - 禁止为具体物品、神、地区、职业写专项规则；禁止在规则里出现具体 id。
   - 常数只能放在规则表里。
2. 禁读自然语言：规则层只读数值维度和固定代号。文字只属于显示层，中英双版同等对待。输入边、守门、文字模型一律按卷二 §1.9、§2.7、§2.8、§2.9 执行，各卷不得另立一套。
3. 北极星：产物由材料属性、职业技能、意图三者共同推出。
4. 一个概念只在一处写全：以 `全书概念台账.md` 为准。台账判给本卷的概念，本卷必须写全；判给别卷的，本卷只引用（写明卷、节、入口），不得重写。台账没有的跨卷概念，记进本卷 §8 开放问题，不要自己认领。
5. 不兼容旧存档；规则只保留一版。

## 卷模板（缺一节不收；见 10 号文档 §3.1）
§0 卷首（范围、依赖卷、覆盖的卷零行号、参照的五款游戏行、读法）
§1 领域总述（真实世界怎样运转；本作现状）
§2 维度表（字段、类型、单位、取值域、onUnknown、出处、校验；全部为 ASCII 代号加 labels）
§3 统一入口（view、谓词、唯一写者；退役哪些旧入口；用扫描式写法规定禁止的旁路）
§4 子系统逐节，每个子系统固定 6 小节：维度、统一入口、规则、交互、数据实例、验收断言
   - 数据实例至少 3 条，其中至少 1 条非西陲、至少 1 条非人类或超自然
   - 验收断言至少包括扫描式、不变量式、扩展性式各 1 条
§5 系统间接口总表
§6 扩展性测试
§7 迁移与退役清单（列出 06a/06b 行号，交给卷十一）
§8 开放问题
附 术语与代号表

## 读法（省额度，但不降质量）
- 必读：
  - 本卷素材包 `素材包/卷X-素材.md`；
  - `全书概念台账.md` 中涉及本卷的行，以及第五节“各卷必须定义的概念清单”；
  - 10 号文档 §二 中本卷那一段。
- 卷一、卷二：只读本卷要引用的章节。先用 Grep 查标题定位，再读那一节；不要通读全卷。
- 现有代码：只在核对素材包里列出的 file:line 时读。
- 不要读调研 01–09 的全文；需要原文细节时，按素材包注明的出处小节去读。

## 交稿前
1. 写一个本卷的自检脚本 F:/dnd-tmp/vols/check-卷X.mjs，检查以下各项，并在本机用 node 运行：
   - §0–§8 齐全；
   - 每个子系统的 6 小节齐全；
   - 正文没有具体 id 字面量，也没有用于判断的中文或英文描述性文本；
   - 台账判给本卷的概念都已写全。
2. 把脚本输出贴在卷末附录。
3. 把成稿复制到 `版本快照/卷X-v1.md`。
