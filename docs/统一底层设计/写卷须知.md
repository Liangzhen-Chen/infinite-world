## 红线
- 本机只允许：静态读文件；git/gh 只读；用 Write/Edit 写文件；先写成文件、再在本机用 node 运行的小核算脚本（放在 F:/dnd-tmp/vols/）。

- 模型与档位：起草、修改用 claude-fable-5-2 中档；审查用 claude-opus-5-5 中档。

## 硬规矩（违反任何一条即不合格）
1. 统一底层：
   - 系统内统一维度、统一入口；系统间走统一接口；行为由通用规则从维度推出。
   - 禁止为具体物品、神、地区、职业写专项规则；禁止在规则里出现具体 id。
   - 常数只能放在规则表里。
2. 禁读自然语言：规则层只读数值维度和固定代号。文字只属于显示层，中英双版同等对待。输入边、守门、文字模型一律按卷二 §1.9、§2.7、§2.8、§2.9 执行，各卷不得另立一套。
3. 北极星：产物由材料属性、职业技能、意图三者共同推出。
4. 一个概念只在一处写全：以 `全书概念台账.md` 为准。台账判给本卷的概念，本卷必须写全；判给别卷的，本卷只引用（写明卷、节、入口），不得重写。台账没有的跨卷概念，记进本卷 §8 开放问题，不要自己认领。
5. 不兼容旧存档；规则只保留一版。

## 补充裁定（11-13 第一波中途）
- 新维度、词表族、单位由本领域卷在自己的 §2 定义并登记，格式与登记机制遵循卷二 §1.5、§1.9 等章节。不要要求卷二回填具体的条目清单；收尾时汇总进卷二各登记节（单位 §1.4、命名 struct §1.5、词表 §1.9、原语与命名空间 §1.12、§2.9），不另建全书登记表（李白裁定第 20 条，11-15）。
- 天气不是事件：天气属于卷二十，由（种子、单元、日）通过纯函数算出。只有越过阈值、引发后果时，才产生事件（全书概念台账 X-33）。
- 哈希只有一种，即存档摘要（卷一 §8.3、卷二 §2.9）。规则层不得读哈希。确定性断言一律写成验收测试，交卷十二执行。
- 结果与推进路径无关：降级档位、离屏折叠等只能由世界内在量决定，不得由单次推进的请求长度或推进类别决定。一次推进 N 天与分段推进合计 N 天，必须得到同一份存档摘要。
- 骰值键：禁止使用全局计数器或存档单调序号。抽取键一律为 (worldSeed, streamCode, subjectId, worldTime, drawSiteCode)，组成规则由卷二十七定义，PRNG 算法归卷二 §1.10。
- 性格与价值观（personality、values）：仍是卷二 §5.5 的存储维度。生成时按种子抽取基础值；后天的变化一律通过修正项叠加，读的是“有效值”，基础值不改成派生。卷二 §5.5 维持现状。
