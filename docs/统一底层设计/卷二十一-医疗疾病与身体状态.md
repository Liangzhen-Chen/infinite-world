## §1 领域总述

### 1.1 真实世界怎样运转

1. 身体出的问题大多是**一个随时间变化的量**：伤口在愈合或溃烂，感染在与免疫赛跑，血在流失或再生，药在血里升高又被代谢掉，体温在偏离或回正。它们的差别只在"什么让它涨、什么让它落"。
2. 得病要有**来源和途径**：同处一室的病人、脏水、腐肉、伤口、蚊蝇。剂量越大、防护越差、没有免疫，越容易得。
3. 药没有"治某病"的标签。药材里有若干**药性**（退热、镇痛、收敛、致泻、有毒），病对某些药性有反应。同一味药量少无效、量多中毒，对孩子和对大象不是一个剂量；会不会用，取决于用药的人认没认对病、估没估准量。
4. 处置（清创、缝合、夹板、手术）的好坏取决于**手艺、器械与材料的物性、场所条件**，做坏了本身就是一次新的伤。
5. 人群里的疫病是个体得病的加总，不是另一回事：隔离、净水、用药改变的是每个人的暴露与病程。

### 1.2 本作现状

- 身体需要已实现（body-needs.mjs、primitives-body.mjs），但"是否清醒、能否行动"散在各处：本地清醒判断 31 处，睡眠正则 83 行，状态文字列表 118 处且彼此不一致。
- 诊疗部分实现（medicine.mjs、medicine-state.mjs）：医疗技能是一个写死的技能 id；医馆靠名称正则认；医师靠职位文字正则认；出诊窗口靠活动文字正则认；错误靠报错文字正则分类。
- 人群疫病有 S/I/R 子账户（population-health.mjs），干预倍率在 health.json，与个体病程是两套参数。
- 状态本体只有 1 条淋湿；伤病没有分类；营养缺乏症、药物成瘾、过敏寄生虫、温度伤害都没有。
- 法术状态另有一套标识与"每层固定比例"的常数（magic-status.mjs）。

### 1.3 本卷的总机制：三条律加数据行

- **病程律**（R21-1.2）。每个身体类状态实例只有一个数 `severity`，每拍按同一条公式变化。公式的项全部来自该状态行的数据与主体的维度：自然进程、照护、免疫、驱动量、药应。饥饿、失血、感冒、醉酒、戒断、失温用同一条公式，差别只在行数据。
- **暴露律**（R21-3.2）。得上一种状态的概率只由剂量、该行的传染率、主体在该途径上的防护与已有免疫算出。病人、脏水、腐食、伤口、病媒只是剂量的四种算法。
- **处置律**（R21-8.3、R21-6.3）。一次处置的质量 = 技能对难度的曲线 × 材料物性项 × 场所与身体的修正；一次给药进入身体的量 = 药材药性 × 给药量 ÷ 体重，给药量由意图定目标、由技能定误差。
- 其余都是数据：状态行、药性轴条目、途径条目、身体需要条目、处置行、材料上的药性与病原含量。新增一种病、一味药、一种处置、一种需要，都只加行。

## §4 子系统

### 4.1 身体类状态实例

#### 4.1.1 维度

§2.1 全表；`status_family` 的身体类条目；`person.healMult`、`person.worsenMult`、`person.immuneGain`；`rules.health.tickMinutes`、`immuneFull`。

#### 4.1.2 统一入口

读 `statusView`、`personView().health`。推进钩子 `healthTick`。写一律经 status.mjs。

#### 4.1.3 规则

- **R21-1.1 适用范围按字段不按族。** 病程律对一切 `target` 为身体类的行生效，不论它由本卷、卷十三、卷十五还是别卷登记，也不论属于哪个族。心智类行归卷二十六 §4.4（想法与心情）的推进规则。
- **R21-1.2 病程律。** 对主体 x 上行 r 的实例 i，一个时长为 Δ 天的整拍：

```text
c    = careLevel(x, i)                                  （R21-9.1，取值 [0,1]；行不可照护则为 0）
base = untended + c ×（tended − untended）              （tended 缺则 base = untended；两者皆缺为 0）
imm  = （i.immunity ≥ rules.health.immuneFull）? immune : 0
drv  = r.driveRX 的值（缺则 0）
rsp  = Σ_a r.responds[a] × conc_a(x)                    （conc_a = 药性轴 a 的浓度容器严重度，无实例为 0）
raw  = base + imm + drv + rsp
rate = raw > 0 ? raw × worsenMult[r.family] : raw × healMult[r.family]
s'   = clamp(s + rate × Δ, 0, lethal 或 1)
immunity' = clamp(immunity +（s > 0 ? perDaySick × immuneGain : perDayNotSick）× Δ, 0, 1)
```

  全部用卷二 §3.3（求值管线）的定点算术；两个倍率取修正后值。
- **R21-1.3 档。** 实例所在的档 = `minSeverity ≤ s` 的最后一档；`s = 0` 的实例不落任何档，不带任何修正。档的修正经 `statusView` 进入求值管线，这是状态影响身体与行为的唯一途径。
- **R21-1.4 档效果。** 每拍对当前档的每个 `effects` 调用求值一次，幅度参数按 Δ 折算；输出交原语执行器。一个状态引出另一个状态（出血加重失血、重伤带来疼痛、极重档带来昏迷）只用这一条，不写状态之间的专用规则。
- **R21-1.5 移除。** `s' = 0` 且行不 `persistent` 且（行无 `immunity` 或 `immunity' = 0`）时移除实例；`duration` 到期移除；有免疫的实例在 `s = 0` 时留作免疫记录，直到免疫衰减到 0。
- **R21-1.6 后遗。** 实例被移除时，若其存续期间到过的最大严重度 ≥ `sequela.above`，在同一部位写入 `sequela.status` 的实例。最大严重度由实例字段记录（§5.3 回填请求）。
- **R21-1.7 致死。** `s' ≥ lethal` 时调卷四 §4.8（死亡结算、尸体、复生点）的 `die`，死因为该状态行。本卷没有别的致死途径，也没有生命值。带终止类实例的主体不再推进其余实例。
- **R21-1.8 整拍。** 推进只在绝对时间的整拍边界进行，一拍恰结算一次，区间不跨拍；拍内发生的摄入、受伤、处置是事件，当刻改严重度。因此结果与一次推进多长、分几次推进无关。统计层与规则层的形态见 §4.10。
- **R21-1.9 四类必备行。** 卷四需要的终止类、睡眠、昏迷、妊娠四行由本卷登记（卷末代号表）。规则只读族条目的三个布尔字段；卷四经其规则表的键引用这些行。睡眠实例由睡眠动作写入与移除（动作归卷九 §4.1（动作目录）），存续期间的作用全在行数据里。

#### 4.1.4 交互

- 卷二：容器格式、写者、谓词。卷四：`bodyView` 收集本卷实例的修正；`die`。
- 卷十三 §4.7（伤病疲劳濒死）、卷十五 §4.3（交互行）、卷七：登记自己的身体类行，自动服从病程律。

### 4.2 伤口、出血、感染

#### 4.2.1 维度

状态行的 `woundOf`、`bodyPart`、`sequela`、`stages`；途径条目中剂量来源为伤口的那些；`person.healMult`；卷十三伤害事件的载荷（部位、伤害类型、该部位损失比例、所及组织层序）。

#### 4.2.2 统一入口

反应钩子 `onDamage`；读 `bodyView().parts`。

#### 4.2.3 规则

- **R21-2.1 伤害变伤口。** 收到伤害结算事件后，取 `woundOf` 含该伤害类型的那一行（加载期保证恰一行），在命中部位写入实例，初始严重度 = 事件给出的该部位损失比例；同部位同一行已有实例则严重度相加后钳位。本卷不重算伤害。
- **R21-2.2 伤的后果全在档上。** 部位完好度下降、出血、疼痛、可感染，都是伤口行各档的修正与档效果（R21-1.4）；伤口深浅用事件给的组织层序作档效果的幅度参数。出血行的严重度是失血速度，它的档效果每拍给失血量行加严重度；失血量行自带回落（造血）并在高档压低泵血与意识。
- **R21-2.3 感染走暴露律。** 伤口实例存续时每拍产生一次伤口途径的暴露（R21-3.2），剂量 = 伤口严重度 × 所在地点的污秽场强度 × 该途径的混合系数；清创与包扎降低的是 `exposureMult` 在该途径上的值与伤口的照护水平，不是另一套"感染概率"。
- **R21-2.4 愈合就是病程律。** 伤口行的 `untended` 可为正（无人处理会恶化）或为负（自愈）；休息、营养、年龄、床位通过 `healMult` 的修正起作用。
- **R21-2.5 断肢与残疾。** 严重度到达伤口行最高档时，该档的部位完好度修正使部位丧失（判定在卷四）；实例移除时按 R21-1.6 留下后遗行。义肢与再生是卷十五与卷三登记的修正来源。
- **R21-2.6 部位合法性。** 挂部位实例的部位须在主体当前身体图内（卷四判）；无定形体只有一个部位，伤都落在它上面，规则不变。

- 卷二十 §4.7（环境场与排放衰减）：污秽场强度。通道：事件订阅、原语执行器。

### 4.3 疾病与免疫、传染

#### 4.3.1 维度

状态行的 `contagion`、`immunity`、`severity.perDay`、`hosts`、`shedCurve`；`route` 族条目；材料的 `agents`；`person.exposureMult`、`person.immuneGain`。

#### 4.3.2 统一入口

`healthTick` 内的暴露判定；读 `prevalenceOf`；统计形态见 §4.10。

#### 4.3.3 规则

- **R21-3.1 暴露的四种剂量算法**（途径条目的 `doseSource`，封闭枚举）：
  - `colocated`：同一地点内带该行实例且可排出者的 `shedCurve(严重度)` 之和 × 本拍共处天数 × 该途径 `mixRX` 的值（读地点的封闭程度、拥挤程度）。
  - `ingested`：本拍摄入各物品的质量 × 其材料 `agents` 中该行的含量。
  - `wound`：R21-2.3。
  - `field`：途径条目 `field` 所指环境场在主体所在地点的强度 × 本拍天数。
- **R21-3.2 暴露律。** 对主体 x、行 r、途径 p、剂量 d：

```text
若 r.hosts 非空且 x 的物种分类链与之不相交 → 不暴露
p_get = 1 − exp(−d × r.contagion.rate × exposureMult[p] ×（1 − immunity_x(r)）)
u     = 骰值键抽取（成分见 R21-3.6）
u < p_get → 写入 r 的实例，严重度取 severity.initial，来源记途径所属的来源种类
```

  已带该行有严重度的实例者不再判定；只留免疫记录者按其免疫值折减。指数用卷二 §1.10（随机实例化）的定点指数表。
- **R21-3.3 病与免疫赛跑。** 患病期间免疫按 `perDaySick × immuneGain` 增长；到满值后 `immune` 项加入病程律，严重度开始回落。在那之前先到致死值的主体死去。老、幼、营养差的主体 `immuneGain` 低，所以更容易死，这不是另写的年龄死亡率。
- **R21-3.4 免疫记忆与再感染。** 痊愈后免疫按 `perDayNotSick` 衰减；衰减快的行可以反复得，衰减为 0 的行终身免疫。
- **R21-3.5 人畜共通与隔绝。** 一行的 `hosts` 同时含两类分类位置时两类主体互相传染；隔离、面罩、净水、驱虫都是对 `exposureMult` 某途径的修正，作用域取所在地点或法域。
- **R21-3.6 抽取键。** 成分为（世界种子、流代号、主体、该拍起点时刻、抽取点代号加行与途径的登记序）；组成规则按卷二十七 §4.8（种子键与骰值键），不含计数器。
- **R21-3.7 只判有来源的行。** 每拍只对"本拍剂量大于 0"的（主体、行、途径）组合判定；剂量由来源方索引给出，不遍历全部行。

#### 4.3.4 交互

- 卷二十 §4.6（水循环与水量）与卷二十 §4.7（环境场与排放衰减）：水体里的污染物材料余额、病媒与污秽场强度。
- 卷三 §4.12（腐坏与保质）：腐坏档上的材料修正可抬高 `agents`；吃下去走摄入事件。
- 卷五、卷八 §4.16（人口统计层）：读 `prevalenceOf`。卷四：`die`、物种分类链。
- 通道：事件（染病、痊愈各发一个动词）。

### 4.4 营养与缺乏症

#### 4.4.1 维度

`body_need` 族；卷四的代谢三率与体力消耗倍率；卷三的营养组（`nutrients`、`energyDensity`、`hydration`）与营养素词表（条目带所属身体需要代号）；`rules.health.fatSatietyPerKg`。

#### 4.4.2 统一入口

反应钩子 `onConsumed`；读 `personView().health.needs`。

#### 4.4.3 规则

- **R21-4.1 需要是亏空容器。** 每个身体需要条目对应一个亏空行，严重度 = 已欠量 ÷（日需量 × 储备天数）。日需量读条目 `needDim` 所指的个体维度（修正后值）；储备天数由 `reserveDaysRX` 算。
- **R21-4.2 消耗。** 亏空行的 `driveRX` 给出每日增长 `1 ÷ 储备天数`；日需量为 0 的主体驱动项为 0，不累积。劳作、行军、寒冷使日需量变大（卷四的修正），亏空因此涨得更快，本卷不另写活动消耗。
- **R21-4.3 补给。** 摄入事件到来时，对每项 `supply` 为摄入的需要：供给量 = 摄入质量 × 该物品中归属此需要的营养量（按卷三的份额加权读出）；严重度减 `供给量 ÷（日需量 × 储备天数）`。靠休息、靠睡眠补的需要，在相应状态实例存续的每拍按条目数据回落。
- **R21-4.4 溢出与转存。** 亏空到达 1 仍继续消耗时，超出部分按同一折算加到 `overflowTo` 所指需要的亏空上；补给使亏空低于 0 的部分，乘 `storeEfficiency` 后先减少 `overflowTo` 的亏空，再有剩余则加到 `excess` 所指的过量行。短期的饱腹与长期的体内储备因此是同一机制的两级。
- **R21-4.5 缺乏症是亏空行的高档。** 缺乏的后果（乏力、夜盲、伤口不愈、致死）是亏空行各档的修正与档效果；微量营养的储备天数长，所以是数周到数月的慢变量。
- **R21-4.6 储备由身体算。** 能量的长期储备天数 = 脂肪组织质量 × `fatSatietyPerKg` ÷ 日需量；脂肪质量由卷四的体重与组织份额给出。胖的、大的、代谢慢的主体饿得久，不需要逐物种填"能饿几天"。
- **R21-4.7 群体。** 统计形态下，聚合体的每项需要只存"人均亏空"一个聚合维度，供给取家户与聚落的口粮结算（卷六），折算式同 R21-4.3；缺量后果的效果族由卷三用度类条目引用。

#### 4.4.4 交互

- 卷三 §4.1（材料属性表）：营养值在物上；营养素词表条目由卷三登记、所属需要代号由本卷给（卷三开放问题 Q-12 由此答复：见卷末代号表）。
- 卷四 §4.7（代谢）：三率与可食判断。卷二十五 §4.9（烹饪酿造）：烹饪折损改的是材料行。
- 卷二十六 §4.4（想法与心情）：饥渴困乏触发想法。卷六：家户口粮结算读日需量之和。
- 通道：事件订阅（摄入）、原语执行器。

### 4.5 过敏、食性、寄生虫、中毒

#### 4.5.1 维度

材料的 `pharm`、`agents`；`person.sensitivity` 与物种的敏感度分布；药性轴条目；状态行的 `hosts`、`contagion`；卷四的可食判断。

#### 4.5.2 统一入口

同一个 `onConsumed`。本节没有自己的入口。

#### 4.5.3 规则

- **R21-5.1 一条摄入律。** 任何物品经任何途径进入身体，只发生三件事：补需要（R21-4.3）、加药性浓度（R21-6.2）、产生病原暴露（R21-3.1 的摄入算法）。食物、饮水、药、毒、腐肉、脏水不分种类。
- **R21-5.2 毒是药性。** 有毒 = 材料在某个药性轴上有含量，该轴的浓度容器高档带伤害性修正并可致死。毒性大小、解毒、耐毒都落在同一组数据上；投毒与服药是同一个给药动作，差别在意图与是否经同意（罪名归卷八b）。
- **R21-5.3 过敏是敏感度。** 个体对某药性轴的 `sensitivity` 由物种分布采样；远高于 1 的个体，常人无感的剂量就使该轴浓度进入高档。过敏原只是在某个轴上有含量的材料。不设过敏名单。
- **R21-5.4 食性不合。** 物种吃不了的东西由卷四的可食判断拦在动作前置；被迫或误食时仍走摄入律，后果由物种级敏感度决定（某物对一类物种有毒、对另一类无害）。
- **R21-5.5 寄生虫与食物中毒是经口的病。** 它们是带经口途径的疾病行；生肉、脏水的 `agents` 含量高，加热、冷冻、腌制后的材料行含量低（卷三以继承写法登记的熟制材料行）。厨师技能与清洁影响的是成品品质档与场所污秽，经已有管线进入含量与暴露倍率。
- **R21-5.6 污染。** 环境里的污染物是材料余额（卷二十）；饮用被污染的水时，污染物材料按其份额带入自己的 `pharm` 与 `agents`。

#### 4.5.4 交互

- 卷三 §4.12（腐坏与保质）与卷三 §4.8（配方通用规则）：腐坏档与熟制改变材料量。卷二十五 §4.9（烹饪酿造）：配方行。
- 卷四 §4.7（代谢）：可食判断。卷八b §4.1（规范栈与法典条目）：投毒的定性。
- 通道：事件订阅（摄入）。

- 【非西陲】东部港口水手对贝类过敏：他在该轴的敏感度采样为 40，一口贝肉即进入该轴浓度容器的极重档；同桌的人无事。
- 【非人类】猎犬偷吃了含兴奋成分的豆制点心：物种级敏感度约六倍，加上体重小，浓度远超人类同量时的值。
- 【超自然】食腐的洞穴爬行种：其分类位置不在肠虫行与腐败病行的 `hosts` 内，吃腐肉不暴露；这是行数据，不是"食腐免疫"分支。

#### 4.5.6 验收断言

- A21-5.S 扫描式：摄入处理只有一个函数入口；其中没有按物品类别、材料、物种的分支；P21-5 命中 0。
- A21-5.I 不变量式：同一摄入事件，把物品拆成两半分两次摄入，三类结果的合计与一次摄入相同（暴露概率按合并剂量等价）；敏感度为 0 的轴浓度增量为 0。
- A21-5.X 扩展性式：新增一种材料（带一条新药性轴的含量）与该轴条目及浓度容器，不改 `.mjs`，吃下它的主体出现相应档，敏感个体更重。

### 4.6 药物与成瘾

#### 4.6.1 维度

`pharm` 族条目全部字段；材料的 `pharm`；`person.sensitivity`；`rules.health.doseLevels`、`doseErrorCurve`；状态行的 `responds`。

#### 4.6.2 统一入口

`onConsumed`（任何摄入）；`onTreat`（由医者给药）；预览 `treatmentPreview`。

#### 4.6.3 规则

- **R21-6.1 药效不是字段。** 一件物品"是什么药、有多强"只由它的材料在各药性轴上的含量决定（按份额加权，再乘成品品质档在该轴上的倍率，方向取轴条目的 `qualitySign`）；制剂由配方从药材得到，含量随产物继承。本卷没有"治疗某病的物品"清单。
- **R21-6.2 进入身体的量。** 质量为 m 的物品经途径 p 进入主体 x，对它含有的每条药性轴 a：

```text
Δconc_a = m × pharm_a(物品) × bio_a[p] × sensitivity_x[a] ÷（refDose_a × massKg_x ^ massExp_a）
```

  加到轴 a 浓度容器的严重度上（无实例则新建）。浓度的回落、各档的作用（镇痛、退热、兴奋、镇静、中毒、致死）都是该容器行的数据，按病程律走。有用的轴与有害的轴同时进入，副作用因此不需要另写。
- **R21-6.3 给药量由意图与技能定。** 医者（或自己）给药时，意图包含：所针对的状态实例、所用物品、剂量档。目标轴 a* = 在医者**所认定**的状态行（R21-8.2）的 `responds` 里，该物品能提供的、使病程项最负的那条轴。目标浓度 = 轴 a* 的 `range.min + 剂量档比例 ×（range.max − range.min）`。给药量：

```text
m = 目标浓度 × refDose_a* × massKg_x ^ massExp ÷（pharm_a*(物品) × bio_a*[p]）× exp(σ × z)
σ = lookup(rules.health.doseErrorCurve, 该处置行所指技能的值)；z 为标准正态抽取（骰值键）
```

  所以：药材决定每克里有什么；技能决定量估得准不准、病认得对不对；意图决定冲着哪个病、下多重的手。认错了病，目标轴就错；估不准量，就偏轻无效或偏重中毒；病人的敏感度医者并不知道，过敏者照常量也会出事。
- **R21-6.4 对病的作用只经药应。** 药性浓度对某个状态的作用 = 病程律里的药应项；对身体能力、心情、属性的作用 = 浓度容器各档的修正。除此之外药不改变任何东西。
- **R21-6.5 耐受、依赖、戒断。** 轴条目可指向耐受行与依赖行。耐受行由浓度驱动上升，它的档给该轴的 `sensitivity` 负修正；依赖行由浓度驱动上升、停用后缓慢回落；戒断行的驱动项在"依赖高而浓度低"时为正。三者都是带 `driveRX` 的普通行。渴求是卷二十六读依赖与戒断实例触发的想法。
- **R21-6.6 过量。** 过量 = 浓度超过 `range.max` 后落入容器的高档；没有单独的过量判定。多种药叠加时，同一轴的浓度相加，不同轴各自成档，相互作用由各档修正在求值管线里按叠加规则合成。
- **R21-6.7 违禁不归本卷。** 本卷只提供药性轴维度与条目字段；某法域禁哪些，是法典条目按物品类别或药性含量写的谓词（卷八b §4.1（规范栈与法典条目））。同一物在两地合法性不同，本卷的规则不变。

#### 4.6.4 交互

- 卷三 §4.8（配方通用规则）：制剂是配方行；成品品质档由制作者技能得出。卷十四 §4.3（技能与熟练）：技能值。
- 卷八b：读药性维度写违禁谓词。卷二十六：`person.personality` 等可作浓度容器档修正的目标；依赖触发想法。
- 卷六：药材与成药的价格由供需得出，本卷不给任何价格修正。通道：事件订阅、原语执行器。

#### 4.6.6 验收断言

- A21-6.S 扫描式：`.mjs` 中物品 id、材料 id、药性轴代号字面量为 0；不存在"物品 → 治疗量"的映射表；P21-9 命中 0。
- A21-6.I 不变量式：同一物品同一途径，浓度增量与给药质量成正比、与体重的 `massExp` 次方成反比；技能升高时给药量的离散度单调不增；剂量档升高时目标浓度单调不减；药性含量为 0 的物品不改变任何浓度。
- A21-6.X 扩展性式：新增一味药材（材料行，两条已有轴的含量）不改 `.mjs` 即可被采集、入药、给药、起效与中毒；新增一条带依赖的药性轴及其三行容器，不改 `.mjs` 即出现耐受与戒断。

### 4.7 环境温度伤害

#### 4.7.1 维度

物种的 `coreTempC`、`coolingC`（卷四登记）；个体的 `selfHeatC`、`coldLimitC`、`heatLimitC`；卷三的材料 `insulation` 与穿着合计 `warmthTotal`；卷二十的体感温度；`rules.health.thermal`。

#### 4.7.2 统一入口

读 `personView().health.thermal`；冷热行的推进在 `healthTick`。体感温度只读卷二十 §4.5（温度量纲与热交换）的 `feltTempC`。

#### 4.7.3 规则

- **R21-7.1 耐受区间由身体与衣着算出，不手填。**

```text
selfHeatC  = lookup(thermal.selfHeatCurve, massKg) × 物种代谢倍率      （可修正：劳作、颤抖、进食提高它）
coverC     = Σ 层序 ≤ thermal.coverDepth 的组织，其材料的 insulation
clothC     = warmthTotal × thermal.cPerWarmth
coldLimitC = coreTempC − selfHeatC − coverC − clothC
heatLimitC = coreTempC − selfHeatC × thermal.heatFraction + coolingC − thermal.trapFactor ×（coverC + clothC）
```

  体大、代谢高、毛厚、穿得多的主体耐寒；同样这些使它怕热。`coreTempC` 为空的物种不适用，本节两类行对它不驱动。
- **R21-7.2 冷热是驱动行。** 受冷行的 `driveRX` 读 `coldLimitC − felt` 的正部，受热行读 `felt − heatLimitC` 的正部，各乘行上的系数并减去回落项；越界越多、时间越长，严重度越高。档上的修正降低操作、移动、意识，极重档致死。
- **R21-7.3 淋湿。** 淋湿是一行由降水暴露量驱动、随时间与温度回落的状态；它经卷二十的体感公式降低体感温度，本卷不重复计算。
- **R21-7.4 冻伤与热伤。** 受冷行高档的档效果在末端部位写入冻伤行（挂部位实例）；选哪个部位由骰值键在叶子部位中按面积权重的倒数抽取。火焰、沸水造成的烧烫伤是伤害类型，走 R21-2.1。
- **R21-7.5 冷热改变需要。** 受冷行与受热行的档修正以日需量为目标（冷时多耗能、热时多耗水），由此接到 §4.4，不另写。
- **R21-7.6 物品自身的冷热**（结冰、熔化、烧毁）归卷三，读地点温度而非体感。

#### 4.7.4 交互

- 卷二十 §4.5（温度量纲与热交换）：`feltTempC`；降水暴露量。卷三 §4.13（服装分层与护甲物性）：`warmthTotal`、透气。卷四：体重、组织与材料、身体图。
- 卷十九：取暖设施经温度场起作用，本卷不读设施。通道：无新增。

#### 4.7.6 验收断言

- A21-7.S 扫描式：`.mjs` 中无任何温度阈值字面量；无按物种、按衣物 id 的分支；不直接读地点温度算伤害（只读体感入口）。

- A21-7.X 扩展性式：新增一个物种行（给出体重分布、组织材料、体内设定温度与散热能力），不改 `.mjs`，它的耐受区间即可求值并在越界时出现冷热状态。

### 4.8 医疗诊治与手术质量

#### 4.8.1 维度

`procedure` 族全部字段；状态行的 `signs`、`obscurity`、`tendable`；过程槽 `process.treatQuality`（登记到卷二 §3.7（旧派生槽的对照与过程主体槽）的过程槽表）；`rules.health.qualityCurve`、`outcomeSpread`。

#### 4.8.2 统一入口

动作"处置"在卷九 §4.1（动作目录）登记一行，槽位为处置行代号、病人、目标实例、物品、剂量档；完成时调 `onTreat`。预览 `treatmentPreview`、可选项 `careOptions`。

#### 4.8.3 规则

- **R21-8.1 谁都可以处置。** 能否施行只看处置行的需求块是否满足（器械能力、耗材类别，卷三 §4.7（需求块））、施行者 `can()` 是否通过、病人或其监护方是否同意（效果族的同意字段）。没有"医者"身份判断；技能低的人也能做，只是质量低。
- **R21-8.2 诊断。** 诊断是一行处置（`outputs` 为知情写入）。对目标实例的状态行 r：诊断质量 ≥ `r.obscurity` 折算值则认定为 r；否则在"与 r 至少共有一个体征"的行里按共有体征数加权抽取一行作为认定结果（骰值键）。认定结果是施行者的一条知情，存取归卷二十二 §4.1（主观视图）。`needsDiagnosis` 的处置读施行者的认定；没有认定则不可施行。
- **R21-8.3 处置质量。**

```text
Q0 = lookup(rules.health.qualityCurve, 技能值 − difficulty)
Qm = Π_k lookup(term_k.curve, 需求块第 term_k.group 组实际所用物品的 term_k.dim)
Q  = clamp(modified(process.treatQuality 基值 Q0 × Qm), 0, 1)
q  = clamp(Q ×（1 + outcomeSpread ×（1 − Q）× t), 0, 1)        （t 为 [−1,1] 上的三角分布抽取，骰值键）
```

  施行者自身的操作与视觉能力、醉酒与疲劳，场所的照明、洁净、床位，器械品质，都是以该过程槽为目标的修正项，由各自的来源登记；本卷不逐项写。
- **R21-8.4 结果。** `q ≥ botchBelow`：以 q 为幅度参数求值 `outputs`（降低目标实例严重度、写入照护实例、给药、截除部位等）；否则求值 `failure`（新的伤口、一次以场所污秽为剂量的伤口暴露等）。耗材在两种结果下都消耗（经账本转入消耗汇）。
- **R21-8.5 手术是难度高的处置行。** 取出异物、截肢、接骨、剖产、植入都是数据行，差别在难度、需求块、材料物性项与后果。材料物性项使"用什么线缝、用什么板固定、用什么布包"有实际差别。
- **R21-8.6 可以对谁做什么是算出来的。** 某实例的可用处置 = 其族在 `aimFamilies` 内且行 `tendable` 的处置行；`careOptions` 给出此集合。新病自动可被已有的通用处置照护。
- **R21-8.7 报错只用代号。** 不可施行的原因返回错误码与需求块的缺项代号，不产生文字；排期冲突、路线不通、付不起诊费各归其卷的错误码。

#### 4.8.4 交互

- 卷十四 §4.3（技能与熟练）：技能值与成长（施行处置给熟练度由该卷订阅事件）。卷三 §4.7（需求块）与卷三 §4.6（工具能力）：器械能力与耗材。
- 卷二十二 §4.1（主观视图）：诊断认定的存取。卷九 §4.12（NPC 决策管线）：用 `treatmentPreview` 评估是否求医、用哪种处置。
- 卷二十六 §4.5（压力累积与崩溃）：发作容器若标为可照护，同样进入 `careOptions`。卷六：诊费是服务交易。
- 通道：动作、原语执行器、账本（耗材）、事件。

### 4.9 照护与康复

#### 4.9.1 维度

照护族的状态行（`tends`、自身的回落速度）；`person.healMult`、`person.worsenMult`；状态行的 `tended`、`sequela`；`rules.health.careMatch`。

#### 4.9.2 统一入口

`personView().health.careNeeds`；照护实例由处置的 `outputs` 写入。

#### 4.9.3 规则

- **R21-9.1 照护水平。** 实例 i 的照护水平 = 主体身上满足"行的 `tends` 含 i 所属族、且部位与 i 相同（i 不挂部位则要求照护实例也不挂部位）"的照护族实例的最大严重度；没有则为 0。照护实例的严重度 = 写入时的处置质量 q。
- **R21-9.2 照护会过期。** 照护行自带回落；回落到 0 即移除，需要重新处置。换药间隔、每日探视因此由行数据的回落速度给出。
- **R21-9.3 休养条件是修正。** 卧床、床铺品质、洁净、保暖、饱足通过 `healMult` 与 `worsenMult` 的修正起作用（来源：睡眠行的档、设施类型行的服务效果、亏空行的档）。本卷不写"在医馆里好得快"的规则。
- **R21-9.4 失能者的需要。** 不能行动的主体不能自己进食饮水；照护者以给予动作完成摄入（走同一摄入律）。无人照护时亏空照常上升，这就是重病无人管会死的原因。
- **R21-9.5 康复与后遗。** 后遗行（R21-1.6）可以是 `untended` 为 0、`tended` 为负的行：只有持续的康复处置才使它回落。永久残疾是两者皆为 0 的行。
- **R21-9.6 求医是决策。** 是否求医、谁去照护不是本卷的规则：卷九的决策管线读 `critical`、`careNeeds` 与 `treatmentPreview`，卷十八的关系决定谁愿意照护。本卷只保证这些读数存在。

#### 4.9.4 交互

- 卷十九 §4.2（设施类型表）：床位与洁净作为设施类型行的服务效果。卷九 §4.12（NPC 决策管线）、卷十八：谁照护。
- 卷二十六：久病、照护他人触发的想法。通道：原语执行器。

### 4.10 公共卫生与疫病钟

#### 4.10.1 维度

`epi.<聚合体>.<状态行>`；状态行的传染与病程字段；聚合体的人数与年龄构成（卷二十七的聚合维度）；`rules.health.stat`；事件类型行的触发式可读的 `prevalence(...)`。

#### 4.10.2 统一入口

`epiTick`、`prevalenceOf`、`courseSummary`。事件类型行只登记，不写事件状态。

#### 4.10.3 规则

- **R21-10.1 三层形态**（向卷二十七 §4.1（三层模拟运行矩阵）登记矩阵行）：个体层为逐实例形态（§4.1–§4.9）；规则层为逐主体批量形态（同一病程律，按该层节拍一拍结算）；统计层为逐聚合体统计形态（本节）。暴露律在统计形态下的写法见 R21-10.3。
- **R21-10.2 病程摘要由行参数闭式得出。** 对行 r、照护水平 c、免疫增益 g：免疫到满的天数 `tImm =（1 − 初始免疫）÷（perDaySick × g）`；峰值 `peak = initial +（untended + c ×（tended − untended））× tImm`；`peak ≥ lethal` 则致死，致死日由同式反解；否则病程天数 = `tImm + peak ÷ |base + immune|`。加载期对 `rules.health.stat.gainQuantiles` 的各分位与聚合体的照护覆盖率求出病死比例与平均病程。不手填病死率、不手填病程天数、不手填再生数。
- **R21-10.3 统计形态的传播。** 聚合体内易感者人数 S = 人数 − 患病 − 免疫；每拍新染人数的期望 = S ×（按 R21-3.2 以"患病比例 × 平均排出量 × 混合系数"为剂量算出的概率）；整数化的余量按骰值键进位（键含聚合体与桶号）。痊愈与病死按 R21-10.2 的平均病程与病死比例折成每拍比例；病死经聚合体减员入口减人并发事件。跨聚合体的传入靠迁移与行旅带入的患病成员，不设"外来输入率"。
- **R21-10.4 折叠与实体化守恒。** 单元由细变粗时，个体实例按行计数并入 `epi.*`；由粗变细时，按骰值键在成员中抽出相应人数写入实例，严重度取该行病程摘要的中位阶段。两个方向患病与免疫人数不变。
- **R21-10.5 公共措施是修正。** 隔离、净水、灭虫、施药、封城是以 `exposureMult`、`healMult`、地点的拥挤程度为目标、作用域为地点或法域的修正项，由决定它的主体（聚落治理、教会、医馆）的动作产生；统计形态读聚合体成员的平均修正值。现 health.json 的三种干预倍率迁为三条修正项数据。
- **R21-10.6 疫病钟。** "某地爆发疫病"是事件类型行：触发式读患病率越阈、水体污染、病媒场强度、粮荒；后果阶段只指向维度（暴露倍率、劳动出勤、行旅通行），不指向价格。检查节拍与抽签沿用卷二十 §4.9（世界时钟事件与灾异）的做法；事件实例的写者在卷二十四。现灾害时钟里的疫病日历条目退役：疫病不按日历来，按条件来。
- **R21-10.7 背景死亡不重复计。** 卷四的背景死亡曲线须扣除本卷已建模的死因；标定办法是统计层长时推进后，各死因合计的年死亡率对齐目标值（卷四开放问题 Q-15 由此答复，标定归数值工作）。

#### 4.10.4 交互

- 卷二十七 §4.2（聚合变体、等价、钉住）：聚合体成员、减员、实体化。卷八 §4.16（人口统计层）、卷五：读患病率。
- 卷二十四 §4.2（事件类型注册表）：登记疫病事件行。卷六：劳动力与供给变化由其自行从出勤与人口读出。

### 4.11 医疗设施与职业接口

#### 4.11.1 维度

处置行的 `service`；设施类型行的服务效果与容量维度（卷十九）；职业行的服务集合（卷十四）；雇佣与成员持有边（卷十八、卷六）。本节没有自己的表。

#### 4.11.2 统一入口

读 `facilityTypeView`、`professionView`；`careOptions` 可按地点过滤出"此处此刻有人能施行的处置"。

#### 4.11.3 规则

- **R21-11.1 医馆不是一类特殊建筑。** 一处设施能提供哪些医疗服务 = 其设施类型行声明的服务代号 ∩ 此刻在岗成员能施行的处置行的 `service`。名称、用途文字不参与。
- **R21-11.2 医者不是一种身份。** 某人能否提供某处置 = 需求块满足、`can()` 通过、技能值使预览质量不低于该处置行的做坏线。职位称谓只在显示层。成员关系读雇佣与成员持有边，不读职位文字。
- **R21-11.3 出诊与排期。** 预约是义务（合同状态机归卷六）；是否在出诊时段读日程槽上的动作代号（卷九），不读活动文字。上门出诊是行程（卷十七）加处置动作。
- **R21-11.4 设施对疗效的作用只经修正。** 床位、洁净、照明、器械是设施类型行与其陈设的维度，作用于过程槽与好转倍率（R21-8.3、R21-9.3）。
- **R21-11.5 药铺是有药材库存的店。** 采购、库存、售价全归卷六；本卷只提供药性读数供买卖双方估计用途。药价随求诊人数上涨是供需结果，现价格乘数入口删除。
- **R21-11.6 慈善与公费。** 施药、义诊、公共防疫的钱是拨款与捐赠的账本转移（卷六），其效果仍是处置与修正项。

#### 4.11.4 交互

- 卷十九 §4.2（设施类型表）：服务效果、容量。卷十四 §4.1（职业表与服务词表）：服务代号由该卷登记，本卷的处置行引用。
- 卷六：诊费、药价、合同。卷十七：出诊行程。卷九：日程与动作。通道：无新增写入。

- A21-11.S 扫描式：设施名称、职位称谓、活动文字的正则为 0（现 medicine-state.mjs 第 29、35、36、39 行，medicine.mjs 第 50、51 行归零）；设施 id、职业 id 字面量为 0。
