## §1 领域总述

### 1.1 真实世界怎样运转

1. 身体出的问题大多是**一个随时间变化的量**：伤口在愈合或溃烂，感染在与免疫赛跑，血在流失或再生，药在血里升高又被代谢掉，体温在偏离或回正。它们的差别只在"什么让它涨、什么让它落"。
2. 得病要有**来源和途径**：同处一室的病人、脏水、腐肉、伤口、蚊蝇。剂量越大、防护越差、没有免疫，越容易得。
3. 药没有"治某病"的标签。药材里有若干**药性**（退热、镇痛、收敛、致泻、有毒），病对某些药性有反应。同一味药量少无效、量多中毒，对孩子和对大象不是一个剂量；会不会用，取决于用药的人认没认对病、估没估准量。
4. 处置（清创、缝合、夹板、手术）的好坏取决于**手艺、器械与材料的物性、场所条件**，做坏了本身就是一次新的伤。
5. 人群里的疫病是个体得病的加总，不是另一回事：隔离、净水、用药改变的是每个人的暴露与病程。

### 1.2 本作现状

- 身体需要已实现（body-needs.mjs、primitives-body.mjs），但"是否清醒、能否行动"散在各处：本地清醒判断 31 处，睡眠正则 83 行，状态文字列表 118 处且彼此不一致。
- 诊疗部分实现（medicine.mjs、medicine-state.mjs）：医疗技能是一个写死的技能 id；医馆靠名称正则认；医师靠职位文字正则认；出诊窗口靠活动文字正则认；错误靠报错文字正则分类。
- 个体得病是另一套实现（npc-life.mjs:463–525，参数在规则键 `npcLife.health`）：按年龄段的年发病次数抽签得病，没有来源和途径；轻重是文字；病程天数与重症病死率手填；重病自动指派照护人。
- 诊断正确率、伤口可治门槛、求医时机、出诊时段、诊费（按排队人数加价）都是 medicine.mjs 里的写死算式；"是不是药"靠物品类别判断；旧健康表（balance/health.json）按三个字面量行键给伤口愈合天数。
- 人群疫病有 S/I/R 子账户（population-health.mjs），干预倍率在旧健康表，与个体病程是两套参数。
- 伤口已有一套字段（种类、骨折、深度、面积、污染、感染风险、每分钟出血量、异物、毒素量），失血、感染、寄生虫、肌腱完好度在法术照护模块里按写死的常量表模拟（magic-care.mjs、magic-ritual.mjs），与凡俗诊疗是两条路。
- 饮水有安全闸：带毒素、病原或浑浊的水被打上布尔标记，饮用动作直接拒绝（items.mjs、household-subsistence.mjs），所以"喝脏水得病"在现状里走不到。
- 状态本体只有 1 条淋湿；营养缺乏症、药物成瘾、过敏、温度伤害都没有。
- 法术状态另有一套标识与"每层固定比例"的常数（magic-status.mjs）。

### 1.3 本卷的总机制：三条律加数据行

- **病程律**（R21-1.2）。每个状态实例只有一个数 `severity`，取值 [0,1]，每拍按同一条公式变化。公式的项全部来自该状态行的数据与主体的维度：自然进程、照护、免疫、驱动量、药应。饥饿、失血、感冒、中毒、戒断、失温用同一条公式，差别只在行数据。
- **实例只有三种来路**：暴露（R21-3.2）、驱动量越过阈值（R21-1.10）、事件或效果族写入（受伤、处置、档效果）。严重度回到 0 的实例由病程律结案，不再推进（R21-1.5）；没有来路就不会再出现。
- **暴露律**（R21-3.2）。得上一种状态的概率只由剂量、该行的传染率、主体在该途径上的防护与已有免疫算出。病人、脏水、腐食、伤口、病媒只是剂量的四种算法。
- **三个不是严重度的量**，各在一处定义：免疫记录（R21-3.3，痊愈后独立存在、按自己的规则衰减）；药性浓度（R21-6.2，单位是治疗阈的倍数，可以大于 1）；照护质量（R21-9.1，照护实例上的一个数）。
- **处置律**（R21-8.3、R21-6.3）。一次处置的质量 = 技能对难度的曲线 × 材料物性项 × 场所与身体的修正；一次给药进入身体的量 = 药材药性 × 给药量 ÷ 体重，给药量由意图定目标、由技能定估计误差。
- 其余都是数据：状态行、药性轴条目、途径条目、身体需要条目、处置行、材料上的药性与病原含量。新增一种病、一味药、一种处置、一种需要，都只加行。

### 2.6 行内 RX 的变量范围（校验码 E-MED-RX-VAR）

`driveRX`、`reserveDaysRX`、`mixRX` 只许读下表的变量。未知传播按卷二 §1.12（派生与聚合原语）；任一所读主体维度为空（不适用）时，整条式子不适用，该行对该主体不求值。行与轴的引用写在数据里，规则代码不出现。

| 变量 | 含义 |
|---|---|
| `subject.<个体或物种维度>` | 修正后值 |
| `self.severity` | 本实例的严重度；用于新建判定时取 0 |
| `sev(<状态行>)` | 同一主体该行实例的严重度；无实例为 0；该行可多实例（挂部位）时取各实例的最大值 |

#### 4.1.3 规则

- **R21-1.1 适用范围按字段不按族。** 病程律对一切状态容器行生效，不论 `target` 是身体类还是心智类，不论由本卷、卷十三、卷十五、卷二十六还是别卷登记，也不论属于哪个族。各类行的差别只是哪些项为零（心智类行没有免疫、药应时这两项为 0）。心智类行的登记、档的含义与效果仍归卷二十六；它的照护同样取 R21-9.1 的照护水平（取值 [0,1]；"有人照看与无人照看二选一"是照护水平取 1 与 0 的特例）。容器因此只有一种推进解释。执行位置见 §8 Q-3。
- **R21-1.2 病程律。** 对主体 x 上行 r 的、严重度 s 大于 0 的实例 i，一个时长为 Δ 天的整拍：

```text
c    = careLevel(x, i)                                  （R21-9.1，取值 [0,1]；行不可照护则为 0）
base = untended + c ×（tended − untended）              （tended 缺则 base = untended；两者皆缺为 0）
imm  = （immuneLevel(x, r) ≥ rules.health.immuneFull）? immune : 0     （免疫记录，R21-3.3；行无 immunity 则为 0）
drv  = 驱动项：r.driveRX 的值；亏空行取 R21-4.2 的式子；都没有则为 0
rsp  = Σ_a r.responds[a] × conc(x, a)                   （药性浓度，R21-6.2；治疗阈倍数，可大于 1）
raw  = base + imm + drv + rsp
rate = raw > 0 ? raw × worsenMult[r.family] : raw × healMult[r.family]
s'   = clamp(s + rate × Δ, 0, lethal 或 1)
```

  全部用卷二 §3.3（求值管线）的定点算术；两个倍率取修正后值；各项读数取整拍边界时刻的当前值。严重度是这条式子唯一推进的量：免疫记录与药性浓度各按自己的规则变化，不在本式里更新。照护行（`tends` 非空）没有 `perDay` 与驱动项，严重度不变，只按 `duration` 到期。
- **R21-1.3 档。** 实例所在的档 = `minSeverity ≤ s` 的最后一档；`s = 0` 的实例不落任何档，不带任何修正。档的修正经 `statusView` 进入求值管线，这是状态影响身体与行为的唯一途径。
- **R21-1.4 档效果。** 每拍对当前档的每个 `effects` 调用求值一次，幅度参数按 Δ 折算；输出交原语执行器。一个状态引出另一个状态（出血累成失血、重伤带来疼痛、极重档带来昏迷、最高档造成部位缺失）只用这一条，不写状态之间的专用规则。**写哪一行由调用方在数据里填**：凡会写状态实例的效果族都有一个"目标行"参数槽（卷末效果族表），执行器只按参数写，代码里不出现任何状态行或族的代号。档效果写出的挂部位实例，部位按调用的部位取法参数定：继承来源实例的部位（缺省）、取处置的目标实例的部位、或在叶子部位中抽取（R21-7.4）。
- **R21-1.5 结案（单点定义）。** 整拍推进后 `s' = 0` 且行不 `persistent` 的实例，由病程律结案：移除实例，此后不再推进。`duration` 到期同样移除。结案与行有没有 `immunity` 无关——免疫不寄存在实例上（R21-3.3）。`persistent` 的行在 `s = 0` 时保留但不推进，只能由事件或效果族写入再抬高。**结案之后同一行要再出现，只有三条来路：一次新的暴露（R21-3.2）、驱动量再次越过阈值（R21-1.10）、事件或效果族写入；三者都是新建一个实例。没有来路就不会复发，也不存在在 0 附近来回的实例。**
- **R21-1.6 后遗。** 实例结案或被移除时，若其存续期间到过的最大严重度 ≥ `sequela.above`，在同一部位写入 `sequela.status` 的实例。最大严重度由实例字段 `peak` 记录（§5.3 回填请求）。
- **R21-1.7 致死。** `s' ≥ lethal` 时调卷四 §4.8（死亡结算、尸体、复生点）的 `die`，死因为该状态行。本卷没有别的致死途径，也没有生命值。带终止类实例的主体不再推进其余实例，本卷各钩子对它也不再产出任何写入（§3.3）。
- **R21-1.8 整拍与拍内次序。** 推进只在绝对时间的整拍边界进行（边界时刻由 `tickMinutes` 从世界纪元起算，到期由卷二十 §4.1（刻、同刻全序、调度器与到期语义）的调度器触发），一拍恰结算一次，区间不跨拍；拍内发生的摄入、受伤、处置是事件，当刻改严重度、浓度或待判剂量。每个边界上按固定次序做七件事：① 驱动行求值并新建实例（R21-1.10）；② 对全部严重度大于 0 的实例走病程律；③ 免疫记录增长（R21-3.3）；④ 结案、后遗、致死；⑤ 档效果；⑥ 用本拍累计的剂量做暴露判定并清零待判剂量（新染上的实例从下一个边界起推进）；⑦ 回收已归零的免疫记录与低于 `concFloor` 的浓度记录。因此结果与一次推进多长、分几次推进无关。统计层与规则层的形态见 §4.10。
- **R21-1.9 四类必备行。** 卷四需要的终止类、睡眠、昏迷、妊娠四行由本卷登记（卷末代号表）。规则只读族条目的三个布尔字段；卷四经其规则表的键引用这些行。睡眠实例由睡眠动作写入与移除（动作归卷九 §4.1（动作目录）），存续期间的作用全在行数据里。
- **R21-1.10 驱动行怎样建实例（单点定义）。** "带驱动的行"= `driveRX` 非空的行，加上被某个身体需要条目指为亏空行的行。受冷、受热、淋湿、耐受、依赖、戒断、药的作用与中毒、各项需要的亏空、出血，都属于这一类，没有例外写法。在每个整拍边界（R21-1.8 第 ① 步），对求值范围内尚无实例的（主体、行；挂部位的行再加部位）组合，以 `s = 0` 代入 R21-1.2 算出 `raw`；`raw` 大于该行的 `driveOnset`（缺省 0）就以 `severity.initial` 新建一个实例，来源种类取行的 `sources`，并在同一个边界的第 ② 步起按病程律推进。此后它与任何别的实例没有区别：涨、落、致死、结案都走 R21-1.2 与 R21-1.5；结案后驱动量再越阈，就再建一个新实例。
  - **求值范围由加载期索引给出，不每拍遍历全部行**：（a）亏空行，对该身体需要适用（基准日需量大于 0）的主体；（b）引用集非空的行，只对"带有引用集内某行的实例，或在引用集内某条轴上浓度大于 0"的主体求值，挂部位的行只对有相应实例的部位求值；（c）引用集为空的行（只读主体维度、地点维度、体感），对 `hosts` 相容且式中所读主体维度都适用的主体求值。索引由行数据推出，规则代码不点名任何行。
  - 个体层与规则层按本条逐主体求值；统计层不逐个建实例，需要类按 R21-4.7 的人均亏空处理。

### 4.2 伤口、出血、感染

#### 4.2.1 维度

状态行的 `woundOf`、`bodyPart`、`sequela`、`stages`、`driveRX`（读 `woundHere`）、`persistent`；途径条目中剂量来源为伤口的那些；`person.healMult`；卷十三伤害事件的载荷（部位、伤害类型、该部位损失比例、所及组织层序）。

#### 4.2.2 统一入口

反应钩子 `onDamage`；读 `bodyView().parts`。

#### 4.2.3 规则

- **R21-2.1 伤害变伤口。** 收到伤害结算事件后，取 `woundOf` 含该伤害类型的那一行（加载期保证恰一行），在命中部位写入实例，初始严重度 = 事件给出的该部位损失比例；同部位同一行已有实例则严重度相加后钳位。本卷不重算伤害。
- **R21-2.2 伤的后果：修正在档上，出血由伤口当前的轻重决定。** 部位完好度下降、疼痛是伤口行各档的修正与档效果（R21-1.4）。**出血行是驱动行**（R21-1.10）：它挂部位，`driveRX` 读同部位的伤口总严重度 `woundHere`，把自己的严重度（出血速度）拉向"由伤口当前轻重决定的目标速度"；伤口愈合或被照护压住，出血随之停止并结案。出血速度不是对伤口档效果的累加，所以浅伤不会越流越凶。失血量才是累加量：出血行各档的档效果每拍给失血量行加严重度（目标行由参数给），失血量行自带回落（造血）并在高档压低泵血与意识。新增一种伤口行不需要改出血行，因为 `woundHere` 按字段取。
- **R21-2.3 感染走暴露律，按伤口算不按人算。** 每个伤口实例存续时，每拍为它所在的部位产生一份伤口途径的剂量：

```text
d = 伤口严重度 × 所在地点的污秽场强度 × 该途径的混合系数 × 本拍天数 ×（1 − careLevel(该伤口实例)）
```

  暴露判定的对象是（主体、行、部位）：这处伤口所在的部位已有该行实例才不再判，别的部位各判各的；染上后新实例就挂在产生剂量的那处伤口的部位。清创与包扎只压低它所照护的那一处伤口的剂量，不是个体级的倍率，也不是另一套"感染概率"。个体级的 `exposureMult` 在伤口途径上只表达全身性的因素（如体质、药浴）。
- **R21-2.4 愈合就是病程律。** 伤口行的 `untended` 可为正（无人处理会恶化）或为负（自愈）；休息、营养、年龄、床位通过 `healMult` 的修正起作用。
- **R21-2.5 断肢与残疾不可回落。** 部位缺失不挂在会回落的档修正上。伤口行最高档的档效果、截除类处置的输出，都调用"加严重度"效果族，把同一部位写成一行**部位缺失行**的实例：该行 `persistent`、没有任何 `perDay`、不可照护，它的档带"部位完好度归零"的修正，所以伤口本身愈合结案后部位仍然缺失。实例结案时另按 R21-1.6 留下后遗行。义肢是卷三登记的修正来源；再生是卷十五的效果族清除部位缺失行的实例。本卷不要求卷四增加持久写入口。
- **R21-2.6 部位合法性。** 挂部位实例的部位须在主体当前身体图内（卷四判）；无定形体只有一个部位，伤都落在它上面，规则不变。

#### 4.2.6 验收断言

- A21-2.S 扫描式：`onDamage` 的实现里伤害类型、部位、组织、物种、物品模板五类代号字面量为 0（按类型标记判，同 P21-2、P21-5）；数值字面量按 P21-6。
- A21-2.I 不变量式：每个伤害类型恰对应一行；运行态挂部位实例的部位恒是主体身体图内的具体部位（感染、出血、部位缺失的实例与产生它的伤口同部位）；对没有任何 `persistent` 实例的主体，撤销全部伤口实例后各部位完好度回到 1；带部位缺失行实例的部位，无论伤口行怎样回落，有效完好度恒为 0；同部位伤口总严重度不增的一段时间内，读它的驱动行实例的严重度不会无界上升（出血不自己累加：`woundHere` 归零后有限拍内结案）；主体身上两处伤口的感染判定互不影响（去掉其中一处的包扎，只改变那一处的剂量）。
- A21-2.X 扩展性式：卷十三新增一个伤害类型并由一行新伤口行认领，不改 `.mjs`，该类型造成的伤可出血、可感染、可愈合、可留后遗。

### 4.3 疾病与免疫、传染

#### 4.3.1 维度

状态行的 `contagion`、`immunity`、`severity.perDay`、`hosts`、`shedCurve`；`route` 族条目；材料的 `agents`；`person.exposureMult`、`person.immuneGain`；`place.crowding`；运行态的免疫记录 `immune.*` 与待判剂量 `pendingDose.*`（§2.7）。

#### 4.3.2 统一入口

`healthTick` 内的暴露判定；读 `prevalenceOf`；统计形态见 §4.10。

#### 4.3.3 规则

- **R21-3.1 暴露的四种剂量算法**（途径条目的 `doseSource`，封闭枚举）：
  - `colocated`：同一地点内带该行实例且可排出者的 `shedCurve(严重度)` 之和 × 本拍共处天数 × 该途径 `mixRX` 的值（读地点的围护开口 `aperture` 与拥挤度 `crowding`，§2.3）。
  - `ingested`：本拍摄入各物品的质量 × 其材料 `agents` 中该行的含量。摄入事件当刻不判定，只把剂量累加进待判剂量（§2.7），整拍一并判。
  - `wound`：R21-2.3，按伤口所在部位各算各的。
  - `field`：途径条目 `field` 所指环境场在主体所在地点的强度 × 本拍天数。**环境场致病只有这一条路**：场行自己的分档后果不得挂身体类状态（R21-5.7）；抗不抗只看本律里的 `hosts`、`exposureMult` 与免疫记录，不另看场行的抗性维度。
- **R21-3.2 暴露律。** 对主体 x、行 r、途径 p、部位 b（行不挂部位则为空）、本拍累计剂量 d：

```text
若 r.hosts 非空且 x 的物种分类链与之不相交 → 不暴露
若 x 在部位 b 上已带 r 的实例（不挂部位的行：x 已带 r 的实例） → 不判定
p_get = 1 − exp(−d × r.contagion.rate × exposureMult[p] ×（1 − immuneLevel(x, r)）)
u     = 骰值键抽取（成分见 R21-3.6）
u < p_get → 新建 r 的一个实例（挂部位的行挂在 b），严重度取 severity.initial，来源记途径所属的来源种类
```

  指数用卷二 §1.10（随机实例化）的定点指数表。一拍内同一组合只判一次，用的是这一拍各来源剂量的合计，所以"一口吃完"和"分两口吃"得到同一个概率、同一个骰值。
- **R21-3.3 免疫记录（单点定义）。** 免疫不是状态实例，也不是实例上的字段，而是 `immune.<主体>.<状态行>` 上的一条独立记录 `{level, asOf}`，不走病程律。它的值由下式惰性读出，写入只有三个时机：

```text
immuneLevel(x, r, 此刻 t)：
  没有记录                      → 0
  x 此刻带 r 的任一实例          → level
  否则                          → max(0, level + r.immunity.perDayNotSick ×（t − asOf 的天数）)

写入时机：
  ① 暴露判定命中、新建实例的当刻：level := immuneLevel(此刻)，asOf := 此刻       （把已衰减的值落下来，没有记录则建一条 level = 0）
  ② 每个整拍、x 带 r 的任一实例时：level := min(1, level + perDaySick × immuneGain × Δ)，asOf := 该边界   （每个（主体、行）一拍只加一次，不按实例个数重复；实例不是经暴露建的、还没有记录时，先建一条 level = 0）
  ③ x 身上 r 的最后一个实例结案的当刻：asOf := 此刻                               （从这一刻起按 perDayNotSick 衰减）
读出为 0 的记录在下一个整拍被回收（R21-1.8 第 ⑦ 步）；回收不改变任何读数。
```

  病与免疫赛跑由此得出：患病期间记录按 `perDaySick × immuneGain` 增长；到 `immuneFull` 后病程律的 `immune` 项生效，严重度开始回落，回到 0 即结案（R21-1.5）。在那之前先到致死值的主体死去。老、幼、营养差的主体 `immuneGain` 低，所以更容易死，这不是另写的年龄死亡率。
- **R21-3.4 免疫记忆与再感染。** 结案之后实例已不存在，留下的只有免疫记录，它按 `perDayNotSick` 自己衰减；衰减快的行可以反复得，`perDayNotSick` 为 0 的行终身免疫。**再得一次只能经一次新的暴露**：暴露律用衰减后的免疫值折减概率，命中则新建一个实例，新实例的免疫从记录的现值接着涨（所以再感染通常更轻、更短）。免疫记录本身不产生任何严重度，没有暴露就永远不会复发。
- **R21-3.5 人畜共通与隔绝。** 一行的 `hosts` 同时含两类分类位置时两类主体互相传染；隔离、面罩、净水、驱虫都是对 `exposureMult` 某途径的修正，作用域取所在地点或法域。
- **R21-3.6 抽取键（本卷全部抽取点在此一处列全）。** 键的五段按卷二十七 §4.8（种子键与骰值键（确定性约束与验收））：（世界种子、流代号、主体段、世界时刻、抽取点代号）。键里不含计数器、存档序号、事件序号、登记序；"针对某主体上的某一条"时，把条目的代号并入主体段成为复合主体（与卷二十 §4.1（刻、同刻全序、调度器与到期语义）同一做法）。

  | 抽取点 | 主体段（复合） | 世界时刻 | 为什么不撞键 |
  |---|---|---|---|
  | 暴露判定 | 主体 + 状态行代号 + 途径代号 + 部位代号（无则空） | 所判那一拍的边界时刻 | 一拍内同一组合只判一次（剂量先合计） |
  | 给药估重、给药估含量（两个抽取点） | 施行者 + 病人 + 处置行代号 + 目标轴代号 | 处置动作完成时刻 | 同一施行者同一时刻只完成一个动作 |
  | 诊断误认 | 施行者 + 病人 + 目标实例的行代号与部位代号 | 处置动作完成时刻 | 同上 |
  | 处置结果 | 施行者 + 病人 + 处置行代号 + 目标实例的行代号与部位代号 | 处置动作完成时刻 | 同上 |
  | 叶子部位抽取 | 主体 + 来源实例的行代号 + 目标行代号 | 该拍边界时刻 | 一拍一行一次 |
  | 统计层进位 | 聚合体 + 状态行代号 + 流向代号（染病、痊愈、病死、失去免疫） | 该层的拍边界时刻 | 一拍一流向一次 |
  | 实体化抽取 | 成员主体 + 状态行代号 | 单元由粗变细的切换时刻 | 每个成员各一次，取值最小的若干人 |
- **R21-3.7 只判有来源的行。** 每拍只对"本拍剂量大于 0"的（主体、行、途径、部位）组合判定；剂量由来源方索引给出，不遍历全部行。

#### 4.3.4 交互

- 卷二十 §4.6（水循环与水量）与卷二十 §4.7（环境场与排放衰减）：水体里的污染物材料余额、病媒与污秽场强度。
- 卷三 §4.12（腐坏与保质）：腐坏档上的材料修正可抬高 `agents`；吃下去走摄入事件。
- 卷五、卷八 §4.16（人口统计层）：读 `prevalenceOf`。卷四：`die`、物种分类链。
- 通道：事件（染病、痊愈各发一个动词）。

### 4.4 营养与缺乏症

#### 4.4.1 维度

`body_need` 族（含 `needRatio`）；`person.needRecover`；卷四的代谢三率（基值与修正后值都读）、体力消耗倍率、`fatKg`；卷三的营养组（`nutrients`、`energyDensity`、`hydration`）与营养素词表（条目带所属身体需要代号）；`rules.health.fatSatietyPerKg`。

#### 4.4.2 统一入口

反应钩子 `onConsumed`；读 `personView().health.needs`。

#### 4.4.3 规则

- **R21-4.1 需要是亏空行；三个量先说清。** 每个身体需要条目 n 对应一个亏空行。对主体 x：

```text
基准日需量 D0 = 条目 needDim 所指个体维度的基值 × needRatio          （基值 = 卷四按物种、体重、阶段派生出的值，未经修正）
当前日需量 D  = 同一维度的修正后值 × needRatio                       （劳作、行军、寒冷、妊娠的修正都已在内）
储备量     R  = D0 × reserveDaysRX 的值                              （这项需要"欠满"是欠多少）
严重度     s  = 已欠量 ÷ R
D0 = 0 → 这项需要对 x 不适用：不建实例、不求值、不报错（§2.8）
```

- **R21-4.2 消耗：增长率与日需量成正比（单点定义）。** 亏空行的驱动项不写在状态行上，由规则从条目算出：

```text
drv =（D − needRecover_x[n] × D0）÷ R
```

  无修正、无回补时 `drv = 1 ÷ 储备天数`；日需量被修正到 1.3 倍，亏空就涨得快 1.3 倍。劳作、行军、寒冷、高热都**只通过修正日需量**起作用——修正挂在卷四登记的个体维度上（卷四 §4.7（代谢）的三率、卷四 §4.6（步态、移动、负重）的体力倍率、本卷冷热行的档修正），本卷不另写活动消耗，也没有第二个进入亏空的入口。亏空行按 R21-1.10 建实例：`drv` 为正且尚无实例时新建，之后走同一条病程律。
- **R21-4.3 补给有两种，都不认状态族。**
  - 摄入：摄入事件到来时，对物品里每种营养素所归属的需要（营养素条目上的所属需要代号）：供给量 = 摄入质量 × 该物品中归属此需要的营养量（按卷三的份额加权读出）；严重度当刻减 `供给量 ÷ R`。
  - 回补：`person.needRecover[n]` 大于 0 时，驱动项里多出一项 `−needRecover × D0 ÷ R`。睡眠、休息怎样回补哪项需要，写成那些状态行的档修正（以 `needRecover` 的某个键为目标）；规则只读这个个体维度，不需要认出"哪个实例算睡眠"。
- **R21-4.3b 缺量后果只走一条通道。** 吃不饱、喝不够的身体后果只有一个来处：亏空行自己的档（R21-4.5）。卷六 §4.12（家户预算与日耗）结算出的缺量，体现为成员实际摄入的减少（个体层是少了摄入事件，统计层是 R21-4.7 的供给不足），亏空按 R21-4.2 自己涨上去。因此归属身体需要的用度类，其缺量后果里不得再给身体类状态加严重度（否则同一顿没吃到的饭被算两次，校验见 R21-5.7）。取暖、衣着一类用度的缺量同理不直接写身体：缺柴使温度场变冷，缺衣使保暖合计变小，受冷行由 R21-1.10 自己出现。
- **R21-4.4 溢出与转存。** 亏空到达 1 仍继续消耗时，超出部分按同一折算加到 `overflowTo` 所指需要的亏空上；补给使亏空低于 0 的部分，乘 `storeEfficiency` 后先减少 `overflowTo` 的亏空，再有剩余则加到 `excess` 所指的过量行。短期的饱腹与长期的体内储备因此是同一机制的两级。
- **R21-4.5 缺乏症是亏空行的高档。** 缺乏的后果（乏力、夜盲、伤口不愈、致死）是亏空行各档的修正与档效果；微量营养的储备天数长，所以是数周到数月的慢变量。微量营养不另设日需量维度：它的日需量 = 基础日需量 × 条目的 `needRatio`，所以吃得多的大个子需要的也多，分子（营养素的量）与分母（该营养素的日需量 × 储备天数）单位一致。
- **R21-4.6 储备由身体算。** 能量的长期储备天数 = 脂肪组织质量 × `fatSatietyPerKg` ÷ 基准日需量（式中用 `need0`，不用修正后值，所以受冷不会让"储备量"变小，只让它耗得快）；脂肪质量由卷四的体重与组织份额给出。胖的、大的、代谢慢的主体饿得久，不需要逐物种填"能饿几天"。
- **R21-4.7 群体与饥荒。** 统计形态下，聚合体的每项需要只存"人均亏空"一个聚合维度：每拍增长取成员当前日需量与基准日需量的人均比（R21-4.2 同式），供给取家户与聚落的口粮结算（卷六 §4.12（家户预算与日耗））实际满足的量，折算式同 R21-4.3。"饥荒"不是另一种状态，也不按日历来：它就是一地的人均亏空高；需要一个世界事件时，由事件类型行的触发式读人均亏空越阈（同 R21-10.6 的做法）。现灾害日历里的饥荒时刻由此接收（§7 M21-14b）。

#### 4.4.4 交互

- 卷三 §4.1（材料属性表）：营养值在物上；营养素词表条目由卷三登记、所属需要代号由本卷给（卷三开放问题 Q-12 由此答复：见卷末代号表）。
- 卷四 §4.7（代谢）：三率与可食判断。卷二十五 §4.9（烹饪酿造）：烹饪折损改的是材料行。
- 卷二十六 §4.4（想法与心情）：饥渴困乏触发想法。卷六：家户口粮结算读日需量之和。
- 通道：事件订阅（摄入）、原语执行器。

#### 4.4.6 验收断言

- A21-4.S 扫描式：`.mjs` 中无身体需要、营养素、食物类别的代号字面量（P21-2 同法）；数值字面量按 P21-6（卷一 R-6（常数只在规则表）的白名单），不另列"消耗常数"一类人眼判据；写亏空行严重度的调用点只有两类——病程律推进与摄入补给（按执行器的输出来源代号计数），没有第三个入口。
- A21-4.I 不变量式：基准日需量为 0 的主体没有任何亏空实例；其余不变时，亏空行每拍的增长量与当前日需量成正比（日需量修正到 k 倍，增长量恰为 k 倍）；任一摄入事件前后，各级亏空的折算总量之差等于供给量乘以相应效率（不凭空多补、不凭空丢失）；亏空对摄入单调不增；同一次缺量只被计一次（卷六结算的缺量事件前后，除摄入减少外没有别的对亏空行的写入）。
- A21-4.X 扩展性式：新增一种营养素与一项身体需要条目及其亏空行，不改 `.mjs`，缺它的主体按储备天数出现缺乏档。

### 4.5 过敏、食性、寄生虫、中毒

#### 4.5.1 维度

材料的 `pharm`、`agents`；`person.sensitivity` 与物种的敏感度分布；药性轴条目；状态行的 `hosts`、`contagion`；卷四的可食判断。

#### 4.5.2 统一入口

同一个 `onConsumed`。本节没有自己的入口。

#### 4.5.3 规则

- **R21-5.1 一条摄入律。** 任何物品经任何途径进入身体，只发生三件事：补需要（R21-4.3）、加药性浓度（R21-6.2）、累加待判的病原剂量（R21-3.1 的摄入算法，整拍判定）。食物、饮水、药、毒、腐肉、脏水不分种类，也没有任何"这东西不让吃"的闸：能不能吃只有卷四的可食判断与行动者自己的决策。
- **R21-5.2 毒是药性。** 有毒 = 材料在某个药性轴上有含量，而有一行状态在 `driveRX` 里读该轴的浓度或过量比、带伤害性修正并可致死（中毒行，R21-6.5）。毒性大小、解毒、耐毒都落在同一组数据上；投毒与服药是同一个给药动作，差别在意图的形态（R21-6.3 的第二种）与是否经同意（罪名归卷八b）。
- **R21-5.3 过敏是敏感度。** 个体对某药性轴的 `sensitivity` 是卷四按物种分布采样并存储的身体特质，本卷只读；远高于 1 的个体，常人无感的剂量就使该轴浓度达到治疗阈的几十倍，远过过量阈值。浓度不受 1 的上限约束，所以"重"与"致死"之间分得出层次。过敏原只是在某个轴上有含量的材料。不设过敏名单。
- **R21-5.4 食性不合。** 物种吃不了的东西由卷四的可食判断拦在动作前置；被迫或误食时仍走摄入律，后果由物种级敏感度决定（某物对一类物种有毒、对另一类无害）。
- **R21-5.5 寄生虫与食物中毒是经口的病。** 它们是带经口途径的疾病行；生肉、脏水的 `agents` 含量高，加热、冷冻、腌制后的材料行含量低（卷三以继承写法登记的熟制材料行）。厨师技能与清洁影响的是成品品质档与场所污秽，经已有管线进入含量与暴露倍率。
- **R21-5.6 污染，以及脏水能喝下去。** 环境里的污染物是材料余额（卷二十 §4.6（水循环与水量））；饮用被污染的水时，污染物材料按其份额带入自己的 `pharm` 与 `agents`，后果走摄入律。现有的饮水安全闸（带毒素、病原或浑浊即拒绝饮用）与液体上的两个布尔污染标记全部删除：喝不喝是卷九的决策，决策者经 `treatmentPreview` 或材料含量的知情（卷二十二）估计风险；不知情的人照喝，然后得病。
- **R21-5.7 别处不得绕过摄入律与暴露律直接写身体（校验码 E-MED-FIELD-BODY）。** 三个别卷的挂载点——环境场行的分档后果（卷二十 §4.7（环境场与排放衰减））、腐坏档的食用后果（卷三 §4.12（腐坏与保质））、用度类条目的缺量后果（卷三 §4.3（物品类别与用度类（九维）））——都只许调用本卷的摄入效果族与暴露效果族，不得出现身体类状态行，也不得调用本卷其余效果族。于是：致病的场只经 `field` 途径走暴露律（R21-3.1），带药性或毒性的气体由场行的档调用摄入效果族、把所携材料按吸入量交给摄入律；腐坏只通过抬高材料的 `agents` 与 `pharm` 起作用，吃下去只算一次；缺量见 R21-4.3b。对应的三条回填请求在 §5.3。

#### 4.5.4 交互

- 卷三 §4.12（腐坏与保质）与卷三 §4.8（配方通用规则）：腐坏档与熟制改变材料量。卷二十五 §4.9（烹饪酿造）：配方行。
- 卷四 §4.7（代谢）：可食判断。卷八b §4.1（规范栈与法典条目）：投毒的定性。
- 通道：事件订阅（摄入）。

- 【超自然】食腐的洞穴爬行种：其分类位置不在肠虫行与腐败病行的 `hosts` 内，吃腐肉不暴露；这是行数据，不是"食腐免疫"分支。

#### 4.5.6 验收断言

- A21-5.S 扫描式：事件订阅登记表中，摄入事件（`consume`）归本卷的订阅者恰为 1 个；该订阅者的实现内 P21-2、P21-5 命中 0（没有以物品类别、材料、物种的代号做的分支）；饮用、进食动作的前置条件里不出现读 `pharm`、`agents` 或污染标记的拒绝分支（旧安全闸归零，逐处见 §7 M21-24）；别卷三个挂载点按 E-MED-FIELD-BODY 加载期校验，命中 0。
- A21-5.I 不变量式，分确定部分与概率部分两条：
  - （确定部分，逐量比较）同一拍内把一件物品拆成两半分两次摄入，与一次摄入相比：各轴浓度在该拍边界的读数之差只来自两次摄入之间的清除量（两次同刻摄入则完全相等）；各亏空行的折算总量相等；待判剂量的合计相等。敏感度为 0 的轴浓度增量为 0。
  - （概率部分，在公式层核对，不比较抽签结果）对定点指数表的全部表点：两份剂量 d1、d2 各自的未中概率之积，等于合并剂量 d1 + d2 的未中概率（差不超过定点末位）。又因一拍内同一组合只判一次、用的是合计剂量，拆与不拆在同一种子下得到同一个骰值与同一个结果，此项可逐例比较。
- A21-5.X 扩展性式：新增一种材料（带一条新药性轴的含量）与该轴条目及读它过量比的一行中毒行，不改 `.mjs`，吃下它的主体浓度上升、过量者出现中毒行的相应档，敏感个体更重。

### 4.6 药物与成瘾

#### 4.6.1 维度

`pharm` 族条目全部字段（`refDose`、`massExp`、`bio`、`clearPerDay`、`overdoseAt`、`better`）；材料的 `pharm`；`person.sensitivity`（卷四登记，本卷只读）；运行态的浓度记录 `conc.*`；`rules.health.doseLevels`、`doseErrorCurve`、`concFloor`；状态行的 `responds` 与读浓度的 `driveRX`；处置行的 `route`。

#### 4.6.2 统一入口

`onConsumed`（任何摄入）；`onTreat`（由医者给药）；预览 `treatmentPreview`。

#### 4.6.3 规则

- **R21-6.1 药效不是字段。** 一件物品"是什么药、有多强"只由它的材料在各药性轴上的含量决定（按份额加权；成品品质的影响已由卷三 §4.5（品质档）的品质表作用在含量上，方向读轴条目的 `better`，本卷不另乘）；制剂由配方从药材得到，含量随产物继承。本卷没有"治疗某病的物品"清单，也不按物品类别判断"是不是药"。
- **R21-6.2 药性浓度（单点定义）。** 浓度是主体在一条药性轴上的一个独立的量，存在 `conc.<主体>.<药性轴>`，**单位是治疗阈的倍数**：1 = 刚达到起效的浓度，可以大于 1，没有上限。它不是状态严重度，不钳位，不走病程律。质量为 m 的物品经途径 p 进入主体 x，对它含有的每条药性轴 a：

```text
Δconc_a = m × pharm_a(物品) × bio_a[p] × sensitivity_x[a] ÷（refDose_a × massKg_x ^ massExp_a）
摄入当刻：value := conc(x, a, 此刻) + Δconc_a；asOf := 此刻
conc(x, a, 此刻 t) = value × exp(−clearPerDay_a ×（t − asOf 的天数）)          （惰性读出，指数用定点指数表；没有记录为 0）
读数低于 rules.health.concFloor 的记录在下一个整拍被回收，回收后读数为 0
```

  `refDose` 的含义随之固定：使浓度恰为 1 倍治疗阈的每公斤体重剂量。有用的轴与有害的轴同时进入，副作用因此不需要另写。
- **R21-6.3 给药量由意图与技能定。** 医者（或自己）给药时，意图有两种形态，槽位都是数据：
  - 形态一，针对一个状态实例：槽位为目标实例、物品、剂量档。目标轴 a* = 在医者**所认定**的状态行（R21-8.2）的 `responds` 里，该物品能提供的、使病程项最负的那条轴。
  - 形态二，直接指定一条轴：槽位为目标轴、物品、剂量档。为了药性本身的作用而用（镇痛、提神、助眠）、给没有目标病的人用、投毒，都是这一种；它不需要诊断。
  - 途径 p 取所用给药类处置行的 `route`，不由代码推断。剂量档可取 `excess`，目标就越过过量阈值。

```text
目标浓度 = 1 + 剂量档比例 ×（overdoseAt_a* − 1）                    （剂量档比例读 rules.health.doseLevels）
M̂ = massKg_x × exp(σ × z1)                                        （医者对病人体重的估计）
Ĉ = pharm_a*(物品) × exp(σ × z2)                                   （医者对这件药材含量的估计）
m = 目标浓度 × refDose_a* × M̂ ^ massExp ÷（Ĉ × bio_a*[p]）
σ = lookup(rules.health.doseErrorCurve, 该处置行所属服务的技能的值)；z1、z2 为两次独立的标准正态抽取（键见 R21-3.6）
```

  真正进入身体的浓度仍按 R21-6.2 用病人的真实体重、药材的真实含量、病人的真实敏感度算。所以：药材决定每克里有什么；技能决定体重估得准不准、药材成色看得准不准、病认得对不对；意图决定冲着哪个病或哪种作用、下多重的手。零技能的人不会自动按体重折算：把孩子估成大人、把陈药当新药，都是 σ 大的结果。认错了病，目标轴就错；病人的敏感度医者并不知道，过敏者照常量也会出事。`treatmentPreview` 取 σ = 0。
- **R21-6.4 浓度只经两条路起作用。** 对某个状态的作用 = 病程律里的药应项（`responds` × 浓度）；对身体能力、心情、属性的作用 = 读该轴浓度的驱动行各档的修正（R21-6.5）。除此之外药不改变任何东西。
- **R21-6.5 作用、中毒、耐受、依赖、戒断都是驱动行。** 它们是在 `driveRX` 里读 `conc(<轴>)` 或 `over(<轴>)` 的普通状态行，严重度仍在 [0,1]，按 R21-1.10 在驱动量越阈时建实例、按病程律推进与结案：作用行把自己拉向"由浓度决定的目标值"，它的档给镇痛、镇静、兴奋等修正；中毒行由过量比驱动上升、自带回落、可致死；耐受行由浓度驱动上升，它的档给该轴的 `sensitivity` 负修正；依赖行由浓度驱动上升、停用后缓慢回落；戒断行的驱动项在"依赖高而浓度低"时为正。轴条目不指向它们，关联由引用集得出。渴求是卷二十六读依赖与戒断实例触发的想法。
- **R21-6.6 过量（阈值的唯一定义处）。** 一条轴的过量阈值只有一个数：药性轴条目的 `overdoseAt`（治疗阈倍数，大于 1）。过量 ⇔ `conc > overdoseAt` ⇔ `over(<轴>) > 0`。剂量档的"1"、行数据里的 `over()`、预览与决策对"会不会过量"的判断，读的都是这一个数；状态行的档阈值是严重度上的阈值，与它无关，两者不需要互相对齐。任何行数据或规则表键不得再写第二个过量数（E-MED-PHARM-SHAPE）。没有单独的过量判定流程。多种药叠加时，同一轴的浓度相加，不同轴各自驱动各自的行，相互作用由各档修正在求值管线里按叠加规则合成。
- **R21-6.7 违禁不归本卷。** 本卷只提供药性轴维度与条目字段；某法域禁哪些，是法典条目按物品类别或药性含量写的谓词（卷八b §4.1（规范栈与法典条目））。同一物在两地合法性不同，本卷的规则不变。

#### 4.6.6 验收断言

- A21-6.S 扫描式：`.mjs` 中物品 id、材料 id、药性轴代号字面量为 0（P21-2、P21-5）；规则表里没有"物品 → 治疗量"一类的映射：P21-2b 命中 0，即归本卷的规则表键中不出现实体或行引用类型的值（现 `medicine.takeHome` 是它要清掉的实例，§7 M21-23）；"是不是药"的判断不读物品类别（读 `categories` 的调用点不在本卷三个文件内）；`overdoseAt` 之外不存在第二个过量阈值（E-MED-PHARM-SHAPE 加载期校验命中 0）；P21-9 命中 0。
- A21-6.I 不变量式：同一物品同一途径，浓度增量与给药质量成正比、与体重的 `massExp` 次方成反比；浓度读数恒 ≥ 0、不受 1 的上限约束，两次摄入之间按清除率单调不增；任一状态实例（含作用行、中毒行）的严重度仍在 [0,1]；技能升高时给药量的离散度单调不增，σ = 0 时给药量恰使真实浓度等于目标浓度（敏感度为 1 时）；剂量档升高时目标浓度单调不减，剂量档比例为 1 时目标浓度恰等于 `overdoseAt`；药性含量为 0 的物品不改变任何浓度；`over()` 大于 0 当且仅当浓度大于 `overdoseAt`。
- A21-6.X 扩展性式：新增一味药材（材料行，两条已有轴的含量）不改 `.mjs` 即可被采集、入药、给药、起效与中毒；新增一条带依赖的药性轴及其作用、中毒、耐受、依赖、戒断五行，不改 `.mjs`、轴条目上不写任何指向它们的字段，即出现起效、过量中毒、耐受与戒断。

### 4.7 环境温度伤害

#### 4.7.1 维度

物种的 `coreTempC`、`coolingC`（卷四登记）；个体的 `selfHeatC`、`coldLimitC`、`heatLimitC`；卷三的材料 `insulation` 与穿着合计 `warmthTotal`；卷二十的体感温度；`rules.health.thermal`。

#### 4.7.2 统一入口

读 `personView().health.thermal`；冷热行的推进在 `healthTick`。体感温度只读卷二十 §4.5（温度量纲与热交换）的 `feltTempC`。

#### 4.7.3 规则

- **R21-7.1 耐受区间由身体与衣着算出，不手填。**

```text
selfHeatC  = lookup(thermal.selfHeatCurve, massKg) × 物种代谢倍率      （可修正：劳作、颤抖、进食提高它）
coverC     = Σ 层序 ≤ thermal.coverDepth 的组织，其材料的 insulation
clothC     = warmthTotal × thermal.cPerWarmth
coldLimitC = coreTempC − selfHeatC − coverC − clothC
heatLimitC = coreTempC − selfHeatC × thermal.heatFraction + coolingC − thermal.trapFactor ×（coverC + clothC）
```

  体大、代谢高、毛厚、穿得多的主体耐寒；同样这些使它怕热。`coreTempC` 为空的物种不适用，本节两类行对它不驱动。
- **R21-7.2 冷热是驱动行。** 受冷行的 `driveRX` 读 `coldLimitC − felt` 的正部，受热行读 `felt − heatLimitC` 的正部，各乘行上的系数并减去回落项；越界越多、时间越长，严重度越高。档上的修正降低操作、移动、意识，极重档致死。它们何时出现，就是 R21-1.10：每个整拍求值，驱动量越过新建阈值即建实例；体感回到区间内后严重度回落到 0 即结案。没有"进入寒冷地点时挂状态"之类的专门入口。
- **R21-7.3 淋湿。** 淋湿同样是驱动行：`driveRX` 读卷二十提供的降水暴露量，即所在地点的 `env.precipMm × skyExposure`（卷二十 §4.5（温度量纲与热交换）规则 5），减去干燥回落项。**它不进体感公式**（该式明确不含淋湿）。淋湿的作用写在本行各档的修正上：以穿着中、材料吸水的衣物的 `item.warmth`（卷三 §4.13（服装分层与护甲物性）提供的修正键）为目标的负修正，使 R21-7.1 的 `clothC` 变小、耐寒下限升高，于是同样的天气下受冷行更早出现。三卷的分工由此闭合：卷二十只给暴露量，卷三只给修正键，状态与修正由本卷的这一行给。修正要指向"主体穿着的物品"，卷二现有作用域里没有这一种，见 §8 Q-13。
- **R21-7.4 冻伤与热伤。** 受冷行高档的档效果调用"加严重度"效果族，目标行填冻伤行，部位取法填"在叶子部位中抽取"：候选是主体身体图里没有子部位的部位，权重为各部位 `sizeFraction`（卷四 §4.2（身体部件图与肢体能力））的倒数（越小的末端越先冻），由骰值键抽取（R21-3.6）。火焰、沸水造成的烧烫伤是伤害类型，走 R21-2.1。
- **R21-7.5 冷热改变需要。** 受冷行与受热行的档修正以日需量为目标（冷时多耗能、热时多耗水）；亏空的增长率与日需量成正比（R21-4.2），所以冷天确实饿得快，不另写。
- **R21-7.6 物品自身的冷热**（结冰、熔化、烧毁）归卷三，读地点温度而非体感。

### 4.8 医疗诊治与手术质量

#### 4.8.1 维度

`procedure` 族全部字段（技能经 `service` 条目的 `skill` 取，处置行不带）；状态行的 `signs`、`obscurity`、`tendable`；过程槽 `process.treatQuality`（登记到卷二 §3.7（旧派生槽的对照与过程主体槽）的过程槽表）；`rules.health.qualityCurve`、`outcomeSpread`、`obscurityScale`；卷末效果族表的参数槽。

#### 4.8.2 统一入口

动作"处置"在卷九 §4.1（动作目录）登记一行，槽位为处置行代号、病人、目标实例（可空）、目标轴（可空，给药的第二种意图形态）、物品、剂量档；给药途径不是槽位，取处置行的 `route`；完成时调 `onTreat`。预览 `treatmentPreview`、可选项 `careOptions`。

#### 4.8.3 规则

- **R21-8.1 谁都可以动手；"自己动手"与"作为服务提供"是两件事。**
  - 自己动手（给自己、给同伴、给牲口处置）：能否施行只看处置行的需求块是否满足（器械能力、耗材类别，卷三 §4.7（需求块（内容与用法）））、施行者 `can()` 是否通过、病人或其监护方是否同意（效果族的同意字段）。没有"医者"身份判断，也没有技能门槛；技能低的人也能做，只是质量低，可能做坏。
  - 作为服务对外提供（挂牌、收诊费、进排期）：是否够格只调卷十四 §4.1（职业维度表与服务词表）的唯一谓词 `canOffer(个体, 处置行的 service, ctx)`，本卷不另写一套判据（R21-11.2）。
  - 处置用哪项技能，取处置行 `service` 条目的 `skill`，处置行自己不带技能字段；难度 `difficulty` 是处置行的字段，只进质量曲线，不作门槛。台账 S-04 "需求块里写技能阈值"与此不同，修改请求见 §5.3。
- **R21-8.2 诊断。** 诊断是一行处置（`outputs` 为知情写入）。对目标实例的状态行 r，诊断质量取 R21-8.3 的 q：

```text
q ≥ r.obscurity ÷ rules.health.obscurityScale → 认定为 r
否则：候选 = 除 r 以外、与 r 至少共有一个体征的状态行；按共有体征数加权抽取一行作为认定结果（骰值键，R21-3.6）
      候选为空 → 没有认定结果（"看不出是什么"），不写知情
```

  认定结果是施行者的一条知情，存取归卷二十二 §4.1（主观视图）。`needsDiagnosis` 的处置读施行者的认定；没有认定则不可施行。
- **R21-8.3 处置质量。**

```text
技能值 = 施行者在该处置行 service 条目的 skill 上的有效值（卷十四 §4.3（技能与熟练））
Q0 = lookup(rules.health.qualityCurve, 技能值 − difficulty)
Qm = Π_k lookup(term_k.curve, 需求块第 term_k.group 组实际所用物品的 term_k.dim)
Q  = clamp(modified(process.treatQuality 基值 Q0 × Qm), 0, 1)
q  = clamp(Q ×（1 + outcomeSpread ×（1 − Q）× t), 0, 1)        （t 为 [−1,1] 上的三角分布抽取，骰值键）
```

  施行者自身的操作与视觉能力、醉酒与疲劳，场所的照明、洁净、床位，器械品质，都是以该过程槽为目标的修正项，由各自的来源登记；本卷不逐项写。
- **R21-8.4 结果。** `q ≥ botchBelow`：以 q 为幅度参数求值 `outputs`（降低目标实例严重度、写入照护实例、给药、把部位写成部位缺失行等）；否则求值 `failure`（新的伤口、一次以场所污秽为剂量的伤口暴露等）。每个调用写哪一行、走哪条途径，都由处置行的数据在效果族的参数槽里填（目标行、途径、部位取法，见卷末效果族表）；执行器不认识任何状态行。耗材在两种结果下都消耗（经账本转入消耗汇）。
- **R21-8.5 手术是难度高的处置行。** 取出异物、截肢、接骨、剖产、植入都是数据行，差别在难度、需求块、材料物性项与后果。材料物性项使"用什么线缝、用什么板固定、用什么布包"有实际差别。
- **R21-8.6 可以对谁做什么是算出来的。** 某实例的可用处置 = 其族在 `aimFamilies` 内且行 `tendable` 的处置行；`careOptions` 给出此集合。新病自动可被已有的通用处置照护。
- **R21-8.7 报错只用代号。** 不可施行的原因返回错误码与需求块的缺项代号，不产生文字；排期冲突、路线不通、付不起诊费各归其卷的错误码。

#### 4.8.4 交互

- 卷十四 §4.3（技能与熟练）：技能值与成长（施行处置给熟练度由该卷订阅事件）。卷三 §4.7（需求块）与卷三 §4.6（工具能力）：器械能力与耗材。
- 卷二十二 §4.1（主观视图）：诊断认定的存取。卷九 §4.12（NPC 决策管线）：用 `treatmentPreview` 评估是否求医、用哪种处置。
- 卷二十六 §4.5（压力累积与崩溃）：发作容器若标为可照护，同样进入 `careOptions`。卷六：诊费是服务交易。
- 通道：动作、原语执行器、账本（耗材）、事件。

#### 4.8.6 验收断言

- A21-8.S 扫描式：技能 id 字面量为 0（现写死的医疗技能常数退役）；职位、设施名称的文字比对为 0；报错文字正则为 0。
- A21-8.I 不变量式：其余不变时 Q 对技能值单调不减、对难度单调不增、对每个材料物性项单调不减；`q < botchBelow` 时不求值 `outputs`；耗材消耗在账本上逐笔守恒；一次处置写出的每个状态实例，其行恰是该处置行数据里某个调用的目标行参数（执行器不会写出数据没点到的行）；诊断的认定结果不等于目标行本身时，必与目标行至少共有一个体征。
- A21-8.X 扩展性式：新增一行处置（新的需求块与一项材料物性）不改 `.mjs` 即可被施行并进入 `careOptions`；新增一项技能并让某处置行指向它，不改 `.mjs`。

### 4.9 照护与康复

#### 4.9.1 维度

照护行（`tends` 非空的状态行；`duration` 给有效期）；照护实例的 `quality` 字段；`person.healMult`、`person.worsenMult`；状态行的 `tended`、`sequela`；`rules.health.careMatch`。

#### 4.9.2 统一入口

`personView().health.careNeeds`；照护实例由处置的 `outputs` 写入。

#### 4.9.3 规则

- **R21-9.1 照护水平（单点定义）。** 照护行 = `tends` 非空的状态行，按这个字段认，不按族认。照护实例上有一个专门的数 `quality`（取值 [0,1]），由"写入照护"效果族在写入时置为那次处置的质量 q，此后不变；它不是严重度，照护实例的严重度恒为行的 `initial`，不表示轻重，也不乘好转或恶化倍率。

```text
careLevel(x, i) = max { c.quality | c 是 x 身上的照护实例，c 的行的 tends 含 i 所属的族，且 c 的部位与 i 相同 }；没有这样的 c 则为 0
（i 不挂部位时要求 c 也不挂部位）
```

  照护水平在照护实例存续期间恒定，不随时间走低；质量低的包扎护得差，但不会失效得更快。
- **R21-9.2 照护会过期。** 照护行用 `duration` 给出有效期，到期由调度器移除（R21-1.5），需要重新处置。换药间隔、每日探视因此由行数据的有效期给出。同一处在有效期内再次处置：新实例的 `quality` 更高则替换，否则只刷新有效期。
- **R21-9.3 休养条件是修正。** 卧床、床铺品质、洁净、保暖、饱足通过 `healMult` 与 `worsenMult` 的修正起作用（来源：睡眠行的档、设施类型行的服务效果、亏空行的档）。本卷不写"在医馆里好得快"的规则。
- **R21-9.4 失能者的需要。** 不能行动的主体不能自己进食饮水；照护者以给予动作完成摄入（走同一摄入律）。无人照护时亏空照常上升，这就是重病无人管会死的原因。
- **R21-9.5 康复与后遗。** 后遗行（R21-1.6）可以是 `untended` 为 0、`tended` 为负的行：只有持续的康复处置才使它回落。永久残疾是两者皆为 0 的行。
- **R21-9.6 求医是决策。** 是否求医、谁去照护不是本卷的规则：卷九的决策管线读 `critical`、`careNeeds` 与 `treatmentPreview`，卷十八的关系决定谁愿意照护。本卷只保证这些读数存在。

#### 4.9.4 交互

- 卷十九 §4.2（设施类型表）：床位与洁净作为设施类型行的服务效果。卷九 §4.12（NPC 决策管线）、卷十八：谁照护。
- 卷二十六：久病、照护他人触发的想法。通道：原语执行器。

#### 4.9.6 验收断言

- A21-9.S 扫描式：读照护实例 `quality` 字段的调用点只在 `careLevel` 一个函数内（与 P21-1 同法，按字段访问的静态位置计数）；本卷三个文件内对 `facilityTypeView`、`professionView` 的调用只出现在 `careOptions` 的地点过滤里，病程律与照护水平的实现不调它们；实现里没有任何族代号字面量（照护行按 `tends` 字段认，P21-2）。
- A21-9.I 不变量式：照护水平 ∈ [0,1]；照护实例存续期间其照护水平不变；照护实例移除后同拍起病程按 `untended`；其余不变时病程对照护水平单调不增；任一照护实例的严重度恒等于其行的 `initial`；一处部位的照护不改变另一处部位任何实例的照护水平。
- A21-9.X 扩展性式：新增一行照护行与写入它的处置行，不改 `.mjs`，其 `tends` 所列族的实例即受其照护。

### 4.10 公共卫生与疫病钟

#### 4.10.1 维度

`epi.<聚合体>.<状态行>`；状态行的传染与病程字段；聚合体的人数、年龄构成、照护覆盖率、人均亏空（卷二十七的聚合维度，§8 Q-9）；`rules.health.stat`（四个键）；`rules.health.immuneAgeCurve`；事件类型行的触发式可读的 `prevalence(...)`。

#### 4.10.2 统一入口

`epiTick`、`prevalenceOf`、`courseSummary`。事件类型行只登记，不写事件状态。

#### 4.10.3 规则

- **R21-10.1 三层形态**（向卷二十七 §4.1（三层模拟运行矩阵）登记矩阵行）：个体层为逐实例形态（§4.1–§4.9）；规则层为逐主体批量形态（同一病程律，按该层节拍一拍结算）；统计层为逐聚合体统计形态（本节）。暴露律在统计形态下的写法见 R21-10.3。
- **R21-10.2 病程摘要由行参数得出，不手填。** `courseSummary(行, {care: c, gain: g})` 返回 `{peak, days, lethal}`，有两种求法，按行的字段在加载期选定：
  - **闭式**，只用于"简单行"：没有驱动项，且各档的档效果不写别的状态行。记 mW、mH 为恶化倍率与好转倍率（统计层取聚合体成员的平均修正值，个体对照时取该个体的值）：

```text
b    = untended + c ×（tended − untended）
up   = b > 0 ? b × mW : b × mH                                   （免疫未满时的日变化）
dn   =（b + immune）> 0 ?（b + immune）× mW :（b + immune）× mH    （免疫已满后的日变化）

行有 immunity：
  tImm =（1 − 初始免疫）÷（perDaySick × g）
  up ≤ 0 且 initial ÷ |up| ≤ tImm → 不等免疫满就结案：peak = initial，days = initial ÷ |up|（up = 0 归入下一种）
  否则 peak = initial + max(up, 0) × tImm
       peak ≥ lethal → 致死，致死日 =（lethal − initial）÷ up
       dn < 0       → 痊愈，days = tImm + peak ÷ |dn|
       dn ≥ 0       → 慢性：不结案，留在患病存量里；dn > 0 时终将致死，致死日 = tImm +（lethal − peak）÷ dn
行无 immunity：
  up < 0 → 痊愈，peak = initial，days = initial ÷ |up|
  up > 0 → 致死，致死日 =（lethal − initial）÷ up
  up = 0 → 慢性
```

  - **试算**，用于其余的行（带驱动项，或档效果会写别的行，例如病的高档引起出血）：加载期用规则层批量形态的同一条病程律，对代表主体在 `stat.careGrid` × `stat.quantilePoints` 的网格上做确定性试算（不含暴露抽签；被档效果写出的行一并推进），存下每个网格点的 `{peak, days, lethal}`；运行期按 c、g 在表内插值。试算用的就是个体层的规则，所以摘要与个体层同源，不是另一套参数。
  - **免疫增益读聚合体的年龄构成**：每个 `epiTick`，由聚合体的年龄构成（卷二十七的聚合维度）经 `immuneAgeCurve` 得到成员免疫增益的分布，在 `stat.quantilePoints` 的各概率点取值 g_k；照护水平取聚合体当时的照护覆盖率（运行期的量，不在加载期定死）。对各 g_k 的摘要等权平均，得到这一拍的病死比例与平均病程。规则表只存"取哪几个概率点"，不存免疫增益的数值；老人多的村子病死比例自然高。
  - 个体给药的药应项不进摘要：统计层的用药只以公共措施的修正出现（R21-10.5）。个体层与统计层的对照试验因此在"没有逐人给药事件"的条件下做（A21-10.I）。
- **R21-10.3 统计形态的传播。** 聚合体按行记四个流向，每拍各算一次期望人数，整数化的余量按骰值键进位（R21-3.6）：

```text
易感 S = 人数 − 患病 − 免疫
有效易感 S_eff = S + 免疫 ×（1 − stat.compartmentMeanImmunity）       （免疫记录线性衰减，舱内成员的平均免疫值；perDayNotSick 为 0 的行这一项不计）
染病   = S_eff × p_get(d)                                            （p_get 即 R21-3.2 的式子，exposureMult 取成员平均修正值）
痊愈   = 患病 ×（1 − 病死比例）× Δ ÷ 平均病程                          （行有 immunity 的进免疫舱，否则回易感）
病死   = 患病 × 病死比例 × Δ ÷ 平均致死日                              （经聚合体减员入口减人并发事件）
失去免疫 = 免疫 × Δ × |perDayNotSick|                                  （回易感；perDayNotSick 为 0 则没有这个流向）
```

  剂量 d 按该行途径的 `doseSource` 四种来源各有聚合写法，与 R21-3.1 一一对应：
  - `colocated`：患病人数 × 平均排出量（`shedCurve` 在该行病程摘要上的时间平均）× 聚合体所在地点的 `mixRX` 值 × Δ。
  - `field`：途径条目所指环境场在聚合体所在单元的强度（统计层不逐步模拟场，取卷二十 §4.7（环境场与排放衰减）给的该层闭式场值）× Δ。
  - `ingested`：卷六 §4.12（家户预算与日耗）本拍口粮与饮水结算实际消耗的各物品人均质量 × 其材料 `agents` 中该行的含量之和。
  - `wound`：以 `epi.*` 中"`woundOf` 非空的行"的患病计数为带伤人数，有效易感只在带伤者中计；d = 伤口行病程摘要的平均严重度 × 所在单元的污秽场强度 × 途径混合系数 × Δ ×（1 − 照护覆盖率）。
  
  跨聚合体的传入靠迁移与行旅带入的患病成员，不设"外来输入率"。
- **R21-10.4 折叠与实体化守恒。** 单元由细变粗时，个体实例按行计数并入 `epi.*` 的患病数，"不带该行实例但免疫读数大于 0"的人计入免疫数；由粗变细时，按骰值键在成员中抽出相应人数：患病者写入实例，严重度取该行病程摘要的中位阶段，免疫者写入免疫记录，值取 `stat.compartmentMeanImmunity`。两个方向患病与免疫人数不变。
- **R21-10.5 公共措施是修正。** 隔离、净水、灭虫、施药、封城是以 `exposureMult`、`healMult`、地点的拥挤程度为目标、作用域为地点或法域的修正项，由决定它的主体（聚落治理、教会、医馆）的动作产生；统计形态读聚合体成员的平均修正值。现 health.json 的三种干预倍率迁为三条修正项数据。
- **R21-10.6 疫病钟。** "某地爆发疫病"是事件类型行：触发式读患病率越阈、水体污染、病媒场强度、粮荒；后果阶段只指向维度（暴露倍率、劳动出勤、行旅通行），不指向价格。检查节拍与抽签沿用卷二十 §4.9（世界时钟事件与灾异）的做法；事件实例的写者在卷二十四。现灾害时钟里的疫病日历条目退役：疫病不按日历来，按条件来。
- **R21-10.7 背景死亡不重复计。** 卷四的背景死亡曲线须扣除本卷已建模的死因；标定办法是统计层长时推进后，各死因合计的年死亡率对齐目标值（卷四开放问题 Q-15 由此答复，标定归数值工作）。

#### 4.10.6 验收断言

- A21-10.S 扫描式：`rules.health.stat` 的键集合恰为 §2.5 所列四个（加载期按键名比对，多一个即违规：再生数、病死率、病程天数、免疫增益数值都无处可填）；状态行与规则表中不存在以日历日为触发条件的疫病条目（`hazardClock` 的疫病段与饥荒时刻键删除后为空）；`epi.*` 只在 `health-stat.mjs` 读写（P21-1）；`health-stat.mjs` 对 `doseSource` 的分支数恰等于枚举值个数。
- A21-10.I 不变量式：折叠再实体化后各行患病与免疫人数不变；四个流向每拍守恒（易感 + 患病 + 免疫 + 累计病死 = 初始人数 + 迁入 − 迁出）；对简单行，闭式摘要与个体层逐拍推进同一（c、g、倍率）的结果之差不超过一拍的步进量；对非简单行，试算表在网格点上与个体层逐拍推进逐值相等。同一单元在"没有逐人给药事件"的条件下强制按个体层与统计层推进同样时长，患病率峰值与累计病死数之差在卷二十七登记的容差内（超出按缺规律处理，不调容差）；任何推进切分下存档摘要相同。
- A21-10.X 扩展性式：新增一行传染病，不改 `.mjs`、不加任何统计层参数，它在统计层自动有传播、病程、病死与免疫流失；分别对四种 `doseSource` 的途径各加一行病，四行都在统计层出现新增患病；新增一行带驱动项的病，摘要自动改用试算。

### 4.11 医疗设施与职业接口

#### 4.11.1 维度

处置行的 `service`；设施类型行的服务效果与容量维度（卷十九）；职业行的服务集合（卷十四）；雇佣与成员持有边（卷十八、卷六）。本节没有自己的表。

#### 4.11.2 统一入口

读 `facilityTypeView`、`professionView`、谓词 `canOffer`（卷十四）；`careOptions` 可按地点过滤出"此处此刻有人能作为服务提供的处置"。

#### 4.11.3 规则

- **R21-11.1 医馆不是一类特殊建筑。** 一处设施此刻能提供哪些医疗服务 = 对其在岗成员逐个调 `canOffer(成员, 服务, ctx)` 为真的服务集合；"所在设施是否列有该服务"是 `canOffer` 四项条件之一（卷十四 §4.1（职业维度表与服务词表）PF-6），本卷不再自己取交集。此处可施行的处置 = `service` 落在该集合内的处置行。名称、用途文字不参与。
- **R21-11.2 医者不是一种身份；够不够格只有一个谓词。** 某人能否**对外提供**某处置 = `canOffer(此人, 该处置行的 service, ctx)`，本卷不另写判据。"技能太低、做了多半要坏的人不该挂牌"这一条，写成服务条目人需求块里的一项（该服务的技能不低于某值，条目数据），由 `canOffer` 的 `qualifies` 一并判；本卷不在代码里拿预览质量与做坏线比较（需求块能否表达这一项见 §8 Q-4）。自己动手不经 `canOffer`（R21-8.1）。职位称谓只在显示层。成员关系读雇佣与成员持有边，不读职位文字。
- **R21-11.3 出诊与排期。** 预约是义务（合同状态机归卷六）；是否在出诊时段读日程槽上的动作代号（卷九），不读活动文字。上门出诊是行程（卷十七）加处置动作。
- **R21-11.4 设施对疗效的作用只经修正。** 床位、洁净、照明、器械是设施类型行与其陈设的维度，作用于过程槽与好转倍率（R21-8.3、R21-9.3）。
- **R21-11.5 药铺是有药材库存的店。** 采购、库存、售价全归卷六；本卷只提供药性读数供买卖双方估计用途。药价随求诊人数上涨是供需结果，现价格乘数入口删除。诊费同理：现"半日工钱折半加药价 ×（1 + 预约数 ÷ 容量）"的写死算式整条删除，诊费是卷六 §4.21（价格四角色）下的服务交易，本卷不给任何乘数（P21-9）。"带回家的药"不是规则表里的物品清单，而是一次普通的买卖加之后的自行摄入。
- **R21-11.6 慈善与公费。** 施药、义诊、公共防疫的钱是拨款与捐赠的账本转移（卷六），其效果仍是处置与修正项。

#### 4.11.4 交互

- 卷十九 §4.2（设施类型表）：服务效果、容量。卷十四 §4.1（职业表与服务词表）：服务代号由该卷登记，本卷的处置行引用。
- 卷六：诊费、药价、合同。卷十七：出诊行程。卷九：日程与动作。通道：无新增写入。

- A21-11.I 不变量式：某地可提供的处置集合 ⊆ 该地设施声明的服务所含处置；集合内每个处置都有一名在岗成员使 `canOffer` 为真，反之亦然（本卷没有第二套资格判据：本卷三个文件内不存在把预览质量与做坏线比较后返回"可否提供"的函数）；成员全部离岗时集合为空；设施损毁到服务效果失效时过程槽修正同步消失。
- A21-11.X 扩展性式：新增一种设施类型行（声明已有服务代号）不改 `.mjs` 即可提供相应处置；新增一种服务代号与指向它的处置行，不改 `.mjs`。
