## §0 卷首

### 0.1 范围

本卷定义"东西和钱怎样流动"：谁持有多少（账本）、东西值多少钱在哪里用哪种价（价格形成与四角色）、人为什么要买（需求）、东西从哪来（生产组织与产业链）、怎样从产地到用地（分销与商队）、人靠什么挣钱（劳动市场）、一户人每天消耗什么（家户预算与日耗）、钱是什么（货币与多币）、欠与还（信用、合同状态机）、产业与租约、公共工程拨款、走私的经济侧，以及全世界的源汇报告与财富汇流。

**本卷的核心不变量只有一条：货币与实物守恒。** 任何资源（铸币、物品、存量、非金点数）的数量只经账本转移改变；凭空出现与凭空消失只发生在登记过的源与汇上，每一笔都带代号、有日预算、进月报。其余二十四个子系统都是这条不变量之上的只读投影或成对转移。

本卷不定义：配方行格式（卷二 §5.18）与配方通用规则、产率、继承（卷三 §4.8）；单件物估值公式与稀缺度（卷三 §4.16）；用度类九维与替代折算（卷三 §4.3、§4.17）；资源场、再生律、规模律与取用律（卷五 §4.7、§4.8）；承载与负重公式（卷四 §4.6）；行程合成、运单条款、路途风险律、关卡（卷十七 §4.1、§4.3、§4.6、§4.7）；税种表与征管、组织与公库归属、人口统计层（卷八 §4.11、§4.1、§4.16）；违禁谓词、治安值函数、违约救济与时效（卷八b §4.1、§4.7、§4.15）；设施类型、工位、维护需求（卷十九 §4.2、§4.3、§4.9）；职业、技能、服务词表（卷十四 §4.1、§4.3）；身体缺乏后果的容器实例（卷二十一 §4.4）；文化偏好权重（卷七 §4.28）。这些只按台账给定的使用方式引用。

### 0.5 读法

§2 是全部维度与规则表；§3 是唯一入口与唯一写者；§4 二十五个子系统各 6 小节；§5 是给别卷的接口。数据实例里的实体一律写成 ‹类：显示说明› 占位，真 id 由内容卡填；本卷自己的词表代号（`purpose_*`、`src_*`、`sink_*`、`ckind_*`、`obl_*`、`cphase_*`、`ophase_*`、`prole_*`、`fee_*` 等）是固定代号，可直接出现。规则表常数一律写成"表名.键名"，数值由内容卡标定，本卷不写数值。"需求"一词在本卷专指市场需求 `demand`（台账 X-25）；需求块写全称。

## §1 领域总述

### 1.1 真实世界怎样运转

1. **东西不会凭空出现**。一袋盐是有人在盐滩上晒出来、有人背到集上的；一捆柴是有人进林子砍的。能从地里长、从矿里挖、从海里晒的才是"来源"，其余都是加工与转手。用掉、烧掉、烂掉、丢掉才是"去处"。
2. **钱也是东西**。铸币是按成色与重量铸出来的金属，铸一枚就少一块料；钱少的地方物价低，劣币出现后好币被藏起来。没有铸币的地方用布、粮、牲口、贝壳记账，道理相同。
3. **价格是供需的结果，不是标签**。同一样东西在产地贱、在远处贵，差价约等于运费加路上被抢的风险再加商人的利润；差价不够就没人运。歉收、围城、封路让供给变少，价格自己涨；通路之后自己落。
4. **人买东西是因为要用**。每户每天要吃、要烧、要穿、要用工具，按人、按户、按牲口、按作坊计。先用自家存的，再自己动手，再花钱买；买不起最要紧的先买。缺了的后果按要紧程度分档：不舒服、伤身体、要命。挨冻和挨饿是同一类事。
5. **行业跟着资源和买主走**。有盐滩才有盐户，有林才有樵夫，有铁矿与煤才有冶户；干这行的人数由周围买得到的人口决定，不是谁规定的。一道工序接一道工序，下游要多少决定上游做多少。
6. **工钱由活计定**。雇主出的价不会高过这个人干出来的东西值的钱，干活的人要的价不会低过养家的开销；人手紧时靠前者，人手多时靠后者。
7. **承诺是可以被追索的东西**。借贷、租约、雇佣、托运、保险、远期交货，都是"谁在什么时候该给谁多少什么"。到期履行就了结，不履行就进入追索。
8. **集市自己长出来**。路口、渡口、产地之间的地方成交多，成交多了价格稳，价格稳了更多人来；没有谁指定哪里是商埠。

### 1.2 本作现状（出处见素材包 §3）

- 账本内核已有：账户是（实体、资源、用途）三元键，转移是改存量的唯一入口，源汇是显式账户并有日预算熔断。但旧状态字段与账本**双写**：个体钱数字段在 22 个模块里被直写，玩家钱数 52 处，聚落公库 8 个模块 12 处，其中一处记账后又按一个地点 id 直写公库。
- 聚落库存只有四个槽（食、木、石、铁），"粮"被写死为一种物品 id；木与石两个槽被读 89 处。
- 市场投影已有且只持久化成交，但九个十进制常数写在代码里，季节涨价是手写乘数，质押状态用中文字面量比较。
- 需求侧只有近期库存口径，没有配方派生需求与文化偏好。家户日耗的用度函数只返回两种用度类；日用自给只在一种燃料上起作用。
- 店铺：三家手工店凭空补货；三类店的货单在生成代码里写了三十多个物品 id。
- 分销：区域定价与真实承运只对一种粮有效，规则表里只配了那一种物品；错误消息用前缀比较做分支。
- 生产：156 种消耗品里 139 种不可再生，112 个生产职业不产出；210 条配方的投入追不到来源。
- 劳动：工价按技能阶查表，不读本地供需；有按任务显示名、按中文正则的分支。
- 货币：两种铸币加一种券；非铸币计价单位全部填成同一种铸币的 id。
- 信用、钱庄、远期、托管、走私、公共工程都已有，但各有读睡眠文字、读职业正则、读章程文字的判断；公共工程与建筑维护的建材只认两种物品。
- 资产：田、铺、宅靠名称关键词区分。
- 月度经济报告、工位负荷、保险、贸易枢纽验收：没有。

结论：守恒的骨架是好的，要做的是三件事——把双写清零；把"只对某一种物品成立"的规则全部换成读九维的通用规则；把价格、工钱、行业人数从手填改成由供需推出。

## §4 子系统

### 4.1 账本三元键与守恒

#### 4.1.1 维度

§2.1 的账户四字段与 `resource`（第一版写作 `reskind`，已并回卷二登记的族名）、`purpose`、`src`、`sink` 四族。运行态：`accounts`（余额）、`ledgerTotals.<资源>.<来源或去处代号> = {cumulative: integer, usedToday: integer, day: integer}`，三个量都以该资源的最小记账单位计，是数量，不是价值。规则表 `ledger.json`：`budget`、`alert`（§2.5）。批次元数据（品质、腐坏、赃物份额、表象）归卷三 §4.4，随资源键中的批次号走。

#### 4.1.2 统一入口

读：`balance`、`accountsOf`、`stockIn`。写：`post`（及其简写 `transfer`）、`openAccount`。全书凡改变任何数量，只有 `post` 一个入口（台账：账户与转移，使用方式"经账本"）。

#### 4.1.3 规则

1. **三元键**：账户由（持有人、资源、用途）唯一确定。同一持有人对同一资源可有多个用途分区；分区之间移动也是一笔转移。聚落库存、公仓、公库、店铺货架、家户储备、钱袋、在途货、托管物、质押物，都只是三元键取不同的值，没有第二种存储。
2. **一笔之内归零**：`post` 接受若干条腿，每条腿是（账户、增减量）。对每一种资源，记 `L` = 本笔普通账户各腿增减量之和，`S` = 本笔记到来源的量，`K` = 本笔记到去处的量（`S`、`K` 都不为负），必须有 `L − S + K = 0`，即 `L = S − K`；否则整笔拒绝，返回原因代号。任一腿使余额为负，整笔拒绝。一笔之内全成或全败。这条式子是规则 4 守恒式的单笔形式：把所有已入账的笔逐项相加，左边得到余额之和，右边得到来源累计减去处累计，两条规则因此是同一条。第一版把符号写反（写成 `L + S − K`），已改正。手算校核（四种腿型逐一代入）：
   - 凭空产出若干件（设为五）：`L` 为正五，`S` 为五，`K` 为零，`L − S + K` 得零，通过。按第一版的式子得十，会被误拒；
   - 纯转移（甲减三、乙加三）：`L` 为零，`S`、`K` 都为零，得零，通过；
   - 用掉七件：`L` 为负七，`S` 为零，`K` 为七，得零，通过；
   - 转换（投入料减四、产物加二，两种资源各自核对）：投入料 `L` 为负四、`K` 为四，得零；产物 `L` 为正二、`S` 为二，得零；两种资源都通过，且来源去处成对（规则 5）。
3. **来源与去处是登记的代号**：不是账户余额，而是按资源累计的两组单调不减的计数。增量腿没有对手减量腿时必须带来源代号，减量腿没有对手增量腿时必须带去处代号；代号必须在该资源种类行的 `sources` 或 `sinks` 之内。
4. **守恒式**（全书经济的总不变量）：对每一种资源，任一时刻，全部普通账户余额之和等于该资源各来源累计之和减去各去处累计之和。
5. **转换成对**：一种资源变成另一种（制造、冶炼、烹饪、铸币、熔毁、屠宰、腐坏成渣）是同一笔 `post` 里"投入记去处、产出记来源"的成对腿；来源与去处条目用 `pairedWith` 互指，缺一腿即拒绝。标了质量守恒的反应，其质量核对由卷三 §4.8 的提案给出，本入口只核对成对。**建造也是转换，没有例外**：建造完工时，耗用的材料记转换去处，同一笔里产出一笔建筑资产分录记转换来源——资源种类的 `family` 为 `resfam_asset`，键是该设施实例，数量是一万基点的所有权份额，按出资比例记到各出资方名下。扩建与修缮不产生新的资源（设施还是那一处，份额不变），耗材属于"用掉"，记消耗去处 `sink_consume`，不属于转换，完好度与工位数由卷十九的写者落定。拆除与毁损反向：资产分录记去处，拆出的材料记来源。人工不是资源，工时以工钱转移和作业记录体现，不占腿。载具、器具这类可移动的制成品本来就是物品，走普通的成对腿。资产种类不在本卷：取卷十九 §4.2 的设施类型（派生量）。
6. **日预算只用数量、分两种通道**：预算与用量一律以该资源的最小记账单位计，在 `ledger.json` 里按（资源种类、代号）给出；账本内核不调用估值，不把数量折成价值。来源与去处条目的 `budgetMode` 分两种：
   - 物理律通道（`bm_physical`）：再生、出生与死亡对平、转换、消耗、腐坏、损耗这类由别卷物理规律算出的量，不限额、不拒单笔，卷五的再生律与卷二十一的摄入不会被本卷截断；当日用量超过 `alert` 时只记一条预警缺口，进月报；
   - 限额通道（`bm_capped`）：只有开局（仅第 0 日）与边界供货两类。限额通道不在单笔上先到先得，而是在世界日结算步里一次分配：当日全部申请先汇总，总量不超过日限额时全部成交；超过时按各申请量的比例向下取整分配，余数按申请主体 id 升序逐个补一单位。分配结果只取决于当日申请的集合，与处理先后无关。
   预算按世界日计，不按推进请求计，所以一次推进多日与分段推进得到同一结果。
7. **转让限制**：资源种类行的 `transferable` 与 `counterpartRX` 在 `post` 内核对；`tr_bound` 的资源只能在持有人与发行者之间移动。非金点数（虔诚、威望、影响力等，由各领域卷登记种类行）与物品、铸币同一机制，区别只在这一行数据（台账 S-15）。
8. **发行背书**：`issuerBacked` 为真的资源，其普通账户余额之和恒等于发行者名下对应义务的未清余额；发行与兑付是"凭证腿加义务变更"同一事务（§4.15）。
9. **持有人终止**：按卷二 §2.6 的实体终止协议分流余额，本卷只提供每种资源的 `onTerminate` 与 `salvageFraction`；不存在"人死钱没"。
10. **库存是聚合视图**：聚落与家户的"库存槽"是 `accountsOf` 按物品的经济大类（卷三 §4.3 规则 C-6）聚合的只读结果，不存槽。`stockIn` 的范围聚合只数 `visibleToMarket` 为真的用途分区与在场持有人。`stockIn` 是原始存量口径，供报告与覆盖天数用；价格里的稀缺项不读它，读 §4.2 规则 3 的 `marketSupply`（扣自留、含在途），由 `priceFor` 作为参数传给卷三。
11. **双写清零**：旧状态字段与适配器的退役由卷一 §6.5 的母卡 LEDGER-1 负责，本卷给出终态：实体行上不存在任何数量字段，读者一律读 `balance`。
12. **占有与归属分开**：账本记的是谁拿着（占有）；东西归谁、谁有权处分，是持有边（卷十八 §4.1）与合同条款的事。承运人账户里的在途货、当铺账户里的当物，都在占有人名下的专用用途分区，归属由对应合同的义务表达。

#### 4.1.4 交互

卷二 §2.6（三条写路之一；终止协议）；卷三 §4.4（批次）、§4.16（读 `stockIn`）；卷五 §4.7（存量账户由其唯一写者经 `post` 写）；卷七、卷八、卷十八（登记点数类资源种类行）；卷八 §4.1（公库是组织的账户，分区代号由其登记到 `purpose` 族）；卷二十七 §4.6（复演核对守恒式）；卷十二（守恒不变量进核心套件）。

#### 4.1.5 数据实例

- 西陲一户农家：对同一种谷物有两个账户，用途分别是自用储备与待售；卖粮先把一部分从前者移到后者，市场只看得到后者。
- 非西陲一支草原商队：组织名下对若干货物各有一个在途用途的账户，成员个人的钱在各自的自由用途账户里；商队解散时按终止协议清算，余额分给成员。
- 超自然一座神祠：名下有一种点数类资源（信众奉献形成，种类行由卷七登记，`transferable` 为只许与发行者往来）；规则与铸币账户相同，只是不能在信众之间转。

#### 4.1.6 验收断言

- 【扫描】A6-1.1：S6-1、S6-8、S6-14 计数为 0；读资源种类行 `transferable`、`counterpartRX`、`sources`、`sinks` 四个字段的模块只有 `kernel/ledger.mjs`（调用图白名单，S6-13 同法）；账本内核对 `priceFor`、`valuation` 的引用计数为 0。
- 【不变量】A6-1.2：任意推进之后，对每一种资源，守恒式严格成立（整数相等，不设容差）；所有余额非负；`issuerBacked` 资源的余额和等于发行者义务未清余额；已终止实体余额为零。把同一段时间分成任意多段推进，`accounts` 与 `ledgerTotals` 逐位相同。单笔层面：每一笔已入账的 `post`，对它涉及的每一种资源都有 `L − S + K = 0`（规则 2）；每一笔转换的来源腿与去处腿成对；每处现存设施实例的资产份额之和等于一万基点，已拆除或毁损的为零。把同一世界日内各笔申请的处理顺序任意打乱，限额通道的分配结果与日终存档摘要相同；物理律通道没有任何一笔因预算被拒。
- 【扩展性】A6-1.3：新增一行资源种类（例如一种只能在行会内部流通的工分），不改代码即可开户、转移、受限转让、进月报；新增一个来源代号并写进某种类行，日预算与报告分组自动生效。

### 4.2 市场投影与价格形成

#### 4.2.1 维度

读：物品九维（卷三 §4.3）、`valueBase` 与稀缺度（卷三 §4.16）、账户余额、成交记录。派生：`sellable`、`marketSupply`。规则表 `market.json`：`depthStepShare`、`scopeRadiusM`、`tradeRingDays`。过程槽 `process.price`（卷二 §3.7 已迁入，单位为价值单位）。

#### 4.2.2 统一入口

读：`marketQuote`、`marketSupply`。写：`executeTrade`。市场不是一个存储物，是对"此地此刻谁手里有多少愿意卖"的只读投影；只有成交被持久化。

#### 4.2.3 规则

1. **市场范围**：一个市场由地点界定，范围是该地点及其包含树内 `visibleToMarket` 账户的在场持有人；范围半径、是否并入邻近集市由 `market.json` 给出，按地点维度取值，不按地点 id。
2. **可售量**：`sellable(持有人, 货) = 该货自由用途余额 − 自留量`。自留量：家户取 §4.12 的备货目标，店铺取 §4.5 的陈列下限，作坊取 §4.7 作业计划的投入占用，其余为 0；任何持有人再加上"已签、未到期、尚未发运的远期交付承诺量"（§4.17 规则 2），为履约备下的货不算可售。可售量不落盘。
3. **供给**：`marketSupply = Σ 范围内 sellable + incoming(时域内预期到货) + 边界实体的当日剩余限额`（§4.17 规则 2 已去重；边界项见 §4.6 规则 8）。按替代池询价时，各成员先用卷三 §4.17 的折合量换成池单位再求和。
4. **边际单价**：第 q 个单位的价 = `priceFor(成交用途, 货, {place, supply: marketSupply − q, demandPerDay})`。稀缺项的公式归卷三 §4.16，但它的存量一侧由本卷喂入：`priceFor` 把本规则的 `marketSupply`（扣自留、含在途）减去已买走的 q 作为 `ctx.supply` 传给卷三，卷三不自己去读 `stockIn`。全书稀缺度因此只有这一个供给口径，"货船将至压低现价""惜售抬价"都由它得到。总价是边际单价沿数量的累加，累加步长取 `depthStepShare`。买得越多越贵、卖得越多越贱由此而来，不另设深度参数。
5. **卖方底价与买方顶价**：每个卖方有底价 = 其进货成本加应付费用加经营利润。进货成本读批次上的 `costBasis`：账本在 `executeTrade` 成交入账时写入本笔单价，在完工 `post` 时写入自产成本（投入的 `costBasis` 之和加工钱加工位费，除以产出件数）；两批合并时按数量加权平均；开局以 `src_genesis` 入账的批次取其估值角色的值。经营利润：持有人是经营者（`isOperator` 为真，即持有提供零售、收购或生产服务的场所，且有货架用途账户或进行态作业）时，店铺取 §4.5 规则 4，其余经营者取 `market.json.operatorMarginShare`；不是经营者的利润为 0。成交沿"底价升序、同价按持有人 id 升序"逐个卖方吃货；边际单价低于某卖方底价时跳过该卖方。买方顶价来自其预算（§4.12）或转售预期（§4.6）。
6. **买卖差**：收购报价（`side` 为卖给本地）= 收购者的转售预期价减去其费用、持有期损耗与经营利润。价差是这几项之和，由数据推出，规则表里没有"买价百分之几、卖价百分之几"。
7. **修正只经价格槽**：议价、交情、立场、阵营价格规则（卷八 §4.14）、技能，一律是 `process.price` 上的修正项，进卷二 §3.3 的管线，受槽的 `bounds` 约束。季节、战争、灾异不许挂价格修正：它们只改供给、需求、路况、治安这些维度（§4.25）。
8. **成交**：`executeTrade` 把货腿、款腿、各费用腿、各税腿放进同一笔 `post`；任一腿失败整笔不成。成交后向 `marketTrades` 追加一条记录。除此之外市场不写任何状态：不存"当前价"，不存"货架"。
9. **数量如实**：`fillable` 是按规则 5 真实吃得到的量；请求量超出时只成交 `fillable`，不凭空补足。
10. **没有回退**：估值未知的货返回未知并记缺口（卷三 §4.16 规则 V-8），不拿任何别的货的价顶替，不回退到旧的手填价，也不当作零（§4.21 规则 9）。
11. **新货也有价**：一件货在当地还没有成交记录时，报价照常成立——边际单价本来就不读成交记录，只读估值与供需。需要"惯常价"的地方（§4.4 规则 3 的预算截断）按 §4.4 规则 4 的次序取这件货自己的估值角色价。

#### 4.2.4 交互

#### 4.2.5 数据实例

### 4.3 市场费用与交易税

#### 4.3.1 维度

`fee` 族条目：`base`（计费基数：成交额、挂牌额、占用天数、件数）、`rateKey`、`payee`（场地业主、中介人、托管人、登记的汇）、`discountCurveKey`、`minKey`。规则表 `fees.json`。税不在本卷：税种、税基、税率、归属、征管都读卷八 §4.11 的税种表（台账 X-15）。

#### 4.3.2 统一入口

读：`feesFor(tradeDraft)`，返回本笔应付的各项市场费用与（调卷八税种表入口算出的）各项税。写：无独立写入口，费与税是 `executeTrade` 同一笔 `post` 的腿。

#### 4.3.3 规则

1. **费用是数据行**：一笔成交适用哪些费用，由成交场地（设施类型提供的服务代号，卷十九 §4.3）、是否经中介、是否托管决定；每项金额 = 基数 × 费率 ×（1 − 折扣），不低于下限。折扣曲线只读数值：付费方的技能值、与收费方的立场数值。
2. **费用默认是转移**：`payee` 指向真实实体（场地业主、中介人、托管人）时是一笔转移。只有条目明确把 `payee` 设为登记的汇时才是去处，并进月报的去处分组。本作没有世界之外的收费方，所以缺省不存在"费用蒸发"。
3. **税只在成交时代征**：`feesFor` 以成交草稿调卷八税种表，得到应税项与归属账户，作为同一笔的税腿；本卷不保存税率，不判断免税，不做征管。
4. **谁付**：每项费、税的承担方由条目与税种行给出（买方、卖方或分担），不由代码缺省。
5. **改单与撤单**：挂牌寄售（§4.17）改价或撤回时适用的费用同样是 `fee` 条目，基数取挂牌额。
6. **费用进底价**：卖方底价（§4.2 规则 5）包含其应付费用与税，所以费税升高自动抬高成交价，不另写传导规则。

#### 4.3.4 交互

卷八 §4.11（税种表，唯一）；卷十九 §4.3（场地提供的服务代号）、§4.15（运营成本）；卷十七 §4.7（通行费是设施服务费，由其定义，不是本节的市场费用）；卷十四（技能值）；卷十八（立场数值）；§4.22（费与税的月报分组）。

#### 4.3.5 数据实例

- 西陲一处官设集场：过秤费按成交额计，`payee` 为场地业主（一个组织），是转移；另按税种表代征一项交易税入该地公库账户。
- 非西陲一处行会控制的港口货栈：中介费按成交额计并随买方与行会的立场数值打折；栈租按占用天数计。
- 非人类一处巨人部族的换货场：只有一项费用，按件数计，以一种非铸币资源支付给主持者；规则与前两例同式。

#### 4.3.6 验收断言

- 【扫描】A6-3.1：费率、税率字面量在规则层为 0；本卷代码中无税种代号字面量、无"免税"判断；按政体名称推税制的写法为 0。
- 【不变量】A6-3.2：每笔成交中，买方付出 = 卖方收入 + 各费用收款方收入 + 各税归属账户收入 + 记入去处的量；`feesFor` 的结果与 `executeTrade` 实际腿逐项相等。
- 【扩展性】A6-3.3：新增一条费用条目并挂到一种设施类型的服务上，不改代码：在该类场地成交自动多一条费用腿并进月报；卷八新增一种税，本卷不改即被代征。

### 4.4 市场需求

#### 4.4.1 维度

读：用度类条目与物品的 `usageClass`、`usagePer`、`dailyUse`、`seasonUseFactor`、`necessityTier`、`substitutePool`、`lifeDays`、`produceSeason`（卷三 §4.3）；作业计划（§4.7）；成交记录；文化偏好权重（卷七 §4.28 的入口）；成员的身体需要日需量（卷二十一 §4.4 身体需要条目 `needDim` 所指的个体维度，取修正后值，身体值来自卷四的代谢与物种维度）；维持居所温度所需的热量（卷二十 §4.5 与卷十九 §4.7 的入口）。用度类条目上由本卷请卷三登记的四个字段（§5.3；含义只在 §4.12 规则 1）：`needSource`、`bodyNeed`、`appliesRX`、`scaleRX`。规则表 `demand.json`：`coverDaysByTier`、`expectWindowDays`、`habitCurve`、`budgetShareByTier`、`neutralPreference`、`minTradesForHabit`。

#### 4.4.2 统一入口

`demand(scope, goodRef 或池代号, horizonDays)` → `{perDay, parts: {use, derived, replace, stockup}}`。本卷"需求"专指这个量（台账 X-25）。

#### 4.4.3 规则

1. **四个来源相加**：
   - 日耗 `use`：范围内每个家户与统计家户按 §4.12 规则 1 算出的该用度类日需要量，减去其预期自给量。预期自给量取该户上一个结算日实际自给满足的量（读 `householdEcon` 的结算记录），不在本次求值里重新预估，所以不与当日的取用决策成环；
   - 配方派生 `derived`：范围内作业计划在时域内要消耗的投入量，沿配方图向上游递推到 §4.9 规定的层数；
   - 更换 `replace`：范围内在用的耐用品与工具，按"在用件数 ÷ 寿命天数"加当前磨损折算；
   - 备货 `stockup`：有出产季节的货，在非出产季之前按 `coverDaysByTier` 给出的覆盖天数补足库存的差额，摊到剩余天数。
2. **先按池、后分到物**：属于替代池的货，四项都先以池单位求和；分到具体成员时用习惯权重 `w = lookup(habitCurve, 可得性 p, 偏好 b)`，`p` 是该成员在当地近期可成交量占池内份额，`b` 是卷七入口给出的文化偏好权重。没有文化数据时 `b` 取 `demand.json.neutralPreference` 并记缺口。
3. **有效需求受支付能力截断**：每户按必需档从高到低分配预算（`budgetShareByTier` 给各档上限份额，剩余下传）；预算不够时低档需求不进入有效需求。支付能力读自由用途的各计价资源余额与预期收入（已签雇佣与租约的应收义务），不再用现金暂代收入。截断所用的价取惯常价（规则 4），不取当刻报价，使"价格读需求、需求读价格"在一次求值内无环。
4. **预期与惯常价**：`expectWindowDays` 内成交量的移动平均作为"惯常成交量"，同一窗口内的成交均价作为"惯常价"，用于规则 2 的可得性、规则 3 的截断与 §4.5、§4.6 的经营预期；预期只读已持久化的成交记录，不另存预期值。取值次序：窗口内该货在当地的成交不少于 `demand.json.minTradesForHabit` 条时用成交记录；不足时，惯常价取这件货自己的 `priceFor`（估值角色、不含稀缺项），惯常成交量取零。这取的是同一件货自己的估值，不是拿别的货或旧的手填价顶替，不违反"没有回退"。新货因此从第一天起就有有效需求。
5. **企业耗用同式**：作坊、车行、军营、神祠的日耗（按工位、按畜、按仪式计）走同一用度类条目的 `usagePer` 取值，没有"企业专用需求表"。
6. **统计人口同口径**：未物化的人口由卷八 §4.16 的统计层给出户数与构成，按同一式计入 `use`；名册为空的地点只有统计项。
7. **时域内不重复**：同一件未来消耗只计入一次；已由远期合同锁定的到货（§4.17）从 `stockup` 中扣除。

#### 4.4.4 交互

卷三 §4.3、§4.17（九维、池折算）、§4.16（稀缺度读本入口）；卷七 §4.28（偏好权重）；卷八 §4.16（统计层）；卷十八 §4.2（家户成员）；卷五 §4.7 规则 5（规模律读"可达需求日量"：以 `reachOf(产地, 货)` 给出的地点集合为 `scope` 调本入口；可及范围的定义只在 §4.6 规则 11）；卷二十一 §4.4（身体需要日需量）；卷四（代谢与物种维度）；卷二十 §4.4（季节）。

#### 4.4.5 数据实例

- 西陲一座三百户的镇：某保存用度类的日耗由户数、人数与条目的每人日用量得出；上游一处晒场的工位数上限由卷五规模律读这个量（扣掉别处已有产能后的净需求）得出，没有任何"此镇需此物若干"的手填数。

### 4.5 店铺经营与补货

#### 4.5.1 维度

`shopkind` 族条目（§2.2）。店铺不是新实体：它是"一个经营者（个人、家户或组织）加一处提供零售或收购服务的场所（卷十九 §4.3）加若干货架用途的账户"。运行态无专有存储；应付账款是合同义务（§4.16）。规则表 `shop.json`：`marginCurve`、`coverDays`、`displayFloorShare`、`restockBatch`（§2.5）。

#### 4.5.2 统一入口

读：`shopView`。写：无专有入口；进货与售货都是 `executeTrade`，雇人是 `contractStep`。生成期派生店由卷十 §4.7 按本节规则登记实例。

#### 4.5.3 规则

1. **品类由条件定**：一家店卖什么 = `shopkind.assortmentRX` 对物品九维与类别代号为真的物品集合，再与"当地有效需求大于零"求交。货单里不出现物品 id；通配写法（全品类）只在条目显式声明时允许。
2. **只向真实持有者进货**：补货是店主作为买方的普通成交，对手是当地有可售量的生产者、别的店或过路商队；当地无货时向外地下远期订单或自己去贩（§4.6、§4.17）。任何路径都不产生来源腿。
3. **补货量**：目标库存 = 惯常成交量（§4.4 规则 4）× `shop.json.coverDays[条目的 coverDaysKey]`，按 `restockBatch` 的批量向上取整；补货量 = 目标库存 − 货架余额 − 在途到货，受店主自由资金与赊账额度（§4.15）约束。
4. **标价**：店的底价 = 进货成本 + 应付费税 + 进货成本 × 经营利润率；利润率 = `lookup(shop.json.marginCurve[条目的 marginCurveKey], 周转天数)`，周转慢的货利润率高；进货成本读批次的 `costBasis`（§4.2 规则 5）。成交价仍由 §4.2 决定，底价只是下限。
5. **陈列下限与惜售**：店铺的自留量上限 = 货架余额 ×（1 − `shop.json.displayFloorShare`），即至少把这一比例的货挂出；余下部分店主可因预期涨价而惜售，惜售与否由其决策规则（卷九的 NPC 决策）读 §4.4 的预期决定。
6. **经营账**：房租、雇工工钱、税是合同义务，到期由 §4.16 结算；连续无力支付即进入违约流程，店铺因此关张，没有"店铺永续"的保底。
7. **派生店**：卷十在生成聚落时，按"当地各品类有效需求 ÷ 单店惯常成交量"得到各 `shopkind` 的店数，再物化场所与经营者；运行期新店由 NPC 的开业决策按同一比较产生。手工设定的店与派生店同一格式。
8. **收购与寄售**：店收购是 §4.2 规则 6 的收购报价；寄售是 §4.17 的保管合同，货在店的寄售用途账户，归属仍在寄售人。

#### 4.5.4 交互

卷十 §4.7（布局模板与派生店登记）、§4.8（物品生成组只用于开局存量，仍须有来源记账，见 §4.22 规则 3）；卷十九 §4.3（场所服务）；卷十四（零售服务代号）；卷九（开业、惜售的决策）；§4.2、§4.3、§4.4、§4.15、§4.16。

#### 4.5.5 数据实例

- 西陲一家杂货铺：条目的品类条件是"日用消耗类且运法不需车"，货架上是什么由当地需求与进得到的货决定；隔壁晒场停工后它进不到某类货，货架自然空掉。
- 非西陲一家海港的舶来品行：品类条件是"来源方式为只能买入且货值密度高于某阈值"，全靠 §4.6 的到货。
- 超自然一处由精怪经营的夜市摊：经营者是非人个体，场所只在夜间提供零售服务（时段许可归卷十九），计价资源是一种非铸币资源；进货、标价、关张规则与前两例相同。

#### 4.5.6 验收断言

- 【扫描】A6-5.1：生成代码与规则层中店铺货单的物品 id 字面量为 0；店铺模块中不带对手减量腿的进货为 0（凭空补货为 0）。
- 【不变量】A6-5.2：任一店铺任一时段，货架余额变化 = 进货成交量 − 售出成交量 − 损耗记入去处的量；店主资金变化 = 售货收入 − 进货支出 − 已付义务。
- 【扩展性】A6-5.3：新增一条 `shopkind` 条目，不改代码：生成期与运行期在需求足够的聚落出现这种店，品类自动确定，能进货、标价、赔本关张。

### 4.6 分销、承运与商队

读：`shipmentProfile`（卷三 §4.18：质量、体积、总值、货值密度、运法、易损份额、最短保质日数）；承载能力（卷四 §4.6）；行程钟点与路况（卷十七 §4.1、卷五 §4.10）；路途风险律（卷十七 §4.6，其输入含沿途治安值，治安值函数归卷八b §4.7）；两地报价（§4.2）。运行态 `tradeRuns`：`{carrier, lots, from, to, departMinute, etaMinute, jobstate}`。规则表 `trade.json`：`minMarginShare`、`provisionReserveDays`、`statBatchGrain`、`reachCostShare`、`carrierMarginShare`、`boundaryQuota`、`boundaryCoinOutflowCapShare`、`externalPriceIndex`、`boundaryMarginShare`（§2.5）。载具的每趟磨损读卷三 §4.10 的耐久与劣化；劫者主体读卷十七路途风险律的返回值。

#### 4.6.2 统一入口

读：`landedCost`、`reachOf`。写：`settleTrade(day)`（贩运决策与发车）；到达、货损、被劫的记账由承运执行（卷十七 §4.3）经 `post` 完成。

#### 4.6.3 规则

1. **到岸成本**（对任何货同式）：`landedCost = 运费 + 风险金 + 费税 + 途中损耗 + 给养`。
   - 运费，自运时按成本式：（行程钟点 × 承运者与随行人畜的工时价 + 载具折旧）÷ 本趟装载量，装载量受承载能力与体积约束；载具折旧 = 卷三 §4.10 给出的这一趟的耐久损失份额 × 载具的重置估值（`priceFor` 估值角色、成本口径）。雇人承运时，运费取承运人的报价（规则 12）；
   - 风险金 = 货物总值 × 路途损失期望比例，该比例由卷十七路途风险律按沿途各段治安值、货值密度、护卫力量算出；
   - 途中损耗 = 易损份额与保质日数相对行程天数的折损（腐坏归卷三 §4.12）；
   - 给养 = 随行人畜在途日耗（各自的用度类，§4.12 同式）乘行程天数，占用载重。
2. **贩运判据**：一趟贩运可行，当且仅当 `目的地收购报价 × 量 − 出发地购入总价 − landedCost ≥ 购入总价 × minMarginShare`。两地价差不足以覆盖到岸成本就没有人运。区域定价对全品类成立，是这一条对每件货分别求值的结果，没有品类名单。
3. **同一规律两种主体**：名册上的商贩个体与统计层的商贩阶层（卷八 §4.16）用同一判据、同一到岸成本函数。统计商贩按 `statBatchGrain` 的批量粒度成批执行，货与款同样落在真实账户（阶层的聚合账户）上，同样占用路途时间。
4. **选货**：商贩在出发地可售货中，按"每单位载重的预期净利"降序装载直到承载或资金用尽；同利时按资源键字典序。由此货值密度高的货走远路、低的只在邻近流动。
5. **在途**：发车时货从卖方转入承运者的在途用途账户；到达后转入买方或承运者自己的待售账户。在途货计入目的地的 `incoming`。
6. **路上的结局都是记账**：被劫是转移，不是去处：货转入卷十七路途风险律返回的劫者主体名下。劫者主体可以是名册上的个体、组织，也可以是卷八b 犯罪生态在统计层的聚合账户，三者都是真实账户持有人。风险律没有返回任何主体时（出事的原因不是被人取走，或取走者不在模拟范围内），货记入登记的去处 `sink_seized`，在月报里单列，不混进损耗。毁损、腐坏记入对应去处。承运人与货主之间的赔付按运单合同（卷十七登记的合同种类行）结算。
7. **商队**：商队是组织（卷八 §4.1），成员、驮畜、载具都是其持有；规模由资金与预期利润决定；带什么货由出发地的可售量决定（规则 4），所以不同来处的商队带货不同，无需为文明写带货表。
8. **边界贸易只作有限兜底**（"买回渠道"与"钱外流上限"只在本条定义，别处一律引用本条）：
   - 主体：模拟范围之外的对手方登记为边界实体，各挂在一个边界节点地点上，持有真实账户。可以登记多个，但下面的限额都按（资源、模拟范围）全局计，多登记实体不会放大限额。
   - 它卖货给范围内：报价 = `externalPriceIndex[该货必需档]` × 该货估值角色的值（不含稀缺项）+ 从边界节点到买方的到岸成本 + 按 `boundaryMarginShare` 计的利润，经 `executeTrade` 成交。它卖出的货以 `src_boundary` 记来源，属限额通道（§4.1 规则 6）。`src_boundary` 的 `families` 不含铸币与凭证：边界实体不能凭空付钱，它付出的每一个单位都是先前收进来的。
   - 钱外流上限：对每种计价资源，`外流余量 = boundaryCoinOutflowCapShare × 范围内该资源总存量 − 全部边界实体账户里该资源的余额`，下限为零。付给边界实体的钱留在它的账户里，仍在账本之内、仍计入守恒式。
   - 日预算受外流上限约束：某货当日的边界供货限额 = `min(boundaryQuota[能否自产][必需档] × 范围内该货日需求, 外流余量 ÷ 边界报价)`。外流余量为零时，当日所有货的边界供货限额都是零，直到钱被买回。"能否自产"取 `chainOf` 的结果：该货沿上游能追到范围内某处资源场潜力、作物或畜产的，取 `ss_local`，否则取 `ss_none`；前者的份额由内容卡标得更低，使边界只在本地断供时起作用。
   - 买回渠道：边界实体是一个普通的收购者，按规则 2 的贩运判据与 §4.2 规则 6 的收购报价买入范围内的货，与任何商贩同式：它的转售预期价 = `externalPriceIndex` × 估值，减去到岸成本与利润得到收购报价；资金仅限它账户里的余额；选货按规则 4。它买走的货记去处 `sink_boundary`。每买回一笔，它的余额下降、外流余量回升，边界供货随之恢复。范围内没有任何它买得起又有利可图的货时，钱停在它账上，边界供货停在上限，这正是"限制钱外流"的含义。
   - 供给口径：边界实体只有"当日剩余限额"那部分计入 `marketSupply`（§4.2 规则 3）。
   - 来源、去处与边界实体的资金余额都进月报。
9. **本地分销**：聚落内持货人卖空后向本聚落真实持有者进货，是规则 2 在同一地点、运费为零时的特例，不另立规则。
10. **抽取**：路上是否出事的随机抽取归卷十七；本节若需打破完全平局，骰值键按写卷须知的五元组组成（世界种子、流代号、主体、世界时间、抽取点代号），不使用全局计数器。
11. **可及范围**（只在本条定义；卷五规模律、§4.4、§4.7、§4.12 说的"可及范围""可达范围"都指它）：`reachOf(甲地, 货)` = 甲地自身，加上所有满足"把一个 `statBatchGrain` 批量的该货从甲地自运到该地，摊到每单位的到岸成本不超过 `reachCostShare` × 该货估值角色的单价（不含稀缺项）"的地点。到岸成本按规则 1 的自运成本式，读当日路况与沿途治安值。阈值比的是估值而不是现价，所以求范围不读报价，不与价格成环。结果按世界日记忆：同一世界日内只算一次，只由世界内的量决定，与推进方式无关。`demand` 接受这个地点集合作为 `scope`。
12. **承运服务的价**：货主雇人承运时，运费是一项服务的成交价。承运人的要价下限 = 规则 1 的自运成本式算出的成本，加按 `carrierMarginShare` 计的经营利润（与 §4.5 规则 4 的底价同式）；货主的出价上限 = 他自运的成本与这趟货价差净利两者中较小的一个；成交位置由承运服务的紧缺度决定，与 §4.11 规则 4 同式（空缺运力对求运货量）。这个价以用途代号 `puse_carriage` 登记到 §4.21，写进运单条款后按已签条款角色冻结。卷十七只管运单条款与执行，不定价。

#### 4.6.5 数据实例

- 西陲两座相距两日路程的镇：一种低货值密度的燃料，两地价差小于到岸成本，无人贩运，只由近处樵采供给；一种保存用度类的货，产地价低而价差足够，每隔数日有人运一趟；途经一段治安值低的山路后风险金升高，运量随之减少、目的地价上升。
- 非西陲一条沙漠驼道：给养占去大半载重，只有货值密度高的货可行；驼队是一个组织，驮畜的承载取其物种行。
- 非人类一支飞行种族的信使行：承载小、行程钟点短、不受地面路况与路匪影响（风险律输入中的路段不同），于是只贩极轻极贵的货；没有为它写任何特例。

#### 4.6.6 验收断言

- 【扫描】A6-6.1：贩运与周贸易代码中物品 id、粮食类别字面量为 0；对错误消息前缀的分支为 0；规则表中不存在按物品配置的贸易条目。
- 【不变量】A6-6.2：每趟贩运，出发地减少量 = 目的地增加量 + 转入劫者主体的量 + 记入 `sink_seized` 的量 + 记入损耗去处的量；商贩资金变化与成交记录逐笔相符；统计商贩与同条件名册商贩对同一机会的判据结果相同。边界：每个世界日每种货，全部边界实体的供货量之和不超过规则 8 的日限额；任一时刻全部边界实体账户里某计价资源的余额不超过 `boundaryCoinOutflowCapShare` × 范围内总存量（成交前校验）；边界实体的每一笔付款之前其余额足够，`src_boundary` 的累计量里铸币与凭证恒为零；把边界实体登记数翻倍，范围内当日可得的边界供货总量不变。`reachOf` 在同一世界日内多次调用结果相同，分段推进与整段推进相同。
- 【扩展性】A6-6.3：新增一件物品并让某地出产，不改代码：若价差足够它会被贩运到别处，不够则不会；新增一种载具或驮畜物种，运费随其承载自动变化。

### 4.7 生产组织：资源、劳动到物品

#### 4.7.1 维度

读：`recipeView`（卷二 §5.18、卷三 §4.8）、`resourceFields` 与规模律（卷五 §4.7）、取用方法行（卷五 §4.8；本卷只为采掘、伐取等产业方法登记数据行）、设施提供的服务与完好度（卷十九）、技能值（卷十四）。运行态 `jobs`：`{producer, site, recipe 或 method, times, intent, startMinute, minutesLeft, jobstate, inputsLocked}`。规则表 `production.json`：`minMarginShare`、`planHorizonDays`、`switchPenaltyMinutes`、`derivedDemandDepth`、`standardWorkdayMinutes`、`standardSkill`、`investHorizonDays`（§2.5）。读：聚落组织行的保有方式维度（请卷八登记，§5.3）、地点的包含树与控制归属（卷五）、建造需求块与工位数（卷十九 §4.4、§4.3）。

#### 4.7.2 统一入口

读：`productionPlanOf`、`stationPlan`（各活动的工位数上限、利润成立的工位数与应归属的主体；卷十在生成期、卷十九在建造时、本卷在运行期都读它）。写：`planProduction(day)`（开工决策）、`runJobs(day)`（推进；完工时取卷三的 `craftOutcome` 提案或调卷五的 `take`，再经 `post` 记账）。

#### 4.7.3 规则

1. **一件产物三样合力**：产物由材料属性（投入料经卷三 §4.8 继承）、职业技能（技能值进入产率与品质）、意图（选哪条配方、哪个候选、批量、用心程度、取向）共同推出。本卷只决定"谁、在哪、做哪条、做多少"，不改产物公式。
2. **谁能做**：开工条件完全取卷三 §4.8 规则 R-1 与卷五 §4.8 规则 1（需求块、技能门槛、工位服务、工具能力、知识、季节、身体能力）；本卷不加任何职业名、任务名条件。
3. **行业由资源推出**：一个地点可能出现的生产活动 = 该地点及其可及范围（`reachOf`，§4.6 规则 11）内 `resourceFields` 对应的取用方法，加上投入料在可及范围内有供给的全部配方。没有该资源场潜力、又运不来投入料的地方，不会出现这门行业。
4. **人数由需求推出**（两个数，各有用处）：
   - 工位数上限：采取类活动直接取卷五规模律；加工类活动同式：`工位数上限 = floor(min(净需求日量, 可得投入日量折成产出) ÷ 单工位日产)`。
   - 净需求日量 = `demand(reachOf(本地, 产物), 产物)` − 可及范围内别处已有产能的日产（别处同产物的在岗工位数 × 单工位日产）− 时域内 `incoming` 摊到每日的量，下限为零。两个可及范围重叠的产地因此不会各按全量配人；卷五规模律的"可达需求日量"读的就是这个净值。同一世界日内各产地按"到需求地的平均到岸成本升序、平局地点 id 升序"依次求值，先求的占掉的需求后求的看不到，结果只由世界内的量决定。
   - 单工位日产 = `craftOutcome`（采取类为 `take` 的取量式）在 `production.json.standardSkill`、配方的首选候选、缺省意图、一个 `standardWorkdayMinutes` 的工时下算出的产出量。卷五规模律所说的"标准工作日工时"就是 `standardWorkdayMinutes` 这个键。
   - 利润成立的工位数：按规则 5 的营利判据逐个工位求值（每多开一个工位，产出多、售价按 §4.2 规则 4 的边际价下降、投入价上升），取判据仍成立的最大工位数。
   - 实际招工与开工以两者中较小的为准：`实际工位数 = min(工位数上限, 利润成立的工位数)`。上限保证不超出资源与需求，利润判据保证没人做赔本生意；§4.11 的招工清单与规则 10 的停产读的是同一个数，不再各用一套口径。
   地点的职业构成是各活动实际工位数的结果，生成期（卷十）与运行期用同一式，不手调。
5. **开工判据与意图**：自用作业——家户或组织自己缺该物且自产成本低于买价（§4.12 规则 3）；营利作业——`预期售价 × 产出 − 投入现价 − 工钱 − 工位费 ≥ 投入现价 × minMarginShare`。预期售价读 §4.4 规则 4 的预期与当前报价。做哪一种，由生产者在全部可行组合里挑：对每个满足开工条件的（配方或方法、各投入项的候选料、意图取值）组合，调 `craftOutcome` 取产出提案并代入判据。营利作业选预期利润最大的组合，自用作业选满足自家用度所需成本最小的组合；完全相同时按配方代号、候选料代号、意图代号的字典序取第一个。意图因此是生产者按处境做出的选择（求量、求质、求省料各有其利），不是一个永远取缺省值的空字段；玩家与受玩家指派的作业由玩家给出意图，其余同式。
6. **作业推进**：开工时投入料移入生产者的作业占用分区；按清醒且在工位的工时扣减 `minutesLeft`（清醒与在场读卷二 §2.5 谓词）；完工时一笔 `post`：投入记转换去处、产物与副产物记转换来源（§4.1 规则 5），工具磨损由卷三写者记录。中途放弃时未消耗的投入移回。
7. **设施不好用就不产出**：工位所在设施完好度使其不再提供所需服务时（判定归卷十九），开工条件不成立。荒废的作坊不出产是这条规则的结果，不是对某处的排除。
8. **雇工与归属**：受雇者的产物归属按其雇佣合同条款，在完工的同一笔 `post` 中直接记入雇主账户；计件工钱是该合同派生的义务。
9. **非营利生产者同律**：怪物据点、军队后勤、神祠工坊是组织，按同一判据（多为自用作业）开工；战利品加工（卷十三 §4.20）只是配方行。
10. **停产**：预期利润连续低于判据、或投入断供，作业不再续开；工位空出，雇工合同到期不续，劳动力回到 §4.11。
11. **工位数要落成真实的设施与雇主**（"推出的工位数怎样实例化、归谁"只在本条定义）。规则 4 算出的数只是一个数；世界里必须有对应的设施实例和持有它的雇主，招工清单才有来处。本卷给数量与归属规则，实例由别卷落地：
    - 交接接口：`stationPlan(地点)` 返回该地点及其下属地点上每项活动的一行 `{activity: 配方或方法, site: 存量单元或地点, capStations: 工位数上限, viableStations: 利润成立的工位数, ownerRef: 应归属的主体}`。它是纯读入口，生成期与运行期同一函数。
    - 归属怎样推出（`ownerRef`）：先定管辖的聚落组织——从活动所在的地点沿包含树向上，取第一个有聚落组织的站点；所在地点不在任何站点之下时，取 `reachOf` 内到岸成本最小的站点的聚落组织，平局取组织 id 升序。再读该聚落组织行的保有方式维度（由卷八登记，封闭代号）：归组织公有的，`ownerRef` 是该组织；归户的，`ownerRef` 是该聚落里对所需服务有效技能最高、且尚无同类设施的家户（平局家户 id 升序）；归上级的，`ownerRef` 是该组织在卷八隶属关系上的上级组织。一处滨海资源场归哪个镇、归镇上的谁，就是这三步的结果，不靠手填，也不点名任何地点。
    - 生成期（卷十 §4.7）：对每个聚落调 `stationPlan`，按实际工位数（规则 4）经卷十九的建造入口物化设施实例与工位，把建筑资产分录以 `src_genesis` 记到 `ownerRef` 名下（§4.1 规则 5、§4.22 规则 3），再生成从业者并签雇佣合同。完好度为零的旧设施不提供服务（规则 7），不计入已有产能。
    - 运行期（开业与投资）：`stationPlan` 给出的实际工位数大于现有工位数时，`ownerRef` 所指主体（没有余力时，可及范围内任何家户、个人、组织）比较"建造成本"与"`investHorizonDays` 内的预期利润"：建造成本 = 卷十九 §4.4 建造需求块各项按 `priceFor` 成交用途的现价加工时按工钱行情的估值；预期利润按规则 5 的判据式。后者不小于前者就立项，采购与施工与 §4.19 规则 4、5 同式（出资人是自己，不经拨款），完工时建筑资产分录记给出资方。几个主体同时想建同一处时，按 `ownerRef` 优先、其余按出资能力降序、再按 id 升序取一个。
    - 缩减：实际工位数长期小于现有工位数时不拆设施；多出的工位空着，业主不再维护则完好度按卷十九规则下降。
12. **统计层的生产同式**：未物化人口的生产不另设聚合产量公式。统计层的每个阶层按其技能分布的代表值（卷八 §4.16 给出）调同一个 `craftOutcome` 或 `take`，投入从阶层聚合账户记去处、产出记来源，同样受规则 4、5 约束；离屏时怎样把多日合并求值归卷二十七的聚合口径，但结果必须与逐日求值相同。

### 4.8 初加工与精炼产率

#### 4.8.1 维度

产率不是本卷的维度：基础产率是配方行的 `yield`，反应产率是材料行的 `reactionYield`，技能对产率的影响是卷三规则表里的曲线（台账 X-01）。本卷只用到：`chainDepth`（§4.9）、工位费（§4.10）、代工合同种类行 `ckind_tolling`（§4.16）。

#### 4.8.2 统一入口

无新增入口。产率结果读 `craftOutcome` 提案；设施、工具、状态对产率的影响是过程槽上的修正项（卷二 §3.7）。

#### 4.8.3 规则

1. **不另写产率公式**：凡"多少原料出多少成品"一律由卷三 §4.8 规则 R-6 给出。本卷任何模块不得自乘产率系数。
2. **卖原料还是卖成品**：持有原料者比较"原料现价"与"成品预期价 × 产率 − 加工成本"，取高者；加工成本含工钱、工位费、燃料等投入现价。这就是 §4.7 规则 5 的判据对初加工的应用。
3. **代工**：没有工位的人可与工位业主签代工合同：料归委托方，在业主的作业占用分区加工，成品按合同约定的份额或工费交还；份额与工费是条款数值。产率差额（技能高于约定基准多出的部分）归谁，由条款代号指定。
4. **残渣与副产物有主**：卷三规则 R-9 给出的副产物与残渣，记入作业归属方账户；它们是普通物品，有需求就有价，没人要且持有人弃置时才记入去处。
5. **设施对产率的影响只走修正项**：炉窑类型、完好度、所在地点的环境量对产率的作用，由卷十九在过程槽上登记修正项；本卷不读设施类型代号做分支。
6. **产率进报告**：每笔转换的投入量与产出量按材料大类汇入月报的"转换"分组（§4.22），供核对产率是否落在数据给定的区间。

#### 4.8.4 交互

卷三 §4.8（唯一一套产率规则）；卷十九 §4.7（炉窑）、§4.3；卷十四 §4.3；卷二十五 §4.9（烹饪与酿造的配方行与折损数据）；§4.9、§4.10、§4.16、§4.22。

#### 4.8.5 数据实例

- 西陲一处冶坊：矿石到粗锭的配方行带基础产率，矿石材料行带该反应的产率；熟练匠人的技能曲线使同样的矿多出一些锭，全部由卷三算出，本卷只记账。

### 4.9 多级产业链

#### 4.9.1 维度

读：卷三登记的三条配方关系（产出、消耗、下游），以及卷三 §4.9 对拆解、回收、熔毁这类逆向行的标记（拆解由制作需求自动导出，按材料拆与熔毁各有其行；本卷只读"这一行是不是逆向行"这个字段，不读名称）。**正向子图**：去掉全部逆向行之后的配方图。派生：`chainDepth(item)` 只在正向子图上定义 = 0（直接出自资源场、作物、畜产或登记的边界来源者）或 `1 + max(各消耗项首选候选的 chainDepth)`。规则表 `production.json`：`derivedDemandDepth`（派生需求向上游递推的层数上限）。

#### 4.9.2 统一入口

读：`chainOf(itemId)` → `{depth, upstream, downstream, recycledFrom, openEnds}`。

#### 4.9.3 规则

1. **链条长度是数据**：有几级加工只取决于配方表里有几条首尾相接的行；代码里没有"几级产业"的常量或按级分支。
2. **需求逐级上推**：下游作业计划的投入需求是上游的市场需求（§4.4 规则 1 的 `derived`），递推至 `derivedDemandDepth` 层；更上游由再上一级的实际采购在下一个结算日体现。
3. **中间品同为货物**：中间品在账本、市场、贩运上与终端品无差别；其经济大类由卷三 §4.3 规则 C-1 派生为原料，必需档由 C-3 沿下游派生。
4. **各级增值由成本推出**：每级的价值 = 投入价值加工与加成（卷三 §4.16 规则 V-1 的递归），没有"第几级基准价"的表。
5. **短板传导**：某一级的可得投入日量不足时，§4.7 规则 4 使该级工位数受限，其下游各级的可得投入随之下降；短板在哪一级，读各级 `min` 取到哪一项即可，不另设瓶颈状态。
6. **断头检查**：`openEnds` 列出沿上游追不到任何来源的投入项（即卷三规则 R-11 报告中的行）；内容卡必须补来源，规则层不兜底、不允许凭空供货。
7. **逆向行只算供给，不算深度**：拆解、回收、熔毁是方向相反的行（卷三 §4.9）。它们照常可以开工、照常成对记账，产出的回收料是上游的一项额外供给（进入 `marketSupply`，从而压低上游的净需求）。但 `chainDepth`、规则 2 的派生需求递推、规则 6 的断头检查与"配方图无环"的检查，都只在正向子图上做，逆向行不参与：成器能熔回料，不等于料的深度要由成器来定。`chainOf` 的 `upstream`、`downstream` 只列正向关系，逆向来源另列在 `recycledFrom`。

#### 4.9.4 交互

卷三 §4.8、§4.9、§4.16；卷二 §1.12（递归派生的环检测）；卷二十五（作物与畜产是深度零的来源）；卷五 §4.7；§4.4、§4.7。

#### 4.9.5 数据实例

- 西陲一条四级链：矿石、粗锭、精料、成器；成器的需求上升后，四级的工位数在随后若干结算日依次上调。

#### 4.9.6 验收断言

- 【扫描】A6-9.1：规则层中表示产业层级的常量与按层级分支为 0；价格或产量按层级查表为 0。
- 【不变量】A6-9.2：在正向子图上，`chainDepth` 对任一正向行满足"产物深度大于各消耗项首选候选的深度"；正向子图无环（加载期）；`openEnds` 为空。加入任意多条逆向行（含"成器熔回料"这种与正向行首尾相接成环的）之后，各物品的 `chainDepth` 不变，加载不报环。

### 4.10 工位负荷与工费

#### 4.10.1 维度

读：设施实例的工位数与其提供的服务代号（卷十九 §4.3）、借用许可条款（卷十九登记的合同种类行）。运行态 `stationUse.<设施>.<服务>.<日> = 占用分钟`。派生：`stationLoad`。规则表 `station.json`：`loadWindowDays`、`loadFeeCurve`、`baseRateBps`。

#### 4.10.2 统一入口

读：`stationLoad(facilityId, serviceCode)`、`stationFee(facilityId, jobDraft)`。写：占用分钟由 `runJobs` 在推进作业时记入 `stationUse`；工位费是作业开工时的一笔转移。

#### 4.10.3 规则

1. **负荷**：`stationLoad = 窗口内该服务占用分钟之和 ÷（工位数 × 窗口内可用分钟）`，窗口为 `loadWindowDays`；可用分钟按设施的开放时段（卷十九）计。
2. **工费**：`stationFee = 作业估值 ×（baseRateBps + lookup(loadFeeCurve, stationLoad)）+ 业主附加`。作业估值 = 该作业各投入项的基础价值之和（经 `priceFor` 以估值角色取，不含稀缺项），所以工费不随一时的市价波动而被操纵。业主附加是借用许可条款里的数值。
3. **工费是转移**：收款方是设施业主；公共设施的业主是组织，工费进其公库账户。没有业主的无主设施工费为零。
4. **拥挤靠价格疏导**：负荷高的工位工费高，使 §4.7 规则 5 的利润判据在此处先不成立，作业自然流向负荷低的设施或别的聚落。不设"每设施最多几单"的硬上限；唯一的硬约束是物理工位数，同一工位同一分钟只容一项作业，其余排队。
5. **排队**：同一工位的作业按预约的开工分钟先后排；同分钟按生产者 id 升序。业主自己的作业是否优先是借用许可条款的一个数值。
6. **自有工位**：业主用自己的工位不付工费，但占用同样计入负荷。
7. **负荷只由世界内的占用决定**：`stationUse` 按世界日记，离屏聚合推进时按同一口径摊入各日，结果与逐日推进相同。

#### 4.10.4 交互

卷十九 §4.3（工位与借用许可）、§4.15（运营成本）；卷八 §4.1（公共设施的业主组织）；§4.7、§4.8、§4.21、§4.22；卷二十七（离屏聚合口径）。

#### 4.10.5 数据实例

- 西陲一座镇上唯一的铁匠炉：冬前修农具的作业集中，负荷升高、工费上涨，一部分活计流向邻村的炉子。
- 非西陲一处行会公用染坊：业主是行会，成员的借用许可附加为零、外人附加为正；负荷规则相同。
- 超自然一处只在月相合适时开放的祭炼台：可用分钟少，窗口内负荷容易升高，工费随之升高；月相对开放时段的影响由卷十九与卷二十给出，本节不知道也不需要知道原因。

#### 4.10.6 验收断言

- 【扫描】A6-10.1：按设施类型代号或设施 id 写工费的分支为 0；工费系数字面量在规则层为 0。
- 【不变量】A6-10.2：`stationLoad` 在零与一之间；任一工位任一分钟至多一项进行态作业；工费付出等于业主收入；把一段时间分段推进，`stationUse` 逐位相同。
- 【扩展性】A6-10.3：新增一种设施类型并声明其提供的服务代号，不改代码：其工位有负荷、有工费、可被排队与借用。

### 4.11 劳动市场与工作分配

#### 4.11.1 维度

#### 4.11.3 规则

1. **招工清单是派生的**：`laborOffers` = 范围内各雇主（作坊、店铺、商队、农庄、工程、家户、组织）的"实际工位数 − 已雇且在岗人数"展开成的空缺，每条带所需服务代号、技能门槛、每日工时、工作地点。实际工位数取 §4.7 规则 4 的 `min(工位数上限, 利润成立的工位数)`，并且不超过该雇主名下设施现有的物理工位数；利润判据不成立的岗位不挂出。一门行业在当地还没有雇主时，空缺不会凭空出现：先由 §4.7 规则 11 落成设施与雇主，才有这里的空缺。不存"招工帖"。
2. **雇主出价上限**：这个岗位一个工日多创造的价值 = 该服务在该处的单工位日产 × 产物现价 − 投入现价 − 工位费（§4.7 规则 5 的各项）。技能高的人产率与品质高（卷三曲线），其上限自然高；不再有"按技能阶查工价"的表。
3. **求职者要价下限**：其家户按当地现价满足必需档用度的日开销，按家中劳动人数分摊，再加换工摩擦（搬迁、换行的成本摊到 `switchFrictionDays`）。
4. **成交工钱**：在下限与上限之间，位置由 `lookup(labor.json.tightnessCurve, laborTightness)` 决定；`laborTightness = 范围内该服务空缺工时 ÷ 求职工时`。人手紧时靠近上限，人手多时靠近下限；上限低于下限时不成交，岗位空着或人失业。
5. **谁干哪样活**（工作分配）：个体在能胜任（技能门槛、身体能力谓词、需求块中的工具能力）的工作里，按 `workPriority` 档从高到低选，同档取工钱高者，再同取服务代号字典序。身体能力丧失使谓词为假，该类工作自动从可选集合消失，不设"禁用工种"名单。
6. **家户与组织内部分工**：同一规则；不付工钱的家内劳动（自给，§4.12）与受雇劳动竞争同一个人的清醒工时，一个人的工时不会被两处同时占用（占用时间是雇佣合同与作业记录的只读视图）。
7. **工钱形式**：工钱义务的资源可以是任何可转让资源（铸币、实物、成品份额），由合同条款定；实物工钱按 `prole_term` 冻结数量而非价值。
8. **跳槽与辞退**：当别处同类岗位的成交工钱超过现工钱加换工摩擦时，个体在通知期满后终止合同另就；雇主在岗位上限跌破现工钱时不续约。通知期是合同条款。
9. **迁徙的经济拉力**：一地的工钱水平与空缺数作为吸引力分量提供给卷五 §4.15 与卷八 §4.16，由对方决定迁徙；本卷不移动人口。
10. **统计劳动力同口径**：未物化人口的就业按同一上限、下限与紧缺度在阶层层面结算，工钱记入阶层聚合账户。

### 4.12 家户预算与日耗

#### 4.12.1 维度

读：家户成员与构成（卷十八 §4.2；家户是组织行）；用度类全族与物品九维（卷三 §4.3）；替代池折算（卷三 §4.17）；自产配方 `selfMakeRecipe`；可及范围内的资源场与取用方法（卷五）；当地报价；成员的身体需要日需量（卷二十一 §4.4 身体需要条目的 `needDim`，身体值归卷四）；成员的耐寒下限与体内设定温度（卷二十一 §4.7、卷四）；居所的围合与保温、炉窑（卷十九 §4.7）；气温与热交换（卷二十 §4.5）。用度类条目上请卷三登记的四个字段：`needSource: enum need_source`（封闭 3 项：`ns_body` 由身体需要定量、`ns_environment` 由维持居所环境定量、`ns_item` 由物品单位日耗定量）、`bodyNeed: ref 身体需要条目 nullable`（`ns_body` 时必填）、`appliesRX: rx nullable` 与 `scaleRX: rx nullable`（只读成员的物种与身体数值维度：是否适用、用量倍率）。运行态 `householdEcon.<家户>.lastSettledDay`、`lastUnmet`。规则表 `household.json`：`selfSupplyTimeShare`、`tierOrder`、`minShortageShare`。

#### 4.12.2 统一入口

读：`householdBudget(householdId, day)`、`unmetSupply`。写：`settleHouseholds(day)`（逐日结算全部家户与统计家户；消耗经 `post` 记入去处）。缺量后果不在本卷：本卷在缺量上只产出一个量——未满足供给量；身体后果统一由卷二十一的身体需要与病程律给出，心理后果由卷二十六的需求容器给出（规则 7）。

#### 4.12.3 规则

1. **需要量遍历用度类全族，随成员的物种与身体而变**（需要量只在本条定义；§4.4、§4.11 都引用本条）。对用度类族的每个条目，按条目的 `needSource` 取家户当日需要量：
   - `ns_body`：需要量 = 家户各成员该身体需要的日需量之和。日需量读卷二十一身体需要条目 `needDim` 所指的个体维度（修正后值），这个值由卷四的代谢、体量、物种维度与当日劳作强度推出，本卷不另存"每人日用量"。日需量为零的成员（不进食的物种）贡献为零。物品能满足多少，按卷三材料上归属该需要的营养量折算，与卷二十一补给律用同一折算。
   - `ns_environment`：需要量 = 把居所维持到"各成员的体感温度都不低于各自耐寒下限"当日所需的热量，由卷二十的热交换入口按当日气温、居所的围合与保温、炉窑效率反推，再按卷三 §4.17 的总热量折算换成燃料池单位。体内设定温度为空的成员（不受冷热影响的物种）不计入；天暖或屋子保温好时需要量自己变小，不靠季节系数。
   - `ns_item`：其余用度（照明、器用、仪式、牲畜饲料、作坊耗材等），需要量 = Σ（按条目计数方式取到的计数：人、户、畜、工位、仪式等）× 物品单位日耗 × 当季用度系数 × 成员倍率。某成员是否计入、倍率多少，由条目的 `appliesRX`、`scaleRX` 读该成员的物种与身体数值维度得出；两个字段为空时全员计入、倍率为一。
   三种来源算出的量都换成池单位进入规则 2。代码不出现任何用度类代号；新增一个条目即多一项日耗。
2. **满足次序**（对每个用度类同式）：① 家中自用储备；② 自给——用家庭成员的空余清醒工时去取用或自制；③ 购买；④ 赊欠与受赠（§4.15、卷十八）；⑤ 仍不足即缺量。
3. **自给是通用地形规则的结果**：家户成员可以对可及范围内任何存量单元调用卷五的取用律，条件只有取用律自己的可行性（方法、工具能力、身体能力、在场）与本户的时间预算（`selfSupplyTimeShare` 乘空余清醒工时，含往返行程钟点）。聚落的站点类型不是条件：靠近林地、水体、滩涂的城镇居民与村民同律，近处存量被取到再生跟不上时取量自然下降，差额转向购买。自制读 `selfMakeRecipe` 并走 §4.7 的自用判据。
4. **预算按必需档分配**：购买时按 `tierOrder` 从最要紧的档开始花钱，同档内按"每单位池量的现价"升序选成员并经习惯权重调整（§4.4 规则 2）。目标是偏好，不是转移：预算视图本身不动任何账户。
5. **消耗记账与分到人**：当日实际用掉的量从自用储备记入消耗去处（`sink_consume`）。满足量在成员之间按各自需要量的比例分（向下取整，余数按成员 id 升序逐个补一单位）。每个成员实际吃下的部分，由本卷按卷二十一摄入钩子要求的形状发一条摄入事件（成员、批次、质量）；实际烧掉的燃料发一条燃烧事件（居所、批次、质量），交卷十九的炉窑与卷二十的温度场。本卷到此为止，物性与身体上的变化都由对方的写者处理。
6. **未满足供给量**（本卷在缺量上的全部产出）：对每个用度类、每个成员，`未满足供给量 = 需要量 − 实际满足量`，`缺量比例 = 未满足供给量 ÷ 需要量`。缺量比例高于 `minShortageShare` 时，发一条未满足供给量事件，携带（成员或阶层引用、用度类代号及其 `bodyNeed`、需要量、满足量、世界日），并写入 `householdEcon.<家户>.lastUnmet`，供 `unmetSupply` 读。事件只带数量，不带效果调用、不带档位。
7. **后果只走一条通道**（缺量后果的唯一口径；别处一律引用本条）。本卷不施加任何后果，不调用用度类条目上的任何效果调用，也不维护缺量的累积与分档：
   - 身体后果只有一个写者：卷二十一。进食不足的后果来自它的身体需要亏空容器——没吃到就没有摄入事件，亏空按它的消耗律上涨，逐级到致死都按它的分档与病程律走。取暖不足的后果来自温度场——烧得少、室温低，体感温度低于耐寒下限，同样由卷二十一的环境温度一节逐级给出。两者都是物理通道自己的结果，未满足供给量事件不再对同一个人追加任何扣罚。
   - 统计层没有逐人的摄入事件：卷二十一按阶层只存人均亏空，它的供给一项取本卷结算出的满足量（需要量减未满足供给量）。这是同一个量换一种取法，仍只有卷二十一一个写者。
   - 心理后果只有一个写者：卷二十六。它的需求容器订阅未满足供给量事件；`ns_item` 类用度（舒适、仪式、器用）缺了，后果只在这里。
   - 取暖与食物两类需要同级：都只经卷二十一的同一套"亏空或暴露逐级加重、长期处于最重档才可能致死"的机制，区别只在各自条目与物种的数据。本卷代码里没有任何一个用度类的专门后果。
   第一版让用度类条目的缺量效果调用再施加一遍后果，与卷二十一重复计罚，已删除；卷三用度类条目上原拟的缺量效果字段，本卷不再使用（§5.3 请卷三撤下或留空）。
8. **不花钱的东西**：可及范围内可以零成本取用的用度（如有可及水体时的饮水）由规则 3 自然满足，不需要"免费"标记。
9. **统计家户同口径**：统计层的家户按同一规则以阶层聚合账户结算，需要量取阶层成员构成的日需量之和；未满足供给量按阶层发出，由卷二十一、卷二十六各自的聚合口径接收（规则 7）。名册为空的聚落同样会缺、会买、会自给。
10. **逐日且与路径无关**：结算以世界日为步，`lastSettledDay` 之后的每一日各算一次；一次推进多日等同逐日推进。

### 4.13 货币、铸币成色与汇率

#### 4.13.1 维度

`coin` 族条目：`metal`（各金属材料的质量份额，即成色）、`massG`、`issuer`、`faceCount`。读：金属材料的估值（卷三 §4.16）、范围内该币存量（`stockIn`）、近期以该币计价的成交枚数（`tradeCount`）。派生：`coinValue`。规则表 `currency.json`：`abundanceCurve`、`acceptanceCurve`、`neutralAcceptance`、`mintFeeBps`、`mintLossShare`、`meltLossShare`、`turnoverDays`（§2.5）。

#### 4.13.2 统一入口

读：`coinValue(currency, placeId)`、`exchangeRate(resourceA, resourceB, placeId)`。写：`mintCoin`、`meltCoin`。

#### 4.13.3 规则

1. **铸币是物**：一枚币的内在价值 = 其金属含量（`massG × metal` 各份额）按材料估值之和。铸币账户与物品账户同在账本里，守恒式相同。
2. **铸造是成对转换**：`mintCoin` 在提供铸造服务的设施里，把金属料记入转换去处、等金属量的新币记入转换来源；金属质量逐腿核对相等（扣除 `currency.json.mintLossShare` 给出的工艺损耗，损耗记入损耗去处）。铸造费是付给发行者的转移。铸币的来源只有两项，明列如下：铸造（本条），与世界生成第 0 日的开局入账（`src_genesis`，§4.22 规则 3）。边界不是铸币的来源：边界实体付出的币都是它先前收进来的（§4.6 规则 8）。除这两项外没有任何途径能让铸币总量增加。
3. **熔毁对称**：`meltCoin` 把币记入去处、金属料记入来源，损耗同理。
4. **购买力**：`coinValue = 内在价值 × lookup(abundanceCurve, 充裕度) × lookup(acceptanceCurve, 接受度)`。充裕度 = 范围内该币存量 ÷（`tradeCount` 给出的近期日均成交枚数 × `currency.json.turnoverDays`）。分子分母都以该币自己的枚数计：成交记录里本来就存着每笔的计价资源与数额，直接求和，不折成价值单位，所以求 `coinValue` 不需要先知道 `coinValue`，没有环。钱少则每枚值得多，物价（以该币计）随之下降，钱多则反之。窗口内没有以该币计价的成交时，充裕度取曲线的中点并记缺口。接受度读发行者在当地的正统性数值与法偿地位（卷八、卷八b 的维度），发行者为空的币接受度取 `currency.json.neutralAcceptance`。
5. **以币计价**：任何报价先以价值单位算出，再除以支付所用币的 `coinValue` 得到枚数，按最小记账单位向上取整（差额归卖方，不产生来源）。
6. **汇率是两种购买力之比**：`exchangeRate(A, B) = coinValue(A) ÷ coinValue(B)`，对非铸币资源则用其 `priceFor` 估值。汇率不存；兑换是一笔普通成交，兑换商的价差按 §4.2 规则 6。
7. **减色**：发行者改铸成色更低的新币是新增一条 `coin` 条目；旧币内在价值更高、被熔或被藏是规则 1 与规则 4 之下持有者自利决策的结果，不写"劣币驱逐良币"规则。
8. **财富与触发**：铸币计入财富汇流（§4.24）；财富对袭击、封爵等的影响由读财富的那些卷决定。
9. **发行权**：谁可以调用 `mintCoin` 由法域条款与铸造设施的持有决定（卷八b、卷十九）；本卷只在动作可行性里读其结果代号。无权铸造同样可行，只是另产生一条供认定的事实（私铸）。

#### 4.13.4 交互

卷三 §4.1、§4.16（金属材料与估值）；卷八（发行者组织、正统性）；卷八b（法偿与私铸的认定）；卷十九（铸造设施与服务）；卷二 §5.23（`coin` 族位置）；§4.1、§4.2、§4.14、§4.22。

#### 4.13.5 数据实例

- 西陲一种银币：发行者是一个王国组织；边远山村里该币存量少而成交仍在，充裕度低，一枚能买到的东西比都城多。
- 非西陲一个城邦改铸含铜更多的新币：新旧两条条目并存，旧币被商人熔成银料出口，月报的"熔毁"分组上升。
- 非人类一个矮人氏族铸的方孔铁钱：发行者在人类聚落的接受度低，购买力接近其金属价值；规则同式。

#### 4.13.6 验收断言

- 【扫描】A6-13.1：规则层铸币种类 id 字面量为 0；汇率、购买力的存储字段为 0；带铸币来源腿的调用点只有两处：`mintCoin`，与世界生成器的开局入账（调用图白名单，S6-13 同法）；`src_boundary` 条目的 `families` 不含铸币族（加载期校验）。
- 【不变量】A6-13.2：每种铸币，全世界余额和（含边界实体账户里的）= 开局入账 + 累计铸造 − 累计熔毁 − 累计记入其余各登记去处的量（损耗、随实体离开范围等）；第 0 日之后 `src_genesis` 的累计量不再变化；每次铸造与熔毁前后金属质量守恒（计入登记损耗）；`coinValue` 的求值依赖图里不出现它自己（卷二 §1.12 的环检测通过）；`exchangeRate(A,B) × exchangeRate(B,A)` 在定点精度内为一。
- 【扩展性】A6-13.3：新增一条 `coin` 条目（新金属配比、新发行者），不改代码：可铸、可熔、有购买力与汇率、进月报。

### 4.14 多币与非铸币计价单位

#### 4.14.1 维度

读：资源种类行的 `unitOfAccount`、`transferable`、`issuerBacked`；合同的 `denomination`；成交记录里的计价资源。派生：`denomination(place)`。

#### 4.14.2 统一入口

读：`denomination(placeId)`、`exchangeRate`。写：无（多币只是账本里多种资源）。

#### 4.14.3 规则

1. **多币天然成立**：账户按资源分开，一个持有人可同时持有任意多种铸币与点数；没有"主钱包"字段。
2. **当地计价单位是派生的**：`denomination(place)` = 该地点成交记录窗口内，按成交额加权的计价资源众数（平局取代号字典序最小，卷二 §1.12 的 `mode`）；没有成交记录的地点沿包含树向上取最近一层的值。全世界没有缺省币。
3. **非铸币可以计价**：凡 `unitOfAccount` 为真的资源（某种实物的一个计量单位、一头牲畜、一个工日、一种点数）都可作合同计价资源与报价单位；其购买力就是它的估值。各地用什么计价，是当地成交记录的结果。
4. **计价与支付分开**：合同以计价资源冻结数额（§4.21 的已签条款角色）；履行时可用别的资源支付，数量按履行当时的 `exchangeRate` 折算，是否必须接受由合同条款的"指定支付资源"与法偿规定（卷八b）决定。
5. **发行者点数**：组织可以发行 `tr_bound` 且 `issuerBacked` 的点数资源（商号积分、行会工分、军功券）：发放时发行者同时负上兑付义务，持有人只能向发行者兑换其货物或服务；不可在第三方之间转。它是第二货币，但不破坏守恒，因为每一点都对应发行者的一笔义务。
6. **找零与凑整**：支付资源的最小记账单位不足以表达应付额时，向上取整到一个最小单位，差额归收款方；可用另一种资源找零时由双方决策，不强制。
7. **兑换损耗只来自价差与费用**：不存在系统兑换窗口；一切兑换都有真实对手方。

#### 4.14.4 交互

卷八b（法偿）；卷七、卷八、卷十八（各自登记点数类资源种类行）；卷十四（服务代号用于"以工日计价"）；§4.1、§4.13、§4.15、§4.16、§4.21。

#### 4.14.5 数据实例

- 西陲一处边市：两国铸币并行，`denomination` 随哪国商队来得多而在两者间变动；旧合同仍按签约时的计价资源结算。
- 非西陲一个游牧部落：计价资源是一种牲畜；聘礼、赔偿、借贷都以头数冻结，可用等值的毡、奶制品支付。
- 超自然一座妖市：计价资源是一种由市主发行的点数（只可与市主往来），入市者先用铸币或物品向市主换取；离市前可换回，市主的兑付义务与点数余额恒等。

#### 4.14.6 验收断言

- 【扫描】A6-14.1：规则层与数据中"缺省币"常量为 0；非铸币计价单位被填成某一种铸币 id 的行为 0。
- 【不变量】A6-14.2：每种 `issuerBacked` 点数，持有人余额和等于发行者未清兑付义务；任一合同存续期内 `denomination` 不变；以任意支付资源履行后，债权人所得按履行时汇率折回计价资源等于应付额（取整差在一个最小单位内）。
- 【扩展性】A6-14.3：把一种现有物品的资源种类行 `unitOfAccount` 设为真，不改代码：它可被合同选作计价资源，可在成交足够多的地点成为当地计价单位。

### 4.15 信用、钱庄与典当

#### 4.15.1 维度

合同种类行：`ckind_loan`、`ckind_deposit`、`ckind_pledge`、`ckind_remit`（汇兑）、`ckind_note`（凭证发行）。过程槽 `process.interestRate`、`process.coinCredit`（卷二 §3.7 已迁入）。派生：`creditStanding`。规则表 `credit.json`：`reserveShare`、`standingWeights`、`pawnAdvanceCurve`、`rateBaseline`、`insurerMarginShare`（§2.5）。

#### 4.15.2 统一入口

读：`creditStanding(subjectId, lenderId)`。写：全部经 `contractStep` 与 `settleObligations`；押品进出是 `post`。

#### 4.15.3 规则

1. **借贷不造钱**：放款是贷方到借方的一笔转移加一条还本付息义务；还款反向。全程没有来源腿，货币总量不变。
2. **利率**：基线取 `rateBaseline`，加上由资信、期限、有无押品算出的修正项，全部进 `process.interestRate` 的管线并受槽的界限约束；利息是义务，不是自动增殖的余额。
3. **资信是派生的**：`creditStanding` = 权重表对以下分量的合成——该主体在贷方知情范围内（卷二十二）的义务履行记录（按期、迟延、违约的次数与金额）、净资产估值（`wealth` 的个人口径）、既有负债、与贷方的立场数值。不存"信用分"。
4. **存款是债权**：存入是存户到钱庄的转移加钱庄对存户的即期偿还义务；存单若可转让，则是 `issuerBacked` 的凭证类资源。钱庄可把收到的钱再贷出，但须满足准备约束：对每一种计价资源分别核算，其库存的该资源 ≥ `reserveShare` × 以该资源计价的未清即期存款义务，不满足时不得新放出该资源的款（放款动作可行性为假）；不同币种不合并、不互抵。
5. **挤兑是结果**：存户凭义务随时支取；库存不足以支付时义务违约，转入卷八b §4.15 的救济与清算，钱庄可以倒闭。没有系统兜底。
6. **汇兑**：甲地存入、乙地支取，是钱庄两处分号之间的内部义务加日后的实物清算运输（§4.6）；清算前乙地分号必须真有钱可付。
7. **典当**：押品从出当人转入当铺的质押用途账户；当金 = `priceFor(押品清算用途, 押品)` × `lookup(pawnAdvanceCurve, 押品类别维度)`；赎回时反向并付息；逾期未赎，押品从质押分区转入当铺自由分区（没收是转移）。押品在质押期间不可售（该用途分区 `visibleToMarket` 为假）。
8. **谁能经营**：经营钱庄、当铺、代理的资格读职业与设施提供的服务代号、以及法域许可条款的结果代号，不读职业名。
9. **赊账**：店铺对熟客的赊销是一条短期给付义务，额度由资信给出，同规则 1–3。
10. **履约窗口**：还款、支取需要双方在场的，读卷二 §2.5 的清醒与在场谓词；不读活动文字。

#### 4.15.4 交互

卷八b §4.15（违约、救济、时效）、§4.2（案件程序）；卷二十二（履行记录的知情范围）；卷十八（立场数值）；卷十四（服务代号）；卷十九（钱庄、当铺设施）；§4.1、§4.14、§4.16、§4.21。

#### 4.15.5 数据实例

- 西陲一家镇上钱庄：收存农户秋后卖粮款，贷给春耕缺种的农户；一年歉收后多笔贷款迟延，其库存跌到准备约束之下，停止放款。
- 非西陲一家跨海汇兑行：商人在此港存银、彼港取银，两港分号每季用船运银清算；船沉则清算延后，彼港分号可能付不出。
- 超自然一位以寿数放贷的妖物：贷出的是铸币，押的是一种由卷十五登记的点数类资源（转让受限）；利率、违约、没收走同一套规则，违约的超自然后果是合同种类行里的效果调用。

#### 4.15.6 验收断言

- 【扫描】A6-15.1：信用代码中含非 ASCII 字符的正则字面量为 0、S6-5 与 S6-6 计数为 0、十进制系数字面量为 0；合同种类族里每个代号在全部数据文件中恰好定义一次（加载期按 id 唯一性校验，重复即报错；三处重复的钱庄默认行因此无法并存），代码中构造合同种类行对象字面量的位置为 0；带来源腿的放款、付息调用点为 0。
- 【不变量】A6-15.2：每笔贷款，借方累计收到 = 贷方累计付出，还本付息同理；钱庄未清即期存款义务 = 各存户债权之和；质押分区余额 = 未了结质押合同的押品量；任何时刻货币总量不因借贷、存取、典当而变。
- 【扩展性】A6-15.3：新增一种信用合同种类行（例如合会式轮流借贷），只写条款与义务模板，不改代码即可签订、结算、违约转救济。

### 4.16 合同状态机

#### 4.16.1 维度

§2.4 的合同与义务记录；`ckind`、`obl`、`crole`、`cterm`、`cphase`、`ophase` 六族。合同阶段（封闭 9 项）：`cphase_draft`、`cphase_offered`、`cphase_active`、`cphase_suspended`、`cphase_fulfilled`、`cphase_breached`、`cphase_cancelled`、`cphase_expired`、`cphase_void`。义务阶段（封闭 7 项）：`ophase_pending`、`ophase_due`、`ophase_partial`、`ophase_done`、`ophase_defaulted`、`ophase_waived`、`ophase_lapsed`。迁移表在 `contract.json`（键：种类、当前阶段、迁移代号；值：下一阶段与须满足的条件代号）。

#### 4.16.2 统一入口

读：`contractView`、`obligationsOf`。写：`contractStep`（要约、承诺、生效、履行一项义务、中止、解除、转让、到期、认定违约）、`settleObligations(day)`。全书一切承诺都走这一套（台账 X-31）：借贷、雇佣、租借、托运、保管、保险、远期、拍卖、代工由本卷登记种类行；运单（卷十七）、封建契约与朝贡（卷八）、婚约（卷十八）、超自然契约（卷十五）、借用许可与住宿（卷十九）、师徒（卷十四）由各卷登记种类行。

#### 4.16.3 规则

1. **合同是数据行的实例**：签一份合同 = 选种类行、填角色与条款数值；义务由种类行的 `obligationTemplate` 按条款派生。代码里没有任何合同种类的专门分支。
2. **生效须同意与权能**：从要约到生效，须各方的同意与处分权（卷九 §4.5、卷八b §4.6）成立；`requiresWitness` 为真者还需见证持有边。不满足时停在要约阶段。
3. **托管**：种类行的 `escrowRule` 所列资源在生效的同一事务里移入各方的托管用途分区（押金、货款、报酬、保证金同式，实物与钱同式）；托管分区 `spendable` 为假。合同了结时按结果在同一事务里释放。
4. **条款冻结**：生效时把价格、数量、计价资源写入 `terms`，此后只读（§4.21 的已签条款角色）；市价变化不影响已签条款。
5. **义务生命周期**：`ophase_pending` 在条件成立且进入窗口时转为到期；窗口内全额给付转为完成，部分给付（种类行允许时）转为部分；窗口结束且过宽限仍未足额转为违约；债权人放弃转为免除；时效届满（期限读卷八b）转为失效。给付本身是一笔 `post`，与阶段变更同一事务。
6. **到期结算与路径无关**：`settleObligations` 按义务窗口的世界分钟与调度器的到期语义（卷二十 §4.1）触发；自动给付只在债务人的决策规则选择履行且自由余额足够时发生。同一分钟到期的多项义务按义务 id 升序处理。
7. **需要在场的履行**：`needsPresence` 为真的义务（当面交付、亲自提供工时）要求双方或其代理在履行地且清醒，读卷二 §2.5 谓词；窗口取种类行条款，不读任何活动文字。
8. **合同阶段由义务汇总**：全部义务完成或免除，合同转为已履行；任一义务违约且未在补正期内补足，合同转为已违约并调用种类行的 `breachHandler`（救济、赔偿、时效、代理、无权处分、善意取得全在卷八b §4.15，本卷不写）；`effectOnBreach` 非空时同时发出其效果调用。
9. **转让与解除**：`assignable` 的合同可把一方角色换人（债权转让、转租、保单转让），是一次迁移；`terminableBy` 所列角色可在通知期后解除，未到期义务转为失效并按条款结算托管。
10. **当事人终止**：一方实体终止时，其义务按卷二 §2.6 的后继规则转给后继或进入清算；无后继的债权失效，托管按条款释放。
11. **保险**（`ckind_insurance`，全由字段组成）：保费是投保人到承保人的给付义务，`qtyRX` 为"保额条款 × 费率条款"；费率由承保人签约前按标的的风险律期望损失加 `credit.json.insurerMarginShare` 的利润报出，签约时冻结为条款。赔付是模板里带 `triggerEvent` 的一条义务：所指事件类型是标的的毁损或灭失事件，`qtyRX` 为 `priceOf(保险赔付用途, 标的) × 承保比例条款`；该用途的估值取材料与成本口径、不含稀缺项，低于市价以抑制骗保。赔付是承保人到投保人的转移，承保人付不出即违约。免赔情形写在该义务的 `conditionRX` 里（只读事件计数与代号，如标的因投保人犯罪被没收的事件计数为零）。
12. **拍卖**（`ckind_auction`，全由字段组成）：出价是一次迁移；`escrowRule` 里出价款那一行的 `replaceOn` 指向出价迁移，于是新出价进托管与前一最高出价释放在同一事务完成；`releaseOn` 指向流拍迁移。截止分钟到时由到期迁移成交：托管款转给卖方、标的转给最高出价者，都是模板派生的义务。
13. **租借**（`ckind_lease`，全由字段组成）：交付义务把标的的占有转给承租方（物品入承租方的借用用途分区，地产为持有边）；到期返还义务由模板派生；损耗赔偿是带 `triggerEvent`（返还事件）的义务，`qtyRX` 为 `priceOf(估值用途, 标的)` 在交付与返还两个时点之差，押金那一行托管的 `releaseOn` 指向返还完成的迁移。
14. **机制只由字段组合**：规则 11 至 13 用到的"事件触发的义务""按迁移释放的托管""按迁移顶替的托管""数量里取估值"四样，分别是 `triggerEvent`、`releaseOn`、`replaceOn` 与 `priceOf` 原语（§2.4）。`contractStep` 只解释这些字段与迁移表；`contract.json` 的键与迁移表里不出现任何合同种类的专名分支，别卷登记的新种类可以自由组合这四样。

### 4.17 远期、托运与在途

#### 4.17.1 维度

合同种类行：`ckind_forward`（远期买卖）、`ckind_custody`（保管与寄售）；托运的种类行由卷十七登记。用途分区：`purpose_transit`、`purpose_custody`、`purpose_escrow`。派生：`incoming`。

#### 4.17.2 统一入口

读：`incoming(placeId, goodRef, horizonDays)`。写：经 `contractStep` 与 `post`。

#### 4.17.3 规则

1. **远期**：约定未来某窗口在某地交付某量某货，价格签约时冻结；买方的货款或定金、卖方的保证金按 `escrowRule` 托管。交付义务到期时卖方须真有货，没有则违约，不凭空生成。
2. **在途货在账上，预期到货不重复数**：任何时刻，在路上的货都在承运者的 `purpose_transit` 分区里，数量、批次如实。`incoming(地点, 货, 时域)` = 预计在时域内到达该地的在途分区货量，加上"未到期、且尚未发运"的远期交付义务量。一项远期义务一旦发运，运单上带着它的义务 id，这部分货只按在途数一次，不再按义务数；卖方为履约备下、还没发运的货，已从他的可售量里扣掉（§4.2 规则 2），所以同一批货在"卖方可售""远期义务""在途"三处里恰好只被数一次。
3. **预期到货进入供给而非库存**：`incoming` 计入 `marketSupply`（§4.2 规则 3），使"货船将至"压低现价；但到货前不可成交现货，`fillable` 只数现货。
4. **寄售与保管**：货移入保管人的 `purpose_custody` 分区；寄售时该分区对市场可见，售出款先入保管人的托管分区，再按合同给付寄售人并扣佣金。保管人挪用是把货移出该分区，可行但产生一条供认定的事实（卷八b）。
5. **托运的货与货主**：托运时货入承运人在途分区，货主持有运单合同的交付债权；货损、货差、迟延的赔偿是该合同的义务。
6. **到达即记账**：到达事件在同一事务里把在途分区的货转入收货方并了结交付义务；收货方不在场时转入其在当地的保管安排，没有则留在承运人保管分区并开始计保管费（§4.3 的条目）。
7. **在途不免腐坏**：在途批次照常按卷三 §4.12 腐坏，腐坏物记入去处。

#### 4.17.4 交互

卷十七 §4.3（运单、货损、索赔）；卷三 §4.4、§4.12；卷八b（挪用的认定）；卷二十 §4.1；§4.2、§4.3、§4.6、§4.16。

#### 4.17.5 数据实例

- 西陲一位磨坊主春天向农户订下秋后的谷：价格冻结、付定金入托管；秋后歉收，农户交不足，部分履行后余额违约。
- 非西陲一支船队在途的香料：两月后到港的数量已计入目的港的供给预期，当地现价提前回落。
- 非人类一个地精氏族替人保管矿石并寄售：货在其保管分区，售出后扣佣给付；氏族解散时按终止协议，保管物返还寄存人。

#### 4.17.6 验收断言

- 【扫描】A6-17.1：在途、托管、保管的数量存放在账本之外的字段为 0；远期交付时带来源腿的记账为 0。
- 【不变量】A6-17.2：`incoming` 等于时域内到达的在途分区货量与"未到期且未发运"的交付义务量之和；去重：对任一远期合同，在它从签约到交付的任何时刻，它的标的量在全世界各地 `marketSupply` 里合计恰好被计入一次（签约后发运前计在目的地的义务项，发运后计在目的地的在途项，卖方所在地的可售量里不含它）；任一运单，发出量 = 到达量 + 转入劫者主体的量 + 记入 `sink_seized` 的量 + 记入损耗去处的量；托管、保管分区的余额只因合同迁移而变。
- 【扩展性】A6-17.3：新增一种远期变体的合同种类行（例如分期交付），不改代码：其未到期交付自动计入 `incoming`。

### 4.18 资产、地产、租约与维护责任

#### 4.18.1 维度

读：持有边（所有、租用、使用，种类表归卷十八 §4.1）；地点行的设施类型、地形、组件类、完好度（卷五、卷十九）；维护需求（卷十九 §4.1、§4.9）。`landuse` 族（§2.2）。派生：`landUse(place)`。合同种类行 `ckind_lease`、`ckind_tenancy`（田佃）、`ckind_sale_property`。建筑资产分录（`resfam_asset`，§2.1；资产种类取卷十九 §4.2 的设施类型）。规则表 `property.json`：`capitalizationYears`、`vacancyCurve`、`valuationOrder`、`rentPositionCurve`（§2.5）。

#### 4.18.2 统一入口

读：`propertyView(placeId)`。写：产权变动是"持有边变更加款项 `post`"的同一事务，经 `contractStep`；本卷为地点类实体向卷三的 `registerValuer` 登记估值器。

#### 4.18.3 规则

1. **用地类别是派生的**：`landUse = first(landuse 族各条目的 whenRX)`，条件只读地点的设施类型代号、地形、组件类、土壤与面积等维度。田、铺、宅、矿、林、场的区分不读名称与用途文字。
2. **资产是持有加估值；建筑有账本分录，土地没有**：一个主体的资产 = 其账户余额 + 其持有边的标的。造出来的建筑（设施实例）进账本：它的所有权份额是 `resfam_asset` 的分录，建成时由转换产出（§4.1 规则 5、§4.19 规则 5），一处实例共一万基点，可按份额分属多人。分录只记"谁占多少份额"，不记价值；价值由估值器给出。建筑的所有权份额以这笔分录为唯一存储，卷十八的"所有"持有边对建筑而言是它的只读投影。土地本身（地点，不是造出来的）不进账本，归属仍只是持有边。
3. **地产估值**：`priceFor(估值用途, 地点)` 按 `property.json.valuationOrder` 列出的口径次序取第一个可得的：租金资本化口径——年净租金 × `capitalizationYears` × `lookup(vacancyCurve, 当地同类空置比例)`，年净租金取现行租约条款；同类租金口径——当地同 `landUse` 的近期租金中位数按面积与完好度折算后同式资本化；重置成本口径——建造需求块各项按估值角色的值之和 × 完好度。次序是规则表的一个键，不在代码。
4. **租金由收益定**：出租人的要价下限 = 维护成本加税；承租人的出价上限 = 用此地能得的净收益（田按预期收成估值，铺按预期经营利润，宅按家户住房用度的预算份额）；成交位置 = `lookup(property.json.rentPositionCurve, 当地同类空置比例)`，空置多时靠近下限。没有租金表。
5. **承租资格**：读需求块与谓词（是否具备耕作、经营所需的技能门槛、是否已有同类持有且超过条款上限），不读职业名。
6. **租约内容**：租期、租金及其资源与周期、押金、可否转租、维护责任方（`maintainer` 条款：出租人或承租人）、收成分成比例（田佃）都是条款数值；租金与返还是模板派生的义务。
7. **维护责任**：卷十九给出每处设施的维护需求（材料按类别与能力的需求块，全材料类适用，不限于个别建材）；责任方按条款负采购与工时的成本，采购是普通成交，施工是作业（§4.7）。责任方不履行，完好度按卷十九规则下降，服务随之丧失（§4.7 规则 7），并构成合同上的不履行。
8. **买卖**：建筑买卖是同一笔 `post` 里资产份额腿与价款腿对转（可以只卖一部分份额）；土地买卖把所有持有边换人并在同一事务完成价款 `post`；存续租约随物转移（承租人不变，出租人角色转让）。建筑被拆除或毁损时，资产分录记入去处（拆出的材料同笔记来源，§4.1 规则 5）。
9. **床位与短租**：住宿是卷十九登记的合同种类行，按同一状态机；本卷只提供其给付结算。
10. **无主与弃置**：持有人终止且无后继时，地产按终止协议成为无主或归上级组织（卷八规则）；无主地产没有租金、不被维护。

卷十八 §4.1（持有种类）；卷十九 §4.1、§4.8、§4.9、§4.15（建筑、住宿、维护、运营成本）；卷五（地点维度）；卷八 §4.11（地产相关税种）；卷八b §4.6（处分权）；卷二十五（收成预期）；卷三 §4.16（`registerValuer`）；§4.16、§4.21、§4.24。

- 西陲一块佃田：`landUse` 由"地形为平地且土壤肥力高于阈值且无设施"的条目命中；分成比例是条款；歉年分成自动减少，不需改租。

### 4.19 公共工程与公库拨款

#### 4.19.1 维度

运行态 `projects.<工程>`：`{sponsor: ref org, target: ref place 或待建设施类型, requirement: ref vocab requirement, budget: 资源与数额, appropriated, spent, jobstate, jobs}`。读：公共设施的维护需求（卷十九 §4.9）、建造需求块（卷十九 §4.4）、组织的公库账户与议案阶段（卷八 §4.1）。规则表 `works.json`：`trancheShares`、`procureHorizonDays`。

#### 4.19.2 统一入口

读：`projectView`。写：`appropriate(projectId, amount, ctx)`；采购与施工走 `executeTrade`、`contractStep`、`runJobs`。

#### 4.19.3 规则

1. **公库是组织的账户**：账户归属与分区由卷八定义，本卷只规定钱怎样从公库流到工程（台账 X-29）。公库收入（税、工费、租金、罚没）全部是别处来的转移，公库不能凭空增加。
2. **立项**：工程由有权职位发起（权能读卷八），其 `requirement` 取自卷十九的维护需求或建造需求块；预算 = 需求块各项按当地现价的估值加工时按当地工钱行情的估值。立项本身不动钱。
3. **拨款**：议案通过后（阶段读卷八），`appropriate` 把款从公库账户转入工程的托管分区，按 `trancheShares` 分期；公库余额不足则拨款失败，工程停在排队。
4. **采购全材料类**：工程按需求块采购，需求块按类别与能力选料（卷三 §4.7），任何满足条件的材料都可用；当地无货则下远期订单或组织贩运。也可直接调用公仓中属于该组织的实物（一笔分区间转移）。
5. **施工**：工时由雇佣合同或徭役义务（卷八登记的合同种类行）提供，作业推进与 §4.7 规则 6 同式。完工记账按 §4.1 规则 5 成对：新建完工时，备料账户里耗用的材料记转换去处，同一笔里产出该设施实例的建筑资产分录记转换来源，一万基点记到出资的组织名下（合资按出资比例）；设施实例本身、它的工位与完好度由卷十九的写者在同一事务落定，资产种类取卷十九的设施类型。修缮与扩建不产生新资源，耗材记消耗去处。工时不是腿，以工钱转移体现。私人建造（§4.7 规则 11）同式，只是没有拨款这一步。
6. **结余与超支**：完工后托管分区余额转回公库；预算不足时工程暂停并可追加拨款，不允许赊出不存在的钱。
7. **挪用可行但留痕**：经手职位把工程托管款移作他用是一笔普通转移，可行；它使"已拨 − 已用于采购与工钱 − 托管余额"不为零，这个差额由月报暴露，供卷八b §4.10 的审计读取。
8. **维护不做的后果**：公共设施得不到维护时完好度下降、服务丧失，是卷十九规则的结果；本卷没有"自动维护"。

#### 4.19.4 交互

### 4.20 走私与违禁品（经济侧）

#### 4.20.1 维度

读：违禁谓词（卷八b §4.1 的法典条目，按法域、针对物品类别或材料属性，经 `lawCodeView`）；关卡与查验（卷十七 §4.7）；治安与执法强度（卷八b §4.7）；税种表中的关税（卷八 §4.11）；知情（卷二十二）。无新增存储。

#### 4.20.2 统一入口

无专有入口。走私是 §4.6 的贩运加一个风险项；违禁货的买卖是 §4.2 的成交，只是可见范围受限。

#### 4.20.3 规则

1. **违不违禁是法域的事**：本卷不存违禁清单；一批货在某地是否违禁、应否缴关税，读法典条目与税种表对该货类别与材料属性的判定结果。同一批货在两个法域结果可以不同。
2. **走私的到岸成本**：在 §4.6 规则 1 之上加 `查获期望损失 = 实际所走路线各关卡的查获概率合成 ×（货值 + 罚没与刑罚的估值）`。查获概率由卷十七的关卡查验规则按藏匿方式、货物体积、查验强度给出；本卷只把它当作一个数。判定针对实际走过的路线，不针对意图。
3. **逃税同式**：合法货绕关逃税是同一比较：省下的关税对查获期望损失。
4. **黑市价是供需的结果**：违禁货在当地的合法供给为零；持有者的可售量只对"知道此人有货"的买方可见（知情读卷二十二），供给薄、稀缺项高，价格自然高于合法地区。规则表里没有黑市加价。
5. **风险金进底价**：贩私者的底价含查获期望损失，传导到成交价。
6. **查获是转移或去处**：被没收的货转入执法组织账户（转移）；被销毁的记入去处；罚金是给付义务。
7. **销赃**：赃物批次带赃物份额（卷三 §4.4）；买方若知情，其出价用 `priceFor` 的赃物处置用途（§4.21）折价；不知情则按常价，事后追夺归卷八b。
8. **组织章程不读文字**：一个组织是否从事走私，由其实际贩运记录与成员的合同体现，不读章程文字。

#### 4.20.4 交互

卷八b §4.1、§4.7、§4.11（违禁谓词、治安、罪名与黑市生态）；卷十七 §4.7（关卡）；卷八 §4.11（关税）；卷二十二（知情范围）；卷三 §4.4（赃物份额）；§4.2、§4.6、§4.21。

#### 4.20.5 数据实例

- 西陲两国边境：一种烈性药材在此国违禁、彼国合法；价差足以覆盖查获期望损失时有人夹带，边关加强查验后查获概率上升，夹带量下降、此国黑市价上升。
- 非西陲一处禁酒的教权城邦：酒类的违禁来自该法域的法典条目（按物品类别）；城外合法，城内只在知情者之间成交。
- 超自然一种被多数法域禁止的亡灵材料：违禁谓词按材料属性命中；任何含该材料的制成品自动违禁，无需逐件列名。

- 【扫描】A6-20.1：本卷代码与规则表中违禁物清单、黑市价格乘数为 0；读组织章程文字为 0；读活动文字判断睡眠为 0。

### 4.21 价格四角色

#### 4.21.1 维度

`prole` 族（封闭 4 项）与 `puse` 族（开放；§2.2）。四角色的含义：

| 角色 | 回答的问题 | 数值来源 | 是否落盘 |
|---|---|---|---|
| `prole_trade` 成交 | 这一笔实际按什么价成交 | §4.2 的边际报价与双方底价、顶价 | 只落成交记录 |
| `prole_worth` 估值 | 这东西现在值多少（质押、典当、遗产、案值、税基、赔偿、保险、财富、事件估值） | 卷三 §4.16 的 `valuation`，按用途行调整 | 不落盘 |
| `prole_term` 已签条款 | 这份合同里约定的是多少 | 合同 `terms`，签约时冻结 | 落在合同 |
| `prole_gate` 源汇资格 | 这一笔来源或去处的量是否在允许之内 | `ledger.json` 的日限额与 §4.6 规则 8 的边界限额，按数量比较，不折成价值 | 落 `ledgerTotals` |

`puse` 条目字段：`role`、`frame`（以谁的视角：持有人、市场、指定观察者）、`liquidationCurveKey`（整批急售折价曲线键，可空）、`includesScarcity`、`basisRule`（取市场口径、成本口径、材料口径、租金资本化口径之一）。

#### 4.21.2 统一入口

`priceFor(puseCode, subjectRef, ctx)` → `Fact{value, role, explain}`。全书任何模块要"一个价"，只能调这个入口并说明用途；它按用途行路由到 `marketQuote`、卷三的 `valuation`、合同条款或预算表（台账 I-03、S-03）。

#### 4.21.3 规则

1. **先问用途，再给价**：调用方必须给出用途代号；入口不提供"缺省价"。同一件东西在不同用途下数值不同是正常的，混用是错误。
2. **路由表是数据**：用途行的 `role` 决定走哪条路；`basisRule` 与 `includesScarcity` 作为参数传给卷三的 `valuation`（其函数内不含角色常数，卷三 §4.16）；`liquidationCurveKey` 非空时对结果按批量占当地日成交量的比例查曲线折价。
3. **用途由各卷登记**：本卷登记成交、收购、质押清算、典当、保险赔付、工位作业估值、财富统计、赃物处置、承运服务（`puse_carriage`，§4.6 规则 12）；税基由卷八登记，损毁与案值、赔偿由卷八b 登记，事件估值由卷二十四登记，法术服务定价由卷十五登记。登记只是加一行。
4. **已签条款优先**：凡标的处在一份有效合同的条款之下，合同当事人之间一律用 `prole_term`，不得用现价改写旧约。
5. **估不出就如实返回**：路由到的估值器返回未知时，本入口返回未知与缺口代号，由调用方按自己的规则处理（不当作零，不回退到别的东西的价）。
6. **表象**：`frame` 指定的观察者未识破伪装时，估值按表象（卷三 §4.16 规则 V-6）；这使受骗买贵成为可能，而不需要特例。
7. **源汇资格不估值**：`prole_gate` 回答的是"量在不在限额内"，按数量与 `ledger.json` 的日限额比较（§4.1 规则 6），不调估值器，所以估值未知时这道闸门照常有定义，账本内核也不反过来依赖经济层。第一版在这里把数量折成价值单位再比较，与 §4.1 的数量口径不一、且造成分层倒挂，已删除。以 `prole_gate` 为角色的用途行，路由到的是限额表，不是估值器。
8. **纯函数**：`priceFor` 不写任何状态；`explain` 的各项连乘加总等于结果。
9. **估值是唯一的定价来源**（旧价格的去留只在本条定义；别处一律引用本条）：
   - 全书一切价的起点只有卷三 §4.16 的估值，经本入口路由。一件物品从未成交过时，它的初始价格也由估值给出：材料价值（成分与用量）、工时（配方工时乘工钱行情）、稀缺度（供给与日需求）三项推出，没有第四个来源。
   - 物品数据上旧的手填价格不再是任何规则的输入：不迁入 `valueBase`（它是卷三的派生量），不作起步价，不作缺省值。四百八十六件物品的旧价格只保留为一份校准参考，交卷十二做验收对照：卷十二对比"估值推出的初始价"与旧价的偏差分布，用来标定卷三的工时价、加成等规则表数值；这份参考不进规则数据，规则层与内容加载器都读不到它。
   - 两种回退都禁止：估值未知时不得回退到旧价，也不得回退到零（把未知当零会让东西白送、让成本为零）。唯一允许的结果是规则 5 的"未知加缺口代号"，由调用方按自己的规则处理（通常是这笔交易或这项决策不成立）。
   - 现有代码里读旧价的位置与逐处处置见 §7。

#### 4.21.4 交互

卷三 §4.16（`valuation`、`registerValuer`、`scarcity`）；卷八 §4.11、卷八b、卷二十四 §4.2、卷十五 §4.17（登记用途行并调入口）；§4.2、§4.10、§4.15、§4.16、§4.18、§4.24。

#### 4.22.1 维度

#### 4.22.2 统一入口

读：`economyReport(scopeRef, periodIndex)`。写：`closePeriod(day)`。

#### 4.22.3 规则

1. **每一笔都有三种标记之一**：`post` 的每条腿要么是转移（有对手腿），要么记来源（产生），要么记去处（消失）；标记由腿的结构决定，不是事后分类。
2. **来源与去处是封闭于登记的**：未登记的代号不可用；每个代号有 `budgetMode`（物理律通道或限额通道，§4.1 规则 6）与报告分组。新增通道必须加词表行，评审可见。上表各行中，限额通道只有 `src_genesis` 与 `src_boundary`，其余都是物理律通道。
3. **开局只在第 0 日，物化不是来源**：世界生成时放进世界的一切（卷十的物品生成组、初始铸币、各存量单元的初始储量、§4.7 规则 11 物化出的建筑资产）都在第 0 日以 `src_genesis` 入账，使守恒式自零时刻起成立；第 0 日之后该来源的日限额恒为零，任何模块不能再用它。这包括未物化的部分：统计层各阶层的财物在第 0 日就记在阶层聚合账户上；每个存量单元（矿脉、林、水体）的初始储量在第 0 日由（世界种子、单元）的纯函数给出并入账，不等到有人第一次去取。运行期把一处地点或一批人口从统计层物化成名册个体，是从阶层聚合账户到这些个体账户的一笔转移，按（世界种子、地点）的纯函数分配，不产生来源腿；所以玩家走到哪里都不会凭空长出东西，结果也不取决于哪里先被看见。
4. **报告周期**：`closePeriod` 在世界日跨过 `report.json.periodDays` 的整数倍时结出上一期，期号 = 世界日整除周期；与推进方式无关。
5. **报告内容**（按范围：全世界、政区、聚落；全部由 `ledgerTotals`、成交记录、合同记录聚合，指标公式是 `indicator` 条目的 `formula`）：
   - 各资源各来源、各去处的期内量（水龙头与下水道）；
   - 各铸币的存量、期内铸造与熔毁、流通速度（期内成交额 ÷ 平均存量）；
   - 价格指数：以期初各必需档的有效需求量为权重的篮子，按期内成交均价计算；篮子按必需档与经济大类分组，不列物品名单；
   - 各经济大类的产出、消耗、期末库存、覆盖天数；
   - 聚落间贸易流量与差额（按成交记录与贩运记录）；
   - 转换的投入产出比（§4.8 规则 6）；
   - 工钱指数、就业与空缺；
   - 费、税、工位费的收款分解；
   - 公共工程的已拨、已用、差额（§4.19 规则 7）；
   - 未清义务总额与期内违约额。
6. **对账**：结期时核对守恒式；不成立即报错并停在该期，不允许带病前进。
7. **套利防线**（可逐项计算，不做全路径搜索）："闭环增值"指标是下面三类局部核对里违反项的计数，结期时计算：
   - 每对互逆的配方行（一条正向行与导出自它的逆向行，§4.9 规则 7）：用同一组估值角色的价，正向产出再逆向拆回，所得投入料的估值不大于起始投入料的估值；
   - 每对计价资源：`exchangeRate(甲, 乙) × exchangeRate(乙, 甲)` 扣除双向应付费用后不大于一；
   - 有界环：在成交、转换、兑换三类边组成的图上，只枚举边数不超过 `report.json.loopMaxLen` 的环，按当期报价（买按卖方报价、卖按收购报价、含费税）沿环走一圈，所得数量不多于起始数量。
   三类都是有限枚举，成本由 `loopMaxLen` 封顶；更长的环不在保证范围内，如实写在报告的口径说明里。
8. **报告是事实不是文字**：`econReports` 只存数值与代号；任何叙述由显示层从这些数值生成。世界内的人能知道多少，取决于卷二十二的知情规则（商人知道行情，不等于知道全表）。
9. **审计读差额**：卷八b §4.10 读报告中的应收实收差、工程差额、税基与实缴差，本卷不判定腐败。

#### 4.22.4 交互

#### 4.22.5 数据实例

- 西陲一个郡的一期报告：某保存用度类的货期内产出、消耗、输入各若干，覆盖天数下降，价格指数中最高必需档分组上行；读者一眼看出是供给问题而非货币问题，因为铸币存量与速度未变。
- 非西陲一个贸易城邦：边界来源与去处两项很大；它卖给边界的货多于买进的，报告里边界实体账户的铸币余额逐期下降，这些币回流到城邦，充裕度上升、以币计的价格指数上行。边界实体的币用完后买不动了，顺差自己收敛，全程没有一枚币凭空出现。
- 非人类一个地下王国：报告范围是该王国的政区；其主要计价资源不是铸币，指数以其 `denomination` 计。

### 4.23 贸易枢纽涌现（验收）

#### 4.23.1 维度

无新增存储。规则表键只用于验收与显示：`report.json.hubThresholds`、`hubRunDays`、`hubHhiMargin`。派生：`tradeVolume(place, window)`、报告指标 `ind_hub_share`（一地成交额占其所在政区的份额）、`ind_trade_hhi` 与 `ind_pop_hhi`（集中度，取赫芬达尔指数：政区内各地点份额的平方和；前者用成交额份额，后者用人口份额）。验收所用的标准世界夹具（地点、路网、人口、资源的固定数据与种子）由卷十二提供，本卷只规定在它上面断言什么。

#### 4.23.2 统一入口

读：`tradeVolume`、`economyReport`。本节是验收断言的集合，不引入机制。

#### 4.23.3 规则

1. **不指定枢纽**：地点行没有"商埠""首府市场"之类影响成交的字段；站点类型、发展度不直接进入报价。
2. **正反馈来自已有规则**：成交多的地方供给深（§4.2 规则 4 边际价平缓）、到货预期多（§4.17）、店铺周转快而利润率低（§4.5 规则 4）、商贩在此更容易配到回程货（§4.6 规则 4）；这些使其对买卖双方更有利，成交进一步集中。
3. **位置优势来自到岸成本**：处在多条产地与销地之间、路况好、治安好的地点，各方向的到岸成本之和小，自然成为集散地；路断、治安恶化后集散地会迁移。
4. **枢纽可以消失**：没有任何粘性状态；资源枯竭、战乱、改道之后成交份额下降，店铺因周转变慢而关张。
5. **显示用标记是派生的**：地图上"商埠"的图标由 `ind_hub_share` 越过阈值得出，属显示层。

#### 4.23.4 交互

卷五 §4.9（发展度的积累可读成交额作为输入，由卷五规则决定）；卷十（生成期不放置枢纽，只放资源与人口）；卷十七（路网）；卷二十九（地图显示）；§4.2、§4.5、§4.6、§4.22。

#### 4.23.5 数据实例

- 西陲一个三岔路口的小村：位于矿区、粮区与河港之间，模拟若干年后其成交份额升为全郡前列，店铺数随之增加。
- 非西陲两座条件相近的港口：因一次偶然的航路封锁，其中一座失去到货，份额被另一座取代且此后未恢复，体现正反馈与路径分化。
- 非人类一处多种族交界的洞口集市：不同种族的货只在此可互换，成交份额高；其成因与人类路口相同。

#### 4.23.6 验收断言

- 【扫描】A6-23.1：地点数据与生成规则中指定市场等级、贸易中心的字段为 0；报价函数的输入里没有站点类型与发展度。
- 【不变量】A6-23.2：在卷十二提供的标准世界夹具上推进 `report.json.hubRunDays` 个世界日后，末期报告满足 `ind_trade_hhi − ind_pop_hhi ≥ report.json.hubHhiMargin`。再做对照：把夹具里标为主干的一条边断开，从同一种子重跑同样天数；记两次运行各自 `ind_hub_share` 最高的地点为甲、乙，若甲不等于乙，则在断边后的路网上，乙到各产地与销地的到岸成本之和小于甲的（两个和都用 `landedCost` 对夹具指定的标准货批算出）；若甲等于乙，断言只要求甲的份额不升。
- 【扩展性】A6-23.3：在夹具上新增一处有资源场潜力的地点与连到它的一条边，不改代码，从同一种子推进 `hubRunDays` 日：与新地点路网距离在两条边以内的地点里，至少有一处的 `ind_hub_share` 高于未新增时同一地点同一期的值。

### 4.24 财富汇流统计

#### 4.24.1 维度

派生：`wealth(scope)`，`scope` 可为个体、家户、组织、聚落、政区。读：账户余额（`countsAsWealth` 的资源）、持有边标的的估值、债权与债务（未清义务）。规则表 `report.json.wealthParts`（分项清单与各自的用途代号）。

#### 4.24.2 统一入口

读：`wealth(scopeRef)` → `{total, parts: {goods, coin, property, claims, debts}}`。

#### 4.24.3 规则

1. **一个统计量**：`wealth = Σ 物品与存量账户按财富统计用途的估值 + Σ 铸币按购买力 + Σ 持有地产与设施的估值 + Σ 债权现值 − Σ 债务现值`。估值全部经 `priceFor`，用途为财富统计（市场口径、不计急售折价）。
2. **范围聚合不重复**：聚落的财富是其居民、家户、驻地组织的财富之和，范围内部互相的债权债务相消；政区同理向上聚合。
3. **只读、不落盘**：财富每次由当前状态算出；带记忆与依赖声明（卷二 §2.3）以控制成本。
4. **谁读它**：叙事调度（卷二十四 §4.3 的加权抽取把目标范围的财富作为世界状态输入）、袭击与掠夺的目标选择（卷十三、卷十六）、阶层流动（卷十八）、封爵与移民吸引（卷八）、资信（§4.15）。这些后果的规则都在对方卷；本卷不因财富触发任何事。
5. **可见财富与真实财富**：`wealth` 接受 `frame` 参数；以外部观察者为视角时，只统计其知情范围内的部分（卷二十二）与表象估值，所以藏富有意义。
6. **非金点数不混入**：`countsAsWealth` 为假的资源（虔诚、威望等）不进总值；它们各有自己的读者。

#### 4.24.4 交互

卷二十四 §4.3（读世界状态）、§4.2（事件估值同走 `priceFor`）；卷十三、卷十六（目标选择）；卷十八（阶层）；卷八；卷二十二（知情范围）；卷三 §4.16；§4.18、§4.21。

#### 4.24.5 数据实例

- 西陲一座因矿而富的镇：财富总值在几年间翻倍，卷二十四的抽取因此提高盗匪袭击类事件对它的权重；镇民把钱换成地产并不改变总值，只改变分项。
- 非西陲一位藏金的行商：外部视角下的财富远低于真实值，劫匪对他的兴趣随之较低。
- 非人类一条龙的巢藏：龙是个体，其财富由巢中账户的铸币与物品估值得出；它作为袭击目标与镇子同式参与抽取权重。

#### 4.24.6 验收断言

- 【扫描】A6-24.1：引用 `report.json.wealthParts` 的模块只有 `wealth` 所在模块（S6-13 同法）；以财富统计用途代号调用 `priceFor` 的模块只有它；状态登记表里单位为价值单位的落盘字段，除成交记录的总价与合同条款外计数为 0（S6-14 同法，财富不落盘）。
- 【不变量】A6-24.2：任一纯转移（范围内部）前后该范围财富不变；范围财富 = 子范围财富和 − 内部相互债权债务的重复计入；`wealth` 调用不改变存档摘要。
- 【扩展性】A6-24.3：新增一种 `countsAsWealth` 为真的资源种类，不改代码即计入财富分项与总值。

### 4.25 战时价格与议和回落

#### 4.25.1 维度

无新增维度。规则表键只有验收参数：`report.json.recoveryWindowPeriods`、`recoverySettlePeriods`、`recoveryTolerance`。本节规定"战争怎样影响价格"的唯一通道：战争只改别卷的维度与账本余额，价格经 §4.2 自己变化。

#### 4.25.2 统一入口

无专有入口。读者照常调 `marketQuote`、`economyReport`。

#### 4.25.3 规则

1. **禁写乘数**：规则层与规则表不得存在"战时价格系数""围城加价""议和折扣"之类的键。季节、灾异、节庆同此禁令。这条禁令靠结构保证，不靠读键名：本卷规则表的键是闭集（S6-11，目录里没有这类键，加不进去）；价格、工钱、利率三个槽上的修正项，条件不得引用季节、天气与灾异、事件类型、战争与围攻状态这几族的维度（S6-12，按维度登记表的族归属判定）；旧的按事件改价的效果族退役（§7）。
2. **战争的五条经济通道**（每条都是已有规则的输入变化）：
   - 供给被切断：围困与封锁使市场范围缩小、在途到货消失（卷十三的围攻状态改变可达性，§4.2 规则 1、§4.17 规则 2）；
   - 需求上升：军队是组织，其成员的用度类日耗、军械的耐用品更换与配方派生需求进入 §4.4；
   - 劳力被抽走：征召是合同种类行，占用个体工时，§4.7 的工位空缺、产量下降；
   - 路途变险：沿途治安值下降，§4.6 的风险金升高、贩运减少；
   - 存量被夺与被毁：掠夺是转移，焚毁记入去处（卷十三 §4.11、§4.12 的结果经 `post`）。
3. **回落同理**：议和、解围、复员使上述输入逐项恢复，价格随覆盖天数回升而回落；回落的快慢取决于在途货多久到、劳力多久回到工位、被毁的存量多久补上，不设回落时长。
4. **囤积与管制是决策与法条**：商人因预期涨价惜售（§4.5 规则 5）、官府限价或征购（卷八b 的法典条目与卷八的征管）各走各的规则；限价使卖方底价高于限价时货从公开市场消失并转入 §4.20 的黑市通道。
5. **战时财政**：军费、赔款、赎金、贡赋都是转移或合同义务（卷八、卷十三登记种类行），进月报的转移分解。

#### 4.25.4 交互

卷十三 §4.11、§4.12（围攻、袭击、掠夺的结果事件，本卷订阅后只做记账）；卷八（征召、征购、赔款的合同种类行）；卷八b（限价法条、治安）；卷十七（路途风险）；§4.2、§4.4、§4.6、§4.7、§4.17、§4.20、§4.22。

#### 4.25.5 数据实例

- 西陲一座被围的城：围困首旬城内主食池覆盖天数从数十日降到数日，价格指数最高必需档分组急升；解围后第一支粮队到达的当旬开始回落。
- 非西陲一场海上封锁：港城只有舶来品涨价，本地自产的货不涨；这是到货通道不同的结果。
- 非人类一次兽潮过境：没有宣战、没有军队组织，但路途风险与田间劳力受到同样的影响，价格走同样的通道上涨；规则不区分战争与兽潮。

#### 4.25.6 验收断言

- 【扫描】A6-25.1：S6-11 与 S6-12 计数为 0（键闭集；价格、工钱、利率槽修正项的条件不引用季节、天气与灾异、事件类型、战争与围攻状态各族的维度）；效果族登记表里以价格槽或任何报价为写入目标的效果族计数为 0。三项都按登记表的结构判定，把键或效果改个名字不影响结果。
- 【不变量】A6-25.2：在卷十二提供的验收场景"围城若干日后解围"与其对照组（同一种子、同一世界、不围城）中：围城期间城内价格指数的每一期值，都可由该期的 `marketSupply` 与 `demand` 代入同一 `priceFor` 复算得出（逐位相等）；解围后的 `recoveryWindowPeriods` 期内，各期指数都不超过围城期间的峰值（允许因到货成批而起伏，不要求单调）；解围满 `recoverySettlePeriods` 期之后，各期指数与对照组同期指数的相对差不超过 `recoveryTolerance`。
- 【扩展性】A6-25.3：卷二十新增一种灾异事件行（只改路况、收成或治安维度），不改本卷：受影响地区价格相应变化并在灾异结束后回落。
