## §0 卷首

### 0.1 范围

本卷定义“内容怎样进到世界里”这一段作者侧的路：一批内容怎样打成一个包（包形状、清单、命名空间），包里的行怎样在别人的行上派生或做局部修改（继承、派生、补丁），包怎样加词表条目与维度、几个包撞在一处时谁先谁后（词汇扩展与冲突次序），包在进入世界之前要过哪些检查、报什么码（加载校验流水线），内容入库之前要过哪几级审批（内容审批管线），包怎样在库里装、换、卸，已有世界怎样只增不删地追加一个包，而不破坏同版确定性（安装、升级、卸载），作者手里有哪些离线工具与示例包（作者工具），以及游戏本体自带的内容怎样用同一条路加载（一方机制表加载）。共八个子系统。

不在本卷：

## §1 领域总述

### 1.1 真实世界怎样运转

一部规则书出了之后，别人给它写补充册：加新的物产、新的教派、新的地方。补充册要能被接上去，靠的是三件事。其一，母本把“什么是一件物品、一种材料、一门手艺”写成了表，补充册只往表里添行，行为由母本的通用规则从行上的数值推出。其二，补充册说清楚自己依赖哪几本、与哪几本不能并用，两本都改同一处时有明文的先后。其三，印行之前有人核对：数值有没有出处，有没有和已有条目重复，有没有碰不该碰的题材。五款参照游戏的教训集中在反面：继承各写一套、整体覆写后者赢、新字段要改程序、数据格式一换外部工具全废。

### 1.2 本作现状

- 包机制未实现：清单、命名空间、词汇扩展、冲突次序、安装卸载都只在设计册里（卷零 20.1、20.3、20.4 三行的现状栏）。
- 一方机制表的加载入口已有，但不带逐表校验器（卷零 §4 核查栏一问的结论）。tools/load-world.mjs:85–86 列出 `world/meta/mechanics/` 目录下的全部数据文件，逐个读入后按“文件名转成的键”挂到世界对象上；server-plugin/runtime-world.mjs:11 用一份写死的集合名单区分“行注释”与“规律表”；runtime-world.mjs:37 对行注释只做一项检查——注释不得改写已审字段的值（注释合并函数在 :23–39、:42–45）；runtime-world.mjs:62 把名单之外的文件一律按键名原样挂上。结构、取值域、引用闭合都没有查。另有一条绕过加载入口的路：runtime-world.mjs:8 在运行时 import `tools/kc-processing.mjs`（卷二 E-PROC-IMPORT），后者在模块顶层直接读机制表文件（kc-processing.mjs:151、:183–189）；item-class.mjs:5 也直接 import 一个数据文件（`world/meta/item-use-tags.json`，不在 `world/meta/mechanics/` 下）。
- 校验码多未实现：通用加载已有；设计册里列的来源、敏感、补丁、配额、神祇上限几类码大多没有实现（卷零 20.2 行）。
- 内容审批工具链已有，但其中的校验脚本靠中文正则读正文：`tools/` 下共 330 行中文正则与子串匹配，分布在 74 个文件里，其中内容校验约 111 行、生成与修复约 180 行、试玩与测量约 39 行；另有 3 处拿错误文案做匹配（调研 06b §1.3）。`tools/` 另有 693 处实例 id 字面量，`world/design/` 的脚本另计 3636 处（调研 06a §一）。这些都不在运行时，但它们决定了什么内容能入库。
- 旧的世界升级与迁移模块（server-plugin/world-upgrade.mjs 等）已由卷二十七 §7 的 M27-7 判为全部退役，本卷不接它们的做法。

### 1.3 五条总则

1. **包只装数据**。包里没有可执行的东西。包能做到什么，取决于核心的通用规则读哪些维度；包做不到的事，要么是核心缺一条通用规则（去改核心，过核心的门），要么本来就不该做。
2. **只有一个加载器、一个展平、一个校验器**。游戏本体的内容也是一个包（命名空间 `core`）。作者工具、内容管线、运行时加载、世界生成的写回，调的是同一份实现（卷一 R-7、卷二 §4.1）。
3. **包与包之间只叠加，不整体覆写**。改别人的行只有两条路：另立新行继承它，或对它打补丁；补丁的产物只能是卷二 §1.3 的作者偏离行（台账 X-39）。同一处被两个包改而没有明文先后，是加载错误，不是“后来者赢”。
4. **结果只由包的集合决定**。包的先后由清单里声明的依赖关系与代号序排出，是包集合的纯函数；与安装的时间先后、目录的列举顺序、玩家手动排序都无关。
5. **世界带着自己的数据走**。一个世界开局时把当时的全部数据冻成副本（卷二十七 R27-4.2）。此后往库里装、换、卸任何包，都不改已有世界；规则只一版，没有迁移（卷一 R-8）。已有世界唯一能做的，是只增不删地追加一个包：只添新定义，已有条目一项不改，已有对象不回溯改（R28-6.6）。

## §4 子系统

### 4.1 包形状、清单与命名空间

对应卷零 A 表 20.1（前半）；台账 V28-01。

#### 4.1.1 维度

清单 `packManifest`（§2.2）；包内文件种类（§2.3）；`pack_role`、`pack_part`（§2.1）；包集合记录（§2.7）。

#### 4.1.2 统一入口

读：`resolvePackSet`（只由 `loadWorld` 与库写者调）、`nsOf`、`packSetView`（§3.1）。写：库写者（§3.2）。扫描 S28-1、S28-4、S28-6、S28-7。

#### 4.1.3 规则

- **R28-1.1 包是一个目录**：一份清单加若干按种类放的数据文件（§2.3），没有别的。游戏本体也是一个包，代号 `core`；它与别的包的差别只有两处——包根的位置与内部布局照卷二 §1.1（文件布局），以及它在包序里恒居首位（R28-3.2）。除此之外，加载器对它没有任何特别处理。
- **R28-1.2 命名空间是代号里的一段**：非本体包的行代号写成“所在表的实体前缀、本包命名空间代号、一个下划线、名字”；词表条目代号写成“族前缀、命名空间代号、下划线、名字”；扩展维度键写成“命名空间代号后接大写字母开头的名字”（维度键不含下划线，卷二 §1.9（代号、显示名与语言边界））。总长仍守卷二的代号长度上限。这一格式在校验的 L0 级按表头的前缀表与清单的 `ns` 核对，与核对实体前缀是同一性质的格式检查；不合即 E-PACK-ID-NS。**运行期不解析代号**：一行属于哪个包，查加载期注册表（`nsOf`），不拆字串（卷二 E-VIEW-ID-PARSE）。本体的行不带命名空间段；代号的唯一性由卷二的全局唯一检查保证（E-DIM-ID-DUPLICATE），不靠这一段。
- **R28-1.3 清单与实物一致**：清单 `parts` 列了的部分必须有文件，有文件的部分必须列在 `parts` 里；包根下不得有 §2.3 之外的文件。任一不合即 E-PACK-FILE-KIND。
- **R28-1.4 版次只是一个整数序号**：`packVersion` 只用于两处整数比较——别的包 `requires` 里的 `minVersion`，以及库写者判断换版的新旧。规则层读不到它。同一命名空间的两个版次不能同在一个包集合里（E-PACK-NS-DUPLICATE）。
- **R28-1.5 角色只影响“默认带不带”**：`example` 与 `fixture` 的包不在正式世界创建的默认包集合里，只有世界创建请求显式列出时才带上。带上之后，它过的校验、得到的行为与 `content` 包完全相同；加载器、校验器、规则层都不读 `role`（S28-1）。
- **R28-1.6 包只装数据**：包里没有脚本、没有可执行文件、没有公式之外的任何“逻辑”。包可以写的公式只有卷二已定的数据侧表达：派生式、rx、修正项、效果族行、分布参数；这些表达的运算符、阶段、作用域、原语都封闭于核心代码，包只能用，不能加（E-PACK-VOCAB-CLOSED）。
- **R28-1.7 开放与封闭的分界**（卷一 §3A.9 在包这一层的落地）：

| 包可以加 | 包不可以加（要加须改核心并过核心的门） |
|---|---|
| 22 张实体表里的实体行、类别行 | 新的实体表种类 |
| 开放词表族的条目（R28-3.3） | 封闭词表族的条目；代码内封闭枚举的值；新的词表族 |
| 已有表上的扩展维度（R28-3.4） | 类型清单里的新类型；单位表里的新单位 |
| 以本包条目为键的规则表行；合并方式登记为单调合成的表上以依赖包条目为键的行（§2.11、R28-4.4）；修正项；效果族行 | 合并方式为 `own_key_only` 的表上以别包条目为键的行；行为代号；效果原语；rx 运算符；修正阶段与作用域 |
| 本包个体的作者偏离行；对依赖包行的补丁（§4.2）；对声明可由包覆写的规则表键的补丁（R28-2.9） | 对别包类别行的任何改写；对别包行的整体覆写、删除或停用；对未声明可由包覆写的规则表键的改写 |
| 语言包片段；命名表成分（卷七 §4.27） | 校验级别；校验豁免 |

  新词表族不许由包加，是因为族要有维度引用它才有用，而引用它的维度连同前缀登记、族字段结构都由归属卷在卷二的机制下登记（写卷须知补充裁定）；包需要新的分类时，用扩展维度引用已有的族，或在已有开放族里加条目。
- **R28-1.8 语言包片段不进数据**：`labels` 部分只进显示层，不进数据副本，不进任何摘要（卷二十七 R27-4.2）。显示名齐不齐由卷二的 E-I18N-LABEL-MISSING 查，只查键。
- **R28-1.9 进数据副本的范围**：`tables`、`vocab`、`rules`、`instances` 四部分的合并结果与 `patches` 编译后的整值，连同 `packSet` 节。`tests` 部分不进世界。

#### 4.1.4 交互

卷二 §1.1、§1.2、§1.9（文件、表头 `namespace`、代号格式与前缀表；包片段怎样并进同名表由本卷 R28-4.1 第 ④ 步定）；卷二十九 §4.1（包的显示名与语言包片段，C28-8）；卷二十七 §4.4（数据副本多一个 `packSet` 节，C28-5）；卷十二 §4.6（`tests` 部分即扩展性数据包，卷十二 C12-9、R12-6.6 已定）。通道：只读。

#### 4.1.5 数据实例

- 【西陲】一个只加一处聚落及其居民的包：`parts` 为 `tables`、`instances`、`labels`；`requires` 只有本体；地点行、设施实例、具名个体的偏离行代号都带本包的命名空间段。加载后它的居民与本体的居民走同一套需求、劳动、关系规则，规则读不到他们来自哪个包。
- 【非西陲】一个加远方一部法典的包：`tables` 里是法典条目行与罪名行，`rules` 里是以本包罪名条目为键的规则表行；`requires` 除本体外还列了提供那片远方政区的包，`minVersion` 取一个整数。那个包不在场时，整个集合加载失败（E-PACK-DEP-MISSING），不会出现“法典在、地方不在”的世界。
- 【超自然】一个加一位神及其教派的包：神祇行、信仰行继承本体的抽象类别行；`vocab` 里给领域族加一个条目并写上位词，于是本体里写在上位领域上的神迹与评价规则对这位新神直接成立，不需要任何一行代码认识它。
- 【非人类】一个 `fixture` 角色的包，只含一行新物种与它的 `tests` 数据：正式开局默认不带它；验收时由场景显式列出，按卷十二 R12-6.2 的固定步骤加、推、断言、撤。

#### 4.1.6 验收断言

- 扫描式：A28-1.1 S28-1、S28-4、S28-6、S28-7 计数为 0；包集合里 E-PACK-FILE-KIND、E-PACK-ID-NS、E-PACK-NS-DUPLICATE 为 0。
- 不变量式：A28-1.2 同一个包集合，改变各包目录在磁盘上的列举顺序、改变入库的先后、把本体之外的包目录整体挪到另一个库路径再加载，得到的数据副本逐字节相同（卷十二的摘要比对模板，比 `dataDigest`；规则层不读摘要）。
- 扩展性式：A28-1.3 新增一个包只需新增一个目录；加入前后代码文件集合的指纹相同（卷十二 R12-6.2 第 ①、⑥ 步）；撤掉它重跑，事件流与从未加过时相同。

### 4.2 继承、派生与补丁

对应卷零 B 表 0.9；台账 V28-02、K-18、X-39。

#### 4.2.1 维度

补丁行 `patchRow`（§2.4）；`patch_op`、`patch_target`（§2.1）；`rules.pack.maxPatchOpsPerDim`（§2.8）。继承写法的五种记号与展平后的有效行是卷二 §1.3（行、继承与取值顺序）的，本卷不加记号。

#### 4.2.2 统一入口

继承展平与取值：卷二的唯一实现。补丁编译：`loadWorld` 内的一步（`kernel/packs.mjs`），产出作者偏离行；它调卷二的展平函数，不自写合并（S28-5）。派生展开：离线工具（§4.7），产出普通的行文件。

#### 4.2.3 规则

- **R28-2.1 继承只有卷二那一套**：包里的行用 `extends`、`abstract` 与四种增删改写法，语义、目标规则、链深上限、环检测一律按卷二 §1.3。本卷只补一条包这一层的条件：`extends` 的目标若在别的包里，那个包必须列在本包清单的 `requires` 里（E-PACK-DEP-UNDECLARED）。展平在全部包合并之后由同一个加载器做一次（卷一 §3A.8）；没有“每个包各自先展平”这回事。
- **R28-2.2 抽象行可以跨包供人继承**：一个包可以只提供 `abstract` 类别行给别的包作父。它展平后丢弃，不成为实体（卷二 §1.3）。
- **R28-2.3 派生是离线展开，产物是普通行**：把一组改动套到许多已有行上（参照《矮人要塞》的变体模板）由作者工具离线完成：作者给出一份只含卷二五种写法的“子行片段”与一个类别成员条件，工具对当前包集合里满足条件的每条基行各写出一条 `extends` 基行、带上片段的实体行，落成本包 `tables` 部分的文件。入库的只有展开后的行；加载器不认识模板，运行时没有模板展开。因此“世界里有哪些行”仍只由包集合的文件决定；以后别的包新加的基行不会自动得到这种变体，要得到就重新展开并换版（R28-6.1）。
- **R28-2.4 补丁的目标与产物**：补丁改的是依赖包里一条实体行（或一个已有作者偏离行的主体）在某个存储维度上的值。编译产物是该行的一条**作者偏离行**，只写整值，落在卷二 §1.3 覆盖顺序总表的“作者偏离行”这一级——不新增一级，不改变任何一级的先后（台账 X-39）。目标行所在的包必须在本包的 `requires` 里；目标不存在、是类别行、是派生维度，或所在表没有作者偏离行（卷二 §1.3：该表表头的偏离行位置为空），即 E-PACK-PATCH-TARGET。补丁只改被指到的那一行：`extends` 它的子行取的是父的实体行有效值（卷二 §1.3），不随父的作者偏离行变，所以补了父行并不改整族（A28-2.2 的应有之义）。
- **R28-2.5 五种操作就是卷二的五种写法**：`set`、`add`、`remove`、`shift`、`scale` 依次对应卷二 §1.3 的整值替换、并入、剔除、相对加减、乘系数。编译时把“目标在这条补丁之前的有效值”当父值、把补丁当一条子行写法，交卷二的同一个展平函数算出整值；定点算术、精度截断、类型限制、父值必须存在的要求都随之相同（不合即 E-PACK-PATCH-OP）。算出的整值须落在目标维度的取值域内（卷二 E-DIM-DOMAIN-RANGE 等）。
- **R28-2.6 编译次序**：全部包的行合并并展平之后，才编译补丁。按包序（R28-3.2）逐包进行；一个包对同一（行、维度）至多一条生效的补丁（多于一条即 E-PACK-PATCH-CONFLICT）。目标行原有的作者偏离行（本体或依赖包 `instances` 部分给的）先于一切补丁生效，补丁在它的值之上算。一行被若干包、若干维度补过之后，结果并成该行的一条偏离行，逐维整值。
- **R28-2.7 条件只看包在不在场**：补丁可带 `when`：`present` 里的包全在集合里、`absent` 里的包全不在集合里，补丁才生效。条件只引用本包清单 `requires` 或 `optional` 里的代号，在加载期求值一次；没有按世界状态、按种子、按语言的条件。不生效的补丁仍查格式，但不解析目标（目标所在的可选包可能不在场）。
- **R28-2.8 不许的五件事**：整体覆写别人的行（同代号再写一条，卷二 E-DIM-ID-DUPLICATE）；删除或停用别人的行；改写别的包的类别行（码义见卷二 §1.3（行、继承与取值顺序）E-DIM-NAMESPACE-OVERRIDE，本卷不复述）；改派生维度（卷二 E-DIM-DERIVED-WRITTEN）；对没有作者偏离行的表打补丁。这些需求一律改用“另立新行继承它”来表达。停用别人的行（李白 11-14 裁定 Q28-3）：不许，也不新增“停用”操作或覆盖语义；确有“把某类行关掉”的需要时，由该表的归属卷登记一个可用性存储维度（读它的生成、开局、交易等规则由归属卷写），包对这个维度打普通的 `set` 补丁，照 R28-2.4 至 R28-2.6 编译成作者偏离行。
- **R28-2.9 规则表键的补丁**（李白 11-14 裁定 Q28-2）：包只许对登记里 `packOverridable` 声明为真的规则表键打补丁；这个布尔的定义在卷二 §4.1“规则表登记”，由该键的归属卷逐键写明，本卷不点名任何键。补丁只许 `set`，新值照过该键登记的结构与取值域校验（卷十二 R12-5.3）；键未登记、未声明为真或用了别的操作即 E-PACK-RULEKEY。规则表没有继承，这不是继承机制的一部分，只是“整值由谁给”的问题。几个包都 `set` 同一个键时，按该键登记的 `multiSourceMerge` 裁：单调合成的三种取值，把本体值与各包的值按该种合成，结果与次序无关；`own_key_only` 时按 R28-3.5 的先后规则逐个作用，没有先后即 E-PACK-PATCH-CONFLICT。别卷写明不得调低的键（例如卷十八 §4.9 的硬下限键）由该键自己的校验守住，补丁绕不过。
- **R28-2.10 补丁与手写偏离行同责**：每条补丁带 `basis`；目标是真实量时带 `sources`（卷二 §1.7（出处与标定））。补丁编译出的偏离行以此作为它的 `basis` 与 `sources`。
- **R28-2.11 补丁够不到生成物**：`generated` 节的行是世界创建时写进数据副本的，不属于任何包，所以不是补丁的合法目标。要影响生成物，改生成器读的模板行、类别行与分布；生成器对改过的值与没改过的值走同一段代码（卷十 R10-9.3）。
- **R28-2.12 补丁之后的复查在校验里**：补丁改了别卷不变量所读的维度时，合并后的世界在流水线最后一步照常过各卷登记的跨表不变量（R28-4.3）；世界内追加只许新增、不改已有项（R28-6.6），已有对象的存储值不变（派生读数可在 `joinedAt` 之后随新增项变化），候选集合已在第 ② 步整体过一遍各卷不变量，不需另设复查。本卷不为任何一个维度写专门的复查。

#### 4.2.4 交互

卷二 §1.3（唯一的继承、展平与覆盖顺序；偏离行位置为空的表不可补丁，卷二现状不放开，Q28-5）；卷二 §1.7（出处）；卷十 §4.9（生成物不受补丁）；卷十八 §4.9（硬下限键的自身校验、C6）；卷二 §4.1“规则表登记”（含本卷 §2.11 两个字段）；卷十二 R12-5.3（按登记校验）。通道：只读、声明写者（`loadWorld` 产出偏离行）。

#### 4.2.5 数据实例

- 【西陲】本体有一种作坊的设施实例，一个包要让其中一处的容量大一些：对该实例打一条 `shift` 补丁，写明 `basis`。编译出的偏离行只含容量这一维的整值；该实例的其余维度仍沿类别链取值，本体以后调类别行的别的维度，这处实例照样跟着变。
- 【非西陲】远方一个包提供一组抽象的聚落类别行，另一个包的三条聚落行各自 `extends` 其中一条并用乘系数的写法调整规模维度。两个包都在场时展平一次；后一个包没有把前一个包列进 `requires`，加载失败，E-PACK-DEP-UNDECLARED 指到那三行。
- 【非人类】作者要给包集合里所有属于某一捕食者类别的物种各出一个体型更大的变体：写一份子行片段（体重乘系数、攻击相关维度相对加减），由派生工具展开成若干条普通物种行。展开的结果过相似度检查时与各自的基行在同一条继承链上，不算重复（卷十六 R16-8.3）。
- 【超自然】一个包给依赖包里的一位神的领域集合加一个条目：`add` 补丁，成员是领域族的一个条目。另有一个兼容补丁写了 `when.present`，只在某个可选包在场时才给同一位神再加一条禁忌；那个可选包不在场，补丁不生效，也不报错。

#### 4.2.6 验收断言

- 扫描式：A28-2.1 S28-5、S28-9 计数为 0；加载后的世界里，补丁编译出的偏离行没有一条带继承记号（卷二 E-DIM-EXTEND-ON-OVERRIDE 为 0）；`kernel/packs.mjs` 里没有维度键、表代号、行代号字面量。
- 不变量式：A28-2.2 对任意目标行、任意一组合法补丁，“先编译补丁再取值”等于“把同样的五种写法手写成一条继承目标的子行、展平后取它自己的值”，逐维相等（性质测试，两边调同一个展平函数只是为了核对编译步没有夹带别的语义）；补丁编译前后，未被任何补丁指到的（行、维度）取值逐一不变。
- 扩展性式：A28-2.3 给某张已定稿的表新加一个存储维度（由本体或某个包），不改补丁编译的任何代码，对该维度的五种操作中类型相合的几种即可用；新加一个带补丁的包，撤掉后事件流与从未加过时相同；某归属卷把一个规则表键的 `packOverridable` 改为真，不改补丁编译代码，包对它的 `set` 补丁即被接受。

### 4.3 词汇扩展与冲突次序

对应卷零 A 表 20.1（后半）；台账 V28-01、S-12。

#### 4.3.1 维度

清单的 `requires`、`after`、`optional`、`conflicts`（§2.2）；`rules.pack.maxPacks`、`rules.pack.maxPatchOpsPerDim`（§2.8）；词表条目的 `broader`（卷二 §1.9）；扩展维度的声明字段（卷二 §1.2）。

#### 4.3.2 统一入口

读：`resolvePackSet`（给出包序）。包序没有别的求法。

#### 4.3.3 规则

- **R28-3.1 依赖与先后各一种声明**：`requires` 是硬依赖——对方必须在场且版次不低于 `minVersion`，本包才可引用对方的行、条目、维度；`after` 是软先后——对方若在场，本包排在它之后，对方不在场不算错。两种声明连成的有向图有环即 E-PACK-DEP-CYCLE。
- **R28-3.2 包序是包集合的纯函数**：本体恒居首位。其余的包反复执行同一步：在“自己的 `requires` 与在场的 `after` 都已排出”的包里，取命名空间代号按代号序最小的一个排出，直到排完。这个次序只由各包的清单决定；没有玩家手动排序，没有按安装时间、按目录列举顺序排的分支（总则 4）。
- **R28-3.3 词汇扩展只往开放族里加，并且要挂上位词**：包可以给卷二 `_vocab.json` 的开放族加条目，条目带族前缀与命名空间段（R28-1.2）。族的条目结构里有上位链字段的，新条目必须写 `broader`，指向一条已存在的条目（本体的、依赖包的，或本包里排在前面的）；缺或指空即 E-PACK-VOCAB-BROADER。规则是写在上位词上的，新条目因此不改代码就得到上位词的全部行为（卷一 §3A.9）。往封闭族、代码内封闭枚举里加值，即 E-PACK-VOCAB-CLOSED。台账 S-12 所问“重名与上位词由谁审”：代号重名与上位词存在由本条机判；两个条目“代号不同而意思相同”是内容判断，有登记相似度维度的表按卷十六 §4.8 机判，其余进人工级的审查勾选项（R28-5.7）。
- **R28-3.4 扩展维度三条限制**：包可以给已有的表加维度，声明字段与卷二 §1.2 相同，另守三条：① 键带命名空间段，不与任何已有维度键相同；已有维度的名、类型、单位、取值域、必填策略一概不得改。② 必填策略只能是 `never`，或 `byClass` 指向本包自己的类别、`ifPresent` 指向本包自己的维度——不得让别的包的行因为多了这个维度而缺必填。③ 必须声明 `onUnknown`；标了 `modifiable` 的带齐卷二要求的叠加与边界字段。任一不合即 E-PACK-DIM-EXT。核心代码不会按名字读一个扩展维度；它靠数据侧的消费者起作用——派生式、rx、修正项的目标键、效果族参数、相似度登记。没有任何消费者的扩展维度不是错误，作者工具在报告里把它单列（R28-7.5）。
- **R28-3.5 同处多改必须有明文先后**：两个包各有一条生效的补丁落在同一（行、维度）或同一规则表键上时，两包之间必须有依赖闭包上的先后——一方在另一方 `requires` 与在场 `after` 的传递闭包里；补丁按包序依次作用。没有这种先后即 E-PACK-PATCH-CONFLICT，由其中一个包的作者在清单里声明 `after` 并换版来消解；玩家自己消解不了——包序不许玩家调，也没有只为声明别的包之间先后而设的包（清单 `parts` 非空，`after` 只排本包自己）。不要求先后的情形有两种：两条都是对集合或映射的 `add` 或 `remove`，且所涉成员互不相同，这时结果与次序无关；规则表键登记的 `multiSourceMerge` 为单调合成时，按 R28-2.9 合成，也与次序无关。同一处叠的条数不得超过 `rules.pack.maxPatchOpsPerDim`（同码）。
- **R28-3.6 互斥只需一方声明**：`conflicts` 列出的包与本包同在一个要加载的集合里，即 E-PACK-CONFLICTS。互斥是包作者对内容的判断，加载器不推断互斥。库不是一个集合：两个互斥的包可以同在库里，只是不能同进一个世界（R28-6.2）。
- **R28-3.7 包数上限**：一个要加载的集合的包数不超过 `rules.pack.maxPacks`（E-PACK-LIMIT）；库里的包数不受它限。上限是为了让加载与校验的耗时有界，不是内容规则。
- **R28-3.8 类别先后不由包序决定**：包加的类别行在取值算法里的位置，照卷二 §1.3 由 `broader` 深度派生；包只可以在本包片段的表头里给本包自己的类别行之间打破同深度的平局，不得重排别的包的类别行。跨包的同深度平局，命中同一维度且值不同时，照卷二报 W-DIM-PRECEDENCE-TIE，由后一个包把对方列进 `requires` 并显式写出相对次序来消解。包序只管补丁的先后，不是第二套覆盖顺序。
- **R28-3.9 冲突种类总表**（全书在包这一层会遇到的冲突与唯一处置）：

| 冲突 | 处置 | 码 |
|---|---|---|
| 两个包有同代号的行或条目 | 加载失败 | 卷二 E-DIM-ID-DUPLICATE |
| 两个包同一命名空间代号 | 加载失败 | E-PACK-NS-DUPLICATE |
| 两个包补同一处而无先后 | 加载失败 | E-PACK-PATCH-CONFLICT |
| 两个包补同一处且有先后 | 按包序叠加 | — |
| 扩展维度键相同 | 加载失败（命名空间段使它只可能来自两个同代号的包） | E-PACK-NS-DUPLICATE |
| 跨包类别行同深度、同维异值 | 告警，显式定序后消除 | 卷二 W-DIM-PRECEDENCE-TIE |
| 声明互斥的包同在 | 加载失败 | E-PACK-CONFLICTS |
| 两个包的物种行相似度过线而不在同一继承链 | 加载失败 | 卷十六 E-BST-DUPLICATE |

#### 4.3.4 交互

卷一 §3A.9（封闭与开放的分界）；卷二 §1.9、§1.2、§1.3（族与前缀、维度声明、类别先后；包片段表头里“只排本包类别”的写法请卷二补，C28-2）；卷十六 §4.8（相似度）；卷二 §3.2（修正项以扩展维度为目标键时的登记）。通道：只读。

#### 4.3.5 数据实例

- 【西陲】两个都改同一处集市设施实例开放时段的包同时在场，互不知道对方：加载失败，E-PACK-PATCH-CONFLICT 指出两条补丁的路径。其中一个包的作者在清单里加上对另一个包的 `after`，两条补丁按包序叠加，结果确定。
- 【非西陲】一个远方的包给地形族加一个条目，上位词是本体的一个地形条目。本体里写在上位地形上的通行、耕作、群落规则对新地形全部成立；该包再用扩展维度给它补一个本体没有的数值量，并用一条派生式把这个量接进本体已有的派生维度。
- 【非人类】两个包各加一种怪物，命名空间代号不同、行代号不同，但登记的相似度维度几乎全同：卷十六 E-BST-DUPLICATE。处置是其中一个包把自己的行改写成继承对方的行，并把对方列进 `requires`。
- 【超自然】一个包想给代码内封闭的修正阶段枚举加一个新阶段：E-PACK-VOCAB-CLOSED。它真正要的效果用已有阶段的修正项加一条 rx 条件表达。

#### 4.3.6 验收断言

- 扫描式：A28-3.1 `resolvePackSet` 之外计算包先后的代码位置数为 0；加载器里读安装时间、目录列举顺序来定序的位置数为 0；包集合里 E-PACK-VOCAB-CLOSED、E-PACK-DIM-EXT 为 0。
- 不变量式：A28-3.2 对任意合法包集合，包序是全序且唯一；任意两条落在同一处的生效补丁，其先后由包序给出，且把集合里与这两个包都无依赖关系的第三个包加入或撤掉，这两条补丁的先后不变；满足 R28-3.5 例外情形的两条补丁交换次序，结果逐值相同（性质测试）。
- 扩展性式：A28-3.3 往一个带上位链的开放族加一个新条目并挂上位词，不改代码，凡以该上位词为条件的规则对带新条目的行逐项生效；把上位词换成另一条，行为随之改变（卷十二 R12-6.5 的改值对照）。

### 4.4 加载校验流水线与报错码

对应卷零 A 表 20.2；台账 V28-03。兼及 A 表 6.11、10.8。

#### 4.4.1 维度

错误码（§2.9）；清单与补丁字段（§2.2、§2.4）。校验分级、报错对象的字段是卷二 §4.1、§4.2 的。

#### 4.4.2 统一入口

`loadWorld`。运行时装配、库写者入库前、作者工具的检查命令、内容管线，调的是这一个函数；世界生成的写回器调的是它最后一步所用的同一个校验函数（卷十 R10-9.1）。扫描 S28-3、S28-4。

#### 4.4.3 规则

- **R28-4.1 七步，次序固定**：

```text
① 发现与清单      读各包根的 pack.json；格式、必填、取值                    L0
② 定集合与包序    依赖、版次、互斥、环、上限；排出包序（R28-3.2）            L2
③ 文件与代号      文件种类与 parts 一致；代号带命名空间段                    L0
④ 合并            表头扩展维度、词表条目、类别行与实体行、规则表行、偏离行   L1/L2
⑤ 展平            卷二 §1.3 的唯一展平，全部表一次
⑥ 补丁编译        按包序；产出作者偏离行与规则表键整值（§4.2）               L1/L2
⑦ 校验            卷二 §4.1 的 L0 至 L4，含各卷登记的跨表不变量
```

  ① 至 ⑥ 是卷二校验器之前的预备步，报的是本卷 §2.9 的码；⑦ 是对卷二校验器的一次调用，报各定义卷的码。右栏标的是该步的码挂在卷二分级的哪一级，本卷不另设级。
  第 ④ 步怎样并片段（包这一层的格式，本卷定）：一个表代号可以有多个文件，每个命名空间至多一个片段；片段表头只带 `kind`、`namespace`、`version`、本包的扩展维度声明与本包类别行之间的同深度次序，`kind`、`version` 须与本体表头相等；`classes`、`rows` 两节按代号取并集（同代号即卷二 E-DIM-ID-DUPLICATE），扩展维度并进该表的维度清单；规则表行按该表登记的 `multiSourceMerge` 并（§2.11）。
- **R28-4.2 全有或全无**：任一步出现错误，整个加载失败，不产出世界；没有“跳过坏包、用剩下的继续”的路径。坏包应当在入库时就被拦在库外：库写者入库前对这个包与它 `requires` 的闭包跑同一条流水线（R28-6.2）。
- **R28-4.3 内容政策类检查不另设槽**：扩展包带来的内容要不要拒，由各定义卷已登记的校验项回答，在第 ⑦ 步对合并后的世界统一执行：引用了不许新建引用的对象（卷七 R7-29.3，E-RESPECT-TIER）；物种行重复与内容配额（卷十六 R16-8.3、R16-2.3，E-BST-DUPLICATE、E-BST-QUOTA）；自带的关系边违反未成年人硬下限（卷十八 C6，E-REL-MINOR-LOAD）；真实量没有出处或仍是占位（卷二 E-DIM-INSTANCE-BASIS、E-DIM-SOURCE-PLACEHOLDER）；具名个体缺文化（卷四，E-PERSON-CULTURE-MISSING）。本卷在这里只保证一件事：这些检查对本体的行与扩展包的行一视同仁，校验器里没有“扩展包从宽”或“本体免查”的分支。别卷的判据需要区分“本包的行”与“依赖包的行”时，调 `nsOf`，不解析代号。
- **R28-4.4 规则表行的多来源合并走通用登记**（一审 T3）：包在自己的 `rules` 部分写的规则表行，以谁的条目为键、多来源怎样合成，一律按该表登记的 `multiSourceMerge`（§2.11）：`own_key_only` 的表只收以本包条目为键的行；登记为 `all_and`、`take_min`、`take_max` 的表，才收以依赖包条目为键的行（该包须在 `requires` 里，否则 E-PACK-DEP-UNDECLARED），同一个键的各来源按登记的那一种合成，结果与包序无关，不需要先后规则。单调合成只会把值朝一个方向推，写一行反方向的值不起作用，作者工具把它列为无效行（R28-7.5）。哪张表取哪一种由该表的归属卷登记，本卷不点名任何表，也不重写任何表的含义与读法（例如档位表由卷七登记，C28-9）。合成之后，已有引用行在别卷的检查里怎样判，由该检查的定义卷定口径（需要区分来源时调 `nsOf`，R28-4.3）。
- **R28-4.5 报错格式是卷二的**：字段、排序、去重、末行统计一律按卷二 §4.2（报错格式）。`path` 指到包内文件与其中的位置；补丁编译出的偏离行出错时，`path` 指到造成它的那条补丁，而不是指到内存里的合并结果。
- **R28-4.6 流水线自身确定**：它的输出只由包集合的文件内容决定，不读墙钟、环境变量、目录列举顺序；同一输入两次运行，报错输出与合并结果逐字节相同（与卷十二 R12-5.8 同法登记）。
- **R28-4.7 流水线一个字也不读**：七步里没有任何一步读显示文字的值；`labels` 部分在这里只被查键齐不齐（卷二 E-I18N-LABEL-MISSING）。需要读文字才能做的检查——显示名与命名组合命中屏蔽词——不在流水线里，在内容构建时由离线程序做（R28-5.4）。所以运行时每次加载都不接触屏蔽词词表。
- **R28-4.8 码都要登记**：本卷 §2.9 即本卷的错误码表，收尾统一汇总；代码里出现而表里查不到的码由卷十二 R12-5.7 报出。
- **R28-4.9 齐全率分包列出**：卷二 L5 的齐全率读数不阻断加载；作者工具把它再按命名空间分列，让包的作者看见自己的行缺哪些维度（R28-7.5）。

#### 4.4.4 交互

卷二 §4.1–§4.3（校验器、格式、码表）；卷七 §4.29（档位读数与码；档位表的合并方式登记，C28-9）；卷十六 §4.8、§4.2（相似度与配额；卷十六 R16-8.3、C16-17 已定在加载期执行，即本流水线第 ⑦ 步）；卷十八 §4.9（加载检查点）；卷十 §4.9（写回器用同一校验函数）；卷十二 §4.5、R12-11.1（本流水线的检查按卷十二 C12-9 登记为条目）。通道：只读。

#### 4.4.5 数据实例

- 【西陲】只有本体一个包的集合：七步走完零错误才允许开局。本体的一行真实量缺出处，与扩展包的一行缺出处，报的是同一个码、同一种路径格式。
- 【非西陲】一个远方包的补丁指向一个它没有列进 `requires` 的包里的行：第 ⑥ 步报 E-PACK-PATCH-TARGET，路径指到补丁文件里的那一条；整个集合不加载。
- 【超自然】一个加神祇的包，其教派行把一位档位里“不许新建引用”的对象列为母体：第 ⑦ 步由卷七的检查报 E-RESPECT-TIER。把该包自己的新神定成更严的档是允许的。该包若给那位对象写一行更宽的档，结果取决于卷七对档位表合并方式的登记（C28-9）：登记为 `own_key_only` 时，这一行以别包条目为键，加载期即报 E-PACK-RULEKEY；登记为 `all_and` 时，逐项取“与”之后仍是原来的严档，这一行不起作用，作者工具在报告里把它列为无效行。
- 【非人类】一个加怪物的包使某一行政层级内同档物种行数超过配额：第 ⑦ 步报卷十六的 E-BST-QUOTA。它与本体自己超配额时报的是同一个码。

#### 4.4.6 验收断言

- 扫描式：A28-4.1 S28-3、S28-4 计数为 0；校验器与加载器里按命名空间放宽或跳过检查的分支数为 0（E-PACK-BRANCH-NS）；代码里出现而未登记的 E-PACK、E-CONTENT 码为 0（卷十二 R12-5.7）。
- 不变量式：A28-4.2 把任意一个合法的扩展包里的全部行改写成本体的行（去掉命名空间段、并入本体文件），与原来“本体加该包”的集合相比，第 ⑦ 步报出的错误集合在码与（表、维度）上相同（卷一 R-7 的互换判据在包这一层的形态）；同一输入两次运行输出逐字节相同。
- 扩展性式：A28-4.3 某卷新登记一条跨表不变量与它的码，不改流水线代码，扩展包的行即受它约束；给流水线喂一个每一步各错一处的坏包集合，每个码都能被报出且路径指到包内文件（卷十二 §4.13 的绕法用例同法登记）。

### 4.5 内容审批管线

对应卷零 A 表 15.7；台账 V28-04、X-04。兼及 A 表 3.14、15.3、14.11、14.15。

#### 4.5.1 维度

`approval_tier`、`approval_cause`（§2.1）；审批记录与级别规则（§2.6）；`rules.content.tierRules`、`rules.content.cautionBands`、`rules.content.humanChecks`（§2.8）；E-CONTENT 三码（§2.9）。

#### 4.5.2 统一入口

读：`requiredTier(row)`（离线）。写：审批执行器是审批记录的唯一写者（§3.2）。离线读文字的程序只有卷十二 R12-2.9 登记的两个与内容有关的：内容构建校验器 `tools/content-build-check.mjs`、命名校验器 `tools/name-blocklist-check.mjs`；二者比对文字时只调卷二 §2.9（外部边界与 Text 模型）的唯一匹配实现。扫描 S28-2、S28-8。

#### 4.5.3 规则

- **R28-5.1 审批的对象是内容行，审批在线下**：一条内容行 = 一行的数据，加上它在各已发布语言的语言包里的显示文字；补丁以（目标表、目标行、维度）为一条。审批是入库之前的离线流程。运行时加载器不读审批记录、不知道一行过了哪一级（S28-2）；拦住未过审内容的是库写者与卷十二的提交关口，不是运行时。
- **R28-5.2 批准绑定内容**（一审 T1）：审批记录绑定该行的内容指纹。指纹只有卷十二 R12-9.3 那一种算法，本卷不另立；本卷请卷十二给它增加“行主体”这一种输入形式（C28-6），覆盖范围定为：该行在当前包集合下展平并编译补丁之后逐维的有效值与来源标记，加上各已发布语言里以该行代号为键的语言包条目。所以不论改的是行自己、它的父类别行、还是别包对它的补丁，只要有效值或来源变了，指纹即变，旧记录失效（E-CONTENT-STALE），要重审。指纹不在世界状态里，规则层读不到，与存档摘要无关。
- **R28-5.3 应过哪一级由数据推出**：`requiredTier(row)` 取对该行成立的各 `approval_cause` 在 `rules.content.tierRules` 里对应级别的最高者。级别有序，过高一级以先有低一级的批准记录为前提。各 `approval_cause` 的判法全是对数据的谓词：`any_row` 恒成立；`has_text` 看语言包里以该行代号为键的条目有没有叙述性形态（哪些形态算叙述性读卷二十九 R29-1.11，C28-8、C29-8；只有名称形态的不算）；`real_quantity` 看该行有没有带 `sources` 的维度；`sensitive_ref` 看该行任一引用指向的对象经卷七 `respectTier` 读出的四个布尔有没有为假的；`caution_value` 见 R28-5.6；`solidified` 看该行是否由固化候选转来（由候选卡文件的登记判，R28-5.9）。没有按包、按作者、按表名、按题材名单定级别的写法。
- **R28-5.4 机判级查什么**：三样，全部可机判。① §4.4 的流水线七步零错误。② 内容构建校验器只校验结构化的东西：固化文字所附的结构化声明与该行的维度值、与账面是否相符（调卷九 §4.11 的同一个审查函数，离线调用，不另写比对）；命名表每个结构在每一种可选槽出现组合下可填（卷十 R10-5.4 的 `reach(0)` 与库的音节区间有交，函数由卷十提供）——这一项是命名结构的离线校验条目（封卷后勘误，卷十 C10-18）：对合并后的每个命名库、库里每个结构、可选槽每一种出现与否的组合（槽数上限按卷十 R10-5.3 的 `rules.gen.name.maxSlots`），各求一次 `reach(0)`，与该库的音节下限、上限所夹区间无交即报卷十的 E-GEN-NAME-EMPTY（运行期本会在该组合上报的码），`path` 指到该结构所在的包内文件与位置，报告列出该组合；只读成分的音节数与槽位声明（代号与数值），不读文字；审慎区间（R28-5.6）；固化的显示文字对屏蔽词词表的比对。③ 命名校验器按卷二 §1.9 做命名库组合对屏蔽词词表的比对。②、③ 两处比对命中即卷二的 E-I18N-BLOCKLIST；词条数据在卷二十九的语言包，文件格式与匹配算法在卷二 §2.9，本卷不定义任何一样（台账 X-04）。
- **R28-5.5 模型审级查什么**：对带叙述性文字的行，离线调用文字模型读这段文字，让它交回结构化声明（卷九 §4.11 的声明结构：种类、主体、谓词、值，全是代号与数值）；程序拿这些声明与作者随行所附的声明、与该行的维度值逐条比对，用的仍是卷九的同一个审查函数。程序不读正文，也不读模型交回的任何自由文字。对不上，该行在这一级为打回。模型不可用时，该行停在机判级，不得以“模型没开”为由按通过处理。
- **R28-5.6 审慎区间**：`rules.content.cautionBands` 给登记的维度各定一个区间；一行在该维度上的有效值（展平与补丁之后）落在区间之外，`caution_value` 成立。区间不是取值域——区间外的值合法，只是必须有人看过。每个区间由该维度的归属卷提出，对该表的所有行同一，不点名任何一行。它用来接住“把一个数登记得反常来绕开规则”的做法（卷十八 §4.9 对物种成熟龄的请求即属此类）。
- **R28-5.7 人工级查什么**：审查人对 `rules.content.humanChecks` 里与该行成立的 `approval_cause` 相应的勾选项逐条作答，缺答即不成立（E-CONTENT-RECORD）。勾选项是登记的代号，它的说明文字在语言包。首批勾选项由各 `approval_cause` 的含义推出：出处与数值对得上；与已有条目没有“代号不同而意思相同”的重复（台账 S-12）；涉及受限对象的写法得当；文字与声明相符的最终确认；审慎区间外的值有正当理由。审查人的身份代号与独立性口径同卷十二 R12-9.5：写这行内容的人不审这行内容——记录的 `authors` 列出写这行的人（§2.6），`reviewer` 在其中即 E-CONTENT-RECORD，该记录不构成批准（一审 T2）。
- **R28-5.8 手写人物档与按需建档**（兼及卷零 3.14、15.3）：手写的具名个体，其规则字段是作者偏离行，过流水线；其介绍文字是固化文字，随附年龄与亲属两种声明（与卷十 R10-4.11 所用的是同两种），在机判级与 `personView` 的年龄、卷十八 `kinView` 的亲属比对。人口模板与生成档案的校验不带任何词表参数（卷十 R10-4.12）。运行期按需建档时模型写出的介绍文字不经本管线，那是卷九 §4.19 入库前守门的事；只有当它被固化成内容行时才进本管线。
- **R28-5.9 固化候选**（兼及卷零 14.15）：卷九学习回路聚出的候选卡转成的行，`solidified` 成立，过与手写行相同的各级，合入之后才会被加载（卷九 R9-15.4、R9-16.4）。运行期不写 `world/`，也不写 `packs/`。
- **R28-5.10 模型审要花钱，是流程式条目**：执行前按既有的预算约定报批；同一内容指纹已有模型级记录的不重复调用。费用账由常设的预算脚本记（R28-7.10）。
- **R28-5.11 两道门各管各的**：仓库内的内容（本体与随本体发布的包）过卷十二的提交关口，要求每一行达到 `requiredTier`（否则 E-CONTENT-TIER）。任何包入玩家的库，库写者只强制机判级里不花钱的部分：流水线，两个离线校验器对该包语言包片段的比对，以及 R28-5.4 ② 的命名结构可填性条目（对该包与其 `requires` 闭包的合并结果求，与 R28-6.2 同一族集合；封卷后勘误，卷十 C10-18：否则包内命名结构没有任何离线校验，运行期才报 E-GEN-NAME-EMPTY）。区别来自“过的是哪道门”，不是来自包的身份；流水线里没有按包身份分支的地方。第三方包入库不强制模型级与人工级（李白 11-14 裁定 Q28-4）；它的审批记录若有，只供显示层标示“已审到哪一级”，规则层、流水线与库写者的放行判定一律不读（S28-2）。
- **R28-5.12 离线脚本的纪律**（卷零 15.7 行的改建方向）：生成与修复脚本在产出数据时就写好代号与数值，产物是 §2.3 的包内文件；校验脚本不得用正则或子串读正文来判内容对错，改读结构化字段与声明；拿错误文案做匹配的地方改比错误码（卷十二 M12-11）。审批不再“一批内容一个脚本”：现有按批次各写一份的审批脚本并进同一个审批执行器，批次只是输入。

#### 4.5.5 数据实例

- 【西陲】一处聚落里手写的具名个体带一段介绍文字，随附年龄与亲属声明。声明的年龄与由该个体出生时刻推出的年龄对不上：机判级不过，报告指到这条声明与这个维度。作者改声明或改数据后，内容指纹变了，重新过机判级。
- 【非西陲】远方一种作物行的产量维度带 `sources`：`real_quantity` 成立。级别规则表把它映到人工级，审查人对“出处与数值对得上”这一勾选项作答后才入库。
- 【非人类】一行物种的成熟龄落在该维度审慎区间的下界之外：`caution_value` 成立，须人工级。这个区间对所有物种行同一，规则与工具里都没有物种名单。
- 【超自然】一段神祇传说的固化文字，其中一个专名命中屏蔽词词表的某一类别：内容构建校验器报 E-I18N-BLOCKLIST，这行文字不入库；该神祇的数据行本身不受影响，因为世界里有没有这位神由档位决定，不由词表决定（卷七 R7-29.4）。

#### 4.5.6 验收断言

- 扫描式：A28-5.1 S28-2、S28-8 计数为 0；审批执行器之外写审批记录的位置数为 0；`tools/content/` 下按批次名、包代号、表名字面量分支的位置数为 0；卷十二 M12-11 所列属于本卷的两处已改比错误码。
- 不变量式：A28-5.2 仓库内任一内容行，都有绑定其当前内容指纹、级别不低于 `requiredTier` 的批准记录（E-CONTENT-TIER、E-CONTENT-STALE 为 0）；对任一行，凡使它的有效值、来源标记或语言包条目改变的改动（改行本身、改其父类别行、别包补丁），旧记录一律失效；只改别的行而不改它的有效值与来源，旧记录照旧有效；同一指纹下有 `rejected` 记录的行不算达到任何一级；审查者在 `authors` 里的记录不算数。`requiredTier` 对同一行两次求值相同，且只随该行的有效值与来源标记、语言包条目、档位读数、两张规则表而变。
- 扩展性式：A28-5.3 给 `rules.content.cautionBands` 新加一个维度的区间，不改工具代码，该表所有落在区间外的行即要求人工级；新增一种声明种类（由其定义卷按卷九 §4.11 登记），不改内容构建校验器，带这种声明的固化文字即被比对。
- 不变量式：A28-5.4（封卷后勘误，卷十 C10-18）仓库内内容与库里每个包的闭包合并结果中，每个命名结构在每一种可选槽出现组合下 `reach(0)` 与所在库的音节区间有交；对这样的结果，卷十 A10-5.2 所说“任一种子、任一实例都不出 E-GEN-NAME-EMPTY”成立。

### 4.6 安装、升级与卸载（同版）

对应卷零 A 表 20.3；台账 V28-05、N-06。兼及 A 表 19.4、19.7，B 表 0.10。回答卷二十七 §8 第 12 条。

#### 4.6.1 维度

`pack_op`（§2.1）；`packLock`、`packSet` 与其 `joinedAt`（§2.7）；本卷登记的 verb 族条目（§2.10）；E-PACK-APPEND-BASE、E-PACK-APPEND-CHANGED（§2.9）。`dataDigest`、`rulesDigest`、存档清单是卷二十七 §4.4 的。

#### 4.6.2 统一入口

库操作：库写者 `tools/pack/library.mjs`，唯一写 `packs/` 与 `packs/lock.json`。读存档清单：卷二十七登记的内核读档入口。世界内追加：一笔内核事务（R28-6.6，只增不删）。`packSet`：唯一写者 `kernel/packs.mjs` 的 `writePackSet`，世界创建事务与世界内追加事务都调它（§3.2）。

#### 4.6.3 规则

- **R28-6.1 三种库操作只改库**：`install`、`upgrade`、`uninstall` 经库写者改 `packs/` 目录与 `packLock`，只在没有世界事务进行时执行（主菜单或离线）。它们不读、不改、不删任何存档里的世界数据。
- **R28-6.2 库操作前过流水线，提交是原子的**（一审 T6）：库不是一个包集合，库写者对“操作之后的库”跑的是一族集合：对每个在库的包，取“它加上它 `requires` 的传递闭包”作一个集合，各跑一次 §4.4 的七步，任何一个不过，库保持原样；另对“默认开局集合”（库里角色为 `content` 的全部包）跑一次，不过只告知、不阻断入库，开局时由世界创建请求给出的集合再跑一次（R28-6.3）。所以两个互斥的包可以同在库里（R28-3.6），`example`、`fixture` 包只在自己的闭包集合里受检，`rules.pack.maxPacks` 只限每个集合不限库。通过后以原子改名提交，`packLock` 是唯一的提交点。卸掉一个仍被别的在库包 `requires` 的包，那个包的闭包集合报 E-PACK-DEP-MISSING，操作不成立，除非连同依赖它的包一起卸。
- **R28-6.3 包集合在开局时冻结**：世界创建请求给出包集合——默认是库里角色为 `content` 的全部包，或请求显式列出的一组。创建事务把合并、展平、编译、校验后的结果冻成这个世界的数据副本（卷二十七 R27-4.2），连同 `packSet` 节（各包的 `joinedAt` 取开局时刻）。此后这个世界只读自己的副本；副本只写一次，以后能加上的只有 R28-6.6 的只写一次的追加段。
- **R28-6.4 已有世界不受库操作影响**：库里装了新包、换了版、卸了包，带着旧集合开局的世界照常读档：它的 `dataDigest` 是它自己副本的摘要，读档时那一次相等比较（卷二十七 R27-4.3）不因库的变化而不等。存档能不能读，不取决于库里还有没有它用过的包。这是卷二十七 §8 第 12 条前半的答案：库操作不产生新世界，也不改旧世界；它只改变“以后新开的世界长什么样”。
- **R28-6.5 没有迁移**：包的新版不会被套到旧世界上；不存在按包的版次或数据格式版改写存档的代码（卷一 R-8、卷二十七 R27-7.5）。核心源码改了导致 `rulesDigest` 不等的旧存档，照卷二十七拒绝加载，原文件不改不删，本卷不提供任何补救路径。
- **R28-6.6 已有世界只能只增不删地追加一个包**（李白 11-14 裁定 Q28-1：默认已有世界不换包；同时允许“只增不删”）：已有世界默认不动——存档不动，数据副本只写一次。玩家要让老世界多出新内容，唯一的路是追加一个包：这个包只能新增定义（新的行、词表条目、以本包条目为键的规则表行等），不得改、删任何已有条目，不得改全局规则表。完整换包（移除包、在世界里换某个包的版次）本版不开放，记为后续项（附 待补清单第 10 项）。追加由 host 的一次带回应句柄的请求发起，在内核里作为一笔事务执行，任一步不过整笔拒绝、世界不变：

```text
① 定候选集合  世界 packSet 里的每个包须以同一版次在库里；缺或版次不同 → E-PACK-APPEND-BASE，拒
              候选集合 = 这些包加上要追加的包
② 候选合并    对候选集合跑 §4.4 七步；失败即拒
③ 求差        候选合并结果与世界副本逐项比（表头与维度声明、行的逐维有效值与来源标记、词表条目、
              规则表行与键、修正项、效果族行）；世界副本里任何一项在候选里被移除或值有变
              → E-PACK-APPEND-CHANGED，报出这些项，拒。generated 节与运行期建行不属于任何包，不参加比较
              候选里新增的每一项 nsOf 必须等于要追加的包；不等 → E-PACK-APPEND-CHANGED，报出这些项，拒
④ 写追加段    只把“新增”的项写成数据副本的一个追加段：只写一次，此后不改；
              新包的 packSet 条目经 writePackSet 写在本追加段内（joinedAt 取事务时刻），原有部分的 packSet 节不改；
              packSetView 读原有节加各追加段（§3.1）
⑤ 提交        发“世界追加了一个包”事件；存档清单的摘要按卷二十七的口径重算（C28-5）
```

  第 ③ 步是通用的求差，不认识任何具体的写法：补丁指到已有行、往已有表上加扩展维度、覆写已有规则表键、给已有对象写单调合成的规则表行、别包的条件补丁因新包在场而翻转——凡使世界副本里已有的某一项变了的，都在这一步被拒。求差只比存储的数据项，所以保证的是：数据副本原有部分与已有对象的存储值不变，不改写任何历史事件与存储值，不回溯改；已有对象的派生读数（例如按类别或族成员汇总的量、作用域按类别命中的新修正项）可因新增项在 `joinedAt` 之后变化，这是“只新增定义”的正常后果，不是改动。也没有任何实体因追加而终止。
- **R28-6.7 卸包终止的是谁**（回答卷二附录 D.3 记在本卷名下的一问）：本版没有。扩展包不是实体，不被终止；库里卸包不改任何已有世界（R28-6.4）；世界内只有追加、没有移除（R28-6.6），所以没有哪个实体会因为包被移除而失去定义行或必填引用，卷二 §2.6 的终止协议在本卷不被调用，也不登记卸包触发条件。卷十八 `end_reason` 族里为包移除与包转换预留的两条原因，本版没有触发它们的路径。完整换包要开放时，须先补齐物品、库存、账户与残骸的终止去留（一审 T4，附 待补清单第 10 项），再定本条。
- **R28-6.8 换版不进已有世界**：库里的换版照 R28-6.1、R28-6.2 只改库。已有世界里某个包换成新版，是“改动”，按 R28-6.6 第 ③ 步即拒；要用新版只能新开世界。同一个包的新版若只在旧版之上新增，作者把新增的部分另作一个包，就可以按 R28-6.6 追加。
- **R28-6.9 追加是世界里的一件事，不是迁移**：规则仍只一版；数据副本原有部分一个字节不改，追加段作为一条入日志的事件加上去。事件载荷只有包代号、版次、新增项计数与追加段摘要（§2.10）；追加段摘要只供复演比较，任何规则不得读它判断逻辑。事务不读墙钟，结果只由（状态、世界副本、候选集合的文件内容）决定；在它之前把世界一次推进到位与分段推进到位，追加后的存档摘要相同。复演走到这条事件时挂上该追加段，在此之前该段不可见。追加之前的存档文件不改不删。
- **R28-6.10 追加不重新生成世界**：`generated` 节随世界保存，追加时不重掷（卷十 R10-9.10）。新包带来的可生成内容，只在 `joinedAt` 之后运行期的生成与新开的世界里出现；已存在的对象不因新包而被改写。`generated` 节与安装的关系（封卷后勘误，卷十 C10-18）：它属数据副本的原有部分，世界创建事务写一次；库里的三种操作不读、不改它（R28-6.1、R28-6.4）；追加段只收包内新增项，不含 `generated` 行，第 ③ 步求差也不比它；第 0 日之后的物化与运行期铸行写的是状态里的偏离行（卷十 R10-1.9、R10-9.11），不写 `generated` 节。所以任何库操作与追加前后，`generated` 节逐字节不变。
- **R28-6.11 库操作前的告知**：卸载或换版之前，库写者可以经读档入口读各存档清单里的 `packSet`（只读；读不成按卷二 §2.9 第 0 条“玩家请求之外发生的读档”处置），把仍带着该包的世界列给显示层。这只是告知：按 R28-6.4，这些世界不受影响，库操作不因此被阻止。

#### 4.6.4 交互

卷二十七 §4.4、§4.7（读档入口、一次相等比较、快照与复演；数据副本的 `packSet` 节与追加段，C28-5）；卷二 §2.9 第 0 条（请求与回应句柄）；卷十 §4.9（`generated` 节不重生成，卷十 R10-9.10 已定）；卷一 §8.5（每个世界保存自己的数据副本）。通道：声明写者、事件。

#### 4.6.5 数据实例

- 【西陲】玩家在已有一个西陲世界之后往库里装了一个加新聚落的包：旧世界读档照常，里面没有那处聚落，存档摘要与装包前逐字节相同；此后新开的世界里有它。玩家若在旧世界里追加这个包：它只有新的地点行、设施实例与具名个体，求差只有“新增”，追加成立；聚落从 `joinedAt` 起在世界里，原有居民与设施的存储值都不变（派生读数可在 `joinedAt` 之后随新增项变化，A28-6.3）。
- 【非西陲】一个远方包换了新版次，其中几条行的数值变了：带旧版开局的世界不受影响；玩家想在老世界里用新版，求差出现“改动”，E-PACK-APPEND-CHANGED，世界不变，只能新开世界。
- 【非人类】在一个世界里追加一个只加两种怪物的包：两行物种与它们的类别行都是新增，追加成立；世界里已有生物的存储值不变，新物种只在此后运行期的生成里出现。玩家此后在库里卸掉这个包，这个世界照常读档——它的追加段在自己的存档里。
- 【超自然】一个包加一位新神，同时给本体一位神祇写了一行更严的档位：这一行以别包条目为键，档位表的合并方式由卷七登记（C28-9）——登记为 `own_key_only` 时，加载期即报 E-PACK-RULEKEY，到不了第 ③ 步；登记为单调合成时，这一行改变了已有对象的档，第 ③ 步报 E-PACK-APPEND-CHANGED，指到这一项。两种情形世界都不变。作者把收紧档位的部分拆成另一个包（只给新开的世界用），只加新神的那个包即可追加。

#### 4.6.6 验收断言

- 扫描式：A28-6.1 库写者之外写 `packs/` 的代码位置数为 0；运行时进程写 `packs/` 为 0；按包版次或数据格式版改写存档的函数数为 0；追加事务里表名、族名、键名的字面量为 0；追加事务里调用 `terminate` 或改写副本原有部分的位置数为 0；`writePackSet` 之外写 `packSet` 的位置数为 0。
- 不变量式：A28-6.2 对任一存档，在库上做任意次、任意次序的三种库操作之后读档，读档成功且存档摘要与操作前相同（卷十二的存读恒等模板）。A28-6.3 追加成功后，数据副本原有部分逐字节不变，追加前已存在的每一个对象的存储值与追加前逐一相同，追加前的历史事件一条不改；已有对象的派生读数可因新增项在 `joinedAt` 之后变化，不在本断言之内（R28-6.6）；追加被拒时，排除日志分区后的世界状态摘要与事务前相同；同一（状态、世界副本、候选集合）执行两次，存档摘要相同。A28-6.5 库检查只看闭包：一个包能否入库，只取决于它与它 `requires` 的传递闭包里各包的文件；往库里加入或撤掉与它无依赖关系的别的包（包括与它互斥的包），结论不变（R28-6.2）。
- 扩展性式：A28-6.4 某卷给一张表新登记一个维度或往一个开放族里加条目的写法，不改追加事务代码，第 ③ 步的求差即覆盖它：只新增的可追加，改动已有项的即被拒。

### 4.7 作者工具与示例包

对应卷零 A 表 20.4；台账 V28-06。兼及 A 表 14.16。回答卷十一 C11-7 的附带一问。

#### 4.7.1 维度

工具命令登记表（本节 R28-7.2）；`pack_role` 的 `example`（§2.1）；`tests` 部分（§2.3）。

#### 4.7.2 统一入口

工具都在 `tools/pack/` 与 `tools/content/` 下，离线运行；它们经 `loadWorld` 读数据，经库写者与审批执行器写（§3.2）。运行时不 import 它们（S28-2）。

#### 4.7.3 规则

- **R28-7.1 工具不另写一套**：加载、展平、取值、校验四件事，工具一律调核心的同一份实现（S28-5）。工具自己只做三类事：把文件摆好（脚手架、展开、入库），把核心算出的结果给人看（解释、差异、文档、报告），以及离线读文字的两个登记程序（R28-7.6）。数据格式有改动时，工具随核心一起变，不会出现“工具认识的格式”与“游戏认识的格式”两样（参照 EVE 静态数据导出重做的教训）。
- **R28-7.2 工具命令是登记项**：

| 命令代号 | 做什么 | 读 | 写 |
|---|---|---|---|
| `new` | 建一个空包的目录与清单骨架 | 无 | 包根（新建） |
| `check` | 对给定包集合跑 §4.4 七步，再跑两个离线校验器 | 包文件、语言包、屏蔽词词表（后者只经卷二的匹配实现） | 报告 |
| `explain` | 对（行、维度）给出取值的来历 | `loadWorld` 的结果 | 报告 |
| `diff` | 比两个包集合的合并结果：移除、改动、新增 | 两次 `loadWorld` 的结果 | 报告 |
| `derive` | 把子行片段展开到满足条件的基行（R28-2.3） | 包集合、片段文件 | 本包 `tables` 部分的文件 |
| `doc` | 由数据生成作者参考（R28-7.4） | 表头、词表、规则表登记、错误码表、语言包 | 文档文件 |
| `report` | 报告项（R28-7.5） | `loadWorld` 的结果 | 报告 |
| `candidates` | 读学习记录，出候选卡骨架（R28-7.7） | 卷九的旁路学习记录 | 包内文件草稿 |
| `approve` | 审批执行器（§4.5） | 包文件、语言包、级别规则 | 审批记录 |
| `library` | 库写者：三种 `pack_op`（§4.6） | 包、`packLock`、存档清单（只读） | `packs/`、`packLock` |

  新增命令要登记进卷十二的离线组（C28-6）；命令的实现里不得出现包代号、表名、行代号字面量。
- **R28-7.3 解释不重算**：`explain` 给出的“这个值来自覆盖顺序的哪一级、哪个包的哪个文件哪一处、经过了哪几条补丁”，直接取自取值算法返回的来源标记与补丁编译留下的来历记录，工具不自己推一遍。包集合加载产出的每个存储值都必须能这样追到一个包文件里的一处（A28-8.2）。
- **R28-7.4 文档由数据生成**：`doc` 从表头（每张表的维度、类型、单位、取值域、必填策略、归属卷节、行为清单）、词表（各开放族及其上位链）、规则表登记、错误码表生成作者参考，并标出哪些维度补丁可达。显示文字取当前语言包，只原样输出。手写的作者说明不得复述这些能由数据生成的内容，免得数据改了而说明过期（参照《十字军之王 3》接口文档过期的教训）。
- **R28-7.5 报告项不是错误**：没有任何消费者的扩展维度（R28-3.4）；不生效的条件补丁；按 R28-4.4 单调合成之后不起作用的规则表行；按命名空间分列的齐全率读数（R28-4.9）；`derive` 上次展开之后包集合里新出现的、满足条件而没有变体的基行。它们只进报告，不阻断加载，也不设告警码（卷二的告警码是封闭的五个）。
- **R28-7.6 读文字的工具只有登记的那几个**：按卷十二 R12-2.9，离线组里可以读文字的程序是按类别登记的；与内容有关的是内容构建校验器与命名校验器两个。本节其余命令对文字只做一件事——原样输出到报告或文档；不比较、不切分、不拿它分支（S28-8）。
- **R28-7.7 学习记录的读取口**（兼及卷零 14.16）：`candidates` 就是卷九 §4.16 所说的线下工具。它读旁路的学习记录，按卷九定的签名计数，对达到卷九所定阈值的签名写出候选卡骨架——一份 §2.3 格式的包内文件草稿。签名怎样组成、阈值取多少归卷九；候选怎样生效归 §4.5。运行期没有任何路径会用到这个工具。
- **R28-7.8 示例包由覆盖要求推出**：示例包的角色是 `example`。要求只有三条，都可机判：① R28-1.7 表左栏的每一种“包可以加”的东西，至少有一个示例包用到；五种补丁操作、条件补丁、跨包继承、离线派生各至少用到一次。② 至少三个示例包，其中至少一个的内容不在西陲，至少一个含非人类或超自然内容。③ 每个示例包同时登记为卷十二的扩展性数据包（卷十二 R12-6.6），按 R12-6.2 的固定步骤加、推、断言、撤。示例包的内容照过 §4.5 的各级。设计册原拟的三个示例题材是否沿用为首批，由内容作者定，见附 待补清单第 5 项；本卷不点名任何一个示例。
- **R28-7.9 一次性转换脚本与常设脚本的分界**（回答卷十一 C11-7）：把旧格式内容转成包内文件、只跑一次的脚本，放 `tools/migrate/`，用完不入主干（卷十一 R11-1.8）。它的留痕是卷十一卡账里的一条转换执行记录：卡号，脚本、输入文件集合、输出文件集合三枚内容指纹（口径同卷十二 R12-9.3）；脚本文本随该卡的审查记录保存。于是脚本虽不在主干，仍可核对“入库的这批数据确由那次转换从那份输入得出”。转换产出的行与手写行一样过 §4.5。会反复运行的生成、修复、审批、预算脚本是常设脚本，放 `tools/content/`，入主干，受 S28-8 与 R28-5.12 约束。转换执行记录这一种事件请卷十一增设（C28-7）。
- **R28-7.10 预算账**：模型审与显示名起草的模型调用，由常设的预算脚本按内容指纹记账；它不决定内容对错，只回答“这一批还剩多少额度”。超额即停，等报批（R28-5.10）。

#### 4.7.4 交互

卷十二 §4.6（示例包即扩展性数据包；工具目录进离线组登记，C28-6）、R12-2.9；卷九 §4.16（学习记录与候选卡的格式，C28-11）；卷十一 §4.1、§4.2（转换执行记录，C28-7）；卷二 §1.3（取值算法的来源标记）；卷二十九 §4.1（文档与报告取显示文字）。通道：无（不读写世界状态）。

#### 4.7.5 数据实例

- 【西陲】作者问“这处作坊实例的容量为什么是这个数”：`explain` 答——来自作者偏离行这一级；由某个包的补丁文件里某一条 `shift` 给出；父值取自某条类别行；该类别行在本体的哪个文件。作者不必读加载器的代码。
- 【非西陲】对一个只加远方法典的包跑 `doc`：生成的参考列出法典表与罪名表每个维度的类型、单位、取值域与归属卷节，并标出其中哪些可被补丁改。本体以后给法典表加了一个维度，重新生成即可，没有手写文档要跟着改。
- 【非人类】`derive` 把一份“体型更大”的子行片段展开到包集合里属于某一捕食者类别的全部物种行，写出若干条普通物种行；半年后另一个包加了一种同类别的物种，`report` 把它列为“满足条件而没有变体的基行”，作者决定要不要重新展开。
- 【超自然】`candidates` 从学习记录里聚出一张候选卡：某一类对象上反复出现、而动作目录里没有的一种做法。骨架是一条效果族行的草稿，显示名留空。作者补齐数值与出处，它以 `solidified` 的身份过各级审批，合入后那批签名在题集回放里不再落进未映射一类（卷九 R9-16.5）。

#### 4.7.6 验收断言

- 扫描式：A28-7.1 S28-2、S28-5、S28-8 计数为 0；`tools/pack/`、`tools/content/` 下包代号、表名、行代号字面量为 0；工具目录里未登记的命令文件数为 0。
- 不变量式：A28-7.2 `check` 对一个包集合报出的错误集合，与运行时 `loadWorld` 对同一集合报出的错误集合逐条相同；`explain` 对任一（行、维度）给出的值与来源，等于取值算法对它的返回；`doc` 两次运行输出逐字节相同，且只随数据与语言包而变。A28-7.3 示例包集合满足 R28-7.8 的三条覆盖要求。
- 扩展性式：A28-7.4 本体给某张表新加一个维度，不改任何工具代码，`doc` 的输出里出现它，`explain` 能解释它，`diff` 能比它；新加一个示例包并登记，卷十二的扩展性套件即多跑它，不改执行器。

### 4.8 一方机制表加载

对应卷零 A 表 20.5；台账 V28-06。

#### 4.8.1 维度

无新字段。本体是命名空间 `core` 的包（§2.2 的 `ns`）；它的数据文件对应卷二 §1.1（文件布局）的各项与规则表登记的各行（卷二 §4.1“规则表登记”）。

#### 4.8.2 统一入口

`loadWorld`。本体的数据没有第二个加载入口；规则模块不直接读数据文件（S28-3）。

#### 4.8.3 规则

- **R28-8.1 本体就是一个包**：游戏自带的内容走 §4.4 的同一条流水线、同一个展平、同一个校验器，与扩展包的差别只有 R28-1.1 所说的两处。“一方机制表”不是另一类东西。
- **R28-8.2 现有机制表文件的归宿只有五种**：并进维度表的行；并进词表；成为登记了结构描述的规则表；迁到语言包；退役。判法先看字段是不是显示与文档文字：是的（显示名、别名、说明一类），不论键是什么，一律按卷二 §6.11 迁出到语言包（卷二十九 §4.1）或进 `basis`，作匹配用的别名退役（输入边归卷二 §1.9），不并进行（一审 T8）。其余看文件内容的键是什么：以实体代号为键、给行补数值或代号字段的，并进该实体表的实体行或作者偏离行；以类别、词表条目为键的参数，进规则表；条目清单并进词表；冻结的出处清单照卷二 §1.7（出处与标定）已定的做法。每个文件具体归哪一种、落到哪张表，由其内容的归属卷在卷二 §6（从现有数据迁移）与各卷迁移节里定，本卷不逐个点名。
- **R28-8.3 按登记加载，不按文件名**：本体包根下的每个数据文件，必须对应卷二 §1.1 布局里的一项或规则表登记里的一行；加载器按登记逐项读。目录里出现登记之外的数据文件，即 E-PACK-FILE-KIND。加载器里没有文件名、集合名的字面量，也没有“把文件名变成键再挂上去”的步骤（S28-4）。
- **R28-8.4 机制表带校验**（卷零 §4 核查栏一问的结论）：现状是不带——入口只做读入与挂载，另有一项“注释不得改写已审值”的相等检查（§1.2）。改建后每张规则表按卷二 §4.1 规则表登记的结构、类型与取值域由统一校验器校验（卷十二 R12-5.3），并进维度表的部分自然受卷二 L0 至 L4 约束；规则模块自带的加载期校验退役（卷十二 M12-7）。
- **R28-8.5 规则模块不直接读文件**：规则层要用的表值一律经读入口取；绕过加载入口直接读数据文件的写法由卷二的边界规则报出，本卷不另立判据。
- **R28-8.6 没有“注释层”**：行注释并进行之后就是行自己的值，与行上别的值没有区别；“注释只补不改、与已有值相等才放行”的合并语义不保留。别的包要改它，走补丁。
- **R28-8.7 加载期没有规则步**：现在的加载路径在合并注释之后还会调用若干“规律”函数改写行的内容。改建后加载器只做五件事：合并、展平、补丁编译、校验、冻成副本。原来由加载期规律算出的东西只有两种去处——是别的维度的函数的，登记为派生维度，在取值时算（卷二 §1.12）；不是函数而是一次性产出的，由离线生成脚本在入库前写进行里并过 §4.5。于是“审定的世界”与“运行时的世界”是同一份数据，不再有审批之后、运行之前被改写的一段。

#### 4.8.4 交互

卷二 §1.1、§1.12、§4.1、§6（布局、派生、校验与规则表登记、各文件的迁移去向）；卷十二 R12-5.3 与 M12-7（按规则表登记校验、旧校验退役）；卷十一（迁移行汇总，§7）。通道：只读。

#### 4.8.5 数据实例

- 【西陲】物品的行注释文件（标签与畜产字段）并进物品表的行：加载后这些维度与该物品的其余维度同在一行，过同一套必填与取值域检查；原来“注释与已审值不等就抛错”的检查不复存在，因为不再有两处来源。
- 【非西陲】一张以远方群落为键的站点生态参数表成为登记了结构描述的规则表：缺一个键或数值越界，加载失败，路径指到该键；它不再靠“文件名恰好是某个键”才被规则找到。
- 【非人类】物种的身体属性注释并进物种表的行；原来在加载时由安装函数算出的畜牧性状，改为物种表上的派生维度，取值时由身体属性推出。给一种新怪物填身体属性，它就得到相应性状，加载器里没有任何物种集合的名单。
- 【超自然】本体里一位神祇的行与扩展包里一位神祇的行，在加载后的索引里并排，`explain` 对二者给出的来历格式相同，只是文件路径一个在本体包根、一个在扩展包包根。

#### 4.8.6 验收断言

- 扫描式：A28-8.1 S28-3、S28-4 计数为 0；加载路径上除展平与补丁编译之外改写行内维度值的函数调用数为 0；本体包根下未登记的数据文件数为 0；规则模块自带的加载期校验函数数为 0。
- 不变量式：A28-8.2 包集合加载产出的每一个存储值（`generated` 节不属于任何包，R28-2.11）都能追到某个包文件里的一处（来历记录无空缺）；加载前后各包文件逐字节不变；同一包集合加载两次，结果逐字节相同。
- 扩展性式：A28-8.3 新登记一张规则表（一行结构描述加一个文件），不改加载器代码，它即被加载与校验；把本体的一张规则表里以某个开放族条目为键的行挪到一个扩展包的 `rules` 部分，其余不动，规则读到的值逐一相同。
