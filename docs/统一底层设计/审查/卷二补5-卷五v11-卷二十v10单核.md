## 一、卷二【十七·补】⑲⑳㉑（§2.6"行改挂"第 3 至 7 点、§2.7、§4.3、修订记录、附录 G）

作者自定的细节，逐项判：

1. **`placement` 改成 `{rows, edges}`**：这是裁定"展开时由 placement 一并给新边"的直接写法。入参、校验、E-RELOC-FIELDS 三处都随着改了，kernelApi 的签名不变（520 行）。不超出裁定。
2. **"作废"就是从边节里删去**：边是没有 id 的 struct（§5.6，1426 行），不是实体，不走终止协议。不留"存着但不作数"的边，正好把 N-2 说的"重新挂上以后旧边复活"这条路从根上堵死。不超出裁定。
3. **每次改挂都先作废再新建，包括直接换到另一个父行**：裁定原文只说了离场与展开。但直接换父行如果不作废，会留下同样的瞬移通道，所以推广到每次改挂是同一个口子的必要覆盖。从离场状态展开时，跨界边已经在离场那一笔删光了，"先作废"是空操作，与裁定不冲突。判为不超出。
4. **边节不登记改写写者，由内核代做**：裁定要求"单点在卷二"，内核代写与终止协议中由内核代写的做法同类。第 3 点写明了"本原语与建行写者之外对边节的写入照旧是 E-VIEW-UNDECLARED-WRITE"，第 6 点把有一端在改挂行范围内的边移出静态量，卷五 §3.3 也跟着改了。没有留下绕过的路。可以接受。
5. **`rewriteRows: "all"`，带 `viaRelocate` 的模式不许用**：如果改挂的范围能写成全部行，§2.6 第 1 点"只许可搬走形制"的限制就被绕开了。禁止这种写法是必要的收口，第 7 点 L2 的条款也随着加了。不超出裁定。
