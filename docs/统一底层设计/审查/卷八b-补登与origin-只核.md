## 二、R8b-14.10 sinceDay 与“公民边 since”定义处 —— 真问题

- `sinceDay` 取 `max(bornMinute, genesisMinute)` 所在日，三个字段的重算法也已写在本卷。这一部分本身正确：值只由成员身份确定（`bornMinute` 按 R27-2.2，`genesisMinute` 按卷十 :210），符合 R27-2.3 第 1 项。
- 问题出在定义引用。R8b-14.10 写“与同一事务所开公民边的 `since` 同一口径（定义处：《第0日生成内容提案》定稿二 :144）”。逐处核查结果如下：
  - 卷八b R8b-1.17 ③（:570）只写公民边 `terms.origin` 记 seeded，没写 `since`。
  - 卷二十七 R27-2.2（:345、:369）只说边的条款（“如 `since`、`origin`”）“只由成员身份确定性重算”，没给公式。
  - 卷十八 R18-1.5（:478）只定义 seeded，`since` 是公共键（:419），没有实体化取值。
  - 全书正文搜 `max(bornMinute` / `genesisMinute` 加 `since`，除本条外无命中。
- 所以改稿者的说法属实：公民边 `terms.since` 的实体化取值只在提案 :144，任何卷的正文都没落。正文把审查目录里的提案当定义处，不合全书单点定义的惯例。实际上公民边的 `since` 在全书仍没有定义，R27-2.2 所说的“条款只由成员身份重算”对公民边无从核验。
- 同类缺口：同一事务开出的居民边，其 `terms.since` 也没有任何卷定义。这是同一缺口，按收卷前清同类，须同批补。
- 改法：在卷八b 本卷写定义。落点放 R8b-1.17 ③，或 R8b-14.10 自身，二选一，只写一处。内容是：成员实体化时，按 `keyHoldings` 所开的公民边、居民边，`terms.since` 取 `max(bornMinute, genesisMinute)`；`sinceDay` 取该分钟所在日，引本卷这一处。删去对提案 :144 的“定义处”引用。
- 附带：提案 :162 仍写 `sinceDay: 当日`。上轮要求该句“改为照此引用”，至今未改。这是提案文件，不是本卷，记账。

## 三、:1224 / :1227 两行 origin 与 R27-2.2/2.3

- 两行的 `concluded` 列（:1217 `hk_hostage`、:1220 `hk_agent_for`）都为真，`termsKeys` 已各补 `origin`，满足卷十八 R18-1.5 的静态条件，不会报 E-HK-PROTOCOL。另外三行（`hk_detained`、`hk_bonded`、`hk_kill_right`）`concluded` 为假，本卷也没有关系条目以 `consent` 指向它们，按条件不需要补，所以没补，这是对的。
