## §8 五条待定：利弊与证据（只陈述）

**Q12-1 删一处、添一处而分量不升，要不要机器直接拒**
- 机器直接拒的好处：§4.8.5 的西陲例（把写死的 id 挪到新文件）不再依赖审查者看出来；R12-8.4 现在把这件事交给人工审查项，而人工项的答复只核对"有没有逐条作答"（E-ACC-REVIEW-CHECKLIST），不核对答得对不对。
- 机器直接拒的代价：函数改名、拆函数都会产生新行键，会误拒。本卷已经有 E-ACC-ROWKEY-DRIFT 和"确认前不算已删"，但确认是由认领它的卡来做，仍然是人判。文件搬迁走卷二 §6.11 的搬迁表重新定位，不受影响。
- 已有的机器网：卷十一 R11-2.6（卷十一:361）的 E-MIG-SCAN-UNCLAIMED 要求逐行清单的每一行都落在某条迁移行的锚点范围内。挪到锚点之外的新文件会被它报出，但它只在阶段退出时卡（"阶段退出前这个数必须是 0"），不在每次提交时卡。折中办法：新行键如果落在任何迁移行锚点之外，在提交关口直接拒；落在锚点之内的，交人工审查。
