## 二、重点核对

### 2.1 显示层三条禁令、V-23/V-24、lookupByLabel、文件级不相交：能否交机器

- **V-23**（L699）：对玩家文字变量只允许 `.normalize('NFC')`、`.trim()`、`.toLowerCase()` 各至多一次按序，以及作为 `Map.get/has` 参数；其余方法、正则、拼接、`obj[text]` 违例。可判：AST 追踪一个变量的全部使用点，白名单封闭。可交机器。
- **V-24**（L700）：① 正则与 `includes/startsWith/indexOf/split/replace/search` "用于分支或返回代号"——"用于分支或返回代号"需要数据流判断，可判性弱；且"模板填槽"最常见写法本身就是正则加 `replace`，白名单与禁令会自相冲突。② 不被规则层 import、③ 不含写入口：import 图可判，写入口集合已枚举（transfer / 原语 / declareStateWriter / writeText，L208），可交机器。建议见真问题 6。
- **lookupByLabel 独立成文件**：L206、L242 写明 `server-plugin/input/lookup-by-label.mjs`；V-22 L716 "lookupByLabel 只在输入边调用"，与 L206 一致。三审时显示层可调用它（旧 3.2），现已改，统一。
- **清单在文件级是否不相交**：口径写了（L206、L242、L357 E-GROUP-OVERLAP），但**数据上就重叠**：L242 把 `extension/input-view.mjs`（"键入提交部分"）放进输入边，L206 的显示层 glob 又含 `extension/**/*.mjs`；文件级清单不能只含"部分"。见真问题 2。

## 三、真问题（必改）

1. **屏蔽词表位置与裁定不一致**：见 2.3；行：L137、L212、L365、L716、L774⑤。
2. **输入边与显示层组清单在 `extension/` 下重叠**：L242 `extension/input-view.mjs`（"键入提交部分"）vs L206 `extension/**/*.mjs`；同一文件不能分属两组、也不能只算一部分。改法：把键入提交部分拆成独立文件（如 `extension/input/submit.mjs`）进输入边，显示层 glob 排除 `extension/input/`；扫描前先展开 glob 到文件，再断言交集为空；并要求 `inputEdge.modules` 不用 glob，只列文件。
3. **V-26 与规范化口径冲突**：L717 仍写"NFC 后逐码元相等才命中（……首尾空格、大小写、标点不同 → fallback）"，与 L238/L240/L273 新口径（去首尾空白、简单大小写折叠后命中）相反，测试会判错。改为：首尾空白差异与大小写差异命中，全半角、标点、多一字少一字、整句含菜单名 → fallback；并补一条候选编号键入的用例。
4. **R-2.1 与 §3.1 第 1 条口径不一致（旧判据残留）**：§3.1.1 已改为句柄机制，但 L267（R-2.1："符合代号格式正则且存在于代号登记表"）、L57（G4"只有登记代号"）、L94、L275（R-2.9"非登记代号字面量"）、L693（V-2）、L698（V-20）、L757（术语表"代号登记表"）仍是第三版平铺名单的写法，条文之间互相矛盾，实现者会按 R-2.1 做。统一为"唯一合法形式是同族句柄，裸字面量一律计入"。
5. **population.mjs:384 `AGE_CLAIM` 文字年龄抽取**未处置（见 2.2）。须在 L216 明写：该行删除（或归入 AI 声明校验），不能写"改读代号"。
6. **守门与显示闸的"命中"算法未定，V-24 的"用于分支"不可判**：
   - `match: word` 与 `match: substring`（L217、L137）：`substring` 用 `includes` 即可；`word`（整词）对英文需要分词，对中文没有词界，没有定义就会有人写正则，而 V-25/V-29 没有限制闸内的字符串操作。须定义 `word` 的算法（建议：按 Unicode 空白与标点切分后逐 token 相等；中文条目一律按 `substring`），并给 V-25、V-29 加白名单（仅 NFC/折叠 + `includes` + 词表迭代，无正则，无其他字串方法）。
   - V-24：把"用于分支或返回代号"改为**整组禁用**该清单上的字符串方法与正则字面量，模板填槽集中到一个登记的模板引擎文件（其输入只来自语言包），该文件单独扫描。这样既可机判，又避免与"模板填槽用 replace"冲突。
