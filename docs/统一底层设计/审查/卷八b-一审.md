## 一、真问题（21 条）

### 1. 羁押、人质、奴役三种边 `intimate` 填真，与卷十八 R18-9.1 的未成年硬下限冲突（类别 5、4）
- 位置：R8b-12.1（L946）、R8b-13.1（L985）、§5.3 首行（L1140）与 json `extra`（L1168–1170）。
- 证据：卷十八 R18-9.1 规定种类行 `intimate` 为真的一切持有边都是受检对象，双方全部参与的身体 `intimateEligible`（要求成年，且 `relMaturity` 达线；输入未知即为假）必须为真，否则运行期 E-REL-INTIMATE-MINOR、加载期 E-REL-MINOR-LOAD 整份拒载。由此：未成年人不能被羁押、作人质、为奴；组织作持有者没有年龄维度，判为假，镇公所不能押人。与本卷自己的例子冲突：L963“执政的幼子作人质”、R8b-13.9“生而为奴”、L962 镇公所押人。卷十八（L442、L1314）只要求 `intimate` 显式填写，并没有要求填真。
- 改法：三行 `intimate` 填假。人身依附的保护（例如禁止对被押者做亲密动作）由动作目录条目的 `intimate` 与 R18-9.1 照常管住，不靠边的种类。

### 2. `place.security` 登记成派生维度，越出卷二 §1.12；读分钟级时刻也违背卷二 §2.2（类别 4）
- 位置：§2.3 L209；R8b-7.1、7.3、7.4（L753–756）。
- 证据：卷二 §1.12 规定 `derived` = RX 加封闭聚合原语，变量只读基值维度。治安值要读任职者此刻的位置与清醒、技能读数、卷十三兵力、`popView`、`state.crimeLoad` 锚点、当前分钟，这些都不是基值维度，也超出原语。卷十九 L122 遇到同类情况，已明确改成视图字段。另外，R8b-7.4 的 `d = floor((now − at) ÷ 1440)` 中 `at` 保留了非整日的相位，所以读数随分钟变化；而卷二 §2.2 规定视图读时间只能精确到 `clock.day`，缓存键也含 `day`。按日缓存会在同一天内读到过期的值。
- 改法：`security` 改为 `placeView()` 的视图字段，台账使用方式“读 `placeView().security`”不用改。负荷锚点改按世界日序号存，`at` 取日序号，`d` 等于两个日序号之差。连带需改已封卷：卷五 §2.1 第 117 行（`derived score` 改为视图字段），台账 X-23 措辞同步。

### 3. 治安值公式的输入有缺口：未知值、单位、统计层执法者、人数常数（类别 1、2、7）
- 位置：R8b-7.1、7.3、7.7、7.10（L753–762）；§6 第 2 条（L1205）。
- 证据：① 卷五 §4.9 规则 4 规定，不挂 `comp_settlement` 的地点没有 `control`（不适用，不是 0），而公式直接用 `C`，荒野、无法之地的治安值没有定义；§6 第 2 条却声称“由函数在 0 处取值”。② `popView().total` 是 Fact，可以是未知（卷八 R8-16.1），`max(P, popFloor)` 没有写未知时怎么办。③ “技能读数之和加驻防兵力读数”把两种量纲直接相加，没有折算常数。④ 卷八 R8-2.1 规定权能只来自职位，统计层聚合体不能任职；R8b-7.10 所说“执法者按聚合体人数计入”时，没有判据说明哪个聚合体算执法者。⑤ R8b-7.7 的“若干人”没有对应的规则表键。
- 改法：给 `C`、`P` 各写一个未知分支，在规则表登记缺省值或改用 `gap`；登记 `law.security.garrisonWeight`；统计层执法读数改读握执行权能的职位数乘阶层技能代表值；登记 `law.response.enforcerCount`。

### 4. R8b-7.2 要读“滞后日数之前的控制度”，世界里没有这份历史（类别 4、7）
- 位置：L754。
- 证据：卷五 §4.9 的 `control` 是逐日改写的扩展标度存储量，只存当前值。打破环的 `progress.json.lagDays` 写在卷五一侧（卷五 L747“控制度目标读治安值……以读前一日值打破”）。本卷要读若干日前的值，只能靠历史快照或事件日志，后者违反本卷模板头第 ⑨ 条。
- 改法：直接读 `control` 当前的存储值。卷五每日结算时，先由控制度目标读治安值，后写 `control`，这样本来就没有代数环。删去“两边都读对方旧值”一句。

### 8. 法典不能携带修正项，卷十八、卷二十一与本卷自己的“公共措施”都落不了地（类别 4、1）
- 位置：R8b-1.11（L515）、R8b-7.1（L753）、§2.2 各形态字段表、§8 Q11。

### 16. 时效起算读了卷六并不存在的字段；事实型请求没有起算点；“时效内事实不会被删”不成立（类别 1、5）
- 位置：R8b-15.4（L1069）、R8b-5.7（L680）、§8 Q7。
- 证据：卷六 §2.4 的义务记录字段是 kind、debtor、creditor、resource、qty、done、place、window、condition、phase、contract，没有“最近一次部分给付时刻”。依据为事实的请求权，规则只列了与义务有关的三个起算点。“最近一次告发”可以重新起算时效，于是时效会延续到事实保留期之后，这与 R8b-5.7“不存在还在时效内但事实已删”相冲突。
- 改法：本卷自建 `state.limitAnchors[claimRef]`，订阅给付事件当刻写入，不需要改卷六；事实型请求从事实时刻起算；规定重新起算时同时顺延所涉事实的 `retainUntil`，或者让起算点不晚于事实时刻加保留日数减期限。

### 17. “可被合法攻击”有两套来源，不变量没有机制保证（类别 5、7）
- 位置：R8b-8.1（L793）、R8b-8.5（L797）、A8b-8.2（L817）。
- 证据：`safetyOf().attackable` 由旗标和通缉边直接推出；`attackLegality` 与 `offensesOfFact` 读的是当地杀伤条目的正当事由。当地法典若没有列“追捕在逃者”这条正当事由，`attackable` 为真，攻击却照样成罪。A8b-8.2 断言前者蕴含后者，但加载校验并不核对这一点。
- 改法：`attackable` 改为“对一名无特殊边的攻击者求 `attackLegality` 得真”的派生，单一来源；或者在加载期按 `lflag.attackable`、通缉种类与各法典杀伤条目的正当事由互相核对（与 R8b-4.8 同式），并给出独立错误码。

### 18. 词表族前缀与字段名冲突（类别 4、5）
- 位置：§2.4（L216–240）、附表封闭枚举（L1290–1302）、`claim` 族字段（L237）。
- 证据：① §2.4 给八个封闭族填的前缀是“—”，附表的取值却都带前缀（`offmode_`、`layer_`、`trial_` 等）。卷二 §1.9 规定代码内封闭枚举不带前缀，`_vocab.json` 族必须登记前缀，两种写法只能取一种。② `normlayer` 的取值用 `layer_`，而卷二族前缀表已有 `layer`→`layer_`，前缀冲突。③ `gatekind`、`claimground`、`birthrule` 三个枚举没有登记。④ 新族 `regime_`、`estate_` 与卷十八代码内枚举 `succession_source` 的值 `regime_head`、`regime_guardian`、`estate_heirs` 同前缀，代号空间会混淆。⑤ `claim` 条目的规则字段叫 `basis`，而卷二 §5.0 把 `basis` 定为“文档字段，规则层不可读”。
- 改法：封闭族统一按卷六 `cphase` 的做法（登记族名与前缀，“封闭 N 项”）；`normlayer` 换前缀，例如 `nlayer_`；补登三个枚举；`regime`、`estate` 两族改为不与 `succession_source` 取值同头的前缀，例如 `custreg_`、`lestate_`；`claim.basis` 改名为 `ground`。

### 19. §5.3 向别卷登记的数据有多处与对方成稿不合（类别 4）
- 位置：L1140–1182；R8b-11.7（L913）；`law.roles.purposes`（L265）。
- 证据：① 聚合种类行用 `agg_outlaw` 等，`agg_` 是卷二聚合原语族的前缀；卷二十七 §2.1 的 `aggkind` 前缀是 `aggk_`。② 三行缺 `pooledResources`，可是 R8b-11.7 要把钱转进 outlaw 聚合账户，没有这一列就没有账户。③ `succeedBy: "heirs"` 不是卷十八 `succession_source` 的取值，应为 `estate_heirs`。④ 卷十八 L1309 写明“做客种类下留置变体的两条钩子随留置种类交卷八b”，`hk_detained` 没有接收 `hooks`。⑤ 保管、托管两个分区是卷六已登记的 `purpose_custody`、`purpose_escrow`（卷六 L1008）。本卷却“新登记保管分区”，并说托管是“卷八已登记”，而卷八 L1284 自己写的是引用卷六。⑥ 卷六 §4.21 规则 3 等的是本卷登记“损毁、案值、赔偿”三个价格用途，本卷只登记了两个。⑦ 到期种类每行必须带 `paceClass`（卷二十 L883），§5.3 的十一种没有提。⑧ 统计层抽取的 `subjectId`：卷二十七 R27-8.6 规定取聚合体或单元的 id，R8b-11.7 取的是地点 id。
- 改法：逐项照对方成稿改正；①②③④⑥⑦ 只改本卷数据；⑤ 改为沿用卷六两行；⑧ 改为取单元 id。

### 20. 缺句柄、缺常数、缺量（类别 1、2）
- 位置：R8b-12.4、12.5（L949–950）；R8b-5.2（L675）；§2.6。
- 证据：① “握看守职责的人”“在场看守”没有句柄。`law.roles.powers` 只有四项，§5.3 却向卷八登记了“看守”权能。② “围合完好”没有阈值，“设施的围合值”也没有指明读哪个维度（卷十九只给卷五的 `aperture`、`skyExposure`）。③ 伤人、杀人这类不涉及批次的动作，`harm` 的来源没有定义，而罪刑条目的 `amountRX` 要读案值；赔命价应当读的数值类门控也没有接上。
- 改法：`law.roles.powers` 加 `guard`；登记 `law.custody.breachApertureMax`，写明读 `aperture`；规定 `harm` 对人身事实取伤势或死亡的估值用途，或取“赔命价”门控值，并写明由谁填。

### 21. 记录号的派生没有规定；案件记录没有寿命，“与事实同寿”的说法不成立（类别 6、5）
- 位置：§2.5（L249–250）、R8b-2.14（L562）、§3.3（L460）。
- 证据：`factId`、`caseId` 的生成方式没写。卷二十七 R27-8.9 要求事件、实体、到期项的 id 一律由（种子、规则代号、主体、时刻、位次）派生，不得用计数；这两个 id 还要进到期项和骰值键。R8b-2.14 说“案件记录与所涉事实记录同寿，见 §3.3”，可是 §3.3 规定事实结案后到期删除，案件只在当事人终止时由清理函数迁到结案、永不删除，两者并不同寿，`state.cases` 会无限增长。
- 改法：写明两种 id 按 R27-8.9 派生（主体取行为人或告发者，位次取登记的抽取点代号）；给已结案件设保留期，到期删除；一事不再理改为只在保留期内核对，并在 §1 说明这一取舍。
