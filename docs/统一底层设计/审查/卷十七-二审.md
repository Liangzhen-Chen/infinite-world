## 二 真问题（改动带出的新问题，均为局部；新真问题，需报李白）

### 二-1 风项自建正弦、余弦数表，与全书唯一的定点三角实现冲突（类别 4）
- 位置：§2.4 `wind.sinCurve`、`wind.cosCurve`（:203）；R17-1.4 风项（:317）；待补第 17 条（:1003）。
- 证据：
  - 全书三角函数只有一处实现：卷二十七 §4.5 的 `fn_sin`、`fn_cos`（卷二十七:510）。
  - A27-5.1 要求"全仓……三角……各只有一处实现，规则层与其他组里同名函数的定义为 0"（卷二十七:535）。
  - 卷二十算太阳赤纬，用的就是这个定点实现（卷二十:583）。
  - 本卷在规则表里另放一套数表当正弦、余弦用，等于第二处实现。
- 改法：
  - 风项改调卷二十七 §4.5 的 `fn_sin`、`fn_cos`；
  - 删去 `wind.*` 两键与待补第 17 条中的数表部分；
  - §4.1.1 维度清单（:303）、§4.5.1（:491）随改。

### 二-2 `downhillMotion` 要带符号的落差，卷五的边是无向的（类别 4）
- 位置：R17-2.11（:388、:389、:390）。
- 证据：
  - 本卷写"落差 `ascentM`（下行为负）"。
  - 卷五的边是无向的，`ascentM` 取绝对值、上下坡同速，这一点卷五记为现状（卷五-地点地形与资源场.md:1217 B 小 11），路况系数也按 `|ascentM|` 求（卷五:775）。
  - 所以边上的这个量不带"沿哪个方向下行"的信息，读不出符号。
- 改法：带符号落差按行进方向现求，等于终点 `elevationM` 减起点 `elevationM`（`elevationM` 是卷五登记的位置量，卷五:247）。卷十九轨道段要写明，它的符号也按行进方向的两端高程取。

### 二-3 R17-2.11 毫米与米混用（类别 5）
- 位置：:389、:390、:391，返回值 :245。
- 证据：
  - `v²` 明写"按毫米与秒的定点整数算"，开方得到的末速度单位是 mm/s。
  - 但这个速度又拿去和 `motion.maxSpeedMps`（m/s）封顶，返回字段也叫 `speedMps`。
  - `stopAtM` 的式子算出的是毫米，正文却写"米"。
  - `kineticJ = 质量 × v² ÷ 2` 直接用 mm²/s² 代入，比焦耳大 10⁶ 倍。
- 改法：
  - 写明换算：封顶与返回前除以 1000（常数除数）；
  - `stopAtM` 除以 1000；
  - `kineticJ` 除以 10⁶，或写明先换成 m/s 再求。

### 二-4 同一种情形，停歇原因两处写法不一（类别 5）
- 位置：R17-1.5 越线通知（:325）；R17-8.4（:625）。
- 证据：
  - R17-1.5 规定：通知投递时 `passOf` 为 `closed` 即转 `halted`，原因为 `blocked`。
  - R17-8.4 说的是同一情形：成员体力见底，`moveSpeedOf` 为 0，于是 `legSpeed` 为 0，触发 `passOf` 第 ④ 项 `closed`。这里却写"因 `rest` 停歇"。
  - 停歇原因要进 `verb_trip_halted` 的载荷，订阅方读到的值会不一致。
- 改法：在 R17-1.5 写明，`closed` 的停歇原因按 `passOf` 的 `missing` 或触发事件的种类定，单点列出对应关系：体力类状态实例对应 `rest`，载具故障对应 `breakdown`，其余对应 `blocked`。R17-8.4 只引用这一处。

### 二-5 E-POS-SYNC 不分行程阶段，与本卷自己的例子和停歇期活动冲突（类别 5）
- 位置：E-POS-SYNC（:232）；R17-1.5（:321）；§4.11.5 例（:748）；R17-2.6 的 `breakdown` 停歇。
- 证据：
  - E-POS-SYNC 的条件是"行程成员中有人另持一条持续活动"即报错，没有分 `moving`、`halted`。
  - 但"随船的测绘者把它们升到 `surveyed`"（:748）是一名行程成员在航行中做测绘，测绘是持续动作（R17-11.5）。
  - 停歇期间修车（卷三乙的修理）、勘察（R17-11.4）也都是成员的持续活动。
  - 照现文这些都报错，只能先"离队"；可本卷动作行里只有"离队"、没有"入队"（:153），离队后回不来。
- 改法：在 E-POS-SYNC 与 R17-1.5 单点限定范围。
  - 只禁止会改变行动者位置的持续活动，即动作行含 `move` 原语或以别的边为工量；
  - 其余持续活动照卷九 R9-1.8 的 `attention` 规则与 march 并存，或者只在 `halted` 时许可；
  - :153 补一条"入队"动作；
  - :748 的例子按所定口径核对。

### 二-6 关卡放行边由谁持有，前后矛盾（T25 未改干净，类别 5）
- 位置：§2.2（:148）与 R17-7.3（:587）写"持有者为关卡设施，标的为领队"；R17-1.3 ②（:313）与 R17-7.1（:579）写"领队持有一条该关卡给出……的关卡放行边"。
- 证据：需求块是对队伍求值的，读的是领队这一侧的持有边。两种写法下，持有者与标的正好相反，需求块读不读得到这条边，结论也相反。
- 改法：只取一种方向（建议持有者为领队、给出方即来源为关卡设施），四处统一，A17-7.2（:607）随改。

### 二-7 围方放行的持有种类没有出处（T23 未改干净，类别 4）
- 位置：§2.2（:148）"持有种类取卷十三登记的围方放行种类"；R17-1.3 ⑤（:313）`roles.holdings.siegePass`。
- 证据：
  - 卷十三没有登记任何"围方放行"持有种类，在卷十三里检索"放行"为 0 命中。
  - 卷九的同意边只有一个种类，即 `rules.consent.edgeKind`（卷九-AI接口.md:122、:261）。
- 改法，二选一：
  - 围方放行直接用卷九同意边（种类即 `rules.consent.edgeKind`，给出方是围方，即被围标志所属的围攻一方），删去 `siegePass` 句柄；
  - 像 `gatePass` 一样由本卷向卷十八登记一行，同时在 §5.3 补 C 项写明读者。
  - 不得指向不存在的卷十三条目。
