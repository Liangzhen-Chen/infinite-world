## §0 统一写法（各项只填与此不同的部分）

**U1 阶段条目字段**（卷十 §2.1 :107 `gstage` 族；先例 卷七 :1039、卷十六 :779–780、卷八 R8-18.9 :1201）。七个必写字段和 `labels` 全部写出，另有一个可省字段 `writesFamilies`（见本条末）。采纳后不再有“补齐前不加载”的条目。
- `phase`：只写入第 0 日数据副本或世界创建事务状态的，取 `worldgen`。要读运行态的，取 `opening` 或 `expand`（R10-1.2、R10-1.10）。
- `scope`：取“产出只依赖它自己和先行阶段”的那一类主体（R10-1.4）。两个主体会写同一个对象时，`scope` 取高一级，或者拆成两个阶段，不许同阶段内互相依赖。
- `after`：本阶段要读的东西由谁产出，就写谁。`before`：同一相里谁要读本阶段的产出，就写谁。两项都写代号字面量（R10-1.1、R10-1.5）。
- `generator`：`worldgen/<名>.mjs`。
- `writesKinds`：本阶段要建行、或要往已有行上补维度的那些实体类，代号取 `kind_<表名>`（卷二 :240“22 类代号本身作枚举时用”，所以 `kind_culture`、`kind_material` 本来就有，卷十 §8 第 18、23 条说“本书未见”不成立）。只调别卷写入口改状态、或只开持有边的阶段取 `[]`（先例 `gstage_people`、`gstage_endow`）。
- `whenRX`：取 null。只有整阶段按主体基值决定跑不跑时才写（R10-1.6）。
- `writesFamilies: set<string>`：可省，缺省为空集。写本阶段要新建条目的开放词表族名。加载时核对两点：该族在卷二 :240 已登记；该族的条目归属允许本卷写。范围外的词表条目提案由写回器拒收，与 `writesKinds` 在同一处校验（R10-9.9）。因为缺省是空集，现有条目都不用补：卷十 :312–330 各条、卷七 :1039、卷八 :1201、卷八b 两条、卷十六 :779–780、卷十七 R17-9.1 都不改。全书可生成的东西，就是全部条目 `writesKinds` 与 `writesFamilies` 的并集。目前只有艺术形式阶段填非空值（§3 第 18 条）。

**U2 种子键**（卷二十七 R27-8.5 :690；卷十 R10-12.3 :874、R10-12.4 :875）。三类，不另造。
- ① 一次性生成抽取：五段为（世界种子，`stream.gen.<阶段名>`，被生成对象的 id，`genesisMinute`，`site.gen.<阶段名>.<字段>`）。对象 id 优先取 `instanceIdOf` 导出的 id。复合对象段里的空成分填 `nil_seedpart`（卷二 :848）。一个字段要取多个不同分布的值时，登记固定个数的位次 `.<j>`，`j` 的上限是规则表键（先例 `site.gen.name.word.<j>`，卷十 §4.12.1）。
- ② 成员级身份采样：键为（个体类，实例 id，抽取点代号），是纯函数，用于统计层不计数的成员属性（先例 R10-4.8 名册职业）。
- ③ 运行期或实体化时的抽取：对象取事件 id 或职位 id，时刻取事务时刻（先例 R8-2.6、R10-12.3 ③）。
- 生成期的抽取一律用 `stream.gen.` 前缀，流代号与抽取点由拥有该阶段的卷自加行（R10-12.4）。卷十 §8 第 19 条按此定：卷二十三 R23-3.3 的形式生成改用 `stream.gen.artforms`，运行期的“作”仍用 `roles.streams.works`。

**U3 规则表键命名与形状**。键名为 `<该卷规则表前缀>.gen.<对象>.<用途>`（先例 `polity.gen.realmRows` 卷八 :324、`form.gen` 卷二十三 :167、`rules.gen.*` 卷十 :147）。数值只出现在数据实例里。形状只用四种：
- (a) **选行**：`list<struct{whenRX: rx, …结果字段}>`，取行序最前的真行，没有真行就不产出（先例 卷八 :324、卷十 `classify.rows`、卷十六 `gen.baseRows`）。用来定“是什么种类”。
- (b) **份额**：`shareBps: integer [0,10000]`，或对象行上的 `map<ref, integer>` 权重。把整数总量照卷二 §3.3 第 3 条分开（前几份向下取整，末份取差），不抽取（先例 R10-4.4、卷七 R7-16.7）。用来定“各有多少”。
- (c) **分布**：`distribution`（卷二 :259–278），按 U2 的键抽取（先例 `rules.gen.pop.fillDist`）。用来定“有多大，带随机”。
- (d) **曲线**：`curve`，由一个已登记的读数查出另一个数，不抽取（先例 `rules.gen.site.perUnit`）。用来定“由什么换算成什么”。
- 个数取 `integer` 或 `distribution(integer)`。每个对象各自的权重优先放在对象自己的数据行上（`gen.speciesWeights` 先例），全局常数放规则表。`whenRX` 只读已登记的数值维度和代号。

**U4 写者与入口**（R10-1.3、R10-9.x、卷十 §3.2 :167–179）。
- 生成器只出提案。建行经写回器。别卷的状态只经该卷已登记的写入口写，在世界创建事务内调用。
- 入口需要“准许者权能”核对的（`enactLaw`、`estateStep`），生成期不调。需要第 0 日写入的，由拥有该路径的卷加一种“只许世界创建事务使用”的提案或参数，越界报该卷的 `E-…-GENESIS-ONLY` 码（先例 卷八 `popApply` 开局建群与 E-POP-GENESIS-ONLY，R8-16.2）。
- `worldgen` 相不建个体行（R10-1.11）。成员级的开局量只走两条路：
  - 统计层要计数的（公民、信仰），走分组键 + `keyHoldings`：实体化时在同一事务里开边，条款只由成员身份重算（R27-2.2 :343、R27-2.3 :354 第 2 项）。
  - 统计层不计数的，走身份采样：在实体化事务里写入（R10-4.8）。

**U5 seeded 口径**（李白 256edd18；卷十四 :524、:574）。
- `concluded` 为真的种类，在个体实例化事务内由生成路径带来的边，`terms.origin` 记 `edge_origin` 的 `seeded`，不记 `consentAct`。运行期的新边照旧要带同意条款的动作（卷十八 R18-1.5，待勘误补）。
- `concluded` 为假的种类不需要 origin，也不新加 terms 键。
- 不点名种类。凡 `concluded` 为真、又要走 U4 第一条路的种类，都要在卷十八键表登记 `origin: enum edge_origin`。

**U6 空值**。规则表行里不设“空结果”，“不生成”由“没有真行”或“份额为 0”表达。键里的空成分填 `nil_seedpart`。分组键的空值本身是一个键值（卷八 :1100）。本提案不新增空码。

**U7 手写优先**。作者已写的行、维度、边照旧，生成器把它们当输入，不出同一序位的提案（R10-1.7）。作者写的 map 维度按键补缺（§3 第 17 条）。

**U8 验收**。每个阶段补两条断言：一条是“打乱主体遍历次序，产出逐字节相同”（A10-1.2 写法）；另一条是本阶段的计数不变式。

## §1 卷八 C10-2：开局政体、持有与职位（审视 R8-18.9，并补开局在任者）

### 1.1 R8-18.9 对照统一写法
- 字段（:1201）符合 U1。`polity.gen.realmRows`、`openTiers` 是 U3(a)，`settlementKind`、`holdCause` 是单值引用（:324–327），命名符合 U3。位次三条（§5.3 :1317）符合 U2。没有抽取，不登记抽取点，符合 U2。
- **要改一处（对齐，不是新设计）**：② 的 `openTiers.whenRX` 读开局人数 `popView(站点).total`。但本阶段排在经济阶段之前，这时还没有清单和床位。按卷八 R8-16.1 :1110，站点比单元小的时候，聚合部分要“按可用床位分摊”，床位总数为 0 时取未知。所以这一项在第 0 日恒为未知，按 R8-18.9 的规定作假，所有站点都写不出 `tier`。生成期的站点开局人数已有登记读数：卷十 R10-3.3 :436 的 `floor(总人数(U) × gen.share ÷ 10000)`，原文就说它是“只在生成期用来定类型、清单与配额”的。改法：② 和 A8-18.2 里的“开局人数”改指这个读数，经 `genView` 读，不读 `popView`。
- ④“开局全部空缺，之后由 `settleOffices` 补缺”不成立（二轮只核 §3），见 1.2。A8-18.2 里“本阶段建的职位行全部空缺”这一句随之改。

### 1.2 开局与离屏的在任者：从居民聚合体产生（新规律）
- **缺什么**：R8-2.5 :599 的五种继任来源，在统计层都找不到候选人；R8-2.10 :604 的代理人也一样。所以离屏的职位永远空着。这和“开局零公民”是同一类问题（李白已否）。
- **规律**：一个职位的候选人取不到合格个体时，从这个组织驻地所在模拟单元的居民聚合体里抽一名成员。先实体化他，再核资格，过了就上任。规律对开局和运行期一样，不分生成与否。
- **按哪些已登记维度**：
  - 候选聚合体：驻地站点 `seat`（卷八 :129）所在 `simUnitOf` 单元内的居民聚合体。聚合种类取句柄 `rules.pop.aggKinds.resident`，见卷八 :1100。
  - 聚合体的读数：只读分组键，即物种、文化、信仰、主业四个键（卷八 :1100），选甲时再加公民键（§2.3），外加成员区间的人数。
  - 年龄：成员区间的 `bornMinute`（卷二十七 R27-2.2）加物种的 `maturityYears`（卷四 §2.1，见卷十六 :796 所列必填维度），未成年的区间不进候选。
  - 资格：仍由 R8-2.2 :596 在实体化之后核，读的是个体维度，不放宽。
- **规则表键**（卷八 `polity.office.*`）：
  - `polity.office.poolRows: list<struct{whenRX: rx, weight: integer ≥ 0}>`，形状 U3(a)。`whenRX` 只读聚合体的分组键值，以及该职位行、所属组织行、种类条目的维度。取行序最前的真行，聚合体的权重 = 该行 `weight` × 已成年成员数。没有真行，或权重之和为 0，就不抽，职位保持空缺。这一项本身就是结果，不是错误。
  - `polity.office.poolTries: integer [1, 16]`：一次补缺最多抽几次（每次是固定的位次）。
- **抽取**：U2 ③，流沿用卷八 R8-2.6 已登记的继任流，对象为职位 id，时刻为空缺发生的分钟。抽取点为 `site.office.poolAgg.<j>`（选聚合体）和 `site.office.poolMember.<j>`（在该聚合体已成年的成员区间里均匀取一个序号），`j < poolTries`。抽中的成员如果已经实体化，就直接用那个个体。
- **写者与入口**：`settleOffices`（:440）在固定刻的同一笔事务里做三件事：调卷二十七 `materialize`（:366）建该成员的基本行；按 R8-2.2 核资格；过了就调 `seatOffice`，`state.accession` 的 `via` 取 `acc_created`（:1456，没有前任、授予者、任命者，也没有选举）；没过就换下一个位次。任职边的种类是 `hk_holds_office`，`concluded` 为假（卷十八 :507 第 10 列），按 U5 不需要 seeded，也不加 origin 键。上任后这个人的足迹不为空，按 R27-2.4 :359 自动钉住，不另写钉住条件。代理（R8-2.10）照旧：补缺成功就不需要代理。
- **不定会怎样**：离屏地区永远没有统治者。`hasPower` 处处为假；R8-6.2 的 `s` 取 0；R8-7 的正统性为 0；R8-5.2 读当家者信仰的那一项随数据而定。
- **同类先例**：R8-2.5 的“比试”一项已有“候选范围内按读数排序、再按骰值键抽”；卷十 R10-4.10 在物化时把成员配到工位。实体化之后再核个体资格，与卷二十七 `materialize` 只建基本行、不动账的口径一致。
- **落点（请李白批准）：卷八 R8-2.5 末尾加一段“统计层候选”。** 个体候选为空时，`successorsOf` 走这一段，开局和运行期都用它。R8-18.9 ④ 改为：开局空缺的职位，在第一个 `settleOffices` 固定刻按 R8-2.5 补上。
  - 代价：
    - 要改已封卷八：R8-2.5、R8-2.6 新增两类位次，A8-2.x 补断言，种子键表加行。

## §2 卷八b C10-3：开局法典绑定、身份等级与公民边

### 2.1 阶段条目（U1，拆成两条）
法典绑定以政区为主体，公民的改记以单元为主体。一个单元可以跨多个落位政区（卷十 R10-4.4），所以合在一个阶段会违反 R10-1.4，要拆成两条：
```json
"gstage_lawbind": {"phase": "worldgen", "scope": "region", "after": ["gstage_polity"], "before": [], "generator": "worldgen/lawbind.mjs", "writesKinds": [], "whenRX": null, "labels": {"zh": "开局法典绑定", "en": "Opening law bindings"}},
"gstage_civic":   {"phase": "worldgen", "scope": "unit",   "after": ["gstage_polity"], "before": ["gstage_economy"], "generator": "worldgen/civic.mjs", "writesKinds": [], "whenRX": null, "labels": {"zh": "开局公民构成", "en": "Opening citizenry"}}
```
`gstage_civic` 的 `before` 取经济阶段，理由是经济阶段 R10-7.2 ④ 按居民聚合体建住处，要看到改记后的聚合体（同卷七 `gstage_faiths` 排在经济阶段之前，:1039）。

### 2.2 开局法典根从哪来（待李白选）
- **现状**：成文法典根 `legislator` 必填（卷八b :176），而生成出来的组织要到第 0 日才有 id，目录行指不到它。习惯层可以留空。为空时，`forumOrgOf` 退到 `governorOf` 给出的组织（R8b-1.15 :559），所以习惯层法典根绑在生成世界上不缺承办组织。
- **甲（推荐）：开局只绑目录里 `legislator` 为空的法典根（习惯层），成文法由运行期政权自己立（R8b-1.10 已有）。**
  - 规则表键：`law.gen.bindRows: list<struct{whenRX: rx, books: set<lawRef>}>`，用 U3(a) 选行形状：取行序最前的真行，把它的 `books` 全部绑上；没有真行就不绑。加载时核对两点：每行 `books` 的条数不超过 R8b-1.14 的单持有者上限，超出即加载失败，所以运行时不会超；每部 `book` 是 `legislator` 为空的法典根。`whenRX` 只读该政区行的基值维度、`gen.seatCulture` 所指文化行的维度、R8-18.9 ① 所建主权组织的种类条目与政体行。每部的 `jurisdictionKinds`（:177）都要含 `rules.gen.pop.cultureLevel`，同在加载时核对。
  - 写者与入口：对 `books` 中每一部按代号升序调 `bindLaw(政区 R, book, ctx)`（:438），由写回器在世界创建事务内调用，`sinceDay` 取第 0 日。只对“R 之下有站点”的落位级政区出提案，跟 R8-18.9 ① 同一个遍历。
  - 代价：开局世界只有习惯层，没有成文法典，法律栈由绑定的习惯法加文化 `lawHabits`（R8b-1.3 :547）组成。`outsiderEstate`（:179）来自习惯法典根。
- **乙：生成期为每个开局主权组织立一部法典根副本。**
  - 规则表键：`law.gen.codeRows: list<struct{whenRX: rx, template: lawRef}>`（U3(a)）选一部目录法典根作模板，code.mjs 加一种只许世界创建事务的立法提案，把模板根和它名下的全部条目复制进 `state.enacted`（:264），`legislator` 写成该组织，条目号照 :279 派生。
  - 代价：`state.enacted` 的体积约为“政体数 × 条目数”。复制条目时 `book` 要改指副本。`enactLaw` 的权能核对要另开一条只许世界创建事务的路径。新增的入口和校验分支都比甲多。

### 2.3 开局公民边（李白 256edd18 ②）
- **查到的缺口**：按裁定，公民边要“经分组键”在实体化时开出。可是居民聚合种类的分组键只有物种、文化、信仰、主业四项（卷八 :1100、:1336），卷二 §5.5 也没有任何经公民边派生的个体维度（卷二 :1498–1510 只有 `faith`、`profession`、`primaryProfession` 三项派生维）。所以“公民种类登进 `keyHoldings`”这一步，现有维度接不上。下面一案是裁定 ② 的必然推论，**报李白知悉**（第三版改）。另一种做法是不加维度、整个聚合体按现有分组键定公民身份，但那样比例只有 0% 和 100% 两档，违反裁定 ② 原文“比例进规则表键”，所以不列为候选（只核 §3）。
- **登记一个派生维 `citizenOf`，放进分组键：**
  - 维度：卷二 §5.5 加 `citizenOf: derived ref org nullable（经持有：卷八b 句柄所列的公民种类）`，写法同 `faith`、`primaryProfession`。居民聚合种类 `keyDims` 加这一项，`keyHoldings` 加公民种类。
  - “与分组键一致”的判法照执业边：未结束的公民边至多一条，且所指等于键值；没有公民边当且仅当键为空；有第二个籍的人照常计入足迹（卷八 :1100）。迁移时分组键随人走，所以本人迁走不失籍，与 R8b-14.9 一致。
  - 生成（第二版改，照卷七 R7-16.7 ③ :1039 在单元一级交提案，不按聚合体逐个交）：
    - 定目标组织：`gstage_civic` 先定“U 的开局主权组织” O，即 R8-18.9 ① 在 U 主份所在政区建的那个主权组织。主份照 R10-4.4 主文化的取法：面积最大者，并列取 id 最小。该政区没有政体时，本单元不出提案。
    - 求公民人数：对 U 里 `citizenOf` 键为空的每个居民聚合体 a，在 `law.gen.citizenRows: list<struct{whenRX: rx, shareBps: integer [0,10000]}>` 里取首条真行的份额（U3(a)+(b)）。`whenRX` 只读 a 的分组键值、O 的种类条目和政体行。再把 a 的人数按 `[shareBps, 10000 − shareBps]` 照卷二 §3.3 第 3 条分成整数，前一份即 `n_a`；没有真行时 `n_a` 为 0。最后求和，`n = Σ_a n_a`。
    - 交提案：`n` 大于 0 时，向 `popApply` 交**一份**改记提案（R8-16.2 :1114）：来源地点取 U 的单元行，桶为 `citizenOf` 键为空，目标键为 O，人数为 `n`。
    - 抽人：桶内逐人抽由 `popApply` 做。骰值键的对象段是“地点 | 桶键 | 目标键”，每个（单元，目标组织）只有一份提案，所以不会撞键。第三、四段照卷二十七 R27-8.5 生成期的写法，空桶键填 `nil_seedpart`。
    - 结果口径：公民与物种、文化等各键的对应只在单元一级按份额成立，与信仰分布、统计层改宗流（R7-16.7 末句）同一口径。
  - 实体化：卷二十七 R27-2.2 照整类规则，按键开公民边，`terms.origin` 记 `seeded`（U5），`since` 取 `max(bornMinute, genesisMinute)`，只由成员身份重算，所以不计足迹。
  - 代价：
    1. 改已封卷二和卷八的分组键，聚合体个数最多翻一倍，经济阶段的住处行随之增加。
    2. 出生键的整类判据（第二版改）：新生儿进入哪个聚合体，由他自己的分组键决定（卷二十七 :344）。其中经 `keyHoldings` 种类派生的键维，若该种类在卷十八种类表 :494–515 的 `concluded` 列为真，出生时取空，因为新生儿无从同意（R8b-14.4 :1072）。若 `concluded` 列为假，照母体的键值。规则只读这一列，不点名种类。照此，公民键出生取空；信奉、执业、居住三种 `concluded` 为假，信仰键、主业键照旧随母体，离屏人口的信仰与主业不随代际流失。
    3. 因为出生键取空，离屏的公民比例会一代代降到零，所以要另补**统计层入籍流**。它是运行期的新流，超出“第 0 日”，**单列请李白批准**（见 §8 第 3b 项），不只当作一项代价带过。写法照卷七 R7-9.4 :766 的改宗流：`law.estate.naturalizeRows: list<struct{whenRX, rateNumerator, rateDenominator}>`，桶为单元内 `citizenOf` 键为空的成员，目标组织取该单元现时的主权组织（`governorOf` 给出的组织沿 `realm` 上溯），经 `popApply` 改记，余数存法照 R7-9.4。不补，就又是“离屏缺规律”。

### 2.4 居民边与等级记录（生成期写 `estates` 的入口）
- **结论**：生成期不写 `state.estates`。按 R8b-14.10 :1078，聚合体成员的等级不逐人存，统计层读 `law.estate.stratumMap`（:339）。等级记录只在成员实体化的那笔事务里写。

- **写者口径**：卷八b :274、:451 的“只经 `estateStep` 与出生取得”改为“只经 `estateStep`、出生取得与成员实体化取得（同由 estate.mjs 写）”。这样 A8b-14.2 :1094 里“每条记录都有现役公民边或居民边”一句自然成立。

- **不定会怎样**：`estateOf` 落到栈首法典根的 `outsiderEstate`；栈为空时取未知（只核 §2 表）。开局选举选不出人。实体化前后等级读数也不相等。

## §7 C10-12 卷三乙：分户时的容器装载（R10-8.7 :665，§8 第 11 条；正文暂不派）
- **规律**：卷二十七 `settleOut`（分户）时，户份额里凡按 T-2 须装进容器的批次（物态条目 `needsHolds` 或 `needsSealed` 为真），在同一事务里按 K-1、K-2（卷三乙 :938–939）装进同一份额里的容器实例。次序：批次按物品代号升序，容器按实例 id 升序，逐件装到 K-1 判为装不下为止。装不进的留在聚合账户，不分出去。

## §10 李白 256edd18 ④ 查证：其他 `concluded` 边在生成期的缺口（只列，不扩写）
