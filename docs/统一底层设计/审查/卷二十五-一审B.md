### 4. "`take` 之外减少在田粮食为 0"与本卷自己的损耗路径矛盾，容易诱导绕过
- 位置：A25-3.1（第 378 行）、S25-5（第 247 行）。对照 §4.1 规则 5、6（`standCurve` 过熟下降，`lossKg` 转入损耗汇）、§3.2 `clearCultivation`（翻掉一茬）、§4.1 规则 6"被毁"、§4.11 A25-11.2。
- 类别：5、7
- 证据：A25-3.1 要求 `take` 与进食动作之外减少在田粮食的调用点为 0（腐坏除外）。但卷五 `settleStocks` 把 `lossKg` 转入损耗汇，`clearCultivation` 也会让现存量消失，烧毁或踩踏同样会让它消失，这几条都不经过 `take`。按原文执行，要么断言必然失败，要么实现者在名义上把损耗改走 `take`，绕过断言。A25-11.2 的分项里也没有"被毁"。
- 建议：断言改为白名单：在田存量账户的转出只许出现在三处，即 `take`、`settleStocks` 的损耗汇转移（原因代号为 `cropGrowth.lossKg`）、`clearCultivation` 的损耗汇转移（带原因代号）。每笔都要带原因代号，并核对总额。被毁统一走效果族，最终落到同一条损耗转移上。A25-11.2 补"被毁"一项。

### 6. 用 `sourceTaxon` 推不出 `sapientShare`
- 位置：§2.2 第 130 行 `sourceTaxon`；§4.12 规则 4（第 702 行）；A25-12.2（第 720 行）"成品的 `sapientShare` = 各投料按质量加权"。
- 类别：1、5
- 证据：`sapient` 是物种维度（卷四），`sourceTaxon` 只记录分类。同一个分类位置下可以既有有心智的物种，也有无心智的物种，分类代号也可以停在较高的层级。食物进了配方以后只剩材料，要算 `sapientShare` 就只能读 `sourceTaxon`，这是推不出来的。另外，如果多个物种共用同一行"肌肉"材料（卷四 `tissues` 允许），`sourceTaxon` 也会丢失。
- 建议：材料维度另加 `sourceSapient: boolean`（由卷四 `tissues → material` 派生，禁手填）；或者规定凡是有 `sourceTaxon` 的组织材料，必须按物种各自成行。二者选一并写进 §8 Q3。A25-12.2 的加权式需要标明依赖这个字段。

### 10. 丰歉指数只在"成熟日"有定义，绝收时永远不成熟，事件时点也没写
