## 六、可能的误报与漏报

误报：
- 同一事实在写入口表与正文各写一次，会按位置各报一处（如卷四清理函数在 §2.6、§3.3、§4.8 各出现一次）；改一处后其余几处也要跟改，合并看。
- 裸字段经 struct 反查：同名字段出现在多个 struct 里时会推出多条路径，其中只有一条是真写的。
- "调 / 经"判定只看行内 16 字内有无目标写者名或其入口函数名；写成"转给某卷处理"而不点模块名的合法调用会被误报。
- 正文句里的动词与路径按"动词之后、下一个动词之前"配对，叙述别的系统做什么（"由内核按表删除 `x`"）而句中恰有清理函数名时可能误配；已跳过"不在 `fn` 里""`fn` 不写"句式。
- 模块到系统的映射取"`x.mjs`（sys）"写法，没写的用文件名；一个系统多个模块而只在一处写了系统名时，同系统的别的模块可能被当成外系统。

漏报：
- 只扫写入口表与清理类函数所在的正文句；普通写入口在正文里描述的写入（不在写入口表里）不扫。写者登记表本身的越卷登记（某卷把别卷路径登记成自己写）属双写，由 `check-dualwrite.mjs` 查。
- 写入对象不带反引号（"身份键""尸体""持有边"）而又没写"`X.mjs` 的写者"时抓不到；写入口表的"写什么"格只写中文时同样抓不到。
- 函数所在模块在全书没有表格登记（第五节）的不判。
- 订阅 `verb_entity_terminated` 后写已终止实体的情形（卷二另有拒写规则）不在本检查内。
