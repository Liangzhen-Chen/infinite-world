# 卷一 独立审查 B

审查对象：F:/dnd/docs/统一底层设计/卷一-总纲与分层.md（750 行，已全读）。对照：调研 01–05、10。
总判：**有条件通过**。分层纪律、门禁、退役机制写得扎实，是本卷强项；缺口集中在"成熟游戏的共享计算机制"没有进入卷一的层次与词汇，以及 R-4 与 V-6 的可检验性。

## 一、关键层遗漏（必改）

1. **修正求值层缺位（CK3 修正键表、EVE dogma、环世界 Stat 求值顺序）。**
   - 卷一只在 I27 / `derived()` 槽里提了一句"add → mul → max → min → clamp"（附录术语表），§2.4 派生形状也只写"缺省带修正槽"。
   - 没有规定：统一修正键表的命名与作用域（05 §8 第 10 条 `<scope>_<what>_<add|mult>`）、固定求值顺序（03 §3.2 九步）、堆叠规则与堆叠惩罚（EVE）、来源可追溯（explain）。
   - A-18 只禁封闭枚举，是"禁令"不是"机制"。05 §3 的特质、传统、建筑、文物、王朝全部输出 modifier，是 CK3 的统一底层；卷一没有把它立为第三层的一级公共设施。
   - 必改：在 §2.4 或 §4 新增"属性与效果分离"一节，立三条：开放属性集合；唯一求值顺序（引用 03 §3.2）；效果只声明"改哪个属性、怎么改、作用域"。并指定卷二落成。
2. **模板继承与需求复用缺位（CDDA copy-from / extend / delete、requirement 复用）。**
   - 全文检索 requirement、copy-from、继承，零命中。
   - G3"只填数据"在没有继承与可复用需求块的情况下，486 件物品每件都要全填，数据量爆炸并重复。CDDA 的配方 / 设施 / 工具需求靠 requirement 复用，是"只填数据"可持续的前提。
   - 必改：§2.2 数据形态加"实例继承（copy-from + extend/delete）"与"可复用条件块 requirement"，作为维度表的标准能力。
3. **历史实体层只隐含。**
   - DF 的做法是国家、宗教、公会、军队同属一种实体加 type（01 §2.4–2.5 结论），神与凡人同一结构加标记。卷一 §4.1 有"实体含群体、临时法人"，但没有明说"组织类型是维度而非结构"，也没有"人↔人、人↔实体、实体↔地点三张链接表"的对应。
   - 建议：在 §4.1 的 Holding 行补一句对应关系；这一层大体已覆盖，属小补。
4. **生成层的位置不清。** G2 靠 R-7，但 DF 的世界生成是"先模拟历史再落地"（实体与人物先有）。卷一分层图里没有"历史模拟 / 生成"的位置；它被放在卷十而不是层里，建议在 §2.7 或 §8 说明生成与历史属于第三层时钟规则的离线批量运行。

## 二、四个目标的机制与可检验

- G1：可检验（计数覆盖），但"五款 335 条每条有处置"过于数量化，是账本而非机制，需要卷零先成。通过。
- G2：R-7 + I41 机制清晰。缺口：没有"无限"的机制说明（分区块 / 种子 / 懒生成与离屏），仅提 I31；应指向卷二十七并写一句。有条件。
- G3：V-6 可检验，但 §12.3 把"一个物品类别、一种设施、一位神……"全部列为"自动获得行为"，**在没有 1、2 条所述修正机制与继承时，神、法术、怪物的行为只能靠写代码**，V-6 对这几类很难成立。神的行为尤其依赖 domain/sphere 推导，卷一没有写规则形状如何从领域词表推出神迹。
- G4：最强。I40、V-4、V-5 可检验。小问题：V-4 的"zh 与 en 哈希相同"要求规则可读状态里没有 name 参与的排序或 id 生成，应在 I40 补一句"id 生成不由显示字派生"。

## 三、局限吸取

- DF 行为写死：R-4、A-1、A-2、A-9 吸取良好；但 DF 的"枚举表全在代码里"（01 §3 第 4 条）对应项是 A-18，仅禁修正键，没有覆盖"职业、领域、价值"等枚举，维度表是否开放应显式写出（§4.4 的"代号"来自词表，但词表本身可否扩展未写）。
- CDDA iuse 写死物品 id：卷一只通过 A-1 泛禁，**没有给出"物品用法由数据声明效果"的替代机制**（即 use_action 由效果族表驱动）。§5.1 提到效果族表只在 AI 开放路径。必改：明确"效果"在物品、法术、设施上共用一个效果族表。
- 环世界 C# 专门类（ThingComp / Worker 类）：卷一无对应条文。第四层"领域各自写规则"在无通用效果机制时会重蹈覆辙。需要加一条 A-n：领域不得以自定义代码类承载内容行为，只能组合第三层四形状。
- EVE 的两套行为表示：A-19 吸取。

## 四、31 卷依赖图与 6 路并行

- 总体合理：波 1 到波 5 的理由成立。
- 问题 1：卷二既是规范又被六卷依赖，**卷二是单点瓶颈**，且依赖本卷尚缺的修正求值与继承规范。卷二必须先定稿再放行波 1；所以 6 路并行实际只能在卷二后开始，卷一 + 卷二 + 卷零是串行前置。写作计划应明说。
- 问题 2：图中卷二十（时间天气）放在波 1，但天气读地形（卷五）；卷二十六心理读身体（卷四）与人格，却也在波 1。应并行但标注"弱依赖，接口以编号小的为准"，已有 §11.2 末句兜底，可接受。
- 问题 3：卷七信仰在波 3，但信仰依赖卷五地点、卷六经济与卷十八社会关系；卷八政治依赖卷七（法律读信仰）。波 3 内部卷七 → 八 → 八b 是串链，不是并行。6 路并行在波 3 实际 7 卷含 3 卷链，需按链拆。
- 问题 4：卷十三战斗、卷十五法术读卷四身体，但伤害类型 / 材料属于卷三；这条依赖线图上有，OK。
- 问题 5：卷二十八扩展包依赖全部卷维度表，放在波 5 合理；但"包隔离 I21"可能影响格式，应提前到卷二。

## 五、过度设计 / 难以实现

1. §12.3 V-6 的八类一起测，在维度表尚未覆盖时代价过大；建议分阶段：每个阶段只测该阶段覆盖的表（§6.4 第 3 条已写，但 V-6 终值描述含"生成"等，冲突，需统一）。
2. I34 的"运行期对显示字挂只读 Proxy 记录读者"：性能与可行性存疑，建议降级为开发模式可选，扫描为唯一门禁。
3. R-6 的"零十进制常数，白名单 0/1 与换算"与 RX 表达式 DSL 内的常数如何界定，卷一没有给出界线；人格阈值、概率这类"规则表里的数"本质仍是魔数，只是搬了位置。建议要求常数必须有 source（卷一已要求）并抽检来源真实性，否则成为形式合规。
4. 43 条不变量一次进 CORE（V-8）实现成本高，建议按阶段分批（§9 已说"分批"，但 V-8 的终值是 43/43，需写阶段表）。
5. 扫描用正则识别"自然语言字面量"的误报：注释、日志、错误消息、测试夹具，需要白名单口径，卷一把细节推给卷十二，可接受。
6. R-2 要求规则代码"零中文字面量"，但允许理解层（06b 待定 1 的 74 行）存在——如何保证它们不被规则层 import，需要 import 图检查，卷一已写"扫描须核对"，但 I19 依赖方向的检查工具现状未写，建议确认。
