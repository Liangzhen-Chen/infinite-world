## 二、真问题

1. **卷九漏了一处到期项：开放提案的预览过期。** R9-4.3（卷九:737）写 `expiresAt = 此刻 + rules.open.previewMinutes`，“到期未确认即 `expired`”，§4.4.4（:745）也写明用了卷二十 §4.1 的“过期到期项”。这是一处到期项，新表没有给它 `due_kind` 行。另外两处可疑：R9-12.7 的“日程槽结束”调度 `npcChoose`，和执行器原语 `schedule`（:629，往到期堆里写）。正文没写这两处是不是到期项、各用什么种类，请编辑判定后补行，或者写明它们不是到期项。同一类问题卷十五也有：本组改了卷十五的 `rank`，但下面这些到期项都没有 `due_kind` 行：术式实例期满、强度归零（:395、:819）、供养到期（:456）、仪式集结时限（R15-7.2 :686）。卷十五 §2 只登了安葬、断祀两行。裁定第 11 条要求全书每个登记到期项的地方都有一行，这几处应该和本组一起补完。
2. **四种新到期项不在卷二十的 `rank` 分配表里。** 卷九四行的 `rank` 指向卷二十 §2.1 分配表（卷二十:151–188），但表里只有 250 号 `due.activity`。卷九修订行说“已交主会话”，可是收尾待办和待裁清单都没有记这件事。同样只在修订行里写了“已交主会话”、没有进台账的还有两项：卷二十一要求卷二十 `env.allowedTargets` 白名单加 `person.exposureMult`；卷十四要求卷二 §3.9 登记四个效果族。卷二、卷二十现在有另一位编辑在改，这三项请主会话交给他在本批落地，并记入台账。在落地之前，这些行的 `rank` 和 `allowedTargets` 都指向不存在的条目。
3. **从业和放弃从业两行的槽位指针装不进去。** 这两行的槽位写成 `vocab: "profession"`，但 `profession` 是卷二 §5.14 的数据表，不是词表族；卷九 §2.2 的 `code` 槽只认 `entityKind`、`vocab`、`recordKind` 三种指向（:184），过不了“`slots` 引用闭合”的校验。编辑已在待裁清单第五节疑点①报了这件事，但仍把它当作能装载的行写进了正文。设专注、取节点两行的槽位是 `lifestyle`、`perk`，这两个是词表族，没有问题。
4. **卷十四的四个效果族在现有格式下写不成行，卷九的动作行也过不了上限覆盖校验。**
   - 卷十四 §5.1:1253 写这四族“依次调本卷 `takeUp`…，所操作的职业、生活方式、节点取动作行唯一槽位的值”。可是效果族的输出只有五类（卷二 §3.9：modifier、status、primitive、event、spawn），`effectCall.params` 只收数值，原语目录又是封闭的（R9-2.1）。“族直接调写入口”和“槽位值传进族里”这两条通道现在都没有。这是待裁清单第五节疑点①所说的缺口，卷十四却按已成立的事写了，属于无据断言，和本卷第六节要修的那类问题同性质。
   - 卷九:206 的校验要求“每个 effectCall 的族都有至少一条 `cap_row` 或一条豁免行”，:395 E-ACT-CAP-MISSING 的定义也是按族判。卷十四说这四族参数为空，“R9-7.5 对空参数集无项可查”，只引了按参数判的 R9-7.5，没有处理按族判的这两处。两种写法下结论相反：按 :206 和 :395，参数为空的族一定报错。要么请李白定参数为空的族怎样过这道校验，要么把 :206、:395 改成服从 R9-7.5 这个定义处，后者也要经批准。
   - 以上第 3、4 条都要等李白对疑点①裁定后才能落地，期间应在卷十四 §5.1 和卷九 §2.2 注明“待裁、暂不可装载”，不要写成已成立。
5. **表 A 的 `cause` 取值域装不下这两个固定规则代号。** 卷二十四表 A:139 `cause` 的取值域是“已登记的动作代号、钩子或反应规则的登记代号”。`rule_static_history` 和 `rule_world_genesis` 都不属于这三类，两卷只写了“本卷登记的固定规则代号”，没说登记在哪个族或哪张表；可卷二十四 §2.3:239 却写了“表 A `cause` 栏可取”。最小修法：表 A:139 的取值域补一句，写明可取各卷经句柄登记的固定规则代号（卷二十四 `roles.causes.*`、卷十 `rules.gen.roles.genesisCause`），并写明这两个代号列在哪里。这是把裁定第 25 条落完整，不是新设计。
