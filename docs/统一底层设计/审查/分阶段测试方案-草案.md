## 3. 共同口径（各阶段都适用）

1. **作数的只有执行记录**。执行者回报里的读数只作参考；云上跑由主会话发起（R12-10.1、R11-5.11）。`accRun` 建成前，执行记录就是门禁 `run` 的 `/work/<dir>.full` 加内容哈希与两轮批准记录号。
2. **对照按子测名**。每次受影响或全量都与同机基线比对"文件×子测名×结论"；新增失败、超时、崩溃单跑复核一次，复核仍败才算真失败。同机同时跑基线与候选，或在机器空闲时跑；不与其他全量抢内存。
3. **不看通过数**。结论只写关口判定、新增失败清单、分量差（R12-10.6、R11-5.7）；汇报区分拟采用/已实施/已验证/已交付（R12-10.8）。
4. **`not_run` 与 `blocked` 算不过**（R12-10.7）。超时文件、浏览器测试、未启用测试台上的条目都要列名，不得省略。
5. **扩展性门"只加一行不改代码"**：按 R12-6.2 七步——记代码指纹 → 数据包加新行（id 新、各维度另取，不抄现成行）→ 加载校验 → 推进 → 按表头行为清单断言 → 再记指纹须相同（否则 E-ACC-EXT-CODE-CHANGED）→ 撤包重跑事件流与未加时相同；另加 R12-6.5 改值对照（驱动维度跨过阈值，行为按规则跟着变）。
6. **北极星对照**（"材料属性、职业技能、意图共同推出产物"）：凡涉及产物的表，扩展性条目必须同时含三种改值对照——只改材料一个维度、只改执行者技能档、只改意图代号，各自让产物按规则变化；任一种不变或靠 id 才变，即判该表未派生。
7. **花费估算**：费用 = 开机时长（h）× 开机当时的竞价单价（元/h）。单价本草案未查到记录，**每次开机前查当时单价**再算；同机并行的任务按时长分摊。估算 >5 元的点先报李白。全量一轮按历史 4–6 h 计，**单价超过约 1 元/h 时全量一轮即超 5 元**——下表凡含全量的格子都标"≥5 元待报"。
8. **耗时估法**：受影响集 = test-impact 选出的文件；时长 ≈ 各文件上次耗时之和 ÷ P，取长尾文件耗时为下限。全量按上次全量实测。

## 5. 实测："上下文反复压缩后仍按设计写好"

**目的**：证明执行会话在真实长任务里经过多次上下文压缩后，产出仍与卷文一致——不丢已定裁定、不重做已完成步骤、不越出卡片文件范围、不退回写死。判据全靠机器读数与独立对照，不采信执行者自述。

**两轮，先纸面后代码**：
- **第一轮（冻结中可做，作为解冻前提）**：载体用阶段甲的 **甲-4（卷六、卷七、卷八、卷八b）**——四卷行数多、卷六体量大，同一会话串行做完四卷，自然压缩概率高；它本来就要做，不另造任务。执行者 Opus（按排期草案）。
- **第二轮（阶段 0，验证代码类）**：载体 **G-1 五项扫描**，执行者 Sonnet（卷一 §6.3 指定）。

**压缩次数**：每轮至少 3 次。以会话记录里的压缩事件计数（主会话用会话管理工具读事件/导出记录检索压缩边界），不以执行者自报为准。自然压缩不足 3 次时，主会话在固定检查点手动触发：甲-4 在每完成一卷并提交后（共 3 个点）；G-1 在每完成一项扫描并提交后。手动触发方式需先确认会话通道支持（§6-7）。
