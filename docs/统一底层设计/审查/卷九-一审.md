### 乙、本卷自身的矛盾、机制漏洞与不确定

**T16 收工时 `workDone` 会超过 `workTotal`，与 A9-1.2 矛盾**（类别 5）
- 位置：R9-1.4（:432）、A9-1.2（:454）。
- 证据：`finishAt` 用 `ceil(need ÷ paceUnits)`，到期结清时 `acc` 会多出不到一个 `paceUnits`；节奏大于 1 时多出的部分可超过一个 `paceScale`。例：`workTotal = 2`、`paceUnits = 19000`、`paceScale = 10000`，`need = 20000`，`ceil(20000 ÷ 19000) = 2` 分钟，`acc = 38000`，`workDone = 3 > 2`。A9-1.2 断言"`workDone` 不超过 `workTotal`"不成立。
- 建议：到期结清时写明 `workDone = min(…, workTotal)`、余数清零（或收工即删记录不再写 `workDone`），并把断言改成与之一致。

**T17 节奏重算与中断检查的触发没有出处，且漏掉行动能力的变化**（类别 7）
- 位置：R9-1.4（:432）、R9-1.6（:434）。
- 证据：重算触发是"`process.workPace` 的依赖集里任一状态键被写入的那次事务提交"，卷二 §2.3 的依赖声明是静态核对与记忆用的，没有"写入即回调"的机制，卷九也没登记订阅。中断检查只在节奏重算与到期时做，而 `can(actor, capability)` 的依赖（昏迷、死亡、被捆）不一定在 `workPace` 的依赖集里：人昏过去后活动照算工、到期才被打断，工也不扣。这是整类绕过。
- 建议：写明触发机制（如在卷二 §2.3 的依赖闭包上登记一个提交后钩子），并把 `can()` 与 `interruptRX` 的依赖并入同一触发集合。

**T18 幂等键与事件 id 会撞**（类别 5、6）
- 位置：§2.9 末段（:338）、R9-3.8（:545）、R9-2.3"恰好产出一条事件"（:490）、R9-3.1 `aftermath`"各自以独立事务执行"（:537）、R9-7.6 反噬"经同一个执行器"（:697）、R9-6.4 多步（:654）。
- 证据：事件 id 只由（行动者、时刻、动作代号、主对象）派生。同一次结算的善后段（成长、事实、反噬）各是独立事务、各产事件，四项全同，id 相同；一次请求多步里在同一分钟买两次同一个卖主的东西，第二步即 E-ACT-DUPLICATE。卷二十七 R27-8.9 的派生成分是（世界种子、规则或指令代号、主体 id、世界时刻、固定位次代号）（卷二十七:665），卷九少了"规则或指令代号/位次"一段。§8 第 5 条只想到了对话，未覆盖这两处。
- 建议：按 R27-8.9 写：善后各事务用各自的登记代号作"规则代号"段；同刻同主体同动作多次提交，用触发它的上一条事件 id 作位次（R27-8.5 已给此法），不靠禁止。

**T19 有条件答应的换算用错权重，与效用式不一致**（类别 5）
- 位置：R9-12.4（:908）、R9-12.6（:910）、R9-13.4（:949）、例子 :925、:963。
- 证据：钱在效用式里按 `w.money` 计（:924 例子"东家倒贴 5 文"是 `−w.money × (−5)`），但所需预付按 `w.reward` 折算成钱；R9-13.4 又说出价差额"作为 `reward` 或 `cost.money`"二选一没定。:963 例子"差 30……还价要求再加 30"只有在 `w.reward` 与 `w.money` 恰好相等时才成立。
- 建议：预付是钱，统一按 `w.money` 折算（除数 `w.money × conditionalStep`，为 0 时 `refuse`）；R9-13.4 写定差额进 `cost.money`。

**T20 留痕用 `fact.set` 写，与 `fact.set` 的契约矛盾**（类别 5）

**T21 上限行与反噬取哪一行没写定**（类别 5）

## 四、§8 中涉及李白的四项设计取舍（只陈述利弊，不替李白定）

**§8 第 1 条 t3 改为 `judge`、`draft`，取消运行期"模型替 NPC 规划""模型写人物档"**
- 利：与卷一 §7.1 第 4 款"AI 不进入逻辑判断"、R-2 一致；人物档里影响规则的字段由规则按种子采样，复演与哈希不受模型影响（R9-14.8）。
- 弊：AI-00:88 现行 T3 = T2 + npcPlanning + profileDraft，玩家可见的档位说明要改；首次交谈的模型起草档案（AI-05:64，每新居民约 0.005–0.01 元）在运行期消失，只剩作者边 `draft`，运行期居民档的文字细节变少。

**§8 第 2 条 运行期不保留 AI 记录文字（删 `records.*.text`）**
- 利：textPaths 少四样登记、少一个 `record-text-gate.mjs`（卷二:776）；编年史一律是事件投影，两档下同构；存档哈希里少一类随模型变的内容。
- 弊：卷一 §7.1 第 5 款设想的"AI 文字是存档内容"在记录类上不再存在，编年、碑记只有模板文字，开 AI 时的风味只在当回合叙述里；删了以后若想恢复，要卷二重新登记。

**§8 第 7 条 选择式判断层的供应方与原文外发**
- 利：只出选择题，答案必在可表达集合 C 内（R9-17.1），不会产生集合外意图；AI-05:60 的现估 T1 Jev 每回合 0.0013–0.006 元，比主持模型选工具（0.09–0.14 元）低一到两个数量级。
- 弊：玩家原文要发给第三方供应方；计价口径、单题选项上限、把握阈值都还没有依据（待补第 5 条、第 7 条）；多一个供应方就多一套条款与可用性风险。

**§8 第 9 条 每次叙述都要过第二校验器（`narrate` 必须与 `validate` 同档），每次多一次请求**——费用估算
- 依据：
  - 价目：Anthropic 官方价目页 platform.claude.com/docs/en/about-claude/pricing（2026-11-13 读取）：Claude Haiku 5.5（提示不超过 10 万 token）输入 0.10、输出 0.50 美元每百万 token；Claude Sonnet 5.5 输入 2、输出 10；Claude Opus 5.5 输入 4、输出 20；缓存命中 Sonnet 5.5 为 0.10、Haiku 5.5 为 0.01。
  - 卷九没有写校验器用哪一档模型，也没有写它的输入输出量（R9-19.10 只说"读叙述文字与其中的实体标记，只输出裁定代号列表"）。以下是假设，须标定：校验器输入 = 校验指令约 1500 + 叙述正文与实体标记约 1000 + 登记名表片段约 500，合计约 3000 token；输出 = 裁定列表约 200 token。上限情形按 AI-05:24 现测"输入中位 2.4 万 token"（若校验器拿到与叙述同样的整份上下文）。
- 估算（不计重请；重请上限 1 次，`rules.gate.retryLimit`，最坏翻倍）：

| 校验器所用模型 | 每次（3000 入 / 200 出） | 每千次 | 每次（24000 入 / 200 出，上限情形） | 每千次 |
|---|---|---|---|---|
| Haiku 5.5 | 3000×0.10 + 200×0.50 = 400 微美元 ≈ 0.0004 美元 | 约 0.40 美元 | 24000×0.10 + 200×0.50 = 2500 微美元 ≈ 0.0025 美元 | 约 2.5 美元 |
| Sonnet 5.5 | 3000×2 + 200×10 = 8000 微美元 ≈ 0.008 美元 | 约 8 美元 | 24000×2 + 200×10 = 50000 微美元 ≈ 0.05 美元 | 约 50 美元 |
| Opus 5.5 | 3000×4 + 200×20 = 16000 微美元 ≈ 0.016 美元 | 约 16 美元 | 24000×4 + 200×20 = 100000 微美元 ≈ 0.10 美元 | 约 100 美元 |

  - 固定的 1500 token 校验指令若命中缓存，Sonnet 5.5 每次省 1500×(2−0.10) ≈ 2850 微美元，每千次约省 2.85 美元。
  - 作对照：若叙述本身也用 Sonnet 5.5，按卷九待补第 8 条的静态提示约 10500 token 加动态约 1000、输出约 800，叙述每次约 11500×2 + 800×10 = 31000 微美元 ≈ 0.031 美元；校验器（3000 入）约增加四分之一。
  - 另见：AI-05:32 记 PT-AI 配置 `config.example.json` 写 Sonnet 5.5"输入 3 / 输出 15 美元每百万 token"，与官方价目页现价（2 / 10）不符，配置里的价目口径需更新。
- 利：卷零:814 已定"开 AI 时由独立于叙述模型的第二个 AI 校验器读叙述"，未标记专名、未成年人情节、注入带偏这三类只有它能检出（R9-19.5 第⑤步），同档绑定保证开叙述就一定有这道检查。
- 弊：每回合多一次请求，费用见上表，延迟叠加（R9-14.4 两次超时串行）；校验器的拒收与审查不符共用一次重请额度，开 AI 时退回模板叙述的概率上升。
