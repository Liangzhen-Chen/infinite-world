# 卷十九 统计层建筑增减提案

提案者：Opus 5.5 中档。只写提案，不改任何卷正文与脚本。
依据：`收尾待办.md`「李白 11-14 statusRow 与卷二十七 §5 三条裁定」二③（卷十九统计层建筑增减时点本轮不批，另走提案）；卷二十七 §5 卷十九行占位（卷二十七:781）与 R27-2.10（卷二十七:378）；`审查/机制项-卷二十七卷二十八-只核.md` 第二、三节（:24、:31、:33）；`docs/产品原则.md` 一 2（玩家不在场时世界照样演化，规模不为省事而缩减）、二 1（派生优先）。

## 结论（先读）

1. **必需。** 现行规则下，未物化站点的设施数与床位只由第 0 日清单给出（卷十 R10-7.4 :626“清单一经写入不再改”，卷二十七 R27-2.10 :378），而统计层没有任何主体会盖房（卷六 §4.7 规则 11 的运行期投资 :627 只写给有名册的主体，卷十九 §4.4 的工程入口只收个人工时）。床位又是人口承载力恒参加取小的一项（卷八 R8-16.4 :1118）。结果：离屏聚落从开局起被开局床位封顶，卷八 §4.16.5 第二例“新开矿的山城成批迁入”在离屏时不可能发生。按“不现实即缺规律”，这里缺的是统计层的建造规律。
2. **只补“增”，不补按人口的“减”。** 人走了房子不会消失，只会空着、失修。建筑数减少只来自实物原因（拆除、翻修、损毁），卷十九已有这些规则。本提案不加“人口降了就减建筑”的规则（理由见 ①-3）。
3. **增建不另立判据。** 应有几座沿用卷十 R10-7.2 五处来源在“当下”的同式读数；卷十九只新增一个统计形态的建造执行器：立项、计工时、完工，走现有的工程入口与唯一写者。
4. **接口有两个候选，待李白选**：甲（经 `requireMaterialized`，R27-2.10 原样不动，推荐）；乙（统计层另存一份只追加的增建清单，须放宽 R27-2.10）。见 ④。

## ① 为何必需

1. **不定会怎样。**
   - 未物化站点的床位 = 清单经卷十九类型派生函数得出的计数（卷十 R10-3.10 :446，卷十 §5.3 :924 的 `genView`/`manifestOf` 读者行）。清单在第 0 日按开局人数折户数、每户一处（卷十 R10-7.2 ④ :619），所以开局床位约等于开局人数。
   - `popCapacity = min(各 support_k, 床位数)`，床位一项恒参加取小（卷八 R8-16.4 :1118）；`headroom = popCapacity − total`（R8-16.5 :1119）。统计层的出生照常发生（R8-16.3），床位不变，`headroom` 很快变负，流条目命中“余量为负”就迁出（R8-16.7）。迁入方也受同一上限约束。于是**离屏聚落的人口被钉在开局床位附近**；资源变富、工钱变高也长不大，只能把人推出去。
   - 单元内各站点人数按床位分摊（卷八 R8-16.1 :1110 第二款），床位不变，分摊比例就永远是开局的比例：离屏的城乡格局不会变。
   - 物化那一刻（观察锚来到）建出的仍是第 0 日清单（卷十 R10-3.8 :444、R10-7.8），即使离屏五十年。物化等价（R10-3.10）要求物化前后设施数相等，这本身没错，错在物化前的数从未随世界变化。
   - 卷十 §8 第 5 条（卷十:1066）与 C10-8（卷十:965）已经把这一项登记为未给出；卷二十七把它留给卷十九（:781）。不定，这个缺口一直留着。
2. **与 R27-2.10 的关系。** R27-2.10 说的是：统计层不改写清单、不另存“统计层建筑数”，要增减未物化站点下的建筑先调 `requireMaterialized`，然后经卷十九的写者写，与个体层同一路；“哪个系统在统计层增减建筑、何时增减，由该系统的矩阵行与其定义卷的规则定”（:378 末句）。也就是说，R27-2.10 只规定了**怎么增**（走物化），没有规定**谁、何时增**。本提案补的正是“谁、何时”。候选甲完全在 R27-2.10 之内；候选乙要放宽它的“不另存统计层建筑数”一句。
3. **为什么不补“按人口减”。**
   - 现实里人口下降留下空房，空房因无人维护而失修，最后倒塌或被拆。卷十九已经有这条链：劣化（§4.1 规则 6，卷十九:322）、维护不做则完好度下降（卷六 §4.19 规则 8）、缩减时不拆设施（卷六 §4.7 规则 11“缩减”款 :629）、拆除与翻修（卷十九 §4.4 规则 3 :501）。
   - 人口下降后空床多了，`headroom` 转正，会吸引迁入。这正是空城重新住满的路径。若按人口自动减建筑，这条路就断了，而且建筑数会变成人口的派生量，与守恒（墙料去哪了）冲突。
   - 遗留的一处：**从未物化过的开局建筑没有完好度**（建行时刻与劣化起点取物化那一天，卷十 R10-3.8 :444），离屏多年后物化出来仍是新房。这不属于“增减时点”，本提案不设计，只列入 ⑦ 记账。

## ③ 增减时点与判据（整类规则）

拟作卷十九 §4.4 新规则 10“统计形态的建造”与 §4.8 新规则（住处缺口来源）。规则文字不出现任何设施类型、文化、地区代号。

1. **在哪一层执行。** 个体层仍照现行规则：由有名册的主体决策（卷六 §4.7 规则 11 运行期款，卷九的 NPC 决策）。规则层与统计层（单元内聚合体不实体化，卷二十七 R27-1.5 :276–277）由新钩子 `settleStatBuild(unitId, span)` 执行，形态 `simform_stat`。
2. **何时执行。** 只在该单元有效层节拍的整拍边界执行（卷二十七 R27-1.6 :281），每拍一次。先后顺序按卷十一 R11-3.14 登记 `after`：排在卷八 `settlePopulation` 与卷六统计劳动力、统计生产的同拍结算之后。这样它读到的是本拍结算后的人数、余额与工钱。
3. **立项判据**（对单元内每个站点，站点按 id 升序；每个来源按 `demandSources` 登记序；同一来源内按（`intendedType` 代号，`ownerRef`）升序）：
   - 缺口 `g = needed − 现有座数`。现有座数 = 该站点类型等于 `intendedType` 的设施数（未物化时读清单的类型派生计数，已物化时数 `facilityView().type`），加上本站点同意图、尚未完工的统计层工程数。
   - `g ≥ statBuild.minGap` 才进入下一步。阈值只是数量，不读文字。
   - 出资方取来源给出的 `ownerRef`。`ownerRef` 是聚合体时用其聚合账户；是组织时用组织账户。出资方的可花余额（不含 `purpose_unmaterialized` 分区，卷六:356）不小于建造成本（卷六 §4.7 规则 11 同一成本式）才立项，否则本拍不立、不记欠账，下一拍重判。
   - 每立一项，`g` 减一，直到小于阈值或付不起为止。同一拍内后立项的读的是前一项入账后的余额，所以结果只取决于状态与上面的固定次序。
4. **住处来源**（首批来源中唯一需要新写的一条，归卷十九 §4.8）：单元缺床 = 单元内居民聚合体成员数之和 − 单元可用床位数（床位口径同卷八 R8-16.4）。缺床大于 0 时，按卷八 R8-16.10 的户规模 `size` 折成缺户数 `ceil(缺床 ÷ size)`（`size ≥ 1`，除数恒为正）。缺户落在哪个站点：取单元内满足卷十九 §4.4 规则 2 前状态的站点中，“非床位各项 `support_k` 的最小值 − 床位数”最大者（即床位最卡脖子的站点；并列取 id 小者）。`ownerRef` 取该站点上缺床最多的居民聚合体（并列取 id 小者），`intendedType` 取住处句柄（卷十 R10-7.2 ④ 同一句柄）。其余四处来源都已有现成读数，执行器直接读，不在本卷重算。
5. **工时与完工。** 立项即 `openBuildProject`，形制与用料由 `chooseForm`、`buildPlan` 按卷十 R10-7.3 生成期同一取法（技能读 `stratumSkill`，发起人取 `ownerRef`，可取料范围取所在单元的存量单元与出资方账户）。工程作为雇主进入招工清单，由卷六统计劳动力在阶层层面供工时（卷六 §4.11 规则 10），每拍 `contributeBuild` 的主体取出工的聚合体 id（先例见 ⑥）。累计工时达到 `laborMinutes` 时 `completeBuild`。料不够、工时不够就跨拍继续；出资方成员归零则照卷十九 §4.4 规则 7 停工，料留在备料账户。
6. **减。** 本规则不减。减只来自卷十九既有的拆除、翻修、损毁（①-3）。

## ④ 与卷十九现有统计层、实体层的接口

现状：卷十九没有统计层规则，也没有登记矩阵行（卷二十七 :300 的收件名单里没有卷十九；卷十七 :835 写“路网装置归卷十九的设施形态”，但卷十九未登记）。对未物化站点，卷十九只经卷十调用的类型派生函数与建行函数参与（卷十 R10-3.10 :446、卷十九 §4.4 规则 9 :527）。

**候选甲（推荐）：经 `requireMaterialized`，统计层不存任何建筑计数。**
- 立项那一笔里，若站点未物化，先调 `requireMaterialized(site, 建筑与房间阶段)`（递归带出分片阶段，卷十 R10-3.6）。理由：前状态（空余面积、处分权）要读分片行与已有建筑行，新行的 `parent` 也是分片行，这属于 R10-3.7 ②“要拿到其下某一行的 id”。居民安置、店铺阶段不请求。
- 此后与个体层同一路：工程、完工建行、砌入记账都走卷十九现有写者与卷六 §4.1 规则 5“新建”款，不改卷六。物化出的行不因离开个体层删除（卷十 R10-3.11）。
- 代价：
  1. 物化粒度是整个站点的建筑阶段。一处大站点的清单可达上万行（卷十 §8 第 13 条，卷十:1074），缺一栋房就要把全站点建出来，而且不可回收。`minGap` 用来减少零星触发，但长期增长的站点终会物化。
  2. 物化出的建筑行此后离屏仍要按卷十九 `settleFacilities` 逐栋结算（卷十九 :390 允许离屏折成闭式），离屏成本随“曾物化过的建筑数”增长，进入卷二十七 R27-3.1 的成本式（:420），会推动降档。
  3. 须在卷二十七登记一项上界（同 R27-3.9–3.11 :443–445 的登记位）：离屏已物化站点数 ≤ 曾触发统计层立项的站点数 + R10-3.7 其他触发数；标定时实测（R27-6.6）。
- 好处：R27-2.10、R10-7.4、卷六 §4.1 规则 5 一字不改；物化后的建筑有完好度、会失修，① 的“减”自然成立；空余面积的判定直接读行。

**候选乙：统计层另存一份只追加的增建清单。**
- 新增站点维度（拟名 `facility.addedManifest`，list<struct:manifestRow>，`ordinal` 接在 `gen.manifest` 之后连续编号，只追加，唯一写者 `construction.mjs`）。统计层完工时追加一行，不建行。物化时卷十的建筑阶段依次建清单行与增建行（R10-7.8 ②），类型派生计数读两份之和（R10-3.10 同口径）。
- 代价：
  1. 须放宽 R27-2.10“不另存统计层建筑数”一句（李白已批的口径）。
  2. 卷六 §4.1 规则 5 的“未物化建筑份额”现只有 `src_genesis` 一个来源（卷六:356）。第 0 日之后要再产生这种份额，须卷六另定一条成对转换路径（墙料转入 `purpose_unmaterialized`，份额以转换来源记入），属卷六的新设计。
  3. 卷十 R10-3.6、R10-7.8、R10-3.10、A10-7.2 跟改；空余面积判定要从两份清单派生占地；增建行同样没有完好度（与 ①-3 的遗留同病）。
- 好处：不触发整站物化，离屏只多存一行一栋，成本可控。

**推荐甲的理由**：甲不新增存储，不放宽已批规则，不动卷六账本；乙的好处只在性能，而性能可以由上界登记与标定实测（R27-6.6）先量出来。若标定显示甲的离屏建筑数超出预算，再报李白改乙。**待李白选。**

## ⑤ 确定性与折叠

- 判据不掷骰。全部次序取固定代号或 id 升序（站点 id、来源登记序、意图代号、`ownerRef`），同拍内顺序立项，结果只由状态与绝对时间决定。
- 只在整拍边界执行，结算区间不跨拍（R27-1.6）。推进请求怎样切分都不改变结果（R27-1.11），换层零头区间照 R27-8.6 :726 取区间起点。
- `chooseForm`、`buildPlan` 是纯读（卷十九 §3.2）；甲的物化是形制类阶段，只由（世界种子、地点）定（卷十 R10-3.8），所以同一拍先物化哪个站点，逐字节无关。
- 折叠：工程记录的键是工程，出资方是聚合体或组织，不是个体，不进任何个体的足迹，不造成钉住（卷二十七 R27-2.3、R27-2.4）。单元在立项后进入个体层：工程照常存在，由招工清单雇到的个体继续出工。离开个体层：未完工程按本规则继续，个体照 R27-2.5 折叠。
- 存档：`buildProject` 与备料账户本来就是存档内容；甲不新增存档项；乙新增增建清单一项，进存档摘要。

## ⑥ 同类先例（都是“统计层同式，主体换成聚合体”）

- 卷六 §4.7 规则 12（卷六:630）：统计层生产不另设公式，阶层按技能代表值调同一个 `craftOutcome`/`take`。
