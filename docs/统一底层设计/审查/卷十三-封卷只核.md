1. **16 行表 B 里有 7 行没写事件记录的 `actor`、`targets` 各取谁**（同一类缺口在卷二十四封卷只核第 2 条已判为真问题）。写了取法的有 9 行：damage（R13-1.11）、encounterClose（R13-18.8）、yielded（R13-18.6）、subdued（R13-18.12）、duelOver（R13-17.5）、routed（R13-8.8）、looted 与 burned（R13-12.9）、missionDone（R13-13.6）。没写的 7 行是：encounterOpen（R13-18.1）、battleOver（R13-11.7）、siegeFallen（R13-11.11、R13-11.17）、siegeLifted（R13-11.9）、held（R13-11.12）、warOver（R13-11.12）、meritNoted（R13-19.3）。这 7 行的 `headSlot` 都写 null，按卷二十四 R24-2.4，`heads` 要取 `actor` 与 `targets` 去重后的个数，所以求不出来，`eventSig` 跟着求不出；R24-2.7 的 `eventCount`、R24-8.2 的 `mentions` 也查不到这几类事件。本段自称写法照卷十八 §2.3，可卷十八 :187 的表有“角色栏”一列，卷二十四 :176 也有。

2. **溃散“每方每场只调一次”没有承载状态**。R13-8.8 规定“只在首次判定成立时调用一次”，A13-8.2 断言“至多一次”，但 `noteRout` 写明“不写状态”，遭遇记录与会战记录的 `sides` 里也没有已溃散标记。R13-8.3 里的“不能行动”会变回能行动，人数会反复越线；遭遇也能经 `attack` 从 `breaking` 回到 `engaged`。实现时只能自己造一个隐藏状态。改法：两种记录的 `sides` 各加 `routed: boolean`，由判定系统在调用 `noteRout` 的同一事务里写，类型与写者照 §2.4；或者给出无状态的判据。小改。

4. **场外任务的完成项与卷二十四 R24-9.2 冲突；`degree` 为 null 时整类委托永远不能认定（核点④）**。
