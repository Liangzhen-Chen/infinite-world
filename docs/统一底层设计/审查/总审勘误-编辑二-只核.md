## 三、问题清单

### 真问题（须改）

**问题 1　卷五:623　取食量的千克折算没有走已有的唯一口径，并且重复乘了可食份额**
- 原文：`按 c 的可食产物每千克对 s 的实得饱腹折成千克（每千克总饱腹取卷三乙 satietyTotal ÷ massKg，实得比例取卷四 edibleShareOf 给的吸收率；为 0 时该项取 0）`
- 为什么：
  1. 卷二十五 §4.11.3 规则 6（卷二十五:724）已经单点写定"折算只有一个口径"：干重 × 饱腹值（每千克干重的总能，卷二 §1.4）× 卷四 `edibleShareOf` 给出的可食各份及其吸收率。卷二十五 §4.5 规则 2（:481）和卷二十一 §4.4 也照这个口径算。编辑者另起了一条 `satietyTotal` 路线。
  2. `satietyTotal` 的定义（卷三乙:1661）是 `massKg × Σ可食份额 × edibleFraction × (1−moisture) × energyDensity`。其中的可食份额和 `edibleFraction` 是卷三的人食组件口径，`energyDensity` 只对 `comp_edible` 的类必填（卷二:1487，见卷四 Q-21）。再乘卷四的物种可食份额和吸收率，可食份额就算了两遍；秸秆、茎叶这类不挂 `comp_edible` 的产物还会落成缺口。
  3. `edibleShareOf` 返回的是按份的列表 `parts[{massShare, assimilation}]`，原文"给的吸收率"没说多份时取哪一个，单位链在多份时没有闭合。
- 单位本身是闭合的：`groupNeeds.food` 的单位是 satiety_per_day，除以每千克实得 satiety，得到千克每日。
- 建议改法：把这一句改成只引卷二十五 §4.11.3 规则 6 的口径，即每千克实得饱腹 = Σ_parts（`massShare × assimilation ×（1 − moisture）× energyDensity`），读的是该份材料的有效值；这个和为 0 或有缺口时，该项取 0 或带缺口，不再读 `satietyTotal`。

**问题 2　卷五:623　"占比"可能大于 1，取食量可能超过日需要**
- 原文：`占比 = s 的在田 c 一份 ÷ 容量(s)`；卷五:614 写的是 `容量(s) = 初级消费项 + 捕食项，同样乘覆盖系数`。
- 为什么：分母乘了覆盖系数，分子"在田 c 一份"没有乘。覆盖系数小于 1、s 又主要靠作物为生时，占比大于 1，`取食量(s,c)` 就超过 `需要千克`。这违反卷二十五 A25-3.2（:428）"不超过该取食者当日的需要"。
- 建议改法：让分子分母同口径。例如占比 = 在田 c 一份 ÷（初级消费项 + 捕食项），都取乘覆盖系数之前的值，分母为 0 时取 0；或者分子也乘覆盖系数。再在 A5-7.2 补一条断言"占比在 [0, 1] 内"。

**问题 3　卷五:623　合计按 min 封了顶，但各取食者各转多少没有定义**
- 原文：`当日取食损耗 = min(可及千克数, Σ_s 取食量(s, c))`……`同日几种取食者可分几笔转出，合计与一笔转出相同`
- 为什么：卷二十五 A25-3.2 要求一对"取食者吃在田作物"的关系每日一笔转移，且这一笔不超过该取食者的需要。所以要逐个取食者转出，但封顶以后各取食者分到多少，卷五没有写；实现可以随意分配，结果依赖实现。
- 建议改法：写明各取食者一笔 = 按卷二 §3.3 第 3 条，把封顶后的合计按 `取食量(s, c)` 的比例分摊给各取食者（没封顶时就是 `取食量(s, c)` 本身）。分摊的次序按物种代号的字典序固定。

**问题 4　卷五:612–614、:623　"c 的可食产物"在一种植物有几个可食部位时不唯一**
- 原文：`edibleBy(s, c 的可食产物)（可食部位按卷二十五植物行 ediblePart）`；`按 c 的可食产物每千克……`
- 为什么：`ediblePart` 是一个集合（卷二十五:106），每个部位各有一种产物；但 `cropForage` 只按植物给一个总千克数（卷二十五:230）。`edibleBy` 和每千克实得饱腹在多部位时没有唯一的输入，问题 1 的公式也就没有单一产物可读。
- 建议改法：二选一，并由主会话定。(i) 卷五按（植物, 部位）分项，`edibleBy` 和折算都逐部位做；这需要卷二十五让 `cropForage` 按部位给可及千克数，是卷二十五的配合项。(ii) 卷五写明多个部位时可及千克数按什么规则分到各部位（例如按各部位现存量的比例），这一步须引用已有维度，不许另设常数。

**问题 5　卷五:1051（§5 卷四行）、卷五:1069（§5 卷二十五行）　跨卷接口表没有补新接口**
- 原文：卷四行只写了 `speciesView`、`bodyView`、尸体入口；卷二十五行只写了生长函数、`clearCultivation`、`take`。
- 为什么：正文现在调用卷四的 `edibleBy`、`edibleShareOf`、`groupNeeds`，读卷二十五的 `cropForage`，并向卷二十五的 `agri.mjs` 发带"取食"代号的损耗转移事件，§5 两行都没有反映。卷二十五:795 的反向行已经写了 `cropForage`，两边不对称。
- 建议改法：卷四行补"调 `edibleBy`、`edibleShareOf`、`groupNeeds`（§4.7 规则 2、3 的在田一份与取食损耗）"。卷二十五行补"读 `cropForage`；`settleStocks` 转出取食损耗并发损耗转移事件（原因代号：取食），由 `agri.mjs` 订阅后分到各记录"。

**问题 6　卷四:75（§0.6 第 7 条）　括号里仍是封闭名单，与 §4.5.1"不列名单"矛盾**
- 原文：`凡声明可遗传的维度（外貌轴、属性、成年体重）用同一个式子……`
- 为什么：§4.5.1 现在写的是"按维度声明，本节不列名单"，并且已经把 `aptitudes` 声明为可遗传。结论条里仍是三项名单，读者会以为天资不可遗传。这属于根本口径，不能记账留后。
- 建议改法：改为"凡在维度声明里标'可遗传'的维度（如外貌轴、属性、成年体重、天资；见 §4.5.1）用同一个式子……"。

**问题 7　卷四:994（G-4）　母语可能对应几行技能，`native` 只能带一项**
- 原文：`对技能表中标为语言且语言等于 nativeLanguage 的技能行，以 seedSkills 的 native 参数给出初始熟练度……随 P-4 那一次 seedSkills 调用写入`
- 为什么：卷十四 SK-8（:713）、:160 规定一门语言分口头和读写两侧（字段 `written`），所以同一语言的技能行通常不止一行。而 `native` 的形状是单个 `{skill, score}`（卷十四:467），又只许调用一次，条文选出几行时写不进去。另外，照原文读写一侧也会拿到母语熟练度，等于人人识字，与卷十四"识字 = `written` 为真的技能读数"的设计相冲。这正是本裁定要并入的那次调用，属于本裁定范围。
- 建议改法：G-4 把选行条件收窄为"`isLanguage` 为真、`language` 等于 `nativeLanguage`、`written` 为假的那一行"；这样的行不存在时不给 `native`。同时请卷十四加一条加载校验："同一 `language` 下 `written` 为假的行至多一条"（卷十四配合）。如果主会话认为母语确实应当覆盖多行，就请卷十四把 `native` 改成列表；两条路选一条。
