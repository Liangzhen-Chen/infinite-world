## 二、新增内容的问题

### 必改

**N1 L-3 与 L-0 自相矛盾（卷一:100、103、167）。** L-0 规定每层只读下层；L-3 却让第二层 view 去"调用第三层派生规则取值"（卷一:167），又说"读 engine.rules 或 derived() 的函数属第三层"（卷一:103）。按卷一自己的判据，写了派生值的 view 属于第三层，第二层就没有 view 了。卷二的 `View.dims` 给修正后值（卷二:312）同样要调求值管线。需要二选一：把"带派生的读"明确放第三层的"组合读"，第二层只留字段查找；或承认第二层可调用第三层的求值管线（一条受限的向上调用，写进 L-0 例外）。

**N2 §3A.2 求值管线没有可验收的唯一定义。** 管线顺序写了，但与卷二逐项不同（见 C1–C3），I44 要求"阶段顺序固定"却有两份不同的固定顺序。同时卷一:418 把"材质/品质乘子"与"组件与状态容器修正"列为独立阶段，没有说它们在引擎里怎样被识别为阶段；卷二里它们只是 mul 修正（卷二:463）。

**N3 §3A.1 属性/效果模型无法落成卷二格式。** 卷一:411–413 要求属性行带 `default`，卷二:182 明令"任何常量缺省都不合法"；卷一效果"不含数字，读源属性"，卷二修正项直接带 `value`（卷二:373）。V-18、I44 的"绕过管线 = 0"在两种模型下含义不同。

**N4 §3A.4 状态容器字段与卷二不一致，且谓词来源冲突（卷一:430–431、168；卷二:247、441）。** 卷一说档里有 `threshold/capacity/awake/duration`，谓词读这些机器字段；卷二档里是 `minSeverity/lifeThreatening`，`capacity/canAct` 读 `bodyView().dims.<capability>` 与 `rules.capacity` 阈值，档里没有 capacity/awake/mode。这直接决定 118 处状态列表怎样退役。

**N5 §8.3 哈希字段集有缺口（卷一:687–692）。** ① 卷二有 `state.displayNames[id]={text,lang}`（卷二:215）与 `npcs.*.name`（卷二:338），都在 state 内但不属于 narration/names/labels/provenance/clientPrefs 五层中的明确一层；"保留在哈希内：state 全部数值与代号字段"这个说法没有机器口径去区分哪些字段是显示字。② 卷一:535 的排除表与卷二 `state-owners.json` 的 `display:true` 集合是两份数据，未规定谁生成谁（应由 state-owners 的 display 集合生成排除表，或在 I40 测试里断言两者相等）。③ 玩家自由命名文字进不进哈希没有定：进则 V-4 在两语言下玩家输入不同时不可比；不进则要明列。

**N6 卡拆分规则内部矛盾（卷一:629–640）。** ① §6.5 的账本卡要在一张卡内把 coins 22 模块、treasury 8 模块、stock 槽及全部读者改完（卷一:631），§6.6 却限定"一张卡改动文件 ≤ 25"（卷一:640），并规定只能按消费者组拆分（卷一:637）。账本卡必然超限，却是"唯一责任卡"，没有例外条款。② §6.6 说"首卡 = schema 上线 + 全部行补齐 + 第一个消费者组改造"（卷一:639），又说"数据补齐可按数据文件拆，校验器必填在全部行补齐后才进 CORE"（卷一:638）；486 件物品、25 文件上限与"首卡全部行补齐"相撞，且"可拆"与"首卡全补齐"互相否定。③ 卡名 `L1-账本单一写入` 与 L-1（两端论）、L1/L2/L4（内容审批级）重名，易混。

**N7 阶段退出硬上限不可无歧义判定（卷一:619）。** "n ≠ 5 时按 k/n 线性插值取上限"没有给出插值的端点与函数（给定 0.6、0.35、0.15、0.05、0 并不是线性序列）。需给出一条公式，例如 `上限(k) = B0 × max(0, 1 − k/n·系数)` 或直接规定"按 k 取最近较严一档"。另外 B0 的 tools 与中文枚举两个分量在 G-3 前没有数值，P1 的硬上限在那之前不可算（流程上 G-3 先于 P1 已保证，但应写明"G-3 未完成不得开 P1"）。

**N8 G-1/G-2 位置冲突（卷一:601–606；卷二:471）。** 卷一限定 G-1"不碰 server-plugin"，G-2 校验器在卷二里是 `server-plugin/dimensions-validate.mjs`；冻结期只许 G-1…G-3（卷一:644），G-2 如何落地没有交代文件范围。

## 三、卷一与卷二一致性（重点）

定义方判定原则：卷一定契约与词汇，卷二定文件格式与求值细节。卷一 §3A 自己写了"卷二 §2–§6 落成格式与求值器"（卷一:407），所以**求值管线、修正项格式、维度类型、文件格式以卷二为定义方，卷一应引用不重定义**；而卷一 §3A 把管线、状态容器、属性元数据全都写成了具体格式，造成两卷各定义一遍且不同。
