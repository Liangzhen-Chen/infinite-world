## 重点核

### ① "aesthetic 聚合 none" 是不是裸 none 空值：不是

- 卷三乙 :551 写的 `none` 是聚合口径代号，属于代码内封闭枚举 `agg_mode`（:534 写明"值不带前缀"），意思是"不聚合，只逐份读"（:544 定义行）。它是一个口径，不是"空值"。按卷二 §1.9（:236、:240），代码内封闭枚举的值本来就不带前缀。这一行原来就列了 `salvageFraction` 等 8 个维度，本批只是把 `aesthetic` 加进同一格。
- 李白 11-14 B 条要管的是"取值为空"的位置该填什么（先例：卷二 §2.9 第 0 条的 `nil_seedpart`，卷二 :836、:2499，它替换的是卷二十七骰值键里当空值用的裸字符串 `none`）。这里 `none` 不当空值用，所以不在 B 条范围内。B 条原文在仓库里没找到，这一判定按派单里的转述（"空值一律用带前缀固定空代号"）做出。
- 脚本：check-卷三 :77 PASS（聚合口径表覆盖 §2.1 的 43 个 number/map/struct/分态字段，缺 0，`aesthetic` 已包括在内）；:215 PASS（M-10 的 none 口径）。

### ② check-divisor 报的卷三乙 :569：误报，不是新引入的无下界除数

- :569 在 §4.1.2，是一句指引："除数是参加部件的质量之和，下界与为 0 时的处置在 M-22"。这句本身不做除法。脚本按"按部件质量加权"这个写法把它算成了隐式分母（脚本也把它归进"不在三扫真命中里"的那类）。
- 真正做除法的地方是 M-22（:583）。脚本没有报它，复核下界也成立：除数是参加部件的 `massKg` 之和；`massKg` 的取值域是 (0,100000]，下限不含 0，等于 0 时加载就失败（§2.2 :155）；所以只要有参加的部件，除数就大于 0。没有参加的部件（没装件、全部不适用、传入的是模板或批次）时，M-22 写明不做除法，返回"不适用"。口径还沿用了 `hmean` 等现有的除数保护（:538–:542 已判已修）。
- 结论：这一批没有引入新的无下界除数，:569 应列为误报。

## 小项（记账，不阻断）
