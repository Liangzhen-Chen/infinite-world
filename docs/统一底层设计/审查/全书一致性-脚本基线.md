## 各脚本的判据

### check-dupnames（A 类：重名）

按 `审查/卷十九-同类清单.md` 的"脚本可核的判据 · A 类"写。只认定义点，不认引用。

抽哪些定义点：
1. **入口**：标题含"统一入口"的章节（各卷 §3、各子系统 `4.x.2`、卷二"二 统一入口"）里，表头含"入口"（不含"旧入口"）或为"函数/出口"那一列的反引号名字，一格里有几个就取几个，签名列按 ` / ` 对齐；同区以 `` - `名字(`` 起首的列表项；同区正文里写成 `` `名字(参数) → 返回` `` 的签名；任何地方写"定义 `名字(…)`"或"`名字(…)` 的定义"的；卷二 §2.7 代码块里 `"文件.mjs#名字"` 形式的登记（kernelApi、groupApi、view、predicates）。
2. **维度与表字段**：§2 里表头首格为"维度/字段/键"的表，首列反引号名字；所属表取最近小标题里"xxx 表"的 xxx，没有就取标题里第一个反引号名字；记类型列、单位列。
3. **词表族与代码内封闭枚举**：表头首格以"族"开头的表的首列族名与前缀；正文里 `族名 → \`前缀_\``；含"代码内封闭"的句子里 `` `名`（值…） ``；族表里某行注明"代码内封闭枚举"的，该行首列的名字全按封闭枚举取。
4. **错误码**：表首列的 `E-…`、`W-…`（破折号后须是字母，所以 §6 扩展性测试的 E-1 不算）。
5. **扫描码与规则码**：§3、§4 表首列的 `字母[数字]-数字`，以及 `- **代号` 起首的规则条（§6 除外）。
6. **规则表键**：§2 里标题含"规则表"的小节中的 `rules.<ns>.<key>`，以及"文件 + 键"表（文件名加小标题里的 `world/rules/…` 目录）。

排除为引用：附录、附表、术语表、迁移与退役清单、开放问题、"本卷使用"、记账栏、影响面表、牵连清单、修改记录、自检与核算输出、JSON 代码块（卷二 §2.7 登记除外）；表格里名字列之外的格含"见卷X / 卷X已定 / 归卷X / 本卷不定义 / 引用"或"卷X §n 给定/定义/登记"的整行。

判定：
- 入口：两卷都有定义即列。抽到的签名参数个数（去掉 `engine`、`state`，带"?/可空/可选/省略"的算可选）不同，或两处都写了返回而不同，判"重名"；否则判"重复定义"（提示级，应改成一处定义一处引用）。
- 签名：定义过的入口在**别卷**正文里以 `` `名字(实参)` `` 出现，实参个数不在定义允许的范围内，判"签名不一"。空括号和带省略号的不算。
- 维度：同一张表上同名而类型或单位不同判"冲突"，相同判"重复定义"；不同表上同名而类型不同判"低级提示"。任一处写"不存在名为 `X`"而 X 出现在维度定义里，判"违反禁令"（本次 0 处）。
- 族与封闭枚举共用一个命名空间：两卷都有定义即列；一边是族一边是封闭枚举、或值集不同，判"重名"，否则"重复定义"。不同族用同一前缀判"前缀冲突"。
- 错误码：两卷都有定义即列（本次 0 处）。
- 代号：不带卷号的裸代号（如 `B-2`）在两卷出现为定义判"裸代号跨卷"；同一代号在同卷两个小节都作定义判"同卷两节定义"。
- 规则表键：两卷都有定义即列（本次 0 处）。

可能误报或漏报：
- 卷二 §2.1 的 22 类实体入口清单与各领域卷的入口表天然重叠，`bodyView`、`placeView` 等 10 个入口都会列为"重复定义"。其中 `capacity`（卷二谓词 vs 卷五资源容量）同卷十九同类清单 A2 判的是真冲突，但卷五没写返回，只能落到提示级；它另在"签名不一"里因卷四的三参调用被抓到。同样，`transfer`（卷二 kernel 导出 vs 卷六入口）须人工看是不是同一个函数。
- 族与卷二 §1.9 首批前缀全表重复（36 处）多是"卷二首批登记 + 领域卷自己登记"的现行写法；`consent_mode` 在卷十八只列名、值在附表，脚本取不到值集，比不出卷二与卷十八值不同（同类清单 A4），落到了提示级。
- 裸代号跨卷 78 处里，卷三与卷四的 A/B/C/D/G/K/M/P 系列成批同号，是现行编号习惯；按判据都算冲突，要不要改编号由李白定。
- 卷十八 §3.6 的规则摘要表与 §4 规则条同号（6 处），可能只是摘要复述，按判据报出。
- 卷十四 §2.8"RX 可读变量"表首格也是"字段"，会被当作表字段，造成 `contract`、`holder`、`place`、`origin` 等低级提示。
- 定义写在纯正文（不在表格、不是列表项起首、不带"定义"字样）的不会被抽到。

### check-exemptrefs（B 类：悬空的排除与豁免）

按同一份清单"B 类"的第 1、2、3、5 条和"§7 第 n 行"写。

匹配：以句号、分号或表格单元为界的一句，含"排除｜豁免｜白名单｜例外｜除外｜不扫｜不参加扫描｜不算旁路｜不在本条范围｜闭集"之一。附录、记账、影响面、迁移、开放问题等排除区里的不看。
抽依据项并比对：
1. **卷节引用** `卷X §n.n`（不写卷名的 `§n.n` 算本卷）：卷文件不存在，判"登记位未落地（该卷未成卷）"；节号在该卷标题里找不到，判"节悬空"。
2. **紧跟引用的登记项**：引用之后最多 80 字、到下一个"卷X / §n / 本卷"为止的反引号名字（标识符、文件名、路径、`rules.` 键；错误码与扫描码不算），到被引节里找（按词边界、不算引用句本身）：节内有、且不在请求句（"请卷X增设/回填"、开放问题）里，判"找到"；节内只在请求句里，判"登记未落地"；节内没有但同卷别处有，判"节号不符（小项）"；全卷都没有，判"悬空"。只写"卷X"不带节号的，在该卷全卷里找。
3. **名单里的文件名**（反引号里的 `.mjs`、`.json`，不含通配）：须在某卷 §3、标题含"写者/入口/登记/声明/白名单/出口/能力对象/文件/闭集/组"的小节，或卷二 §2.7、§2.9 里出现，否则判"文件未登记"。
4. **"按文件名登记"的名单**：冒号后以顿号分隔的名单项，不带反引号又含汉字的，判"名单含角色描述"。
5. **"卷X §n … 登记为Y的模块/文件/函数"**：Y 须在被引节出现，否则判"悬空（被引节无此角色字段）"。
6. **"§7 第 n 行"**：被引节里须有首格为 n 的表行，否则判"行号悬空"。

未实现：清单第 4 条"同一对象两份读者/写者白名单不相容"（如卷三 P-7 与 P-10），第 6 条里"依据为某登记表的某字段、但字段名没写成反引号"的情形（如卷六 S6-12 的"族字段"、S6-14 的单位）。这两类仍须人工核。

可能误报或漏报：
- 80 字窗口里的反引号名字不一定是"被依据的登记项"，可能只是同句里顺带提到的名字（如卷一 V-2 的 `error.message`、卷六 S6-13 的 `post`）。
- 文件名按字面找，同名不同路径（`input/normalize.mjs` 与 `server-plugin/input/normalize.mjs`）各算一次；登记处若只写目录通配也找不到。
- "节号不符"多是引用写了上级节号、实物在相邻小节，属小项。
- 被引卷未成卷的（卷七、八、九、十二、二十八）在成卷前一直报。

### check-replypath（存档类路径与菜单回合可达）

依据 `审查/卷一卷二-同类清单.md` 的 A 类与 C 类。清单 C 类没给脚本判据，这里按 C 类表头的做法（逐一核对卷二 §2.7 `kernelApi`、`groupApi`、`assembly.calls` 与 §2.9 第 0 条的路由、能力对象、回应通道各环）写成机判。

甲、存档类路径：
1. **路径未接回应通道**：一行（列表项连同缩进更深的续行算一个单元）含"存档/读档/快照"，又含玩家可见的动作迹象（玩家、菜单、请求、路由、入口、出口、拒、失败、报错、`E-SAVE`/`E-SEAL`/`E-LOAD`、下载、写盘、槽位；"推进请求"不算），而同一单元里既没有回应通道的记号（`ReplyResult`、`postReply`、回应通道、`ReplyCap`、`onReply`、`reply-composer`、`ReplyHandle`、`save_export`、"§2.9 第 0 条"、"存档四路"），也没有写明是内部或离线动作（内部、离线、不回应、tests、tools、夹具、测试场景、按事件数、不变量、断言、复演、验收、扫描式、计数为 0），即报。单独的"导出/导入"不作触发词（多指模块导出）。扫描表行、卷二第 0 条自己的路由表、六环表、能力对象表不报。
2. **存档类错误码无回应去处**：码名以 `E-SAVE/E-SEAL/E-LOAD/E-SNAP` 开头、或定义行提到存档、读档、导入、导出的错误码，定义行里没写 `ReplyResult`、回应、拒收代号、玩家，即报。
3. **能力对象持有者不在回应通道**：能力对象表里拿到 `ReplyCap` 的文件，须是六环表里调 `ReplyCap` 的 `send` 的一方；拿到 `RequestCap` 的文件，须是第 1 环的入口（同类清单 A-1 的抓法；本次 0 处，卷二已改）。
4. **存档路由发出方不在回应通道**、**只有导出没有导入**（同类清单 A-6 的抓法；本次 0 处，卷二已加 `save_import`）。

乙、菜单回合可达（不开 AI、只点选）：
1. 起点：六环表里除 `input` 路由那一支以外的全部文件（`menu-entry.mjs`、`reply-channel.mjs`、`router-caps.mjs`、`reply-composer.mjs`、`envelope-exit.mjs` 等）及其所在组；kernel 活动则规则层活动（kernel 经登记钩子回调）；客户端组都算活动。
2. 逐个看 kernelApi、groupApi 的导出：kernel 自己的导出组内可调；`callers` 含 `*`、或含活动组、或 `callerFiles` 里有活动文件（或活动组里的文件，aiGate、inputEdge 除外），算可达，并把它所在的文件和组标为活动，反复到不再变化。只由装配文件在 `init` 调的挂接函数算可达但不激活其组。
3. 另看 `textWriters` 的写者文件、能力对象表里服务端接收方。
4. 走不到的分三种：调用方全在 inputEdge（只处理带键入文字的 `input` 路由）的，判"本来不该在菜单回合出现"，不计；调用方全在 aiGate 的，判"同根"，随 aiGate 对外入口一起出现，不单计；说明里与叙述、对白、文字记录有关的，判"AI 输出类缺通路"（开着 AI 只点选、或删掉输入边时无调用链），计入命中；其余判"缺通路"，计入命中。
5. 凡写"经 `menu` 路由上报错误码"的，`menu` 上行载荷的说明里须有错误码字段（本次 0 处，卷二已补）。
6. 卷二写了"没有输入边时带 `slot_kind:text` 的动作不进菜单"，那么任何地方说"删掉/拔掉输入边后全部动作仍可经菜单到达"而不写"除起名、手记/文字槽位"的，判"说法过宽"。

可能误报或漏报：
- 甲 1 是按字面同现判断的。"存档"在不少地方指"存进 state 的东西"（如卷一 235、卷二 596 讲文字入库），不是玩家的存档动作，会误报；一个动作若在别段才写回应方式，本段也会被报。按卷看，卷二十七 14 处、卷二 12 处、卷一 8 处，人工看时先看这三卷。
