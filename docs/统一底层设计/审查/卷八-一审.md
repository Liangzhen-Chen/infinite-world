## 真问题（28 条）

### T1　改写卷二已定维度的名与类型（需改已封卷）
- 位置：§2.1–§2.3（L119–L186）；§5.2 卷二行（L1179）。
- 类别：4
- 证据：卷二 §5 开头：“本卷定格式、公共字段与首批字段表；各卷只加行、不改已定维度的名/单位/类型”。本卷改动不只是加行：改名 `salaryTable→salary`、`taxRules→taxes`、`levyRule→levy`；改类型 `charter: rx → struct`、`levyRule: rx → struct`、`taxRules` 的 `rate: fraction → rateBps: integer`、`to: ref office → payee: enum`；改必填 `org.seat` always→nullable、`office.jurisdictionLevel`/`office.succession` always→nullable；`org.offices` 由存储改为 derived；`office.appointedBy` 由 `refs[kind office, vocab election]` 收窄为只指职位。卷二 §6.7 写的迁移去向（`taxRules.to` 接贡金去处）也随之失效。
- 建议：能沿用卷二名字的一律沿用（`salaryTable`、`taxRules`、`levyRule`）；确需改类型或必填的（`charter` 结构化、`seat` 可空以容无地政体、税项结构、`offices` 派生、`appointedBy` 收窄）逐项列成补订单报李白，由卷二补订后本卷再对齐；在此之前 §2 不得自称“以本节为准”。

### T2　任职边“互斥”与多席、共治、代理、摄政冲突；本卷内部也自相矛盾（需改已封卷）
- 位置：§2.2 `seats`（L152）；R8-2.3（L516）；R8-2.10（L523）；R8-9.1、R8-9.3、R8-9.5（L766–L770）；A8-2.2（L540）；A8-9.2（L786）。
- 类别：4、5
- 证据：卷十八 L465 `hk_holds_office` 的 `exclusive` 为 true（同一标的至多一条现役边），R18-1.5 规定新边成立前旧边须先离任。于是 `seats` 大于 1 的职位、R8-9.1 共治都写不进去；R8-2.10 任职者丧失行动能力时另立 `acting` 边、R8-9.3 幼主在任时另立摄政边，都会把原任职者挤下去，与 R8-9.5“原任职者自该刻起恢复生效”矛盾。本卷内部：R8-2.3 与 A8-2.2 要求现役任职边数不超过 `seats`，而 `seats` 为 1 的职位在摄政期同时有幼主边与摄政边，断言必然失败。
- 建议：卷十八该行改 `exclusive: false`，用该表已有的 `capacityKey` 指向 `office.seats`（报李白改已封卷）；代理与摄政改为本卷向卷十八新登记的一种独立持有种类（不占席位、`functional` 为真），`hasPower` 同时读两种边；A8-2.2 改为“正任边数不超过 `seats`”。

### T3　居民聚合种类行与卷二十七、卷十八、卷二冲突（需改已封卷）
- 位置：R8-16.1（L1022）、R8-16.7（L1028）、R8-16.8（L1029）；§5.3 JSON `aggKindRow`（L1227）。
- 类别：4、1
- 证据：
  1. 卷二十七 R27-1.1、R27-2.1：聚合体 id 由（种类、**模拟单元**、分组键）决定，单元是政区级的隐含键。本行 `keyHoldings` 为空，同一单元内各站点的居民落在同一个聚合体里，`popView(place)` 按站点计数、`state.popRem[placeId]`、站点之间的迁徙、站点承载力都无从表达。卷二十七 §4.2.5 第 1 例用“居住类”作 `keyHoldings`，但卷十八 L454 `hk_resides` 的 `pins` 为 `pside_none`，依卷十八 L128 不得进 `keyHoldings`。
  2. `keyDims` 取物种、文化、信仰、职业。卷二 §5.5：`faith` 是经 `devotee_of` 派生，`profession` 是经 `practices` 派生的 **set**。分组键须是单值的已登记维度（卷二十七 R27-2.8）；而且成员身上的信奉边、执业边按 R27-2.3 第 2 项计入足迹，不在 `keyHoldings` 就把每个成员钉住，统计层无法折叠；`hk_devotee_of` 同样是 `pside_none`。
  3. 统计层出生的新成员按什么键入哪个聚合体（孩子带不带父母的职业键）未写。
- 建议：按站点分组须让卷十八给 `hk_resides`（及信奉、执业）开 `pins` 资格并列入 `keyHoldings`，这要改已封卷十八，报李白；或者本卷改为“人口统计层的最细粒度是模拟单元”，站点级人数改由个体层与卷十的布局派生，这会牵动 R8-16 全节，须先定方向。职业键改为单值的“主业”维度或去掉。

### T4　`popView` 在个体层重复计数
- 位置：R8-16.1（L1022）；A8-16.2（L1048）。
- 类别：5、4
- 证据：卷二十七 R27-2.6：实体化“只建立基本行”，被实体化的成员**仍留在成员区间里**。本卷 `total = 常住个体数 + 各聚合体成员数`，个体层每个实体化居民数了两次；A8-16.2 把这个式子写成了不变量。
- 建议：改为“不在任何成员区间里的常住个体数 + 各聚合体成员区间长度之和”，与卷二十七 A27-2.3 同口径。

### T5　迁徙余数的键与计算粒度不一致
- 位置：R8-16.7（L1028）；§2.5 L228；§2.7 L293；§3.3 去留表 L427。
- 类别：5、6
- 证据：R8-16.7 对“每个地点、每个居民聚合体”分别算 `acc = rem + 成员数 × rateNumerator`，余数却存 `state.popRem[placeId][flowRow]`。一地有多个聚合体时共用一个余数，结果取决于遍历顺序，切片不变断言也不成立。
- 建议：键改为 `[aggregateId][flowRow]`；去留表相应改动（聚合体不删除，去留处理同 `vitalRem`）。

### T6　统计层减员按年龄段算数、却在全体成员里均匀抽人
- 位置：R8-16.3（L1024）。
- 类别：7
- 证据：减员数是各年龄段“人数 × 该段死亡率”之和，但抽人是在整张有序成员表上按骰值键抽位置，不分年龄段。老人死亡率高、青壮低这一事实在抽人这一步被抹平，统计层的年龄结构会持续偏离个体层，卷二十七 R27-1.9 的层间一致性比较必然越过容差。生育一侧同理（可生育段的人数决定增员数，但不影响谁“生”）。
- 建议：按年龄段分别结转：余数键加年龄段代号（段的边界取规则表的相对年龄刻度，由 `bornMinute` 现算），每段只在本段成员里抽。

### T7　去向分配的余数总给 id 最大的候选
- 位置：R8-16.8（L1029）；数据实例 L1041。
- 类别：7
- 证据：前几份 `floor(out × score_j ÷ Σscore)`、末份取差，候选按地点 id 升序。每拍每个聚合体的 `out` 通常只有个位数，余下的人全归 id 最大的那个候选；本卷自己的例子就是评分 30 的候选得 0 人、评分 10 的得 1 人。迁徙去向实际由地点 id 序决定，评分失效。
- 建议：改用卷二 §3.3 第 3 条的“按顺序照累计量分摊”，按（来源、流行）累计已迁人数，各目的地按评分配额排成一列；或按评分作权重用骰值键逐人抽，键登记在卷二十七。

### T8　迁徙评分的权重与单位没有出处
- 位置：R8-16.6（L1027）；§2.4 `popflow`（L214）。
- 类别：1、2
- 证据：“路程项”“隔阂项”没有权重、曲线或规则表键，行程钟点、接纳度怎样换成评分单位没写；各分量单位不同（人、score、钱），只靠 `destWeights` 线性相加；`destWeights` 挂在流条目上，而个体迁居决策（卷九）调同一函数时没有流条目可取，权重从哪来不明。“权重也不计入”在不做归一化的和式里没有含义。
- 建议：规则表加 `pop.migration.scoreWeights` 与路程、隔阂两条曲线（输出同一评分单位）；流条目只决定迁出量；个体与统计层共用这一组权重。

### T10　余数分母不是规则表键，且不能保证固定
- 位置：§2.7（L291–L294）；R8-11.5、R8-16.7、R8-19.3。
- 类别：4
- 证据：卷二 §1.2 `.remDenominator`：“正整数的规则表键（rules.<卷>.<键>）……分母登记只有这一处”；§3.3 第 5 条：分母在存续期内固定，改分母只许取整数倍。本卷税额余数写“固定 10000”，人流余数取流条目的 `rateDenominator`，影响力余数取来源条目的 `denominator`。词表条目可被内容包改写，没有整数倍校验，也不是规则表键。
- 建议：三个余数各登记一个分母规则表键（如 `rules.polity.tax.remDenominator`）；条目只给分子，分母不足的按整数倍换算到表键分母。

### T11　征管漏损在余数结转之前多了一次整除
- 位置：R8-11.9（L845），配合 R8-11.5（L841）。
- 类别：7、4
- 证据：先算“核到税基 = 真实税基 × (10000 − leak) ÷ 10000”，再进 `acc = rem + base × rate`。一个增量式里有两次整除，违反卷二 §3.3 第 5 条“只许有这一次整除”；按期核定的小税基每期都被先截一次，持续偏低，余数救不回来。
- 建议：并成一式：`acc = rem + 真实税基 × (10000 − leak) × rate`，分母取 10⁸（登记为规则表键），只整除一次。

### T12　贡赋按基点乘入账额，每期截断、无余数
- 位置：R8-10.2（L802）。
- 类别：7
- 证据：每期贡赋 = 贡赋基点 × 下级该期税收入账 ÷ 10000，逐期向下截断，误差始终朝一个方向累积，与税额的余数结转口径不一致（卷二 §3.3 第 5 条）。
- 建议：贡赋义务的数额式按第 5 条带余数结转，余数键（契约、期）登记在 §2.5、§2.7；或改为在封建契约上冻结一个整数分子、分母，由卷六的义务结算按第 5 条结转（需与卷六确认）。

### T13　类型写法违反卷二 §1.5（整数键 map、内联枚举、未登记的枚举族）
