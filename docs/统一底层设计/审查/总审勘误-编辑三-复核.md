## 五 问题清单

**A.【真问题，同类残留】卷十五 :669 R15-7.1**
- 原文：“所施条目给收尾时的检定、各成功度的效果与反噬（经 `castShape`）”。
- 为什么：这一句仍说反噬由 `castShape` 按所施条目给，与 :343、R15-1.9（:435）、李白 20:13 ①（反噬不取自槽位）直接相抵。上轮第二节第 1 项已经点到 R15-7.1，本批没有清掉。
- 建议改法：改为“所施条目给收尾时的检定与各成功度的效果（经 `castShape`）；反噬取动作行 `backlash` 的固定列表（R15-1.9）”，并在本卷 1114zs5 勘误行补记这一处。

**B.【同类残留】卷九 :1423 乙表 P7 ①**
- 原文：“`castShape` 登记返回形状按 R9-1.13 的键名补 `backlash` 与 `degreeBps`（现返回无这两键…）”。
- 为什么：这是卷九仍挂着的对卷十五的请求。李白 20:13 ①已经把 `backlash` 一项否掉，`degreeBps` 和其余键卷十五也已登记，这条请求的状态过时了，读者会以为卷十五还欠一个 `backlash` 键。
- 建议改法：在 P7 末尾补状态句：“`backlash` 一项按李白 11-14 20:13 ①不采纳（卷十五施法行 `backlash` 写固定列表，R15-1.9）；`degreeBps` 与 R9-1.13 其余键已由卷十五 §3.1 登记”，并记进本卷 1114zs5 勘误行。:194、:533 保留 `backlash | from_slot` 这个通用选项不算矛盾，因为那是通用机制、现在没有行用它，不必改。

**C.【须改：另立了一个结构名登记处】卷二 :645 §2.7 第 1 点**
- 原文：“为 `shape` 时写本卷已登记的结构名，现登记两个：`requirement_block`（§1.13 需求块）、`effect_call_list`（§3.9 …`list<effectCall>`），增结构名须改本卷”。
- 为什么：卷二 :199 已经规定命名结构的登记处是 §1.5 的“命名 struct 登记”表，并写明“新增命名 struct 须在此登记并说明定义处”，而且 :212 已登了 `struct:effectCall`（定义处 §3.9）。§2.7 又自开一张结构名清单，造成两处登记，其中 `effect_call_list` 与 `struct:effectCall` 是同一个结构；不合“一个概念只在一处写全”。本批的卷二检查脚本输出也把 `requirement_`、`effect_` 报为未登记前缀。裁定说的是“卷二已登记结构名”，按 :199，就应当指 §1.5。
- 建议改法：§1.5 命名 struct 表补一行 `struct:requirementBlock`（定义处 §1.13）；§2.7 第 1 点改为“为 `shape` 时写 §1.5 命名 struct 登记里的结构，单个写 `struct:<名>`，列表写 `list<struct:<名>>`”，删掉“现登记两个……增结构名须改本卷”；第 3 点的加载核对随改；卷九 R9-1.13 末句、卷十五 :330、:331 两行的 `refFamily` 随改为 `struct:requirementBlock`、`list<struct:effectCall>`。如果李白认为 §2.7 的清单就是他说的“已登记”，就只需在 §1.5 表末注一句“`shape` 行结构名另见 §2.7”，说明两处的分工。

**D.【措辞，记账，不阻塞】卷十五 :905 R15-12.8**
- 原文：“易手出处读这条边自身的开边事件，不另存”。
- 为什么：卷十八的持有边没有存开边事件的 id（`holding_terms` 只有 `since` 等，全卷没有“开边事件”这个说法），规则也不得读可修剪的事件日志，所以“读”没有现成的读法。目前没有规则读这个出处，不影响执行。
- 建议：改为“易手出处即开立这条边的那条持有变化事件（卷十八 R18-1.11），本卷不另存”。下次勘误卷十五时一并改。
