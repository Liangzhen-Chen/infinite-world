## 四、整类判据缺陷（交主会话处理，不逐条手改档）

- **缺陷甲：撤回或否定没有排除**（B1、B12），涉及判据 3 的 R1 与 R3。
  - R1 只看名称格里有没有这个标识符，不看同一行是否写着"已删去"一类的撤回说明，所以入口表里保留的删除行会被认作登记。
  - R3 只看登记动词是否出现在标识符之前，不识别"没有…""不存在"一类的否定，所以否定句会被认作登记。
  - 后果：凡是撤回后在入口表或断言里留下删除说明的代号，都会被归入 A 或 B。这样不会漏掉真缺失，但会把撤回项算成"已登记"。
- **缺陷乙：签名里的参数名被认作名称**（B10），涉及判据 1 的"不带反引号的同名 ASCII 整词"与 R1 名称格的组合。
  - 入口表首列是函数签名时，`engine`、`state`、`ctx` 这类参数名都会被当成"该格含有这个标识符"。
  - 后果：扫描抽出的普通参数名会被归入 A 或 B。
- **缺陷丙：动词在标识符之后的定义写法被漏认**，影响召回率。证据是 B4 偏到 B，以及 C 档第二节列出的 17 条已登记。
  - 修订三把 R3 收紧为"动词必须在标识符之前"，于是"在 `systems.<名>.x` 登记：{…}"这种动词在后的写法认不出来。
  - 另有几种定义写法 R1 到 R4 都不覆盖：JSON 自登记、"固定空码 `x`（…）："、花括号里的结构字段、行内"`enum x`（代码内封闭：…）"、"受控原语 `x(…)`"、"入口：`x(…)`"、§5 里的"本卷登记的…"二级标题。
  - 后果：条目从 A 偏到 B，或从 A、B 偏到 C、D，不会产生假的"已登记"，但 C、D 档里会有一部分其实已有定义。

按李白规则：A、B 两档的抽查都没有真缺失，A 档整档定性"已登记"。B 档因缺陷甲、乙出现误分，"已登记"中混有噪声或撤回项，比例约 20%，但不需要补登记的这个结论不受影响。是否要修判据甲、乙、丙后重跑，由主会话决定。
