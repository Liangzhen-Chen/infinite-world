## 压缩边界标记与计数命令（只读）

- 标记：记录中一行含 `"subtype":"compact_boundary"`。这一行带 `compactMetadata`，里面有 trigger、preTokens 和保留段的 headUuid、anchorUuid、tailUuid。
- 计数：`grep -c '"subtype":"compact_boundary"' <子会话记录路径>`
- 分段：每次压缩把会话切成一段。段 k 等于第 k 个边界到第 k+1 个边界之间的工具调用。用各边界行的 `timestamp` 与 `uuid`，对照各提交时间，划分各段改动。
- O1 判法：在每个边界行之后、第一次 Edit 或 Write 之前，记录里要依次出现三份文件的读取：`审查/甲4-设计要点表.md`、`F:/dnd/AGENTS.md`、`docs/PLAN.md` 当前步骤。

## 风险（报李白）

- 压缩阈值约 97.6 万 token。要累计 3 次压缩，单个会话的上下文增长总量约需 300 万 token。按以往大编辑会话 40 万到 50 万 token 的读数估，甲-4 四卷加甲-6 末批加阶段乙纸面卡，未必能满 3 次。届时按裁定第四条第 4 项停报，不判通过。
