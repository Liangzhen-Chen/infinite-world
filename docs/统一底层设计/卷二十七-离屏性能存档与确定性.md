## §1 领域总述

### 1.1 真实世界怎样运转

1. **世界不因没人看而停。** 远处的庄稼照样成熟，远处的人照样生老病死、欠债还钱。观察者不在场，改变的只是他知道多少，不是事情发不发生。
2. **远处的事只以总量为人所知。** 一个人对邻村知道张三李四，对邻省只知道“今年歉收、人口约几万”。总量由个体加总得到，不是另一套规律。所以粗算必须是细算的加总，两者不许各走各的规律。
3. **守恒不分远近。** 钱、粮、人不会因为离得远就凭空多出或消失。
4. **同因同果，但结果是分布。** 同样的起点、同样的偶然，结局相同；换一组偶然，结局在一个合理范围内散开。个别不合常理的结果可以有，整体分布不许偏。
5. **记录是发生过的事的账。** 一本只往后写、不涂改的流水账，加上隔一段时间盘一次的存量，就能回到任何一次盘点之后的任何时刻。

### 1.3 进程归属（待卷二收口后对齐）

本卷按下列划分写，卷二收口后若写法不同，以卷二为准，本卷只改引用：

- **Node 服务端进程**：权威状态、推进、聚合、成本判定、存档读写、复演，全部在这里（kernel 组与规则层）。
- **浏览器扩展进程**：只有 display 组与 host 组文件（卷二 §2.7）；不持有权威数据（卷一 L-9）；不向规则层提供时钟、随机数或任何熵；跨进程只经卷二 §2.9 第 1 条登记的入口与出口传代号结构和已筛查文字。
- 由此得出本卷三条约束：① 扩展重载或断线后只重取投影，服务端状态与存档摘要不变；② 性能预算分两段记账，本卷只管服务端一段（§4.6）；③ 同一条玩家指令重复送达不得结算两次（§8 开放问题 1）。

## §4 子系统

### 4.1 三层模拟运行矩阵

#### 4.1.1 维度

`unitAdminLevel`、`individualMaxHops`、`ruleMaxHops`、`ruleSharedAncestorLevel`、`globalUnitTier`、`cadenceMinutes`、`matrix`、`observables`、`driftTolerance`、`driftToleranceDefault`、`driftStat`、`seedSampleSize`；状态 `simProgress.<unit>.through`。

#### 4.1.2 统一入口

`simUnitOf`、`baseTierOf`、`simTierOf`、`advancePlan`；写者 `sim-advance.mjs`。

#### 4.1.3 规则

- **R27-1.1 模拟单元**：每个主体属于恰一个模拟单元（`simUnitOf`）。
  - 有地点的主体取其地点的单元。地点的单元 = 包含树上第一个行政层级等于 `unitAdminLevel` 的祖先。
  - 没有这样的祖先时（荒野、海域、秘境这类不属于该级政区的地点），不取根：从该地点向上走，停在第一个行政层级高于 `unitAdminLevel` 的祖先或根之前，取停下之前的最后一个节点作单元（它可以是地点自身）。所以互不相连的无政区区域各是各的单元，不会并成一个。
  - 没有地点的主体（组织、信仰、神祇、账户一类）归**全局单元**。全局单元不参与跳数计算，它的层固定取 `globalUnitTier`，不随观察锚变。
  - 单元邻接只读卷五 §4.14 规则 2 的 `placeView().neighbors`（两个单元相邻，当且仅当存在一条边连接两者的后代），本卷不自定义，也不再读手写的邻接清单。该判据对无政区单元同样有定义；请卷五确认同一入口对它们给出结果（§8 第 11 条）。
- **R27-1.2 观察锚**：观察锚 = 状态里登记为玩家控制的实体所在的单元集合，经该登记的定义卷提供的 view 读取。它与输入边无关：输入边整体拔除、只用菜单时（卷一 §2.10），锚照样存在；复演时也能从状态得到。锚可以有多个；状态里没有玩家控制的实体时（无人值守）锚为空集。
- **R27-1.3 层的判定分两步**：
  - **基础层**（`baseTierOf`，纯函数，只读拓扑、观察锚与规则表）：设 h = 单元到最近观察锚的跳数，不连通或没有锚记为无穷大。h ≤ `individualMaxHops` 为个体层；否则 h ≤ `ruleMaxHops`，或 `ruleSharedAncestorLevel` 非空且与某个锚在该级有共同祖先，为规则层；其余为统计层。
  - **有效层**（`simTierOf`）：同一判定，但两个半径与共同祖先条件取“表值按状态里的 `simDegrade.level` 套用降级阶梯之后”的值（R27-3.4）。锚所在单元恒为个体层，降级不得改变这一点。
  - 钉住（R27-2.4）、折叠（R27-2.5）、推进计划、层序值、他卷读层，读的都是有效层。基础层只用于解释和断言 A27-1.2。
- **R27-1.4 层不落盘**：有效层随时由 R27-1.3 从状态算出，不写进状态，也不写到任何实体身上。落盘的只有每个单元的 `through` 和全局的 `simDegrade`。因为档位在状态里，读档或复演时任何时刻的有效层都能原样重算。
- **R27-1.5 运行矩阵**：每个系统对每一层声明一个形态。
  - `simform_individual`：逐实体行、按到期项结算。只在个体层合法（个体层单元的聚合成员全部实体化，R27-2.6）。
  - `simform_batch`：逐主体行、按该层节拍结算。主体可以是实体，也可以是地点、地块、设施这类非人口主体。该单元里的聚合体不实体化，按同一系统的统计形态规则结算。
  - `simform_stat`：逐聚合体或逐单元、按该层节拍结算，只读写人数、聚合账户与聚合维度。
  - `simform_derived`：该系统在该层的量是时刻的纯函数，由（种子、单元、时刻）算出，不结算、不留状态（例如卷二十的天气）。它三层相同。
  - `simform_frozen`：不随时间变，只由事件行改动；仅当该系统在该层没有登记任何时钟形状的规则时合法。
  - 校验：形态与该系统登记的规则不相容即 E-SIM-FORM-INVALID；主体类出现在聚合种类表里的系统，在规则层与统计层必须有统计形态的规则；新系统不声明矩阵行即加载失败。卷二十 §5.3 各行所用的说法与本族的对应见 §5。
- **R27-1.6 节拍桶对齐**：粗形态（批量、统计）的结算区间永不跨越绝对时间的整拍边界，桶号 = 时刻整除节拍（卷二十 §4.1 的钩子若带相位偏移，边界相应平移，仍是绝对时间的函数）。
  - 平常的一次推进只结算**完整的桶**：区间 [`through`, 下一个整拍边界) 走完才结算，`through` 只停在边界上。推进请求的终点落在桶中间时，这半个桶不结算，留给以后的推进。
  - 规则按传入的区间时长 `spanMinutes` 结算；完整的桶时长等于节拍。只有换层时才会出现不满一拍的区间（R27-1.7）。
  - 因此“在哪里停下、分几次走”不影响任何一个桶的结算内容。
- **R27-1.7 换层协议**：单元的有效层发生变化有两个来源，处理不同。
  - **观察锚变动引起**（可以发生在任何时刻 t）：① 追赶在改锚的提案之前、在同一事务内执行，读的是改锚之前的状态，“原来的形态”就是用改锚前的锚和状态里的档位算出的有效层所对应的形态；② 由粗变细：先按原来的粗形态结算完整的桶到 t 之前最后一个整拍边界，再对零头区间 [该边界, t) 按原来的粗形态结算一次，`spanMinutes` 取零头长度，然后 `through` = t，再实体化（R27-2.6）、换细形态；③ 由细变粗：单元按细形态已算到 t，`through` = t，折叠（R27-2.5），之后粗形态的第一个区间是 [t, 下一个整拍边界)，`spanMinutes` 取这段长度，此后回到完整的桶；④ 零头区间内的抽取，键里的时刻取区间起点（R27-8.6）。这样 [整拍边界, t) 和 [t, 下一个整拍边界) 各恰好结算一次，既无缺口也无重叠。没人看的那段时间按粗形态算，这是既定事实，不回头重算。
  - **档位重评引起**：只发生在评档块边界（R27-3.3）。块长是最粗一层节拍的整数倍，所以这一刻所有单元都正好在整拍边界上，没有零头；先按旧档位把各单元结算到该边界，再写新档位，再折叠或实体化。
  - 锚变动是世界里发生的事（由玩家指令或规则的提案引起），评档边界是绝对时间，两者都与“这一次推进请求从哪到哪”无关。
- **R27-1.8 钉住个体不随层变粗**：统计层或规则层单元里被钉住的个体（§4.2）仍按个体形态结算，结算时刻取自身最早到期项。
- **R27-1.9 层间一致性**：同一系统的粗形态必须是细形态的加总——守恒量逐笔守恒（经账本，卷六 §4.1）；`observables` 列出的可观测量按下面的办法比较：取 `seedSampleSize` 组世界种子，同一单元分别强制按个体层与统计层推进同样时长，各得一组样本；按 `driftStat` 指定的统计量算两组样本之差（`ds_mean_ratio`：两组均值之比减 1 的绝对值，以个体层一组的均值为分母；两组均值都为 0 时不做除法，漂移取 0；只有分母为 0 时不做除法，按超出容差判；`ds_ks`：两样本 KS 统计量），不得超过该维度的 `driftTolerance`。超出即判为“缺规律”，修在该系统的规则层，不许调容差掩盖（调容差须李白批）。
- **R27-1.10 推进计划怎样到调度器**：`advancePlan` 在规则层，调度器在内核，内核不 import 规则层，也不读规则表。数据这样流动：服务端装配文件（`index.mjs`）对每个评档块调 `advancePlan` 取得计划，把它作为参数交给内核的推进入口；计划里每个单元只带整数——层序值（`simtier` 的序值）、步长分钟、要结算的区间。块内若有提案改变了观察锚，换层协议在该事务内完成后，调度器结束当前计划段并向装配文件返回“计划失效”代号，由装配文件重新取计划；内核自己不判层。
- **R27-1.11 推进结果与推进路径无关**：从同一状态出发、其间的玩家指令相同，世界推进到同一时刻的结果只取决于状态与时刻，不取决于推进请求怎样切分、每次请求多长、请求属于哪一类、在哪一刻存过盘读过档。本卷为此立三条约束，任何后续修改不得破坏：① 档位只在绝对时间的评档块边界由状态算出并存入状态（R27-3.2、R27-3.3）；② 粗形态的结算区间只由整拍边界和换层时刻界定（R27-1.6、R27-1.7）；③ 折叠与实体化的时机只由整拍边界、换层时刻和规则的写入决定（R27-2.5、R27-2.6）。

#### 4.1.6 验收断言

- **A27-1.1（扫描式）**：S27-1 命中数为 0；规则层与内核中行政层级族条目的字面量为 0，层判定只经 `simTierOf` 与 `baseTierOf`；内核对规则层的 import 为 0。
- **A27-1.2（不变量式）**：对任意状态，`baseTierOf` 只依赖拓扑、观察锚与规则表——同一状态调用两次结果相同，改动任何非锚实体不改变任何单元的基础层。`simTierOf` 只比它多依赖 `simDegrade.level`——档位不变时，改动任何非锚实体不改变任何单元的有效层。
- **A27-1.3（验收测试，分段无关；交卷十二机器化）**：从同一存档出发、不夹玩家指令，把世界推进 N 分钟。分别取：一次推进 N 分钟；按任意切分分 k 次推进合计 N 分钟；每次换用不同的推进类别标签；中途在任意切点存盘再读档。各种走法结束时的**排除日志分区后的世界状态摘要两两相等**（定义见 R27-4.1；各走法的推进请求日志条数与类别标签本就不同，所以不比存档摘要）。测试取遍基准场景表的每一行，N 至少覆盖跨一个评档块边界、终点落在桶中间这两种情形。测试在不开文字模型的档位下跑；开着文字模型时改用卷一 V-13 的口径（事件流与 textPaths 之外的状态逐值相等）。
- **A27-1.4（不变量式，层间一致）**：R27-1.9 的基准对矩阵里每个声明了 `observables` 的系统都通过。
- **A27-1.5（扩展性式）**：新增一个系统，只加系统声明行与矩阵行，不改 `sim-tiers.mjs` 与 `sim-advance.mjs`，A27-1.2 至 A27-1.4 仍通过。
- **A27-1.6（扩展性式）**：换一张拓扑完全不同的世界（非西陲、含不连通区域与无政区地点），不改任何代码与规则表，A27-1.2、A27-1.3 通过；互不相连的两块无政区区域属于不同单元。
- **A27-1.7（不变量式，换层不缺不重）**：在任意时刻 t 让观察锚进入或离开一个单元，对该单元每个声明了粗形态的系统，结算区间首尾相接地覆盖全程——没有哪一分钟被结算两次或漏掉（按结算记录的区间核对）；由粗变细、由细变粗两个方向各测。
- **A27-1.8（验收测试，档位与请求无关；交卷十二机器化）**：`costPlan` 的签名里没有请求参数（扫描）；同一状态下发出长度不同、类别标签不同的推进请求，到达同一时刻后 `simDegrade` 两个字段相同；两次评档之间 `simDegrade` 不变。

### 4.2 聚合变体、等价、钉住

#### 4.2.1 维度

聚合种类表字段 `aggKind`、`subjectKind`、`keyDims`、`keyHoldings`、`pooledResources`、`shareRule`、`shareDist`；状态 `aggregates.<aggregate>.{kind, unit, key, members, nextOrdinal}`。

#### 4.2.2 统一入口

`pinned`、`aggregateView`；写者 `aggregate.mjs`；三个动作 `fold`（折叠）、`materialize`（实体化）、`settleOut`（分户）都以一条事件加原语列表提交。足迹经内核的反向索引导出读取（向卷二 §2.7 kernelApi 登记，见 §5）。

#### 4.2.3 规则

- **R27-2.1 聚合变体是什么**：一个聚合体代表若干个“没有个人历史”的同类个体。它只存所在单元、分组键、成员区间和下一个序号；人数 = 成员区间长度之和，是派生量。
  - **聚合体 id**：由（聚合种类, 所在单元, 分组键取值）经卷二 §1.10 的派生函数确定性得出，在种子键登记表里登记为 `role_id` 的一行。同一组键永远得到同一个 id。
  - **聚合体一经建立不删除**：成员区间可以为空，`nextOrdinal` 保留。这样同一组键不会“删了重建”而把序号从头再发一遍，成员身份不会撞。
  - 每个聚合体有一个**自身来源键**，由聚合体 id 派生，用作在它名下出生的成员的 `origin`。
- **R27-2.2 成员身份**：每个成员由（来源种子键, 序号）唯一标识，终身不变。个体的实例 id 由这一对按卷十的实例 id 导出规则确定性得到；个体的各采样维度由卷二 §1.10 的采样函数从实例 id 算出，不落盘；出生时刻取所在成员区间的 `bornMinute`，为空时由采样得出；实体化时按分组键写入的维度（如卷二 §5.5 `culture`，聚合体成员实体化取分组键中的文化），由成员身份所属聚合体的分组键重算，现值与之相等的属基本行、不计入足迹（R27-2.3），不能由此重算的照常计入。分组键里经 `keyHoldings` 种类派生的维度（如卷二 §5.5 `faith` 经信奉边），实体化时在同一事务里按该维键值开该种持有边（键值为空则不开），边的条款（`terms`，如 `since`、`origin`）只由成员身份确定性重算；条款等于重算值的这类边与基本行同等对待、不计入足迹（R27-2.3），条款不同的边或多出来的边照常计入。所以同一个成员无论被实体化多少次，都是同一个 id、同一组属性。
  - **出生取得成员身份**：凡实体类出现在聚合种类表里的个体，不论在哪一层出生，出生时都从其分组键对应的聚合体（没有就建立）取 `nextOrdinal`，身份为（该聚合体的自身来源键, 序号），出生时刻记为 `bornMinute`。统计层的出生时刻取所在结算区间的起点。
  - **没有成员身份的个体**（世界数据里手写的、id 不由上述规则导出的）不可折叠，恒为钉住，原因代号 `pin_identity`。
- **R27-2.3 等价**：一个个体与聚合体中的一个成员等价，当且仅当它有成员身份且**足迹为空**。先定义**基本行**：该个体的实体行里，pathTypes（卷二 §2.7）标为“可由成员身份重算”的字段，并且现值等于按 R27-2.2 重算出的值。基本行有哪些字段只由 pathTypes 的这个标记决定，不手写清单（标记的登记见 §5）。足迹 = 下列各项的并集：
  1. 状态中以该 id 为路径段的全部路径，**基本行和聚合机制自身的路径除外**；以及任何以引用类型指向该 id 的路径（按 pathTypes 判定）。实体行里没有上述标记的字段、或有标记但现值与重算值不同的字段，都计入足迹；
  2. 以该 id 为端点的未结束持有边，种类在 `keyHoldings` 内且与分组键一致的除外；
  3. 引用该 id 的未了结义务；
  4. 到期堆中以该 id 为对象的条目；
  5. 该 id 名下余额非零的账户，资源在 `pooledResources` 内的除外。
  足迹由内核维护的反向索引得出；索引是投影，可随时丢弃重建，不落盘。
- **R27-2.4 钉住**：`pinned` 为真，当且仅当足迹非空，或没有成员身份，或该实体是玩家控制的实体，或它所在单元的有效层是个体层。`reasons` 给出命中的类别代号，只用于解释；任何代码不得按原因代号分支。**不存在逐条手写的钉住条件清单**：哪个系统在个体身上留了状态，哪个系统就自动把他钉住。
- **R27-2.5 折叠**：对 `pinned` 为假的个体执行，时机只有两种——该单元有效层节拍的整拍边界；换层协议内（R27-1.7）。两者都由状态与绝对时间决定，与推进请求怎样切分无关。
  - 未分户的个体（仍在成员区间里）：折叠 = 删除基本行，别的都不动。
  - 已分户的个体：折叠 = 把他名下 `pooledResources` 各资源的余额经账本全部转入聚合账户，把成员序号并回成员区间（`bornMinute` 相同且序号相邻的并成一段），删除基本行。
  - 个人名下的余额并入总数后，谁原来有多少就不再保留——“没有个人历史的人只以总量存在”正是折叠的含义（§1.1 第 2 条）。这是一次真实的状态变化，不是可逆的换表示。
  - 对足迹非空的个体折叠即 E-AGG-FOLD-FOOTPRINT。
- **R27-2.6 实体化与分户分开**：
  - **实体化**（`materialize`）只建立基本行，**不动账**：成员在 `pooledResources` 里的份额仍留在聚合账户。按指定的成员身份实体化；被实体化的成员仍留在成员区间里，除新增基本行外不改任何状态。分组键里经 `keyHoldings` 种类派生的维度，实体化时在同一事务里按键值开该种持有边，条款只由成员身份确定性重算（R27-2.2）；条款等于重算值的这类边与基本行同等对待、不计足迹，条款不同的边或多出来的边照常计足迹。单元的有效层变为个体层时，该单元全部聚合体的全部成员实体化；离开个体层时按 R27-2.5 折叠。
  - **分户**（`settleOut`）：某条规则要对一个成员个人名下的 `pooledResources` 账户记账时，先把他的份额从聚合账户转到个人账户，再记这笔账。份额按 `shareRule`：`share_percapita` 为聚合账户余额整除“当前尚未分户的成员数”，余数留在聚合账户；`share_sampled` 为按 `shareDist` 抽取并钳在聚合账户余额之内，键按 R27-8.6。分户后该成员从成员区间移出，成为普通个体。
  - **规则要对聚合体里“某一个”成员写个人状态时**，取哪一个由骰值键抽取决定（R27-8.6），随后实体化该成员。
  - 分户发生在哪一刻、先后次序如何，由规则的写入在同刻全序里的位置决定，是世界里发生的事，与推进请求怎样切分无关。
- **R27-2.7 统计形态下的增减与迁移**：减员按骰值键在有序成员表上抽位置；增员按 R27-2.2 取 `nextOrdinal` 并加一；在聚合体之间迁移时成员保留原来的（来源种子键, 序号）与 `bornMinute`，只换所属聚合体。成员区间保持有序、互不重叠（否则 E-AGG-MEMBER-OVERLAP）。
- **R27-2.8 分组键只用已声明、且不随时钟变的维度**：`keyDims` 必须是该实体类已登记的枚举型或引用型维度；用未登记维度即 E-AGG-KEY-UNDECLARED。由时钟派生的维度（年龄段一类）不得作分组键，否则 E-AGG-KEY-CLOCKED——聚合体不逐个成员存状态，没法在某个成员跨过界线的那一刻把他挪到另一个聚合体。需要按年龄这类量区分时，由统计形态的规则从成员区间的 `bornMinute` 现算。所在单元是隐含键，由 `simUnitOf` 给出，存在 `aggregates.<aggregate>.unit`，不写进 `keyDims`。聚合种类表不出现任何具体实体 id。
- **R27-2.9 可折叠的前提是“随时间变的事实由时钟派生”**：凡希望其主体可折叠的系统，空闲时不得在个体身上留增量状态；年龄这类量由出生时刻与时钟派生（卷二 §1.12）。留了状态不是错误，只是该个体会被钉住。

- **A27-2.1（扫描式）**：S27-9 命中数为 0（`aggregate.mjs` 及其 import 闭包里没有任何实体类、物种、组织、持有种类、义务种类、状态族、记录种类、系统键的句柄字面量，钉住只由足迹推出）；S27-2 命中数为 0。
- **A27-2.2（验收测试，往返恒等；交卷十二机器化）**：① 对任一聚合成员，实体化后不对他做任何写入就折叠，排除日志分区后的世界状态摘要（定义见 R27-4.1）与实体化之前相等；② 对任一未分户、足迹为空的个体，折叠后再按同一成员身份实体化，该摘要与折叠之前相等。往返多出的折叠、实体化两条事件只在日志分区里，不在比较范围内。已分户的个体不在本条之内——他的折叠按 R27-2.5 是真实的状态变化，由 A27-2.3 的守恒和 A27-2.4 的身份稳定约束。
- **A27-2.3（不变量式，守恒）**：任意折叠、实体化、分户、迁移前后，每种资源的全局总量不变；全局人数 = 各聚合体成员区间长度之和 + 不在任何成员区间里的个体数，只在出生与死亡事件上变化；同一成员身份不同时出现在两个成员区间里。
- **A27-2.4（不变量式，身份稳定）**：同一（来源种子键, 序号）在任意多次实体化之间，实例 id 与全部采样维度相同。
- **A27-2.5（扩展性式）**：新增一个在个体身上留状态的系统，不改 `aggregate.mjs`，带该状态的个体自动 `pinned` 为真。
- **A27-2.6（扩展性式）**：新增一种聚合种类（任意实体类、任意分组键），只加一行，A27-2.2 至 A27-2.4 通过。

### 4.3 成本模型与降级阶梯

#### 4.3.1 维度

`coef`、`coefMaterialize`、`costSubjects`、`budgetCuPerChunk`、`chunkMinutes`、`ladder`；状态 `simDegrade.level`、`simDegrade.atChunk`；派生量 `costUnits`（不落盘）。

#### 4.3.2 统一入口

`costPlan`、`degradeLevelOf`；`sim-advance.mjs` 在评档块边界调用 `costPlan` 并写 `simDegrade`；`simTierOf` 读 `simDegrade.level` 取有效半径。

#### 4.3.3 规则

- **R27-3.1 成本是算出来的，不是量出来的**：成本按**一个评档块**计，不按一次推进请求计。给定状态与一个候选档位，预计成本 = 对每个单元、每个系统求和：主体数 × 块内拍数 × `coef[system][form]`，再加一次性的实体化成本。
  - 形态取该单元在候选档位下的有效层所对应的矩阵格；块内拍数 = `chunkMinutes` ÷ 该层节拍，是规则表常数。
  - 主体数：个体与批量形态取该单元内 `costSubjects[system]` 所列实体类的行数，其中出现在聚合种类表里的类按“成员区间长度之和 + 不在成员区间里的个体数”计（不看当下有多少成员恰好已实体化）；统计形态取聚合体个数；派生与冻结形态为 0。
  - 一次性成本 = `coefMaterialize` × 候选档位下将处于个体层、而现在还没有基本行的成员数。
  - 全部整数运算。输入只有状态与规则表。
- **R27-3.2 降级只由世界内在的量决定**：档位的输入只有三类——单元到观察锚的距离（经有效层）、各单元里各实体类的主体数与足迹（经钉住）、规则表。下列各项一律不得进入档位判定，也不得进入任何状态：
  - 单次推进请求的长度、起止时刻、类别标签（`advclass`）；
  - 实测耗时、内存、机器负载、AI 额度、网络状况、墙钟。
  理由有两条。其一，降级会改变哪些单元按哪种形态结算，如果它取决于机器快慢，同一种子在本机与云上就会走出不同的世界（违反卷一 I50）。其二，如果它取决于请求怎样切分，“一次推进 N 天”与“分 k 次推进合计 N 天”就会得到不同的世界（违反 R27-1.11）。
- **R27-3.3 评档**：只在绝对时间的评档块边界进行（时刻是 `chunkMinutes` 的整数倍；开局时刻算第一次），由调度器在该时刻的固定阶段触发，属于时钟形状的规则。
  - 步骤：先按旧档位把各单元结算到该边界（R27-1.7）；再读此刻的状态，从 0 档起逐档套用 `ladder`，取使 R27-3.1 的预计成本不超过 `budgetCuPerChunk` 的最小档；把它写入 `simDegrade.level`，块号写入 `simDegrade.atChunk`。
  - 两次评档之间档位不变，哪怕其间主体数变了。
  - 到了最高档仍超预算，按最高档执行，并经内核报告出口记一条 E-COST-OVER-BUDGET（告警级，不改状态）。
  - 推进请求跨过边界时在边界处评档；请求恰好停在块中间时不评档。所以某一时刻的档位只取决于最近一个边界处的状态，与请求怎样切分无关（A27-1.8）。
- **R27-3.4 阶梯操作**（累加）：`deg_individual_hops` 把个体层半径减去 `amount`，下限为 0；`deg_rule_hops` 把规则层半径减去 `amount`，下限为个体层半径；`deg_drop_shared_ancestor` 停用共同祖先条件。节拍不在可降之列——改节拍就是改规律。卷二十 §4.10.4 所说“降级改的是层与精度”，在本卷的含义就是：改的是哪些单元落在哪一层，从而改了它们的结算形态；没有别的“精度”开关。
- **R27-3.5 长推进分块**：推进请求跨过评档块边界时，按块逐段推进，每到边界按 R27-3.3 评档、按 R27-1.10 重新取计划。由 R27-1.11，分块不改变结果。块与块之间让出执行权由服务端装配文件（`index.mjs`）负责——推进在 Node 服务端进程，host 组在客户端进程，管不到这里（待卷二收口后对齐）。让出只影响别的请求何时被受理，不影响本次推进的结果；让出期间到达的玩家指令排在本次推进之后，或由装配文件先截断本次推进再受理，两种做法都把实际发生的（指令、目标时刻）写进日志（R27-7.3）。
- **R27-3.6 系数是世界数据的一部分**：`coef` 由基准标定后入库（§4.6），随世界数据副本一起存进存档（§4.4）。所以重新标定只影响新开的世界，已有世界的降级行为不变。
- **R27-3.7 单向读**：卷九 §4.14 可以经 `degradeLevelOf` 读档位来调低 AI 档位；反过来，AI 档位、费用账、模型可用性不得被本节读取（卷一 I42）。

#### 4.3.4 交互

卷九 §4.14（读档位）；卷二十 §4.1（在评档块边界触发评档；推进多少分钟由推进请求给出）；卷二十 §4.10（节奏只在入堆时缩放延迟类到期项的密度，不改节拍与同刻全序，**不是成本模型的输入**，本节不读它）；§4.1（有效层）；§4.6（标定系数、核对预计成本与实测的相关性）。

#### 4.3.6 验收断言

- **A27-3.1（扫描式）**：S27-3 命中数为 0；`cost-model.mjs` 与 `sim-tiers.mjs` 的输入声明（卷二 §2.3）里没有 AI、费用账、旁路记录相关的状态键；`costPlan`、`advancePlan` 的参数表与 3.1 所列完全一致，没有请求长度、类别标签或其他表外参数。
- **A27-3.2（不变量式）**：同一状态，`costPlan` 在本机与云上、在项目支持的每个 Node 版本下返回值逐位相同。
- **A27-3.3（不变量式）**：任意档位下，观察锚所在单元的层为个体层；任意档位下 A27-2.3 的守恒成立。
- **A27-3.4（不变量式）**：`degradeLevel` 对预算单调——预算调大，档位不升。
- **A27-3.5（扩展性式）**：新增一个系统，只加系数行即进入成本模型；缺行即加载失败，不存在“默认零成本”。
- **A27-3.6（扩展性式）**：在阶梯里增删一档只改规则表，A27-3.2 至 A27-3.4 仍通过。

### 4.4 存档（事件日志加快照、分片）

#### 4.4.1 维度

`shards`、`snapshotEveryEvents`、`segmentEvents`、`keepSnapshots`。清单字段：`rulesDigest`、`dataDigest`、`snapshotIndex`、`clockMinute`、`shardDigests`、`logSegments`、`saveDigest`（存档摘要，只此一种）；另有不进逻辑文档的显示字段（R27-4.10）。

#### 4.4.2 统一入口

卷二 §2.9 第 1 条登记的内核读档入口与存档写盘出口；本卷不新增文件边界。扫描 S27-7。

#### 4.4.3 规则

- **R27-4.1 逻辑文档与物理布局分离；摘要只有一种**：存档在逻辑上是一份文档，分五个部分（族 `docpart`）——世界数据副本、状态、持有、账本、事件日志。**存档摘要**对逻辑文档计算，口径与排除表完全按卷二 §2.9 第 3 条（卷一 §8.3：只有一种哈希），本卷不另立口径，也不设第二种哈希。物理上怎样切片不影响存档摘要。
  - 规则层不得读取存档摘要或任何摘要（S27-8）。摘要只供三处使用：存档读写、门禁、测试。
  - 本卷所有“同种子复现”“分段无关”“存读恒等”一类的确定性要求都写成验收测试：两边各得一份存档，比较存档摘要，由卷十二机器化。
  - 例外只有 A27-1.3、A27-2.2、A27-8.2 三条：它们的两边按构造就有不同的事件日志（推进请求条数不同、多出折叠与实体化事件）或不同的登记表，所以比的是**排除日志分区后的世界状态摘要**——用存档摘要的同一算法、同一张排除表（排除表只引用卷一 §8.3 的单点定义，本卷不另抄），计算对象只取 `doc_state`、`doc_holdings`、`doc_ledger` 三个部分；`doc_log` 不计入，`doc_data` 不属世界状态、另由 `dataDigest` 标识。它只是存档摘要在计算对象上的限定，只供测试使用，不落清单，不是第二种哈希。
  - 开着文字模型时两边的 AI 文字可以不同，存档摘要按构造就不同；这时按卷一 §8.3、V-13 的口径比“事件流与 textPaths 之外的状态逐值相等”，或者把同一份 AI 输出回放后再比存档摘要。这是引用卷一的比较办法，不是新哈希。
- **R27-4.2 每个世界自带数据副本**：开局时把当时的维度表、规则表、词表冻结成一份副本存进存档（卷一 §8.5），其摘要为 `dataDigest`。世界此后只读自己的副本。语言包不在副本内，换语言包不改任何摘要。
- **R27-4.3 规则指纹**：`rulesDigest` 由内核与规则层的源码摘要和 `dataDigest` 合成。读档时只做一次相等比较：不等即拒绝加载（E-SAVE-RULES-MISMATCH），不迁移、不尝试修补，也不改不删该存档文件。显示层、语言包、host 的改动不进 `rulesDigest`。本条只管“比较这一步”；已有世界能不能安装或卸载扩展包、装了之后数据副本与两个摘要怎样算，由卷二十八 §4.6 定（§8 第 12 条），本卷不替它裁定。
- **R27-4.4 字段序列化声明读 pathTypes**：哪些路径存、存成什么类型，唯一依据是卷二 §2.7 的 pathTypes。任何系统不写自己的序列化函数；没有声明的路径写不进状态，自然也进不了存档。
- **R27-4.5 事件日志加快照**：日志只追加，每 `segmentEvents` 条封成一段；每 `snapshotEveryEvents` 条事件做一次快照。恢复 = 最近一个完好快照 + 其后的日志段按 `replay_apply` 重放（§4.7）。
- **R27-4.6 分片**：`shards` 覆盖逻辑文档的全部五个部分，每行用 `part` 指明属于哪一部分；每个部分里的每条路径恰属一片（状态路径的匹配语义用卷二 §2.7；世界数据副本按表、持有与账本按其定义卷登记的路径、日志按段）。任何一部分有路径没被覆盖即 E-SAVE-SHARD-UNCOVERED，两片重叠同样报错。
  - `part_single` 整片一个文件；`part_by_unit` 按模拟单元再切。
  - `part_by_segment` 按追加的先后切段，**只能用于只追加的路径**：事件日志，以及 pathTypes 带“只追加”标记的状态路径（该标记的登记见 §5）。对没有该标记的路径用它即加载失败。
  - 快照不是第六个部分：一个快照就是那一刻逻辑文档除日志外四个部分的分片集合，由清单的 `snapshotIndex` 指到。
  - 同一个 Sealed 值不跨片拆开。
- **R27-4.7 写时复制**：每个分片文件按内容摘要寻址。存档时只写摘要变了的片；没变的片不重写。远处统计层单元的片很少变，所以一次存档的写入量与“变了多少”成正比，不与世界总量成正比。分片摘要只用于完整性与去重，不是存档摘要，也不构成另一种可比较的哈希。现存储层在日志段之间记的前后相接摘要链并入本条：段的完整性由清单里逐段的摘要保证，不再另维护一条链（M27-8）。
- **R27-4.8 原子提交**：先写齐新分片，最后以原子改名提交清单。清单是唯一的提交点；清单引用的片缺失或摘要不符即 E-SAVE-SHARD-DIGEST，回退到上一个完好清单并报 E-SAVE-TORN。
- **R27-4.9 保留与修剪（只管存档的日志与快照）**：保留最近 `keepSnapshots` 个快照及其后的日志段。修剪只在快照点、只由规则表参数触发；不由磁盘余量、墙钟或手动时机触发。不被任何保留清单引用的分片文件才可回收。本条不碰状态：状态里的领域记录何时过期、最多留几条是规则语义，由记录所属的领域卷用到期项（卷二十 §4.1）表达，参数进规则表——它不得跟快照间隔挂钩，否则改一个存储参数就改了世界（M27-13）。
- **R27-4.10 墙钟只在清单的显示字段里，由内核之外传入**：存档时间、存档名这类给玩家看的信息放在清单的显示字段，不进逻辑文档，因而不进存档摘要。它们的值由服务端装配文件在调用存档出口时作为不透明的显示参数传入；存档出口原样写下，不读、不比较、不据此分支。内核自己不取墙钟（S27-3），规则层读不到这些字段。战役标识不得用随机标识函数生成：需要确定性的由世界种子派生，只为区分存档文件的由装配文件传入并同样只作显示字段（M27-17）。
- **R27-4.11 进程归属**（待卷二收口后对齐）：存档读写只在 Node 服务端进程。扩展进程不保存任何权威数据，其本地偏好属于客户端偏好层（卷一 §8.3 排除层）。

#### 4.4.4 交互

卷二 §2.9（摘要口径、Sealed、读写边界）；卷二 §2.7（pathTypes）；卷二十八 §4.6（安装、升级、卸载时调读档入口，并遵守 R27-4.3 的一次相等比较；装包后摘要怎样算由它定）；卷十二（把 A27-4.2、A27-4.3 做成机器执行的验收测试）；§4.7（复演）；§4.1（按单元切片）。

- **A27-4.2（验收测试，分片无关；交卷十二机器化）**：同一逻辑文档换任意合法分片表存盘再读回，存档摘要不变。
- **A27-4.3（验收测试，存读恒等；交卷十二机器化）**：任意时刻存盘后读回，继续推进同样的指令序列，与不存盘直接推进相比，存档摘要在每个快照点相等（不开文字模型；开着时按 R27-4.1 的卷一口径比）。
- **A27-4.4（不变量式，中断安全）**：在写盘的任一步骤中断，读档得到的要么是新清单的完整状态，要么是上一个清单的完整状态。
- **A27-4.5（不变量式，语言无关）**：换语言包、换显示层版本后读同一存档，`rulesDigest` 与存档摘要不变（接卷一 I40）；改动清单显示字段（存档时间、存档名）也不改变存档摘要。
- **A27-4.6（不变量式，拒绝而不破坏）**：`rulesDigest` 不符时读档失败，存档目录下所有文件的字节与修改前相同。
- **A27-4.7（扩展性式）**：新增一个系统及其状态键，只在 pathTypes 与分片表登记，不改存档读写文件，A27-4.2、A27-4.3 通过。

### 4.5 确定性数值

#### 4.5.1 维度

`mathAllow`、`safeIntMax`、`fnTables`；族 `detfn`；卷二 §1.5 各数值类型的 `precision`（引用）。

#### 4.5.2 统一入口

求值走卷二 §3.3 管线；超越函数只经内核的定点数学设施（现 det-math.mjs，归入 kernel 组，导出名向卷二 §2.7 kernelApi 登记）；集合遍历只经内核提供的按键排序遍历；扫描 S27-3、S27-4、S27-8。

#### 4.5.3 规则

- **R27-5.1 状态里的数只有两种**：整数（绝对值不超过 `safeIntMax`），或按维度 `precision` 的定点数（底层同样是不超过 `safeIntMax` 的整数）。非有限值、负零不得进入状态（E-DET-NONFINITE）。一次写入会让某个数超出 `safeIntMax` 时，该写入被拒绝并报 E-DET-OVERFLOW，不截断、不换别的表示法；状态里不存在“用字串装的大整数”（卷二 §1.5：字串不得出现在运行期可写路径）。确有超大数需求的领域，报卷二 §1.5 增类型，本卷不自立。
- **R27-5.2 运算**：规则层的数值运算只有三条路——卷二 §3.3 求值管线；内核定点数学设施；`mathAllow` 列出的整数安全成员（取整、绝对值、最大最小、符号一类）。其余数学成员在规则层出现即 E-DET-FLOAT。内核定点数学设施是全仓超越函数的**唯一实现**，按下面的定义做（卷二十 §4.1.4 所指“卷二十七 §4.5 定义”即此）：
  - 族 `detfn` 的每个函数在 `fnTables` 里有一行，写明输入标度 `inScale`、输出标度 `outScale`、定义域 [`domainMin`, `domainMax`]（按输入标度的整数）、表步长 `step`、表值 `values`。
  - 求值：输入落在两个表点之间时做线性插值，全程整数运算，除法向零截断，结果按 `outScale` 给出。输入超出定义域即报 E-DET-DOMAIN 并拒绝，不外推、不钳位。
  - `fn_exp` 不另立表：直接用卷二 §1.10 冻结的指数表及其算法，本卷的这一行只指向它。现 det-math.mjs 里自带的指数实现删除（M27-9）。
  - `fn_sqrt` 用卷二 §1.10 的整数开方（牛顿法固定步数），不查表；`fn_pow` 由 `fn_exp` 与 `fn_ln` 组合，底数须为正；`fn_sin`、`fn_cos` 的表覆盖一个整周期，输入先按周期取余；`fn_atan` 的定义域之外用恒等式折回。
  - 表值由 tools 组的生成脚本离线算出后入库并带摘要，运行时只读表、不现算；门禁重新生成并逐位比对入库文件。表是世界数据副本的一部分（R27-4.2）。
  - 各行的标度、步长取值在首次标定时填入并写依据；指数表的归属以卷二为准（§8 第 14 条）。
- **R27-5.3 顺序**：凡结果依赖遍历顺序的地方，顺序必须由 id 的码点序或数值键决定。排序必须给出全序比较函数，比较键只能是 id 或数值（卷一 I40）；不得使用依赖区域设置的比较；不得依赖对象键的插入顺序来自何处。违例 E-DET-ORDER。
- **R27-5.4 同步**：规则层与内核的结算是同步的；结果不得依赖异步回调的完成先后。计时器与墙钟不在可用全局之内（卷二 §2.9 第 1 条）。
- **R27-5.5 时钟**：规则只认分钟时钟（卷二十 §4.1）。墙钟不进状态、不进键、不进任何判定。
- **R27-5.6 同刻全序**：同一分钟内的结算次序由调度器的全序键唯一决定（卷二十 §4.1、卷二 §2.7 的阶段与排序键），与注册顺序、文件加载顺序无关。
- **R27-5.7 跨环境**：同一输入在本机与云、在项目支持的每个 Node 版本下结果逐位相同。凡做不到这一点的语言特性，一律列入禁用并由 S27-4 扫描。
- **R27-5.8 存档摘要的实现与断言**：摘要排除表由卷二 §2.9 第 3 条的规则生成；本卷负责把生成器接进门禁并断言入库文件与生成结果一致（E-DIGEST-EXCLUDE-DRIFT，卷二 §4.3）。摘要函数只在存档读写文件、门禁与测试里可用；规则层引用它即 E-DIGEST-READ（S27-8）。

#### 4.5.4 交互

卷二 §3.3、§1.5、§2.9；卷二十 §4.1；卷六（价格等定点量使用同一设施，不自带分母常数——现行分母常数迁入规则表，归卷六登记）；卷十二（扫描实现）。

#### 4.5.6 验收断言

- **A27-5.1（扫描式）**：S27-3、S27-4、S27-8 命中数为 0；全仓指数、对数、三角、开方、幂各只有一处实现（内核定点数学设施），规则层与其他组里同名函数的定义为 0。
- **A27-5.2（不变量式）**：任意状态的全部数值路径满足 R27-5.1；存盘读回后逐位相等；`fnTables` 入库文件与生成脚本的输出逐位相同。
- **A27-5.3（不变量式）**：把系统注册顺序、数据文件加载顺序、状态集合的插入顺序各自打乱后重跑同一指令序列，事件流逐字节相同。
- **A27-5.4（验收测试，跨环境；交卷十二机器化）**：同一指令序列在本机与云、在项目支持的每个 Node 版本下，事件流逐字节相同、存档摘要相等（卷一 I50）。
- **A27-5.5（扩展性式）**：新增一个需要超越函数的规则，只调内核设施；新增一张查找表只加数据，A27-5.4 仍通过。

### 4.6 性能门与基准

#### 4.6.1 维度

`scenarios`、`budgets`、`regressRatio`、`scaleRatioMax`、`runs`、`metricClass`、`costCorrMin`、`distTest`、`distAlpha`、`distSampleSize`、`keyCorrMax`；族 `perfmetric`、`metricclass`、`scenariotag`。

#### 4.6.2 统一入口

基准执行器在 tools 组，不在运行时；结果写基线文件，由门禁读取。规则层与内核不得读基线文件。

#### 4.6.3 规则

- **R27-6.1 两类指标分开拦，类别是数据**：每个指标的类别写在规则表 `metricClass` 里，门禁只读这张表，代码与正文里不出现“哪个指标属于哪一类”的清单。
  - **计数类**（`mc_count`）：与机器无关、逐位可复现，进核心门禁，每次合入都拦。首批：成本单位、事件数、存档字节数。
  - **计时类**（`mc_timing`）：只在云上的参考环境跑，每场景跑 `runs` 次取中位数，在阶段收口与大改动时拦。首批：回合耗时、推进一日耗时、存盘与读档耗时、堆内存。
  - 新增指标 = 加一个词表条目、在 `metricClass` 里加一行、加一个采集点；门禁判定代码不改（A27-6.4）。
- **R27-6.2 三道判据**：绝对预算（`budgets`）；相对基线的回退上限（`regressRatio`）；规模判据——同一场景把 `sizeClass` 翻倍，计数类指标的增幅不得超过 `scaleRatioMax`，用来在合入时就拦住平方级以上的写法。
- **R27-6.3 基线**：基线文件入库，按（场景, 系统键）分行记录计数类指标，按场景记录计时类指标。
  - 计数类：对已有的（场景, 系统键）行，基线只降不升。
  - 新增内容怎样进基线：新增系统、新增场景、重新标定系数都会让计数上升。升幅只有同时满足下面两条才被接受——① 升高的行全部属于本次合入新登记的系统键或新增的场景行，或者本次合入改动了 `coef` 且附有 R27-6.6 的标定依据；② 新增部分通过 R27-6.2 的规模判据。已有系统的行在同一次合入里仍然只降不升。
  - 基线文件不能单独改：门禁核对基线文件的每一处升高都能对上同一次合入里的一条新增登记或标定依据，对不上即 E-PERF-BASELINE-UNJUSTIFIED。把已有行的基线调高须李白批，并在该行写明批准依据。
  - 计时类基线在通过后更新为新中位数。
- **R27-6.4 场景是数据，覆盖要求是对标签的计数**：一个基准场景 = 一行（世界种子、规模、推进时长、推进类别标签、覆盖标签 `tags`、参与的系统键 `systems`）。场景表必须满足：带 `st_other_region` 的行至少 1 行；带 `st_nonhuman_major` 的至少 1 行；带 `st_supernatural_major` 的至少 1 行；同时带 `st_no_anchor` 与 `st_long_advance` 的至少 1 行。门禁按标签计数判定，不读场景的说明文字。标签是否属实由采集数据核对：例如带 `st_no_anchor` 的场景全程观察锚为空集，带 `st_nonhuman_major` 的场景成本分解里非人类主体类占多数。
- **R27-6.5 层间一致性基准**（`pm_tier_drift`）：R27-1.9 的比较在这里执行，统计量取 `driftStat`，样本组数取 `seedSampleSize`，容差取 `driftTolerance`。
- **R27-6.6 标定**：`coef` 由基准对每个（系统, 形态）单独测得每主体每拍的耗时中位数，取整入库；`coefMaterialize` 同法测得。同时核对预计成本与实测计时的秩相关系数，低于 `costCorrMin` 即要求重新标定。带“待标定”的字段在第一次标定后填入，并写明标定环境与日期（basis）。**截止条件**：阶段收口门禁检查全部待标定字段，任何一个未填或没有依据即 E-PERF-UNCALIBRATED，收口不过；在那之前门禁对未填项只记录不拦。
- **R27-6.7 分段记账**（待卷二收口后对齐）：`pm_turn_ms` 只量服务端从收到指令到产出投影这一段；传输与扩展渲染另由显示层卷记账。
- **R27-6.8 守恒是性能门的前置条件**：基准场景结束时调用卷六 §4.22 的源汇报告，任何一种资源不平即该次基准作废，不记成绩。

- **A27-6.5（扩展性式）**：新增一个系统后，若它没有出现在任何场景的成本分解里，门禁报覆盖缺口。

### 4.7 复演与规则只一版

#### 4.7.1 维度

族 `replaymode`；清单字段 `rulesDigest`（§4.4）。

#### 4.7.2 统一入口

`replay_apply` 在读档入口内部；`replay_verify` 在 tests 与 tools 组。扫描 S27-5。

#### 4.7.3 规则

- **R27-7.1 规则只有一版**（卷一 R-8）：代码里不存在“按存档版本走不同分支”的任何写法。事件、义务、记录上不带复演版本标记；整份存档只有一个 `rulesDigest`。现有代码里的运行期版本标记、投递版本标记、各领域的更新版本标记及其相等比较分支全部删除，只留现行那一支（M27-15）；卷一 R-8 判定与 V-17 里给存储与迁移留的例外随之取消（§8 第 15 条）。
- **R27-7.2 两种复演**：`replay_apply` 把日志里记录的原语列表原样施加，用于读档恢复；`replay_verify` 从快照出发，只取日志里的玩家指令与外来输入，重新跑规则，要求重新产生的事件流与日志逐字节相同，用于验证确定性。任一事件不同即 E-REPLAY-DIVERGE，报告第一处分歧的事件序号与原语序号。
- **R27-7.3 外来输入全部入日志**：能影响规则状态的外来输入只有两种，都写进日志——① 玩家指令（封闭代号集合内的动作代号加参数）；② 推进请求（目标分钟）。
  - 推进请求的目标分钟必须是请求自带的参数。由墙钟计时器触发的推进、离线补推也一样：计时器只负责“触发一次请求”，目标分钟由装配文件作为参数给出并入日志；内核与规则层不拿墙钟换算时长。`replay_verify` 只认日志里的数。
  - 推进类别标签（`advclass`）可以随请求记在日志里供统计，但它不影响结果（R27-3.2），复演不依赖它。
  - **AI 的任何输出都不得写进 textPaths 之外的状态**（卷一 I42）。模型产出的结构化内容（人口档案一类）同样在禁止之列：需要这类内容时由规则层按种子键采样生成；模型只能写文字路径，经 aiGate 以 Sealed 入库。现有把模型生成的档案当作已接受内容写入状态的路径退役（M27-16）。
  - `replay_verify` 遇到文字路径时从存档取已有的 Sealed，不重新调用模型（录制回放归卷九 §4.18）。
- **R27-7.4 不迁移**：不存在迁移表、兼容层、旧引擎、读档时的格式转换入口。`rulesDigest` 不符的存档不能加载（R27-4.3）。“不动原存档”的含义仅是不改、不删存档文件。
- **R27-7.5 本卷只管读档时的一次比较**：读档入口对 `rulesDigest` 做一次相等比较，不等即拒绝，不迁移。已有世界能不能安装、卸载扩展包，装包后数据副本与摘要怎样算、算不算新世界，都由卷二十八 §4.6 定（§8 第 12 条，涉及产品取舍处请李白定），本卷不裁定。
- **R27-7.6 开局缺省**：新世界的缺省值全部来自卷十 §4.12；不存在“为旧存档补缺省”的路径。
- **R27-7.7 复演是日常门禁**：每个基准场景（§4.6）结束后都对其日志做一次 `replay_verify`。

#### 4.7.4 交互

卷二十八 §4.6；卷九 §4.18；卷十 §4.12；卷十一（退役 §7 所列目录与文件）；卷十二（S27-5 与 `replay_verify` 进门禁）。

| 5 | — | 规则代码改过之后读旧存档 | E-SAVE-RULES-MISMATCH；文件原样保留 |

#### 4.7.6 验收断言

- **A27-7.1（扫描式）**：S27-5 命中数为 0；仓库中 legacy、compat、migrations 目录不存在；对这三者的 import 为 0；名字以迁移结尾的规则层文件为 0；aiGate 组登记的写者能写的路径全部在 textPaths 之内（按写者登记表与 pathTypes 核对）。
- **A27-7.2（不变量式）**：任意存档从任意保留的快照做 `replay_verify`，事件流逐字节相同；日志里含计时器触发的推进时同样成立。
- **A27-7.5（验收测试，AI 不入逻辑；交卷十二机器化）**：同种子、同玩家输入，不开文字模型与开着文字模型各推进同样时长，事件流逐事件相同，textPaths 之外的全部状态路径逐值相等（卷一 V-13 的口径，不比摘要）。

### 4.8 种子键与骰值键（确定性约束与验收）

种子键的格式、派生函数、PRNG 算法一律见卷二 §1.10，五段原则见卷一 §8.2。本节规定：骰值键五段各取什么成分（R27-8.5，主会话 11-13 裁定）、必须满足的约束、怎么验。

#### 4.8.1 维度

族 `seedrole`；现有种子键登记表的各列（文件、种类、表达式、次数、前缀、角色）——表的格式归卷二 §1.10，本节只读。

#### 4.8.2 统一入口

抽取只经卷二 §1.10 的采样函数与内核的骰值键包装；种子键类型只由内核构造（卷二 §2.9 第 2 条）；扫描 S27-6。

#### 4.8.3 规则

- **R27-8.1 全登记**：规则层与内核的每一个随机抽取点、每一个由种子派生 id 的点，都在登记表里有一行；源码与登记表双向比对，任一侧多出即 E-SEED-KEY（沿用现有机制）。
- **R27-8.2 键的成分只能是代号、id、整数**：种子键与骰值键的任何成分不得来自文字、AI 输出、墙钟、内存地址、遍历次序、调用计数、存档序号或入堆序号。类型上由“种子键只由内核按文法构造”保证；另由 `replay_verify` 动态核对。违例 E-SEED-COMPONENT。
- **R27-8.3 分流（流独立）**：随机数按键即取即算，不存在跨调用共享的随机数流或游标。键里又没有任何计数（R27-8.5），因此新增、删除、重排任何一个抽取点，不改变其他抽取点得到的值。出现带游标的随机数对象即 E-SEED-STREAM。
- **R27-8.4 域分隔**：不同用途的抽取点，流代号或抽取点代号至少有一个不同；登记表中角色为 `role_seed` 的行，（流代号, 抽取点代号）两两不同，且前缀不得为空。静态查登记表：有重复或空前缀即 E-SEED-COLLISION。动态在 `replay_verify` 中查重：同一个键在两个不同的事务里被求值即 E-SEED-COLLISION——这说明有两个不同的场合没有被五段区分开，要改的是该抽取点对“对象”或“时刻”的取法，不是往键里加计数。
- **R27-8.5 骰值键的组成（全书唯一写法）**：每一次抽取的键恰为五段——

  `(worldSeed, streamCode, subjectId, worldTime, drawSiteCode)`

  - `worldSeed`：世界种子（卷一 §8.2 的“战役种子”）。
  - `streamCode`：流代号，即登记表里该用途的前缀代号（卷一 §8.2 的“规则 id”）。固定代号。
  - `subjectId`：这次抽取针对的对象的 id——实体、聚合体、模拟单元、地点，或一条确定性派生的事件、到期项的 id（R27-8.9）。
  - `worldTime`：世界时钟的分钟数。整拍结算取结算区间的起点；按日、按季的抽取取该日、该季的起始分钟。
  - `drawSiteCode`：抽取点代号（卷一 §8.2 的“序号”，但它**不是计数**）。每个抽取点在登记表里有固定代号；一个抽取点一次要取多个值时，登记固定个数的位次，每个位次是一个不同的抽取点代号（卷二十的 `drawSlots` 即这种写法）。
  - **禁止**：全局计数器、存档单调序号、入堆序号、调用次数、循环下标，以及其他任何表示“第几次”的量，都不得进入键。循环里对不同对象各抽一次时，区分靠 `subjectId`；需要从一个键得到一串值（例如不放回地抽 k 个）时，由卷二 §1.10 的采样函数从这一个键展开，不另造键。
  - 因为在给定的（流、对象、时刻）之下，用到哪个抽取点代号是代码位置决定的固定值，所以新增一个抽取点只多出一个新键，不会改变任何既有抽取点的键与取值（A27-8.2）。
  - PRNG 算法、由键到随机数的派生函数归卷二 §1.10；本条只定键由哪五段组成。**卷二十 §4.1.3 第 6 条“动作与反应用存档单调序号”的写法须改为本键**：动作与反应的抽取同样取固定的抽取点代号；同一刻对同一主体的多次反应，以触发它的事件 id 作 `subjectId` 来区分。卷二十全序键里的 `enqueuedSeq` 只用于排序，不得进入任何骰值键，也不得成为事件 id 的派生成分（§5、§8 第 13 条）。
- **R27-8.6 聚合与换层的抽取**：统计形态的抽取，`subjectId` 取聚合体 id（逐单元的取单元 id），`worldTime` 取结算区间的起点——完整的桶取桶的起始分钟，换层产生的零头区间取该区间的起点（R27-1.7）。同一单元的各个结算区间起点互不相同，所以键不撞。从聚合体里抽“某一个成员”、分户时抽份额，`subjectId` 取聚合体 id（抽份额取成员的实例 id），`worldTime` 取当时的分钟，抽取点代号取发起这次写入的规则的登记代号。由此分段无关（A27-1.3）与身份稳定（A27-2.4）才成立。
- **R27-8.7 熵的去处**：`role_entropy`（非确定来源）只允许出现在 aiGate 与 host 组，且其值不得流入规则层与内核。规则层与内核中该角色的行数为 0。只用来量延迟的墙钟不是熵源，不登记为这个角色；它归显示与旁路记录一侧，由卷九 §4.18 与卷二的组白名单安排（§8 第 16 条）。
- **R27-8.8 分布质量**：对卷二 §1.10 的每种首批分布，离线抽取 `distSampleSize` 个样本，按 `distTest` 指定的方法做拟合度检验，显著性水平 `distAlpha`，被拒绝即不过；另取若干对只差一段的键，核对两条输出序列的相关系数绝对值不超过 `keyCorrMax`。换种子的分布比较（A27-8.4）用 `seedSampleSize` 组种子，统计量与容差同 R27-1.9。规律是分布：验的是整体，不是单次。
- **R27-8.9 事件 id 与实体 id 确定性派生**：规则层与内核产生的事件 id、实体 id、到期项 id 一律经卷二 §1.10 的派生函数由（世界种子、产生它的规则或指令的代号、主体 id、世界时刻、固定的位次代号）得出，不得含随机标识、墙钟、计数。原因有两条：这些 id 会作为骰值键的 `subjectId`；`replay_verify` 要求事件流逐字节复现。现有带随机值的事件 id 改为派生（M27-12）。同一刻同一主体在同一规则下产生多条事件时，用什么成分区分由卷二十与卷二给出细则（§8 第 13 条），原则同上：不得用计数。

#### 4.8.4 交互

卷二 §1.10（格式、派生函数、PRNG 与采样）；卷十 §4.12（登记生成期键域）；卷九 §4.18（费用账与录制回放不得成为键的成分）；卷二十 §4.1（其第 6 条须改用 R27-8.5 的键；`drawSlots` 的固定位次就是抽取点代号）；卷十二（A27-8.2 至 A27-8.4 机器化）；§4.7（动态核对）。

#### 4.8.6 验收断言

- **A27-8.1（扫描式）**：S27-6、S27-10 命中数为 0；登记表与源码双向比对无差；登记表里种子角色的行前缀非空且（流代号, 抽取点代号）两两不同；规则层与内核中 `role_entropy` 行数为 0；骰值键包装的参数表恰为五段，调用处没有计数器、存档序号、入堆序号流入。
- **A27-8.2（验收测试，插入无关；交卷十二机器化）**：在任意位置新增一个抽取点后重跑，除该点自身引起的后果外，其余抽取点的取值与新增前逐个相同。用只读取不使用的探针点验证：加探针前后事件流逐字节相同、排除日志分区后的世界状态摘要（定义见 R27-4.1）相等；探针在种子键登记表里多出的一行落在 `doc_data`，不在比较范围内。探针分别加在环境与时钟规则、动作、反应三类位置上，三类都要过。
- **A27-8.3（不变量式，无碰撞）**：任意基准场景的 `replay_verify` 中，没有哪个键在两个不同的事务里被求值；不同（流代号, 对象, 时刻, 抽取点代号）产生的键两两不同。
- **A27-8.4（验收测试，同种子同输出；交卷十二机器化）**：同一世界种子两次生成并推进，事件流逐字节相同、存档摘要相等（卷一 I50；不开文字模型）；换 `seedSampleSize` 组种子后，`observables` 的分布按 R27-8.8 的方法比较落在容差内。
- **A27-8.5（扩展性式）**：新增一个带随机性的系统，只登记行并调用统一包装，A27-8.2 至 A27-8.4 不改测试代码即覆盖到它。
