## §1 领域总述

### 1.1 真实世界怎样运转

1. 一栋房子先是一堆材料围出来的空间，然后才是"某种房子"。墙厚、用料、开口、屋顶决定它挡不挡风雨、保不保温、隔不隔声、烧不烧得起来、撞不撞得破。
2. 房子能干什么，取决于里面装了什么：有炉才能打铁，有床才能睡人，有磨才能磨面。同一栋屋壳，搬走炉子换上货架，就从铺子变成了仓库。
3. 盖成什么样由三件事定：手头有什么料，匠人会什么，主人想要什么。同一份图纸，石料与泥坯盖出来的不是同一栋房子；同一堆料，熟手与生手盖出来的也不是。
4. 房子天天在坏。日晒雨淋、人来人往都在磨它；没人修就漏、就塌，里面的东西跟着遭殃。
5. 各地房子长得不一样，一半因为当地有什么料、是什么气候，一半因为当地人的习惯。
6. 设施要人、要料、要燃料才转得起来；断了供，服务就停。

### 1.2 本作现状（出处见素材包 §3）

- 建筑事实在 `facilities.mjs`，投影在 `facility-state.mjs`。`facilityKind`（:30–36）已是统一入口，但 436 个建筑实例里只有 1 处 `facilityType` 数据，435 处是 `purpose` 自由文本，入口只好用 purpose 加 name 的正则兜底。
- 另有五处各写一遍正则：education-state.mjs:238/279、medicine-state.mjs:29/39、law-codes.mjs:59、finance-assets.mjs:234/302/537、water-cycle.mjs:33；升格判断 promotion.mjs:54/60/61 同样读 purpose 与 name。
- 建材只有木、石两个物品 id：public-projects.mjs:119/130/167/347–348、building-maintenance.mjs:49；全仓库 `.wood`、`.stone` 字段读取 89 处。
- 床位检查由活动文字决定：engine.mjs:423–834 以 `args.activity` 等于"睡眠""休息"的字面量分支；building-maintenance.mjs:239/284 用正则测睡眠与赶路。
- 工位（workstation-services.mjs）靠 purpose 识别，每类设施只有 1 个工位；借用许可没有结构。
- 形制与布局是散文；炉窑热量卡（t-hb-heat）未合入；可移动建筑、房间评价、仓储区域、机关都没有实现。

### 1.3 本卷的四条主张

1. **设施类型是推出来的，不是填出来的。** 建筑实例只存"实物"（形制、用料、尺寸、装了哪些固定装置）与"意图"（`intendedType`）。它此刻算哪种设施，由功能量 `functions`（固定装置与屋壳提供了多少遮蔽、床位、炉膛……）、围合量、围护材料对照设施类型行的门槛推出。任何地方都不读 purpose。
2. **建造产物由材料、技能、意图共同推出（北极星）。** 意图给出类型、形制、尺寸、用心程度；材料给出围护的导热、强度、易燃、劣化、可盖层数；技能给出能否开工、工时与品质档。三者缺一个，算不出一栋房子。
3. **固定装置一律是物品实例。** 炉、床、磨、货架、祭坛、压力板都是带 `comp_fixture` 的物品，材料、品质、耐久全走卷三；本卷只规定"装在哪、提供什么功能"。这样家具不再是没有定义的特殊东西。
4. **围合只写到卷五的围合维度上。** 有围护的建筑行挂卷五登记的 `comp_enclosure`，本卷只负责算出 `aperture`、`skyExposure`、`envelopeUaWPerK`、`soundLossDb` 的值；不另设"室内""有屋顶"之类的字段。

### 2.3 物品表上归本卷登记的组件 `comp_fixture`（固定装置）

`comp_fixture` 的 requires：`fixtureKind`（enum fixture）。固定装置的材料、品质、耐久、容器字段（`volumeCapacity`、`preserveMult`）都是卷三已有的物品维度，本卷不重复。"装在哪"不是维度，是一条持有边（持有种类由卷十八登记，本卷请求登记一个"安装"种类，§8 Q4）；关系 `rel_installed`（物品实例 → place）供聚合读取。

## §3 统一入口

### 3.1 读入口（唯一）

- `facilityTypeView(engine, typeId)`：卷二 §2.1 第 8 行给定；返回 §2.2 全部维度。
- `facilityView(engine, state, placeId)`：建筑实例或房间。返回 `placeView` 的 `dims`（含 §2.1 存储维度与卷五的围合维度）加 §2.1"视图派生字段"表各项。纯读：不开户、不入账、不写状态；读与不读存档摘要相同。
- 任何模块要知道"这栋房子是什么、能干什么、有几张床、几个工位、值多少印象分"，只能读 `facilityView`。本卷不设第二个读函数。
