## 如何审查

先读指南0章和13章，再检查docs/阶段2验收矩阵.md、docs/已知问题.md、docs/决策记录.md。这些文档有大量历史状态，应以本文件和实际代码为准；不要把文档的宣称当成证据。docs/实施日志.md和docs/进度.md用于追溯，tests/fixtures/legacy/及AI检查包/保留原始审查背景。

请逐项对照指南，识别已完成、部分实现、缺失和证据不足的要求，特别检查引擎与真实酒馆连接是否成立，NPC认知、承诺及记忆是否有实际处理器，已有规则是否只是测试夹具或目录文本。审查最后一次未验证改动，寻找会破坏已发布内容、存档迁移、生态守恒或审核证明的缺陷。测试应核对覆盖范围，不默认绿色结果代表完整需求。

也请评估推进速度：是否在反复扩充孤立模块和重复测试，是否可以减少返工并更快形成可验证的完整玩法。给出按依赖和用户体验排序的具体后续工作，注明需要先修的阻塞点；不以缩小用户原始要求作为提速办法。

本项目通常运行npm ci、npm test、npm run build-world；阶段0的预期失败由npm run test:baseline核对，不能删掉。真实场景使用npm run test:scenarios -- --quick，需要用户本地DEEPSEEK_API_KEY，审查包不提供密钥。部分部署工具依赖SillyTavern本体的依赖，包中没有第三方运行时，不把运行时缺失误判为业务功能已验证。
