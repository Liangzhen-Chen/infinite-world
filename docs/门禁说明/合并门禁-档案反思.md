# 合并门禁：卡档案与自我反思（第三层）说明

写给要据此出违规样例的人。规矩原文只在 docs/派活卡头规矩.md 第五节（题面、小节名、证据判据都在那里，代码照它读）；本文说明怎么查、查什么、漏什么。

## 1. 四层各管什么
- 第一层 派卡门禁：派卡脚本拼卡头、核自查，见派卡门禁卡（另排）。
- 第二层 提交门禁：.githooks/pre-commit 本地提交时只跑 pre_commit 门禁（其余条目见 C0 检查脚本卡）；档案检查挂在 .githooks/commit-msg（git 把提交说明文件路径作第一个参数传入），由 tools/accept/commit-hook.mjs 的 cardArchiveCheck 做（`node tools/accept/commit-hook.mjs --msg-file <说明文件>`）。原因：pre-commit 阶段读不到提交说明，主会话 squash 合并时拿不到「卡分支：」行，会按当前分支名找档案目录而误拒。
- 第三层 合并门禁（本文）：.githooks/pre-push → tools/accept/pre-push.mjs，推往 master 时重跑档案检查，并重跑 pre_commit。
- 第四层 定时全库扫描：见定时扫描卡（另排）。

## 2. pre-push 查哪些提交
- 只在推送目标是 refs/heads/master 时查；删除分支、推别的分支不查。
- 查本次要推的每个新提交：远端已有该分支时取 `远端sha..本地sha`，远端没有时取 `本地sha --not --remotes`。
- 合并提交（多于一个父）免查。
- 一个提交"要查档案"：改动了 server-plugin/、world/、tools/、docs/统一底层设计/ 下的文件，且不全在例外前缀 docs/统一底层设计/版本快照/ 下。只改 docs/卡档案/、tests/、其他 docs/ 的提交不触发档案检查（但碰验收目录 tests/acceptance/ 的提交触发角色检查，见 5）。
- 该提交的提交说明须有「卡分支：<分支名>」一行，档案目录 = docs/卡档案/<分支名里 / 换成 ->/。
- 档案读推送后最新版（本地 sha 的树），不是该提交当时的版本；规矩文件读远端当前版（远端没有第五节时才用本地版）。
- 生效线：规矩第五节「门禁生效提交」填了 7～40 位提交号时，该提交及其祖先不查（立门禁前就写好的历史提交）；没回填（写着别的字）或在本库里找不到该提交时，不跳过任何提交。取远端当前版规矩里的值（远端没有第五节时才用本地版）。
- squash 合并：提交说明写 `卡分支：<分支名>`、`角色：合并`、`标识：<合并者标识>`，门禁照卡分支找档案目录，按推送时的全套小节核；不核三方标识，验收目录的改动不限角色。主会话在自己的分支上 `git merge --squash` 后提交，这三行在 commit-msg 阶段就要写（说明缺卡分支行时提交阶段退回当前分支名找档案目录，找不到即拒）。主会话直提的只改裁定、交接、PLAN 等非触发目录文档的提交不触发检查。
- git 原生合并提交（有 MERGE_HEAD）在 commit-msg 阶段同样免查（`isMerge`）。
- 全部提交过关后，再跑一遍 pre_commit（accRun，同提交钩子）；不过也拒推。

## 3. 档案查什么（每个文件、每个小节）
目录里五个文件：派卡.md、开发.md、反思.md、出题.md、审查.md；各文件按 `## 小节名` 分节，小节名须与规矩表完全相同。表中「查于」为提交的行，提交和推送都查；为推送的（出题.md、审查.md）只在推送查。
- 派卡.md：派卡人与模型（文本）；三方标识（条目，≥3 条，字段 角色/模型/标识）；设计依据（条目，每条须含「卷X:行」）；依赖核查（条目，每条须含「文件:行」或「不存在→处理办法」）；拆分理由（文本）。
- 开发.md：改动清单（条目，每条字段 位置[须文件:行]、做了什么、依据[须卷:行或裁定/勘误/Q-号/李白·亮圳日期]、公共部件）；交DeepSeek小卡（文本）。
- 反思.md：最开头（第一个 `## ` 之前）是九项自查表，题面与规矩第三节一字不差，每行「是」+证据格里必须有「卷:行、文件:行、命令末行」至少一种实据（只写「✓」「已核」「做完了」等一律拒，不靠枚举敷衍词），第 6 项写确定的"共 N 行"，任一处不许留 "__"；是否合理完成（文本，须含「`命令` ……末行」或文件:行）；偏离逐项（条目，字段 代码位置[文件:行]、设计原文[卷:行]、偏成、理由）。
- 出题.md：出题人与模型（文本）；依据与测试（条目，字段 依据[卷:行]、测的是什么、测试位置[文件:行]）。
- 审查.md：审查人与模型轮次（文本）；逐项审查（条目，每条含文件:行）；发现与处理（文本）；抽查自我反思（条目，≥3 条，字段 抽查条目、对照[文件:行/卷:行/命令末行]、结论）。

### 什么算有证据
- 卷:行：`卷` + 数字或汉字数字 + 至多 20 个非冒号字符 + 冒号（中西文皆可）+ 数字，如 `卷十二:163`、`卷四 §2.1 :327`。
- 文件:行：路径（可含中文）+ .mjs/.js/.json/.md/.sh + 冒号 + 数字，如 `tools/accept/run.mjs:12`。
- 命令末行：反引号里的命令含 node/git/sh/ls/wc/grep/cat，后面同一行出现「末行」，如 `` `node --test x` 末行：# pass 3 ``。
- 裁定号：裁定/勘误 + 编号，或 Q-数字，或 李白/亮圳 + 月-日。
- 不存在处理：`不存在→` 或 `不存在->` 后跟至少两个字。
具体正则以规矩文件为准。

### 引用核实（文件:行、卷:行）
- 所有被检查的小节正文里、以及九项自查表证据格里，每一处「文件:行」都要对到该提交的树（提交时读暂存区，推送时读推送后的最新提交）：文件必须存在，行号须在 1 到文件行数之间；否则拒（文件不存在、行号为 0 或超过行数）。
- 每一处「卷:行」要在卷文件目录 docs/统一底层设计/ 里找到卷号完全相同的卷文件（卷二 不会匹配 卷二十；卷三 可匹配 卷三甲、卷三乙，行号取其中最长的），行号在范围内；找不到卷文件也拒。
- 「档案里没有被检查的小节」（如派卡.md 末尾自加的「卡文原文」）不核。

### 什么算敷衍（一律拒）
- 值（文本小节全文、条目字段值、无字段条目全文）去掉标点符号后为空，或是空话词（是、否、无、有、好、已核、同上、略、ok、n/a、done、yes、no），如只写 ✓、是、无。
- 无证据要求的值不足 4 个字（唯一例外：「无理由」，以及三个角色名写码/出题/审卡）。
- 要求证据的小节或字段里一个证据种类的写法都没有。
- 条目小节条数不够；条目缺某个字段；字段值为空。
- 偏离项必须有「理由」字段；确实没有理由要写「无理由」，字段缺失或为空即拒。
- 反思.md 偏离逐项没有偏离时：小节里写「无偏离」，同时须列出核过的设计条目，卷:行至少 3 个；只写「无偏离」拒。

## 4. 三方分离
- 派卡.md「三方标识」写码、出题各恰一条，审卡每轮复核一条、可多条（规矩键「三方可多条角色」登记，按轮次排），缺一方、角色重复、角色名不在这三个里、标识为空，都拒。
- 全部「标识」（含每条审卡）必须互不相同，任一审卡标识不得等于写码或出题标识（模型名可以相同，会话或代理标识不许相同）；比较前统一小写、去掉首尾空白，只差大小写或首尾空白算同一个。提交说明的标识与三方标识比较时同样规范化。中间的空格、全角半角、连字符下划线之差不规范化，算不同。
- 推送时标识里含占位词「待指派」即拒；提交时允许占位。
- 提交说明须写两行：`角色：<写码|出题|审卡>`、`标识：<标识>`（凡触发档案检查或碰验收目录的提交，commit-msg 阶段和推送时都核；理由：commit-msg 读得到说明，早核早拦，三方标识读暂存区版本，提交阶段允许占位词，推送阶段不许）：角色须在三个之内，标识须与三方标识里该角色的标识完全一致（审卡有多条时，等于其中某一条即可，用未登记的审卡标识拒）。
- 验收目录 tests/acceptance/ 只许角色为「出题」的提交改动；角色是写码或审卡却碰了该目录，拒。

## 5. 绕过标记怎么判
- 提交说明里有一行以「绕过门禁：」开头（后面写原因）即带绕过标记。
- 带标记的提交，不再查平时的各小节，改为只查档案 开发.md 的「绕过记录」小节：条目 ≥1，字段 谁、为什么、通知号，都须非空非空话（≥4 字）。读不到档案目录（没有「卡分支：」行或目录不存在）也拒。
- 角色标记检查（4）对带标记的提交照样做。
- 没有标记又不合格的提交一律拒；所以 --no-verify 的提交只有两条路：补全档案，或登记绕过记录。

## 6. 会漏什么（已知盲区，照实写）
- pre-commit 阶段看不到提交说明，所以档案检查移到 commit-msg 钩子；commit-msg 读得到说明，角色标记、绕过标记在提交阶段就核。直接调 `cardArchiveCheck(root)` 不带说明（message 为 null）时才退回当前分支名、不核角色。
- 只检查"形"加"引用存在"：文件:行、卷:行会核文件存在、行号在范围内，但不核那一行的内容是否真能支撑所写的结论（指向文件第 1 行也放行）；命令末行不核命令是否真跑过、末行输出是否真实；命令里引用的路径不核。
- 九项自查表的敷衍判法：以前只核「证据非空」（所以只写「✓」「已核」也曾放行，这是初版漏掉的一条，现已改为须含上述三种实据之一）；但「证据格里塞一个真实存在的文件:行」仍可糊弄，核对属实靠审卡抽查，脚本不判。
- 抽查是否属实、偏离理由是否站得住、「设计依据」里的卷:行是否真是依据，靠审卡的人，脚本不判。
- 角色「合并」的提交：验收目录的改动不限角色，squash 会把写码方对验收目录的改动一并带进来，脚本不核来源，靠合入前对分支上各提交逐个过 pre-push 把关。
- 出题.md 可由主会话代拷（出题-来源.md 记哈希），门禁只核出题.md 的小节与证据，不核哈希与源文件一致，那由审卡方在审查.md 里核。
- 标识规范化只做小写和首尾空白；同一个人换写法（空格、符号、别名）查不出。
- 标识、通知号只核非空与互异，不核真实性；角色标记写谎（写码方冒充出题方，抄对出题的标识）查不出，只靠标识不外传。
- 绕过标记一旦配合合格的绕过记录，档案其余各项不再查，绕过多少次、是否真报了李白，脚本不知道，要靠通知流水人工对。
- 只改 docs/卡档案/ 的提交不单独触发检查；一次不碰触发目录的推送（纯文档、纯测试）完全不查档案。
- 三方「模型」可以相同，只要求标识不同；"出题的不是写码的同一个模型"只能靠规矩与审卡人把关。
- 推送目标只认 refs/heads/master；pre_commit 重跑用的是本机当前工作树，不是被推的提交树；推送的提交不是当前检出时，两者可能不一致。
- 合并提交整体免查，合并时带进来的未合格提交不会在合并提交上被查（会在其自己的提交上被查，若它也在本次推送范围内）。
- 工作区里没有 git 的目录（临时目录）提交检查直接放行。
- 没有验收目录必须非空的检查（出题人没出测试，只要出题.md 写得合格就放行）；不核验收测试与出题.md 描述是否对得上。
- 在远端用 web 界面、或不经 pre-push 的方式（如换机器未装钩子）推送，本层不管；core.hooksPath 要设为 .githooks。

## 7. 怎么跑
- 钩子挂接：仓库已设 `git config core.hooksPath .githooks`，pre-commit、commit-msg、pre-push 都在这个目录。
- 本机推送时自动跑；手动：`node tools/accept/pre-push.mjs`，stdin 喂 `<本地ref> <本地sha> <远端ref> <远端sha>` 行（远端 sha 全 0 表示远端没有该分支），可加 `--root <目录>`。
- 提交时检查：`node tools/accept/commit-hook.mjs`（和 pre-commit 一样，只跑 pre_commit）；档案检查 `node tools/accept/commit-hook.mjs --msg-file <说明文件>`（commit-msg 钩子调它）。
- 回归测试：`node --test tests/accept/card-archive.test.mjs`（作者自己的回归，不作验收依据）。

## 8. 拦住后怎么报
- 提交时终端报 `E-ACC-CARD-ARCHIVE <缺什么>`，最后一行 `commit_msg rejected`；推送时报 `E-ACC-CARD-ARCHIVE <提交前 9 位> <缺什么>`，最后一行 `pre_push rejected`（或 pre_commit 重跑失败的条目名）。
- 按原因补档案或改提交说明后重推；不要 --no-verify 绕过、不要改规矩文件放宽（规矩取远端版，改了也不生效）。
- 确需绕过：按 5 写绕过记录并先通知李白拿通知号（通知命令见 CLAUDE.md「通知」）。
- 同一提交连续两次补不过：停下，向主会话报原因与判断，由主会话决定。
