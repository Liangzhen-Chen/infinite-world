写者：Claude Sonnet 5.5（C0 卡及续做）。本说明供独立样例测试者据此出违规样例；验收以独立样例为准，仓库里的故意违规回归（tests/accept/c0-checks.test.mjs 与 tests/accept/bypass/ 下各类夹具）只作回归，不作验收依据。

**版本说明**：亮圳规定任何检查代码都不许靠认字面文字来判（李白更正裁定 msg-1122-2255-c0ast）。本版（11-23 清晨）把 C0 各检测器改成**按语法树判**。只认字面文字的旧版本留在分支历史里当对照：提交 740807130（词法归一版）、9a5271f3a（token 模式版），不作正式 C0。

## 一、总则

- 挂在 `node tools/accept/run.mjs pre_commit`（提交钩子 commit-hook.mjs 调同一入口）与 `pre_merge`（块验收）。规则都是登记条目（state in_core，必过），一条 report_only 的待人审清单除外。
- **解析器**：acorn（package.json 的 devDependencies，版本 8.19.0 锁死进 package-lock.json）。只许 tools/accept 引用；条目 vol12.S12-12.pp_no_acorn_runtime（零违例必过）保证 server-plugin 各组（含 gate 组）里没有任何对 acorn 的 import、export … from、require()，以及说明符是常量的 import()（说明符折叠不出常量的 import(x) 守卫配的是 dynamic: false，不报；常量说明符的才拦）；经 node:module / module 的 createRequire 得来的 require（不论叫什么名字、是否与全局 require 同名，也不论是 `createRequire(…)('acorn')` 直接调用）同样算模块边。**合入后需要在仓库根跑一次 `npm ci`（或 `npm install`）装上 acorn**，否则提交钩子找不到 acorn。
- **语法树能力**（tools/accept/lib/ast.mjs，被各检测器共用，一处实现）：
  - 作用域与绑定：import、var/let/const、函数形参、函数声明、对象与数组解构、类、catch 参数；局部同名变量遮蔽全局名时按遮蔽后的绑定判（`const Math = {…}; Math.sqrt()` 不报）。
  - 取值来源 origins：别名（`const p = Math.sqrt`）、解构（`const { sqrt } = Math`、`const { Math: M } = globalThis`）、计算属性名（下标折叠得出常量字串：`Math['sqrt']`、`Math[K]`，K 是 const 拼出的字串）、`.bind(…)`、`.call/.apply`、条件与逻辑表达式（取并集）、逗号表达式、对象与数组字面量成员（含按变量下标取并取并集）、`Reflect.get(obj, key)`（等同 obj[key]）、`Reflect.apply(f, …)`（被调用方取 f）、局部函数的返回值、局部函数形参（取本文件内所有调用点传入的实参来源，并保留形参自己的名字，如 `tx`）、默认形参、let/var 的赋值语句、全局对象前缀（globalThis/window/self/global）。
  - 常量折叠：字面量、模板串、`+` 拼接、const 别名、从相对 import 来的 const（跨文件一层一层跟）。
  - 动态下标：下标折叠不出常量的取成员记为 dynamic；按规则要求报 `review:dynamic`（待人审）。
- 范围：除特别写明，扫 server-plugin 下 rules、kernel、textcore、inputEdge、outputGate、aiGate、assembly 七个模块组的代码文件（gate 组、tools/、tests/、legacy 不扫；acorn 守卫多扫 gate 组）。文件解析失败报 `parseError`（码 E-ACC-ITEM-PARAM），不静默跳过。
- 判定档：
  - **零违例档**（expect zero）：命中数必须为 0，现在就拦。
  - **报告档**（expect le_baseline）：命中行键集合必须是 tools/accept/baseline.json 对应分量 rowKeys 的子集——新增任一行键即不过（哪怕总数持平），减少则过。行键 = `分量|文件|所在符号路径|节点种类|同符号内序号`，不含行号。同一函数里新增同类命中得到新序号，算新违例。
  - **待人审清单**（expect report_only）：只报不拦。
- 规则的参数、例外、基线都在数据里：scanclasses.json（各类别的 callees 函数表、astRules 规则、fileSets、dynamicRoots）、items.json（条目参数）、criteria.json（判据文字与修订）、baseline.json（基线行键）。每条 astRules 规则带 kind（种类名）与参数；种类的实现是 tools/accept/lib/ast-rules.mjs 里的语法树小函数，**规则的名单、方法名、分隔符、例外文件都在数据里，代码里只有 JS 语言本身的结构（节点类型、比较运算符、Reflect/Proxy/call/apply 语义，以及 Set、join、stringify 一类语言内建名）**。检测器里仍有少量文件名与路径常量：单位表文件名 LAYOUT.units（取公共部件 server-plugin/kernel/load/layout.mjs，无 import、无副作用的冻结常量；world.mjs 也从它引（不再导出，没有别处从 world.mjs 引 LAYOUT），只此一处。检测器不能直接 import world.mjs：它装配整个内核，副作用会改变前缀登记）、维度表目录与 _vocab.json、seed-keys.json、clock 表等登记文件的路径（lit_scope、seed_sites、decl_cmp 里），这些是登记文件的位置，不是规则的内容。例外（exceptFiles、fileSets）须带卷:行依据。
- 码都是登记码；`review:dynamic` 是节点种类（行键里的一段），不是错误码。

## 四、会漏什么（已知盲区，照实写，没有“不会漏”）

语法树把词法层的盲区大部分补上，下面是**仍然追不到**的：
- **动态代码**：`eval`、`new Function` 只能整体报（pp_eval），里面的调用追不到。第五轮已补：`Reflect.construct(F, …)`、`Reflect.apply(f, …)`（被调用方取第一个实参）、`new Proxy(target, handler)`（对代理的取成员与调用等同对目标）、`Function.prototype.call.call(f, …)` 与 `g.call.call(f, …)`（对象本身是 call/apply 方法引用时被调用方取第一个实参）。仍不跟：Proxy 的 handler 里写的拦截（get/apply 陷阱返回的别的函数）、`Reflect.construct` 带第三个实参 newTarget 的构造语义、`Function.prototype.bind.call`、把 call/apply 放进变量再多层嵌套传递。
- **运行期下标**：`cal[key]` 的 key 不是常量时，取的是哪个成员无法判断。硬拦只覆盖 pp_dynamic_index 的根列表（Math、globalThis、state 等）；其余对象上的动态下标进 pp_dynamic_review 清单，**只报不拦**。因此“用变量下标绕开 yearMinutes 一类名字规则”在提交时不会被拦住，只会出现在待人审清单里。
- **跨文件别名（第五轮补，范围以实测为准）**：相对路径的 import 按模块导入导出解析，跟到定义处取原名：导出的 const 别名（`export const root = Math.sqrt`）、导出函数的返回值（`pick()` 返回 `Math.sqrt`）、导出对象的成员（`T.r`）、`import * as A` 命名空间取成员（`A.root`）、`export { x as y }`、`export { x } from`、`export *`、default 导出，以及形参从别的文件传进来（别的文件 import 了本函数并调用，取它们的实参来源，一个形参最多看 50 个调用点）。**仍不跟**：非相对说明符（包名、`node:` 内置）、动态 `import()` 取到的模块、`require`、`export *` 与同名导出冲突时的优先级（取所有可能，多报不漏）、跨文件的 `let` 被别处改写、形参经数组方法（`map`、`reduce` 回调）传进别的文件、经对象成员传进别的文件的函数形参（`obj.run(Math.sqrt)` 的 `obj` 来自别的文件且 `run` 是对象方法，只跟 import 来的函数名与命名空间成员）、类方法的形参（只跟函数声明与 const 绑定的函数）、说明符解析只看文件是否在本次扫描范围里（范围外的文件不跟）。跨文件跟的深度有上限（导出链 10 层、取值来源 12 层、每个节点来源最多留 24 个），超了按未知处理，会漏。
- **属性赋值与其他传递**：（第四轮已补：同文件内 `o.f = Math.sqrt; o.f(x)`、类里 `this.f = …`、类字段 `f = …` 经 `this.f` 调用；赋值右侧并进该属性的来源，不分先后。）仍不跟：对象在别的文件被改写、`o[k] = …` 下标折叠不出常量的赋值、跨文件的函数返回值与形参传递（第五轮起跨文件也跟，范围见下“跨文件别名”条）、经数组方法（`map`、`reduce` 的回调参数）传入的函数不跟。
- **let 在闭包里被多处重新赋值**：只取所有 `名 = 表达式` 赋值的并集，不分先后与控制流，会多报；复杂控制流下的少报也可能。
- **类**：`this` 上的别名按“同一个类体里的 this 是同一个对象”处理（第四轮补，不分方法、不分实例）；继承、子类对父类字段的改写、类外 `instance.f` 与类内 `this.f` 的对应不跟。
- **动态 import 与 require 的运行期说明符**：折叠不出常量时 moduleEdge 报 review:dynamic（待人审），不报具体模块。
- **规范序列化（按定义判，第六轮）**：只认“同一函数里有取键 + 排序 + 拼串，并且结果流进 sinks 里登记的摘要或存储函数”。第八轮补了自写 hash 包装函数、自写摘要函数、取键排序辅助函数、对象成员、单层循环手写交换（见第四之七节）。仍会漏：流向用的存储接口既不在类别行 sinks 里、形状又不是逐字符取码混合（别的存储接口）；经数组方法回调（`.forEach((s) => sha256Text(s))` 的回调形参）转手、跨 4 层以上转手；结果经 `JSON.stringify` 之外的方式拼出（Buffer 拼接）；排序用第三方库；取键用点名函数之外、又不经自写辅助函数（辅助函数里再调辅助函数的两层）；手写排序只认“两层循环里比较并赋值”与“单层循环里同一数组两元素相比并按下标交换”，递归快排、归并不认。形状像但流向不明的，列进 pp_canonical_review（见下；它只认函数里自己写出的取键排序，不认经辅助函数的）。
- **键串拼接**：`join` 的分隔符与 `+` 拼接只认 `| : .`；第四轮补：数组里夹着分隔符再 `join('')`、`a.concat('#', b)` 这两种形式的分隔符认 `| : . # ,`（夹在元素之间的单个符号几乎只会是在拼键）。仍不报：经函数返回值、`String.raw`、模板串里直接写 `${a}:${b}`（非 sha256Text 实参时）不报（后者由 pp_tpl_key 管跨文件重复，单文件内不拦）。
- **邻接方向**（第五轮补：变量加减 1 的邻居位置 `[x + 1, y]`、`{x: x, y: y - 1}` 也算一个邻居，与单位向量一样攒够三个就报；两个分量都带偏移（对角）、偏移不是 1、偏移量来自变量的不算）：非 0、±1 的向量、从数据文件读入的、用 concat 拼出的、少于三个向量的表不报；第四轮补：实参是常量表达式（`1 - 0`）、spread 展开数组字面量（`[...A, [0, 1]]`）、push 到 `this.dirs` 一类成员链都数得出。逐个 push 只跟同一个绑定或同一条成员链上的 push，经函数返回再 push、spread 的不是字面量也不是 const 数组字面量的不跟。
- **种类分支**：从登记数据派生的表（读进来的表、由数据建的 Set 或 Map）查种类不算分支，那是应当的写法；**代码里写死的对象字面量查表、写死的字面量清单 `.includes`/`has` 要报**（与第 26 条一致）；`kindOf(x) === 'house'` 一类经函数取种类的比较已补（函数名在类别行 calls 里登记，现只有 kindOf，别的取种类函数要先登记才认）；`startsWith`、正则判种类不查；字段名不在 kind/type/class/category/form/species/role/subtype 里的漏；对象查表只认下标直接是这些成员（或沿 const 一层解开的变量）；`.type` 只在与字串字面量比较时才报。
- **按名字名单判的规则**（pp_region_cell 的 regionCellM、cellM；pp_material_read 的 MATERIAL、material）：名单放在类别行数据里，按取值来源（别名、解构、成员访问跟到原名，取来源路径的末段）精确比，不用正则前缀；成员访问（`g.regionCellM`）照认，形参、解构形参、无初值局部以名单里的名字声明的也认（第八轮改回：这类名单是数据字段名而不是全局名，形参以字段名声明就是在携带该字段值；遮蔽不认只用于按全局名判的规则，如 Math、setTimeout）。名单外的同义名字（换成别的属性名）仍漏，那是名单的边界。
- **持有与账本读点**：按键名认属性，不判对象是不是状态（别的对象的同名字段也会报，进基线）；经 `Object.keys(state)`、`Object.entries(state)` 整体枚举的不跟（decl_cmp dynamicState 已有该类检查，未并入 C0）。
- **计时器**：`setImmediate`、`queueMicrotask`、`timers/promises` 不查。**浮点**：手写开方（牛顿迭代、`x * x` 反推）、上表之外的 Math 成员、变量指数的 `**`（仅 review:dynamic 待人审）不拦。
- **例外按文件整体豁免**：例外文件里新增违规不报。
- **基线机制**：基线只在 pre_merge --write --merge-ref 时由执行器写；某分量尚无基线行时 pre_commit 不拦它（首次登记只在合入关口）。行键不含行号，同一函数里“删一处同类违例、同时新增一处”会得到相同行键而漏报。
- **既有检测器的词法部分**：C0 之前的卡建的检测器（call_edge 的测试临时根与路径实参判法、path_access 的 write/display/stateRead/ref、lit_scope 的实体前缀与数值判法等）仍是词法判，不属于 C0，没有改。
- 范围只含七个模块组（acorn 守卫多一个 gate 组）；tools/、tests/、legacy、world 数据（除 state-owners.json 与 _units.json、seed-keys、clock 表）不扫。

## 四之二、第四轮（独立验收后）修了什么

独立验收对第三版（fc46be41c）给出漏拦与误拒，本轮按类别修，每类都在 tests/accept/bypass 补了回归用例（float_math-18~21、timer_global-05、pp_canonical_def-14/15、pp_unit_literal-02/03、pp_neighbors-17~19、pp_key_concat-14~16、pp_kind_branch-15~18）。

**误拒（正常写法不许拦）**
1. **遮蔽多报**：形参或无初值的局部名叫 Math、setTimeout 一类，之前按名字当成全局报了。现在取值来源给形参和无初值局部名打 `shadow` 标记，按全局名判的规则（call_edge 的函数表、成员引用、嵌套调用、RegExp 等）一律跳过带标记的来源。按“状态根名”判的规则不受影响（形参叫 state 照认）；undo_raw_push 的 `tx.undo.push` 本来就是形参名，类别行加了 `localRoots: ["tx"]` 点名照认。形参被调用方传入真全局（`f(Math)`）时，那条来源不带标记，照报。
2. **种类分支三种误拒**：`x.category !== ''`（与空串比是判有无，不算写死分支）；`row[kind]`（按行取字段，只有被查的对象是写死的对象字面量才算“按种类查表”）；`known.has(x.kind)`（接收者必须是字面量字串清单：数组字面量或 `new Set([…])`，由登记数据派生的 Set 不算写死）。这一类基线分量从 83 降到 5。
3. **属性名字串撞单位代号**：`o['year']`、对象键、类成员键、`'year' in o` 不是取值，不计；单位只认值位置。

**漏拦（原先放过的写法）**
4. **单位折叠漏**：`'cop' + 'per'`、没有字面量单位的模板串，整个表达式折叠得出已登记单位才报（里面已有字面量本身就是单位的，由那个字面量自己报，不重复）。
5. **push 表达式漏**：逐个 push 邻接向量，实参是常量表达式、接收者是 `this.dirs` 一类成员链、spread 展开数组字面量拼表，都数得出。
6. 规范序列化的迭代式（显式栈）、`[a,'#',b].join('')` 与 `concat` 夹分隔符、`o.f = Math.sqrt` 与类里 `this.f = Math.sqrt` 的别名、`kindOf(x) === '…'`，见第四节对应条目。

**本轮没有补的**：运行期动态下标（仍只报待人审）、跨文件函数返回与形参、eval 与动态 import 说明符，以及上面各条列出的“仍不跟”。

## 四之三、第五轮（独立验收第四轮结果后）

## 五、怎么跑

- 先装依赖：仓库根 `npm ci`（装 acorn 8.19.0）。
- 提交前：`node tools/accept/run.mjs pre_commit`（退出码 0 放行；verdict 为 pass）。
- 块验收：`node tools/accept/run.mjs pre_merge --merge-ref <合入号>`，写基线加 `--write`。
- 回归测试：`node --test tests/accept/c0-checks.test.mjs`；绕法用例回归在 `node --test tests/accept/runner.test.mjs`。
- 入口生产调用者报告（只报不拦，也按语法树判）：`node tools/accept/entry-report.mjs`，加 `--strict` 则有任一入口不通退出 1；入口清单在 tools/accept/entries.json，快照 docs/卡回报/c0-entry-callers.md。

## 六、拦住后怎么报

- pre_commit 失败时 commit-hook 向 stderr 打印 `pre_commit rejected`，再每个不过条目一行：`条目键 错误码`。报告档条目基线上升报 E-ACC-BASELINE-UP；零违例档条目报其自带码。
- 完整报告（JSON）：run.mjs 标准输出，字段 items.failed 列不过条目，components.<分量> 给 b0、last、current、diff。
- 命中行（文件、行、符号、节点种类）：加 `--write` 后在 tools/accept/hits.json 与 tools/accept/out/<内容指纹>/pre_commit.json；每行带 rowKey，节点种类形如 `规则名:种类`，`review:dynamic` 即待人审。
- 基线清单：tools/accept/baseline.json，按 compCode 找（C0 各分量名以 `_ast` 结尾，另 c_pp_dynamic_index、c_pp_float_pow），rowKeys 即允许存在的既有违例。
- 修一条转一条拦：修理卡合入时用 pre_merge --write 让该分量基线清空，之后该分量为 0 才过。
