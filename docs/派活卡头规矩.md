# 派活卡头硬规矩（亮圳2026-11-18批准；任何人给任何子代理派活，每份任务最顶上原样放）

## 一、你在做什么（先读这段）
你在写《无限原野》：世界上最自由的文字 RPG，九省 31 郡全规模、真实运转的中西合璧修仙世界（docs/产品原则.md 一.1–2）。
眼下的方向：一步步把游戏做到能真玩一局——块 6「第一个可玩竖切片（无 AI、菜单）」（docs/新底子方案-v0.md :131）。
判断任何改动先问：它让游戏离能玩更近了吗？
但"能玩"是方向，北极星是底线：能玩必须是按北极星做出来的能玩。不许为了先跑起来走捷径——不许写死、写特例、跳过规则引擎、拿假数据或简化版顶上、缩小世界规模、"先这样以后再改"。两者冲突时一律守北极星，停下写明冲突交主会话，不自己取舍。
不可动摇的四条（产品原则原句）：
- 规则引擎是唯一真相；不开 LLM 也能完整游玩（一.3）。
- 派生优先：价格、工时、难度、权限都从世界状态推出，不写死，不按 ID 或场景特判（二.1）。
- 最小完整改动，删除优先：先问"它需要存在吗"（三.3）。
- 验收以设计与试玩为准，不以分数为目标；不为测试造东西（三.1–2）。

## 二、硬规矩（违反任一条，卡直接打回）
1. 照卷文写，不自补。卷文推不出或矛盾：停下写"未找到/卷文矛盾"，不编出处（出处写到"卷:行"）。
2. 不写特例：修复落在规则层或原语层，不为某个 id、物品、文件名、卷名单开分支。
3. 不留绕过口子：任何限额、门槛、校验，不能因为某个特殊值（如"不限"、0、空、null）被跳过；特殊值要么按卷文明确处理，要么拒收报错。
4. 测试测行为，不测当前偶然数字：期望值按卷文公式手算，或在测试里先造好前提再断言；不许把仓库此刻的基线读数、计数抄进断言。
5. 不为数字好看改代码：不许为了让违例数、计数下降而改写本来允许的写法；不许把字面量改名成假常量来骗过检查器。拿不准是否允许，查卷文白名单，查不到就留原样并报告。
6. 不改测试来过关，不降门槛；测试本身错了就停下说明理由，由主会话定。
7. 只动卡文列出的文件；顺手的整理、格式化、"以后用"的抽象一律不做。diff 越小越好。
8. 合入前或基线变动后，跑全量测试（命令以卡文为准），贴命令和结尾输出；没跑就写"未跑"，不写"通过"。
9. 模块化（亮圳 11-22 18:27「模块化原则1122」）：模块之间接口固定；规则和参数放数据里，不写在代码里；一个模块能单独替换，不牵动别的模块；经验估计或调研后才定的做法和数值先只做一种，但要留好以后加种类、改做法的位置（同材料表：加一种只添一行数据）。不另起大重构，不推翻已合并的卡。
10. 写死是绝对红线（亮圳 11-22 19:20「红线写死1122」）：除世界设定外，任何系统里的数值、规则、种类一律放数据表，可单独替换；代码里不许出现写死的数值、种类分支、规则常量。已有公共部件就必须调它，不许自己另算一份；公共部件缺了要扩，就扩那个公共部件本身，并在回报里写明，不受第 7 条"只动卡文列出的文件"所限，也不许在本卡里另抄一份。检查脚本拦新增写死。

## 四、给派卡人（主会话）的写卡规矩
- 卡文顺序固定：①本卡头（上面一至三节）→ ②目标 2–3 句大白话（做什么、为什么、做完游戏多了什么）→ ③要照做的卷文原句（带"卷:行"）→ ④只需要的文件片段 → ⑤验收命令。
- 派卡前先查前提：本卡依赖的数据行、组件类、规则表在主线上是否已存在（李白 11-22 15:21）；有缺的，先补前置卡或报裁定，不派会被挡住的卡。
- 除了勘误前置，还要把规矩检查对照表（docs/迁移体检/）里该卡的依赖行逐行核一遍：依赖别卡的产出、"现状"列写缺的前置，都要在主线上已落（李白 11-22 18:33，覆盖所有卡）。
- 卡文"目标"后固定写四句（李白 11-22 18:40，模块化原则）：①模块之间接口固定（列本卡导出的入口与形状）；②规则和参数放数据里（列本卡新登的规则表键或族字段）；③本模块可单独替换（换实现时只改哪个文件）；④同一判断只一处（列本卡新加的分派表或判据的唯一位置）。审 diff 时加一问：有没有新增按种类、按代号的 if 链。
- 审卡必查写死（亮圳 11-22 19:20）：每个新增数值、种类、规则常量，都要能指出它在哪张数据表、哪个键；每处计算都要能指出它调的是哪个公共部件。指不出的，一律判必须改。
- 派给 DeepSeek 的每张小卡必须写清四样（亮圳 11-22 19:49 原话"可以更多的东西给ds，你们写清楚prompt它没这么蠢吧""就是你们prompt写不清楚"）：①设计书原文摘句加 卷:行；②要改的文件与段落（文件:行或函数名）；③必须调用的公共部件（入口名与提供方文件）；④验收标准（具体命令与期望）。比对、批量机械改动一律交 DeepSeek，写卡人只审整合。
- 派卡前对着总登记表 tools/accept/entry-registry.json 核本卡依赖入口的 needs 闭包：闭包里每个入口都要已建且有生产调用者，或明写由本卡建（李白「总登记表1122」Q-12；卷二 §2.7 勘误 1124k110）。
- 查前置不只查函数在不在，还要查生产代码里有没有真实调用者；本卡要接的入口若只有测试调用，先确认归哪张卡建（李白 11-22 18:36，覆盖所有卡）。
- 不贴进度、花费、通知、裁定历史；这些与写码无关。
- 卡文正文（不含文件片段）控制在一屏内；文件片段放中间，结尾再重复一句目标和验收命令。
