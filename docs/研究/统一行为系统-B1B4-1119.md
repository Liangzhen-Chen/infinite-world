## 结论摘要（≤300 字）

现行设计已经有一条好的"单步选择器"：卷九 §4.12 的候选→底线→效用取最大，驱力权重来自人格、价值、需求、心情（卷二十六 R26-9.1/9.2）。缺的是选择器上面那一层：每个人此刻挂着哪些心事、为了办成一件事要先办哪件事、办不了时找谁帮。主推方案甲是在现管线上面加三样东西，都尽量用已有机件：①"心事表"（派生，不存）汇总需求、合同义务、委托、职责、愿望；②有限深度的"方法表"（数据行，深 3 层）把心事拆成第一步动作再交给原选择器；③委派统一成一个"要约"原语，定向走对话邀约、公开走委托，人情记成一种新合同。长期愿望做成长时限的发作行（推广卷二十六的奇想）。要落状态的只有愿望、承诺和人情合同。设计改卷约 2 周，写码约 4–5 周（放在块 6 之后）。块 2–6 的已建代码不受影响。拍板清单共 10 条。

### 1.3 B1 四个缺口的落点与矛盾

1. **长期愿望**：无。最接近的是奇想（R26-7.3），时限短、只绑偏好键、只认动词结束。卷二十六 M26-22 :1287 把旧"野心字段"删成地位驱力权重——权重说明"多想要地位"，说不出"想当这个县的县丞"。
2. **每人一张待办清单**：无统一视图。各来源散在：需求（卷二十六容器→只抬权重）、义务（卷六 `obligationsOf`）、委托（卷二十四，NPC 只能经知情读告示）、职责（R9-12.8 只在 `conflicts` 段当否决用，:1097）、日程（卷九 `agendas`，只是时段）。没有"轻重缓急"：R9-12.4 里没有截止时间、没有违约后果的估值。
3. **多步规划**：无。矛盾点：R9-14.8 说规划归 §4.12，§4.12 只有一步。后果是饿着又没钱的人，"买饭"候选 U 最高，进 `resolve()` 后在报价段失败，下一个决策时刻还选它——不会想到先借、先干活、先当东西。卷六 §4.12 规则 2 的"④ 赊欠与受赠"在家户层有，在个人决策里没有入口。
4. **委派代劳**：零件都有（雇佣、借贷、成交、委托、对话请求），但没有"我缺什么→找谁→用哪种方式求"的选择逻辑；"受赠""搭把手""人情往来"在卷十八、卷六都无合同种类与立场来源行。
5. **两套决策并行**（B4 相关）：卷六的自动结算（温饱、工作分配、贩运、开工）与卷九 `npcChoose` 各管一摊，边界没写清：个体层一个人既被 `settleHouseholds` 自动买粮，又可能由 `npcChoose` 选"去买饭"，会重复。

## 二、方案（B1/B2）：在只靠规则的前提下让每个人有自己的行为

### 2.0 总体形状

```
来源（数据行）                     派生，不存                       已有
需求容器 ─┐
合同义务 ─┤                ┌─ 心事表 concernsOf(人, 时刻) ─┐
委托承接 ─┼→ 心事来源行 ──→│  每条：目标、重要度、紧迫度     │→ 方法表展开（深≤3）→ 第一步候选 ─→ 卷九 R9-12.2–12.7 原样取最大
职位职责 ─┤                └─ 取前 k 条                     ┘          ↑                            ↓
亲友缺口 ─┤                                                        读价格、路程、对方肯不肯的估计      承诺 decisionCommit（已有键，加一栏）
愿望实例 ─┘（发作行，存）                                                                          ↓
                                                                                               resolve()，求人走"要约"
```

原则：选择器只有一个（卷九），本方案只往里喂"更聪明的候选"和"更真实的贡献值"，不另起一条决策路。

### 2.1 心事表（即"待办清单"，避开与日程 `agendas` 重名）

- **形状**：`concern = {concernId, source, goal, weight, urgency, deadline}`。`concernId` 由（来源行代号、对象 id）组成，与卷九候选 id 同样稳定，不含序号。
- **目标 `goal` 是结构化条件，封闭几种**：`goal_have`（持有某资源或某类物不少于 q）、`goal_at`（到某地）、`goal_dim`（某维度过某阈）、`goal_obl`（履行某条义务）、`goal_rel`（与某人有某关系）、`goal_made`（做出满足 `matchDim` 的作品，即奇想现有的完成条件）。只读代号与数值，不读文字。
- **来源是数据行 `concern_source`**（形状照 `candidate_provider`）：`{id, goalKind, fromRX, weightRX, urgencyRX, maxConcerns}`。首批来源与读入口：

| 来源 | 读什么 | 生成什么心事 |
|---|---|---|
| 需求 | 卷二十一身体需要亏空、卷二十六需求心理量（经视图输出）、卷六 `unmetSupply` | `goal_have` 某用度类池量 |
| 义务 | 卷六 `obligationsOf(本人)`（债、雇佣出工、租金、婚约、封建契约、人情） | `goal_obl`，`deadline` 取义务窗口 |
| 委托 | 本人已承接的委托（新增读入口，见 §4）；本人发布未了的委托 | `goal_obl` 或"催办/加价" |
| 职责 | 职位行与卷八职责（当家者对组织的缺口：组织的 `unmetSupply`、工程缺工） | 以组织为受益者的 `goal_have` |
| 亲友缺口 | 本人**已知**的亲属、关系人的缺量事件、受伤、被押（卷二十二知情域） | 替别人办的心事；重要度乘亲缘驱力与立场 |
| 愿望 | 本人进行中的愿望实例（§2.5） | 愿望的目标 |
| 日程 | 本人当刻日程槽 | 保持现状的心事（已有 `switchMargin` 承担） |

- **重要度 `weight` 不写死**：= `Σ_d driveWeight[d] × goalContrib[d]`，`goalContrib` 取来源行登记的驱力贡献（需求类直接用 `needSatisfiers()` 那条路径的驱力；义务类用尽责驱力乘违约后果估值，后果读卷六合同种类行的 `breachHandler` 与卷八b 后果估值；亲友类乘 `stance` 归一值）。人格、价值、心情经驱力权重自然进来。
- **紧迫度 `urgency`**：`lookup(rules.concern.urgencyCurve, 剩余时间 ÷ 估计所需时间)`；需求类的"剩余时间"取亏空到下一档的时间（卷二十一病程律可算出越线时刻）。曲线是数据。
- **优先级** = `weight × urgency`，取前 `rules.concern.topK` 条展开（建议 3）。并列按 `concernId` 码序。
- **不存**：心事表是状态的纯函数，与 R26-4.6"想法不落状态"同一口诀。

### 2.2 方法表与多步规划（最小可行形式）

技术参照与取舍：GOAP（目标导向动作规划，前向或后向搜索动作序列）通用但搜索量不可控、难以只读数据行解释；HTN（层次任务网络，SHOP2 一类）把"目标→可选做法→子目标"写成数据，搜索有界、可解释，适合本项目"行是数据、代码不认内容"的规矩；BDI（信念—愿望—意图）提供"意图要坚持、到期复核"的思路，本方案用已有 `decisionCommit` 承担。选 **有界 HTN 式方法表**，不做通用搜索。

- **方法行 `method`**：`{id, goalKind, whenRX, steps: list<step>, drives, costRX}`；`step` 二选一：`{action, slotsFrom}`（卷九动作行）或 `{subgoal}`（又一个 `goal`）。同一 `goalKind` 可有多条方法，彼此是"或"。例：`goal_have(食物)` 的方法有：取储备、自采（卷五取用律）、自制、买、借（赊）、求人给、偷。`goal_have(钱)` 的方法有：出工、卖东西、典当、借、讨债。
- **展开**：对每条前 k 心事，按方法行逐条展开，遇 `subgoal` 且其目标此刻不成立则递归，深度上限 `rules.plan.maxDepth`（建议 3），每层方法数上限 `rules.plan.maxMethods`（建议 4）。每条心事最多 `4 + 4² + 4³ = 84` 个节点，前 3 条心事合计不超过 252 个节点。
- **每条完整做法的估值**：沿链求和代价（钱经 `priceFor`、时间经卷十七行程与动作 `baseMinutes`、风险经 `legalityOf` 与路途风险律、求人的社会代价见 §2.3），乘链上"对方肯"的估计概率，得该做法的期望代价；方法行自带 `drives`（如"偷"给攻击正、尽责负；"求人给"给地位负），人格因此会挑做法：同样缺粮，好面子的先当东西，脸皮厚的先去求人。
- **交给选择器的是第一步**：最佳做法的第一个可执行动作成为一个候选，`contrib` 取**心事**的驱力贡献（不是动作行的常数贡献），`cost` 取整条链的期望代价。这样"去找邻居借米"这个动作的效用里装着"为了不挨饿"。其余原有候选照旧，统一按 R9-12.4 取最大。
- **不存计划**：每个决策时刻重新展开。为防止今天借粮、明天改主意，承诺 `decisionCommit` 加一栏 `concernId`；承诺未到期时，同一心事的新第一步只要还在最佳做法上就续用，换心事仍要越过 `switchMargin`（R9-12.7 原句）。
- **失败的记忆**：被某人拒绝是已有事件（卷九 R9-12.14 :1103 `verb_invite_refused`）；"对方肯不肯"的估计读本人已知事件里该人对本人的拒绝与答应次数乘显著度（卷十八 R18-5.4 的写法），所以被拒过的人下次排后面，不需新状态。

### 2.3 委派：统一成一个"要约"原语

结论：**一个原语，两条路由，若干合同种类**。

- **原语**：向对象提出一份要约 = 对话邀约（卷九 R9-13.1 请求、R9-13.4 出价）＋一份合同草案（卷六 §4.16 的种类行）。对方是 NPC 由 `npcDecision` 答，有席位者开待应答记录（R9-12.15 :1104）。全部已有。
- **两条路由**：知道找谁 → 定向要约；不知道找谁、或定向都被拒 → 发布委托（卷二十四 R24-5.2 :564，NPC 选它的前提是发布者行的 `needRX` 在他视角下成立）。"先找熟人、找不到再贴告示"由方法表的次序与代价自然得出。
- **合同种类区分形式**（都是卷六种类行，代码不分支）：

| 说法 | 合同种类 | 状态 |
|---|---|---|
| 雇人 | `ckind_employment` | 已有（卷六 §4.11） |
| 借粮、借钱 | `ckind_loan`（实物计价按卷六 §4.14 规则 3） | 已有 |
| 以物换物 | 不立长约，`executeTrade` 一笔成交，`offer.give/take` 都是物 | 已有（R9-13.4、卷六 §4.2 规则 8） |
| 求人给、受赠 | 无义务的赠与转移；受赠方立一条人情 | **新增**人情种类 |
| 人情往来、搭把手 | `ckind_favor`（新）：无托管；义务为"债权人日后请求时回帮一次"，额度以工时或估值计；违约不进卷八b 诉讼，只触发立场来源行（失信） | **新增** |
| 公开求助 | 委托（发布者类型行） | 已有 |

- **人情从哪里来**：两条路。①明求：搭把手、受赠时同一事务立 `ckind_favor`。②暗欠：把卷十五 R15-9.6 的 `debtRows`（事件→自动立恩债）**移到卷六或卷十八作为通用行族**，超自然恩债、冤债改为它的几条数据行；"救急""出殡帮忙"这类世俗事件登记同族行即自动立人情。这是删除优先：两套立债机制并成一套。
- **找谁**：候选对象取本人主观视图里已知的人（卷二十二），按"估计肯不肯 × 估计有没有"排序取前 `rules.plan.maxAskees`（建议 3）。"估计肯不肯"只读本人一侧的量：本人对他的立场、两人关系（`related`）、他欠本人的人情（`obligationsOf` 债权方是本人）、被他拒过的次数；"估计有没有"读本人对他财富的外部视角（卷六 `wealth` 可见口径，经卷二十二 R22-1.6）。**不读对方真值**。
- **求人的社会代价**：进 `cost.relation`（R9-12.4 的结构里已有此栏，公式里却没有对应项，见 §7 改卷清单）= 新欠人情的估值 × 本人地位驱力载荷。所以骄傲的人宁可多走路自己做。

### 2.4 性格、记忆、关系喂进打分（"看起来像在权衡"）

| 喂入项 | 进哪一处 | 现有依据 | 新增 |
|---|---|---|---|
| 人格、价值 | 驱力权重 → 心事重要度、方法行 `drives` | R26-9.1 | 方法行带 `drives`，人格挑做法 |
| 心情、压力 | 驱力修正、决策噪声 | R26-9.2、R26-9.3 | 无 |
| 记忆 | 积怨（对提出者）；"肯不肯"估计（对求助对象）；亲友缺口的知情 | R9-12.3、R18-5.3/5.4 | 对"被求者"也读同一套 |
| 关系网 | 立场读数、亲缘驱力乘立场、人情债权债务 | R9-12.3、卷十八 §4.4 | 亲友缺口来源、人情合同 |
| 职业 | 方法可行性（`canOffer`）、出工义务 | 卷十四 PF-6、卷六 §4.11 | 无 |
| 法律 | 底线剔除、风险代价、义务心事 | R9-12.2、R9-12.4 | 无 |

"显得聪明"主要来自三处：心事替代常数贡献（行动有理由）；方法链（会绕路办事）；对不同人求不同事（关系与记忆真起作用）。不靠更多随机。

### 2.5 长期愿望：推广奇想，不另立机件

- **做法**：愿望 = 一条长时限的发作行（卷二十六 §4.5、§4.7 的同一形状）。资格读人格、价值、职业、年龄等（`applies`、`hazardRX`），按危险率抽中（R26-5.3 的骰值键，已登记抽取点），绑定项取目标（R26-5.5），完成条件达成即成功结束（R26-5.6），到期或心灰意冷（`exitOnGateLeave` 读一个"挫败"心理量）即放弃。
- **需要的两处小推广**：①绑定项可取**实体**（某职位、某人、某地、某物），不只是偏好键——取法仍按加权或取顶，权重读本人主观视图里的数值（例：想娶谁，权重读好感；想当什么官，权重读够格程度）；②完成条件除 `exitOnVerb` 外可写一个 `goal`（§2.1 的结构化条件），例如"持有某职位的任职边"。
- 愿望进心事表，经方法表展开；愿望容器的档修正还可抬对应驱力（地位、财富、亲缘），所以有志向的人平时也会多攒钱、多结交。
- **例**：一个有野心的书吏，地位驱力高，抽中"当本县主簿"愿望（绑定到主簿职位行）；心事展开：够格（卷十四技能门槛）→学艺；有空缺→等现任出缺或攀关系（求县令推荐，要约＋人情）；三年未成而挫败心理量越界→放弃，转一条压力想法。

### 2.6 与 R26-4.6"想法不落状态"的关系：哪些必须落状态

判别口诀照台账："能由别的维度算出即派生"（R26-4.6 原句）。

| 东西 | 落不落 | 理由 |
|---|---|---|
| 心事表、优先级 | 不落 | 来源全是已存状态（容器、合同、委托、知情）的函数 |
| 计划（方法展开） | 不落 | 每个决策时刻可重算；成本见 §6 |
| 愿望 | **落**，作发作容器实例（已有存法） | 抽中那一刻带随机与当时情境，事后无法从现状重算；与发作、奇想同类 |
| 承诺（我答应了别人/我认定这件事先做） | **落**：对别人的承诺是合同（已有）；对自己的坚持是 `decisionCommit` 加 `concernId` 一栏 | 合同本来就是状态；坚持防横跳 |
| 人情 | **落**，作 `ckind_favor` 合同 | 是两人之间的义务，必须可查、可转让、可违约 |
| 被拒、被帮的记忆 | 不落新东西 | 已是事件日志与知情 |

所以 R26-4.6 不用改：它管的是"想法"（推心理量的条目），本方案新增的状态都落在已有的容器与合同里，不新增状态顶层键。

### 2.7 确定性与存档

- 心事、方法展开、对象排序全是纯函数；并列一律按代号或 id 码序（与 R9-12.7 同）。
- 随机只有三处，全部是已登记抽取点的五段骰值键（卷二十七 §4.8）：决策扰动（R26-9.4，已有）、愿望抽中与绑定（R26-5.3/5.5，已有键形，需为愿望行登记抽取点代号）、方法内若需打破平局（建议不用随机，用码序）。
- 决策时刻集合不变（R9-12.7），所以"推进 N 天与分段合计 N 天"同结果；方法展开读的价格、路程都按世界日记忆（卷六 §4.6 规则 11 `reachOf` 已是此法）。
- 存档只多两样：愿望容器实例、人情合同；都走已有存法与复演。

### 2.8 离屏粗形态怎样折叠（只给接口，细节留 O1/O2/O4）

| 层 | 形态 | 心事与规划 |
|---|---|---|
| 个体层 | `simform_individual` | 全套：前 3 条心事、深 3 层 |
| 规则层 | `simform_batch`，按层节拍 | 每拍每人只取前 1 条心事、深 1 层（只看直接方法，不递归）；求人只走定向要约、不发委托；名册商贩照卷六 §4.6 规则 3 原判据 |
| 统计层 | `simform_stat` | 无个人心事；阶层行为就是卷六阶层规则（温饱满足次序、阶层就业、统计商贩），即方法表在聚合层的"已折叠版本" |
| 钉住个体 | 照个体层（R27-1.8） | 全套 |

留给 O1/O2 的接口问题（本研究不定）：①折叠时愿望实例去留（建议：钉住者保留；其余丢弃，实体化时按危险率重抽，属"粗算结果约束下推演"的一部分）；②人情合同在折叠后债务人进入聚合体时怎么记（合同是账本级东西，卷六 §4.16 规则 10 当事人终止规则可借用，但折叠不是终止）；③层间一致性（R27-1.9）要求统计层的卷六阶层规则是个体层方法表的加总，需在卷二十七 `observables` 里登记"缺量比例""借贷笔数"等可观测量做漂移检验。

## 三、B2：随机种子能否突破规则、无来由发生（只评估，不定）

### 3.1 现状：规则之内已经有不少"随机"

- 决策扰动：每个候选一份正态扰动，心乱时更大（R26-9.3/9.4）。
- 发作：崩溃、疯狂、灵感、奇想按危险率随机发生（R26-5.2/5.3）。奇想就是"突然想做一件作品"，已经接近"无来由"。
- 脉冲事件：卷二十四 R24-3.6/3.7 :485–:486 的逐日抽取，事件"有登记出处"——每个引出都能追到行、主体、日、骰值键。
- 这些都不动北极星第一条（规则引擎是唯一真相），因为随机只决定"规则允许的几个结果里取哪个"。

### 3.2 几种受控形式与利弊

| 形式 | 做法 | 好处 | 风险 | 动北极星吗 |
|---|---|---|---|---|
| 甲：心血来潮行 | 脉冲行的一种，`scopeKind` 为个体，引出时给此人加一条愿望或短期心事（绑定随机） | 有出处、可追溯；人会突然想去远方、想拜师 | 基率标定不好会显得乱 | 不动：仍是登记行 |
| 乙：冲动发作 | 发作行，期间大幅抬决策噪声（R26-9.3 已允许容器档抬噪声） | 让人偶尔做次优选择，像"一时糊涂" | 太大则行为像乱码 | 不动 |
| 丙：绝境放宽底线 | 极度匮乏或压力档挂修正项，下调本人的底线档阈（`redLineValence` 由规则表改为可修正维度） | "饿极了偷"是因果可讲的 | 需改 R9-12.2 的阈值来源 | 不动：仍是规则，只是规则读状态 |
| 丁：越过前提 | 随机让某动作无视前提或守恒成功（无钱买到、凭空得物） | 戏剧性强 | 破坏守恒与"不伪造前提、成功"（北极星二.4），复演可解释性丧失 | **动**，且冲撞北极星一.4 |
| 戊：无出处的世界事件 | 不登记行、直接写状态 | 无 | 越过唯一写路（卷九 §1.3），破坏审计 | **动** |

评估意见：甲、乙、丙在现有框架内就能做，本质是"随机加在规则选哪条上"，可满足"偶尔无来由"的观感；丁、戊才是真的突破规则，代价是守恒、追溯、北极星一.3/一.4 同时失守，不建议。若亮圳仍想要"规则外的事"，可考虑把它限定成**作者工具里登记的、带标签的神意/天命事件族**（卷二十八作者工具 + 卷二十四脉冲行），仍走 `resolve()`、仍记来源——这其实还是甲。

## 四、B3：任务系统接口（委托系统本身不改）

### 4.1 NPC 怎么用委托通道

- NPC 发布：方法表里的"公开求助"一步就是卷二十四的通用发布动作（R24-5.2）；出价照 R24-5.4 派生。

- NPC↔NPC、NPC↔玩家同一条路（R24-5.11）。

### 4.2 玩家"任务日志"投影：需要补的读入口与字段

卷二十九面板只经登记的只读入口取数，看别人只经带观察者的入口（卷二十九 R29-3.1/3.2 :611–:612）。现有入口（卷二十四 :343）：`commissionView(id)`、`commissionsAt(place)`（真值，只给界面与验收）、`commissionsBy(publisher)`、`commissionBrief`。缺口：

| 需要 | 现状 | 建议补 |
|---|---|---|
| 我听说过的委托 | 无入口；`commissionsAt` 是真值，决策不得用，面板用会泄漏未知告示 | `commissionsKnownTo(observer)`：带观察者，取观察者已知集合里告示动词（`roles.verbs.commissionPosted`）的事件所指委托，返回他所信那一版的条款 |
| 我接下的委托 | `commissionsBy` 只按发布者 | `commissionsTakenBy(entity)`：读合同里本人任承接角色的委托；或统一为 `commissionsOf(entity, role)` |
| 我欠的、别人欠我的（债、人情、雇佣、租约） | 卷六 `obligationsOf` 已有，但未登记为面板可用入口及返回 schema | 登记 `obligationsOf` 的返回 schema（卷二 §2.7） |
| 告示难度与我自己的判断 | `commissionView` 有 `estimate`（发布者视角）；`commissionBrief` 现算承接者视角 | 无需新入口；面板两栏并列 |
| 截止与提醒 | 合同条款里有期限 | 不新增状态；面板行按"剩余时间档"排序与高亮（R29-3.5 的 `bands`） |

日志一行建议字段（全部是代号、id、数值）：委托 id、发布者类型行代号、发布者（按观察者所知显示）、槽位所绑实体、出价（观察者所知版本）、我方角色、合同阶段（仅当事方可见）、期限、告示难度档、我自己的难度档与 `laborCost`、已得放款合计。

注意两点：①交差未获认定时卷二十四只"请求作废"、不发事件（R24-5.7 :569 末句），玩家只能在当步结果里看到拒绝；若要在日志留痕，需在卷二十四加一条事件，**这算改委托系统**，列为拍板项而不擅定。②日志只认当前知情（R29-3.11），被骗、被推翻（R24-5.10）都会随所信改变。

## 五、B4：经济怎样接统一行为系统

### 5.1 边界：自动结算管日常，心事管缺口与抉择

卷六现有的自动结算（温饱满足次序、工作分配、贩运判据、开工）本质上是**习惯性行为**，保留。统一行为系统接在三处：

1. **缺口进心事**：卷六 §4.12 规则 6 的未满足供给量事件 → 需求类心事；方法表接手"借、求、当、偷、多干活"。卷六规则 2 的"④ 赊欠与受赠"在个体层由方法表执行，统计层仍由阶层规则执行。
2. **抉择进候选**：开店、换工、贩一趟货、借钱做买卖、惜售（卷六 §4.5 规则 5 :534 已写"由卷九 NPC 决策读预期决定"）都是心事或候选；卷六的判据函数（贩运判据、开工判据、`landedCost`、`wageQuote`、`priceFor`）作为方法行的代价估计器，不再各自直接"做决定"。
3. **执行只经卷六写入口**：`executeTrade`、`contractStep`、`post`。

需在卷六写清一句：个体层家户的"购买"一步由谁执行（建议：仍由 `settleHouseholds` 自动执行，心事只处理它没满足的部分），避免与 `npcChoose` 重复买。

### 5.2 "接受度"到底是什么、怎样算

卷六里"接受度"只出现在铸币购买力一处（卷六 §4.13 规则 4 :880）：

`coinValue = 内在价值 × lookup(abundanceCurve, 充裕度) × lookup(acceptanceCurve, 接受度)`

- 内在价值 = 金属含量按材料估值之和（规则 1）。
- 充裕度 = 范围内该币存量 ÷（近期日均成交枚数 × `turnoverDays`）；无成交取曲线中点并记缺口。
- 接受度 = "读发行者在当地的正统性数值与法偿地位（卷八、卷八b 的维度）"；发行者为空取 `neutralAcceptance`。**这里只说了读什么，没说怎么合成**（见 §5.4 缺口 1）。

而亮圳问的"对方肯不肯跟我做这笔买卖"，在设计里是另外一套量的合成，不叫接受度：

1. **能不能接触**：同一市场范围或可及范围（卷六 §4.2 规则 1、§4.6 规则 11）；双方能对话（共同语言，卷十四 `sharedLanguage`）。
2. **让不让做生意**：卷十八待遇档 `treatment.access`、`serviceFactor`（卷十八 :140；立场档派生）；组织之间读组织对组织的立场（R18-4.6 :831）。
3. **什么价**：`priceFor(用途, 货, ctx)`，阵营、交情、议价一律只经价格槽修正（卷六 §4.2 规则 7 :421）。
4. **答不答应**：卷九 R9-13.4 :1137——应答者按自己的主观视图对双方物项估值，"所得估值 − 所付估值"取负进 `cost.money`，代入 R9-12.4 算 U；U ≥ 0 答应，否则按 R9-12.6 还价。

所以一笔交易被接受 ⇔ ①②成立且 ④的 U ≥ 0；币的接受度只影响③④里"这枚币值多少"。

### 5.3 非人与非人互相通商：完整例子

（数值全是示意数，待标定；公式逐项照卷文。）

- **双方**：‹组织：蛛人部族›（地下，产蛛丝；当地计价资源 `denomination` = 蛛丝束，卷六 §4.14 规则 2/3）与‹组织：狐妖村落›（山林，产灵芝；计价资源 = 干灵芝片）。两者都没有铸币。交界处有一个洞口集市（卷六 §4.23 :1327 那类多种族集市），两边都在可及范围内。
- **起因（狐一侧的心事）**：村落要修洞府（卷六 §4.19 公共工程同式），需求块要绳索 20 份。村落当家者（职位任职者）的心事来源是"职责"：组织缺口 → `goal_have(绳索类, 20)`，重要度 = 尽责驱力 0.6 × 职责贡献 0.8 = 0.48。
- **方法展开（深 3）**：自制绳索 → 子目标 `goal_have(丝或麻, 足量)` → 本村无丝、麻在可及范围内采不足 → 买丝（洞口集市）→ 子目标 `goal_have(灵芝片 ≥ 报价)`：村仓有 → 可行。另一条"发委托请人送丝"代价更高（出价＋托管）。选"去集市买丝"，第一步动作 = 前往集市并出价。
- **报价**：集市 `marketQuote` 用同一函数（卷六 §4.2 规则 4），丝以集市的计价资源计；狐带的是灵芝，兑换走 `exchangeRate(丝, 灵芝) = priceFor(丝) ÷ priceFor(灵芝)`（卷六 §4.13 规则 6：非铸币用其估值）。设集市估值：丝 5 价值单位/束，灵芝 4/片，汇率 1.25，20 束丝 = 100 价值单位 = 25 片灵芝。
- **蛛人摊主怎样决定（R9-13.4 + R9-12.4）**：狐出价 `offer = {give: 灵芝 30 片, take: 丝 20 束}`。
  - 摊主视角估值：所得 30×4 = 120，所付 20×5 = 100，差额 +20 → `cost.money = −20` → `−w.money × cost.money = −0.01 × (−20) = +0.20`。
  - 驱力项：灵芝对蛛人若是某种需求的满足物（`needSatisfiers()` 读效果族的 `direction`，R26-3.5）才有贡献；设无，0。
  - 关系项：蛛人对狐的好感立场 −10（"戒备"档），`stanceWeights.regard` 0.005 → −0.05。积怨 0。
  - 时间 20 分钟 × 0.002 = −0.04；风险 0；扰动 +0.01。
  - `U = 0.20 − 0.05 − 0.04 + 0.01 = 0.12 ≥ 0` → 答应。成交走 `executeTrade`：货腿、款腿同一笔 `post`（卷六 §4.2 规则 8）。
  - 若狐只出 24 片（96）：差额 −4 → −0.04；`U = −0.04 − 0.05 − 0.04 + 0.01 = −0.12` → 按 R9-12.6，`conditionalStep` 5：所需补价 `ceil(0.12 ÷ (0.01×5)) × 5 = 15` 价值单位 → 还价（`counter`）"再加 15"。折成灵芝 = 15 ÷ 4 = 3.75 → 按最小记账单位向上取整 4 片（卷六 §4.13 规则 5 同式）。
- **如果狐拿人类王国的银币来付**：银币在洞口集市的购买力 = 内在价值 × 充裕度曲线 × 接受度曲线。王国在蛛人地界正统性读数低、无法偿地位 → 接受度低 → 曲线值小 → 同样 100 价值单位要更多枚银币；摊主不另设"拒收"规则，币不值钱自然 U 低。
- **为什么蛛人也会主动来卖**：蛛人一侧的名册商贩按卷六 §4.6 规则 2 贩运判据，集市收购价扣到岸成本仍有利 → 运丝来；规则层与统计层同判据（规则 3）。
- **组织之间的长期往来**：两族当家者谈成一份长期供丝合同（`ckind` 远期，卷六 §4.17），以灵芝计价冻结条款（§4.14 规则 4）；违约走卷八b。两族立场经条约持有边传导（R18-4.4/4.6）。

### 5.4 缺的变量与写法

1. **接受度合成式**：卷六 §4.13 规则 4 只列读数来源，未定公式与取值域；未写读卷八 `legitimacy` 的哪一栏、卷八b 法偿门控（`lawGate`，卷八b R8b-4.7 :727）怎样折成 [0,1]；当地无政体（荒野、非人部落）时取什么。建议：`接受度 = max(法偿折价, 发行者正统性读数归一)`，当地法域无该发行者记录取 `neutralAcceptance`。
2. **主观使用价值**：R9-13.4 只按 `priceFor` 市场口径估物，对方真需要这东西时没有加项。建议：所得物项若在 `needSatisfiers()` 索引里，按满足量给对应驱力 `contrib`。否则缺盐的部落与不缺盐的部落对同一包盐给同一个价。
3. **非铸币市场的还价单位**：R9-12.6 的补价是"钱"，R9-13.4 写成"在对方的 give 上加一笔"，没说以哪种资源加；建议取当地 `denomination` 并按规则 5 向上取整。
4. **组织谁来决定**：组织本身不调 `npcChoose`；当家者以职责来源的心事替组织办事。卷八有当家者（R8-6.4 :812），但"组织缺口 → 当家者心事"的读入口未写。
5. **无共同语言的交易**：对话要约要不要共同语言、手势以物换物是否允许，卷九与卷十四未明说。
6. **`cost.relation` 有栏无项**：卷九候选结构有 `cost.relation`（:1082），R9-12.4 公式里没有它的权重项。

## 六、计算成本（只给口径，细节留 O4）

记 N = 个体层人数，m = 每人每日决策时刻数，C = 每次候选数，D = 驱力数（10），k = 展开心事数，b = 每层方法数，d = 深度。

- 现行管线每日：`N × m × C × O(D + 立场读数)`。
- 加心事与规划后每次决策多出：心事来源 `O(来源行数 × 每行条目)` ＋ 展开节点 `k × (b + b² + … + b^d)` = 3 × 84 = 252 个节点（上界）。
- 示意量级：N = 1 万、m = 10、C = 50 时，现行约 500 万次候选打分/世界日；加规划后上界约 2500 万次节点估值/世界日。按每次 2–5 微秒估，约 1–2 分钟一个世界日，长推进不可接受，必须缓存与降级：
  - **可缓存**：价格、路程、可及范围按（地点、世界日）记忆（卷六 `reachOf` 已是此法）；"对某人肯不肯"的估计按（本人、对方）缓存，以两人间新知事件为失效条件；心事表按卷九 R9-1.12 同法登记"重查集合"，只在所依路径被写时重算；承诺未到期且心事未变时不重展开（预计把展开次数从 m 次降到每人每日 1–2 次）。
  - **降级**：规则层 k = 1、d = 1；统计层不逐人；卷二十七降级阶梯只改层，不改 k、d（R27-3.4 原则：节拍与规律不降，只降层）。k、d 是规则表常数，随世界存档，不随机器变。
- 系统登记：新增"心事与规划"作为卷二十七的一个系统（矩阵行、`coef`、`costSubjects`），与 R27-3.8 `activityRecheck` 同样只加数据行。

## 七、推荐、改卷清单、工作量、拍板清单

### 7.1 主推方案甲：心事表 + 有界方法表 + 要约原语（本文 §2–§5）

- 选择器只一个（卷九），新增的是喂入层；新状态只落已有容器与合同。
- 好处：改动集中、路径无关与确定性不受影响、每个决定能按"心事—方法—第一步—效用分项"解释（便于试玩调参与验收）。
- 代价：方法表要写一批数据行（首批约 30–50 行），标定量大；规划深度有上限，极长链条（十步以上的阴谋）做不出，要靠愿望分阶段。

### 7.2 备选方案乙：显式意图存档（BDI 式）

- 每人存一份当前意图（选定的完整做法及进度），只在失败或到期时重规划。
- 好处：多日计划更连贯，计算更省（不每次重展开）。
- 代价：多一个随人数线性增长的状态；计划与世界变化之间要写失效规则（每类前提都要订阅），与 R26-4.6 的口诀相违；存档变大；折叠时还要处理。只有在 O4 实测证明甲的重展开太贵时再考虑。

### 7.5 需要亮圳拍板的决策（10 条）

1. **待办清单存不存**：派生不存（只存愿望、承诺、人情）／每人存一份。建议：派生不存。
2. **多步规划的形式**：有界方法表（深 3、宽 4）／只补一层前提／通用搜索规划。建议：有界方法表。
3. **委派统一成一个原语吗**：一个"要约"原语（定向对话＋公开委托两路，合同种类区分雇、借、换、人情、搭手）／每种委派各自一套。建议：一个原语。
4. **人情怎么记**：新增"人情合同"并把卷十五事件立债机制改成通用行族／只用好感立场派生。建议：人情合同＋通用行族。
5. **长期愿望怎么承载**：推广奇想发作行／另立愿望表。建议：推广发作行。
6. **日常温饱谁管**：卷六自动结算管日常、心事只接缺口与抉择／全部经心事表。建议：前者。
7. **随机能否突破规则**：只许规则内随机（心血来潮行、冲动发作、绝境放宽底线）／允许越过前提与守恒。建议：只许规则内随机。
8. **玩家日志范围**：只列委托／委托加全部契约义务（债、人情、雇佣、租约）。建议：后者。
9. **交差未获认定要不要留事件**：加一条事件（属改委托系统）／不加，只在当步结果里提示。建议：不加，守"委托系统不改"。
10. **离屏怎样降**：规则层只展开 1 条心事 1 层、统计层由卷六阶层规则代表、愿望折叠去留交 O1/O2／三层都做全套。建议：前者。
