## A. 先读

### A.1 阅读顺序
每个新会话：docs/产品原则.md（北极星，自动约束一切）→ docs/当前状态.md（短交接：位置、下一步、阻碍）→ 本文 A、C → D 里当前阶段那一节 → 与任务直接相关的设计章节和源码。其余按需检索，不通读。

### A.2 权威顺序
用户的新指示 > docs/产品原则.md > 本文 > docs/架构设计/ > docs/当前状态.md > 代码与实际运行结果 > 其他文档。文档与代码冲突时，以实际运行结果为准，并回头改正文档。

### A.3 不可违反
1. 不读 secrets.json；DeepSeek key 只从环境变量。不部署；不动用户原存档（不改、不删存档文件）。
2. 世界内容只写 world/；不手改 dist/；已发布内容只经审批管线。
3. 不降标准、不删失败测试、不放宽断言；保留基线 23 项预期失败。
4. 真实模型如实记账；真实试玩前先向用户报价。
5. 静态提示 ≤12000 字符，基线 10593 不得上涨。
6. 所有测试加 TEMP=F:/dnd-tmp；文件只放 F 盘。
7. 规则只有一版：不做旧存档兼容、不加复演版本标记；同版确定性必须保留。
8. **不再做一次迁移。** 默认在现有架构上渐进演化。大面积改数据形状、重写主路径、全量改存档格式都算迁移：必须单列"为什么非迁不可、代价（天数与影响面）、不迁的后果"，由用户拍板。执行中发现某卡实际要变成迁移，立即停卡上报，不沿原卡扩大。

### A.4 分工
- 用户：产品经理，只看效果、听技术方案对后续迭代的影响。只问真正的产品取舍；技术问题主会话自己定。
- 主会话：协调者兼设计者。拆卡、写卡、审 diff、合并、维护文档、小问题自己修（几十行内、合并冲突、单点回归）。
- 执行者：写大块代码。选谁见 C.2。

## C. 工作方法

### C.1 单位与节奏
- 工作单位是"一个真实行为及其后果闭合"（玩家或 NPC 发起 → 规则裁决 → 账本/持有/义务改变 → 回执 → 知情投影），不是"再建一层接口"。
- 竖切片推进：每阶段都有可玩版本（3–5 条链无 AI 通关 + 一页"现在能玩什么、怎么进入、已知限制"）。
- 单卡 ≤4 会话；更大的派卡前先拆。可并行的卡并行，公共接点（engine、primitives-runtime、transition、注册表、index、客户端回执）每期指定一位所有者，其他卡提需求、由主会话安排串行落地。

### C.2 执行者选择
- 优先 Codex：默认 gpt-6-luna；较难实现 gpt-6.1-sol；方向性/设计性/全批审计 gpt-6-astra（gpt-6.1-astra 不被账号支持）。默认 medium。
- Codex 不可用时：Claude 子代理，默认 Sonnet（effort=medium）；Sonnet 明确做不好的核心难题用 Opus，先告诉用户。
- 换思考档位要开新会话，不在旧会话里切。
- 核心卡（账本、存档、同意与权能、司法、调度、改断言）由另一家审：Codex 写 → Claude 审；Claude 写 → Codex 审（Codex 不可用期间用另一个 Claude 模型，全新上下文、对抗口径）。
- 同时最多 4 路；每路最多 2 个 node 进程；机器内存是真正的瓶颈，以门禁调度器的内存准入为准。

### C.3 派卡
- 写 logs/sessions/<名>.body.md，再 `GATE_BASE=<阶段分支> sh F:/dnd-tools/codex-card.sh <名> <模型> <worktree> [effort] [分钟]`；等卡 `sh F:/dnd-tools/wait-cards.sh <名>`。**派前核对 `<名>.base` 是当前阶段分支**（10-27 s5r1 误用 master，门禁 97 分钟作废）。
- 只读卡（审计、提案、研究）删除 `<名>.wt`，不跑门禁。
- 卡头固定规则在 F:/dnd-tools/card-header.md：进程规则、测试逐文件单进程、输出过滤为摘要、时限、硬约束、交卡前必跑。
- 卡正文必须能独立看懂：改哪些文件、做什么、验收命令、做完汇报什么（改了哪些文件、命令与结果、偏离、未解决；不贴完整代码与日志）。
- 按根因派卡，附主会话分诊结果，不让执行者从头摸底。
- 给用户看：派卡时附 body.md 链接。

### C.4 交卡前必跑（执行者）
1. CORE：tests/engine、tests/storage、tests/plugin。
2. 同步四件套：先 `node tools/export-actions.mjs`，再 actions-catalog、action-registry、advance-registry、arch-metrics。
3. 本卡新增/修改的测试；本卡改到的模块的同名测试；变更负责者点名的跨模块消费者（例：改 storage 加 save-roundtrip，改义务加 advance/transition 的真实消费者）。
4. 受影响的不变量组（tests/invariants/，随阶段建立，见 E）。
5. 禁区自查：docs/架构设计/、已审 W1 骨架 world/design/、dist/、docs/待办.md、docs/问题.md。
6. 结算数值改变须附手算锚点；用被测函数自己算期望值的测试一律打回。
7. **不得重生成金快照**（不设 UPDATE_ADVANCE_GOLDEN）：有意改变时列"字段：旧→新、原因、设计条款"，主会话审核后统一重生成。

### C.5 门禁（r7）
- 候选先冻结再测（临时索引建快照提交）；冻结失败报 INCOMPLETE，不回落到活工作区。
- **验收集合与运行分档是两件事**：卡片显式验收、CORE、同名测试无论快慢都必跑并阻塞；快/慢档只决定排程和时限。
- 慢档：中位 PASS ≥60 秒、只有 TIMEOUT 历史、或跑过阈值的 FAIL，与 slow-tests.tsv 取并集。慢档每 3 卡或 4 小时有一次扫描，调度器必须给它容量。
- 基线缓存按基线提交 + 工具指纹，只替代第一轮；只对首轮基线没 PASS 的文件做独立复跑。
- 失败分四类记录：行为差异、基线同败（同用例同断言）、环境阻断（EPERM 等，由主会话沙箱外补跑）、尚未完成（TIMEOUT/INCOMPLETE 不算 PASS）。"再跑到绿"不是证据；竞态要修根因，不能延长等待或固定幸运种子。
- 测试文件逐个单独进程，不合并进程提速（会掩盖循环导入）。

### C.6 主会话合并前审查
亲自读 diff，逐项勾：按测试打补丁、写死特判、放宽断言、为测试造设施、代填同意、写枚举字面、浮点进状态、直接改旧字段、刷金快照。再跑 tests/overfit-guard。提交用 `sh F:/dnd-tools/guard-commit.sh <worktree> "<msg>" <路径...>`（先跑 overfit-guard，不过拒绝提交）。合入后跑 CORE；合并改到相关接点的，再补受影响项。

### C.7 金快照
只由主会话重生成：先用 F:/dnd-tools/golden-diff/ 在旧、新两个提交上各跑一次推进场景，逐字段比对最终状态；每一处差异都要对上某张卡报告的有意改动与设计条款，才允许重生成，并在提交信息里逐条写明。执行者一律不得刷新。数值纪律改造（W5）这类大批量改值集中在一张卡里做一次。阶段中已批准但未重建的差异记为"待收口"，不得标"全部测试已过"。

### C.8 测试纪律
- 测试前提用真实游戏动作产生（setup.prelude），或用 applyIntentSetup 声明"非考查对象"；不为测试造接口、人物、地点、权限或内容。
- 不变量性质测试用 fast-check，固定种子。
- 意图题集冻结只作体检，如实报数；判分器冻结；每阶段新题由未参与者出。

### C.9 性能
- 以玩家的**安静模式**为准：机器空闲、夜间（用户夜间安静、白天均衡，由用户决定，主会话不改电源模式）。
- 功能门禁与性能门分开：功能门禁里的计时断言失败不作性能结论。
- 性能门：与基线配对测量，不慢于基线 10%；临界补到三对取中位；最终还要满足绝对预算（B14），相对变快不能代替达标。
- "安静模式"要对应到玩家真实运行选项；advance-registry 里删 schedule/tier 的 quiet 夹具不能当性能证据。

### C.10 阶段收口（全部满足）
1. 全量逐文件扫描（并行 ≤3）新失败 0；基线 23 项不动；已知失败登记归属。
2. 慢档一次全绿（或每项已归因到登记的后续阶段）。
3. 性能门（C.9）。
4. 已建不变量组零违例。
5. 本阶段负责的判据 100%；依赖后续阶段的逐条登记到 docs/A3-后续阶段登记.md（含阻塞接点与接收阶段），todo 不能靠挪阶段消失。
6. 可玩版本 + 无 AI 通关。
7. 小规模真实试玩（先报价）；无授权标 PLAYTEST_PENDING。
8. overfit-guard 通过；浏览器测试沙箱外补跑通过。
9. 工作区清理（旧工作树、旧日志、旧脚本）。
干净后用 F:/dnd-tools/land.sh 合 master，登记 PROGRESS / CHANGELOG / 当前状态。

### C.11 停止规则
- 同一步两种实质不同的修法都失败：停下，保留已完成部分，向用户报原因和判断；不换个名字再试第三次（新工具 Jev 类探索除外）。
- 方案确定后不推翻；确需改方案，先说理由等用户同意。
- 新会话或中断恢复：先查 PLAN.md 与各工作树未提交改动/分支，从第一个未完成步骤继续。

### C.12 额度
- Claude 周额度每周四上午约 10 点重置；只要求重置前不用完，按任务价值自行判断用量。派子代理前、收卡时用 get_usage 查。
- 真实模型（DeepSeek）累计授权 ≤100 元，单次 >10 元先报；如实记账。

### C.13 文档
- docs/当前状态.md：短交接（当前位置 / 下一步 / 阻碍），每轮更新；历史移到 PROGRESS。
- docs/待用户确认.md：只放产品取舍，白话，带选项、推荐与对玩家体验的影响。
- 设计改动登记 docs/架构设计/修订记录.md。

## E. 架构修订（定稿口径）

### E.1 修订主体：单一执行点 + 不变量 + 完成语义
1. **同意与权能只有一个入口。** consent()/authority() 是所有动作路径的共同前置；调用方填的 consent/promisor/speaker/force 一律无效。来源三种：本人决策、合法委托/代理、法典或法院强制，各带来源事件；force 进入对抗裁决。
2. **完成四问。** 每个回执说明：是否已提交、结果、是否待决、是否不确定。重试取回原回执，不重复执行。
3. **账本双写有退出日程。** S5 漂移上报 → S6 拒绝漂移 → S7 起逐领域旧字段改只读投影 → 无独立写者才删除。差分推导永久保留为 I16 校验。写回投影不得丢原始事实。
4. **不变量是 CORE 资产**，分阶段建立，阶段收口零违例。
5. **知情双层**：构造按观察者主观视图，出口剥调试字段；规划模型输入按主体隔离。
6. **数值**：持久化只存整数或有理数；超越函数用引擎确定性近似；精度按领域；已签条款冻结。
7. **价格四角色**：成交、估值、已签条款、源汇资格。
8. **等价三类**：精确承诺零容差；分布等价；叙述近似。
9. **钉住看责任**，可释放。
10. **事后结算读行为时快照**，不读当前名册。
11. **配方按材料、工具、工时、技能裁决**，不设估值上限。
12. **声明**：只核新增数据包里进入裁决的声明；行为证据靠十年运行期悬挂扫描。
