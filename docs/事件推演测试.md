# 事件推演测试（盲出题 → 代码核对）

用途：定期检查“世界在真实情境下会不会算出合理结果”。出题者不看代码，只按世界描述提出 20 个跨系统随机事件；核对者对照现有代码（必要时写一次性脚本实际推进引擎）逐条判定。用户要求后续多跑几次，每次一个 run 目录。

## 每轮步骤
1. 出题：主会话派一个不看代码的 agent，提示词固定为 `docs/probes/proposer.prompt.md`（系统清单随新系统合入更新，改动在本文件末尾记一行）。结果存 `docs/probes/run-NNN/events.md`。
2. 核对：交 Codex Sol 或 Claude 子代理（只读主线的临时 worktree，可在 scratch 下写一次性脚本跑 WorldEngine，不改仓库文件），提示词模板 `docs/probes/verifier.prompt.md`，把 NNN 换成本轮编号。产出 `docs/probes/run-NNN/verdict.md`：每个事件逐条预期判定“合理/部分/错误/缺失”，附文件:行号或脚本实测结果，并标出是否属于写死值问题。
3. 主会话汇总：`docs/probes/run-NNN/summary.md` 写通过率（按预期条数计）、错误与缺失清单；能立卡的进 docs/PLAN.md（R 卡或 G 卡），并在下表登记。
4. 不因测试结果修改测试题本身；下一轮换新题，同一题可复跑以验证修复。
5. 脚本化（S0 起）：每轮题目写成 `tests/probes/run-NNN/e*.mjs`（每条预期一个判定函数），`npm run metrics:probes` 出分并对照 `tests/probes/run-NNN/baseline.json`；`npm run test:probes` 中基线为合理的条目必须保持，其余以 target 目标分记录。

## 出题与判分纪律（2026-10-15 用户要求“不要为了提高分数出简单题”）
- 出题者不看代码与设计；主会话不删题、不改题、不挑题，整套原样使用。
- 难度要求写进出题提示：至少一半为刁钻边界（多系统同时转移、时序竞争、身份多次变化、跨政体跨层级、长离屏累积、信息不对称、玩家钻空子、守恒漏洞），每题≥4系统，每题至少一条二阶后果。
- 每轮用从未用于设计或修订的新题；修订者参考过的题只做回归，不计达标分。
- 判分者独立、不看前轮结论；“需补数据但未说明数据位置”不计为自然得出；出现设计矛盾当轮不达标。
- 2026-10-15 起（用户开最高档）：设计判分员与设计修订者固定用 Fable（max），保证各轮口径一致且从严；出题者用常规档以保持视角多样。
