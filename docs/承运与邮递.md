# 承运与邮递

现有 `world_trade` 的 `operation=transport` 办理承运，`operation=post` 办理邮递。不指定资产时，承运入口返回当地当前可用的资产及下一班出发时间。河湾船夫的既有包船设定对应渡口的一艘实船，服务仍要求船夫实际在场、清醒且未被其他事务占用。

`transport` 的 `task=register` 制造资产，`mode` 可选 `cart`、`boat` 或 `pack`。车消耗20份木料和2份铁料，船消耗60份木料和4份铁料；驮队的 `item` 填已有自有动物实例，不生成牲畜。车的完整容量为600公斤、3立方米、4座，船为2400公斤、12立方米、12座；驮畜能力读取当前物种及照料状态。耐久低于60时容量减半，低于25时停用，行驶和火伤会损耗耐久。

资产编号填 `contract`，目的地填 `location`，货物用 `item` 与 `quantity`，乘客用 `service=passage`。不指定 `task` 时询价，`task=book` 才扣实物和运费；`escort` 可指定在场且可行动的护送者，报酬进入原委托托管账，到达后支付。班次按整点出发，一张运单独占其资产直至抵达；报价由实际路线和载荷计算，路段风险参与定价，税费进入当前公账。

`task=lease` 以 `seller` 指定实际在场的契约对方，`consent=true` 表示本次同意，`minutes`、`coins` 分别为租期和租金。玩家资产租给该对方，对方资产租给玩家，租约须覆盖预计承运全程。所有者可在资产所在地用 `task=repair` 消耗木料修复空闲资产。

用 `task=trace`、`business=运单编号` 查询途中路段与停靠记录。封路或桥路损坏会滞留，承运失能同样停止行进，不会按最初估时强制到达；条件恢复后继续行驶。货物抵达而收件人不在场时留在到站账，收件人到场后用 `task=collect` 提取，单件物品的编号和耐久随货转移。

`task=intercept` 要求实际接触运单，仍有可行动护送者时须先处理护送者。被扣运单保留货物与扣货人，不能重复发班；原货主或承运人同地取得扣货人本次同意后，可用 `task=recover` 续运。护送任务沿现有任务记录结算，截获会发布窃取事件，后续追索继续使用既有法律与赏金流程。

邮递的 `buyer` 是收件人，`contract` 是首段承运资产，`item` 是玩家写下的信文。需要接力时，`instances` 按顺序填写后续承运资产，交接站从这些资产的实际所在地派生；末站使用收件人的当前地址，也可通过 `location` 指明已经确认的地址。在场NPC同意代寄时，`business` 填寄信NPC，`consent=true`，`item` 改填其本人持有且允许收件人获知的记忆编号。

信件保存寄出时的陈述，承运人持有封信不会自动知道内容。`task=open`、`business=信件编号` 仅允许实际持信者开封，拆信所得仍是未核实的陈述；`task=lose` 记录现场失件，停止交付。`task=trace` 显示逐站交接和回执状态；收件人离址或无法阅读时等待，回执须另走真实返程，到达寄信人原地址后才确认。

NPC原有携信请求遇到可支付的第三方班次时会购买服务，无服务时保留原携带路径。周贸易公仓遇到可用承运资产时支付运费并采用同一在途系统，粮食批次和货款托管继续由原公仓账结算，承运单只引用该账，不复制粮食。
