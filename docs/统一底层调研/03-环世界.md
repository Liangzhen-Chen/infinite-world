## 1. 摘要

- RimWorld 的内容层是一组 **Def**（XML 对象）：ThingDef、StatDef、StuffCategoryDef、RecipeDef、HediffDef、TraitDef、ResearchProjectDef、IncidentDef、BiomeDef…。C# 类的公开字段就是 XML 标签；`List<T>` 用 `<li>`；指向其他 Def 的字段写 defName；`Class=` 属性选 C# 类（[Def classes](https://rimworldwiki.com/wiki/Modding_Tutorials/Def_classes)）。
- **一切数值走 Stat**。StatDef 定义基值、上下限、取整规则、`parts`（StatPart）、`skillNeedFactors`、`capacityFactors`、`postProcessCurve` 等；求值顺序固定（基值 → 偏移 → 倍率 → 材质因子/品质因子/材质偏移/品质偏移 → 组件 → StatParts → 后处理曲线 → 取整 → 钳位）（[Stat](https://rimworldwiki.com/wiki/Stat)）。
- **Stuff（材质）** 是第二个枢轴：钢、木、布、皮各自有 `stuffProps`（categories、statFactors、statOffsets…）；任何"可选材质"的东西（墙、床、剑、甲、雕像）在生成时乘上材质的因子、加上材质的偏移。板甲的锋利护甲 = 0.9（物品的材质效果倍率）× 材质的 StuffPower_Armor_Sharp（钢 0.9 → 81%，玻璃钢 1.14 → 102.6%，木 0.54 → 48.6%）（[Stuff](https://rimworldwiki.com/wiki/Stuff)、[Plate armor](https://rimworldwiki.com/wiki/Plate_armor)）。
- **Quality（品质）** 是第三个枢轴：七档，每类 Stat 有自己的品质乘数表（市值 0.5–5.0 带上限、护甲 0.6–1.8、近战伤害 0.8–1.65、美观 -0.1–8.0…），由制作者技能滚动（[Quality](https://rimworldwiki.com/wiki/Quality)）。
- **市值不是手填的**：默认 M = (成分市值 + 工时 × 0.0036) × 品质 × 耐久，再取整。用板甲、长剑在钢/玻璃钢/木三种材质上核算，六个 Normal 值与三个 Legendary 值全部与 wiki 一致（第 13 节）（[Market Value](https://rimworldwiki.com/wiki/Market_Value)）。
- **Comp** 把行为做成可插拔积木：`comps` 列表里每个 `<li Class="CompProperties_X">` 给 Thing 挂一个 ThingComp（可燃、可腐、电力、品质、艺术、禁用开关…）；Hediff 也有 HediffComp（SeverityPerDay、Immunizable、TendDuration、Disappears）。Tynan 本人说 comp 是"设计模式，不是正式概念"（[ThingComp](https://rimworldwiki.com/wiki/Modding_Tutorials/ThingComp)、[Mehni gist](https://gist.github.com/Mehni/b3f46b3b08f70cd74746a46f89d2d7a8)）。
- **Hediff** 统一表达伤、病、瘾、义体、药效、环境状态：stages 按严重度分档，每档改能力（capMods）、Stat、疼痛、呕吐等（[Hediff](https://rimworldwiki.com/wiki/Hediff)）。
- 局限：ThingDef 有 200 多个标签，"太多无法逐一记录"；行为真正落在 `thingClass`、`workerClass`、`compClass`、`hediffClass` 指向的 C# 类里；新增标签必须写 C#（DefModExtension）；StatWorker（如 StatWorker_MarketValue、StatWorker_MeleeAverageDPS）是 C# 专门类。

## 2. 数据组织总览：Def 即数据、Thing 即实例

- **映射规则**（[Def classes](https://rimworldwiki.com/wiki/Modding_Tutorials/Def_classes)）：C# `public bool alwaysHaulable;` ↔ `<alwaysHaulable>true</alwaysHaulable>`；只读属性（如 `IsStuff`）不进 XML；嵌套对象（`<stuffProps>` ↔ `StuffProperties` 类）；`List<StuffCategoryDef>` 的每个 `<li>` 是 defName；`List<StatModifier>` 用自定义解析 `LoadDataFromXmlCustom`，写成 `<Beauty>6</Beauty>`（标签名即 StatDef 的 defName）；`<ThingDef Class="MyNamespace.MyDef">` 选自定义 Def 子类；`<thingClass>` 指运行时类。注意：继承不传递 `Class` 属性，子 Def 要重写。
- **类与对象**（[roxxploxx 教程](https://github.com/roxxploxx/RimWorldModGuide/wiki/SHORTTUTORIAL%3A-Things-and-ThingDef-and-Components)）：ThingDef 之于 Thing"类似类与对象"；ThingWithComps 的 `this.comps` 是实例化的组件，`this.def.comps` 是 XML 数据；常量数据通过 `def` / `props` 读，可变数据存实例并由 `ExposeData`/`PostExposeData` 存档。
- **哪些要 C#**（[Essence](https://rimworldwiki.com/wiki/Modding_Tutorials/Essence)）：复用已有功能只要 XML；新行为写 C# 类再由 XML 引用（thingClass / Class=）；改既有 C# 方法用 Harmony 前后插桩。
- **抽象基类链**（[RWModdingResources · abstracts](https://spdskatr.github.io/RWModdingResources/abstracts)）：`BaseWeapon`（Abstract，`ThingDefs_Misc\Weapons_Base.xml`）→ `BaseGun`（加武器类别与科技等级）→ `BaseMakeableGun`（挂到加工台）→ `BaseHumanMakeableGun` → 具体 `Gun_Revolver`。子 Def 继承父的全部值，单值覆盖、列表追加。

## 3. 统一维度一：Stat（StatDef）

### 3.1 定义字段

wiki 用显示名列出 StatDef 的属性（[Stat](https://rimworldwiki.com/wiki/Stat)）：Def Name / Label / Description；Stat Base Value（默认基值）；Stat Minimum / Maximum（钳位）；Round Value、Round To Five Over（>阈值取 5 的倍数）；Apply Factors If Negative；Parts（StatPart 列表）；Post Process Curve；Post Process Stat Factors；Skill Need Factors / Offsets；Capacity Factors / Offsets；Stuff 与 Equipment 的因子/偏移列表；Always Hide、Hide At Value、Show On Untradeables、Scenario Randomizable、To String Style。

### 3.2 求值顺序

[Stat](https://rimworldwiki.com/wiki/Stat) 给出两阶段：

阶段一（未定稿值）：
1. 基值。
2. **偏移（加）**——对 Pawn：技能需求偏移、能力偏移、特质、Hediff 偏移、意识形态/基因/年龄偏移；穿戴装备的 `equippedStatOffsets`。
3. **倍率（乘）**——特质、Hediff 因子、意识形态/基因/年龄因子。
4. **材质步**——× 材质 statFactor（负值默认跳过，除非 Apply Factors If Negative）→ × 品质因子 → + 材质 statOffset → + 品质偏移。
5. 能力（abilities）因子、戒律修正。
6. 对 Thing：Comp 偏移 → Comp 因子 → 物品自身 statFactors → 技能需求因子 → 能力因子（按权重混合）→ 灵感偏移/因子。

阶段二（定稿）：
1. 各 **StatPart** 依次变换。
2. 后处理曲线。
3. 后处理 Stat 因子（Thing 请求时）。
4. 场景因子。
5. 超过阈值取 5 的倍数；按设置取整。
6. 钳到 [min, max]。

### 3.3 StatPart 与 StatWorker

- **StatPart**：挂在 StatDef `parts` 里的 C# 小类，在定稿阶段改值。wiki 的 Parts 属性页列出（节选）：StatPart_Quality、StatPart_Stuff、StatPart_Health、StatPart_Outdoors、StatPart_RoomStat、StatPart_ContentsBeauty、StatPart_BodySize、StatPart_MaxChanceIfRotting、StatPart_EnvironmentalEffects、StatPart_Pollution、StatPart_NoxiousHaze、StatPart_ToxicFallout、StatPart_WornByCorpse、StatPart_IsCorpseFresh、StatPart_WeaponTraitsMarketValueOffset、StatPart_Biocoded、StatPart_Genes、StatPart_Age、StatPart_BiosculptingSpeedFactor、StatPart_GrowthVatSpeedFactor（[Property:Parts](https://rimworldwiki.com/wiki/Property:Parts)）。
- **StatWorker**：整条 Stat 的求值类，默认一个通用 worker，特殊 Stat 换专用类：MarketValue/MarketValueIgnoreHp → `StatWorker_MarketValue`；MeleeWeapon_AverageDPS → `StatWorker_MeleeAverageDPS`；MeleeWeapon_AverageArmorPenetration → `StatWorker_MeleeAverageArmorPenetration`；ShootingAccuracyTurret → `StatWorker_ShootingAccuracy`（[Stat/Core Basics General](https://rimworldwiki.com/wiki/Stat/Core_Basics_General)、[Stat/Core Weapons Melee](https://rimworldwiki.com/wiki/Stat/Core_Weapons_Melee)）。

### 3.4 关键 Stat 定义举例

- **ArmorRating_Sharp**（[Armor - Sharp](https://rimworldwiki.com/wiki/Armor_-_Sharp)）：类别 Apparel；默认 0%；min 0% / max 200%；parts：StatPart_Quality（Awful 60%、Poor 80%、Normal 100%、Good 115%、Excellent 130%、Masterwork 145%、Legendary 180%）、StatPart_Stuff（priority 100，stuffPowerStat = StuffPower_Armor_Sharp，multiplierStat = StuffEffectMultiplierArmor）。Blunt、Heat 同构，Insulation_Cold/Heat 的 StatPart_Stuff 指向 StuffPower_Insulation_* 与 StuffEffectMultiplierInsulation_*，品质因子 80%–180%（[Stat/Core Apparel](https://rimworldwiki.com/wiki/Stat/Core_Apparel)）。
- **StuffEffectMultiplierArmor**（[Armor - Material Effect Multiplier](https://rimworldwiki.com/wiki/Armor_-_Material_Effect_Multiplier)）：物品侧的"材质效果倍率"，默认 0，Always Hide；板甲 0.9、防弹头盔 0.7、简易头盔 0.5、斗篷/夹克 0.3、圆顶帽 0.2、奴隶项圈 0。游戏对三种护甲只用这一个倍率 Stat。
- **StuffPower_Armor_Sharp/Blunt/Heat、StuffPower_Insulation_Cold/Heat**（[Stat/Core Stuff](https://rimworldwiki.com/wiki/Stat/Core_Stuff)）：材质侧的"做成此物时的乘数"，类别"Multipliers when made of this"，默认 0。
- **MarketValue**（[Stat/Core Basics General](https://rimworldwiki.com/wiki/Stat/Core_Basics_General)、[Market Value Ignoring Hitpoints](https://rimworldwiki.com/wiki/Market_Value_Ignoring_Hitpoints)）：worker StatWorker_MarketValue；min 0；Round To Five Over 200；parts：StatPart_Quality（Awful 0.5、Poor 0.75、Normal 1、Good 1.25（+500 上限）、Excellent 1.5（+1000）、Masterwork 2.5（+2000）、Legendary 5（+3000））、StatPart_WornByCorpse（×0.1）、StatPart_IsCorpseFresh（非新鲜尸体 ×0）、StatPart_WeaponTraitsMarketValueOffset（人格武器特质 ±300–1000）、StatPart_Biocoded（×0）、StatPart_ReloadMarketValue、StatPart_Genes（Biotech）、StatPart_Health（曲线 (0,0) (0.5,0.1) (0.6,0.5) (0.9,1.0)）、StatPart_Age（Biotech，人类 (3,0.5) (13,0.9) (18,1)）。
- **DeteriorationRate**：StatPart_Quality（200%→10%）+ StatPart_EnvironmentalEffects（露天 +50%、户外 +50%）+ 污染/毒雾/辐射尘等 Part。**Beauty**：StatPart_Quality（-10%→800%）+ StatPart_ContentsBeauty。**Comfort**：StatPart_Quality（76%→170%）。**Mass**：StatPart_BodySize、_GearAndInventoryMass、_AddedBodyPartsMass 等。**Nutrition**：StatPart_BodySize、_IsFlesh、_IsCorpseFresh、_PlantGrowthNutritionFactor（同上页）。
- **MeleeWeapon_DamageMultiplier**：StatPart_Quality 0.8/0.9/1.0/1.1/1.2/1.45/1.65；**SharpDamageMultiplier / BluntDamageMultiplier / MeleeWeapon_CooldownMultiplier**：默认 100%、min 5%，是"材质乘数"类 Stat（[Stat/Core Weapons Melee](https://rimworldwiki.com/wiki/Stat/Core_Weapons_Melee)、[Stat](https://rimworldwiki.com/wiki/Stat) 的 Stuff Stat Factors 列表：Melee Cooldown、Sharp Damage、Blunt Damage、Insulation Heat/Cold、Armor Heat/Blunt/Sharp）。

## 4. 统一维度二：Stuff（材质）

### 4.1 概念

Stuff 让玩家在制作/建造前选材料，材料属性改变成品；可选材质的东西叫"stuffable"，包括大多数建筑、家具、近战武器、服装。材质分类：Leathery（各种皮）、Fabric（布、羊毛、超织）、Woody（只有木）、Metallic（钢、玻璃钢、金、银、铀、生物铁、黑曜石）、Stony（石砖、玉）、Bioferrite（同时属 Metallic）。配方可接受多类——床接受 Metallic/Woody/Stony，所以木床易燃、石床不舒适、玉例外。Stuff 于 0.7.581 加入，此前"木墙"和"金属墙"要分别定义（[Stuff](https://rimworldwiki.com/wiki/Stuff)）。

### 4.2 材质定义（stuffProps）

`StuffProperties` 字段：`smeltable`、`appearance`、`soundImpactStuff`、`statOffsets`、`categories`（`StuffCategoryDef` 列表）等；XML 形如 `<stuffProps><categories><li>Metallic</li></categories><statOffsets><Beauty>6</Beauty></statOffsets></stuffProps>`（[Def classes](https://rimworldwiki.com/wiki/Modding_Tutorials/Def_classes)）。

### 4.3 物品侧

- `stuffCategories`：接受哪些材质类别；`costStuffCount`：需要多少材质（小体积材质 ×10）；板甲 170、长剑 100、床 45、小刀 30（[Plate armor](https://rimworldwiki.com/wiki/Plate_armor)、[Longsword](https://rimworldwiki.com/wiki/Longsword)、[Steel](https://rimworldwiki.com/wiki/Steel)）。
- 物品的 `statBases` 给"材质效果倍率"（StuffEffectMultiplierArmor、Insulation 倍率等）与非材质量（Mass、WorkToMake、MaxHitPoints 基值）。板甲：Mass 15 kg、HP 290、Armor 倍率 0.9/0.9/0.9、Insulation 冷 1.0× 热 0.0×、WorkToMake 38000 ticks、Crafting 7；长剑：Mass 2 kg、WorkToMake 18000、Crafting 5、三种攻击（柄 9 钝 13% AP 2 s；尖 23 刺 34% 2.6 s；刃 23 切 34% 2.6 s）。

七档：Awful、Poor、Normal、Good、Excellent、Masterwork、Legendary。各 Stat 自己的乘数表（[Quality](https://rimworldwiki.com/wiki/Quality)）：

| Poor | 0.5 | 0.75 | 1.50 | 0.90 | 90% | 100% | 0.80 | 0.90 | 0.88 | 0.92 | 0.95 |
| Normal | 1.0 | 1.00 | 1.00 | 1.00 | 100% | 100% | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 |
| Good | 2.0 | 1.25（≤+500） | 0.80 | 1.10 | 110% | 100% | 1.15 | 1.10 | 1.12 | 1.08 | 1.05 |
| Excellent | 3.0 | 1.50（≤+1000） | 0.60 | 1.20 | 120% | 100% | 1.30 | 1.20 | 1.24 | 1.14 | 1.10 |
| Masterwork | 5.0 | 2.50（≤+2000） | 0.30 | 1.45 | 135% | 125% | 1.45 | 1.50 | 1.45 | 1.25 | 1.15 |

## 6. 统一维度四：Comp（组件）

- **附着**（[ThingComp](https://rimworldwiki.com/wiki/Modding_Tutorials/ThingComp)）：有参数的写 `<comps><li Class="CompProperties_X"><字段>…</字段></li></comps>`；无参数的写 `<li><compClass>MyComp</compClass></li>`；第三方加 comp 用 `PatchOperationAdd`，不确定目标有没有 `comps` 节点时套 `PatchOperationConditional`。
- **生命周期**：Thing 创建 → `PostMake()` → `InitializeComps()` 逐个实例化并 `Initialize(props)`；钩子 CompTick / CompTickRare（须与 TickerType 匹配）、PostExposeData（存档）、CompGetGizmosExtra（按钮）、PostPreApplyDamage（可吞掉伤害）、CompInspectStringExtra（检视文字）、PostPrintOnto / CompPrintForPowerGrid（画到分块图层）、CompProperties.ResolveReferences（参与多阶段加载的引用解析）（[ThingComp](https://rimworldwiki.com/wiki/Modding_Tutorials/ThingComp)、[Mehni gist](https://gist.github.com/Mehni/b3f46b3b08f70cd74746a46f89d2d7a8)）。
- **示例**：CompProperties_Power 按配置实例化不同 comp 类；CompFlickable 挂在电炉上；CompQuality；神经训练器用 TransformLabel；Fire 用 DrawGhost；`<li Class="CompProperties_Forbiddable"/>` 是 Class= 属性的典型用法（[Linking XML and C#](https://rimworldwiki.com/wiki/Modding_Tutorials/Linking_XML_and_C)）；药物 ThingDef 的 `comps` 挂 `CompProperties_Drug`（[Custom Drug](https://www.rimworldwiki.com/wiki/Modding_Tutorials/Custom_Drug)）。
- **注意**：不是所有 Thing 都有 comps（石块不是 ThingWithComps），要 `TryGetComp<T>()` 判空；子 Def 重复定义同一 comp 会被算两次。
- **comp 家族**（[Custom Comp Classes](https://rimworldwiki.com/wiki/Modding_Tutorials/Custom_Comp_Classes)）：HediffComp（挂在健康状态上）、ThingComp、WorldObjectComp、MapComponent、WorldComponent、GameComponent、StorytellerComp——同一个模式在不同作用域复用。

## 7. 统一维度五：Hediff（健康差分）

- **定义**：施加于整身或某部位的修改器，表示疾病、伤、义体、药效、环境状态（[Hediff](https://rimworldwiki.com/wiki/Hediff)）。
- **HediffDef 结构**：`hediffClass`（HediffWithComps、Injury、Hediff_Addiction、Hediff_High、Hediff_MissingPart…）；`stages[]` 按 `minSeverity` 分档，每档 `capMods`（Consciousness/Moving/Manipulation/Breathing… 的 offset）、`statOffsets`/`statFactors`（Pain、Sleep Fall Rate、Hunger Rate…）、`painOffset`、`vomitMtbDays`、`lifeThreatening`、`mentalStateGivers`；`comps[]`：SeverityPerDay、Immunizable、TendDuration、Disappears、DrugEffectFactor、SkillDecay、Discoverable；顶层：defaultLabelColor、isBad、lethalSeverity、initialSeverity、minSeverity/maxSeverity、chronic、makesSickThought、tendable、scenarioCanAdd、removeOnRedressChanceByDaysCurve；`injuryProps`（出血率、每严重度疼痛）、`addedPartProps`（[Hediff](https://rimworldwiki.com/wiki/Hediff)、[Hediffs](https://rimworldwiki.com/wiki/Hediffs)）。
- **实例 Flu**（[Hediffs/Core/Local/Infections/Flu](https://rimworldwiki.com/wiki/Hediffs/Core/Local/Infections/Flu)）：HediffWithComps；initialSeverity 0.1%；lethalSeverity 100%；tendable；makesSickThought；comps：TendDuration（baseTendDurationHours 12，severityPerDayTended -7.73%）、Immunizable（severityPerDayNotImmune +24.88%，immunityPerDaySick +23.88%，severityPerDayImmune -49.47%，immunityPerDayNotSick -6%）；stages：minor（意识 -5%、操作 -5%、呼吸 -10%）、major（minSeverity 66.6%，vomitMtbDays 1.5，-10/-10/-15%）、extreme（83.3%，lifeThreatening，vomitMtbDays 0.75，painOffset +5%，-15/-20/-20%）；removeOnRedress 曲线 0 天 0% → 7 天 50% → 20 天 100%。
- **药物链**（[Custom Drug](https://www.rimworldwiki.com/wiki/Modding_Tutorials/Custom_Drug)）：ThingDef（ParentName=MakeableDrugBase；`ingestible.outcomeDoers` 用 `IngestionOutcomeDoer_GiveHediff` 给定严重度；`recipeMaker` + `costList`；`comps` 挂 CompProperties_Drug）→ HediffDef（`hediffClass` Hediff_High；stages 降痛降意识；comps HediffCompProperties_SeverityPerDay 让严重度随时间下降，`showHoursToRecover`）。1.6 起药物需求改为 HediffDef 根上的 `chemicalNeed`，非药物需求用 HediffStage 的 `enablesNeeds`（[搜索摘录：1.6 Mod Updates](https://rimworldwiki.com/wiki/Modding_Tutorials/RimWorld_1.6_Mod_Updates)）。
- **身体模型**（[Health](https://rimworldwiki.com/wiki/Health)）：能力（Sight、Hearing、Moving、Manipulation、Talking、Eating、Breathing、Blood Filtration、Blood Pumping、Digestion；Consciousness 由疼痛及若干能力推出）由身体部位推导；机械 pawn 用传感器/反应堆等类比部位；疼痛 >10% 影响意识；Moving <15% 倒地；Blood Pumping 或 Digestion 到 0 即死；手术可换器官/装义体。

## 8. 统一维度六：Trait / Gene / Precept——同一出口

- **Trait**：TraitDef 带 `degreeDatas`（同一特质谱的多档）；每档有 label、description、`statOffsets`/`statFactors`、`skillGains`、commonality；社区转录的 Industriousness 谱：Industrious（degree 2，WorkSpeedGlobal +35%）、Hard worker（1，+20%）、Lazy（-1，-20%）、Slothful（-2，-35%），commonality 2；Brawler：Melee +4、Shooting -10、近战命中 +4、持远程武器 -10 心情；Fast walker：移速 +0.2 c/s（[User:Pangaea/Trait test](https://rimworldwiki.com/wiki/User:Pangaea/Trait_test)、[Traits](https://rimworldwiki.com/wiki/Traits)）。特质还能禁用精神状态/灵感、给冥想专注类型、给疾病 MTB（Sickly 30 天），同谱只能持一档。
- **Gene**（Biotech）：GeneDef 带代谢效率（改饥饿率）、复杂度（基因处理器需求与合成时间）、`statOffsets`、能力；分 germline / xenogene / archite；xenotype 打包基因（[Genes](https://rimworldwiki.com/wiki/Genes)）。基因也进入市值：StatPart_Genes（基因数因子 max(3.5−0.5n, 0.5)、archite 因子 1+3a、各基因自身因子）（[Market Value Ignoring Hitpoints](https://rimworldwiki.com/wiki/Market_Value_Ignoring_Hitpoints)）。
- **Precept**（Ideology）：戒律决定对行为的反应，多数"给心情想法、改意见、加 Stat"；meme 解锁戒律/角色/仪式（[Ideoligion](https://rimworldwiki.com/wiki/Ideoligion)）。
- 三者在 Stat 求值顺序里都是"偏移 → 倍率"两步的来源（第 3.2 节：特质、Hediff、意识形态、基因、年龄）。也就是说 RimWorld 没有"特质系统的属性"或"基因系统的属性"，只有 Stat。

## 9. RecipeDef 与 recipeMaker

- **RecipeDef**：与工作台配对把成分变产物；`ingredients` 可按大类（任意肉、任意食物）定义；`fixedIngredientFilter`（硬过滤，不满足的不出现在选料里）；`defaultIngredientFilter`（新账单默认，可改，例如餐默认排除人肉）；未定义过滤器则接受一切（[RecipeDef](https://rimworldwiki.com/wiki/RecipeDef)）。`workAmount`（Smelter 教程示例 1000）；`recipeUsers` 列出能执行的建筑，或由建筑的 `recipes` 列出配方，或在产品 ThingDef 用 `recipeMaker` 从产品侧声明——三种方向都是 defName 引用（[Compatibility with defs](https://rimworldwiki.com/wiki/Modding_Tutorials/Compatibility_with_defs)）；研究门控用 `researchPrerequisite(s)`。
- **recipeMaker 实例**（[Basic Melee Weapon](https://www.rimworldwiki.com/wiki/Modding_Tutorials/Basic_Melee_Weapon)）：`<ThingDef ParentName="BaseMeleeWeapon_Sharp_Quality">`，`costStuffCount 40`，`statBases{WorkToMake 10000, Mass 0.75}`，`equippedStatOffsets{PlantWorkSpeed 0.10}`，`tools[]`（handle Blunt 9 / point Stab 14 / edge Cut 14，cooldownTime 2），`recipeMaker{researchPrerequisite Smithing, skillRequirements{Crafting 2}, displayPriority 409}`。父类 `BaseMeleeWeapon_Sharp_Quality` 提供材质类别、品质 comp、加工台等。
- 要点：配方引用"类别/过滤器/父类"，不点名物品；产物属性在生成时由 Stuff + Quality 算（第 10 节）。

## 10. 行为怎样由维度算出

### 10.1 市值

M = (I + W × 0.0036) × Q × H（[Market Value](https://rimworldwiki.com/wiki/Market_Value)）：I = 全部成分市值（材质则 costStuffCount × 材质市值）；W = 工时 ticks（60 ticks/s；材质的 WorkToMake 因子已乘入）；Q = 品质乘数（Good 以上有绝对增益上限）；H = 耐久曲线（≥90% HP 全额；60%→50%；50%→10%；曲线 (0,0)(0.5,0.1)(0.6,0.5)(0.9,1)）。取整：>200 取 5 的倍数，>10 取整，≤10 保留小数；污秽衣物 ×0.1；生物编码武器 ×0；可装填物减去装填弹药市值。wiki 示例 I=100、W=1200 → 104.32 → 104。核算见第 13 节。

### 10.2 护甲与保暖

护甲 = 物品 StuffEffectMultiplierArmor × 材质 StuffPower_Armor_X × 品质护甲因子，钳 0–200%；逐层从外到内结算。战斗判定：先减穿透，再与 0–100 随机数比——低于剩余护甲一半：完全弹开；一半到全额之间：伤害减半并转钝击；高于护甲：无效。例 90% 护甲对 10% 穿透 → 40% 弹开、40% 减半、20% 无效（[Armor - Sharp](https://rimworldwiki.com/wiki/Armor_-_Sharp)）。保暖 = 物品 Insulation 倍率 × 材质 StuffPower_Insulation（钢 +3 °C、木 +8/+4、布 +18/+18）× 品质保暖因子。板甲（Normal）实测表：钢 81%/40.5%/54%、玻璃钢 102.6%/49.5%/58.5%、木 48.6%/48.6%/36%、铀 97.2%/48.6%/58.5%、金 64.8%/32.4%/32.4%（[Plate armor](https://rimworldwiki.com/wiki/Plate_armor)）。

### 10.3 近战伤害

每种攻击（tools）基础 power × 材质 Sharp/BluntDamageMultiplier × 品质 MeleeWeapon_DamageMultiplier；冷却 × 材质 MeleeWeapon_CooldownMultiplier。长剑：钢刃 23 / 2.6 s；玻璃钢刃 25.3 / 2.08 s（×1.1，×0.8）、柄 8.1（9×0.9）；木刃 9.2（×0.4）；传奇钢刃 37.95（×1.65）；DPS 由 StatWorker_MeleeAverageDPS 从各攻击的 power/cooldown 平均（[Longsword](https://rimworldwiki.com/wiki/Longsword)、[Stat/Core Weapons Melee](https://rimworldwiki.com/wiki/Stat/Core_Weapons_Melee)）。

### 10.4 温度、腐坏、营养

- 温度：每个封闭带顶房间一个温度，户外随纬度/季节/时刻/生物群系；墙、顶、门、通风口控制换热，双层墙更保温；舒适区由服装保暖拓宽，超 10 °C 触发中暑/低温症 Hediff（[Temperature](https://rimworldwiki.com/wiki/Temperature)）。
- 腐坏：食物随温度与暴露腐坏（CompRottable 是实现，但 wiki Food 页未点名）；食物中毒几率受厨师技能与房间清洁影响，FoodPoisonChanceFixedHuman 有 StatPart_MaxChanceIfRotting（[Food](https://rimworldwiki.com/wiki/Food)、[Stat/Core Basics General](https://rimworldwiki.com/wiki/Stat/Core_Basics_General)）。
- 营养：Nutrition 是 Stat，生食 0.05、简餐/盛宴 0.9–1.0；对尸体/动物由 StatPart_BodySize、StatPart_IsFlesh、StatPart_IsCorpseFresh 推（同上）。

### 10.5 房间、美观、劣化

房间 Impressiveness 由 Wealth、Beauty、Space、Cleanliness 合成，弱项权重大、小房间有上限；角色（卧室/餐厅/医院）决定哪些 Stat 生效（[Room stats](https://rimworldwiki.com/wiki/Room_stats)）。物品 Beauty = 基值 × 品质美观因子（雕像的描述由殖民地历史事件生成）（[Art](https://rimworldwiki.com/wiki/Art)）。劣化率 = 基值 × 品质 × 环境 Part（露天/户外 +50%，污染 ×1.5，毒雾/辐射尘 ×3）。

## 11. Def 继承与补丁

- **ParentName / Name / Abstract**（[XML file structure](https://rimworldwiki.com/wiki/Modding_Tutorials/XML_file_structure)）：`Name="X"` 给模板起名；`ParentName="X"` 复制其全部内容再增改；`Abstract="True"` 的 Def 处理完继承后被丢弃，不实例化。规则："列表追加，其他标签覆盖"；`Inherit="False"` 让子标签不取父值（例 `<weaponTags Inherit="False">` 只保留子列表）。ParentName 指向不存在的 Def 会崩；A15 起可跨模组继承抽象 Def。
- **PatchOperation**（[PatchOperations](https://rimworldwiki.com/wiki/Modding_Tutorials/PatchOperations)、[Modifying defs](https://rimworldwiki.com/wiki/Modding_Tutorials/Modifying_defs)）：用 XPath 定点改既有 Def 而不整体覆盖——Add（追加/前置子节点，如 `Defs/ThingDef[defName="Wall"]/statBases` 加 `<Mass>10</Mass>`）、Insert（兄弟前/后）、Remove、Replace、AttributeAdd/Set/Remove、AddModExtension、SetName（改节点名，适合 `statBases/Insulation_Cold → Insulation_Heat` 这类字典键）、Sequence（顺序执行，一失败即停）、Conditional（match/nomatch）、FindMod（按模组名分支）、Test（已过时）。整体覆写 Def 被 wiki 评为"不兼容"：同 defName 后加载者赢。只对 XML 定义的 Def 有效，生成式 Def（肉、尸体）不行。
- **DefModExtension**：给 Def 加新字段的推荐方式，`<modExtensions><li Class="…">`（[Linking XML and C#](https://rimworldwiki.com/wiki/Modding_Tutorials/Linking_XML_and_C)）。

## 12. 系统之间怎样互相引用

```
StatDef ◄── ThingDef.statBases / statFactors / equippedStatOffsets
        ◄── StuffProperties.statFactors / statOffsets           （材质 → 任何 Stat）
        ◄── TraitDef.degreeDatas.statOffsets/statFactors        （特质 → Stat）
        ◄── HediffStage.statOffsets/statFactors/capMods         （健康 → Stat/能力）
        ◄── GeneDef.statOffsets  / PreceptDef / 年龄曲线
        ◄── StatDef.parts[StatPart_*]  StatDef.workerClass[StatWorker_*]
        ◄── skillNeedFactors[SkillDef]  capacityFactors[PawnCapacityDef]
ThingDef.stuffCategories[StuffCategoryDef] ◄── StuffProperties.categories
ThingDef.costList[ThingDef]  costStuffCount  recipeMaker{researchPrerequisite[ResearchProjectDef], skillRequirements[SkillDef], recipeUsers[ThingDef]}
RecipeDef.ingredients.filter[ThingCategoryDef|ThingDef]  products[ThingDef]  recipeUsers[ThingDef]
ThingDef.comps[CompProperties_*]  thingClass[C#]  ingestible.outcomeDoers → HediffDef
HediffDef.hediffClass[C#]  comps[HediffCompProperties_*]  stages.capMods[PawnCapacityDef]
ThingDef.tools[].capacities[ToolCapacityDef→DamageDef]  verbs → ProjectileDef
BiomeDef → PlantDef/PawnKindDef commonality, WeatherDef commonality, disease MTB
FactionDef → PawnKindDef, TraderKindDef(tradeTags) → ThingDef.tradeTags
IncidentDef ← Storyteller(points ← Wealth = Σ MarketValue)
RoomRole ← Buildings; Impressiveness ← Beauty(Stat)/Wealth(MarketValue)/Cleanliness
```

要点：Stat 是唯一的数值汇流点；Stuff 与 Quality 是生成期的两个乘子；Comp/Hediff 是行为与状态的两个容器；一切跨系统引用都是 defName 或 Class 名。市值又把物品、建筑、pawn 折成"财富"，财富再驱动袭击点数——经济、叙事、战斗由同一条 Stat 串起来。

## 14. 局限：仍写在 C# 专门类里的东西

1. **thingClass**：Thing 的运行时行为类（Pawn、Building、Plant、Apparel、各种 Building_X）。ThingDef 有 200 多个标签，wiki 直言"too many to document"，查某标签含义要用 ILSpy 反编译找读取处；`intricate` 标签的行为就在 `SmeltProducts` 方法里（[ThingDef](https://rimworldwiki.com/wiki/Modding_Tutorials/ThingDef)）。
2. **workerClass**：BiomeDef、GenStepDef、StatDef（StatWorker）、IncidentDef、RecipeDef（手术 workerClass）等都靠 worker 类执行；新 worker 必须写 C#（[Linking XML and C#](https://rimworldwiki.com/wiki/Modding_Tutorials/Linking_XML_and_C)）。
3. **StatPart 与 StatWorker 是 C#**：StatPart_Health 的曲线、StatPart_Genes 的公式、StatWorker_MarketValue 的"成分 + 工时"逻辑都在代码里，XML 只给参数（[Market Value Ignoring Hitpoints](https://rimworldwiki.com/wiki/Market_Value_Ignoring_Hitpoints)）。
4. **compClass / hediffClass**：每个 comp 的实际行为是 C#；Hediff 的 Hediff_High、Hediff_Addiction、Injury 各有专门类。
5. **自定义解析**：`LoadDataFromXmlCustom`（如 StatModifier）是反射找到的 C# 方法，结构体不支持（[Linking XML and C#](https://rimworldwiki.com/wiki/Modding_Tutorials/Linking_XML_and_C)）。
6. **新字段需要 C#**：加标签必须用 DefModExtension 或 Def 子类（[ThingDef](https://rimworldwiki.com/wiki/Modding_Tutorials/ThingDef)）。
7. **生成式 Def**：肉、尸体、皮等由代码按动物生成，不能用 XPath 补丁（[Modifying defs](https://rimworldwiki.com/wiki/Modding_Tutorials/Modifying_defs)）。
8. **求值顺序写死**：第 3.2 节的两阶段顺序是引擎固定的，不能在 XML 里调。
9. **无正式 API**：wiki 声明 RimWorld 没有正式 modding API，几乎所有资料由社区整理（[搜索摘录](https://rimworldwiki.com/wiki/Modding_Tutorials)）。
10. **本次没取到的原件**：Core 的 `Items_Resource_Stuff.xml`、`Stats_Apparel.xml`、`MeleeMedieval.xml`、`Traits_*.xml`、`Hediffs_Local_Infections.xml` 原文（无公开 GitHub 镜像可读；数值全部来自 wiki 转录）；TraitDef 字段全表；RecipeDef 完整字段表（wiki 页只写了三个过滤器）。

## 16. 对 infinite-world 的启示（只借鉴架构）

1. **一个 Stat 管线，所有数值都从它出**：定义时给基值/上下限/取整/后处理曲线，求值时按固定顺序叠加来源（特质、状态、装备、材质、品质、环境）。特质/基因/状态/戒律就不再是"系统"，只是 Stat 的来源表。
2. **把"材质"和"品质"做成两个独立乘子**：成品不写数，成品只写"材质效果倍率 + 材质类别 + 工时 + 用量"，材质写"做成此物时的乘数/偏移"，品质写"每类 Stat 的档位表"。这样 N 种物品 × M 种材质 × 7 档品质不需要任何逐一定义，而且市值能从同一份数据算出来（第 13 节证明公式自洽）。
3. **市值作为全局汇流**：物品/建筑/人物的市值相加得财富，财富驱动袭击、任务难度、心情。一个 Stat 把经济、叙事、战斗耦合在一起，这是"底层统一才能让系统互相对话"的范例。
4. **Hediff 式的"状态容器"**：伤、病、瘾、义体、环境都用同一结构（分档 + 每档改能力/Stat + 可插拔 comp），再由 Health 把部位能力推成意识/移动/操作。我们的人物状态可以照此只留一种容器。
5. **Comp 是行为积木，不是继承树**：可燃、可腐、电力、品质、艺术各是一个 comp；任何实体按需挂。继承只用于"数据默认值"（ParentName/Abstract），行为靠组合。
6. **引用靶向类别而非个体**：配方成分用过滤器/类别，材质用类别，商人用 tradeTags，建筑用 recipeUsers；派生出来的新物品自动落进这些集合。
7. **补丁优先于覆写**：XPath 定点修改 + Inherit="False" + 列表追加规则，让多来源数据能叠加而不是互相覆盖——对我们的"规则层一版、派生优先"原则是现成参照。
8. **教训**：RimWorld 的 Stat 求值顺序、StatPart、StatWorker 全在代码里，XML 只能给参数；ThingDef 标签多到无法文档化；没有正式 API。我们应把"求值顺序"和"Part 组合"也做成数据，并对每个可写字段保留一份可自动生成的字段表。
