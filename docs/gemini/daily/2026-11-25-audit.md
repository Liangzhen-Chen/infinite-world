## 三、追加评估：派活两方案对比（A 内置子代理 vs B `orca agent launch` 独立工作树会话）

> 应亮圳 2026-11-25 12:32 伦敦追加要求（李白 `msg_f4a7d4f5a344`），结合本仓实测 CLI 能力（`orca agent launch --help`、`orca worktree create --help`、`orca terminal create --help`、`orca agent installed --json`）与现行额度裁定（`CLAUDE.md:16-19`、`K1125-P4`、`tools/dispatch/dispatch.mjs`）给出独立评估。

### 3.1 核心结论（先说推荐）

1. **A 与 B 直接二选一：B 明显优于 A**（写代码、出题、审卡三大主力活，A 绝不适合，B 在分支隔离、防遗忘、可追查、多卡并行上全面压倒 A）。
2. **结合本项目额度硬红线，必须点破裸 B 的实测隐患并采用「B 的 API 可见化落法（B'）」**：
   - 经实测 `orca agent launch --help` 与 `orca orchestration worker-start --help`，**两者都没有 `--env`、没有 API Key 注入、也没有 `--max-budget-usd` 参数**；本机默认 `--agent claude` 启动的是交互式 Claude 会话，**默认依然吃 Claude Ultra 会员额**，且无法切到 DeepSeek API（`deepseek-flash`），还会绕过 `dispatch.mjs` 的采样温度 `0.0`、三方模型族硬核与 `.dispatch-receipt.json` 记账。
   - 因此，本项目写码/出题/审卡的**最优落法是 B'**：用 `orca worktree create --setup skip`（**不带 `--agent`**）在独立分支建受 Orca 托管的工作树 → 再用 `orca terminal create --worktree <selector> --title "<卡号|模型>" --command "node tools/dispatch/dispatch.mjs ..."` 在 **Orca 可见终端标签页** 里拉起无头 API 执行。它同时吃到了 B 的全部可见/隔离/抗失忆/可追查红利，又 **100% 守住“写码/出题/审卡只花 DeepSeek API + Claude API、零耗会员额”** 的底线。
   - **裸 `orca agent launch`（B 原版）仅适合两类场景**：① 启动非 Claude 会员额的独立席位（如 `--agent antigravity` 做架构复审、或已显式绑定 API 计费的 `opencode`）；② 若亮圳专门拍板对极少数高难度跨卷卡特许动用 Claude 会员额开独立会话。

### 3.2 四维度硬对比（A vs 裸 B vs 推荐 B'）

| 维度 | 方案 A：主会话内置子代理（`Agent`） | 方案 B（裸）：`orca agent launch` 独立工作树会话 | 推荐方案 B'：Orca 独立工作树 + `orca terminal create` 跑 `dispatch.mjs` |
|---|---|---|---|
| **额度与成本** | **差（撞红线）**：直接烧主会话同一个 Claude Ultra 会员额，无法走 DeepSeek API，违背亮圳 11-24 原话『主会话仅调度 不允许派任何会员额度』（且当前已被 `K1125-P4` 禁用）。 | **有隐患（默认仍撞红线）**：`--agent claude` 无 `--env` 隔离，默认仍烧 Claude 会员额，不能派 DeepSeek API，无自动预算/收据记账；仅对 `antigravity` 等非 Claude 席位安全。 | **最优**：写码走 `deepseek-flash`（几毛钱/卡）、出题走 Haiku API、审卡走 Sonnet/Opus API，**零占会员额**，天然锁温度 `0.0`、三方模型族互异与收据记账。 |
