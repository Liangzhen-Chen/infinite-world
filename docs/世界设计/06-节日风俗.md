## 0. 一句话

节日、婚丧、成年礼、禁忌都是**同一种东西**：文化记录里的一条"风俗条目"（custom entry），由历法窗或人生事件触发，经现有仪式动作形状（action-rite.mjs）与节日运行时（festival.mjs）执行，消耗真实物资、改变立场与知情、占用日程。风俗与法律的分界只有一条：**违犯风俗产生 `slight` 事件（丢脸、被排斥），不产生罪名**；风俗被反复以同一方式裁断后才沉淀成法（07）。

## 2. 风俗条目：统一数据形状

### 2.1 新文件 world/lore/customs.json（风俗；与 07 的 world/law/customs.json 习惯法条目是**两个文件**，前者违犯只丢脸，后者违犯进案件）

```json
{
  "$schema": "lore/customs@1",
  "entries": [
    {
      "id": "custom:civic:tea_first",
      "culture": "culture_civic",
      "kind": "hospitality",
      "name": "客来先茶",
      "trigger": {"event": "guest_arrives", "roles": {"host": "resident", "guest": "visitor"}},
      "expect": {"actor": "host", "action": "offer", "goods": "goods:tea", "withinMinutes": 15},
      "counterExpect": {"actor": "guest", "action": "accept", "orElse": "slight:refuse_hospitality"},
      "onObserve": {"met": {"standing": {"holder": "guest", "target": "host", "delta": 2}},
                    "missed": {"slight": {"id": "slight:no_tea", "severity": 1, "spreads": true}}},
      "exempt": [{"when": "mourning(host)"}, {"when": "goods_unavailable(goods:tea, place)"}],
      "sources": [{"work": "东京梦华录", "note": "待客先茶后酒；只作合理性参照"}]
    }
  ]
}
```

字段：
- `kind` 枚举：`festival`（年度）、`rite_of_passage`（出生/成年/婚/丧/寿）、`hospitality`（待客）、`greeting`（称谓见面）、`gift`（送礼与回礼）、`seating`（座次）、`taboo`（禁忌）、`mourning`（守丧）、`calendar_duty`（周期义务：祭灶、祭祖、守夜）。
- `trigger`：事件族（见 §2.3 列表）或 `window`（01 §3.2 `windows[].id`）。
- `expect` / `counterExpect`：对哪一方期待哪个注册动作（verbs.json 已有 `offer`/`accept`/`give`/`greet`，无则按 06 §6.4 登记为原语模板，无需处理器）。
- `onObserve.met/missed`：`standing`（走 adjustStanding）、`slight`（§4 新事件族）、`rumor`（festival.mjs runtime.effects 已有形状）、`obligation`（义务，如回礼 `promise`）。
- `exempt`：RX 谓词列表；`mourning(x)`、`goods_unavailable(goods, place)`、`stranger(x)`（外来者首次不计，读 01 §4.7 aff）。
- `sources`：出处（可空；只是合理性参照，不绑时代）。

加载校验：E-CUSTOM-CULTURE（culture 存在）、E-CUSTOM-GOODS（goods 词存在于 tags.json）、E-CUSTOM-TRIGGER（事件族在 §2.3 清单内）、E-CUSTOM-WINDOW（window 在该文化 `windows` 内）。

### 2.2 festivals.json 每条新增/调整字段（现有 24 条字段全部保留）

```json
{
  "id": "festival_lantern_capital",
  "culture": "culture_civic",
  "trigger": {"window": "window:lantern"},
  "calendar": {"month": 1, "day": 15, "durationDays": 1, "marketDay": true, "rule": "annual_nomination_with_conditions"},
  "economy": {
    "demandSpike": [{"goods": "goods:lamp_oil", "multiplier": 3, "daysBefore": 5},
                    {"goods": "goods:paper", "multiplier": 2, "daysBefore": 10}],
    "laborDemand": [{"work": "灯匠", "workers": 6, "daysBefore": 10, "wageMultiplier": 1.2}],
    "marketClosed": false,
    "feeToHost": {"goods": "coin", "perAttendee": 0}
  },
  "social": {"courtshipBonus": 0.05, "giftExpected": null, "disputeForum": false},
  "rite": "rite:lantern_release"
}
```

- `trigger.window` 有则优先于 `calendar`（01 §4.6 已定）；`calendar` 保留作回退与旧存档等价。
- `economy.demandSpike`：进入 15 §15.2 "预期需求（季节、疫情、工程材料）"项——market.mjs:156–220 `stockSupply` 的 `demand` 现在 = max(货架上限, 个人需求+保留+承诺)；新增一项 `festivalDemand = Σ 命中节日 × multiplier × 近期日需求`，在 `daysBefore` 窗内生效。**不写新存储**：从 festivalCalendar 与当前分钟派生。
- `economy.laborDemand`：进 labor-market.mjs:71 `laborOffers`，owner = `runtime.host`（节日主办人钱袋/组织公库出钱；现有 :86 "balance<d.wage return" 保证付不起就不招）。
- `social.courtshipBonus`：npc-life.mjs:372 `marriageChancePerDay` 当日乘 (1+bonus)；`disputeForum: true` 表示该节日是口证/合议日（翡翠嗅迹日、草原帐会）——07 的 oral 层案件在此日开庭。
- `rite`：引用 world/actions/*.json 中带 `rite` 块的动作 id（13 §13.5）；节日当日由 host 发起，参加者为 roles。

## 3. 人生礼仪（rite_of_passage）

### 3.1 通用规则

每种礼仪是一个带 `rite` 块的动作（13 §13.5 形状，action-rite.mjs 直接执行），文化记录经 `customs.json` 指定**本文化用哪个 rite、谁主持、谁必须在场、花什么、多久**。同一 rite id 可被多文化引用；文化差异落在 `stages[].materials`、`roles`、`officiant`、`window`，不另写代码。

```
执行序：trigger 事件 → 查当事人 culture(x)（01 §4.1）→ 取该文化 kind 匹配的 custom → 创建 rite project（action-rite.mjs:239–241）
     → 各阶段按 window/materials/roles 结算 → 完成：onObserve.met；超期未办：onObserve.missed（slight + 13 §13.7 未安息路径）
缺省：文化记录缺该 kind 的 custom → 加载期错误（01 §6.5 纪律），不运行期回退
```

### 3.2 成年礼（coming_of_age）

- 触发：`npcIsMinor` 由 true 变 false 之日（rules.npcLife.adultAge 现为全局 18 → 改为文化记录 `adultAge`，缺省列入 01 §3.2 必填；现有存档所有居民都是 culture_river → 填 18 等价）。
- 效果（数据）：开立 `citizen_of`/`resident_of` 资格（governance.resident/citizen 现有）、可婚（marriageBlocker 现读 adultAge）、可入职（professions entry）。**东陆志怪圈**另加"课试"：education.examinations 现有 18 条全是乡试式，改为文化记录 `comingOfAge.exam: "exam_civic"`（可空）；通过与否不改成年事实，只改 `rank` 候选（H8 阶层流动的入口）。
- 首版实例（每圈 ≥1）：

| 圈 | id | 阶段 | 材料（goods） | 主持/在场 | 出处（合理性） |
|---|---|---|---|---|---|
| marches | rite:first_furrow 开犋礼 | 1 阶 120 分钟，`window: day` | goods:grain_oat 2 | 户主 + 邻户 1 | 农耕社会成年与分灶（culture_river.facts.family "成年子女可分灶"） |
| eastern | rite:capping 冠笄礼 | 2 阶（告祖 60、加冠 60） | goods:cloth_hemp 1、goods:wine_grain 1 | 父系尊长 + 宾 1 | 《仪礼·士冠礼》结构（ctext.org），只取三加之形 |
| western | rite:first_oath 初誓 | 1 阶 60，`window: day`，地点 temple | goods:candle 1 | 堂区牧者（祭司变体，09） | 中世纪堂区坚振与成年誓（Keith Thomas《Religion and the Decline of Magic》第 2 章） |

### 3.3 婚（betrothal → wedding）

现状 marry 一步到位、无财产流动。改为两步，均为数据：
- `betrothal`：courtship 满 `days` 后先创建 `promise` 义务（obligations.json 现有种类）：双方户主互为债务人/债权人，标的 = 文化 `marriage.transfer`（见下），期限 = `betrothalDays`（数据，首版 30–90）。
- `wedding`：期限内举行 rite；完成才写 `state.family.marriages`（npc-life.mjs:291 原逻辑移到 rite 完成回调）；聘礼/嫁资按 `marriage.transfer` 真实 transfer（守恒，走 ledger）。
- 文化记录新增：

```json
"marriage": {
  "form": "monogamy",                 // monogamy | polygyny(maxSpouses) | walking(不同户、不共财)
  "residence": "patrilocal",          // patrilocal | matrilocal | neolocal | natolocal(各留原户)
  "transfer": [{"from": "groom_household", "to": "bride_household", "goods": "goods:sheep", "qty": 9, "kind": "brideprice"},
               {"from": "bride_household", "to": "couple", "goods": "goods:cloth_wool", "qty": 4, "kind": "dowry"}],
  "betrothalDays": 60,
  "forbidden": ["same_clan", "within_mourning"],
  "rite": "rite:wedding_steppe",
  "divorce": "mutual"                 // mutual | husband_only | council
}
```

- `residence` 决定婚后 `resides`/`household_member` 变化（npc-life.mjs:289 现用 `households:[ha,hb]` 并列，不动；新增迁户事件按 residence 执行；`natolocal` 对应翡翠"血缘家户与劳动家户可不同"）。
- `form: polygyny` 时 marriageBlocker 的"已有在婚配偶"检查改读 `maxSpouses`；**现有存档全是 culture_river monogamy → 行为不变**。
- `forbidden.same_clan` 读 07 的 clan 条目（家法层）；`within_mourning` 读 §3.4 守丧状态。
- 首版实例：marches `rite:wedding_hearth`（共灶：双方户各出 goods:grain_oat 1，见证 2 人）；eastern `rite:wedding_six`（三阶：纳采/亲迎/合卺，goods:wine_grain、goods:cloth_silk 作聘，patrilocal，《仪礼·士昏礼》六礼只取形）；western `rite:wedding_church`（temple，牧者主持，dowry 以 goods:cloth_wool，中世纪英格兰婚姻须教堂门前公证——Michael Sheehan《Marriage, Family, and Law in Medieval Europe》第 3 章）；steppe `rite:wedding_tents`（brideprice 以 goods:sheep 计，patrilocal，帐会见证）；canopy `rite:wedding_branch`（natolocal，记名树下互记名，无财产转移）。

### 3.4 丧（death → burial → mourning）

- 触发：recordEntityDeath（npc-life.mjs:561）发出 `death` 事件后，按死者 culture(x) 取 `burial` custom；01 §3.2 `burial{deadlineDays, riteFamily, rebirth, ancestorCult, ancestorUpkeepDays}` 已定形。
- 流程：`deadlineDays` 内由继承人/户主发起 `rite:funeral_*`（主祭资格读持有：祭司/僧侣/道士/殓葬师变体，13 §13.6）；完成 → 死者 `afterlife=rested`（13 §13.7）；超期 → 未安息路径（13 §13.7，由 04/14 细化）+ 家户 `slight:unburied` 严重度 3。
- 守丧：rite 完成开立状态 `mourning`（statuses.json 新增，duration = `mourningDays`）；期间 `cuisine.taboo[when:mourning]`（01 §3.2）生效、不婚、不赴宴（festivalScheduleAt :221 跳过）、服色 `dress.mourning`（13 文档）。
- 祭祖：`ancestorCult:true` 的文化，葬仪完成同时开立 `upkeep` 周期义务（obligations.json 现有种类）：债务人 = 户，标的 = `goods:incense` 1 / `ancestorUpkeepDays`，汇 `sink:consume`；断祀 N 期 → 13 §13.7 饥渴亡魂。这是 00 §D8 "家家有神龛"的经济实体。
- 墓地：建筑类别新增 `grave`（locations purpose），由 05 文档的场所密度一并生成（shrine 同级）；无墓地文化（草原、林冠）`burial.disposal: sky | tree | river` 不建实体，只留 `mark:memorial`（现有 mark）。
- 首版实例：marches `rite:funeral_furrow`（土葬，deadline 3，mourning 30，goods:cloth_hemp 1）；eastern `rite:funeral_seven`（土葬，deadline 7，mourning 49 并七七祭，ancestorCult true、upkeep 15 日，goods:incense、goods:paper_money；《朱子家礼》丧礼章只取七七与祭祖之形）；western `rite:funeral_parish`（教堂墓地，deadline 3，mourning 40，牧者主持，goods:candle；Lecouteux《The Return of the Dead》第 4 章死者固定归期对应 `window:dead_night`）；steppe `rite:funeral_sky`（disposal sky，deadline 2，mourning 7，无墓；参照《元史·祭祀志》简述，游戏内原创）；canopy `rite:funeral_leaf`（disposal tree，记名树刻名 = `mark:memorial`，mourning 20；被遗忘 = 嗅迹亡魂，01 §2.5）。

### 3.5 出生与寿

- 出生：npc-life.mjs:325 入户改读文化 `descent`（01 §3.2）：patrilineal → 父户，matrilineal → 母户，bilateral → 婚姻 `residence` 所在户，household_of(x) 指定。**现有 culture_river 填 bilateral + 现有 residence 等价于"母亲所在户"→ 不变**。出生第 N 日 `rite:naming_*`（命名礼，命名规则读 cultures.naming 已有）。

## 4. 风俗失礼：`slight` 事件族（F6 的实现）

```
slight 事件 = {kind:'slight', id, actor, offended:[...], witnesses:[...], severity:1|2|3, culture, source: custom id, spreads: bool}
后果（全部走现有机制，不新增罪名）：
  立场：对每个 offended 与 witnesses 中同文化者 adjustStanding(holder, actor, −k·severity)，k = 文化记录 `slightStandingPerSeverity`（首版 3）
  传闻：spreads → rumor（festival.mjs runtime.effects.rumor 同形），salience = severity
  衰减：按 balance/social.json halfLife.class（severity 1 → pleasantryDays 30；2 → favorDays 180；3 → graceYears 10）

```

## 8. 边界情况

1. **混居与跨文化婚**：双方 culture 不同 → 取 `marriage.rite` 时按 01 §4.7 aff 高的一方？不：按**婚后居住户的文化**（residence 决定），另一方家户可举行自己的 rite 作第二阶段（可选 custom `kind:'rite_of_passage', second:true`）；聘礼/嫁资按各自文化 transfer 的交集，缺的一方不转（不伪造同意）。
2. **外来者失礼**：severity × (1 − aff)；首次来访 `stranger(x)` exempt 列出的条目不计。
3. **守丧中的节日**：festivalScheduleAt 跳过；玩家强行参加 → `slight:feast_in_mourning` 2。
4. **物资缺货**：hospitality 的 goods 本地不可得（01 §4.8 available=false）→ exempt，不算失礼；替代品由 `cuisine.hospitality.offer` 列表顺序取下一个。
5. **节日取消**：现有 `annual_nomination_with_conditions` 条件不满足（festival_ditchmeal "修渠验收通过才开灶"）→ 不举办，不扣物资（festival.mjs runtime.cancellation 现有）；demandSpike 仍在节前出现（人们备货）但节后无消耗 → 价格回落更慢，这是真实后果。
6. **玩家无文化记录字段**：01 §6.4 建档出身；旧存档 = culture_river。兽裔出身**首版开放**（李白决定，亮圳未特别要求），由数据开关 `rules.levels.initial.openOrigins.includeMonsterSocieties: true` 控制，关掉即只剩人类文化；开放时玩家按 culture_beast 的 greeting（嗅布）行事才不失礼，关闭时兽裔礼仪只影响 NPC 一侧。
7. **怪物社会 8 个小文化**（无节日）：首版各给 1 个节日 + 待客 1 条（由其 facts 散文改写，03 文档确认），否则 remote-generation 的 festival_host 无物可办。
8. **闰月**：calendar.json 闰月在 6 月后、`obligationsSkip:true`；周期义务（祭祖、供食）在闰月跳过一次是现有行为，不改；固定日节日不在闰月出现（月 id 不同）。
