### 2.3 成本可见（产品原则三.6"如实记账"延伸到玩家）

- 设置页与回合尾显示：本回合 / 今日 / 本局花费（读 model-usage.jsonl 的 measured costUpperYuan）。

### 2.4 预留回收规则（修 X10）

deepseek-client 在发请求前按"字节 × 未命中价 + max_tokens × 输出价"预留，传输失败也按预留计。保留这个保守口径（用户要求不低估），但加一条：**失败请求的预留在 24 小时后若无 measured 回填，记为 `unknownReserved` 单列**，不并入 spent；报表两栏都给。这与历史账本迁移里"中断的旧请求按未知预留保留"（content-budget.mjs）同口径，只是把它制度化。

## 3. 速度

### 3.1 延迟预算（每回合，玩家感知）

| 档 | 目标（估算，无实测依据，作为设计目标） | 组成 |
|---|---|---|
| T0 | <0.3 秒 | 本地解析 + 预览 + 结算 + 模板 |
| T1 | <1.2 秒 | + Jev 2–3 次串行请求 0.3–0.6 秒（Jev 方案实测 0.15–0.27 秒/次） |
| T2 结算可见 | <1.5 秒 | 理解调用 1 次 + 结算；叙述异步（narrate=llm-async）后到 |
| T2 叙述到达 | <15 秒 | 叙述 + 确定性审查 + 模型审查 0–1 次 |

**原则**：结算与回执**先显示**（模板行），模型叙述后到并替换显示（async 已有机制）。玩家永远不等模型才能继续下一步。

### 3.2 分级超时（修 X9）

| 调用 | 超时 | 超时后 |
|---|---|---|
| R1 理解（选工具） | 20 秒 | 回本地路径（候选/预填构造器） |
| R1 补跑 | 15 秒 | 不再补，发回执模板 |
| R2 叙述 | 30 秒 | 发模板；草稿进异步补审队列（§5.3） |
| 模型审查 | 20 秒 | 视为"未验证"而非 failed→降级（§6.2） |
| R3 规划 | 60 秒（离屏，不阻塞回合） | 回规则排序 |
| R4 档案 | 60 秒（离屏） | polish=pending |
| Jev | 3 秒（Jev 方案 §3.3） | 无 Jev |

### 3.3 并行与缓存

- 理解与场景读取并行（Jev 方案 §4.2 建议）。
- 静态提示区固定（prompt bundle 10587 token，Jev 方案 §四）利于命中缓存（命中价 0.04 vs 未命中 2，差 50 倍）；回合内可变部分放末尾。
- 不做向量检索（盘点 §2：词法检索，无嵌入）；本系列不新增嵌入依赖。

## 4. 可复现与录制回放

### 4.1 旁路记录（sideband）是可复现的全部依据

形状见 AI-04 §6.2。规则：
- 每次模型调用（R1–R4、审查、Jev）必须写一条，含 requestHash、model、response、status、latencyMs、costYuan。
- 存档重放时，调用点先查 sideband[turn].calls[n]：有 → 用其 response；无 → 本地路径。**重放永不发真实请求**（验收 VAI-05-3）。
- sideband 文件可随存档导出（playtest-runner 的 bundle 已"carry every world version they replay on"，同口径）。

### 4.2 哈希范围（I-E 的落地，先核再定）

- 第一步（AI-21 卡）：读 storage.mjs digest 的实际覆盖，列出 prose/provenance/claimVariants/sideband 是否在内。
- 目标：digest 覆盖规则可读状态；不覆盖 AI 文字类字段。若现状已覆盖 prose，用**字段级排除表**（数据 `digest-exclude.json`）排除，不改 digest 算法。
- 验收：同存档 T0 与 T2 回放 30 日 digest 相同（VAI-00-4）。

### 4.3 录制夹具的来源与生命周期（不为测试造东西）

- 夹具 = 真实试玩的 sideband（DeepSeek 主持 + 脚本玩家，或 PT-AI 轨迹），**不手写模型应答**。
- 每份夹具绑定：代码提交、contentHash、模型 id、存档种子。任一变 → 夹具只能做"回放是否仍能结算"的回归，不能做文字质量断言。
- 过时夹具（contentHash 变且回放结算失败）删除并重录，不打补丁改应答。
- 记忆规则"上传副本生命周期"同口径：夹具有本机备份哈希、有取代者、无依赖即可清。

## 5. 降级路径与断点续行

### 5.1 调用结果状态机

每次调用结果 ∈ {ok, timeout, failed(HTTP/格式), rejected(审查 hard), budget(额度尽), nokey}。降级动作表（数据 `degrade-rules.json`，按角色 × 状态）：

| 角色 × 状态 | 动作 | 玩家看到 |
|---|---|---|
| R1 × 任一非 ok | 本地路径（候选 / 预填构造器） | 候选按钮或构造器；一行"理解服务不可用，已用本地匹配" |
| R2 × timeout/failed/budget/nokey | 发模板；草稿入异步补审队列 | 模板叙述（正式） |
| R2 × rejected(hard) | 句级裁剪后发布（§6.3）；全部句被裁 → 模板 | 裁剪后文字或模板 |
| 审查 × timeout/failed | 标 `unverified`，按 §6.2 处理 | 同上 |
| R3 规划 × 任一非 ok | 规则排序 | 无感 |
| R3 档案 × 任一非 ok | polish=pending | 无感 |
| Jev × 任一非 ok | 无 Jev（Jev 方案 §3.3：连续 3 次失败熔断 60 秒） | 一行提示 |
| 任一 × budget | 自动降到不花钱的最近档（T2→T1 若有 Jev 否则 T0） | 设置页标记 |

**不变量 RL-10**：没有任何状态会导致 `abort session`；已 committed 的事件不回滚。

### 5.2 回合内断点

- 预览已出 → 玩家确认 → 结算，这一段**不涉及模型**，断网不影响。
- 预览未出（R1 调用中断）→ 本地路径重新理解同一句话；玩家原话仍在输入框。
- 结算已出、叙述未到 → 模板已显示；叙述草稿若到达且审查通过则替换显示（async 现有行为）。

### 5.3 回合间断点：异步补审与补润色队列

- 队列文件 `<store>/<campaign>/pending-model.jsonl`：`{kind: narration|profile|rumorVariant, turn, draft, reason}`。
- 网络恢复 / 密钥配置后，按队列顺序补做；补审通过的叙述**只替换显示层**（sideband.narration.published 与界面），**不写事件、不改 digest**。
- 【待定·亮圳】P05-1：是否允许"事后替换已显示的模板叙述为模型叙述"。推荐：允许，但在该条叙述旁标一个小记号（"已润色"），不覆盖玩家已经读过的历史滚动区之外的内容。不选的代价：断网一次后整段历史永远是模板，且草稿白费。
- 队列上限：每局 ≤200 条，超出丢弃最旧（草稿不是真相）。

### 5.4 整场级：换模型与断网

- 换模型（换 key、换模型 id）：同存档直接继续；sideband 从此记新 model；无需迁移。旧回合回放仍用旧 sideband。
- 断网：全部角色进入 nokey 等价状态；设置页显示 T0 行为；恢复后自动回到配置档位，不需重启。
- 密钥失效（401）：同 nokey，提示一次。

## 6. 事故逐条修复设计

### 6.1 X1 审查拒绝整场中断 → "永不停场"不变量

10-15 已修（记失败、继续、按比例统计）。本册把它写成三条可验收规则：
1. finishContractTurn 的任何 throw 只影响本回合文字，由 publishedTurnText 降级链兜住（turn-contract.mjs:8–13 已有），**调用方不得因 review 结果中止会话**（grep playtest-runner、runtime.js 无 `stopOnFailure` 基于 review 的分支；runner 的 stopOnFailure 只用于断言失败且默认 false）。
2. 回合记录 `turnOutcome ∈ {published, trimmed, template, failed}`，试玩报告按比例统计（≥90% 指南口径保留为观测，不作停场条件）。
3. 验收 VAI-05-6：注入 20 次 hard 拒绝，整场继续，committed 事件数不减。

### 6.2 X2 网络中断 = 叙述降级 → 区分"未验证"与"有问题"

现 canCommit 把 `review.model.status==='failed'` 当成不可提交。改为三态：

```
localReview = 确定性检查（时间/地点/账本/知情/代理/命名/尾注 + 数字出处 + 决定一致）
modelReview ∈ {passed, serious, failed/timeout}
publish =
  localReview.serious            → 句级裁剪（§6.3）
  modelReview = passed           → 发布
  modelReview = serious          → 句级裁剪
  modelReview = failed/timeout   → 【待定·亮圳】P05-2 两种做法：
        A（推荐）：本地审查全过 → 发布，标 unverified（事件流小记号），草稿入补审队列，补审 serious 则事后裁剪显示
        B：发模板，草稿入补审队列，补审通过后替换显示（§5.3）
```

推荐 A 的理由：本地确定性审查经本系列加强后（数字出处、决定一致、时间地点、知情）已能堵住盘点 §2 举的全部实例（"一堂八铜""十二点开秤"都是数字无出处）；模型审查主要抓"编造非数字事实"，这类在 unverified 标记 + 事后裁剪下风险可控。不选 A 的代价：网络抖动一次就是一段模板，与 X3 合流。选 B 的代价：体验差；选 A 的风险：少数编造句在补审前可见——产品原则二.4"真实不粉饰"要求对玩家标明 unverified，所以记号不可省。

### 6.3 X3 叙述靠模板兜底 → 句级裁剪 + 模板正式化 + 补审升级

- **句级裁剪**：审查已是"逐句出处"（consistency-review.mjs），issues 带 quote。发布时删除 serious issue 命中的句子（及其从句），保留其余；删后若 must 项（AI-02 §6.2）缺失，用模板句补该 must 项；全部删光才整段模板。sideband.publishedSource 记 `sentence-trimmed`。
- **模板正式化**：AI-01 §6 的变体、文化 locale、回执槽位；质量验收 VAI-01-6。模板不再是"降级产物"，是 T0 的正式文本。
- **补审升级**：§5.3。
- 观测指标（现状"叙述质量与降级比例无可观测数据"）：每局统计 publishedSource 分布 {llm, sentence-trimmed, template, unverified}，试玩报告必含。目标值无依据，先观测两轮再定。

### 6.4 X4 补跑滥用 no_action、参数填错 → 候选约束与补跑契约

- `world_no_action` 只在 gate 的 candidates 为空时出现在补跑工具面；有候选时补跑的 tool_choice 限定为 world_act / world_propose（tools 列表动态生成，不是 prompt 劝说）。
- 参数：world_act 的 slots 值由引擎在工具 schema 里给 enum（候选集，已有 select(entities) 口径），模型填候选外 → 退回候选一次 → 仍错 → 预填构造器交玩家（不再第三次调用）。
- 补跑次数仍 1 次（成本），但补跑前先做本地 constructIntent，若本地已有唯一高置信候选，直接用本地结果，不补跑（省一次调用）。

### 6.5 X5 历史窗口撑爆 → 裁剪规则（数据）

- 发给模型的历史只带**最近 4 回合**的玩家原话 + 发布文字（a4llm 建议），更早的只带一行回执摘要（事件流投影）；world_search 查询结果**不进历史**，只在当回合工具回执里出现一次（下回合即丢）。
- 回执进提示时只带 narrate.must/mustNot、applied、trimmed、decisionCard、quotes；不带 trace。
- 规则放 `history-window.json`：{turns: 4, receiptFields: [...], searchResultsPersist: false}；playtest-runner 的 historyWindow 参数已有同口径入口。

### 6.6 X6 场景前提错误 → setup.prelude

产品原则三.2：测试前提用真实游戏动作产生。试玩场景的 `initial` 只允许 {新角色, prelude: [真实 world_act 序列]}；不允许直接写状态。现 runner 已禁"用新角色代替隔离会话"（playtest-runner.mjs:39），本册加校验：scenario.initial 含 state/patches 字段 → 拒载。

### 6.7 X7 评分分段失败整场无分 → 按段计分

叙述评分（两回合一段、9000 token）改为每段独立记分，失败段记 `unscored`，整场分 = 已评段均值 + unscored 比例；unscored >30% 的场不作验收依据但保留数据。
