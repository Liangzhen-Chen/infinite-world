## 本册回答什么 / 依赖哪些册

**回答**：盘点问题 c——玩家（经 AI 或经构造器）提出的新想法怎么落到引擎里，分三级：**临时处理**（只在本场有效）、**记成世界事实**（写进存档，可复现）、**审核后固化成数据**（进入 world/ 数据，经 L1/L2/L4 审批）。每一级写清触发条件、数据形状、审批流程、怎么保证存档一致、怎么不破坏经济与世界规律（守恒、价格、材料属性派生——北极星"材料属性 + 职业技能 + 意图共同推出产物"）。

**依赖**：AI-00（K4 新事物、RL-2/RL-3/RL-5/RL-7、I-E）；AI-02 §3（八步管线，所有落地都先过它）、§4（接得住的类别）、§5（拒绝形状）；AI-04 §4（AI 润色回写白名单与 provenance）；通用门设计稿 §2（效果族表，固化的目标之一）、§3.5（create/learn 路由）、§3.6（期望值天花板）；13 册 §3.1 / 实施日程 WD-25（材料属性体系）；08 册（价格派生）；12 册 §4.5 与命名方案 §4（命名校验）；开发指南 v2 第 10 章（L1–L4 流程）。

**一句话**：一个想法在世界里留下的东西只有三种形态——**痕迹**（别人可能注意到，但不改变任何账）、**事实**（在这个存档里永远成立，可重放，经原语结算所以守恒）、**数据**（进入 world/，所有存档都能遇到，经过和开发期内容同一套 L1/L2/L4）。AI 在三级里都只是"起草者"，三级的闸门全是确定性规则和人。

## 2. 三级的定义与分界（一张表）

| | L-T 临时 | L-F 世界事实 | L-C 固化数据 |
|---|---|---|---|
| 一句话 | 留下痕迹，不改账 | 在本存档里成立，守恒、可重放 | 进入 world/，所有存档可遇 |
| 有效范围 | 本存档，**效果有时限**（status duration / mark reactionWindow / memory TTL） | 本存档，永久（实体可被毁、义务可清偿，但事件永在） | 所有新开存档；旧存档不回填 |
| 写到哪 | 存档事件 + records（mark:*、memory、rumor seed）；**不新增持有、不动账** | 存档事件 + holdings/instances/obligations（经原语） | world/ 数据文件（items、recipes、open-sources、templates、legends、locations.features…） |
| 谁闸门 | 八步管线 V1–V4 + mark 规则 | 八步管线全部（含 V5 来源派生、V6 守恒、V7 同意） | L1（含新增经济与派生校验）→ L2 → L3 → L4 人读 |
| AI 的角色 | R1 抽意图；R2 叙述；R3 NPC 反应台词 | 同左；**不参与结算** | R4 起草草案说明文字、L2 审查；**不写数据** |
| 触发 | 任何想法，包括被拒绝的 | 想法的效果在族表有来源 | 频次阈值 / 玩家申请 / PT-AI 发现 / 开发者抽取（§5.1） |
| 可复现 | 事件重放得到同一 mark/memory；反应按种子键 | 事件重放逐字节相同 | 数据版本随仓库提交；存档记录开局时的内容哈希（已有 contentHash 口径） |
| 经济 | 零影响（mark 材料是本人原物件，消耗入账但不产生价值） | 守恒：产物价值由材料+工时派生，卖出按性状估价 | 价格/配方经 BalSim 口径校验后才入库 |

分界规则（由数据决定）：

- 提案 effects 全部 ∈ {emit, create(mark), status(self, duration ≤ 当日), fact.set(memory/rumor 类 record)} → **L-T**。
- 任一 effect 改 holdings / instances / obligations / 非 self 的 status / 地点 feature → **L-F**（必须过 V5–V7）。
- L-C 从不由单个回合触发；它是**离线**流程（§5）。

## 3. L-T 临时处理：只在本场有效

### 3.1 触发条件

四种来源都进 L-T：
1. 玩家明确选「留下痕迹」（拒绝形状里的 canMark，AI-02 §5.2；构造器"找不到族"）。
2. 想法被拒绝（任何拒绝码）且玩家没选替代 → 自动生成一条**念头记录**（不是 mark 实体，见 §3.2 第 4 项）。
3. 对白中的闲聊、宣称、许诺（未成义务的）→ NPC memory 条目（world_remember 已有）。
4. 短时效自我状态（"我要专心/警惕/祈祷一刻"）→ status(self) 且 duration ≤ 当日剩余分钟。

### 3.2 数据形状（四种，全部已有或扩字段）

| 形态 | 落点 | 形状 | 时限 |
|---|---|---|---|
| mark 实体 | holdings.entities[mark:*] + records[`mark:<id>`] | 现有：author, location, zone, text(≤max), materials[{resource, entity, qty}], tags[]（∈ openTagging.tags）, active, suppressed | reactionWindow 内触发反应；之后仍在（可被毁） |
| 念头记录 | records[`thought:<turn>:<n>`] | `{intent(原话 ≤200), rejectionCode, family?, at, tags[]}` | 90 日无引用自动清理（record-cleanup.mjs pruneRecords 已有机制） |
| memory 条目 | npcs[id].memoryStream | 现有 world_remember：subject/key/content/source/rumor/truth/motive/knowers/keywords | npc-memory TTL 与保护期 |
| 短时 status | state.player.statuses | 现有 status 原语：{kind, magnitude ≤ cap, duration ≤ 当日} | duration |

**标签**：mark 与念头都带 `tags[]`，只能取 `openTagging.tags`（数据）。R1 可以从原话里**选**标签（候选内），不能造标签。标签是"任何创意至少能留下带标签的痕迹并引起系统反应"（产品原则二.3）里的"带标签"。

### 3.3 "只在本场有效"与可复现怎么同时成立

- **写进存档的是事件**，不是效果的持续。mark/念头/memory/status 都经事件入账，所以重放得到同样的东西；"只在本场有效"指它们**不改变任何账、不派生任何价格、不进 world/**，并且有时限。
- 旁路记录里的 AI 文字（R2 叙述、R3 台词）不进事件；重放时读旁路记录显示同样的文字（AI-05 §3）。
- 反应（reactToMark）用种子键 `mark:react:<markId>:<observer>` 决定在场者是否注意、注意到什么（现有 rules 读 openReactions），确定性。

### 3.4 系统反应（让留痕"引起系统反应"）

现有 openReactions.rules 只覆盖 mark。扩到念头与 memory，**规则整类**：

| 痕迹 | 反应（数据规则） | 执行者 |
|---|---|---|
| mark | 在场者观察 → memory 条目 → 可能成为传闻种子（npc-rumors 现有"被见证的世界事件"路径） | reactToMark |
| 念头 | 不触发 NPC；进玩家"念头簿"界面（personal-panels）；同类念头累计 ≥N → 提示"这个念头出现过 N 次，要告诉设计者吗"（§5.1 申请入口） | 客户端投影 + records 计数 |
| memory（闲聊内容） | 下次 greet 模板引用 `{lastTopic}`（AI-01 §5.3）；含"宣称"的条目在传闻层按 truth=unverified 传播 | dialogue 模板；npc-rumors |
| 短时 status | 影响当回合检定（context.modifier 来源之一，带 reason） | checks.mjs |

### 3.5 经济与规律

L-T 不改账的唯一例外是 mark 的材料消耗（本人原物件 → sink:consume），这是真实消耗，入账守恒。不允许 L-T 产生任何持有、义务、价格变化；校验：L-T 路径的提案 effects 中出现 holding.*/obligation.*/transfer(非 mark 材料) → 升级为 L-F 走全管线，不是拒绝。

## 4. L-F 世界事实：写进存档，可复现

### 4.1 触发条件

提案经 V5 派生到来源、V6 守恒、V7 对方点头、玩家确认。四类典型 K4：

| 类 | 效果 | 来源派生 | 结果 |
|---|---|---|---|
| 粗制新物 | create(item crude) + transfer(materials→sink:consume) | 技能阶 × 工具 × 职业材料（action-limits.mjs:267） | 新 item instance，性状派生（§4.3） |
| 个人配方 | 粗制成功后 records[`recipe:personal:<actor>:<hash>`] | 自动，由本次 materials+skill+tool 的哈希 | 下次可在工坊卡直接"再做一件"（无 AI 也能复用） |
| 起名 | fact.set(instance.name) / fact.set(feature.name) | writableFact 白名单（name: string, maxLength） | 实例名；经命名校验（§4.4） |
| 立物 | create(feature) 于地点（碑、标记桩、小祠、路牌） | physical.create 族行：materials + 工时 + 地点权能（公共地需治理同意，私地需所有者） | locations.features 的**存档层**条目（不改 world/locations.json） |
| 自定约定 | obligation.create ×n | 对方 npcDecision | 义务，现有到期/清偿 |
| 牵、拆、搬、改置 | transfer/destroy/move/transition | 效果族表 | 现有实体状态变化 |

### 4.2 数据形状

**item instance（粗制产物）**（state.itemInstances[id]，现有结构扩字段）：

```json
{
  "id": "inst_<hash12>",
  "item": "core:item",                      // 模板，不是 world item id
  "name": "皮护腕",                          // 经 §4.4 校验；缺省由派生名规则给
  "quality": "crude",
  "madeBy": "player", "madeAt": 123456, "eventId": "...",
  "materials": [{"resource": "item_leather_scrap", "qty": 1}, {"resource": "item_hemp_cord", "qty": 1}],
  "skill": "skill_leatherwork_01", "skillTier": 1, "tool": "item_awl",
  "derived": {"traits": ["leather", "wearable", "wrist"], "weightKg": 0.12, "durability": 18, "value": 7, "slot": "wrist"},
  "prose": null,                             // AI 润色（AI-04 §4）；规则不读
  "provenance": {"path": "open:proposal", "envelope": "sideband:<turn>:<n>"}
}
```

- `derived.*` 全部由 **材料属性 + 技能阶 + 意图（means.manner / 目标部位）** 的派生函数算出（§4.3），不接受提案里给的值（RL-3）。
- `name` 若提案没给，由派生名规则 `nameFor(derived.traits, materials, culture)` 产生（如"皮护腕""粗麻绳结"），读 naming 数据的 `thing` 模板（命名方案 §4.2 形状加 `thing: {templates, pools}`；这是对命名方案的扩展提议，见 AI-06 冲突清单 C-5）。

**个人配方**（records）：

```json
"recipe:personal:player:<hash8>": {"materials":[...], "skill":"...", "tool":"...", "manner":"careful", "producedTraits":[...], "count":3, "lastAt":...}
```

**地点 feature（存档层）**：

```json
"features:loc_hw:<hash8>": {"kind":"monument|signpost|shrine_small|marker", "name":"...", "inscription":{"language":"lang:river","script":"...","text":"..."}, "madeBy":"player", "madeAt":..., "materials":[...], "derived":{"legibility":1.0,"durability":120}}
```

与 14 册 §3.4 碑刻 feature 形状对齐（language/script/text/legibility），只是落在存档层而非 locations.json。

### 4.3 性状与价值派生（北极星的落地点）

```
traits   = ∪ materials[i].traits（material-props，WD-25） ∩ 该职业可赋予的性状集（professions[skill.profession].grants，数据）
           + 意图性状：means.manner ∈ {careful→+durable} ；目标部位（提案 target 为 self 的 bodyPart 槽）→ slot
weight   = Σ materials.weight × qty
durability = base(material 最低 durability) × tierMul[skillTier] × qualityMul[crude]    （三表均数据）
value    = Σ materials.value × qty + laborMinutes × wageOf(profession, region)        （08 册 valueOf 口径）
sellPrice = market 对"杂物"的估价：value × crudeDiscount（数据），不进 goods 定价表
```

- **不进 goods 定价表**是防绕经济的关键：粗制物在市场上只能按性状估价卖给收杂货的（merchant 类 business），不能被当成 world item 流通、不能被 NPC 需求侧拉高价格。只有 L-C 固化后的物品才有 goods 条目。
- 期望值天花板（通用门 §3.6）：单日 crude 产出的总 value ≤ 该技能阶的日产出上限（数据），超出部分 derived.value 按比例折减并写 trimmed。

### 4.4 起名的校验（规则整类）

fact.set(name) 与 create 时的 name 一律过 `naming.mjs` 的校验函数（命名方案 NM-3 的产物），**不是单独的名字过滤器**：
- 长度 ≤ writableFact 白名单 maxLength；
- 字集：按玩家文化 `naming.style`——zh 圈须在常用字表内（允许 ≤1 个表外字，E-NAME-CHARSET 为 warning 不拒绝，因为玩家自己的东西可以怪一点）；
- blocklist 三档（命名方案 §3.3）：deny 档拒绝 E-SENSITIVE；
- 重字：不得与神名整词相同（E-NAME-DUP）；
- 不得与同地点已有实体同名（nameOk 现有）。
- 拒绝时 worldReason："这名字在这里叫不响/犯忌"，替代：派生名。

### 4.5 存档一致

- 所有 L-F 均事件入账，digest 覆盖 holdings/instances/records/obligations；重放逐字节相同（VAI-03-4）。
- `prose`、`provenance.envelope` 不进 digest（I-E）。
- 粗制物的 `item` 字段永远是模板 id（thing/core:item），不引用将来可能被固化的新 id，所以固化不会让旧存档的实例失效。

### 4.6 经济与规律不变量

| 不变量 | 校验 | 位置 |
|---|---|---|
| 守恒：Σ create.value ≤ Σ consumed materials.value + labor | derived.value 公式只读材料与工时 | V6 + 派生函数 |
| 无新 goods：L-F 不写 market.goods / 不进 settlement 需求 | 粗制物 `item` ∈ 模板集 | 校验 E-INSTANCE-TEMPLATE |
| 日产出上限 | 通用门 §3.6 | V5 |
| 性状来源：traits ⊆ 材料 traits ∪ 职业 grants ∪ 意图性状 | 派生函数 | V5 |
| 不改他人 | V4/V7 | — |
| 价格不由提案给 | 提案 schema 无 price；derived.value 只读派生 | V1/V5 |

## 5. L-C 固化：审核后进入 world 数据

### 5.1 触发条件（四个入口，都进同一个队列）

| 入口 | 条件 | 产生什么 |
|---|---|---|
| 频次 | 离线统计器扫所有存档（或试玩轨迹）的 records：同一 `recipe:personal` 哈希（材料类 + 技能 + 性状集）在 ≥ N 个存档或 ≥ M 次出现；同一拒绝码 + 同一效果形状（op 组合 + 目标类）在 ≥ N 场出现 | 草案候选 |
| 玩家申请 | 念头簿或构造器"告诉设计者"按钮 → 本地写 `world/drafts/inbox/<存档id>/<n>.json`（不上传、不联网；玩家自己决定是否随反馈提交） | 申请条目 |
| PT-AI 发现 | tools/ptai 轨迹里标 `blocked`/`unreal` 的回合（PLAN.md PT-AI 节：找自由度受阻与不现实结果） | 候选 |
| 开发者抽取 | 主会话读试玩报告指定 | 候选 |

N、M 是 `world/rules/tables/canonization.json` 的数据（首版建议 N=3 存档或 M=10 次，标待校准）。

### 5.2 草案的五种目标形态

固化不是"把玩家造的东西原样放进 world/"，而是**把它背后缺的那条规律或内容补上**（记忆规则"不现实=缺规律"；红线"一类一起覆盖"）。草案生成器按候选的类型选目标：

| 候选类型 | 固化目标 | 文件 | 说明 |
|---|---|---|---|
| 反复出现的粗制物（同材料类+性状集） | 正式物品 + 配方 | world/meta/items.json、recipes.json | 配方 inputs 取材料**类**（tag），不取单品；output value 由 BalSim 口径复核 |
| 反复被拒的效果形状（E-OPEN-SOURCE） | 效果族表新行 | world/rules/tables/open-sources/*.json | 行描述"看什么数据"（物性、技能阶、设施），不写意图词 |
| 反复出现的同类留痕/念头（同 tags 组合） | 登记动作（加速模板）或模板文本 | world/actions/*.json；locale/events.json | 通用门 §8.1："注册动作只是开放路径已能执行的组合的加速模板" |
| 玩家立的碑/祠/路牌文字被多存档引用 | 传说条目（legends/*.json）或 rumor seed | world/lore/legends、rumors.json | 走 14 册 §4.4 派生 A 的形状，status: authored-seed |
| 对白/叙述里反复缺的表达 | 对话模板、事件模板变体 | world/templates/dialogue、locale/events.json | AI-01 §5.1、§6 |

生成器只产出**骨架 JSON + 说明文字草稿**；说明文字可由 R4（DeepSeek）起草（走 content-pipeline 的现有草稿路径），骨架字段由程序从存档统计派生，模型不改骨架（与居民档案"身份由代码分配"同口径）。

### 5.3 审批流（复用开发期管线，加三条 L1）

```
草案 world/drafts/canon-<批>/<entry>.json
  → L1 自动校验（全部条目）：
       现有：schema、id 规则、标签存在、blocklist、常用字、重字（命名方案 §5.3）
       新增 L1-E（经济）：recipe.output.value ≤ Σ inputs.value + labor × 行业系数（balance 表）；goods 条目的基准价与同类 ±30% 内（数据阈值）
       新增 L1-D（派生）：item.traits ⊆ ∪ materials.traits ∪ profession.grants；不得手填与材料矛盾的性状（木器不防火）
       新增 L1-R（红线）：open-sources 行与 actions 条目里不得出现实体 id / 文化 id / 意图词字面量（grep 式校验）
  → L2 模型审（每条一次 DeepSeek 非思考调用，骨架+说明 → contradictions）；按 11-09 决定 B：数值判定须写算式，程序比对；算术误判自动重问一次；事实项任何路径不计通过
  → L3 定点重写 ≤2 次（只改说明文字，不改骨架）
  → L4 主会话抽读 ≥ 每批 20% 且每类 ≥1 条
  → 入 world/；提交；contentHash 变
```

- 预算：每批一个 budget.json，上限沿用现有口径（单卡 ≤1.5–20 元按规模；盘点 §4：D12 卡 D 58 次 0.207 元/上限 1.5 元；W1 一组 5.6–7.2 元/上限 20 元）。L2 每条约 0.003–0.006 元（按盘点各卡"次数/元"反推：D12 58 次 0.207 元 ≈ 0.0036 元/次；T102 47 次 0.117 元 ≈ 0.0025 元/次）。**这些是现有账本的量级，不是新报价。**
- 发布条件不变：L1 无错、L2 无硬矛盾、L4 通过。
- 中断续跑：事实项不计通过（5c65a531 口径）；指纹变更重绑不重跑（t155 口径）。

### 5.4 固化与已有存档

- **不回填旧存档**（记忆规则：规则只一版、不加版本标记、不改不删存档文件）。旧存档里的粗制物仍是 `item: core:item` 的实例，自己的 derived 值不变；新开存档能在市场与配方里遇到固化后的正式物品。
- 旧存档加载新数据时，若新 goods 与旧实例 traits 相同，**不自动合并**；玩家可用正式配方做新的，旧的仍是旧的。这是"同版确定性"的代价，接受。
- 存档记录开局 contentHash（现有）；升级后的 conflicts 数记录在案（命名方案 N10 同口径）。

### 5.5 固化的禁区

- 不固化**单个存档里的具名个人**（玩家的 NPC 朋友不会变成 world/people 数据）——人口由 population 种子派生，固化个人会破坏其他存档的名册种子。
- 不固化改变守恒、价格公式、法律硬规则的东西；这些是设计决定，走设计文档，不走草案。
- 不为固化而补"只给某个存档用"的世界内容（产品原则三.2）。
