## 0. 一句话

历史已经有一副好骨架：80 条事件、4 个纪元、每条有**真相版与流传版**（`accounts.verified/received`）和**今日留痕**（`presentTrace`）。缺的是：八个省的史纲只有 8 个文化各 10 条、全是"制度惯例"一种留痕、与 260 条传闻互不引用、与规则（法典、债务、世仇、节日）不绑定。本稿做四件事：把留痕扩成六种并各自**绑到现有机制**（习惯条目、义务、组织关系、节日、碑刻、职位）；把传闻层改成**从历史与世界状态派生种子**，260 条手写传闻成为校验样本；定殡葬与祭祖的规则（它们是中式地区的经济与家庭核心，也是亡魂的闸门）；定玩家建档的出身选择——含兽裔开关（李白决定首版开放，亮圳未特别要求，`rules.playerOrigins.allowBeastkin` 可随时关）。

## 2. 概念模型

```
纪元 era ── 共享年表（春历）；每文化对同一纪元有自己的叫法（eras.names）
事件 history ── accounts.verified（真相层，规则可读）/ received（传说层，知情条目）
            ── presentTrace.type ∈ {institutional_practice, custom_law, treaty_term, standing_debt, feud, festival, monument, office}
                 每种 type 绑一个现有机制的数据条目（§4.2）
传闻种子 rumor ── 派生自：history.received、世界状态指标（10 §4.7 失传、11 §4.3 spread、11 §4.7 newsLag）、生灵 legend 层（13 §13.1）；手写 260 条是样本
碑刻 monument ── 地点 feature，带 inscription{language, script, text, history}
亡者 ── 死亡事件 → burial 义务（户）→ rite:funeral → 墓/祠/记名树 实体 → 祭祖周期义务 → 断祀 → 亡魂（03/04）
玩家 ── 出身文化 → 出生地候选、语言、单位、立场、背景（技能小初值 + 1 熟人 + 3 传闻种子）
```

## 3. 数据结构

### 3.1 eras.json 扩字段

```json
{"id": "era_covenants", "name": "复契期", "start": -1000, "end": -201,
 "names": {"culture_civic": "立誓厅时代", "culture_steppe": "粗绳盟前", "culture_forge": "退楔之后", "culture_north": "长夜数灯期", "culture_canopy": "记名树初植"},
 "sphereTheme": {"sphere:eastern_zhiguai": "契与讼", "sphere:western_folk": "矿与冬", "sphere:steppe_sky": "井与盟", "sphere:canopy": "名与林", "sphere:marches": "渠与界"}}
```
- `names` 缺的文化用 `name`；只是叙述投影。`current`：春历元年 = 0，当前游戏年 = 存档 minute 折算（calendar 现有），首版开局年 = 春历 1 年（item_literacy_primer "春历元年修订本"已暗示）。

### 3.2 history.json 每条扩字段（现有字段全保留）

```json
{"id": "history_civic_06", "year": -388, "name": "桥债入家契",
 "cultures": ["culture_civic"],
 "presentTrace": {"type": "standing_debt", "entity": "faction_oathkeepers", "fact": "…",
                  "binding": {"kind": "obligation", "ref": "oblig_hist_civic_06", "file": "people/baseline.json"}},
 "accounts": {"verified": {...}, "received": {"truth": "partial_or_false", "falseClaim": "…", "correction": "…", "spreadCultures": ["culture_civic", "culture_river"]}},
 "legendSeeds": 2,
 "monument": {"location": "loc_zl_bridge", "inscription": {"language": "lang:old_covenant", "script": "script:zhonglu", "text": "…", "legibility": 0.7}}}
```
- `cultures[]`（多文化事件；旧 `culture` 保留为 `cultures[0]`）。
- `presentTrace.type` 枚举扩为 8 种；`binding` 指向该留痕对应的数据条目（§4.2 表）。加载校验 E-HISTORY-BINDING：type ≠ institutional_practice 时 binding 必填且 ref 存在。
- `accounts.received.spreadCultures`：传说在哪些文化流传（派生传闻种子的 source 从这些文化的居民里取）。
- `legendSeeds`：该事件派生的传闻种子数（首版 1–3）。
- `monument` 可选。

### 3.3 传闻种子派生（不新建文件；rumors.json 260 条保留为 `status: authored-seed`）

派生种子形状与现有 rumor 相同，`status: "derived"`、`id` = `rumor_d_<来源>_<n>`（确定性）、`evidence` 指向来源集合（新增 collection 枚举 `history`、`monsters`、`skills`、`recipes`、`schools`）。§4.4 给生成规则。

### 3.4 碑刻与古迹（locations features）

```json
{"id": "feature_mon_zl_bridge_stele", "kind": "monument", "name": "桥债碑", "position": [1, 0], "access": "public",
 "inscription": {"language": "lang:old_covenant", "script": "script:zhonglu", "text": "…", "legibility": 0.7, "history": "history_civic_06"},
 "material": "material:stone", "madeAt": -388}
```
- `legibility` 随磨损下降（13 §4.2 材料 decay）；阅读前置 = 12 §4.3 读文书规则 × legibility（检定）。`madeAt` 供"年久成精"（13 §13.3 C5，03 文档）读。

### 3.5 殡葬与祭祖（文化 `burial`，01 §3.2 已定形状；本稿补字段）

```json
"burial": {"deadlineDays": 7, "riteFamily": "rite:funeral", "mode": "inhume|cremate|sky|tree|sea|cairn", "site": "cemetery|churchyard|named_tree|none|household_shrine",
           "rebirth": true, "ancestorCult": true, "ancestorUpkeepDays": 15, "mourningDays": 49, "lapseToShadeDays": 360,
           "offerings": ["goods:food_ready", "goods:incense"], "graveGoodsShare": 0.02}
```
- 场所类别 `cemetery` / `churchyard` / `named_tree`（05 密度公式用 shrine 行的参数生成：每聚落 ≥ 1 处墓地，`site` 为 none 的文化不生成）。
- 义务 kind `burial`（新注册，obligations.json）：debtor = 亡者所属户（无户 → 所在聚落公库，05 relief），creditor = 亡者（interim 实体，附录 A）；deadline = 死亡 + deadlineDays。
- 义务 kind `ancestor_upkeep`：周期 = ancestorUpkeepDays，debtor = 户，内容 = 向户神龛/墓 transfer offerings（数量 1）；连续缺 `lapseToShadeDays` → 事件 `ancestor_lapsed` → 03/04 的 `super:dead/shade` 生成入口。

### 3.6 玩家出身（rules.json 新节 + character.mjs 参数）

```json
"playerOrigins": {
  "allowBeastkin": true,
  "allowMonsterSocieties": true,
  "note": "李白决定首版开放兽裔与怪物社会出身，亮圳未特别要求；关掉即回到仅人类文化",
  "defaultCulture": "culture_river",
  "backgroundsPerCulture": 3,
  "startingSecondLanguage": 100,
  "startingSkillBoost": 60,

  "contactStanding": 20

```
- `createCharacter(options)` 允许键扩为 `name, gender, appearance, attributes, birthplace, culture, background`（character.mjs:10 白名单改）。
- 文化记录 `backgrounds[]`（新字段，每文化 ≥ 3）：

```json
"backgrounds": [
  {"id": "bg_civic_clerk_child", "name": "书办人家", "skills": {"skill_literacy": 60}, "secondLanguage": "lang:common", "contactRole": "office:clerk|faction:faction_gatehouse", "items": [{"goods": "goods:writing_kit", "n": 1}], "rumorTopics": ["factions", "history"]},
  {"id": "bg_civic_ward_market", "name": "坊市学徒", "skills": {"skill_life_3_core": 60}, "secondLanguage": "lang:reed", "contactRole": "trade:merchant", "items": [], "rumorTopics": ["locations", "regions"]},

```
- `contactRole`：熟人由**角色谓词**在出生聚落里找（持该 office / member_of 该 faction / 该职业 / 该 school 成员），找不到 → 远郡物化时生成（remote-generation 的 keyPeople 机制）；不写 NPC id。

## 4. 规则

### 4.1 年表与"各圈史纲"的派生

```
圈史纲(sphere) = history 中 cultures ∩ cultures(sphere) ≠ ∅ 的事件按 year 排序，按 era 分节，节名 = eras.names[主文化] ?? era.name
文化年表(culture) = cultures ∋ culture
地点年表(loc)     = contactAnchor == loc ∨ monument.location == loc ∨ references ∋ loc
```
- ui-history.mjs:9 `history()` 投影加 `scope: sphere|culture|location` 参数；真相层只对**已核实**知情开放（现有 evidenceAccess 规则），其余显示 received 版。

### 4.2 今日留痕 → 机制绑定（R4）

| presentTrace.type | 绑到 | 数据落点 | 规则效果 |
|---|---|---|---|
| institutional_practice | 无（文字） | — | 叙述；现有 80 条保持 |
| custom_law | 习惯条目 | world/law/customs.json 条目 `origin: history_id` | 01 §4.4 层叠读；判决 explain 显示"此俗源于某年某事" |
| treaty_term | 政体通行/关税条款 | regions.neighbors[].terms → 11 §3.1 customs 项 `origin` | 关卡与关税读 |
| standing_debt | 义务 | people/baseline.json 开局义务（债务人/债权人 = 现有组织或家户） | 现有 obligations 到期与清偿；可被玩家清偿或继承 |
| feud | 组织关系 | lore/faction-relations.json 条目 `origin`，stance hostile | 现有 faction-relations 读；成员间立场初值 − |
| festival | 节日 | festivals.json `origin: history_id` | 节日叙述与仪式名 |
| monument | 碑刻 feature | locations.json features（§3.4） | 可读、可拓、年久成精入口 |
| office | 职位设立 | office-succession.json `origin` | 职位存在的理由 |

- **只绑，不生**：事件不会在运行期"发生"；绑定是开局数据的注释，让规则输出能解释来源。
- 现有 80 条：按 fact 文字机械归类，预计 institutional 50、custom_law 12、standing_debt 6、feud 5、festival 4、office 3；归类表进卡（§7 M1）。

### 4.3 碑刻、古迹与"历史在物上"

```
生成：history.monument 定义 → 对应地点物化时创建 feature（存档事实）；白石镇辖下现有地点可直接补（古冢 loc_wild_sb_barrow 作 history_river_* 某条的 monument）
阅读：12 §4.3 前置 × legibility：check 难度 = 10 + round((1 − legibility)·15)；成功 → 知情条目 = accounts.verified.claim（**碑是真相层**，但 falseClaim 若刻在碑上则 truth 按碑文——数据可写 inscriptionAccount: verified|received）
拓印：抄写员配方 `recipe_rubbing`（材料 paper、ink）→ 文书物品，继承 language/script/text
损毁：material decay（13）；人为破坏 = destroy 原语 → 事件 → 传闻
年久成精：feature.madeAt 与 13 §13.3 C5 规则（03 文档）
```

### 4.4 传闻种子派生（R2；260 条手写 = 校验样本）

```
来源 A 历史：对每条 history、每个 c ∈ received.spreadCultures：生成 legendSeeds 个种子
   claim = received.falseClaim 的变体（按 distortion 模板：省地点 / 省条件 / 夸大），truth = received.truth == partial_or_false ? (种子序号为偶 ? half : false) : true
   source = 确定性选 c 文化居民中年龄最大者（键 `rumor:hist:<id>:<n>`），carriers = source 同户成员
   evidence = [{collection: "history", id, field: "accounts.received"}]；verification = correction 文字
来源 B 状态指标（时钟规则，每 30 日）：
   10 §4.7 status(entity)==unique → "只有某地某门还会 X"（truth true）
   11 §4.3 spread(recipe) 新增郡 → "某地新来会做 X 的匠人"（true）
   11 §4.7 newsLag：事件距此 ≥ 2 跳 → 转述时 half 概率 +0.1/跳（替换 npc-rumors 的 `distortion` 文字为规则）
   13 §13.1 生灵 legend 层：每物种 legend 条目 → 种子（truth 按 legend.truth）
来源 C 玩家行为：现有 06 §6.7 mark 与事件 → npc-rumors 现有
传播：现有 transmissionChain（讲述者→听者）；加**居民间自传**：同聚落每日 `rumorSpreadPerDay 0.2` 概率由 carrier 传给一名同户/同街区成员（时钟规则，键 `rumor:spread:<id>:<day>`）；跨聚落随迁徙与商队（11）
衰减：种子 `heardCount` 90 日无新传 → 退出活跃集（仍在知情层）
```
- 260 条手写：加 `evidence` 指向 history 的（凡 claim 涉及历史的，预计 ≈ 40 条）补 `{collection: "history", id}`；其余不动。验收：派生 A 对 80 条产生 ≥ 120 个种子，每圈 ≥ 15；与手写无 id 冲突。

### 4.5 殡葬与祭祖（U3，13 §13.7 的落地）

```
死亡事件（lifecycle 现有）→ 反应规则：
  1. 创建 burial 义务（§3.5），deadline = 死亡 + culture(亡者).burial.deadlineDays    culture 用 01 §4.1 派生（亡者生前）
  2. 若 burial.ancestorCult → 创建 ancestor_upkeep 周期义务（债务人 = 户）
  3. 服丧状态 mourning（亡者直系）持续 mourningDays → cuisine.taboo(when: mourning) 生效（01 §3.2）、婚配冷却
履行 burial = 仪式动作 rite:funeral（action-rite.mjs 现有仪式形状，stages 按文化 mode：inhume 掘墓+下葬+封土；cremate 积薪+焚+收骨；sky 置于高台（草原）；tree 系于记名树并刻名（林冠）；sea 舟送（琥珀）；cairn 垒石（星湾/草原））
   主祭资格：13 §13.6 仪式族资格谓词——祭司/僧侣/道士/萨满/堂区牧者 或 户主（简仪，效力 0.6）；殓葬师生活职业（新，内容）效力 1.0
   场所：site 类别地点（cemetery 等）；无场所 → 仪式效力 ×0.5 并留下 `improper_burial` 事件
   费用：graveGoodsShare × 亡者遗产（随葬，sink）+ 主祭费（职业 fee）
未履行（超 deadline）→ 事件 unburied → 03/04：super:dead 生成概率 ↑（数据 `unburiedShadeChance`），亡者户 standing −（邻里）
祭祖：ancestor_upkeep 到期 → 户向神龛/墓 transfer offerings；履行 → 户 `ancestorFavor` 修正项 +（小幅：家户运势类修正槽，首版只影响 omen/dream tell 通道 04）；缺 lapseToShadeDays → ancestor_lapsed → 亡魂（被遗忘者：林冠"嗅迹亡魂"、东陆"无祀孤魂"同一规则）
清明/中元/亡者夜：节日 trigger window（01 §4.6）→ 当日祭祖效力 ×efficacyMul；集体仪式可一次清偿全聚落该周期的 ancestor_upkeep（放河灯）
墓地容量：每聚落 cemetery 面积 = pop·deathRate·yearsKept·m²/墓（数据），满 → 需扩建（公共工程现有）或合葬（文化允许则 `ossuary`）
```
五圈首版 burial 表：

| 文化 | mode / site | deadlineDays | ancestorCult / upkeepDays | mourningDays | rebirth |
|---|---|---|---|---|---|
| river | inhume / cemetery | 7 | true / 30（门槛刻名） | 27 | true（两圈交汇：止波寺度亡 + 芦衡观） |
| civic、reed、salt、mist | inhume / cemetery + 祠堂龛 | 7 | true / 15 | 49 | true（十殿轮回，04） |
| forge、north、coast | inhume / churchyard | 3 | false（守夜 + 亡者夜一年一度 → upkeepDays 360） | 30 | false（坟中坐者：unburied/improper → draugr 型） |
| steppe | sky→cairn / none（敖包记石） | 1（不留尸） | true / 90（祭火） | 9 | false |
| canopy、beast | tree / named_tree | 5 | true / 30（记名） | 20 | false（被遗忘者化嗅迹亡魂） |
| 怪物社会 6 | 各按散文（灰窟：窑道封室；狐族：根洞；裂炉营：共炉烬） | 3–7 | 部分 | — | — |

### 4.6 情报与秘密（U6，最小闭环）

```
秘密 = 知情条目（05 §5.4）带 `access: {holders: [...], kind: oath|guild|state|personal}`；持有者外泄 = 事件 disclosure → 规范栈（门规/誓言条目，10 §3.2 breaches secret_disclosure）
暗号 = 事实 `password:{faction}`，对话 ask 带正确暗号 → npcDecision 的 trust 临时 +（修正项 `social:password`）
密会 = 场所 access consent + windows midnight（01 §3.2）→ 被目击概率按 airModel.hearingRadius 与在场者
间谍 = NPC 持 mentor_of/ member_of 多重 + 秘密条目 holders；不做专门职业；隐秘结社（现有 1）的成员规范含保密
传闻真伪核验 = rumor.verification 文字 → 动作 `verify_rumor` 走 evidence（已存在的 evidence 字段：去对应 collection/id 查看即核实，产生 truth 知情）
```

### 4.7 玩家建档流程与出身（U10；01 §6.4、§7 M5）

```
步 0 选种族：候选 = 可玩种族（卷四 G-1/G-2：playableClass 的物种行），玩家自己挑，不由出身文化决定（亮圳 2026-11-27 拍板「玩家自己挑种族」）；
      无缺省（种族槽必填，S1-3d 主会话 Q1）；playerOrigins.allowBeastkin=false 时候选只剩 human
步 1 选出身文化：候选 = cultures.json 全部 18 条，过滤：
      playerOrigins.allowMonsterSocieties=false → 排除 culture_ms_*
      缺省 = defaultCulture（culture_river）→ 旧存档等价
```

## 5. 边界情况

1. **真相层泄露**：ui-history 只对已核实知情显示 verified；碑文若 `inscriptionAccount: received` 则碑也会"说谎"（王侯刻碑自夸是真实的）。
2. **多文化事件**（王国建立、旧约）：`cultures` 多项，每文化 received 版可不同 → `accounts.receivedBy: {culture: {...}}` 可选覆盖；未覆盖用通用 received。
3. **没有历史的文化**（beast/reed/mist/小文化）：首版各补 ≥ 5 条（§6）；怪物社会 6 条各 2 条（它们近世才成社会，年份多在 era_near）。
4. **亡者无户**（旅人、玩家同伴）：burial 债务人 = 所在聚落公库 → relief 支出 → 公库紧张时 improper_burial 多 → 亡魂多（客死他乡的真实后果）。
5. **玩家死亡**：现有 revivalAnchor/复活规则不动；玩家"尸体"不进 burial（现有死亡规则是复活点机制）。
6. **跨文化葬礼**：亡者文化 ≠ 当地文化 → 当地无对应 site（如中陆人死在草原）→ 效力 ×0.5 或请同文化主祭（迁徙/商队中的祭司）；这就是"叶落归根"运尸（承运可运尸：物品化的 interim 实体）。
7. **开局年**：春历 1 年；80 条全为负年；首版新增事件允许 0 到当前年（近事）。
8. **兽裔玩家在人类聚落**：aff 由 01 表（canopy ↔ 各圈 .2–.4）→ 标价、立场、师傅意愿都更难，但无硬禁；语言用 lang:beast + second（建档背景给 lang:canopy 或 common 100）。
9. **旧存档**：无 culture/background 事实 → 读 defaultCulture 与起始聚落主文化（01 §7 M5），不写回。
