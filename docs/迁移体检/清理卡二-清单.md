## 查证方法（已实跑）

1. 新底子引用面 = server-plugin/、tools/accept/、tests/、.githooks/、package.json、world/ontology。在这些位置 grep `tools/…`：只有 package.json:10 引用 `tools/backup.mjs`（scripts.backup）。tests/accept 里出现的 tools/x.mjs、tools/fx-*.mjs、tools/c.mjs 是造出来喂扫描器的假路径，不指向真实文件；world/ontology/derived-fields.json:6 的 tools/derived-scan.mjs、tags.json:1022 的 tools/yaoguai-defs.mjs 是数据里的文字说明，不是程序引用（derived-scan.mjs 早已不在 tools/；yaoguai-defs.mjs 判删，文字说明不受影响）。
2. 反向：tools/*.mjs 里 `from '../server-plugin/…'` 只命中 dim-coverage.mjs:7、convert-material.mjs:11–13，均指向现存的 server-plugin/kernel/**。其余脚本不 import 新底子。
3. tools 内互相 import：只有 test-impact/{collect,select}.mjs → test-impact/common.mjs（目录内部）；tmp-root.mjs、top-level-statements.mjs 无任何 importer（grep tools、tests、server-plugin、docs/统一底层设计/脚本、.githooks 零命中）。
4. docs/统一底层设计/脚本/ 里的 tools/*.mjs 字样（content-pipeline、derived-scan、k8-guard、kc-processing、load-world、npc-profile-validation、w3-wave-score）是已封卷检查脚本里对旧文件的历史引用，不构成运行依赖，删除这些脚本不改卷文与脚本。

判定规则：被新底子或运维引用且不依赖已删旧代码→留；只服务旧内容、旧试玩、旧迁移、旧内容管线→删；拿不准→待判。
