## 口径

- **自**（自然得出）：设计正文给出确定的结果来源——哪个派生 / 表 / 条款 / 规则决定、按什么口径算——并且按题面给出的数据算出的结果与预期一致。预期本身是定性的（"下降""不变或微升""与地图一致"），而设计在结构上保证了这个方向，也判自。
- **补**（需补数据）：设计给了机制和数据位置，但预期要求的数值或幅度（"约 5 分钟""接近满值""+1~+3""30→60"之类）要靠正文里没有的数据才能确定；或者结果取决于题面没给、设计也没规定缺省的输入。数据位置写明了也不算自然得出。
- **缺**（设计缺口）：正文没有能产生该结果的规则，只能推测设计者本意。
- **矛**（设计矛盾）：按正文算出的值与题面预期不一致。
- 引用写法：章 §节；附录 A 记作 A §。"占位数据"指正文说明以 数值平衡调研 等非证据文件为准的数据，本审查一律视为没有。

### 全部未通过条目（52 条，按根因归组）

**G1 零售与大宗的边界依赖题面未给的存量（4 条，补；有矛盾风险）**：D01①③、D02①③。15 §15.2 只在 q ≤ max(1, 本地有效存量 × 0.05) 时按 quote × q 成交，所以买 3 个馒头要求本地存量 ≥ 60，卖 5 张兔皮要求 ≥ 100。存量低于此时走积分：买馒头的均价 > 4，总额 > 12；卖兔皮的均价 < 6，总额 < 30。正文算例直接写 12 / 30，没写这个前提；按一般村铺的存量会算出与题面不同的数。

**G2 动作耗时没有任何数值（18 条，补）**：D01⑤、D05⑤、D07③、D12③、D13③、D14③、D15③、D16⑤、D17③、D20①、D21③、D22⑤、D23④、D27⑤、D31④、D34④、D36⑤、D38④。06 §6.4 / §6.7 规定耗时由动作的 `cost.time`（或配方 laborMinutes、收获速率、交锋）派生、不能自报，但正文没有一条日常动作的耗时数据。也没有"持续一个时辰"这类由玩家指定时长的槽：只有等待和睡眠写了时长。

**G3 身体需求量的消耗与恢复只是占位（3 条，补）**：D04④、D33②（睡后"接近满值"）、D06③（"未降到 0"）。A §A.15 body.json 的 drainPerHour / recover.sleep 指向非证据文件。

**G4 印象权重表没有数值或缺行（3 条，补）**：D03⑤（±2）、D21②（+1~+3，≤ +5）、D30④（按时还款没有正向"守信"行）。

**G5 天气对旅行的影响没有给出（3 条，补）**：D09②（雨天因子没有，方向也没写）、D09③、D09④（没有"淋湿"的规则行）。

**G6 动作 / 配方 / 产出的内容数据没给（11 条，补）**：D10⑤（没有"已锄进度"事实）、D12①（没有播种动作与用种量）、D13①（没有基准产量与面积）、D14①（典型日收入表没有数值）、D14④ 与 D17④（正文没写"做活带来熟练度"）、D15②（钓鱼不声明耗饵）、D16②（鲫鱼汤配方没有燃料量）、D17②（品质 RX 没有数据）、D19④（3 天授艺到不到"入门"没有阈值）、D20②（练习按 6.6 自学检定可能"无进展 / −k"，还是走 practice 规则的确定增量，正文没定）。

**G7 凭证物品没有声明（3 条，补）**：D27③、D28⑤（deposit 行没写存单，也没写支取要不要凭单）、D37③（征管流程不出具完税凭据）。

**G8 承运的出发时刻不确定（2 条，补）**：D25③、D26④。条款到期日 ≠ 实际到达；20 里当日即可走完，正文没有驿传 / 车行发车日程的规则，所以"次日到"不是确定结果。

**G9 营业时间的端点口径（1 条，补）**：D08②。"辰时至酉时"是否含酉时没有口径；若含酉时，酉时末仍营业，与预期相反。

**G10 播种语义缺失（1 条，缺）**：D12②。作物生长的输入只有积温与 condition（01 §1.10、05 §5.5），没有播种、作物种类与覆盖面积；田地没有"已播种"事实，照字面读，没播种的田也会生长。

**G11 外伤愈合速率（1 条，补）**：D32⑤。heal 幅度"按阶"，外伤恢复时钟没有数据，单次治疗能否补满定不下来。

**G12 二手转述的日期失真（1 条，补）**：D40③。失真表的 replace_detail 可替换细节，正文没有限定日期是否在可替换之列，也没给概率。

**G13 借贷利率区间（1 条，补；有矛盾风险）**：D29③。正文唯一的 loan 种类数据（03 §3.3）利率下限 0.005，而 obligation.create 按种类区间限定条款（06 §6.3），无息借贷会被拒或被裁到 0.5%（金额取整后仍是 100，但记录不是"无息"）；core 的区间没有定。

### 判分备注

- 设计正文为日常题写的明确口径都已核对通过：D04⑤ lodges、D11 / D28 的 anchorsBetween 算例、D23③ 承接、D25⑤ read_on_receipt、D26④ 的 bailment 待取部分、D34 的 body 与 loyalty、D35 / D05 的零售口径、D40 的 src:husbandry。
- 失分主要不在结构，而在数据：51 / 52 是"机制与数据位置都有，但数值或缺省没给"。其中 G2 + G3 + G4 共 24 条，补一张"日常动作耗时 / 身体速率 / 事件权重"的 core 缺省表即可一次解决。G1 与 G13 补数据时要同时改口径：零售阈值加一个绝对下限（例如 `max(k, 存量 × retailShare)`），loan 的利率下限允许 0；否则即使补了数据，结果也会与题面矛盾。
