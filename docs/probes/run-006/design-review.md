## 判分口径

- **自**（自然得出）：只用设计正文已写明的概念、规则形状、不变量、协议、统一模型、动作层、空间、时序、扩展点与契约附表，加数据即可得到；每条写出用到哪几节、加什么数据、数据放在设计规定的哪个位置与形状。需要"推测设计者本意"的不算。
- **数**（需补数据但设计未说明数据位置或形状）：机制方向对，但设计没有给出该数据应放在哪个文件/字段、是什么形状，或所需的查询函数不在附录 A §A.13。
- **缺**（设计缺口）：没有机制能得出，或设计规则会得出相反结果。
- **矛**（设计矛盾）：不同章节说法冲突并落在该条预期上；不落题的矛盾另列于"全部设计矛盾清单"。
- 计数单位：E 题的每条编号预期各 1 条，"二阶"合计 1 条（E 共 118 条）；N1–N5 按"加什么 / 装上后各子句 / 易错"拆条，N6–N8 按"加什么 / 装上后各子句 / 卸掉后各子句 / 同装"拆条（N 共 44 条）。总计 162 条。
- 达标线：自然得出 ≥ 95% 且零矛盾（落题或不落题均计）。

## 逐题判定

### E1 ★ 中秋庙会的轻钱（5 条：自 4、缺 1）

建模：轻钱 = 新的铸币资源种类（`world/ontology/resources.json`，带 01 §1.6 / 15 §15.3 的货币事实 `money:{metal: copper, fineness 低, weight 低, issuer}`）；赌坊 = business + `operates`；东家对钱庄的 `share`；香火箱 = 寺观实体的账户；收缴令 = 郡府法典认可条款变更（`recognition.legalTender.accepted` 去掉轻钱）+ 执行动作。

- ① 以钱计价物价上涨、以银计价基本不变 — **自**。15 §15.3：铸币价值 = 金属商品类价值 × 含量 × 发行信用 × 充裕度；轻钱流入使本地铜金属存量（"本地铸币存量 × 含量"）上升 → 足钱价值下降 → 以足钱计的报价（quote = value ÷ value(计价铸币)）上升；银币价值不受影响。数据：轻钱资源种类（位置如上）；赌坊"按面值收轻钱"是它自己的兑换动作条款（15 §15.3 兑换 = 两笔互逆 transfer + 自定汇率），不需要任何 NPC "被骗"。注：设计里可替代物没有 `purports`（01 §1.2 只给物品个体；15 §15.9 明言铸币不跟踪），所以"轻钱在不知情者手里按足钱流通"这一情境本身不可表达——成交永远按真实资源种类结算，这与预期①不冲突，但见③。
- ② 钱庄对轻钱折价兑付、按实值计息 — **自**。01 §1.4 / 15 §15.3"合同只记资源种类与数量，从不换算"：存款义务记为 `resource: 轻钱`，利息闭式按该资源累计，其实值由市场投影给出；钱庄收不收轻钱是 npcDecision（05 §5.7）+ 法典 `legalTender.accepted`（05 §5.2.4 认可条款）。数据：法典认可条款、钱庄章程。
- ③ 善意持有者没收不定罪，私铸者与明知收兑的赌坊东家分别论罪 — **缺**。两处无机制：(a) **私铸行为没有原语路径**：铸币只能从 `src:mint` 流入且 `src:mint` 只许发行政体（01 §1.6、12 §12.2.3、15 §15.3），`create` 只造实体不造数量资源（06 §6.3），因此"私铸"在世界内发生不了，轻钱只能靠 `src:genesis` 作者数据预置；"私铸案发"没有可立案的事件。(b) "善意/明知"对可替代物无法派生：持有者的自知域含随身账户（§A.8），账户键就是资源种类，所以每个持有轻钱的人都"知道"自己持的是轻钱；罪名谓词 `knows(x, …)` 只能读事件，没有"不知道这是轻钱"的状态。可用"取得时刻是否早于知道收缴令"作代理（谓词读 `knows(actor, 收缴令事件)` 与取得事件时刻），但这是对题意的改写，且仍不能定私铸者的罪。
- ④ 赌债是否受保护按本政体法典 — **自**。05 §5.2.4 / §A.7 的内容类型 `contract_validity`（12 §12.10.2 已示范 `contracts.void`）；赌债作为 loan/promise 义务在创建时把效力判定冻结进条款快照（01 §1.4、12 §12.5.4"合同效力以签约时为准"）；王国法典写 `void: [contract:gambling_debt]`（词在 contract 族下）。数据：法典 `law/codes.json` 契约效力条目。
- 二阶（香火钱多为轻钱 → 寺观购买力缩水、修缮延期；东家涉案 → 股东撤资）— **自**。寺观公库按资源种类分账户，修缮 = project 义务，材料按 quote 采购，公库不足则停工（I2、01 §1.4 project 行、15 §15.4 ppi）；撤资 = `holding.transfer(share)` 由自治候选触发（05 §5.7.1，need:安全 / need:钱，applicability 读 `believes(self, bank_insolvent)` 等主观视图）。数据：经济包 `autonomy/candidates.json` 一条"撤资"候选。
- 易错（倒手存钱庄凭空造钱）：I1 按资源种类守恒，不会发生。

### E2 ★ 冬夜地震（6 条：自 4、缺 1、矛 1）

建模：地震 = 生态包灾害时钟规则（paceable、major）产出原语：设施 condition（郡狱外墙、矿口）、路线封闭持有、新建堰塞湖 node 实体（create，带水量账户）；囚犯 = `guest_of{detained}` + impaired 状态 + 案件执行阶段；官矿 = node + 官府 `owns` + 矿口 building（通道类设施）。

- ① 伤亡按子夜 NPC 所在位置（家中）结算 — **自**。01 §1.5 站位由日程派生、05 §5.8 基准作息（夜在家）；灾害规则对 `located(x)` 落在受灾子树内的实体施 vital（05 §5.5 灾害 → 原语）。数据：灾害规则的选择器用 `persons(location in …)`（§A.13）。养狗户伤亡更低：地震前兆事件（数据：规则先发一条低显著度、只对听觉阈低的生灵可感知的 `tremor` 事件）→ 狗（tamed creature）反应规则 emit 声音 → 主人感知（01 §1.5 听觉）→ 自治候选"逃出屋外"→ 主震时不在屋内。全部在已有形状内。
- ② 逃犯刑期不清零、自首减等、原官职/职业不恢复 — **矛**（落题）。04 §4.1 / §4.5 把"拘留"列为失能类：impaired 时"行为能力与同意能力派生为假"，§A.3 同；于是囚犯不能发起任何提案，"趁夜逃散"没有行为者。但 05 §5.2.7 把"越狱、逃亡"列为执行阶段原语失败的原因，01 §1.3 `guest_of` 写"detained 离开需东道同意或脱逃"——两处都预设囚犯能自行脱逃。两种说法冲突；按 04 的规则，本题的逃散只能是外力（劫狱）或根本不发生。其余子项在机制上是通的：刑期在案件实体的执行到期项上（05 §5.2.7，缉获后"重登记"，但余刑还是重算没有写明）；自首是法律包动作，减等由刑罚 RX 读情节（05 §5.2.4）；官职不恢复要靠章程 `removalTriggers`"被判某类罪名"（04 §4.6，未声明则只 suspend，出狱即恢复）。
- ③ 下游水源存量骤降，溃坝风险随降水累积 — **自**。河段有向边与水量账户（01 §1.5、05 §5.5）；滑坡 = 路线/河段封闭 + create 堰塞湖 node（规则可用 create，06 §6.3）；入流经 `src:weather`、槽 `weather:precipitation`（§A.16）；溃坝概率 = 灾害时钟规则读堰塞湖水量账户 ÷ 容量（槽 `ecology:floodRisk`）。数据：生态包 `rules/clock.json` 一条"堰塞湖"规则与容量表。
- ④ 矿脉储量不因地震增减；入口封闭期间官方产量 0、盗采有产出 — **自**。01 §1.5 / §1.10：可采量 = min(储量, 通道设施 condition 派生容量) × 修正项（槽 `facilities:extraction`）；储量账户不动。官方产量 = 产量派生 × 在岗工时 `laborHours`（05 §5.1），封矿期间经营者日程片段为空 → 0；侧洞 = 另一座引用该 node 的通道类 building（数据：world/geo 建筑清单），盗采动作从同一储量账户 transfer，受侧洞容量限制。数据：侧洞设施、封矿期的经营状态。
- ⑤ 石料木料、工匠工钱上涨 — **缺**（工钱部分）。材料：15 §15.2 预期需求含"工程材料"→ 价格升，自。工匠工钱：设计没有劳务的市场投影——15 §15.2 的 value() 只对商品类；wage 义务的金额是雇佣动作的条款（01 §1.4"按实际工时"），05 §5.1 用工候选只决定招不招，不决定出价；§A.16 没有 `economy:wage` 槽；06 §6.7 的"典型日收入表"是上限不是行情。"工钱整体上升"无处派生（与 E16③ 同根）。
- 二阶（逃犯欠钱庄分期 → 担保人被追偿；首领离巢方向与兽群下山方向一致）— **自**。保人 = 新义务种类（`ontology/obligations.json`：debtor 保人 → creditor 钱庄，由违约事件触发的反应规则 `obligation.settle`），形状合规；首领离巢 = 自治候选（drive:territory 读栖地容量，13 §13.3）、兽群 = 迁徙流量规则读容量（05 §5.5），两者读同一组被地震压低的容量值，方向一致是派生结果而非随机。

### E3 ★ 湾港通译（5 条：自 3、缺 2）

建模：契约 = forward/delivery 类义务（条款快照）+ 文书物品（`records`）；通译 = 在场 companion，答复经 `actedAs: interpreter` 转述（06 §6.9.2、§A.15）；回扣 = 通译的 `deceive` tell + 自留 transfer。

- ① 契约以哪种文本为准按星湾法典 — **缺**。设计不给文书任何语言属性，11 §11.1 明确"不做书面语与口语之分、玩家可见的外语文本"，13 §13.2 的语言只是技能 `lang:*`。义务只有一份 `terms`（真相），玩家手里只有通译转述的版本（知情）。"以湾文文本还是以转述为准"是对两份**文本**的选择，设计里不存在第二份文本可供法典选择；只能走②的欺诈撤销。
- ② 通译欺诈为个人罪、契约可撤销、已交付渔获折价返还 — **自**。05 §5.2.3 roles + 谓词读 `deceive` 标签与 `actedAs`（通译以代办身份作出的 tell）；05 §5.2.7 民事⑨救济：撤销 → 返还原物 → 返还不能折价。数据：星湾法典 `offense:fraud` 谓词一条、民事⑨。
- ③ 玩家不识湾文时只能看到通译转述，不应直接得知原文细节 — **缺**。口头部分成立（§A.15 沟通度 0 → 只能经通译）；但契约是文书物品，阅读 = `tell(源 = 物品)`，前置只有识字技能（05 §5.4"读书 = learn 前置派生（识字技能…）"，11 §11.1"写作系统只以识字技能表达"）——玩家识字即可直接读出湾文契约的 `records` 全文，不存在"学会湾语后才能复读"的触发点。设计规则会得出相反结果。
- ④ 渔民先对玩家好感下降，真相传开后转向通译 — **自**。违约/争执事件对玩家产生 impress（05 §5.6）；起因链含通译的 deceive tell（01 §1.7 多因），reveal/识破事件进入渔民知情集合后，归因系数按角色把印象分给通译（05 §5.6 归因系数、§5.4 更正）。数据：角色归因系数表。
- 二阶（港口缺通译 → 交易成本上升 → 内陆鱼价上涨）— **自**。沟通度 0 → 手势交易，不能缔结带条款的义务（§A.15）→ 收购契减少 → 供给流量降 → 15 §15.2 到岸成本/有效存量 → 内陆鱼价升。
- 易错（叙述者无视语言障碍）：08 §8.4 审查核对知情与投影，口头部分可守；文书部分见③。

### E4 ★ 部盟的学徒（6 条：自 6）

建模：间谍 = person，`purports`（化名、混血外貌，13 §13.4 的 purports 用于人）；真实的 `member_of`（部盟，visibility 仅成员）与 `citizen_of`；在镇的 `employed_by`、`certified`（铁匠）、`member_of`（商会）、`holds_office`（账房）；防图 = 文书物品（records），分批经驿传 delivery 义务寄出；驿站 = org，有账簿（05 §5.4 记账反应）。

- ① 暴露前投票与签字有效，暴露后不溯及无效 — **自**。投票是 motion 实体上的事件（05 §5.2.5），签字是以商会职位 `actedAs` 作出的事件与义务（05 §5.3），事件只追加；暴露 = reveal 事件 → 商会章程 `expel`（05 §5.3 字段表）关闭 member_of/holds_office；此后不能再以职位行事，已成立的义务照常（04 §4.5"委托不撤"）。若法典要撤销，走民事⑨且善意第三人不追。数据：商会章程 expel 条件、法典对冒名签约的效力条款。
- ② 截获信件作证物，驿传记录可查已寄出几封 — **自**。信件 = 文书物品；截获 = holding.transfer/扣押（判决或职位权能）；驿站 org 的账簿按 05 §5.4 记账反应追加每笔 delivery 义务的创建与交付事件，镇守阅读账簿 = tell(源 = 账簿)；证据评分收 document 类（05 §5.2.7）。数据：驿站组织章程声明记账。
- ③ 审判还是引渡视两国当前外交状态 — **自**。引渡由 `allied_with` 条款与政体关系投影派生（01 §1.3、05 §5.2.4）；战争/和平是关系状态（05 §5.10）；是否移交由王国政体的自治候选（05 §5.7.3，读 `diplomacy:leverage`、standing）或玩家作镇守的动作决定。
- ④ 学到的锻造技艺不因身份暴露消失 — **自**。技能熟练度是慢变事实（01 §1.2）；certified 被开除只把派生封顶（04 §4.3 certified vacated 行）。
- ⑤ 部盟对王国好感下降 — **自**。拘捕是对部盟成员（隐蔽 member_of）的 harm 事件；05 §5.3"成员受害 → 组织立场"与 §5.6 沿 member_of 传导；双键分离保证 standing(部盟, 王国) 独立于 standing(部盟, 玩家)。
- 二阶（师傅被疑连坐、生意下滑；在镇兽人遭排斥、部盟商品涨价）— **自**。accomplice 要求 `knows(x, 意图)`（05 §5.2.3），师傅不知情则无案；"被疑"是推断规则产 belief（05 §5.4，数据：法律/社会包 `rules/inferences.json`）→ 立场降 → 顾客选店读 standing（15 §15.2 店家与关系项）；排斥 = 居民对 citizen_of 部盟者的立场沿属人传导（05 §5.6）→ 交易减少 → 供给降 → 价升。
- 易错（暴露后全镇立刻知情；已寄出防图不影响防守）：传闻按通道延迟（05 §5.4）；防守结算读城防设施 condition 与修正项（05 §5.10 `military:strength`），敌方"知道布防"要写成 `combat`/战役求解器的修正项读对方知情集合——形状可用（槽 `military:strength` 的 when 读 `knows(敌方组织, 防图事件)`），数据在军事包。

### E5 ★ 替身服刑（6 条：自 6；附一处前提问题）

建模：判决 = 案件执行阶段：`move(玩家, 牢房)` + impaired（拘留）+ `employed_by(官矿)` 劳役（05 §5.2.7）；狱吏 = 典狱职位持有人，职权表（治理包数据）含收监/释放/派工；乞丐 = person；替身 = 狱吏以 `actedAs` 释放玩家（关闭状态与劳役持有）并把乞丐以 `guest_of{detained}` + employed_by 收入。

- 前提问题（不计分，但影响情境成立）：被拘留的玩家按 04 §4.1 失能，不能发起"买通狱吏"的提案；贿赂只能在收监前约定或由第三人代为。与 E2② 同一矛盾根。

### E9 ★ 三地换汇（6 条：自 4、数 1、缺 1）

### N2 ★ 纸币"交子"（6 条：自 4、缺 2）

- 加什么 (a) 钱庄发行可兑现纸币 — **自**（以票据形状）。纸币不能是铸币资源：`src:mint` 只许发行政体（15 §15.3、12 §12.2.3）。可行形状是不记名票据：bill 义务（出票钱庄 → 持票人，01 §1.4"债权人可为不记名=持票人"）+ 每张纸币一个代表物品（`represents` 指向该义务），流通 = `holding.transfer(owns)`，兑现 = 到网点 settle（15 §15.5）。数据：经济包义务种类 `banknote`（上位 bill）与票据物品模板。
- 加什么 (b) 超发导致通胀 — **缺**。15 §15.1 明写"不做信用创造（钱庄只能把手里的钱贷出去，I2）"；15 §15.3 的货币价值公式只对金属铸币（金属商品类存量 × 含量），票据不进"流通存量"，报价以法定铸币为 unit——纸币发行量不进入任何价格公式，"超发 → 物价"没有传导路径。要得到通胀必须改 core 货币模型（把可兑现票据计入该铸币的活跃存量或另立信用货币定价），不是只加数据。
- 装上后 (i) 官府是否收纸币缴税需明确 — **自**。法典认可条款"承认的凭证（盐引、汇票）"（05 §5.2.4、§A.7 recognition）；税的清偿按 05 §5.1 票据结算 = 附条件清偿。数据：法典 recognition 条目。
- 装上后 (ii) 远方郡不认纸币时需兑换 — **自**。bill 兑付前提是兑付地有该钱庄 branch（01 §1.4）；无网点 → 只能持票回网点或经他人折价收购（npcDecision 读主观信用）。
- 装上后 (iii) 挤兑时纸币贬值 — **自**。持票人对钱庄偿付能力的 belief（05 §5.4，R2-E2③ 拒收汇票同形）压低 itemValue 的"真伪与来历"项（15 §15.2 读 viewer 主观视图）与收票意愿。
- 易错（纸币与铜钱等值且无限发行；超发不影响物价）— **缺**。前半可由 (iii) 的主观折价避免；后半正是 (b)：设计里超发确实不影响物价，而发行（创建 bill 义务）本身不受任何总量约束。
- 第三方视角：若 N2 作为第三方包，还会撞上 `src:mint` 政体限制与货币价值公式不可扩展（`economy:coinCredit` 槽只给金属铸币）。契约附表 B 对"货币供给"没有槽。

### N3 ★ 监狱与刑罚执行（4 条：自 3、矛 1）

- 加什么（刑期、劳役产出、探监、狱中疾病、减刑与大赦、狱中帮派）— **矛**（落题，与 E2②/E13③ 同根）。可得的部分：刑期 = 案件执行阶段的到期项（05 §5.2.7）；劳役产出 = employed_by 公家 + laborHours（05 §5.1）；狱中疾病 = 病例事实按同地传播（05 §5.5）；减刑 = 改案件执行到期项的判决动作（数据）；大赦 = 政体动作对案件集合执行（关闭 wanted、提前执行释放）。不可得的部分：探监（对话）与狱中帮派（member_of、暗号、争斗）都要求囚犯有行为能力与同意能力，而 04 §4.1/§4.5、§A.3 把拘留列为失能（行为能力为假），与 01 §1.3"脱逃"、05 §5.2.7"越狱"冲突。按 04，囚犯是不能说话、不能结社、不能同意的静物。

- 装上后 (b) 大赦需追溯到具体刑期 — **自**。案件是实体，执行阶段与余刑可读（§A.7 七阶段），大赦动作的选择器用 RX 过滤 `entities(case, …)`（§A.13）；每件案一条子事件。数据：法律包"大赦"动作。

## 专项评估

### ① 时序与并发（I31、争夺池、补算）

- 五阶段 + 排序键 + 序号 + 骰值键含序号的骨架是自洽的，I31 的"刻集合由日程堆唯一确定"（14 §14.3）是逐日 vs 一次等价的关键，写得清楚。
- **争夺池（3′）的粒度未定**：14 §14.2 说"指向同一互斥标的的提案不在提交时结算而登记到争夺池"，但一个提案通常含多条原语（买货 = 钱 + 货两笔转移）。只延迟争夺的那条会破坏提案的事务原子性；延迟整个提案则阶段 4 对阶段 1 事件的反应已经跑过，而被延迟提案的事件要到 3′ 才产生，反应队列的广度优先顺序出现"先反应后发生"。"最后存量"争夺更难：只有在刻末才知道多笔转移之和超过存量，意味着所有对同一账户的转移都要延迟。06 §6.5 第 8 步又要求提案同步返回 applied/check——对争夺型提案只能返回"待裁决"。这是实现复杂度之外的语义空洞（11 §11.2 第 22 条只承认复杂度）。
- C3（transition 顺序两说）见矛盾清单。
- 补算：事件插在读取事务之前、seq 连续，且刻集合与步长无关——成立。未处理的是**补算递归**：A 区补算时读 B 区（到岸成本沿路线读他郡存量），B 补算又读 A，14 §14.3 没有终止规则或"读取时刻以外不得再触发补算"的约束。
- 反应链截断 `reaction_cut`"不在下一刻续算"：settlement 优先级类（货损条款、记账、冲回）若恰在被截断的链尾，账本虽守恒但义务状态与文书会与事件不一致；应规定 settlement 类不受深度上限或截断后登记到期项。
- 刻回滚后"用剩余规则重跑本刻"：重跑的骰值键含序号，序号已变 → 同一玩家提案在重跑中可能得到不同骰值；对玩家可见的"同一动作两种结果"没有说明，重放一致性成立但体验口径缺。
- 结论：结构合格，争夺池的提案粒度、补算递归、截断与 settlement 类三处需补规定。

### ② 守恒漏洞与玩家套利

- 已有防线（15 §15.9 三十余条）覆盖面广，批次 taint、出清滑点、远期可靠度、程序成本、改币一次性换算都到位。
- 新发现：(1) **制造产出无源**（S3）——若引擎默认从"无"产出，I1 按资源种类失效；若实现者临时加源而无每日预算，配方链（卤水 → 盐 → …）可能被刷。(2) **法律类状态无权限解除**（M4）：解除 detained/被封存的提案只受难度派生约束。(3) **事件窗口无计数**（M2）：免税额、滥诉计数、常客识别在数据上写不出来，缺省退化为每次重置（E9 的易错点正是设计缺省）。(4) **票据无限签发**：bill/banknote 的创建不受任何总量约束（I2 只管账户），挤兑靠 npcDecision 与破产兜底；对玩家开钱庄的情形，开票→他处贴现→破产的循环没有探测用例（标杆 B04.4 列表也没有）。(5) **suspend 不停俸**（M6）：被停职者照领俸禄。(6) **holding.rescale 的"持有人同意"**对 NPC 由 npcDecision 给出，若章程 `votingWeight: by_share` 且玩家持多数，稀释少数 NPC 只需表决——合法但应在 B04.4 加用例。
- 可替代伪币/轻钱按真实种类结算（M7）堵住了"轻钱入账造钱"，代价是 E1 类骗局不可表达。
- 结论：守恒本身无漏洞；漏洞集中在"谁有权"（状态、票据）与"缺少计数"两类。

### ③ 性能与降级

- 07 §7.5 的量级估算只计入规范谓词、感知、主观视图、市场闭式、归约；**自治候选与推断规则**（每 NPC 每日对全部候选求 applicability/utility、对全部推断前提求值）没有进入估算，也没有像反应/罪名那样的守卫索引（12 §12.2.3 自治候选行只校验 RX 只读主观视图）。按 5×10³ 次决策/日 × 几百条候选 × 10²–10³ 节点，已与 0.5 s 的主观视图预算同量级，且 B14.8"默认档降级 0 次"的依据因此不完整。
- **钉住 (c)** 把 owns 任一具名物品个体的实体都钉住；设计又把地契、当票、汇票做成物品个体（01 §1.4 票据 = 义务 + 代表物品），于是每个有地契的农户都被钉住并在规则层逐日自治——与"统计层只模拟聚合与稀疏义务"（11 §11.1）相抵触，规模下可能把规则层人口推向全体居民。
- 争夺池要求延迟结算，刻末批处理的内存与复杂度未估。
- D1"见证按需展开"把存储换时间（每事件存感知快照版本 + 差异），长线存档体积影响未估；退役表 `tables` 区随卸载增长已被设计者承认。
- 降级永不改语义、输入事件化（budget_set/config_set）是正确的；D3 滞回合理。
- 结论：模型方向正确，但两项遗漏（候选/推断成本、钉住过宽）会直接撞 B14 门槛。

### ④ 复杂度与可理解性

- 枚举面：19 原语、7 触发、8+4 交接类、5+3 两端消失、10 民事类、13 卸载策略、30 修正槽、32 不变量、5 阶段 + 3′、9 退役区、四种声明式规则形状、八种连接点。附录 A 收口有效，但同一词在章内仍有局部定义漂移（X1、X2、X3、X4）。
- "同形复用"掩盖了几处特例：insolvent 是协议的"变体"；补丁"不是层"却参与合成；争夺池是"子步"；`pins` 一词两义。读者要靠附录 A 与 14 章互相对照才能确定一次死亡的事件顺序。
- 失能/受限的概念合并（C1）是可理解性问题的典型：一个词同时承担"不能思考"与"不能离开"。
- 对第三方作者：rules 档"五件事 + 两个 auto"是好的收敛；但 N2/N6 一类需要改货币模型、N1 需要改阅读前置的包，作者无法从 `pack doc` 的"接口缺口"报告之外得到任何提示，建议在 12 §12.1"不做"里把"货币模型、语言/文书、阅读前置、劳务市场"列为明确边界。
- 09 章的历史叙述（设计者已承认）与 12 §12.11.3 的"已完成记录"增加噪音。

### ⑥ "只加数据"是否成立

- E 题 118 条中 109 条只加数据可得，且数据位置多数能落到具体文件：法典（`law/codes.json` 的罪名/民事/程序/认可条目）、章程字段、持有与义务种类（`ontology/*.json`）、自治候选、推断规则、修正项、文化记录。
- 不成立的集中在五个核心边界：劳务市场（E2⑤、E16③）、制造/私铸的产出源（E1③）、文书语言（E3①③、N1）、拘留失能（E2②、E13③、N3）、非金属货币定价（N2、N6）。另有两处"方向对、落点无"：事件窗口计数（E9②）与失真表扩展（N1 (a)）。
- 第三方包（N6–N8）：命名空间、依赖守卫、槽位冲突、卸载策略（convert/keep/convert_entity/redeem）、实体代次与墓碑足以覆盖三题的装卸与同装预期；契约附表 B/C 对 N7/N8 足够（transport:*、combat:deterrence、economy:price、税表、规范补丁）。N6 的冥币暴露附表 B 没有货币供给/信用类槽，也暴露 15 §15.3 的公式只对金属。
- "只加数据"对内容包成立，对**改 core 经济模型输入**的规则包仍半开放：附表 B 开的是乘子，不是公式分支。

### ⑦ 对照标杆标准仍平庸或缺位的维度

- **劳务与工资**：B18 覆盖商号经营，没有劳动力价格；工资是合同常数，没有市场。这是经济维度最明显的缺位。
- **货币与信用**：B18.6 只测改币；纸币、兑现承诺、信用货币被 15 §15.1 排除，而中古经济的真实套利与危机多从这里来（交子、挤兑）；与"业界标杆"的 Victoria 3 级深度相比平庸。
- **受限状态与囚禁玩法**：C1 使监狱、人质、软禁、幽禁一类玩法要么不可玩，要么让玩家角色"消失"三个月；B06.6 的"不卡死"只管任务，没有管"玩家可操作性"。
- **语言与文书**：只到沟通度；B18.3 的通译题可过，但契约语言、翻译、伪译这类信息不对称玩法无法成立。
- **制造链**：生产只写了"产量派生"，配方、副产品、质量继承没有数据形状，守恒源缺失（S3）；对比 Factorio/DF 的物品流水线明显薄。
- **认知对可替代物的不确定性**：伪币、掺假粮、以次充好只能靠"品质档是账户键"（15 §15.2）表达，买家永远看穿；B06 主观认知在"物"上是空白。
- **性能口径**：候选与推断未计入成本模型，B14.8 的"0 次降级"依据不足。
- 做得好的维度（供对比）：因果可追溯、守恒审计、转移协议、规范栈、主观视图四域、开放扩展的装卸语义与报错、同意作为裁决输入、争夺公平性目标——这些仍是业界少见的组合。
