# 续卡 llm1b-candidates：准确重放测量 + 把候选命中率做上去（仍不调用付费模型）

你的上一卡已提交到 t-llm1（只在分支，未合入 s4a）。主会话审查：机制部分可以，但"直达命中 0/20"来自粗略重建的场景（无原档，在场者/地点/库存不对），几乎每回合只出 core:move、core:time，**测量不可信，也证明不了方法可行**。整个方案取决于候选命中率，本卡把它测准并做上去。

## 1. 准确重放测量（先做）
- 试玩记录 logs/sessions/a3-playtest/<轮次>/真实试玩.json 与 真实试玩失败.json 里有每回合实际调用的引擎动作（calls：tool/args/result）。从每个会话的开局（场景 json 的 initial / setup）起，按顺序用引擎原样重放这些已结算的调用，精确还原每回合开始前的文档状态（用当前引擎；规则已变导致某调用不再成立时，记录并跳过该会话后续，不要伪造状态）。
- 场景定义在 tests/playtests/*.json（冻结，只读）。若某会话无法从记录完整还原，写明原因与数量。
- 在**全部回合**上测量（不只失败回合）：对有明确动作判据的回合（场景 expectedTools 或记录中成功的状态改变调用），统计"正确动作（工具 + 关键参数，如目的地、交易对象与物品、学习技能、制造配方）是否出现在候选前 5 内"；对创意/开放类回合，统计是否给出"都不是 → 开放提案"路径。报：总回合、可判回合、命中数、命中率，按场景分组；列出未命中回合的原因分类。

## 2. 改进候选生成器，直到可判回合命中率 ≥ 85%
- 按未命中原因修根因：例如关键词/别名索引缺漏、在场者与可交易物未进入候选、学习/练习/制造/战斗/等待类动作的参数没从场景事实派生、多步意图（先学后练）只给第一步等。派生优先：从场景事实与动作目录派生，不写场景特判、不按测试原话写词表（tests/overfit-guard 必须过）。
- 候选数上限 5（含"都不是/查更多"另计）；参数由引擎填，缺槽要说明。
- 自由度底线不变：创意意图不得被近似候选吞掉。

## 3. 可选对比（不花钱的部分）
若时间允许，统计每回合给模型的输入 token（新/旧）与回执 token（新/旧）在准确重放下的数值。

## 不要
不调用付费 API；不改冻结语料、scorer、tests/playtests；不新增复演版本标记；不改 docs/、dist/。

## 验收
测量脚本放 tools/（例如 tools/candidate-replay.mjs），可重复运行；命中率 ≥85% 或给出到不了的确切原因；tests/turn-confirm 及上一卡相关测试、overfit-guard、arch-metrics、system-map、CORE 全过；静态提示 ≤10593；performance 通过。
汇报（≤400 字）：重放还原了多少会话/回合、命中率（改前/改后，按场景）、未命中原因与修法、token 对比、改动文件、命令与 pass/fail、偏离与未解决。
