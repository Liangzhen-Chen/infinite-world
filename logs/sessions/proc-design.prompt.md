【进程规则】只能结束你本会话亲自启动并记录了 PID 的进程；禁止用 Stop-Process/taskkill 按名称或批量结束 node（Codex 本身也是 node）。临时调试文件结束前删除。
【测试运行规则】验收命令里的测试文件逐个单独运行（每个文件一条 node --test --test-isolation=none tests/<文件>），不要把多个文件放进同一条命令同进程跑——会互相预加载模块、掩盖循环导入与顺序依赖（10-23 教训）。
【测试输出规则】测试命令输出必须过滤为摘要，PowerShell：`node --test --test-isolation=none <文件> 2>&1 | Select-String -Pattern "^ℹ (pass|fail)|^✖|^not ok" | Select-Object -First 40`（沙箱会拒绝 grep/head）；禁止读取完整测试输出；需要细节时只看单个失败用例最后 30 行。
【环境】沙箱不允许 git 写操作（merge/add/commit/checkout），只用 git status/diff/log/show/grep；改完不提交，由主会话代提交。浏览器与子进程类测试会 EPERM，列出即可，由主会话在沙箱外补跑。node 命令设 TEMP/TMP 为 F:/dnd-tmp；最多 3 个 node 进程。
【时限】本卡有总时限（见下方“限时”），接近时停手，把已完成、剩余、下一步写进交接报告。
【硬约束】不删/跳过测试、不放宽断言（改测试只允许对齐设计且保留断言意图，逐处写依据）；不读 secrets.json；不部署；不改 docs/架构设计/；世界内容只写 world/、不手改 dist/。用中文汇报。

限时：75 分钟（到 65 分钟时停手写交接）。

# 卡 proc-design：把本项目的开发流程设计到生产级（只出设计，不写实现）

## 背景（项目现状，供你判断，不是让你沿用）
- 游戏《无限原野》：规则引擎（server-plugin/）+ 世界数据（world/）+ 约 453 个测试文件（tests/，node:test，每文件单独进程跑）。引擎是中枢，几乎每个测试都加载它。
- 一台 Windows 机器，32 核，内存是瓶颈（空闲常低于 5GB；单个测试进程 0.5–2GB）。每张卡最多 2 个 node 测试进程。
- 角色：主会话（Claude）是协调者：拆卡、写指令、审 diff、跑门禁、合入、向产品经理汇报。执行者：Codex（luna 默认 / sol 较难 / astra 设计审计；沙箱内能读写工作区、跑单个测试，但不能起子进程、浏览器、git 写操作）；Claude 子代理（Sonnet/Opus，在主会话环境里，能真实跑子进程、浏览器、git）。产品经理只看效果。
- 分支：master ← 阶段集成分支（如 s5a）← 每张卡一个 worktree（F:/dnd-wt/<名>）。执行者不提交，主会话审完用 guard-commit.sh（先跑 overfit-guard 防背题）代提交，再合入集成分支；阶段收口跑全量扫描、性能门槛、浏览器测试后 land.sh 合 master。
- 现有门禁：交卡后 wait-cards.sh 自动跑 card-gate.mjs：按 import 关系选受影响测试（几乎总是 ~430 个），跳过 slow-tests.tsv 的 15 个慢文件（它们占全量 67% 时间），失败的文件到基线 worktree（BIS2）复跑，按失败用例名对比分新回归/基线同败。
- 覆盖率选测（test-impact/）：按 V8 函数覆盖记录每个测试执行过哪些函数，改动只选执行过被改函数的测试；地图还没建成过。

## 近期暴露的问题（10-23 到 10-26）
1. 一天合 16 张卡后全量扫描才发现 22 个回归；后改为交卡自动门禁。
2. 门禁按"文件是否失败"对比，漏过一个真回归（同文件基线恰好挂着另一个用例）；改为按用例。
3. 基线偶发失败让门禁把真回归误判为基线同败；加了基线复跑。没有偶发测试名单。
4. 覆盖率收集卡在一个慢测试上 4 小时无人发现（主会话自己起的后台任务没有卡死检测；脚本无单测超时、单个错误会让整轮不出结果）。
5. 门禁一张卡 94 分钟；4 个门禁同时跑互相抢内存。
6. 测试会改写 docs/测试报告/ 下截图与 docs/system-map.*，每次交卡都混进改动，要手工剔除。
7. 主会话手写的工具多次在真实使用时才暴露 bug（工具链本身缺测试）。
8. 两次在 overfit-guard 未通过时提交（已改为 guard-commit.sh 强制）。
9. 执行者偶尔改禁改文档、留下孤儿测试进程。
