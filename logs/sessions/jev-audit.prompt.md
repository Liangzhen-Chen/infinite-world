# 卡 jev-audit：全局盘点"适合接入判断模型（Jev）"的点（只读，不改代码，不花钱）

工作区 F:/dnd-wt/S5A（master 最新，只读；产出只写 F:/dnd/logs/sessions/jev-audit.final.md 与 jev-audit.json）。先读 docs/产品原则.md 与 docs/架构设计/ 中与对话、NPC 决策、开放提案、知情/传闻、文书、契约、审判、叙述审查相关的章节（自己找），只汇报结论。

## 背景
Jev（TypeSafe System One）是"只出判断、不写内容"的模型：choice（从给定选项中选 1，最多 255 个选项，带概率）、score（有序等级打分）、noul（是/否概率），一次请求可含最多 128 题，约 0.2 秒/次，极便宜。中文能用。实测：从给定动作中选具体动作很准；对"这是否是超出现有动作的创意意图"会过度自信地套近似动作。
产品边界（不得违反）：**规则引擎是唯一真相**，模型不决定任何结果；**没有模型时游戏也必须完整可玩**（每个接入点都要有无模型的兜底，例如退回当前规则或让玩家显式选择）。Jev 只能做"把文字翻译成引擎可用的结构化判断"，选项必须由引擎从世界事实派生给出，结果由引擎规则消费。

## 已知线索（主会话已核实）
- server-plugin/dialogue.mjs：persuade/threaten/bribe/deceive 只做魅力对精神的对掷，不看玩家说了什么；成功也只回"具体的事还得另议"，不改变后续 npcDecision。玩家说话的方式与内容几乎不影响 NPC。
- server-plugin/open-actions.mjs prepareOpenAction：开放提案可只交 intent 文本，由无模型构造器（action-constructor.mjs）按关键词猜，实测命中低；或由模型直接写 effects。
- 叙述编造检查目前由 DeepSeek 逐句审查（consistency-review / consistency-service）。

## 要做
全局盘点所有"需要理解一段文字才能做出判断"的点，包括但不限于：玩家对 NPC 说的话（语气、诉求、许诺、威胁、奉承、谎言、论据是否切中对方利益/性格）、NPC 之间的转述与传闻（是否失真、可信度）、玩家写的文书/契约条款/告示内容（性质分类、是否伪造声明、是否有效条款）、开放提案（想改变什么对象/属性/方向/手段）、命名与指代（"那个卖刀的"指谁）、审判中的证言与陈述（是否自相矛盾、是否承认）、宗教/许愿/祈祷内容、教学中的提问、玩家自定义目标/计划、叙述审查等。对每个点给出：
1. 位置（文件:函数），现在怎么处理（忽略 / 关键词 / 固定选项 / DeepSeek 生成 / 掷骰）。
2. 若接 Jev：问什么（题型与题目）、**选项由引擎从哪些世界事实派生**、引擎哪条规则消费这个判断（现有规则还是需新增）。
3. 无模型兜底怎么做。
4. 对玩法的价值（1–5，按"世界更真实、玩家说的话更有分量、自由度更高"），实现难度（1–5），风险（例如被玩家刷判断、提示注入、过度自信）。
5. 是否需要新增规则（如 NPC 决策加入"说话方式"输入）——标出属于哪个阶段（S5/S6/A4…）。
